## 00.总览：为什么再写一本 Go 教程

市面上 Go 教程大体分两类：

1. **"语法速查"**：Tour of Go、菜鸟教程之类，能让你 1 小时跑出 Hello World，但合上书就不会写项目。
2. **"源码深挖"**：《Go 语言设计与实现》《Go 语言高级编程》之类，对**已经写过 Go 一两年**的工程师极其有用，但新手翻两页就劝退。

**本书要做的，是用四卷本同时解决"上手慢"和"难度断层"两个问题**：

```
卷一《语法卷》  ──→  你能读懂任何 Go 代码 / 能写 200-500 行的小工具
卷二《工程卷》  ──→  你能独立写一个 5000-10000 行的后端系统
卷三《底层卷》  ──→  你能在 Go 源码层面给团队做技术分享 / 看得懂 runtime
卷四《实战卷》  ──→  你能上线、定位 OOM / 死锁 / GC 抖动 / goroutine 泄漏
```

> **本书与 C++ 版四卷本姊妹篇完全对位**：如果你同时学过 C++ 那一套，本书每一章末尾会有「**与 C++ 对照**」小节，帮你快速建立"两个语言怎么解决同一问题"的对照表。

- **可独立阅读**：卷四前半部分（pprof / trace / race detector）只需要会写 Go，不需要懂 runtime。

## 07.Go 版本基线与工具链约定

| 项 | 约定 |
|---|------|
| 语言版本 | **Go 1.22** 为主基线，1.21 / 1.23 差异点单独说明 |
| 模块管理 | `go mod`（不讨论 GOPATH 老模式，仅在卷一第 17 章作为历史介绍） |
| 编辑器 | VS Code + Go 扩展 / GoLand 二选一，不要求一致 |
| 操作系统 | macOS / Linux / Windows 均可，案例代码不涉及平台特定 syscall |
| 构建命令 | `go build` / `go test` / `go vet` / `go run` 全部使用官方工具链 |
| 第三方库 | 卷一不引入；卷二仅引入 `golang.org/x/...` 与 `gorilla/...` 等极轻量库；卷三、卷四引入 pprof / trace / OpenTelemetry |
| 代码风格 | `gofmt` + `goimports` + `golangci-lint`（默认配置）三件套 |
