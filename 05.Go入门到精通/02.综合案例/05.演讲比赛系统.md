## 01.需求说明
- 12 名选手抽签分组，第一轮淘汰 6 人，第二轮取前 3 名
- 每轮结束输出排名 CSV，比赛记录持久化

## 03.数据模型（占位）
```go
type Speaker struct {
    ID    int
    Name  string
    Score [2]float64 // 两轮成绩
}

speakers := map[int]*Speaker{}
groups   := [4][]int{} // 4 组分签
```

> **本案例完整代码、双轮淘汰逻辑、排序稳定性讨论将在卷二定稿阶段补全。**

## 07.项目总结
- 学会用 slice 表达"组"，用 map 索引"id → 对象"
- 学会 `sort.SliceStable` 与 `slices.SortStableFunc` 区别

## 08.技术思考
1. 为什么 `slices.Sort` 不稳定？什么时候稳定排序重要？
2. 抽签的随机性如何避免每次启动相同？（`math/rand.New` + 种子）
