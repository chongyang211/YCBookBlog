- **代码量**：~600 行 / 5 个文件

## 01.需求说明
- 用户写 `func TestXxx(t *T) {}` 风格的函数
- 框架自动发现并执行
- 支持 `assert.Equal` / `assert.NoError` 等
- 支持子测试 `t.Run("name", func(t *T){})`

## 03.断言库 assert（占位）
```go
type T struct {
    name   string
    failed bool
    msgs   []string
}

func (t *T) Errorf(format string, args ...any) {
    t.failed = true
    t.msgs = append(t.msgs, fmt.Sprintf(format, args...))
}

func Equal(t *T, want, got any) { ... }
```

> **本案例完整代码、反射查找函数的 hack、与官方 testing 包对比将在卷二定稿阶段补全。**

## 07.项目总结
- 理解 `go test` 是"用代码生成 main 函数 + 反射调用"
- 学会反射 API（`reflect.TypeOf` / `ValueOf` / `Call`）
- 学会 `go:generate` 注入代码

## 08.技术思考
1. 为什么官方 `testing.T` 用 `t *testing.T` 而不是接口？
2. 反射性能比直接调用慢多少？
3. 怎么实现 "测试隔离"（每个 case 独立子进程）？

## 09.延伸挑战
1. 加 fuzzing 支持
2. 加并行执行（`t.Parallel`）
3. 输出 JUnit XML 兼容格式
