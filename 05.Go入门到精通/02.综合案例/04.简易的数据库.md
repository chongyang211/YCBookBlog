## 01.需求说明
- REPL：`> SET k v` / `> GET k` / `> DEL k` / `> KEYS pattern`
- 每次 SET / DEL 都追加写到 `aof.log`
- 启动时重放 `aof.log` 恢复数据

## 03.KVStore 类型设计（占位）
```go
type KVStore struct {
    mu   sync.RWMutex
    data map[string]string
    aof  *os.File
}

func (s *KVStore) Set(k, v string) error { ... }
```

## 07.项目总结
- 学会"读写锁"在读多写少场景的优势
- 体会到 Redis 的 AOF 是怎么从一个 map 演化来的

## 08.技术思考
1. 为什么 RWMutex 在写多场景反而比 Mutex 慢？
2. AOF 写盘是同步还是异步？崩溃丢多少数据？
3. 如果 key 是 1 千万级别，重启加载 AOF 要多久？

## 09.延伸挑战
1. 加 RDB 快照机制（每 N 秒 dump 整张 map）
2. 加 TTL 过期支持
3. 把 AOF 重写策略实现（去重 / 压缩历史命令）
