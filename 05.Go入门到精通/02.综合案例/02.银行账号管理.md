## 01.需求说明
- 开户 / 销户 / 存款 / 取款 / 转账 / 查询余额 / 列出所有账户
- 退出时把账户数据 dump 到 `bank.json`，启动时加载

## 02.项目结构与 go.mod
```
02-bank/
├── go.mod
├── main.go         # CLI 主循环
├── account.go      # Account struct + 方法

```

## 07.项目总结
- 引入"仓储模式"分离数据访问与业务逻辑
- 学会用 `defer file.Close()` + `os.WriteFile` 做原子写

## 08.技术思考
1. 为什么转账要"先扣后加"还是"先加后扣"？崩溃中场会发生什么？
2. JSON 编解码时的字段大小写问题？
3. 多个进程同时写 `bank.json` 会怎样？

## 09.延伸挑战
1. 把 JSON 改成 CSV，对比两种格式的可读性 / 性能
2. 加上文件锁（`flock`）防多进程冲突
3. 把"先扣后加"改成 WAL（预写日志），崩溃后能重放
