
# 卷二 · 综合案例总导读

> 本卷是**卷一《语法卷》**的配套实战篇。学完卷一 18 章基础语法后，通过 12 个循序渐进的项目把散落的知识点串起来，形成"能独立写项目"的能力。其中 **12.MiniKVStore** 是"集大成的毕业设计"，一口气覆盖卷一 16 章。

---

## 01.定位与使用方式

本卷的每一篇都按**"照着写 · 抄得懂 · 改得动"**三个层次设计：

1. **照着写**：每个小节先给需求、再给代码片段，读者跟着键入即可跑通。
2. **抄得懂**：代码后必有"为什么这样写 / 关键机制原理"小节，回答"Go 为什么不能像 Python/Java 那样随手写"。
3. **改得动**：每篇结尾留 2-3 个"延伸挑战"，鼓励读者用新学的特性重构。

> **声明**：本卷代码风格以 **Go 1.22** 为基线，泛型（1.18+）、`slices`/`maps` 标准库（1.21+）默认就用；构建仅依赖官方工具链（`go build` / `go test` / `go vet`）；第三方库尽量选 `golang.org/x/...` 等极轻量。

### 5.2 代码风格

| 项目 | 约定 |
|------|------|
| 命名 | 类型 `PascalCase`、函数/变量 `camelCase`、未导出小写、常量 `UPPER_SNAKE` 或 `camelCase` |
| 包名 | 全小写，不用下划线，不复数；与目录同名 |
| 错误返回 | `if err != nil { return ..., fmt.Errorf("xxx: %w", err) }` 三段式 |
| `panic` 使用 | 仅用于"程序员错误"（断言不变量），不能用作业务错误 |
| 接收者 | 大对象 / 需修改 → 指针；小值类型（time、坐标）→ 值 |
| 上下文传递 | 第一个参数 `ctx context.Context`，绝不存到 struct |
| 内存 | 优先 slice / map 内置类型；只有热点路径才 `sync.Pool` |
| 标准 | 基线 Go 1.22；用到 1.23+ 特性会标注 `🆕 Go 1.23` |
| 测试 | 表驱动 + 子测试（`t.Run`）；目录同名 `xxx_test.go` |

## 06.常见疑问 FAQ

**Q1：为什么 01 通讯录用 `map[string]Student`，不用 ORM 数据库？**

A：本卷前 4 个案例的目的是"练熟语法"，不是"练熟工具链"。引入数据库 / ORM 会让初学者陷入"环境配置 4 小时、写代码 1 小时"的常见困境。等到第 12 案例 MiniKVStore，我们会**自己手写一个 KV 存储**，亲眼看到 etcd / Redis 是怎么从一个 map 演化来的。

**Q2：为什么 03 职工管理用接口多态，不用嵌入字段？**

A：03 的主题就是接口——通过同一个 `Worker` 接口，让员工 / 经理 / 老板的 `ShowInfo()` 各不相同。Go 的"多态"只有接口这一条路，本案例就是要让你彻底理解"接口隐式实现 + 接口值的两个指针"这件事。嵌入字段（"组合优于继承"）会在第 06 案例机房预约里作为"代码复用"工具用到。

**Q3：并发三连（07/08/09）之间是什么关系？**

A：
- **07 票务**：goroutine 最基础——几个 `go func` + 一把 `sync.Mutex`，看到"为什么并发不安全"。
- **08 轮训**：单线程 `time.Ticker` + 策略模式，看到"`func` 类型 + 接口"的威力。
- **09 协程池**：前两者的融合——多 goroutine + 任务 channel + `context` 取消，把 07 的裸 `go` 升级为工程级组件。

**Q4：10 和 11 和前 9 个有什么不同？**

A：前 9 个是"业务模拟"（能跑就行）；10 和 11 是"工具型"（为别的项目服务），更贴近真实工程师在做的事——**写一个工具给别人用**。这也是"从学习者到工程师"的最后一跃。10 用反射写测试 runner，11 用反射写 JSON 编解码——把卷一第 8、11、16、18 章的"高级特性"全用上。

**Q5：12 MiniKVStore 和前面 11 个的关系？**

A：前 11 个每篇只覆盖卷一 2-3 章，是"专题练习"；**12 是毕业设计**——一个项目把卷一 16 章串起来。它不是"加难度"，而是"换视角"：从"练单点"切到"做系统"。

12 案例的设计：

```
迭代 1（MVP）：单机内存 KV，纯 map，CLI 交互             → 串第 5、7、9 章
迭代 2（持久化）：AOF + JSON 编码，崩溃恢复               → 串第 11、15 章
迭代 3（命令模式）：解析协议，分发命令                    → 串第 10、16 章
迭代 4（并发安全）：RWMutex + sync.Pool                  → 串第 14 章
迭代 5（网络服务）：TCP server + bufio + context        → 串第 12、13、15 章
迭代 6（副本与一致性）：raft 简化版（不必生产可用）        → 串第 12-14 章
```

预计用 5 次（每次 1.5-2 小时）读完，分别对应迭代 1 / 2 / 3 / 4-5 / 6。建议把它放到学完前 11 个之后再做——前面的零件你都熟悉了，回头看 12 时会有"原来如此"的爽感。
