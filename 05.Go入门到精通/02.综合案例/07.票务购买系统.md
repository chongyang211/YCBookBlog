## 01.需求说明
- 100 个买家同时抢 50 张票
- 每个买家只能抢 1 张，超额不允许
- 全过程结构化日志输出，崩溃可追溯

## 03.第一版（占位）
```go
type TicketPool struct {
    remaining int
}

func (p *TicketPool) Buy(buyerID int) bool {
    if p.remaining > 0 {  // ❌ TOCTOU 竞态
        p.remaining--
        return true
    }
    return false
}
```

> **本案例完整代码、race detector 输出解读、Mutex 与原子计数对比将在卷二定稿阶段补全。**

## 07.项目总结
- 亲眼看到"竞态条件"如何把 50 张票卖成 200 张
- 学会 `go run -race` 检测竞态
- 学会 `slog` 替代 `log` 包

## 08.技术思考
1. 如果用 `atomic.Int32` 替代 Mutex，性能差多少？
2. 如果引入"购票前 5 秒锁定"机制，怎么实现？
3. 真实票务系统是怎么做防超卖的？（数据库行锁 / Redis 原子操作）

## 09.延伸挑战
