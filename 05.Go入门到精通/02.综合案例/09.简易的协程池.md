## 01.需求说明
- 固定 N 个 worker goroutine
- 任务通过 `Submit(fn)` 提交，返回 `Future`
- `Future.Wait()` 等待结果
- `Pool.Shutdown(ctx)` 优雅关闭

## 03.Pool 类型设计（占位）
```go
type Pool struct {
    tasks chan task
    wg    sync.WaitGroup
    once  sync.Once
    quit  chan struct{}
}

type task struct {
    fn     func() (any, error)
    result chan<- result
}
```

> **本案例完整代码、双队列设计、优雅停止细节将在卷二定稿阶段补全。**

## 08.项目总结
- 学会用 channel 实现工作队列
- 学会 `sync.Once` 保证只关闭一次
- 学会 benchmark 测试

## 09.技术思考
1. 任务队列满了应该阻塞还是丢弃？两种策略对比
2. 一个 worker panic 应该重启还是终止整个池？
3. 与第三方库（`ants` / `tunny`）对比

## 10.延伸挑战
1. 加任务优先级队列（多 channel）
2. 加任务超时支持（`context.WithTimeout` 封进 task）
3. 实现"一致性 hash 分配"让相同 key 的任务走同一 worker
