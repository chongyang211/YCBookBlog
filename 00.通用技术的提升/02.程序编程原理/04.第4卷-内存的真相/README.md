# 第 4 卷｜内存的真相

> **从内存模型到垃圾回收**——理解程序运行的物理基础。

---

## 🎯 这一卷要回答什么

内存是程序员永远绕不开的话题。OOM、内存泄漏、Full GC、栈溢出——你也许都见过，但能回答下面这些"为什么"吗？

- **为什么 Java/Go/Python 都有 GC，但实现完全不同？** 三色标记、分代、ZGC、Tracing、引用计数究竟在权衡什么？
- **栈和堆**——这两个名字几乎每个程序员都用过，但它们在 OS 层面真的是"两个独立的物理区域"吗？
- **强引用 / 软引用 / 弱引用 / 虚引用**——为什么需要四种？没有的语言（如 Rust）是怎么应对的？
- **深拷贝 vs 浅拷贝 vs Copy-on-Write**——为什么 Linux 的 fork 用 COW？这个思想还能用在哪里？
- **JMM、C++ MM、Go MM**——为什么三个语言要各自定义一套"内存模型"？它们冲突还是兼容？

第 4 卷不只讲 GC 算法，**它讲"程序的物理基础如何决定语言的设计"**。

```mermaid
flowchart LR
    A[31 内存模型<br/>硬件 → 语言抽象] --> B[32 堆栈<br/>分配的两套机制]
```

**内存模型决定怎么"读 / 写"，堆栈决定怎么"分配"，GC 决定怎么"回收"，引用决定怎么"持有"，拷贝决定怎么"复制"**——五个动作覆盖了内存生命周期的全部命题。
