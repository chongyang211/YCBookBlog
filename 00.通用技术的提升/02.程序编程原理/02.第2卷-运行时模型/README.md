# 第 2 卷｜运行时模型

> **从类到对象，从加载到访问**——程序运行时究竟发生了什么？

---

## 🎯 这一卷要回答什么

写了多年代码，你真的理解下面这些"日常动作"吗？

- 一行 `new User()`，从字节码到内存中的对象，CPU 究竟做了多少事？
- `obj.method()` 这句调用，编译期和运行时谁来决定该调谁？为什么 C++ 要 vtable，Java 要 itable？
- `class.getDeclaredField("x").set(obj, 1)`，反射看似"魔法"，背后是不是真的违反了访问控制？
- 双亲委派为什么是双亲？打破它会发生什么？热修复、Tomcat 隔离、模块化为什么都跟它有关？

第 2 卷把"运行时"从黑盒拆开，让你能在脑中**画出 new 对象的每一帧 CPU 状态**。

## 🔗 知识脉络

```mermaid
flowchart LR
    A[07 类加载<br/>磁盘字节码 → 方法区] --> B[08 对象创建<br/>方法区 → 堆对象]
    B --> C[09 对象访问<br/>堆对象 → 方法调用]
    C --> D[10 反射<br/>运行时操作类元数据]
    D -.闭环.-> A
```

**类加载是"准备"，对象创建是"诞生"，方法访问是"行动"，反射是"在运行时回头改写自己"**——这是一个对象从无到有再到自我修改的全过程。
