# Set 实际应用与设计原理

> 本篇深入剖析 Set 家族中核心实现——HashSet、LinkedHashSet、TreeSet、CopyOnWriteArraySet、EnumSet 以及并发 Set 的设计思想、核心原理及实际应用场景，带你由浅入深理解每种 Set 背后的工程取舍。


## 01. 从需求出发：集合的本质

### 1.1 数学中的集合

集合（Set）是数学中最基础的概念之一——**一组不重复元素的无序集**。它支持三个核心操作：

```
判断元素是否属于集合：x ∈ S ?        → contains(x)
将元素加入集合：      S = S ∪ {x}    → add(x)
从集合中移除元素：    S = S \ {x}    → remove(x)
```

以及集合间的运算：

```
并集：A ∪ B  → 所有属于A或属于B的元素
交集：A ∩ B  → 同时属于A和B的元素
差集：A \ B  → 属于A但不属于B的元素
对称差：A △ B → 属于A或属于B，但不同时属于两者
```

### 1.2 为什么需要多种 Set？

```
场景A：用户ID去重 → 只需要快速判断"有没有" → HashSet
场景B：去重且保持插入顺序 → LinkedHashSet
场景C：有序集合（如排行榜过滤）→ TreeSet
场景D：多线程环境下的去重 → ConcurrentHashMap.newKeySet()
场景E：枚举值的组合（权限位标记）→ EnumSet
```

### 1.3 Set 家族全景图

```

                        Set

       ┌─────────────────┼──────────────────┐

  AbstractSet        SortedSet          «interface»

```


## 02. HashSet：HashMap 的优雅委托

### 2.1 核心设计：一行代码的奥秘

HashSet 的全部秘密就在它的内部实现——**它就是一个只用 key 的 HashMap**：

```java
public class HashSet<E> extends AbstractSet<E> implements Set<E> {
    
    // 底层就是一个 HashMap
    private transient HashMap<E,Object> map;
    
    // 所有 value 共享这一个对象（占位符）
    private static final Object PRESENT = new Object();
    
    public HashSet() {
        map = new HashMap<>();
    }
    
    public boolean add(E e) {
        return map.put(e, PRESENT) == null;  // 如果key不存在，put返回null
    }
    
    public boolean remove(Object o) {
        return map.remove(o) == PRESENT;
    }
    
    public boolean contains(Object o) {
        return map.containsKey(o);
    }
    
    public int size() {
        return map.size();
    }
}
```

**设计思想：委托模式**

```
"不要重复发明轮子。"

HashMap 已经实现了：
  - 高效的哈希定位 → O(1)
  - 完善的冲突解决 → 链表 + 红黑树
  - 动态扩容 → 均摊 O(1)
  - 扰动函数 → 减少碰撞

HashSet 只需要一层薄薄的委托，就获得了 HashMap 的全部能力。
代价是每个元素多了一个 PRESENT 引用（8字节），但换来了：
  - 零重复代码
  - 自动获得 HashMap 的所有优化（如红黑树升级）
  - 维护成本为零
```

### 2.2 PRESENT 的精妙

```java
private static final Object PRESENT = new Object();
```

为什么不用 `null` 作为 value？

```java
// 如果用 null：
map.put("key1", null);   // 返回 null（key1是新插入的）
map.put("key1", null);   // 返回 null（key1已存在，旧value就是null）

// 无法区分"新插入"还是"已存在"！
// add() 方法需要这个区分来返回 true/false

// 用 PRESENT：
map.put("key1", PRESENT);  // 返回 null → add 返回 true（新插入）
map.put("key1", PRESENT);  // 返回 PRESENT → add 返回 false（已存在）
```

**PRESENT 是 static final**：所有 HashSet 实例的所有元素共享同一个 PRESENT 对象，内存开销仅一个对象（16字节对象头 + 0字节内容）。每个 Entry 中的 value 引用（8字节）指向它。

### 2.3 hashCode 与 equals 契约

HashSet 能正确工作的前提是元素正确实现了 `hashCode()` 和 `equals()`：

```java
// 契约规则：
// 1. a.equals(b) == true → a.hashCode() == b.hashCode()（必须）
// 2. a.hashCode() == b.hashCode() → a.equals(b) 不一定（允许碰撞）
// 3. a.equals(b) == false → hashCode 可以相同也可以不同

// 违反契约的后果：
class BadKey {
    int id;
    String name;
    
    @Override
    public boolean equals(Object o) {
        return this.id == ((BadKey) o).id;  // 只比较id
    }
    
    // 忘记重写 hashCode！使用默认的 Object.hashCode()（内存地址）
}

HashSet<BadKey> set = new HashSet<>();
BadKey k1 = new BadKey(1, "Alice");
BadKey k2 = new BadKey(1, "Alice");

set.add(k1);
set.contains(k2);  // false！k1 和 k2 的 hashCode 不同 → 定位到不同的桶 → 找不到
set.add(k2);
set.size();         // 2！应该是1，但因为 hashCode 不同，被当作不同元素
```

**正确的实现**：

```java
class GoodKey {
    int id;
    String name;
    
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        GoodKey that = (GoodKey) o;
        return id == that.id && Objects.equals(name, that.name);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(id, name);  // 与 equals 使用相同的字段
    }
}
```

### 2.4 实际应用

```java
// 场景1：数据去重
List<String> listWithDuplicates = Arrays.asList("a", "b", "a", "c", "b");
Set<String> unique = new HashSet<>(listWithDuplicates);
// unique = {"a", "b", "c"}  注意：顺序不确定！

// 场景2：快速成员检测
Set<String> blacklist = new HashSet<>(loadBlacklist());
if (blacklist.contains(userId)) {
    reject();
}

// 场景3：集合运算
Set<String> setA = new HashSet<>(Arrays.asList("a", "b", "c", "d"));
Set<String> setB = new HashSet<>(Arrays.asList("c", "d", "e", "f"));

// 交集
Set<String> intersection = new HashSet<>(setA);
intersection.retainAll(setB);  // {"c", "d"}

// 并集
Set<String> union = new HashSet<>(setA);
union.addAll(setB);            // {"a", "b", "c", "d", "e", "f"}

// 差集
Set<String> difference = new HashSet<>(setA);
difference.removeAll(setB);    // {"a", "b"}
```


## 03. LinkedHashSet：有序的 HashSet

### 3.1 实现原理

LinkedHashSet 继承自 HashSet，底层使用 LinkedHashMap：

```java
public class LinkedHashSet<E> extends HashSet<E> {
    
    // 构造器调用 HashSet 的特殊构造器（包内可见）
    public LinkedHashSet() {
        super(16, .75f, true);  // 第三个参数 true 表示使用 LinkedHashMap
    }
}

// HashSet 中对应的构造器：
HashSet(int initialCapacity, float loadFactor, boolean dummy) {
    map = new LinkedHashMap<>(initialCapacity, loadFactor);
}
```

**只要构造器传入 LinkedHashMap，就自动获得了插入顺序的维护能力。**

### 3.2 与 HashSet 的对比

```java
// HashSet：遍历顺序不可预测
Set<String> hashSet = new HashSet<>();
hashSet.add("banana");
hashSet.add("apple");
hashSet.add("cherry");
for (String s : hashSet) System.out.print(s + " ");
// 可能输出：apple cherry banana（取决于hash值）

// LinkedHashSet：保持插入顺序
Set<String> linkedSet = new LinkedHashSet<>();
linkedSet.add("banana");
linkedSet.add("apple");
linkedSet.add("cherry");
for (String s : linkedSet) System.out.print(s + " ");
// 一定输出：banana apple cherry ✓
```

| 维度 | HashSet | LinkedHashSet |
|------|---------|---------------|
| 底层 | HashMap | LinkedHashMap |
| 插入顺序 | 不保证 | 保持 |
| 内存 | 较少 | 每个节点多 before/after 指针（+16字节） |
| 插入性能 | 略快 | 略慢（维护链表） |
| 遍历性能 | 较慢（遍历桶数组，可能有空桶） | 较快（沿链表遍历，无空桶跳过） |

### 3.3 实际应用

```java
// 场景1：去重且保持顺序
List<String> input = Arrays.asList("c", "a", "b", "a", "c", "d");
List<String> uniqueOrdered = new ArrayList<>(new LinkedHashSet<>(input));
// ["c", "a", "b", "d"] — 去重且保持首次出现的顺序

// 场景2：有序的标签集合
LinkedHashSet<String> tags = new LinkedHashSet<>();
tags.add("Java");
tags.add("并发");
tags.add("集合");
// 输出到前端时保持用户添加的顺序

// 场景3：JSON 序列化字段顺序
// 很多 JSON 库使用 LinkedHashSet/LinkedHashMap 保持字段顺序
```


## 04. TreeSet：红黑树的有序 Set

### 4.1 核心设计

TreeSet 底层使用 TreeMap，和 HashSet 委托 HashMap 完全同构：

```java
public class TreeSet<E> extends AbstractSet<E> implements NavigableSet<E> {
    
    private transient NavigableMap<E,Object> m;
    private static final Object PRESENT = new Object();
    
    public TreeSet() {
        this(new TreeMap<E,Object>());
    }
    
    public boolean add(E e) {
        return m.put(e, PRESENT) == null;
    }
}
```

### 4.2 有序集合的独特操作

```java
TreeSet<Integer> scores = new TreeSet<>();
scores.addAll(Arrays.asList(78, 92, 85, 95, 88, 73, 99));

// 基本有序操作
scores.first();           // 73（最小值）
scores.last();            // 99（最大值）

// 邻近查询
scores.floor(90);         // 88（≤90 的最大值）
scores.ceiling(90);       // 92（≥90 的最小值）
scores.lower(88);         // 85（<88 的最大值）
scores.higher(88);        // 92（>88 的最小值）

// 范围查询
scores.subSet(80, 96);    // [85, 88, 92, 95]
scores.headSet(85);       // [73, 78]
scores.tailSet(90);       // [92, 95, 99]

// 弹出操作（像优先队列一样使用）
scores.pollFirst();       // 弹出并返回 73
scores.pollLast();        // 弹出并返回 99
```

### 4.3 自定义排序

```java
// 方式1：元素实现 Comparable
TreeSet<String> names = new TreeSet<>();  // 自然排序（字典序）

// 方式2：传入 Comparator
TreeSet<String> byLength = new TreeSet<>(Comparator.comparingInt(String::length));
byLength.addAll(Arrays.asList("apple", "hi", "banana", "ok"));
// 遍历：hi → ok → apple → banana（按长度排序）

// 方式3：复合排序（先按长度，长度相同按字典序）
TreeSet<String> complex = new TreeSet<>(
    Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder())
);
```

### 4.4 操作复杂度

| 操作 | HashSet | TreeSet |
|------|---------|--------|
| add | O(1) | O(log N) |
| remove | O(1) | O(log N) |
| contains | O(1) | O(log N) |
| first/last | N/A | O(log N) |
| floor/ceiling | N/A | O(log N) |
| 范围查询 | N/A | O(log N + K) |

### 4.5 实际应用

```java
// 场景1：维护有序的唯一值集合
TreeSet<LocalDate> holidays = new TreeSet<>();
holidays.add(LocalDate.of(2025, 1, 1));
holidays.add(LocalDate.of(2025, 5, 1));
holidays.add(LocalDate.of(2025, 10, 1));
// 自动按日期排序

// 查找下一个假日
LocalDate today = LocalDate.now();
LocalDate nextHoliday = holidays.ceiling(today);

// 场景2：区间判断
TreeSet<Integer> breakpoints = new TreeSet<>(Arrays.asList(0, 60, 70, 80, 90, 100));
int score = 85;
int level = breakpoints.floor(score);  // 80 → 对应"良好"

// 场景3：滑动窗口中的有序集合
// 如 LeetCode 220：存在重复元素III
// 维护窗口内的 TreeSet，用 floor/ceiling 快速查找相近元素
```


## 05. EnumSet：极致性能的位向量

### 5.1 设计思想

当 Set 的元素是枚举类型时，可以用**位向量**（bit vector）实现：每个枚举值对应一个 bit，1 表示存在，0 表示不存在。

```java
enum Permission { READ, WRITE, EXECUTE, DELETE, ADMIN }

// 内部表示（一个 long 就够了，最多支持 64 个枚举值）：
// READ=0, WRITE=1, EXECUTE=2, DELETE=3, ADMIN=4
// 
// 二进制：00000...00101
//                    ^^^
//                    │││
//         EXECUTE────┘│└──── READ
//                     └──── WRITE 不在集合中
```

```java
// 使用
EnumSet<Permission> userPerms = EnumSet.of(Permission.READ, Permission.WRITE);
EnumSet<Permission> adminPerms = EnumSet.allOf(Permission.class);
EnumSet<Permission> noPerms = EnumSet.noneOf(Permission.class);

// 集合运算（全部是位运算！）
userPerms.contains(Permission.READ);  // (bits & (1L << READ.ordinal())) != 0  → O(1)
userPerms.add(Permission.EXECUTE);    // bits |= (1L << EXECUTE.ordinal())     → O(1)
userPerms.remove(Permission.WRITE);   // bits &= ~(1L << WRITE.ordinal())      → O(1)

// 交集、并集、差集也是位运算
// 速度比 HashSet 快一个数量级
```

### 5.2 两种内部实现

```java
// JDK 内部根据枚举值数量自动选择：
public static <E extends Enum<E>> EnumSet<E> noneOf(Class<E> elementType) {
    Enum<?>[] universe = getUniverse(elementType);
    if (universe.length <= 64)
        return new RegularEnumSet<>(elementType, universe);   // 一个 long
    else
        return new JumboEnumSet<>(elementType, universe);      // long 数组
}

// RegularEnumSet：内部就一个 long elements;
// 所有操作都是一条位运算指令，性能极致

// JumboEnumSet：内部是 long[] elements;
// 超过64个枚举值时使用，仍然比 HashSet 高效得多
```

### 5.3 性能对比

```
存储 30 个枚举值的集合：

HashSet<Permission>:
  30 个 HashMap.Node 对象 ≈ 30 × 48B = 1440B
  + HashMap 底层数组 ≈ 64 × 8B = 512B
  总计 ≈ 2KB

EnumSet<Permission>:
  一个 long = 8B
  总计 = 8B

内存差距：250倍！
性能差距：contains 操作 HashSet 需要哈希计算+可能的链表遍历，
         EnumSet 只需一条 AND 指令，快 10-50 倍。
```

### 5.4 实际应用

```java
// 场景1：权限管理
EnumSet<Permission> permissions = EnumSet.of(Permission.READ, Permission.WRITE);
if (permissions.containsAll(EnumSet.of(Permission.READ, Permission.EXECUTE))) {
    // 权限检查
}

// 场景2：状态机的有效状态集合
enum State { INIT, RUNNING, PAUSED, STOPPED, ERROR }
EnumSet<State> activeStates = EnumSet.of(State.RUNNING, State.PAUSED);
if (activeStates.contains(currentState)) {
    // 处于活跃状态
}

// 场景3：星期几的选择（如重复闹钟）
EnumSet<DayOfWeek> workDays = EnumSet.range(DayOfWeek.MONDAY, DayOfWeek.FRIDAY);
EnumSet<DayOfWeek> weekends = EnumSet.complementOf(workDays);  // 补集
```


## 06. 并发 Set 实现

### 6.1 ConcurrentHashMap.newKeySet()

```java
// JDK 8+ 推荐的并发 Set
Set<String> concurrentSet = ConcurrentHashMap.newKeySet();

// 或者从已有 ConcurrentHashMap 获取
ConcurrentHashMap<String, Boolean> map = new ConcurrentHashMap<>();
Set<String> keySet = map.keySet(Boolean.TRUE);  // 可以 add 的 keySet 视图
```

内部实现就是 ConcurrentHashMap 的 key 集合，具有 ConcurrentHashMap 的全部并发性能。

### 6.2 CopyOnWriteArraySet

```java
// CopyOnWriteArraySet 底层使用 CopyOnWriteArrayList
public class CopyOnWriteArraySet<E> extends AbstractSet<E> {
    private final CopyOnWriteArrayList<E> al;
    
    public boolean add(E e) {
        return al.addIfAbsent(e);  // 遍历检查是否已存在
    }
    
    public boolean contains(Object o) {
        return al.contains(o);  // 遍历查找 → O(N)！
    }
}
```

**注意**：CopyOnWriteArraySet 的 `contains` 是 O(N) 的！因为底层是数组遍历。只适合**极小数据量（< 100）且读远多于写**的场景。

### 6.3 ConcurrentSkipListSet

```java
// 基于跳表的并发有序 Set
ConcurrentSkipListSet<Integer> sortedSet = new ConcurrentSkipListSet<>();
sortedSet.addAll(Arrays.asList(5, 3, 8, 1, 9));
sortedSet.first();  // 1
sortedSet.last();   // 9
// 线程安全 + 有序 + O(log N)
```

### 6.4 并发 Set 选型

| 实现 | 有序 | contains | add | 适用场景 |
|------|------|----------|-----|---------|
| ConcurrentHashMap.newKeySet() | 否 | O(1) | O(1) | 通用高并发去重 |
| CopyOnWriteArraySet | 否 | O(N) | O(N) | 极小集合，读多写少 |
| ConcurrentSkipListSet | 是 | O(log N) | O(log N) | 需要有序的并发场景 |
| Collections.synchronizedSet | 否 | O(1) | O(1) | 简单场景 |


## 07. 全面对比与选型指南

### 7.1 核心对比

| 维度 | HashSet | LinkedHashSet | TreeSet | EnumSet | COWArraySet |
|------|---------|---------------|---------|---------|-------------|
| 底层 | HashMap | LinkedHashMap | TreeMap | 位向量 | COWArrayList |
| 有序性 | 无 | 插入序 | 自然序 | 枚举序 | 插入序 |
| add | O(1) | O(1) | O(log N) | O(1) 位运算 | O(N) |
| contains | O(1) | O(1) | O(log N) | O(1) 位运算 | O(N) |
| 内存 | 中等 | 较高 | 较高 | **极低** | 低 |
| null | 允许 | 允许 | 不允许 | 不允许 | 允许 |
| 线程安全 | 否 | 否 | 否 | 否 | 是 |

### 7.2 选型决策树

```
你的元素类型是什么？
  │
  ├── 枚举类型
  │     └── EnumSet ✅（无脑选，性能碾压一切）
  │
  ├── 需要按元素排序？
  │     ├── 是 + 单线程 → TreeSet
  │     └── 是 + 多线程 → ConcurrentSkipListSet
  │
  ├── 需要保持插入顺序？
  │     └── 是 → LinkedHashSet
  │
  ├── 需要线程安全？
  │     ├── 大数据量 → ConcurrentHashMap.newKeySet() ✅
  │     └── 小数据量 + 读多写少 → CopyOnWriteArraySet
  │
  └── 通用场景
        └── HashSet ✅
```

### 7.3 跨语言 Set 实现对比

| 语言 | 无序Set | 有序Set | 并发Set | 特殊Set |
|------|---------|---------|---------|--------|
| Java | HashSet | TreeSet | ConcurrentHashMap.newKeySet() | EnumSet, LinkedHashSet |
| Go | map[T]struct{} | 无内置 | sync.Map 包装 | 无 |
| Python | set | 无内置(SortedSet) | 无内置 | frozenset(不可变) |
| Rust | HashSet | BTreeSet | 无内置(dashmap) | 无 |
| C++ | unordered_set | set(红黑树) | 无内置(tbb) | bitset |
| Swift | Set | 无内置 | 需加锁 | OptionSet(位掩码) |
| JavaScript | Set | 无内置 | N/A | WeakSet |
| Kotlin | HashSet | TreeSet | ConcurrentHashMap.newKeySet() | enumSetOf |

**Go 的惯用法**：Go 没有内置 Set 类型，惯用 `map[string]struct{}` 模拟。`struct{}` 大小为 0，不占额外内存：

```go
// Go 的 Set 惯用法
visited := make(map[string]struct{})
visited["url1"] = struct{}{}

if _, ok := visited["url1"]; ok {
    // 已访问
}
```

**Python 的 frozenset**：不可变集合，可以作为字典的 key 或其他集合的元素：

```python
# frozenset 是 hashable 的
s = frozenset([1, 2, 3])
d = {s: "value"}  # frozenset 可以当 dict 的 key
```


## 08. 高级话题

### 8.1 不可变 Set（JDK 9+）

```java
// JDK 9 引入的工厂方法
Set<String> immutable = Set.of("a", "b", "c");
immutable.add("d");  // 抛出 UnsupportedOperationException

// 特点：
// 1. 不允许 null 元素
// 2. 不允许重复元素（重复会抛异常）
// 3. 遍历顺序在每次 JVM 启动时随机化（防止依赖顺序的 bug）
// 4. 内部有针对 0-2 个元素的特殊实现，极致省内存
```

### 8.2 Guava 的高级 Set 工具

```java
// Sets 工具类（Google Guava）
Set<String> a = Set.of("1", "2", "3", "4");
Set<String> b = Set.of("3", "4", "5", "6");

Sets.intersection(a, b);   // 视图：{"3", "4"}  不复制数据
Sets.union(a, b);           // 视图：{"1","2","3","4","5","6"}
Sets.difference(a, b);      // 视图：{"1", "2"}
Sets.symmetricDifference(a, b);  // 视图：{"1", "2", "5", "6"}

// 笛卡尔积
Set<List<String>> cartesian = Sets.cartesianProduct(a, b);

// PowerSet（幂集）
Set<Set<String>> powerSet = Sets.powerSet(Set.of("a", "b", "c"));
// {{}, {a}, {b}, {c}, {a,b}, {a,c}, {b,c}, {a,b,c}}
```

### 8.3 BitSet：超大规模去重

当需要对海量整数去重时，HashSet 的内存开销太大。BitSet 用一个 bit 表示一个数字的存在性：

```java
// 10亿个整数去重
BitSet bitSet = new BitSet(1_000_000_000);

// 标记数字存在
bitSet.set(12345);
bitSet.set(67890);

// 检查是否存在
bitSet.get(12345);  // true

// 内存：10亿 bit = 125MB
// 如果用 HashSet<Integer>：10亿 × ~48B = 48GB！
```
