### 01.红黑树的由来与设计

#### 1.1 疑惑：为什么AVL树还不够

上一篇我们学习了AVL树，它通过严格的平衡条件（平衡因子 ≤ 1）保证了O(log N)的查找性能。但AVL树有一个严重的问题：

**插入和删除时旋转太频繁**。

| 场景 | AVL树 | 影响 |
|------|-------|------|
| 插入 | 最多1次旋转 | 可以接受 |
| 删除 | 可能O(log N)次旋转 | 代价高昂 |
| 频繁修改 | 旋转开销累积 | 整体性能下降 |

在实际工程中，很多场景（如HashMap的冲突链表、进程调度、定时器管理）需要频繁的插入和删除。AVL树在这些场景中的旋转开销是不可接受的。

**核心矛盾**：AVL追求的是"完美平衡"，但完美的代价是高昂的维护成本。

#### 1.2 从BST到AVL再到红黑树的演变

```
BST（1960s前）
  ↓ 问题：可能退化为链表 O(N)
AVL树（1962）
  ↓ 问题：删除时旋转次数多 O(log N)次旋转
  ↓ 问题：维护平衡因子开销大
红黑树（1972-1978）
  ↓ 解决：放宽平衡条件，最多3次旋转
  ↓ 成为工业级标准方案
```

**技术演变的核心逻辑**：从"追求完美"到"追求足够好"。红黑树不要求严格平衡，只要求"大致平衡"——最长路径不超过最短路径的2倍。这个"不完美"的妥协换来了更低的维护成本。

#### 1.3 红黑树的发明历程

红黑树的前身是**对称二叉B树（Symmetric Binary B-tree）**，由Rudolf Bayer在1972年提出。1978年，Leo Guibas和Robert Sedgewick在此基础上引入了红黑着色方案，正式命名为"红黑树（Red-Black Tree）"。

有趣的是，Sedgewick教授后来回忆说，选择"红"和"黑"是因为当时他们使用的激光打印机能打印出漂亮的红色和黑色。

#### 1.4 红黑树的核心思想

**一句话概括**：通过给节点染色（红/黑），并维护一组颜色约束，保证树的高度不超过 2·log₂(N+1)。

**与AVL树的本质区别**：
- AVL树通过**数值**（平衡因子）控制平衡
- 红黑树通过**颜色约束**控制平衡

颜色约束比数值约束更宽松，因此红黑树允许一定程度的不平衡，换取了更少的旋转操作。


### 02.红黑树的五大性质

#### 2.1 五大性质详解

红黑树的每个节点带有一个颜色属性（红或黑），并且满足以下五条性质：

| 编号 | 性质 | 说明 |
|------|------|------|
| 1 | 每个节点是红色或黑色 | 颜色只有两种 |
| 2 | 根节点是黑色 | 根必须黑 |
| 3 | 每个叶子节点（NIL）是黑色 | NIL是哨兵节点 |
| 4 | 红色节点的子节点必须是黑色 | 不能有连续的红色节点 |
| 5 | 从任意节点到其所有后代叶子的路径上，黑色节点数量相同 | **最核心的性质** |

```
一棵合法的红黑树：

           B:13
          /     \
       R:8      R:17
       / \       / \
     B:1  B:11 B:15  B:25
      \          \    / \
      R:6      R:16 R:22 R:27

B = Black, R = Red
每条从根到NIL的路径上都有3个黑色节点（黑高=3）
```

#### 2.2 疑惑：为什么是这五条性质

**性质4（不能连续红色）和性质5（黑高相同）是核心**，其他三条是辅助。

**论证**——为什么这两条性质能保证"大致平衡"：

假设黑高为 h（从根到叶子的黑色节点数）。

- **最短路径**：全是黑色节点，长度 = h
- **最长路径**：红黑交替排列，长度 = 2h（因为性质4不允许连续红色，最多红黑交替）

因此：**最长路径 ≤ 2 × 最短路径**

这意味着红黑树不会像BST那样退化为链表，也不需要像AVL那样严格平衡。

#### 2.3 黑高（Black Height）的概念

**黑高**：从某个节点出发（不含该节点本身），到达任意叶子节点（NIL）路径上的黑色节点数。

由性质5可知，一个节点的黑高是唯一确定的（所有路径上黑色节点数相同）。

```
           B:13 (黑高=3)
          /     \
       R:8       R:17 (黑高=2)
       / \
     B:1  B:11 (黑高=1)
```

#### 2.4 红黑树的高度证明

**定理**：含有 N 个内部节点的红黑树的高度 h ≤ 2·log₂(N+1)

**证明**：
1. 以某节点 x 为根的子树至少包含 2^(bh(x)) - 1 个内部节点（数学归纳法可证）
2. 由性质4，从根到叶子的路径上，黑色节点至少占一半，即 bh(root) ≥ h/2
3. N ≥ 2^(h/2) - 1
4. h ≤ 2·log₂(N+1)

**结果**：查找、插入、删除的时间复杂度都是 O(log N)。

#### 2.5 红黑树与2-3-4树的等价关系

红黑树实际上是2-3-4树（一种B树）的二叉表示。理解这个等价关系能帮助理解红黑树的本质。

**2-3-4树**：每个节点可以有2、3或4个子节点。

**等价转换规则**：
- 黑色节点 = 2-节点
- 黑色节点+一个红色子节点 = 3-节点
- 黑色节点+两个红色子节点 = 4-节点

```
2-3-4树节点：         红黑树表示：

  [B]                    B
 / \                    / \
                      

  [A|B]                  B           或        A
  / | \                 / \                   / \
                      A                          B
                     / \                        / \
                    (红色A是B的左子节点)    (红色B是A的右子节点)

  [A|B|C]                B
  / | | \              /   \
                     A(红)  C(红)
                    / \    / \
```

**这个等价关系的意义**：
1. 红黑树的插入修复本质上是2-3-4树节点的分裂
2. 红黑树的删除修复本质上是2-3-4树节点的合并和借用
3. 理解了2-3-4树就理解了红黑树的全部操作


### 03.红黑树的旋转操作

#### 3.1 左旋操作详解

左旋是以某个节点为**支点**，将它**旋转到左子节点位置**，其右子节点上升为父节点。

```
左旋节点X：

     X                    Y
    / \                  / \
   α   Y       →       X   γ
      / \              / \
     β   γ            α   β
```

**关键步骤**：
1. Y的左子树β变为X的右子树
2. X变为Y的左子节点
3. Y取代X原来的位置

```python
def left_rotate(self, x):
    y = x.right           # y是x的右子节点
    x.right = y.left      # β变为x的右子树
    if y.left != self.NIL:
        y.left.parent = x
    y.parent = x.parent   # y取代x的位置
    if x.parent is None:
        self.root = y
    elif x == x.parent.left:
        x.parent.left = y
    else:
        x.parent.right = y
    y.left = x            # x成为y的左子节点
    x.parent = y
```

#### 3.2 右旋操作详解

右旋是左旋的镜像操作。

```
右旋节点Y：

       Y                  X
      / \                / \
     X   γ      →      α   Y
    / \                    / \
   α   β                 β   γ
```

```python
def right_rotate(self, y):
    x = y.left
    y.left = x.right
    if x.right != self.NIL:
        x.right.parent = y
    x.parent = y.parent
    if y.parent is None:
        self.root = x
    elif y == y.parent.right:
        y.parent.right = x
    else:
        y.parent.left = x
    x.right = y
    y.parent = x
```

#### 3.3 旋转的本质：重新分配平衡

**旋转不改变BST的有序性**（中序遍历结果不变），只是改变了树的形状，使其更接近平衡。

左旋和右旋是一对互逆操作：对X左旋后再对Y右旋，回到原来的结构。

旋转的时间复杂度是O(1)——只修改了几个指针。


### 04.红黑树的插入操作

#### 4.1 插入的基本策略

1. 按BST的规则找到插入位置
2. 新节点染为**红色**
3. 如果违反了红黑树性质，进行修复（变色+旋转）

#### 4.2 疑惑：为什么新节点染红色

**答疑**：新节点染红色只可能违反性质4（不能连续红色），而不会违反性质5（黑高相同）。

如果染黑色，则必然违反性质5——增加了某条路径上的黑色节点数，所有路径都会受影响，修复代价极高。

而违反性质4只是局部问题，可以通过局部的变色和旋转修复。

```
选择红色：可能违反性质4（局部问题，易修复）
选择黑色：必然违反性质5（全局问题，难修复）
```

#### 4.3 插入的三种修复情况

设新插入节点为N，父节点为P，祖父节点为G，叔叔节点为U。

**前提条件**：N是红色，P也是红色（违反了性质4）。

---

**情况1：叔叔U是红色** —— 变色上溯

```
修复前：              修复后：
      G(B)                G(R) ← 变红，继续向上检查
     / \                 / \
   P(R)  U(R)         P(B)  U(B) ← 变黑
   /                   /
  N(R)               N(R)
```

操作：P和U变黑，G变红，然后以G为新的N继续向上检查。

**本质**（2-3-4树视角）：4-节点满了，需要分裂——中间元素（G）上提。

---

**情况2：叔叔U是黑色，N是P的同侧子节点** —— 一次旋转+变色

```
N是P的左子节点，P是G的左子节点（LL型）：

修复前：              修复后：
      G(B)                P(B)
     / \                 / \
   P(R)  U(B)         N(R)  G(R)
   /                          \
  N(R)                        U(B)
```

操作：P变黑，G变红，对G右旋。

---

**情况3：叔叔U是黑色，N是P的异侧子节点** —— 两次旋转+变色

```
N是P的右子节点，P是G的左子节点（LR型）：

修复前：              先对P左旋：          再对G右旋：
      G(B)                G(B)                N(B)
     / \                 / \                 / \
   P(R)  U(B)         N(R)  U(B)          P(R)  G(R)
     \                /                            \
     N(R)           P(R)                           U(B)
```

操作：先对P左旋（转化为情况2），再对G右旋+变色。

#### 4.4 插入修复的完整实现

```python
def insert_fixup(self, z):
    while z.parent and z.parent.color == RED:
        if z.parent == z.parent.parent.left:
            # 父节点是祖父的左子节点
            uncle = z.parent.parent.right
            
            if uncle.color == RED:
                # 情况1：叔叔是红色
                z.parent.color = BLACK
                uncle.color = BLACK
                z.parent.parent.color = RED
                z = z.parent.parent  # 上溯
            else:
                if z == z.parent.right:
                    # 情况3：N是右子节点（LR型），先左旋转化为情况2
                    z = z.parent
                    self.left_rotate(z)
                # 情况2：N是左子节点（LL型）
                z.parent.color = BLACK
                z.parent.parent.color = RED
                self.right_rotate(z.parent.parent)
        else:
            # 镜像情况：父节点是祖父的右子节点
            uncle = z.parent.parent.left
            
            if uncle.color == RED:
                z.parent.color = BLACK
                uncle.color = BLACK
                z.parent.parent.color = RED
                z = z.parent.parent
            else:
                if z == z.parent.left:
                    z = z.parent
                    self.right_rotate(z)
                z.parent.color = BLACK
                z.parent.parent.color = RED
                self.left_rotate(z.parent.parent)
    
    self.root.color = BLACK  # 保证根是黑色
```

**复杂度分析**：
- 情况1可能向上传播O(log N)次，但只做变色（O(1)每次）
- 情况2和情况3各只做1-2次旋转
- **总旋转次数最多2次**

### 05.红黑树的删除操作

#### 5.1 删除的基本策略

红黑树的删除是最复杂的操作。基本思路：

1. 按BST规则执行删除（找到替代节点）
2. 如果删除的节点是红色——直接删除，不影响红黑性质
3. 如果删除的节点是黑色——路径上少了一个黑色节点，违反性质5，需要修复

**关键洞察**：只有删除黑色节点时才需要修复。红色节点的删除不影响黑高。

#### 5.2 删除的四种修复情况

设被删除节点的替代者为X，X的兄弟节点为S，S的子节点为SL和SR。

**情况1：兄弟S是红色**

```
修复前：                  修复后（转化为情况2/3/4）：
     P(B)                      S(B)
    / \                       / \
  X(B) S(R)        →       P(R) SR(B)
       / \                 / \
     SL(B) SR(B)         X(B) SL(B)
```

操作：S变黑，P变红，对P左旋。此时X的新兄弟变为黑色，转化为情况2/3/4。

---

**情况2：兄弟S是黑色，且S的两个子节点都是黑色**

```
修复前：                修复后：
     P(?)                   P(?)  ← 颜色不变
    / \                    / \
  X(B) S(B)      →      X(B) S(R)  ← S变红
       / \                    / \
     SL(B) SR(B)           SL(B) SR(B)
```

操作：S变红。如果P是红色则P变黑（修复完成）；如果P是黑色则以P为新的X继续向上修复。

**本质**：S变红后，S那一侧也少了一个黑色节点，两边平衡了。但P所在子树整体少了一个黑色节点，可能需要继续向上修复。

---

**情况3：兄弟S是黑色，S的远侄子（SR）是黑色，近侄子（SL）是红色**

```
修复前：                修复后（转化为情况4）：
     P(?)                   P(?)
    / \                    / \
  X(B) S(B)      →      X(B) SL(B)
       / \                      \
     SL(R) SR(B)               S(R)
                                 \
                                SR(B)
```

操作：SL变黑，S变红，对S右旋。转化为情况4。

---

**情况4：兄弟S是黑色，S的远侄子（SR）是红色**

```
修复前：                修复后（修复完成）：
     P(?)                   S(P的颜色)
    / \                    / \
  X(B) S(B)      →      P(B)  SR(B)
       / \              / \
     SL(?) SR(R)      X(B) SL(?)
```

操作：S变为P的颜色，P变黑，SR变黑，对P左旋。**修复完成**。

这是唯一直接完成修复的情况。通过旋转"借用"了S那一侧的一个红色节点，填补了X这边缺失的黑色节点。

#### 5.3 删除修复的完整实现

```python
def delete_fixup(self, x):
    while x != self.root and x.color == BLACK:
        if x == x.parent.left:
            sibling = x.parent.right
            
            # 情况1：兄弟是红色
            if sibling.color == RED:
                sibling.color = BLACK
                x.parent.color = RED
                self.left_rotate(x.parent)
                sibling = x.parent.right
            
            # 情况2：兄弟的两个子节点都是黑色
            if sibling.left.color == BLACK and sibling.right.color == BLACK:
                sibling.color = RED
                x = x.parent
            else:
                # 情况3：兄弟的远侄子是黑色
                if sibling.right.color == BLACK:
                    sibling.left.color = BLACK
                    sibling.color = RED
                    self.right_rotate(sibling)
                    sibling = x.parent.right
                
                # 情况4：兄弟的远侄子是红色
                sibling.color = x.parent.color
                x.parent.color = BLACK
                sibling.right.color = BLACK
                self.left_rotate(x.parent)
                x = self.root  # 退出循环
        else:
            # 镜像情况
            sibling = x.parent.left
            if sibling.color == RED:
                sibling.color = BLACK
                x.parent.color = RED
                self.right_rotate(x.parent)
                sibling = x.parent.left
            if sibling.right.color == BLACK and sibling.left.color == BLACK:
                sibling.color = RED
                x = x.parent
            else:
                if sibling.left.color == BLACK:
                    sibling.right.color = BLACK
                    sibling.color = RED
                    self.left_rotate(sibling)
                    sibling = x.parent.left
                sibling.color = x.parent.color
                x.parent.color = BLACK
                sibling.left.color = BLACK
                self.right_rotate(x.parent)
                x = self.root
    
    x.color = BLACK
```

**复杂度分析**：
- 情况1转化为情况2/3/4，最多发生1次
- 情况2可能向上传播O(log N)次，但只做变色
- 情况3转化为情况4，最多发生1次
- 情况4直接完成，发生1次
- **总旋转次数最多3次**

### 06.红黑树的工业级应用

#### 6.1 Java TreeMap/TreeSet

Java的`TreeMap`和`TreeSet`底层就是红黑树：

```java
// TreeMap中的红黑树节点定义
static final class Entry<K,V> implements Map.Entry<K,V> {
    K key;
    V value;
    Entry<K,V> left;
    Entry<K,V> right;
    Entry<K,V> parent;
    boolean color = BLACK;
}
```

**TreeMap的特点**：
- 键有序（可以范围查询）
- 查找/插入/删除都是O(log N)
- 不允许null键（需要比较）

```java
TreeMap<String, Integer> map = new TreeMap<>();
map.put("banana", 2);
map.put("apple", 1);
map.put("cherry", 3);

// 有序遍历
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}
// 输出：apple: 1, banana: 2, cherry: 3（按键排序）

// 范围查询
SortedMap<String, Integer> sub = map.subMap("apple", "cherry");
```

#### 6.2 Linux内核CFS调度器

Linux的**完全公平调度器（Completely Fair Scheduler, CFS）** 使用红黑树管理进程：

- 每个进程有一个**虚拟运行时间（vruntime）**
- 红黑树按vruntime排序
- 每次调度选择vruntime最小的进程（红黑树最左节点）
- 新进程插入或进程运行后vruntime更新，在红黑树中调整位置

```
为什么CFS选择红黑树？
1. 需要频繁插入/删除（进程创建、销毁、状态变化）
2. 需要快速找到最小值（最左节点 O(log N)，可缓存到O(1)）
3. 红黑树的最坏情况性能有保证（实时性要求）
```

#### 6.3 C++ STL map/set

C++标准库的`std::map`、`std::set`、`std::multimap`、`std::multiset`都基于红黑树。

```cpp
#include <map>
#include <set>

std::map<std::string, int> m;
m["apple"] = 1;
m["banana"] = 2;

// 有序遍历
for (auto& [key, val] : m) {
    std::cout << key << ": " << val << std::endl;
}

// lower_bound / upper_bound 范围查询
auto it = m.lower_bound("banana");
```

#### 6.4 Nginx定时器管理

Nginx使用红黑树管理定时器事件：

- 每个定时器有一个超时时间
- 红黑树按超时时间排序
- 每次检查最左节点（最早超时的定时器）
- 定时器的增删改查都是O(log N)

#### 6.5 与其他平衡树的对比选择

| 数据结构 | 查找 | 插入 | 删除 | 旋转次数（最坏） | 典型应用 |
|---------|------|------|------|----------------|---------|
| AVL树 | O(log N) | O(log N) | O(log N) | O(log N) | 查找密集型 |
| 红黑树 | O(log N) | O(log N) | O(log N) | ≤ 3 | 通用场景 |
| B树 | O(log N) | O(log N) | O(log N) | - | 磁盘IO |
| 跳表 | O(log N) | O(log N) | O(log N) | 无旋转 | Redis有序集合 |

**选择建议**：
- 通用内存数据结构 → **红黑树**（Java TreeMap, C++ map）
- 查找远多于修改 → AVL树
- 磁盘存储/数据库索引 → B树/B+树
- 实现简单、支持并发 → 跳表（Skip List）


### 07.红黑树完整实现

#### 7.1 数据结构定义

```python
RED = True
BLACK = False

class RBNode:
    def __init__(self, key, color=RED):
        self.key = key
        self.color = color
        self.left = None
        self.right = None
        self.parent = None

class RedBlackTree:
    def __init__(self):
        self.NIL = RBNode(key=None, color=BLACK)  # 哨兵节点
        self.root = self.NIL
```

#### 7.2 完整代码实现

```python
class RedBlackTree:
    def __init__(self):
        self.NIL = RBNode(key=None, color=BLACK)
        self.root = self.NIL
    
    def insert(self, key):
        node = RBNode(key)
        node.left = self.NIL
        node.right = self.NIL
        
        # BST插入
        parent = None
        current = self.root
        while current != self.NIL:
            parent = current
            if key < current.key:
                current = current.left
            elif key > current.key:
                current = current.right
            else:
                return  # 不允许重复
        
        node.parent = parent
        if parent is None:
            self.root = node
        elif key < parent.key:
            parent.left = node
        else:
            parent.right = node
        
        # 修复红黑性质
        self._insert_fixup(node)
    
    def _insert_fixup(self, z):
        while z.parent and z.parent.color == RED:
            if z.parent == z.parent.parent.left:
                uncle = z.parent.parent.right
                if uncle.color == RED:
                    z.parent.color = BLACK
                    uncle.color = BLACK
                    z.parent.parent.color = RED
                    z = z.parent.parent
                else:
                    if z == z.parent.right:
                        z = z.parent
                        self._left_rotate(z)
                    z.parent.color = BLACK
                    z.parent.parent.color = RED
                    self._right_rotate(z.parent.parent)
            else:
                uncle = z.parent.parent.left
                if uncle.color == RED:
                    z.parent.color = BLACK
                    uncle.color = BLACK
                    z.parent.parent.color = RED
                    z = z.parent.parent
                else:
                    if z == z.parent.left:
                        z = z.parent
                        self._right_rotate(z)
                    z.parent.color = BLACK
                    z.parent.parent.color = RED
                    self._left_rotate(z.parent.parent)
        self.root.color = BLACK
    
    def _left_rotate(self, x):
        y = x.right
        x.right = y.left
        if y.left != self.NIL:
            y.left.parent = x
        y.parent = x.parent
        if x.parent is None:
            self.root = y
        elif x == x.parent.left:
            x.parent.left = y
        else:
            x.parent.right = y
        y.left = x
        x.parent = y
    
    def _right_rotate(self, y):
        x = y.left
        y.left = x.right
        if x.right != self.NIL:
            x.right.parent = y
        x.parent = y.parent
        if y.parent is None:
            self.root = x
        elif y == y.parent.right:
            y.parent.right = x
        else:
            y.parent.left = x
        x.right = y
        y.parent = x
    
    def search(self, key):
        current = self.root
        while current != self.NIL:
            if key == current.key:
                return current
            elif key < current.key:
                current = current.left
            else:
                current = current.right
        return None
    
    def inorder(self):
        result = []
        self._inorder(self.root, result)
        return result
    
    def _inorder(self, node, result):
        if node != self.NIL:
            self._inorder(node.left, result)
            color = "R" if node.color == RED else "B"
            result.append(f"{color}:{node.key}")
            self._inorder(node.right, result)
```

```c
/* C语言红黑树核心结构 */
typedef enum { RED, BLACK } Color;

typedef struct RBNode {
    int key;
    Color color;
    struct RBNode *left, *right, *parent;
} RBNode;

typedef struct {
    RBNode *root;
    RBNode *NIL;  /* 哨兵节点 */
} RBTree;

RBTree* create_rbtree() {
    RBTree *tree = (RBTree*)malloc(sizeof(RBTree));
    tree->NIL = (RBNode*)malloc(sizeof(RBNode));
    tree->NIL->color = BLACK;
    tree->NIL->left = tree->NIL->right = tree->NIL->parent = NULL;
    tree->root = tree->NIL;
    return tree;
}
```

#### 7.3 复杂度分析总结

| 操作 | 时间复杂度 | 旋转次数（最坏） |
|------|-----------|----------------|
| 查找 | O(log N) | 0 |
| 插入 | O(log N) | ≤ 2 |
| 删除 | O(log N) | ≤ 3 |
| 遍历 | O(N) | 0 |
| 空间 | O(N) | - |

**红黑树的核心优势**：旋转次数有常数上界。无论树有多大，插入最多旋转2次，删除最多旋转3次。这是红黑树成为工业级首选的根本原因。

**记忆要点**：
1. 新节点染红（只可能违反性质4，不违反性质5）
2. 插入修复看**叔叔颜色**——红色则变色上溯，黑色则旋转
3. 删除修复看**兄弟颜色和侄子颜色**——四种情况逐步转化
4. 红黑树 ≈ 2-3-4树的二叉表示，理解等价关系有助于理解操作
