## 01.问题域定义

### 1.1 现象
- 点击按钮后"等了一会才有反应"
- 滑动过渡动画顿挫
- 输入框打字延迟
- 下拉刷新 / 转场动画掉帧

### 1.2 度量准则
- **INP** (Interaction to Next Paint)
- **Tap Latency**：触摸到下一帧绘制
- **Animation Frame Drop Ratio**：动画期间丢帧率
- **Gesture Recognition Latency**：手势识别耗时


## 02.第一性原理

提纲：
- 交互闭环：输入采样 → 事件分发 → 业务响应 → 帧产出 → 显示
- 每段的物理上限（输入采样率 / 事件队列 / 帧时钟）
- "输入即帧"原理：理想情况下交互延迟 = 1 帧
- 动画的两类实现：主线程逐帧 vs 系统合成器（compositor）


## 03.度量与采集

| 平台 | 采集 |
|---|---|
| Android | `MotionEvent.getEventTime` 到首帧 / Choreographer doFrame |
| iOS | `UIEvent.timestamp` 到 displayLink / `MetricKit` |
| Web | `event.timeStamp` 到 `requestAnimationFrame` / Web Vitals INP |
| 嵌入式 | 触屏 IRQ 时间戳到帧缓冲 swap |


## 04.归因方法

提纲：
- 交互卡顿决策树（事件分发 / 业务逻辑 / 重渲染 / 合成）
- 动画掉帧归因（主线程被抢 vs GPU 慢 vs 资源准备不及）


## 05.求证实验 ⭐

候选实验：
- 主线程动画 vs Compositor 动画在主线程被压力时的稳定性对比
- React 同步 setState vs 并发渲染对 INP 的影响
- iOS Auto Layout 复杂度对触摸延迟的影响


## 06.优化策略

跨平台通用：
- 交互即时反馈（按下立即视觉反馈，业务异步）
- 动画交给合成器（GPU），避免主线程逐帧
- 减少手势期间的非必要工作
- 输入预测 / 帧预测（高级）

平台特化：
- Android：RenderThread / Compose 动画
- iOS：Core Animation 隐式动画 / CADisplayLink
- Web：`will-change` / CSS Transform / `transform-only` 动画
- 嵌入式：硬件图层加速 / 双缓冲
