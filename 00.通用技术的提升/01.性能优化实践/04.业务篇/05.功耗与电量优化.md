## 01.问题域定义

### 1.1 现象
- 用户反馈"耗电快"
- 后台被系统杀死
- 设备发烫触发降频，性能进一步劣化
- 嵌入式设备续航不达预期

### 1.2 度量准则
- 单位时间能耗（mAh / hour）
- 单功能能耗（mAh / 任务）
- 唤醒次数与时长（wakeup count / time）
- CPU 频率分布（高频驻留比）
- 屏幕 / 定位 / 网络 / 传感器开启时长


## 02.第一性原理

提纲：
- 能耗模型：E = P × t = (V × I) × t
- 能耗大户：屏幕、CPU 高频、Modem（4G/5G）、定位、传感器
- 调度的能效：DVFS / big.LITTLE / EAS
- 频率与能效的非线性（高频每提升 10% 能耗提升 30%+）
- 唤醒代价：一次唤醒可能消耗 1-2 秒的待机电量

## 05.求证实验 ⭐

候选实验：

- 定位高精度 vs 平衡模式能耗对比

## 06.优化策略

跨平台通用：
- **批量化**：减少唤醒次数（合并定时器、合并网络）
- **延迟与对齐**：把可推迟任务对齐到下一次必然唤醒
- **降频与降级**：低优先级任务允许在小核运行
- **按需开启**：屏幕亮 / 前台才开启高耗模块
- **反向预算**：每个功能给定能耗预算

平台特化：
- Android：JobScheduler / WorkManager / Doze 适配
- iOS：BGTaskScheduler / Background Modes 合理使用
- 嵌入式：DVFS / 睡眠态 / 唤醒源管理
