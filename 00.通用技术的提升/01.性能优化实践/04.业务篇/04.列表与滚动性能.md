## 01.问题域定义

### 1.1 现象
- 滚动卡顿 / 掉帧
- 滚动加载新数据时白屏
- 长列表内存爆涨
- "复用率不高"导致 ViewHolder / Cell 反复创建

### 1.2 度量准则
- 滚动期间帧时长 P99
- ViewHolder / Cell 复用率
- 滚动时大卡顿率（> 700ms 帧）
- 加载更多的等待时长


## 02.第一性原理

提纲：
- 列表的本质：**虚拟化（Virtualization）+ 视图复用**
- 滚动的物理过程：手势 → 偏移计算 → 视图回收/绑定 → 重排重绘
- 跨平台同构模型：所有列表都遵循 "DataSource + ViewHolder Pool + Recycler"
- 性能预算：60fps = 单帧 16.67ms = bind 一项数据 + 预测下一项预取


## 03.度量与采集

| 平台 | 采集 |
|---|---|
| Android | `RecyclerView.OnFlingListener` + FrameMetrics + bindViewHolder 耗时 |
| iOS | `scrollViewDidScroll` + CADisplayLink + `cellForRowAt` 耗时 |
| Web | `IntersectionObserver` + rAF + 虚拟列表渲染耗时 |
| 嵌入式 | 滚动事件 + 帧缓冲交换计数 |

## 06.优化策略

跨平台通用：
- itemType 收敛 ≤ 3 种
- 图片预解码 + 内存缓存
- 富文本预排版
- 滚动期间暂停非必要动画 / 网络
- 数据预取（下一屏 prefetch）

平台特化：
- Android：RecyclerView Prefetch / DiffUtil
- iOS：UICollectionView Prefetching / DataSource Prefetch API
- Web：`content-visibility: auto` / `react-window` / Intersection Observer
- 嵌入式：固定行高 + 双缓冲
