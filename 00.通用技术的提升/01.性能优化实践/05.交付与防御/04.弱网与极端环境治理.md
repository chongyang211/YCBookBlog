## 01.问题域定义

### 1.1 真实环境的"长尾"
- 弱网：地铁、电梯、跨国漫游
- 低端机：千元机、3 年以上老机
- 高温降频：夏天 / 长时间游戏 / 充电同时使用
- 低电量：触发省电模式
- 后台压力：内存紧张 / IO 抢占

### 1.2 度量准则
- 弱网占比（RTT / 丢包率超阈值的会话比例）
- 低端机性能 SLO（独立切片）
- 降频会话占比
- 极端环境下的 P99 / 灾难体验比例


## 02.第一性原理

提纲：
- 真实分布的"长尾"本质：实验室是均值，线上是 P99
- 三类极端因素：网络（带宽/延迟/丢包）、设备（CPU/内存）、环境（温度/电量）
- 极端环境治理的本质：**降级而非崩溃，可用而非完美**


## 03.度量与采集

提纲：
- 弱网检测算法（连续 RTT 滑窗、TCP 重传率推断）
- 设备分档算法（CPU / 内存 / GPU 综合打分）
- 温度状态获取（ThermalManager / NSProcessInfo.thermalState）
- 后台压力检测（onTrimMemory / didReceiveMemoryWarning）


## 04.归因方法

提纲：
- "为什么只在某类用户上出现"决策树

## 05.求证实验 ⭐

候选实验：
- 模拟弱网（300ms RTT + 5% 丢包）下首屏可用性对比
- 低端机（2GB RAM）冷启动 OOM 概率统计
- 高温降频后 FPS 分布对比


## 06.优化策略

跨平台通用：
- **弱网**：超时分级、智能重试、关键资源 inline、CDN 选优、HTTP/3 / QUIC
- **低端机**：降级路径（少图片 / 少动画 / 关闭推荐 / 限制并发）
- **高温**：感知 thermal state 主动降级（关闭高耗模块）
- **低电量**：Power Save Mode 适配
- **后台压力**：主动释放、避免被杀

平台特化：
- Android：Performance Class、Build.MODEL 黑名单兜底
- iOS：ProcessInfo `lowPowerModeEnabled` / `thermalState`
- Web：`navigator.connection` / `deviceMemory` / Save-Data
- 嵌入式：硬件抽象层提供功耗 / 温度查询
