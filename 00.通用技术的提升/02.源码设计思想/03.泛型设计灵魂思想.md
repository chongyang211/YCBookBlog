## 1.泛型编程概述

### 1.1 泛型概述说明

泛型编程（Generic Programming）是一种编程范式，它允许程序员编写与类型无关的代码，通过参数化类型来实现代码的复用性和类型安全性。泛型的核心在于将类型作为参数，使得同一套代码可以处理多种不同的数据类型。

### 1.4 泛型基本定义

- **泛型（Generics）**：一种允许在定义类、接口和方法时使用类型参数的机制
- **类型参数（Type Parameter）**：在泛型定义中使用的占位符，代表具体的类型
- **类型实参（Type Argument）**：在使用泛型时提供的具体类型

### 1.5 历史背景与发展

发展历程

1. **1970年代**：ML语言首次引入参数多态性概念
2. **1980年代**：Ada语言实现了早期的泛型机制
3. **1990年代**：C++模板系统奠定了现代泛型编程基础
4. **2000年代**：Java 5.0和C# 2.0引入泛型，推动主流应用
5. **2010年代至今**：Go、Rust、TypeScript等现代语言进一步完善泛型设计

推动因素

- **代码复用需求**：避免为不同类型编写重复代码
- **类型安全要求**：在编译期检查类型错误
- **性能优化需要**：减少运行时类型检查和装箱拆箱开销
- **API设计改进**：提供更清晰、更安全的接口

## 解决的核心问题

### 1. 代码重复问题
**问题**：为不同类型编写相似的代码
```cpp
// 没有泛型时需要为每种类型编写
class IntStack {
    int* data;
    // ... 实现
};

class StringStack {
    string* data;
    // ... 相同的实现逻辑
};
```

**解决方案**：
```cpp
// 使用泛型统一实现
template<typename T>
class Stack {
    T* data;
    // ... 一套实现处理所有类型
};
```

### 2. 类型安全问题
**问题**：使用Object或void*导致运行时类型错误
```java
// Java 1.4 及之前
List list = new ArrayList();
list.add("Hello");
list.add(42);
String str = (String) list.get(1); // 运行时ClassCastException
```

**解决方案**：
```java
// 使用泛型
List<String> list = new ArrayList<String>();
list.add("Hello");
// list.add(42); // 编译错误，类型不匹配
String str = list.get(0); // 无需强制转换
```

### 3. 性能问题
**问题**：装箱拆箱和运行时类型检查的开销
**解决方案**：编译时类型特化，避免运行时开销

### 4. API表达力问题
**问题**：无法清晰表达类型之间的关系
**解决方案**：通过泛型约束表达复杂的类型关系

## 编译器实现原理

### 1. 类型擦除（Type Erasure）- Java方式
```java
// 源代码
List<String> stringList = new ArrayList<String>();

// 编译后等价于
List stringList = new ArrayList();
```

**特点**：
- 运行时不保留泛型信息
- 向后兼容性好
- 存在一些限制（如不能创建泛型数组）

### 2. 单态化（Monomorphization）- C++/Rust方式
```cpp
// 模板定义
template<typename T>
void func(T value) { /* ... */ }

// 使用
func<int>(42);
func<string>("hello");

// 编译器生成
void func_int(int value) { /* ... */ }
void func_string(string value) { /* ... */ }
```

**特点**：
- 为每个类型实例化生成专门代码
- 零运行时开销
- 可能导致代码膨胀

### 3. 装箱统一表示（Boxed Uniform Representation）- C#方式
```csharp
// 值类型自动装箱为引用类型
List<int> numbers = new List<int>();
// 内部统一处理为引用类型
```

**特点**：
- 运行时保留类型信息
- 值类型需要装箱
- 支持反射和运行时类型查询

### 4. 编译时检查流程
1. **语法分析**：解析泛型语法结构
2. **类型推断**：推断类型参数
3. **约束检查**：验证类型参数满足约束条件
4. **代码生成**：根据实现策略生成目标代码

## 性能考量

### 1. 编译时开销
- **模板实例化**：可能导致编译时间增长
- **代码膨胀**：每个类型实例化都生成代码
- **优化策略**：使用显式实例化、extern template

```cpp

    return a + b;
```

- **类型擦除**：共享实现，内存友好
- **单态化**：每个类型独立实现，可能增加内存使用
- **优化技巧**：使用类型特化减少不必要的实例化

# 泛型设计方案技术文档

## 1. 泛型由来背景与动机

### 1.1 软件工程中的类型安全挑战

在早期的编程语言发展过程中，程序员面临着一个根本性的矛盾：如何在保证类型安全的同时实现代码的通用性和复用性。这个问题在面向对象编程语言中尤为突出，特别是在处理集合类和数据结构时。

在Java 1.5之前，所有的集合类（如ArrayList、HashMap等）都只能存储Object类型的对象。这种设计虽然提供了最大的灵活性，但也带来了严重的问题：

**类型安全缺失的具体表现：**
- 程序员可以向同一个集合中添加任意类型的对象，导致数据类型混乱
- 从集合中取出对象时必须进行强制类型转换，这个过程容易出错
- 类型错误只能在运行时被发现，增加了调试和维护的难度
- 代码的可读性和可维护性大大降低

**性能问题的根源：**
在没有泛型的时代，基本数据类型（如int、double等）需要通过装箱操作转换为对应的包装类（Integer、Double等）才能存储在集合中。这个过程不仅消耗额外的内存，还带来了显著的性能开销。每次装箱和拆箱操作都涉及对象的创建和垃圾回收，在大量数据处理时会成为性能瓶颈。

### 1.2 代码重复与维护性问题

在泛型出现之前，程序员经常需要为不同的数据类型编写几乎相同的代码。例如，如果需要实现一个栈数据结构，可能需要分别实现IntStack、StringStack、ObjectStack等多个版本。这种做法违反了软件工程中的DRY（Don't Repeat Yourself）原则，带来了以下问题：

**代码重复的负面影响：**
- 增加了代码库的体积，提高了维护成本
- 当需要修改算法逻辑时，必须在多个地方进行相同的修改
- 容易出现不一致的实现，导致bug的产生
- 新增数据类型时需要重新实现整套代码

**API设计的复杂性：**
没有泛型的API设计往往需要大量的重载方法或者复杂的类型检查逻辑。这不仅增加了API的复杂性，也降低了代码的可读性和易用性。

### 1.3 编译时检查的重要性

软件工程实践表明，越早发现错误，修复成本越低。运行时错误不仅难以调试，还可能导致生产环境的系统崩溃。泛型的引入使得许多类型相关的错误可以在编译时被发现和修复，这对软件质量的提升具有重要意义。

**编译时检查的优势：**
- 错误发现时间提前，降低了调试成本
- 提高了代码的健壮性和可靠性
- 减少了生产环境中的运行时异常
- 提供了更好的IDE支持和代码提示功能

### 1.4 泛型设计的核心目标

基于上述问题的分析，泛型设计的核心目标可以总结为以下几个方面：

**1. 类型安全保障**
泛型通过在编译时进行严格的类型检查，确保类型错误在编译阶段就被发现和修复。这种机制不仅提高了代码的安全性，还增强了程序员对代码正确性的信心。

**2. 代码复用最大化**
通过类型参数化，一套泛型代码可以适用于多种不同的数据类型，大大提高了代码的复用性。这不仅减少了代码量，还提高了维护效率。

**3. 性能优化**
泛型的实现机制（如Java的类型擦除、C++的模板特化等）可以在保证类型安全的同时，避免不必要的类型转换和装箱拆箱操作，从而提升程序的运行效率。

**4. API表达力增强**
泛型使得API的设计更加清晰和富有表达力。通过类型参数，API可以明确地表达其对参数类型的要求和返回值的类型，提高了代码的可读性和可维护性。

**5. 向后兼容性**
在引入泛型的过程中，必须考虑与现有代码的兼容性。良好的泛型设计应该能够在不破坏现有代码的前提下，提供新的类型安全特性。

### 1.5 泛型解决问题的深层意义

泛型的引入不仅仅是一个语法特性的增加，更是编程语言类型系统的一次重要进化。它体现了软件工程中对以下几个重要原则的追求：

**抽象与具体的平衡**
泛型提供了一种在抽象和具体之间找到平衡的方法。它允许程序员编写足够抽象的代码以实现复用，同时又保持足够的类型信息以确保安全性。

**编译时优化与运行时效率**
通过将类型检查和优化工作前移到编译时，泛型实现了编译时安全性和运行时效率的双重目标。

**语言表达力的提升**
泛型增强了编程语言的表达能力，使程序员能够更精确地描述程序的意图和约束，从而编写出更加清晰和可维护的代码。

## 2. 泛型简单案例

### 2.1 Java泛型案例

```java
// 没有泛型的情况
class OldList {
    private Object[] items = new Object[10];
    private int size = 0;
    
    public void add(Object item) {
        items[size++] = item;
    }
    
    public Object get(int index) {
        return items[index];
    }
}

// 使用泛型的情况
class GenericList<T> {
    private Object[] items = new Object[10];
    private int size = 0;
    
    public void add(T item) {
        items[size++] = item;
    }
    
    @SuppressWarnings("unchecked")
    public T get(int index) {
        return (T) items[index];
    }
}

// 使用示例
public class GenericExample {
    public static void main(String[] args) {
        // 旧方式：需要类型转换，不安全
        OldList oldList = new OldList();
        oldList.add("Hello");
        String str = (String) oldList.get(0); // 需要强制转换
        
        // 泛型方式：类型安全，无需转换
        GenericList<String> stringList = new GenericList<>();
        stringList.add("Hello");
        String str2 = stringList.get(0); // 无需转换
        
        GenericList<Integer> intList = new GenericList<>();
        intList.add(42);
        Integer num = intList.get(0);
    }
}
```

### 2.2 C++模板案例

```cpp
#include <iostream>
#include <vector>

// 函数模板
template<typename T>
T max(T a, T b) {
    return (a > b) ? a : b;
}

// 类模板
template<typename T>
class Stack {
private:
    std::vector<T> elements;
    
public:
    void push(const T& element) {
        elements.push_back(element);
    }
    
    T pop() {
        if (elements.empty()) {
            throw std::runtime_error("Stack is empty");
        }
        T top = elements.back();
        elements.pop_back();
        return top;
    }
    
    bool empty() const {
        return elements.empty();
    }
};

int main() {

    std::cout << max(3.14, 2.71) << std::endl;   // double版本
    
    // 使用类模板
    Stack<int> intStack;
    intStack.push(42);
    intStack.push(100);
    
    Stack<std::string> stringStack;
    stringStack.push("Hello");
    stringStack.push("World");
    
    return 0;
```

## 4. 泛型的实现原理与设计原则

### 4.1 泛型实现的核心原理

#### 4.1.1 类型参数化原理

泛型的本质是将类型作为参数，实现代码的参数化多态：

```java
// 类型参数化的本质
public class Box<T> {
    private T content;
    
    // T作为类型参数，在实例化时确定具体类型
    public void set(T content) { this.content = content; }
    public T get() { return content; }
}

// 编译器会为每个具体类型生成相应的类型检查代码
Box<String> stringBox = new Box<>(); // T = String
Box<Integer> intBox = new Box<>();   // T = Integer
```

#### 4.1.2 类型系统理论基础

泛型基于以下类型系统理论：

1. **参数多态（Parametric Polymorphism）**：同一代码适用于多种类型
2. **类型安全（Type Safety）**：编译时保证类型正确性
3. **类型推断（Type Inference）**：编译器自动推导类型
4. **子类型关系（Subtyping）**：类型之间的继承关系

```java
// 参数多态示例
public static <T> void swap(T[] array, int i, int j) {
    T temp = array[i];  // T可以是任何类型
    array[i] = array[j];
    array[j] = temp;
}

// 有界多态 - 限制类型参数的范围
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;  // T必须实现Comparable
}
```

#### 4.1.3 编译器处理机制

编译器处理泛型的核心步骤：

```java

List<String> list = new ArrayList<String>();
list.add("Hello");
String str = list.get(0);

// 编译器处理过程：
// 1. 类型检查：验证add("Hello")和get()返回String的类型正确性

// 编译后的字节码等价于：

```

### 4.2 编译时类型检查的深层机制

编译时类型检查是泛型系统的核心支柱，它通过静态分析确保程序在运行前就具备类型安全性。这个过程涉及复杂的类型理论和编译器技术，是现代编程语言类型系统的重要组成部分。

#### 4.2.1 类型约束系统的设计哲学

类型约束系统的设计基于一个核心理念：在编译时尽可能多地捕获潜在的类型错误，同时保持足够的灵活性以支持合理的编程模式。这个系统需要在严格性和实用性之间找到平衡点。

**约束系统的层次结构：**

1. **基础类型约束**：确保类型参数满足最基本的使用要求
2. **继承约束**：利用面向对象的继承关系建立类型层次
3. **接口约束**：通过接口契约定义行为能力
4. **组合约束**：多个约束条件的逻辑组合

**类型约束的实现机制：**

编译器在处理泛型代码时，会建立一个类型约束图，用于跟踪所有类型参数之间的关系和限制。这个图包含了类型变量、约束条件、以及它们之间的依赖关系。当编译器遇到类型使用时，会检查这个使用是否满足约束图中定义的所有条件。

#### 4.2.2 类型约束检查的具体实现

编译器通过类型约束确保类型安全：

```java
public class TypeConstraints {

    }
```

### 4.3 类型推断机制的深入解析

类型推断是泛型系统中最复杂也最重要的特性之一。它允许编译器在程序员没有显式指定类型参数的情况下，自动推导出正确的类型信息。这个机制不仅提高了代码的简洁性，还减少了程序员的认知负担，使得泛型代码更加易读和易写。

#### 4.3.1 类型推断的理论基础

类型推断基于类型理论中的统一算法（Unification Algorithm）和约束求解技术。编译器通过分析代码中的类型使用模式，建立一系列类型等式和不等式，然后求解这个约束系统来确定类型参数的具体值。

**推断过程的核心步骤：**

1. **信息收集阶段**：编译器扫描代码，收集所有与类型参数相关的使用信息
2. **约束生成阶段**：基于收集到的信息生成类型约束条件
3. **约束求解阶段**：使用统一算法求解约束系统
4. **结果验证阶段**：验证推断结果是否满足所有类型安全要求

**推断算法的复杂性：**

类型推断算法需要处理多种复杂情况，包括递归类型、高阶类型、协变逆变关系等。在某些情况下，可能存在多个有效的推断结果，编译器需要选择最具体或最合适的那个。当推断失败时，编译器会要求程序员提供显式的类型注解。

#### 4.3.2 局部类型推断的实现机制

局部类型推断是指在特定的代码上下文中进行的类型推断，它利用局部信息来确定类型参数的值。这种推断通常发生在方法调用、变量声明、表达式求值等场景中。

**上下文敏感的推断：**

编译器会考虑表达式的使用上下文来进行更精确的类型推断。例如，当一个泛型方法的返回值被赋值给一个具有明确类型的变量时，编译器可以利用这个目标类型信息来推断方法的类型参数。

**推断的优先级规则：**

当存在多个可能的推断结果时，编译器会按照预定义的优先级规则进行选择：
- 更具体的类型优于更抽象的类型
- 有界类型参数的边界类型具有更高优先级
- 显式类型注解总是优于推断结果

```java
public class TypeInference {
```

### 4.4 代码复用机制的设计理念

代码复用是泛型设计的核心目标之一，它通过类型参数化实现了"一次编写，多处使用"的理想。泛型的代码复用机制不仅仅是简单的代码共享，而是一种深层次的抽象技术，它允许程序员在保持类型安全的前提下，编写出高度通用和可重用的代码。

#### 4.4.1 参数化多态的复用原理

参数化多态（Parametric Polymorphism）是泛型实现代码复用的理论基础。与传统的继承多态不同，参数化多态通过类型参数来实现抽象，使得同一份代码可以在不同的类型上下文中工作。

**复用层次的分类：**

1. **算法复用**：相同的算法逻辑适用于不同的数据类型
2. **数据结构复用**：相同的数据组织方式适用于不同的元素类型
3. **设计模式复用**：相同的设计模式适用于不同的业务对象
4. **框架复用**：相同的框架结构适用于不同的应用场景

**复用的质量评估标准：**

- **通用性**：代码能够适用的类型范围
- **安全性**：复用过程中的类型安全保障
- **效率性**：复用代码的执行效率
- **可维护性**：复用代码的修改和扩展难度

#### 4.4.2 泛型复用模式的设计原则

在设计泛型复用代码时，需要遵循一系列重要的设计原则，这些原则确保了复用代码的质量和可维护性。

**最小化约束原则：**
泛型代码应该对类型参数施加尽可能少的约束，只保留算法或数据结构正常工作所必需的约束条件。这样可以最大化代码的适用范围。

**职责单一原则：**
每个泛型类或方法应该只负责一个明确的职责，避免将多个不相关的功能混合在一起。这有助于提高代码的可理解性和可测试性。

**开放封闭原则：**
泛型代码应该对扩展开放，对修改封闭。通过合理的类型参数设计，可以在不修改现有代码的情况下支持新的类型。

#### 4.4.3 泛型代码复用的实现模式


### 4.5 向后兼容性的设计挑战与解决方案

向后兼容性是泛型设计中最具挑战性的问题之一。当一门编程语言引入泛型特性时，必须确保现有的代码库能够继续正常工作，同时又要为新代码提供类型安全的保障。这个要求在技术实现上带来了巨大的复杂性，需要在语言设计、编译器实现、运行时系统等多个层面进行精心的权衡和设计。

#### 4.5.1 兼容性设计的核心挑战

**历史包袱的处理：**
在泛型引入之前，大量的代码库已经基于非泛型的API进行开发。这些代码不仅数量庞大，而且往往是关键业务系统的核心组件。如果泛型的引入导致这些代码无法编译或运行，将会给整个生态系统带来灾难性的影响。

**类型安全与兼容性的矛盾：**
泛型的核心价值在于提供编译时的类型安全保障，但向后兼容性要求允许非类型安全的代码继续存在。如何在这两个看似矛盾的需求之间找到平衡点，是泛型设计的关键挑战。

**性能影响的最小化：**
兼容性机制不应该对程序的运行时性能产生显著影响。特别是对于那些没有使用泛型特性的旧代码，其性能表现应该与引入泛型之前保持一致。

#### 4.5.2 原始类型兼容机制的设计理念

原始类型（Raw Type）是实现向后兼容性的核心机制。它允许泛型类在没有类型参数的情况下被使用，从而保持与旧代码的兼容性。

**原始类型的语义定义：**
原始类型本质上是泛型类型的一个特殊实例，其中所有的类型参数都被擦除或替换为其上界。这种设计使得原始类型可以与任何具体的泛型实例进行互操作，但同时也失去了类型安全的保障。

**兼容性转换的规则：**
- 泛型类型可以安全地转换为对应的原始类型
- 原始类型向泛型类型的转换会产生编译警告
- 运行时类型检查仍然基于擦除后的类型信息

**警告系统的设计：**
编译器通过警告系统来提醒程序员潜在的类型安全问题。这些警告不会阻止编译过程，但会鼓励程序员逐步迁移到类型安全的泛型代码。

#### 4.5.3 兼容性机制的实现细节

**类型擦除与兼容性：**
Java采用的类型擦除机制在实现向后兼容性方面发挥了关键作用。通过在编译时移除泛型类型信息，运行时的类型系统保持了与泛型引入之前的完全一致性。

**方法签名的处理：**
在泛型继承和重写的场景中，编译器需要生成桥接方法来保持方法签名的兼容性。这些桥接方法在字节码层面确保了多态调用的正确性。

**反射API的扩展：**
为了支持泛型信息的运行时访问，反射API需要进行相应的扩展。同时，这些扩展必须保持与现有反射代码的兼容性。

### 5.1 泛型擦除

Java泛型采用类型擦除实现，编译后泛型信息被移除：

```java
// 编译前

List<Integer> intList = new ArrayList<Integer>();

// 编译后（伪代码）
List stringList = new ArrayList();
List intList = new ArrayList();

// 因此以下代码为true
System.out.println(stringList.getClass() == intList.getClass()); // true
```

## 总结

泛型设计的核心思想是通过参数化类型来实现代码复用和类型安全。不同语言的泛型实现各有特色：

1. **Java**：通过类型擦除保证向后兼容，但牺牲了运行时类型信息
2. **C++**：通过模板提供最强大的编译时能力，但增加了复杂性
3. **C#**：在运行时保留泛型信息，提供了最佳的运行时支持
4. **TypeScript**：提供了灵活的结构化类型系统，适合JavaScript生态
5. **Go**：提供了简洁实用的泛型支持，注重性能和简单性

选择合适的泛型设计需要根据语言特性、性能要求、兼容性需求和开发复杂度等因素综合考虑。

## 01.泛型的概述

### 1.1 类型安全问题

在没有泛型的情况下，代码通常使用 `Object` 类型来支持多种数据类型，但这种方式会导致类型转换错误（`ClassCastException`）。泛型通过在编译时检查类型，确保代码的类型安全。

```java
List list = new ArrayList();
list.add("Hello");
list.add(123); // 允许添加任意类型

String str = (String) list.get(1); // 运行时抛出 ClassCastException
```


### 1.2 泛型由来背景

集合可以存储多种数据类型的元素，那么在存储的时候没有任何问题，但是在获取元素，并向下转型的时候，可能会存在一个错误，而这个错误就是ClassCastException。

集合的这种可以存储多种数据类型的元素的这个特点，不怎么友好，程序存在一些安全隐患。

那么为了出来这种安全隐患，我们应该限定一个集合存储元素的数据类型，我们只让他存储统一中数据类型的元素，那么在做向下转型的是就不会存在这种安全隐患了。

这个时候，就需要使用泛型。泛型的出现减少了很多强转的操作，同时避免了很多运行时的错误，在编译期完成检查类型转化。

### 1.3 引入泛型的动机
- 了解引入泛型的动机，就先从语法糖开始了解。
    - 语法糖（Syntactic Sugar），也称糖衣语法，是由英国计算机学家Peter.J.Landin发明的一个术语，指在计算机语言中添加的某种语法，这种语法对语言的功能并没有影响，但是更方便程序员使用。
    - Java中最常用的语法糖主要有泛型、变长参数、条件编译、自动拆装箱、内部类等。虚拟机并不支持这些语法，它们在编译阶段就被还原回了简单的基础语法结构，这个过程成为解语法糖。
- 为何使用这种语法糖
    - Java 泛型就是把一种语法糖，通过泛型使得在编译阶段完成一些类型转换的工作，避免在运行时强制类型转换而出现`ClassCastException`，即类型转换异常。
- 泛型的格式
    * <数据类型>    这里的数据类型只能是引用数据类型
    * <数据类型1 ， 数据类型2 , ....>


### 1.4 好处和弊端
- ①类型安全。类型错误现在在编译期间就被捕获到了，而不是在运行时当作java.lang.ClassCastException展示出来，将类型检查从运行时挪到编译时有助于开发者更容易找到错误，并提高程序的可靠性。
- ②消除了代码中许多的强制类型转换，增强了代码的可读性。
- ③为较大的优化带来了可能。优化了程序设计，解决了黄色警告线。


### 1.5 泛型简单案例

**示例：非泛型的强制类型转换**

```java
List list = new ArrayList();
list.add("Hello");
String str = (String) list.get(0); // 需要强制类型转换
```

当然这是完全允许的，因为List里面的内容是Object类型的，自然任何对象类型都可以放入、都可以取出，但是这么写会有两个问题：

- 1、当一个对象放入集合时，集合不会记住此对象的类型，当再次从集合中取出此对象时，该对象的编译类型变成了Object。
- 2、运行时需要人为地强制转换类型到具体目标，实际的程序绝不会这么简单，一个不小心就会出现java.lang.ClassCastException。

**示例：泛型的类型推断**

```java
List<String> list = new ArrayList<>();
list.add("Hello");
String str = list.get(0); // 无需强制类型转换
```


泛型是对Java语言类型系统的一种扩展，有点类似于C++的模板，可以把类型参数看作是使用参数化类型时指定的类型的一个占位符。引入泛型，是对Java语言一个较大的功能增强，带来了很多的好处。

### 1.7 可读性和灵活性
- 泛型除了能进行编译器类型检查和规避类型强制转换外，还能有效地提高代码的可读性。
    - 如果不使用泛型，当一个不清楚业务场景的人在对集合进行操作时，无法知道list中存储的是什么类型的对象，如果使用了泛型，就能够通过其类型参数判断出当前的业务场景，也增加了代码的可读性，同时也可以大胆地在抽象继承的基础上进行开发了。
- 泛型使用上的灵活性体现在很多方面，因为它本身实质上就是对于继承在使用上的一种增强。
    - 因为泛型在具体工作时，当编译器在编译源码的时候，首先要进行泛型类型参数的检查，检查出类型不匹配等问题，然后进行类型擦除并同时在类型参数出现的位置插入强制转换指令，从而实现泛型。



## 02.泛型的使用
### 2.1 泛型类的概述及使用
* A:泛型类概述:         把泛型定义在类上
* B:定义格式:           public class 类名<泛型类型1,…>
* C:注意事项:           泛型类型必须是引用类型


### 2.2 泛型方法的概述和使用
* A:泛型方法概述:    把泛型定义在方法上
* B:定义格式:           public <泛型类型> 返回类型 方法名(泛型类型 变量名)
    ```
    public <T> void show(T t) {
    
    }
    ```
- **所谓泛型方法，就是在声明方法时定义一个或多个类型形参。** 泛型方法的用法格式如下：
    ```
    修饰符<T, S> 返回值类型 方法名（形参列表）｛
       方法体
    ｝
    ```
- **注意要点：** 
    - 方法声明中定义的形参只能在该方法里使用，而接口、类声明中定义的类型形参则可以在整个接口、类中使用。当调用`fun()`方法时，根据传入的实际对象，编译器就会判断出类型形参T所代表的实际类型。
    ```
    class Demo{  
      public <T> T fun(T t){   // 可以接收任意类型的数据  
       return t ;     // 直接把参数返回  
      }  
    };  
    public class GenericsDemo26{  
      public static void main(String args[]){  
        Demo d = new Demo() ; // 实例化Demo对象  
        String str = d.fun("汤姆") ; // 传递字符串  
        int i = d.fun(30) ;  // 传递数字，自动装箱  
        System.out.println(str) ; // 输出内容  
        System.out.println(i) ;  // 输出内容  
      }  
    };
    ```


### 2.3 泛型接口的概述和使用
- 先来看一个案例
    * A:泛型接口概述:    把泛型定义在接口上
    * B:定义格式:        public interface 接口名<泛型类型>
    ```
    /**
     * 泛型接口的定义格式:        修饰符  interface 接口名<数据类型> {}
     */
    public interface Inter<T> {
        public abstract void show(T t) ;
    }
    
    /**
     * 子类是泛型类
     */
    public class InterImpl<E> implements Inter<E> {
        @Override
        public void show(E t) {
            System.out.println(t);
        }
    }
    
    
    Inter<String> inter = new InterImpl<String>() ;
    inter.show("hello") ;
    ```
- 然后看看源码中泛型的使用，下面是JDK 1.5 以后，List接口，以及ArrayList类的代码片段。
    ```
    //定义接口时指定了一个类型形参，该形参名为E
    public interface List<E> extends Collection<E> {
       //在该接口里，E可以作为类型使用
       public E get(int index) {}
       public void add(E e) {} 
    }
    
    //定义类时指定了一个类型形参，该形参名为E
    public class ArrayList<E> extends AbstractList<E> implements List<E> {
       //在该类里，E可以作为类型使用
       public void set(E e) {
       .......................
       }
    }
    ```
    - 这就是**泛型的实质：允许在定义接口、类时声明类型形参，类型形参在整个接口、类体内可当成类型使用，几乎所有可使用普通类型的地方都可以使用这种类型形参。**[博客](https://github.com/yangchong211/YCBlogs)
- **泛型类派生子类**
    - 当创建了带泛型声明的接口、父类之后，可以为该接口创建实现类，或者从该父类派生子类，需要注意：**使用这些接口、父类派生子类时不能再包含类型形参，需要传入具体的类型。**  
    - 错误的方式：
        ```
        public class A extends Container<K, V>{}
        ```
    - 正确的方式：
        ```
        public class A extends Container<Integer, String>{}
        ```
    - 也可以不指定具体的类型，此时系统会把K,V形参当成Object类型处理。如下：
        ```
        public class A extends Container{}
        ```


### 2.4 泛型类的概述和使用
- 定义一个容器类，存放键值对key-value，键值对的类型不确定，可以使用泛型来定义，分别指定为K和V。
    ```
    public class Container<K, V> {
    
        private K key;
        private V value;
    
        public Container(K k, V v) {
            key = k;
            value = v;
        }
    
        public K getkey() {
            return key;
        }
    
        public V getValue() {
            return value;
        }
    
        public void setKey() {
            this.key = key;
        }
    
        public void setValue() {
            this.value = value;
        }
    
    }
    ```
- 在使用Container类时，只需要指定K，V的具体类型即可，从而创建出逻辑上不同的Container实例，用来存放不同的数据类型。
    ```
    public static void main(String[] args) {
        Container<String,String>  c1=new Container<String ,String>("name","hello");
        Container<String,Integer> c2=new Container<String,Integer>("age",22);
        Container<Double,Double>  c3=new Container<Double,Double>(1.1,1.3);
        System.out.println(c1.getKey() + " : " + c1.getValue());      
        System.out.println(c2.getKey() + " : " + c2.getValue());                                                               
        System.out.println(c3.getKey() + " : " + c3.getValue());
    }
    ```
- 在JDK 1.7 增加了泛型的“菱形”语法：**Java允许在构造器后不需要带完成的泛型信息，只要给出一对尖括号（&lt;&gt;）即可，Java可以推断尖括号里应该是什么泛型信息。如下所示：
    ```
    Container<String,String> c1=new Container<>("name","hello");
    Container<String,Integer> c2=new Container<>("age",22);
    ```



### 2.5 泛型构造器的概述
- 正如泛型方法允许在方法签名中声明类型形参一样，Java也允许在构造器签名中声明类型形参，这样就产生了所谓的泛型构造器。
- 和使用普通泛型方法一样没区别，一种是显式指定泛型参数，另一种是隐式推断，如果是显式指定则以显式指定的类型参数为准，如果传入的参数的类型和指定的类型实参不符，将会编译报错。
    ```
    public class Person {
        public <T> Person(T t) {
            System.out.println(t);
        }
    }
    ```
- 如何使用
    ```
    public static void main(String[] args){
        //隐式
        new Person(22);
        //显示
        new<String> Person("hello");
    }
    ```
- 这里唯一需要特殊注明的就是，
    - 如果构造器是泛型构造器，同时该类也是一个泛型类的情况下应该如何使用泛型构造器：因为泛型构造器可以显式指定自己的类型参数（需要用到菱形，放在构造器之前），而泛型类自己的类型实参也需要指定（菱形放在构造器之后），这就同时出现了两个菱形了，这就会有一些小问题，具体用法再这里总结一下。  
以下面这个例子为代表
    ```
    public class Person<E> {
        public <T> Person(T t) {
            System.out.println(t);
        }
    }
    ```
    - 这种用法：`Person<String> a = new <Integer>Person<>(15);`这种语法不允许，会直接编译报错！




## 03.泛型高级之通配符
### 3.1 为什么要使用通配符
* 通配符的设计存在一定的场景，例如在使用泛型后，首先声明了一个Animal的类，而后声明了一个继承Animal类的Cat类，显然Cat类是Animal类的子类，但是List<Cat>却不是List<Animal>的子类型，而在程序中往往需要表达这样的逻辑关系。为了解决这种类似的场景，在泛型的参数类型的基础上新增了通配符的用法。


### 3.2 <? extends T> 上界通配符
- 上界通配符顾名思义，<? extends T>表示的是类型的上界【**包含自身**】，因此通配的参数化类型可能是T或T的子类。
    - 正因为无法确定具体的类型是什么，add方法受限（可以添加null，因为null表示任何类型），但可以从列表中获取元素后赋值给父类型。如上图中的第一个例子，第三个add()操作会受限，原因在于List<Animal>和List<Cat>是List<? extends Animal>的子类型。
    ```
    它表示集合中的所有元素都是Animal类型或者其子类
    List<? extends Animal>
    ```
- 这就是所谓的上限通配符，使用关键字extends来实现，实例化时，指定类型实参只能是extends后类型的子类或其本身。 
    - 例如：
    - 这样就确定集合中元素的类型，虽然不确定具体的类型，但最起码知道其父类。然后进行其他操作。
    ```
    //Cat是其子类
    List<? extends Animal> list = new ArrayList<Cat>();
    ```


### 3.3 <? super T> 下界通配符
- 下界通配符<? super T>表示的是参数化类型是T的超类型（**包含自身**），层层至上，直至Object
    - 编译器无从判断get()返回的对象的类型是什么，因此get()方法受限。但是可以进行add()方法，add()方法可以添加T类型和T类型的子类型，如第二个例子中首先添加了一个Cat类型对象，然后添加了两个Cat子类类型的对象，这种方法是可行的，但是如果添加一个Animal类型的对象，显然将继承的关系弄反了，是不可行的。
    ``` java
    它表示集合中的所有元素都是Cat类型或者其父类
    List <? super Cat>
    ```
- 这就是所谓的下限通配符，使用关键字super来实现，实例化时，指定类型实参只能是extends后类型的子类或其本身。  
    - 例如：
    ```
    //Shape是其父类
    List<? super Cat> list = new ArrayList<Animal>();
    ```

### 3.6 <?> 和<T>的区别
- List<T>和List<?>的区别，这问的有点含糊。类型参数“<T>”和无界通配符“<?>”的区别吧？
- 讨论“<T>"和"<?>"，首先要区分开两种不同的场景：
    - 第一，声明一个泛型类或泛型方法。
    - 第二，使用泛型类或泛型方法。
    - 类型参数“<T>”主要用于第一种，声明泛型类或泛型方法。无界通配符“<?>”主要用于第二种，使用泛型类或泛型方法。
- <T>声明泛型类的类型参数
    - List<T>最应该出现的地方，应该是定义一个泛型List容器。但List是库里自带的容器，看看ArrayList的源码头一行：
    ```
    public class ArrayList<E> extends AbstractList<E> implements List<E>, RandomAccess, Cloneable, java.o.Serializable {
        ... ...
    }
    ```
    - ArrayList<E>中的“E”也是类型参数。只是表示容器中元素Element的时候，习惯用“E”。换一个简单的例子，我们自己定义一个新泛型容器叫Box<T>。
    ```
    class Box<T>{
        private T item1;
        private T item2;
    }
    ```
    - 为什么这里要用类型参数？因为这是一种”约束“，为了保证Box里的item1, item2都是同一个类型T。Box<String>，代表两个item都是String。Box<Integer>里两个item都是Integer。
    - List容器库里都帮我们写好了，所以我们是不会去定义List<T>的。那什么时候会出现List<T>？有几种情况，要么是作为泛型类的成员字段或成员方法的参数间接出现。还是刚才Box<T>的例子，
    ```
    class Box<T>{
        private List<T> item;
        public List<T> get(){return item;}
        public void set(List<T> t){item=t;}
    }
    ```
    - 现在Box类里有三个地方出现了List<T>：
        - 成员字段item的类型
        - get( )方法的返回值
        - set( )方法的参数
    - 这里写成List<T>为了表示和Box<T>类型参数保持一致。
- <T>声明泛型方法
    - 另外一种会出现List<T>的地方是泛型方法。
        - 比如Function类的reduce是个静态泛型方法，负责对列表里的所有元素求和。这里的List<T>出现在参数，函数返回值和函数内部，也是为了保持泛型类型的一致性。
    ```
    class Fuction{
        public static <T> List<T> reduce(List<T> list){
            //...do something
        }
    }
    ```
- 声明泛型类不能用无界通配符<?>
    - 反观List<?>，首先要明确通配符不能拿来声明泛型。像下面这样用通配符"?"来表示类型参数的约束是肯定不行的。
    ``` java
    //Error Example，这种不行
    class Box<?>{
        private ? item1;
        private ? item2;
    }
    ```
    - 通配符是拿来使用定义好的泛型的。比如用<?>声明List容器的变量类型，然后用一个实例对象给它赋值的时候就比较灵活。
    ```
    List<?> list = new ArrayList<String>();
    ```
- <?>的各种坑
    - 但List<?>这个写法非常坑。
        - 因为，这时候通配符会捕获具体的String类型，但编译器不叫它String，而是起个临时的代号，比如”CAP#1“。所以以后再也不能往list里存任何元素，包括String。唯一能存的就是null。
    ```
    List<?> list = new ArrayList<String>();
    
    list.add("hello");    //ERROR
    list.add(111);    //ERROR
    
    //argument mismatch; String cannot be converted to CAP#1
    //argument mismatch; int cannot be converted to CAP#1
    ```
    - 另外如果拿List<?>做参数，也会有奇妙的事情发生。还是刚才Box<T>的例子，有get()和set()两个方法，一个存，一个取。
    ```
    class Box<T>{
        private List<T> item;
        public List<T> get(){return item;}
        public void set(List<T> t){item=t;}
        //把item取出来，再放回去
        public void getSet(Box<?> box){box.set(box.get());}    //ERROR
    }
    ```
    - 新的getSet()方法，只是把item先用get()方法读出来，然后再用set()方法存回去。按理说不可能有问题。实际运行却会报错。
        - error: incompatible types: Object cannot be converted to CAP#1
        - 原因和前面一样，通配符box<?>.set()的参数类型被编译器捕获，命名为CAP#1，和box<?>.get()返回的Object对象无法匹配。
    - 解决方法，是要给getSet()方法写一个辅助函数，具体原理可以去查《Java核心技术-卷1》，泛型这章，或者《Java编程思想》。都有讲。
    ``` java
    class Box<T>{
        private List<T> item;
        public List<T> get(){return item;}
        public void set(List<T> t){item=t;}
        //helper()函数辅助getSet()方法存取元素
        public void getSet(Box<?> box){helper(box);}
        public <V> void helper(Box<V> box){box.set(box.get());}
    }
    ```
- 有界通配符<? extends XXX>，<? super XXX>
    - 实际更常用的是<? extends XXX>或者<? super XXX>两种，带有上下界的通配符。


## 04.泛型的设计原则

泛型的设计遵循以下原则：

1. **类型参数化**：通过类型参数（如 `T`）实现代码的通用性。
2. **编译时类型检查**：在编译时确保类型安全，避免运行时错误。
3. **代码复用**：减少重复代码，提高开发效率。
4. **类型推断**：编译器根据上下文自动推断类型，简化代码。
5. **向后兼容**：泛型与非泛型代码可以共存，确保旧代码的兼容性。


### 4.1 类型参数化
### 4.2 编译时类型检查
### 4.3 代码复用

泛型允许编写通用的代码，适用于多种数据类型，而不需要为每种类型编写重复的代码。

**示例：非泛型的重复代码**


## 05.理解泛型擦除

### 5.1 什么是泛型擦除

泛型的 **类型擦除（Type Erasure）** 是 Java 泛型实现的核心机制之一，它通过在编译时擦除泛型类型信息，确保与旧版本 Java 代码的兼容性。

然而，类型擦除也带来了一些限制，例如在运行时无法直接获取泛型类型参数。就是指编译器编译带类型说明的集合时会去掉“类型”信息

### 5.2 类型擦除原理

在 Java 中，泛型类型参数在编译时会被擦除，替换为 `Object` 或指定的上限类型。这是为了确保泛型代码与非泛型代码的兼容性。

**示例：类型擦除**

```java
class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}
```

编译后，`T` 会被替换为 `Object`：

```java
class Box {
    private Object value;
    public void set(Object value) { this.value = value; }
    public Object get() { return value; }
}
```

如果 `T` 有上限类型（如 `T extends Number`），则 `T` 会被替换为上限类型（如 `Number`）。

### 5.3 类型擦除影响

类型擦除导致以下限制：

1. **无法直接获取泛型类型参数**：在运行时，泛型类型信息被擦除，无法直接通过反射获取。
2. **无法创建泛型数组**：由于类型擦除，无法在运行时检查数组的类型安全。
3. **无法重载泛型方法**：泛型方法在类型擦除后可能具有相同的方法签名，导致编译错误。


### 5.4 泛型擦除案例

泛型是提供给javac编译器使用的，限定集合的输入类型，编译器编译带类型说明的集合时会去掉“类型”信息。

```java
public class GenericTest {
    public static void main(String[] args) {
        new GenericTest().testType();
    }

    public void testType(){
        ArrayList<Integer> collection1 = new ArrayList<Integer>();
        ArrayList<String> collection2= new ArrayList<String>();
        
        System.out.println(collection1.getClass()==collection2.getClass());
        //两者class类型一样,即字节码一致
        
        System.out.println(collection2.getClass().getName());
        //class均为java.util.ArrayList,并无实际类型参数信息
    }
}
```

输出日志如下：

```text
true
java.util.ArrayList
```

不管为泛型的类型形参传入哪一种类型实参，对于Java来说，它们依然被当成同一类处理，在内存中也只占用一块内存空间。

从Java泛型这一概念提出的目的来看，其只是作用于代码编译阶段，在编译过程中，对于正确检验泛型结果后，会将泛型的相关信息擦出，也就是说，成功编译过后的class文件中是不包含任何泛型信息的。泛型信息不会进入到运行时阶段。


### 5.5 获得泛型类型参数

把泛型变量当成方法的参数，利用Method类的getGenericParameterTypes方法来获取泛型的实际类型参数


1. 在子类中指定具体的泛型类型参数，然后通过反射获取父类的泛型类型信息。

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

class IntBox extends Box<Integer> {} // 子类指定具体类型

public class Main {
    public static void main(String[] args) {
        Type type = IntBox.class.getGenericSuperclass(); // 获取父类的泛型类型
        if (type instanceof ParameterizedType) {
            ParameterizedType pType = (ParameterizedType) type;
            Type[] actualTypeArguments = pType.getActualTypeArguments();
            System.out.println("泛型类型参数: " + actualTypeArguments[0]); // 输出: class java.lang.Integer
        }
    }
}
```

2. 在方法中传递泛型类型的实例，然后通过反射获取其类型信息。

```java
public class GenericTest {

    public static void main(String[] args) throws Exception {
        getParamType();
    }
    
     /*利用反射获取方法参数的实际参数类型*/
    public static void getParamType() throws NoSuchMethodException{
        Method method = GenericTest.class.getMethod("applyMap",Map.class);
        //获取方法的泛型参数的类型
        Type[] types = method.getGenericParameterTypes();
        System.out.println(types[0]);
        //参数化的类型
        ParameterizedType pType  = (ParameterizedType)types[0];
        //原始类型
        System.out.println(pType.getRawType());
        //实际类型参数
        System.out.println(pType.getActualTypeArguments()[0]);
        System.out.println(pType.getActualTypeArguments()[1]);
    }

    /*供测试参数类型的方法*/
    public static void applyMap(Map<Integer,String> map){

    }
}
```

输出结果：

```text
java.util.Map<java.lang.Integer, java.lang.String>
interface java.util.Map
class java.lang.Integer
class java.lang.String
```






## 06.泛型的使用限制
### 6.1模糊性错误
- 对泛型类 User< T, K > 而言，声明了两个泛型类参数：T 和 K。在类中试图根据类型参数的不同重载 set() 方法。这看起来没什么问题，可编译器会报错
    ```
    public class User<T, K> {
        
        //重载错误
        public void set(T t) {
            
        }
    
    	//重载错误
        public void set(K k) {
    
        }
    }
    ```
- 首先，当声明 User 对象时，T 和 K 实际上不需要一定是不同的类型，以下的两种写法都是正确的
    ```
    public class GenericMain {
        public static void main(String[] args) {
            User<String, Integer> stringIntegerUser = new User<>();
            User<String, String> stringStringUser = new User<>();
        }
    }
    ```
    - 对于第二种情况，T 和 K 都将被 String 替换，这使得 set() 方法的两个版本完全相同，所以会导致重载失败。
- 此外，对 set() 方法的类型擦除会使两个版本都变为如下形式：[博客](https://github.com/yangchong211/YCBlogs)
    - 一样会导致重载失败
    ```
    public void set(Object o) {
        
    }
    ```


### 6.2 不能实例化类型参数
- 不能创建类型参数的实例。因为编译器不知道创建哪种类型的对象，T 只是一个占位符
    ```
    public class User<T> {
    
        private T t;
    
        public User() {
            //错误
            t = new T();
        }
    }
    ```



## 6.3 对静态成员的限制
- 静态成员不能使用在类中声明的类型参数，但是可以声明静态的泛型方法
    ```
    public class User<T> {
    
        //错误
        private static T t;
    
        //错误
        public static T getT() {
            return t;
        }
    
        //正确
        public static <K> void test(K k) {
    
        }
    }
    ```



### 6.4 对泛型数组的限制
- 不能实例化元素类型为类型参数的数组，但是可以将数组指向类型兼容的数组的引用
    ```
    public class User<T> {
    
        private T[] values;
    
        public User(T[] values) {
            //错误，不能实例化元素类型为类型参数的数组
            this.values = new T[5];
            //正确，可以将values 指向类型兼容的数组的引用
            this.values = values;
        }
    }
    ```
- 此外，不能创建特定类型的泛型引用数组，但使用通配符的话可以创建指向泛型类型的引用的数组
    ```
    public class User<T> {
    
        private T[] values;
    
        public User(T[] values) {
            this.values = values;
        }
    }
    
    
    public class GenericMain {
    
        public static void main(String[] args) {
            //错误，不能创建特定类型的泛型引用数组
            User<String>[] stringUsers = new User<>[10];
            //正确，使用通配符的话，可以创建指向泛型类型的引用的数组
            User<?>[] users = new User<?>[10];
        }
    }
    ```



### 6.5对泛型异常的限制
- 泛型类不能扩展 Throwable，意味着不能创建泛型异常类
