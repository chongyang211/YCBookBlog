## 1.为何要浮点数

### 1.1 浮点数由来

计算机只有有限的位（32/64位），要表示的数却是无限的（实数连续统）。整数只能表示离散点，科学计算需要表示极大（`6.02×10²³`）和极小（`1.6×10⁻¹⁹`）的数。

**核心矛盾**：用有限的位表示无限精度的实数 → **必然有精度损失**。浮点数的设计就是在有限位数下，最大化可表示范围和精度。

## 2.IEEE754标准

IEEE754标准——所有语言的共同基础

1985 年制定，几乎所有现代 CPU 和语言都遵循。**Java float、C double、JS number、C++ float/double 底层完全一样。**

### 2.1 存储结构

```
单精度 float (32位):
┌─────┬──────────┬───────────────────────────┐
│ 符号 │  指数(8位) │       尾数(23位)           │
│ 1bit │  Exponent │       Mantissa            │
└─────┴──────────┴───────────────────────────┘

双精度 double (64位):
┌─────┬───────────┬────────────────────────────────────────────────────┐
│ 符号 │ 指数(11位) │                  尾数(52位)                        │
│ 1bit │  Exponent  │                  Mantissa                        │
└─────┴───────────┴────────────────────────────────────────────────────┘
```

### 2.2 值的计算公式

```
值 = (-1)^S × 1.M × 2^(E - bias)

S = 符号位 (0正1负)
M = 尾数 (二进制小数)
E = 指数 (无符号整数)
bias = 127 (float) / 1023 (double)
```

**关键设计**：尾数隐含一个前导 `1`（规格化数），相当于**免费多了1位精度**。`1.M` 中的 `1` 不存储。

### 2.3 0.1的存储

实例：`0.1`的存储

```
0.1 (十进制)

转二进制: 0.1 = 0.0001100110011001100110011... (无限循环!)

float存储 (23位尾数截断):
  符号: 0
  指数: 01111011 (= 123, 实际指数 = 123 - 127 = -4)
  尾数: 10011001100110011001101 (最后一位进位)

实际值: 0.100000001490116119384765625...
误差:   +1.49 × 10⁻⁸
```

**这就是 `0.1 + 0.2 ≠ 0.3` 的根本原因——十进制小数在二进制中可能是无限循环。**

## 3.五类特殊值

### 3.1 特殊情况

IEEE 754 用指数的全 0 和全 1 编码了特殊情况：

| 指数 | 尾数 | 含义 | 设计目的 |
|------|------|------|---------|
| 全 0 | 全 0 | **±0** | 正零和负零（`+0 == -0` 但 `1/+0 = +∞`, `1/-0 = -∞`） |
| 全 0 | 非 0 | **非规格化数** | 填补 0 和最小规格化数之间的间隙（渐进下溢） |
| 全 1 | 全 0 | **±∞** | 溢出的确定性结果（`1.0/0.0 = +∞`） |
| 全 1 | 非 0 | **NaN** | 非法运算的结果（`0.0/0.0`, `√(-1)`） |
| 其他 | 任意 | **规格化数** | 正常浮点数 |

### 3.2 NaN特殊行为

```
NaN ≠ NaN        // 唯一一个不等于自身的值！
NaN + x = NaN    // 任何运算传播NaN
NaN > 1 = false  // 任何比较返回false
NaN == NaN = false
```

**设计哲学**：NaN 是"毒药"，一旦产生就污染整个计算链，强迫程序员处理它，而不是默默产生错误结果。
