## 1.线程背景说明

### 1.1 多道程序设计

**从单道批处理到多道程序**。早期计算机是**单道批处理**——CPU 一次只执行一个程序，I/O 时 CPU 完全空闲。

```
时间线：
[====CPU运算====][--------I/O等待--------][====CPU运算====]
                  ↑ CPU 在此完全空闲，利用率极低
```

**多道程序设计**引入了**进程（Process）**概念——操作系统可以同时加载多个程序，CPU 在一个进程等待 I/O 时切换到另一个进程。

### 1.2 进程的代价

进程解决了 CPU 利用率问题，但每个进程拥有**独立的地址空间**：

| 资源 | 开销 |
|------|------|
| 虚拟内存页表 | 每个进程独立，切换需刷新 TLB |
| 文件描述符表 | 独立副本 |
| 信号处理表 | 独立副本 |
| 堆、数据段 | 独立副本 |

进程间通信（IPC）需要经过内核态：管道、消息队列、共享内存、Socket……代价高昂。

**核心矛盾**：很多时候一个程序内部需要并发（如 Web 服务器同时处理多个请求），如果每个并发单元都是独立进程，创建/销毁/切换/通信的开销太大。

### 1.3 线程的诞生

**线程（Thread）= 轻量级进程**，核心思想：

> **共享进程的地址空间和资源，仅独立维护执行流所必需的最小状态。**

```
┌─────────────── 进程 ───────────────┐
│  代码段（共享）                      │
│  数据段/堆（共享）                   │
│  文件描述符（共享）                  │
│  信号处理（共享）                    │
│                                     │
│  ┌─Thread 1─┐  ┌─Thread 2─┐       │
│  │ 栈        │  │ 栈        │       │
│  │ PC寄存器  │  │ PC寄存器  │       │
│  │ 线程局部  │  │ 线程局部  │       │
│  │ 状态      │  │ 状态      │       │
│  └──────────┘  └──────────┘       │
└─────────────────────────────────────┘
```

**线程独有的最小状态**：

- **程序计数器（PC）**：当前执行到哪条指令
- **寄存器集合**：CPU 寄存器的快照
- **栈（Stack）**：函数调用链、局部变量
- **线程局部存储（TLS）**：线程私有数据
