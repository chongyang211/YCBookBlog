## 01.并发编程挑战

### 1.1 核心挑战

- **数据竞争**：多个线程同时访问共享数据
- **原子性**：操作的不可分割性
- **可见性**：一个线程对共享变量的修改对其他线程的可见性
- **有序性**：程序执行的顺序性保证

## 02.多线程脏数据

为什么会出现脏数据？脏数据的产生主要源于以下几个方面：

### 2.1 CPU缓存一致性

```mermaid
graph TB
    subgraph "CPU架构"
        CPU1[CPU Core 1]
        CPU2[CPU Core 2]
        L1_1[L1 Cache]

        CPU1 --> L1_1
        CPU2 --> L1_2
        L1_1 --> L2
        L1_2 --> L2
        L2 --> L3
        L3 --> RAM
    end
```

### 2.2 指令重排序

```mermaid
sequenceDiagram
    participant T1 as 线程1
    participant T2 as 线程2
    participant Memory as 内存
    
    Note over T1,T2: 原始代码顺序
    T1->>Memory: x = 1
    T1->>Memory: flag = true
    T2->>Memory: if(flag) print(x)
    
    Note over T1,T2: 重排序后可能的执行顺序
    T1->>Memory: flag = true
    T2->>Memory: if(flag) print(x) // 可能打印0
    T1->>Memory: x = 1
```

### 2.3 原子性缺失

多步操作在执行过程中被其他线程中断，导致数据不一致。
