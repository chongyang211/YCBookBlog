## 5. 不同语言中的实现

### 5.1 Java虚拟机

Java中的类加载器层次结构：
- **Bootstrap ClassLoader**（引导类加载器）：加载核心类库
- **Extension ClassLoader**（扩展类加载器）：加载扩展类库
- **Application ClassLoader**（应用类加载器）：加载应用程序类
- **Custom ClassLoader**（自定义类加载器）：用户自定义的加载器

### 5.2 .NET Framework

.NET中的程序集加载机制：
- **GAC（Global Assembly Cache）**：全局程序集缓存
- **Application Domain**：应用程序域级别的加载
- **Assembly.LoadFrom/LoadFile**：自定义加载方式

### 5.3 Python模块系统

Python的模块导入机制：
- **Built-in modules**：内置模块
- **Standard library**：标准库模块
- **Third-party packages**：第三方包
- **Local modules**：本地模块

### 5.4 Node.js模块系统

Node.js的require机制：
- **Core modules**：核心模块
- **node_modules**：依赖模块
- **Relative/Absolute paths**：相对/绝对路径模块

## 6. 实现示例

### 6.1 Java实现示例

```java
public class CustomClassLoader extends ClassLoader {
    
    @Override
    protected Class<?> loadClass(String name, boolean resolve) 
            throws ClassNotFoundException {
        
        // 1. 检查类是否已经加载
        Class<?> clazz = findLoadedClass(name);
        if (clazz != null) {
            return clazz;
        }
        
        // 2. 委派给父加载器
        try {
            if (getParent() != null) {
                clazz = getParent().loadClass(name);
            } else {
                clazz = findBootstrapClassOrNull(name);
            }
        } catch (ClassNotFoundException e) {
            // 父加载器无法加载
        }
        
        // 3. 如果父加载器无法加载，自己尝试加载
        if (clazz == null) {
            clazz = findClass(name);
        }
        
        // 4. 如果需要解析，则解析类
        if (resolve) {
            resolveClass(clazz);
        }
        
        return clazz;
    }
    
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        // 自定义的类查找和加载逻辑
        byte[] classData = loadClassData(name);
        return defineClass(name, classData, 0, classData.length);
    }
}
```

### 6.2 C++实现示例

```cpp
class ModuleLoader {
private:
    std::shared_ptr<ModuleLoader> parent;
    std::unordered_map<std::string, std::shared_ptr<Module>> loadedModules;
    
public:
    std::shared_ptr<Module> loadModule(const std::string& name) {
        // 1. 检查是否已加载
        auto it = loadedModules.find(name);
        if (it != loadedModules.end()) {
            return it->second;
        }
        
        // 2. 委派给父加载器
        if (parent) {
            try {
                auto module = parent->loadModule(name);
                if (module) {
                    return module;
                }
            } catch (const ModuleNotFoundException& e) {
                // 父加载器无法加载，继续执行
            }
        }
        
        // 3. 自己尝试加载
        auto module = findModule(name);
        if (module) {
            loadedModules[name] = module;
            return module;
        }
        
        throw ModuleNotFoundException("Module not found: " + name);
    }
    
protected:
    virtual std::shared_ptr<Module> findModule(const std::string& name) = 0;
};
```

## 7. 优势与局限性

### 7.1 优势

1. **安全性高**：防止核心类被恶意替换
2. **性能优化**：避免重复加载，节省内存
3. **结构清晰**：层次化的加载结构便于管理
4. **扩展性好**：可以方便地添加自定义加载器
5. **一致性强**：保证系统行为的可预测性

### 7.2 局限性

1. **灵活性限制**：某些场景下可能需要打破双亲委派
2. **性能开销**：委派过程可能带来额外的性能开销
3. **复杂性增加**：增加了系统的复杂性
4. **调试困难**：问题定位可能变得复杂

## 8. 最佳实践

### 8.1 设计原则

1. **明确职责**：每个加载器应该有明确的职责范围
2. **避免循环依赖**：防止加载器之间形成循环依赖
3. **异常处理**：合理处理加载失败的情况
4. **缓存策略**：实现有效的缓存机制

### 8.2 使用建议

1. **谨慎打破**：只在必要时才打破双亲委派机制
2. **文档记录**：详细记录自定义加载器的行为
3. **测试覆盖**：确保加载逻辑的正确性
4. **性能监控**：监控加载性能，及时优化
