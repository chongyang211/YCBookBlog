## 1.轮询业务背景

### 1.1 了解业务背景

在现代软件系统中，轮询是一种重要的通信和状态检测机制，主要应用于以下场景：

实时推送，使用轮询的方式可以实现实时推送功能。当客户端连接到服务器之后，服务器就可以通过轮询不断的向客户端推送实时消息。

监控系统，实现监控系统的功能。当需要监控某个系统的状态时，可以使用轮询不断的查询该系统的状态信息，并及时的进行预防措施，或者做数据上报操作。用轮询！

二维码扫码，比如超市的支付硬件设备，会一直轮训扫码。当你靠近二维码支付的时候，就立马读取到二维码数据进行支付。用轮询！

即时通信聊天，比如你跟某个人聊天，这个时候你们两个之间的通信，则会使用建立长链接。用心跳！

### 1.2 什么是轮询

轮询是一种主动查询机制，客户端定期向服务器发送请求以获取最新状态或数据。

简单理解比如：App 端每隔一段时间上报一次定位信息，App 端每隔一段时间拉去一次用户状态等，这些应该都是轮询请求。

轮询的特点

- **主动性**：客户端主动发起请求
- **周期性**：按照固定或动态间隔执行
- **拉取模式**：从服务器拉取数据
- **状态查询**：获取当前最新状态

> 轮询的类型

**1. 短轮询（Short Polling）**
```
Client                    Server
  |                         |
  |-------- Request ------->|
  |<------- Response -------|
  |                         |
  |-- Wait (固定间隔) -------|
  |                         |
  |-------- Request ------->|
  |<------- Response -------|
```

**2. 长轮询（Long Polling）**

```
Client                    Server
  |                         |
  |-------- Request ------->|
  |                         | (服务器保持连接)
  |                         | (等待数据变化)
  |<------- Response -------|
  |                         |
  |-------- Request ------->| (立即发起下一次请求)
```

### 1.3 什么是心跳

心跳的应用场景：场景有推送，统计，即时通讯。采用socket进行长连接，客户端和服务端双向推送消息。

心跳是一种保活机制，用于维持连接状态和检测对端是否存活。心跳的特点

- **保活性**：维持连接不被断开
- **检测性**：检测对端是否正常
- **轻量级**：数据包通常很小
- **双向性**：可以是单向或双向


## 2.心跳VS轮询

- 心跳与轮询的区别
  - 主机在检查与从机之间的连接（判断与从机之间的连接是否断开）时，一般有心跳与轮询这两种方式。这两个方式都需要主机定时逐个查询从机的状态，但它们查询的策略有所不同。
- 轮询
  - 在轮询方式中，主机逐个查询的方式是主动向从机发送一条查询信息，然后根据从机的应答情况来判断从机的状态。
  - 比方说，主机要求从机返回一个状态码来代表当前从机所处的状态，但如果从机没有应答，就认为与从机之间的连接已经断开。
- 心跳
  - 在心跳方式中，主机逐个查询的方式是直接从一种状态信息表中查询，此状态信息表上记录了所有从机的状态信息，而此状态信息表是由各个从机自己主动去更新的。
  - 如果有从机长期没有去更新此表，就认为与该从机之间的连接已经断开。

### 2.1 功能对比

| 特性 | 轮询 | 心跳 |
|------|------|------|
| **主要目的** | 获取数据/状态 | 保持连接/检测存活 |
| **数据传输** | 业务数据 | 控制信息 |
| **频率** | 相对较低 | 相对较高 |
| **网络开销** | 较大 | 较小 |
| **实时性** | 取决于轮询间隔 | 高实时性 |
| **复杂度** | 相对简单 | 需要状态管理 |

### 2.2 使用场景对比

轮询适用场景

- **数据同步**：定期获取服务器最新数据
- **状态查询**：查询任务执行进度
- **批量处理**：定期处理积累的数据
- **非实时业务**：对实时性要求不高的场景

心跳适用场景

- **连接保活**：防止NAT超时或防火墙断开
- **故障检测**：快速发现网络或服务异常
- **负载均衡**：维持服务器连接池
- **实时通信**：WebSocket、长连接等

## 3.轮询执行角度

### 3.1 固定速率执行

固定速率执行是指任务按照固定的时间间隔启动，不管上一次任务是否完成。

特点

- **启动间隔固定**：每次任务启动的时间间隔是固定的
- **可能并发**：如果任务执行时间超过间隔，可能出现并发执行
- **时间漂移小**：长期运行不会出现时间累积误差

执行时序图

```text
时间轴: 0----5----10----15----20----25----30
任务1:  |====|
任务2:       |========|
任务3:                |====|
任务4:                     |====|
任务5:                          |========|
```

适用场景

- **数据采集**：需要精确时间间隔的传感器数据采集
- **性能监控**：系统性能指标的定期采集
- **实时性要求高**：对时间精度要求较高的场景

### 3.2 固定延迟执行

固定延迟执行是指在上一次任务完成后，等待固定时间再启动下一次任务。

特点

- **完成后延迟**：任务完成后才开始计算下次执行时间
- **无并发风险**：不会出现同一任务的并发执行
- **时间可能漂移**：长期运行可能出现时间累积误差

执行时序图

```
时间轴: 0----5----10----15----20----25----30
任务1:  |====|
任务2:       |-----|========|
任务3:                      |-----|====|
任务4:                               |-----|====|
说明:   |====| 表示任务执行
        |-----| 表示固定延迟等待
```

适用场景

- **资源密集型任务**：避免系统过载
- **依赖性任务**：后续任务依赖前一任务的结果
- **错误恢复**：任务失败后需要等待一段时间再重试

### 3.3 选择建议

选择固定速率执行的情况

- **时间精度要求高**：如数据采集、监控指标
- **任务执行时间稳定**：任务执行时间相对固定且较短
- **实时性要求**：需要保证执行频率的一致性

选择固定延迟执行的情况

- **任务执行时间不确定**：如网络请求、文件处理
- **避免系统过载**：防止任务堆积导致系统压力过大
- **错误恢复场景**：任务失败后需要等待再重试


## 4.Java设计思路

### 4.0 实现轮训思路

- 具体有哪些可以实现轮训执行任务的操作
  - 第一种方案：使用Thread.sleep实现轮询。一直做while循环
  - 第二种方案：使用ScheduledExecutorService实现轮询
  - 第三种方案：使用Timer实现定时性周期性任务轮训
  - 第四种方案：使用Handler不断发送消息来实现轮训
- 从轮询执行角度分析任务执行类型
  - 第一种属于固定速率执行，每个执行都相对于初始执行的计划执行时间进行调度。如果由于任何原因而延迟执行，则两个或更多执行将快速连续发生以“赶上”。
  - 第二种属于固定延迟执行，每个执行都相对于前一次执行的实际执行时间进行调度。如果由于任何原因延迟执行，后续执行也将被延迟。
- 每一种方案对应的执行类型说明
  - 第一种，第四种：是属于固定延迟执行
  - 第二种，第三种：是属于固定速率执行

### 4.1 Thread.sleep实现轮询

简单来说，写一个线程执行while死循环操作。然后使用sleep让当前线程睡眠，然后执行任务操作。

```java
public void simplePolling() {
    while (true) {
        try {
            // 线程睡眠1秒钟
            Thread.sleep(1000);
            // 轮询的代码
            System.out.println("polling...");
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}
```

### 4.2 ScheduledExecutorService实现轮询

通过创建ScheduledExecutorService线程池实现轮询，scheduleAtFixedRate方法会在0秒后开始轮询，并且每隔1秒进行轮询。

```java
public void scheduledPolling() {
    ScheduledExecutorService scheduledExecutorService = Executors.newScheduledThreadPool(1);
    // 固定速率执行
    scheduledExecutorService.scheduleAtFixedRate(() -> {
        // 轮询的代码
        System.out.println("polling...");
    }, 0, 1, TimeUnit.SECONDS);
}
```

支持动态间隔

```java
public void scheduledPolling() {
    ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
    scheduler.schedule(() -> {
        try {
            performPolling();
        } catch (Exception e) {
            System.err.println("轮询异常: " + e.getMessage());
        } finally {
            // 递归调度下一次执行
            scheduledPolling();
        }
    }, currentInterval, TimeUnit.SECONDS);
}

private void performPolling() {
    System.out.println("执行轮询，当前间隔: " + currentInterval + "秒");
    // 根据业务逻辑动态调整间隔
    if (isSystemBusy()) {
        currentInterval = Math.min(currentInterval * 2, 300); // 最大5分钟
    } else {
        currentInterval = Math.max(currentInterval / 2, 10);  // 最小10秒
    }
}
```

### 4.3 Timer实现轮训

使用timer定时执行TimerTask，然后开始延迟轮询操作

```java
timer = new Timer();
timer.schedule(new CommitTimer(), 0, getSleepTime());
private class CommitTimer extends TimerTask {
    @Override
    public void run() {
        // 轮询的代码
        doAction();
    }
}
```

**特点**：1.单线程执行所有任务；2.任务异常会影响后续任务；3.不推荐在生产环境使用

**优点**：1.使用简单；2.内存占用小

**缺点**：1.单线程，任务阻塞会影响其他任务；2.异常处理不友好；3.不支持线程池

### 4.4 使用Handler不断发送消息来实现轮训

在HandleMessage方法中执行任务，任务结束后向MessageQueue中添加延时消息。

```java
HandlerThread handlerThread = new HandlerThread("LooperThread");
handlerThread.start();
handler = new Handler(handlerThread.getLooper()) {
    @Override
    public void handleMessage(Message msg) {
        super.handleMessage(msg);
        if (msg.what == MSG_GET_COMPARE_RESULT) {
            // 轮询的代码
            doAction();
            //向MessageQueue中添加延时消息，后重复执行以上任务
            handler.sendEmptyMessageDelayed(MSG_GET_COMPARE_RESULT, getSleepTime());
        }
    }
};
```

### 4.7 各种方式区别

- 使用Thread.sleep实现轮询
  - 使用Thread.sleep实现轮询，当销毁之后，没有办法再次开始循环，因为线程interrupt，线程死亡。再次使用需要新创建线程对象！
- 使用ScheduledExecutorService实现轮询
  - 使用ScheduledExecutorService线程池实现轮训，销毁之后还是可以再次开始循环操作。
- 使用Timer实现定时性周期性任务轮训
  - 使用timer定时执行TimerTask，如果有异步任务，下次任务开始执行时需要判断上次任务是否完成，从而导致任务间隔时间不可控。
- 使用Handler不断发送消息来实现轮训
  - 如果有异步任务，只需在异步任务执行完毕后再向MessageQueue中添加延时消息，任务间隔时间可控。性能开销相对很低！
- 使用Service服务和闹钟AlarmManager实现轮询
  - 开启一个Service,这样消耗显而易见，在app内存持续暴涨情况下这个服务又被kill的可能。
  - 可以把Service声明成进程，以及提高到前台，也可以采用广播来启动，但逃不过第三方安全软件kill的可能


## 5.C++实现轮询

### 5.1 std::thread实现轮训

通过一个独立的线程（polling_thread_）定期执行任务（task_）。 变量 running_ 控制线程的运行状态，确保线程可以安全地启动和停止。

在每次任务执行后，通过 std::this_thread::sleep_for 实现睡眠。

```cpp
void PollerThread::start() {
    if (running_.exchange(true)) {
        // 避免重复运行
        return;
    }
    polling_thread_ = std::thread([this] {
        // 通过开关控制轮训是否进行或者停止
        while (running_.load()) {
            // 执行任务。这里是阻塞式的
            task_();
            // 通过休眠设置间隔。这里可以根据业务动态调整事件
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
        }
    });
}
```

### 5.2 thread多任务轮询

多线程任务轮询，即通过多个线程并行执行多个任务，每个线程负责定期执行一个任务。

1. 多线程并行：通过 std::vector<std::thread> 管理所有线程。每个任务由一个独立的线程执行，线程之间互不干扰。
2. 任务轮询：每个线程在一个循环中不断执行任务，并通过 std::this_thread::sleep_for 实现轮询间隔。
3. 线程状态控制：当 running_ 为 true 时，线程继续执行任务；当 running_ 为 false 时，线程退出循环。
4. 线程安全：使用原子变量 running_ 确保线程状态的读写是线程安全的。在 stop() 方法中，通过 join() 确保所有线程正确结束。

```cpp
class MultiTaskPolling {
private:
    std::vector<std::thread> threads_;       // 线程池
    std::atomic<bool> running_{false};       // 控制所有线程的运行状态
    std::vector<std::function<void()>> tasks_; // 任务列表
    std::chrono::milliseconds interval_;     // 轮询间隔

public:
    MultiTaskPolling(std::chrono::milliseconds interval, std::vector<std::function<void()>> tasks)
        : interval_(interval), tasks_(std::move(tasks)) {}

    ~MultiTaskPolling() {
        stop();
    }

    // 启动所有任务轮询
    void start() {
        if (running_.exchange(true)) return; // 已经在运行
        for (size_t i = 0; i < tasks_.size(); ++i) {
            threads_.emplace_back([this, i]() {
                while (running_.load()) {
                    tasks_[i](); // 执行任务
                    std::this_thread::sleep_for(interval_); // 轮询间隔
                }
            });
        }
    }

    // 停止所有任务轮询
    void stop() {
        running_.store(false);
        for (auto& thread : threads_) {
            if (thread.joinable()) thread.join();
        }
    }
};

// 示例任务函数
void task1() {
    std::cout << "任务1执行: " << 
        std::chrono::duration_cast<std::chrono::milliseconds>(
            std::chrono::system_clock::now().time_since_epoch()).count() 
        << std::endl;
}

void task2() {
    std::cout << "任务2执行: " << 
        std::chrono::duration_cast<std::chrono::milliseconds>(
            std::chrono::system_clock::now().time_since_epoch()).count() 
        << std::endl;
}

int main() {
    // 定义任务列表
    std::vector<std::function<void()>> tasks = {task1, task2};
    // 创建多任务轮询对象，设置轮询间隔为1秒
    MultiTaskPolling polling(std::chrono::seconds(1), tasks);
    // 启动轮询
    polling.start();
    // 主线程等待10秒
    std::this_thread::sleep_for(std::chrono::seconds(10));
    // 停止轮询
    polling.stop();
    return 0;
}
```

### 5.3 boost单任务轮询

基于boost::asio的实现，单任务异步轮询

```cpp
void scheduleNext() {
    if (!running_) return;
    timer_->expires_after(interval_);
    timer_->async_wait([this](boost::system::error_code ec) {
        if (!ec && running_) {
            executeTask();
            // 继续下一次调度
            scheduleNext();
        }
    });
}
```

### 5.6 实现方式的对比

| 实现方式 | 优点 | 缺点 | 适用场景 |
|----------|------|------|----------|
| **std::thread** | 简单直接，跨平台 | 资源占用大，扩展性差 | 简单轮询任务 |
| **boost::asio** | 异步高效，功能丰富 | 依赖boost库，学习成本高 | 高并发网络应用 |
| **epoll** | 性能极高，系统级优化 | 仅限Linux，实现复杂 | 高性能服务器 |
| **协程** | 代码简洁，内存效率高 | 需要C++20，生态不成熟 | 现代C++应用 |


## 6.轮训性能优化

### 6.1 关键性能指标

**时间相关指标**

- **执行延迟（Execution Latency）**：从触发时间到实际执行的延迟
- **执行时间（Execution Time）**：单次轮询任务的执行时间
- **时间精度（Time Precision）**：实际执行间隔与预期间隔的偏差
- **响应时间（Response Time）**：从数据变化到检测到变化的时间

**可靠性指标**

- **成功率**：轮询任务成功执行的比例
- **错误率**：轮询过程中出现错误的比例
- **可用性**：轮询服务的可用时间比例

### 6.2 减少轮询频率

**动态间隔调整**

```java
public void performPolling() {
    // 检查数据是否有变化
    boolean hasChanges = checkForChanges();
    if (hasChanges) {
        // 有变化，减少间隔
        consecutiveNoChanges = 0;
        currentInterval = Math.max(currentInterval / 2, minInterval);
    } else {
        // 无变化，增加间隔
        consecutiveNoChanges++;
        if (consecutiveNoChanges >= backoffThreshold) {
            currentInterval = Math.min(currentInterval * 2, maxInterval);
        }
    }
}
```
