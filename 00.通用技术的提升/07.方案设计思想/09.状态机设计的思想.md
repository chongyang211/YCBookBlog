## 1.什么是状态机

### 1.1 一句话概括

状态机（State Machine）是一种数学模型，用于描述系统在不同状态之间的转换行为。它是一种抽象的计算模型，能够精确描述系统在任意时刻的状态以及状态之间的转换条件。

状态机就是一个“智能开关”，它根据当前的状态和输入，按照预定的规则决定下一步该做什么。它把复杂的行为分解成简单的状态和规则，让系统更清晰、更可控。

### 1.2 订单状态机

想象一下，你在网上买了一件商品，订单会经历多个状态，比如：

1. **待支付**：你刚下单，但还没付钱。
2. **已支付**：你付了钱，商家准备发货。
3. **已发货**：商家把商品寄出了，正在运输中。
4. **已收货**：你收到了商品。
5. **已完成**：你确认收货，订单完成。
6. **已取消**：你取消了订单。

这些状态之间的切换是由你的操作（输入）触发的，比如付款、取消订单、确认收货等。

订单状态机就是一个“智能流程管理器”，它根据订单的当前状态和你的操作，决定订单的下一个状态。比如：

- 你支付了钱，订单从“待支付”变成“已支付”。
- 你取消了订单，订单变成“已取消”。

### 1.3 状态机定义

状态机是一种数学模型，用于描述系统在不同状态之间的行为。它由以下核心组件构成：

1. **状态（State）**：系统当前所处的“模式”或“情况”。订单的当前阶段，比如“待支付”、“已支付”等。
2. **事件（Event）**：触发状态变化的输入或动作。比如“支付”、“取消订单”、“确认收货”等。
3. **转换（Transition）**：状态之间的切换规则，从一个状态到另一个状态的变化。比如“支付”事件会将订单从“待支付”切换到“已支付”。
4. **动作（Action）**：在状态转换时执行的操作。比如发送发货通知、更新库存等。

### 1.4 状态机类型

状态机主要分为两类：

1. **有限状态机（Finite State Machine, FSM）**： 系统状态的数量是有限的。例如，交通信号灯的状态（红、黄、绿）。
2. **无限状态机（Infinite State Machine）**：系统状态的数量是无限的。例如，计数器的状态（理论上可以无限增加）。

### 1.6 状态机流程

**订单状态机的完整流程**

1. **初始状态：待支付**
  - **事件**：用户支付。
  - **转换**：待支付 → 已支付。
  - **动作**：更新状态为“已支付”，发送支付成功通知。

2. **状态：已支付**
  - **事件**：商家发货。
  - **转换**：已支付 → 已发货。
  - **动作**：更新状态为“已发货”，发送发货通知。

3. **状态：已发货**
  - **事件**：用户确认收货。
  - **转换**：已发货 → 已收货。
  - **动作**：更新状态为“已收货”，发送确认收货通知。

4. **状态：已收货**
  - **事件**：用户确认订单完成。
  - **转换**：已收货 → 已完成。
  - **动作**：更新状态为“已完成”，记录交易完成。

5. **状态：已取消**
  - **事件**：用户取消订单，或支付超时。
  - **转换**：待支付 → 已取消。
  - **动作**：更新状态为“已取消”，释放库存。


## 2.来看一个案例

### 2.1 业务的需求

场景：订单有多个状态，包括：待支付、已支付、已发货、已收货、已完成、已取消。

订单状态转换规则：

```text
待支付 -> 已支付（支付）
已支付 -> 已发货（发货）
已发货 -> 已收货（确认收货）
已收货 -> 已完成（完成订单）
待支付 -> 已取消（取消订单）
已支付 -> 已取消（取消订单，需退款）
```

### 2.2 无状态机实现

```java
/**
 * 不使用状态机的订单服务
 * 问题：大量if-else判断，状态逻辑分散，难以维护和扩展
 */
public class SimpleOrderServiceWithoutStateMachine {

    public enum OrderStatus {
        PENDING, PAID, SHIPPED, RECEIVED, COMPLETED, CANCELLED
    }

    static class Order {
        private String orderId;
        private OrderStatus status;
        private double amount;

        public Order(String orderId, double amount) {
            this.orderId = orderId;
            this.amount = amount;
            this.status = OrderStatus.PENDING;
        }

        // getters and setters
        public String getOrderId() { return orderId; }
        public OrderStatus getStatus() { return status; }
        public void setStatus(OrderStatus status) { this.status = status; }
        public double getAmount() { return amount; }
    }

    public class OrderService {
        /**
         * 支付订单 - 充满if-else的实现
         */
        public boolean payOrder(Order order, double amount) {
            // 状态检查逻辑分散在各个方法中
            if (order.getStatus() != OrderStatus.PENDING) {
                System.out.println("订单状态不是待支付，无法支付");
                return false;
            }
            if (amount < order.getAmount()) {
                System.out.println("支付金额不足");
                return false;
            }
            // 业务逻辑处理
            System.out.println("处理支付...");
            order.setStatus(OrderStatus.PAID);
            System.out.println("支付成功，状态: " + order.getStatus());
            return true;
        }

        /**
         * 发货订单 - 重复的状态检查模式
         */
        public boolean shipOrder(Order order) {
            if (order.getStatus() != OrderStatus.PAID) {
                System.out.println("订单状态不是已支付，无法发货");
                return false;
            }
            System.out.println("处理发货...");
            order.setStatus(OrderStatus.SHIPPED);
            System.out.println("发货成功，状态: " + order.getStatus());
            return true;
        }

        /**
         * 取消订单 - 复杂的多状态处理逻辑
         */
        public boolean cancelOrder(Order order) {
            OrderStatus currentStatus = order.getStatus();
            // 根据不同状态执行不同逻辑 - 状态转换逻辑分散
            if (currentStatus == OrderStatus.PENDING) {
                System.out.println("取消待支付订单");
                order.setStatus(OrderStatus.CANCELLED);
                return true;
            } else if (currentStatus == OrderStatus.PAID) {
                System.out.println("取消已支付订单，需要退款");
                // 退款逻辑
                order.setStatus(OrderStatus.CANCELLED);
                return true;
            } else if (currentStatus == OrderStatus.SHIPPED) {
                System.out.println("取消已发货订单，需要拦截物流");
                // 拦截物流逻辑
                order.setStatus(OrderStatus.CANCELLED);
                return true;
            } else {
                System.out.println("当前状态不能取消: " + currentStatus);
                return false;
            }
        }

        /**
         * 确认收货
         */
        public boolean confirmReceipt(Order order) {
            if (order.getStatus() != OrderStatus.SHIPPED) {
                System.out.println("订单状态不是已发货，无法确认收货");
                return false;
            }
            System.out.println("确认收货...");
            order.setStatus(OrderStatus.RECEIVED);
            System.out.println("确认收货成功，状态: " + order.getStatus());
            return true;
        }
    }

    public static void main(String[] args) {
        SimpleOrderServiceWithoutStateMachine demo = new SimpleOrderServiceWithoutStateMachine();
        OrderService service = demo.new OrderService();
        System.out.println("=== 不使用状态机的订单服务 ===");
        // 创建订单
        Order order = new Order("ORDER001", 100.0);
        System.out.println("创建订单，初始状态: " + order.getStatus());
        // 正常流程
        service.payOrder(order, 100.0);
        service.shipOrder(order);
        // 尝试非法操作：已发货状态下支付
        System.out.println("\n尝试非法操作：");
        service.payOrder(order, 100.0);  // 应该失败
        service.confirmReceipt(order);
        System.out.println("\n最终状态: " + order.getStatus());
    }
}
```

无状态机版本的问题分析：

1. 代码重复：每个方法都有相同的空值检查和状态检查
2. 逻辑分散：状态转换规则分散在各个方法中
3. 难以扩展：新增状态或操作需要修改多个方法
4. 容易出错：条件判断复杂，容易遗漏边界情况
5. 难以测试：每个方法都有一堆前置条件

### 2.3 有状态机实现

#### 2.3.1 状态 (States)设计

订单的状态是订单当前所处的阶段，包括：

- **待支付**：订单已创建，但用户还未支付。
- **已支付**：用户已支付，商家准备发货。
- **已发货**：商家已发货，商品在运输中。
- **已收货**：用户已收到商品。
- **已完成**：用户确认收货，订单完成。
- **已取消**：订单被取消。

```java
public enum OrderState {
    PENDING,       // 待支付 - 初始状态
    PAID,          // 已支付 - 中间状态
    SHIPPED,       // 已发货 - 中间状态  
    RECEIVED,      // 已收货 - 中间状态
    COMPLETED,     // 已完成 - 终态
    CANCELLED      // 已取消 - 终态
}
```

**状态分类：**

- **初始状态**：`PENDING` - 订单创建时的默认状态
- **中间状态**：`PAID`, `SHIPPED`, `RECEIVED` - 可以继续转换的状态
- **终态**：`COMPLETED`, `CANCELLED` - 不能再转换的最终状态

**状态特征：**

- 每个状态代表订单在业务流程中的一个阶段
- 状态是互斥的，订单在任意时刻只能处于一个状态
- 状态具有业务含义，反映订单的当前处理阶段


#### 2.3.2 事件 (Events)设计

事件是触发状态变化的用户操作或系统行为，包括：

- **支付**：用户完成支付。
- **发货**：商家发货。
- **收货**：用户确认收到商品。
- **取消**：用户或商家取消订单。
- **超时**：支付超时，订单自动取消。

```java
public enum OrderEvent {
    PAY,            // 支付事件 - 触发支付流程
    SHIP,           // 发货事件 - 触发发货流程
    CANCEL,         // 取消事件 - 触发取消流程
    CONFIRM_RECEIPT,// 确认收货事件 - 触发收货确认
    COMPLETE        // 完成事件 - 触发订单完成
}
```

**事件特征：**

- 事件是触发状态转换的外部刺激
- 事件通常对应用户操作或系统触发的业务动作
- 同一个事件在不同状态下可能产生不同的转换结果
- 事件是瞬时的，不持久存在

#### 2.3.3 转换 (Transitions)设计

转换是状态之间的切换规则，由事件触发。例如：

- **待支付 → 已支付**：用户支付了订单。
- **待支付 → 已取消**：用户取消了订单，或支付超时。
- **已支付 → 已发货**：商家发货。
- **已发货 → 已收货**：用户确认收货。
- **已收货 → 已完成**：用户确认订单完成。

转换规则在 `getNextState()` 方法中定义：

```java
private OrderState getNextState(OrderState currentState, OrderEvent event) {
    switch (currentState) {
        case PENDING:
            if (event == OrderEvent.PAY) return OrderState.PAID;        // PENDING + PAY → PAID
            if (event == OrderEvent.CANCEL) return OrderState.CANCELLED; // PENDING + CANCEL → CANCELLED
            break;
            
        case PAID:
            if (event == OrderEvent.SHIP) return OrderState.SHIPPED;     // PAID + SHIP → SHIPPED
            if (event == OrderEvent.CANCEL) return OrderState.CANCELLED; // PAID + CANCEL → CANCELLED
            break;
            
        case SHIPPED:
            if (event == OrderEvent.CONFIRM_RECEIPT) return OrderState.RECEIVED; // SHIPPED + CONFIRM_RECEIPT → RECEIVED
            if (event == OrderEvent.CANCEL) return OrderState.CANCELLED;         // SHIPPED + CANCEL → CANCELLED
            break;
            
        case RECEIVED:
            if (event == OrderEvent.COMPLETE) return OrderState.COMPLETED; // RECEIVED + COMPLETE → COMPLETED
            break;
            
        case COMPLETED:
        case CANCELLED:
            // 终态，不允许转换
            break;
    }
    return null; // 不支持的转换
}
```

**转换规则表：**

| 当前状态 | 事件 | 目标状态 | 说明 |
|---------|------|---------|------|
| PENDING | PAY | PAID | 待支付→已支付 |
| PENDING | CANCEL | CANCELLED | 待支付→已取消 |
| PAID | SHIP | SHIPPED | 已支付→已发货 |
| PAID | CANCEL | CANCELLED | 已支付→已取消 |
| SHIPPED | CONFIRM_RECEIPT | RECEIVED | 已发货→已收货 |
| SHIPPED | CANCEL | CANCELLED | 已发货→已取消 |
| RECEIVED | COMPLETE | COMPLETED | 已收货→已完成 |
| COMPLETED | - | - | 终态，无转换 |
| CANCELLED | - | - | 终态，无转换 |

**转换特征：**

- 转换是有条件的：只有特定的 (状态,事件) 组合才能触发转换
- 转换是确定性的：相同的 (状态,事件) 组合总是产生相同的结果
- 非法转换会被拒绝：不在转换表中的组合返回null

#### 2.3.4 动作 (Actions)设计

动作是在状态转换时执行的具体操作，例如：

- **支付成功**：更新订单状态为“已支付”，并发送支付成功通知。
- **发货**：更新订单状态为“已发货”，并发送发货通知。
- **取消订单**：更新订单状态为“已取消”，并释放库存。
- **确认收货**：更新订单状态为“已收货”，并发送确认收货通知。
- **订单完成**：更新订单状态为“已完成”，并记录交易完成。

动作在 `executeBusinessLogic()` 方法中定义：

```java
private boolean executeBusinessLogic(OrderState from, OrderEvent event, OrderState to) {
    switch (event) {
        case PAY:
            System.out.println("执行支付逻辑...");
            // 实际业务：调用支付接口、扣减库存、发送通知等
            return true;
            
        case SHIP:
            System.out.println("执行发货逻辑...");
            // 实际业务：创建物流单、更新库存、发送发货通知等
            return true;
            
        case CANCEL:
            System.out.println("执行取消逻辑...");
            // 根据当前状态执行不同的取消逻辑
            if (from == OrderState.PAID || from == OrderState.SHIPPED) {
                System.out.println("处理退款...");
                // 实际业务：退款处理、恢复库存等
            }
            return true;
            
        case CONFIRM_RECEIPT:
            System.out.println("执行确认收货逻辑...");
            // 实际业务：更新物流状态、启动自动确认计时器等
            return true;
            
        case COMPLETE:
            System.out.println("执行完成订单逻辑...");
            // 实际业务：发放积分、生成评价入口、归档订单等
            return true;
            
        default:
            return false;
    }
}
```

**动作类型：**

- **进入动作**：状态转换时执行的业务逻辑
- **条件动作**：根据源状态执行不同逻辑（如取消时的退款处理）
- **副作用**：打印日志、发送通知、更新数据库等



#### 2.3.5 状态机运行环境

状态机运行环境 (State Machine Context)设计

```java
static class OrderStateMachine {
    private Order order;  // 状态机上下文数据
    
    public OrderStateMachine(Order order) {
        this.order = order;
    }
    
    // 状态机的核心运行方法
    public boolean trigger(OrderEvent event) {
        OrderState currentState = order.getStatus();
        OrderState newState = getNextState(currentState, event);
        
        if (newState == null) {
            System.out.println("不支持的状态转换: " + currentState + " -> " + event);
            return false;
        }
        
        // 执行转换前的业务逻辑
        if (executeBusinessLogic(currentState, event, newState)) {
            order.setStatus(newState);  // 更新状态
            System.out.println("状态转换: " + currentState + " -> " + newState);
            return true;
        }
        
        return false;
    }
}
```

运行环境特征

- **状态存储**：Order对象存储当前状态
- **事件处理**：trigger()方法统一处理所有事件
- **转换控制**：getNextState()控制状态转换逻辑
- **业务执行**：executeBusinessLogic()执行业务动作
- **错误处理**：非法转换的统一处理机制

```java
/**
 * 使用状态机的订单服务实现
 * 特点：状态转换逻辑集中，代码清晰，易于扩展
 */
public class SimpleOrderServiceWithStateMachine {

    // 1. 定义状态枚举
    public enum OrderState {
        PENDING, PAID, SHIPPED, RECEIVED, COMPLETED, CANCELLED
    }

    // 2. 定义事件枚举
    public enum OrderEvent {
        PAY, SHIP, CANCEL, CONFIRM_RECEIPT, COMPLETE
    }

    static class Order {
        private String orderId;
        private OrderState status;
        private double amount;

        public Order(String orderId, double amount) {
            this.orderId = orderId;
            this.amount = amount;
            this.status = OrderState.PENDING;
        }

        // getters and setters
        public String getOrderId() { return orderId; }
        public OrderState getStatus() { return status; }
        public void setStatus(OrderState status) { this.status = status; }
        public double getAmount() { return amount; }
    }

    /**
     * 状态机核心 - 所有状态转换逻辑集中在这里
     */
    static class OrderStateMachine {
        private Order order;

        public OrderStateMachine(Order order) {
            this.order = order;
        }

        /**
         * 触发事件，执行状态转换
         * 核心优势：统一的状态转换入口
         */
        public boolean trigger(OrderEvent event) {
            OrderState currentState = order.getStatus();
            OrderState newState = getNextState(currentState, event);
            if (newState == null) {
                System.out.println("不支持的状态转换: " + currentState + " -> " + event);
                return false;
            }
            // 执行转换前的业务逻辑
            if (executeBusinessLogic(currentState, event, newState)) {
                order.setStatus(newState);
                System.out.println("状态转换: " + currentState + " -> " + newState);
                return true;
            }
            return false;
        }

        /**
         * 状态转换规则 - 集中定义所有转换规则
         * 优势：一目了然，易于维护
         */
        private OrderState getNextState(OrderState currentState, OrderEvent event) {
            switch (currentState) {
                case PENDING:
                    if (event == OrderEvent.PAY) return OrderState.PAID;
                    if (event == OrderEvent.CANCEL) return OrderState.CANCELLED;
                    break;
                case PAID:
                    if (event == OrderEvent.SHIP) return OrderState.SHIPPED;
                    if (event == OrderEvent.CANCEL) return OrderState.CANCELLED;
                    break;
                case SHIPPED:
                    if (event == OrderEvent.CONFIRM_RECEIPT) return OrderState.RECEIVED;
                    if (event == OrderEvent.CANCEL) return OrderState.CANCELLED;
                    break;
                case RECEIVED:
                    if (event == OrderEvent.COMPLETE) return OrderState.COMPLETED;
                    break;
                case COMPLETED:
                case CANCELLED:
                    // 终态，不允许转换
                    break;
            }
            return null; // 不支持的转换
        }

        /**
         * 执行业务逻辑 - 根据状态转换执行相应的业务操作
         */
        private boolean executeBusinessLogic(OrderState from, OrderEvent event, OrderState to) {
            switch (event) {
                case PAY:
                    System.out.println("执行支付逻辑...");
                    return true;
                case SHIP:
                    System.out.println("执行发货逻辑...");
                    return true;
                case CANCEL:
                    System.out.println("执行取消逻辑...");
                    // 根据当前状态执行不同的取消逻辑
                    if (from == OrderState.PAID || from == OrderState.SHIPPED) {
                        System.out.println("处理退款...");
                    }
                    return true;
                case CONFIRM_RECEIPT:
                    System.out.println("执行确认收货逻辑...");
                    return true;
                case COMPLETE:
                    System.out.println("执行完成订单逻辑...");
                    return true;
                default:
                    return false;
            }
        }
    }

    public class OrderService {

        /**
         * 支付订单 - 简洁的实现，只需触发事件
         */
        public boolean payOrder(Order order, double amount) {
            if (amount < order.getAmount()) {
                System.out.println("支付金额不足");
                return false;
            }
            OrderStateMachine stateMachine = new OrderStateMachine(order);
            return stateMachine.trigger(OrderEvent.PAY);
        }

        /**
         * 发货订单 - 简洁的实现
         */
        public boolean shipOrder(Order order) {
            OrderStateMachine stateMachine = new OrderStateMachine(order);
            return stateMachine.trigger(OrderEvent.SHIP);
        }

        /**
         * 取消订单 - 简洁的实现，状态机自动处理复杂逻辑
         */
        public boolean cancelOrder(Order order) {
            OrderStateMachine stateMachine = new OrderStateMachine(order);
            return stateMachine.trigger(OrderEvent.CANCEL);
        }

        /**
         * 确认收货 - 简洁的实现
         */
        public boolean confirmReceipt(Order order) {
            OrderStateMachine stateMachine = new OrderStateMachine(order);
            return stateMachine.trigger(OrderEvent.CONFIRM_RECEIPT);
        }

        /**
         * 完成订单 - 简洁的实现
         */
        public boolean completeOrder(Order order) {
            OrderStateMachine stateMachine = new OrderStateMachine(order);
            return stateMachine.trigger(OrderEvent.COMPLETE);
        }
    }

    public static void main(String[] args) {
        SimpleOrderServiceWithStateMachine demo = new SimpleOrderServiceWithStateMachine();
        OrderService service = demo.new OrderService();
        System.out.println("=== 使用状态机的订单服务 ===");
        // 创建订单
        Order order = new Order("ORDER001", 100.0);
        System.out.println("创建订单，初始状态: " + order.getStatus());
        // 正常流程
        service.payOrder(order, 100.0);
        service.shipOrder(order);
        // 尝试非法操作：已发货状态下支付
        System.out.println("\n尝试非法操作：");
        service.payOrder(order, 100.0);  // 状态机自动拒绝
        service.confirmReceipt(order);
        service.completeOrder(order);
        System.out.println("\n最终状态: " + order.getStatus());
    }
}
```

### 2.6 核心思想机制

状态机的核心思想非常直观：在任何时刻，程序（或它的一部分）都处于一个且仅一个预定义的“状态”中。它的行为取决于当前状态，而状态的改变则由发生的事件来触发。

## 06.状态机核心要素

### 6.1 状态机组成要素

状态机的几个核心要素：

1. 状态：系统所有可能的情况被精确定义为有限个数的“状态”（如状态A、状态B）。这是系统行为的“模式”。
2. 事件：来自外部或内部的“事件”（如事件X、事件Y)是触发状态迁移的输入信号。
3. 转移：定义在特定状态下，响应某个事件，并可能满足特定条件时，系统将执行一个动作并迁移到新的状态（或保持原状态）。
4. 动作：状态转移发生时可以伴随一个可执行的动作。

## 08.状态机案例

### 8.1 状态机基础框架

```cpp
#include <iostream>
#include <memory>
#include <unordered_map>
#include <functional>

// 前向声明
class StateMachine;
class State;

// 事件基类
class Event {
public:
    virtual ~Event() = default;
    virtual std::string getName() const = 0;
};

// 具体事件类
class StartEvent : public Event {
public:
    std::string getName() const override { return "StartEvent"; }
};

class StopEvent : public Event {
public:
    std::string getName() const override { return "StopEvent"; }
};

class PauseEvent : public Event {
public:
    std::string getName() const override { return "PauseEvent"; }
};

class ResumeEvent : public Event {
public:
    std::string getName() const override { return "ResumeEvent"; }
};

// 状态基类
class State {
public:
    virtual ~State() = default;
    virtual std::string getName() const = 0;
    virtual void onEnter(StateMachine* sm) {}
    virtual void onExit(StateMachine* sm) {}
    virtual std::shared_ptr<State> handleEvent(
        StateMachine* sm, 
        const Event& event
    ) = 0;
};

// 状态机类
class StateMachine {
private:
    std::shared_ptr<State> currentState_;
    std::unordered_map<std::string, std::shared_ptr<State>> states_;
    
public:
    StateMachine() = default;
    
    // 添加状态
    void addState(const std::string& name, std::shared_ptr<State> state) {
        states_[name] = state;
    }
    
    // 设置初始状态
    void setInitialState(const std::string& stateName) {
        auto it = states_.find(stateName);
        if (it != states_.end()) {
            currentState_ = it->second;
            currentState_->onEnter(this);
            std::cout << "状态机启动，初始状态: " << currentState_->getName() << std::endl;
        }
    }
    
    // 处理事件
    void handleEvent(const Event& event) {
        if (!currentState_) {
            std::cout << "错误: 状态机未初始化" << std::endl;
            return;
        }
        
        std::cout << "当前状态: " << currentState_->getName() 
                  << ", 接收事件: " << event.getName() << std::endl;
        
        auto nextState = currentState_->handleEvent(this, event);
        
        if (nextState && nextState != currentState_) {
            // 执行状态转换
            currentState_->onExit(this);
            std::cout << "状态转换: " << currentState_->getName() 
                      << " -> " << nextState->getName() << std::endl;
            currentState_ = nextState;
            currentState_->onEnter(this);
        }
    }
    
    // 获取当前状态
    std::string getCurrentStateName() const {
        return currentState_ ? currentState_->getName() : "None";
    }
    
    // 获取状态
    std::shared_ptr<State> getState(const std::string& name) {
        auto it = states_.find(name);
        return (it != states_.end()) ? it->second : nullptr;
    }
};
```

class IdleState : public State {
public:
    std::string getName() const override { return "Idle"; }
    
    void onEnter(StateMachine* sm) override {
        std::cout << "进入空闲状态 - 系统准备就绪" << std::endl;
    }
    
    void onExit(StateMachine* sm) override {
        std::cout << "退出空闲状态" << std::endl;
    }
    
    std::shared_ptr<State> handleEvent(StateMachine* sm, const Event& event) override {
        if (event.getName() == "StartEvent") {
            return sm->getState("Running");
        }
        std::cout << "空闲状态忽略事件: " << event.getName() << std::endl;
        return nullptr;
    }
};

// 运行状态
class RunningState : public State {
public:
    std::string getName() const override { return "Running"; }
    
    void onEnter(StateMachine* sm) override {
        std::cout << "进入运行状态 - 开始执行任务" << std::endl;
    }
    
    void onExit(StateMachine* sm) override {
        std::cout << "退出运行状态 - 停止执行任务" << std::endl;
    }
    
    std::shared_ptr<State> handleEvent(StateMachine* sm, const Event& event) override {
        if (event.getName() == "PauseEvent") {
            return sm->getState("Paused");
        } else if (event.getName() == "StopEvent") {
            return sm->getState("Idle");
        }
        std::cout << "运行状态忽略事件: " << event.getName() << std::endl;
        return nullptr;
    }
};

        std::cout << "进入暂停状态 - 任务已暂停" << std::endl;
    }
    
    void onExit(StateMachine* sm) override {
        std::cout << "退出暂停状态" << std::endl;
    }
    
    std::shared_ptr<State> handleEvent(StateMachine* sm, const Event& event) override {
        if (event.getName() == "ResumeEvent") {
            return sm->getState("Running");
        } else if (event.getName() == "StopEvent") {
            return sm->getState("Idle");
        }
        std::cout << "暂停状态忽略事件: " << event.getName() << std::endl;
        return nullptr;
    }
};

## 10.总结和分析

### 10.1 核心要点回顾

1. **应用场景广泛**：从游戏开发到业务流程，从网络协议到用户界面
2. **解决复杂性问题**：将复杂的条件逻辑转换为清晰的状态转换
3. **设计思想明确**：状态驱动、事件响应、确定性转换
4. **实现相对简单**：基于面向对象的设计模式，易于理解和实现
5. **存在固有问题**：状态爆炸、性能开销、设计复杂度
