激活

1. 设备端生成密钥（公钥/私钥），私钥存起来
2. 设备端发起与服务端的密钥交换，把公钥发上去，签名
3. 服务器端验证签名，返回自己的公钥
4. 客户端验证服务端的签名，把服务端的公钥存起来
5. 客户端确认激活完成

请求鉴权

1. 用设备端的私钥对 body进行签名，带了请求的时间戳
2. 用服务器的公钥对 body进行加密（可选）
3. 服务器收到请求，用设备端的公钥对签名进行验证签名，并校验时间戳，是否在正负 5 分钟以内
4. 服务端用服务器的私钥，对 body 进行解密
5. 返回结果，也是签名、加密的
6. 客户端同样做验证签名、解密

## 01.设备鉴权须知

### 1.1 设备鉴权应用

**设备鉴权**是确保设备身份合法性和安全性的关键机制，广泛应用于物联网（IoT）、智能家居、工业控制等领域。

### 1.2 设备鉴权目标

- **身份验证**：确认设备的身份是否合法。
- **数据完整性**：确保设备与服务器之间的通信数据未被篡改。
- **防止重放攻击**：防止攻击者截获并重复发送合法请求。
- **防止伪造**：防止攻击者伪造设备身份进行非法操作。

### 1.3 设备鉴权要素

**设备标识**

- 每个设备需要有一个唯一的标识符（如设备 ID、MAC 地址、序列号等）。
- 设备标识符应具有唯一性和不可伪造性。

**密钥管理**

- 设备与服务器之间需要共享密钥或使用非对称加密的公私钥对。
- 密钥应安全存储，避免泄露。

**鉴权协议**

- 设计安全的鉴权协议，确保设备与服务器之间的通信安全。
- 常见的鉴权协议包括 OAuth、JWT、HMAC 等。

**时间同步**

- 使用时间戳或随机数（Nonce）防止重放攻击。
- 设备与服务器之间需要保持时间同步。


## 02.鉴权方案设计思路
### 2.1 基于对称密钥鉴权
- **原理**：设备与服务器共享一个对称密钥，通过加密或签名验证设备身份。
- **流程**：
  1. 设备生成一个包含设备 ID 和时间戳的请求。
  2. 使用对称密钥对请求进行 HMAC 签名。
  3. 服务器验证签名和时间戳，确认设备身份。
- **优点**：实现简单，性能高效。
- **缺点**：密钥管理复杂，密钥泄露风险高。



### 2.2 基于非对称密钥鉴权
- **原理**：设备使用私钥对请求签名，服务器使用公钥验证签名。
- **流程**：
  1. 设备生成一个包含设备 ID 和时间戳的请求。
  2. 使用私钥对请求进行签名。
  3. 服务器使用设备的公钥验证签名和时间戳，确认设备身份。
- **优点**：安全性高，密钥管理简单。
- **缺点**：性能开销较大。

### 2.3 基于证书的鉴权
- **原理**：设备使用数字证书证明身份，服务器验证证书的合法性。
- **流程**：
  1. 设备向服务器发送包含设备 ID 和数字证书的请求。
  2. 服务器验证证书的合法性（如签名、有效期等）。
  3. 服务器确认设备身份。
- **优点**：安全性高，支持复杂的信任链。
- **缺点**：实现复杂，证书管理成本高。

### 2.4 基于OAuth的鉴权
- **原理**：设备通过 OAuth 协议获取访问令牌，服务器验证令牌的合法性。
- **流程**：
  1. 设备向认证服务器请求访问令牌。
  2. 认证服务器验证设备身份并颁发令牌。
  3. 设备使用令牌访问资源服务器。
  4. 资源服务器验证令牌的合法性。
- **优点**：支持第三方授权，灵活性高。
- **缺点**：实现复杂，性能开销较大。


## 03.接口安全性鉴权
### 3.1 接口安全目标

- **身份验证**：确认请求方的身份是否合法。
- **权限控制**：确保请求方只能访问其被授权的资源。
- **数据完整性**：防止数据在传输过程中被篡改。
- **防止重放攻击**：防止攻击者截获并重复发送合法请求。
- **防止信息泄露**：确保敏感数据不被泄露。

### 3.4 身份合法校验

- **作用**：确认请求方的身份是否合法。
- **常见方案**：
  - **API Key**：为每个客户端分配一个唯一的 API Key，客户端在请求中携带该 Key。
  - **OAuth 2.0**：使用 OAuth 2.0 协议进行身份验证和授权。
  - **JWT（JSON Web Token）**：客户端在登录后获取 JWT，后续请求中携带 JWT 进行身份验证。


### 3.5 数据完整性

- **作用**：防止数据在传输过程中被篡改。
- **实现**：
  - 使用 HMAC（哈希消息认证码）对请求数据进行签名，服务器验证签名。
  - 使用数字签名（如 RSA）确保数据的完整性和来源可信。


### 3.6 防止重放共计

- **作用**：防止攻击者截获并重复发送合法请求。
- **实现**：
  - 使用时间戳：请求中携带时间戳，服务器验证时间戳是否在有效范围内。
  - 使用随机数（Nonce）：请求中携带唯一的随机数，服务器记录已使用的 Nonce，防止重复使用。

### 3.7 防止信息泄露

- **作用**：确保敏感数据不被泄露。
- **实现**：
  - 对敏感数据（如密码、令牌）进行加密存储和传输。
  - 在响应中过滤敏感信息，避免泄露。


#### **4.1 密钥安全**
- 密钥应安全存储，避免明文存储。
- 使用硬件安全模块（HSM）或可信执行环境（TEE）保护密钥。

#### **4.2 防止重放攻击**
- 使用时间戳或随机数（Nonce）确保请求的唯一性。
- 服务器应维护一个已使用 Nonce 的列表，防止重复使用。

#### **4.3 防止中间人攻击**
- 使用 TLS/SSL 加密通信，防止数据被窃听或篡改。
- 验证服务器证书的合法性，避免伪造服务器。

#### **4.4 防止设备伪造**
- 使用硬件唯一标识符（如芯片 ID）绑定设备身份。
- 定期更新设备密钥或证书，降低泄露风险。
