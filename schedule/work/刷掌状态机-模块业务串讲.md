# biz/comm/palm_flow 刷掌状态机 · 业务串讲

> **一句话定位**：刷掌一轮会话的**大脑内核**——21 态 HFSM2 分层状态机（6 Head + 瞬态分发）+ Strategy 模式四策略纯函数决策 + Verdict variant 驱动流转 + 双通道异步（React 同步切态 / FlowAction 队列异步消费）+ token/epoch 双防串。模式差异（识别/录掌/混合/反扫码）全部收敛在 Strategy 子类，主干 FSM 对模式无感知。
> **场次**：45 分钟（21 文件约 2,600 行，本模块是全仓业务心脏，建议单独一场）　**听众**：同组开发 / 评审人 / 后续接手者
> **对照模版**：`06.技术模版/04.业务串讲的模版.md` 第 08 章　**代码基线**：`palm_app_linux/src/biz/comm/palm_flow/`（2026-10-09 全量精读）
> **前置阅读**：《刷掌会话》（Controller 消费侧——Action 谁来执行）、《通知器》（事件广播谁消费）、《O4 错误码治理》（retcode 映射全景）

## 1. 需求与业务背景  [7min · 先现象后价值]

### 1.1 需求与业务背景
- **来源**：spec FR-1~FR-19 系列（多 story 演进：134755867 加验 / 135094532 录掌等待 / 135810205 HOST_ACK 统一出货 / 136969382 端侧识别 / 137286676 反扫码 / 137913126 上报中转）。
- **问题**（老 PosSession 时代的四大痛点）：① 四种模式（识别/HOST 录掌/混合/CPM 反扫码）逻辑散落，每加一种模式全文件渗透；② 决策点既做服务端码映射又做流转判断，改一处崩三处（bug 1070139249163538699 的根源）；③ 「在飞网络响应串进新一轮」和「timer 迟到触发」两类竞态无系统性防御；④ 录掌/加验/回执等「等待外部输入」的态无法用扁平状态机表达。
- **目标**：模式差异 Strategy 化；决策纯函数化 + Verdict 强类型；等待态可组合成子树；竞态防御成为框架能力而非个案补丁。

### 1.2 业务边界
- **做**：一轮会话内的状态流转、决策、等待、超时、结果分发（0xA3 事件选择）、灯效随广播派发、per-round 配置快照。
- **不做**：Action 执行（HTTP/SDK 调用——PalmSessionController）、事件消费上行（PosNotifier）、错误码映射（Controller 生产点完成，见 3.9）、结果灯 3s 展示窗（DeviceStateMachine ShowingResult* 承载）。

### 1.3 关键业务规则
- **四种模式一条主干**：`0x01 识别→提交识别`；`0x02 HOST 录掌→优选直转注册`；`0x03 混合→先识别，100025 未录入则置 `recognition_attempted` 回 Detecting 二轮走注册`；`0x05 CPM→注册探测 Unregistered 等用户扫身份码`。工厂 `MakePalmFlowStrategy`（strategy.cpp:376-392）按 palm_mode 字节实例化，未知字节安全默认识别 + LOG_E。
- **Verdict 即协议**（flow_events.h:190-198）：`PostOptVerdict = V_Submit | V_EnterRegister | V_Complete`；`PostRecVerdict = V_Complete | V_RetryDetect | V_RequireVerify | V_RetryVerify`；`PostRegisterVerdict = V_Complete | V_RequireVerify | V_WaitBindInput | V_WaitScanInput`。**新增 alternative → 所有 Dispatch* 编译失败**（static_assert(kAlwaysFalse)）。
- **completion_source 四值决定出货形状**（flow_context.h:116-122）：kNormal→0xA3 识别回执 / kBindFinished→is_bind_palm=1 / kScanFinished→0x02 扫码 / **kAbort→静默，不发 0xA3 不调度 cooldown**。
- **错误码契约**（flow_events.h:112-118，bug 1070139249163538699）：事件 `code` 恒为模组码（Controller 生产点完成映射/直落），`server_code` 原始码透传——**决策点不再做映射**。
- **可打断性**（machine.cpp:163-171）：OptPassed 起到 BizProcess 子树结束不可打断；`WaitingBindInput/WaitingScanInput` 归入 RegisteringHead **继承**不可打断——「不发明 per-state 特例」。

- **[定义]** flow_events / flow_context / flow_actions / session_profile / palm_flow_fsm_def（四头文件一图）。

## 2. 整体设计与模块划分  [6min · 先图后讲]

### 2.1 四层架构图
```
┌─ Strategy（纯函数，模式差异全部在此）──────────────────────┐
│ Recognition/HostEnrollment/Hybrid/CpmEnrollment            │
│  DecidePostOpt / DecidePostRec / DecidePostRegister        │
│  → 返回 Verdict variant（不碰状态机，只读 ctx）           │
└──────────────┬─────────────────────────────────────────────┘
               │ VerdictPost*Event（Controller 消费 Action 后回喂）
┌──────────────▼─────────────────────────────────────────────┐
│ States（HFSM2 层级）                                        │
│  enter: BroadcastEnter(灯) + arm timer + 入队 Action        │
│  react: 收事件 → 写 ctx → 入队 kDecidePost* 或 changeTo     │
│  update: 瞬态分发（Entry 类）+ 完结源出货（ResultObtained）  │
│  Dispatch*: Verdict → changeTo + 写 exit_code/source       │
└──────────────┬─────────────────────────────────────────────┘
               │ 5 个闭包（request_action/emit_event/broadcast/arm/disarm）
┌──────────────▼─────────────────────────────────────────────┐
│ Machine（wrapper）                                          │
│  React<E>: fsm react + update（同步，调用栈内完成）         │
│  actions_ 队列 + WaitWork（Controller RunLoop 消费）        │
│  state_timer + token；round_epoch（P0-8 防串轮）            │
│  change_sig_/event_sig_（Notifier 订阅）+ ReportFlowLight   │
└────────────────────────────────────────────────────────────┘
```
分层关键：**决策纯函数 → Verdict 强类型 → 状态只做跳转与记账 → wrapper 只做 IO 编排**。状态头文件不依赖 wrapper（闭包反转依赖，palm_flow_states.h:8-10）；Strategy 不持有 Session 引用、禁 IO/锁/阻塞（strategy.h:26-30）。

### 2.2 状态树（fsm_def.h:88-99 + states.h 注释即文档）
```
Root
├─ Created ──StartReq→ Starting ──StartOk→ [Running]
│                            └StartFail(kAbort)→ Stopping
└─ [Running]（Head：StopReq/ScanComplete 一处覆盖全子树）
   ├─ Detecting ─PalmEntered→ PalmEntered ─OptPass→ OptPassed
   │    └update: retry>max → FSM_INTERNAL_ERROR 收敛
   └─ [BizProcess]（Head：不可打断区间）
      ├─ [Recognizing] RecognizeEntry ─(本地同步开?)→ Local | Cloud
      ├─ [Registering] RegisterEntry → RegisterSubmitting
      │                 ├─ V_WaitBindInput → WaitingBindInput（等上位机 BindPalm）
      │                 └─ V_WaitScanInput → WaitingScanInput ⇄ RegisterByCodeSubmitting
      │                                    （162/163 重试往返，deadline 不重置）
      ├─ [Verifying] VerifyEntry → Verifying ⇄ VerifySubmitting（100038 重试<3）
      ├─ ResultObtained（瞬态出货口：按 completion_source emit 0xA3 事件）
      │    └need_host_ack? → WaitingHostAck（20s/ack→160）: → Stopping
      ├─ Stopping（纯结束态：emit OnSessionComplete + 0xA8；kAbort 静默）
      └─ Done
```

## 3. 逐模块实现讲解  [13min · 业务意图先行]

### 3.1 flow_events.h（391 行）：类型即文档
- 30+ 事件结构体按域分组：生命周期 / SDK 检测信号 / 请求响应 / 统一超时（Kind+token）/ 决策回喂 V_* / 广播与事件上行。**每个事件的注释都写明生产者、消费者与字段语义**（如 RecResponseEvent 的 code/server_code 契约，:112-118）。
- `IsPalmIdCodeContent`（:64-69）：身份码校验单一事实源——FSM 门禁与 Controller 防御性复检共用（palmpact:// 前缀，与 O1 HostProtocol 对齐）。

### 3.2 flow_context.h（161 行）：会话级数据载体，**每块字段标注写者**
- 分区注释标明责任分布（:16-20）：Strategy 只读 / Controller 在 enter-exit 与事件处理写 / Stopping 转入前已被写好 / Notifier 读广播派副作用。
- 上报中转字段（137913126 FR-6.x）：start_source / traceparent / opt_frame_image_id / event_actions_log / 各 wait·submit 时间戳——**FSM 是全链路时序事实的持有者**，上报层只做组装。

### 3.3 palm_flow_fsm_def.h + state_base：类型系统固化父子关系
- 6 Head + 20 leaf；`M::Composite` 嵌套取代旧虚函数 BelongsToRunning（state_base.h:15-16）；`using PalmFlowStateBase::react;` 防 C++ 名称隐藏（:28-34，HFSM2 deepReact 的 static_cast 寻址要求）。
- `BroadcastEnter`（state_base.cpp:25-31）：进入即带 `LightFor(ctx)` 虚函数灯效广播——**灯随状态走，订阅者无需回查**。瞬态状态刻意不广播（RegisterEntry/VerifyEntry/RecognizeEntry/ResultObtained 四个「对外隐形」态）。

### 3.4 palm_flow_states.cpp（1082 行）：三个 Dispatch visitor + 失败收敛
- `DispatchPostOpt/PostRec/PostRegister`（:47-154）：`std::visit` + if constexpr 链 + static_assert 兜底——**编译期穷尽检查**，新增 Verdict alternative 少写一个分支直接编译失败。
- `ConvergeEnrollSubmitFailure`（:168-186）：两条录掌链路（HOST BindPalm / CPM register-by-code）共用收敛模板，按 `enroll_wait` 去向分派报 binding 还是 enrollment。
- RunningHead 两个 react 是「父状态一处覆盖」的样板（:202-229）：StopReq→kAbort 静默停；ScanComplete 用 **isActive 检查实现父让子**（TopDown 顺序父先执行，反扫码子树激活时父 return 让事件下沉）。

### 3.5 palm_flow_machine.cpp：wrapper 三件宝
- 构造顺序注释（:15-39）：**闭包必须先于 FSM 实例绑定**——HFSM2 Root::Instance 构造即自动 enter CreatedState 并触发 broadcast，按值成员构造会 bad_function_call（:114-117 债务注释）。
- `Reset`（:49-78）：轮间过渡集中地——cancel timer + ++token、清 actions、整体换 FlowContext（新 session_id/trace_id）、++epoch、重建 FSM 实例。
- `WaitWork` 唤醒契约（:90-101）：ready 条件含 Done——Stopping→Done 只走 changeTo 不入队 Action，不唤醒则 RunLoop 卡死、下一轮起不来（注释 :91-93）。`DoBroadcast` 末尾 Wake 同因（:198-201）。

### 3.6 palm_flow_strategy.cpp：四策略 + 单源路由
- `EnrollRoutingForMethod`（:34-50）：CPM/HOST 等待去向**单一事实源**——CpmEnrollment 覆写、Hybrid 按 `hybrid_enroll_method` 快照、基类默认 HOST，三条路径自动跟随（story 137286676 契约变更只改一处）。

- `CheckNeedVerifyAndExtractId`（:98-131）：const_cast 写 ctx.verify_id/method——**承认的架构债**（.h:58-63 注释：Verdict 不带 payload；改造后可移除）。

### 3.7 recognize_retcode.h：57 行的映射契约

## 4. 核心代码实现细节与原理（重点）  [12min · 讲透原理]

### 4.1 深挖①：闭包反转依赖——状态不认识 wrapper
- **问题**：状态需要入队 Action / 发事件 / 广播 / 定时——这些能力在 wrapper。若状态头 include wrapper，则 wrapper（持 FSM 实例，实例化需状态完整定义）↔ 状态（需 wrapper 类型）循环。
- **解法**（fsm_def.h:37-51）：`PalmFlowFsmContext` 持 5 个 `std::function` 闭包，wrapper 构造 body 内绑定（machine.cpp:18-28），状态只见 `PalmFlowFsmContext` 前向类型。**把「能力」从类型依赖降级为值依赖**——编译期解环，运行期一次间接调用开销。
- **代价**：闭包必须先绑定——构造顺序债务（4.5 见 machine.cpp:114-117 注释），换来的是 21 个状态零 include wrapper。

### 4.2 深挖②：React 同步 + Action 异步的双通道模型
- **React<E>**（machine.h:59-63）：`fsm_->react + update` 在调用栈内同步完成切换（含 enter/exit 钩子、全部 ctx 写入）——**一轮内不存在中间态可见性**：订阅者要么看到旧态、要么看到新态，没有「切了一半」。
- **FlowAction 队列**：重活动作（HTTP/SDK）入队由 Controller RunLoop `WaitWork/PopAction` 异步消费——**状态机永不阻塞**。请求完成后 Controller `React(RespEvent)` 回喂 → Strategy 决策 → `React(VerdictEvent)` 再回喂状态机。一次网络往返 = 两次 React，中间 ctx 承载 `last_rec_resp`。
- **WaitWork 唤醒契约**（machine.cpp:90-101 + :198-201 两处注释）：唤醒条件 = actions 非空 **或 Done**。Stopping→Done 只 changeTo 不入队，漏了 Done 条件 RunLoop 永眠——**「无 Action 的状态迁移」也必须唤醒消费者**，这是队列+条件变量模型的隐藏税。

### 4.3 深挖③：token/epoch——竞态防御成为框架能力
- **state_timer_token_**（machine.cpp:204-227）：每次 arm/disarm `++token`，在飞回调 fire 时比对——**迟到的 timer 自动失效**。状态切换的 exit→disarm 与新 enter→arm 之间不存在「旧 timer 打中新状态」的窗口。
- **round_epoch_（P0-8）**：Reset 时 ++；ConsumeAction 网络返回后校验（machine.h:80-81 注释）——**旧轮在飞响应到达新轮直接丢弃**。与 4.1《启动应用》restarter 的 PID 文件锁、trace 链路「快照优于引用」同族：**活性/身份判定交给单调递增的 token，而非比对内容**。
- **组合效果**：删掉任何一个，现象都是「偶发串轮」——极难复现的线上幽灵，框架层一次解决所有状态共担。

### 4.4 深挖④：「首入写一次」——deadline 语义 vs 重 arm 语义
- WaitingScanInput 的窗口（states.cpp:751-812）：`scan_input_deadline` 首入设定，162/163 重试往返（WaitingScanInput⇄RegisterByCodeSubmitting）**不重置**——用户总等待时长是硬约束，重试失败不能白送时间。arm 的时长 = `deadline - now`（剩余量），窗口在 HTTP 在飞期间耗尽则 arm 1ms 收敛 SCAN_INPUT_TIMEOUT（:779-784 注释处理 changeTo 不能在 enter 调的约束）。
- 对照 Verifying 重试轮 `verify_wait_enter_ts` **覆盖写**（states.cpp:933-935 注释：FR-2.4 口径取最后一轮）——**同一模块内两种时间语义并存**：窗口类（不可续）用 deadline+剩余量，口径类（取末轮）用覆盖写。改任何一处前先问属于哪类。
- WaitingBindInput 的对称差异：失败重试**留在状态内不重入**（:715-728，timer 已 disarm，等 StopPalm 或首窗超时退出）——「不可重试收敛」由 `IsEnrollSubmitNonRetryable` 单源判定（3.7）。

- 闭包先绑后构造（machine.cpp:114-117）；Strategy const_cast（strategy.h:58-63）；RegisterSubmitting→加验入口 TODO「实际仅识别走加验，此入口待判断」（fsm_def.h:161）——**见 6.2-F3**。
