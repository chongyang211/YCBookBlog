# scripts/S99palmapp 启动应用（监督塔）· 业务串讲

> **一句话定位**：palmapp 的**三层监督启动塔**——`S99palmapp`（开机守卫，观察 2s 判「脚本损坏」）→ `restart.sh`（外层循环，快慢失败分类 + 恢复分发）→ `restarter`（C++ 内层，fork/exec + 心跳监控 + 真崩溃计数）→ `palmapp` 本体（`--signal-parent 10` 心跳）。核心设计：**完成信标（/tmp/restart_done）区分「设计内退出」与「控制流断裂」**；双层崩溃计数只在「真崩溃」上累积；恢复分发按 OTA 上下文路由（retry_ota → 兜底 factory_reset），恢复事件原子落盘供下次开机上报。
> **场次**：45 分钟（4 文件约 775 行 shell/C++，难点全在「为什么分三层」与退出码语义）　**听众**：同组开发 / 评审人 / 后续接手者
> **对照模版**：`06.技术模版/04.业务串讲的模版.md` 第 08 章　**代码基线**：`scripts/S99palmapp` + `assets/scripts/restart.sh|stop.sh` + `tools/restarter/restarter.cpp`（2026-10-08 全量精读）

## 1. 需求与业务背景  [8min · 先现象后价值]

### 1.1 需求与业务背景
- **来源**：无人值守支付设备不能「死给你看」——palmapp 崩溃/挂死/升级损坏必须**自愈**，且恢复动作本身也可能失败，需要兜底链。
- **问题**（决定三层结构的三类故障，**故障分类决定谁处理**）：
  1. **脚本本身损坏**（文件截断/`set -e` 中断/语法错/exec 失败/SIGKILL）——控制流到不了设计出口；
  2. **启动失败**（fork/exec 失败、二进制损坏）——restarter 立即退出；
  3. **运行期崩溃/挂死**——真崩溃（信号死）或心跳停（挂死）。
  另有外部停止（stop.sh/看门狗/OOM）**绝不能**被当成崩溃累积。
- **目标**：三类故障各有归属处理；设计内退出与异常死可区分；崩溃计数只算真崩溃；外部杀不触发恢复；恢复失败可重试（下次开机）。

### 1.2 业务边界
- **做**：开机守卫、双层监督、心跳监控（30s 无心跳 SIGKILL）、崩溃计数（内层 3 次信号死 / 外层 3 次快失败）、恢复分发（ota_pending→retry_ota else factory_reset）、恢复事件持久化、优雅停止、调试开关（guard.env 模拟崩溃 / disable_self_recovery）。
- **不做**：OTA 下载（upgrade_schd）；recovery 事件上报（RecoveryReporter，业务上报串讲 3.5）；ROM 恢复的 system_update 细节（system_server）。

### 1.3 关键业务规则
- **退出码语义**（三层契约）：
  | 码 | 含义 | 产生方 → 消费方 |
  |---|---|---|
  | 0 | palmapp 正常退出（外层清零计数、退出循环） | restarter → restart.sh |
  | 2 | 内层崩溃阈值快路径 | restarter → restart.sh（直接 do_recover） |
  | ≥128 | 信号终止 = 外部杀，**不计数** | restarter → restart.sh |
  | 非 0 非 2 | 应用自启重启（_RestartNow），重启不计数 | restarter → restarter |
- **beacon 规则**：restart.sh **每条设计出口都写 /tmp/restart_done**——S99 观察 2s 内死亡且无 beacon → 控制流断裂 → factory_reset（S99palmapp:8-14 注释）。
- **心跳规则**：palmapp `--signal-parent 10`（每 10s SIGUSR1）；restarter `-m 30`（30s 无心跳 SIGKILL 判 kCrash）——**挂死与崩溃同被监督**。
- **计数规则**（外层，restart.sh:314-369）：`elapsed<5s` 才计（启动失败）；`>=128` 不计；`>=300s` 稳定运行重置；`[5,300)` 不变。内层（restarter.cpp:194-212）：仅 `WIFSIGNALED` 真崩溃计数，稳定 60s 重置，达 3 → exit 2。

### 1.4 改动范围（链路组成）
- **[开机守卫]** `scripts/S99palmapp`（154 行）：观察窗口 + beacon 判定 + 去重。
- **[外层循环]** `assets/scripts/restart.sh`（375 行）：监督循环 + do_recover + 事件持久化 + 优雅停止 trap。
- **[内层监督]** `tools/restarter/restarter.cpp`（223 行）：fork/exec、心跳、崩溃分类计数。
- **[停止]** `assets/scripts/stop.sh`（23 行）：**顺序敏感**的三步杀。
- **[验证/文档]** `scripts/guard-release-verify.sh`（发布验证）+ `docs/guard-self-recovery-design.md`（权威设计）。

## 2. 整体设计与模块划分  [6min · 先图后讲]

### 2.1 架构与分层
```
 开机（init.d S99，最后阶段）
   S99palmapp start
     ├ restart.sh 缺失 → skip（卸载/变体容忍）
     ├ pid 去重（/tmp/restart_sh.pid + kill -0）
     ├ rm beacon → 后台起 restart.sh（保持父子关系以便观察）→ sleep 2
     ├ 活着 → hand off（此后全交给监督塔）
     └ 死了：有 beacon → 设计内退出，不动
              无 beacon → 控制流断裂 → factory_reset(data_app)
 ─────────────────────────────────────────────
 restart.sh（外层 while）
   ├ do_recover：ota_pending 有 → retry_ota(app:opkg/rom:system_update)
   │                    失败 → factory_reset 兜底
   │        无 → factory_reset(continuous_crash)
   │   恢复事件原子落盘（tmp+mv+双sync）→ 下次开机 RecoveryReporter 上报(16160)
   ├ 后台起 restarter → wait（POSIX 唯一可中断暂停，配合 trap）
   └ 按退出码分类计数（1.3 表）→ 达阈值 3 → do_recover
 ─────────────────────────────────────────────
 restarter（内层）
   fork/exec palmapp --signal-parent 10
   waitpid + SIGALRM/SIGUSR1（心跳）→ 30s 无心跳 SIGKILL=kCrash
   WIFSIGNALED=kCrash 计数（稳定60s重置）→ 达3 → exit 2（快路径）
 ─────────────────────────────────────────────
 palmapp（本体：bootstrapper → 全家桶启动）
 stop.sh：①killall restart.sh（trap 清计数+beacon）②killall restarter ③kill palmapp
```
分层关键：**每层只管一类故障**——S99 管「脚本损坏」（2s 窗口 + beacon）、外层管「启动快失败」（elapsed 分类）、内层管「运行期崩溃/挂死」（信号死/心跳停）。**故障向下穿透，处理向上收敛**。

### 2.2 核心数据流（一次崩溃自愈之旅）
```
palmapp 运行中 SIGSEGV → restarter 判 kCrash → 计数1 → -s 1s 后重启
 → 再崩再计 → 第 3 次 → restarter exit 2（快路径）
 → restart.sh 收 rc=2 → 计数+1 → do_recover
    有 ota_pending？→ retry_ota（opkg force-reinstall / system_update）
       成功 → app: postinst 经 S99 重启；rom: 直接 reboot
       失败 → factory_reset 兜底（事件记 factory_reset rc）
    无 → factory_reset
 → 事件落盘 /data/palmapp/guard/recovery_event（原子写）
 → 重装/重启后 palmapp 起来 → RecoveryReporter 读文件上报 16160 → 乐观 unlink
```

## 3. 逐模块实现讲解  [15min · 业务意图先行]

### 3.1 `S99palmapp`：2 秒守卫　:85-153
- **为什么直接起而不 detach**（:108-112 注释）：`start-stop-daemon -b` 会脱离父子关系、拿不到退出状态——**保持父关系才能观察**。
- **去重**（:95-106）：S99 start 可能被多次触发；pid 文件在 /tmp（开机清零）+ `kill -0` 判活——第二实例会经 pid 锁误杀第一实例（restart.sh lockcheck），注释 :96-99 点明。
- **disable prop 读取时机**（:57-81）：正常路径只读一次；**FAIL 决策点重读 + 5×0.5s 重试**（属性服务开机早期可能未加载 vendor props）——重试只在恢复路径，正常启动零延迟。
- `system_recovery` 失败只 log「retry next boot」（:138-140）——恢复幂等，靠下次开机重试。

### 3.2 `restart.sh`：外层循环　:217-374
- **trap 优雅停止**（:251-269）：TERM/INT/HUP → 杀 restarter 子进程 + **清计数** + beacon + exit——**没有 trap，外部杀会被循环重新拉起、计数误升误触 recover**（注释 :252-257 是本脚本最重要的设计说明）。
- **wait 是唯一可中断暂停**（:292-293 注释）：POSIX sh 里只有 `wait` 能被信号打断——这是外层能用 trap 的前提。
- **计数三区分类**（:335-367）：`>=128` 外部杀不计 / `<5s` 快失败计 / `>=300s` 稳定重置 / 中间不动。**已知盲区自评**（:344-350 注释）：restarter 运行中 SIGSEGV（rc=139）被归外部杀漏计——「极罕见；单次漏计不改变行为（阈值 3）」——**风险自我声明的范本**。
- `GUARD_SIMULATE_CRASH_TIMES`（:283-289）：注入 `--simulate-crash-times N` 让 palmapp 前 N 次启动主动 SIGSEGV——**崩溃自愈的可测性开关**。

### 3.3 `restarter`：内层监督　restarter.cpp
- **退出分类三态**（:29-39 + 130-157）：kNoRestart（正常退 0 / 外部杀 -k）/ kRestart（非零 exit = 应用自启重启，**不计**）/ kCrash（信号死 / 30s 无心跳 SIGKILL / WIFSTOPPED 保守计）。
- **心跳**（:85-93 + 107-127）：SIGUSR1 更新 `last_child_heartbeat`；SIGALRM 周期唤醒 waitpid（EINTR）→ 检查心跳超时。
- **计数与稳定重置**（:194-212）：连续 3 次真崩溃 → `exit 2`；上两次崩溃间隔 ≥60s 视为曾稳定，重置。
- 注意：`stable_run_reset` 的 60s 与 bootstrapper 的 60s OTA 观察窗**数值相同纯属巧合，不可合并**（design doc :228-230 明示；bootstrapper.cpp:62-65 同注释）——两个 60 同名异物。

### 3.4 `do_recover`：恢复分发　:153-215
- **ota_pending 三段式** `<type>|<target_version>|<pkg_hint>`；`resolve_pkg` 优先 installer 记录的 hint（它知道自己刚下了哪个文件），空/丢失回退 `ls -t` 最新——**空 pkg 视为失败走 factory_reset 兜底**。
- **先写意图事件再执行**（:179-182 注释）：成功的 opkg install 的 postinst 会 `killall restart.sh` 杀死本脚本——后写就丢了。
- **原子写 + 双 sync**（:111-130）：tmp 写入 → sync（数据落盘）→ mv → sync（rename 元数据持久）——掉电安全。
- `set +e/-e` 包裹 retry_ota（:170-186）：rc 要驱动 fallback，失败不能中断脚本。

### 3.5 `stop.sh`：顺序敏感的三步　:6-11
- **先杀 restart.sh**（trap 清计数+beacon+退出循环）→ 再杀 restarter → 再杀 palmapp——顺序错了外层会看到 restarter 死而重新拉起、S99 重复 start 叠加实例（注释 :7-10）。

## 4. 核心代码实现细节与原理（重点）  [10min · 讲透原理]

### 4.1 深挖①：beacon——「控制流可达设计出口」的证明
- 区分两类死：**设计内退出**（palmapp 正常退/外部停——写了 beacon）vs **控制流断裂**（截断/set -e abort/语法错/exec 失败/SIGKILL——**来不及写**）。
- 关键性质（restart.sh:14-19 注释）：**任何 debug 编辑不影响 beacon**——只要控制流能走到任何一条设计出口，beacon 就在。所以守卫判定的是「脚本是否完好可达出口」，不是「退出码是否正确」。
- 这是 shell 监督体系的通用手法：**信标表达可达性，退出码表达意愿，两者正交**。

### 4.2 深挖②：双层计数为什么不能合并
- 内层（restarter）拥有最准的**信号信息**（WIFSIGNALED vs WEXITSTATUS）——只有它能判「真崩溃」；外层（shell）只拿得到退出码，`>=128` 猜信号——所以**计数主体在内层**，外层只对内层给不了的信息（restarter 自身启动失败）做补充分类。
- 外层 `exit 2` 快路径：内层已达阈值时**跳过外层计数直接 recover**——两层阈值不叠加（内 3 或 外 3，先到先触发）。

### 4.3 深挖③：恢复分发的兜底链与幂等
```
retry_ota（优先保留升级成果）
  ├ 成功：app→postinst 重启链 / rom→直接 reboot
  └ 失败（含空 pkg rc=98 / 未知类型 rc=99）→ factory_reset
factory_reset（data_app：重装出厂捆绑 app）
  └ 失败 → S99 只 log → 下次开机重试（幂等：损坏的 restart.sh 每次开机都被 factory_reset 覆盖修复）
```
- **为什么 retry_ota 优先**：升级中途崩溃（ota_pending 存在）大概率是**新包问题**——重试同一包（force-reinstall/downgrade）比重装旧版更接近用户意图；重试也失败才承认包坏，退厂。

### 4.4 深挖④：心跳窗口的隐性契约
- palmapp 必须在 **30s 内发出首个心跳**（`-m 30`，restarter.cpp:119）——启动超过 30s 无心跳即被 SIGKILL 判 crash。这是**应用与监督器的隐性启动预算**：bootstrapper 全家桶（Network/MQTT/属性/激活…前十四篇串讲的所有 Init）挤在这 30s 里——**新增启动重活前先量这个预算**。

## 5. 边界、异常与测试  [5min · 别一笔带过]

### 5.1 边界条件
| 场景 | 行为 |
|---|---|
| restart.sh 缺失 | S99 skip（卸载/变体容忍；opkg 中断是覆盖不是缺失，:16-18 注释） |

## 6. 踩坑与接手注意事项（含审阅发现）  [审阅 + 雷区]

### 6.2 接手者雷区地图（⚠️ 本次审阅发现）
| # | 现象 | 代码位置 | 风险 / 建议 |
|---|---|---|---|
| **G1** | **30s 心跳预算是隐性契约**（4.4）——启动链新增重活（前十四篇串讲的各 Init）都挤在里面，超时即被 SIGKILL 判 crash | restart.sh:295(-m 30) | 启动耗时纳入发布验证；bootstrapper 各步打点 |
| **G2** | 已知盲区（自评）：restarter 运行中 SIGSEGV（139≥128）被归外部杀漏计——阈值 3 兜底，注释即风险清单 | restart.sh:344-350 | 保持认知即可；若 restarter 稳定性恶化再收紧 |
| **G3** | `killall "restart.sh"` 按进程名杀——设备上若有其他同名脚本会误杀（stop.sh 与 opkg postinst 两处用） | stop.sh:11 / postinst | 低概率；改用 pid 文件杀更精确 |
| **G4** | 外层计数文件在 /tmp——**崩溃计数不跨重启**：连续「崩溃→重启设备」的循环每轮清零，永远到不了阈值 3 | restart.sh:238 | 有意设计（重启视为稳定）但要知晓：依赖「重启不解决」的故障只能靠 ota_pending/单轮内 3 连崩触发 |
| **G5** | OBSERVE_SECONDS=2 假定 restart.sh 正常路径 2s 内必存活（进 while 拉起 restarter 后即挂起等待）——若未来在循环前加重活，误判脚本损坏→factory_reset | S99palmapp:28 | 循环前保持轻量；改窗口需评估 |
| **G6** | 三个 60 同名异物（内层重置/OTA 观察窗/`--stable-run-reset-count`）——design doc 明示「不可合并」 | design doc :228-230 | 改任何一个先读该声明 |

**给接手者的硬提醒**：
- 🔴 **stop 顺序不能动**（先 restart.sh → restarter → palmapp）——任何一步颠倒都会叠加实例或误计数（stop.sh:7-10 注释是血的教训）。
- 🟡 改 restart.sh 任何路径，**确保控制流仍可达某条设计出口**（beacon 语义）——加 `exit` 前想想 S99 会怎么看你的死法。
- 🟡 do_recover 里写事件的时机（先意图后执行）不能换——postinst 会杀本脚本。
