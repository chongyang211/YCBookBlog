> **一句话定位**：刷掌会话事件（`palm.*` 五事件族）上报链的三件套——**协议常量**（report_actions.h:46-52，平台路由键）+ **数据结构**（`PalmSessionReportItem`，FR-3 18 字段：必填 9 + 条件 9）+ **单一装载点**（`PalmActionEventReporter::Emit`，palm_session_controller 10 个发射分支汇入），经 25261 共表（OTLP scope）入平台。设计核心：**参数结构与协议结构分离**（会话级字段直读 FlowContext，不重复定义）+ **空值裁剪靠类型系统**（optional 无值不写键）+ **单汇合点防字段漂移**。

## 1. 需求与业务背景  [8min · 先现象后价值]

### 1.1 需求与业务背景
- **来源**：Story 137913126（FR-2/FR-3）——刷掌业务需要**事件级观测**：平台要按会话聚合分析成功率/转化率/耗时分布，排障要能凭一个号贯通设备与后端日志。
- **问题**：① 一个刷掌会话产生 1~4 条业务事件（识别/录掌/绑定/加验）+ 1 条终态聚合——字段有**会话级**（同会话同值）与**事件级**（每次不同）两类；② 部分字段只在特定场景有意义（local 无 HTTP 自然无 traceparent）——强制全装会满屏空值；③ 装载点若散落各状态分支，字段口径必然漂移。
- **目标**：五事件族统一协议；会话级字段一处定义；条件字段自动裁剪；单一装载点集中治理。

### 1.2 业务边界
- **做**：5 action 常量、18 字段协议结构、Emit 装载（含 JSON 留痕）、10 个发射分支、event_actions_log 会话轨迹聚合、25261 队列注册。
- **不做**：OTel metrics 通道（recognition_metrics_reporter，刷掌串讲 3.4——成功率指标那侧）；POS 0xA3 上行（PosNotifier）；后端归因语义；`server_event_cost` 的服务端耗时（后端未返回，恒不装——已知欠账 E2）。

### 1.3 关键业务规则
- **五事件族**（report_actions.h:46-52，平台按 attributes.action 路由）：
  | action | 装载时机 | route 值 |
  |---|---|---|
  | `palm.recognition.result` | 识别收敛（含离线优选 fake success=0） | cloud/local |
  | `palm.enrollment.result` | HOST 探测 / CPM 反扫码录掌收敛 | cloud |
  | `palm.binding.result` | HOST 等绑定输入收敛 | cloud（绑定无 local） |
  | `palm.verification.result` | 加验收敛 | cloud/local |
  | `palm.session.end` | 会话终态聚合（每会话恒 1 条，含 abort） | 不装 |
- **字段三档**（palm_session_report_item.h）：
  - **必填 9**（FR-3 #1~#4/#8~#12 + happen_time）：action/session_id/client_trace_id/work_mode/result_code/opt_frame_image_id/opt_live_duration_ms/client_event_cost/happen_time；
  - **条件 9**（optional 无值不写键）：start_source/action_type/route/retry_count/detect_duration_ms/wait_ms/submit_ms/traceparent/server_response_code；
  - **session.end 专属 4**：end_state/end_action/event_actions/last_state。
- **route 值口径**（report_attribute_keys.h:27-28）：`kRouteRemote="cloud"`（**常量名是历史遗留**，值已统一 cloud）/`kRouteLocal="local"`——与 OTel metrics 通道一致；item.h:84 注释写 remote 是**注释漂移**（6.2-E3）。
- **结果码双轨**：`result_code`（面向上位机/用户，模组码或按发射点决定）与 `server_response_code`（服务端原始码，归因用）分离。

### 1.4 改动范围（链路组成）
- **[协议常量]** report_actions.h:46-52（5 action）+ report_attribute_keys.h（work_mode/route/end_state 枚举）。
- **[数据结构]** `protocol/palm_session_report_item.h`（188 行）：18 字段 + to_json 条件写键 + 空 Fill 钩子 + 无快捷函数声明。
- **[装载点]** `biz/comm/palm_session/palm_action_event_reporter.h/.cpp`（112 行）：PalmActionEventParams（发射点输入）+ Emit。
- **[发射点]** palm_session_controller.cpp 10 处（见 3.3）。
- **[下游]** report 框架 25261（业务上报串讲已覆盖：HeartBeatThread → 队列 → Builder trace/span/happen_time）。

## 2. 整体设计与模块划分  [6min · 先图后讲]

### 2.1 架构与分层
```
 palm_session_controller（10 个发射分支）
   │ 各分支只构造 PalmActionEventParams（事件差异输入）
   ▼
 PalmActionEventReporter::Emit（唯一装载点，palm_action_event_reporter.cpp:23-109）
   ├ 会话级字段直读 FlowContext（session_id/trace_id/palm_mode/
   │   opt_frame_image_id/opt_live_duration_ms/start_source/traceparent）
   ├ 事件差异字段从 Params（action_type/route/retry/wait/submit/server_code）
   ├ 计算字段现场算（client_event_cost = now - ctx.start_time；
   │   happen_time = 墙钟 ms）
   ├ 空值裁剪：optional 无值不装；opt_frame_image_id 空串合法照装
   ├ JSON 留痕（DEBUG_BUILD LOG_I / RELEASE LOG_D，:98-102）
   └ rp.Commit() → report 框架（业务上报串讲 4.2 两阶段填充）
        → 25261 队列 → Builder（client_trace_id→traceId、traceparent→spanId、
           happen_time→timeUnixNano）→ /iot/report/logs
```
分层关键：**「参数结构与协议结构分离」**——Params 只承载「每个事件点不同的输入」（.h:20-23 注释），会话级字段不重复定义、Emit 直读 ctx——**一处定义、一处装载**，字段口径不可能漂移。

### 2.2 核心数据流（一次混合会话的事件族）
```
StartPalm（host）→ 会话 ctx（session_id=trace_id 前 12 位、start_source="host"）
 → 识别收敛 → Emit(palm.recognition.result, route=cloud, server_response_code=100025)
   → ctx.event_actions_log.push_back（:1270）
 → Hybrid 切注册 → 绑定收敛 → Emit(palm.binding.result, wait_ms/submit_ms)
   → event_actions_log 再 push
 → 会话结束 → Emit(palm.session.end, end_state=fail, event_actions=
   "palm.recognition.result,palm.binding.result"（join ","）, last_state=WaitingBindInput)
 后台按 session_id 聚合三条事件 → 会话轨迹与分段耗时全景
```

## 3. 逐模块实现讲解  [15min · 业务意图先行]

### 3.1 `PalmSessionReportItem`：18 字段协议　palm_session_report_item.h
- **to_json 条件写键**（:135-159）：9 必填无条件写；9 条件 `if (has_value)` 才写——**裁剪逻辑在类型系统里，不在 if-else 链里**。
- **空 Fill 钩子**（:163-164）：`FillInContext/FillBeforeQueue` 显式空实现——声明「本协议字段全部由 Emit 显式装载，无自动填充需求（设备标识在 Resource）」——与 report 框架两阶段填充的对接契约（业务上报串讲 4.2）。
- **无快捷函数声明**（:166-170）：设计决策写明三点理由——第二装载点=字段漂移风险；service 层不能依赖 biz 层 FlowContext（**方向不可倒**）；新增字段/新 action 一律改 Emit 一处。

### 3.2 `PalmActionEventReporter::Emit`：装载实现　palm_action_event_reporter.cpp:23-109
- **装载三段**：协议基线（:36-53，会话级直读 ctx + 计算字段现场算）→ 条件字段（:55-81，Params 的 optional 逐一搬运）→ session.end 专属（:83-91）。
- **happen_time 的注释**（:52）：「Builder 用其覆写 timeUnixNano，**消除断网重试偏移**」——事件时间与投递时间的正交（业务上报串讲 4.4 的 builder 侧对偶）。
- **JSON 留痕**（:93-102）：通用管道的 LOG_D 已注释化（面向全协议噪音大），改在本汇合点打印——**5 个 action 每会话 ≤5 条，日志量有界**；按构建类型分级（DEBUG LOG_I 落盘 / RELEASE LOG_D）。
- 异常兜底 try/catch（:105-108）——装载失败不上抛、不 crash。

## 4. 核心代码实现细节与原理（重点）  [10min · 讲透原理]

### 4.1 深挖①：单汇合点的三重价值（item.h:166-170）
- **防字段漂移**：10 个发射分支若各自装载，同名字段的取值口径必然分裂（此字段取 exit_code 还是 server_code？彼处空串还是不装？）——单汇合点把口径决定权集中到 Emit 一处。
- **依赖方向**：service 层（report）不能 include biz 层（FlowContext）——**方向不可倒**；所以装载点放 biz 层（palm_action_event_reporter 在 biz/comm/palm_session），service 层只有纯数据结构。
- **演进成本**：新增字段改三处固定清单（Params 加 optional + Emit 搬运 + to_json 写键）——机械且可 review；新增 action 只加常量 + 发射点。

### 4.2 深挖②：空值裁剪的类型系统化
- **四种空值语义并存**（.h:25-30 注释）：`nullptr → 不装`（action_type/route）；`optional 无值 → 不装`（条件 9）；**local 路径 ctx.traceparent 为空自然不装**（因果裁剪）；`opt_frame_image_id 空串合法照装`（FR-3 #9 未命中优选帧——空串是事实不是缺失）。
- **为什么不用 if-else 链**：裁剪规则随字段类型走（optional 的 has_value 内建）——新增字段零裁剪代码；漏装错误在 review 一眼可见（搬运遗漏=永不写键）。

### 4.3 深挖③：会话轨迹的聚合机制（event_actions_log）
- ctx 维护 `event_actions_log`（vector<string>），每条业务事件 Emit 后 push（发射点 :561 等）；session.end 时 join "," 成 `event_actions`、末位作 `end_action`（Params :55-56）。
- **last_state 的定位价值**（item.h:129-133 注释）：abort 会话 end_action/event_actions 为空——`last_state`（FlowStateName(ev.from)）是唯一线索，回答「死在哪个流程阶段」（Detecting/OptPassed/Verifying/WaitingBindInput/WaitingScanInput）。

### 4.4 深挖④：跨通道口径统一（Logs vs Metrics）
- work_mode 与 route 的字符串值**两通道共用**（report_attribute_keys.h:35-38 注释明示「Logs/Metrics 两通道共用，语义相同」）——PalmModeToString（reporter.cpp:12-21）同时服务 25261 的 work_mode 与 OTel 的 palm_mode 标签。
- 唯一历史遗留：**常量名 `kRouteRemote` 的值是 "cloud"**（attribute_keys.h:27）——重命名前叫 remote，值先统一、名未跟上（E3）；**改值危险（双端契约），改名安全**。
