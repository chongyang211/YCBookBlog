# Network · 04 传输层与执行载体

> 系列第四篇，承接《01.请求管线与网络模块.md》。覆盖 HttpRequest（cpr 封装）的初始化与双形态、网络状态单例、统计与执行载体盘点。

## 一、HttpRequest：cpr::Session 封装（http_request.cpp，116 行）

### 1.1 首次构造一次性初始化（StaticInitializer，:49-63）五件事

```text
① curl_global_init(CURL_GLOBAL_DEFAULT)
② 内置 CA 装载：kEmbedCaCert → AES-GCM 解密（硬编码 16B 密钥 :23）
   → ZSTD 解压 → curl_blob（CURL_BLOB_NOCOPY）        （:22-46）
③ curl_share_init 共享 DNS / SSL_SESSION / CONNECT 三类数据
   （配全局锁函数 CurlShareLockFunc/Unlock :15-20）——多 Session 共享连接池/DNS
④ cpr::async 线程池 max 扩到 32（注释 "MUST run first"，:62）
⑤ 每 Session：禁系统 CA（CAPATH/CAINFO=nullptr）只信内置 blob
   + DNS 缓存 60s→1h（:73）
```

### 1.2 双形态与线程归属

| 形态 | 执行地 | 消费方 |
|---|---|---|
| Sync（GetSync/PostSync/PutSync/DownloadSync） | **调用方线程阻塞** | Network 管线（全部 IoT 请求）、OTA 下载 |
| Async（GetAsync/PostAsync/.../DownloadAsync） | **cpr::async 自带线程池**（max 32）→ 完成后 post 回调用方 executor | OTA 下载 DownloadAsync 等直用方（Network 管线未用） |

### 1.3 OTA 专属选项（构造不带，避免影响 IoT/License）

- SetLowSpeedLimit(bytes_per_sec, timeout_sec)：低速熔断（<1KB/s 持续 30s abort）；
- SetTcpKeepAlive(on, idle, interval)：TCP keepalive（死链早发现）。

详见 OTA 下载文档（.idea/v2.2.0/ota-download-observability-plan.md）。

## 二、NetworkInfo：全局网络状态单例（network_info.h）

- NetworkType（None/Cellular/Wifi/Ethernet/Other）+ ConnectState（Disconnected/Connecting/Connected/Unknown）+ 离线模式（atomic）；
- **写入口 friend 门禁**：UpdateNetworkType/UpdateConnectState 仅 friend class NetworkMonitorService 可调——状态源唯一（监视服务全流程见《10.网络监视服务全流程.md》）；
- 对外只读：IsConnected() / InOfflineMode() + OfflineModeStateChangeSig。

## 三、NetworkStat：请求统计（network_stat.h）

- 每请求经 ReportDeviceRequest 上报（管线 SCOPE_EXIT 保证无论成败必记）：path/error/上下行字节/耗时；
- GetLastNetAvailableTime()：最近一次网络可用时间点——断网恢复类加速路径的判定依据。

## 五、观察点

1. **Network 管线全同步**：Async 方法存在但管线未用——各调用方靠专用线程（network/license/iot）隔离阻塞，主线程直调会卡业务；
2. cpr 线程池由 OTA DownloadAsync 等直用方消费，容量无监控；
3. curl share 句柄进程生命周期持有不释放（单例语义，可接受）；
4. DualLinkTdiRequest 是 stub（恒返回 -1，network.cpp:732-737）——消费前须确认未接入。
