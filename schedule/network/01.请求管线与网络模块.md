# Network · 02 请求管线与网络模块（facility/network）

> 范围：`src/facility/network/`。设备侧**全部 HTTP 出网的唯一通道**：请求管线（签名/trace/域名/响应解析/错误分类）+ 网络状态单例 + 统计 + 诊断子树。承接《01.网络监视服务全流程.md》（service 层监视服务是本模块 NetworkInfo 单例的唯一写方与下游联动方）；诊断细节另见《network-diagnosis-handbook.md》。

## 二、IoT 请求管线全流程（IotDeviceRequestImpl，network.cpp:468-637）

### 2.1 端到端时序（标注线程归属）

```text
调用方线程（network/license/iot 等专用线程，全程阻塞）
  │
  1. SCOPE_EXIT 统计（:482-485）：无论成败/异常，退出时
     NetworkStat::ReportDeviceRequest(path, error, 上下行字节, 耗时)
  2. CHECK_IOT_DEVICE_HOST_SET（:101 宏）：iot_device_host_ 未设置
     → ERR_PALM_IOT_HOST_NOT_SET 直接返回（未激活期域名未注入）
  3. 签名（:501-514 四选一，见第三节）→ Authorization header
     签名失败（SE 未初始化等）→ ERR_PALM_IOT_SIGN_FAILED，不发网络请求
  4. trace 决策（:529-540，story 137332527/135784881）：
     override_trace_id 非空（刷掌会话/激活会话串联）→ 复用 + 随机 span
     否则 GenerateTraceparent(true)：锁内新 32hex trace + 16hex span
     裸 trace_id 从 header 固定位移 [3,35) 提取——避免锁外回读共享成员
  5. Header 装配（:547-551）：Authorization + Content-Type(json/protobuf)
     + Accept + traceparent；zerus 非空再 UpdateHeader x-zerus-env
     （调试环境路由，device_debug 云属性，仅首条 LOG_I 防刷屏 :558-564）
  6. body 日志门控（:578-586）：log_body=false 时只打长度——
     palm_data/特征/encrypted_key 等敏感 body 禁止入日志（接入红线）
  7. 同步发送（:590-604）：PostSync/PutSync/GetSync → libcurl（阻塞在调用方线程）
  8. 汇总日志（:608）：method path -> status (耗时ms) trace up/down 字节数
  9. ParseIoTHttpResponse（:216-282）统一解析 → IoTResponse
     （error_code, server_code, body, error_message, trace_id, traceparent 全量回带）
```

### 2.2 响应解析决策树（ParseIoTHttpResponse，:216-282）

```text
cpr error 对象存在？
  ├─ 是 → ClassifyCprError 归类（第四节表）+ error.message + trace 尾缀
  └─ 否 → body 可解析出 {"code": N}？
        ├─ N != 0 → server_code=N + ERR_PALM_IOT_HTTP_SERVER_ERROR(20407)
        │            error_msg = 本地文案 "Server error: code=N"（服务端原文仅进日志）
        ├─ 解析异常（非 JSON）→ 按下方 status 分支走
        └─ code==0 或无 code 字段
              ├─ status==200 → SUCCESS
              ├─ 4xx → 20104
              ├─ 5xx → 20407
              └─ 其他（3xx 等）→ UNKNOWN_ERROR
所有分支均回带 trace_id + traceparent（with_trace 包装，:223-227）
```

### 2.3 域名管理（:120-154）

`SetIotDeviceHost` 存 raw host（自动剥 https:// / http:// 前缀）：

| 取值接口 | 返回 | 用途 |
|---|---|---|
| GetIotDeviceHost | `https://{host}` | HTTP URL 拼接 |
| GetDeviceDomainHost | raw `{host}` | `link-{host}` 端点（MQTT broker / NTP，facility 04/10 篇） |

`SetActivationSession(domain, session_id, session_key)` 三件套注入（激活期），`ClearActivationSession` 激活成功后清。

## 三、签名体系（四型，:371-465）

**公共骨架**：nonce(32 随机) + timestamp(秒) + `SHA256(method\n path\n ts\n nonce\n body\n)` → 按 scheme 签名 → `Authorization: {scheme} device_sn=...,nonce_str=...,signature=...,timestamp=...[,session_id=...]`

| IoTSignType | scheme | 密钥来源 | 包装 |
|---|---|---|---|
| SIMPLE | SIMPLE-HMAC-SM3 | 固定密钥 kSimpleSignKey | 裸 base64 |
| ACTIVATION | ACTIVATION-HMAC-SM3 | **激活会话密钥**（SetActivationSession 注入，激活成功 ClearActivationSession） | 带 session_id |
| DEVICE | IOTDEVICE-SHA256-SM2 | **SE SignDataHash** | PalmSignPackage protobuf（type=DeviceAuthSign） |
| RECOGNIZE | 同上 | **SE SignPayAuth（anti_replay=true）** | type=DeviceRecogSign |

SE 未初始化 → 签名返回空 → 请求直接失败 `ERR_PALM_IOT_SIGN_FAILED`（不发网络请求）。

## 四、错误分类与文案治理（本模块最有味道的部分）

**ClassifyCprError**（:179-214，IoT 与 OTA 下载共用）：

| 码 | 场景 |
|---|---|
| 20101 | OPERATION_TIMEDOUT |
| 20102 | 网络断（连接失败/DNS/收发失败/代理解析 5 种 cpr 码） |
| 20105 | **SSL 证书独立成码**（story 137332527）——握手/证书校验失败含"设备时间不对导致 not-yet-valid"，可行动性强（联动 NTP 预同步） |
| 20104 | TLS 拆分后残余 + 4xx + 意外状态码 |
| 20407 | 5xx |

**error_msg 文案治理**（:228-254）：

- 服务端**原文仅进日志**（LOG 原文 + trace_id 后台检索）——不透传 error_msg，防网关包装的 gRPC 错误串（如 "Unauthenticated: rpc error:…"）污染 UI；
- error_msg 统一本地文案（"Server error: code=N"）+ **`[trace_id:xxx]` 是唯一允许的附加尾缀格式**（network.h 治理约束）；
- `kErrorMsgMaxLength=512` 防变长 string 溢出 uint16 前缀，超长**砍头保尾**（BuildErrorNotification :63-68——尾部含具体原因与 trace 尾缀，不可丢；截断是 BuildErrorNotification 的职责，非 Parse 层）；
- **BuildErrorNotification**（:42-70，对外通知的统一出口）：server_code 非 0 时经各链路注入的 `ServerCodeMapper` 映射为通知码；**漏传 mapper → LOG_W 留痕**（"复用面变大后是高发坑"）——新链路接入必须传 mapper，否则静默丢映射；
- 空文案兜底：有 server_code → "Server error: code=N"，否则 "error_code:N"。

**IsNetworkError 收录规则**（:72-92 注释，重试语义的权威定义）：

| 码 | 收录 | 理由 |
|---|---|---|
| 20101 TIMEOUT | ✓ | 纯网络 |
| 20102 NETWORK_ERROR | ✓ | 纯网络 |
| 20104 CLIENT_ERROR | ✓（保守） | **混合语义**：(a) 网络类错+IsConnected（DNS/TCP 瞬时，占绝大多数）；(b) 4xx 无业务结构（当前腾讯网关 4xx 带 code → 走 20407）——若未来出现 20104 死循环，收敛为只留 20101+20102 |
| 20105 SSL_CERT | ✗ | 证书问题重试无意义（可行动：查证书/NTP） |
| 20407 / 20205 / UNKNOWN | ✗ | 后台已明确响应或本地永久错 |

## 五、周边组件

- **HttpRequest**（http_request.cpp）：cpr::Session 封装。**首次构造触发一次性初始化**（StaticInitializer，:49-63）五件事：① curl_global_init；② **内置 CA 证书装载**——kEmbedCaCert 经 AES-GCM 解密 + zstd 解压为 curl_blob（:22-46，硬编码 16B 密钥，混淆级）；③ curl_share_init 共享 **DNS / SSL_SESSION / CONNECT** 三类数据（配全局锁函数）；④ cpr::async 线程池 max 扩到 32（注释 "MUST run first"）；⑤ 每 Session 禁系统 CA（CAPATH/CAINFO=nullptr）只信内置 blob + **DNS 缓存 60s→1h**（:73）。SetLowSpeedLimit / SetTcpKeepAlive 仅供 OTA 下载（构造不带，避免影响 IoT/License）。Async 方法走 cpr::async 自带线程池（又一执行载体）；Sync 在调用方线程直跑；
- **NetworkInfo**：NetworkType + ConnectState + 离线模式（atomic）+ OfflineModeStateChangeSig；写入口 friend 门禁（唯一写方 NetworkMonitorService，见《01》篇）；
- **diagnosis/**：5 策略检测链 → 自动测速（4 触发：网络切换/断网恢复/检测后/30min 周期）→ 弱网分级 → DiagnosisReporter 上报 25261 + SpeedTestNotifier 0xA7 推上位机（story 137345399，Phase2 装配）——详见《network-diagnosis-handbook.md》。

## 七、观察点

1. **管线全同步**：IotDeviceRequestImpl 用 PostSync 在调用方线程阻塞——HttpRequest 的 Async 方法存在但 Network 管线未用；各调用方靠专用线程（network/license/iot）隔离阻塞，主线程直调会卡业务；
2. **SE 签名串进请求延迟**：DEVICE/RECOGNIZE 签名在调用方线程同步走 SE——识别高频请求每次多一次 SE 操作（RECOGNIZE 为 anti_replay=true，SE 内部多一步计数）；
3. **iot_device_host_ / session_id_ / session_key_ 无锁**：写在激活流程、读在各请求线程——激活期间无并发请求所以实际安全，但属"靠时序保证"的无保护共享；
4. **trace 三级体系**：请求级（默认新 trace）/ 会话级（刷掌 override，story 135784881）/ 激活级（ActivationService 持有串联，story 137332527）——网络层是默认生成点，override 优先；
5. **log_body 门控的血泪注释**（:578-586）：此前该日志无条件打印，请求 body（palm_data/特征/密钥）一直在泄——**敏感 body 调用方必须传 log_body=false，接入红线**；
6. **两处硬编码密钥均属混淆级**：kSimpleSignKey（SIMPLE 签名固定密钥，:98）与内置 CA 的 AES 密钥（http_request.cpp:23）——源码可见，防直读不防逆向，安全边界同《06.Config与Cache持久化.md》第四节第 1 条；
7. **执行载体再 +1**：HttpRequest 的 Async 方法走 cpr::async 自带线程池（max 32，:62）——与 Threads::Pool/scheduler iot_pool_ 并存的第三个通用池；Network 管线当前只用 Sync，该池实际由 OTA DownloadAsync 等直用方消费；
8. `kDefaultSslPath "/etc/ssl/certs"`（network.cpp:95，注释 "use system bundled ssl ca for now"）疑似遗留——实际证书链路已切内置 CA blob（系统 CA 在 Session 构造中被显式禁用），该常量勿再引用；
9. DualLinkTdiRequest 是 stub（恒返回 -1，:732-737）——消费前须确认未接入。
