# Network · 02 签名与安全

> 系列第二篇，承接《01.请求管线与网络模块.md》第二节（管线中"四选一签名"一步的展开）。覆盖签名体系、SE 依赖链、内置证书链与安全边界。

## 一、签名体系（四型，network.cpp:371-465）

**公共骨架**：nonce(32 随机) + timestamp(秒) + `SHA256(method\n path\n ts\n nonce\n body\n)` → 按 scheme 签名 → `Authorization: {scheme} device_sn=...,nonce_str=...,signature=...,timestamp=...[,session_id=...]`

| IoTSignType | scheme | 密钥来源 | 包装 |
|---|---|---|---|
| SIMPLE | SIMPLE-HMAC-SM3 | 固定密钥 kSimpleSignKey | 裸 base64 |
| ACTIVATION | ACTIVATION-HMAC-SM3 | **激活会话密钥**（SetActivationSession 注入，激活成功 ClearActivationSession） | 带 session_id |
| DEVICE | IOTDEVICE-SHA256-SM2 | **SE SignDataHash** | PalmSignPackage protobuf（type=DeviceAuthSign） |
| RECOGNIZE | 同上 | **SE SignPayAuth（anti_replay=true）** | type=DeviceRecogSign |

**使用方速查**：

| 链路 | 签名型 |
|---|---|
| 激活 registration 查询（ActivationGetRequest） | SIMPLE（network.cpp:712-717） |
| 激活 start / confirm-key-change | ACTIVATION |
| 激活 confirm | DEVICE（以设备身份通知） |
| 常规 IoT（license/shadow/ota/heartbeat/report） | DEVICE（默认） |
| 识别 / 注册（palm_flow） | RECOGNIZE |

SE 未初始化 → 签名返回空 → 请求直接失败 `ERR_PALM_IOT_SIGN_FAILED`（**不发网络请求**——管线第 3 步短路）。

## 二、SE 依赖链

DEVICE/RECOGNIZE 签名委托 SeKeyStore（SM2，私钥不出芯片）：

```text
GenerateDeviceAuth：SeKeyStore::SignDataHash(sha256_hex)
  → PalmSignPackage{version="1", sign, type="DeviceAuthSign"} 序列化 + base64
GenerateRecogAuth：SeKeyStore::SignPayAuth(sha256_hex, anti_replay=true, need_base64=false)
  → PalmSignPackage{..., type="DeviceRecogSign"}
```

性能注意：签名在**调用方线程同步执行**——识别高频请求每次多一次 SE 操作，RECOGNIZE 的 anti_replay=true 在 SE 内部还多一步计数。详见《docs/facility/09.SeKeyStore.md》。

## 三、内置证书链（http_request.cpp）

```text
编译期内嵌 kEmbedCaCert（AES-GCM 加密 + 压缩）
  → 首个 HttpRequest 构造时（StaticInitializer）：
    AesGcmDecrypt（硬编码 16B 密钥，:23）→ ZSTD 解压 → curl_blob（CURL_BLOB_NOCOPY）
  → 每个 Session：禁系统 CA（CURLOPT_CAPATH/CAINFO=nullptr）→ 只信内置 blob
```

配套决策：SSL 证书错误独立成 20105（可行动：查证书/NTP——设备时间不对是证书 not-yet-valid 的常见根因，联动激活前 NTP 预同步）。系统 CA 路径常量 `kDefaultSslPath`（network.cpp:95）为遗留物，勿再引用。

## 四、安全边界（观察点沉淀）

1. **两处硬编码密钥均属混淆级**：kSimpleSignKey（SIMPLE 固定密钥，network.cpp:98）与内置 CA 的 AES 密钥（http_request.cpp:23）——源码可见，防直读不防逆向；安全边界同《docs/facility/06.Config与Cache持久化.md》第四节第 1 条；
2. **log_body 接入红线**（:578-586）：此前该日志无条件打印，请求 body（palm_data/特征/encrypted_key）一直在泄——**敏感 body 调用方必须传 log_body=false**；
3. 私钥类材料（会话密钥/SE 私钥）不经本模块落盘——session_key_ 仅内存持有，激活成功即 ClearActivationSession。
