
# OTA 状态上报全流程

## 一、上报通道与状态定义

- 通道：`ReportUpgradeStatus` → HTTP `/iot/devices/{sn}/upgrade-status/report`，经 `ReliableRequest` 可靠队列（终态必达、断网补发、request_id 幂等）（`upgrade_schd.cpp:1284-1290`）。
- 状态值定义（`upgrade_schd.cpp:55-58`）：

| status | 含义 |
|---|---|
| 6 | 下载中 |
| 7 | 安装中 |
| 3 | 升级成功 |
| 4 | 升级失败 |

每个任务（按 task_uid）生命周期内依次上报：`6 → 7 → 3/4`，或在下载阶段夭折为 `6 → 4`。

## 二、全流程状态上报时序

```
云端任务下发（轮询/MQTT）
  │
  ├─ FilterUpgradeTasks 预筛
  │    ├─ 本地版本 == 目标版本 → 上报 [3] 成功, err=0（视为已达成）
  │    ├─ 本地版本 >  目标版本 → 上报 [4] 失败, err=30519（只升不降）
  │    └─ 通过 → 进入下载
  │
  ├─ 下载开始     → 上报 [6] 下载中, err=0          (FR-1)
  │
  ├─ 下载失败     → 上报 [4] 失败
  │    ├─ MAC/MD5 校验失败       err=30503
  │    └─ 其他全部失败           err=20407 *（v2.2.0 拆分为 30510/30502，见注）
  │
  ├─ 下载成功 → 安装开始 → 上报 [7] 安装中, err=0   (FR-3)
  │
  ├─ 安装失败     → 上报 [4] 失败                   (FR-5)
  │    ├─ installer 缺失          err=30512
  │    ├─ 安装超时                err=30508
  │    └─ 其他安装错误            err=30511
  │
  ├─ 安装成功 → 重启（此阶段不上报）
  │
  ├─ 重启后版本核对
  │    ├─ 版本匹配               → 上报 [3] 成功, err=0
  │    └─ 版本不匹配             → 上报 [4] 失败, err=30511
  │
  └─ 整体流程超时（>1h，轮询入口检查）→ 上报 [4] 失败, err=30515  (FR-6)
```

## 四、几点补充说明

1. **同一轮只升一类**：SE > ROM > APP 取最高优先级的一类执行（`upgrade_schd.cpp:523-539`），一轮上报只涉及该类中最高版本的任务。
2. **多任务批量下载**：下载阶段逐任务上报 `6`，某任务下载失败即报 `4` 并终止该任务；整体下载失败（如列表请求失败）不逐任务补报。
3. **重启恢复路径**：重启后靠持久化 session（task_uid / 安装前基准版本）补报终态；session 缺 `current_version` 时按 application_id 反查兜底（`upgrade_schd.h:220-224`）。
4. **中途断电/强杀**：无 `4` 失败上报，任务由后台超时策略收敛（设备侧 30515 仅在轮询仍在跑时触发）。
5. **对照提醒**：本通道错误码与 PosLink 通知上位机的错误码是**两套体系**（PosLink 传原始码，本通道传映射码），勿混用。
