## 〇、函数定位

```text
ExecuteUpgradeQuery（每 60s 轮询 / MQTT push 触发）
  → FilterUpgradeTasks（版本比对，已满足则跳过）
  → DownloadAllTasks（循环）                upgrade_schd.cpp:641
      └─ DownloadTask(单个任务)             :688   ← 本文档主体
  → ADVICE gate → InstallAllTasks
```

每次 `DownloadTask` 处理**一个**升级任务，返回 `0=成功` 或原始错误码。

## 一、DownloadTask 流程（upgrade_schd.cpp:688）

### 1. 准备与开始埋点（:689-705）

| 步骤 | 内容 | 通道 |
|---|---|---|
| 确定下载文件名 | `GetDownloadFilename(task)` | — |
| 埋点 `kOtaStartDownload` | version + sub_appid | 16160 |
| 任务页上报 `Downloading(6)+0` | 后台任务页进入"下载中" | upgrade-status/report |

### 2. 进度心跳回调（:707-732）

- 心跳间隔 = **kLowSpeedTimeoutSec（60s）**——与 curl 低速熔断窗口绑定同一常量
  （`DownloadService` 构造节流器时显式传入），调整熔断窗口会同步改变心跳频率；
- 节流器 `DownloadProgressThrottler` 内层限频后触发，组装 16160 埋点：
  - `progress_pct`：`(offset+now)/total` 绝对百分比，clamp 0~100；Content-Length 未知时 **-1**（不猜值）；
  - `speed_bps`：尾部窗口滑动平均速率（**停滞期报 0——弱网归因最有用的信号**）；
  - `task_uid` + `version`：与后台任务关联键；
- Commit 走 HeartBeat 线程异步入队，不阻塞下载线程；回调异常被节流器吞掉（FR-5）。
- 边界：首个间隔内完成的下载无进度事件（只有 start + success/fail）。

### 3. `DownloadService::Download` 内部（download_service.cpp:141）

```text
① 缓存检查：目标文件已存在且 MD5 匹配 → 直接返回路径（跳过下载，文件级"断点"）
        │ 未命中（MD5 不符则删缓存文件）
        ▼
② 策略分支（云端 device_ops.download_strategy 下发，缺省 FULL）
  NONE：trunc 打开 .crdownload，直下（无断点语义）
  FULL：追加方式打开 .crdownload → seekp 尾部取 offset
        → offset>0 时 Range 探测（GET Range:bytes=0-0，15s 总超时）：
             206 → 服务端支持续传，保留 offset          download_service.cpp:255
             200/416 → 不支持（或 offset 越界）→ truncate 从头重下
             其他（网络错/5xx）→ 本轮失败                :272
        → 带 Range: bytes={offset}- 主下载               :285
③ 传输中守护（FULL/NONE 同）：
     限速 1MB/s（上限保护）
     总超时 15min（超时报 20101 → 平台 30510）
     低速熔断：最近 60s 平均 < 1KB/s 断开（窗口 2026-10-19 复盘由 30s 放宽，
       依据：误杀一次≈平台退避数分钟，多等 30s 仅失败确认变慢；
       僵尸爬行边缘由 15min 总超时兜底）
     TCP keepalive（idle 60s / interval 30s）
     10MB 粒度本地日志 ＋ 60s 心跳（16160）
④ 完成链：状态码 2xx 校验 → MD5 校验（失败删半成品，防脏数据）→ rename 落盘
返回：variant<string 落盘路径> 或 int32 错误码
```

**断点续传的文件级保障**：

- 半成品固定后缀 `.crdownload`，与正式文件隔离；失败保留、成功 rename；
- `DownloadAllTasks` 清理下载目录时**显式排除** `.crdownload`（upgrade_schd.cpp:653），
  断点跨查询周期、跨进程重启均有效；
- MD5 校验失败（换包/半包）时主动删除 `.crdownload`，杜绝脏续传。

### 4a. 失败分支（:753-766）——四条通道一次收口

| 顺序 | 通道 | 内容 |
|---|---|---|
| ① | task 标记 | `download_success=false`，`download_error_code`=**原始码** |
| ② | 埋点 `kOtaDownloadFail` | `result_code`=**原始细码**（30520/20101/…）+ `timecost` |
| ③ | 上位机 PosLink | `FAILED` + 原始码；msg 含 `ToReportCode` 映射码 |
| ④ | 任务页 `ReportUpgradeStatus` | `Fail(4)` + `ToReportCode` 映射码（见下表） |

返回原始 `error_code` 给调用方。

**错误码映射表（`ToReportCode`，upgrade_schd.cpp:66）**：

| 原始码 | 场景 | 任务页上报码 |
|---|---|---|
| 20101 | 请求超时（15min 总超时 / 连接超时） | **30510** 下载超时 |
| 30520 | **弱网低速熔断**（60s 均值 <1KB/s 被低速保护断开） | **30520** 透传——平台据此归因终端弱网 |
| 30503 | MD5 校验失败（配错包） | **30503** 透传 |
| 其余（20102/20104/20105/20407…） | 连接失败 / 4xx / 5xx 等 | **30502** 其他下载失败 |

弱网判定 `IsLowSpeedAbort`（download_service.cpp:67）：libcurl 把"低速中止"与
"普通超时"都归为 `OPERATION_TIMEDOUT`，按消息文案 `"too slow"` 区分——
依赖 libcurl 文案，跨版本升级需回归验证。

### 4b. 成功分支（:769-775）

- `task.download_path` 记录落盘路径，`download_success=true`；
- 埋点 `kOtaDownloadSuccess` + `timecost`（`result_code=0`）；
- 任务页/上位机此阶段**不推进**（Installing 在安装阶段才发）。

## 二、重试机制：三层，逐层说明

### 层 1：文件缓存（同 URL 重试零成本）

`Download()` 入口先查目标文件——已存在且 MD5 匹配直接返回。适用"下载成功但
后续安装阶段失败重走"的场景。

### 层 2：断点续传（跨查询周期 / 跨重启）

FULL 策略内建 Range 续传：`.crdownload` 保留 + probe 探测 + `Range: bytes={offset}-`。
设备重新进入下载时从断点接力，已下载字节零浪费。
**实测（2026-10-19 事故）**：三次下载接力 10.9MB → 19.3MB → 完成，
19,299,266 + 37,528,298 = 56,827,564，与首次 total 分毫不差。

### 层 3：跨会话轮询重试（设备 60s 待命 + 平台控制节奏）

```text
下载失败 → 上报 Fail(4)+错误码 → FinishUpgrade 结束本轮
设备侧：upgrade_query 调度器每 60s 查询一次，任务仍在则重新进入下载（续传接力）
平台侧：收到失败上报后按退避策略隐藏任务（2026-10-19 实测隐藏 8 分钟，count:0×7）
```

**重要：设备侧无本地立即重试**——失败即上报、结束本轮，重推节奏完全由平台
退避策略决定。弱网场景下这是总时长的最大变量（事故复盘：19 分钟总时长中
8 分钟耗在平台退避空窗）。优化方向（未实施，需评估）：
① 平台对 30520/30510 缩短重推退避；② 设备侧本地快速重试（改失败上报语义，单独立项）。

## 三、已知边界与注意项

| # | 边界 | 说明 |
|---|---|---|
| 1 | 僵尸爬行 | 网络维持恰好 >1KB/s 的平均速率时低速熔断不触发，靠 15min 总超时截断（此时报 30510 而非 30520） |
| 2 | probe 低速保护是死配置 | probe 总超时 15s < 低速窗口 60s，低速保护永不触发；probe 失败（网络错/5xx）**直接放弃本轮下载**，不降级为截断重下——已知可优化点 |
| 3 | 弱网判定依赖 libcurl 文案 | `"too slow"` 子串匹配，libcurl 升级需回归验证 |
| 4 | 心跳频率与熔断窗口绑定 | 同为 kLowSpeedTimeoutSec（60s）——调熔断窗口会同步改变心跳粒度（2026-10-20 review 确认的设计耦合，有注释声明） |
| 5 | 批次部分失败 | 任一任务失败 → 整体返回非 0 → 本轮全部任务不进安装（DownloadAllTasks 语义，:681-683） |
| 6 | 下载无本地重试 | 失败即四通道收口，重试依赖平台重推 + 断点续传接力 |

## 四、实战案例（2026-10-19，A4O400SPG11001405RH5E6X）

| 时刻 | 事件 |
|---|---|
| 16:37:44 | 查到 ROM 2.1.0.137，FULL 下载启动（56.8MB） |
| 16:39:56 | 进度 10.5MB（~146KB/s）→ 链路骤停 |
| 16:40:37 | 熔断（<1KB/s 持续 30s，当时窗口为 30s）→ 失败上报 |
| 16:40~16:47 | 平台退避空窗（任务隐藏，count:0）；期间心跳/OTA 查询多次超时 |
| 16:48:44 | 平台重推 → 续传 10.9MB（probe 206）→ 又下 8.4MB → 骤停 |
| 16:50:25 | 二次熔断 → 失败上报 |
| 16:51:44 | 平台重推 → 续传 19.3MB → 稳定 ~180KB/s |
| 16:55:05 | 下完（37.5MB 剩余）→ MD5 通过 → 安装 → 重启 |
| 16:56:20 | 版本验证 2.1.0.137，升级成功 |

该案例推动了：低速窗口 30s→60s、弱网熔断独立成码 30520、平台退避缩短建议。
