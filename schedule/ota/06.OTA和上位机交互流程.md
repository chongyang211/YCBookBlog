
# OTA 升级 · 模组与上位机（PosLink）交互流程

## 一、总体模型

- **升级的发起方是云端/模组，不是上位机**：模组通过定时轮询 HTTP + MQTT 下行推送两条路径获取升级任务（`upgrade_schd.cpp:266-313`），上位机没有任何“触发升级”的指令通道。
- **上位机在 OTA 中的角色只有两个**：
  1. **被动接收状态通知**（`PosUpgradeStatusChangeReq`，模组 → 上位机单向）；
  2. **ADVICE（建议升级）任务的用户确认**（`0xB3` 一问一答）。
- **后台任务页上报（`ReportUpgradeStatus` → IoT）与上位机通知是两条独立通道**，错误码体系不一致（见第五节）。

## 二、端到端时序

```
云后台                模组(palm_app_linux)                    上位机(palm_manager)
  │ 定时轮询/MQTT推送     │                                        │
  │────任务列表────────→ │ FilterUpgradeTasks(只升不降/优先级)      │
  │                     │ 下载阶段（无任何上位机通知）*             │
  │                     │ [仅 ADVICE 任务] 0xB3 弹窗询问 ────────→ │ 弹窗等用户选择
  │                     │ ←─────── 0xB3 resp(user_choice) ────── │ replyAdviceUpgrade
  │                     │ RequestEnter(kUpgrading)                │
  │                     │ ── Installing(0x02) ──────────────────→ │ "升级中"
  │                     │ 安装                                     │
  │                     │ 失败: ── Failed(0x05)+err ────────────→ │ "失败"
  │                     │ 成功: ── Rebooting(0x03) ─────────────→ │ "重启中"
  │                     │ 重启 → 版本核对                          │
  │ ←─ status 上报 ───── │ ── Success(0x04) / Failed(0x05) ─────→ │ 终态
```

## 三、分阶段说明

### 1. 任务获取与筛选（无上位机交互）

- 触发：`BaseFrequencyScheduler` 定时轮询（`ExecuteUpgradeQuery`），或 MQTT 下行（`MESSAGE_TYPE_DOWN_OTA=1`）即时触发（`upgrade_schd.cpp:266-313, 383-414`）。
- 筛选：按 appid 去重取最高版本；本地版本 ≥ 目标版本则拒绝（相同报成功、更低报 30519，仅报后台）；按 SE > ROM > APP 优先级取一类执行（`upgrade_schd.cpp:471-539`）。

### 2. 下载阶段（无上位机交互）

- 下载全程不通知上位机。下载失败在后续 `Failed` 通知中统一体现（`upgrade_schd.cpp:716`）。

### 3. ADVICE 确认关卡（唯一一次“上位机 → 模组”的决策交互）

仅对 `ADVICE`（建议升级）类型任务，下载完成后、安装前询问上位机（`upgrade_schd.cpp:434-447`）：

| 环节 | 说明 |
|---|---|
| 模组 → 上位机 | `0xB3 PosAppAdviceUpgradeNotifyReq{task_id, version, changelog, timeout_seconds}` |
| 上位机 SDK | 回调 `AdviceUpgradeListener.onAdviceUpgradeRequest(AdviceUpgradeInfo)`，业务层弹窗 |
| 上位机 → 模组 | `PalmManager.replyAdviceUpgrade(taskId, userChoice)`；`APPROVE=0x01` / `REJECT=0x02` |
| 超时兜底 | 模组 pos_link AsyncRequest 超时合成 `kUserChoiceTimeout=0x03`，业务侧倒计时归零应回 APPROVE（10s 无响应 = 直接装） |
| 老上位机 | 回复码 131（不识别 0xB3）→ 降级为直接安装 |
| 无 listener | SDK 立即代答 APPROVE |
| Reject/Timeout/无链路 | 任务本轮剔除，进 60min 冷却窗，沉默跳过（`upgrade_gate_handler.h:65-74`） |

### 4. 安装与终态通知（模组 → 上位机单向）

进入安装前先获取设备状态权 `RequestEnter(kUpgrading)`，被拒则放弃本轮（**无上位机通知**）；成功则 `NotifyModuleState(true)` 并进入安装（`upgrade_schd.cpp:449-466`）。

各终态/中间态通知点：

| 时机 | 通知 | 位置 |
|---|---|---|
| 开始安装 | `Installing(0x02)` | `upgrade_schd.cpp:811` |
| 安装失败 | `Failed(0x05)` + install 原始错误码（如 30508/30512） | `upgrade_schd.cpp:827` |
| 安装成功、准备重启 | `Rebooting(0x03)` | `upgrade_schd.cpp:864` |
| 重启后版本核对通过 | `Success(0x04)`（仅首次） | `upgrade_schd.cpp:1199` |
| 重启后版本不匹配 | `Failed(0x05)` + 30511 | `upgrade_schd.cpp:1204` |

## 四、协议定义

**状态变更通知** `PosUpgradeStatusChangeReq`（模组 → 上位机，模组端 `pos_request_handler.cpp:1171-1186`，上位机端经 `ConnectionManager.handleUpgradeStatusChange` 转 `UpgradeProgress`）：

| 字段 | 取值 |
|---|---|
| `upgrade_type` | 0x01=SE / 0x02=ROM / 0x03=APP |
| `upgrade_status` | 0x02=安装中 / 0x03=重启中 / 0x04=成功 / 0x05=失败（0x01=下载中**预留未用**） |
| `error_code` | 失败时的错误码，成功为 0 |
| `error_msg` | 描述文本 |

## 五、错误码两套体系（易混淆点）

| 失败场景 | 上位机收到的码（PosLink） | 后台任务页收到的码 |
|---|---|---|
| MD5 校验失败 | DownloadService 原始码 | 30503 |
| 下载超时 | DownloadService 原始码（多报 30502） | 30510 |
| 其他下载失败 | 原始码（多为 30502） | 30502 |
| 安装失败 | install 原始码（30508/30512） | 30508/30511/30512 |
| 重启后版本不匹配 | 30511 | 30511 |

- PosLink 通道传的是**原始错误码**，后台通道是**映射后任务页码**，两者不是同一套。
- 上位机 SDK 只消费成功/失败状态（demo 失败文案固定），**不消费错误码**。

## 六、上位机（palm_manager SDK）侧接口

| 接口 | 用途 |
|---|---|
| `UpgradeListener.onUpgradeProgress(UpgradeProgress)` | 接收状态通知（主线程回调） |
| `AdviceUpgradeListener.onAdviceUpgradeRequest(AdviceUpgradeInfo)` | 接收 0xB3 弹窗请求（主线程回调） |
| `PalmManager.replyAdviceUpgrade(taskId, userChoice)` | 回复用户选择，**必须**在超时窗口内调用 |

## 七、已知缺口（上位机收不到终态的场景）

以下失败路径**只报后台、不发 PosLink 终态通知**，上位机会停留在“升级中”状态：

1. 整体流程超时 >1h（`upgrade_schd.cpp:1261-1274`，后台 30515）；
2. 只升不降拒绝（`upgrade_schd.cpp:496-506`，后台 30519）；
3. ADVICE 关卡全部任务被剔除 / `RequestEnter(kUpgrading)` 被拒（`upgrade_schd.cpp:443-457`）。
