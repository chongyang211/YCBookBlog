## 一、模块角色

`IotUpgradeSchd`（单例）管理三类升级对象，各自带独立 installer：

| 类型 | 对象 | Installer | 说明 |
|---|---|---|---|
| kApp | PalmApp 自升级 | `AppInstaller` | opkg/自升级 |
| kRom | 系统 ROM | `RomInstaller` | 升级系统（内部走 SystemInterface） |
| kFirmware | SE 固件 | `SeFirmwareInstaller` | SE OTA SDK |

三者的共同抽象 `BaseUpgrade`：appid（session 恢复主键）、当前版本、下载目录、启停钩子。

## 二、触发：三种来源汇入同一入口

```
① 定时轮询    BaseFrequencyScheduler 注册 "upgrade_query" 任务
② MQTT 秒推   MESSAGE_TYPE_DOWN_OTA → HandleOtaPushMessage（OtaLinkMsg 完整任务体，免一次 HTTP）
③ 连接事件    MQTT ConnectedSig → OnMqttConnectionChanged(true) → 主动查一次
                    全部汇入 ExecuteUpgradeQuery(pushed?)
```

**轮询调频**：

- MQTT 已连：**5min** 兜底档（`kUpgradeQueryNormalMultiplier`）
- MQTT 断开：收紧 **1min**（`kUpgradeQueryNoPushMultiplier`）
- 查询失败：10min 退避档
- 连接恢复时额外主动查一次（避免错过窗口）；`requires_time_synced` 守卫

**互斥保护**：`LockBusy()` CAS 原子锁 + `Busy()` 短路——升级期间所有新查询直接跳过；每轮入口先 `CheckAndHandleUpgradeTimeout`（整体 1h 超时强收，FR-6 报 30515）。

## 三、查询与过滤（FilterUpgradeTasks）

```
batch-query HTTP（或 MQTT 推送体直接注入）
   ▼
FilterUpgradeTasks（upgrade_schd.cpp:471）：
  ① application_id 找不到本地模块 → 丢弃
  ② 版本比对：
      本地 ≥ 目标 → 同版本报 Succ(3)（平台重推收敛）/ 降级报 Fail(4)+30519，不执行
  ③ 同 appid 多版本 → 取最高
  ④ 优先级选择：SE > ROM > APP（一轮只做一种，APP 按 finish_action 排序）
```

## 四、下载阶段

```
DownloadAllTasks（串行逐任务）
  └─ CleanFolder 保留本批 .crdownload（断点续传）
  └─ DownloadTask：
      ① 埋点 kOtaStartDownload + FR-1: Downloading(6) 上报
      ② DownloadService::Download：
           缓存命中（dest 存在且 MD5 对）→ 直接复用
           FULL 策略：.crdownload + Range 探测（206 续传/200、416 截断）
           限速 1MB/s / 15min 超时 / 低速熔断 1KB/s@30s / ClassifyCprError 分类
           下载完成 CheckMac（MD5）→ 失败返回 30503
      ③ 成功：埋点 kOtaDownloadSuccess（含 timecost）
        失败：埋点 kOtaDownloadFail（result_code=原始细码）+ PosLink Failed
              + FR-2: Fail(4)+30503(MD5)/20407(其余折叠) 上报
```

单任务失败不中断批次（其他任务继续）；全失败则本轮结束，等下一轮查询重试（无熔断——MD5 失败已决策不做熔断，靠后台撤单）。

## 五、ADVICE 关卡（建议升级，story 136589242）

下载完成 → 安装开始之间，对 `upgrade_mode=ADVICE` 的任务**询问上位机**（`upgrade_gate_handler`）：
- Approve / 老上位机 131 降级 → 保留进入安装
- Reject / Timeout / 无链路 / 冷却窗内 → 剔除本轮，记冷却沉默
- FORCE / ATONCE 不经关卡直接装

关卡协程跑在主线程；被剔除后无任务存活 → `FinishUpgrade`。

## 六、安装阶段（OTA 专用线程）

```
NotifyModuleState(true)（模组进入升级态，DeviceFsm 已在 kUpgrading）
  ▼
InstallAllTasks 逐任务：
  ① curr_install_task_ 快照（含 pre_install_version）+ FR-3: Installing(7) + PosLink Installing
  ② DoInvokeUpgrade：installer->Install 扔独立线程，future.wait_for(超时保护)
       AppInstaller → opkg 安装（先持久化 ota_pending 供 guard 自愈派发）
       RomInstaller → SystemInterface::UpgradeSystem（协程回主线程）
       SeFirmwareInstaller → SE OTA SDK（内置包先复制副本防被删，1.7.1 fix）
  ③ 失败：PosLink Failed + FR-5: Fail(4)+30508(超时)/30511(执行错)/30512(无 installer)
    成功：**不上报成功**（安装命令返回 0 ≠ 真成功）
  ▼
全部完成：session_info（appid/target_version/notified）写 MMKV → RebootSync
```

**核心设计**：`install_result==0` 只代表安装命令成功，**真成功必须重启后版本号比对**——所有终态收敛推迟到重启后。

## 七、重启后闭环（CheckPendingUpgradeSession）

```
SetupUpgrades → CheckPendingUpgradeSession（MMKV 读 session）
  ▼
ExecuteUpgradePostLogic（upgrade_schd.cpp:1176）逐条目：
  FindUpgradeByAppId → GetVersion()（重启后的真实版本）vs target_version 比对
    ├─ 一致 → 上报 Succ(3) + PosLink Success（notified 去重，只弹一次框）
    └─ 不一致 → Fail(4)
  消化判定：
    成功/后台拒收/历史脏数据（无 plat_application_id）→ 可清 session
    仅网络类失败（IsNetworkError）→ 保留 session 下轮重试（回写 notified）
```

三条必守约束（代码注释原文提炼）：上位机通知只发一次（notified 持久化去重）；脏数据视为已消化；只有网络类失败才保留重试。

## 八、失败自愈配套

- `AppInstaller` 安装前持久化 `ota_pending`——装完 palmapp 起不来时 guard.sh 派发 `retry_ota`/`factory_reset`（错误码 50801）
- 整体 1h 超时 → 30515 收敛
- OTA 状态上报全部经 **ReliableRequest**（Succ/Fail critical 必达，四段幂等 request_id）

## 九、日志锚点（按时间序）

```
ota push received, msg_id: {msg.ShortDebugString()}          ← MQTT 秒推
start upgrade schedule, multiplier: {}s                       ← 轮询档位
mqtt connected/disconnected, upgrade query multiplier ->      ← 调频
filter upgrade tasks, SE/rom/app tasks sorted                 ← 过滤结果
downloading task {i}/{n}, task_uid:                           ← 下载开始（每任务）
download bytes: {now}, total: {total}                         ← 下载进度（每10MB）
download success/failed, elapsed_ms:                          ← 下载结果
installing task {i}/{n}                                       ← 安装开始
start install with timeout: {} seconds                        ← installer 超时
install success (NOT verified) ... will verify by version check ← 安装命令完成
caching upgrade session info, json:                           ← session 落盘
rebooting device in 3 seconds                                 ← 重启
found pending upgrade session                                 ← 重启后恢复
execute upgrade post logic, upgrade_infos count:              ← 终态比对
ota flow end, total_ms:                                       ← 全流程收尾
```

**一句话总结**：OTA 是“轮询/秒推双触发 → 过滤选优先级 → 下载（断点续传+MD5）→ 建议升级关卡 → 安装（超时保护+ota_pending 自愈锚点）→ 重启 → 版本比对定终态”的闭环；安装命令成功不算成功，重启后版本对上才算，全程状态经 ReliableRequest 必达上报。
