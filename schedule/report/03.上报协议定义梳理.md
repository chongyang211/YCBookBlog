
> 范围：`src/service/report/protocol/` 五个头文件。协议 = 一张后台表（log_id）的数据契约；本文梳理继承体系、各协议的定位/字段/使用方式与选型指引。配套阅读：《01.上报模块整体全流程.md》（管道）、《02.上报协议装配层梳理.md》（OTLP 装配）。

## 一、继承体系总览

```text
ReportItemBase<Derived>                      （Commit/Holder/注册基座，report_item_base.h）
└── PalmReportItem<Derived>                  （CRTP 业务字段基类：全字段 + Fill + 快捷函数）
    ├── PalmIotReportItem                    16160  MMPayPalmIoTReport        通用 IoT 埋点
    ├── PalmAppReportItem                    25261  MMPayPalmAppTerminalReport 通用终端埋点（+opt 字段）
    └── （PalmSessionReportItem）            25261  共表                       刷掌会话事件族（不走 CRTP，独立严格协议）
PalmMetricsReportItem                        99001  PalmMetrics                Metrics 通道信封
```

**注册机制**：每个协议头文件尾部 `REPORT_PROTOCOL_REGISTER(XxxItem)` 静态注册 `{kTableId, kBizName}`；`ReportService::DoInit` 遍历注册表为每个 table_id 建 ReportQueue。25261 被两个协议类注册（insert_or_assign），共享同一队列。

**CRTP 设计收益**（palm_report_item.h 头注释）：子类只声明 `kBizName/kTableId` + 注册宏，Create 工厂、Report* 快捷函数、JSON 序列化、Fill* 全部自动继承、零重复。

## 二、PalmReportItem 基类字段（16160/25261 共用字段模型）

### 2.1 业务字段（调用方填充）

| 组 | 字段 | 说明 |
|---|---|---|
| 标识 | `event_name` / `action` / `attribute_id` / `report_type` | 事件名 / 操作行为 / 业务属性 id / 上报类型；**action 是平台路由键** |
| 用户/页面 | `user_id` / `user_type` / `page` / `position` / `page_from` / `result_id` | 交互埋点用 |
| 结果 | `result_code`（int，非 optional）/ `result_msg` / `secondary_error_code` | 0=成功 |
| 扩展位 | `ext_key_1~3` + `ext_str_value_1~3`、`ext_number_key` + `ext_number_value_1` | **字符串扩展 3 对 + 数值扩展 1 对**——简化模型的核心容量 |
| 链路 | `trace_id` / `client_trace_id` | 后者才是设备端 session 级标识（trace_id 会被后台覆盖，story 135784881） |
| 耗时 | `time_cost` | 事件耗时 |

### 2.2 自动填充字段（业务方不填）

| 钩子 | 时机 | 填充内容 |
|---|---|---|
| `FillInContext()` | Commit 时（业务线程） | `happen_time`（墙钟）；`session_id/session_type/session_timecost`（空时取会话信息） |
| `FillBeforeQueue()` | HeartBeat 入队线程 | `report_time`、`seq`、`env_id`、设备/App 快照（app_version、device_sn、camera_sn、package_name、flavor、rom_version、network_type、report_policy、biz_id 等 ~15 项） |

### 2.3 快捷上报函数（静态，一行埋点）

`ReportAction` / `ReportEvent` / `ReportActionEvent` / `ReportActionResult`(±msg) / `ReportActionExt`(±Num) / `ReportActionExts` / `ReportPage`——覆盖"纯 action / 带结果 / 带扩展位 / 页面浏览"四类高频形态。

## 三、四个具体协议

### 3.1 PalmIotReportItem —— 16160 通用 IoT 埋点

- **定位**：Network / OTA 等通用埋点，零扩展——纯继承基类字段；OTA 下载进度/成败、心跳等 `iot.*` action 走这里；
- **通道**：/iot/report/logs，BaseLogsBuilder（scope=16160），失败重试不丢；
- **字段容量注意**：ext 槽位有限（字符串 3 + 数值 1），多维度数据需挤槽位或升级协议（OTA 进度埋点曾因此做槽位取舍，见 v2.2.0 方案）。

### 3.2 PalmAppReportItem —— 25261 通用终端埋点

- **定位**：Recognition / Recover / Guard / PalmCore 等终端侧 action 埋点；
- **专属扩展**（相对基类）：`opt_frame_image_id`（优选帧图像 ID）、`opt_work_mode`——仅 25261 表使用，自定义 to_json 追加序列化；
- **通道**：/iot/report/logs，PalmAppReportLogsBuilder（scope=25261，6 项 Resource + trace 链装配）。

### 3.3 PalmSessionReportItem —— 25261 共表的刷掌会话事件族

- **定位**：`palm.recognition.result / palm.enrollment.result / palm.binding.result / palm.verification.result / palm.session.end` 五类事件的**严格协议**（FR-3 字段规范），与 PalmAppReportItem 共表共队列，平台按 `attributes.action` 区分；
- **与 CRTP 族的差异**：
  - 不走 PalmReportItem 简化模型，23 个强类型字段（9 必装 + 10 optional 条件 + 4 个 session.end 专属），optional 未赋值 → to_json 不写键（自然裁剪）；
  - `FillInContext/FillBeforeQueue` 显式置空——**全部字段由 `PalmActionEventReporter::Emit` 单点装载**（协议头注释明示：快捷函数会制造第二装载点且需向 service 层引入 biz 依赖，方向不可倒；新增字段/新 action 一律改 Emit 一处）；
- 字段全集与逐 action 装配矩阵见《docs/13.刷掌上报事件说明.md》。

### 3.4 PalmMetricsReportItem —— 99001 Metrics 通道信封

- **定位**：把 OTLP `ExportMetricsServiceReq` JSON 整包当作一条队列记录（设备端本地 table_id，后端靠协议体内 scope.name 区分指标组）；
- **无业务字段**：队列文件 palmapp_99001；上传走 /iot/report/metrics 逐条发；网络类失败丢弃（时效性数据，避免无网堆积）；
- 生产方：`metrics_resource_reporter`（设备资源）、`recognition_metrics_reporter`（识别指标）等经 `ReportMetricsToQueue` 入队。

## 四、协议选型指引

| 场景 | 用哪个 | 说明 |
|---|---|---|
| OTA/IoT 通用埋点 | `PalmIotReportItem` | 一行快捷函数即可；ext 槽位内表达 |
| 终端侧 action 埋点 / 需优选帧 ID | `PalmAppReportItem` | 25261 表，享受 trace 链装配 |
| 刷掌会话五类事件 | `PalmSessionReportItem`（经 Emit） | 禁止绕过 Emit 直接 Create——字段漂移风险 |
| 指标/计数 | `PalmMetricsReportItem`（经 ReportMetricsToQueue） | 整包 OTLP，时效性数据 |
| 新后台表 | 新建 Item 子类 + 注册宏 + report_service 上传分派 + Builder | 见《01.上报模块整体全流程.md》第六节 |

## 五、对比小结：两代字段模型

| | CRTP 简化模型（16160/25261 通用） | PalmSessionReportItem 严格协议 |
|---|---|---|
| 字段 | 固定槽位（ext×3+1） | 语义化强类型 23 字段 |
| 装载点 | 任意业务代码 + 快捷函数 | Emit 单点 |
| 序列化 | NLOHMANN_DEFINE_TYPE_INTRUSIVE_WITH_DEFAULT（全键输出） | 手写 to_json（optional 裁剪） |
| 适用 | 高频、低维度、快速接入 | 低频、多维度、需后端字段规范 |

趋势：严格协议（25261 会话族）代表新协议的推荐形态；简化模型槽位扩展性有限，新增长维度数据建议新开严格协议而非挤 ext 槽位。
