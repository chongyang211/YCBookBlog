# Facility · 09 SeKeyStore（SE 安全元件门面）

> 系列第九篇。覆盖 keystore/ 模块：KeyStore 抽象、SeKeyStore 五块能力、SE 内部时间维护、专属线程并发模型与生命周期。承接《01.总览与分层架构.md》。

## 一、定位与组成

| 文件 | 角色 |
|---|---|
| keystore.h | 抽象基类 `KeyStore`：签名接口族 + `kSoftKeyStore/kSeKeyStore` 两型（软实现当前不存在，SE 是唯一实现） |
| sekeystore.h/.cpp | `SeKeyStore` 单例：SE 安全芯片（wxpayface SE）vendor SDK（`se_api::`）的 C++ 门面 |
| wxpayface_se.proto | SE 返回的 protobuf 结构（如 ILinkAuthCode）解析定义 |

核心价值：**私钥永远不出芯片**——签名/密钥协商/解密全部委托 SE 硬件完成，模组侧只见签名结果。它是全进程信任根：网络层 DEVICE/RECOGNIZE 签名、激活密钥交换、出厂状态判定全从这里走。

## 二、五块能力

### 2.1 签名族（核心，keystore.h:37-42）

| 方法 | SE API | 特点 |
|---|---|---|
| SignDataHash | ComputeDeviceAuthSignature | 基础设备认证签名 |
| SignDeviceAuth | 同上（包装） | sign_src 恒空（SE 侧不留源） |
| SignIlinkAuth | ComputeILinkAuthSignature | SE 返回 **protobuf**（含 timestamp），解析后拆 sign+timestamp |
| SignCommonAuth | ComputeAuthSign(With/Without)AntiReplay | anti_replay 可选——**防重放由 SE 内部计数实现** |
| SignPayAuth | ComputePaySign(With/Without)AntiReplay | 支付签名，同上 |

统一错误约定：`status_code != 0 → LOG_E + 返回空 SignResult`——**调用方必须判空**（时间不可信期防重放签名被 SE 拒时也会返回空）。

### 2.2 密钥交换（激活链路专用，activation 05 篇 Step2~4 的底层）

- `GetAllSePubKeys()`（:200-218）：读 8 个 key index 的设备公钥（payload 1+64 字节，首字节**硬置 0x04**——ECC uncompressed 点格式标志）；
- `ExchangeKeyWithServer`：ImportCustomServerPubKey（导入服务端公钥）+ ExchangeKeyAuthVerifyInfo（SE 内完成密钥协商，吐回 device auth/verify code）；
- `ConfirmExchangeKeyWithServer(confirm_code)` = SetSeCustomFactoryStatus——**确认即出厂**；
- `HasExchangedKeyWithServer()`：出厂状态 11=已激活 / 0=未激活——Step1 激活判定的数据源。

### 2.3 SE 信息与配置

SN / SDK / COS 版本、解锁命令（GetSeUnlockCmd/Unlock）、芯片信息、`Get/SetSeCustomSvrUrl`——**激活域名双存储的 SE 侧**（device 侧是系统属性，见《docs/activation/04.域名与证书校验.md》）。

### 2.4 解密

`AsyncDeviceAuthDecrypt`（协程版，设备认证密钥解密，:400-415）。

### 2.5 SE 内部时间维护（防重放的基础，:417-458）

SE 芯片内部维护自己的时间戳，需要宿主校准：

```text
Init（:71-81）：
  系统时间不可信 → need_time_repair_ = true（等签名时再修）
  可信           → SyncSeTime：system_clock → SetSeTimestamp（SE）

每次签名前 PreSetupSign（:442-458）：
  need_time_repair_ 或 CheckSysTimeChanged()？
    CheckSysTimeChanged（:417-425）：
      |Δsteady − Δsystem| > 1s → 判定墙钟中途被改
      （双时钟交叉比对，不受"墙钟跳变但单调钟没动"欺骗）
    → 系统时间可信才执行 SyncSeTime 修复；不可信则只 LOG_W
```

## 三、并发模型：专属 "se" 线程

- 构造时 `Threads::CreateThread("se")`（:40）——**动态创建的常驻命名线程**，阻塞的 se_api 调用全部串行在此线程，不占全局线程组（《03.线程模型与调度.md》线程全景"自持"类）；
- `AsyncSignCommonAuth / AsyncSignPayAuth / AsyncExchangeKeyWithServer`（async_initiate 协程友好）：SE 调用 post 到 se 线程执行，完成后 post 回**调用方 executor**（:260-265）——协程可在任意线程 co_await；
- 同步接口（SignXXX）直接在调用方线程阻塞执行——高频路径注意不要在主线程同步调，新接入方优先用 Async 版本。

## 四、生命周期与 SE 共享

```text
GlobalInit（进程级一次，:290-303）：SE SDK 日志接入统一 Logger（tag="se"）→ SeInit
Instance Init：读 SDK/COS/SN/RunMode 信息 → 时间校准（见 2.5）
DeInit（:84-114）：停 se 线程 → SeUnInit **释放 SE 资源给其他 App**
  ——SE 是设备上多 App 共享资源；激活完成后 OnActivated 调 DeInit
  （activation 05 篇：SetActivationStatus(REGISTERED) 触发），下次需要时再 Init
```

双层状态：`inited_`（实例已初始化）+ `global_inited_succ_`（SDK 全局态）；Init 有 "already inited" 幂等保护。

## 五、观察点

1. **时间修复失败不阻断签名**：PreSetupSign 返回 void，签名照常执行——时间不可信期的防重放签名要么被 SE 拒（空结果）要么时间戳异常，调用方判空逻辑必须覆盖此场景；
2. 所有 SE 调用共用 1024B 栈缓冲接输出（:118 等），`resize(ret.data_len)` 依赖 SDK 不超写——对 vendor SDK 的信任约定；
3. key index 表（kSeKeyIndexUpdateTradeKey=0 … Reserved7=7，sekeystore.h:83-92）与 30509/30513 等预留错误码同属"预留位"设计——新增密钥用途优先启用保留位，不开新段。
