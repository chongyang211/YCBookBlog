# Facility · 10 Link（P2P 厂测通道）

> 系列第十篇。覆盖 link/ 模块：local_link SDK 的 P2P 命令通道封装（产线厂测/设备自检专用）。承接《01.总览与分层架构.md》。

## 一、定位

**与业务串口 PosLink 毫无关系**：facility/link 是 **local_link SDK 的 P2P 命令通道封装**，唯一用途是**产线厂测/设备自检**（DeviceInspect）期间，测试工装经 **PL2303 USB 串口**（物理层 phylink）与模组收发 JSON 命令。

| 文件 | 角色 |
|---|---|
| local_link.h/.cpp（37 行） | `LocalLink`：SDK 一次性全局准备——**只接日志 sink，不初始化 SDK** |
| p2p_link.h/.cpp | `P2pLink`：P2P 通道本体（生命周期/收发/phylink） |

关键约束（p2p_link.h:18-22 注释）：**pos_link 与 p2p_link 互斥**（共用串口资源）——通道只在 `DeviceInspectController::Enter()` 到 stop 之间存活，正常业务期 SDK 永不初始化。PosLink 串口实现在 `src/biz/pos/`，勿混淆。

## 二、LocalLink：日志 sink 一次性接线（local_link.cpp:18-34）

`EnsureInit` 幂等：`local_link_logger_set` 把 SDK 日志（级别 0-trace~4-error，与统一 Logger **1:1 对齐**）接入 cross::comm::Logger（tag="locallink"）。SDK 本体的 `local_link_init_p2p` 不在这里——由 P2pLink 在自检激活时才调，保证互斥语义。

## 三、P2pLink 生命周期（与 DeviceInspectController 绑定）

```text
DeviceInspectController::Enter
  → InitForDeviceInsepect(fids)（:63-67，注意拼写：Insepect 为源码固化的误拼）
      1. thr_->Post：首次则 EnsureInit（日志）→ local_link_init_p2p
         → 注册连接状态回调 → [company-bus 编译开关] phylink 常开
         已 init 则幂等跳过，只追加注册 FID
      2. local_link_p2p_register_func_process(fid, cb) 逐个注册功能号处理器
      3. SetPhylinkEnable(true)：enable PL2303 USB 串口 phylink
                    │
运行期：FID + JSON 通道（请求/响应配对由 SDK 按 FID 处理，无 msg_id 概念）
  收：SDK 回调 → OnDataReceived → Post MainThread 派发 callback_map_[fid]
  发：WriteAsync 协程（:70-74）→ post 到 p2p_link 线程执行 SDK send → 回调用方 executor
  连接态：ConnectionStateChangeSig 统一在主线程触发（:29-35，含安全握手结果）
                    │
stop / 重启前 UnInit（:127-138）
  → 清回调 → [非 company-bus] disable phylink——串口资源释放后才能走 reboot
```

## 四、phylink 的故事（:105-116 长 TODO，调查线索刻意保留）

模块里最值得读的注释——一个现场问题的完整调查链：

- SDK 会预载 **CH9329_P2P** 线（/dev/ttyCH29，优先级 99）在 **UART_P2P**（ttyS2，优先级 103）之上；
- P20 机型上 open 时主机未检测到（UART registers connect:false）→ SDK 把备用活动线交给 CH9329 并**关闭 ttyS2**（2026-08-31 现场实测）；
- **Plan A**（disable CH9329 + 去掉 PL2303 enable，让 UART 独占）：实施并验证 SDK 会重开 UART，**然后回滚**——根因是 P20 接线的 UART connect 检测永不置位（P10 立即置位；connect:false 下重开的 UART 忽略对端字节）；
- 结论：待 connect 检测根因解决后再议 Plan A。

另一分支：`PALM_BIZ_COMPANY_BUS` 编译开关下，phylink 在 Init 时即 enable 且 **UnInit 不释放**（is_need_enable_phylink_，:88,39-44）——公司总线模式串口常驻。

## 五、并发模型

- 专属 **"p2p_link" 线程**（CreateThread 动态常驻，:14）——SDK send 等阻塞调用串行于此（《03.线程模型与调度.md》动态常驻类）；
- 收发双向均走 Post：收 → MainThread 派发回调；发 → p2p_link 线程执行后回调用方 executor（与 SeKeyStore 的 Async 模式同款）。

## 六、观察点

1. `AddReceiveDataCallback` 写 callback_map_ 无锁，读点在 MainThread（OnDataReceived）——依赖"注册只发生在自检入口单线程"的纪律，facility 层无强制；
2. 公开 API 拼写固化：InitForDeviceInsepect（Inspect 误拼为 Insepect）——改名成本 > 收益，调用与文档沿用需注意；
3. has_enable_phylink_ / is_need_enable_phylink_ 双标志组合（普通模式 UnInit 释放 / company-bus 常驻）语义正确但绕——新增 phylink 线类型时建议收敛成枚举；
4. pos_link/p2p_link 互斥的正确性**完全依赖 DeviceInspectController 的进出纪律**——facility 层无强制（如 SDK 检测到 pos_link 句柄即拒启）；互斥破坏的故障表现是串口数据串扰，排查时先查进出时序；
5. phylink CH9329/UART 优先级问题（第四节）待根因解决后回访 Plan A——动 SetPhylinkEnable 前必读 :105-116 注释。
