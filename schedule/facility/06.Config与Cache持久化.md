# Facility · 06 Config 与 Cache 持久化

> 系列第六篇。覆盖 Config（MMKV KV 配置）与 FileCaches（MMKV 文件缓存）两个持久化门面：初始化流程、API 语义、加密与过期设计、消费方清单。承接《01.总览与分层架构.md》。

## 一、定位

facility L0 纯基础件，封装腾讯 MMKV，提供**加密的、断电安全的持久化存储**，两个门面：

| 门面 | 存什么 | 实例 |
|---|---|---|
| config/ `Config` | KV 配置（标量/字符串/向量） | Global 单例 + CreateStandalone 命名实例 |
| cache/ `FileCaches` | 文件内容（按 key 取路径/内容） | 命名实例（如 `ImgInstance()`） |

## 二、Config 初始化流程（config.cpp:30-68）

```text
首次 Config::Global() 调用
  1. InitGlobalMMKV（call_once 幂等）：
     - registerLogHandler(HandleMMKVLog)   ← MMKV 日志接入统一 Logger（tag="mmkv"）
     - initializeMMKV(Application::GetDataDir())
  2. 构造静态实例（name="global"，enable_expire=false）：
     a. 确保 Application::GetDataPath("config/") 存在
     b. 密钥生成（<1ms）：
        Pbkdf2KeyGen(name + "_" + Device::GetSn(), 16B 固定盐, 16 字节, 迭代 100)
     c. MMKV::mmkvWithID(name, MMKV_SINGLE_PROCESS, &crypt_key, &config_dir)
     d. enable/disableAutoKeyExpire 按实例配置
```

## 三、Config API 与读取三态

**类型支持**（enable_if 编译期约束）：bool / int32~uint64 / float / double / string(+view) / vector\<string\>；显式模板实例化于 cpp 末尾。

| 读取语义 | API | 适用 |
|---|---|---|
| 区分"无键" | `Value<T>(key) → optional<T>` | 键不存在与默认值同值需区分时 |
| 带默认值 | `ValueOrDefault(key, def)` | 绝大多数读配置场景 |
| 管理 | `Contains / AllKeys / Count / ClearAll / Remove` | 巡检与清理 |

写入：`SetValue → SetValueWithUnsafeExpires(key, val, expires=0)`，MMKV set 同步落 mmap。
刷盘：`Flush()` 同步 sync（退出路径 BootStrapper::Exit 调用）；`FlushAsync()` 投 `Threads::Pool()` 通用线程池异步刷（注意：不是 scheduler 的 iot_pool_，见 03 篇线程全景）。

## 四、四个关键设计点

1. **加密绑定设备**：口令 = `实例名_SN`，密文拷到其他设备解不开——防拆机直读/配置挪用。**但盐 kConfigCryptKey 硬编码源码（:15），属混淆级防护而非密码学强度**——密钥类敏感材料仍走 keystore/SE，不进 Config；
2. **过期即 "Unsafe"**（:48 注释）：设备无 RTC，时间跳变会使 MMKV 过期判断不可靠——**设过期值前必须系统时间已同步**；且 Global 实例整体禁用过期，要过期必须 `CreateStandalone(name, true)`。与《04.NTP时间体系.md》墙钟依赖清单呼应；
3. **MMKV_SINGLE_PROCESS**（:39）：无跨进程文件锁开销，正确性由 palmapp PID 单实例保证（app.cpp RunGuardCheck）；
4. **日志接入**：MMKV 内部日志经 handler 转入统一 Logger——损坏/裁剪告警在主日志系统可见。

## 五、FileCaches（cache/file_caches.h）

轻量文件内容缓存：`SaveCacheFile(key, content)` / `GetCacheFilePath(key)` / `ReadCacheFile(key)`，全部协程接口；内容存 MMKV，key 命名实例（`ImgInstance()` 用于二维码图、TTS 音频等）。Init 在 Phase1（bootstrapper.cpp:194）。与 Config 共用 MMKV 基建（root 目录 + 日志 handler），但独立实例、无加密（无 SN 口令）。

## 六、消费方清单（跨重启状态）

| 消费方 | key | 用途 |
|---|---|---|
| Recover | `recover_dev_reboot:time`（vector） | 设备重启限频窗口（05 篇） |
| ActivationService | `activation_confirmed` | 补发 confirm 依据（activation 05 篇） |
| RecognitionModeConfig / PalmBehavior | 云端行为配置 | 识别模式熔断等 |
| LicenseManager | 授权状态 | 检查时机判断（kLicenseChecking 门控） |
| FileCaches | 图片/音频内容 | TTS、二维码图缓存 |

## 七、接入检查清单与观察点

**接入检查**：
1. 新增跨重启状态优先评估 Global()（无过期语义）；需要过期必须 standalone 实例 + 确认时间已同步；
2. key 命名稳定化——key 进 AllKeys 巡检，勿拼动态串；
3. 敏感材料（密钥/token）不进 Config（混淆级加密不构成防护）——走 SeKeyStore；
4. standalone 实例靠调用方 delete 释放（析构 close MMKV）——漏 delete 泄漏 fd/mmap 至进程退出。

**观察点**：
1. `ValueOrDefault` 特化的默认值参数写死 `false`（:152 等，靠 has_val 兜底）——语义正确但可读性瑕疵；
2. FileCaches 无加密且无容量上限/淘汰策略——大文件缓存增长靠业务自觉，建议巡检项加 MMKV 文件大小；
3. MMKV mmap 写入本身已持久，高频小配置写入无需手动 Flush；Flush 仅退出/关键节点使用——避免把 Flush 当普通写后置流程滥用。
