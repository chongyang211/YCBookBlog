# Facility · 11 Log 日志体系

> 系列第十一篇。覆盖 log/ 模块：cross Logger 与 xlog 后端的接线、全仓日志拓扑、实测日志量基线与观察点。承接《01.总览与分层架构.md》。

## 一、定位

**两层架构的"接线层"**：真正的日志 API 在 `cross/comm/logger.h`（`cross::comm::Logger`，全仓统一门面——业务 LOG_I/W/E 和各 SDK 日志都汇入它）；facility/log 只做一件事：**Init 时决定 Logger 的输出路由到哪个后端**。

## 二、两个后端（Logger::Init，logger.cpp:37-89）

| 后端 | 场景 | 实现 |
|---|---|---|
| **kXLog**（默认，量产） | 腾讯 mars xlog | 见下表 |
| kSysLog | 特殊/调试场景 | spdlog syslog_sink（标识 "palmapp"） |

**xlog 配置要点**（:38-55）：

| 项 | 值 | 说明 |
|---|---|---|
| 路径/前缀 | data/palmapp/log / "palmapp" | palmapp_YYYYMMDD_N.xlog 按天+序号滚动 |
| 压缩+加密 | **zstd + 公钥加密**（:19-21 硬编码公钥） | 防拆机直读——平台持私钥解密 |
| regression_time_measure | **2023-01-01**（:46-49） | 无 RTC 设备的时间回退基线——xlog 对早于该时间的日志的处理依据（与 TimeStateManager 的 2023 基线年呼应，《04.NTP时间体系.md》） |
| 单文件上限 | 20MB（:33） | 滚动到新文件；注释标注"量产建议调回 20MB"（说明历史上调大过） |
| 保留策略 | **按存活时长严格 7 天**（:35），滚动文件不占天数配额 | 与"按个数清理"的区别写在注释里 |

**接线方式**：cross Logger 输出经回调（:56-65）转 `xlogger_Write`。DEBUG 构建（!NDEBUG）额外挂 stdout 彩色 sink（pattern 带文件:行号:函数），调试时双写控制台。

## 三、全仓日志拓扑（本模块是汇聚终点）

```text
业务 LOG_I/W/E ──────────────┐
MMKV 日志 handler（tag=mmkv） ├──→ cross::comm::Logger（name="app"）
SE SDK 日志（tag=se）─────────┤        │ callback sink
local_link 日志（tag=locallink）┘        ▼
                              xlogger_Write → zstd+加密 → data/palmapp/log/*.xlog
                                             → [DEBUG] 同步 stdout
```

这正是《06.Config与Cache持久化.md》（mmkv）、《09.SeKeyStore.md》（se）、《10.Link（P2P厂测通道）.md》（locallink）三篇里"SDK 日志接入统一 Logger"的终点站——**全仓只有一条日志通道，tag 区分来源**。

## 四、日志量基线（:23-26 注释——实测数据，新增高频日志前先对照）

> 测试方法：模组传感器上方放静止物体长时间遮挡，观察极限日志量。

| 模式 | 场景 | 明文 | xlog 落盘 |
|---|---|---|---|
| A | 会话反复开始/结束（稳态，80~116 次/分钟） | 1.15 GB/天 | **153 MB/天** |
| B | 同会话每帧推 POS 掌状态（~20 次/秒） | 3.36 GB/天 | **425 MB/天** |
| C | 无遮挡（正常） | — | **6.3 MB/天** |

压缩率约 **7.5~8 倍**。这组数字是评估"新日志会不会打爆磁盘/流量"的唯一实测依据。

## 五、Flush（:91-99）

- `FlushSync`：cross Logger Flush + appender_flush_sync——**退出路径 BootStrapper::Exit 用它**（《02.启动与退出编排.md》第四节清理链末位）；
- `FlushAsync`：异步版。

## 六、观察点

1. **kLogRelativePath 的静态初始化顺序风险**（:29）：static const string 在全局静态初始化期调用 Application::GetDataDir()——跨编译单元 static init 顺序未定义，若 Application 实例此刻尚未解析数据目录，路径会固化为空前缀。当前恰好工作，属脆弱依赖（对比：Config 构造里是运行时调用，无此问题）；
2. **两个 2023 基线语义不同**：本模块 regression_time_measure（xlog 内部时间回退处理）与 TimeStateManager 基线年（时间可信判定，04 篇）同值不同义——类似 restarter 60s 巧合（《02.启动与退出编排.md》观察点 4），调整任一需检查另一个，勿顺手统一；
3. **磁盘占用上限推算**：20MB/文件 × 7 天存活——模式 B 极端场景 425MB/天 × 7 ≈ 3GB 日志体量，低容量分区需评估；模式 A/C 下无压力；
4. xlog 公钥为公开材料（无私钥无妨），但**换平台/换加密对需同步更新** kXlogPubKey，否则日志平台解不开；
5. Logger::~Logger 调 closelog()（:102）——仅 kSysLog 路径有意义；xlog 路径靠 FlushSync 收尾，进程退出析构顺序（Logger 静态实例 vs xlog 全局态）需留意。
