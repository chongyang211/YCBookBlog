## 刷掌流程状态机（palm_flow）快速上手指南

底层是开源库 **HFSM2**（`service/activation/fsm/hfsm2/`），本项目在它之上封装了一套固定骨架。掌握下面的内容即可上手。

---

### 一、文件地图（读代码的顺序）

| 文件 | 角色 | 一句话 |
|---|---|---|
| `flow_events.h` | 词汇表 | `FlowState` 枚举 + 输入事件 + Verdict + 上行事件 |
| `flow_context.h` | 黑板 | `FlowContext` 会话数据，全员共享读写 |
| `flow_actions.h` | 工单 | `FlowAction` 枚举，状态委托 Controller 的异步任务 |
| `palm_flow_fsm_def.h` | 图纸 | HFSM2 配置 + 状态树声明 + 转移图注释（**看懂转移先看这里的 ASCII 图**） |
| `palm_flow_state_base.h` | 基类契约 | `BroadcastEnter` / `LightFor` / react 穿透 |
| `palm_flow_states.h/.cpp` | 血肉 | 26 个状态的 enter/react/update 实现 + 3 个 Verdict Dispatch |
| `palm_flow_strategy.h/.cpp` | 大脑 | 4 种业务模式的决策（纯函数，返 Verdict） |
| `palm_flow_machine.h/.cpp` | 引擎外壳 | 闭包绑定 / Action 队列 / 定时器 / Reset |
| `../palm_session/palm_session_controller.*` | 司机 | 跑轮循环 / `ConsumeAction` 执行 / SDK 信号封送 |

### 二、核心运行模型（必须先理解）

```
状态机 = 单线程同步 react + 异步工单

React(事件)   ← 同步、调用栈内完成所有转移，无锁
request_action(工单) ← 状态只入队，不干活
ConsumeAction(工单)  ← Controller 协程里干 IO，完成后 React(结果事件)
```

任何耗时操作（HTTP / SDK 调用 / 扫码）**绝不出现在状态的 enter/react 里**，一律走 Action。

### 三、编码规范（本项目的硬约定）

1. **状态三分职责**：
   - `enter` 第一行调 `BroadcastEnter(control, FlowState::kXxx)`（瞬态除外）；有等待就 `arm_timer` + `emit_event` 通知外部；
   - `exit` 第一行调 `disarm_timer()`（对称取消，无 timer 也是 no-op）；
   - `react` 只做三件事：**写 ctx → 入队 Action 或 changeTo → 必要时写 exit_code**。
2. **写自己的 react 必须 `using PalmFlowStateBase::react;`**，否则基类空模板被名字隐藏，未处理事件直接编译错。
3. **Verdict 穷尽**：Dispatch 用 `if constexpr ... else static_assert(kAlwaysFalse<T>)`——给 Verdict variant 加新分支，所有 Dispatch 必须同步处理，否则编译失败（故意的）。
4. **Strategy 纯函数**：决策方法禁 IO / 锁 / 阻塞 / 改 ctx。需要数据 → Controller 在 `RunOneRound` 预取进 `profile`/`ctx`。
5. **数据传递靠 ctx 信箱**：状态 A 写 `pending_xxx` → Controller 消费 → 结果写回 `last_xxx`。不要在状态间直接传参。
6. **超时统一走 `StateTimeoutEvent`**：Kind 枚举区分，`token` 自动防过期回调串状态，不要自建定时器。
7. **权限分布**（FR-8）：Strategy 只读 ctx；Controller 和状态 react 写 ctx；`Stopping` 不再修改。
8. **瞬态状态**（Entry/ResultObtained）：`enter` 留空，分发放 `update(FullControl&)`（HFSM2 限制：`enter(PlanControl)` 内不能 changeTo）。

### 四、典型场景操作手册

**场景 1：加一个新状态（如新的等待态）**
① `fsm_def.h`：前向声明 + 挂进 `FSM` 树（选对 Head——要不可打断就放 `BizProcessHead` 下）+ 加 `FlowState` 枚举值 + 转移图注释补边；
② `states.h`：声明 enter/react/LightFor + 写行为契约注释；
③ `states.cpp`：实现；`machine.cpp` 的 `CurrentState()` 串查补一行；
④ 新事件在 `flow_events.h` 定义。

**场景 2：加一种异步操作（如新 HTTP 接口）**
① `flow_actions.h` 加枚举（写清楚触发状态和消费行为）；
② 状态在 enter/react 里 `request_action(新枚举)`；
③ Controller `ConsumeAction` 加 case：干 IO → 映射错误码 → `React(结果事件)`；
④ 定义结果事件 + 状态 react 它。

**场景 3：改决策逻辑（某模式在决策点行为不同）**
去 `palm_flow_strategy.cpp` 对应子类 override，返回已有 Verdict。**不要**改 Dispatch/状态代码。

**场景 4：加新业务模式**
① `flow_events.h` 加 `V_Xxx` Verdict + Dispatch 补分支；
② `palm_flow_strategy` 加子类 + 工厂加映射（`SessionProfile` 带 palm_mode 字节）；
③ 复用现有状态树，尽量不加新状态。

**场景 5：排查一轮会话**
入口三点：`RunOneRound`（轮从哪开始）→ `ConsumeAction` 的 switch（每个 Action 干了什么）→ `fsm_def.h` 转移图（边怎么走）。日志搜 `PalmFlow: A -> B`（DoBroadcast 打的转移流水）。

### 五、易踩的坑

- **长寿 machine + 每轮 strategy**：跨轮数据必须进 `Reset` 清理；在飞网络回调必须校验 `Epoch()`，否则旧轮响应串新轮；
- **调用线程**：`React` 必须主线程；SDK 回调先 Post（参考 `ConnectSdkSignals`）；
- **事件是 TopDown 分发**：父 Head react 先于子状态——`RunningHead` 拦了事件子状态就收不到（`ScanCompleteEvent` 有 `isActive` 放行特例，新增拦截时注意）；
- **旧路径别碰**：`biz/pos/strategy/` 和 `PosSession` 是遗留方案，新逻辑一律走 palm_flow。
