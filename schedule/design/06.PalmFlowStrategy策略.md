## `palm_flow_strategy.h/.cpp` 的作用

这是状态机的**策略层（spec FR-17）**——把“不同业务模式（识别/注册/Hybrid/反扫码）在决策点的**差异**”集中到 Strategy 子类里，主干 FSM 与模式解耦。状态机遇到决策点时不自己判断，而是调 Strategy 拿一个 **Verdict**，再按 Verdict 走边。

## 文件结构

**.h（接口 + 工厂）**：
- `IPalmFlowStrategy` 接口，4 个决策点 + 1 个配置点：
  - `GetProfile()` — 启动期一次性：产出本模式的 `SessionProfile`（工作模式、recognize_mode），Controller 写入 ctx；
  - `DecidePostOpt` — 优选通过后走哪条路；
  - `DecidePostRec` — 识别/加验响应后走哪条路；
  - `DecidePostLocalIdentify` — 端侧识别结果决策（基类默认调自由函数 `DecideLocalIdentify`）；
  - `DecidePostRegister` — 注册响应决策（基类默认实现，Host/Hybrid 共用）。
- 两个自由函数：`EnrollRoutingForMethod`（CPM/HOST 录掌等待去向的**单一事实源**）、`DecideLocalIdentify`（端侧结果 → recognize_info JSON + Verdict）。
- `MakePalmFlowStrategy(palm_mode_byte)` 工厂：0x01 识别 / 0x02 Host 注册 / 0x03 Hybrid / 0x05 CPM 反扫码，未知值安全回退 Recognition。

**强约束（.h 第 26–30 行）**：决策方法是**同步纯函数**——禁 IO/锁/阻塞/改 ctx，数据由 Controller 预取进 ctx，Strategy 只读（唯一例外是 `verify_id`/`verify_method` 作为 Verdict 传出参数经 `const_cast` 写入，注释里明确这是技术债）。

**.cpp 四个实现**：

| Strategy | 关键差异 |
|---|---|
| `RecognitionFlowStrategy` | `DecidePostOpt` 恒 `V_Submit`；`DecidePostRec` 处理加验 100038 / need_verify / 普通收敛 |
| `HostEnrollmentFlowStrategy` | `DecidePostOpt` 恒 `V_EnterRegister`；`DecidePostRegister` 用基类默认（Unregistered → `V_WaitBindInput`） |
| `CpmEnrollmentFlowStrategy` | 继承 Host，只改两点：probe 用 CPM 模式；`OnRegisterUnregistered` 覆写 → `V_WaitScanInput`（反扫码） |
| `HybridFlowStrategy` | `DecidePostOpt` 按 `ctx.recognition_attempted` 二选一（FR-5 一轮两阶段的核心）；`DecidePostRec` 命中 **100025** → `V_RetryDetect{switch_sdk_to_register=true}`（切注册二轮）；端侧识别失败也转 `V_RetryDetect` 走云端注册复核 |

四个决策的**公共骨架**都是：失败码直落 `V_Complete{code, "", server_code}` → 加验判定 `CheckNeedVerifyAndExtractId`（解析 `verify_info.need_verify`，`verify_method` 不解析业务含义原样透传——服务端加枚举模组零改动）→ `ShouldRetryVerify`（100038 且 retry<3）。

## 对应状态机里的内容

Strategy 对应状态转移图上的**“决策边标签”**——就是 `palm_flow_fsm_def.h` 转移图注释里那些 `V_xxx` 边的**决策来源**：

| 状态机决策点（状态） | 调用的 Strategy 方法 | 决定的出边 |
|---|---|---|
| `OptPassedState.react(VerdictPostOptEvent)` | `DecidePostOpt` | `V_Submit`→RecognizeEntry / `V_EnterRegister`→RegisterEntry / `V_Complete`→ResultObtained |
| `LocalRecognizing/Recognizing/VerifySubmitting.react(VerdictPostRecEvent)` | `DecidePostRec` / `DecidePostLocalIdentify` | `V_Complete`→ResultObtained / `V_RetryDetect`→Detecting / `V_RequireVerify`→VerifyEntry / `V_RetryVerify`→Verifying |
| `RegisterSubmitting.react(VerdictPostRegisterEvent)` | `DecidePostRegister` | `V_Complete`→ResultObtained / `V_RequireVerify`→VerifyEntry / `V_WaitBindInput`→WaitingBindInput / `V_WaitScanInput`→WaitingScanInput |

分工边界（整套架构里的一环）：
- **Strategy**：读 ctx → 返回 Verdict（“该往哪走”），纯函数，不碰状态机；
- **`palm_flow_states.cpp` 的 Dispatch 函数**：消费 Verdict → 执行 `changeTo` + 写 ctx（Verdict → 实际边的“翻译器”）；
- **Verdict 类型**定义在 `flow_events.h`（`PostOptVerdict` 等 variant）；
- 判断依据的数据在 `flow_context.h`（`last_rec_resp`、`recognition_attempted`、`verify_retry_count`、`hybrid_enroll_method`…）；
- Strategy 实例由 **Controller** 在 Reset 时经工厂创建（`.h` 第 35–37 行：GetProfile 结果由 Controller 写入 ctx）。

一句话总结：状态机定义了“在哪些路口可以转向”（OptPassed/识别响应/注册响应三个决策点 + 有限 Verdict 选项），`palm_flow_strategy` 决定“**这种业务模式在每个路口实际选哪条边**”——它是同一张状态图被识别、注册、Hybrid、反扫码四种业务复用的开关层。
