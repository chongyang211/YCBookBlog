## `palm_flow_machine.h/.cpp` 的作用

`PalmFlowMachine` 是 **HFSM2 引擎之上的唯一运行时外壳（wrapper）**（spec FR-10/FR-14）。前面几问的文件分别是“词汇/黑板/图纸/状态行为”，而这对文件是**让图纸真正转起来的机器本体**——外部世界（Controller、SDK 适配层、Notifier）只跟它打交道，不直接碰 HFSM2。

它承担五个职责：

### 1. 装配：构造函数绑定五件套闭包（cpp 第 13–40 行）

把 `PalmFlowFsmContext` 里的 5 个 `std::function` 绑到自己的私有 wrapper 方法上：

| 闭包 | 绑定到 | 语义 |
|---|---|---|
| `request_action` | `DoRequestAction` | 状态入队 Action（push `actions_` + `Wake()`） |
| `emit_event` | `DoEmitEvent` | 状态上行事件（`event_sig_` 广播给 Notifier） |
| `broadcast` | `DoBroadcast` | 状态变化广播 + 派灯 + 唤醒 RunLoop |
| `arm_timer` / `disarm_timer` | `DoArmStateTimer` / `DoDisarmStateTimer` | 状态级超时定时器 |

注意 cpp 第 37–39 行的顺序约束：**必须先绑闭包再构造 `fsm_`**——HFSM2 实例构造时会自动 enter `CreatedState`，其 `enter` 会立刻调 `broadcast`，闭包未就位会 `bad_function_call`。

### 2. 事件入口：`React<E>()`（h 第 59–63 行）

外部喂事件的唯一入口：`fsm_->react(e)` + `fsm_->update()`。HFSM2 的 react 是**同步**的——状态切换、enter/exit、`changeTo` 都在调用栈内完成，单线程（主线程 executor）串行化，因此无并发问题。

### 3. Action 队列 + RunLoop 唤醒契约（h 第 65–69 行，cpp 第 84–105 行）

- `HasPendingActions()` / `PopAction()` — Controller `DrainActionsUntilDone()` 的消费接口；
- `WaitWork()` — 协程挂起点，条件变量等待 **“actions_ 非空 或 已到 Done"**（cpp 第 94–97 行）；
- `Wake()` — 三个地方会触发：入队 Action、`DoBroadcast` 状态切换末尾。关键在 `DoBroadcast` 也 wake（cpp 第 198–201 行）：Stopping→Done 这条 timer 路径只 `changeTo<Done>` 不派 Action，不 wake 会导致 `RunOneRound` 卡死、下一轮起不来。

### 4. 状态超时定时器（cpp 第 204–227 行）

`DoArmStateTimer` 实现 `StateTimeoutEvent` 机制：取消旧 timer + `++token` + 新 timer。回调里双重校验（`ec` 取消 / token 过期），防上一状态的旧定时器回调串到新状态——这就是 `StateTimeoutEvent.token` 字段的来源。

### 5. 轮间复位：`Reset(profile)`（cpp 第 49–78 行）

刷掌设备**长寿单例、一轮一 Reset**（spec FR-14）的全部轮间清理：
1. 取消 state_timer + `++token`（上一轮在飞 timer 失效）；
2. 清空 `actions_`；
3. 重置 `biz_ctx`（新生成 trace_id，session_id 取 trace_id 前 12 位保证可关联；写入新 profile）；
4. `++round_epoch_`（P0-8 防陈旧响应：Controller 网络返回后比对 epoch，不一致丢弃——防旧轮响应串新轮）；
5. 重建 `FSM::Instance`，自动回到 `CreatedState`。

## 对应状态机里的内容

对应关系按“状态机的运行时关注点”划分：

- **状态实例本身**：持有 `FSM::Instance`（图纸的实例化产物），`React` 是驱动状态图转移的总入口；
- **状态查询 API ↔ 状态图节点**：`CurrentState()` 串查所有 leaf（子状态先于父，防父状态吞掉精确值）映射回 `FlowState` 枚举；`IsActive<T>()` 穿透 HFSM2 模板给 Controller 用（如按 `IsActive<VerifyingHead>` 路由 `/verify-palm`）；`IsInterruptible()` 实现转移图上“BizProcessHead 不可打断”的规则（cpp 第 163–171 行，`OptPassedState` + `BizProcessHead` 一次覆盖两个子树）；`IsIdle()`/`IsBizFinished()` 对应图的边界态（Created/Stopping/Done）；
- **闭包五件套 ↔ 图上的横切机制**：Action 入队（FR-11）、事件上行（FR-19）、状态广播+派灯（FR-13/FR-18）、状态超时（`StateTimeoutEvent` 的来源）——这些都不是某个状态的私有物，而是所有状态共用的基础设施；
- **Reset ↔ 状态机生命周期**：状态图只描述“一轮”内部（Created→…→Done），跨轮的清理/重建/防串轮（epoch、timer token、actions 清空）全在这个 wrapper 层，图上不可见。

一句话总结：`palm_flow_fsm_def.h` 是图纸，`palm_flow_states.cpp` 是各状态的血肉，而 `PalmFlowMachine` 是**把图纸装进引擎、接好输入输出管线、并管理“一轮一轮”生命周期的运行时主机**——Controller 只面对它这一层 API。
