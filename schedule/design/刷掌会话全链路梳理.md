**三层职责**：
- **协议层**（`pos_link` + `PosRequestHandler`）：wire 编解码 + 命令派发。
- **调度层**（`PalmSessionController`）：会话生命周期 + SDK 事件转 FSM 事件 + Action 异步执行。
- **流程层**（`PalmFlowMachine` + Strategy）：业务状态流转 + 模式决策。

## 2. 两个触发场景

### 2.1 场景 1：上位机触发（host → 0x0E StartPalmEx）

**典型用途**：收银台"开始刷掌"按钮、"扫码支付" debug 页。

#### 2.1.1 wire 协议（唯一入口）
```cpp
// pos_link/pos_link_app.h:37, 130
constexpr uint16_t kPosAppStartPalmExCmdId = 0x0E;
struct PosAppStartPalmExReq {
  uint8_t msg_cmd;
  uint8_t offline_preferred;   // 0=follow_config / 1=off / 2=on（is_debug_test 复用此字段=2 的值）
  uint8_t scan_mode;           // 0=follow_config / 1=off / 2=scan_only / 3=scan_both
  uint8_t reserved;
};
```

> ⚠️ wire 里**没有** `work_mode / palm_mode / host_ack` —— 这些完全由 `PalmBehavior` 配置给出。

#### 2.1.2 完整调用链


#### 2.1.3 回包
`PosAppStartPalmExResp` 返 `(ret_code, palm_mode)` —— `palm_mode` 从 `PalmBehavior` 换算后回显，让上位机确认本轮生效模式。

### 2.2 场景 2：掌唤 AutoStart（设备自循环）

**典型用途**：设备空闲时持续等待手掌，用户走过来即刷。

#### 2.2.1 触发源

```
每一轮刷掌结束
     ▼
Controller::OnFlowEvent(OnSessionCompleteEvent)   palm_session_controller.cpp:1767,1832
     │
     └→ ScheduleAutoStart()                       palm_session_controller.cpp:1860
          │ 1. 守卫：PalmBehavior::allow_palm_wake != kOn → 直接返回（掌唤总开关关）
          │ 2. 守卫：当前 is_debug_test_session → 直接返回（debug 轮不续）
          │ 3. 读 delay_sec = PalmBehavior::GetPalmWakeRestartIntervalSec()
          │ 4. 起 asio::steady_timer(delay_sec)（可被 CancelPendingAutoStart 撤销）
          │ 5. 到期：
          │    a. pending_offline_ / pending_scan_ 来自 PalmBehavior
          │    b. pending_start_source_ = "palm"
          │    c. DeviceStateMachine::RequestEnter(kPalmRunning, kFromAutoResume)
          ▼
     （汇入场景 1 的 RunForever → RunOneRound 共用管道）
```

#### 2.2.2 与场景 1 的差异

| 维度 | 场景 1（host） | 场景 2（palm） |
|---|---|---|
| wire 命令 | 0x0E StartPalmEx | 无（无需上位机参与） |
| 入口函数 | `RequestStart` | `ScheduleAutoStart` |
| `pending_start_source_` | `"host"` | `"palm"` |
| 触发时机 | host 主动按钮 | 上一轮结束 + delay_sec |
| debug 模式 | wire offline_preferred=kOn 可开 | 不进入 debug（第 2 条守卫） |
| 目标状态 | `kPalmRunning` 或 `kDebugTesting` | 恒 `kPalmRunning` |

#### 2.2.3 竞争撤销（关键）

掌唤 timer 可能与上位机命令**并发**：

- 用户按下 0x0E 时掌唤 timer 还没到期 → `RequestStart` 开头 `CancelPendingAutoStart()` 把它杀掉，host 命令优先。
- Controller 用 `auto_start_epoch_` 做防抖：timer 回调里对比 epoch，撤销后到期的 timer 回调自解。

### 3.3 Finish 收敛桥（Story 137913126）

每棵子树**出口必过**一个瞬态 Finish，统一发 `palm.*.result` 事件后转 `ResultObtained`：

| Finish | 职责 | emit |
|---|---|---|
| `RecognitionFinishState` | 识别收敛（Local/Cloud/离线优选 fake success） | `palm.recognition.result` |
| `EnrollmentFinishState` | 按 `enroll_wait` 分派：绑定/扫码/探测注册 | `palm.binding.result` / `palm.enrollment.result` |
| `VerificationFinishState` | 加验收敛（成功/129/拒绝/submit 超时） | `palm.verification.result` |

**结构保证**："离开子树必过 Finish"——详见 `palm-flow-finish-state-refactor.md`。

## 4. 四大业务（在流程中的角色）

| 业务 | FSM 落地状态 | 触发 Verdict | HTTP | 终态事件 |
|---|---|---|---|---|
| **识别** | `LocalRecognizing` / `Recognizing` | `V_Submit` → kDecidePostRec | `/recognize`（云端）/ 无（端侧） | `OnPalmResultEvent` + `palm.recognition.result` |
| **录掌（探测）** | `RegisterSubmitting` | `V_EnterRegister` → kDecidePostRegister | `/register-palm`（探测轮） | 已注册：`palm.enrollment.result` ；未注册 → 走绑定/反扫码 |
| **录掌（HOST 绑定）** | `WaitingBindInput` → `kProcessBindPalm` | `V_WaitBindInput` | `/bind-palm`（BindPalmFlow） | `OnBindResultEvent` + `palm.binding.result` |
| **录掌（CPM 反扫码）** | `WaitingScanInput` → `RegisterByCodeSubmitting` | `V_WaitScanInput` | `/register-palm`（含身份码） | `OnBindResultEvent`（统一 Bind 回执）+ `palm.enrollment.result` |
| **加验** | `Verifying` → `VerifySubmitting` | `V_RequireVerify` | `/verify-palm`（复用 kRecRequest） | `OnPalmResultEvent` + `palm.verification.result` |

### 4.1 Strategy 路径（按 PalmMode 分叉）

```
  V_Submit            V_EnterRegister V_EnterRegister  V_Submit   V_Complete(0)

  Recognizing         RegisterSubmit  RegisterSubmit     │     RecognitionFinish
```

> 详见 `palm-flow-state-machine.md § Strategy`，含 4 种 PalmMode 与 wire 值的映射表。

### 4.2 加验何时触发

**与路径无关**：识别 / HOST 注册 / CPM 注册的 HTTP 响应里只要带 `verify_info.need_verify=true`，Strategy 就返 `V_RequireVerify` 进加验子树。实际绝大多数场景是**识别后要求加验**（防盗刷）。

```
Recognizing / RegisterSubmitting / VerifySubmitting
                    │
                    ▼
             kDecidePostRec （加验/识别混合决策入口）
                    │
                    ▼
            Strategy.DecidePostRec
                    │
        verify_info.need_verify==true
                    │
                    ▼
            V_RequireVerify ─→ VerifyEntry → Verifying
```

## 5. 上下行协议表

### 5.1 下行命令（host → 模组）

| cmd id | 名称 | 入口（PosRequestHandler） | 转换为 FSM | 触发时机 |
|---|---|---|---|---|
| `0x0E` | `StartPalmEx` | `HandleStartPalmExRequest` | 不直接 React，走 Controller::RequestStart | 启动一轮 |
| `0x09` | `BindPalm` | `HandleBindPalmRequest` | `BindPalmRequestEvent` | WaitingBindInput 等待时 host 下发用户信息 |
| `0x0D` | `VerifyPalm` | `HandleVerifyPalmRequest` | `VerifyDataEvent` / `VerifyErrorEvent` | Verifying 等待时 host 下发加验结果 |
| `0x14` | `HostResultAck` | `HandleHostResultAckRequest` | `HostAckResultEvent` | WaitingHostAck 等待时 host 回执 |

### 5.2 上行命令（模组 → host）

| cmd id | 名称 | 发送点（PosRequestHandler） | FSM 事件源 | 用途 |
|---|---|---|---|---|
| `0xAA` | `SessionStart` | `SendPalmSessionStartNotify` | `OnPalmSessionStartEvent` | 会话开始，带 session_id |
| `0xAB` | `VerifyNotify` | `SendPalmVerifyNotify` | `NeedVerifyEvent` | 请 host 下发加验数据 |
| `0xAC` | `BindInputNotify` | `SendPalmBindInputNotify` | `NeedBindInputEvent` | 请 host 下发 BindPalm 或请用户出示身份码 |
| `0xA3` | `RecognizeResult` | `OnPalmResult` / `OnBindResult` / `OnScanCodeResult` | `OnPalmResultEvent` / `OnBindResultEvent` / `OnScanResultEvent` | 三合一结果终态回执 |
| `0xA8` | `HostAckComplete` | — | `HostAckCompleteEvent` | HOST_ACK 完成通知 |

### 5.3 0xA3 的三副面孔

```cpp
// recognize_type / is_bind_palm 字段组合
0x01 / 0  → OnPalmResult      识别/加验结果（含 need_host_ack）
0x02 / 0  → OnScanCodeResult  扫码支付结果（kScanFinished）
   0 / 1  → OnBindResult      录掌/绑定结果（HOST BindPalm 或 CPM 反扫码统一回执）
```

## 6. 事件 & 数据生命周期

### 6.1 SDK 五路 signal → FSM 事件

| SDK Signal | PalmCoreManager 来源 | Controller 转换 | FSM 事件 |
|---|---|---|---|
| `PalmStatusSig` | 检测状态变更 | `code==kFirstPalmFound` → `PalmEnteredEvent`；`code==kOptSucPreDi` → `OptPassEvent`；其他 → `PalmStatusEvent` + `PalmStatusUpEvent`（上行 0xAA 的 status 字段） | `PalmEnteredEvent` / `OptPassEvent` / `PalmStatusEvent` |
| `PalmOptLiveCompleteSig` | 优选活体采集完成 | 拿 palm_data / camera_data | `PalmDataReadyEvent` |
| `PalmLocalIdentifyCompleteSig` | 端侧识别完成 | 带 code + scene_attach | `LocalIdentifyResultEvent` |
| `CodeScanResultSig` | 扫码器完成 | 带 content | `ScanCompleteEvent` |
| `PalmReportEventSig` | SDK 内部埋点 | **不转 FSM 事件**：直接写 FlowContext（opt_live_duration_ms / opt_frame_image_id）或独立上报 `kSdkActionLocalIdentifyCost` | — |

> 所有回调封送路径统一：`Threads::MainThread()->Post([=]{ if (!machine_) return; machine_->React(...); })`

### 6.2 关键 FlowContext 字段

| 字段 | 写入点 | 消费点 |
|---|---|---|
| `palm_data` / `camera_data` | OptPassed.react(PalmDataReadyEvent) | ConsumeAction(kRecRequest/kRegisterRequest) |
| `last_rec_resp` | Recognizing/VerifySubmitting.react(RecResponseEvent) | kDecidePostRec（Strategy） + 加验/识别事件的 server_code |
| `last_register_resp` | RegisterSubmitting.react(RegisterResponseEvent) | kDecidePostRegister + EnrollmentFinish 的 server_code |
| `enroll_wait` | WaitingBindInput.enter → kBindInput；WaitingScanInput.enter → kScanInput | EnrollmentFinish.update 分派 binding/enrollment event |
| `recognition_route` | LocalRecognizing/Recognizing.enter；离线优选 Controller 手动置 | RecognitionFinish.update 分派 route=local/remote |
| `verify_id / verify_method / verify_retry_count` | DecidePostRec 返 V_RequireVerify 时写入 / V_RetryVerify 时自增 | Verifying.enter 发 NeedVerifyEvent；Strategy 判 100038 重试上限 |
| `completion_source` | 各出口 react 置（kNormal/kBindFinished/kScanFinished/kAbort） | ResultObtained.update 分派 emit 哪个 event |
| `bind_result` | WaitingBindInput/RegisterByCodeSubmit 成功 react 写入 OnBindResultEvent | ResultObtained.update emit OnBindResultEvent |
| `exit_code` / `server_code` | 各出口 react 置；Strategy V_Complete 携带 | 结果灯色、palm.*.result 事件、0xA3 回执 |

1. 协议层 → 调度层 → 流程层的三跳延迟非常低（host 发命令到 FSM 开跑 ~25ms）
2. 真正的"识别耗时"= HTTP /recognize 响应时间（上表 ~485ms）
3. 结果灯 3s 期间可被新一轮 RequestStart 的 `CancelResultLightTimer` 杀掉（Host 急刷场景）
4. palm.session.end 聚合了 `event_actions_log`（本例 = `["palm.recognition.result"]`）

### 7.1 其他 4 条典型路径（简表）

| 场景 | 关键分支 | 终态事件 | 0xA3 字段 |
|---|---|---|---|
| **端侧识别成功** | OptPassed → RecognizeEntry → LocalRecognizing（无 HTTP）→ V_Complete | OnPalmResultEvent | type=0x01, bind=0 |
| **HOST 录掌成功** | OptPassed → RegisterEntry → RegisterSubmitting (未注册) → V_WaitBindInput → WaitingBindInput → 收到 0x09 → kProcessBindPalm → BindPalmFlow → 成功 | OnBindResultEvent | type=0, bind=1 |
| **CPM 反扫码录掌成功** | RegisterSubmitting (未注册) → V_WaitScanInput → WaitingScanInput → ScanComplete → RegisterByCodeSubmit → 成功 | OnBindResultEvent | type=0, bind=1 |
| **识别 + 加验成功** | Recognizing → kDecidePostRec 返 V_RequireVerify → VerifyEntry → Verifying（0xAB 请 host 下发） → 收 0x0D → VerifySubmitting → /verify-palm → V_Complete | OnPalmResultEvent | type=0x01, bind=0 |

## 9. 快速定位 Bug 的三问

1. **问题发生在哪一跳？**
   - 没发命令？看协议层（PosRequestHandler）；
   - 命令到了但 FSM 没动？看调度层（Controller::ConsumeAction / 封送）；
   - FSM 动了但走错？看流程层（Strategy Verdict / state react）。

2. **当前在哪个状态？**
   - 看日志 `BroadcastEnter` 的 `FlowState` 名；或抓包观察 0xAA/0xAC/0xAB 通知序列。

3. **ctx 关键字段对不对？**
   - `completion_source` → 决定 ResultObtained 发什么事件
   - `enroll_wait` → 决定 Enrollment 的 action 类型
   - `recognition_route` → 决定 recognition.result 的 route
   - `is_recognition` + `need_host_ack` → 决定是否进 WaitingHostAck
   - `exit_code` → 决定结果灯色 + 0xA3 的 ret_code
