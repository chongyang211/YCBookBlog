## 刷掌状态机一句话架构

**纯逻辑状态机（palm_flow）+ 现实世界适配层（Controller）**。状态机只做决策和转移，所有耗时操作（网络/SDK/扫码）都委托出去。

## 三层分工

```
外部输入 ──▶ PalmSessionController（司机）
                │  翻译：SDK/POS 事件 → React(XxxEvent)
                │  执行：PopAction → 网络请求/SDK调用
                ▼
            PalmFlowMachine（引擎外壳，绑定闭包/定时器/队列）
                ▼
            HFSM2 状态树（图纸 fsm_def + 血肉 states + 大脑 strategy）
```

## 主流程（一轮会话）

```
Created → Starting(启SDK检测)
  → Detecting(等手进入) → PalmEntered → OptPassed(优选通过)
       │
       ├─ 识别模式 → Recognizing(云端HTTP/端侧SDK二选一)
       ├─ 注册模式 → RegisterSubmitting(提交注册)
       └─ Hybrid   → 先识别，100025未录入则回 Detecting 切注册再来一轮
       
业务响应后由 Strategy 返 Verdict 决定去向：
  成功 → ResultObtained(统一出口，按完结源发0xA3)
       → WaitingHostAck(可选) → Stopping(停SDK) → Done
  需加验 → Verifying(发0xAB等0x0D) → VerifySubmitting
  未录入 → WaitingBindInput(等上位机录掌) 或 WaitingScanInput(反扫码等身份码)
任意运行态收到 StopReq → Stopping（kAbort，静默退出）
```

## 核心处理机制（四个关键字）

1. **Context**：共享黑板，所有状态读写同一份会话数据（响应、重试计数、退出码）；
2. **Action**：状态入队“工单”→ Controller 排空执行 → 结果以 Event 回灌。状态机永不阻塞等 IO；
3. **Verdict**：Strategy 在三个决策点（优选后/识别后/注册后）返回决策，Dispatch 函数翻译成 `changeTo`，`static_assert` 强制穷尽所有分支；
4. **Timeout**：每个等待状态 enter 时 arm 定时器（token 防串轮），超时以 `StateTimeoutEvent` 统一收敛到 Stopping。

## 两个横切规则

- `RunningHead` 一处 react 拦截 StopReq → 运行区任意状态可打断；
- `BizProcessHead` 子树（提交中/等待输入）不可打断，保证业务原子性。

**分层本质**：状态图定义“有哪些路”，Strategy 决定“走哪条”，Action/Event 是状态机与现实之间的“桥”——出桥的活 Controller 干，回桥的结果状态机判。
