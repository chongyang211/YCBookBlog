# biz/comm 刷掌业务（palm_flow + palm_session）· 业务串讲

> **一句话定位**：刷掌设备的**核心业务引擎**——`PalmSessionController`（总调度 + 全部 IO）驱动长寿 `PalmFlowMachine`（HFSM2，22 状态三层树）逐轮完成「注册/识别/绑定/加验」四种会话；`PalmFlowStrategy`（四种 palm_mode 策略）以同步纯函数产出 Verdict；**FlowAction 队列**把「状态想做的重活」交给 Controller 执行——状态纯逻辑、Controller 做 IO。识别结果经 0xA3/0xAB/0xAC/0xA8 上行 POS，指标走 OTel metrics。
> **场次**：90 分钟（25 文件、controller 单文件 1956 行，全工程最大业务模块）　**听众**：同组开发 / 评审人 / 后续接手者
> **对照模版**：`06.技术模版/04.业务串讲的模版.md` 第 08 章　**代码基线**：`palm_app_linux/src/biz/comm/`（2026-10-08 审阅；两项关键仲裁已实测坐实）
> **勘误声明**：本篇坐实 **25261 palm.\* 会话事件族整体 TODO**（`PalmActionEventReporter` 类不存在）——《业务上报-模块业务串讲》中「palm_action_event_reporter.cpp 是会话事件族唯一装载点」的表述**有误**，以本篇为准。

## 1. 需求与业务背景  [10min · 先现象后价值]

### 1.1 需求来源与问题
- **来源**：刷掌设备的四类业务会话——**识别**（收银扣掌纹）、**注册**（用户录掌纹）、**绑定**（掌纹↔会员码）、**加验**（二次确认）；外加离线优选、掌唤自动启动、自检测试模式。
- **问题**（决定架构的三条）：① 会话内状态迁移极多（扫码/优选/本地识别/云端识别/等输入/host ack…），手写 switch 必然失控；② 决策逻辑（要不要注册/要不要加验/重试几次）与 IO（HTTP/SDK/扫码）必须分离，否则无法测试；③ 一轮会话内并发源多（SDK 信号、网络响应、POS 命令、timer），旧轮响应串新轮是真实事故源。
- **目标**：状态机声明式管理迁移；决策纯函数化；IO 收敛单点；跨轮串扰有防护（epoch/token）。

### 1.2 业务边界
- **做**：四种会话全流程、本地/云端识别路由、四种 palm_mode 策略、dwell 云控超时体系、POS 协议上行、OTel 识别指标、离线优选短路、掌唤调度、核验记录（PII 加密落库）。
- **不做**：25261 会话事件上报（**整体 TODO**，见 6.2-F1）；POS 协议本体（biz/notifier）；SDK 端侧识别（palm_core）；上位机交互协议（pos_request_handler 只做入口）。

### 1.3 关键业务规则
- **四种 palm_mode**（strategy.cpp:376-392 工厂）：0x01 Recognition / 0x02 HostEnrollment / 0x03 Hybrid（`recognition_attempted` 二轮）/ 0x05 CpmEnrollment——未知值降 Recognition+LOG_E。
- **本地/云端路由**（states.cpp:15-18 + palm_core_manager.cpp:26-28）：`IsFeatureSyncEnabled() && work_mode==kIdentify`（仅核身模式）→ LocalRecognizing（3s 超时→165）；其余走云端 Recognizing。
- **错误码契约**（flow_events.h:112-118）：响应事件 `code=模组码、server_code=原始服务端码`——映射唯一调用点在 Controller 请求生产点（bug 1070139249163538699 之后 Strategy 决策点不再映射）。
- **双语义映射**（recognize_retcode.cpp:7-34）：`100025` → register?114(质量问题):306(未注册)；`10007` → register?163:141；`10023`→118；`100038`→117（retry<3）；default→141；`IsEnrollSubmitNonRetryable` **仅 116 收敛**，其余 0xAC 重试。
- **dwell 体系**（dwell_config.h:33-52）：max_opt_retry(3)/request_timeout[3,30]s/verify_timeout(30s)/**bind_input_timeout(40s，绑定与扫码输入共用)**/host_ack_timeout(20s)/result_dwell(3s)；**0x0B 上位机可写白名单已收窄为仅 bind_input_timeout**（:149-153）。

### 1.4 改动范围（模块组成）
- **[流程层]** palm_flow/ 23 文件：machine（HFSM2 wrapper）/states（22 状态）/strategy（4 策略）/dwell_config/local_scene_attach/session_profile + 三枚举头 + 6 测试。
- **[会话层]** palm_session/ 2 文件：PalmSessionController（1956 行）。

## 2. 整体设计与模块划分  [10min · 先图后讲]

### 2.1 架构与分层
```
 POS 上位机（0x04 StartPalm / 0x06 BindPalm / 0x0D 加验 / 0x14 HostAck / StopPalm）
   │ pos_request_handler（入口 + License 门禁）          设备自检（device_inspect）
   ▼
 PalmSessionController（单例，MainThread）—— 总调度 + 全部 IO
   RunForever → ScheduleLoop → RunOneRound（:665-702）：
     MakeStrategy → dwell 快照 → machine_->Reset（新 session_id/trace_id）
     → React(StartReq) → DrainActionsUntilDone(:1907-1915)
        PopAction → ConsumeAction：
          kRecRequest/kRegisterRequest   → AsyncExec 同步 HTTP（ThreadPool）
          kDecidePostOpt/Rec/Register    → Strategy 纯函数 → Verdict → React
          kSwitchSdkToRegister / kProcessBindPalm / kStartScanInput ...
   ▼
 PalmFlowMachine（HFSM2，React 同步单线程）
   Running → BizProcess → Recognizing(本地/云端)/Registering/Verifying
          + ResultObtained/WaitingHostAck → Stopping/Done
   状态只做：迁移判定、arm/disarm timer、emit 事件、入队 FlowAction
   ▼
 PalmFlowStrategy（同步纯函数，禁 IO/锁/阻塞）
   DecidePostOpt/Rec/Register/LocalIdentify → Verdict（std::visit 编译期穷举）
 ─────────────────────────────────────────────
 输出：PosNotifier（0xA3/0xAB/0xAC/0xA8）｜OTel metrics｜核验记录(PII 加密)
```
分层关键（本模块最值得学的架构决策）：**三层各管一段**——Strategy 只算「下一步该干嘛」（纯函数可穷举单测）；FSM 只管「我现在是谁、等什么、什么时候超时」（声明式迁移）；Controller 只做「真去干」（HTTP/SDK/扫码/DeviceFsm）。**FlowAction 是状态与 IO 之间唯一的桥**——状态想发请求只能入队，不能自己发。与 iot 模块（base_cmd KeepSelf）、detection（Manager 编排）同一哲学的集大成。

### 2.2 模块职责
| 组件 | 职责 |
|---|---|
| `PalmSessionController` | 会话轮循环、FlowAction 消费、网络/SDK/扫码 IO、DeviceFsm 交互、掌唤调度 |
| `PalmFlowMachine` | FSM 包装：React/update、轮间 Reset、单 timer 模型、epoch |
| `PalmFlowStrategy` ×4 | 决策纯函数（Verdict 产出） |
| `PalmFlowDwellConfig` | 云控超时/重试参数（clamp + MMKV） |
| `LocalSceneAttach` | 端侧识别用户快照解析（Base64+protobuf wire 手写解析） |
| `recognize_retcode` | 服务端码→模组码映射（双语义） |

### 2.3 核心数据流（一次云端识别的完整旅程）
```
POS 0x04 StartPalm → RequestEnter(kPalmRunning) → RunOneRound
 → FSM：Created→Starting→Detecting（SDK 信号 PalmEntered/OptPass）
 → OptPassed：关扫码、emit 0x01、入队 kDecidePostOpt
 → Controller：离线优选短路 或 Strategy.DecidePostOpt → Verdict
 → RecognizeEntry：ShouldUseLocalIdentify？→ Cloud Recognizing
 → 入队 kRecRequest → Controller：AsyncExec（ThreadPool 同步 HTTP）
    IotRecogPostRequest("/wecardpalm/device/recognize", body, trace_id, 10s)
    （RECOGNIZE 签名；epoch 校验防串轮 :939-946）
 → 三级分类（:948-995）：网络错 111 / 无应答 141 / 服务端 MapRec
 → RecResponseEvent{code=模组码, server_code} → kDecidePostRec
 → Strategy.DecidePostRec → V_Complete（或 Hybrid 切注册/加验）
 → ResultObtained：CompletionSource 决定发哪种 0xA3 → PosNotifier 上行
 → HOST_ACK（仅识别成功+result_action_mode）→ WaitingHostAck → Stopping
 → OnSessionCompleteEvent：Controller 消费（结果灯 + result_dwell + 掌唤调度）
```

## 3. 逐模块实现讲解  [25min · 业务意图先行]

### 3.1 `PalmFlowMachine`：HFSM2 包装　palm_flow_machine.h/.cpp
- **轮间 Reset**（:47-53 + cpp:49-78）：取消 timer + **token 自增** + 清 actions + **整建新 FlowContext（新 session_id/trace_id）** + `++round_epoch_`——P0-8 防旧轮响应串新轮的根基。
- **单 timer 模型**（DoArmStateTimer :204-218）：cancel 旧 + `++state_timer_token_`，回调闭包自比 token 再 React——**同态重入不误触发旧超时**。
- `session_id = trace_id.substr(0,12)`、`trace_id = GenerateRandomHexString(32)`（:31-32/:63-65）——每轮新值，两者可互相关联（story 135784881）；SDK 上报的 client_trace_id 也取自它（palm_core_manager.cpp:240-242）。

### 3.2 `palm_flow_states`：22 状态要点（表格见子报告，串讲挑五个讲）
- **RecognizeEntry 瞬态**（:457-466）：update 里按 `ShouldUseLocalIdentify` 分派——本地/云端的岔路口在状态侧而非 Controller。
- **WaitingBindInput / WaitingScanInput**（:621-812）：失败不重置计时继续等（116 收敛）；扫码非 `palmpact://` → 0xAC(162) 留守；deadline 跨 162/163 重试不重置。
- **ResultObtained 统一 0xA3 出口**（:318-356）：按 `CompletionSource{Normal/Abort/ScanFinished/BindFinished}` 派发 OnPalm/Bind/ScanResult + HOST_ACK 判定。
- **Verdict 派发**：`std::visit` + `static_assert(kAlwaysFalse)` **编译期穷举**（:47-151）——新增 Verdict 忘了处理 = 编译不过，不是运行时漏分支。

### 3.3 `PalmFlowStrategy`：四种模式策略
- **决策差异核心**：`DecidePostOpt`（Hybrid 的 `recognition_attempted` 二轮）；`DecidePostRec`（Hybrid：`100025→切注册`、`100038→加验`、need_verify→加验）；`DecidePostLocalIdentify`（未命中→**165 专属码**，2026-09-16 产品决策不再用 306；命中→scene_attach 构造 15 字段 JSON）；`DecidePostRegister`（Unregistered→`EnrollRoutingForMethod` 单一事实源：kCpm→扫码输入，kHost→绑定输入）。
- **强约束与一个口子**（strategy.h:26-30）：同步纯函数禁 IO/锁——但 `CheckNeedVerifyAndExtractId` 用 **const_cast 写 verify_id**（:127-129，注释自认是 Verdict 无 payload 的临时解法，6.2-F7）。

### 3.4 `PalmSessionController`：1956 行的骨架
- **启动链**（Run :502-610）：构造 machine → RegisterGracefulExit(kPalmRunning/kDebugTesting) → 订阅 DeviceState/PalmBehavior/连接态 → CoSpawn RunForever。
- **ConsumeAction 四类**：请求生产（kRec/kRegister，:860-1086）；决策消费（kDecidePost\*，:1098-1268）；SDK 切换/扫码/绑定；metrics 上报挂在决策消费内。
- **网络三处 AsyncExec**（:280/:381/:921）：ThreadPool 同步 HTTP；enroll/register-palm 用 **DEVICE 签名**、verify-palm 默认、recognize 走 `IotRecogPostRequest`（**RECOGNIZE 专用**）；lambda 捕获 trace_id，返回后 **epoch 校验**（:939-946）。
- **server_code 三级分类**（:948-995）：`IsNetworkError`→111/128；无服务端应答→141 兜底不上行细分；服务端应答→MapRec 双语义。BindPalm **不透传**（:315-323），RegisterByCode **透传**（:420-431，163 重试需要原始码）。

### 3.5 `LocalSceneAttach`：Base64(protobuf wire) 手写解析
- SDK 端侧识别命中返回服务端预置用户快照（palm_id/user_id/user_name/physical_card_no/tag_names）；手写 varint/length 解析，未知字段跳过（前向兼容）、截断/垃圾返回 nullopt；**头注释 :40-42 固化了 2026-09-15 误实现为 JSON 导致命中被丢弃的教训**——这是本模块最好的「坑写成文档」范例。

## 4. 核心代码实现细节与原理（重点）  [15min · 讲透原理]

### 4.1 深挖①：FlowAction 队列——状态与 IO 的唯一桥
- 状态类**只能**入队（request_action 闭包），不能自己发 HTTP/调 SDK——所以 states 全部可单测（palm_flow_local_identify_test 用真 FSM + io_context 跑行为）；Controller 的 ConsumeAction 是 IO 唯一入口。
- **对照三兄弟**：iot 模块（命令对象自持自报）、detection（Manager 编排策略）、本模块（队列+消费者）——三种「编排/执行分离」中**队列式最强**：状态侧零 IO 依赖，测试面最大。

### 4.2 深挖②：防串轮三件套（P0-8）
- **round_epoch**（machine 层）：网络返回后比对（:939-946）——旧轮响应到达时丢弃。
- **state_timer_token**（machine 层）：单 timer 重 arm 时自增，回调闭包自比——防旧超时误触发。
- **session_id 匹配丢弃**（LocalRecognizing :468-508）：SDK 信号带 sid，不匹配丢弃。
- 三层防护针对同一类事故：**异步源比会话轮活得久**。与 MQTT dedup、report 队列 request_id 属同族思想：令牌比身份。

### 4.3 深挖③：本地/云端双路由的完整判定链
```
work_mode==kIdentify（核身）？ ──否──→ 云端 Recognizing
        │是
特征同步开关 IsFeatureSyncEnabled()？
        │是 → LocalRecognizing（3s 超时 165）
             命中 → scene_attach 15 字段 JSON + 核验记录(PII 加密) + metrics(local)
             未命中 → 165（Hybrid 覆写→切云端注册）
```
- **为什么仅核身模式**：注册/混合模式需要服务端决策（need_verify/Unregistered 路由），端侧识别拿不到这些判定材料——**本地化只裁剪「纯判定」场景**。

### 4.4 深挖④：超时双轨的陷阱（6.2-F4 的原理）
- dwell `request_timeout`（云控 [3,30]s）arm 的是**状态机 timer**；HTTP 层却是固定 `kPalmHttpTimeout=10s`（controller.cpp:37-39）——**两者管同一次请求**。把 request_timeout 云控调到 30s：状态机愿意等 30s，但 HTTP 10s 先断→落 111 网络错。「调大超时」实际无效，**超时语义被 HTTP 层劫持**。超时与真网络错在上位机视角同为 111（6.2-F5），叠加后更不可辨。
