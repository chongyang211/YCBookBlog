## `flow_actions.h` 的作用

这个文件定义了 `FlowAction` 枚举——刷掌流程状态机的**异步“工单”类型**（spec FR-11）。整个机制是三层协作：

1. **状态层**（`palm_flow_fsm_def.h` + `palm_flow_states.cpp`，基于 HFSM2）：状态在 `enter` / `react` 回调里通过 `ctx.request_action(...)` 把动作入队，状态本身不做耗时工作；
2. **队列层**（`palm_flow_machine.cpp`）：`DoRequestAction` 把动作 push 进 `actions_` 并 `Wake()`，对外提供 `HasPendingActions()` / `PopAction()` / `WaitWork()`；
3. **消费层**（`palm_session_controller.cpp`）：Controller 的 `DrainActionsUntilDone()` 循环 `PopAction()` → `ConsumeAction()`，在里面执行真正耗时的 SDK 调用 / 网络请求，完成后 `machine_->React( XxxEvent )` 把结果回灌给状态机。

也就是说：**状态机只负责“决策 + 入队 Action”，Controller 负责“执行 + 回 React 事件”**，Action 就是两者之间的命令枚举。

## 各 Action 对应的状态机内容

| Action | 入队位置（状态机） | Controller 干什么 |
|---|---|---|
| `kRunOnStart` | `StartingState::enter` | `WaitInitDone` → `StartPalmDetect`（按 ScanMode 视情 `StartCodeScan`）→ React `StartOkEvent` |
| `kRunOnStop` | `StoppingState::enter` | 停检测/扫码、断开信号等收尾 |
| `kRecRequest` | 采掌数据就绪的状态 react（palm_data/camera_data 齐备），加验路径复用 | 按 `IsActive<VerifyingHead>` 区分调 `/verify-palm`（加验）或 `/recognize`（识别） |
| `kRegisterRequest` | 注册采集状态数据就绪时 | 调注册请求 |
| `kDecidePostRec` | 识别/加验响应 `react`（及本地识别结果） | 根据识别结果决策下一状态（通过/重试/失败） |
| `kDecidePostRegister` | 注册响应 react | 根据注册结果决策 |
| `kDecidePostOpt` | 离线优选通过后（先 `StopCodeScan` 防扫码与识别并发） | 优选后续决策 |
| `kSwitchSdkToRegister` | Hybrid 100025 切注册路径（retry 逻辑中，flags 重置处） | 切 SDK 检测模式到 register（幂等），保证下一轮 detect 用 register 模式采集 |
| `kProcessBindPalm` | `WaitingBindInput` 收到 `BindPalmRequestEvent`（story 135094532） | 调 `BindPalmFlow`，完成后 React `BindPalmResultEvent` |
| `kStartScanInput` | `WaitingScanInput::enter`（含 162/163 重试回等待，每次进入都重入队，因扫码是每次扫描后自停的） | `StartCodeScan(kScanPalmSession)` 会话中途动态开扫码 |
| `kRegisterByCodeRequest` | `RegisterByCodeSubmitting::enter`（反扫码注册） | `StopCodeScan` + 前缀防御性复检 + `POST /wecardpalm/device/register-palm`，完成后 React `RegisterByCodeResultEvent` |

一句话总结：`FlowAction` 是**状态机的“出边指令集”**——每个枚举值对应状态图中某个状态在特定时机要委托给 Controller 执行的一段异步副作用（SDK 操作或网络请求），执行结果再以 Event 形式驱动状态转移。
