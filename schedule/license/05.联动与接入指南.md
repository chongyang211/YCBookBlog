# License · 联动与接入指南

> 系列第五篇。覆盖 LicenseManager 与周边模块的全部联动点（0xB0/0xB2 上位机通知、DeviceFsm 钩子、Shadow 上报、刷掌门闸），以及新增触发源/设备态/授权入口的接入检查清单。

## 一、对外联动总图

```text
                    LicenseManager（AuthState 所有者）
  state_signal_（0xB0）|                | auth_result_signal_（0xB2）
  AuthStateChange      |                | AuthActionResult(ret_code/error_msg)
                       v                v
              PosNotifier（订阅双信号，pos_notifier.cpp:31-34）
                       | SendLicenseStateChangeMsg / SendLicenseAuthResultMsg
                       v
              PosLink 0xB0 / 0xB2 -> 上位机弹窗展示

  ResolveLicenseDeviceState -> DeviceStateMachine（ResolveIdleTarget 仲裁）
  OnEnter/OnExit 钩子 <- kLicenseUnauthorized / kLicenseRefreshing 设备态
  MaybeReportShadow / ForceReportShadow -> PaasShadow（module_auth 属性）
  CanStartPalm() <- palm_session_controller（StartPalm 门闸，W1 fix）
```

## 二、0xB0 / 0xB2 双通道消费

| 通道 | 信号 | PosLink 指令 | 内容 |
|---|---|---|---|
| X（状态跃迁） | state_signal_ | 0xB0 kPosAppLicenseStateNotifyCmdId | AuthStateChange{from, to, summary}，不含错误码 |
| Y（动作结果） | auth_result_signal_ | 0xB2 kPosAppLicenseAuthResultCmdId | AuthActionResult{trigger, ret_code(409xx 段), error_msg, summary}，仅动作收尾一次 |

消费链：PosNotifier 订阅两信号（:31-34）-> SendLicenseStateChangeMsg / SendLicenseAuthResultMsg（pos_request_handler.h:150-155）-> 0xB0/0xB2 帧（transferer 白名单 pos_transferer.cpp:51-52）。

语义提醒：0xB0 **每次跃迁都发**（含 kAuthorizing 保护态进出），0xB2 只在动作收尾发一次——上位机应以 0xB0 驱动状态展示、以 0xB2 驱动结果提示。

## 三、上位机指令入口（下行）

| PosLink 指令 | 处理 | 说明 |
|---|---|---|
| 0x10 LicenseAuthorize | HandleLicenseAuthorizeRequest -> EnterAuthorizeFlow | 目标态在 LicenseManager 内选择（owns AuthState）；迁移合法性由 CanEnterFrom 仲裁；结果经 0xB0/0xB2 |
| 0x12 | HandleEnterActivationFlowRequest -> EnterActivationFlow | 仅 kLicenseUnauthorized 可切 kUnactivated |
| 0x13 LicenseExitRefresh | 退出 license refresh | fire_and_forget |

设计原则（pos_request_handler.h:258-260）：目标态选择与 AuthState 判定全部收敛在 LicenseManager，Pos 层只表达意图；扫码由设备态 OnEnter 自动启动，不在 Pos 层启停。

## 四、CanStartPalm 门闸（刷掌启动硬校验）

消费点：palm_session_controller.cpp:148-155（DoStartPalmSession，覆盖 0x04 StartPalm 与 0x0E StartPalmEx）：

```cpp
RefreshAuthState(RefreshReason::kPrePalmCheck);   // W1 fix
if (!CanStartPalm()) { /* AuthState -> ret_code 单点映射拒绝 */ }
```

两个细节：

1. **W1 fix**：CanStartPalm 前先触发复检——避免读到周期定时器 tick 之间的陈旧 AuthState（如恰好过期）。注意 Refresh 是异步投递 LicenseThread 的，本轮读到的仍是现值，语义是"触发复检供下轮 + 本轮用现值判"；
2. **kChecking 的 ret_code 语义**："还没检查完"而非"检查过没通过"——必须回"检查进行中"让上位机等待，与 02 篇 kChecking 禁止复检口径呼应。

## 五、Shadow 上报（module_auth 属性）

| 项 | 说明 |
|---|---|
| 属性 | module_auth：module_license_status（0 未授权/1 已授权/2 已过期）+ module_license_expiry_time（UTC 秒） |
| 载体 | ModuleAuthProvider（FR-7.3，Init 时注册到 PaasShadow） |
| 触发 | SetAuthState -> MaybeReportShadow（status/expiry 双键去重，FR-14.3） |
| 强制 | ForceReportShadow：PaasShadow::Start 后 / 时间可信回调后（去重导致 Start 前 flush 失败的值不再重发） |

与 shadow 模块分工：license 只负责"取值 + 何时报"，批量/实时通道与重试由 PaasShadow 统一处理（见《docs/shadow/03.device-side-上行同步.md》）。

## 六、接入检查清单

**新增授权状态复检触发源**：

1. RefreshReason 新增枚举（日志归因）；
2. 调 RefreshAuthState(new_reason)——禁止直调 CheckAuthLocal / RequestEnter(ResolveIdleTarget)；
3. 确认不违反两个跳过条件语义（kChecking / in_authorizing 期间本就被跳过）。

**新增 license 相关设备态**：

1. 设备态 OnEnter 调 OnEnterXxx 钩子，复核逻辑写在 LicenseManager 内（返回 false 触发重仲裁）；
2. ResolveLicenseDeviceState 补映射分支；
3. 评估是否需要扫码启停（StartAuthorizeScan/StopAuthorizeScan 幂等封装）。

**新增授权入口（非扫码）**：

1. 复用 DoAuthorize 收口对（SucceedAuthorize/FailAuthorize），不得绕过——状态流转、退保护态、0xB2、标志清理四件事缺一不可；
2. 先设置 authorizing_source_（决定失败回退目标与 AuthState 保留策略）；
3. 评估是否需要 ForceReportShadow（见第五节去重陷阱）。

**通用红线**：

- 日志不打 license 内容与 secret（gen_lic 的 secret_key 已有意排除，见 03 篇）；
- license 文件只经 LicenseStorage 原子写，禁止旁路直写。
