# Activation · 扫码与激活码解析

> 系列第三篇，承接《02.状态机与阶段流转.md》。覆盖激活码从扫码分发到解析为 PalmActivationCode 的链路：分发门闸双语义、三格式轻量识别、四路解析器、状态清理。

## 一、分发链入口：TryHandleScanCode 双语义

```text
PalmCoreManager 扫码分发（优先级 (3)：操作码 -> License -> 激活码 -> 业务码）
  v
ActivationController::TryHandleScanCode(content)
  - IsActivationCode(content) == false -> return false（放行业务码链路）
  - == true（是激活码）-> 派发到激活流程（FSM 内部按状态决定处理或丢弃）
      -> return true（吞码：不产生 CodeScanResultSig，不进业务会话）
```

双语义的关键在 **FSM 按当前状态决定处理或丢弃**：

| 当前状态 | 行为 |
|---|---|
| kWaitingForQRCode | 正常处理：OnQRCodeScanned -> WaitingForQRCode.react（qr_data 存 context） |
| 其他状态（含 kActivated/kError/kChecking） | **吞掉但不处理**——已激活后扫激活码无意义，错误/检查态扫激活码也不应打断 |

另有一个反向保护（service.h:110-117）：非激活扫码状态下扫到激活码，`IsActivationCode` 用于**吞掉激活码避免误上报上位机**（如已激活设备扫了历史激活码，不应触发支付失败弹窗）。

## 二、IsActivationCode：三格式轻量识别

仅做**格式前缀检测，不做完整解析**（原始二进制 protobuf 格式无法识别，返回 false——盲区见观察点）：

| 格式 | 识别特征 | 说明 |
|---|---|---|
| wxpact:// 前缀 | 字符串前缀 | 标准激活码 |
| 扁平格式 | `action:100000000` 开头（kActivationCodeAction，palm_core SDK ActionCodeResult 扁平格式） | SDK 扫码结果直出形态 |
| JSON 数组格式 | `[[` 开头 | JSON 数组包裹形态 |

## 三、四路解析器族（ActivationService）

`StartActivationFromQRCode`（FSM QRCodeScanned -> StartActivation 阶段调用）内部自动完成"解析 + 域名证书校验"，解析部分按格式四路分派：

| 解析器 | 输入形态 | 说明 |
|---|---|---|
| `ParseBase64ToActivationCode` | Base64 字符串 | IsBase64Format 判定后 Base64 解码 -> protobuf |
| `ParseBinaryToActivationCode` | 原始二进制 | 直接 protobuf 反序列化 PalmActivationCode |
| `ParseJsonToActivationCode` | JSON（含 [[ 数组） | JSON 字段提取 |
| `ParseActionCodeResultToActivationCode` | SDK 扁平结果串 | action:100000000 键值对提取 |

解析成功 -> `ValidateActivationCode()`（字段校验）-> 提取**激活域名**（驱动 04 篇的证书校验与域名双写）。

## 四、PalmActivationCode 与状态清理

- 解析产物 `PalmActivationCode` 持有于 `activation_code_`（unique_ptr），`GetActivationCode()` 供激活各步骤读取（域名、业务参数等）；
- `Reset()`：清空激活码与临时状态——重扫场景（可重试错误回扫码态后再次扫码）时由流程调用，防止上一次的残留字段污染本次；
- 解析过程的 trace_id（story 137332527）：激活服务会话级 trace_id 与网络层 trace_id 串起整条激活链路日志。

## 五、观察点

1. **二进制 protobuf 格式是 IsActivationCode 的识别盲区**——未激活态下扫到二进制激活码不会接单，会透传业务链路（现象：扫码无反应）；该格式若现网仍存在，需要 palm_core 侧保证不会直出此形态，或补充特征识别；
2. `IsActivationCode` 只做前缀检测——内容合法性（签名/时间戳/域名）在 StartActivationFromQRCode 内完整校验，"识别"与"验证"分层；
3. 吞码语义依赖设备态：kChecking（启动检查中）扫激活码也会被吞——检查通常秒级完成，用户极少感知；若 SE 检查慢（卡 SE 资源竞争），可能出现"扫了没反应"，需按 GetActivationPhase 排查；
4. 四路解析器与 palm_core SDK 的 ActionCodeResult 格式耦合（action:100000000 魔数）——SDK 改格式需同步。
