# Activation · 状态机与阶段流转

> 系列第二篇，承接《01.总览与架构.md》。覆盖 ActivationStateMachine 的 11 个平铺子态、事件驱动全表、错误分流三分法、Phase 归并逻辑与 DeviceFsm 联动。

## 一、FSM 结构：PeerRoot 平铺（非嵌套）

```cpp
using FSM = M::PeerRoot<
  Idle, CheckActivationStatus, NotActivated, WaitingForQRCode, QRCodeScanned,
  StartActivation, KeyExchange, ConfirmKeyExchange, Activated,
  PalmServiceUnavailable, Error >;
```

11 个**平铺对等状态**（非 HFSM 嵌套树）——与 PalmFlow 的 Composite 子树风格不同：激活是**线性流水线 + 两个汇点（Activated/Error）**，无需区域隔离，平铺即可。

外部可见的 Phase（GetCurrentPhase 归并，hpp:526-538）：

| ActivationPhase | 活跃子态 |
|---|---|
| kActivated | Activated |
| kChecking | CheckActivationStatus |
| kNotActivated | NotActivated / WaitingForQRCode |
| kActivating | QRCodeScanned / StartActivation / KeyExchange / ConfirmKeyExchange |
| kPalmServiceUnavailable | PalmServiceUnavailable |
| kError | Error |
| kIdle | 其余（初始） |

## 三、迁移全图

```text
Idle --StartCheck--> CheckActivationStatus
CheckActivationStatus --CheckedActivated--> Activated
CheckActivationStatus --CheckedNotActivated--> NotActivated
CheckActivationStatus --ErrorOccurred--> Error
NotActivated --enter 自动--> WaitingForQRCode
NotActivated --ErrorOccurred--> Error
WaitingForQRCode --QRCodeScanned--> QRCodeScanned（qr_data 存 context）
WaitingForQRCode --PalmServiceUnavailable--> PalmServiceUnavailable
WaitingForQRCode --ErrorOccurred--> Error
QRCodeScanned --QRCodeParsed--> StartActivation（activation_code 存 context）
QRCodeScanned --ErrorOccurred--> Error
StartActivation --ActivationStarted--> KeyExchange
StartActivation --ErrorOccurred--> Error
KeyExchange --KeyExchangeSuccess--> ConfirmKeyExchange
KeyExchange --ErrorOccurred--> Error
ConfirmKeyExchange --ActivationConfirmed--> Activated（is_activated=true）
ConfirmKeyExchange --ErrorOccurred--> Error
```

**每个业务子态都启用 ErrorOccurredEvent 处理**（统一走 HandleErrorEvent：写 context 三字段 + changeTo<Error>）——错误处理是"结构式"而非逐处约定。

## 四、错误分流三分法

| 类别 | 去向 | 例子 |
|---|---|---|
| 可重试错误（**含网络错误**） | 回 WaitingForQRCode（允许重扫） | 网络/超时/服务端可重试码 |
| 致命错误 | 停留 kError | 致命错误码 |
| PalmApp 服务不可用 | kPalmServiceUnavailable（等待 PalmServiceAvailableEvent 恢复） | PalmApp 服务健康检查失败 |

重试/致命的判定依据 `context.retry_server_code` 与错误码分类（Controller 侧 OnError → 派发事件时决定）。激活与 verify_record 的语义差异：激活是**交互式流程**（需要人扫码），自动重试无意义，可重试错误回扫码态等下一次人工输入；verify_record 是无人值守补报，自动重试 + 降频。

## 五、DeviceFsm 联动（v6.4，spec 3.6）

```text
进入 kStartActivation（真正开始动设备/网络）：
  OnActivationStart -> RequestEnter(kActivating)
    被拒（kPalmRunning/kUpgrading/kInspecting 等占用）-> OnError
    -> ActivationFsm 转 kError，整套激活终止（不死等）
NotifyActivationPhase（Phase 去重：last_notified_phase_ 不同才通知）：
  kActivated              -> 请求退出到 Idle
  kError / kPalmServiceUnavailable -> 退到 Unactivated
  kActivating             -> 不在此处退（OnActivationStart 已单独 RequestEnter）
```

Phase 回调消费：PosRequestHandler 的 `SendActivationStatusChangeMsg` 上报上位机（激活阶段通知，含 error_code/msg）——上位机扫码授权 UI 依赖此通道驱动界面状态。

## 六、观察点

1. **PeerRoot 平铺 vs PalmFlow Composite**：激活 FSM 无并发/嵌套需求，平铺可读性最好；但状态数增长（如增加绑定流程）时需重新评估是否引入层级；
2. Error 态的恢复出口是 PalmServiceAvailableEvent / 重扫（WaitingForQRCode 需经新扫码事件）——**没有自动重试定时器**，与激活的交互式语义一致；
3. `Activated` 是终态且**不处理错误**（:357-359 注释）——已激活后进入本 FSM 的事件被忽略；重新激活/换域名需走其他路径（如设备恢复出厂重置 prop+SE）；
4. context（is_activated/qr_data/activation_code/error 三件套/retry_server_code）是平铺状态间唯一的传参通道——与 PalmFlow 的 FlowContext 同思想；
5. GetCurrentPhase 用 isActive 链式归并——新增子态时记得同步归并表，否则 Phase 会误报 kIdle。
