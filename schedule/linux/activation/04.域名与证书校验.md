# Activation · 域名与证书校验

> 系列第四篇。覆盖激活域名的双重存储管理与证书链校验（DomainValidator）。激活码中携带的域名必须通过证书校验才会落地——这是"防止激活码指向恶意服务器"的核心防线。

## 一、域名双重存储设计（prop 首选 + SE 备份）

| 存储 | 键/机制 | 角色 |
|---|---|---|
| 系统属性 | `ro.vendor.palmactivation.server_host` | **首选数据源**（读写快、易诊断） |
| SE 芯片 | SeKeyStore 内存储 | **备份数据源**（抗系统属性被清除） |

`GetVerifiedServerDomain()` 对齐策略（互恢复设计）：

```text
prop 非空：SE 为空或不一致 -> 同步 prop -> SE（SE 追平）
prop 为空：SE 非空 -> 恢复 SE -> prop（自愈）
两者都空  -> 异常（nullopt）——无网络时无法自愈，需重新扫码激活
返回有效域名（任一来源），校验通过后设备即拥有专属通信域名
```

`StoreServerDomain(domain)` 写入策略：以**系统属性写入结果**为返回值；SE 同步失败仅警告（prop 可用即视为成功）。`QuickCheckActivated` 只读该属性（不碰 SE/云端），是全系统最快的激活快判。

## 二、证书校验四步（CheckDomainValid，domain_validator.cpp:60-98）

```text
前置：Network::SetActivationSession 已用激活域名配置会话（校验发生在域名落地前）
  |
  v (1) DownloadCertificate（:100-139）
      GET /license（ActivationGetRequest，SIMPLE 签名）
      -> JSON {"license": "<证书>"} 提取 license 字段
      解析失败 -> ERR_PALM_IOT_PARSE_ERROR
  v (2) CheckDomainValidAndFetchInfo（:141-286）证书解析与验签
      a. 清理 PEM（去 BEGIN/END 标记与空白）-> base64 解码 -> DER
      b. d2i_X509 加载目标证书
      c. 加载内置根证书 certs/domain_certificate.crt
      d. X509_verify：用根证书公钥验证目标证书签名
         （单级自设计 CA——只验"由内置根签发"，不做链深/CA 标志检查）
      e. 提取 CertificateInfo{not_before, not_after, CN, O, L, ST, C}
      任一步失败 -> nullopt -> DOMAIN_VALIDATION_ERROR
  v (3) PerformCheckInfo（:288-304）
      - 有效期：now 在 [not_before, not_after] 内
      - 域名匹配：证书 CN == 激活域名（精确匹配，无 SAN 检查）
  v (4) 成功 -> ERR_PALM_IOT_SUCCESS（后续 StoreServerDomain 落地）
```

所有失败文案统一带 ` [trace_id:xxx]` 尾缀（WithLicenseTraceId，story 137332527：/license 请求已发出，谁生成文案谁带单号）——上屏即可售后定位。

## 三、根证书加载（LoadRootCertificate，:306-332）

按序尝试三个路径，取第一个非空：

1. `<app_dir>/res/certs/domain_certificate.crt`（随包资源）
2. `<app_dir>/certs/domain_certificate.crt`
3. `/data/palmapp/certs/domain_certificate.crt`（数据目录，可运营侧替换？——以实现为准）

三路径全空 -> 根证书加载失败 -> 校验失败（激活无法完成）。

## 四、观察点

1. **有效期校验依赖设备时间**：PerformCheckInfo 用 time(nullptr)——设备时间未同步（1970）时 `now < not_before` 必失败，域名校验无法通过。上游流程需保证 NTP 先行（网络已通即可对时）；排查"激活报 domain validation failed"时先查设备时间；
2. **mktime 时区问题**：not_before/not_after 经 ASN1_TIME_to_tm（UTC 分量）+ mktime（**本地时区**解释）转 time_t——设备时区非 UTC 时有效期边界会偏移数小时。极端时区 + 贴边有效期可能误判，建议改用 timegm；
3. **域名匹配仅 CN 精确匹配**，无 SAN（Subject Alternative Name）检查——现代证书惯例是 SAN 优先，CN 匹配对当前自签证书够用，但扩展证书形态时需补；
4. **证书内容全量打日志**（:74/:117 LOG_I 证书 PEM 原文）——证书是公开数据无敏感性，但日志量偏大（每条激活尝试数 KB）；
5. 根证书为**内置单级自设计 CA**——轮换根证书需升级固件（同 license 篇观察点），三路径设计为运营侧替换留了一个口子（/data 路径）。
