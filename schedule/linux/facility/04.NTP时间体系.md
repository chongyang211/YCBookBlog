# Facility · 04 NTP 时间体系

> 系列第四篇。设备无 RTC 保障，开机墙钟可能停在 1970。覆盖三层时间设计、TimeStateManager 可信判定、NtpTimeSync 的 SNTP 协议实现（RFC 5905 精简模式）、同步时机状态机、双回调机制与墙钟依赖清单。承接《01.总览与分层架构.md》。

## 一、三层时间设计

| 层 | 模块 | 职责 |
|---|---|---|
| 单调时钟 | 各模块 steady_timer | 所有定时器/超时/测量一律 steady_clock——不受跳变影响 |
| 墙钟可信判定 | time/time_state_manager | 集中判定"系统时间是否可信"并广播状态 |
| 校时 | ntp/ntp_time_sync | SNTP 对时，settimeofday 校系统钟 + hwclock 持久化 RTC |

## 二、TimeStateManager：时间可信状态机（time_state_manager.h，story 136515343）

**定位**：集中式时间可信管理——统一"系统时间是否可信"的判定与广播，替代各模块分散轮询。所有依赖墙钟的逻辑（MMKV 过期、Recover 限频窗口、证书校验、License 窗口）都以它为唯一裁决源。

**核心原则**（:22-24 注释）：判定依据是"**本地时间是否合法**（越过 2023 出厂基线）"，而非"NTP 是否同步过"——NTP 只是触发复检的时机之一，本管理器不依赖 NTP。

**状态机**：`kUntrusted → kTrusted` **单向跃迁，永不回退**；跃迁时触发 `time_trusted_sig_`（one-shot，CAS 保证只触发一次）。另有 `time_sync_sig_`（persistent，每次 NTP 同步成功触发，本期无订阅者——为"运行时时间跳变处理"预留）。

**四个复检触发时机**（Init 全部布防）：

| # | 时机 | 覆盖场景 | 代码 |
|---|---|---|---|
| 1 | Init 立即检查 | RTC 非出厂默认值（重启后 hwclock 恢复成功）——激活前即可直接 trusted | :32 |
| 2 | NTP boot sync 完成回调 | 常规路径：开机 NTP 校准后 | :36-38 |
| 3 | NTP 任意同步成功回调 | 运行期周期/补同步 | :39-41 |
| 4 | **5s 轮询任务**（time_state_trust_poll，kSync） | **外部时间源无回调的场景**：system ntpd、RTC 恢复修正了时钟但 app 层 NTP 回调不触发——否则状态永远卡在 kUntrusted（:43-46 注释明确写了该反例） | :47-55 |

轮询任务**自禁用**设计：trusted 后 SetTaskEnabled(false)，不占用调度器。

**并发设计**（全仓回调竞态处理最严谨的实现）：

| 机制 | 实现 |
|---|---|
| 状态读取 | atomic acquire/release——IsTimeTrusted() < 1ns 热路径无锁 |
| one-shot 保证 | trusted_fired_ 的 **CAS**（:76-81）：只有第一次 false→true 的线程执行跃迁+触发——防 NTP 回调线程与轮询任务并发跃迁重复触发 |
| **注册双重检查**（:103-126） | RegisterTimeTrustedCallback：① 已 trusted → 立即执行返回；② connect 后**再查一次**——connect 期间可能已被并发跃迁，若错过则手动执行+断开，**保证事件不丢** |
| 时间解析 | localtime_r（:67）——NTP 回调线程可能并发调用 |

可测性：IsLocalTimeValid 拆无参/有参两版（:56-57），有参版纯判定可注入时间戳，配套 time_state_manager_test.cpp 单测。

**消费**：广播状态变更；scheduler 的时间门控（requires_time_synced）、MMKV 过期判断等均以此为准。

## 三、NtpTimeSync：协议与算法（ntp_time_sync.cpp）

**SNTP 精简模式（RFC 5905）**：48 字节 UDP 包（static_assert 校验，:44），请求 `LI=0/VN=4/Mode=3`（0x23，:185），端口 123，IPv4。

**单次同步节奏（DoSync，:126）**：最多 3 次尝试（kMaxRetries），总预算 15s（steady 计时，:133），单次接收超时 3s（SO_RCVTIMEO）。

**时钟偏移计算（:228-248）**——经典四时间戳公式：

```text
offset = ((T2 − T1) + (T3 − T4)) / 2          # T2/T3 = 服务器收/发时刻（响应携带）
corrected = T4 + offset                        # T1/T4 = 客户端发/收时刻
```

实现细节值得注意：

1. **T4 用 steady 差值合成**（:241-243）：`T4 = T1 + (t4_steady − t1_steady)`——往返时长取自单调时钟，避免测量窗口内墙钟被其他源改动导致 T4 失真；
2. **T1 即使是 1970 也算得准**：本地钟偏差在公式中自补偿（本地慢 X → offset 偏大 X），corrected 恒为正确 UTC——这正是 NTP 设计的精髓，未同步期首同步即可直接校准；
3. **响应校验三道**（:218-238）：mode ∈ {4(server), 5(broadcast)}、stratum ∈ [1,15]（stratum 0 = KoD 直接拒绝）、T2/T3 非零。

**落盘（SetSystemRtcTime，:257）**：`settimeofday` 跳变校钟（失败才算同步失败）→ `hwclock --systohc --utc` 持久化 RTC（失败仅 LOG_W——重启后会回退，由 TimeStateManager 基线兜底）。

**服务器推导（:99-107）**：`BuildNtpServerAddress(host) = "link-" + host`（如域名 `api.xxx.com` → NTP 服务器 `link-api.xxx.com`）；host 取 `Network::GetDeviceDomainHost()`（激活后才有值，未激活返回空 → `SERVER_NOT_CONFIGURED`）。

## 四、同步时机状态机

```text
                StartBootSync（Phase2 注册，bootstrapper.cpp:308）
                     │ 注册 scheduler 任务：基频 5s × 初始延迟 3（=15s 首跑）
                     ▼
        ┌─── boot sync 循环（kLow/kAsync）───┐
        │  SyncTime() 失败                    │ 成功
        │  retries++ ≥3 → 切 60s 慢档         │ boot_sync_done_=true
        │  （C3 fix：不放弃，见下）            │ 停任务 + 通知 boot one-shot 回调
        └─────────────────────────────────────┘ + 触发 persistent 回调
                     ▲                                    │
        OnNetworkConnected（:90）                           ▼
        重置 retries、恢复 5s 快档              首次成功时惰性注册 periodic 任务
        （仅 boot 未完成时有效）                （24h，默认 disabled → Enable）
                                                     │
                              ┌── periodic 循环 ─────┤
                              │ 失败：按连接态降档重试 │ 成功：恢复 24h
                              │ connected→10s         │ + NotifySyncDoneCallbacks
                              │ disconnected→60s      │
                              └──────────────────────┘
```

| 时机 | 行为 | 代码 |
|---|---|---|
| boot 首同步 | Phase2 注册，15s 后首跑，之后 5s 一试 | ntp_time_sync.cpp:60-88 |
| boot 连续失败 ≥3 次 | **切 60s 慢档继续重试，永不放弃**（C3 fix，:76-84） | 同上 |
| 网络恢复 | OnNetworkConnected：重置计数、恢复 5s 快档 | :90-97 |
| 首次成功 | 惰性注册并启用 24h 周期任务 | :145-146, 276-291 |
| 周期失败 | 按连接态 10s/60s 降档重试 | :301-306 |
| 激活前 | SyncTimeWithDomain(激活域名)——独立前置同步，非阻塞 | :118-124（见 activation 05 篇） |

**C3 fix 语义**（:76-79 注释）：`OnNetworkConnected` 不可靠——网络"已连接"但 NTP 服务器不可达不会触发该回调；且 LicenseManager 要求设备停留在 kLicenseChecking 直到 NTP 成功。所以 boot 失败不能靠"等网络事件"，必须自持慢轮询。

## 五、回调机制（Story 136057693）

| 回调 | 语义 | 触发时机 | 消费方 |
|---|---|---|---|
| `RegisterBootSyncDoneCallback`（:310） | **one-shot**；已 done 则立即同步执行 | 首次 boot 同步成功 | boot 后才能初始化的模块 |
| `RegisterSyncDoneCallback`（:336） | **persistent**；每次同步成功都触发（boot + periodic） | 每次成功 | LicenseManager：`RefreshAuthState(kNtpSync)`——运行时钟变化后重校授权窗口 |

**线程注意**：回调在 NTP 任务线程（scheduler iot_pool，kAsync）执行；`RegisterBootSyncDoneCallback` 在已 done 时**在调用者线程内联同步执行**——注册回调里不可做重活/阻塞，且此时不能假设处于任何特定线程。

| 码 | 场景 |

## 七、墙钟依赖清单（设计时必查）

| 消费方 | 用途 | 对时间可信的要求 |
|---|---|---|
| MMKV Config 过期时间 | KV 过期（config.h:48-49 注释） | **需时间同步后才可用**，未同步期过期语义不可靠 |
| Recover 重启限频窗口 | 60min 窗口按墙钟统计（recover.cpp:59-74） | 依赖墙钟，极端情况（校时回拨）窗口判断失真 |
| 日志/xlog 时间戳 | 排查排序 | 未同步期显示 1970，属已知现象 |
| 证书有效期校验 | 激活域名证书（activation 04 篇） | 激活前 SyncTimeWithDomain 预同步兜底（非阻塞） |
| License 授权窗口 | 授权时效校验 | boot sync 完成 + persistent 回调驱动重校（第五节） |
| OTA/心跳等业务时间 | 上报 happen_time 等 | 走墙钟，未同步期由平台容忍 |

**新增性质**："每隔 X""超过 Y 时间"类逻辑，先判断该用 steady（间隔测量）还是墙钟（绝对时刻/跨重启），跨重启窗口一律墙钟并评估可信前提。

## 八、观察点

1. **回调注册竞态窗口**：`RegisterBootSyncDoneCallback` 先查 `IsBootSyncDone()` 再拿锁 push——若检查后、入队前恰好发生 Notify（swap 走空列表），该回调永远不被调用。窗口极小但存在，保险写法是注册即持锁复查 done 标志；
2. **offset 无质量过滤**：SNTP 单样本、假设上下行对称，无 RTT 剔除/多样本择优——移动网络下偏差可达百 ms 级；对当前消费方（日志/证书/授权窗口）可接受，未来若用于计费/精确鉴权需升级；
3. **settimeofday 直接跳变**：无 slew 平滑——跳变瞬间墙钟消费者（限频窗口、MMKV 过期）受影响，steady 定时器无感（已有分层设计兜住）；
4. hwclock 走 `system()` shell 调用（:268），失败仅告警——RTC 未持久化时重启回 1970，靠 TimeStateManager 基线判定"不可信"重新走 boot sync，链路自洽；
5. boot sync 与 periodic 是两个独立任务，periodic 在首次成功后才注册（惰性）——若设备始终无法同步，periodic 永不注册，boot 慢轮询是唯一驱动，符合 C3 fix 设计；
6. 服务器域名硬拼 `"link-"` 前缀（:100）——云端 DNS 需保证 `link-<域名>` 均可解析，新增环境/域名时需网络侧确认；
7. **TimeStateManager 状态单向、无降级**：trusted 后运行时若时间被改坏（回拨/清零），IsTimeTrusted() 仍返回 true——当前消费方（MMKV 过期、限频窗口）会拿到失真时间；time_sync_sig_ 预留接口正是为此准备，尚未接线；
8. TimeStateManager 判定只看"年份 ≥ 2023"下界，不校验合理性上界——时钟跑飞到未来同样算 trusted（对证书校验是真实风险，激活前 SyncTimeWithDomain 预同步为缓解措施，见第二节第五节）；
9. NtpTimeSync 的 RegisterBootSyncDoneCallback 存在丢回调竞态窗口（第 1 条），**TimeStateManager 的注册双重检查（第二节）是教科书解法**——修复时可照搬。
