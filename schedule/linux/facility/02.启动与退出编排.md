# Facility · 02 启动与退出编排

> 系列第二篇。覆盖 main → Application::Run → BootStrapper 两阶段启动全流程、Phase2 的订阅时序契约、三条退出路径与 restarter 分类契约。承接《01.总览与分层架构.md》。

## 一、入口链（app/app.cpp:261 `Application::Run`）

```text
main.cpp:5 → Application::Run
  1. Setup/ParseArgs（env、signal-parent、simulate-crash 参数）
  2. MaybeSimulateCrash（Story 136123576 验证钩子）
     位置有意为之：ParseArgs 后（参数先可读）、RunGuardCheck 前（不碰 pid 锁）；
     持久计数器控制，自终止于 N 次崩溃后
  3. RunGuardCheck PID 锁防多实例（app.cpp:170）
     失败（已有实例在跑）→ return 0 —— **退出码 0 让 restarter 既不重启也不计 crash**
  4. Threads::Instance()->RunMainThread(...)：
       注册 SIGINT/SIGTERM → HandleSignal
       CoSpawn SetupSignalParent（可选：周期 kill(getppid(), SIGUSR1) 心跳父进程）
       Threads::Init() 起全局线程组
       BootStrapper::Run()
```

## 三、Phase 2：激活后（bootstrapper.cpp:243 `OnActivationStatusChanged`）

```text
1. LightNotifier/PosNotifier 订阅（先订阅！）
2. PosNotifier 注入 PosRequestHandler（GetGlobalPosRequestHandler 首调即创建，
   无需依赖 SessionDriver 已启动）
3. 网络诊断收尾装配（未激活也启用——排查场景常在未激活时）：
   DiagnosisReporter / SpeedTestNotifier / StartAutoSpeedTest（Story 137345399）
4. IotService::RegisterBiCommHandlers（提前注册不依赖激活的 handler，如 uploadLog，
   保证未激活时 Host 得到 40002 而非 41001）
5. PalmSessionController::Run（PalmRunning owner + 信号订阅）
   PosNotifier SetPalmFlowSubscriber（FR-19 Flow 轨，同样 Post 主线程靠 FIFO 排序）
6. Post 到主线程：DeviceStateMachine::Start(is_activated)
   ├─ 已激活 → TryStartActivatedServices()（call_once 防重）
   │    NTP boot 同步 → PaasShadow 订阅/Start → MqttService → ReportService
   │    → IotService → HeartbeatService → QRCode → MetricsResourceReporter → VerifyRecord
   │    DeviceFsm 去向由 ResolveIdleTarget 仲裁：已授权 kIdle / 未授权 kLicenseUnauthorized
   │    （IoT 服务只依赖激活不依赖授权——未授权时 OTA 通道仍可用）
   └─ 未激活 → 停在 kUnactivated（红灯，待激活）
```

**订阅时序契约**（:247-257 注释，v6.4.1 修正）：DeviceFsm `Start` 的同步 Transition 末尾会派 light_sig_ 首次广播；若 Start 先于订阅 Post 执行，广播发到无人订阅的信号上，被迫走旁路兜底灯光（违背"DeviceFsm 是灯效唯一对外信号源"契约）。修正方式：订阅与 Start 都 Post 主线程，**FIFO 保证订阅先执行**。新增"启动即广播"的模块时必须沿用此契约。

## 四、退出：三条路径与 restarter 分类契约

```text
路径 A 正常退出：SIGINT/SIGTERM → HandleSignal → BootStrapper::Exit（bootstrapper.cpp:400）
  → Config::Flush → PalmCoreManager::FlushLog → Logger::FlushSync → io_context 结束 → return

路径 B 主动重启：Application::Restart 协程（app.cpp:304）
  → WaitAppSessionIdle(1, 3s) 等刷掌会话空闲（超时也重启，仅 LOG_E）
  → _RestartNow → Exit() → ::_exit(1)

路径 C 快速重启：Application::_RestartNow（app.cpp:295）直接 Exit + ::_exit(1)
  （Recover 等"不等会话"的场景走这条）
```

**restarter 分类契约**（app.cpp:298-301 注释，跨进程约定）：

| 退出形态 | restarter 行为 |
|---|---|
| `WIFEXITED` 且退出码非 0（如 `_exit(1)`） | **重启进程，但不计为 crash** |
| `WIFSIGNALED`（被信号杀死） | 重启**且计为 crash**（进 guard.sh 崩溃分类） |
| 退出码 0（如 RunGuardCheck 失败） | 不重启、不计数 |

因此：主动重启必须走 `_exit(1)`（B/C 路径），**绝不可 abort/被信号杀**——否则一次计划内重启会污染崩溃计数，触发误降级。

**guard.sh 崩溃分类联动**（Story 136123576）：进程被杀时若 `/data/palmapp/guard/ota_pending` 存在 → 归类 ota_crash，否则 continuous_crash。ArmPalmappStableTimer 启动 60s 后 unlink 该标记（"稳定运行 = 当前版本健康"），防止 OTA 后一次无关崩溃被误归类。**注意**：60s 与 restarter 的 `--stable-run-reset-count`（也 60s）**数值巧合、作用域不同**（后者重置 restarter 内部崩溃计数）——原注释明确勿统一（:65-68）。

## 五、接入检查清单

**新增启动项**：
1. 判断归属 Phase1（激活前可用）还是 Phase2（TryStartActivatedServices，依赖激活）；
2. Phase2 新项放进 `TryStartActivatedServices` 的 `call_once` 内，按现有编号顺序追加；
3. 启动即广播的信号：订阅必须先 Post、Start 后 Post（第三节契约），禁止同步初始化混排；
4. 顺序敏感项在 bootstrapper.cpp 原位注释依赖原因（story 号 + 为什么不能动），不要重排既有行；
5. 重活归属线程：guard 类进 IotThread（Post）、SDK 回调类由 palm_core 统一 Post 主线程——启动序列里禁止同步做网络/大 IO。

**新增退出/重启调用**：
1. 计划内重启一律 `_RestartNow`（走 `_exit(1)`），禁止 abort/raise 信号（触发 crash 计数，见第四节契约）；
2. 会话敏感的重启用 `Restart` 协程（等 3s 空闲）；快速路径才用 `_RestartNow`；
3. 多实例场景：二次启动必须退出码 0（不惊动 restarter）。

**观察点**：
1. BootTask/task_graph 静态注册机制已废弃（SetTaskDeps 空实现，bootstrapper.cpp:141-142），文档/新人勿按任务图理解；
2. Phase1 顺序为硬编码，无编译期/运行期依赖校验，重排风险靠注释约束；
3. TryStartActivatedServices 的 call_once 意味着这些服务**不会因反复激活回调而重启**——若未来支持"重新激活换域名"，需评估该语义；
4. ArmPalmappStableTimer 的 60s 与 restarter 同值巧合、语义不同——调整任一侧时需检查另一侧，勿"顺手统一"；
5. Restart 协程等会话空闲上限 3s，长会话（加验等待输入 40s+）期间重启仍会打断会话——是否可接受取决于业务，当前为已知取舍。
