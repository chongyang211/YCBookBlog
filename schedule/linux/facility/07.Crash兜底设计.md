# Facility · 07 Crash 兜底（exception_track）

> 系列第七篇。覆盖 crash/ 模块：未捕获异常的"临终日志"兜底。承接《05.故障恢复与韧性.md》（本模块即该篇五层漏斗的 L2）。

## 一、作用

全模块只有一个功能：`ExceptionTrack::TrackUnhandledException()` 安装 `std::set_terminate` 处理器（exception_track.cpp:34）。当 C++ 异常逃逸到顶层（没有 catch 接住、noexcept 函数里抛异常、线程退出时仍有活跃异常）触发 `std::terminate` 时，**在进程死掉前把异常类型和 what() 写一条 FATAL 日志，再 abort**。

它不阻止崩溃（也阻止不了），只保证崩溃"有遗言"：事后在 xlog 直接搜 `terminate called after throwing an instance of 'xxx'` 即可定位，不依赖 core dump。

## 二、工作流程

```text
异常逃逸 → std::terminate
  → TerminateHandlerWithLog（:11-30）
      1. current_exception() 有活跃异常？
         ├─ 有 → throw; 重新抛给自己 catch：
         │    catch(std::exception&) → demangle 类型名 + what()
         │      → snprintf 进预分配 512B 静态缓冲
         │      → Logger 直写 kLevelFatal
         │    catch(...)             → FATAL "unknown type exception"
         └─ 无（如裸 std::terminate 调用）→ 不写日志，直接 abort
      2. std::abort() 结束进程
         （WIFSIGNALED → restarter 计为 crash → guard.sh 崩溃分类，见 02 篇第四节）
```

调用时机：Phase1 第 2 步（bootstrapper.cpp:147），紧跟 Logger::Init 之后——日志可用即安装，覆盖尽可能早。

## 三、三个设计点

1. **预分配 512B 静态缓冲**（:12）：崩溃现场禁止堆分配（堆可能已损坏或耗尽——std::bad_alloc 本身就是常见 terminate 原因），handler 内只允许栈/静态内存。snprintf 到静态缓冲、Logger 直写（不走会分配的 fmt 路径）都遵守这一约束；
2. **re-throw 自检技巧**（:16）：`throw;` 把当前异常重新抛进自己的 try——这是 terminate handler 里获取异常对象的唯一标准做法；
3. **`current_exception()` 为空则跳过日志**（:14）：区分"异常逃逸"与"其他 terminate 原因"（裸 terminate、join 自身等），后者无内容可写，不强凑日志。

## 四、边界：它不覆盖什么

| 场景 | 是否覆盖 | 兜底方 |
|---|---|---|
| 未捕获 C++ 异常 | ✓ 本模块 | — |
| 段错误/空指针等**信号崩溃** | ✗ | L5 外部守护（restarter→guard.sh）+ 重启后 RecoveryReporter 补报崩溃现场（02 篇第二节） |
| assert 失败 | ✗（走 SIGABRT，不经 terminate） | L5 |
| 崩溃后的恢复动作 | ✗（只留痕不恢复） | L3 Recover / L5 守护 |

**与 restarter 分类契约的关系**（02 篇第四节）：本模块走 `std::abort()` → 被信号杀死 → **计为 crash**——正确行为，未捕获异常本就应算崩溃；计划内重启走 `_exit(1)` 不计 crash。两条路径在 restarter 侧的分类各归其位。

## 五、观察点

1. **无 stack trace**：只有异常类型 + what() 文本，无堆栈回溯（arm 上引 libunwind/stacktrace 有成本，当前取舍可理解）——复杂崩溃仍需 L5 的 RecoveryReporter 现场文件与日志上下文定位；
2. `typeid(e).name()` 在多重/虚拟继承的异常类上 demangle 可能不完整（罕见，实战影响小）；
3. FATAL 遗言若恰逢 xlog 自身故障（磁盘满等）会丢——磁盘满本身常是异常根源，属已知盲区，靠 L5 兜底。
