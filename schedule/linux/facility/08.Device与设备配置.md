# Facility · 08 Device 与设备配置

> 系列第八篇。覆盖 device/ 模块三个单例：Device（设备静态信息+属性通道）、PalmBehavior（云端行为配置+本地设置双轨）、RecognitionModeConfig（重启生效型配置闭环）。承接《01.总览与分层架构.md》。

## 一、模块定位

三个文件三个角色，共同回答"这台设备是什么、该有什么行为"：

| 文件 | 角色 | 一句话 |
|---|---|---|
| device.h/.cpp | `Device` 单例 | 设备静态信息快照（SN/机型/ROM）+ 系统属性访问 + 运维查询 + 运维云属性订阅 |
| palm_behavior.h/.cpp | `PalmBehavior` 单例 | 云端 `palm_behavior` 属性（业务行为开关）+ 一组刻意与云端隔离的**纯本地设置** |
| recognition_mode_config.h/.cpp | `RecognitionModeConfig` 单例 | 云端 `recognition_mode` 属性的"下发→生效→回报"闭环，带**防重启死循环四道防护** |

三者都是 PaasShadow 云属性的消费端，设计取向不同：Device 只做"通道+落地"，PalmBehavior 做"云端配置+本地配置双轨"，RecognitionModeConfig 做"需重启生效配置的完整生命周期管理"。

## 二、Device：静态信息 + 属性通道

**Init 流程**（device.cpp:102-，Phase1 第 3 步）：

```text
1. 读 /proc/device-tree/serial-number → device_sn_（trim \r\n\0 空格）
2. 读 /etc/version（K=V 逐行）→ device_props_（ROM 版本/型号等）
3. 读应用启动参数 → env_use_beta / env_993_route（测试环境路由）
```

四块对外能力：

| 块 | 内容 |
|---|---|
| 静态信息 | GetSn / GetBasicProp / GetRomVersion / GetModel；机型判断 O2/O3/O4（prop key 因 PALM_O4 编译开关不同：ro.build.* vs RK_*）；Capacity 位掩码（kDisplay） |
| 系统属性 | GetSystemPropSync / SetSystemProp / 协程版 GetSystemProp——激活域名（activation 04 篇）、disable_self_recovery 等的存取通道 |
| 运维查询 | 协程版 GetIccid / GetImei / GetIpv4 / GetNetworkType / GetTotalSize 等 |
| 时间可信 helper | SysTimeSynced / CheckTimeSyncedOrSkipLog——**scheduler 时间门控的实现落点**（60s 按模块节流告警，《03.线程模型与调度.md》第三节） |

**激活后云属性订阅**（InitDeviceBehavior / InitOperateAdb / InitDeviceDebug / InitDeviceOps，Phase2 经 PaasShadow 注册）：如 device_ops 的 `disable_self_recovery` 云端下发 → 归一化（YES/NO，:39-57）→ 写系统属性 `ro.vendor.palmapp.disable_self_recovery`（外部守护/恢复层可读）；`zerus_id` 调试环境由 device_debug 属性控制（互斥锁保护）。

## 三、PalmBehavior：云端配置与本地配置的双轨设计

**云端轨**（PalmBehavior::Config，8 字段随云属性 JSON 下发）：

| 字段 | 语义 |
|---|---|
| app_type | Pay / Kyc |
| allow_palm_wake + mode_after_palm_wake / mode_after_host_wake | 唤醒开关与唤醒后模式（HOST_ENROLLMENT / CPM / RECOGNITION / HYBRID） |
| output_protocol / output_content | USB_HOST / WIEGAND；USER_ID / OTC / CARD_NUMBER |
| result_action_mode | 设备自闭环 / **上位机回执**（HOST_ACK，story 135810205） |
| hybrid_enroll_method | HYBRID 未注册时走 HOST 绑定 / CPM 反扫码（story 137286676） |

- 双信号订阅：云端 changed + **device-side 缓存被云端覆盖**（后者只重载内存不回写——"值本就来自云端，回写会来回覆盖"，palm_behavior.h:199-201 注释）；
- `UpdateSingleParam(key, value)`：0x0B 上位机写入入口，错误码 122（未知 key）/ 123（非法枚举）；`OnChanged()` 信号供 biz 订阅。

**本地轨**（刻意隔离：不进云端 JSON、不经 PaasShadow 上报、不触发云端语义的 OnChanged）：

| 字段 | 持久化 | 说明 |
|---|---|---|
| palm_wake_restart_interval | 独立 MMKV `palm_local_settings` | 1~5s clamp，默认 3 |
| offline_preferred | **内存 only**（重启丢，上位机 SDK init 后重设） | 离线优选 per-call override |
| scan_mode | 持久化（同 MMKV） | 扫码模式 |
| flow_dwell_config | 同 MMKV（key 前缀 flow_dwell_*） | 刷掌状态机驻留参数（story 135094532）：0x0B 写 → FR-1 权限矩阵校验 → clamp → 落盘 → OnChanged；Controller 每轮 RunOneRound 取快照 |

`BuildPalmBehaviorConfigBase64()`：云端 8 字段 + 本地字段合成 base64(JSON)，供 0x0A 查询应答 / 0xA9 变更通知 / 0xA8 会话开始快照——**会话快照应在会话开始时捕获**（配置可能中途被 0x0B 改）。

## 四、RecognitionModeConfig：重启生效型配置的完整闭环

云属性 `recognition_mode`（{"mode":"CLOUD"|"ON_DEVICE"}）→ 识别引擎 `enable_local_feature_sync` 传参。**为何重启生效而非热切换**（:40-42 注释）：SDK 不持久化该参数，每次 Init 必须显式传；且 vendor README 明示 false→true 的运行时切换不可靠。

```text
Phase1：Init（PaasShadow::Init 后、PalmCoreManager::Init 前）
        读 cloud-side 缓存 → target_mode_（决定引擎特征同步传参）
        Start（PaasShadow::Start 前，否则丢首次 Notify）
                    │
运行期变更（MainThread）HandleModeChange：
  四道防护（缺一即可能死循环重启，:44-48）：
    ① 值语义幂等比对（解析成枚举再比，不比字符串）
    ② 持久化确认（重读 device-side 缓存核对新值已落地）
    ③ 启动冷却期 30s（冷却内变更暂存 pending_target_，到点重走主流程）
    ④ 熔断：连续 3 次 applied ≠ target → 熔断（30min 惰性衰减；计数/最近重启
       时间戳/熔断 target 三态持久化 MMKV "recognition_mode_state"；
       后续下发不同值即解除并放行一次）
        → RestartApp
                    │
引擎 Init 完成 → OnEngineInitialized(applied)：
  EvaluateConvergence（applied==target 清零计数，否则 +1 触发熔断判定）
  ReportAppliedMode 回报实际生效值到云端
  （实时 → 批量 → 首拉完成回调重试 三级递进——boot 期前两级被门禁挡下）
```

两个硬教训已固化进源码注释：

- 🔴 **读错通道事故**（:116-117）：recognition_mode 是**云端属性**（c_data），device-side 只承载回报的生效值——曾因读错通道导致配置变更完全无效（2026-09-09 zerus 实测）；
- **ParseMode 任何非法都回退 kCloud**（:97-98）：端侧识别是"需要明确开启"的能力，不确定就落安全的云端识别。

## 五、观察点

1. **跨层依赖**：device.cpp include `service/paas_shadow/*` 与 `service/download_service.h`，palm_behavior.h include `biz/comm/palm_flow/...`——L1 模块反向依赖 service/biz 层，与《01.总览与分层架构.md》"facility 不依赖业务层"的原则有出入（时序靠 PaasShadow 信号机制解耦，但编译期依赖已形成）；
2. **SN 读失败仅 LOG_E 不阻断**（device.cpp:107-108）：`device_sn_` 为空会连锁影响 Config 加密口令、激活、上报——init 契约上 SN 是硬前置，值得升级为 fail-fast 或至少状态暴露；
3. PalmBehavior 三把细粒度锁（config_/local_settings_/flow_dwell_）+ GetConfig 返回拷贝快照——设计干净；但 `BuildPalmBehaviorConfigBase64` 是 static 且跨锁拼装，存在"拼装期间配置被改"窗口，快照语义靠调用方会话开始时捕获兜底；
4. RecognitionModeConfig 是"重启生效型配置"的范本（幂等+确认+冷却+熔断+回报五件套）——若未来出现第二个此类配置，建议抽通用骨架而不是再抄一份四道防护。
