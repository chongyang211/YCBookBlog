# 刷掌事件（palm.*）上报全流程

## 总览

```text
PalmFlow 状态机各状态 / PalmSessionController（打点采集，写 FlowContext）
        │ 收敛桥（Finish 子状态）决策分支调用
        ▼
PalmActionEmitters（5 个发射函数，防重 + 从 ctx 组装事件字段）
        │ PalmActionEventParams
        ▼
PalmActionEventReporter::Emit（协议装配唯一汇合点）
        │ Commit → to_json
        ▼
ReportTo(25261) → ReportQueue 持久化队列（/userdata/.palmos/report/）
        │ ReportLogs 定时批量出队
        ▼
PalmAppReportLogsBuilder（OTLP LogRecord 装配，scope=25261）
        │
        ▼ HTTP 上送 → 平台按 attributes.action 路由
```

每会话 1~4 条业务事件 + 1 条会话终态聚合（`palm.session.end`）。

## 一、状态机内的采集与汇流（FlowContext）

### 1.1 角色分工（flow_context.h）

`FlowContext` 是会话级数据载体，也是上报字段唯一的采集汇流点：

- **Strategy** 只读 ctx（决策不落字段）；
- **Controller** 在状态 enter/exit 与事件处理时**写** ctx（打点采集的主体）；
- **Stopping** 转入前已被上一个状态写好，自身不修改；
- **Finish 收敛桥 / 发射函数** 收敛时**读** ctx 组装事件。

### 1.2 会话不变量（`machine_->Reset(profile)` 时固化）

| 字段 | 说明 |
|---|---|
| `session_id` | 一次刷掌会话一个 id，全部事件同值，平台聚合键 |
| `trace_id` | 32 hex 会话级跨端链路标识，后端由它生成 LogRecord.traceId |
| `profile` / `start_time` | 工作模式等会话配置 / 会话起点（`client_event_cost` 基准） |
| `start_source` | kRunOnStart 唯一入口写一次：`"host"`（上位机 StartPalm）/ `"palm"`（掌唤自启），后续不再覆盖 |

### 1.3 打点采集表（写入者 → 消费字段）

上报字段不"现算"，而是状态机各环节**打点写入 ctx**，发射时统一读取：

| ctx 字段 | 写入者 / 时机 | 消费点（上报字段） |
|---|---|---|
| `opt_pass_time` | `OptPassed::enter`（优选通过） | recognition 的 `detect_duration_ms`（与 start_time 差值） |
| `opt_live_duration_ms` / `opt_frame_image_id` | palm_core 信号经 `PalmReportEventSig` 封送主线程后写入 | `opt_live_duration_ms` / `opt_frame_image_id` |
| `recognition_route` | `LocalRecognizingState.enter`→kLocal；`RecognizingState.enter`→kCloud；离线优选 fake success 由 Controller 手动置 kLocal | recognition 的 `route` |
| `last_rec_resp` / `last_local_identify_result` / `last_register_resp` | 各识别/注册响应 react 写入（含 `server_code`） | `result_code`、`server_response_code` |
| `traceparent` | 云端业务响应（IoTResponse::traceparent）经响应事件透传写入；local/无 HTTP 场景为空 | attribute `traceparent` 原文 + LogRecord span 段 |
| `last_http_cost_ms` | 识别/注册探测/身份码注册响应时更新（verify-palm、bind-palm 不更新，由 submit_ms 承载） | enrollment/verification 的 `server_event_cost` |
| `verify_wait_enter_ts` | `Verifying` enter（重试轮覆盖写） | verification 的 `wait_ms` |
| `verify_submit_enter_ts` | verify-palm 请求发出时 | verification 的 `submit_ms` |
| `enroll_wait_enter_ts` | `WaitingBindInput`/`WaitingScanInput` enter 首入写一次（重试往返不重置） | binding/enrollment 的 `wait_ms` |
| `bind_submit_enter_ts` | `ConsumeAction(kProcessBindPalm)`（BindPalm 发出前） | binding 的 `submit_ms` |
| `cpm_retry_count` | WaitingScanInput / RegisterByCodeSubmitting 可重试失败自增（162/163 轮） | enrollment 的 `retry_count` |
| `verify_retry_count` | `V_RetryVerify` 自增（100038 轮，Strategy 判上限） | verification 的 `retry_count` |
| `exit_code` / `server_code` / `completion_source` | 各收敛点 react / Finish 写入 | `result_code`、`end_state` 判定 |
| `event_actions_log` / `last_action_route` | `MarkEmitted`（每 emit 一条业务事件 push） | session.end 的 `event_actions` / `end_action` / `route` |

**采集原则**：

1. 打点只写时间戳与标记，耗时在发射时统一计算（`now - enter_ts`），避免状态机内散落计时逻辑；
2. 重试轮**覆盖写**等待/提交起点（加验）或**保持首入**（录掌等待窗口），口径在字段注释中约定；
3. 路由类信息（cloud/local）在状态进入时分叉点写入，收敛处不做二次推断。

## 二、发射调用点（收敛桥）

| 发射函数 | 调用位置 | 覆盖场景 |
|---|---|---|
| `EmitRecognitionResult` | `RecognitionFinishState.update`（palm_flow_states.cpp:1063）+ Controller 两处例外（hybrid `V_RetryDetect` / 离线优选 fake success，palm_session_controller.cpp:1211） | 云端识别成败 / 端侧识别与 164 超时 / 离线优选短路 |
| `EmitBindingResult` | `EnrollmentFinishState.update`（:1078，按 `enroll_wait==kBindInput` 分派） | /bind-palm 成功 / 116 掌库满 / 124 等待超时 |
| `EmitEnrollmentResult` | `EnrollmentFinishState.update`（:1093，else 分支） | CPM 反扫码（161 超时）/ HOST 探测注册轮（141 超时 / V_Complete） |
| `EmitVerificationResult` | `VerificationFinishState.update`（:1103）统一收口 | 加验成功 / 129 等待超时 / 上位机拒绝 / submit 超时 |
| `EmitSessionEnd` | Controller 订阅 `PalmFlowChange`，`ev.to==kStopping` 时（palm_session_controller.cpp:518），`last_state=FlowStateName(ev.from)` | 每会话恒 1 条；`end_state`：abort（用户取消/超时中断）优先于 exit_code 推导的 success/fail |

防重与留痕（`ShouldEmit` / `MarkEmitted`）细节见下节。

## 三、事件族（5 个 action，report_actions.h）

| action | 触发点 | 特有字段 |
|---|---|---|
| `palm.recognition.result` | 识别收敛（含离线优选短路、hybrid 未注册分支） | `detect_duration_ms`、`route`（cloud/local） |
| `palm.enrollment.result` | 录掌收敛（HOST 探测 / CPM 扫码 / 注册轮） | `retry_count`（CPM 162/163 轮）、`server_response_code` |
| `palm.binding.result` | HOST 绑定收敛（成功 / 124 超时 / 116 非重试失败） | `wait_ms`、`submit_ms`（BindPalm 往返） |
| `palm.verification.result` | 加验收敛（129 超时 / 拒绝 / V_Complete 统一收口） | `retry_count`（100038 轮）、`wait_ms`、`submit_ms` |
| `palm.session.end` | 每会话恒 1 条（kStopping） | `end_state`(success/fail/abort)、`end_action`、`event_actions`（轨迹 join）、`last_state` |

## 四、发射层：防重与组装（palm_action_emitters.cpp）

1. **防重**：`ShouldEmit` 查会话"签到表"——每棵 Finish 子树只有一个收敛桥，结构上保证单事件只发一次；**例外**：`session.end` 不走防重（abort 会话恰恰靠它标记 `end_state="abort"`）；
2. **组装**：各 Emit 函数从 ctx 读打点装 `action_type`（recognize/enroll/verify/bind）、`route`（cloud/local）、耗时切片（`detect/wait/submit_ms` = now − 对应 enter_ts）、`server_response_code`（云端响应业务码，与模组码分离）；
3. **留痕**：`MarkEmitted` 写签到表（push `event_actions_log`、更新 `last_action_route`）——同时供防重和 `session.end` 的轨迹汇总。

## 五、协议装配（`PalmActionEventReporter::Emit`，palm_action_event_reporter.cpp）

**必装基线（每条事件）**：

| 字段 | 来源 | 用途 |
|---|---|---|
| `action` | 入参 | 事件类型，平台路由键 |
| `session_id` / `client_trace_id` | `FlowContext` | 会话聚合 / 后端 traceId 生成 |
| `work_mode` | `profile.palm_mode` 枚举→串 | recognition/enrollment_host/hybrid/enrollment_cpm |
| `result_code` | 各发射点（exit_code 或 server_code） | 业务结果，0=成功 |
| `opt_frame_image_id` / `opt_live_duration_ms` | ctx | 空串=未命中优选帧（合法值） |
| `client_event_cost` | `now - ctx.start_time` | 会话起点→本事件耗时 |
| `happen_time` | 墙钟 ms | Builder 覆写 `timeUnixNano`，消除断网重试时间偏移 |

**条件字段**（`optional` 未赋值 → to_json 不写键，自然裁剪）：`start_source`、`action_type`、`route`、各耗时、`retry_count`、`traceparent`（云端响应带回的 W3C 原文，反查后端链路；local 场景为空不装）、`server_response_code`。

**session.end 专属**：`end_state` / `end_action` / `event_actions` / `last_state`。

**留痕与容错**：装配完成后打印完整协议 JSON（当前 LOG_I，TODO 正式版降级/注释）；`Commit` 全程 try/catch，上报异常不影响刷掌业务。

## 六、传输管道（Commit 之后）

```text
Commit()（report_item_base.ipp）
  → FillInContext（公共上下文：SN、版本等）
  → Post 到 HeartBeatThread（业务线程立即返回）
      → FillBeforeQueue + to_json（strip null）
      → ReportService::ReportTo(25261, json) 入队
ReportQueue（mmap 持久化，/userdata/.palmos/report/palmapp_25261）
  → 断网/重启后自动补发，不丢不重
ReportLogs() 定时批量出队
  → 按 t_id==25261 分派 PalmAppReportLogsBuilder
      → Resource：device_sn / os_type / device_model / app_version / os_version / se_firmware_version
      → Scope：name="25261"（数字 scope，后端路由键）
      → LogRecord：timeUnixNano=happen_time 覆写、severity、attributes=事件字段
                  traceparent → trace_id/span_id（反解 span 段，非法则降级留空）
  → OTLP JSON HTTP 上送 → 平台按 attributes.action 分发到对应事件表
```

## 七、端到端时序示例（云端识别+加验会话）

```text
会话启动(StartPalm, start_source="host")
  │ Reset: session_id/trace_id/start_time 固化
  ├─ OptPassed.enter 打点 opt_pass_time ──→ palm.recognition.result (route=cloud, detect_ms)
  ├─ Verifying.enter 打点 verify_wait_enter_ts（100038 轮 → verify_retry_count++，覆盖写）
  ├─ 加验收敛 ──────────────────────────→ palm.verification.result (submit_ms, server_response_code)
  └─ kStopping ────────────────────────→ palm.session.end (end_state, event_actions="recognition,verification", last_state)
```

每条独立入队、独立补发；平台侧用 `session_id` 聚回一次完整会话。
