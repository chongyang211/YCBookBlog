## 一次刷掌会话的完整代码流转

### 第 0 步：启动（进程生命周期只做一次）

```
BootStrapper::Run()
  └─ PalmSessionController::Instance()->Run()
       ├─ 注册 IGracefulExit 给 DeviceFsm（打断接口）
       ├─ 订阅 DeviceStateChange / PalmBehavior 信号
       └─ CoSpawn RunForever()          ← 常驻协程，挂起等待
```

### 第 1 步：等设备进入刷掌态 → 起调度循环

```cpp
// RunForever (controller:614)
co_await (WaitState(kPalmRunning) || WaitState(kDebugTesting));  // 竞速等待
co_await ScheduleLoop();
```

`ScheduleLoop`（:636）在设备态持续期间循环跑轮，每轮完成且 `Done` 后 break 退出，交还 RunForever 重新同步。

### 第 2 步：开一轮 — `RunOneRound(palm_mode)`（:665）

触发源任一：上位机 0x04 `RequestStart`、掌唤 `ScheduleAutoStart`、自检 `StartPalmTest`。一轮开始：

```cpp
strategy_ = MakePalmFlowStrategy(palm_mode);        // ① 每轮新建 Strategy
profile = strategy_->GetProfile();                  // ② 取模式配置
// ③ 从 PalmBehavior 快照超时/重试参数 + 预取 hybrid_enroll_method
machine_->Reset(profile);                           // ④ 状态机重置→CreatedState
event_sig_proxy_(OnPalmSessionStartEvent{...});     // ⑤ 通知上位机会话启动
ConnectSdkSignals();                                // ⑥ 订阅 5 路 SDK 信号
machine_->React(StartReqEvent{});                   // ⑦ 状态机点火：Created→Starting
co_await DrainActionsUntilDone();                   // ⑧ 进入驱动循环（本轮心脏）
ResetRoundState();                                  // ⑨ 尾部清理
```

### 第 3 步：驱动循环 — `DrainActionsUntilDone`（:1907）

这是整轮的“心脏”，一个经典的**事件-动作泵**：

```cpp
while (true) {
  while (machine_->HasPendingActions())
    co_await ConsumeAction(machine_->PopAction());  // 排空工单队列
  if (machine_->IsActive<DoneState>()) break;       // 一轮结束
  co_await machine_->WaitWork();                    // 挂起，等 Wake()
}
```

### 第 4 步：一次典型识别的完整环（事件→Action→React）

以云识别为例，一次完整的“泵循环”：

```
① SDK 回调线程: OnOptLiveComplete(OptLiveComplete信号)
     → ConnectSdkSignals 的回调 Post 到主线程
     → machine_->React(OptPassEvent / PalmDataReadyEvent)   【同步执行】

② 主线程状态机内: OptPassedState::enter
     → StopCodeScan + ctx.request_action(kDecidePostOpt)     【入队工单】
     → DoRequestAction: actions_.push_back + Wake()          【唤醒泵】

③ Controller: ConsumeAction(kDecidePostOpt)
     → strategy_->DecidePostOpt(ctx) → V_Submit              【大脑决策】
     → machine_->React(VerdictPostOptEvent{V_Submit})

④ 状态机: DispatchPostOpt → changeTo<RecognizeEntry> → update → CloudRecognizing
     → enter: 数据齐备则 request_action(kRecRequest) + arm_timer

⑤ Controller: ConsumeAction(kRecRequest)
     → epoch 校验（防串轮）→ HTTP POST /recognize（协程 await，不占主线程）
     → 服务端码映射 MapRecServerCodeToModule
     → machine_->React(RecResponseEvent{code, server_code, body})

⑥ 状态机: RecognizingState::react(RecResponseEvent) → 写 ctx.last_rec_resp
     → request_action(kDecidePostRec)

⑦ Controller: ConsumeAction(kDecidePostRec)
     → strategy_->DecidePostRec(ctx) → V_Complete
     → React(VerdictPostRecEvent) → DispatchPostRec
       → 写 ctx.exit_code/completion_source → changeTo<ResultObtained>

⑧ ResultObtained::update: 按 completion_source emit OnPalmResultEvent
     → event_sig_ → PosNotifier 发 0xA3 给上位机
     → changeTo<Stopping>

⑨ Stopping::enter: request_action(kRunOnStop)
     → ConsumeAction: StopPalmDetect + StopCodeScan
     → emit OnSessionCompleteEvent
⑩ Controller::OnFlowEvent 收到 Complete 事件:
     → 3s 结果灯窗口 RequestExitTo(ShowingResult*)
     → StopOkEvent → Done → DrainActionsUntilDone 跳出 → ResetRoundState
     → 设备态回 Idle，ScheduleLoop break
```

### 并行发生的事

- **SDK 信号持续注入**：检测期间 `PalmEnteredEvent`、扫码 `ScanCompleteEvent` 等随时 `React` 进来，状态机同步处理；
- **超时**：等待态的 timer 到点 → `DoArmStateTimer` 回调校验 token → `React(StateTimeoutEvent)` → 状态收敛退出；
- **外部打断**：上位机 0x05 或设备切换 → `RequestExit()` → React `StopReqEvent` → RunningHead 统一拦截 → kAbort → Stopping。

### 本质

整个会话就是**主线程上的一个协程**（`DrainActionsUntilDone`）反复执行“`React(事件)` 同步推进状态图 → 取出 `Action` → 异步干 IO → 结果再 `React`”这个循环，直到状态图到达 `Done`。状态机每次 React 在调用栈内瞬间完成（无锁单线程），耗时操作全部落在 Action 消费里 await。
