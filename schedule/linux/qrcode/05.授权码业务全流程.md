
## 一、码格式与两种类型

`QrLicenseDecoder` 解码（base64 + 解密 + JSON），分两类：

| 类型 | 内容 | 处理方式 |
|---|---|---|
| **kGenLic 生成型** | `lic_url` + `lic_appid` + `lic_secret_key` | `yt_auth_init_online_with_cache_ex` 联网向授权服务生成 license 并落盘 |
| **kFeedLic 喂入型** | `license` 字段（完整 license 串） | `yt_auth_init_by_string` 本地校验直接入库 |

## 二、授权状态机（AuthState，LicenseManager 持有）

```
Init：加载本地 license（yt_auth_init_by_path）
  → kChecking（等 NTP 时间可信，防 1970 误判过期）
      │ 时间可信事件 time_trusted_conn_ → LoadAndCheckLicense
      ▼
  kAuthorized ◄────────────────┐
      │ 过期（CheckAuthLocal 定时复核）      │ 扫新授权码成功
      ▼                        │
  kUnauthorized ──┐            │
  kExpired ───────┤ OnEnter 开扫码  │
  kError ─────────┘    │
        ▼              │
  kLicenseAuthorizing（保护态，扫码授权进行中）
        │
        ├─ 成功 → kAuthorized
        └─ 失败 → 回来源态（Unauthorized 继续扫 / Refreshing 保留旧 license 继续扫）
```

**谁触发开扫码**（`kScanLicense` 消费者）：
1. `kLicenseUnauthorized` 设备态 OnEnter（未授权/过期/出错时自动等码）
2. `kLicenseRefreshing` 设备态 OnEnter（已授权想换新码，旧 license 仍有效）
3. POS 0x10 指令 `EnterAuthorizeFlow`（按 AuthState 自动选目标态）

## 三、全流程（一个授权码从扫到生效）

```
扫码 → PalmCoreManager::OnCodeScanResult（明文日志）
  │
  ▼ TryHandleScanCode（license_manager.cpp:299）
  ├─ 仅 kLicenseUnauthorized / kLicenseRefreshing 设备态响应（其余放行走业务码）
  ├─ IsLikelyLicenseQrCode 轻量预检（长度+字符集，完整校验留到 DoAuthorize）
  ▼
  AuthorizeFromQRCode：状态互斥（kChecking/kAuthorizing 拒绝）+ in_authorizing_ 原子防重入
  │ → LicenseThread 异步（与激活流程同线程串行，天然互斥）
  ▼
  DoAuthorize（license_manager.cpp:343）
  ├─ ① SetAuthState(kAuthorizing) + RequestEnterWithRetry(kLicenseAuthorizing)
  ├─ ② QrLicenseDecoder::Decode（base64+解密+JSON；失败 → 40904）
  ├─ ③ 有效期校验：
  │     时间未同步 → 40907 TIME_UNTRUSTED（防 1970 误判）★
  │     超出 start/end 窗口 → 40910 QR_EXPIRED
  ├─ ④ 按类型执行（见上表：kGenLic 联网生成 / kFeedLic 本地校验入库）
  │     yt 校验失败映射 40901/40902/40905/40909(SN不匹配)/40913(服务端拒绝)/40914/40915(设备数超限)
  ▼
  ├─ 成功 → SucceedAuthorize：SetAuthState(kAuthorized) + sync() 强制刷盘
  │         （嵌入式 write-back cache，防掉电丢 license）+ PostExitToSteady + 发 0xB2
  └─ 失败 → FailAuthorize：SetAuthStateOnAuthFailure
            （Refreshing 来源保留 kAuthorized——旧 license 未被覆盖；
             其他来源设 kUnauthorized）+ 回退到来源设备态（继续等码）+ 发 0xB2
```

## 四、对外通知（双通道 + Shadow）

| 通道 | 内容 | 触发 |
|---|---|---|
| **0xB0** | 授权状态跃迁（`state_signal_` → PosNotifier） | 每次 SetAuthState |
| **0xB2** | 授权动作结果（`auth_result_signal_`，成功/失败+错误码+摘要） | 每次授权动作收口 |
| **Shadow** | `module_auth` 属性（带去重缓存；`ForceReportShadow` 跳过去重兜底） | 状态变化 |

## 五、关键设计点

| 设计 | 说明 |
|---|---|
| **时间可信是前置条件** | 授权全程依赖系统时间（有效期判断），NTP 未同步前拒绝授权（40907）；`kChecking` 阶段禁止 `RefreshAuthState` 复检——license 尚未 load，强行检查会得出伪“未授权”且状态机不可回退（头部注释重点强调） |
| **失败不破坏现状** | 换码失败（kFromRefreshing）保留旧 kAuthorized——旧 license 还在磁盘上没被覆盖，继续可用；这是“先校验后落盘”顺序的自然结果 |
| **`sync()` 强制刷盘** | 嵌入式 write-back cache 下 `Save` 后必须 `sync()`，否则掉电丢授权 |
| **与激活的关系** | 激活（404xx，写 SE 信任根）在前；License（409xx，业务授权）在后。`CanStartPalm()` 要求 `kAuthorized`；开机 Idle 仲裁链：已授权 → 查激活，未授权 → 停 `kLicenseUnauthorized` 等码 |
| **统一收敛入口** | 所有改变授权状态的事件（NTP/定时/前置校验/激活成功/保护态退出）必须走 `RefreshAuthState`（100ms 去抖），禁止绕过 |

## 六、日志锚点（排查用）

```
LicenseManager: license QR detected, entering authorization flow   ← 识别为授权码
LicenseManager: DoAuthorize, qr_len=, source=                      ← 进入授权流程（来源）
LicenseManager: QR expired / time not synced                       ← 有效期问题
LicenseManager: gen_lic, url=, appid=                              ← 生成型开始联网
LicenseManager: yt_auth_init_by_string failed, yt_ret=, mapped=    ← 喂入型校验失败
LicenseManager: load failed, ret=, unauthorized                    ← 开机加载失败
LicenseManager: no valid license / CheckAuthLocal                  ← 状态复核
LicenseManager: OnEnterLicenseUnauthorized, start authorize scan   ← 开扫码等码
```

**一句话总结**：授权码是设备业务能力的“驾驶证”——未授权/过期时自动开扫码等码，扫码后走“解码 → 时间窗校验 → yt 授权库校验 → 落盘 sync”，成功发 0xB0/0xB2 + Shadow，失败按来源回退（换码失败不伤旧证），全程以时间可信为前置。与激活码的分岔点同样在 `OnCodeScanResult` 分发链，互斥条件是设备态（`kLicenseUnauthorized/Refreshing` vs `WaitingForQRCode`）。
