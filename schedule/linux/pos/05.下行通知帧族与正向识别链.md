# Pos · 05 下行通知帧族与正向识别链

> 系列第五篇，承接《02》《04》。下行方向：FSM/业务事件 → PosRequestHandler 组帧 → transferer 发送。覆盖通知帧族逐个（发送时机 + 关键字段）与正向识别端到端串联（含 0xA3 字段展开、need_host_ack 判定）。

## 一、下行帧族总表

| 帧 | 指令常量 | 发送时机（触发源） | 发送 API 形态 |
|---|---|---|---|
| 0xA1 检测中 | Recognizing | 会话启动（OnStart） | Send |
| 0xA3 识别/绑定/扫码结果 | RecognizeResult | FSM 收敛（识别/绑定/扫码三类共用同一 cmd_id，靠 recognize_type 区分） | Send（Request 型，等 ack） |
| 0xA5 优选图通知 | PalmStatus | 识别命中（OnPalmRecognized 前置） | Send |
| 0xAB 加验通知 | PalmVerifyNotify | Verifying.enter（等上位机 0x0D） | AsyncRequest 等 reply |
| 0xAC 绑定/扫码等待通知 | PalmBindInputNotify | WaitingBindInput / WaitingScanInput enter + 失败重试提示（162/163/10007 等） | Send |
| 0xA7 测速通知 | SpeedTestNotify | SpeedTestNotifier 等级穿越 | SendAndGetResponse（等 reply，131 降级） |
| 状态类 | PalmStatus / ModuleStateChange | FSM 状态广播经 PosNotifier 派发（SendStateChangeMsg :835） | Send |
| TTS | PlayTts | 播报请求（转发上位机发声） | Request 型（NeedHandleResponse 回灌 Resp） |
| 激活/升级状态 | ActivationStatusChange / UpgradeStatusChange | ActivationController / IotUpgradeSchd 回调转发 | Send |
| 授权族 | LicenseStateChange / LicenseAuthResult | LicenseManager 回调转发（story 136057693） | Send |
| 行为变更 | PalmBehaviorChange | PalmBehavior OnChanged 转发（:1258） | Send |

正向链三帧（0xA1 → 0xA5 → 0xA3）构成"检测中 → 优选命中 → 结果"时序；0xAB/0xAC 是会话中途的"等输入"通知。

## 二、0xA3 结果帧展开（:355-395）——下行帧的"全家桶"

```text
帧体 = PosAppRecognizeResultReq{
  ret_code:    模组结果码（uint32）
  session_id:  会话 ID
  result_data: base64(JSON) —— 业务字段统一封装，便于扩展
}
```

result_data JSON 字段（按 recognize_type 区分）：

| 字段 | recognize_type=0x01（识别/绑定收敛） | 0x02（扫码结果） |
|---|---|---|
| recognize_type | 0x01 | 0x02 |
| palm_state / session_key / otc / palm_id / user_id / card_number / user_name | ✓ | — |
| server_code | ✓ 后台原始码 | — |
| **need_host_ack** | ✓（story 135810205，决定上位机是否回 0x14） | — |
| palm_direction / can_enroll_another_palm | ✓ 双掌录入（story 135894232） | — |
| is_bind_palm | 收敛类型标识（绑定路径 =1，识别/扫码 =0） | =0 |
| scan_code | — | ✓ 扫码明文（日志含内容，xlog 加密存储，对账用） |

设计要点：**业务字段不进帧头、统一 base64(JSON) 进 result_data**（:366 注释"便于上位机扩展参数"）——新增字段不动协议结构。

## 三、need_host_ack 判定（story 135810205）

- 识别成功且 `result_action_mode == kHostAcknowledgement`（云端 palm_behavior 配置）→ need_host_ack=true → FSM 进 **WaitingHostAck**（等 0x14，3s 超时按 160 收敛）；
- 其余（设备自闭环模式）→ false → 直接 Stopping。
- 上位机回 0x14 仅被 WaitingHostAck 态接受（04 篇 2.1），错态回 HOST_ACK_TERMINATED。

## 四、正向识别端到端串联（识别成功 + HOST_ACK 模式示例）

```text
[上位机] 0x04 StartPalm
[模组]   Resp(0x04) + 0xA1 检测中
[模组]   SDK 检测 → 优选命中 → 0xA5 优选图通知
[模组]   /recognize HTTP → 收敛
[模组]   RecognitionFinish 发 palm.recognition.result（上报通道）
[模组]   OnPalmResult 组 0xA3{result_data: need_host_ack=true, srv=0,...}
[上位机] 0x14 HostResultAck
[模组]   FSM WaitingHostAck → HostAckResultEvent → Stopping → Done
[模组]   0xA3 变体（is_bind_palm=1）……（仅绑定路径）
```

旁路对照：识别 306 未注册 → 0xA3(306) 中途成绩单 + 0xAC 等待绑定通知（Hall 等待 40s）；CPM → 0xAC 等扫码（40s 窗）。

## 五、观察点

1. **0xA3 是三类收敛的共用 cmd_id**（recognize_type 0x01/0x02 + is_bind_palm 区分）——上位机解析必须先看 result_data 里的 recognize_type，帧头无区分；
2. `happen_time` 类元数据不上 wire（结果帧只含业务字段）；时序对账靠上位机收包时间 + 模组日志（xlog）；
3. OnScanCodeResult 的明文扫码内容进日志（:399-401 注释：对账关键点）——依赖 xlog 加密（facility/11 篇）兜底敏感性；
4. 0xA3 走 Send（分支 2，AsyncRequest 等 ack）——上位机离线时该发送会阻塞至超时才返回，发送侧全部 detached CoSpawn 不阻塞业务；
5. 下行帧族与上报事件（25261 通道）是**两套独立通道**：上位机收 0x 帧、后台收 OTLP——同一收敛双发，字段语义对齐但载体不同（排障时两边对照）。
