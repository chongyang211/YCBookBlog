# Pos · 06 跨语言通信与 SDK 架构

> 系列第六篇，承接《05.下行通知帧族与正向识别链》。视角切换到**上位机侧**：Android Demo 如何通过 PosLink SDK（Java + C++ 跨语言）与模组通信——覆盖四层架构、下行指令与上行事件的逐跳链路、Djinni 跨语言机制、新增指令的改动清单。

## 一、四层架构总览

```
palm_manager/android/demo              Demo 应用（Java）
    │  PalmManager.getInstance().startPalmEx(...) / setModuleEventListener(...)
    ▼
palm_manager/android/pos_link          PosLink Android SDK
  ├─ Java 编排层   PalmManager / ConnectionManager / ModuleController / PalmSession
  ├─ Djinni 生成层 com.tencent.wxpayface.pos_link.*（Client 接口、PosXxxReq/Resp 记录类、回调接口）
  └─ JNI/NDK 层    src/main/cpp：client_impl / server_impl + generated_jni/native_*（JNI 胶水）
        │  JNI（JNIEnv / support-lib/jni/djinni_support.cpp 运行时）
        ▼
pos_link/（C++ 协议核，与模组侧同源）
  帧封装/解析（0x7E 帧头尾 + 转义 + CRC32）、msg_id、请求超时重试
        │  串口（ClientConfig：serialPath + baudRate + flowControl）或 TCP
        ▼
刷掌模组（palm_app_linux：PosLinkServer → PosTransferer → FSM，见 01~05 篇）
```

**分层原则**：业务逻辑在 Java 层（编排/重连/缓存），协议字节在 C++ 层（pos_link 核）——跨语言边界只有"结构体字段"的 marshal/unmarshal，不涉及帧细节。

## 二、模块目录与职责

| 位置 | 所属层 | 内容 | 职责 |
|---|---|---|---|
| `demo/` | **Demo 应用层** | MainActivity、各 Fragment/Activity | 业务界面；仅调 PalmManager 公开 API，不感知协议 |
| `pos_link/src/main/java/com/tencent/palm/` | **SDK Java 编排层** | `PalmManager`（门单例，加载 `libpalm_manager`）、`internal/ModuleController`（设备控制指令编排 + 状态事件分发）、`ConnectionManager`（连接生命周期/重连）、`PalmSession`、`CallbackDispatcher`（线程切换） | 业务编排层 |
| `pos_link/src/main/java/com/tencent/wxpayface/pos_link/` | **Djinni 生成层（Java）** | **Djinni 生成的 Java**：`Client` 接口、`PosStartPalmExReq/PosBindPalmReq/PosRecognizeResultReq` 等记录类、`PosXxxCallback` 回调接口 | Java 侧看到的"协议对象" |
| `pos_link/src/main/cpp/` | **JNI/NDK 层（C++ 实现）** | `client_impl.cpp`（C++ 侧 Client 实现）、`server_impl.cpp`（处理模组发来的请求，如 0xAD BiComm——Android 侧此指令是**服务端**角色）、`bicomm_manager` | C++ 实现 |
| `pos_link/src/main/generated_jni/`（165 个文件） | **JNI/NDK 层（生成胶水）** | `native_client.cpp`、`native_pos_start_palm_ex_resp.cpp` 等 | 每个协议消息一对"Java ↔ C++"转换器（JNI glue） |
| `support-lib/jni/djinni_support.cpp` | **JNI/NDK 层（运行时）** | Djinni 运行时 | JNIEnv 管理、字符串/引用/异常转换公共基础 |
| `pos_link/`（仓库根，同源库） | **C++ 协议核层** | `pos_link_protocol.h`（帧格式）、`pos_link_app.h`（手写指令）、`generated/pos_app_commands.gen.h`（commands.yaml 生成） | 协议核——**与模组侧同源**，两侧协议永不错配的机制 |

## 三、下行指令链路（以 startPalmEx 为例，逐跳）

```text
① Demo
   PalmManager.getInstance().startPalmEx(offlinePreferred, scanMode)
② SDK Java 编排层
   组 PosStartPalmExReq（djinni 记录类：offline_preferred / scan_mode）
   → ConnectionManager → djinni Client 代理
③ JNI（generated_jni/native_client.cpp）
   Java 对象 marshal → C++ 结构体 → client_impl → pos_link 协议核封装成帧
   （0x7E 帧头 + msg_cmd=0x0E + 字段 + CRC32；msg_id 新分配，请求 5s 超时 3 次重试）
④ 串口 → 模组 PosLinkServer → PosTransferer → FSM（03 篇）
⑤ 模组回 Resp（同 cmd_id 0x0E，帧头 reply_msg_id 对应原请求）→ 原路返回
⑥ Java
   JNI unmarshal → PosStartPalmExResp（ret_code/session_id/palm_mode）
   → djinni 回调 → startPalmEx 的 callback 回到 Demo
```

## 四、上行事件链路（以 0xA3 识别结果为例，逐跳）

```text
模组 PosTransferer 发 0xA3 推送（post-rec 收敛，ret_code/session_id/result_data）
  → Android pos_link 协议核收帧解析（去转义/校验 CRC32）
  → client_impl.cpp 解析出 PosRecognizeResultReq
  → native_client_biz_listener（C++ 侧业务监听器，djinni 接口的 C++ 实现）
  → Djinni 反向回调（C++ 调 Java）
  → Java 层 CallbackDispatcher（切回调度线程）
  → ModuleEventListener / PalmBehaviorListener 等监听器
  → PalmManager 回调 → Demo
```

`ModuleController` 在链路中承担业务编排：设备控制指令（control/light/hostState/queryInfo）、模组 SN 缓存（连接成功后 refreshModuleSnAsync 查询写入）、状态事件按监听器分发。

## 五、跨语言机制：Djinni 代码生成器

**核心设计：手写 JNI 胶水被生成器替代。** 协议消息的跨语言转换全部由 Djinni 从接口定义生成，保证 Java/C++ 两侧签名与字段永不漂移。

| 组成 | 位置 | 作用 |
|---|---|---|
| Djinni 生成层 | `generated_jni/native_*.cpp/h`（165 个文件） | 每个协议消息一对转换器：Java 对象 → C++ 结构体（下行），C++ 结果 → Java 回调（上行） |
| Java 生成类 | `com.tencent.wxpayface.pos_link.*` | 记录类（Req/Resp）、回调接口、`Client`/`Server` 接口 |
| 运行时 | `support-lib/jni/djinni_support.cpp` | JNIEnv 附加/分离、std::string ↔ jstring、引用与异常转换 |
| C++ 实现 | `client_impl.cpp` / `server_impl.cpp` | 实现 djinni 生成的 C++ 接口，对接 pos_link 协议核 |

**线程模型**：C++ 收包在 pos_link 自有线程；Java 侧统一由 `CallbackDispatcher` 切回调度线程后再分发监听器——Demo 回调线程安全。

## 六、连接与传输配置

`ConnectionManager` 把 `PalmConfig` 翻译为 djinni `ClientConfig` 后建立连接：

```java
new ClientConfig(cfg.getTcpIp(), cfg.getTcpPort(),
                 cfg.getSerialPath(), cfg.getSerialBaudRate(), cfg.isSerialFlowControl(),
                 cfg.getLogPath(), ProtocolType.POS_PROTOCOL);
```

- **串口模式**：serialPath（如 /dev/ttyS*）+ baudRate + flowControl——物理层即 03 篇所述 RS232/UART
- **TCP 模式**：tcpIp/tcpPort（备选传输，协议核不感知差异）
- 连接断开由 ConnectionManager 负责重连调度（reconnect timeout/future 管理）

## 七、新增一条指令的改动清单（跨四层）

以"新增 0x16 某指令"为例，按依赖顺序：

1. `palm_manager/scripts/commands.yaml`：定义 cmd_id 与字段（**单一事实源**）
2. 重新生成：`pos_app_commands.gen.h`（C++ 结构体，两侧同源库共用）
3. `pos_link/`：如需手写补充（wire 细节），对齐 `pos_link_app.h` 模式
4. Android `generated_jni` / `wxpayface.pos_link`：Djinni 重新生成 Java 记录类与 JNI glue
5. `client_impl.cpp` / `server_impl.cpp`：接入收发实现
6. SDK Java 编排层：`ModuleController` / `PalmSession` 增加编排方法与监听器
7. `PalmManager`：按需暴露公开 API
8. 文档：`commands.yaml` 与协议文档（用户版）同步
