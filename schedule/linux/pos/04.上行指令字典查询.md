# Pos · 04 上行指令字典（host → 模组）

> 系列第四篇，承接《02.总览与架构.md》《03.传输层与帧协议.md》。覆盖 `PosRequestHandler::HandleRequest`（pos_request_handler.cpp:233-352）分发树：上位机每个 0x 指令的入口校验、处理动作与回包。收包路径与双 ACK 机制见《03》篇第三节。

## 一、分发骨架

```text
OnReceiveData（MainThread）→ HandleRequest(DataPackage)
  → 逐个 else-if 匹配 function_id（:239-317，20 个已知指令）
  → WireUnserialize<对应 Req> → HandleXxxRequest
  → 兜底（:335-350）：
      未知 Resp → 静默丢弃（避免反弹错误帧）
      未知 Req  → SendFrameError(kPosMsgProtocolVersionErr)——上位机据此提示"请更新模组"
```

两条横切规则：
- **0xAD 的 Resp 防御拦截**（:287-290）：BiComm 响应由 send_request_func_ 直通处理，误路由进 HandleRequest 时静默丢弃，避免 Resp 被当 Req 反序列化；
- **inspect 指令（9090-9095）已迁出**（:236-238）：厂测 FID 走 local_link p2p 通道（DeviceInspectController 自注册），HandleRequest 不再路由。

## 三、兜底与版本兼容

| 场景 | 行为 | 依据 |
|---|---|---|
| 未知 Req | SendFrameError(**kPosMsgProtocolVersionErr**)——上位机提示"请更新模组" | :341-349，protocol-command-level-compat-design.md §4.1 |
| 未知 Resp | 静默丢弃 | :336-339 |
| 老上位机收到新 Req | 帧层回错误码（各发送侧已处理 131/不支持降级，如 0xA7 连败停推） | 《06》篇 |

## 四、观察点

1. **分发树为 20+ 段 else-if 链**：新增指令加一个 else-if + 一个 Handle 函数；表驱动重构可选项（当前规模尚可维护）；
2. 前置校验不统一：0x0D/0xA6/0x14 有 FSM 态校验，0x04 依赖 DeviceFsm 门闸拒绝，查询类无校验——**新增"会话态敏感"指令时必须显式加 IsActive 校验**（参照 0x0D）；
3. function_id 是 int（DataPackage 历史结构），帧协议层是 uint16_t——兜底分支的显式窄化（:345-347）是既有约定，新增兜底路径沿用；
4. 指令常量全部定义在 pos_link 库（kPosApp*CmdId）——本层只拿枚举值，指令码语义变更需进 pos_link。
