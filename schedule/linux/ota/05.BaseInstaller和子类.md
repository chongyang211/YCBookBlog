`installer/` 目录是 OTA 的**安装执行层**——全流程图中【安装】环节 `DoInvokeUpgrade → installer->Install(...)` 的被调方。与 Upgrade 对象（描述层）配套：一个负责“我是谁”，一个负责“怎么把我装进去”。

## 结构：一个接口 + 三个执行器

```
BaseInstaller（抽象接口）
  ├─ Install(upgrade, package_path, mac, version) → 0 成功 / 错误码
  ├─ GetInstallTimeout()                          // 供 DoInvokeUpgrade 的 future.wait_for 超时保护（30508）
  └─ WriteOtaPending(type, version, package_path) // ★ 自愈锚点（protected，各子类复用）
```

| Installer | 超时 | 安装方式 | mac 参数 |
|---|---|---|---|
| `AppInstaller` | **1min** | `opkg install --force-reinstall --force-downgrade`（system 调用，日志入 app_upgrade.log） | 忽略 |
| `RomInstaller` | **10min** | `SystemInterface::UpgradeSystem(path, version, mac)`——协程桥接 promise/future | 透传（ROM 二次校验） |
| `SeFirmwareInstaller` | **2min** | `se_api::UpdateKernel(zip)`——SE OTA SDK | 忽略 |

## 三个关键机制

**1. `WriteOtaPending` 自愈锚点（App/Rom 装前必写）**

安装前先把 `<type>|<version>|<package_path>` 持久化到 `/data/palmapp/guard/ota_pending`：
- 装完 palmapp 正常起来 → 锚点清除
- **装完起不来** → guard.sh 恢复分支读到锚点，派发 `retry_ota`（重试）或连续失败 `factory_reset`（恢复出厂）——这就是“装砖了能自愈”的机制（错误码 50801 OTA_CRASH）

**2. App：opkg 双 force 参数 + 环境变量钩子**

`--force-reinstall --force-downgrade`（允许重装和降级）；若 `ShouldKeepClosedDuringInstall()`（BaseUpgrade 的钩子）为真，前置 `APP_POST_INSTALL_NO_RESTART=true` 让 opkg 装完不自动拉起应用。

**3. SE：三种包来源 + 内置包保护**

`Install` 本身只有一件事——`UpdateKernel`，但外围有两个易踩坑的处理：
- **chdir("/tmp")**：SE SDK 在 cwd 下建临时目录，而 cwd 通常是不可写的 `/`
- **SDK 会删除输入 zip**：内置 `res/se` 出厂包必须跨重启存活，所以 `CheckAndUpgrade()` 先复制到 scratch 目录（`/data/palmapp/ota/se_firmware_input`）再把副本交给 Install；OTA 下载包和测试包则是一次性的，直接消费

## 一个特殊旁路：`CheckAndUpgrade()`（SE 离线升级）

`SeFirmwareInstaller` 还有一个**不走 OTA 主链路**的静态方法（开机引导时调用）：

```
DetectFirmware：扫包（ZY-{chip}-{version}.zip，取最高版本）
  优先级：测试后门 /data/palmapp/test/se > 内置 res/se
CheckAndHandleDowngrade：当前 COS < 1.0.0 → CustomReset 重置 + 清数据目录（保留日志）
CompareVersion：内置包更新才升级
  成功 → 删测试包 / Se DeInit / RebootSync
```

用途：随固件包发布内置 SE 固件（“出厂即最新”），与云端 OTA 下载链路独立；也服务于产线测试（测试包升级后自动删除防重复触发）。

## 在 OTA 全流程中的位置

```
【安装】InstallAllTasks（OtaInstallThread）
  └─ 逐任务 DoInvokeUpgrade
       ├─ GetInstaller(type)          ← 按 UpgradeType 分发到三个 installer
       ├─ 埋点 kOtaPerformUpgrade
       ├─ installer->Install(...)     ← ★ 本目录：真正的安装动作
       └─ future.wait_for(GetInstallTimeout())  ← 超时 → 30508
```

**一句话总结**：`installer/` = OTA 的“安装手”——三个组件（App/ROM/SE）各自的安装方式封装（opkg / 系统升级 / SE OTA SDK），统一在 `Install` 接口后面，带各自的超时预算；装前写 `ota_pending` 锚点接通 guard 自愈闭环。与 Upgrade 对象是“身份”与“执行”的分离：调度器只管配对调用，换安装方式只需换 installer。
