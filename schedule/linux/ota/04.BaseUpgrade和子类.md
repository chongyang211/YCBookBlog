BaseUpgrade和子类是 OTA 的**升级对象描述层**——回答“要升级谁、现在什么版本”的问题。它们是 `upgrade_schd` 里 `upgrades_` 数组的成员，本身**不含下载和安装逻辑**（那是 DownloadService 和 Installer 的职责），是纯粹的“身份+版本”描述符。

## 结构：一个基类 + 三个子类

| 类 | GetAppId | GetVersion（实时查询） | 对应 OTA 升级对象 |
|---|---|---|---|
| `BaseUpgrade`（抽象基类） | — | 纯虚 | 可升级对象的公共契约 |
| `PalmAppUpgrade` | `Application::GetAppid()` | 应用版本号 | **刷掌应用自升级**（opkg） |
| `RomUpgrade` | `"rom"` | `Device::GetFullRomVersion()` | **系统 ROM 升级**（model 取 `ro.build.rom.model` = "O4_palmapp_pos"） |
| `SeFirmwareUpgrade` | `"se"` | `SeKeyStore::GetSeCosVersion()` | **SE 固件升级**（package "ZY"/sign "S3"，版本来自 SE 芯片 COS） |

`BaseUpgrade` 持有的字段就是后台 OTA 任务的“应用身份”：

| 字段 | 用途 |
|---|---|
| `appid` | 本地唯一键（**重启后 session 恢复靠它找回模块**，注释强调必须非空唯一） |
| `app_package_name` / `app_sign` / `sub_app_scene` | 注册参数（向后台换取身份） |
| `sub_appid` / `plat_application_id` | 注册成功后由后台下发，之后与后台任务的关联键 |
| `GetDownloadFolder()` = `ota/<sub_folder>` | **每类升级独立的下载目录**（互不干扰） |
| `ShouldKeepClosedDuringInstall` / `Shutdown` / `Startup` | 安装期间的生命周期钩子（当前基类默认空实现，预留） |

## 在 OTA 全流程中的位置（每一步都在用它）

```
① 注册     QueryRegistration：用 package_name + signature + sub_app_scene
            向后台查询 → 换回 sub_appid + plat_application_id（写回对象）
② 任务查询  QueryUpgrade：收集 GetVersion() + plat_application_id → batch-query
③ 过滤     FilterUpgradeTasks：CompareVersion(GetVersion(), 目标版本)
④ 下载     GetDownloadFolder()：每类独立目录
⑤ 安装     DoInvokeUpgrade(upgrade, ...)：对象作为参数传给 installer
⑥ 重启闭环  ExecuteUpgradePostLogic：GetVersion()（重启后的新版本）
            == target_version → Succ(3)
```

## 两个关键设计

**1. 描述与执行分离**

```
BaseUpgrade（描述符："我是谁、我什么版本"）     ← 本组文件
BaseInstaller（执行器："怎么把我装进去"）       ← installer/ 目录
IotUpgradeSchd（编排器：把两者配对驱动）        ← upgrade_schd
```

升级一个新组件 = 加一对 Upgrade + Installer，编排逻辑零改动。

**2. `GetVersion()` 是活查询而非缓存值**——每次调用实时读当前版本（App 读运行时版本、ROM 读系统属性、SE 读芯片 COS 版本）。这正是**重启闭环**的基石：

```
重启前：target_version 记入 session（MMKV）
重启后：ExecuteUpgradePostLogic 调 GetVersion()
        安装成功 → 版本已变成 target → Succ(3)
        安装失败 → 版本没变 → Fail(4)
```

如果 version 是安装时缓存的静态值，这个比对就失去意义了。

**一句话总结**：这组文件 = OTA 的“升级对象名册”——App/ROM/SE 三个可升级组件的身份档案（appid、包名签名、实时版本查询、独立下载目录），供调度器完成注册、查版本、过滤、目录隔离和重启后终态比对；“怎么下”和“怎么装”分别在 DownloadService 和 Installer 里。
