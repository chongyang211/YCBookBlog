
**OTA 的总调度器/编排器**——OTA 全流程的“大脑”。它自己不下载、不安装，负责把触发、决策、下载、安装、恢复这些环节串成闭环。

## 它在 OTA 里扮演的角色

```
后台 OTA 平台 ──下发任务──► IotUpgradeSchd（编排器）──调度──► 各执行部件
                                │
   "何时升级、升不升、升哪个、   │     "怎么下载"→ DownloadService（外部模块）
    现在到哪一步、结果如何上报"  │     "怎么安装"→ 3 个 Installer（App/Rom/SE）
                                │     "怎么恢复"→ guard.sh + MMKV session
```

## 全流程调用链

```
【初始化】Init → (IotThread) SetupUpgrades
    ├─ AddUpgradeObjects：App/Rom/SE 三模块注册
    ├─ CheckPendingUpgradeSession：MMKV 读 session → ExecuteUpgradePostLogic（重启闭环，见下）
    ├─ InitInstallers：App/Rom/SE 三 installer 工厂
    └─ StartSchedule：注册轮询任务（requires_time_synced）+ MQTT DOWN_OTA handler + 连接信号

【触发】三源汇入 ExecuteUpgradeQuery（池线程）
    ├─ 轮询：MQTT 已连 5min / 断开 1min / 查询失败 10min 退避（requires_time_synced）
    ├─ MQTT 秒推：HandleOtaPushMessage 解析 OtaLinkMsg（完整任务体，免一次 HTTP；失败走轮询兜底）
    └─ 连接恢复：主动补查一次
    ├─ CheckAndHandleUpgradeTimeout：整体 >1h → Fail(4)+30515 → FinishUpgrade
    ├─ LockBusy（CAS 互斥，升级中直接 skip）
    ├─ QueryUpgrade → BatchQueryUpgradeDetail（HTTP batch-query；pushed 非空时跳过）
    └─ FilterUpgradeTasks：映射表查模块（无 → 丢弃）
        → 同版本 Succ(3) / 降级 Fail(4)+30519 → 同 appid 取最高
        → 分桶选优先级 SE > ROM > APP（空 → UnlockBusy → return）

【下载】DownloadAllTasks → 逐任务 DownloadTask（池线程）
    ├─ 埋点 kOtaStartDownload + ReportUpgradeStatus(Downloading(6))
    ├─ DownloadService::Download：缓存复用 / .crdownload 续传(Range 探测)
    │   / 限速 1MB/s / 15min 超时 / 低速熔断 1KB/s@30s / CheckMac 失败 30503
    ├─ 失败 → kOtaDownloadFail(原始细码) + PosLink Failed
    │         + Fail(4) 三码分流（30503 MD5 / 30510 超时 / 30502 其他）
    ├─ 成功 → kOtaDownloadSuccess（含 timecost）
    └─ 全失败或超时 → FinishUpgrade（单任务失败不中断批次，等下轮查询重试）

【关卡】MainThread 协程
    ├─ advice_gate_.HandleAdviceGate：ADVICE 问上位机
    │   （Approve/老上位机 131 保留；Reject/Timeout/无链路/冷却剔除；FORCE/ATONCE 直过）
    └─ 剔完为空 → FinishUpgrade
    ├─ RequestEnter(kUpgrading) 被拒（OTA/自愈占用等）→ FinishUpgrade
    └─ NotifyModuleState(true) → OtaInstallThread

【安装】InstallAllTasks（OtaInstallThread）
    ├─ session_info 写 MMKV（重启后恢复的依据）
    └─ 逐任务：
        ├─ curr_install_task_ 快照(+pre_install_version) + PosLink Installing
        ├─ ReportUpgradeStatus(Installing(7))
        ├─ DoInvokeUpgrade → installer->Install（独立线程 + future 超时 30508）
        │   AppInstaller(opkg+ota_pending 自愈锚点) / RomInstaller / SeFirmwareInstaller(SE 副本)
        ├─ 失败 → PosLink Failed + Fail(4) + 30508/30511/30512
        └─ 成功 → 仅置位不上报——install 返回 0 ≠ 真成功
    └─ Rebooting 通知 → RebootSync 重启

【重启闭环】重启 → SetupUpgrades → CheckPendingUpgradeSession（IotThread）
    └─ ExecuteUpgradePostLogic：FindUpgradeByAppId
        GetVersion()（重启后真实版本）== target_version？
          → Succ(3) / Fail(4)（ReliableRequest 必达）+ PosLink 通知（notified 去重，只弹一次框）
        网络类失败 → 保留 session 重试；全部消化 → 清 session

【收尾】FinishUpgrade：LOG 耗时 → 复位 curr_install_task_/installing_
    → UnlockBusy → NotifyModuleState(false)（回归空闲）

状态上报唯一出口：ReportUpgradeStatus → ReliableRequest::Submit
（request_id 四段幂等 task_uid_appid_status_error_code；Succ/Fail critical 必达）
错误码位置：下载 30503/30510/30502（DownloadTask）｜安装 30508/30511/30512
          ｜超时 30515（>1h）｜拒绝 30519（FilterUpgradeTasks）
```

## 职责 ↔ OTA 概念映射表

| OTA 概念 | 对应代码 | 作用 |
|---|---|---|
| **任务获取**（轮询/秒推） | `StartSchedule` / `HandleOtaPushMessage` / `OnMqttConnectionChanged` / `TryTriggerUpgradeQuery` | 三种触发源汇入 `ExecuteUpgradeQuery`；调频（5min/1min/10min） |
| **任务匹配** | `CheckAndQueryRegistrations` / `application_id_map_` / `FindUpgradeByApplicationId` | 后台 `application_id` ↔ 本地升级模块的映射表 |
| **升级决策** | `FilterUpgradeTasks` | 同版本成功/降级拒绝（30519）/去重/优先级 SE>ROM>APP |
| **下载编排** | `DownloadAllTasks` / `DownloadTask` | 逐任务下载 + FR-1/FR-2 分阶段上报 + MD5 校验 + 错误码分流 |
| **建议升级关卡** | `advice_gate_`（`UpgradeGateHandler`）+ `SetAdviceGate` | ADVICE 模式询问上位机、冷却窗 |
| **安装编排** | `InstallAllTasks` / `DoInvokeUpgrade` / `GetInstaller` | 逐任务调 installer（future 超时保护）+ FR-3/FR-5 上报 + session 落盘 |
| **重启闭环** | `CheckPendingUpgradeSession` / `ExecuteUpgradePostLogic` | 重启后版本比对 → Succ(3)/Fail(4)，notified 去重 |
| **整体超时** | `kOverallUpgradeTimeout`(1h) / `IsUpgradeTimeout` / `CheckAndHandleUpgradeTimeout` | FR-6: 30515 |
| **互斥** | `busy_`（CAS）/ `installing_` / `LockBusy` | 升级期间拒绝新查询/并发升级 |
| **当前任务快照** | `curr_install_task_`（unique_ptr） | 安装线程写/超时线程读，含 `pre_install_version` |
| **跨重启会话** | `UpgradeSessionInfo`/`UpgradeInfo` + `kConfigKeyUpgradeSessionInfo`（MMKV） | 重启后找回“我正在升什么” |
| **状态上报** | `ReportUpgradeStatus`（两个重载）→ ReliableRequest | `upgrade_task_uid`/`application_id`/`upgrade_status` 上报后台 |
| **上位机通知** | `NotifyModuleState` / `NotifyUpgradeStatus` / `UpgradeTypeToProto` | PosLink 模组状态 + 升级细粒度状态（0x01~0x03 类型 / 0x02~0x05 状态） |

## 内部成员结构（三组核心对象）

```
IotUpgradeSchd
 ├─ upgrades_        : 3 个 BaseUpgrade（App/Rom/SE）——"要升级谁"（版本、appid、下载目录）
 ├─ installers_      : 3 个 BaseInstaller ——————"怎么装"（按类型分发）
 ├─ DownloadService  : 外部模块 ——————————————"怎么下载"（限速/续传/MD5）
 ├─ busy_ / curr_install_task_ / session info ——— "现在升到哪了"（含跨重启）
 └─ advice_gate_ / ReliableRequest / PosLink 通知 ——"问谁、报给谁"
```

## 状态机视角

```
Downloading(6) ──下载成功──► Installing(7) ──重启+版本比对──► Succ(3)
      │                          │                            ▲
      │ 失败(FR-2)               │ 失败(FR-5)                 │ 同版本直接收敛（#1）
      ▼                          ▼                            │
   Fail(4) ◄──── 降级拒绝(30519, #2) / 超时(30515, #8) / 比对失败(#7) ─┘
```

**成功终态（Succ 3）只有两个来源**：#1 同版本直接收敛（没装就达标）和 #7 重启后版本比对（真正的安装成功）——安装阶段从不报成功，这是“install 返回 0 ≠ 真成功”设计在上报侧的体现。

## 一句话总结

**`upgrade_schd` = OTA 的调度与编排层**：对应 OTA 的“任务生命周期管理”——从后台任务进来（轮询/秒推），到决定升不升（过滤）、怎么下（编排 DownloadService）、要不要问用户（ADVICE 关卡）、怎么装（分发 Installer）、装完怎么确认（session + 重启比对）、每一步怎么让后台和上位机知道（ReliableRequest + PosLink）——全流程的唯一编排入口，但每种“体力活”都委托给专门的执行模块。
