# PosLink 桌面上位机 · 06 IPC 与进程模型

> 范围：Electron 三层（Renderer / Main / utilityProcess worker）的进程划分、IPC 通道全表与安全姿态。bridge 内部（worker RPC、事件 tap）见《05.原生桥接层设计.md》；跨进程线程规则见《04.线程模型与内存契约.md》。

## 一、进程拓扑

```text
┌─ Renderer（Chromium 渲染进程）────────────────────────────┐
│ Next.js 16 静态导出 + React 19                            │
│ contextIsolation + sandbox + 无 Node：                    │
│ 只见 window.posLink / window.app 两个 contextBridge 对象   │
└───────────────┬───────────────────────────────────────────┘
                │ ipcRenderer.invoke / .on（经 preload 白名单）
┌─ Electron Main ─▼─────────────────────────────────────────┐
│ 窗口 · app:// 协议 · 单实例锁 · 预检 · 菜单/About           │
│ crashReporter（仅本地） · electron-log · electron-store    │
│ serialport 枚举（只列不开）                                │
│ PosLinkBridge（worker 生命周期所有者）                      │
└───────────────┬───────────────────────────────────────────┘
                │ utilityProcess 消息通道（structured clone）
┌─ bridge-worker（utilityProcess）──────────────────────────┐
│ koffi.load → pl_* 调用（唯一 FFI 接触点，串行 RPC）         │──── 串口 ──► O41
└───────────────────────────────────────────────────────────┘
```

**崩溃域**：worker 崩溃（FFI/核心层）不影响 Main 与 Renderer——一次性重生后渲染层收到 `worker-restarted` 塌缩回 Home；Main 崩溃即应用退出；Renderer 崩溃/reload 只丢 UI 状态，串口链路在 Main，靠挂载探测自愈（《01》）。

## 二、主进程职责（`electron/main.ts`）

| 机制 | 说明 |
|---|---|
| 单实例锁 | `requestSingleInstanceLock()`：两个实例会抢串口；第二个实例直接退出，`second-instance` 时唤起已有窗口 |
| `app://` 自定义协议 | Next 静态导出按 clean path 导航（如 `/settings`），raw `file://` 下全部 404（打包冒烟发现）；`app://` 把每个 clean path 映射到预渲染文件（`path` / `path.html` / `path/index.html` 首中即得），standard+secure 特权使 fetch/Link prefetch 表现如真实 origin |
| 窗口安全姿态 | `contextIsolation: true` + `nodeIntegration: false` + `sandbox: true`——渲染层一切能力经 preload 白名单 |
| 启动预检 | 首窗口加载前 `preflightLibrary()`（存在/可读），失败弹窗退出，不让 worker 内 dlopen 抛栈（《05》§3.2） |
| About 面板 | `setAboutPanelOptions` 钉住 `app.getVersion()`——dev/ad-hoc 构建的 Info.plist 会漂移，保证菜单里看到的版本与 CHANGELOG 一致 |
| crashReporter | 仅本地留存 .dmp，随日志 ZIP 导出走（《07》） |
| 生命周期 | `whenReady` → initLogger → 预检 → 窗口；退出路径 `teardownBridge()`（先 destroy 句柄再杀 worker） |

dev 模式：加载 `http://localhost:3100`（HMR）+ 打开 DevTools；生产：`app://./index.html`。

## 三、preload：唯一 API 面（`electron/preload.ts`）

设计声明（文件头注）：**通道名全部钉死在此文件**，preload 即可审计的 API 面（A-12）；渲染层无 Node 全局、无裸 ipcRenderer。

暴露两个对象：

### `window.posLink: PosLinkApi`

```text
listSerialPorts()                                  串口只列不开
init() / connect(path,baud) / disconnect() / isConnected()
sendHandshake / sendQueryInfo / sendStartPalm / sendStopPalm /
sendSetPalmBehavior / sendQueryPalmBehavior / sendRaw / lastError
onConnectionState(cb) / onPush(cb) / onTraffic(cb) 订阅返回退订函数
forwardLog(level, message)                         fire-and-forget，日志路径绝不阻塞渲染层
```

全部请求走 `ipcRenderer.invoke`（Promise）。注意 API 形态与 C API 的差异：渲染层**没有** `destroy`——句柄生命周期归 Main（进程退出统一清理，防止渲染层误拆链路）。

### `window.app`（AppApi）

`version()` / `platform()` / `getStore` / `setStore` / `listLogFiles` / `exportLogsZip(mode)` / `openLogsDir` / `revealLastExport`。

安全细节：**日志导出不接受渲染层传入的任何路径参数**——保存目标只由原生对话框决定，渲染层无法指定任意写盘路径。

## 四、IPC 通道全表（`electron/ipc/channels.ts`）

常量为三方共享的唯一事实源（main handler / preload 白名单 / 渲染层实现）：

| 分组 | 通道 | 方向 | 说明 |
|---|---|---|---|
| 串口 | `serial:list` | R→M | 只枚举，永不打开/写入 |
| 生命周期 | `poslink:init` / `create` / `connect` / `disconnect` / `destroy` / `isConnected` | R→M | 映射到 PosLinkBridge |
| 类型化请求 | `poslink:sendHandshake` / `sendQueryInfo` / `sendStartPalm` / `sendStopPalm` / `sendSetPalmBehavior` / `sendQueryPalmBehavior` / `sendRaw` / `lastError` | R→M | 每次附带 traffic 回显 |
| 事件广播 | `poslink:onConnection` / `onPush` / `onWorkerEvent` | M→R | webContents.send 到所有窗口 |
| 应用信息 | `app:version` / `app:platform` | R→M | About / 平台分支 |
| 调试 | `debug:onTraffic` | M→R | 每请求回显记录 |
| 日志 | `log:forward`（R→M，单向 send）/ `log:listFiles` / `log:exportZip` / `log:openDir` / `log:revealExport` | 混合 | 文件日志与 ZIP 导出 |
| 存储 | `store:get` / `store:set` | R→M | electron-store 持久化 |

## 五、handler 层机制（`electron/ipc/pos-link.handler.ts`）

持有**全应用唯一**的 `PosLinkBridge` 实例（模块级单例），把 invoke 通道映射到 bridge：

- `poslink:init` → `initBridge()`：首次调用创建 bridge 并 `init + create`，随后挂三个事件转发：
  - `push` → 广播 `poslink:onPush`；
  - `connection` → 广播 `poslink:onConnection`；
  - `worker-restarted` → 广播 `poslink:onWorkerEvent {kind:'restarted'}`（渲染层语义：连接已失，回 Home）；
- 6 个类型化请求 + raw 全部经 **`wrapTraffic()` 包装**：`{cmd, req, rc, resp, ms, ts}` 调试回显（`hrtime` 计时），响应体 JSON 序列化后**截断 200 字符**（防 0xA3 大 blob 刷屏），错误也回显后原样 re-throw（渲染层照常 reject）；
- 请求未 init 即调用 → 结构化错误 `poslink bridge not initialised`；
- 退出路径 `teardownBridge()`：destroy 句柄 → 杀 worker → 实例置空。

其余 handler：`serial.handler.ts`（仅枚举）、`store.handler.ts`（electron-store 读写）、`log.handler.ts` + `log-collect.ts`（ZIP 导出与凭证扫描，《07》）。

## 六、事件广播模型

| 源事件 | 传播链 | 渲染层语义 |
|---|---|---|
| 0xA3 / 0xA1 推送 | io 线程回调 → worker 同步拷贝 → tap → `onPush` 事件 → 广播 | 识别结果三道闸门 / 模组状态条（《01》《07》） |
| PlConnState | 同上（无指针载荷） | 拔线判定（userInitiated 区分主动/自发断开） |
| worker 重生 | `worker-restarted` → `poslink:onWorkerEvent` | 连接已失，塌缩回 idle |
| traffic 回显 | handler 层生成 → `debug:onTraffic` | /debug 环形缓冲（300 条） |

广播目标是 `BrowserWindow.getAllWindows()` 全量——当前单窗口，多窗口场景天然成立；渲染层订阅均返回退订函数，hook 卸载时清理。

## 七、安全姿态小结

| 面 | 措施 |
|---|---|
| 渲染进程 | contextIsolation + sandbox + 无 Node；仅 preload 白名单两个对象 |
| IPC 面 | 通道名固定、可审计；invoke 均有 handler，事件单向广播 |
| 文件系统 | 日志导出无渲染层路径参数；写盘目标只由原生对话框决定 |
| 进程隔离 | FFI 崩溃域收敛在 worker；单实例锁防串口争抢 |
| 日志 | 渲染层 console 转发单向 send（不阻塞）；导出前凭证扫描（《07》） |
| 协议数据 | 识别凭证解析期丢弃、不落日志（《01》《07》） |
