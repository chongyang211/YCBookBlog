# PosLink 桌面上位机 · 03 C 契约与 ABI 设计

> 范围：`pos_link/c_api/`——把 C++ pos_link 核心包装为纯 C11 动态库的 S1 层。头文件调用规则与线程/内存细节见《04.线程模型与内存契约.md》；demo 侧如何消费本契约见《05.原生桥接层设计.md》与《08.协议字典与TS镜像.md》。

## 一、定位与契约地位

`include/pos_link_c_api.h`（471 行）是 **dylib 与所有调用方之间唯一的公共契约**（当前调用方：Electron utilityProcess 内的 Node koffi；预留 C#/Python/Rust 绑定）。冻结策略（头文件自述）：

- **破坏性变更**（删字段 / 改宽 / 重排）→ 必须同步递增 `pl_abi_version()` 与 SOVERSION；
- **增量式变更**（新增枚举值、末尾追加函数、启用尾部 reserved 字段）→ 向后兼容，版本号不变。

头文件是纯 C11，三种模式编译验证过：`gcc -std=c11`、`cl /std:c11`（MSVC 语法检查）、`clang++ -std=c++14`（`extern "C"` 保证符号按 C 方式修饰）。

## 二、导出防线（符号可见性）

| 防线 | 机制 |
|---|---|
| 编译期 | 父级 CMake 施加 `-fvisibility=hidden`，Unix 下未标注的符号**全部**从动态符号表消失；`POSLINK_C_API` 宏是唯一出口（Win=dllexport/dllimport，Unix=`visibility("default")`） |
| 构建后 | `scripts/verify_symbols.sh`：导出符号白名单校验，必须恰好 17 个 `pl_*`、零泄漏——也是 demo `stage:native` 暂存时的门禁（《05》） |
| 运行期 | `pl_abi_version()` 整数比对，demo 启动即校验，不匹配走干净报错路径（《05》） |

另有禁用词门禁 `scripts/verify_banned_words.sh`（交付文件不得出现中文协议/UX 词汇），与原生库仓库共用同一扫描器约定。

## 三、数据类型全景

### 3.1 枚举（宽度锁定为 `sizeof(int)`）

| 枚举 | 值 | 说明 |
|---|---|---|
| `PlStatus` | 0 / 负值 | 所有 `pl_*` 函数返回码，见 3.4 错误码表 |
| `PlPushType` | `RECOGNIZE_RESULT=0`、`MODULE_STATE=1` | 唯一暴露的 cmd_id 形态（D-12）：内部映射 0xA3 / 0xA1；未知值注册时返回 `PL_ERR_INVALID_ARG`，旧调用方只是收不到新推送，不会出错 |
| `PlConnState` | 0~3 | DISCONNECTED / CONNECTING / CONNECTED / CLOSING，与核心连接阶段一一对应 |
| `PlLogLevel` | 0~4 | TRACE~ERROR，对应 spdlog，供宿主汇流 dylib 内部日志 |

### 3.2 结构体（D-11：扁平 POD，变长用 `const char* + size_t`）

结构形态规则：不含任何 C++ 类型；变长载荷（UTF-8 或 base64 字符串）一律 `const char* + size_t` 对，**指针仅在交付它的那次回调执行期间有效**；dylib 内不引入任何 JSON 库，`info/config_data/result_data` 透传给调用方解析（有意决策，避免依赖膨胀）。

| 命令 | Req | Resp / Push | 关键字段 |
|---|---|---|---|
| 0x0C 握手 | `PlHandshakeReq`（2×u16：当前版本/最低版本） | `PlHandshakeResp` | ret_code **u32**：0 / 130 / 131 / 132 / 134；回带模组版本区间 + error_msg |
| 0x04 启动刷掌 | `PlStartPalmReq`（u16 biz_type） | `PlStartPalmResp` | ret_code **u16**（D-13）；session_id；palm_mode：0x01 识别 / 0x02 注册 / 0x03 混合 |
| 0x05 停止刷掌 | `PlStopPalmReq`（1B 占位） | `PlStopPalmResp` | ret_code **u32** |
| 0xA0 查询模组信息 | 1B 占位 | `PlQueryInfoResp` | `info`：UTF-8 JSON，调用方解析 |
| 0x0B 设置行为参数 | key/value 两对 char*+len | `PlSetPalmBehaviorResp` | ret_code **u16**：0 成功 / 1 未知 key / 2 非法值 |
| 0x0A 查询行为配置 | 1B 占位 | `PlQueryPalmBehaviorResp` | `config_data`：base64(JSON) 透传 |
| 0xA3 识别结果推送 | — | `PlRecognizeResultPush` | ret_code **u32** + session_id + result_data（base64 JSON 14 字段） |
| 0xA1 模组状态推送 | — | `PlModuleStatePush` | u16 state |

**D-13 位宽精确**是刻意的：Handshake/StopPalm/RecognizeResult 用 u32，StartPalm/SetPalmBehavior 用 u16——FFI 侧声明必须逐字对齐，混用会导致高字节截断（demo 的 `declarations.ts` 注释反复强调，见《08》）。

### 3.3 回调类型（5 个）

```c
PlPushCallback      (type, payload, payload_len, user_ctx)         /* payload 按 type 强转对应结构体 */
PlConnStateCallback (new_state, user_ctx)
PlLogCallback       (level, msg, msg_len, user_ctx)                /* msg 不保证 NUL 结尾，用 msg_len */
PlRespCallback      (rc, resp, resp_len, user_ctx)                 /* resp 仅 rc==PL_OK 时非 NULL */
PlRawRespCallback   (rc, reply_cmd, reply_code, payload, len, ctx) /* 原始线缆响应体 */
```

共同保证：全部在 dylib 内 Asio io 线程触发；同一句柄回调不可重入；载荷指针帧内有效。注册规则：每槽位单回调、覆盖式；传 `cb=NULL` 注销；注册表互斥锁保护，线程安全。

### 3.4 错误码（PlStatus 全表）

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | `PL_OK` | 成功 |
| -1 | `PL_ERR_INVALID_ARG` | 传了 NULL / 枚举越界 |
| -2 | `PL_ERR_NOT_CONNECTED` | 连接建立前发请求 |
| -3 | `PL_ERR_ALREADY_CONNECTED` | 已连接再 connect |
| -4 | `PL_ERR_INVALID_HANDLE` | 句柄已释放 / 未分配 |
| -10 | `PL_ERR_IO` | Asio 串口 / socket 错误 |
| -11 | `PL_ERR_TIMEOUT` | 响应超时（默认 10s） |
| -12 | `PL_ERR_PROTO` | 帧格式非法 / 协议不匹配 |
| -13 | `PL_ERR_REMOTE` | 模组应答非零 ret_code，看 resp 结构体 |
| -20 | `PL_ERR_SHUTTING_DOWN` | 句柄已 destroy |
| -99 | `PL_ERR_INTERNAL` | 未分类，看 `pl_last_error_message()` |

设计取向：新增负值对"统一按 `rc < 0` 判错"的调用方是向后兼容的，优先增量扩展。**双层错误面**：`PlStatus` 是成帧层（含 MapReplyMsgCode：模组 reply_msg_code 0→PL_OK、131→PL_ERR_PROTO、0xFE/0xFF 帧层哨兵→PL_ERR_INTERNAL、其余→PL_ERR_REMOTE），各 Resp 内的 ret_code 是协议层——排查时先看 rc 再看 resp（《07》的 AppError 即按此分层映射）。

## 四、17 个 ABI 函数

| 组 | 函数 | 要点 |
|---|---|---|
| 生命周期 5 | `pl_abi_version` / `pl_client_create` / `pl_client_destroy` / `pl_connect_serial(h,path,baud,flow)` / `pl_disconnect` | 句柄不透明指针，只能 `pl_client_destroy` 释放（free/delete 是 UB）；`pl_disconnect` 幂等；**IO 错误后的重连不由 dylib 负责**（S2 设计） |
| 状态 1 | `pl_is_connected` | CONNECTED 返 1，否则 0（含刚创建的句柄） |
| 请求 6 | `pl_send_handshake / start_palm / stop_palm / query_info / set_palm_behavior / query_palm_behavior` | 全异步：立即返回 PlStatus（入队结果），应答经 `PlRespCallback`；req 由封送层拷入线缆帧 |
| 回调 3 | `pl_set_push_callback / connection_state / log` | 槽位覆盖式，NULL 注销，线程安全 |
| 逃生 1 | `pl_send_raw(h, cmd_id, payload, len, cb, ctx)` | 唯一感知原始 cmd_id 的函数；组帧/校验和与类型化完全一致；保留给未建模命令（0x0E StartPalmEx、0xA2 PalmStatus）与调试 |
| 诊断 1 | `pl_last_error_message` | 线程级 256B 缓冲；指针在本线程下一次 ABI 调用前有效；可能返回 NULL |

## 五、ABI 指纹（编译期守护）

头文件第 6 节用 `POSLINK_STATIC_ASSERT`（C++=`static_assert`，C11=`_Static_assert`）锁定布局，意外漂移（中间插字段、改窄位宽）**在编译期即暴露**——dylib 构建与每个重新编译该头文件的集成方都受保护；把头文件拷进自己仓库做 FFI 声明的 koffi 调用方免费获得守护：

- 4 个枚举宽度 = `sizeof(int)`（不指定底层类型，依赖 C 标准 int 枚举规则）；
- 纯 POD 无指针结构体的精确尺寸：HandshakeReq=4 / StartPalmReq=2 / 占位 Req=1 / StopPalmResp=4 / SetPalmBehaviorResp=2 / ModuleStatePush=2；
- 带 `(char*, size_t)` 尾部的结构体只断言**定宽前缀的 offsetof**（如 HandshakeResp.protocol_version==4、min==6）；指针尾部偏移按 LP64（==8，含填充）/ 32 位（==4）分支断言——凡依赖 `sizeof(char*)` 的平台相关量刻意不进指纹（避免割裂 32/64 位目标）。

## 六、构建与产物

**构建双模式**（`c_api/CMakeLists.txt`，C++14，cmake ≥3.16）：

| 模式 | 触发 | 链接 | 用途 |
|---|---|---|---|
| 子模块模式（生产） | 由 palm_manager 顶层 CMake 驱动（检测到 `TARGET WxpayPosLink`） | `WxpayPosLink + WxpayCrossComm` + Boost；Win 另链 ws2_32/crypt32 | 真实 dylib / dll |
| 独立 PoC 模式 | 直接 `cmake -S . -B build`，find_package Homebrew 依赖 | 只编 `pl_stub.cpp + pl_errors.cpp` | 无核心源码时验证 17 导出面 / 跑 env-free 测试 |

**产物**：macOS `libposlink.dylib`（VERSION 0.0.1 / SOVERSION 0）、Windows `pos_link_c_api.dll`（无 lib 前缀）。安装树 = 头文件 + dylib + README。工具链矩阵在 `cmake/`（darwin-arm64 / darwin-x64 / win32-x64 / win32-ia32，含 MinGW 的 termios 兼容垫片）；`scripts/` 下另有 `package_release.sh` 打包到 `release/2.3.0/<platform>/`、Windows mingw 交叉与 MSVC 原生构建脚本。

**依赖**（`DEPENDENCIES.md`）：核心两静态库 + Boost.Asio（header-only）+ fmt 12 + spdlog 1.17 + zlib；明确不用 Conan（交叉编译矩阵复杂度），明确不引入 JSON 库（D-11）。fmt 10+ 移除 ostream 隐式回退的兼容经 `fmt_adapters_internal.h` 适配器（`error_code` / `PosMsgId` 的 `ostream_formatter`）解决，`-include` 强制注入每个编译单元。

**发布注意**：macOS 上 Homebrew 依赖是绝对路径（`/opt/homebrew/...`），发布前须经 `install_name_tool` 重写为 `@loader_path` 或静态链接——demo 侧 `fix:native-deps` 脚本承担此项（《05》）。

## 七、与非 C 宿主的对接要点（给未来绑定方）

1. 声明 17 个符号时位宽逐字对齐（D-13），参照 `c_api/tests/koffi_smoke.mjs` 的配方；
2. 回调内**同步拷贝**全部指针载荷（帧作用域生命周期）；
3. 重连 = destroy 旧句柄 → create 新句柄（io_context one-shot）；
4. 启动时先查 `pl_abi_version()`，再发任何结构体调用；
5. 日志回调拿到的 `msg` 不保证 NUL 结尾，必须用 `msg_len`。
