
> 范围：`src/service/heartbeat_service.h/.cpp` + `heartbeat_entity.h`。心跳服务是设备"活着且在线"的周期性证明，同时承担在线状态查询源、可靠请求队列唤醒旁证、软件版本属性上报托管三个职责。

## 一、定位与作用

| 职责 | 说明 |
|---|---|
| **在线证明** | 每 60s 向 IoT 后台 POST `/iot/devices/{sn}/heartbeat`，后台据此判定设备在线 |
| **在线状态查询源** | `GetOnlineStatus()` 返回最近一次心跳结果（atomic），供设备状态查询（如 PosLink 设备信息 `iot_online` 字段，pos_request_handler.cpp:698）使用 |
| **可靠队列唤醒旁证** | 心跳成功 = 网络可用的旁证，调用 `ReliableRequest::NotifyHeartbeatOk()` 唤醒可靠请求队列扫描——作为网络状态信号之外的第二条唤醒路径 |
| **版本属性上报托管** | `SoftwareVersionProvider`（FR-8）向 PaasShadow 注册，周期性上报 palmapp/ROM/SE 固件三版本（已从心跳循环迁移，FR-8.4） |

## 二、启动时序（BootStrapper）

## 三、运行循环（DoInit，heartbeat_service.cpp:60-123）

```text
DoInit（HeartBeatThread 上执行）
  ├─ 注册时间可信回调（Story 136515343）：
  │    TimeStateManager 时间同步完成后 → 立即补发一次心跳（不等下一周期）
  └─ CoSpawn 60s 心跳循环（steady_timer）：
        每轮：
        ├─ CheckTimeSyncedOrSkipLog：系统时间未同步 → 跳过本轮
        │   （签名 HTTP 必败；跳过日志有节流，不刷屏）
        ├─ 更新 current_timestamp_seconds_
        ├─ ReportDeviceOnlineStatus() → online_ok_.store(结果)
        ├─ 成功 → ReliableRequest::NotifyHeartbeatOk()
        │   （三重失效兜底语义：心跳断+网络信号丢+无入队时调度器休眠不扫，
        │    彼时发送必败无害；任一恢复即唤醒——reliable_request.h:74-77）
        └─ timer.expires_after(60s) → 等待下一轮
```

循环特征：

- **固定 60s 间隔**（`kHeartbeatInterval`），响应对 `heartbeat_interval_sec` 的动态调整是 TODO（:152-153）；
- 时间同步是前置门闸：未同步时不发请求（签名必败），靠时间可信回调实现"同步后立即补发"；
- 整个循环运行在 HeartBeatThread（与 Report 入队、恢复上报同线程，见《docs/report/04.report核心实现分析.md》线程模型）。

## 四、单次心跳报文（ReportDeviceOnlineStatus，:125-160）

**请求**：`POST /iot/devices/{sn}/heartbeat`，超时 5s

| 字段 | 值 |
|---|---|
| `device_sn` | Device::GetSn()（空则直接失败） |
| `timestamp` | 客户端时间戳（秒，本轮更新的 `current_timestamp_seconds_`） |

**响应**（`DeviceHeartbeatResp`，heartbeat_entity.h）：

| 字段 | 语义 | 当前消费状态 |
|---|---|---|
| `server_time` | 服务器时间戳（秒） | 仅 LOG_D（服务端时间纠偏未实现） |
| `heartbeat_interval_sec` | 心跳间隔（默认 60） | 解析但未消费（动态间隔 TODO） |
| `need_config_sync` | 是否需要配置同步 | 解析但未消费 |

结果写回：`online_ok_`（atomic）→ `GetOnlineStatus()`；失败打 LOG_W（含时间戳）。

## 五、SoftwareVersionProvider（FR-8，:27-42）

| 项 | 值 |
|---|---|
| Identifier | `software_version` |
| 来源类型 | `kSystemRuntime` |
| 刷新间隔 | 60s（与原心跳周期一致；注释论证：GetValue 开销极低 + PaasShadow 值去重，值不变不发网络请求，60s 与 300s 实际网络开销相同） |
| 上报内容 | JSON：`palmapp_version` + `rom_version` + `se_firmware_version` |

版本上报的历史演进：FR-8.4 将 `CheckAndReportVersionChanges` / `ReportSoftwareVersionProperty` 从心跳循环移除，统一收敛到 Provider 机制（:162-163）——心跳循环现在只保留在线状态上报。

## 六、与周边模块的关系

| 模块 | 关系 |
|---|---|
| Report 模块 | 目前**独立**：心跳不产生 Report 埋点；接入 Report 后启用的代码已写好（注释态）——`palm.heartbeat` Metrics（BaseMetricsBuilder，scope "mmiot"，:166-185）与 `face.iotservice.heartbeat.cycle` 埋点（:104-106） |
| ReliableRequest | 心跳成功是其扫描唤醒的三条路径之一（网络信号 / 队列入队 / 心跳旁证） |
| PaasShadow | Provider 宿主：软件版本属性的注册与周期刷新 |
| TimeStateManager | 时间可信事件订阅（补偿心跳）；循环内时间门闸 |
| PosLink 设备信息 | `GetOnlineStatus()` 作为 `iot_online` 字段出口 |
