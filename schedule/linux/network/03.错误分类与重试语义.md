# Network · 03 错误分类与重试语义

> 系列第三篇，承接《01.请求管线与网络模块.md》。覆盖错误码分类、error_msg 文案治理与"是否值得重试"的权威定义——本模块最有味道的部分。

## 一、ClassifyCprError 五码分类（network.cpp:179-214，IoT 与 OTA 下载共用）

| 码 | 场景 |
|---|---|
| 20101 | OPERATION_TIMEDOUT（cpr 超时） |
| 20102 | 网络断（连接失败/DNS 解析失败/收发失败/代理解析失败 5 种 cpr 码） |
| 20105 | **SSL 证书独立成码**（story 137332527）——握手/证书校验失败含"设备时间不对导致 not-yet-valid"，可行动性强（联动 NTP 预同步） |
| 20104 | TLS 拆分后残余 + 4xx + 意外状态码（3xx 等） |
| 20407 | 5xx |

## 二、响应解析决策树（ParseIoTHttpResponse，:216-282）

```text
cpr error 对象存在？
  ├─ 是 → ClassifyCprError 归类 + error.message + trace 尾缀
  └─ 否 → body 可解析出 {"code": N}？
        ├─ N != 0 → server_code=N + 20407
        │            error_msg = 本地文案 "Server error: code=N"（服务端原文仅进日志）
        ├─ 解析异常（非 JSON）→ 按 status 分支走
        └─ code==0 或无 code 字段
              ├─ status==200 → SUCCESS
              ├─ 4xx → 20104
              ├─ 5xx → 20407
              └─ 其他 → UNKNOWN_ERROR
所有分支均回带 trace_id + traceparent（with_trace 包装）
```

## 三、error_msg 文案治理（:228-254）

- 服务端**原文仅进日志**（LOG 原文 + trace_id 后台检索）——不透传 error_msg，防网关包装的 gRPC 错误串（如 "Unauthenticated: rpc error:…"）污染 UI；
- error_msg 统一本地文案（"Server error: code=N"）+ **`[trace_id:xxx]` 是唯一允许的附加尾缀格式**（network.h 治理约束）；
- `kErrorMsgMaxLength=512` 防变长 string 溢出 uint16 前缀；
- 空文案兜底：有 server_code → "Server error: code=N"，否则 "error_code:N"。

## 四、BuildErrorNotification：对外通知统一出口（:42-70）

- server_code 非 0 时经各链路注入的 `ServerCodeMapper` 映射为通知码；
- **漏传 mapper → LOG_W 留痕**（"复用面变大后是高发坑"）——新链路接入必须传 mapper，否则静默丢映射；
- **超长砍头保尾**（:63-68）：尾部含具体原因与 trace 尾缀，不可丢（截断职责在此层，非 Parse 层）。

## 五、IsNetworkError：重试语义的权威定义（:72-92）

| 码 | 收录 | 理由 |
|---|---|---|
| 20101 TIMEOUT | ✓ | 纯网络 |
| 20102 NETWORK_ERROR | ✓ | 纯网络 |
| 20104 CLIENT_ERROR | ✓（保守） | **混合语义**：(a) 网络类错+IsConnected（DNS/TCP 瞬时，占绝大多数）；(b) 4xx 无业务结构（当前腾讯网关 4xx 带 code → 走 20407）——若未来出现 20104 死循环，收敛为只留 20101+20102 |
| 20105 SSL_CERT | ✗ | 证书问题重试无意义（可行动：查证书/NTP） |
| 20407 / 20205 / UNKNOWN | ✗ | 后台已明确响应或本地永久错 |

## 六、服务端码与模组码隔离（server_errcode.h）

- 服务端码由 ParseIoTHttpResponse 从响应体 code 字段产生，归属网络模块管理；
- **经各链路的 Map*ServerCodeToModule 映射成模组码后才上 wire，禁止与模组码同字段混用**；
- 识别/注册的服务端码暂留 biz 层 recognize_retcode.h（与映射函数强相关）；激活链路映射见 activation_controller.h。
