## 二、IoT 请求管线全流程（IotDeviceRequestImpl，network.cpp:468-637）

### 2.1 端到端时序（标注线程归属）

```text
调用方线程（network/license/iot 等专用线程，全程阻塞）
  │
  1. SCOPE_EXIT 统计（:482-485）：无论成败/异常，退出时
     NetworkStat::ReportDeviceRequest(path, error, 上下行字节, 耗时)
  2. CHECK_IOT_DEVICE_HOST_SET（:101 宏）：iot_device_host_ 未设置
     → ERR_PALM_IOT_HOST_NOT_SET 直接返回（未激活期域名未注入）
  3. 签名（:501-514 四选一，见《02.签名与安全.md》）→ Authorization header
     签名失败（SE 未初始化等）→ ERR_PALM_IOT_SIGN_FAILED，不发网络请求
  4. trace 决策（:529-540，story 137332527/135784881）：
     override_trace_id 非空（刷掌会话/激活会话串联）→ 复用 + 随机 span
     否则 GenerateTraceparent(true)：锁内新 32hex trace + 16hex span
     裸 trace_id 从 header 固定位移 [3,35) 提取——避免锁外回读共享成员
  5. Header 装配（:547-551）：Authorization + Content-Type(json/protobuf)
     + Accept + traceparent；zerus 非空再 UpdateHeader x-zerus-env
     （调试环境路由，device_debug 云属性，仅首条 LOG_I 防刷屏 :558-564）
  6. body 日志门控（:578-586）：log_body=false 时只打长度——
     palm_data/特征/encrypted_key 等敏感 body 禁止入日志（接入红线）
  7. 同步发送（:590-604）：PostSync/PutSync/GetSync → libcurl（阻塞在调用方线程）
  8. 汇总日志（:608）：method path -> status (耗时ms) trace up/down 字节数
  9. ParseIoTHttpResponse（:216-282）统一解析 → IoTResponse
     （error_code, server_code, body, error_message, trace_id, traceparent 全量回带）
```

### 2.2 响应解析决策树（简版）

```text
cpr error → ClassifyCprError 归类（《03》篇五码表）
否则 body {"code":N≠0} → server_code + 20407（服务端原文仅进日志）
否则按 status：200→SUCCESS / 4xx→20104 / 5xx→20407 / 其他→UNKNOWN
所有分支回带 trace_id + traceparent（完整决策树见《03》篇第二节）
```

### 2.3 域名管理（:120-154）

`SetIotDeviceHost` 存 raw host（自动剥 https:// / http:// 前缀）：

| 取值接口 | 返回 | 用途 |
|---|---|---|
| GetIotDeviceHost | `https://{host}` | HTTP URL 拼接 |
| GetDeviceDomainHost | raw `{host}` | `link-{host}` 端点（MQTT broker / NTP，《docs/facility/04》《10》） |

`SetActivationSession(domain, session_id, session_key)` 三件套注入（激活期），`ClearActivationSession` 激活成功后清。

## 三、消费方全景

| API | 消费方 |
|---|---|
| IotDeviceRequest/Get/Put（含 trace_id 重载） | license/shadow/ota/heartbeat/report 全部 IoT 服务 |
| IotRecogPostRequest | 识别/注册（palm_flow，RECOGNIZE 签名） |
| ActivationGet/PostRequest | 激活链路（**60s 超时** kActivationRequestTimeout，常规 15s——激活链含 SE 密钥交换放宽）。签名差异：Get（registration 查询）走 SIMPLE（:712-717）；Post 由调用方传 type（见《02.签名与安全.md》速查表） |
| HttpRequest 直用 | OTA 下载（限速/低速熔断/keepalive，《04.传输层与执行载体.md》1.3） |
| DualLinkTdiRequest | TODO stub（恒返回 -1，:732-737） |

## 四、观察点（管线相关；专题观察点见各篇）

1. **iot_device_host_ / session_id_ / session_key_ 无锁**：写在激活流程、读在各请求线程——激活期间无并发请求所以实际安全，但属"靠时序保证"的无保护共享；
2. **trace 三级体系**：请求级（默认新 trace）/ 会话级（刷掌 override，story 135784881）/ 激活级（ActivationService 持有串联，story 137332527）——网络层是默认生成点，override 优先。
