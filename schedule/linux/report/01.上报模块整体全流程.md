## 二、写入侧全流程（业务 → 队列）

```text
业务代码（OTA 调度器 / PalmActionEventReporter / 各 Reporter）
  |  (1) 组装：auto rp = XxxReportItem::Create(); rp->field = ...;
  v
rp.Commit()                                        (report_item_base.ipp)
  |  (2) Report::ReportItem（report.ipp）
  |     - FillInContext()      协议钩子：公共上下文（SN、版本等，各协议自定义）
  |     - Post 到 HeartBeatThread            <- 业务线程立即返回，不阻塞
  v
HeartBeat 线程（ReportTo 要求在此线程调用，非线程安全）
  |  (3) FillBeforeQueue() -> to_json（strip null）-> ReportService::ReportTo(kTableId, json)
  v
ReportQueue（cross::ReportQueue，每表一个）
  |  (4) mmap 持久化文件 /userdata/.palmos/report/palmapp_<table_id>（AES 加密）
  |     掉电/断网/重启不丢，重启后自动续传
  v  落盘完成 = 上报责任移交队列（调用方无需关心结果）
```

要点：

1. **Commit 是 fire-and-forget**：唯一例外是 RecoveryReporter 的 "optimistic unlink"（Commit 投递到 HeartBeat 与实际落盘间有微秒级盲区，源码注释已声明为已知边界）；
2. **协议注册**：各协议头文件里 `REPORT_PROTOCOL_REGISTER(XxxItem)` 静态注册 `{kTableId, kBizName}`，`ReportService::DoInit` 遍历注册表为每张表建队列（report_service.cpp DoInit）；
3. **25261 是共表**：`PalmAppReportItem`（通用 action 埋点）与 `PalmSessionReportItem`（刷掌会话事件族）同 table_id，共用一个队列和 Builder，平台按 `attributes.action` 路由。

## 三、上传侧全流程（队列 → 后台）

```text
BaseFrequencyScheduler（每表一个独立任务，60s 周期，随机 offset + 每表递增 5s 错峰）
  |  (5) 定时器仅投递任务（kSync，<1ms，不占调度线程做 IO）
  v
ReportService 独立线程池（2 线程，与通用调度隔离）
  |  (6) UploadQueue(table_id)
  |     - 队列批量取出 <=200 条（kUploadReportMaxNumOnce）
  |     - 按 table_id 分派上传通道：
  |         16160 / 25261 -> ReportLogs()           （OTLP Logs）
  |         99001         -> UploadMetricsFromQueue()（逐条 OTLP Metrics）
  v
Builder 装配（OTLP 协议化）
  |  16160 -> BaseLogsBuilder（scope="16160"，通用设备属性）
  |  25261 -> PalmAppReportLogsBuilder（scope="25261"
  |           + 6 项设备 Resource 属性 + traceparent -> traceId/spanId）
  v
HTTP 上传（Network::IotDeviceRequest，超时 5s）
  |  16160/25261 -> POST /iot/report/logs   （整批一个请求）
  |  99001       -> POST /iot/report/metrics（逐条请求）
  v
结果处理（关键语义差异）
  - Logs 成功 -> 队列 commit（数据删除）
  - Logs 失败 -> RestoreTaken（条目放回，下轮重试，不丢）
  - Metrics 网络类失败（断网/超时）-> 丢弃：时效性数据，避免无网堆积
  - 未知 table_id -> 丢弃并告警（防 RestoreTaken 死循环）
```

补充机制：

- **FlushQueue(table_id)**：紧急上报入口，绕过 60s 定时器立即投递上传任务（需在 HeartBeat 线程调用，保证入队已完成）；
- **SyncAll**：预留空实现。

## 四、三条通道速查

| 通道 | table_id / 队列文件 | 装载数据 | Builder | 端点 | 失败语义 |
|---|---|---|---|---|---|
| IoT 埋点 | 16160 / palmapp_16160 | OTA 各 action、IoT 通用埋点（ext_key×3 + number×1 简化模型） | BaseLogsBuilder | /iot/report/logs | 重试不丢 |
| 终端事件 | 25261 / palmapp_25261 | 通用 action 埋点（PalmAppReportItem）+ 刷掌会话事件族（PalmSessionReportItem，23 字段严格协议） | PalmAppReportLogsBuilder | /iot/report/logs | 重试不丢 |
| Metrics | 99001 / palmapp_99001 | 设备资源 / 识别指标（ExportMetricsServiceReq 整包） | （无 Builder，原样逐条发） | /iot/report/metrics | 网络失败丢弃 |

## 五、线程模型

| 线程 | 职责 |
|---|---|
| 业务线程（FSM/OTA/…） | 组装 Item、Commit（非阻塞投递） |
| HeartBeatThread | FillInContext/BeforeQueue、to_json、**入队**（ReportTo 非线程安全，限本线程） |
| 调度器线程 | 定时器到点只 PostUploadTask（<1ms） |
| report_pool（×2） | 出队、Builder 装配、HTTP 上传、commit/restore |

## 六、新增一条上报的路径（开发者视角）

1. **已有协议**：选对 Item（16160 埋点 / 25261 事件），`Create()` 填字段后 `Commit()` 即可，不碰管道；
2. **新表**：`protocol/` 新建 Item（`kTableId` / `kBizName` + `REPORT_PROTOCOL_REGISTER`）→ `report_service.cpp` 上传分派加分支 → 需要定制 OTLP 装配则新建 Builder 并在 `ReportLogs` 注册；
3. **约定**：
   - 25261 会话事件族的字段装载只允许 `PalmActionEventReporter::Emit` 单点（防字段漂移，协议头注释明示）；
   - 上报异常一律 try/catch 吞掉，不反压业务。
