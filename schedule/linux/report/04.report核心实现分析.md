## 三、关键实现机制

### 2.1 协议注册：函数内静态 map + 静态初始化期写入

```cpp
// report.cpp
std::map<uint32_t, const char*>* Report::RegisteredProtos() {
  static std::map<uint32_t, const char*> register_protos;  // 函数内 static，规避静态初始化顺序问题
  return &register_protos;
}
```

- 各协议头文件的 `REPORT_PROTOCOL_REGISTER` 宏生成 `StaticInitializer`，**在 main 之前的静态初始化阶段**调 `RegisterReportProtocol` 写入 map；
- 因此 `ReportService::DoInit`（运行期）只读这张表建队列——读写天然分离，无需加锁；
- include 顺序无关：谁先谁后都进同一张表，25261 双协议注册被 `insert_or_assign` 自然合并。

### 2.2 Commit 链路：两段式填充 + 单线程收敛

```cpp
// report.ipp
void Report::ReportItem(ReportItemHolder<T>&& item) {
  item->FillInContext();                    // (1) 调用线程：happen_time、会话信息
  Threads::HeartBeatThread()->Post([item = std::move(item)]() {   // (2) move 捕获，所有权移交
    item->FillBeforeQueue();                // (3) HeartBeat 线程：设备快照、seq、report_time
    std::string j = DumpJsonStripNull(&jo(item));
    ReportService::Instance()->ReportTo(T::kTableId, std::move(j));   // (4) 入队
  });
}
```

设计意图：**所有跨协议的写操作收敛到 HeartBeat 单线程**——`ReportTo` 标注 non-threadsafe、`GenSeq` 标注 non-threadsafe，都靠"只有 HeartBeat 会调"保证安全。

`ReportItemHolder` 语义上类似 unique_ptr，Commit 即移交所有权，之后访问 Holder 是悬垂（头注释明确警告）。

### 2.3 ReportTo：入队即终态

```cpp
ReportTo(tid, json) -> ques_[tid]->PushBack(json)
  队列不存在（未注册/未 Init）-> LOG_W 丢弃
  PushBack 失败（队列满）    -> LOG_W "report save queue fail" 丢弃
```

**没有内存缓冲兜底**——落盘失败就是丢了。这是有意的取舍（上报非关键路径），但意味着队列容量是隐含的 SLA 参数。

### 2.4 UploadQueue：take / commit / restore 三原语循环

```cpp
while (true) {
  rpts = que->Take(200);          // 取一批（最多 200 条）
  if (rpts.empty()) { CommitTaken(); break; }        // 取空：正常退出
  success = 分派上传(...);
  if (!success) { RestoreTaken(); break; }           // 失败：整批放回，下轮重试
  CommitTaken();                  // 成功：这批从持久层删除，继续取下一批
}
```

- take/commit/restore 是队列的核心事务语义：Take 先"摘出"（防并发重复读），成功才 Commit 删除，失败 Restore 放回——**至少一次**投递；
- 失败即 break（不重试当前批），等待下一个 60s 周期，天然形成退避；
- 分派只认三个 tid：16160/25261 -> ReportLogs，99001 -> Metrics；**未知 tid 直接置 success 丢弃**（注释明示防 RestoreTaken 死循环）。

### 2.5 三通道上传实现

| 通道 | 实现 | 端点/超时 | 失败语义 |
|---|---|---|---|
| Logs(16160/25261) | `ReportLogs`：按 tid 选 Builder（16160 基类 / 25261 PalmApp 专属）-> 整批一个 OTLP 请求 | `/iot/report/logs`，5s | 失败统一 RestoreTaken |
| Metrics(99001) | `UploadMetricsFromQueue`：**逐条**发（每条是完整 ExportMetricsServiceReq） | `/iot/report/metrics`，5s | 细分（见下） |
| （遗留） | `DoUploadReport`：`COMM_REPORT` 端点，`{business_name, report_data[]}` 包裹，10s 超时 + DEVICE 签名 | COMM_REPORT | 返回 bool |

Metrics 的失败细分（UploadMetricsFromQueue）：

- **网络类错误**（20102 断网 / 20101 超时 / 20104 客户端错）-> 返回 true（=已消费），**整批丢弃**——metrics 是时效性数据，避免无网堆积；
- **其他错误** -> 返回 false，RestoreTaken 下轮重试；
- 注意逐条循环中任何一条网络失败即丢弃整批（含已发成功的剩余条目）——Metrics 场景可接受，复用此函数时需留意。

### 2.6 生命周期与线程隔离

```text
DoInit（BootStrapper 阶段）：建目录 /userdata/.palmos/report/ + 按注册表建队列（此时不上传）
Start：建 2 线程 report_pool + 每表注册调度任务（60s，随机 offset，表间 +5s 步进错峰）
Stop：停调度、置 running=false、队列 reset
```

两级线程隔离：调度器线程只 PostUploadTask（<1ms），网络 IO 全在 report_pool——上报慢/失败不会拖垮业务调度。

| 线程 | 职责 |
|---|---|
| 业务线程（FSM/OTA/…） | 组装 Item、Commit（非阻塞投递） |
| HeartBeatThread | FillInContext/BeforeQueue、to_json、**入队**（ReportTo 非线程安全，限本线程） |
| 调度器线程 | 定时器到点只 PostUploadTask（<1ms） |
| report_pool（×2） | 出队、Builder 装配、HTTP 上传、commit/restore |

## 四、实现级观察（疑似问题 / 遗留）

| # | 观察 | 位置 | 严重度 |

| 3 | DoUploadReport（COMM_REPORT 老通道）在 UploadQueue 分派中已无调用方 | report_service.cpp | 低：遗留代码，确认无外部调用后可清 |
