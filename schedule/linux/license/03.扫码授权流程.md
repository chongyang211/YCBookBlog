# License · 扫码授权流程

> 系列第三篇，承接《02.授权状态机与复检收敛.md》。覆盖授权二维码从扫码分发到 license 落盘生效的完整链路：分发门闸 -> DoAuthorize 三分支 -> Succeed/FailAuthorize 收口。

## 一、入口：分发链优先级二与双态门闸

```text
PalmCoreManager 扫码分发（优先级：操作码 -> License -> 激活码 -> 业务码）
  ▼
TryHandleScanCode(content)（manager.cpp:299，主线程）
  ├─ 门闸 1（W2 fix）：设备态必须是 kLicenseUnauthorized / kLicenseRefreshing
  │    —— 其他状态（含 kPalmRunning）不接单，直接 return false 放行后续模块
  ├─ 门闸 2：IsLikelyLicenseQrCode 轻量预检（长度+字符集，主线程毫秒级）
  │    —— 快速排除支付码/激活码/操作码，避免主线程做 ZIP 解密卡 UI
  ├─ 置 authorizing_source_（kFromUnauthorized / kFromRefreshing，据当前设备态）
  └─ Post LicenseThread -> DoAuthorize(qr_data)
       （LicenseThread 与激活流程同线程串行——授权与激活天然互斥）
```

## 二、DoAuthorize 全链路（manager.cpp:343-425）

```text
DoAuthorize(qr_data)
  1. SetAuthState(kAuthorizing) + RequestEnterWithRetry(kLicenseAuthorizing)
       （保护态：互斥挡刷掌；重试 3 次 x 500ms，失败不强切）
  2. QrLicenseDecoder::Decode
       Base64 -> MiniDecryptor 解密 ZIP -> 提取 output/qr.json -> JSON parse
       -> ValidateTimestamp（结构层时间校验）
       失败 -> FailAuthorize(ERR_PALM_LICENSE_QR_INVALID)
  3. 业务层有效期双保险（:360-379）：
       decoded 带时间窗时，先查 Device::SysTimeSynced()
         —— 时间未同步 -> FailAuthorize(ERR_PALM_LICENSE_TIME_UNTRUSTED)
         （system_clock 为 1970 纪元，会误判 start_ts 未到/已过期）
       再查 now 是否在 [start_ts, end_ts] 窗口内
         越界 -> FailAuthorize(ERR_PALM_LICENSE_QR_EXPIRED)
  4. 按 code_type 三分支：
```

### 4.1 gen_lic——拉云端 license（在线）

```text
content: { lic_url, lic_appid, lic_secret_key }
  ▼
yt_auth_init_online_with_cache_ex(ctx, url, kLicenseStoragePath, appid, secret_key, err_buf, 256)
  （经 LicenseNetworkProxy 走 license.youtu 后端；err_buf 携带细分错误，
   Story 138418526：后台原始码+原文 / 网络失败详情，不引入全局状态）
  失败 -> MapYtFetchError(ret) + BuildFetchErrorMsg(err_buf) -> FailAuthorize
  成功 -> new_summary = FetchLicenseSummaryFromYt()
```

### 4.2 feed_lic——直接写入 license（离线）

```text
content: { license: <license bytes 字符串> }
  ▼
yt_auth_init_by_string(ctx, license_str, "")     # 授权库本地验签/导入
  失败 -> MapYtLocalVerifyError(ret) -> FailAuthorize
  成功 -> LicenseStorage::Save(cloud_p.lic)       # 原子写（tmp+rename）
       -> new_summary = FetchLicenseSummaryFromYt()
```

### 4.3 get_device_info——本流程不支持

`kGetDeviceInfo` 用于服务端组包场景（携带 device_id+url），DoAuthorize 未处理该分支，落入 else -> `FailAuthorize(ERR_PALM_LICENSE_QR_INVALID, "unsupported code_type")`。

## 三、SucceedAuthorize 收口（:427-441）

```text
current_license_ = summary（加锁）
SetAuthState(kAuthorized, summary)
  ├─ MaybeReportShadow（module_auth 上报，去重）
  ├─ state_signal_（0xB0：kAuthorizing -> kAuthorized）
sync()                                  # 嵌入式 write-back cache，强制刷盘
PostExitToSteady()
  # kIdle 优先级 10 < 保护态 60，RequestEnter 会被拒——用 PostExitToSteady 绕过优先级检查
EmitAuthResult(kAuthorize, 0, "", summary)   # 0xB2 成功
in_authorizing_=false; authorizing_source_=kNone
```

## 四、FailAuthorize 收口（:443-448）

```text
SetAuthStateOnAuthFailure()             # C2 fix：按 source 设 AuthState
  ├─ kFromRefreshing -> 保留 kAuthorized（旧 license 仍在磁盘，未被覆盖）
  └─ 其他            -> kUnauthorized（首次授权失败，无有效 license）
PostExitTo(ResolveAuthorizingFailureTarget())
  ├─ kFromUnauthorized -> kLicenseUnauthorized（OnEnter 重启扫码继续等重扫）
  ├─ kFromRefreshing   -> kLicenseRefreshing（保留旧 license 继续等）
  └─ kNone             -> kLicenseUnauthorized（兜底）
EmitAuthResult(kAuthorize, ret_code, err_msg, nullopt)   # 0xB2 失败（409xx 段）
in_authorizing_=false
```

失败回退矩阵的核心：**失败不丢旧授权**——refreshing 场景 license 覆盖发生在 yt 库导入成功之后才落盘，失败时磁盘上仍是旧 license。

## 五、相关上位机入口

| 入口 | 触发 | 行为 |
|---|---|---|
| `EnterAuthorizeFlow`（0x10） | 上位机指令 | 目标选择在 LicenseManager（owns AuthState）：kAuthorized -> kLicenseRefreshing，否则 kLicenseUnauthorized；迁移合法性由状态机 CanEnterFrom 仲裁（kUnactivated 不能进 Refreshing）；结果经 0xB0/0xB2 |
| `EnterActivationFlow` | 未授权转激活 | 仅 kLicenseUnauthorized 可进入 kUnactivated |

## 六、观察点

1. `kGetDeviceInfo` 码型在 DoAuthorize 中落入 else 拒绝——该码型服务于服务端组包环节，若运维流程出现"设备信息码"单独扫描的场景，需要补分支；
2. gen_lic 的 `lic_secret_key` 随二维码携带（打印日志时仅打 url/appid，secret 不落日志——:384-388 的日志字段选择是有意的）；
3. `sync()` 强制刷盘在 SucceedAuthorize 中、Fe Lic 的 Save 之后——保证重启后 license 文件完整；GenLic 路径落盘由 yt 库内部完成（是否有 sync 取决于库实现）；
4. 双层时间校验（Decode 结构层 + DoAuthorize 业务层）+ SysTimeSynced 门闸——时间不可信时宁可拒绝授权也不误判有效期；
5. `completion` 类单飞：DoAuthorize 运行在 LicenseThread 且与激活互斥，但 `TryHandleScanCode` 无 in-flight 防重（`in_authorizing_` 在 DoAuthorize 内才置位）——理论上两次快速扫码可各 Post 一次 DoAuthorize 串行执行两次（第二次会覆盖第一次结果，幂等可接受）。
