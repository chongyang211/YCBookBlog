# License · 存储与网络代理

> 系列第四篇。覆盖 license 的持久化（LicenseStorage）与 yt-mobile-auth 授权库的网络出口（LicenseNetworkProxy）两个基础设施组件。

## 一、LicenseStorage——license 文件持久化

### 1.1 定位与安全边界

- 路径：`/data/persist/cloud_p.lic`（绝对路径，目录不存在时递归创建）；
- **不加密**（头注释明示）：授权库 yt-mobile-auth 内部已做签名校验——文件被篡改无法通过 `yt_auth_init_by_path` 校验，加密无增益。

### 1.2 原子写（Save，C4 fix，license_storage.cpp:15-50）

```text
EnsureDirectoryExists（逐级 mkdir -p，忽略 EEXIST）
  ▼
写 {path}.tmp（binary | trunc）
  ├─ 打开失败 -> -2
  ├─ 写失败   -> -3
  ▼
chmod 600（S_IRUSR | S_IWUSR，仅 root 可读写）
  ▼
rename(tmp -> path)                        ← 原子替换
  ├─ rename 失败 -> unlink(tmp) 清理 -> -4
  ▼
成功（LOG_I "saved (atomic)"）
```

防的场景（C4）：**掉电导致半写 license 文件**——rename 的原子性保证目标路径要么是完整旧文件要么是完整新文件。

### 1.3 掉电窗口的完整链路

`Save` 本身只 close（flush 到内核）未 fsync 物理盘；物理落盘由上层 **SucceedAuthorize 统一 `sync()`**（03 篇第三节）强制完成。时序：yt 库导入成功（内存）-> Save（tmp+rename）-> SucceedAuthorize `sync()`。极端掉电窗口：rename 后 sync 前掉电——rename 语义下文件内容仍完整（页缓存由内核保证 rename 原子性），理论上无半写风险。

## 二、LicenseNetworkProxy——授权库的网络出口

### 2.1 定位

实现 yt-mobile-auth 的 `INetworkProxy` 接口，`Init` 时经 `yt_auth_set_network_proxy` 注入（Deinit 置空清理）。**授权库不直接依赖 curl**——所有 gen_lic 的云端请求（license.youtu 后端）经此代理走设备统一的 HttpRequest（cpr/curl）栈。

### 2.2 PostJson 实现（license_network_proxy.cpp:11-47）

```text
PostJson(url, body, resp_out, http_code_out)
  ├─ 参数判空 -> ERR_PALM_IOT_INVALID_PARAM
  ├─ HttpRequest：Content-Type application/json
  │    超时：建连 10s / 整包 60s（kConnectTimeoutMs / kRequestTimeoutMs）
  ├─ PostSync
  ├─ cpr 层错误（DNS/连接/超时）-> ERR_PALM_IOT_NETWORK_ERROR
  ├─ HTTP 非 2xx -> ERR_PALM_LICENSE_NETWORK（resp 原文带回供授权库解析）
  └─ 2xx -> ERR_PALM_IOT_SUCCESS
```

### 2.3 超时推导（:37-42 注释）

原 5s 建连 + 15s 整包在弱网/高延迟现场**响应未返回即判超时**，放宽为 10s + 60s（与激活流程 kActivationRequestTimeout 对齐）。代价：PostJson 是授权库 worker 线程的同步阻塞调用——**超时拉长会同步拉长 kLicenseAuthorizing 保护态停留**（最坏 60s+，期间刷掌被设备态互斥挡住）。

### 2.4 错误码映射链（ gen_lic 失败时的完整旅程）

```text
PostJson 返回码 / yt 库 ret
  -> MapYtFetchError(ret)        # yt 库错误 -> 409xx 段（ERR_PALM_LICENSE_*）
  -> BuildFetchErrorMsg(ret, err_buf)   # err_buf 携带后台原始码+原文（Story 138418526）
  -> FailAuthorize(mapped, msg)  # 0xB2 通知上位机
```

## 三、观察点

1. **Save 无 fsync**：close 只保证写入页缓存——物理落盘依赖 SucceedAuthorize 的统一 `sync()`；若未来有不经 SucceedAuthorize 的 Save 调用点，掉电窗口会重现半写风险（rename 保证内容完整，但可能丢最后一次授权）；
2. **PostJson 全量打印 body**（:19，LOG_I body=…）：gen_lic 流程请求体由授权库构造，若含 secret_key/设备敏感信息需评估日志脱敏（当前 gen_lic 侧日志有意不打 secret，此处口径不一致）；
3. `EnsureDirectoryExists` 逐级 mkdir 忽略全部错误（含权限不足）——失败会在后续 open 时以 -2 呈现，错误归因略绕但无害；
4. 非 2xx 时把响应原文带回授权库（`*resp_out = resp.text`）——授权库可解析后台业务错误（与 err_buf 细分错误机制衔接）。
