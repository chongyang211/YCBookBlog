# biz/pos模块全流程

> 一句话定位:模组侧的"POS 协议门面"——通过串口(`/dev/ttyS2` 115200,0x7E 帧)与上位机收银机收发 0x 协议字,承接刷掌会话的启停、识别结果上报(0xA3)、上位机输入(0x0D 加验 / 0xA6 绑定 / 扫码),并承载 uploadLog(BiComm 0xAD)与测速(0xA7)两个旁路。

## 一、分层结构

```
上位机(POS 收银机)
   ↕ 串口 0x 帧(pos_link 库:0x7E 帧头尾 + 转义)
pos_transferer        传输层:持有 PosLinkServer 单例,三向发送(Send / SendAndGetResponse / SendFrameError)
   ↕
pos_request_handler   协议中枢(单例,经 GetGlobalPosRequestHandler() 获取):
                      上行 HandleRequest 大分发(0x04/0x0E/0x05/0x0D/0xA6/0x14/0xAD…)
                      + 下行通知帧构建(0xA3 结果 / 0xA5 优选图 / 0xAB 加验通知 / 0xAC 绑定通知 / 0xA7 测速)
   ↕
pos_session           业务会话(BizSession,继承公共层 PalmServiceSession):
                      驱动 SDK 检测 → 识别 HTTP → 委托策略处理响应 → 结果上报
strategy/             模式策略族:IPalmModeStrategy + Recognition/Enrollment/Hybrid 三策略 + 工厂(0x01/02/03)
   ↕
PalmSessionController(palm_flow FSM)  ← 会话状态机在 palm_flow 层,pos 层通过它进出
```

### 各文件职责

| 文件 | 职责 |
|---|---|

| `pos_request_handler` | 协议中枢:上行所有 Req 的分发入口(大 if-else,pos_request_handler.cpp:239-350)+ 下行所有通知帧的构建发送 |
| `pos_session` | 业务会话:驱动 SDK 检测 → 识别网络请求 → 委托策略处理;持有 `PosRequestHandler` 与 `IPalmModeStrategy`(pos_session.h:86-88) |
| `bicomm_manager` | 通用双向控制指令(0xAD)管理器:task_id 生成/去重/超时/Base64/ACK 自动回复,发起方+执行方双向(bicomm_manager.h:96-171) |
| `upload_log_handler` | BiComm `uploadLog` 执行方 handler:参数校验 → 调 O1 后端建指令 → 经 IotCmdUploadLog 桥接 → 5 阶段回推(upload_log_handler.h:6-15) |

### strategy/ 策略族

- **IPalmModeStrategy**(接口,palm_mode_strategy.h:28-40):`GetPalmWorkMode()`(SDK 检测模式)/ `GetRecognizeMode()` / `HandleResponse(ctx, session)`(模式特有响应处理);
- **RecognitionStrategy**(识别,含 `HandleStandardResult` 复用)、**EnrollmentStrategy**(注册,保存掌纹数据)、**HybridStrategy**(混合,继承识别策略,支持运行时切注册,hybrid_strategy.h:10-15);
- **PalmModeStrategyFactory**:palm_mode 0x01/0x02/0x03 → 识别/注册/混合,其他兜底识别(palm_mode_strategy_factory.h:15-19);
- 消费方仅 `PosSession`:StartSession 时工厂创建(pos_session.cpp:104),`OnPalmRecognized` 公共流程(停检测 → 发识别请求 → JSON 解析)后委托 `HandleResponse`(pos_session.cpp:321-335);混合模式运行时 `SwitchStrategy` 切换(pos_session.cpp:430-433)。

## 二、三条核心链路

### ① 正向识别链(会话启动 → 0xA3 → host-ack)

1. 上位机 0x04/0x0E → 串口 → `HandleRequest` → `HandleStartPalm(Ex)Request` → `DoStartPalmSession`:PrepareStartPalm → ComputePalmMode → **`PalmSessionController::Instance()->RequestStart(...)`**(pos_request_handler.cpp:540,进入 palm_flow FSM);
2. FSM 进入会话态 → `PosSession::StartSession` 创建策略、启 SDK 检测(`PalmCoreManager::StartPalmDetect`,pos_session.cpp:104-111、438);`OnStart` 发 0xA1"检测中"(pos_session.cpp:172);
3. SDK 识别命中 → `OnPalmRecognized`(pos_session.cpp:261):发 0xA5 优选图通知 → 停检测 → 线程池同步 POST `/wecardpalm/device/recognize`(pos_session.cpp:340-344)→ 策略 `HandleResponse` → `ReportResultAndStop` → `OnPalmResult`;
4. `OnPalmResult` 组 `PosAppRecognizeResultReq`(**0xA3**),业务字段 base64(JSON) 放 `result_data`,带 `need_host_ack` 标志(pos_request_handler.cpp:383-394);
5. 上位机回 **0x14** host-ack → `HandleHostResultAckRequest`(pos_request_handler.cpp:1315-1341):喂 FSM `HostAckResultEvent`,仅 kWaitingHostAck 态接受,否则回 HOST_ACK_TERMINATED。

### ② 上行输入链(上位机 → 模组)

全部经串口线程 → MainThread Post → `PosRequestHandler::HandleRequest` 分发:

- **0x0D 加验**:`HandleVerifyPalmRequest` —— 校验 `IsActive<VerifyingHead>()` + session_id → ACK + `React(VerifyDataEvent)` 进 FSM(pos_request_handler.cpp:1106-1108;发送侧 0xAB 通知见 :898,超时触发 `StateTimeoutEvent`);
- **0xA6 BindPalm**:`HandleBindPalmRequest` → `controller->OnBindPalmRequest(...)`,FSM 需在 WaitingBindInput 态,否则回错(pos_request_handler.cpp:604-614);结果经 `OnBindResult` 上行(0xA3 变体,recognize_type=0,:421-447);
- **扫码**:`OnScanCodeResult`(:397-419)——由 `PosSession::OnScanCode` 回调驱动,封装为 0xA3 类通知(recognize_type=0x02);
- 其他:0x05 Stop、0x06/0x07 查询、0x0B/0x0C 控制/灯、0x0F-0x13 License/激活、0x15 网络诊断等。

### ③ 旁路链

- **uploadLog(BiComm)**:上位机发 **0xAD** → `HandleBiCommRequest` → `BiCommManager::OnBiCommRequest`(pos_request_handler.cpp:283-292)→ 分发给 `UploadLogHandler::HandleRequest`:校验 → CAS 抢单 → IotThread 上调后端建指令(upload_log_handler.cpp:139)→ 云端下发指令由 `IotCmdUploadLog` 回调 `OnCmdStatus`(5 阶段 0x20/0x21/0x22/0x10/0x11)→ `BiCommManager::NotifyPhase` 回推上位机;
- **speed_test**:后端测速结果经 `NetworkDiagnosis::AddSpeedTestObserver` 多播 → `SpeedTestNotifier::OnSpeedTestResult` 等级穿越判定 → MainThread 协程调 `SendSpeedTestNotifyMsg`(**0xA7**,AsyncRequest 等 reply),131 或连续 3 次失败即永久停推(speed_test_notifier.cpp:64-88)。

## 三、线程模型(3 个边界,1 个收敛点)

- **全部业务收敛在 MainThread 协程**(boost::asio 单线程):`HandleRequest` 分发、策略处理、0xA3/0xA7 发送全部 `Threads::MainThread()->CoSpawn`(pos_request_handler.cpp 全文 30+ 处);BiCommManager 明确约束"所有方法必须在 MainThread 调用"(bicomm_manager.h:18);
- 跨线程仅 3 处边界:
  1. **串口专用线程**:`PosLinkServerHolder` 自建 `thr_`(pos_transferer.cpp:127),收包后 `Threads::MainThread()->Post` 投递——**跨线程唯一入口**(pos_transferer.cpp:169);发送时再 post 回串口线程写帧(:214);
  2. **线程池(Network)**:识别 HTTP 经 `ThreadPool::Instance()->AsyncExec` 执行(pos_session.cpp:341-344),协程 co_await 回 MainThread;
  3. **IotThread**:仅 uploadLog 的后端 HTTP 调用与软超时定时器串行于此,避免阻塞刷掌主链路(upload_log_handler.cpp:139/166),结果经 mutex 保护的映射表回 MainThread。

## 五、与 palm_flow 层的分工

`palm_flow` 只管会话状态流转与业务事件上报(结果日志/metrics),所有"与上位机说话"的协议细节隔离在本层;两层经 `PalmSessionController` 单点互调:pos 层调它进/出会话、喂事件,它经 `GetGlobalPosRequestHandler()` 反向调本层发通知帧。
