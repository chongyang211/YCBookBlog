
## `palm_session_controller.h/.cpp` 的作用

`PalmSessionController` 是**刷掌业务的总调度器 / 状态机的“司机”**（spec FR-14/15/16）——单例、长寿，`DeviceFsm.PalmRunning` 状态的 owner。如果说 `PalmFlowMachine` 是状态机引擎主机，那 Controller 就是**拥有这台主机、决定什么时候开一轮、并替状态机干脏活累活（IO/网络/SDK）的角色**。外部世界（POS 请求处理、DeviceFsm、自检模块）都通过它接入。

## 职责分解

### 1. 生命周期驱动：RunForever → ScheduleLoop → RunOneRound（cpp 第 614–690 行）

- **`RunForever`**：单次 `Run()` 后 CoSpawn，循环等 `DeviceState::kPalmRunning || kDebugTesting`（竞速语义），进入即起 `ScheduleLoop`；
- **`ScheduleLoop`**：在这两个设备状态下连续跑轮；一轮 `Done` 后 break，等设备状态离开再由 RunForever 重新同步（防旧轮与上位机新 RequestStart 冲突）；
- **`RunOneRound(palm_mode)`**（spec FR-10）：每轮开始时——
  1. `MakePalmFlowStrategy(palm_mode)` 创建**每轮新的 Strategy**（长寿 machine + 每轮 strategy 的组合）；
  2. `GetProfile()` + 从 `PalmBehavior` 快照统一配置（超时/重试上限等）+ 预取 `hybrid_enroll_method`（保证 Strategy 决策保持纯函数无锁）；
  3. `machine_->Reset(profile)`——状态机回到 `CreatedState`，然后 React(`StartReqEvent`) 启动一轮；
  4. `DrainActionsUntilDone()`：**RunLoop 主体**（cpp 第 1907–1915 行）——循环 `PopAction()` → `ConsumeAction()`，排空后 `WaitWork()` 挂起，直到 `DoneState`。

### 2. `ConsumeAction`——Action 工单的执行车间（cpp 第 791 行起）

之前多问提到的 `FlowAction` 在这里逐一落地：`kRunOnStart`→`WaitInitDone`+`StartPalmDetect`+视情开扫码；`kRecRequest`→按 `IsActive<VerifyingHead>` 路由 `/verify-palm` 或 `/recognize`；`kRegisterByCodeRequest`→`RegisterByCodeFlow`；`kProcessBindPalm`→`BindPalmFlow`……网络/SDK 返回后做**轮次 epoch 校验**（P0-8，防旧轮响应串新轮）、服务端码 → 模组码映射（`MapRecServerCodeToModule`），再 `machine_->React(XxxEvent)` 回灌状态机。

### 3. SDK 信号封送（spec FR-12，`ConnectSdkSignals`）

订阅 PalmCore 五路 SDK 信号（report/palm_status/opt_live/local_identify/code_scan），在 SDK 回调线程 **Post 到主线程** 后转成 `PalmEnteredEvent`/`OptPassEvent`/`PalmDataReadyEvent`/`LocalIdentifyResultEvent`/`ScanCompleteEvent` 喂给状态机——输入事件的大半来源。

### 4. POS 协议接入面

- `RequestStart` / `RequestStop` — 0x04/0x05 的入口，写 `pending_offline_/pending_scan_` 传参；
- `OnBindPalmRequest`（0x06）— 仅 `WaitingBindInputState` 激活时接受，React `BindPalmRequestEvent`；
- `HandleVerifyData`（0x0D）— base64/JSON 解析后 React `VerifyDataEvent` 或 `VerifyErrorEvent`；
- `HandleHostAckResult`（0x14）— React `HostAckResultEvent`；
- `TriggerVerifyTimeout` — 旧上位机 transport 超时时主动注入超时事件。

### 5. 上行路由 + 收尾

- 代理 machine 的 `change_sig_`/`event_sig_` → `change_sig_proxy_`/`event_sig_proxy_`，`PosNotifier` 订阅后转 0xA3/0xAB/0xAC/0xA8 等报文；
- `OnFlowEvent` 消费 `OnSessionCompleteEvent`：起 3s 结果灯窗口（`RequestExitTo(ShowingResult*)`）、`ScheduleAutoStart` cooldown 自启、`RequestExitTo(kIdle)`；
- `ResetRoundState()`：每轮尾部断开 SDK 信号、释放 strategy、清 pending_*；
- 跨 session 暂存：`PendingEnrollData`（注册探测数据跨会话供 BindPalm 复用）。

### 6. DeviceFsm 集成（IGracefulExit）

`RequestExit()` / `IsInterruptible()`（透传 machine 的查询）——设备状态机切换/抢占时对刷掌会话做优雅打断（kAbort 路径的发起方）。

## 对应状态机里的内容

Controller 本身**不含任何状态**，它对应状态机图上的所有“图外机制”：

| 状态机关注点 | Controller 承担的部分 |
|---|---|
| 图的启动与轮转 | `RunOneRound` 的 Reset + `StartReqEvent`；“一轮”边界的持有者 |
| 图上的 Action 出边（FR-11） | `ConsumeAction` 全部实现——图上所有“委托外部执行”的节点出口 |
| 图的输入边来源 | SDK 信号封送（检测/扫码链）+ POS 命令（0x04/05/06/0D/14 → 各 Event） |
| 图的输出边去向 | 订阅 event_sig_ 转发 PosNotifier；`OnSessionCompleteEvent` 驱动设备状态回 Idle |
| 决策所需数据 | 预取配置进 profile（Strategy 纯函数化的前提） |
| 防串轮/防陈旧 | epoch 校验（ConsumeAction）、timer token（Machine 层） |
| 图外的 interrupt 规则 | `IGracefulExit` 接入，StopReq/kAbort 的触发方 |

一句话总结：前面看的 palm_flow 全家（events/context/actions/fsm_def/states/strategy/machine）构成一台**纯逻辑状态机**——不含任何 IO；`PalmSessionController` 是把它接到真实世界的**适配与调度外壳**：决定何时开轮、把 SDK/POS 的现实事件翻译成 `React(...)`、把 `FlowAction` 翻译成真实的网络请求和 SDK 调用、再把结果事件回灌——状态机图上每条出边的“实际动作”，最终都落在这个文件里。
