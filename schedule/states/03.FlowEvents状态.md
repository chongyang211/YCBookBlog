## `flow_events.h` 的作用

这是状态机的**事件与状态词汇表**，内容比前两个文件更靠“骨架”层，包含五类定义（对应 spec FR-2/FR-3/FR-9/FR-13/FR-19）：

1. **`FlowState` 枚举** — 状态机所有状态的对外编号；
2. **强类型输入事件**（FR-9）— 外界（SDK、上位机、Controller、超时器）喂给状态机的 `React(...)` 事件；
3. **Verdict 决策类型** — Strategy 的决策结果，以 `VerdictXxxEvent` 回喂状态机驱动转移；
4. **`PalmFlowChange`** — 状态变化广播结构；
5. **`PalmFlowEvent` variant** — 状态机到 `PosNotifier` 的**事件型上行**（对外副作用：灯效、0x01/0xA3/0xAB/0xAC 报文等）。

## 与状态机的对应关系

**1. `FlowState`（第 20–42 行）— 就是状态图本身的状态集合**：
- 主干：`kCreated → kStarting → kDetecting → kPalmEntered → kOptPassed`
- 识别子树：`kRecognizeEntry`（瞬态分派）→ `kLocalRecognizing` / `kCloudRecognizing`
- 注册子树：`kRegisterEntry` → `kRegisterSubmitting` → `kWaitingBindInput` / `kWaitingScanInput` / `kRegisterByCodeSubmitting`
- 加验子树：`kVerifyEntry` → `kVerifying` → `kVerifySubmitting`
- 统一出口：`kResultObtained` → `kWaitingHostAck` → `kStopping` → `kDone`

**2. 输入事件 — 对应状态图的“入边触发源”，按来源分组**：
- 生命周期：`StartReqEvent`/`StopReqEvent`（上位机请求）、`StartOkEvent`/`StartFailEvent`/`StopOkEvent`（Controller 消费 Action 后回喂）
- SDK 信号：`PalmEnteredEvent`/`OptPassEvent`/`PalmDataReadyEvent`（检测采集链）、`LocalIdentifyResultEvent`（端侧识别）、`ScanCompleteEvent`（扫码自然完结）
- 上位机协议：`VerifyDataEvent`（0x0D 加验数据）、`BindPalmRequestEvent`（0x06 录掌）、`HostAckResultEvent`（0x14 回执）
- Controller 回喂：`RecResponseEvent`/`RegisterResponseEvent`（HTTP 响应，code 已统一映射为模组码 + 原始 `server_code`）、`BindPalmResultEvent`/`RegisterByCodeResultEvent`/`VerifyErrorEvent`
- 统一超时：`StateTimeoutEvent`（带 `Kind` 区分各状态的等待超时，`token` 防过期定时器误触发）

**3. Verdict（第 160–195 行）— 对应状态图上的“决策转移边”**：
Strategy（`DecidePostOpt`/`DecidePostRec`/`DecidePostRegister`）消费 `FlowContext` 里的响应数据后返回 `std::variant` Verdict，用 `kAlwaysFalse` + visitor 做**编译期完整性检查**（新增分支必须被处理）：
- `PostOptVerdict`：优选后 → 提交识别 / 进注册 / 结束
- `PostRecVerdict`：识别后 → 完成 / 重试检测 / 需加验 / 加验重试
- `PostRegisterVerdict`：注册后 → 完成 / 加验 / 等 `BindPalm`（`V_WaitBindInput`）/ 等身份码（`V_WaitScanInput`）

即：上一问 `FlowContext` 里的 `recognition_attempted`、`verify_retry_count`、`palm_state` 等字段，就是这些 Verdict 分支的判断依据。

**4. `PalmFlowEvent` 上行（第 369–381 行）— 对应状态的“出口副作用”**：
状态在 `enter`/`react` 时 emit，`PosNotifier::OnFlowEvent` 消费并转成对外报文：`NeedVerifyEvent`→0xAB、`NeedBindInputEvent`→0xAC、`OnPalmResultEvent`/`OnBindResultEvent`/`OnScanResultEvent`→0xA3、`HostAckCompleteEvent`→0xA8、`RecognizeStartEvent`→0x01 等。

一句话总结：如果把状态机比作一台机器，`flow_events.h` 定义了它的**状态名牌（FlowState）、输入信号线（输入事件）、控制开关挡位（Verdict）和输出信号线（PalmFlowEvent）**；`flow_context.h` 是它的内存，`flow_actions.h` 是它委托外协（Controller）干活的工单。
