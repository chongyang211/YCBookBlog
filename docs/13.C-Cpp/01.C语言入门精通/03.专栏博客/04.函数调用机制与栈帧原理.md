## 一、引言：函数调用背后发生了什么

### 1.1 一个简单的函数调用

```c
#include <stdio.h>

int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main() {
    int result = add(3, 4);
    printf("result = %d\n", result);
    return 0;
}
```

**疑惑**：当CPU执行 `add(3, 4)` 时，参数3和4是怎么传给add函数的？add函数如何知道执行完后要回到main的哪一行？局部变量sum存放在哪里？

**答案**：这一切都依赖于栈帧（Stack Frame）机制。每次函数调用，都会在栈上创建一个帧，保存参数、局部变量、返回地址等信息。函数返回时，栈帧被销毁，控制权回到调用者。

### 1.2 函数调用的全景视图

```
调用者(Caller)                被调用者(Callee)
    │                              │
    ├─ 准备参数（寄存器/栈）         │
    ├─ call指令                    │
    │   ├─ 压入返回地址              │
    │   └─ 跳转到函数入口 ──────────→├─ 函数序言(Prologue)
    │                              │   ├─ 保存旧RBP
    │                              │   ├─ 设置新RBP = RSP
    │                              │   └─ 分配局部变量空间
    │                              ├─ 函数体执行
    │                              │   ├─ 访问参数
    │                              │   ├─ 使用局部变量
    │                              │   └─ 计算返回值
    │                              ├─ 函数尾声(Epilogue)
    │                              │   ├─ 将返回值放入RAX
    │                              │   ├─ 恢复RSP和RBP
    │  ←───────────────────────────│   └─ ret（弹出返回地址并跳转）
    ├─ 获取返回值（从RAX）           │
    └─ 继续执行                     │
```

## 二、调用约定（Calling Convention）

### 2.1 什么是调用约定

调用约定定义了函数调用时的一系列规则：
- 参数如何传递（寄存器还是栈，从左到右还是从右到左）
- 谁负责清理栈上的参数
- 哪些寄存器由调用者保存，哪些由被调用者保存
- 返回值如何传递

### 2.2 x86-64 System V ABI（Linux/macOS）

```
参数传递顺序：
  整数/指针参数: RDI, RSI, RDX, RCX, R8, R9（前6个）
  浮点参数:     XMM0-XMM7（前8个）
  超出的参数:    通过栈传递（从右到左压栈）

返回值：
  整数/指针: RAX（128位用RAX:RDX）
  浮点:     XMM0（128位用XMM0:XMM1）

栈清理：调用者负责

Caller-saved寄存器（调用者保存）:
  RAX, RCX, RDX, RSI, RDI, R8-R11, XMM0-XMM15

Callee-saved寄存器（被调用者保存）:
  RBX, RBP, R12-R15
```

### 2.3 x86-64 Windows (Microsoft x64)

```
参数传递顺序：
  整数/指针: RCX, RDX, R8, R9（前4个）
  浮点:     XMM0-XMM3（前4个）
  
Shadow Space: 调用者必须在栈上预留32字节
  （即使参数在寄存器中传递，也要预留）
```

### 2.4 32位x86调用约定

```
cdecl（C默认）:
  - 参数从右到左压栈
  - 调用者清理栈
  - 返回值在EAX

stdcall（Windows API）:
  - 参数从右到左压栈
  - 被调用者清理栈
  - 返回值在EAX

fastcall:
  - 前两个参数通过ECX、EDX传递
  - 其余参数从右到左压栈
```

### 2.5 为什么从右到左压栈？

```c
// 为了支持可变参数函数
printf("hello %d %s", 42, "world");

// 从右到左压栈后：
// 栈顶 → "hello %d %s" (第一个参数，地址已知)
//         42
//         "world"
// 函数可以通过第一个参数（格式字符串）确定后续参数的数量和类型
```

## 三、栈帧的完整结构

### 3.1 典型的栈帧布局（x86-64）

```
高地址
+----------------------------------+
|     调用者的栈帧                   |
+----------------------------------+
|  第7个参数（如果有的话）           |  ← 超过6个的参数
+----------------------------------+
|  返回地址 (8字节)                 |  ← call指令压入
+----------------------------------+
|  旧的RBP (8字节)                 |  ← push rbp
+----------------------------------+ ← RBP（帧基址指针）
|  局部变量1                        |
|  局部变量2                        |
|  ...                             |
|  被调用者保存的寄存器              |
|  临时数据                         |
+----------------------------------+ ← RSP（栈顶指针）
低地址
```

### 3.2 RBP与RSP的关系

```
RBP (Frame Pointer / Base Pointer):
  - 指向当前栈帧的固定位置
  - 在函数执行过程中保持不变
  - 通过RBP的固定偏移访问参数和局部变量

RSP (Stack Pointer):
  - 始终指向栈顶
  - 随着push/pop操作而变化
  - sub rsp, N 分配空间; add rsp, N 释放空间

访问方式：
  局部变量:  [rbp - offset]
  函数参数:  [rbp + offset]（栈传递的参数）
  返回地址:  [rbp + 8]
  旧RBP:    [rbp]
```

### 3.3 省略帧指针（Frame Pointer Omission）

```bash
# gcc -O2 默认开启 -fomit-frame-pointer
# 不使用RBP作为帧指针，通过RSP的已知偏移量访问所有数据
# 好处：释放RBP寄存器用于其他用途
# 坏处：调试和栈回溯更困难

# 保留帧指针（推荐调试时使用）
gcc -fno-omit-frame-pointer -g program.c
```

## 四、函数调用的汇编级分析

### 4.1 完整的调用过程

```c
int callee(int a, int b, int c) {
    int x = a + b;
    int y = x + c;
    return y;
}

int caller() {
    int result = callee(1, 2, 3);
    return result;
}
```

编译后的汇编（gcc -O0, x86-64）：

```asm
caller:
    push   rbp                  ; 保存旧帧指针
    mov    rbp, rsp             ; 设置新帧指针
    sub    rsp, 16              ; 为局部变量分配空间
    
    ; 准备参数（通过寄存器）
    mov    edx, 3               ; 第3个参数 c = 3
    mov    esi, 2               ; 第2个参数 b = 2
    mov    edi, 1               ; 第1个参数 a = 1
    
    call   callee               ; 调用callee（压入返回地址并跳转）
    
    mov    DWORD PTR [rbp-4], eax  ; result = 返回值
    mov    eax, DWORD PTR [rbp-4]  ; 准备返回值
    leave                          ; mov rsp,rbp; pop rbp
    ret                            ; 返回

callee:
    push   rbp                  ; 保存调用者的帧指针
    mov    rbp, rsp             ; 设置新帧指针
    
    ; 将寄存器参数保存到栈上（debug模式）
    mov    DWORD PTR [rbp-20], edi  ; a = 1
    mov    DWORD PTR [rbp-24], esi  ; b = 2
    mov    DWORD PTR [rbp-28], edx  ; c = 3
    
    ; int x = a + b;
    mov    edx, DWORD PTR [rbp-20]
    mov    eax, DWORD PTR [rbp-24]
    add    eax, edx
    mov    DWORD PTR [rbp-4], eax   ; x = a + b
    
    ; int y = x + c;
    mov    edx, DWORD PTR [rbp-4]
    mov    eax, DWORD PTR [rbp-28]
    add    eax, edx
    mov    DWORD PTR [rbp-8], eax   ; y = x + c
    
    ; return y;
    mov    eax, DWORD PTR [rbp-8]   ; 返回值放入eax
    pop    rbp                       ; 恢复旧帧指针
    ret                              ; 返回（弹出返回地址并跳转）
```

### 4.2 call和ret指令的本质

```asm
; call target 等价于：
push   rip          ; 将下一条指令地址（返回地址）压栈
jmp    target       ; 跳转到目标函数

; ret 等价于：
pop    rip          ; 从栈中弹出返回地址到RIP
                    ; CPU自动跳转到该地址继续执行
```

### 4.3 函数序言与尾声的标准模式

```asm
; 序言（Prologue）— 标准形式
function_start:
    push   rbp           ; 1. 保存旧帧指针
    mov    rbp, rsp      ; 2. 建立新帧指针
    sub    rsp, N        ; 3. 分配局部变量空间
    ; （可选）push callee-saved寄存器

; 尾声（Epilogue）— 标准形式
function_end:
    ; （可选）pop callee-saved寄存器
    mov    rsp, rbp      ; 1. 释放局部变量空间
    pop    rbp           ; 2. 恢复旧帧指针
    ret                  ; 3. 返回
    
; leave指令 = mov rsp, rbp + pop rbp（两条指令合一）
```

## 五、参数传递机制

### 5.1 值传递

```c
void modify(int x) {
    x = 100;  // 修改的是副本，不影响原变量
}

int main() {
    int a = 42;
    modify(a);
    printf("a = %d\n", a);  // 仍然是42
    return 0;
}
```

### 5.2 地址传递（模拟引用传递）

```c
void modify_ptr(int *x) {
    *x = 100;  // 通过地址修改原变量
}

int main() {
    int a = 42;
    modify_ptr(&a);
    printf("a = %d\n", a);  // 100
    return 0;
}
```

### 5.3 大结构体的传递

```c
struct BigData {
    int array[1000];
};

// 值传递：整个结构体被复制到栈上（4000字节！）
void by_value(struct BigData data) {
    data.array[0] = 999;
}

// 指针传递：只传递8字节的指针
void by_pointer(struct BigData *data) {
    data->array[0] = 999;
}

// const指针传递：既高效又安全
void by_const_pointer(const struct BigData *data) {
    // data->array[0] = 999;  // 编译错误
    printf("%d\n", data->array[0]);
}
```

### 5.4 超过6个参数时的栈传递

```c
long func(long a, long b, long c, long d, long e, long f, long g, long h) {
    return a + b + c + d + e + f + g + h;
}

int main() {
    long result = func(1, 2, 3, 4, 5, 6, 7, 8);
    return 0;
}
```

```asm
main:
    ; 前6个参数通过寄存器传递
    mov    r9d, 6           ; 第6个参数 f
    mov    r8d, 5           ; 第5个参数 e
    mov    ecx, 4           ; 第4个参数 d
    mov    edx, 3           ; 第3个参数 c
    mov    esi, 2           ; 第2个参数 b
    mov    edi, 1           ; 第1个参数 a
    
    ; 第7、8个参数通过栈传递（从右到左）
    push   8                ; 第8个参数 h（先压栈）
    push   7                ; 第7个参数 g
    
    call   func
    add    rsp, 16          ; 调用者清理栈（2个参数 × 8字节）
```

## 六、返回值的传递机制

### 6.1 基本类型返回值

```c
int    return_int()    { return 42; }     // 通过EAX返回
long   return_long()   { return 42L; }    // 通过RAX返回
double return_double() { return 3.14; }   // 通过XMM0返回
```

### 6.2 大结构体返回值

```c
struct Big {
    long a, b, c, d, e;  // 40字节
};

struct Big create_big() {
    struct Big b = {1, 2, 3, 4, 5};
    return b;
}

int main() {
    struct Big b = create_big();
    return 0;
}
```

**疑惑**：大结构体不能放在寄存器中返回，如何处理？

**答案**：编译器使用"隐藏参数"技术：

```asm
; 编译器实际生成的代码等价于：
; void create_big(struct Big *__hidden_return) {
;     __hidden_return->a = 1;
;     __hidden_return->b = 2;
;     ...
; }

main:
    sub    rsp, 48              ; 在调用者栈上分配空间
    lea    rdi, [rsp]           ; 将空间地址作为隐藏的第一个参数
    call   create_big           ; create_big直接写入调用者的空间

create_big:
    ; rdi 指向调用者为返回值准备的空间
    mov    QWORD PTR [rdi],    1
    mov    QWORD PTR [rdi+8],  2
    mov    QWORD PTR [rdi+16], 3
    mov    QWORD PTR [rdi+24], 4
    mov    QWORD PTR [rdi+32], 5
    mov    rax, rdi              ; 返回指针
    ret
```

### 6.3 小结构体的寄存器优化

```c
struct Small {
    int x, y;  // 8字节，恰好一个寄存器
};

struct Small make_small() {
    struct Small s = {10, 20};
    return s;
}
// 编译器可能将整个结构体打包到RAX中返回
// 高32位 = y, 低32位 = x
```

## 七、局部变量的分配与生命周期

### 7.1 局部变量在栈上的分配

```c
void func() {
    int a = 10;      // [rbp-4]
    int b = 20;      // [rbp-8]
    char c = 'A';    // [rbp-9]（实际可能对齐到[rbp-12]）
    double d = 3.14; // [rbp-24]（8字节对齐）
}
```

编译器在函数序言中通过 `sub rsp, N` 一次性为所有局部变量分配空间。

### 7.2 变量的存储类别

```c
auto int a = 10;      // auto是默认的，通常省略。存储在栈上
static int b = 20;    // 存储在.data段，生命周期为整个程序
register int c = 30;  // 建议编译器放在寄存器中（现代编译器自动决定）
extern int d;         // 声明外部变量，不分配存储
```

### 7.3 局部变量的未初始化问题

```c
void dangerous() {
    int arr[100];  // 栈上分配，不初始化
    // arr中的值是上次使用这块栈空间时遗留的旧数据
    
    printf("arr[0] = %d\n", arr[0]);  // 随机值（UB）
}

void safe() {
    int arr[100] = {0};  // 全部初始化为0
    // 或者
    int arr2[100];
    memset(arr2, 0, sizeof(arr2));
}
```

### 7.4 复合字面量的生命周期

```c
// C99复合字面量
int *p = (int[]){1, 2, 3};  // 在函数内：生命周期同块作用域
                              // 在函数外：静态存储期

// 常见用法：临时数组作为函数参数
void process(int *data, int n);
process((int[]){10, 20, 30}, 3);
```

## 八、递归调用的栈帧分析

### 8.1 递归的栈帧累积

```c
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

int main() {
    int result = factorial(5);
    printf("5! = %d\n", result);
    return 0;
}
```

调用 `factorial(5)` 时的栈帧变化：

```
调用过程（栈向下增长）：

main栈帧
├── factorial(5)  n=5, 返回地址→main
│   ├── factorial(4)  n=4, 返回地址→factorial(5)
│   │   ├── factorial(3)  n=3, 返回地址→factorial(4)
│   │   │   ├── factorial(2)  n=2, 返回地址→factorial(3)
│   │   │   │   ├── factorial(1)  n=1, 返回1
│   │   │   │   └── 返回 2*1 = 2
│   │   │   └── 返回 3*2 = 6
│   │   └── 返回 4*6 = 24
│   └── 返回 5*24 = 120
└── result = 120

最大栈深度：5个栈帧同时存在
每个栈帧大小：约32-48字节
总栈消耗：约160-240字节
```

### 8.2 递归深度过大导致栈溢出

```c
// 计算fibonacci的递归版本
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}

// fib(40) 需要约 2^40 ≈ 10亿次调用
// 递归树的最大深度为40，但时间复杂度是指数级

// 迭代版本
int fib_iter(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
```

### 8.3 递归转迭代的通用方法

```c
// 使用显式栈模拟递归
typedef struct {
    int n;
    int state;      // 0: 初始, 1: 等待左子树, 2: 等待右子树
    int left_result;
} Frame;

int fib_explicit_stack(int n) {
    if (n <= 1) return n;
    
    Frame stack[100];
    int top = 0;
    int result = 0;
    
    stack[top].n = n;
    stack[top].state = 0;
    
    while (top >= 0) {
        Frame *f = &stack[top];
        
        if (f->n <= 1) {
            result = f->n;
            top--;
            continue;
        }
        
        if (f->state == 0) {
            f->state = 1;
            // "递归调用" fib(n-1)
            top++;
            stack[top].n = f->n - 1;
            stack[top].state = 0;
        } else if (f->state == 1) {
            f->left_result = result;
            f->state = 2;
            // "递归调用" fib(n-2)
            top++;
            stack[top].n = f->n - 2;
            stack[top].state = 0;
        } else {
            result = f->left_result + result;
            top--;
        }
    }
    
    return result;
}
```

## 九、尾调用优化（TCO）

### 9.1 什么是尾调用

```c
// 尾调用：函数的最后一个操作是调用另一个函数（或自身）
// 且不需要对返回值做任何额外处理

// 尾调用
int tail_factorial(int n, int acc) {
    if (n <= 1) return acc;
    return tail_factorial(n - 1, n * acc);  // 最后一个操作就是调用
}

// 非尾调用
int non_tail_factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // 调用后还需要乘以n
}
```

### 9.2 尾调用优化的原理

```
未优化的尾递归：每次调用创建新栈帧
main → tail_factorial(5, 1)
           → tail_factorial(4, 5)
                → tail_factorial(3, 20)
                     → tail_factorial(2, 60)
                          → tail_factorial(1, 120)

优化后：复用同一个栈帧
main → tail_factorial(5, 1)  // 修改参数，跳转到函数开头
       tail_factorial(4, 5)  // 同一个栈帧
       tail_factorial(3, 20)
       tail_factorial(2, 60)
       tail_factorial(1, 120) → 返回120
```

### 9.3 编译器的尾调用优化

```asm
; 优化前（每次调用用call）
tail_factorial:
    cmp    edi, 1
    jle    .return
    imul   esi, edi      ; acc *= n
    dec    edi            ; n--
    call   tail_factorial ; 创建新栈帧
    ret

; 优化后（用jmp替代call）
tail_factorial:
    cmp    edi, 1
    jle    .return
    imul   esi, edi      ; acc *= n
    dec    edi            ; n--
    jmp    tail_factorial ; 跳转，不创建新栈帧！
.return:
    mov    eax, esi
    ret
```

```bash
# 开启优化才会触发TCO
gcc -O2 program.c  # -O2或更高优化级别
```

### 9.4 C语言中TCO的限制

```c
// C标准不保证TCO，只是编译器优化
// 以下情况可能阻止TCO：
// 1. 函数内有VLA
// 2. 使用了alloca()
// 3. 调用后有清理代码（如释放资源）
// 4. 被调用函数的参数比调用者多
// 5. 需要进行类型转换

// 因此，在C中写递归算法时
// 不能完全依赖TCO，最好自行改写为迭代
```

## 十、可变参数函数的实现原理

### 10.1 va_list的使用

```c
#include <stdarg.h>

int sum(int count, ...) {
    va_list args;
    va_start(args, count);  // 初始化args，count是最后一个固定参数
    
    int total = 0;
    for (int i = 0; i < count; i++) {
        total += va_arg(args, int);  // 按类型读取下一个参数
    }
    
    va_end(args);  // 清理
    return total;
}

int main() {
    printf("sum = %d\n", sum(4, 10, 20, 30, 40));  // 100
    return 0;
}
```

### 10.2 底层实现原理

在x86-64 System V ABI下：

```c
// va_list 的实际结构（glibc/x86-64）
typedef struct {
    unsigned int gp_offset;     // 下一个整数寄存器参数的偏移
    unsigned int fp_offset;     // 下一个浮点寄存器参数的偏移
    void *overflow_arg_area;    // 栈上参数的指针
    void *reg_save_area;        // 寄存器保存区域的指针
} va_list[1];

// va_start 的工作：
// 1. 将所有可能传参的寄存器保存到reg_save_area
// 2. 设置gp_offset指向第一个可变参数
// 3. 设置overflow_arg_area指向栈上的额外参数

// va_arg 的工作：
// 1. 检查参数是否在寄存器保存区（gp_offset < 48）
//    是 → 从reg_save_area + gp_offset 读取，增加gp_offset
//    否 → 从overflow_arg_area 读取，增加overflow_arg_area
```

### 10.3 实现自己的printf

```c
#include <stdarg.h>
#include <stdio.h>
#include <string.h>

void my_printf(const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);
    
    while (*fmt) {
        if (*fmt == '%') {
            fmt++;
            switch (*fmt) {
                case 'd': {
                    int val = va_arg(args, int);
                    // 简化：用标准printf输出单个值
                    printf("%d", val);
                    break;
                }
                case 's': {
                    char *str = va_arg(args, char*);
                    fputs(str, stdout);
                    break;
                }
                case 'c': {
                    // char 被提升为 int
                    char c = (char)va_arg(args, int);
                    putchar(c);
                    break;
                }
                case '%':
                    putchar('%');
                    break;
                default:
                    putchar('%');
                    putchar(*fmt);
                    break;
            }
        } else {
            putchar(*fmt);
        }
        fmt++;
    }
    
    va_end(args);
}
```

### 10.4 可变参数的类型提升

```c
// 可变参数函数中，小类型会被提升：
// char/short → int  （整数提升）
// float → double    （默认参数提升）

int sum_chars(int count, ...) {
    va_list args;
    va_start(args, count);
    int total = 0;
    for (int i = 0; i < count; i++) {
        // 注意：必须用int而不是char来读取
        total += va_arg(args, int);  // 正确
        // total += va_arg(args, char);  // 未定义行为！
    }
    va_end(args);
    return total;
}
```

## 十一、函数指针与间接调用

### 11.1 直接调用 vs 间接调用

```asm
; 直接调用：目标地址在编译时确定
call   0x401234           ; 硬编码地址
; 或
call   function_name      ; 链接时确定地址

; 间接调用：目标地址在运行时确定
call   rax                ; 通过寄存器
call   QWORD PTR [rbp-8]  ; 通过内存中的值
```

### 11.2 间接调用的性能影响

```c
// 直接调用：CPU可以预测分支目标，流水线不中断
// 间接调用：分支预测困难，可能导致流水线冲刷

// 紧密循环中的函数指针调用可能比直接调用慢2-5倍
// 但在大多数场景下，这个开销微不足道

typedef int (*Operation)(int, int);
Operation op = add;

// 热循环中避免间接调用
for (int i = 0; i < 1000000; i++) {
    result += op(a, b);  // 间接调用，可能较慢
}

// 如果可能，将判断提到循环外
if (mode == ADD) {
    for (int i = 0; i < 1000000; i++) {
        result += add(a, b);  // 直接调用，可被内联
    }
}
```

## 十二、内联函数

### 12.1 inline关键字

```c
// C99引入inline
static inline int max(int a, int b) {
    return a > b ? a : b;
}

int main() {
    int x = max(3, 5);
    // 编译器可能将max的函数体直接插入到调用处
    // 等价于: int x = 3 > 5 ? 3 : 5;
    return 0;
}
```

### 12.2 内联的条件与限制

```c
// inline只是建议，编译器可以忽略
// 以下情况通常不会内联：
// 1. 函数体太大
// 2. 递归函数
// 3. 通过函数指针调用
// 4. 取了函数的地址
// 5. 编译优化级别为-O0

// 强制内联（GCC扩展）
static inline __attribute__((always_inline)) int forced_max(int a, int b) {
    return a > b ? a : b;
}

// 禁止内联（GCC扩展）
__attribute__((noinline)) int never_inline_func(int x) {
    return x * 2;
}
```

### 12.3 inline与宏的比较

```c
// 宏
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// 内联函数
static inline int max(int a, int b) {
    return a > b ? a : b;
}

// 宏的问题：
int x = 5, y = 3;
int result = MAX(x++, y++);  // x被增加两次！展开为 ((x++) > (y++) ? (x++) : (y++))

// 内联函数没有这个问题：
int result2 = max(x++, y++);  // 参数只求值一次

// 内联函数优于宏：
// 1. 类型安全
// 2. 参数只求值一次
// 3. 有自己的作用域
// 4. 可以设断点调试
```

## 十三、栈保护与安全机制

### 13.1 栈金丝雀（Stack Canary）

```c
// 编译器在栈帧中插入一个随机值（canary）
// 如果发生缓冲区溢出覆盖了canary，函数返回时检测到不一致并终止程序

void vulnerable(const char *input) {
    char buffer[64];
    // 编译器在buffer和返回地址之间插入canary
    
    // 栈布局：
    // [buffer(64B)] [canary(8B)] [saved RBP] [return address]
    
    strcpy(buffer, input);  // 溢出可能覆盖canary
    
    // 函数返回前检查canary
    // if (canary != original_canary) __stack_chk_fail();
}
```

```bash
# 启用栈保护
gcc -fstack-protector program.c         # 保护有char数组的函数
gcc -fstack-protector-all program.c     # 保护所有函数
gcc -fstack-protector-strong program.c  # 智能选择保护（推荐）
gcc -fno-stack-protector program.c      # 禁用栈保护
```

### 13.2 ASLR（地址空间布局随机化）

```c
#include <stdio.h>

int main() {
    int local;
    printf("栈变量地址: %p\n", &local);
    
    void *heap = malloc(100);
    printf("堆变量地址: %p\n", heap);
    
    printf("main地址:   %p\n", main);
    
    free(heap);
    return 0;
}

// 每次运行地址不同（ASLR开启时）：
// 运行1: 栈:0x7ffd1234  堆:0x555abc  main:0x55deed
// 运行2: 栈:0x7ffc5678  堆:0x555def  main:0x55dabc
```

### 13.3 DEP/NX位（数据执行保护）

```
将栈和堆标记为不可执行：
- 即使攻击者将shellcode注入到栈上
- 当CPU尝试执行栈上的代码时，会触发异常
- 需要硬件支持（NX bit / XD bit）

现代攻击方式（绕过NX）：
- ROP（Return-Oriented Programming）：利用现有代码段的gadget
- JOP（Jump-Oriented Programming）
```

### 13.4 RELRO（Relocation Read-Only）

```bash
# 编译选项
gcc -Wl,-z,relro,-z,now program.c

# Partial RELRO: .got 和部分.got.plt 只读
# Full RELRO:    整个.got 和 .got.plt 只读
# 防止攻击者覆盖GOT表项来劫持函数调用
```

## 十四、setjmp/longjmp非局部跳转

### 14.1 基本使用

```c
#include <setjmp.h>
#include <stdio.h>

jmp_buf env;

void deep_function() {
    printf("进入deep_function\n");
    longjmp(env, 42);  // 跳回setjmp的位置，返回值42
    printf("这行永远不会执行\n");
}

int main() {
    int val = setjmp(env);  // 第一次返回0
    
    if (val == 0) {
        printf("setjmp返回0，正常流程\n");
        deep_function();
    } else {
        printf("从longjmp返回，val = %d\n", val);
    }
    
    return 0;
}

// 输出:
// setjmp返回0，正常流程
// 进入deep_function
// 从longjmp返回，val = 42
```

### 14.2 原理：保存和恢复上下文

```c
// setjmp保存的内容（jmp_buf结构）：
// 1. 栈指针（RSP）
// 2. 帧指针（RBP）
// 3. 返回地址（RIP/PC）
// 4. Callee-saved寄存器（RBX, R12-R15）
// 5. 信号掩码（某些实现）

// longjmp恢复这些寄存器，效果等同于"跳回"到setjmp的位置

// 注意：longjmp不会释放中间函数的栈帧
// 也不会调用局部对象的析构函数（C++中更危险）
// 不会关闭打开的文件等资源
```

### 14.3 用setjmp/longjmp实现异常处理

```c
#include <setjmp.h>
#include <stdio.h>

#define TRY       if (setjmp(exception_env) == 0)
#define CATCH(e)  else if (exception_code == (e))
#define THROW(e)  do { exception_code = (e); longjmp(exception_env, 1); } while(0)

static jmp_buf exception_env;
static int exception_code;

enum { ERR_NONE, ERR_DIVIDE_BY_ZERO, ERR_OUT_OF_MEMORY };

int safe_divide(int a, int b) {
    if (b == 0) THROW(ERR_DIVIDE_BY_ZERO);
    return a / b;
}

int main() {
    TRY {
        int result = safe_divide(10, 0);
        printf("结果: %d\n", result);
    }
    CATCH(ERR_DIVIDE_BY_ZERO) {
        printf("捕获异常: 除以零\n");
    }
    
    return 0;
}
```

### 14.4 setjmp/longjmp的注意事项

```c
// 1. 调用longjmp后，setjmp所在函数中的非volatile局部变量值是不确定的
jmp_buf env;
int val = setjmp(env);
int x = 10;  // 非volatile
if (val == 0) {
    x = 20;
    longjmp(env, 1);
}
// x的值不确定！可能是10也可能是20

// 解决方案：使用volatile
volatile int x = 10;

// 2. 不能在setjmp所在的函数返回后调用longjmp
//    因为栈帧已经被销毁
```

## 十五、总结与面试高频问题

### 15.1 核心知识总结

```
函数调用机制全景图：

1. 调用约定
   ├── 参数传递: 寄存器优先（x86-64: RDI,RSI,RDX,RCX,R8,R9）
   ├── 返回值:   RAX（整数）, XMM0（浮点）
   └── 栈清理:   调用者负责（cdecl/System V）

2. 栈帧结构
   ├── 返回地址 → 函数参数 → 旧RBP → 局部变量
   ├── RBP: 帧基址（稳定锚点）
   └── RSP: 栈顶（动态变化）

3. 函数序言/尾声
   ├── Prologue: push rbp; mov rbp,rsp; sub rsp,N
   └── Epilogue: leave; ret

4. 高级主题
   ├── 递归: 栈帧累积，注意深度
   ├── 尾调用优化: jmp替代call，复用栈帧
   ├── 可变参数: va_list遍历寄存器+栈参数
   └── 安全机制: Canary, ASLR, NX, RELRO
```

### 15.2 面试高频问题

**Q1: 函数调用的开销有多大？**

```
直接调用的开销：
1. call指令:     保存返回地址（1-3个时钟周期）
2. 序言:         push rbp + mov rbp,rsp + sub rsp,N（3-5个周期）
3. 参数传递:     寄存器操作（0-2个周期）
4. 尾声:         leave + ret（3-5个周期）
总计约10-20个时钟周期

间接调用额外开销：
- 分支预测失败: 可能多10-20个周期
```

**Q2: 栈和堆分配的性能对比？**

```
栈分配: sub rsp, N → 1条指令，1个时钟周期
堆分配: malloc(N)  → 搜索空闲链表，可能触发系统调用
                     10-1000个时钟周期（取决于分配器和场景）

栈释放: add rsp, N 或 leave → 1条指令
堆释放: free(p)   → 更新空闲链表，可能合并相邻块
```

**Q3: 为什么递归可能很慢？**

```
1. 每次调用都创建栈帧（内存分配和初始化）
2. 频繁的函数调用和返回（call/ret的管理开销）
3. 大量数据在寄存器和栈之间来回搬运
4. 可能破坏CPU缓存的局部性
5. 如果递归过深，触发缓存缺失甚至栈溢出

优化方案：
- 尾递归 + 编译器优化
- 手动转迭代
- 使用显式栈（堆上分配，不受栈大小限制）
```

**Q4: 解释一下栈溢出攻击的原理？**

```
1. 攻击者向栈上的缓冲区写入超长数据
2. 溢出数据覆盖了返回地址
3. 函数返回时，跳转到攻击者指定的地址
4. 执行攻击者注入的代码（shellcode）

防御措施：
- 栈金丝雀(Canary): 检测溢出
- ASLR: 随机化地址，无法预测跳转目标
- NX位: 栈不可执行
- 安全编码: 使用strncpy代替strcpy
```
