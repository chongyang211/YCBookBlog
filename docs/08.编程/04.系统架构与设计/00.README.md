# 系统架构与设计系列

> 从设计模式到架构模式——当系统变大了，招式和纪律还够用吗

## 系列导读

设计模式解决的是**类与类之间的关系**，架构模式解决的是**模块与模块之间的边界**。本系列从单体分层出发，逐步深入到六边形架构、CQRS、事件驱动、微服务，最后回到 DDD 战略设计，形成从"代码设计"到"系统设计"的完整升级。


## 学习方法

本系列延续**疑惑→答疑→论证→结论**的教学模式：

1. **疑惑**：从系统性能瓶颈、维护成本爆炸等真实架构问题切入
2. **答疑**：给出架构层面的根本解法
3. **论证**：通过架构图、对比分析深入理解
4. **结论**：总结选型决策树，明确"什么时候用、什么时候不用"
