从你的输出来看，`adb` 启动失败，原因是 `Address already in use`，即 `adb` 的端口（默认是 `5037`）被占用了。以下是解决这个问题的步骤：

---

### **解决方法 1：终止占用端口的进程**

1. 查找占用 `5037` 端口的进程：
   ```bash
   lsof -i :5037
   ```
   输出示例：
   ```
   COMMAND   PID USER   FD   TYPE             DEVICE SIZE/OFF NODE NAME
   adb     12345 user   12u  IPv4 0x1234567890abcdef      0t0  TCP *:5037 (LISTEN)
   ```

2. 终止占用端口的进程：
   ```bash
   kill -9 <PID>
   ```
   将 `<PID>` 替换为实际的进程 ID（例如 `12345`）。

3. 重新启动 `adb`：
   ```bash
   adb start-server
   ```

---

### **解决方法 2：强制重启 `adb`**
1. 强制终止所有 `adb` 进程：
   ```bash
   adb kill-server
   ```

2. 重新启动 `adb`：
   ```bash
   adb start-server
   ```

---

### **解决方法 3：检查是否有其他 `adb` 实例在运行**
1. 检查是否有多个 `adb` 实例在运行：
   ```bash
   ps aux | grep adb
   ```

2. 如果发现有多个 `adb` 进程，终止它们：
   ```bash
   killall adb
   ```

3. 重新启动 `adb`：
   ```bash
   adb start-server
   ```

---

### **解决方法 4：更改 `adb` 端口**
如果 `5037` 端口被其他程序占用，可以尝试更改 `adb` 的端口。

1. 设置新的端口号（例如 `5038`）：
   ```bash
   export ADB_LOCAL_TRANSPORT_PORT=5038
   ```

2. 启动 `adb`：
   ```bash
   adb start-server
   ```

3. 检查 `adb` 是否正常运行：
   ```bash
   adb devices
   ```

---

### **解决方法 5：重启电脑**
如果以上方法都无法解决问题，可以尝试重启电脑，然后重新启动 `adb`。

---

### **总结**

以下是解决 `adb` 启动失败的步骤：
1. 终止占用 `5037` 端口的进程。
2. 强制重启 `adb`。
3. 检查是否有其他 `adb` 实例在运行。
4. 更改 `adb` 端口。
5. 重启电脑。

按照以上步骤操作后，`adb` 应该可以正常启动。如果问题仍然存在，请提供更多信息，我会进一步协助你解决问题！ 🚀
