## 3.1 扩展函数与属性

### 3.1.1 扩展函数语法

```kotlin
fun String.lastChar(): Char = this[length - 1]

"hello".lastChar()   // 'o'
```

看起来像给 `String` 加了个方法，实际上是**静态函数** + **`this` 参数**的语法糖。

### 3.1.2 静态派发本质

```kotlin
open class Animal
class Dog : Animal()

fun Animal.name() = "Animal"
fun Dog.name() = "Dog"

val a: Animal = Dog()
a.name()   // 输出 "Animal" —— 按声明类型分发！
```

**关键结论**：扩展函数是**静态派发**（按变量声明类型分发），不是虚方法（按运行时类型分发）。**它不参与多态**。

*[骨架占位：反编译看看——扩展函数就是一个带静态 `String receiver` 参数的 static 函数]*

### 3.1.3 扩展属性用法

```kotlin
val String.lastChar: Char
    get() = this[length - 1]
```

**限制**：扩展属性不能有 backing field，只能有 getter/setter。

### 3.1.4 综合案例与思考

*[骨架占位：给 Android `View` 加一批扩展函数——`View.dp`、`View.visible()`、`View.gone()`]*

## 3.2 Lambda与函数式

### 3.2.1 函数类型语法

```kotlin
val add: (Int, Int) -> Int = { a, b -> a + b }
val greet: () -> Unit = { println("Hi") }
val withReceiver: String.() -> Int = { length }
```

**核心**：`(A, B) -> R` 是一等类型，本质上是接口 `Function2<A, B, R>`。

### 3.2.2 高阶函数概念

**高阶函数** = 接受或返回函数的函数。

```kotlin
fun <T, R> Iterable<T>.myMap(transform: (T) -> R): List<R> {
    val result = mutableListOf<R>()
    for (item in this) result.add(transform(item))
    return result
}
```

### 3.2.3 inline函数意义

```kotlin
inline fun <T> Iterable<T>.myFilter(predicate: (T) -> Boolean): List<T> { ... }
```

`inline` 让高阶函数在调用点**代码展开**，Lambda 不再是对象分配。字节码原理见 [原理篇 4](../02.核心原理/04.inline与reified原理.md)。

**用法准则**：接受 Lambda 参数的高阶函数**建议 inline**；不接受 Lambda 的函数**不要 inline**（膨胀无收益）。

## 3.3 作用域函数深潜

### 3.3.1 五兄弟对比

| 函数 | 接收者引用 | 返回值 | 典型场景 |
|---|---|---|---|
| `let` | `it` | Lambda 结果 | 空安全链、局部改名 |
| `run` | `this` | Lambda 结果 | 对象配置 + 计算 |
| `with` | `this` | Lambda 结果 | 非扩展写法的 `run` |
| `apply` | `this` | 接收者本身 | 对象初始化建造 |
| `also` | `it` | 接收者本身 | 副作用（打印、日志） |

### 3.3.2 接收者与参数

**核心区分**：
- `this` 接收者：Lambda 内可以直接调用成员（`this.` 可省略）
- `it` 参数：Lambda 内像访问普通变量（可改名）

```kotlin
val ok = Config().apply {         // this
    debug = true
    timeout = 30
}

val length = "hello".let {         // it
    println(it)
    it.length
}
```

### 3.3.3 场景决策表

```
需要返回接收者本身吗？
├─ 是：需要用 this 简洁访问成员？
│    ├─ 是 → apply
│    └─ 否 → also
└─ 否：需要用 this 简洁访问成员？
     ├─ 是 → run（或 with）
     └─ 否 → let
```

## 3.4 空安全实战技巧

### 3.4.1 let链式空安全

```kotlin
user?.address?.city?.let { println("city=$it") }
```

只有 `user`、`address`、`city` 都非 null 时才执行 Lambda。

### 3.4.2 takeIf与takeUnless

```kotlin
val positive = x.takeIf { it > 0 }         // 满足则返回自身，否则 null
val nonBlank = str.takeUnless { it.isBlank() }
```

### 3.4.3 契约函数requireNotNull

```kotlin
fun send(msg: String?) {
    val notNull = requireNotNull(msg) { "msg 不能为 null" }
    // 这里 notNull 已经被智能转换为 String（非空）
}
```

**关键**：`requireNotNull` / `checkNotNull` 用 `contract` 让编译器识别为空断言。

## 3.5 DSL构建能力

### 3.5.1 DSL三大支柱

Kotlin DSL 靠 3 个语法支柱：

1. **尾随 Lambda**：花括号放函数外
2. **带接收者的 Lambda**：`T.() -> Unit`
3. **中缀函数**：`infix fun a.foo(b: B)` → `a foo b`

### 3.5.2 mini_html_DSL

```kotlin
fun html(block: Html.() -> Unit): Html = Html().apply(block)

class Html {
    fun body(block: Body.() -> Unit) { }
}

html {
    body {
        // ...
    }
}
```

### 3.5.3 DslMarker防作用域穿透

`@DslMarker` 注解可以防止嵌套 DSL 内部 Lambda 访问外层接收者，避免语义混淆。

## 3.6 协程初识

### 3.6.1 suspend关键字

```kotlin
suspend fun fetchUser(id: Long): User {
    delay(100)     // 挂起 100ms 但不阻塞线程
    return User(id, "K")
}
```

`suspend` 表示"可挂起"——不占用线程即可等待。字节码原理见 [原理篇 3](../02.核心原理/03.协程调度器原理.md)。

**规则**：`suspend fun` 只能在另一个 `suspend fun` 或协程构建器里调用。

### 3.6.2 launch与async

| 构建器 | 返回 | 用途 |
|---|---|---|
| `launch` | `Job` | 启动一个"发射后不管"的协程 |
| `async` | `Deferred<T>` | 启动一个"要拿返回值"的协程，用 `.await()` 获取 |

```kotlin
scope.launch {
    val user = fetchUser(1L)      // suspend 调用
    println(user)
}

val deferred = scope.async { fetchUser(2L) }
val result = deferred.await()
```

### 3.6.3 Dispatchers调度器

| 调度器 | 场景 |
|---|---|
| `Dispatchers.Main` | UI 线程（Android） |
| `Dispatchers.IO` | 网络/文件 IO 密集 |
| `Dispatchers.Default` | CPU 密集计算 |
| `Dispatchers.Unconfined` | 不切线程（很少用） |

```kotlin
val data = withContext(Dispatchers.IO) { httpFetch() }
```

### 3.6.4 结构化并发第一课

```kotlin
coroutineScope {
    val a = async { fetchA() }
    val b = async { fetchB() }
    a.await() + b.await()          // 出块时保证所有子协程完成或取消
}
```

**核心原则**：**每个协程都必须有一个明确的 scope**，避免 `GlobalScope` 泄漏。

## 3.7 与Java互操作

### 3.7.1 JvmStatic与JvmField

```kotlin
class Api {
    companion object {
        @JvmStatic
        fun of() = Api()
        
        @JvmField
        val TAG = "Api"
    }
}
```

Java 侧就能写 `Api.of()` 和 `Api.TAG`，而不是 `Api.Companion.of()`。

### 3.7.2 JvmOverloads

```kotlin
class HttpClient @JvmOverloads constructor(
    val timeout: Int = 30,
    val retry: Int = 3
)
```

生成多个 Java 侧的重载构造，抹平 Java 无默认参数的差距。

### 3.7.3 平台类型陷阱

Java 侧的 `String` 传给 Kotlin，类型被标为 `String!`——**既可能非空也可能可空**，Kotlin 不再帮你做静态检查。

*[骨架占位：解决方案：Java 侧加 `@Nullable` / `@NotNull` 注解]*

### 3.7.4 SAM转换

Java 单方法接口（如 `Runnable`、`Comparator`）可用 Lambda 直接构造：

```kotlin
Thread { println("run") }.start()    // 传 Lambda 就是 Runnable
```

**注意**：Kotlin 接口自身不支持 SAM，除非用 `fun interface` 声明（Kotlin 1.4+）。

## 3.10 新手陷阱Top5

| # | 陷阱 | 症状 | 正确姿势 |
|---|---|---|---|
| 1 | `inline` 过度或不当使用 | JAR 膨胀 / public inline 破坏 ABI | 只在接受 Lambda 的高阶函数上用 |
| 2 | `suspend` 不能在裸 Lambda 里用 | 编译报错 | Lambda 声明为 `suspend () -> Unit` |
| 3 | `launch` 未捕获异常 | 静默崩溃 | 用 `CoroutineExceptionHandler` 或 `try-catch` |
| 4 | 扩展函数被当多态 | 覆盖失败 | 记住"扩展是静态派发" |
| 5 | `companion object` 未加 `@JvmStatic` 让 Java 调用蛋疼 | Java 侧多一层 `.Companion.` | SDK 场景务必标 `@JvmStatic` |
