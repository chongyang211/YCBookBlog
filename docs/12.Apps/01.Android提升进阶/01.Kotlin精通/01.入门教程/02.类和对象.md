## 2.1 类的介绍

### 2.1.1 类的含义

类是一种用户自定义类型，用于封装**属性**（数据）与**行为**（函数）。Kotlin 类可以看作 Java 类的"精简升级版"——同样的语义，一半的代码。

```kotlin
class Person(val name: String, var age: Int)
```

这一行等价于 Java 的十几行 boilerplate（字段、构造、getter/setter），后面 2.10 节我们会亲眼看看它编译后的字节码。

### 2.1.2 Kotlin与Java差异

| 维度 | Java | Kotlin |
|---|---|---|
| 默认可继承 | 是（可 extends） | **否**（默认 final） |
| 默认可见性 | package-private | **public** |
| 字段与访问器 | 手写 getter/setter | 属性自带 |
| 单一继承 + 多接口 | 一致 | 一致 |
| 多构造 | 多个 `public XXX(...)` | 主构造 + 次构造 |
| 静态成员 | `static` 关键字 | `companion object` |

### 2.1.3 默认final的哲学

Kotlin 借鉴 Joshua Bloch《Effective Java》条款 17："要么设计好继承并写好文档，要么禁止继承"。所以默认给你 `final`——想继承请显式写 `open`。

*[骨架占位：与 Java 15 `sealed class` 演进方向对齐的分析]*

### 2.1.4 综合案例与思考

*[骨架占位：把一段 Java Bean 逐行迁移成 Kotlin，感受行数缩水]*

**思考**：为什么 Kotlin 把默认可见性从 Java 的 `package-private` 改成 `public`？

## 2.2 类定义与实例化

### 2.2.1 主构造函数

```kotlin
class Person(val name: String, var age: Int) {
    // 类体
}
```

**主构造**写在类头，参数可以直接加 `val/var` 变成属性（一石二鸟）。

### 2.2.2 次构造函数

```kotlin
class Person(val name: String) {
    var age: Int = 0
    constructor(name: String, age: Int) : this(name) {
        this.age = age
    }
}
```

**规则**：次构造必须直接或间接调用主构造。

### 2.2.3 init初始化块

```kotlin
class Person(val name: String) {
    init {
        require(name.isNotBlank()) { "name不能为空" }
    }
}
```

`init` 块在主构造后、次构造前执行；多个 `init` 按声明顺序运行。

### 2.2.4 无new关键字

```kotlin
val p = Person("Kotlin", 10)   // 没有 new
```

Kotlin 抛弃了 `new` —— 少一个关键字，语法更接近函数调用。

*[骨架占位：设计动机：让工厂函数、构造函数、单例访问器在调用侧写法一致]*

### 2.2.5 综合案例与思考

*[骨架占位：设计一个 `HttpRequest` 类，用主构造放必填参数，用次构造/默认参数放可选参数]*

**思考**：主构造 + 默认参数 vs 多个次构造，什么时候用哪种？

## 2.3 属性与字段

### 2.3.1 属性并非字段

**关键观念**：Kotlin 只有"属性"没有"字段"。`val name` 声明的是一个**属性**（自带 getter），编译器**可能**为它生成一个私有字段（叫 backing field）。

```kotlin
class Person {
    val fullName: String get() = "$firstName $lastName"   // 没有 backing field
    var firstName: String = ""                             // 有 backing field
    var lastName: String = ""
}
```

### 2.3.2 自定义getter

```kotlin
class Rect(val w: Int, val h: Int) {
    val area: Int
        get() = w * h
}
```

### 2.3.3 field幕后字段

`field` 是**只能**在自定义 getter/setter 里使用的关键字，指向属性的 backing field：

```kotlin
var value: Int = 0
    set(newValue) {
        require(newValue >= 0)
        field = newValue         // 用 field，不要用 value
    }
```

*[骨架占位：为什么不能用属性名自己给自己赋值 —— 会无限递归 setter]*

### 2.3.4 lateinit与lazy

| 修饰 | 适用 | 语义 |
|---|---|---|
| `lateinit var` | 非空引用类型 | 保证使用前会赋值，运行时检查 |
| `by lazy { }` | `val` | 首次访问时计算，之后缓存 |

```kotlin
lateinit var repo: UserRepo
val config: Config by lazy { loadConfig() }
```

*[骨架占位：`by lazy` 的三种线程模式，详见原理篇 5]*

### 2.3.5 综合案例与思考

*[骨架占位：`Temperature` 类——属性内部做单位换算，展示 field 与自定义 setter]*

**思考**：什么时候属性该有 backing field？编译器如何判断？

## 2.4 可见性修饰符

### 2.4.1 四种可见性

| 修饰符 | 类内成员 | 顶层声明 |
|---|---|---|
| `public`（默认） | 处处可见 | 处处可见 |
| `internal` | 同 module 可见 | 同 module 可见 |
| `protected` | 类内与子类 | ❌ 顶层不可用 |
| `private` | 类内 | 同文件 |

### 2.4.2 internal是什么

Kotlin 独有 —— 表示"同 module 可见"。**module** 定义为：一起编译的一组 Kotlin 文件（一个 Gradle module / IntelliJ module / Maven project）。

*[骨架占位：`internal` 在 Java 侧的调用体验（会看到名字被 mangle）]*

### 2.4.3 顶层可见性

Kotlin 允许**顶层函数**（不在任何类里的函数），它们的可见性规则参考类内成员。

### 2.4.4 综合案例与思考

*[骨架占位：SDK 设计场景——用 `internal` 让实现细节对外不可见]*

**思考**：为什么 Kotlin 抛弃了 Java 的 `package-private`？

## 2.5 特殊类家族

Kotlin 特殊类是**语言级糖**，每一个都对应一个具体的编译产物。

### 2.5.1 数据类data

```kotlin
data class User(val id: Long, val name: String)
```

编译器自动生成：`equals` / `hashCode` / `toString` / `copy` / `componentN`。详细字节码见 [原理篇 2](../02.核心原理/02.data类与equals原理.md)。

### 2.5.2 密封类sealed

```kotlin
sealed class Result<out T>
class Success<T>(val data: T) : Result<T>()
class Failure(val err: Throwable) : Result<Nothing>()
```

**核心特性**：所有直接子类必须在**同文件**（或同 module，Kotlin 1.5+）。让 `when` 表达式可穷尽性检查。

*[骨架占位：sealed class vs enum class 的取舍]*

### 2.5.3 枚举类enum

```kotlin
enum class Color(val hex: String) {
    RED("#FF0000"), GREEN("#00FF00"), BLUE("#0000FF");
    fun brightness() = hex.substring(1).toInt(16)
}
```

**Kotlin 枚举 = Java 枚举**，编译目标一致，但语法更整洁。

### 2.5.4 单例object

```kotlin
object AppConfig {
    var debug = false
    fun load() { }
}

AppConfig.debug = true       // 直接用类名访问
```

`object` 声明的类**只有一个实例**，编译成带 `INSTANCE` 静态字段的 final class。

### 2.5.5 伴生对象companion

```kotlin
class User private constructor(val id: Long) {
    companion object {
        fun of(id: Long) = User(id)
    }
}

val u = User.of(42)
```

**伴生对象是宿主类的一个内部单例**，用来放"类级"的工厂/常量。不是 Java 的 `static`——不加 `@JvmStatic` 时 Java 侧调用要写 `User.Companion.of(42)`。

### 2.5.6 内联类value

```kotlin
@JvmInline
value class UserId(val value: Long)
```

编译后运行时是**裸 Long**，不装箱、不多一次分配——用来给基础类型加上类型安全。**Kotlin 1.5 稳定**。

### 2.5.7 综合案例与思考

*[骨架占位：网络请求 `Result` 状态机：sealed + data class 组合建模]*

**思考**：`object`、`companion object`、`class ... { object ... }` 三者语义分别是什么？

## 2.6 继承与接口

### 2.6.1 open显式打开

```kotlin
open class Animal { open fun speak() { } }
class Dog : Animal() { override fun speak() { } }   // 冒号 + 圆括号=调用父类构造
```

**必须**加 `open` 才能被继承或 override —— 与 Java "默认可继承" 相反。

### 2.6.2 override强制标注

Kotlin 强制加 `override` 关键字，签名错误会立即报错，避免 Java 的 "静默失败"。

### 2.6.3 接口默认方法

```kotlin
interface Animal {
    fun speak()
    fun greet() = println("Hi")    // 默认方法
}
```

Kotlin 接口天然支持默认方法，甚至可以有属性（无 backing field）。

### 2.6.4 抽象类vs接口

| 需求 | 选择 |
|---|---|
| 需要状态（backing field） | 抽象类 |
| 多重实现能力 | 接口 |
| 二者都要 | 接口做行为、抽象类做骨架 |

### 2.6.5 综合案例与思考

*[骨架占位：多接口冲突 `super<A>.foo()` 消歧义]*

**思考**：Kotlin 为什么不允许多继承类，却允许实现多个带默认方法的接口？

## 2.7 委托机制

### 2.7.1 类委托by

```kotlin
interface Repo { fun save(): Int }
class RepoImpl : Repo { override fun save() = 1 }

class LoggingRepo(val delegate: Repo) : Repo by delegate {
    override fun save(): Int {
        println("before save")
        return delegate.save()
    }
}
```

`Repo by delegate` 表示"接口 Repo 的方法全部转发到 delegate"，可以选择性 override 加逻辑。**组合优于继承**的语言级支持。

### 2.7.2 属性委托by

```kotlin
val lazyName: String by lazy { computeName() }
var observed: String by Delegates.observable("init") { _, old, new ->
    println("$old -> $new")
}
```

### 2.7.3 内建委托家族

| 委托 | 用途 |
|---|---|
| `lazy` | 惰性求值 |
| `Delegates.observable` | 属性变化观察 |
| `Delegates.vetoable` | 属性变化否决 |
| `Delegates.notNull` | 无初始值的非空 val 变量 |
| `Map` 委托 | `val name: String by map` 从 Map 里取值 |

*[骨架占位：委托字节码原理详见原理篇 5]*

### 2.7.4 综合案例与思考

*[骨架占位：给一个 `Repository` 加日志与缓存两层装饰，全部用委托]*

## 2.8 泛型与型变

### 2.8.1 泛型类与函数

```kotlin
class Box<T>(val value: T)
fun <T> singletonList(item: T): List<T> = listOf(item)
```

### 2.8.2 in与out型变

| 关键字 | 含义 | 记忆 |
|---|---|---|
| `out T` | 协变（生产者） | 只**出**不进 |
| `in T` | 逆变（消费者） | 只**进**不出 |
| （无） | 不变 | 两者都可 |

```kotlin
interface Producer<out T> { fun produce(): T }        // 只返回 T
interface Consumer<in T>  { fun consume(t: T) }        // 只消费 T
```

### 2.8.3 reified具化类型

Kotlin 独有——**在 inline 函数里**能保留泛型类型：

```kotlin
inline fun <reified T> Any.isType(): Boolean = this is T

val ok = "hi".isType<String>()   // true
```

字节码原理见 [原理篇 4](../02.核心原理/04.inline与reified原理.md)。

### 2.8.4 where约束语法

```kotlin
fun <T> copyWhenGreater(list: List<T>, threshold: T): List<T>
    where T : CharSequence, T : Comparable<T> {
    return list.filter { it > threshold }
}
```

## 2.10 类和对象底层原理

### 2.10.1 属性编译成什么

一段 Kotlin：
```kotlin
class Person(val name: String, var age: Int)
```

用 `kotlinc -d out/` 编译后，`javap -p Person`：

```
public final class Person {
    private final java.lang.String name;
    private int age;
    public Person(java.lang.String, int);
    public final java.lang.String getName();
    public final int getAge();
    public final void setAge(int);
}
```

*[骨架占位：详细逐字段分析；`@NotNull` 参数校验注入]*

### 2.10.2 data类生成物

`data class User(val id: Long, val name: String)` 会生成：`equals` / `hashCode` / `toString` / `copy` / `component1` / `component2`。

*[骨架占位：javap 输出片段 + 每个方法的实现骨架]*

### 2.10.3 object的字节码

`object AppConfig { }` 生成一个 `final class AppConfig` + `public static final AppConfig INSTANCE`。

*[骨架占位：静态初始化时序、线程安全保证——通过类加载器 lock]*

### 2.10.4 委托的字节码

`class C : I by impl` 生成一个持有 `impl` 字段的类，接口每个方法都转发到 `impl`。

*[骨架占位：与 Java `Proxy` 的性能对比——委托是编译期生成，Proxy 是运行时生成]*

## 2.12 新手陷阱Top5

| # | 陷阱 | 症状 | 正确姿势 |
|---|---|---|---|
| 1 | `data class` 继承 | 继承 data class 破坏等价对称性 | data class 永远设为 final |
| 2 | `object` 与 `companion object` 混淆 | 想要静态方法但访问不到 | 类级用 companion，全局用 object |
| 3 | `lateinit` 未初始化访问 | `UninitializedPropertyAccessException` | `::prop.isInitialized` 先判断 |
| 4 | 构造顺序踩坑 | 主构造属性未初始化时 `init` 已运行 | 别在 init 依赖后声明的属性 |
| 5 | `open` 忘加导致无法 override | 子类 override 编译报错 | 有意为之的可继承点显式 `open` |
