# 加验流程（Identity Verification）

## 1. 背景

后端在 `recognizePalm` 返回时若携带 `verify_info.need_verify=true`，表示该用户需要额外身份核验（输入手机号后 4 位）。后端再通过 `verifyPalm` 校验 `verify_id + last4`，校验通过后才下发 `user_id + otc`。

适用模式：`Recognition` / `Hybrid` / `QREnrollment` 及其 `Host*` 版本共 7 个 Page，行为完全一致，由 `BaseCoordinator` 统一封装。

## 2. 端到端时序

```
Native (BaseCoordinator)                   Web (xxxPage.vue)
─────────────────────────                  ─────────────────
recognizePalm
  └─ need_verify=true
       │ enterIdentityVerification
       │   ├─ TTS: ENTER_THE_LAST_DIGITS
       │   ├─ stage = ENTER_MOBILE_REGISTRATION_REVERIFY
       │   ├─ 保存 verifyId
       │   └─ broadcast `xxx:identity_verification` ──► phase = identity_verification
       │                                                IdentityVerification 组件
       │                                                  ↓ user 输入 last4
       │                                                call('submitIdentityVerification', { last4 })
       │ ◄────────────────────────────────────────────
       │
       │ validateIdentityInput → doVerifyPalm
       │   ├─ resp.code == 0
       │   │    ├─ stage = REVERIFY_SUCCESS
       │   │    └─ notifyHostSuccess(user_id, otc) ──► xxx:success → phase = result_success
       │   │
       │   └─ resp.code != 0
       │        ├─ hostCode = mapVerifyErr(resp.code)
       │        ├─ if hostCode == 213: TTS CHECK_YOUR_PHONE_NUMBER
       │        └─ notifyFailure(hostCode, msg) ──► xxx:failure → phase = result_failure
       │                                            ↓ 倒计时
       │                                            onFailureDone 分流
```

## 3. 错误码映射（verifyPalm 专属）

| 后端 code | 上位机 code | 含义 | 用户可纠正 | 前端处理 |
| --- | --- | --- | --- | --- |
| 100038 | **213** `CODE_VERIFY_FAIL` | 手机尾号不匹配 | ✅ | 累加重试，回输入页 |
| 1000 | 213 `CODE_VERIFY_FAIL` | 参数错误（兜底归并） | ✅ | 同上 |
| 1010 | 302 `CODE_SERVICE_ERROR` | 服务异常 | ❌ | 仅展示失败页后回默认页 |
| 120017 / 120018 | 304 `CODE_BIZ_SERVICE_REJECTED` | OTC 服务拒绝 | ❌ | 同上；120018 透传 `biz_info` |
| 其他 | 302（兜底） | 未知业务码 | ❌ | 同上 |
| 网络/HTTP | 301 / 500（`toHostCode`） | 传输/解码失败 | ❌ | 同上 |

**关键原则**：只有映射为 `213` 的错误才表示"用户可纠正"，才播 `CHECK_YOUR_PHONE_NUMBER` 并由前端引导重试；其余错误属于不可纠正错误，不要误导用户。

## 4. 前端状态与分流

### 关键状态

```ts
const IDENTITY_RETRY_LIMIT = 3;
const IDENTITY_RETRYABLE_CODE = 213;

const phase = ref<Phase>('waiting');               // 包含 identity_verification / result_failure
const identityErrorCount = ref(0);                  // 仅 213 累加
const isFailureFromIdentity = ref(false);           // 加验上下文标志（失败页标题分流）
```

### failure 事件处理

```ts
'xxx:failure': ({ code }) => {
  if (phase.value === 'identity_verification') {
    isFailureFromIdentity.value = true;             // 标题用"核验失败"
    if (code === IDENTITY_RETRYABLE_CODE) {
      identityErrorCount.value += 1;                // 仅 213 走可重试分支
    }
  }
  phase.value = 'result_failure';
  startCountdown(RESULT_DISPLAY_SEC, onFailureDone);
}
```

### `onFailureDone` 三路分流

| 条件 | 行为 |
| --- | --- |
| `identityErrorCount === 0` | `reset()`：非加验场景 或 加验不可纠正错误 → 回默认页 |
| `identityErrorCount >= 3` | `cancelIdentityVerification(true)`：3 次尾号都错 → 终止会话 |
| `0 < identityErrorCount < 3` | 回 `identity_verification` 重试，`isFailureFromIdentity` 清零 |

### 失败页标题（i18n）

| 上下文 | key | 中文 |
| --- | --- | --- |
| 加验失败 | `xxx.identityFailed` | 核验失败 |
| 其他失败 | `xxx.recognizeFailed` / `enrollFailed` / `failed` | 识别失败 / 录入失败 / 失败 |

由父组件计算 `failureTitle` 后传入 `<ResultFailure :title="failureTitle" />`，组件本身保持无业务感知。

## 5. JSBridge 接口

| 方向 | 事件 / 方法 | 说明 |
| --- | --- | --- |
| Native → Web | `xxx:identity_verification` | 进入加验态，前端切到 `IdentityVerification` 组件 |
| Web → Native | `submitIdentityVerification({ last4 })` | 提交手机号后 4 位 |
| Web → Native | `cancelIdentityVerification({ exceededLimit })` | 用户取消 / 倒计时超时 / 重试超限 |
| Native → Web | `xxx:success` | 加验通过，下发 `user_id + otc` |
| Native → Web | `xxx:failure` | 加验失败，携带 `code/message` |

`xxx` 命名空间：`recognition` / `hybrid` / `qrEnrollment` / `hostRecognition` / `hostHybrid` / `hostEnrollment` / `hostQrEnrollment`。

## 6. Host 模式补充

Host 系列在 `commandReceived`（收到上位机新指令）时需清理残留 flag：

```ts
identityErrorCount.value = 0;
isFailureFromIdentity.value = false;
```

避免上一次 `result_failure` 倒计时未结束被新 wakeup 打断时，下一轮加验态继承了脏状态。

## 7. 重试次数策略

- 上限维护在前端 `IDENTITY_RETRY_LIMIT=3`，Native 无状态。
- 超限时前端调 `cancelIdentityVerification({ exceededLimit: true })`，Native 据此走 `notifyFailure(CODE_VERIFY_FAIL)` 终止会话，避免无限重试。
