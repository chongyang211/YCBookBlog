## 7.1 案例引入：5000 条数据的 ListView 卡顿

某工程师用 `ListModel` 存了 5000 条 CAN 报文数据，发现在 ARM A53 板上滑动到第 200 条左右 FPS 从 60 掉到 18：

```qml
ListModel { id: dataModel }
ListView {
    model: dataModel
    delegate: Rectangle { /* 每条 8 个子元素 */ }
}
// 问题：ListModel 把 5000 条数据全存在 JS 堆里，
//       delegate 在每次 model 变化时全部重建——5000 个 QML 对象树节点
```

**根因**：`ListModel` 每条数据是一个 `QObject` + JS 属性，5000 条 ≈ 5000 个 QObject —— 对象树爆炸。**修复**：换 `QAbstractListModel`（C++ 侧），让引擎只在视口内创建 delegate（~12 个而不是 5000 个）。

## 7.2 Model/View/Delegate 三角色

```
Model（数据）              View（视图）              Delegate（模板）
┌─────────────┐          ┌─────────────┐          ┌─────────────┐
│ Row 0: data │ ──提供──→│ ListView    │──渲染──→ │ Rectangle { │
│ Row 1: data │          │ GridView    │  N 份副本 │   Text {...}│
│ Row 2: ...  │          │ TableView   │          │ }           │
└─────────────┘          └─────────────┘          └─────────────┘
```

**三个角色的职责边界**：Model 只管数据存取、View 管视口滚动和 delegate 复用、Delegate 管单条数据的视觉呈现。

## 7.3 ListView 视口渲染原理

**核心机制——delegate 复用池**：

```
视口能显示 10 个 delegate → 引擎只创建 ~12 个 delegate（2 个 buffer）
  ↓ 用户向上滑动
滑出的 delegate 不销毁 → 回收到复用池 → 塞入新数据 → 从底部"冒出来"
  ↓
始终只有 ~12 个 QQuickItem 在对象树中 ← 内存 O(1) 而非 O(N)
```

```qml
ListView {
    model: 10000
    delegate: contactDelegate
    reuseItems: true           // Qt 5.15+ 必须开启
    cacheBuffer: 200           // 预渲染视口外 200px
    snapMode: ListView.SnapToItem
}
```

## 7.4 内置数据模型

| 模型 | 适用 | 特点 |
|---|---|---|
| `ListModel` | < 200 条静态数据 | JS 侧，每条一个 QObject，改数据用 `set()` / `append()` |
| `XmlListModel` | XML 数据源 | 声明式 XPath 查询 |
| `int` (数字) | 简单重复列表 | `model: 100` → delegate 的 `index` 从 0 到 99 |
| `Repeater` | 非滚动列表 | 无复用池，子元素全部创建 |
| `ObjectModel` | QML 对象列表 | 每条数据本身就是一个 QML Item |

## 7.5 C++ 自定义 QAbstractListModel

```cpp
class CanMessageModel : public QAbstractListModel {
    Q_OBJECT
public:
    enum Roles { Timestamp = Qt::UserRole + 1, CanId, Data };

    int rowCount(const QModelIndex& = {}) const override { return m_data.size(); }
    QVariant data(const QModelIndex& idx, int role) const override {
        const auto& msg = m_data[idx.row()];
        switch (role) {
            case Timestamp: return msg.timestamp;
            case CanId:     return msg.canId;
            case Data:      return msg.data;
        }
        return {};
    }
    QHash<int, QByteArray> roleNames() const override {
        return {{Timestamp,"timestamp"},{CanId,"canId"},{Data,"data"}};
    }

    // 分批追加
    void appendBatch(const QVector<CanMessage>& batch) {
        beginInsertRows({}, m_data.size(), m_data.size()+batch.size()-1);
        m_data.append(batch);
        endInsertRows();
    }

private:
    QVector<CanMessage> m_data;
};
```

```qml
ListView {
    model: CanMessageModel { }
    delegate: Text { text: timestamp + " | " + canId + " | " + data }
}
```

**对比**：

| 维度 | `ListModel` | `QAbstractListModel` |
|---|---|---|
| 数据存储 | JS 堆，QObject 每行 | C++ heap，紧凑内存布局 |
| 5000 行内存 | ~5 MB | ~500 KB |
| 批量插入 | 逐行 append | `beginInsertRows/endInsertRows` 一次通知 |
| 线程安全 | 仅 GUI 线程 | 可后台线程填充 |

## 7.6 综合实战：万级 CAN 报文实时列表

```qml
ListView {
    id: canView; anchors.fill: parent
    model: canModel; reuseItems: true; cacheBuffer: 300
    delegate: Row {
        spacing: 8
        Text { text: timestamp; font.pixelSize: 11; width: 80 }
        Text { text: "0x" + canId.toString(16); width: 60; font.bold: true }
        Text { text: data; elide: Text.ElideRight; width: 200 }
    }
}
// C++ 侧每 100ms 从 CAN 总线读取一批数据 → beginInsertRows → ListView 仅更新视口内的 delegate
```

## 7.7 速查表

| 概念 | 一句话 |
|---|---|
| **Model** | 数据来源——QML ListModel 或 C++ QAbstractListModel |
| **reuseItems** | ListView delegate 复用池开关——Qt 5.15+ 必开 |
| **cacheBuffer** | 视口外预渲染像素数——开大减少白块但增加内存 |
| **roleNames()** | C++ model 的角色名映射——QML 侧 `data` 变 `canId` 等 |
| **beginInsertRows** | 批量数据插入的信号——比逐行 append 快 100× |
