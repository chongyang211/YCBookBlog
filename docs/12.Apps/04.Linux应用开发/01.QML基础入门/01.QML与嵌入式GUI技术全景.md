# 01.QML与嵌入式GUI技术全景

> 从嵌入式 GUI 选型到 Qt/QML 架构全景——为什么 QML 是嵌入式交互界面的最优解？本文是整个专栏的"地图"。

## 1. 案例引入

### 1.1 一个真实的嵌入式 GUI 选型故事

```
某工业 HMI 触摸屏项目需求：
  硬件：ARM Cortex-A7, 512MB RAM, 无 GPU
  软件：Linux 3.10 内核, 无 X11/Wayland
  要求：60fps 仪表盘动画, < 2s 启动

团队尝试了三个方案：
  方案 A: C++ Widget + QPainter   → 启动 1.5s, CPU 绘制卡到 15fps
  方案 B: HTML5 + Chromium        → 启动 8s, 内存占用 380MB
  方案 C: QML + EGLFS + Qt Quick  → 启动 1.8s, 稳定 55fps, 内存 80MB

为什么 QML 能在这种受限设备上流畅运行？
答案就在 QML 的架构设计中——本章为你揭秘。
```

## 2. 嵌入式 GUI 技术选型全景

### 2.1 技术方案对比矩阵

```
┌────────────────┬──────────┬──────────┬──────────┬──────────┐
│     方案       │  启动速度 │  渲染性能 │  内存占用 │  开发效率 │
├────────────────┼──────────┼──────────┼──────────┼──────────┤
│ Qt Widget      │  快 ★★★  │ 中(C++绘制)│ 低 ★★★★★ │ 中 ★★★  │
│ Qt Quick(QML)  │  快 ★★★★ │ 高(硬件加速)│ 低 ★★★★  │ 高 ★★★★★ │
│ HTML5/Electron │  慢 ★    │ 低(浏览器) │ 高 ★     │ 高 ★★★★★ │
│ LVGL(C绘图)    │  快 ★★★★★│ 低(CPU)   │ 低 ★★★★★ │ 低 ★★   │
│ Flutter(嵌入式)│  中 ★★   │ 高(Impeller)│ 中 ★★★  │ 高 ★★★★ │
└────────────────┴──────────┴──────────┴──────────┴──────────┘

结论：Qt Quick(QML) 是嵌入式交互界面的"甜点方案"——
      开发效率接近 HTML5，性能接近原生 C++，资源占用远低于浏览器方案。
```

### 2.2 Qt 是什么，QML 又是什么

```
Qt 是什么？
  跨平台 C++ 应用框架，包含：
    QtCore      → 信号槽、事件循环、线程
    QtGui       → 2D 图形、字体、OpenGL
    QtWidgets   → 传统控件（QPushButton 等）
    QtQuick     → QML 引擎 + Scene Graph 渲染器 ← 本章主角
    QtNetwork   → 网络编程
    … 还有 20+ 个模块

QML 是什么？
  QML = Qt Meta-Object Language
  - 声明式 UI 语言（类 JSON/CSS 语法）
  - 内置 JavaScript 脚本引擎
  - 编译为 C++ 对象树，由 Scene Graph 渲染到 GPU/framebuffer
  - 关键区分：QML 是语言，Qt Quick 是渲染框架
```

### 2.3 Qt 框架分层架构

```
┌──────────────────────────────────────────────────────┐
│                  应用层                               │
│  ┌─────────────┐ ┌──────────────────┐                │
│  │ QML 界面层   │ │  C++ 业务逻辑层  │                │
│  └──────┬───────┘ └────────┬─────────┘                │
│         │                  │                          │
├─────────┴──────────────────┴──────────────────────────┤
│              Qt Quick 框架                            │
│  ┌─────────────┐ ┌─────────────┐ ┌──────────────┐   │
│  │ QML 引擎     │ │ Scene Graph │ │ Quick Items  │   │
│  │ 解析/执行     │ │ 渲染管线    │ │ 基础UI组件   │   │
│  └──────┬───────┘ └──────┬──────┘ └──────┬───────┘   │
├─────────┴────────────────┴───────────────┴───────────┤
│              Qt 核心库                                │
│  QtCore │ QtGui │ Qt Network │ Qt Multimedia │ ...   │
├──────────────────────────────────────────────────────┤
│              平台抽象层 (QPA)                          │
│  ┌──────────┐ ┌──────────┐ ┌────────┐ ┌─────────┐  │
│  │ XCB(X11)│ │ Wayland  │ │ EGLFS  │ │LinuxFB  │  │
│  │ 桌面     │ │ 桌面     │ │无窗口  │ │fb直接绘 │  │
│  └──────────┘ └──────────┘ └────────┘ └─────────┘  │
├──────────────────────────────────────────────────────┤
│              Linux / 硬件                               │
│  OpenGL ES / Vulkan / framebuffer / GPU / CPU          │
└──────────────────────────────────────────────────────┘
```

> **关键概念——QPA（Qt Platform Abstraction）**：
> QPA 是 Qt 和底层操作系统的桥梁。桌面 Linux 用 XCB/Wayland，
> 嵌入式设备用 EGLFS（无窗口系统，直接写 framebuffer + OpenGL ES）。
> 这就是为什么 QML 可以在"没有桌面环境"的嵌入式板子上跑。

## 3. QML 与其他 UI 方案的本质区别

### 3.1 QML vs HTML5：渲染不同

```
HTML5 的渲染：
  HTML → DOM Tree → CSS 解析 → Layout → Paint → Composite
  问题：DOM 操作 JS 驱动，Layout 是 CPU 密集型
  每次重排都需要浏览器引擎走完整管线

QML 的渲染：
  QML → 解析 → QObject Tree → Scene Graph → GPU Batch Render
  优势：
    1. QObject Tree 是 C++ 对象（不是字符串），操作更快
    2. Scene Graph 直接生成 GPU 渲染命令
    3. 只重绘变化的节点（脏区域机制）
    4. 批量提交（Reduce State Change）
```

### 3.2 QML vs Qt Widget：声明式 vs 命令式

```
Widget 方式（命令式）：
  QPushButton *btn = new QPushButton("点击", this);
  btn->setGeometry(100, 200, 120, 40);
  btn->setStyleSheet("background-color: blue");
  // 每一步显式"做"

QML 方式（声明式）：
  Button {
      x: 100; y: 200; width: 120; height: 40
      text: "点击"
      background: Rectangle { color: "blue" }
  }
  // 描述"最终长什么样"，引擎负责计算变化
```

## 4. 快速体验：第一个嵌入式 QML 应用

### 4.1 环境准备

```bash
# Ubuntu/Debian 开发环境
sudo apt install qt6-base-dev qt6-declarative-dev qtcreator cmake g++
# 交叉编译工具链（ARM）
sudo apt install gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf
```

### 4.2 Hello QML

```qml
// main.qml
import QtQuick

Window {
    width: 800; height: 480; visible: true; title: "Hello Embedded"

    Rectangle {
        anchors.centerIn: parent
        width: 200; height: 100; radius: 10
        color: "#42b883"
        Text {
            anchors.centerIn: parent
            text: "Hello QML!"; color: "white"; font.pixelSize: 24
        }
    }
}
```

### 4.3 main.cpp 入口

```cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>

int main(int argc, char *argv[]) {
    QGuiApplication app(argc, argv);
    QQmlApplicationEngine engine;
    engine.load(QUrl("qrc:/main.qml"));
    return app.exec();  // 进入事件循环
}
```

### 4.4 在嵌入式设备运行（无桌面环境）

```bash
# 开发板（ARM Linux，无 X11）：
./myapp -platform eglfs
# -platform eglfs：告诉 Qt 直接用 framebuffer + OpenGL ES 渲染
# 不需要 X11 服务器！
```

## 6. 速查表

| 概念 | 一句话解释 |
|---|---|
| QML | 声明式 UI 语言，编译为 C++ 对象树 |
| Qt Quick | QML 的渲染框架（含 Scene Graph） |
| Scene Graph | GPU 优化渲染管线，批处理绘制命令 |
| QPA | 平台抽象层，适配 X11/Wayland/EGLFS/framebuffer |
| EGLFS | 无窗口系统的嵌入式渲染后端 |
| QML Engine | 解析 QML 文本 → 创建 QObject 树 → 管理绑定 |
