## 6.1 案例引入

### 6.1.1 触摸穿透导致两个按钮同时响应

某 HMI 工程师在车机上做了一个弹出菜单，叠在导航地图上。点菜单里的"关闭"按钮，**菜单关掉了，但地图上被菜单挡住的"目的地"按钮也触发了**：

```qml
// 地图层
MapView {
    Button {
        id: destBtn
        text: "设目的地"; anchors.centerIn: parent
        onClicked: nav.startNavigate()
    }
}

// 弹窗层（覆盖在地图上）
Popup {
    id: menu
    modal: false          // ⚠️ 没设 modal: true——事件穿透
    Button {
        text: "关闭"
        onClicked: menu.close()  // 用户点这里 → 两个按钮都触发
    }
}
```

### 6.1.2 揭开谜底：mouse.accepted 与事件冒泡

QML 的事件系统默认行为：**事件从最上层的 Item 开始分发，如果上层不处理（`mouse.accepted = false`），事件向下层冒泡**。

```
Popup → Button(onClicked: 菜单关闭) → mouse.accepted = true ✓
                                      → 事件在此终止，不再向下

但上面的代码里，Popup modal: false → Popup 不拦截穿透事件
→ 事件的 dispatch 链同时包括了底下的 MapView 内的 Button
→ 两个 onClicked 同时触发
```

修复：

```qml
Popup {
    modal: true                     // ✅ 拦截穿透——Popup 外的所有事件被吞掉

    // 或手动控制
    MouseArea {
        anchors.fill: parent
        onPressed: mouse.accepted = true   // 吞掉事件，不传给下层
    }
}
```

## 6.2 鼠标事件系统

**MouseArea 的信号层级**：

```qml
MouseArea {
    anchors.fill: parent

    onClicked:    console.log("clicked")       // 按下+释放 在同一区域内
    onPressed:    console.log("pressed", mouse.x, mouse.y)
    onReleased:   console.log("released")
    onDoubleClicked: console.log("double")
    onPressAndHold:  console.log("长按")
    onPositionChanged: console.log("移动", mouse.x)
    onWheel:         console.log("滚轮", wheel.angleDelta.y)

    // hover 需要显式启用
    hoverEnabled: true
    onEntered:  console.log("鼠标进入")
    onExited:   console.log("鼠标离开")

    // 拖拽
    drag.target: draggableItem
    drag.axis: Drag.XAndYAxis
}
```

**`mouse.accepted` 控制事件传播**：

```qml
Item {
    MouseArea {
        anchors.fill: parent
        onClicked: {
            if (someCondition) mouse.accepted = true   // 吃掉事件，不向下传递
            else                mouse.accepted = false  // 放行，让下层 Item 处理
        }
    }
}
```

**事件传播链（C++ 底层）**：

```
QGuiApplication::notify(receiver, event)
  → QQuickWindow::sendEvent(item, event)
    → QQuickItem::childMouseEventFilter(item, event)
      → 从 z-order 最高的子元素开始递归分发
        → for each child (z-order 降序):
            if child.contains(event.pos) {
                event.setAccepted(false)
                sendEvent(child, event)
                if event.isAccepted() return  // ← 事件被上层吃掉，停止分发
            }
```

## 6.3 触摸事件与多点触控

嵌入式设备几乎全是触摸屏。QML 的 `MultiPointTouchArea` 处理多点触控：

```qml
MultiPointTouchArea {
    anchors.fill: parent
    minimumTouchPoints: 1
    maximumTouchPoints: 5

    touchPoints: [
        TouchPoint { id: tp1 },
        TouchPoint { id: tp2 },
        TouchPoint { id: tp3 }
    ]

    onPressed: (points) => {
        for (var i = 0; i < points.length; i++) {
            console.log("手指", points[i].pointId,
                        "按下于", points[i].x, points[i].y)
        }
    }

    onUpdated: (points) => {
        // 双指缩放示例
        if (points.length >= 2) {
            var dx = points[0].x - points[1].x
            var dy = points[0].y - points[1].y
            var dist = Math.sqrt(dx*dx + dy*dy)
            // dist 变化 → 缩放
        }
    }
}
```

**触摸事件的底层来源——evdev**：

```
触摸屏硬件 → Linux Input 子系统 → /dev/input/event*
  → Qt QPA (eglfs/evdevtouch) → QTouchEvent
    → QQuickWindow → MultiPointTouchArea / MouseArea
```

## 6.4 键盘事件与焦点管理

```qml
Item {
    focus: true               // 主动请求焦点
    Keys.onPressed: (event) => {
        if (event.key === Qt.Key_Return) console.log("回车")
        if (event.key === Qt.Key_Escape) console.log("ESC")
        event.accepted = true

    // FocusScope 创建独立的焦点域（车机双屏各管各的焦点）

        id: screen1
        TextInput { focus: true }
    }
}
```

## 6.6 综合实战：车机双屏事件隔离

车机场景：主驾屏（仪表盘）+ 副驾屏（娱乐导航），两个屏幕独立的触摸屏，但有物理按钮（方向盘按键）在两个屏上都可能响应。

```qml
ApplicationWindow {
    // FocusScope 隔离两个屏幕的焦点
    FocusScope { id: driverScope; /* 仪表盘 */ }
    FocusScope { id: passengerScope; /* 导航娱乐 */ }

    // 方向盘按键——全局快捷键
    Keys.onPressed: (event) => {
        if (event.key === Qt.Key_F1) {
            // 当前活动 FocusScope 的 Item 收到事件
            activeFocusItem.handleF1()
        }
    }

    // 两个触摸屏各自独立——不互相干扰
    MultiPointTouchArea { id: driverTouch; /* 主驾屏 */ }
    MultiPointTouchArea { id: passengerTouch; /* 副驾屏 */ }
}
```

## 6.7 本章新手陷阱

| # | 陷阱 | 修复 |
|---|---|---|
| 1 | `Popup modal: false` 导致事件穿透 | 弹出层必须 `modal: true` |
| 2 | `hoverEnabled` 默认 false——鼠标悬停无效 | 显式设置 `hoverEnabled: true` |
| 3 | `mouse.accepted` 忘设 → 事件一路穿透 | 确认处理完的事件设置 `accepted = true` |
| 4 | `FocusScope` 内外焦点混乱 | 每个独立的"屏"或"页面"用 FocusScope 包一层 |
| 5 | `MultiPointTouchArea` 和 `MouseArea` 冲突 | 同一区域二选一 |

## 6.8 训练题

**修复触摸穿透**：下面的弹出菜单点击"删除"按钮时，底下的 `ListView` 的 delegate 也响应了点击。修复它。

```qml
ListView {
    model: 100
    delegate: MouseArea { onClicked: console.log("item clicked") }
}

Popup {
    y: 100; width: 200; height: 150
    // 缺失什么？
    Button { text: "删除"; onClicked: popup.close() }
}
```

<details>
<summary>答案</summary>

`Popup` 未设置 `modal: true`。加上即可：

```qml
Popup {
    modal: true          // ← 修复
    y: 100
    ...
}
```
</details>

## 6.9 速查表

| 概念 | 一句话 |
|---|---|
| **MouseArea** | 鼠标/单点触摸事件处理——onClicked/onPressed/onReleased 等信号 |
| **mouse.accepted** | 控制事件是否继续向下传播——true = 停止冒泡 |
| **MultiPointTouchArea** | 多点触摸（双指缩放等）——touchPoints 数组管理所有触点 |
| **Keys** | 附加属性——onPressed/onReleased 监听物理键盘 |
| **FocusScope** | 创建独立焦点域——双屏车机各管各的 Tab 切换 |
| **PinchArea** | 双指捏合手势——onPinchUpdated 里取 scale/rotation |
| **hoverEnabled** | MouseArea 默认不跟踪鼠标悬停——必须显式开启 |

**核心哲学**：

```
QML 的事件系统 = z-order 降序分发 + mouse.accepted 冒泡终止 + FocusScope 焦点隔离。
三招搞定所有车机/嵌入式触摸场景。
```
