# 面试复盘

> 记录模板、失败分析、持续改进——不复盘的面了也白面

## 一、为什么要复盘——不记录等于白面

```text
一场面试 1 小时，你被问了 10+ 个技术问题。
如果你面完就翻篇——下一次面试，同样的问题你还是答不好。

复盘不是让你自责——是让你发现"我在哪里卡住了"，然后补上。
你面的每一场都是免费的实战训练。不复盘＝浪费了入场券。
```

---

## 二、面试后三十分钟的记录模板

```text
面试完趁着还在公司楼下（或者刚关掉视频），花 5 分钟填这个：

## 面试记录
- 公司/岗位：
- 日期：
- 面试官角色（TL/架构师/HR）：

## 技术问题清单
| # | 问题 | 我的回答 | 答对了吗？ | 标准答案/改进 |
|---|---|---|---|---|
| 1 | HashMap 和 ConcurrentHashMap 区别 | ... | ❌ | 查漏补缺 |
| 2 | 系统设计：设计一个短链系统 | ... | ✅ | 还不错 |

## 卡壳点记录
我卡在哪了？心跳加速的时候，面试官在问什么？
→ 例："动态规划那道题，我知道要用 DP 但推不出状态转移方程"

## 反问中学到的信息
我问了什么？面试官怎么回答的？
→ 能判断这个团队的技术氛围和工作强度

## 这次面试最大的收获（只写一条）
→ 例："以前没准备过消息队列的对比，这次面试官问了——回去补"
```

## 三、失败分析——不是"我不够好"

```text
面试失败有三种原因，只有一种是你需要担心的：

类型 1：技能不匹配（能补）
  → "他们要做云原生，我没学过 K8s"
  → 这不是你不行——这是方向不同。如果这是你想去的方向，去学。

类型 2：面试发挥失常（能练）
  → "考了一道常规算法题，紧张得脑子一片空白"
  → 多模拟面试。找人 mock interview，或者自己录自己讲。

类型 3：气场不合（不是你的问题）
  → "面试官全程看电脑，问的问题都很敷衍"
  → 这家公司不值得去——面试官的态度就是入职后同事的态度。
```

**拿到拒信不是审判——是一个数据点。** 10 次失败里可能有 5 次是方向不匹配、3 次发挥失常、2 次气场问题——真正需要你大补的只有 3 次。

## 四、持续改进——两周一个循环

```text
面试准备不是"下周要面了我今晚突击"——是长期积累。

两周循环：
  第 1 周：面 2-3 家 → 每次面完立刻复盘
  第 2 周：复盘弱项 → 针对性地学 → 找 mock interview 验证
  循环

不要一次性面 10 家——你会连续犯同样的错误，而且没时间在面试之间改进。
理想节奏：一周最多面 3 家，每两家之间隔一天用来复盘和补漏。
```

## 五、建立个人知识漏洞库

```text
每场面试后，更新你的三个列表：

1. 答得好的问题（自信区）
   → "Kafka 的 consumer group rebalance 过程"
   → 下次被问到类似的可以把这块经验讲得更精彩

2. 答得模糊的问题（灰色区）
   → "MySQL 的隔离级别和幻读的关系"
   → 看了但没理解透——这就是本周要啃的

3. 完全不会的问题（盲区）
   → "聊聊你对 Linux IO 模型的理解"
   → 这就是你的知识地图上的空白——标记下来，排期学习
```

**一个月后回看——你的盲区列表变短了，自信心变长了。** 这就是复盘的复利。

## 六、心态——面试是概率游戏

```text
一个技术岗平均收到 200 份简历，面 15 个人，发 3 个 offer，最后 1 人入职。
你拿到 offer 的概率大约 1/15。

这意味着：
  - 你需要面 15 家才能期望拿到 1 个 offer
  - 被拒 14 次不是"你不值钱"——是概率本来就如此
  - 你需要的不是"每一场都赢"，是"在拿到 offer 之前别崩"

把每一场面试当练习，把 offer 当 bonus——心态会好很多。
```

## 七、小结

```text
面试复盘三步法：

1. 立刻记录 → 面完后 30 分钟内填模板。靠大脑记=没记录
2. 分类归因 → 是技能不匹配、发挥失常、还是气场问题？只有技能问题需要你"改正"
3. 两周循环 → 面→复盘→补漏→再面。不要连续面不总结
```

**行动清单**：

- [ ] 把面试记录模板存到你的笔记软件里——下次面完直接打开填
- [ ] 回看最近 3 次面试被问到的算法题——哪类你最弱？本周集中练一类
- [ ] 找一个人帮你做一次 mock interview——你自己录下来听，你会发现很多口头禅和逻辑断层
