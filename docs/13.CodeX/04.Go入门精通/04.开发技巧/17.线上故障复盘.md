## 一、复盘方法论

每个事故按以下 7 步复盘：

1. **现象**：业务方看到了什么
2. **影响**：SLI 损失（延迟 / 错误率 / 可用率）
3. **时间线**：T0 触发 → T1 告警 → T2 介入 → T3 缓解 → T4 修复
4. **直接原因**：哪行代码 / 哪个配置 / 哪个外部依赖
5. **根本原因（5-Whys）**：为什么会有这行代码 / 配置 / 依赖
6. **修复**：临时措施 + 长期措施
7. **改进**：流程 / 工具 / 演练

## 二、事故 1：单条慢 SQL 拖垮服务（占位）

- **现象**：某接口 P99 从 50ms 涨到 5s，连锁打满线程池
- **直接原因**：新加的索引被回表，DBA 没参与评审
- **根因（5-Whys）**：
  1. 为什么慢？→ 索引未命中
  2. 为什么没命中？→ where 条件用了 `OR`
  3. 为什么用 OR？→ 业务方临时加需求
  4. 为什么没评审？→ 上线流程没强制 DBA 审核
  5. 为什么没强制？→ 流程缺失
- **改进**：
  - 短期：紧急索引 + SQL 重写
  - 长期：CI 加 `slow query lint`、所有 SQL 必须 DBA 审核

> **5 个事故的完整时间线、pprof / trace 截图、修复代码 diff 将在卷四定稿阶段补全。**

## 七、本卷总结：从"会写 Go"到"会救 Go"

经过卷四 17 篇的洗礼，你应当具备：

- ✅ 看到 panic 栈能 1 分钟定位代码行
- ✅ 看到 OOM 能用 pprof 抓 heap 找泄漏
- ✅ 看到延迟抖动能用 trace 找出 GC / 调度 / syscall 哪种瓶颈
- ✅ 看到事故能写 5-Whys 复盘文档
- ✅ 能给团队搭一套可观测性平台（slog + Prometheus + OTel）

至此，《现代 Go 由浅入深：从入门到工程精通》四卷本完结。

```
卷一《语法卷》  ✅ 你能读懂任何 Go 代码 / 能写 200-500 行的小工具
卷二《工程卷》  ✅ 你能独立写一个 5000-10000 行的后端系统
卷三《底层卷》  ✅ 你能在 Go 源码层面给团队做技术分享
卷四《实战卷》  ✅ 你能上线、定位 OOM / 死锁 / GC 抖动 / goroutine 泄漏
```

恭喜你完成这场 8 个月的旅程。
