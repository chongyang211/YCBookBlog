# 00.JS 专栏写作模板

> 本文件用于规范《JavaScript 核心原理深度专栏》全 16 篇的统一写作风格。
> **每写一篇新文章前，请先对照本模板检查骨架是否齐全。**

---

## 一、文件命名与编号

| 要素 | 规则 |
|---|---|
| **文件名** | `NN.标题（不超过20个汉字）.md` |
| **编号 NN** | 两位数，从 01 至 16，全册连续编号 |
| **标题风格** | 动宾落点，避免空泛（❌ "JavaScript 引擎" → ✅ "引擎执行管线全景"） |
| **二级/三级标题** | **最少 4 字，最多 8 字**，同级标题对仗工整 |

---

## 二、骨架结构（10 章法）

每篇文章必须包含以下 10 章，缺一不可：

```
1. 案例引入        ← 真实线上 BUG / 反直觉代码片段，制造悬念
2. 架构概览        ← 一张总图 + 「为什么这么切」的反向论证
3~9. 核心原理拆解   ← 7 章，每章一个独立子主题，章内 3~8 节
   每章至少包含: 代码/ASCII 结构图/表格 + 「疑惑—论证—结论」段
10. 综合案例串讲   ← 必须回扣第 1 章，逐条回答所有疑问
   并升华 3~4 条「设计哲学」
```

**核心原则**：第 1 章埋的所有疑问，第 10 章必须**全部回答**。中间章节是"取证过程"。

## 四、写作风格红线

### 4.1 语气与人称

- 用 **「我们」** 不用「你/笔者」——拉近距离
- 句末**避免「了、哦、呢、嘛」**等弱化语气词
- 关键结论用 `**加粗**`，给读者标靶

### 4.2 论证模式（重点）

每个核心原理点必须按 **「疑惑 → 论证 → 结论」** 三段式展开：

```markdown
**疑惑**：为什么 setTimeout(fn, 0) 在浏览器里最少要等 4ms？

**论证**：
1. HTML 规范 §8.6 规定：嵌套层级 ≥ 5 时，最小超时固定为 4ms
2. 这不是 V8 的限制，是浏览器渲染引擎的设计——保证事件循环不被密集的 0ms 定时器饿死
3. Chrome DevTools Performance 面板实测：第 1 次 setTimeout(fn, 0) 延迟 ≈ 1ms，
   第 6 次起稳定在 4.7ms（含调用开销）
4. Node.js 里 setTimeout(fn, 0) 最小 1ms（libuv），不受此规则约束——
   所以同一段代码在浏览器和 Node 里行为不同

**结论**：setTimeout(fn, 0) 的延迟不是"尽可能快"，而是浏览器为了防饿死引入的
「夹持」机制。需要更精确的微任务调度应优先考虑 queueMicrotask 或 Promise。
```

**严禁**直接抛结论（"setTimeout 最少 4ms 是为了性能"）——读者要的是**推导过程**。

### 4.3 图示要求

- 对象内存结构、执行流程、状态机 — 必须配 **ASCII 图**（用 Unicode 框线 ┌─┐│└─┘）
- 多分支决策 — 用 **mermaid 流程图**
- 横向对比 ≥ 3 项 — 用表格
- **每个核心子章节至少有 1 个图或表**

### 4.4 代码片段

- JS 代码必须可运行（ES2022 基线，Chrome ≥ 110 / Node ≥ 18）
- **标注输出** `// → "expected output"` ——读者不用实际跑代码也能跟上
- 注释用中文，贴在关键行**右侧或上方**
- 单段代码 **不超过 50 行**，超过就拆
- 涉及 V8 行为时，标注验证方式（如 `--allow-natives-syntax` / `%DebugPrint`）
- **刻意构造「bad」代码再修复**：先给出会触发 bug 的写法，再给出修复后的写法——读者看到对比才有体感

### 4.5 融合写作策略（本专栏特有）

因为每篇融合了 3 篇当量的知识密度，需要注意：

| 策略 | 说明 |
|---|---|
| **主题递进** | 7 个原理章之间必须有一条「主线」串联，不能是离散拼盘 |
| **交叉索引** | A 章原理在 B 章用上时，明确写出 `（我们在 §3.2 讲过...）` |
| **删繁就简** | 每个子原理给最精炼的推导，不堆砌所有细节——附「进一步阅读」链接即可 |
| **一图串三题** | 能用一张图同时解释 A/B/C 三个子原理时，优先合并 |

## 五、综合案例（第 10 章）三件套

| 子节 | 内容 | 示例 |
|---|---|---|
| **10.1 案例真相揭晓** | 逐条回答第 1 章的疑问 ①②③④⑤⑥⑦ | "回到那个循环里 var 输出的诡异日志，现在能逐条作答了..." |
| **10.2 一个 X 的一生** | 把核心实体的完整生命周期串成一棵树 | "`const fn = () => { const a = 1; return () => a; }` 这一行从 V8 解析到 GC 回收的完整旅程" |
| **10.3 设计哲学回扣** | 升华 3~4 条跨篇适用的设计原则 | "惰性求值 / 不可变优先 / 宿主抽象 / 渐进增强" |
| **10.4 速查表** | 一张可截图保存的总结表 | 事件循环阶段-来源-优先级矩阵 / Proxy 13 个 trap 速查 / 模块双轨互操作全景 |

## 六、章节自检清单

写完一篇后，逐条对照：

- [ ] 第 1 章是**真实代码**吗？（不是教科书例子，最好来自线上 BUG / StackOverflow 高票问题）
- [ ] 第 1 章末尾是否列出了 **5~7 个待解答的疑问**？
- [ ] 中间 7 章每章是否有 **「疑惑—论证—结论」段**？
- [ ] 中间 7 章每章是否至少有 **1 个代码片段 / ASCII 图 / 表格**？
- [ ] 中间 7 章是否有一条**主题递进主线**（不是拼盘）？
- [ ] 第 10.1 节是否**逐条**回答了第 1 章的每一个疑问？
- [ ] 第 10.2 节是否串起本篇 **80% 以上**的知识点？
- [ ] 第 10.3 节是否提炼出 3~4 条**可迁移的设计哲学**？
- [ ] 全篇标题是否动宾落点，二级标题是否对仗工整？
- [ ] 是否过渡到下一篇？（末尾写 "下一篇我们顺着 XXX 这条线，进入 N+1 篇《XXX》"）

## 七、篇幅与章节参考

| 项 | 推荐区间 |
|---|---|
| 总章数 | **10 章（固定）** |
| 每章子节数 | 3~8 节 |
| 总字数 | 1.5~2.5 万字 |
| 总行数 | 1200~1800 行（含代码与图） |
| 代码 / 图 / 表占比 | 30%~40% |
| 单篇建议写作周期 | 2~4 周 |

## 八、写作前置 SOP

```mermaid
flowchart LR
    A[选题] --> B[找一段真实 JS 代码<br/>作为开篇案例]
    B --> C[列出 5~7 个疑问<br/>= 中间章节的提纲]
    C --> D[确定 7 个原理章<br/>的主题递进主线]
    D --> E[按「疑惑→论证→结论」<br/>填充每一节]
    E --> F[第 10 章逐一回扣案例<br/>升华设计哲学]
    F --> G[自检清单逐项过]
    G --> H[更新 README 进度状态]
```

## 九、JS 专属要求（区别于 C++ 专栏）

| 要求 | 说明 |
|---|---|
| **V8 内部视角** | 凡涉及对象/闭包/数组/GC，有条件的给出 V8 源码对应文件与函数名（如 `src/objects/js-objects.h`），或用 `%DebugPrint` / `--allow-natives-syntax` 验证 |
| **ECMA-262 规范对照** | 涉及类型转换/==/Promise/模块等显式行为时，标注对应规范条款（如 ECMA-262 §7.2.15） |
| **Chrome DevTools 验证** | 渲染/性能/内存相关结论，用 Performance 面板/Memory 面板/Console 截图佐证 |
| **Node vs 浏览器差异** | 涉及事件循环/定时器/Stream/模块等行为时，必须对比 Node.js 和浏览器的不同表现 |
| **标准演进标注** | 标注 ES6/ES2017/ES2020/ES2022 等引入版本及 TC39 Stage |
| **跨端注意** | 涉及 Worker/WebSocket/Storage 等 API 时，标注在浏览器/Node/React Native/小程序各端的可用性 |
| **增量版本提示** | 如果旧版 12 篇中有同名或同主题文章，在章节开头标注 "从旧版《XX》的第 Y 章深化而来" |

## 十、篇间衔接规范

每篇结尾必须包含：

```markdown
---

**下一步**：解决了「XXX 是怎么 YYY 的」之后，我们进入「ZZZ」——[NN+1.标题](NN+1.标题.md)。
```

每篇开头（第 1 章前）建议包含：

```markdown
> 📍 上接第 NN-1 篇《XXX》。我们知道了 AAA 和 BBB。本文要回答的下一个问题是：CCC 是怎么实现的？
```
