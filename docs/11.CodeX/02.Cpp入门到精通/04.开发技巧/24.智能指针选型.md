# 第28章：智能指针选型

## 问题现场

```cpp
// 这段代码能跑——但内存泄漏、double-free 风险全有
MyClass* p = new MyClass();
someFunc(p);    // 该谁 delete？
delete p;       // 万一 someFunc 已经删了 → double-free
```

## 决策树

```
这个对象有唯一的拥有者吗？
├─ 是 → std::unique_ptr       （99% 的情况选它）
├─ 否 → 有多个拥有者吗？
│        ├─ 是 → std::shared_ptr  （引用计数）
│        └─ 否 → 你搞错了，重新设计
└─ 需要打破 shared_ptr 循环引用？
     └─ 是 → std::weak_ptr
```

## 方案对比

| 类型 | 所有权 | 拷贝 | 开销 | 一句话 |
|------|--------|------|------|-------|
| `unique_ptr` | 独占 | 不可拷贝，可 move | 零开销 | **新的 `T*`** |
| `shared_ptr` | 共享 | 引用计数 | 16B 控制块 | **慎用** |
| `weak_ptr` | 观察 | 不增加计数 | 同 shared | 打破循环 |

## 常见陷阱

```cpp
// ❌ 用裸指针构造 shared_ptr——两个控制块导致 double-free
auto* raw = new int(42);
std::shared_ptr<int> a(raw);
std::shared_ptr<int> b(raw);  // 两个独立的引用计数！

// ✅ 用 make_shared / make_unique
auto a = std::make_shared<int>(42);
auto b = a;  // 共享同一控制块

// ❌ shared_ptr 循环引用 → 永不释放
struct Node { std::shared_ptr<Node> next; };
// ✅ 改为 weak_ptr
struct Node { std::weak_ptr<Node> next; };
```

## 精简版速查

> **口诀**：默认 `unique_ptr`，共享才用 `shared_ptr`，打破循环用 `weak_ptr`。永远用 `make_*` 而非 `new`。

```cpp
auto p = std::make_unique<MyClass>();     // 首选
auto s = std::make_shared<MyClass>();     // 多拥有者时
auto w = std::weak_ptr<MyClass>(s);       // 打破循环
```
