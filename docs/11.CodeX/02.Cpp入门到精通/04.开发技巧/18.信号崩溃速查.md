# 第20章：信号崩溃速查

## 问题现场

```cpp
// 程序突然死掉，dmesg 看到一行：
// a.out[12345]: segfault at 0 ip 00007f... sp 00007f... error 4 in a.out
```

## 根因

Linux 内核通过**信号(Signal)**通知进程异常，C++ 崩溃本质是收到了某个信号。

## 信号对照表

| 信号 | 编号 | 典型原因 | 必查 |
|------|------|---------|------|
| `SIGSEGV` | 11 | 空指针解引用、栈溢出、写只读内存 | `bt` 看调用栈 |
| `SIGBUS` | 10 | 未对齐访问、mmap 失败后读写 | `si_code` 区分类型 |
| `SIGABRT` | 6 | `assert` 失败、`abort()`、double-free | 查 abort 原因 |
| `SIGFPE` | 8 | 整数除0、浮点异常 | 检查除法/取模 |
| `SIGILL` | 4 | 非法指令、CPU 不支持当前指令集 | `-march=native` 问题 |

## 快速定位三步法

```bash
# 1. 开 core dump
ulimit -c unlimited

# 2. 用 gdb 分析 core
gdb ./a.out core
(gdb) bt full        # 崩溃调用栈
(gdb) info registers  # CPU 状态
(gdb) frame 0        # 切到崩溃帧

# 3. 查 si_code 判断具体原因
(gdb) p $_siginfo.si_code
# SEGV_MAPERR(1) = 访问未映射内存
# SEGV_ACCERR(2) = 权限不足
```

## 方案对比

| 方案 | 命令/工具 | 适用 |
|------|----------|------|
| 看信号 | `dmesg \| tail` | 知道"死于什么" |
| 抓现场 | `ulimit -c` + gdb | 事后分析 |
| 实时调试 | `gdb --args ./a.out` | 能复现的 bug |
| 快速定位 | AddressSanitizer | 内存问题首选 |

## 精简版速查

> **口诀**：segfault 查空指针，bus error 查对齐，abort 查断言。开 core dump 是第一步。

```bash
ulimit -c unlimited && ./a.out && gdb ./a.out core -batch -ex "bt full"
```
