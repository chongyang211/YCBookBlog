# 第23章：Core Dump 破案

## 问题现场

线上程序崩溃后重启，日志只说了"exited with signal 11"。没有堆栈，没有变量值——怎么办？

→ **Core Dump**：崩溃瞬间把整个进程的内存镜像保存成文件。

## 开启 Core Dump

```bash
# ① 取消大小限制
ulimit -c unlimited

# ② 指定 core 文件路径（不设置会生成在当前目录或 systemd 接管）
echo "/tmp/core-%e-%p-%t" | sudo tee /proc/sys/kernel/core_pattern
# %e=程序名 %p=pid %t=时间戳

# ③ 确认
cat /proc/sys/kernel/core_pattern
```

## 破案三步法

```bash
# 1. 加载 core
gdb ./a.out /tmp/core-a.out-12345-1718456789

# 2. 看崩溃点
(gdb) bt full           # 完整调用栈 + 每帧局部变量
(gdb) info registers    # 看 rip 指向哪条指令

# 3. 查具体变量
(gdb) frame 2           # 切到第2帧（比如业务逻辑层）
(gdb) info locals       # 这帧的所有局部变量
(gdb) p ptr->field      # 打印对象成员
```

## 典型案例

```cpp
// coredump 显示：
// #0 0x00007f... in memcpy () from /lib/libc.so.6
// #1 0x000055... in Data::copy (this=0x0, ...)  ← this=0x0！
// → 空指针调成员函数，memcpy 的 dest 是 null

// 修复前：obj->copy(buf);  // obj 可能是 nullptr
// 修复后：if (obj) obj->copy(buf);
```

## 常见坑

| 现象 | 原因 | 解决 |
|------|------|------|
| core 文件找不到 | systemd 接管了 | 改 `/proc/sys/kernel/core_pattern` |
| `bt` 只有 1 帧 | 编译没加 `-g` | 重编译加 `-g` |
| 变量值显示 `optimized out` | O2 优化掉了 | 调试时用 `-O0` |
| core 文件 0 字节 | 磁盘满或 ulimit 为 0 | `ulimit -c unlimited` |

## 精简版速查

> **口诀**：`ulimit -c unlimited` 开 core → `gdb bin core` 看 `bt full` → `frame N` 查业务逻辑。

```bash
ulimit -c unlimited && ./a.out 2>&1
[ $? -ne 0 ] && gdb ./a.out core -batch -ex "bt full"
```
