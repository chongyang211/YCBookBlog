# 第22章：GDB/LLDB 十命令速查

## 问题现场

程序崩了，没有 core dump，只能重现调试。GDB 命令太多记不住——其实10条就够了。

## GDB vs LLDB 十命令对照

| 场景 | GDB | LLDB |
|------|-----|------|
| 启动调试 | `gdb --args ./a.out arg1` | `lldb -- ./a.out arg1` |
| 设断点 | `b func` `b file.cpp:42` | `b func` `b file.cpp:42` |
| 运行 | `r` | `r` |
| 单步 | `n`(next) `s`(step in) | `n` `s` |
| 看栈 | `bt` | `bt` |
| 切帧 | `frame 3` | `frame select 3` |
| 看变量 | `p var` | `p var` / `v var` |
| 看内存 | `x/16x addr` | `memory read addr` |
| 条件断点 | `b 42 if x>5` | `b 42` `condition 1 x>5` |
| 继续 | `c` | `c` |

## 三种最常用组合

```bash
# 组合1：崩溃现场（core dump）
gdb ./a.out core
(gdb) bt full          # 完整调用栈
(gdb) frame 0          # 切到崩溃点
(gdb) info locals      # 局部变量

# 组合2：实时调试
gdb --args ./a.out
(gdb) b main           # 断点在 main
(gdb) r                # 跑
(gdb) n                # 逐行

# 组合3：不交互直接拿信息
gdb ./a.out core -batch -ex "bt full" -ex "info registers"
```

## GDB 必加编译选项

```bash
# ⭐ 核心：-g 加调试符号，-O0 关优化（变量值才准确）
g++ -g -O0 -o a.out a.cpp
# 不要只用 -O2 调试——变量被优化掉后 p 显示 <optimized out>
```

## 精简版速查

> **口诀**：`b` 断点 → `r` 跑 → `bt` 看栈 → `p` 查变量 → `n` 单步 → `c` 继续。

```bash
gdb --args ./a.out -ex "b main" -ex "r"
```
