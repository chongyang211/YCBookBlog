# 第30章：多线程锁选型

## 问题现场

```cpp
std::mutex m;
void f() {
    m.lock();     // 如果中间抛异常 → 永远不解锁
    do_work();
    m.unlock();
}
```

## 根因

手动 `lock/unlock` 不可靠。C++ 提供 RAII 锁包装，并针对不同场景设计了不同锁。

## 锁的选型决策树

```
读写比例如何？
├─ 读多写少 → std::shared_mutex + shared_lock（C++17）
├─ 读少写多 → std::mutex + lock_guard
├─ 极简场景 → std::atomic （无锁）
└─ 同一线程可能重入？→ std::recursive_mutex（慎用）
```

## 方案对比

| 锁类型 | 包装器 | 适用 | 特别注意 |
|--------|--------|------|---------|
| `mutex` | `lock_guard`/`unique_lock` | 默认首选 | 不可重入 |
| `shared_mutex` | `shared_lock`(读) `unique_lock`(写) | 读多写少 | C++17 |
| `atomic` | 无 | 单个变量 | 只支持基本运算 |
| `recursive_mutex` | 同 mutex | 同线程可能重入 | 通常是设计问题 |

## 典型用法

```cpp
// 基础：lock_guard 自动管理
std::mutex mtx;
void safe_write() {
    std::lock_guard<std::mutex> lock(mtx);
    shared_data++;  // 离开作用域自动解锁
}

// 读多写少：shared_mutex
std::shared_mutex rw_mtx;
void read()  { std::shared_lock lock(rw_mtx); return shared_data; }
void write() { std::unique_lock lock(rw_mtx); shared_data = ...; }
```

## 常见死锁与解决

```cpp
// ❌ 死锁：A 等 B，B 等 A
// ✅ std::lock 同时锁多个
std::lock(m1, m2);          // 原子地锁两个
std::lock_guard g1(m1, std::adopt_lock);
std::lock_guard g2(m2, std::adopt_lock);
```

## 精简版速查

> **口诀**：默认 `mutex` + `lock_guard`，读多写少 `shared_mutex`，单变量 `atomic`。

```cpp
std::lock_guard<std::mutex> lock(mtx);  // 最简安全写法
```
