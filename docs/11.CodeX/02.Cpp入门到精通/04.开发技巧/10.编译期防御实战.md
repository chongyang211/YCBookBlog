# 第31章：编译期防御编程

## 问题现场

```cpp
int getValue() { return 42; }
getValue();  // 返回值被忽略——可能是个 bug
// 编译器沉默，运行时才发现
```

## 根因

C++ 运行时不报"潜在的 bug"，但编译器可以做大量检查——主动加防御让 bug 在编译时暴露。

## 四件套速览

| 特性 | 写法 | 防御什么 | C++版本 |
|------|------|---------|---------|
| `static_assert` | `static_assert(sizeof(T)<=16)` | 编译期条件检查 | C++11 |
| `[[nodiscard]]` | `[[nodiscard]] int f()` | 忽略返回值 | C++17 |
| `constexpr` | `constexpr int f()` | 确保编译期可求值 | C++11 |
| `= delete` | `A(const A&) = delete` | 禁止拷贝 / 禁止某些重载 | C++11 |

## 实战场景

```cpp
// ① 禁止拷贝（unique_ptr 就是这样做的）
class NonCopyable {
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};

// ② 让返回值必须被使用
[[nodiscard]] bool tryParse(const std::string& s, int& out);
// tryParse("123", result);  // ⚠️ 编译器警告：返回值被忽略

// ③ 编译期断言
template<typename T>
void process(T data) {
    static_assert(sizeof(T) <= 16, "T too large for small buffer");
}
```

## 方案对比

| 方案 | 检测时机 | 代价 | 适用 |
|------|---------|------|------|
| `static_assert` | 编译期 | 零 | 类型大小、常量条件 |
| `[[nodiscard]]` | 编译期 | 零 | 不要忽略返回值的函数 |
| `= delete` | 编译期 | 零 | 禁止拷贝/移动/某些重载 |
| `constexpr` | 编译期 | 限制函数复杂度 | 常量计算 |
| `-Wall -Wextra` | 编译期 | 零 | 所有项目必加 |

## 精简版速查

> **口诀**：`static_assert` 验条件，`[[nodiscard]]` 防忽略，`= delete` 禁拷贝，`-Wall -Wextra` 是底线。

```bash
g++ -Wall -Wextra -Werror -o a.out a.cpp  # 把警告当错误
```
