## 01.前言介绍

### 1.1 异步是JavaScript的灵魂

JavaScript最核心的设计特征之一就是**异步**。从网络请求到用户交互，从文件I/O到动画渲染，几乎所有有意义的操作都是异步的。

但异步也是最容易出错的地方。理解事件循环的底层原理，是写出正确、高效异步代码的前提。

### 1.2 一个引发思考的问题

```javascript
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");

// 输出顺序是？
```

如果你不确定答案是`1, 4, 3, 2`，或者知道答案但不确定原因，本文会给出完整解释。


## 02.为什么JavaScript是单线程

### 2.1 历史原因

**疑惑**：多线程不是更高效吗？为什么JavaScript选择单线程？

**答疑**：1995年，JavaScript被设计为浏览器脚本语言，主要任务是操作DOM。如果多个线程同时修改同一个DOM节点，会产生竞态条件：

```javascript
// 假设JavaScript是多线程的
// 线程1
document.getElementById("btn").textContent = "Hello";

// 线程2（同时执行）
document.getElementById("btn").remove();

// 结果：不确定！取决于哪个线程先执行
```

**论证**：多线程DOM操作需要锁机制，极大增加编程复杂度。对于当时的Web脚本场景，单线程 + 事件驱动是最合理的选择。

**结果**：JavaScript至今保持单线程模型，但通过**Web Workers**提供了在后台线程执行计算密集型任务的能力（Worker不能访问DOM）。

### 2.2 单线程的挑战

```javascript
// 如果同步执行网络请求
const response = syncFetch("https://api.example.com/data"); // 阻塞5秒
console.log(response);  // 5秒后才执行
// 这5秒内页面完全冻结——用户无法点击、滚动、输入
```

解决方案就是**异步**：发起请求后立即返回，结果通过回调通知：

```javascript
fetch("https://api.example.com/data")
    .then(response => response.json())
    .then(data => console.log(data));
// 不阻塞，立即继续执行后面的代码
```


## 03.事件循环的完整模型

### 3.1 运行时架构

```
┌──────────────────────────────────────────────────┐
│                  JavaScript运行时                  │
│                                                    │
│  ┌──────────────┐     ┌──────────────────┐        │
│  │  调用栈       │     │  堆（Heap）       │        │
│  │  (Call Stack) │     │  对象存储         │        │
│  │              │     │                  │        │
│  │ main()       │     │  { ... }         │        │
│  │ foo()        │     │  [ ... ]         │        │
│  │ bar()        │     │                  │        │
│  └──────────────┘     └──────────────────┘        │
│         ↕                                          │
│  ┌────────────────────────────────────────┐       │
│  │         事件循环（Event Loop）           │       │
│  └────────────────────────────────────────┘       │
│         ↕                    ↕                     │
│  ┌──────────────┐    ┌──────────────────┐         │
│  │ 微任务队列    │    │  宏任务队列        │         │
│  │ (Microtask)  │    │  (Macrotask)     │         │
│  │              │    │                  │         │
│  │ Promise.then │    │ setTimeout       │         │
│  │ queueMicro.. │    │ setInterval      │         │
│  │ MutationObs. │    │ I/O callbacks    │         │
│  │              │    │ UI rendering     │         │
│  └──────────────┘    └──────────────────┘         │
│                                                    │
│  ┌────────────────────────────────────────┐       │
│  │         Web APIs / Node APIs           │       │
│  │  (setTimeout, fetch, DOM events等)     │       │
│  └────────────────────────────────────────┘       │
└──────────────────────────────────────────────────┘
```

### 3.2 事件循环算法

```
EventLoop:
  while (true) {
    1. 从宏任务队列取出一个任务（最早的那个）
    2. 执行该任务（直到调用栈清空）
    3. 执行所有微任务（清空微任务队列）
       while (microtaskQueue.length > 0) {
         执行队首微任务
         // 微任务中产生的新微任务也要在本轮处理
       }
    4. 如果需要渲染（通常60fps = 每16.7ms一次）：
       a. 执行requestAnimationFrame回调
       b. 执行布局计算
       c. 执行绘制
    5. 回到步骤1
  }
```

### 3.3 回到开篇的问题

```javascript
console.log("1");           // ① 同步代码，立即执行

setTimeout(() => {           // ② 注册宏任务
    console.log("2");
}, 0);

Promise.resolve().then(() => { // ③ 注册微任务
    console.log("3");
});

console.log("4");           // ④ 同步代码，立即执行
```

执行过程：

```
1. 执行同步代码（当前宏任务——脚本）
   → 输出 "1"
   → setTimeout回调进入宏任务队列
   → Promise.then回调进入微任务队列
   → 输出 "4"
   → 调用栈清空

2. 清空微任务队列
   → 输出 "3"

3. 取出下一个宏任务（setTimeout回调）
   → 输出 "2"

最终输出: 1, 4, 3, 2
```


## 04.微任务与宏任务

### 4.1 分类详表

**宏任务（Macrotask / Task）**：

| 来源 | 环境 |
|------|------|
| 整体脚本（script） | 浏览器/Node |
| setTimeout | 浏览器/Node |
| setInterval | 浏览器/Node |
| setImmediate | Node |
| I/O | Node |
| UI rendering | 浏览器 |
| MessageChannel | 浏览器 |
| requestAnimationFrame | 浏览器（特殊，在渲染前执行） |

**微任务（Microtask）**：

| 来源 | 环境 |
|------|------|
| Promise.then/catch/finally | 浏览器/Node |
| queueMicrotask() | 浏览器/Node |
| MutationObserver | 浏览器 |
| process.nextTick | Node（优先级最高） |

### 4.2 微任务的优先级

微任务总是在当前宏任务结束后、下一个宏任务开始前执行：

```javascript
setTimeout(() => console.log("timeout 1"), 0);
setTimeout(() => console.log("timeout 2"), 0);

Promise.resolve().then(() => {
    console.log("promise 1");
    Promise.resolve().then(() => {
        console.log("promise 2");
    });
});

// 输出: promise 1, promise 2, timeout 1, timeout 2
// 微任务中创建的微任务在同一轮清空
```

### 4.3 微任务的"饥饿"问题

```javascript
// 危险！微任务递归会阻塞事件循环
function endlessMicrotask() {
    Promise.resolve().then(() => {
        endlessMicrotask();  // 永远产生新的微任务
    });
}

endlessMicrotask();
// 事件循环永远卡在"清空微任务队列"这一步
// 宏任务（包括渲染）永远得不到执行
// 页面完全冻结
```

对比：

```javascript
// setTimeout不会"饥饿"
function endlessMacrotask() {
    setTimeout(() => {
        endlessMacrotask();  // 注册新的宏任务
    }, 0);
}

endlessMacrotask();
// 每次迭代之间，事件循环会处理其他宏任务和渲染
// 页面不会冻结
```

### 4.4 复杂输出顺序分析

```javascript
console.log("start");

setTimeout(() => {
    console.log("timeout");
    Promise.resolve().then(() => console.log("promise in timeout"));
}, 0);

Promise.resolve().then(() => {
    console.log("promise 1");
    setTimeout(() => console.log("timeout in promise"), 0);
}).then(() => {
    console.log("promise 2");
});

console.log("end");
```

分析：

```
宏任务1（脚本）:
  输出: "start"
  注册: setTimeout → 宏任务队列
  注册: Promise.then → 微任务队列
  输出: "end"
  
清空微任务:
  执行promise 1的then：
    输出: "promise 1"
    注册: setTimeout → 宏任务队列
    注册: .then (promise 2) → 微任务队列
  执行promise 2的then：
    输出: "promise 2"

宏任务2（第一个setTimeout）:
  输出: "timeout"
  注册: Promise.then → 微任务队列
  
清空微任务:
  输出: "promise in timeout"

宏任务3（第二个setTimeout）:
  输出: "timeout in promise"

最终: start, end, promise 1, promise 2, timeout, promise in timeout, timeout in promise
```


## 05.Promise的底层实现

### 5.1 Promise的状态机

Promise内部是一个**状态机**：

```
       ┌────────────┐
       │  pending    │ ← 初始状态
       └──┬─────┬───┘
          │     │
  resolve │     │ reject
          ↓     ↓
   ┌──────┐   ┌──────┐
   │fulfilled│   │rejected│ ← 终态（不可变）
   └──────┘   └──────┘
```

### 5.2 简化版Promise实现

```javascript
class SimplePromise {
    constructor(executor) {
        this.state = 'pending';
        this.value = undefined;
        this.callbacks = [];
        
        const resolve = (value) => {
            if (this.state !== 'pending') return;
            this.state = 'fulfilled';
            this.value = value;
            this.callbacks.forEach(cb => cb.onFulfilled(value));
        };
        
        const reject = (reason) => {
            if (this.state !== 'pending') return;
            this.state = 'rejected';
            this.value = reason;
            this.callbacks.forEach(cb => cb.onRejected(reason));
        };
        
        try {
            executor(resolve, reject);
        } catch (err) {
            reject(err);
        }
    }
    
    then(onFulfilled, onRejected) {
        onFulfilled = typeof onFulfilled === 'function' ? onFulfilled : v => v;
        onRejected = typeof onRejected === 'function' ? onRejected : e => { throw e; };
        
        const promise2 = new SimplePromise((resolve, reject) => {
            const handle = (fn, value) => {
                // 关键：then的回调必须异步执行（微任务）
                queueMicrotask(() => {
                    try {
                        const result = fn(value);
                        if (result instanceof SimplePromise) {
                            result.then(resolve, reject);
                        } else {
                            resolve(result);
                        }
                    } catch (err) {
                        reject(err);
                    }
                });
            };
            
            if (this.state === 'fulfilled') {
                handle(onFulfilled, this.value);
            } else if (this.state === 'rejected') {
                handle(onRejected, this.value);
            } else {
                this.callbacks.push({
                    onFulfilled: (v) => handle(onFulfilled, v),
                    onRejected: (r) => handle(onRejected, r)
                });
            }
        });
        
        return promise2;
    }
    
    catch(onRejected) {
        return this.then(null, onRejected);
    }
    
    finally(callback) {
        return this.then(
            value => SimplePromise.resolve(callback()).then(() => value),
            reason => SimplePromise.resolve(callback()).then(() => { throw reason; })
        );
    }
    
    static resolve(value) {
        if (value instanceof SimplePromise) return value;
        return new SimplePromise(resolve => resolve(value));
    }
    
    static reject(reason) {
        return new SimplePromise((_, reject) => reject(reason));
    }
}
```

### 5.3 then的链式调用原理

```javascript
Promise.resolve(1)
    .then(v => v + 1)     // 返回2
    .then(v => v * 3)     // 返回6
    .then(v => {
        console.log(v);   // 6
        throw new Error("oops");
    })
    .catch(err => {
        console.log(err.message); // "oops"
        return "recovered";
    })
    .then(v => {
        console.log(v);   // "recovered"
    });
```

**每个then/catch返回一个新的Promise**。这是链式调用的关键。

### 5.4 Promise.all的实现

```javascript
SimplePromise.all = function(promises) {
    return new SimplePromise((resolve, reject) => {
        const results = [];
        let completed = 0;
        const total = promises.length;
        
        if (total === 0) return resolve([]);
        
        promises.forEach((p, i) => {
            SimplePromise.resolve(p).then(
                value => {
                    results[i] = value;
                    completed++;
                    if (completed === total) resolve(results);
                },
                reject  // 任何一个失败就整体失败
            );
        });
    });
};
```

### 5.5 Promise.race / Promise.allSettled / Promise.any

```javascript
// race：第一个完成的（无论成功失败）决定结果
Promise.race([
    fetch('/api1'),
    new Promise((_, reject) => setTimeout(() => reject('timeout'), 5000))
]);

// allSettled：等所有完成，不管成功失败（ES2020）
const results = await Promise.allSettled([
    fetch('/api1'),
    fetch('/api2'),
    fetch('/api3')
]);
// results: [
//   { status: 'fulfilled', value: Response },
//   { status: 'rejected', reason: Error },
//   { status: 'fulfilled', value: Response }
// ]

// any：第一个成功的（ES2021）
// 全部失败才reject（AggregateError）
```


## 06.async/await的本质

### 6.1 async/await是Generator + Promise的语法糖

```javascript
// async/await版本
async function fetchData() {
    const resp = await fetch('/api');
    const data = await resp.json();
    return data;
}

// 等价的Generator + Promise版本
function fetchData() {
    return spawn(function* () {
        const resp = yield fetch('/api');
        const data = yield resp.json();
        return data;
    });
}

function spawn(genFn) {
    return new Promise((resolve, reject) => {
        const gen = genFn();
        
        function step(nextFn) {
            let result;
            try {
                result = nextFn();
            } catch(e) {
                return reject(e);
            }
            if (result.done) return resolve(result.value);
            
            Promise.resolve(result.value).then(
                v => step(() => gen.next(v)),
                e => step(() => gen.throw(e))
            );
        }
        
        step(() => gen.next());
    });
}
```

### 6.2 await的微任务调度

```javascript
async function foo() {
    console.log("foo start");      // 同步执行
    await Promise.resolve();        // 暂停，注册微任务
    console.log("foo after await"); // 微任务中恢复执行
}

console.log("start");
foo();
console.log("end");

// 输出: start, foo start, end, foo after await
```

`await`做了什么：

```
1. 执行await后面的表达式
2. 将async函数剩余部分包装为微任务
3. 将该微任务加入微任务队列
4. 退出async函数，让出控制权
5. 在后续的微任务阶段恢复执行
```

### 6.3 async函数的返回值

```javascript
// async函数总是返回Promise
async function foo() { return 42; }
foo();  // Promise {<fulfilled>: 42}

async function bar() { throw new Error("oops"); }
bar();  // Promise {<rejected>: Error: oops}

// 返回的Promise如果是thenable，会被解包
async function baz() { return Promise.resolve(42); }
baz();  // Promise {<fulfilled>: 42}（不是Promise套Promise）
```

### 6.4 顶层await

```javascript
// ES2022：模块中可以使用顶层await
// module.mjs
const data = await fetch('/api/config').then(r => r.json());
export { data };

// 导入该模块的代码会等待fetch完成
import { data } from './module.mjs';
```

### 6.5 async/await的错误处理

```javascript
// try/catch是最自然的错误处理方式
async function fetchUser(id) {
    try {
        const resp = await fetch(`/api/users/${id}`);
        if (!resp.ok) throw new Error(`HTTP ${resp.status}`);
        return await resp.json();
    } catch (err) {
        console.error("Failed to fetch user:", err);
        return null;  // 优雅降级
    }
}

// 工具函数方式（Go风格）
async function to(promise) {
    try {
        const result = await promise;
        return [null, result];
    } catch (err) {
        return [err, null];
    }
}

const [err, user] = await to(fetchUser(1));
if (err) {
    // 处理错误
}
```


## 07.定时器的真相

### 7.1 setTimeout不保证精确计时

```javascript
// 这不会在恰好100ms后执行
setTimeout(() => {
    console.log("100ms later?");
}, 100);
```

setTimeout的100ms只是**最小延迟**，实际延迟可能更长：

1. **主线程忙碌时**：回调要等调用栈清空才能执行
2. **嵌套定时器限制**：嵌套层数超过5时，最小延迟强制为4ms
3. **后台标签页**：浏览器可能将最小延迟提高到1000ms

### 7.2 嵌套定时器的4ms限制

```javascript
// HTML规范规定：嵌套层数>5时，最小间隔为4ms
let start = Date.now();
let count = 0;

function nest() {
    count++;
    if (count <= 10) {
        setTimeout(() => {
            console.log(`${count}: ${Date.now() - start}ms`);
            nest();
        }, 0);
    }
}
nest();

// 大致输出:
// 1: 1ms    (前5层可以0延迟)
// 2: 1ms
// 3: 2ms
// 4: 2ms
// 5: 3ms
// 6: 7ms    (开始4ms限制)
// 7: 11ms
// 8: 15ms
// ...
```

### 7.3 setInterval的问题

```javascript
// setInterval的隐患
setInterval(() => {
    // 如果执行时间超过间隔时间
    // 回调会堆积，或者间隔被跳过
    heavyOperation();  // 执行200ms
}, 100);  // 间隔100ms

// 更好的方案：递归setTimeout
function betterInterval() {
    heavyOperation();
    setTimeout(betterInterval, 100);  // 上一次结束后再等100ms
}
```

### 7.4 精确计时方案

```javascript
// 使用performance.now()获取高精度时间
function preciseDelay(ms) {
    return new Promise(resolve => {
        const start = performance.now();
        function check() {
            if (performance.now() - start >= ms) {
                resolve();
            } else {
                requestAnimationFrame(check);
            }
        }
        requestAnimationFrame(check);
    });
}
```


## 08.requestAnimationFrame与渲染时机

### 8.1 浏览器的渲染流水线

```
一帧的完整流程（~16.7ms @60fps）:
  
  1. 处理输入事件（点击、滚动、键盘）
  2. 执行宏任务
  3. 清空微任务
  4. 执行requestAnimationFrame回调 ← 渲染前最后的操作机会
  5. 布局计算（Layout / Reflow）
  6. 绘制（Paint）
  7. 合成（Composite）
  
  如果还有时间剩余:
  8. 执行requestIdleCallback ← 空闲时间回调
```

### 8.2 requestAnimationFrame的正确使用

```javascript
// 动画循环
function animate() {
    // 更新动画状态
    element.style.transform = `translateX(${position}px)`;
    position += 2;
    
    // 请求下一帧
    if (position < 500) {
        requestAnimationFrame(animate);
    }
}

requestAnimationFrame(animate);
```

**为什么不用setTimeout做动画**：

1. setTimeout不与屏幕刷新同步，可能在两帧之间更新，造成画面撕裂
2. 标签页不可见时，setTimeout仍在执行（浪费资源），rAF会暂停
3. rAF的回调会接收精确的时间戳参数

### 8.3 requestIdleCallback

```javascript
// 利用浏览器空闲时间执行非紧急任务
requestIdleCallback((deadline) => {
    // deadline.timeRemaining() 返回当前帧剩余的空闲时间（ms）
    while (deadline.timeRemaining() > 0 && tasks.length > 0) {
        processTask(tasks.pop());
    }
    
    // 如果还有任务没处理完，注册下一次空闲回调
    if (tasks.length > 0) {
        requestIdleCallback(processRemainingTasks);
    }
}, { timeout: 5000 });  // 最多等5秒，防止饥饿
```

### 8.4 微任务与渲染的关系

```javascript
// 微任务在渲染前执行
document.body.style.background = 'red';
Promise.resolve().then(() => {
    document.body.style.background = 'blue';
});
// 用户看到的直接是蓝色，红色不会闪烁
// 因为微任务在渲染前执行，DOM变更被合并

// 但如果在宏任务中改变
document.body.style.background = 'red';
setTimeout(() => {
    document.body.style.background = 'blue';
}, 0);
// 红色可能会闪烁一帧（取决于setTimeout的执行时机）
```


## 09.Node.js事件循环差异

### 9.1 Node.js事件循环的阶段

```
Node.js事件循环（libuv实现）:

   ┌───────────────────────────┐
┌─>│           timers          │ ← setTimeout/setInterval
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │     pending callbacks     │ ← 系统级回调（如TCP错误）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │       idle, prepare       │ ← 内部使用
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │           poll            │ ← I/O回调，等待新I/O
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │           check           │ ← setImmediate
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │      close callbacks      │ ← close事件（socket.on('close'))
│  └─────────────┬─────────────┘
│                │
└────────────────┘  每个阶段之间都会清空微任务队列
```

### 9.2 setImmediate vs setTimeout(0)

```javascript
// 在主模块中，顺序不确定
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
// 可能 timeout先 也可能 immediate先

// 在I/O回调中，setImmediate总是先执行
const fs = require('fs');
fs.readFile(__filename, () => {
    setImmediate(() => console.log("immediate"));
    setTimeout(() => console.log("timeout"), 0);
});
// 输出: immediate, timeout
// 因为I/O回调在poll阶段，下一个阶段是check（setImmediate）
```

### 9.3 process.nextTick

```javascript
// process.nextTick不属于事件循环的任何阶段
// 它在每个阶段转换之间执行，优先级高于其他微任务

Promise.resolve().then(() => console.log("promise"));
process.nextTick(() => console.log("nextTick"));
// 输出: nextTick, promise
```

**注意**：过度使用`process.nextTick`会导致I/O饥饿（类似微任务递归的问题）。


## 10.异步错误处理

### 10.1 异步错误无法被同步try/catch捕获

```javascript
// 这不会捕获到错误
try {
    setTimeout(() => {
        throw new Error("async error");
    }, 0);
} catch (e) {
    // 永远不会执行到这里
    console.log("caught:", e);
}
// Error: async error（未被捕获，成为unhandled error）
```

### 10.2 Promise错误链

```javascript
fetch('/api')
    .then(r => r.json())
    .then(data => {
        throw new Error("processing error");
    })
    .catch(err => {
        console.log("Caught:", err.message);
        // catch之后链恢复为fulfilled
        return "recovered";
    })
    .then(v => {
        console.log("Recovered:", v);
    });
```

### 10.3 未处理的Promise拒绝

```javascript
// 没有catch的rejected Promise
Promise.reject(new Error("unhandled"));

// 浏览器和Node.js都会触发事件
window.addEventListener('unhandledrejection', event => {
    console.log('Unhandled:', event.reason);
    event.preventDefault();  // 阻止默认行为（控制台报错）
});

// Node.js
process.on('unhandledRejection', (reason, promise) => {
    console.log('Unhandled Rejection:', reason);
});
```

### 10.4 async/await的错误传播

```javascript
async function a() { throw new Error("from a"); }
async function b() { await a(); }  // 错误自动传播
async function c() { await b(); }  // 继续传播

// 在最外层捕获
try {
    await c();
} catch (err) {
    console.log(err.message);  // "from a"
    console.log(err.stack);    // 包含完整的async调用栈
}
```


## 11.并发控制模式

### 11.1 并行执行

```javascript
// Promise.all：所有完成才返回
const [users, posts, comments] = await Promise.all([
    fetchUsers(),
    fetchPosts(),
    fetchComments()
]);
// 三个请求并行执行，总时间 = max(三个请求时间)
```

### 11.2 控制并发数

```javascript
// 限制同时进行的请求数量
async function asyncPool(limit, items, fn) {
    const results = [];
    const executing = new Set();
    
    for (const [index, item] of items.entries()) {
        const p = Promise.resolve().then(() => fn(item, index));
        results.push(p);
        executing.add(p);
        
        const clean = () => executing.delete(p);
        p.then(clean, clean);
        
        if (executing.size >= limit) {
            await Promise.race(executing);
        }
    }
    
    return Promise.all(results);
}

// 使用：最多同时3个请求
const urls = Array.from({ length: 100 }, (_, i) => `/api/item/${i}`);
const results = await asyncPool(3, urls, url => fetch(url).then(r => r.json()));
```

### 11.3 竞态与取消

```javascript
// AbortController用于取消请求
const controller = new AbortController();

setTimeout(() => controller.abort(), 5000);  // 5秒超时

try {
    const resp = await fetch('/api/data', {
        signal: controller.signal
    });
    const data = await resp.json();
} catch (err) {
    if (err.name === 'AbortError') {
        console.log('请求被取消');
    }
}
```

```javascript
// 防止竞态条件：只使用最新请求的结果
function useLatest(fn) {
    let currentId = 0;
    return async function(...args) {
        const id = ++currentId;
        const result = await fn(...args);
        if (id !== currentId) {
            throw new Error('Stale request');
        }
        return result;
    };
}

const search = useLatest(async (query) => {
    const resp = await fetch(`/api/search?q=${query}`);
    return resp.json();
});
```

### 11.4 串行执行

```javascript
// 按顺序执行异步任务
async function serial(tasks) {
    const results = [];
    for (const task of tasks) {
        results.push(await task());
    }
    return results;
}

// 或用reduce
function serialReduce(tasks) {
    return tasks.reduce(
        (chain, task) => chain.then(results => 
            task().then(result => [...results, result])
        ),
        Promise.resolve([])
    );
}
```


## 12.异步编程的演进与未来

### 12.1 异步模式演进

```
回调函数（Callback）
  ↓ 问题：回调地狱
事件监听（EventEmitter）
  ↓ 问题：流程难追踪
Promise
  ↓ 问题：链式调用仍然冗长
Generator + co
  ↓ 问题：需要运行器
async/await
  ↓ 问题：无法取消
AbortController + async/await
  ↓ 当前最佳实践
```

### 12.2 异步迭代

```javascript
// for await...of 处理异步数据流
async function* generateNumbers() {
    yield 1;
    await sleep(100);
    yield 2;
    await sleep(100);
    yield 3;
}

for await (const num of generateNumbers()) {
    console.log(num);  // 1（等100ms）2（等100ms）3
}

// 实际应用：逐行读取大文件
import { createReadStream } from 'fs';
import { createInterface } from 'readline';

const rl = createInterface({
    input: createReadStream('large-file.txt')
});

for await (const line of rl) {
    // 逐行处理，内存友好
    processLine(line);
}
```

### 12.3 Observable模式（RxJS）

```javascript
// Observable是对异步数据流的抽象
// 比Promise更强大：支持多值、取消、操作符

import { fromEvent, interval } from 'rxjs';
import { debounceTime, map, switchMap, takeUntil } from 'rxjs/operators';

// 搜索框的实时搜索
const input$ = fromEvent(searchInput, 'input');
const destroy$ = fromEvent(component, 'destroy');

input$.pipe(
    debounceTime(300),           // 防抖
    map(e => e.target.value),    // 提取值
    switchMap(query =>           // 取消旧请求，发起新请求
        fetch(`/api/search?q=${query}`).then(r => r.json())
    ),
    takeUntil(destroy$)          // 组件销毁时自动取消
).subscribe(results => {
    renderResults(results);
});
```

### 12.4 总结：事件循环的核心要点

1. **JavaScript是单线程的**——事件循环是实现异步的机制
2. **一个宏任务 → 清空所有微任务 → 可能渲染 → 下一个宏任务**
3. **微任务优先级高于宏任务**——Promise.then在setTimeout之前
4. **await暂停async函数**——剩余代码作为微任务调度
5. **Promise实现基于状态机 + 微任务调度**
6. **setTimeout不精确**——只保证最小延迟
7. **rAF与渲染同步**——动画应用rAF而非setTimeout
8. **Node.js事件循环有6个阶段**——与浏览器模型不同
