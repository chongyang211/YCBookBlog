## 01.前言介绍

### 1.1 JavaScript的独特继承模型

几乎所有面向对象语言都支持继承，但实现方式大不相同：

- **Java/C++**：基于类（Class-based），编译时确定继承关系
- **JavaScript**：基于原型（Prototype-based），运行时通过原型链实现

这种差异不是设计上的妥协，而是Brendan Eich受Self语言启发做出的**刻意选择**——原型继承比类继承更灵活、更动态。

### 1.2 疑惑：为什么不直接用类

1995年Netscape要求Brendan Eich设计一种"看起来像Java"的脚本语言。但他认为，一种用于Web脚本的语言不需要类这种重量级抽象。

**答疑**：原型继承的核心思想是——**对象直接从其他对象继承**，不需要类作为中间层。这更符合JavaScript作为动态脚本语言的定位。

**论证**：

```javascript
// 原型继承：对象直接继承对象
const animal = {
    speak() { console.log("..."); }
};

const dog = Object.create(animal);
dog.speak = function() { console.log("Woof!"); };
// dog直接从animal继承，没有类的参与
```

**结果**：ES6引入的`class`语法只是原型继承的**语法糖**，底层机制没有改变。理解原型链才是理解JavaScript面向对象的根本。


## 02.对象的原型本质

### 2.1 [[Prototype]]内部属性

每个JavaScript对象（除了`null`）都有一个内部属性`[[Prototype]]`，指向另一个对象（它的原型）：

```javascript
const obj = { x: 1 };

// [[Prototype]]不能直接访问，但可以通过以下方式操作：
Object.getPrototypeOf(obj);        // 获取原型（推荐）
obj.__proto__;                      // 获取原型（非标准，但被广泛支持）
Object.setPrototypeOf(obj, proto); // 设置原型（不推荐，性能差）
```

### 2.2 __proto__ vs prototype

这是最常见的困惑源。它们是完全不同的东西：

```javascript
function Person(name) {
    this.name = name;
}

// Person.prototype 是一个普通对象
// 它是通过 new Person() 创建的实例的原型
Person.prototype.greet = function() {
    return `Hi, I'm ${this.name}`;
};

const alice = new Person("Alice");

// alice.__proto__ === Person.prototype
// alice的[[Prototype]]指向Person.prototype
console.log(alice.__proto__ === Person.prototype);  // true

// Person.prototype 是函数的属性
// __proto__ 是对象的[[Prototype]]访问器
// 二者的关系：实例的__proto__指向构造函数的prototype
```

**区分**：

| 概念 | 属于谁 | 是什么 |
|------|--------|--------|
| `__proto__` | 每个对象 | 指向该对象的原型（即`[[Prototype]]`） |
| `prototype` | 函数对象 | 作为构造函数时，new出来的实例的原型 |

### 2.3 默认的prototype对象

```javascript
function Foo() {}

// Foo.prototype自动包含一个constructor属性，指回Foo本身
console.log(Foo.prototype.constructor === Foo);  // true

// 这形成了一个循环引用
// Foo → Foo.prototype → Foo.prototype.constructor → Foo
```

这个`constructor`属性的存在使得实例可以找到创建它的构造函数：

```javascript
const obj = new Foo();
console.log(obj.constructor === Foo);  // true
// obj自身没有constructor，沿原型链在Foo.prototype上找到
```


## 03.原型链的完整模型

### 3.1 核心方程

```
实例.__proto__ === 构造函数.prototype
构造函数.prototype.constructor === 构造函数
```

### 3.2 完整的原型链图

```
                              null
                               ↑
                    Object.prototype
                    (__proto__: null)
                         ↑            ↑
              Foo.prototype          Function.prototype
              (__proto__:            (__proto__:
               Object.prototype)     Object.prototype)
                   ↑                      ↑
              foo实例                  Foo函数
              (__proto__:             (__proto__:
               Foo.prototype)         Function.prototype)
```

### 3.3 用代码验证

```javascript
function Foo() {}
const foo = new Foo();

// 实例 → 构造函数.prototype
foo.__proto__ === Foo.prototype;                    // true

// 构造函数.prototype → Object.prototype
Foo.prototype.__proto__ === Object.prototype;       // true

// Object.prototype → null（原型链终点）
Object.prototype.__proto__ === null;                // true

// 函数也是对象，有自己的原型链
Foo.__proto__ === Function.prototype;               // true
Function.prototype.__proto__ === Object.prototype;  // true

// 有趣的循环：Function是自己的实例
Function.__proto__ === Function.prototype;           // true
// Object也是Function的实例
Object.__proto__ === Function.prototype;             // true
```

### 3.4 原始类型的原型链

```javascript
// 原始类型通过自动装箱（Auto-boxing）访问原型方法
"hello".toUpperCase();
// 等价于：new String("hello").toUpperCase()

// 字符串原型链
"hello".__proto__ === String.prototype;             // true
String.prototype.__proto__ === Object.prototype;    // true

// 数字原型链
(42).__proto__ === Number.prototype;                 // true

// 但null和undefined没有原型
// null.__proto__   → TypeError
// undefined.foo    → TypeError
```

### 3.5 特殊对象的原型链

```javascript
// 数组
[].__proto__ === Array.prototype;                   // true
Array.prototype.__proto__ === Object.prototype;     // true

// 正则
/regex/.__proto__ === RegExp.prototype;             // true

// 函数
(function(){}).__proto__ === Function.prototype;    // true

// Date
new Date().__proto__ === Date.prototype;            // true
```

所有原型链最终都汇聚到`Object.prototype`，然后到`null`。这就是为什么所有对象都有`toString()`、`hasOwnProperty()`等方法——它们定义在`Object.prototype`上。


## 04.属性查找与原型链遍历

### 4.1 属性查找算法

当访问对象的属性时，引擎执行以下算法：

```
GetProperty(obj, name):
  1. 检查obj自身是否有name属性（OwnProperty）
  2. 如果有，返回该属性值
  3. 如果没有，获取obj.[[Prototype]]
  4. 如果[[Prototype]]为null，返回undefined
  5. 递归：GetProperty(obj.[[Prototype]], name)
```

```javascript
function Animal(name) {
    this.name = name;  // 自身属性
}
Animal.prototype.speak = function() {  // 原型属性
    return `${this.name} makes a sound`;
};

Object.prototype.exists = true;  // Object原型上的属性

const dog = new Animal("Dog");

// 查找dog.name
// 1. dog自身有name → 返回"Dog"

// 查找dog.speak
// 1. dog自身没有speak
// 2. dog.__proto__ (Animal.prototype)有speak → 返回函数

// 查找dog.exists
// 1. dog自身没有
// 2. Animal.prototype没有
// 3. Object.prototype有exists → 返回true

// 查找dog.nonexistent
// 1. dog自身没有
// 2. Animal.prototype没有
// 3. Object.prototype没有
// 4. null → 返回undefined
```

### 4.2 属性遮蔽（Property Shadowing）

```javascript
Animal.prototype.legs = 4;

const snake = new Animal("Snake");
snake.legs = 0;  // 在自身创建同名属性

console.log(snake.legs);          // 0（自身属性遮蔽了原型属性）
console.log(snake.__proto__.legs); // 4（原型上的属性仍在）

delete snake.legs;                 // 删除自身属性
console.log(snake.legs);          // 4（原型属性重新"可见"）
```

### 4.3 hasOwnProperty vs in

```javascript
const obj = Object.create({ inherited: 1 });
obj.own = 2;

// in操作符：检查整条原型链
"own" in obj;        // true
"inherited" in obj;  // true

// hasOwnProperty：只检查自身属性
obj.hasOwnProperty("own");        // true
obj.hasOwnProperty("inherited");  // false

// 更安全的写法（防止hasOwnProperty被覆盖）
Object.prototype.hasOwnProperty.call(obj, "own");  // true

// ES2022新方法
Object.hasOwn(obj, "own");  // true（推荐）
```

### 4.4 属性枚举

```javascript
const parent = { a: 1 };
const child = Object.create(parent);
child.b = 2;

// for...in 遍历自身和原型链上的可枚举属性
for (let key in child) {
    console.log(key);  // "b", "a"
}

// Object.keys 只返回自身可枚举属性
Object.keys(child);  // ["b"]

// Object.getOwnPropertyNames 返回自身所有属性（包括不可枚举）
Object.getOwnPropertyNames(child);  // ["b"]

// Reflect.ownKeys 返回自身所有键（包括Symbol）
Reflect.ownKeys(child);  // ["b"]
```

### 4.5 V8中的属性查找优化

V8并不是每次都"遍历"原型链。通过**隐藏类（Hidden Class）**和**内联缓存（Inline Cache）**，原型链上的属性查找可以被优化为直接内存访问：

```javascript
function Point(x, y) {
    this.x = x;
    this.y = y;
}
Point.prototype.sum = function() { return this.x + this.y; };

const p = new Point(1, 2);
p.sum();  // 第一次查找：遍历原型链，缓存结果
p.sum();  // 之后：直接从缓存获取，不遍历

// V8的内联缓存记录：
// p.sum → 如果p的HC是X，那么sum在原型的offset Y
```


## 05.构造函数与new的底层原理

### 5.1 new操作符的四个步骤

```javascript
function Person(name) {
    this.name = name;
}

const alice = new Person("Alice");
```

`new Person("Alice")`在引擎内部做了什么：

```
1. 创建一个新的空对象: {}
2. 将新对象的[[Prototype]]设为Person.prototype
3. 将Person函数的this绑定到新对象，执行函数体
4. 如果函数返回了一个对象，则使用该对象；否则返回步骤1创建的对象
```

### 5.2 手动实现new

```javascript
function myNew(Constructor, ...args) {
    // Step 1: 创建新对象，原型指向构造函数的prototype
    const obj = Object.create(Constructor.prototype);
    
    // Step 2: 执行构造函数，this指向新对象
    const result = Constructor.apply(obj, args);
    
    // Step 3: 如果构造函数返回了对象，使用它；否则返回新对象
    return (result !== null && typeof result === 'object') ? result : obj;
}

// 验证
function Foo(x) { this.x = x; }
Foo.prototype.getX = function() { return this.x; };

const a = myNew(Foo, 42);
console.log(a.x);            // 42
console.log(a.getX());       // 42
console.log(a instanceof Foo); // true
```

### 5.3 构造函数返回值的影响

```javascript
// 返回原始值——被忽略
function A() {
    this.x = 1;
    return 42;  // 被忽略
}
new A();  // { x: 1 }

// 返回对象——使用返回的对象
function B() {
    this.x = 1;
    return { y: 2 };  // 使用这个对象
}
new B();  // { y: 2 }（没有x属性）

// 这就是为什么工厂函数和new有时候行为不同
```

### 5.4 [[Construct]] vs [[Call]]

函数对象有两个内部方法：

```javascript
function Foo() {
    // 如何判断函数是被new调用还是直接调用？
    if (new.target) {
        console.log("通过new调用");
    } else {
        console.log("直接调用");
    }
}

Foo();      // "直接调用"   → 触发 [[Call]]
new Foo();  // "通过new调用" → 触发 [[Construct]]
```

**箭头函数没有[[Construct]]**：

```javascript
const Arrow = () => {};
new Arrow();  // TypeError: Arrow is not a constructor
```


## 06.继承的演进之路

### 6.1 原型链继承

```javascript
function Animal(name) {
    this.name = name;
    this.colors = ["black"];
}
Animal.prototype.speak = function() {
    return `${this.name} speaks`;
};

function Dog(name) {
    this.name = name;
}
Dog.prototype = new Animal();

const d1 = new Dog("Rex");
const d2 = new Dog("Buddy");

// 问题1：引用类型共享
d1.colors.push("white");
console.log(d2.colors);  // ["black", "white"]（被污染了！）

// 问题2：无法向父构造函数传参
```

### 6.2 借用构造函数

```javascript
function Animal(name) {
    this.name = name;
    this.colors = ["black"];
}
Animal.prototype.speak = function() {
    return `${this.name} speaks`;
};

function Dog(name, breed) {
    Animal.call(this, name);  // 借用父构造函数
    this.breed = breed;
}

const d1 = new Dog("Rex", "Lab");
const d2 = new Dog("Buddy", "Poodle");

d1.colors.push("white");
console.log(d2.colors);  // ["black"]（独立了！）

// 问题：方法在构造函数中定义，无法复用
d1.speak();  // TypeError: d1.speak is not a function
// 原型上的方法不可用
```

### 6.3 组合继承（最常用的经典方案）

```javascript
function Animal(name) {
    this.name = name;
    this.colors = ["black"];
}
Animal.prototype.speak = function() {
    return `${this.name} speaks`;
};

function Dog(name, breed) {
    Animal.call(this, name);   // 第一次调用Animal（借用构造函数）
    this.breed = breed;
}

Dog.prototype = new Animal();  // 第二次调用Animal（设置原型）
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function() {
    return "Woof!";
};

const d = new Dog("Rex", "Lab");
d.speak();  // "Rex speaks"
d.bark();   // "Woof!"

// 问题：Animal构造函数被调用了两次
// Dog.prototype上有无用的name和colors属性
```

### 6.4 寄生组合继承（理想方案）

```javascript
function Animal(name) {
    this.name = name;
    this.colors = ["black"];
}
Animal.prototype.speak = function() {
    return `${this.name} speaks`;
};

function Dog(name, breed) {
    Animal.call(this, name);  // 只调用一次Animal
    this.breed = breed;
}

// 关键：不通过new Animal()设置原型
// 而是创建一个[[Prototype]]指向Animal.prototype的空对象
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function() {
    return "Woof!";
};
```

**Object.create(Animal.prototype)**做了什么：

```
创建空对象 {} 
设置其[[Prototype]]为 Animal.prototype
返回该对象
```

这样Dog.prototype上没有多余的属性，Animal只被调用一次。

### 6.5 继承方式对比

| 方式 | 引用共享 | 可传参 | 原型方法可用 | 效率 |
|------|---------|--------|------------|------|
| 原型链 | ❌共享 | ❌不能 | ✅可用 | 一般 |
| 借用构造函数 | ✅独立 | ✅可以 | ❌不可用 | 差 |
| 组合继承 | ✅独立 | ✅可以 | ✅可用 | 调用两次 |
| 寄生组合 | ✅独立 | ✅可以 | ✅可用 | ✅最优 |


## 07.ES6 class的本质

### 7.1 class是语法糖

```javascript
class Animal {
    constructor(name) {
        this.name = name;
    }
    speak() {
        return `${this.name} speaks`;
    }
}

// 完全等价于：
function Animal(name) {
    this.name = name;
}
Animal.prototype.speak = function() {
    return `${this.name} speaks`;
};
```

验证：

```javascript
typeof Animal;  // "function"
Animal.prototype.constructor === Animal;  // true

const a = new Animal("Cat");
a.__proto__ === Animal.prototype;  // true
```

### 7.2 class与function的差异

虽然是语法糖，但class有一些额外的约束：

```javascript
// 1. class不能不用new调用
class Foo {}
Foo();  // TypeError: Class constructor Foo cannot be invoked without 'new'

// 2. class声明不会提升（有TDZ）
const a = new Bar();  // ReferenceError
class Bar {}

// 3. class内部默认严格模式
class Strict {
    method() {
        // 这里自动是严格模式
        x = 1;  // ReferenceError（未声明就赋值）
    }
}

// 4. class的方法不可枚举
class C {
    foo() {}
}
Object.keys(C.prototype);  // []（空！方法不可枚举）

// 对比function版本
function D() {}
D.prototype.foo = function() {};
Object.keys(D.prototype);  // ["foo"]（可枚举）
```

### 7.3 extends的底层实现

```javascript
class Animal {
    constructor(name) {
        this.name = name;
    }
    speak() {
        return `${this.name} speaks`;
    }
}

class Dog extends Animal {
    constructor(name, breed) {
        super(name);  // 必须先调用super
        this.breed = breed;
    }
    bark() {
        return "Woof!";
    }
}
```

`extends`在底层做了什么：

```javascript
// 1. 设置原型链
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

// 2. 设置构造函数的原型链（用于静态方法继承）
Object.setPrototypeOf(Dog, Animal);
// 这意味着：Dog.__proto__ === Animal
// 所以Dog可以访问Animal的静态方法
```

### 7.4 super关键字的原理

```javascript
class Parent {
    constructor() {
        this.x = 1;
    }
    hello() {
        return "parent hello";
    }
}

class Child extends Parent {
    constructor() {
        // super()调用父类构造函数
        // 在class继承中，this在super()之前是不存在的
        super();
        this.y = 2;
    }
    hello() {
        // super.hello()调用父类原型上的方法
        return super.hello() + " + child hello";
    }
}
```

**super()的内部机制**：

1. 调用`Parent.[[Construct]]()`创建`this`对象
2. 将`this`对象的`[[Prototype]]`设为`Child.prototype`
3. 返回`this`对象给Child的构造函数使用

这就解释了为什么**必须在访问this之前调用super()**。

### 7.5 私有字段

```javascript
class Account {
    #balance = 0;  // 私有字段（ES2022）
    
    deposit(amount) {
        if (amount > 0) {
            this.#balance += amount;
        }
    }
    
    get balance() {
        return this.#balance;
    }
}

const acc = new Account();
acc.deposit(100);
acc.balance;    // 100
acc.#balance;   // SyntaxError!
```

私有字段不存在于原型链上，它是每个实例独有的。V8使用内部的Private Brand Check机制来确保只有类自身的方法才能访问私有字段。

### 7.6 静态方法与静态字段

```javascript
class MathHelper {
    static PI = 3.14159;
    
    static add(a, b) {
        return a + b;
    }
}

// 静态成员属于构造函数本身，不在prototype上
MathHelper.PI;      // 3.14159
MathHelper.add(1,2); // 3

// 实例访问不到
const m = new MathHelper();
m.PI;   // undefined
m.add;  // undefined
```

静态方法可以被继承（因为`extends`设置了`Child.__proto__ === Parent`）：

```javascript
class Child extends MathHelper {}
Child.PI;       // 3.14159
Child.add(1,2); // 3
```


## 08.原型链的性能考量

### 8.1 原型链长度的影响

```javascript
// 原型链越长，查找越慢（虽然IC通常能缓存）
const a = {};
const b = Object.create(a);
const c = Object.create(b);
const d = Object.create(c);
const e = Object.create(d);

// 在e上查找a的属性需要遍历4层原型
e.somePropOnA;  // 要经过 e → d → c → b → a
```

V8的IC会缓存原型链上的属性位置，所以**重复访问不会反复遍历**。但以下情况会导致IC失效：

1. 原型链中任何对象的形状发生变化
2. 原型本身被替换

### 8.2 修改prototype的代价

```javascript
function Foo() {}
const a = new Foo();

// 直接修改prototype对象的属性——代价小
Foo.prototype.newMethod = function() {};

// 替换整个prototype对象——代价大！
Foo.prototype = { completelyNew: true };
// 所有已有的IC缓存失效
// V8需要重新建立所有相关的隐藏类转换
```

### 8.3 Object.setPrototypeOf的性能问题

```javascript
const obj = { x: 1 };
const proto = { y: 2 };

// 运行时修改原型——非常昂贵
Object.setPrototypeOf(obj, proto);
// V8必须：
// 1. 放弃当前的隐藏类
// 2. 创建新的隐藏类
// 3. 所有相关IC失效
// 4. 可能触发去优化
```

MDN官方警告：`Object.setPrototypeOf()`是一个非常慢的操作。如果性能重要，应该用`Object.create()`在创建时就设置好原型。

### 8.4 最佳实践

```javascript
// ✅ 好：创建时确定原型
const child = Object.create(parent);

// ✅ 好：给prototype添加方法
Parent.prototype.method = function() {};

// ❌ 差：运行时修改原型
Object.setPrototypeOf(existing, newProto);

// ❌ 差：替换整个prototype
Foo.prototype = newObject;  // 已有实例的原型链断裂

// ✅ 好：使用class（自动正确设置原型链）
class Child extends Parent {}
```


## 09.instanceof与类型判断原理

### 9.1 instanceof的算法

`instanceof`检查构造函数的`prototype`是否出现在对象的原型链上：

```
obj instanceof Constructor
等价于：
Constructor.prototype 是否在 obj的原型链上？
```

```javascript
function Foo() {}
const foo = new Foo();

foo instanceof Foo;     // true
// foo.__proto__ === Foo.prototype → true

foo instanceof Object;  // true
// foo.__proto__ (Foo.prototype)
// Foo.prototype.__proto__ === Object.prototype → true
```

### 9.2 手动实现instanceof

```javascript
function myInstanceOf(obj, Constructor) {
    if (obj === null || typeof obj !== 'object') return false;
    
    let proto = Object.getPrototypeOf(obj);
    const target = Constructor.prototype;
    
    while (proto !== null) {
        if (proto === target) return true;
        proto = Object.getPrototypeOf(proto);
    }
    
    return false;
}

// 验证
myInstanceOf([], Array);    // true
myInstanceOf([], Object);   // true
myInstanceOf({}, Array);    // false
```

### 9.3 Symbol.hasInstance

可以自定义instanceof的行为：

```javascript
class EvenNumber {
    static [Symbol.hasInstance](num) {
        return typeof num === 'number' && num % 2 === 0;
    }
}

2 instanceof EvenNumber;   // true
3 instanceof EvenNumber;   // false
"2" instanceof EvenNumber; // false
```

### 9.4 instanceof的边界情况

```javascript
// 原始类型总是返回false
"hello" instanceof String;  // false
42 instanceof Number;       // false

// 跨iframe/realm时失效
// iframe中的Array !== 父页面的Array
// iframe中创建的数组 instanceof Array 返回 false

// 更可靠的类型检查
Object.prototype.toString.call([]);        // "[object Array]"
Object.prototype.toString.call(/regex/);   // "[object RegExp]"
Array.isArray([]);                          // true（跨realm也正确）
```

### 9.5 完整的类型判断方案

```javascript
function getType(value) {
    if (value === null) return 'null';
    if (value === undefined) return 'undefined';
    
    const type = typeof value;
    if (type !== 'object') return type;  // 'number', 'string', 'boolean', etc.
    
    // 对象类型用Object.prototype.toString
    const tag = Object.prototype.toString.call(value);
    // "[object Array]" → "Array"
    return tag.slice(8, -1);
}

getType(null);        // "null"
getType(42);          // "number"
getType([]);          // "Array"
getType(/regex/);     // "RegExp"
getType(new Map());   // "Map"
getType(new Date());  // "Date"
```


## 10.Object.create与原型式继承

### 10.1 Object.create的原理

```javascript
// Object.create的polyfill
function objectCreate(proto, propertiesObject) {
    if (typeof proto !== 'object' && typeof proto !== 'function' && proto !== null) {
        throw new TypeError('Object prototype may only be an Object or null');
    }
    
    function F() {}
    F.prototype = proto;
    const obj = new F();
    
    if (propertiesObject !== undefined) {
        Object.defineProperties(obj, propertiesObject);
    }
    
    return obj;
}
```

### 10.2 Object.create(null) 的特殊用途

```javascript
// 创建一个没有原型的纯净对象
const dict = Object.create(null);
dict.hasOwnProperty = "oops";  // 不会覆盖Object.prototype.hasOwnProperty
// 因为dict根本没有原型链，没有继承的方法

// 用作纯净的字典/映射
dict["key"] = "value";
"toString" in dict;  // false（没有继承toString）

// 对比普通对象
const obj = {};
"toString" in obj;   // true（继承了Object.prototype.toString）
```

`Object.create(null)`常用于：
- 作为Map的替代品（旧代码中）
- 避免原型污染攻击
- 纯粹的键值存储

### 10.3 属性描述符

Object.create的第二个参数可以定义属性描述符：

```javascript
const obj = Object.create(Object.prototype, {
    name: {
        value: "Alice",
        writable: true,
        enumerable: true,
        configurable: true
    },
    age: {
        get() { return this._age; },
        set(v) { this._age = v > 0 ? v : 0; },
        enumerable: true,
        configurable: true
    }
});
```


## 11.Mixin模式与多继承模拟

### 11.1 JavaScript不支持多继承

```javascript
// 无法同时继承两个类
class C extends A, B {}  // SyntaxError
```

### 11.2 Mixin模式

```javascript
// 定义Mixin为函数
const Serializable = (Base) => class extends Base {
    toJSON() {
        return JSON.stringify(this);
    }
    static fromJSON(json) {
        return Object.assign(new this(), JSON.parse(json));
    }
};

const Validatable = (Base) => class extends Base {
    validate() {
        for (const [key, value] of Object.entries(this)) {
            if (value === null || value === undefined) {
                throw new Error(`${key} is required`);
            }
        }
        return true;
    }
};

// 组合使用
class User extends Serializable(Validatable(Object)) {
    constructor(name, email) {
        super();
        this.name = name;
        this.email = email;
    }
}

const user = new User("Alice", "alice@example.com");
user.validate();  // true
user.toJSON();    // '{"name":"Alice","email":"alice@example.com"}'
```

### 11.3 Mixin的原型链分析

```javascript
class User extends Serializable(Validatable(Object)) {}

// 原型链：
// user → User.prototype → Serializable_class.prototype → Validatable_class.prototype → Object.prototype → null
```

Mixin函数每次调用都返回一个新的匿名类，这些类链式继承，形成了一条长原型链。

### 11.4 Object.assign方式的Mixin

```javascript
// 更简单但功能更弱的Mixin方式
const EventEmitter = {
    on(event, listener) {
        if (!this._events) this._events = {};
        if (!this._events[event]) this._events[event] = [];
        this._events[event].push(listener);
        return this;
    },
    emit(event, ...args) {
        if (this._events && this._events[event]) {
            this._events[event].forEach(fn => fn.apply(this, args));
        }
        return this;
    }
};

class Button {
    constructor(text) {
        this.text = text;
    }
}

Object.assign(Button.prototype, EventEmitter);

const btn = new Button("Click me");
btn.on("click", () => console.log("Clicked!"));
btn.emit("click");  // "Clicked!"
```

这种方式将方法直接复制到目标原型上，不创建额外的原型链层级。但缺点是无法使用`super`和`instanceof`检查。


## 12.原型污染与安全防护

### 12.1 什么是原型污染

原型污染（Prototype Pollution）是一种安全漏洞，攻击者通过修改`Object.prototype`来影响所有对象：

```javascript
// 不安全的深合并函数
function unsafeMerge(target, source) {
    for (const key in source) {
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            unsafeMerge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}

// 攻击payload
const malicious = JSON.parse('{"__proto__": {"isAdmin": true}}');
unsafeMerge({}, malicious);

// 现在所有对象都有isAdmin属性了！
const user = {};
console.log(user.isAdmin);  // true ← 原型被污染
```

### 12.2 防护措施

```javascript
// 1. 使用Object.create(null)作为存储
const safeMap = Object.create(null);

// 2. 过滤危险的键名
function safeMerge(target, source) {
    for (const key of Object.keys(source)) {
        if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
            continue;  // 跳过危险键
        }
        if (typeof source[key] === 'object' && source[key] !== null) {
            target[key] = target[key] || {};
            safeMerge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}

// 3. Object.freeze冻结原型
Object.freeze(Object.prototype);
// 防止任何修改（但可能破坏依赖原型修改的库）

// 4. 使用Map代替普通对象
const map = new Map();
// Map不受原型污染影响
```

### 12.3 密封与冻结

```javascript
// Object.preventExtensions — 禁止添加新属性
const obj1 = { x: 1 };
Object.preventExtensions(obj1);
obj1.y = 2;        // 静默失败（严格模式TypeError）
obj1.x = 10;       // 允许修改已有属性

// Object.seal — 禁止添加/删除属性，禁止配置变更
const obj2 = { x: 1 };
Object.seal(obj2);
obj2.y = 2;        // 失败
delete obj2.x;     // 失败
obj2.x = 10;       // 允许修改值

// Object.freeze — 完全不可变
const obj3 = { x: 1 };
Object.freeze(obj3);
obj3.x = 10;       // 失败
obj3.y = 2;        // 失败

// 注意：freeze是浅冻结
const obj4 = { nested: { y: 2 } };
Object.freeze(obj4);
obj4.nested.y = 99; // 成功！nested对象未被冻结
```

### 12.4 总结：原型链的核心要点

1. **对象通过[[Prototype]]链接成链**——属性查找沿链向上
2. **所有链最终到Object.prototype → null**
3. **prototype是函数的属性**，`__proto__`是对象的原型引用
4. **new的本质**是创建对象、设置原型、执行构造函数
5. **继承的最佳实践**：寄生组合继承 → ES6 class
6. **class是语法糖**但有额外的安全约束
7. **IC和隐藏类**使原型链查找在实际运行中接近O(1)
8. **原型链安全**：防止污染、适度冻结、使用Map
