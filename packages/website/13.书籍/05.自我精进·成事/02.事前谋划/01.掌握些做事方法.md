## 01.看一个真实案例

我做技术第三年的时候，自我感觉相当良好：不挑活、不甩锅、加班最多、需求也接得最多。直到一次跨部门项目复盘会上，我所在小组负责的接口在上线第二天出了 P1 故障，原因是我提前没和数据团队对齐字段口径。会议室里所有人都看着我，产品老大只问了一句：「你之前为什么没跟数据组确认？」

我答：「我以为他们的接口和我们对齐了」。老大叹了一口气说：**「『我以为』三个字，是我从你嘴里听到第三次了」**。

那一刻我才意识到，我所谓的「靠谱」，其实只是「任劳任怨」。**我做完了眼前的需求，但事前不主动了解上下游、事中不和协作方拉齐、事后也没有复盘沉淀**。我所有的努力都集中在一个最窄的环节里，自然每次都会在事前和事后翻车。

那场复盘开完，部门一位老前辈把我拉到楼下抽烟，跟我讲了一段我一直记到现在的话：

> 做事靠谱不靠谱，行业里有三条公认的标准：第一是有没有**闭环思维**，你管不管事前事后；第二是有没有**方法论**，你做事是凭感觉还是有套路；第三是能不能**拿到结果**，拿不到结果，前两条都白搭。

他说完这三条，我脑子里那种「我已经很努力了」的虚假成就感，第一次被戳破。**后来这一年，我真的按这三条去重新构建自己的做事方式，整个人的「职场质感」才彻底变了**。这一节，我就把当时学到的整套做事方法论，从头讲给你。

**用一个每天都在用的场景理解「闭环」**：你打车说「去机场」。开环的司机凭记忆一路开，堵没堵、飞机准点没、他都不管，你只能忐忑坐着；闭环的高德地图规划路线、实时说「前方拥堵 500 米」、主动提示「新路线快 5 分钟」、最后确认「您已到达」。**闭环思维就是给自己的工作装一台「高德地图」：在不确定中反馈、在反馈中调整、在调整中掌控**。

## 02.断点自测三问

在往下读之前，先做三道判断题。任意一题命中，这一节就值得你认真读完。

| 断点 | 自测题 | 症状描述 |
|:----:|:------|:--------|
| 只顾事中 | 你上一个交付的事情，事前有没有主动了解「为什么做」？事后有没有主动做过总结？ | 只在「事中」努力，事前事后放羊 |
| 全凭感觉 | 你回答「你是怎么做出来的」，能说出一套可复用的方法吗？ | 没有方法论支撑，做一次算一次 |
| 结果不闭环 | 事情做完之后，你有没有主动跟老板汇报结果和下一步？ | 等别人来问 = 让别人评价你 |

三道题依次对应本节的三条主线：**闭环思维 = 事前 + 事中 + 事后**、**用方法论替代感觉**、**主动交付结果**。你在哪一条上薄，就重点看那一段。

## 03.先来说一个背景

先看一个案例，你在工作中肯定听到过这样的评价：「这个人做事很靠谱」或者「这个人做事很厉害」。同一个部门的人，级别一样、岗位职责一样、参与的项目也差不多，为什么你会觉得其中某些人做事就是比大部分人更靠谱、更厉害呢？

你可能会认为这是因为他们态度更积极、更加会表现。但是如果你带过团队就会知道，**做事的态度和做事的能力不是等价的**。尤其是在部门绩效拉通和晋升预审这些场合，如果你向其他部门的负责人介绍的时候说自己团队的某个成员「做事积极主动，很认真，很拼」，那么多半会被「怼」得很惨。

那么，高级别的管理者是怎么判断你的做事能力强不强的呢？有三条判断标准是能够达成共识的。

## 04.能力的判断标准

**判断标准一：闭环思维**。闭环思维是最基本的能力要素，也就是说，**做事的时候不能只是完成任务了事，而是要从端到端的角度去思考和落地**。

无论什么事情，端到端的过程都可以分为事前规划、事中执行和事后总结三个阶段，但是大部分人都只关注「事中执行」的阶段，而对事前和事后两个阶段并不在意。三个阶段的核心动作与状态对比很清晰：

| 阶段 | 核心动作 | 大部分人的状态 | 闭环思维的做法 |
|:----|:----|:----|:----|
| **事前规划** | 了解背景、明确价值 | 「这不是我的事」 | 主动了解「为什么做、价值是什么」|
| **事中执行** | 落地方案、推进任务 | 只关注这个阶段 | 高质量执行 + 及时同步信息 |
| **事后总结** | 复盘结果、提炼经验 | 觉得「不是必须的」| 主动总结、汇报、沉淀方法论 |

举个开发案例：**你只负责开发环节，但如果按照闭环思维来做事**，在做之前你除了理解需求之外，还应该去了解「为什么做这个需求」「需求的价值是什么」（事前规划）；需求上线之后，你还应该去了解「需求上线后的结果怎么样」「具体的业务数据是多少」「我通过做这件事情收获了什么」（事后总结）。而如果你本来就是端到端地负责某件事情的话，那就更加需要学会事后复盘、给领导汇报等技巧，而不是做完事情之后被动地等着别人来问结果。

**判断标准二：方法论**。有了闭环思维，做事就已经比较靠谱了。但是事情能不能做得漂亮，光有闭环思维是不够的，还需要看你做事有没有方法论，也就是说：**你做事的时候不只是靠经验教训的历史积累，还有一套系统的流程或者模板**。

方法论有两大优势：**保证下限**（无论遇到什么情况都能取得比较好的结果，能够保证交付质量的下限；否则如果只凭经验，那么下次情况稍微发生一些变化你就不适应了）；**逻辑说服**（你的行为背后是有一套逻辑支撑的，而不是拍脑袋随便拍出来的，这样会更有说服力）。

**判断标准三：拿到好结果**。有了方法论是不是就一定很厉害呢？其实还不一定。首先，你的方法论可能是错误的；其次，你之前形成的方法论可能很厉害，但并不适合当前公司或者业务。所以最后，**判断你的方法论好不好，其实还是要看最后的结果好不好、给公司带来了多少价值**。这也是很多从大公司出来的高 P 人员拿着原来的方法论到了中小公司或者创业公司、生搬硬套导致水土不服的原因。

## 05.讲究做事的方法

经过多年的实践检验和筛选，我逐步形成了一套系统的做事方法论，它按照闭环思维的三个阶段展开：

**事前规划**阶段的核心方法：**OKR 规划法**：英特尔提出、谷歌发扬光大的方法，通过合理地设定目标和分解关键成果来弥补 KPI 的缺陷。OKR 不同于传统 KPI 规划，更加注重聚焦和逻辑，你可以理解为「**OKR 教你如何制定牛逼的 KPI**」（详见 2.3）。

**事中执行**是大部分人最熟悉、也最容易「不讲究」的阶段：

1. **3C 方案设计法**（原创）：通过制定多个备选方案来系统地分析事情相关的方方面面，避免思维狭隘，用于设计合理的落地方案（详见 2.8）。
2. **PDCA 执行法**（美国提出、日本发扬光大）：通过四个环节的循环来把控执行过程，保证具体事项高效高质地落地（详见 3.1）。
3. **5W 根因分析法**（丰田五问法）：通过五个为什么来深挖问题本质，用于分析根本原因（详见 3.3）。
4. **5S 问题处理法**（原创）：通过五个步骤来解决问题，化「危」为「机」（详见 3.4）。

**事后总结**往往是最被忽略却最值钱的阶段，它直接决定你能不能从一件事里「长出能力」：

1. **4D 总结法**（原创）：通过四个维度来整理做事的收获，能够帮助你在完成任务后进一步全方位地提升自己的能力（详见 4.1）。
2. **金字塔汇报法**（麦肯锡）：通过遵循四个原则来展示工作成果，从而更容易获得高级别管理人员的认可（详见 4.2）。
3. **四线复盘法**（原创）：通过四个角度来复盘重大问题，达到公平公正的处理效果，避免背锅和甩锅（详见 4.3）。

## 06.做事方法论全景

按照闭环三阶段展开，本册后面所有章节的方法论可以归为三大类，覆盖事前、事中、事后全流程：

| 阶段 | 方法论 | 用途 |
|:----|:----|:----|
| **事前规划** | OKR 规划法 | 制定工作规划和目标 |
| | SMART 目标法 | 设定清晰可衡量的目标 |
| | SWOT 分析法 | 分析内外部优势与劣势 |
| **事中执行** | 3C 方案设计法 | 设计有理有据的方案 |
| | PDCA 执行法 | 保证事项高效落地 |
| | 5W 根因分析法 | 深挖问题根本原因 |
| | 5S 问题处理法 | 系统地处理问题 |
| | 番茄工作法 | 提升专注力与执行效率 |
| | RACI 责任矩阵 | 明确任务角色分工 |
| **事后总结** | 4D 总结法 | 全方位事后总结 |
| | 金字塔汇报法 | 结构化展示工作成果 |
| | 四线复盘法 | 重大问题复盘改进 |
| | STAR 汇报法 | 结构化讲述工作经历 |

除上面三大类之外，还有一类「无处不在」的通用方法论，包括**二八法则、六顶思考帽、MECE 分析法、鱼骨图分析法**等。它们不属于事前、事中、事后任何一个阶段，但可以在任何阶段灵活使用，是真正帮助你建立「思维质感」的底层工具。

## 07.这几个坑我踩过

**坑一：贪多学 10 种、一个都没用起来**。第一次接触做事方法论时我打了鸡血，把 OKR / PDCA / SMART / 5W / 4D 全部学完，笔记记了 30 多页。结果一个月过去，工作里我一个都没有真正用起来，**因为「学了」和「用了」中间隔着 100 次机械练习**。后来我只挑了 PDCA 一个方法，逼自己每一个任务都完整跑一遍，跑满 30 天后再学下一个。

**坑二：把方法论当装饰**。有段时间我特别喜欢在周会上说「用 SMART 拆一下」「先做 SWOT」，但结果并没有更好：**因为我只是把术语当装饰，从没真正按方法论的步骤走完过**。后来我立了一条硬规矩：说出来的方法论必须现场把每一步展开写在白板上，说不清楚就是没懂。

**坑三：方法论用错场景**。我曾经在一个只需要 1 天交付的紧急需求上用 OKR 拆目标、用 SWOT 分析优劣，结果 4 个小时耗在写文档上，需求延迟 1 天。**方法论有它的适用尺度**：日常小事用 PDCA 就够了，只有战略级动作才配得上 OKR + SWOT 这类重型工具。

## 08.总结回顾本章节

**做事能力 = 闭环思维 + 方法论 + 结果，三者缺一不可**。

你应该带走三件事：

1. **补齐事前和事后，是从「勤快」升到「靠谱」的分水岭**：多数人只在事中努力，闭环思维是最容易补、也最快见效的一层。
2. **方法论少即是多，一个方法用 30 天胜过 10 个方法各用 3 天**：知道 100 种方法不如把 3 种方法用到形成肌肉记忆。
3. **方法论的价值 = 让你这次比上次做得更好**：不能被结果验证的方法论都是装饰。

## 09.后来发生的改变

**1. 「事前 5 问」+ 「事后小结」**。那次背锅之后的下一周，我就给自己强行加了两条死规矩：**每个需求开始前 30 分钟做「事前 5 问」**（为什么做、谁是受益方、有哪些上下游、最坏会出什么事、做完拿什么衡量）；**每个需求上线后第二天补一份 200 字的「事后小结」**。第一周写的时候极度别扭，几乎每件事都暴露出「我其实不知道为什么做」。但坚持一个月后，我发现自己接需求时脑子里冒的问题越来越精准，事前对齐的会议越来越短：**因为很多疑问我已经提前想清楚了**。

**2. 挑两个方法用一个月**。我没有贪多。从全景图里我只挑了两个最常用的：事中执行的 PDCA、事中决策的 3C 方案设计法。一个月里凡是做事，我都强迫自己用一次：接到一个迭代任务，先 P（写计划）→ D（动手做）→ C（自查 + 测试）→ A（复盘改进）；任何要做选择的地方，必列 3 个备选方案，写出优缺点。一个月后我发现一个让我自己都意外的变化，**我做事的「返工率」骤降**。以前总是上线后才发现遗漏，现在很多坑在 P 阶段就被堵掉了。

**3. 半年后成方法论沉淀代表**。半年后的部门盘点，我被点名作为方法论沉淀的代表，做了一次内部分享，分享主题是「我是怎么把每件事都做闭环的」。**Leader 在我那一格的评语只有一句：「做事的『手感』不一样了，可以扛大事了」**。更让我自己有感触的是，我已经不再害怕复盘会了：因为现在每次复盘我都能讲清楚：我为什么这么决策、用了什么方法、结果如何、下次怎么改。**做事方法论真正改变我的，不是让我多做了多少事，而是让我每件事都「长在了我身上」**。

## 10.今天起改变三点

**1. 建立闭环思维**。接到下一个任务时，不要直接埋头开干。先花 10 分钟了解：为什么要做这件事？它的价值是什么？做完之后，再花 10 分钟总结：结果怎么样？我学到了什么？下次可以怎么改进？**这 30 分钟的额外投入，会让你的做事质量产生质的飞跃**。

**2. 选择一个方法论实践**。不要贪多，先从最简单的开始。推荐从 PDCA 执行法入手，下一次做事的时候，先列计划（Plan），再执行（Do），做完检查结果（Check），最后总结改进（Action）。**用一个月时间把这个方法练熟，再去学习下一个**。

**3. 用结果验证方法论**。方法论好不好，不是看理论多么高大上，而是看用了之后结果有没有变好。每次使用方法论后，记录一下：用了什么方法？效果如何？哪里可以改进？**持续迭代，形成属于你自己的做事方法体系**。

**送你一个每天都能用的「闭环小工具」：5 分钟回执法**。邮件 / 消息发出去 5 分钟内，一定在 IM 里补一句「刚发了 XXX，方便看一眼吗？」如果对方没回，5 分钟后电话再补一通。听起来啰嗦，但效果惊人：**「我以为对方在做」这句话从此从你的语言里消失**。这条小规则单独一个动作就能让你的协作事故率降一大半，是所有做事方法论中「投入最小、收益最大」的一条。

## 11.课后作业思考下

1. **闭环自检**：回顾你最近完成的一个项目或任务，用「事前规划 - 事中执行 - 事后总结」三个阶段来审视，你在哪个阶段做得好，哪个阶段有欠缺？

2. **观察靠谱人**：找一位你认为「做事很靠谱」的同事或前辈，观察他 / 她做事的方式，看看能否识别出他 / 她使用了哪些方法论（即使他 / 她自己并不自知）。

3. **实践一个新方法**：从本章列出的方法论全景中，选择一个你从未用过的方法论，在下一周的工作中刻意实践一次，记录使用过程和效果。

4. **沉淀你的方法论**：思考一下：你自己有没有什么独特的做事方法？如果有，试着用「背景 - 步骤 - 案例 - 适用场景」的结构把它整理出来，形成你自己的方法论。
