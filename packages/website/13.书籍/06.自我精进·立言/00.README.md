系列贯穿语是「**学得会，做得到，说得清**」，本卷负责最后一环——**说得清**，并把能力放大出去。

## 2. 为什么叫「立言」

**「立言」= 内在思想 + 外在言说**，一个词同时涵盖本卷两块内容：

```text
立言
 ├─ 立（思想）：专注 · 记忆 · 思考 · 质疑 · 情商   → 第 4 章
 └─ 言（言说）：底蕴 · 沟通 · 提问 · 演讲         → 第 1-3 章
```

所以第 4 章的 7 节思维内容**不是跑题，而是「立」的那半边**。这正是本书区别于市面「话术类」表达书的关键——**只教话术的书，读者学完依然说不出有内容的话**。

同时，「立言」出自传统「三不朽」（立德、立功、立言）：

```text
卷一 学习（修己）  →  卷二 成事（立功）  →  卷三 立言（传世）
```

## 8. 出版级质量标准

本册所有正文均以 [14. 思考能力的提升](./14.思考能力的提升.md) 的开篇对比案例（「小李 2 小时画图 vs 我 3 天 30 页 PPT」）与卷一 [1.2 需求层次的模型](../04.自我精进·学习/02.需求层次的模型.md) 为标杆样板。开篇必是数据化对比案例，冲突感与画面感俱全，写清人、时、地、数，而不是「有一个朋友」式的模糊叙事。理论段后两百字内必须接作者一手经验；由于本册立意是「立言 = 立（思想）+ 言（言说）」，第 4 章每一节结尾必须补一段「这个思维能力如何在第 1-3 章的表达场景里兑现」的案例链，让「立」与「言」在正文层咬合。

每节 mermaid 控制在两张以内且必须承载因果或流程，罗列型图（把文字搬进方框、无信息增量的）一律删除或降级为表格——本册图密度问题三册最重，图瘦身放在最优先。少用 `- ` 列表与 `> ` 引用，用流畅段落 + `**bold**` 强调；凡列表超过 5 项即改写为段落。技术场景每节至少一处，可以是写技术分享稿、做技术演讲、写述职材料、跨团队评审答辩。

结尾五段式必备：总结回顾三件事、后来发生的改变、今天起改变三点、课后作业思考、下一站过渡。每章开头须有一张 30 秒可读完的断点自测表，与开篇的「三层欠账」框架直接挂钩。所有小节标题严格控制在 7 字。
