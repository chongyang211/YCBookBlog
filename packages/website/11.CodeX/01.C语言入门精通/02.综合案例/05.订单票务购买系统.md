# 第五章：C语言 订单票务购买系统

本章是综合案例的**第五关·并发栈集大成**，前 4 个案例都是**单线程程序**，从本章开始我们正式踏入"多核时代"，理解为什么"加锁"看起来简单，写错却会导致**死锁、数据竞争、活锁**等"幽灵 BUG"。本案例把**票务购买 + 线程池**两大经典场景融合为一个完整的"多线程订单系统"，一次练遍 C 并发的**八大核心**：

> 1. **`pthread_create` + `pthread_join`**：最基础的"启动线程 + 等待回收"
> 2. **`pthread_mutex_t`**：互斥锁——临界区的入门标配
> 3. **`pthread_cond_t`**：条件变量，生产者-消费者模式，订单队列的灵魂
> 4. **`pthread_rwlock_t`**：读写锁，多读单写
> 5. **C11 `atomic_int` + CAS**：无锁计数器、原子扣库存（`<stdatomic.h>`）
> 6. **手写 mini future** ⭐：C 没有 future/promise——用"结果槽 + mutex + cond"亲手造一个，你就看穿了 C++ `std::future` 的裸机本质
> 7. **完整的线程池组件**：可重用的工业级线程池（函数指针 + `void*` 泛型）
> 8. **策略模式**：不同订单类型（普通/秒杀/批量）用不同的下单策略——**函数指针表**（03 案例手动 vtable 的进阶应用）

> 📌 **和 C++ 版同一道题的两种解法**：C++ 版（[05.订单票务购买系统](../02.Cpp入门到精通/02.综合案例/05.订单票务购买系统.md)）靠 `std::thread + RAII lock_guard + future + 模板` 把并发细节藏进语言特性；C 版**没有 RAII、没有 future、没有模板、没有 lambda**——你将亲手写出这些机制被隐藏前的样子：**`goto unlock` 管锁、手写 future、函数指针当 std::function**。写完本章再看 C++ 的 `<thread>`/`<future>`，你会知道每一层语法糖下面是什么。

**学习方式**：本案例按"并发原语拆解 → 写代码 → 跑压测 → 看竞态 → 加锁修复"五步法循环。总共 7 个阶段、约 14 小时，建议分 4 天完成。**并发代码不能只"跑过一次"**，一定要跑 benchmark 反复压测，才能揭出隐藏的竞态问题。

⚠️ **C 语言新手并发五宗罪**（每一宗本章都会现场演示）：

> 1. **忘了 `pthread_mutex_unlock`**（提前 return 走了）→ 全部线程永久卡死
> 2. **`pthread_cond_wait` 不套 while** → 虚假唤醒直接穿透条件检查
> 3. **忘了 `-pthread` 编译开关** → `undefined reference to pthread_create`
> 4. **裸 int 多线程读写** → 数据竞争是**未定义行为**，超卖/撕裂随缘
> 5. **`pthread_detach` 后线程还摸主线程的栈变量** → 悬垂指针段错误

## 01.项目需求和功能

### 1.1 业务场景

电商秒杀系统是工业界最经典的并发场景：
- 商品库存有限（如 100 件）
- 几千个用户同时下单
- 必须保证：**不超卖、不漏单、响应快**

本案例用 **pthread + C11 atomic** 实现一个微缩版的订单系统，同时演示**线程池**这个工业组件。线程池是几乎所有 C 服务端应用（Nginx、Redis 6.0+、memcached）的基石，你后续学网络编程、数据库都绕不开它。

> 💼 **pthread 是什么**：POSIX Threads——1995 年标准化的线程库，Linux/macOS 系统自带。C11 标准也定义了 `<threads.h>`（thrd_create），但工业界实际仍以 pthread 为主（挑战 A 会带你体验 C11 线程库）。

### 1.2 三种下单策略

| 策略 | 特点 | 实现要点 |
|------|------|---------|
| **普通下单** normal | 单线程逐个处理 | 加 mutex 保护订单列表即可 |
| **秒杀下单** flash | 高并发抢库存 | atomic CAS 防超卖 + 线程池并发 |
| **批量下单** batch | 一次提交多个订单 | future 收集每批的处理结果 |

**业务规则**：
- 用户输入"商品 ID + 数量"即下单
- 系统校验库存→扣减→生成订单→记录日志
- 任何一步失败，整个下单返回失败

### 1.3 并发挑战

**典型 BUG 重现**，这一节告诉你"为什么不加锁就会出问题"：

```c
/* ❌ 错误代码（不加锁）*/
typedef struct {
    int stock;              /* ⚠️ 裸 int */
} product_bad_t;

bool buy(product_bad_t *p, int n) {
    if (p->stock >= n) {    /* ① 检查 */
        p->stock -= n;      /* ② 扣减 */
        return true;
    }
    return false;
}

/* 1000 个线程同时调 buy(p, 1) 会怎样？
 * 假设 stock = 1，线程 A 和 B 同时进 if (p->stock >= n)，都通过
 * A 执行 p->stock -= n → stock = 0
 * B 执行 p->stock -= n → stock = -1   ⚠️ 超卖了！*/
```

**修正方案**：用 C11 `atomic_int` 配合 CAS 循环，详见第 05 节。

## 02.阻塞队列基础组件

```
┌─ 🎯 阶段 ① 目标 ────────────────────────────────────────┐
│ 完成什么：blocking_queue_t（线程安全的生产者消费者队列）   │
│ 不做什么：还不接 ThreadPool，先把队列单独跑通              │
│ 验收标准：1 生产者 + 1 消费者两个线程互不干扰跑通 100 条数据 │
│ 预计耗时：60 min · 4 Step（每步都能编译运行）              │
└──────────────────────────────────────────────────────────┘
```

💡 **为什么先做这个？** —— 线程池 = "工人 + 任务队列"。任务队列单独抽出来叫 `blocking_queue`，它会被工人线程并发 push/pop。先把队列做对，线程池就成功了一半。

⚠️ **本阶段的核心难点**：你要**亲眼看到**"不加锁会乱"，所以我们故意从"无锁裸版"起步，先看到崩溃，再一步步加 `mutex` → `cond` → `shutdown` 把它治好。

---

### 灵魂三问：动手前先想清楚

❓ **既然链表/数组谁都会写，为什么还要专门包一个"阻塞队列"？**

来看反例：

```c
/* ❌ 反例：直接让多线程操作裸链表 */
naive_queue_t q;                                 /* head/tail 两个指针 */

void *producer(void *arg) {
    for (int i = 0; i < 1000; i++) nq_push(&q, box(i));   /* 写 */
    return NULL;
}
void *consumer(void *arg) {
    while (!done) {
        void *v = nq_pop(&q);                    /* 读 */
        if (v) count++;
    }
    return NULL;
}
```

**问题**：

1. **裸链表不是线程安全的**——`tail->next = n` 和 `head = head->next` 被并发改写，**指针直接损坏 → segfault**
2. **"空检查 + pop"不是原子的**——刚检查非空，下一微秒被别的线程 pop 掉，你再 pop 就是空指针解引用
3. **没办法"等数据来"**——只能 `while(1)` 死循环空转，100% 吃 CPU

✅ **正确做法**：把"队列 + 锁 + 条件变量"封装成一个组件，**让所有并发细节集中在一个文件里**。这就是软件工程上的"封装变化"。

❓ **为什么要先做无锁版（Step 1.1）再加锁（Step 1.3）？不是浪费时间吗？** 答：**这是教学法刻意安排**。如果一上来就给你"完美的最终版"，你只会**机械记住代码**而不知道每一行的存在意义。**先看到无锁版的崩溃**（Step 1.2），你才会真正理解 mutex / cond / shutdown 一个都不能少。**这与 04 案例 §8.3 offset 错位 BUG**、**03 案例 §08 加载顺序 BUG** 同源——**先有问题，后有解法**。

❓ **C 没有 RAII（lock_guard），unlock 怎么保证不丢？**

C++ 的 `lock_guard` 靠"析构函数自动执行"兜底；C 只能靠**纪律 + 代码结构**——**所有出口共用一个 unlock 点**，惯用法是 `goto unlock`：

```c
bool queue_op(my_queue_t *q, ...) {
    bool ok = false;
    pthread_mutex_lock(&q->mtx);
    if (出错了条件1) goto unlock;          /* ⭐ 所有提前退出走同一出口 */
    if (出错了条件2) goto unlock;
    ... 正常逻辑，ok = true ...
unlock:                                     /* ⭐ 唯一 unlock 点 */
    pthread_mutex_unlock(&q->mtx);
    return ok;
}
```

> 🔑 这与 04 案例 JSON 解析器的 `goto fail` 是**同一个惯用法**：C 没有异常和析构，**"集中出口 + goto 收尾"就是 C 的 try/finally**。Linux 内核里最多的一行代码就是 `goto out`。

```c
#define BLOCKING_QUEUE_H

} blocking_queue_t;

void bq_destroy(blocking_queue_t *q);
```

```c
/* blocking_queue.c（v1）*/
#include "blocking_queue.h"

#include <stdlib.h>

void bq_init(blocking_queue_t *q) {
    q->head = q->tail = NULL;
    q->len = 0;
}

void bq_destroy(blocking_queue_t *q) {
    bq_node_t *n = q->head;
    while (n) {
        bq_node_t *next = n->next;
        free(n);
        n = next;
    }
    q->head = q->tail = NULL;
    q->len = 0;
}

void bq_push(blocking_queue_t *q, void *item) {
    bq_node_t *n = malloc(sizeof *n);
    n->item = item;
    n->next = NULL;
    if (q->tail) q->tail->next = n;
    else         q->head = n;          /* 第一个元素 */
    q->tail = n;
    q->len++;
}

bool bq_pop(blocking_queue_t *q, void **out) {
    if (!q->head) return false;
    bq_node_t *n = q->head;
    *out = n->item;
    q->head = n->next;
    if (!q->head) q->tail = NULL;      /* 弹空了 */
    q->len--;
    free(n);
    return true;
}

size_t bq_size(blocking_queue_t *q) { return q->len; }
```

```c
#include <stdatomic.h>
```

### Step 1.3 mutex 修复竞争

**升级 `blocking_queue.h/.c`**（v2：加 mutex）：

```c
#include <pthread.h>

typedef struct {
    bq_node_t *head;
    bq_node_t *tail;
    size_t len;
    pthread_mutex_t mtx;            /* ⭐ 全部操作都由它保护 */

/* 接口签名升级：push 返回成败（可能 shutdown/内存失败）*/

```

```c
/* blocking_queue.c（v2：每个操作"lock → 干活 → unlock"）*/
bool bq_init(blocking_queue_t *q) {
    q->head = q->tail = NULL;
    q->len = 0;
    return pthread_mutex_init(&q->mtx, NULL) == 0;
}

bool bq_push(blocking_queue_t *q, void *item) {
    pthread_mutex_lock(&q->mtx);
    bq_node_t *n = malloc(sizeof *n);
    if (!n) {
        pthread_mutex_unlock(&q->mtx);      /* ⭐ 失败路径也要解锁！*/
        return false;
    }
    n->item = item;
    n->next = NULL;
    if (q->tail) q->tail->next = n;
    else         q->head = n;
    q->tail = n;
    q->len++;
    pthread_mutex_unlock(&q->mtx);
    return true;
}

bool bq_pop(blocking_queue_t *q, void **out) {
    pthread_mutex_lock(&q->mtx);
    if (!q->head) {
        pthread_mutex_unlock(&q->mtx);      /* ⭐ 空也要解锁 */
        return false;
    }
    bq_node_t *n = q->head;
    *out = n->item;
    q->head = n->next;
    if (!q->head) q->tail = NULL;
    q->len--;
    free(n);
    pthread_mutex_unlock(&q->mtx);
    return true;
}

size_t bq_size(blocking_queue_t *q) {
    pthread_mutex_lock(&q->mtx);
    size_t n = q->len;                      /* ⭐ 连"读 len"也要锁 */
    pthread_mutex_unlock(&q->mtx);
    return n;
}
```

### Step 1.4 阻塞 pop 与停机

**升级为最终版**：加 `pthread_cond_t` + `shutdown`：

```c
/* blocking_queue.h（v3：阻塞 + shutdown）*/
#include <pthread.h>

typedef struct {
    bq_node_t *head;
    bq_node_t *tail;
    size_t len;
    pthread_mutex_t mtx;
    pthread_cond_t  not_empty;      /* ⭐ 队列非空时通知 */
    bool stopped;
} blocking_queue_t;

bool  bq_init(blocking_queue_t *q);
void  bq_destroy(blocking_queue_t *q);
bool  bq_push(blocking_queue_t *q, void *item);
bool  bq_pop(blocking_queue_t *q, void **out);    /* 阻塞版 */
void  bq_shutdown(blocking_queue_t *q);
size_t bq_size(blocking_queue_t *q);
```

```c
/* blocking_queue.c（v3）*/
bool bq_init(blocking_queue_t *q) {
    q->head = q->tail = NULL;
    q->len = 0;
    q->stopped = false;
    if (pthread_mutex_init(&q->mtx, NULL) != 0) return false;
    if (pthread_cond_init(&q->not_empty, NULL) != 0) {
        pthread_mutex_destroy(&q->mtx);
        return false;
    }
    return true;
}

bool bq_push(blocking_queue_t *q, void *item) {
    bq_node_t *n = malloc(sizeof *n);
    if (!n) return false;
    n->item = item;
    n->next = NULL;

    pthread_mutex_lock(&q->mtx);
    if (q->stopped) {
        pthread_mutex_unlock(&q->mtx);
        free(n);
        return false;                       /* 停机后拒收 */
    }
    if (q->tail) q->tail->next = n;
    else         q->head = n;
    q->tail = n;
    q->len++;
    pthread_mutex_unlock(&q->mtx);
    pthread_cond_signal(&q->not_empty);     /* ⭐ 锁外通知（性能更好）*/
    return true;
}

bool bq_pop(blocking_queue_t *q, void **out) {
    pthread_mutex_lock(&q->mtx);
    /* ⭐ while 而不是 if：防虚假唤醒 + 防多个消费者竞争 */
    while (q->len == 0 && !q->stopped)
        pthread_cond_wait(&q->not_empty, &q->mtx);
    if (q->len == 0) {                      /* stopped 且空：下班信号 */
        pthread_mutex_unlock(&q->mtx);
        return false;
    }
    bq_node_t *n = q->head;
    *out = n->item;
    q->head = n->next;
    if (!q->head) q->tail = NULL;
    q->len--;
    free(n);
    pthread_mutex_unlock(&q->mtx);
    return true;
}

void bq_shutdown(blocking_queue_t *q) {
    pthread_mutex_lock(&q->mtx);
    q->stopped = true;                      /* 存量任务仍会被消费完 */
    pthread_mutex_unlock(&q->mtx);
    pthread_cond_broadcast(&q->not_empty);  /* ⭐ 唤醒所有等待者 */
}
```

### 灵魂三问：线程池设计要点

❓ **为什么不每来一个任务就 pthread_create 一个线程？**

来看反例：

```c
/* ❌ 每个请求开一个线程 */
void handle_request(request_t *r) {
    pthread_t tid;
    pthread_create(&tid, NULL, do_handle, r);
    pthread_detach(tid);                /* 挥手告别，生死不管 */
}
```

**问题**：

1. **创建线程很贵**——Linux `pthread_create` 约 50 微秒，处理一个简单请求可能就 1 微秒，**99% 时间花在创建线程**
2. **线程数无上限**——10 万个请求来了你就有 10 万个线程，**直接 OOM 或被内核拒绝**（每个线程默认 8MB 栈）
3. **detach 后生死不明**——主线程先退出，线程摸到的资源全部悬垂（并发五宗罪第五条）
4. **没有背压（backpressure）**——所有请求并发处理，下游数据库直接被打挂

✅ **正确做法**：固定数量的工人线程 + 任务队列，**线程数受控、复用线程、有天然背压**。

❓ **C 没有 future，"异步返回结果"怎么办？**

C++ 的 `pool.submit([]{ return 42; })` 返回 `std::future<int>`——**C 没有这东西，那就手写一个**。future 的本质剥掉语法糖只有三样：

```text
future = 结果槽（void* result）
       + 就绪标志（bool done）
       + 一对 mutex/cond（"还没好就睡，好了叫你"）
```

**Step 2.2 用 30 行 C 写出它**——写完你就知道 `std::future`、`std::promise` 里面装的是什么了。

❓ **为什么 `pool_destroy` 必须先 shutdown 队列再 join 线程？反过来行不行？**

**绝对不行**！来看反例：

```c
/* ❌ 反例：先 join 再 shutdown */
void pool_destroy_bad(thread_pool_t *p) {
    for (size_t i = 0; i < p->n; i++)
        pthread_join(p->workers[i], NULL);   /* ⚠️ 工人正阻塞在 bq_pop */
    bq_shutdown(&p->q);                       /* 永远跑不到这里 */
}
```

**会发生什么**：工人线程正卡在 `pthread_cond_wait` 上等任务。主线程 `pthread_join` 等工人结束。**双方互等 → 永久死锁**。

✅ **正确顺序**：**先 shutdown 让 bq_pop 返回 false → 工人 break 循环 → join 顺利完成**。

🔑 **教学要点**：**资源释放顺序在并发里和构造顺序一样重要**。C++ 靠"析构函数反序执行"的 RAII 规则自动保证；C 里这条纪律完全靠你自己排。

```c
/* thread_pool.c（v1）*/
#include "thread_pool.h"

#include <stdlib.h>

static void *worker_main(void *arg) {
    thread_pool_t *p = arg;
    for (;;) {
        task_t *t;
        if (!bq_pop(&p->q, (void **)&t)) break;   /* shutdown 且空：下班 */
        t->fn(t->arg);                            /* 执行任务 */
        free(t);
    }
    return NULL;
}

bool pool_init(thread_pool_t *p, size_t n) {
    p->workers = calloc(n, sizeof *p->workers);
    if (!p->workers) return false;
    if (!bq_init(&p->q)) {
        free(p->workers);
        return false;
    }
    p->n = 0;
    for (size_t i = 0; i < n; i++) {
        if (pthread_create(&p->workers[i], NULL, worker_main, p) != 0)
            return p->n > 0;                      /* 教学从简：部分启动也接受 */
        p->n++;
    }
    return true;
}

bool pool_submit_simple(thread_pool_t *p, task_fn fn, void *arg) {
    task_t *t = malloc(sizeof *t);
    if (!t) return false;
    t->fn = fn;
    t->arg = arg;
    if (!bq_push(&p->q, t)) {                     /* 已 shutdown */
        free(t);
        return false;
    }
    return true;
}

void pool_destroy(thread_pool_t *p) {
    bq_shutdown(&p->q);                           /* ⭐ 先停机 */
    for (size_t i = 0; i < p->n; i++)
        pthread_join(p->workers[i], NULL);        /* ⭐ 再 join */
    bq_destroy(&p->q);
    free(p->workers);
    p->workers = NULL;
    p->n = 0;
}
```

### Step 2.2 手写 future 入门

在写正式 submit 前，**先单独把手写 future 练熟**——这是 C 版替代 C++ `packaged_task/future/promise` 三剑客的 30 行核心。

**新建 `src/future.h`**：

```c
/* future.h —— 手写 mini future：C++ std::future 的裸机原理 */
#ifndef FUTURE_H
#define FUTURE_H

#include <pthread.h>
#include <stdbool.h>

typedef struct {
    void          *result;     /* 结果槽 */
    bool           done;       /* 就绪标志 */
    pthread_mutex_t mtx;
    pthread_cond_t  cv;
} future_t;

bool  future_init(future_t *f);
void  future_set(future_t *f, void *result);   /* worker 调用，恰好一次 */
void *future_get(future_t *f);                 /* 调用方阻塞直到 set */
void  future_destroy(future_t *f);

#endif
```

```c
/* future.c */
#include "future.h"

bool future_init(future_t *f) {
    f->result = NULL;
    f->done = false;
    if (pthread_mutex_init(&f->mtx, NULL) != 0) return false;
    if (pthread_cond_init(&f->cv, NULL) != 0) {
        pthread_mutex_destroy(&f->mtx);
        return false;
    }
    return true;
}

void future_set(future_t *f, void *result) {
    pthread_mutex_lock(&f->mtx);
    f->result = result;
    f->done = true;
    pthread_mutex_unlock(&f->mtx);
    pthread_cond_broadcast(&f->cv);     /* 叫醒所有等待者 */
}

void *future_get(future_t *f) {
    pthread_mutex_lock(&f->mtx);
    while (!f->done)                    /* ⭐ while 防虚假唤醒 */
        pthread_cond_wait(&f->cv, &f->mtx);
    void *r = f->result;
    pthread_mutex_unlock(&f->mtx);
    return r;
}

void future_destroy(future_t *f) {
    pthread_mutex_destroy(&f->mtx);
    pthread_cond_destroy(&f->cv);
}
```

📚 **对照 C++ 三剑客**（现在能看穿它们了）：

> - `std::promise<T>` = 本案例 `future_set` 的写入端（promise 持有的共享状态就是这个结构体）
> - `std::future<T>` = 本案例 `future_get` 的读取端
> - `std::packaged_task<F>` = "自动调 fn 并把返回值 future_set 进去"的打包器——**下一步的 thread_pool 就要手工实现这个打包**
>
> **一个结构体 + 一对锁/条件变量，就是 future 的全部**。C++ 没有魔法，只有语法糖。

### Step 2.3 submit 与异步返回

**升级 `thread_pool.h/.c`**（v2：submit + future）：

```c
/* thread_pool.h（v2：submit 带异步结果）*/
typedef struct {
    task_fn    fn;
    void      *arg;
    future_t  *fut;     /* NULL = fire-and-forget（不关心结果）*/
} task_t;

/* 提交任务：
 *   want_result = false → 返回 NULL，submit 即"发射后不管"
 *   want_result = true  → 返回 future*，调用方必须 future_get 后 future_destroy */
future_t *pool_submit(thread_pool_t *p, task_fn fn, void *arg,
                      bool want_result);
```

```c
/* thread_pool.c（v2 新增部分）*/
static void *worker_main(void *arg) {
    thread_pool_t *p = arg;
    for (;;) {
        task_t *t;
        if (!bq_pop(&p->q, (void **)&t)) break;
        void *result = t->fn(t->arg);            /* ⭐ 相当于执行 packaged_task */
        if (t->fut) future_set(t->fut, result);  /* ⭐ 结果自动回填 future */
        free(t);
    }
    return NULL;
}

future_t *pool_submit(thread_pool_t *p, task_fn fn, void *arg,
                      bool want_result) {
    task_t *t = malloc(sizeof *t);
    if (!t) return NULL;
    t->fn = fn;
    t->arg = arg;
    t->fut = NULL;

    if (want_result) {
        t->fut = malloc(sizeof *t->fut);
        if (!t->fut || !future_init(t->fut)) {
            free(t->fut);
            free(t);
            return NULL;
        }
    }
    /* ⭐ 先把 future 准备好，再 push——顺序不能反！
     *    push 后任务可能立刻被工人执行，future 必须已经就位 */
    if (!bq_push(&p->q, t)) {
        if (t->fut) { future_destroy(t->fut); free(t->fut); }
        free(t);
        return NULL;
    }
    return t->fut;
}
```

### Step 3.1 Order 单线程跑通

**新建 `src/order.h`**：

```c
/* order.h（v1：mutex 版）*/
#ifndef ORDER_H
#define ORDER_H

#include <pthread.h>
#include <stdatomic.h>
#include <stdbool.h>
#include <stddef.h>

typedef struct {
    int id;
    int user_id;
    int product_id;
    int quantity;
} order_t;

typedef struct {
    order_t   *orders;
    size_t     len, cap;
    pthread_mutex_t mtx;             /* v1 用普通 mutex */
    atomic_int next_id;              /* ⭐ ID 自增用原子 */
} order_manager_t;

void  om_init(order_manager_t *m);
void  om_destroy(order_manager_t *m);
int   om_add_order(order_manager_t *m, int user_id, int product_id, int qty);
bool  om_find_order(order_manager_t *m, int id, order_t *out);
size_t om_size(order_manager_t *m);

#endif
```

```c
/* order.c（v1）*/
#include "order.h"

#include <stdlib.h>

void om_init(order_manager_t *m) {
    m->orders = NULL;
    m->len = m->cap = 0;
    pthread_mutex_init(&m->mtx, NULL);
    atomic_init(&m->next_id, 1);
}

void om_destroy(order_manager_t *m) {
    free(m->orders);
    pthread_mutex_destroy(&m->mtx);
}

int om_add_order(order_manager_t *m, int user_id, int product_id, int qty) {
    order_t o = {
        .id         = atomic_fetch_add(&m->next_id, 1),   /* ⭐ 原子自增，ID 永不重复 */
        .user_id    = user_id,
        .product_id = product_id,
        .quantity   = qty,
    };

    pthread_mutex_lock(&m->mtx);
    if (m->len == m->cap) {
        size_t nc = m->cap ? m->cap * 2 : 16;
        order_t *no = realloc(m->orders, nc * sizeof *no);
        if (!no) {
            pthread_mutex_unlock(&m->mtx);                /* ⭐ 失败路径也要解锁 */
            return -1;
        }
        m->orders = no;
        m->cap = nc;
    }
    m->orders[m->len++] = o;
    pthread_mutex_unlock(&m->mtx);
    return o.id;
}

bool om_find_order(order_manager_t *m, int id, order_t *out) {
    bool found = false;
    pthread_mutex_lock(&m->mtx);
    for (size_t i = 0; i < m->len; i++) {
        if (m->orders[i].id == id) {
            *out = m->orders[i];                          /* 拷贝出参，锁外使用 */
            found = true;
            break;
        }
    }
    pthread_mutex_unlock(&m->mtx);
    return found;
}

size_t om_size(order_manager_t *m) {
    pthread_mutex_lock(&m->mtx);
    size_t n = m->len;
    pthread_mutex_unlock(&m->mtx);
    return n;
}
```

> 💡 注意两个细节：① `atomic_fetch_add` 在**锁外**执行——ID 生成不依赖订单数组，没必要占着锁自增；② `om_find_order` 把订单**拷贝到出参**再返回——**绝不能返回内部指针**（unlock 后另一线程可能 realloc 把它变成悬垂指针）。

### Step 3.2 mutex 基线压测

**升级测试**，4 个写线程 + 8 个读线程同时跑：

```c
/* test_mgr.c（v2：并发压测）*/
#include <pthread.h>
#include <stdatomic.h>
#include <stdio.h>
#include <time.h>

#include "src/order.h"

#define WRITES    1000       /* 每个写线程下 1000 单 */
#define READS     100000     /* 每个读线程查 10w 次 */
#define W_THREADS 4
#define R_THREADS 8

static order_manager_t mgr;
static atomic_int read_hits = 0;

static double now_ms(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000.0 + ts.tv_nsec / 1e6;
}

static void *writer(void *arg) {
    long w = (long)arg;
    for (int i = 0; i < WRITES; i++)
        om_add_order(&mgr, (int)w, 1, 1);
    return NULL;
}

static void *reader(void *arg) {
    (void)arg;
    order_t o;
    for (int i = 0; i < READS; i++)
        if (om_find_order(&mgr, 1, &o))
            atomic_fetch_add(&read_hits, 1);
    return NULL;
}

int main(void) {
    om_init(&mgr);
    double t0 = now_ms();

    pthread_t ts[W_THREADS + R_THREADS];
    for (long w = 0; w < W_THREADS; w++)
        pthread_create(&ts[w], NULL, writer, (void *)w);
    for (int r = 0; r < R_THREADS; r++)
        pthread_create(&ts[W_THREADS + r], NULL, reader, NULL);
    for (int i = 0; i < W_THREADS + R_THREADS; i++)
        pthread_join(ts[i], NULL);

    double ms = now_ms() - t0;
    printf("orders = %zu (expect=%d)\n", om_size(&mgr), W_THREADS * WRITES);
    printf("read hits = %d / %d\n", atomic_load(&read_hits), R_THREADS * READS);

    om_destroy(&mgr);
    return 0;
}
```

### Step 3.3 rwlock 升级

```c
/* order.c（v2：三处改动）*/
void om_init(order_manager_t *m) {
    m->orders = NULL;
    m->len = m->cap = 0;
    pthread_rwlock_init(&m->rwlock, NULL);
    atomic_init(&m->next_id, 1);
}

int om_add_order(order_manager_t *m, int user_id, int product_id, int qty) {
    order_t o = {
        .id = atomic_fetch_add(&m->next_id, 1),
        .user_id = user_id, .product_id = product_id, .quantity = qty,
    };
    pthread_rwlock_wrlock(&m->rwlock);       /* ⭐ 写：独占锁 */
    /* ...与 v1 相同的扩容 + 追加（unlock 换成 rwlock_unlock）... */
    pthread_rwlock_unlock(&m->rwlock);
    return o.id;
}

bool om_find_order(order_manager_t *m, int id, order_t *out) {
    bool found = false;
    pthread_rwlock_rdlock(&m->rwlock);       /* ⭐ 读：共享锁！*/
    for (size_t i = 0; i < m->len; i++) {
        if (m->orders[i].id == id) { *out = m->orders[i]; found = true; break; }
    }
    pthread_rwlock_unlock(&m->rwlock);
    return found;
}

size_t om_orders_by_user(order_manager_t *m, int user_id,
                         order_t *out, size_t cap) {
    size_t n = 0;
    pthread_rwlock_rdlock(&m->rwlock);       /* 读锁 */
    for (size_t i = 0; i < m->len && n < cap; i++)
        if (m->orders[i].user_id == user_id) out[n++] = m->orders[i];
    pthread_rwlock_unlock(&m->rwlock);
    return n;
}
```

📚 **pthread_rwlock 访问规则**：

> | 当前持有 | 谁能进入 |
> |------|---------|
> | 无锁 | 任何线程 |

### Step 4.2 千线程见超卖

**升级测试**，100 件库存 + 200 个并发线程，每人买 1 件：

```c
/* test_product.c（v2：并发压测）*/

#include <stdatomic.h>
#include <stdio.h>

#include "src/product.h"

#define BUYERS 200

static product_t g_p;
static atomic_int success_count = 0;     /* ⭐ 计数也必须是原子！ */

static void *buyer(void *arg) {
    (void)arg;
    if (product_buy(&g_p, 1))

    for (int i = 0; i < BUYERS; i++)

    int stock = product_get_stock(&g_p);
    printf("成功购买:  %d 件\n", success);
    printf("剩余库存:  %d 件\n", stock);
    printf("原始库存:  100\n");
    printf("一致性:    %s\n",
```

**BUG 解释**，两个线程交错执行：

```text
线程 A 进入 product_buy(p, 1)：
  ① if (p->stock >= 1)        读 stock = 1，通过 ✅
  [此时被 OS 切走]
线程 B 进入 product_buy(p, 1)：
  ① if (p->stock >= 1)        读 stock = 1，也通过 ✅
  ② p->stock -= 1             stock = 0
  返回 true
线程 A 恢复：
  ② p->stock -= 1             stock = -1   💥 超卖！
  返回 true
```

📚 **核心错误**：`if (stock>=n) stock-=n` 这两步操作**不是原子的**——读和写中间被其他线程插入了相同的读和写，条件判断失效。这就是经典的 **check-then-act race**。在 C 标准里这甚至是未定义行为（无同步的多线程读写同一对象）——**它"恰好"跑成超卖是硬件给面子，跑成什么都合法**。

### Step 4.3 atomic CAS 修复

**升级 `product.h/.c`** 为最终版：

```c
/* product.h（v2：C11 atomic CAS 版）*/
#ifndef PRODUCT_H
#define PRODUCT_H

#include <stdatomic.h>
#include <stdbool.h>

typedef struct {
    int         id;
    const char *name;
    double      price;
    atomic_int  stock;         /* ⭐ 改成 C11 原子变量 */
} product_t;

void product_init(product_t *p, int id, const char *name,
                  double price, int stock);
int  product_stock(product_t *p);

/* ⭐⭐⭐ CAS 循环扣库存（防超卖）*/
bool product_try_deduct(product_t *p, int n);
void product_restock(product_t *p, int n);

#endif
```

```c
/* product.c（v2）*/
#include "product.h"

void product_init(product_t *p, int id, const char *name,
                  double price, int stock) {
    p->id = id;
    p->name = name;
    p->price = price;
    atomic_init(&p->stock, stock);
}

int product_stock(product_t *p) {
    return atomic_load(&p->stock);       /* 原子读 */
}

bool product_try_deduct(product_t *p, int n) {
    int cur = atomic_load(&p->stock);
    while (cur >= n) {
        /* CAS：如果 stock 仍然是 cur，则把它改成 cur - n
         * 失败时 cur 会被自动更新为最新值，进入下一轮 */
        if (atomic_compare_exchange_weak(&p->stock, &cur, cur - n))
            return true;                 /* 成功扣减 */
    }
    return false;                        /* 库存不够（cur < n）*/
}

void product_restock(product_t *p, int n) {
    atomic_fetch_add(&p->stock, n);
}
```

✅ **零超卖、零漏单**，这就是 atomic CAS 的力量。

**CAS（Compare-And-Swap）执行轨迹**：

> ```text
> 初始 stock = 1
> 线程 A 进入 product_try_deduct(p, 1)：cur = 1，尝试 CAS(1 → 0)
> 线程 B 进入 product_try_deduct(p, 1)：cur = 1，尝试 CAS(1 → 0)
>
> → A 先执行 CAS 成功：stock = 0，返回 true
> → B 的 CAS 失败：cur 自动被更新为 0
> → B 检查 cur >= 1 失败，跳出 while，返回 false
> ```

**整个"判断+扣减"是一个不可分割的硬件指令**，OS 切线程也插不进缝。

💼 **weak vs strong**：`atomic_compare_exchange_weak` 在某些 CPU（如 ARM）会"伪失败"（即使值相等也偶尔返回 false），但循环里会立即重试，**性能比 strong 好**。一次性判断必须用 strong。**CAS 循环里永远首选 weak**——与 C++ `compare_exchange_weak` 完全同名同义。

### 加餐 · 死锁现场实录

⚠️ **强烈建议跑一遍**（并发四大金刚之二）——race condition 你刚见过了，**死锁是另一种灾难**：程序不崩、不报错，只是**永远卡死**。你今天踩过这个坑，将来上线代码就不会重蹈覆辙。

**场景**：用户想把账户 A 的钱**转账**到账户 B。每个账户有自己的锁。

```c
/* deadlock_demo.c（v1：经典交叉申请，必死锁）*/
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

typedef struct {
    int balance;
    pthread_mutex_t mtx;
} account_t;

void account_init(account_t *a, int b) {
    a->balance = b;
    pthread_mutex_init(&a->mtx, NULL);
}

/* ⚠️ 错误的转账实现：先锁 from 再锁 to */
void transfer_bad(account_t *from, account_t *to, int amount) {
    pthread_mutex_lock(&from->mtx);
    usleep(10000);                        /* ⭐ 放大死锁概率 */
    pthread_mutex_lock(&to->mtx);         /* 对方可能已持有 → 永久等待 */
    from->balance -= amount;
    to->balance   += amount;
    pthread_mutex_unlock(&to->mtx);
    pthread_mutex_unlock(&from->mtx);
}

static account_t g_a, g_b;

static void *t1_main(void *arg) {
    (void)arg;
    transfer_bad(&g_a, &g_b, 100);        /* 先锁 a 再锁 b */
    return NULL;
}
static void *t2_main(void *arg) {
    (void)arg;
    transfer_bad(&g_b, &g_a, 200);        /* 先锁 b 再锁 a ⚠️ */
    return NULL;
}

int main(void) {
    account_init(&g_a, 1000);
    account_init(&g_b, 1000);

    pthread_t t1, t2;
    pthread_create(&t1, NULL, t1_main, NULL);
    pthread_create(&t2, NULL, t2_main, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("done a=%d b=%d\n", g_a.balance, g_b.balance);
    return 0;
}
```

🧪 编译运行：

```text
$ gcc -std=c11 -pthread deadlock_demo.c -o dd && ./dd
（程序卡死，永远不输出 done）

# 用 Ctrl+C 强行结束，或用另一个终端看线程栈：
$ gdb -p $(pidof dd) -ex "thread apply all bt"   # Linux
# t1 持有 a.mtx，等 b.mtx
# t2 持有 b.mtx，等 a.mtx
# 互相等对方释放 → 永久死锁
```

⚠️ **死锁四要素全部满足**（操作系统课的"必考"）：

1. **互斥** —— mutex 同一时间只能被一个线程持有 ✅
2. **持有并等待** —— t1 持有 a.mtx 还想要 b.mtx ✅
3. **不可剥夺** —— 持有的锁 OS 不会强制收回 ✅
4. **循环等待** —— t1 等 t2，t2 等 t1，形成环 ✅

> 📚 **为什么死锁比 race condition 更可怕？**
> - **race** 的崩溃**有报错**（segfault / 数据错乱），容易发现
> - **deadlock** **没报错**，程序就在那里"安静地"卡死，监控指标全绿，QPS = 0，运维以为机器卡了重启就行，**重启完还会再死**

#### 修复方案 A：手写 trylock 回退（std::lock 思想的裸机版）

C++ 有 `std::lock(m1, m2)` 一次锁全部；**C 没有——那就手写它**：拿第二把锁失败就**放弃第一把重来**，打破"持有并等待"：

```c
/* 修复版 1：trylock + 回退 */
void transfer_trylock(account_t *from, account_t *to, int amount) {
    for (;;) {
        pthread_mutex_lock(&from->mtx);
        if (pthread_mutex_trylock(&to->mtx) == 0) {
            /* ⭐ 两把都拿到了：要么全拿，要么全放 */
            from->balance -= amount;
            to->balance   += amount;
            pthread_mutex_unlock(&to->mtx);
            pthread_mutex_unlock(&from->mtx);
            return;
        }
        pthread_mutex_unlock(&from->mtx);  /* ⭐ 拿不到就全放掉 */
        usleep(rand() % 2000);             /* 随机退避：防两个线程同步空转（活锁）*/
    }
}
```

> 📚 **这就是 `std::lock` 的内部原理**：反复 trylock，失败就把已拿到的全部释放重来——**要么全拿到，要么一个都不拿**，死锁条件被打破。注意 `usleep(rand()%2000)` 的**随机退避**：如果两个线程永远同步地"拿-放-拿-放"，会陷入**活锁**（Livelock）——没死锁但谁也前进不了。随机化让它们错开节奏。

#### 修复方案 B：锁顺序约定（更通用）

trylock 回退只能解决**这一对锁**。如果系统里有 1000 个 Account，锁的对象**事先不知道**，怎么办？

✅ **业界标准做法**：**全局规定一个"锁顺序"**，比如按地址排序：

```c
/* 修复版 2：锁顺序约定（按地址排序）*/
void transfer_ordered(account_t *from, account_t *to, int amount) {
    /* ⭐ 全局约定：永远先锁地址小的一把 */
    account_t *first  = (from < to) ? from : to;
    account_t *second = (from < to) ? to   : from;

    pthread_mutex_lock(&first->mtx);
    pthread_mutex_lock(&second->mtx);
    from->balance -= amount;
    to->balance   += amount;
    pthread_mutex_unlock(&second->mtx);
    pthread_mutex_unlock(&first->mtx);
}
```

**这样不管 t1 是 transfer(a,b) 还是 t2 是 transfer(b,a)，两个线程都会按"小地址先锁"的顺序申请，循环等待就被打破了**。

> 💼 **真实工程经验**：**MySQL InnoDB、PostgreSQL 的行锁、Linux 内核的 spinlock** 都用"锁顺序"避免死锁。**给每个锁分配一个全局唯一的 rank（等级），只能从小 rank 申请到大 rank**，这是"锁层次"（lock hierarchy）的最严格形式，违反层次会直接 panic。

✅ **死锁治好了**。**这一节学到的不仅是两个函数**，更是**面对并发资源依赖图的两种通用思想**：

1. **原子获取所有依赖**（trylock 回退思想 = C++ std::lock）
2. **强制全局顺序**（锁层次思想）

> 🔑 **教学要点**：本案例 §02-§07 的真实代码里**没有"两把 mutex 交叉申请"的场景**，所以这是加餐演示。但**生产环境一旦你有"操作多个对象"的业务**（订单转账、库存调拨、消息群发），死锁就会找上门。**今天先在这里扎扎实实见过它一次**。

## 06.策略模式下单

```
┌─ 🎯 阶段 ⑤ 目标 ────────────────────────────────────────┐
│ 完成什么：用策略模式串起 ThreadPool + Product + OrderManager │
│           三种下单方式：normal / flash / batch              │
│ 不做什么：暂不做 CLI，先用 main 直接调对比效果               │
│ 验收标准：同样下 1000 单，flash 比 normal 明显加速           │
│ 预计耗时：60 min · 3 Step                                  │
└──────────────────────────────────────────────────────────┘
```

💡 **策略模式（Strategy Pattern）**：把"做某事的多种方式"抽成接口，调用方传哪个就用哪个。C 没有 virtual 和 class，但有**函数指针结构体**——03 案例手动 vtable 的直接复用。同样是下单，单线程顺序 vs 线程池并发 vs 分批，**调用代码完全不变，只换策略结构体里的函数指针**。

---

### 灵魂三问：为什么不用 if-else？

**三种下单方式直接写 `if (mode == FLASH) { ... } else if (mode == BATCH) { ... }` 不就完了？**

来看反例：

```c
/* ❌ 反例：if-else 巨型函数 */
int *place_orders(int mode, product_t *p, order_manager_t *mgr,
                  int user_id, const int *qtys, size_t n, size_t *out_n) {
    if (mode == NORMAL) {
        /* 50 行普通下单代码 */
    } else if (mode == FLASH) {
        /* 80 行秒杀代码（涉及线程池 + future）*/
    } else if (mode == BATCH) {
        /* 60 行分批代码（涉及批处理）*/
    }
    /* 想加个分布式策略？再 else if？*/
}
```

**问题**：

1. **违反开闭原则**——加新策略要改这个巨型函数
2. **依赖发散**——这一个函数同时依赖 thread_pool / future / 分批逻辑，**没法单独测试 normal 路径**
3. **switch case 永远在迭代**——业务越发展越乱

✅ **正确做法**：抽"函数指针接口" + 三个独立实现，**加新策略只需新增一个函数 + 一个 init，不动旧代码**。这就是策略模式的"开"（对扩展开放）"闭"（对修改关闭）。

❓ **为什么 flash/batch 策略接 `thread_pool_t *` 指针而不是自己建一个？**

来看反例：

```c
/* ❌ 反例：策略内部自己建线程池 */
typedef struct {
    thread_pool_t pool;      /* 每个策略对象 8 个工人 */
} flash_selfish_t;
```

**问题**：

1. **资源浪费**——程序里如果同时有 normal + flash + batch 实例，会有 3 个线程池 = 24 个线程
2. **生命周期失控**——策略销毁时线程池跟着销毁，**正在跑的任务被强制中断**
3. **测试困难**——单测 flash 必须真启 8 个线程，跑不快

✅ **正确做法**：**依赖注入**——线程池由调用方创建并传入，策略对象只是"用户"。

❓ **C 的函数指针策略和 C++ 虚函数有什么差别？**

> - C++ 虚函数：**编译器自动生成 vtable**，`s->placeOrders(...)` 自动查表分发
> - C 函数指针：**vtable 你自己写**（结构体里放函数指针），调用 `s->place_orders(s, ...)` 手动传 self
> - 差别本质：**C++ 把"第一个参数 self"和"查表"藏进了语法；C 让你看到虚函数调用的全部真相**——03 案例讲手动 vtable 时埋的这颗种子，本章开花

🔑 **教学要点**：策略模式的精髓不是"避免 if-else"，而是**让"算法族"成为一等公民**——它们可以被传递、组合、替换、单独测试。

`src/strategy.c`（第一部分：共用任务 + normal 策略）：

```c
/* strategy.c（part 1）*/
#include "strategy.h"

#include <inttypes.h>
#include <stdlib.h>

/* ===== 共用的单笔下单逻辑 =====
 * 返回订单号或 -1，用 intptr_t 装箱进 void* 回传（§Step 2.3 同款技巧）*/
typedef struct {
    product_t       *p;
    order_manager_t *m;
    int              user_id;
    int              qty;
} order_arg_t;

static void *place_one(void *arg) {
    order_arg_t *a = arg;
    if (product_try_deduct(a->p, a->qty))
        return (void *)(intptr_t)om_add_order(a->m, a->user_id,
                                              a->p->id, a->qty);
    return (void *)(intptr_t)-1;
}

/* ---------- normal：单线程顺序 ---------- */
static int *normal_place(order_strategy_t *s, product_t *p,
                         order_manager_t *m, int user_id,
                         const int *qtys, size_t n, size_t *out_n) {
    (void)s;
    int *ids = malloc(n * sizeof *ids);
    if (!ids) { *out_n = 0; return NULL; }
    for (size_t i = 0; i < n; i++) {
        order_arg_t a = { p, m, user_id, qtys[i] };
        ids[i] = (int)(intptr_t)place_one(&a);      /* 直接调用，不开线程 */
    }
    *out_n = n;
    return ids;
}

void strategy_normal_init(order_strategy_t *s) {
    s->place_orders = normal_place;
    s->pool = NULL;
    s->batch_size = 0;
}
```

### Step 5.2 FlashStrategy 并发

`src/strategy.c`（第二部分）：

```c
/* strategy.c（part 2：flash 策略）*/
static int *flash_place(order_strategy_t *s, product_t *p,
                        order_manager_t *m, int user_id,
                        const int *qtys, size_t n, size_t *out_n) {
    int *ids = malloc(n * sizeof *ids);
    order_arg_t *args = malloc(n * sizeof *args);
    future_t **futs = malloc(n * sizeof *futs);
    if (!ids || !args || !futs) {
        free(ids); free(args); free(futs);
        *out_n = 0;
        return NULL;
    }

    /* ⭐ 每笔下单作为一个 task 提交，工人并发抢库存 */
    for (size_t i = 0; i < n; i++) {
        args[i] = (order_arg_t){ p, m, user_id, qtys[i] };
        futs[i] = pool_submit(s->pool, place_one, &args[i], true);
    }
    /* 收集所有结果（按提交顺序）——args 在全部 get 前必须存活！*/
    for (size_t i = 0; i < n; i++)
        ids[i] = futs[i] ? (int)(intptr_t)future_get(futs[i]) : -1;
    for (size_t i = 0; i < n; i++) {
        if (futs[i]) { future_destroy(futs[i]); free(futs[i]); }
    }
    free(args);
    free(futs);
    *out_n = n;
    return ids;
}

void strategy_flash_init(order_strategy_t *s, thread_pool_t *pool) {
    s->place_orders = flash_place;
    s->pool = pool;
    s->batch_size = 0;
}
```

### Step 5.3 BatchStrategy 分批

`src/strategy.c`（第三部分）：

```c
/* strategy.c（part 3：batch 策略）*/
static int *batch_place(order_strategy_t *s, product_t *p,
                        order_manager_t *m, int user_id,
                        const int *qtys, size_t n, size_t *out_n) {
    int *ids = malloc(n * sizeof *ids);
    if (!ids) { *out_n = 0; return NULL; }
    size_t bs = s->batch_size ? s->batch_size : 10;

    /* ⭐ 每 bs 个为一组：组内并发，组间串行 */
    for (size_t i = 0; i < n; i += bs) {
        size_t end = (i + bs < n) ? i + bs : n;

        order_arg_t *args = malloc((end - i) * sizeof *args);
        future_t **futs = malloc((end - i) * sizeof *futs);
        if (!args || !futs) { free(args); free(futs); continue; }

        for (size_t j = i; j < end; j++) {
            args[j - i] = (order_arg_t){ p, m, user_id, qtys[j] };
            futs[j - i] = pool_submit(s->pool, place_one,
                                      &args[j - i], true);
        }
        /* 等本批全部完成，再开下一批 */
        for (size_t j = i; j < end; j++)
            ids[j] = futs[j - i] ? (int)(intptr_t)future_get(futs[j - i]) : -1;
        for (size_t j = i; j < end; j++) {
            if (futs[j - i]) { future_destroy(futs[j - i]); free(futs[j - i]); }
        }
        free(args);
        free(futs);
    }
    *out_n = n;
    return ids;
}

void strategy_batch_init(order_strategy_t *s, thread_pool_t *pool,
                         size_t batch_size) {
    s->place_orders = batch_place;
    s->pool = pool;
    s->batch_size = batch_size;
}
```

## 07.线程安全 Logger

```
┌─ 🎯 阶段 ⑥ 目标 ────────────────────────────────────────┐
│ 完成什么：Logger —— 线程安全的格式化日志                   │
│ 不做什么：不做日志分级（DEBUG/INFO/ERROR）、不写文件        │
│ 验收标准：先写裸 printf 看日志撕成乱码 → 加锁后行行清晰      │
│ 预计耗时：30 min · 2 Step（造 BUG → 修 BUG）              │
└──────────────────────────────────────────────────────────┘
```

💡 **printf 本身不保证"整行原子"** —— 多线程各自多次 printf，输出会**字符级**交错。比如线程 A 输出 "Hello\n"、线程 B 输出 "World\n"，可能变成 "HelWloolrd\n\n"。**这一阶段我们让你看到这种乱码，再用"锁外格式化 + 锁内一次输出"修好它**。

---

### Step 6.1 裸 printf 见撕裂

**不写 Logger，直接用 printf 起步**：

```c
/* test_log.c（v1：裸 printf，会撕裂）*/
#include <pthread.h>
#include <stdio.h>

static void *worker(void *arg) {
    long t = (long)arg;
    for (int i = 0; i < 5; i++) {
        /* 故意分多次 printf 输出，放大撕裂效应 */
        printf("[Thread %ld] ", t);
        printf("iter ");
        printf("%d", i);
        printf("\n");
    }
    return NULL;
}

int main(void) {
    pthread_t ts[4];
    for (long t = 0; t < 4; t++)
        pthread_create(&ts[t], NULL, worker, (void *)t);
    for (int t = 0; t < 4; t++)
        pthread_join(ts[t], NULL);
    return 0;
}
```

⚠️ **看见了吗——"[Thread 0] iter 0" 和 "[Thread 1] iter 0" 完全交错在一起，根本读不懂哪条来自哪个线程**。

📚 **为什么 printf 不安全？** —— 每条 `printf` 是一次独立调用，C 标准只保证**单次调用的输出不交叉**（glibc 对 stdio 流有内部锁）；但你**分 4 次拼一行**，4 次调用之间随时可能被切走。想整行原子，必须**一次调用输出整行**。

### Step 6.2 vsnprintf 行原子 Logger

**新建 `src/logger.h` / `logger.c`**：

```c
/* logger.h */
#ifndef LOGGER_H
#define LOGGER_H

void logger_info(const char *fmt, ...)
        __attribute__((format(printf, 1, 2)));

#endif
```

```c
/* logger.c —— 线程安全 + 时间戳 + 行原子 */
#include "logger.h"

#include <pthread.h>
#include <stdarg.h>
#include <stdio.h>
#include <sys/time.h>
#include <time.h>

static pthread_mutex_t g_log_mtx = PTHREAD_MUTEX_INITIALIZER;

/* 生成 "HH:MM:SS.mmm" 时间戳 */
static void timestamp(char buf[16]) {
    struct timeval tv;
    gettimeofday(&tv, NULL);
    struct tm tmv;
    localtime_r(&tv.tv_sec, &tmv);            /* ⭐ _r 后缀：线程安全版 */
    snprintf(buf, 16, "%02d:%02d:%02d.%03d",
             tmv.tm_hour, tmv.tm_min, tmv.tm_sec,
             (int)(tv.tv_usec / 1000));
}

void logger_info(const char *fmt, ...) {
    char line[256];
    char ts[16];

    /* ⭐ ① 锁外：先把整行格式化到栈缓冲 */
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(line, sizeof line, fmt, ap);
    va_end(ap);
    timestamp(ts);

    /* ⭐ ② 锁内：只做一次输出——行原子 */
    pthread_mutex_lock(&g_log_mtx);
    fprintf(stdout, "[%s][T%lu] %s\n",
            ts, (unsigned long)pthread_self() % 100000, line);
    fflush(stdout);
    pthread_mutex_unlock(&g_log_mtx);
}
```

### Step 7.2 benchmark 万级并发

**新建 `benchmark.c`**，这是最终验收：

```c
/* benchmark.c —— 万级并发压测 + 一致性校验 */
#include <pthread.h>
#include <stdatomic.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>

#include "src/order.h"
#include "src/product.h"
#include "src/strategy.h"
#include "src/thread_pool.h"

#define TOTAL_USERS     1000
#define ORDERS_PER_USER 10
#define INITIAL_STOCK   5000        /* ⭐ 故意 < 总请求 10000 */

static product_t       g_product;
static order_manager_t g_mgr;
static order_strategy_t g_flash;
static atomic_int g_total_success = 0;

static double now_ms(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000.0 + ts.tv_nsec / 1e6;
}

/* 每个用户一个线程：调用 flash 策略（内部 submit 到线程池）*/
static void *user_thread(void *arg) {
    (void)arg;
    int qtys[ORDERS_PER_USER];
    for (int i = 0; i < ORDERS_PER_USER; i++) qtys[i] = 1;

    size_t n = 0;
    int *ids = g_flash.place_orders(&g_flash, &g_product, &g_mgr,
                                    0, qtys, ORDERS_PER_USER, &n);
    int ok = 0;
    for (size_t i = 0; i < n; i++) if (ids[i] > 0) ok++;
    atomic_fetch_add(&g_total_success, ok);
    free(ids);
    return NULL;
}

int main(void) {
    long nt = sysconf(_SC_NPROCESSORS_ONLN);

    thread_pool_t pool;
    pool_init(&pool, (size_t)(nt > 0 ? nt : 4));

    om_init(&g_mgr);
    product_init(&g_product, 1, "iPhone 15", 7999.0, INITIAL_STOCK);
    strategy_flash_init(&g_flash, &pool);

    double t0 = now_ms();

    /* 启动 1000 个用户线程，每人下 10 单 */
    pthread_t users[TOTAL_USERS];
    for (int u = 0; u < TOTAL_USERS; u++)
        pthread_create(&users[u], NULL, user_thread, NULL);
    for (int u = 0; u < TOTAL_USERS; u++)
        pthread_join(users[u], NULL);

    double ms = now_ms() - t0;

    int total    = TOTAL_USERS * ORDERS_PER_USER;
    int success  = atomic_load(&g_total_success);
    int leftover = product_stock(&g_product);

    printf("========================================\n");
    printf("总请求数:    %d\n", total);
    printf("成功订单:    %d\n", success);
    printf("剩余库存:    %d\n", leftover);
    printf("总耗时:     %.0f ms\n", ms);
    printf("QPS:        %.0f\n", total * 1000.0 / ms);

    /* ⭐⭐⭐ 关键一致性验证 */
    bool consistent = (success + leftover == INITIAL_STOCK);
    printf("一致性校验: 成功(%d) + 剩余(%d) == 初始(%d) ? %s\n",
           success, leftover, INITIAL_STOCK,
           consistent ? "✅ PASS" : "❌ FAIL：超卖或漏单！");
    printf("========================================\n");

    pool_destroy(&pool);
    om_destroy(&g_mgr);
    return consistent ? 0 : 1;      /* 一致则退出码 0 */
}
```

## 10.项目技术思考

### 10.1 三种同步的对比

```c
/* 三种实现"线程安全计数器"的方法 */
/* ① mutex 版：约 25 ns/次 */
static pthread_mutex_t m1 = PTHREAD_MUTEX_INITIALIZER;
static int v1;
void c1_inc(void) { pthread_mutex_lock(&m1); v1++;
                    pthread_mutex_unlock(&m1); }

/* ② rwlock 版：读约 30ns（可并发），写约 35ns */
static pthread_rwlock_t rw = PTHREAD_RWLOCK_INITIALIZER;
static int v2;
void c2_inc(void) { pthread_rwlock_wrlock(&rw); v2++;
                    pthread_rwlock_unlock(&rw); }
int  c2_get(void) { pthread_rwlock_rdlock(&rw); int r = v2;
                    pthread_rwlock_unlock(&rw); return r; }

/* ③ C11 atomic 版：约 5 ns/次 */
static atomic_int v3;
void c3_inc(void) { atomic_fetch_add(&v3, 1); }
int  c3_get(void) { return atomic_load(&v3); }
```

**结论**：单变量场景永远首选 atomic；**多变量需要"事务一致性"**（比如"扣库存 + 记订单"必须同时成对发生）才用 mutex/rwlock。

### 10.2 cond_wait 为什么必须套 while

`pthread_cond_wait(&cv, &mtx)` 的内部行为（伪码）：

```c
int pthread_cond_wait(pthread_cond_t *cv, pthread_mutex_t *mtx) {
    pthread_mutex_unlock(mtx);        /* 1. 释放锁（否则别人改不了条件）*/
    futex_wait(cv);                   /* 2. 挂起，等 signal/broadcast */
    pthread_mutex_lock(mtx);          /* 3. 醒来后重新拿锁 */
    return 0;
}
```

**必须套 while 的两个理由**：

1. **虚假唤醒（spurious wakeup）**：OS 允许在没有 signal 的情况下唤醒线程（futex 机制的实现细节）——醒来时条件**未必成立**
2. **多消费者竞争**：signal 唤醒 A、B 两个线程，A 先拿到锁消费了数据，B 拿到锁时队列**又空了**

```c
/* ❌ if 版：虚假唤醒直接穿透 */
if (q->len == 0)
    pthread_cond_wait(&q->not_empty, &q->mtx);   /* 醒来时队列可能还是空 */
/* → 对空队列 pop → 崩 */

/* ✅ while 版：醒来重查条件，不成立继续睡 */
while (q->len == 0 && !q->stopped)
    pthread_cond_wait(&q->not_empty, &q->mtx);   /* 条件不满足就再睡 */
```

> 📚 **对比 C++**：`cv.wait(lock, 谓词)` 的带谓词版本**就是编译器帮你把 while 循环套上了**。C 版必须自己写——现在你知道那个语法糖在帮你挡什么了。

### 10.3 C 没有 RAII：锁的生命周期

C++ 的 `lock_guard` 靠析构函数保证**任何路径都解锁**；C 只有三条路可走：

**① goto unlock（本章主用）**——所有出口共用一个解锁点：

```c
bool op(queue_t *q) {
    bool ok = false;
    pthread_mutex_lock(&q->mtx);
    if (err1) goto out;
    if (err2) goto out;
    ok = do_work(q);
out:
    pthread_mutex_unlock(&q->mtx);
    return ok;
}
```

**② 守卫宏（模拟 lock_guard）**——利用 `for` 循环 + 清理属性：

```c
#define LOCK_GUARD(m) \
    for (bool _once = (pthread_mutex_lock(m), true); _once; \
         _once = false, pthread_mutex_unlock(m))
```

GCC/Clang 有 `__attribute__((cleanup))` 能做到更地道的 RAII，但那是编译器扩展。**守卫宏的问题**：`break` 会提前跳出循环导致不解锁——**不如 goto 直白可靠**，生产 C 代码里 goto 仍是主流。

**③ `pthread_cleanup_push/pop`**——pthread 自带的"取消清理栈"，配合 `pthread_cancel` 使用，平时罕见。

> 💼 **顺带一句 detach**：`pthread_detach` 让线程"自生自灭"，但主线程退出时 detach 的线程**连同进程一起被杀**——它若还摸着你的栈变量/全局锁，就是悬垂访问。**本案例全程 join，纪律就是安全**。
>
> 🔑 **这就是 C++ RAII 存在的意义**：把"忘记 unlock"从"人为纪律"变成"语言保证"。写完本章 C 版，你就能体会 `lock_guard` 三个字值多少钱。

**挑战 B（进阶）· 实现"写者优先"的 rwlock**

当前 `pthread_rwlock` 在大量读时，写线程会"饿死"（永远拿不到锁）。请用 mutex + 2 个 cond + 计数器实现"写优先"：有写请求排队时，阻止新读者进入。这正是 §04 rwlock"不是银弹"警告的根治方案。

**挑战 C（现代化）· SPSC 无锁环形队列**

用 `atomic_int` 的 acquire/release 语义实现**单生产者单消费者**无锁环形队列（`_Atomic size_t head, tail` + 环形数组），让生产者-消费者彻底绕开 mutex。这是 Linux 内核 `kfifo`、DPDK 全部性能的秘密——也是"内存序（memory_order）"最好的入门实验场。
