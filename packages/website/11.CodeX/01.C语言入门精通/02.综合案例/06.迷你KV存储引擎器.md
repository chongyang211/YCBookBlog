## 01.需求说明

### 1.1 为什么做 KV 存储

KV（Key-Value）存储是后端世界最常见的数据结构，Redis、Memcached、etcd、RocksDB 本质上都是 KV。它的接口极简（GET/SET/DEL），但要做"对"，需要解决一连串工程问题：

| 工程问题 | 在本案例中的体现 | 用到的知识点 |
|---------|----------------|--------------|
| 一个 key 能存多种类型的值 | `mkv_value_t` 用 tagged union 表达 | 结构体/联合体（04 案例同款）|
| C 没有现成哈希表容器 | **手写 FNV-1a + 链地址法哈希表** | 数组 + 链表 + 指针 |
| 命令越加越多怎么办 | 命令模式：每加一个命令只新增一个结构体 + 函数 | 函数指针（03/05 案例同款）|
| 进程一关数据就没了 | AOF 追加日志 + 启动重放 | 文件 IO |
| 多客户端同时读写崩了 | `pthread_rwlock` + 手动加解锁 | 线程和锁（05 案例同款）|
| key 设了 TTL 谁来删 | 后台 pthread + 惰性删除 | 线程 + `atomic_bool` |
| 写错命令程序就崩 | 错误码 + 出参上下文体系 | 错误处理（04 案例同款）|
| 调试时想看哪行打的日志 | `KV_LOG` 宏 + `__FILE__/__LINE__` | 预处理器 |

**这恰好就是全书的 14 章。** 我们不是为了"凑覆盖"才做 KV，而是 KV 这个题目天然需要这些技术，做一遍刚好把它们用对位置。

**Makefile（最终版，一次性给出）**：

```makefile
CC      := gcc
CFLAGS  := -std=c11 -Wall -Wextra -O2 -pthread
INC     := -Iinclude
SRC     := $(wildcard src/*.c)
SRC_NOMAIN := $(filter-out src/main.c,$(SRC))
OBJ     := $(SRC_NOMAIN:.c=.o)

mini_kv: $(OBJ) src/main.o
	$(CC) $(CFLAGS) $(INC) -o $@ $^

TESTS := test_value test_store test_aof test_race stress
$(TESTS): %: tests/%.c $(OBJ)
	$(CC) $(CFLAGS) $(INC) -o $@ tests/$*.c $(OBJ)

%.o: %.c $(wildcard include/mkv/*.h)
	$(CC) $(CFLAGS) $(INC) -c $< -o $@

all: mini_kv $(TESTS)
clean:
	rm -f $(OBJ) src/main.o mini_kv $(TESTS)
.PHONY: all clean
```

## 02.MVP 骨架启动

🎯 **阶段① · MVP 骨架（约 1 小时）**：Step 1.1 最小 REPL → Step 1.2 enum 命令 → Step 1.3 零拷贝切词。验收：`SET k 1` 见 `[TODO] SET`、`WRONG` 见 `(error) unknown command`、`EXIT` 干净退出。

### 灵魂三问：动手前先想清楚

❓ **为什么第一步是 REPL 不是哈希表？**

```c
/* ❌ 反例：上来就写"看起来很核心"的存储 */
int main(void) {
    char *kv_name = "zhangsan";   /* 一个变量演示，敲不进新命令、没有解析、无法扩展 */
}
```

✅ **先做 REPL 壳子**——它确立"server 进程持续运行 + 反复处理命令"的架构。**容器反而最容易补，第三阶段才出现**。骨架（控制流）比器官（容器）优先。

❓ **C 的 enum 是弱类型，怎么当"强类型"用？**

C++ 有 `enum class` 挡隐式转换；C 没有，用**三件纪律逼近**：① 枚举值统一前缀 `MKV_CMD_`（手动模拟命名空间隔离）；② 打印/序列化只走配套的转换函数；③ `switch` 分发不写 default，让 `-Wswitch` 漏 case 时报警告。反例：`strcmp(tokens[0], "SET")` 散落各处——一处大小写不一致就出 bug，且 `"SEt"` 拼错编译器不吭声。✅ **输入边界一次性 parse 成枚举**，脏字符串只能存活在 1 行代码里。

❓ **string_view 的 C 版长什么样？**

C++ 的 `std::string_view` 剥掉语法糖就是**指针 + 长度**二元组：

```c
typedef struct { const char *p; size_t len; } mkv_tok_t;
```

危险点一模一样：**切片不延长源生命周期**——返回值仅在当前命令处理周期内使用，源 `line` 还活着，安全。

🔑 **MVP 的意义不是"代码少"，而是"最薄一层端到端跑通，再分层加肉"**。

### Step 1.1 最小 REPL 循环

> 📁 **归属文件**：`src/main.c`（阶段①临时版，后续多轮重写）

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char line[1024];
    printf("MiniKV v0.1 - type EXIT to quit.\n");
    for (;;) {
        printf("> ");
        if (!fgets(line, sizeof line, stdin)) break;   /* Ctrl-D 退出 */
        line[strcspn(line, "\r\n")] = '\0';             /* 掐换行 */
        if (line[0] == '\0') continue;
        printf("(unknown) you said: %s\n", line);
    }
    return 0;
}
```

**✅ 验证**：`make mini_kv && ./mini_kv`，敲一行回显一行、Ctrl-D 干净退出。

💡 `fgets` 读 EOF 返回 NULL、读空行返回非 NULL——`if (!fgets(...)) break` 的语义是"EOF 才退"。**永远不要用 `gets`（已删除）和 `scanf("%s")`（不查边界）**。

### Step 1.2 enum 命令

> 📁 **修改文件**：`include/mkv/command.h` + `src/command.c`（**新建**）

```c
/* include/mkv/command.h */
#ifndef MKV_COMMAND_H
#define MKV_COMMAND_H
#include <stddef.h>

enum mkv_cmd_type {
    MKV_CMD_SET, MKV_CMD_GET, MKV_CMD_DEL, MKV_CMD_EXPIRE,
    MKV_CMD_TTL, MKV_CMD_KEYS, MKV_CMD_SAVE, MKV_CMD_EXIT,
    MKV_CMD_UNKNOWN
};

enum mkv_cmd_type mkv_parse_cmd_type(const char *s, size_t len);
#endif
```

```c
/* src/command.c */
#include "mkv/command.h"
#include <ctype.h>
#include <string.h>

/* 大小写不敏感比较定长切片 */
static int eq_ignore_case(const char *s, size_t len, const char *upper) {
    if (strlen(upper) != len) return 0;
    for (size_t i = 0; i < len; i++)
        if (toupper((unsigned char)s[i]) != (unsigned char)upper[i]) return 0;
    return 1;
}

enum mkv_cmd_type mkv_parse_cmd_type(const char *s, size_t len) {
    if (eq_ignore_case(s, len, "SET"))    return MKV_CMD_SET;
    if (eq_ignore_case(s, len, "GET"))    return MKV_CMD_GET;
    if (eq_ignore_case(s, len, "DEL"))    return MKV_CMD_DEL;
    if (eq_ignore_case(s, len, "EXPIRE")) return MKV_CMD_EXPIRE;
    if (eq_ignore_case(s, len, "TTL"))    return MKV_CMD_TTL;
    if (eq_ignore_case(s, len, "KEYS"))   return MKV_CMD_KEYS;
    if (eq_ignore_case(s, len, "SAVE"))   return MKV_CMD_SAVE;
    if (eq_ignore_case(s, len, "EXIT"))   return MKV_CMD_EXIT;
    return MKV_CMD_UNKNOWN;
}
```

main 里改 `switch (mkv_parse_cmd_type(...))` 分发 9 个 case（8 命令 + UNKNOWN）。

**✅ 验证**：`SET / get / wrong` 分别得到 `[TODO] SET` / `[TODO] GET`（大小写不敏感）/ `(error) unknown command`。**从此 main 里再无字符串比较命令名**。

⚠️ **ctype 铁律**（最后一次强调）：`toupper/isdigit` 入参必须先转 `(unsigned char)`，汉字字节（负值 char）直接传是 **UB**。

### Step 1.3 零拷贝切词

> 📁 **修改文件**：`command.h` + `command.c`（追加）

```c
/* include/mkv/command.h（追加）*/
typedef struct {
    const char *p;      /* 指向源字符串内部，零拷贝 */
    size_t      len;
} mkv_tok_t;

size_t mkv_tokenize(const char *line, mkv_tok_t *out, size_t cap);
```

```c
/* src/command.c（追加）*/
size_t mkv_tokenize(const char *line, mkv_tok_t *out, size_t cap) {
    size_t n = 0, i = 0, len = strlen(line);
    while (i < len && n < cap) {
        while (i < len && isspace((unsigned char)line[i])) i++;   /* 跳空白 */
        size_t start = i;
        while (i < len && !isspace((unsigned char)line[i])) i++;  /* 吞 token */
        if (start < i) {
            out[n].p = line + start;      /* ⭐ 零拷贝：只记位置和长度 */
            out[n].len = i - start;
            n++;
        }
    }
    return n;
}
```

**✅ 验证**：多空格、tab 分隔都能正确切分，且**全程零 malloc**。

> 💡 `mkv_tok_t` 就是 `std::string_view`，`mkv_tokenize` 就是 C++ 版的 `tokenize`——**C++17 用 16 字节的类把 (p, len) 包起来，C 直接裸写结构体**。

## 03.Value 类型表达

🎯 **阶段② · Value 表达（约 1 小时）**：Step 2.1 tagged union 定义 → Step 2.2 switch 穷尽输出 → Step 2.3 字符串自动推断类型。验收：`42` 认成 int、`3.14` 认成 double、`hello` 认成 string。

KV 的 V 天生需要"一个变量装多种类型"。Python/JS 天然支持，C 是静态语言需要技巧——**04 案例 `json_value_t` 的直系后代**。

### Step 2.1 tagged union 定义 Value

### Step 2.3 类型推断函数

```c
/* src/value.c（追加）*/
#include <ctype.h>
#include <errno.h>

/* 切片 → NUL 结尾的栈拷贝（strtoll/strtod 只吃 C 字符串）*/
static bool tok_copy(const char *p, size_t len, char *buf, size_t cap) {
    if (len >= cap) return false;
    memcpy(buf, p, len);
    buf[len] = '\0';
    return true;
}

mkv_value_t mkv_value_from_token(const char *p, size_t len) {
    /* 分支 1：特殊字面量 */
    if (len == 4 && strncmp(p, "true", 4) == 0)  return mkv_bool(true);
    if (len == 5 && strncmp(p, "false", 5) == 0) return mkv_bool(false);
    if (len == 3 && strncmp(p, "nil", 3) == 0)   return mkv_null();

    /* 分支 2：全数字（可带负号）→ int64 */
    size_t start = (len > 0 && p[0] == '-') ? 1 : 0;
    if (start < len) {
        bool all_digit = true;
        for (size_t i = start; i < len; i++)
            if (!isdigit((unsigned char)p[i])) { all_digit = false; break; }
        if (all_digit) {
            char buf[32];
            if (tok_copy(p, len, buf, sizeof buf)) {
                char *end;
                errno = 0;
                long long v = strtoll(buf, &end, 10);
                if (*end == '\0' && errno == 0)      /* ⭐ 溢出查 errno 降级 */
                    return mkv_int((int64_t)v);
            }
        }
    }

    /* 分支 3：含小数点且能解析 → double */
    if (memchr(p, '.', len)) {
        char buf[64];
        if (tok_copy(p, len, buf, sizeof buf)) {
            char *end;
            double d = strtod(buf, &end);
            if (*end == '\0') return mkv_double(d);
        }
    }

    /* 分支 4：兜底字符串 */
    char buf[256];
    if (tok_copy(p, len, buf, sizeof buf)) return mkv_string(buf);
    return mkv_null();
}
```

**易错点**：① **分支顺序不能换**——`"3.14"` 先被"全数字"拒掉（含 `.`）才进 double 分支，反了会把 `42` 误判成 `42.0`；② `errno = 0` 再 `strtoll`——C++ 版用 `catch(...)` 吞 `stoll` 异常降级，C 版 **strtoll 不抛异常只设 errno**，"异常降级"翻译成"查 errno 降级"。

**✅ 验证**（保留为 `tests/test_value.c`）：`42→(integer) 42`、`-7→(integer) -7`、`3.14→(double) 3.14`、`true→true`、`nil→(nil)`、`hello→"hello"`、`42abc→"42abc"`（不是纯数字落字符串）。

### Step 3.1 Entry 与 TTL

> 📁 **归属文件**：`include/mkv/entry.h`（**新建**，短小全部放头文件）

```c
#ifndef MKV_ENTRY_H
#define MKV_ENTRY_H

#include <stdbool.h>
#include <stdint.h>
#include <time.h>

#include "mkv/value.h"

/* 单调时钟毫秒数：C 版 steady_clock */
static inline int64_t mkv_now_ms(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (int64_t)ts.tv_sec * 1000 + ts.tv_nsec / 1000000;
}

typedef struct {
    mkv_value_t value;
    bool        has_expire;      /* C 的 "optional"：显式 bool 标志 */
    int64_t     expire_ms;       /* 绝对过期点（MONOTONIC 毫秒）*/
    int64_t     created_ms;
    uint64_t    version;         /* 每次 SET 覆写 +1，将来做 CAS */
} mkv_entry_t;

static inline bool mkv_entry_expired(const mkv_entry_t *e) {
    return e->has_expire && mkv_now_ms() >= e->expire_ms;
}

#endif
```

**细节都不是随便写的**：

1. **`bool has_expire` 显式标志**：C++ 用 `std::optional<time_point>`；C 的两个选择——魔法值（`expire_ms=-1`）或显式 bool。**选 bool**：魔法值要求所有代码记得约定，bool 让"无值"在结构体上看得见（04 案例同款取舍）。
2. **`CLOCK_MONOTONIC` 不是 `CLOCK_REALTIME`**：REALTIME 是墙上时钟，用户改系统时间 TTL 全乱套；MONOTONIC 单调递增——**它就是 C++ `steady_clock` 的 POSIX 本体**。TTL/超时永远用它。
3. **`static inline` 放头文件**：C99 起头文件函数的标准姿势，不产生链接冲突。

**✅ 验证**：设 1 秒过期 → `expired=0`；`usleep(1.5s)` → `expired=1`。

```c
    char *key;               /* strdup，所有权归本条目 */

static size_t g_len = 0;

    for (size_t i = 0; i < g_len; i++)
        if (strcmp(g_pairs[i].key, key) == 0) return &g_pairs[i];
    return NULL;
}

/* switch 里的两个 case：*/
case MKV_CMD_SET: {
    if (ntok != 3) { printf("(error) usage: SET key value\n"); break; }
    char key[256];
    snprintf(key, sizeof key, "%.*s", (int)t[1].len, t[1].p);   /* 切片→C串 */

    if (kv) {
        mkv_value_free(&kv->entry.value);
        kv->entry.value = mkv_value_from_token(t[2].p, t[2].len);
        kv->entry.version++;
        kv->entry.has_expire = false;    /* Redis 语义：SET 覆盖清 TTL */
    } else if (g_len < 1024) {
        g_pairs[g_len].key = mkv_xstrdup(key);
        g_pairs[g_len].entry.value = mkv_value_from_token(t[2].p, t[2].len);
        g_pairs[g_len].entry.created_ms = mkv_now_ms();
        g_len++;
    }
    printf("OK\n");
    break;
}
case MKV_CMD_GET: {
    if (ntok != 2) { printf("(error) usage: GET key\n"); break; }
    char key[256];
    snprintf(key, sizeof key, "%.*s", (int)t[1].len, t[1].p);
    kv_pair_t *kv = kv_find(key);
    if (!kv || mkv_entry_expired(&kv->entry)) printf("(nil)\n");   /* 惰性删除 */
    else {
        char buf[256];
        mkv_format(&kv->entry.value, buf, sizeof buf);
        printf("%s\n", buf);
    }
    break;
}
```

### 4.4 结构体浅拷贝陷阱

C++ 版在这里讲"五法则零定义胜利"；**C 没有这个福利，反向的坑才是重点**：

```c
mkv_entry_t a = { .value = mkv_string("hello") };
mkv_entry_t b = a;                 /* ⚠️ 结构体赋值 = 逐字节浅拷贝 */
/* a.as.s 和 b.as.s 指向同一块堆内存！*/
mkv_value_free(&a.value);
mkv_value_free(&b.value);          /* 💥 double free，glibc abort */
```

**C 结构体天生"全拷贝"，但指针成员只拷地址不拷内容**——这就是为什么 `mkv_value_clone` 必须手写深拷贝、为什么 §06 的 `store_get` 必须"锁内 clone、锁外使用"。**所有权纪律贯穿全案**（04 立过、05 用过、本章毕业再考）。

## 05.Command 命令模式

🎯 **阶段④ · 命令模式重构（约 1.5 小时，第 2 次会话上半场）**：Step 4.1 造 BUG 看 200 行 switch → 4.2 基类嵌入接口 → 4.3 具体命令 → 4.4 工厂 → 4.5 main 大瘦身。

### 灵魂三问：动手前先想清楚

❓ **if-else 真能继续用吗？** 8 命令时 main ~150 行凑合；80 命令时 main ~1500 行是地狱。对比：加新命令 if-else 改 3 处 vs 命令模式加 1 个结构体改 1 处；单测一条命令 if-else 必须启动整个 REPL vs 命令模式直接调函数；持久化逻辑 if-else 散落 8 处 case vs 集中在 `to_aof_line` 一处。**抽象的成本先付、收益延期，但延期收益永远 >> 先付成本**。

❓ **C 没有 virtual，多态从哪来？** C++ 虚函数 = 编译器生成的函数指针表 + 自动查表。C 版把这张表**手写进结构体**，本章用**"基类嵌入 + 向下转型"**（Linux 内核 `container_of` 的教学版）：

```c
/* 公共头部：所有命令结构体的第一个成员必须是它 */
typedef struct cmd_base {
    const char *name;                                    /* "SET" */
    bool is_write;
    mkv_err_t (*execute)(struct cmd_base *self, mkv_store_t *store,
                         char *out, size_t out_cap);
    char *(*to_aof_line)(const struct cmd_base *self);
} cmd_base_t;

typedef struct {
    cmd_base_t base;         /* ⭐ 必须是第一个成员 */
    char *key;
    mkv_value_t value;
    char *raw_token;
} set_cmd_t;
```

**多态调用**：`cmd->execute(cmd, store, out, cap)`——传入 `set_cmd_t*` 但因其第一成员就是 base，`(cmd_base_t*)&set_cmd` 地址相同，**向上转型零成本**；execute 内部再 `(set_cmd_t *)self` 转回取字段。**这就是 C++ 编译器在 `class SetCmd : public Command` 背后做的事**。

❓ **为什么 `to_aof_line` 独立函数指针？** 若 main 自己拼 AOF，就必须向下转型拿 `set_cmd_t` 的字段——封装破产，且 switch 又长回来了。✅ 每个命令自己负责"我该怎么写进 AOF"——单一职责原则。

### Step 4.1 if-else 大爆炸

> ❌ **反例演示**：**不入工程**。把 8 个命令全塞 main：每个 case 里"参数校验 + 业务 + AOF 写盘 + 输出"四件事挤一起，没法单测；加 `INCR` 要改 3 处写 30 行。**写到 100 行你就会厌恶——有这种感觉说明你准备好了**。

### Step 4.3 实现具体命令

> 📁 **归属文件**：`src/command.c`（追加）

```c
#include "mkv/store.h"
#include "mkv/entry.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static char *tok_strdup(const mkv_tok_t *t) {
    char *s = malloc(t->len + 1);
    if (!s) return NULL;
    memcpy(s, t->p, t->len);
    s[t->len] = '\0';
    return s;
}

/* ========== SET ========== */
static mkv_err_t set_cmd_execute(cmd_base_t *self, mkv_store_t *store,
                                 char *out, size_t cap) {
    set_cmd_t *c = (set_cmd_t *)self;           /* ⭐ 向下转型取字段 */
    store_set(store, c->key, c->value);
    snprintf(out, cap, "OK");
    return MKV_OK;
}

static char *set_cmd_to_aof(const cmd_base_t *self) {
    const set_cmd_t *c = (const set_cmd_t *)self;
    size_t n = strlen(c->key) + strlen(c->raw_token) + 8;
    char *line = malloc(n);
    if (line) snprintf(line, n, "SET %s %s\n", c->key, c->raw_token);
    return line;
}

static cmd_base_t *set_cmd_new(const char *key, mkv_value_t v, const char *raw) {
    set_cmd_t *c = calloc(1, sizeof *c);
    if (!c) return NULL;
    c->base = (cmd_base_t){ "SET", true, set_cmd_execute, set_cmd_to_aof };
    c->key = mkv_xstrdup(key);
    c->value = v;
    c->raw_token = mkv_xstrdup(raw);
    return &c->base;
}

/* ========== GET ========== */
static mkv_err_t get_cmd_execute(cmd_base_t *self, mkv_store_t *store,
                                 char *out, size_t cap) {
    get_cmd_t *c = (get_cmd_t *)self;
    mkv_value_t v;
    if (!store_get(store, c->key, &v)) { snprintf(out, cap, "(nil)"); return MKV_OK; }
    mkv_format(&v, out, cap);
    mkv_value_free(&v);
    return MKV_OK;
}

/* ========== DEL / EXPIRE（模式相同，从简）========== */
static mkv_err_t del_cmd_execute(cmd_base_t *self, mkv_store_t *store,
                                 char *out, size_t cap) {
    (void)self;
    snprintf(out, cap, "(integer) %d", store_del(store, ((del_cmd_t *)self)->key));
    return MKV_OK;
}

static mkv_err_t expire_cmd_execute(cmd_base_t *self, mkv_store_t *store,
                                    char *out, size_t cap) {
    expire_cmd_t *c = (expire_cmd_t *)self;
    snprintf(out, cap, store_expire(store, c->key, c->seconds) ? "OK"
                                                               : "(integer) 0");
    return MKV_OK;
}
```

（`get/del/expire_cmd_new` 与 `set_cmd_new` 同模式：calloc + 填 base 指针 + strdup 字段，此处从简。）

**多态的甜头**：调用方只持 `cmd_base_t *`，`cmd->execute(cmd, ...)` 调到哪个函数由结构体里的指针决定——**虚函数表的工作，只是这张表现在是你手写的**。

### Step 4.4 命令工厂

```c
/* src/command.c（追加）*/
static bool need_args(size_t ntok, size_t want, mkv_err_t *err) {
    if (ntok != want + 1) { *err = MKV_ERR_SYNTAX; return false; }
    return true;
}

cmd_base_t *mkv_command_parse(const mkv_tok_t *t, size_t ntok, mkv_err_t *err) {
    if (ntok == 0) { *err = MKV_ERR_SYNTAX; return NULL; }
    char key[256], raw[256];

    switch (mkv_parse_cmd_type(t[0].p, t[0].len)) {
    case MKV_CMD_SET:
        if (!need_args(ntok, 2, err)) return NULL;
        snprintf(key, sizeof key, "%.*s", (int)t[1].len, t[1].p);
        snprintf(raw, sizeof raw, "%.*s", (int)t[2].len, t[2].p);
        return set_cmd_new(key, mkv_value_from_token(t[2].p, t[2].len), raw);

    case MKV_CMD_GET:
    case MKV_CMD_DEL:
        if (!need_args(ntok, 1, err)) return NULL;
        snprintf(key, sizeof key, "%.*s", (int)t[1].len, t[1].p);
        return (t[0].p[0] == 'G' || t[0].p[0] == 'g')
             ? get_cmd_new(key) : del_cmd_new(key);

    case MKV_CMD_EXPIRE: {
        if (!need_args(ntok, 2, err)) return NULL;
        char sec[32];
        snprintf(key, sizeof key, "%.*s", (int)t[1].len, t[1].p);
        snprintf(sec, sizeof sec, "%.*s", (int)t[2].len, t[2].p);
        char *end;
        long n = strtol(sec, &end, 10);        /* ⭐ 失败不抛异常：查 end */
        if (*end != '\0' || n < 0) { *err = MKV_ERR_SYNTAX; return NULL; }
        return expire_cmd_new(key, (int)n);
    }
    default:
        *err = MKV_ERR_SYNTAX;
        return NULL;                            /* EXIT/UNKNOWN 由 main 提前处理 */
    }
}

void mkv_command_free(cmd_base_t *cmd) {
    if (!cmd) return;
    if (strcmp(cmd->name, "SET") == 0) {
        set_cmd_t *c = (set_cmd_t *)cmd;
        free(c->key);
        mkv_value_free(&c->value);
        free(c->raw_token);
    } else {
        free(((get_cmd_t *)cmd)->key);          /* get/del/expire 字段布局同 */
    }
    free(cmd);
}
```

> ⚠️ **C 版特有的尴尬**：`mkv_command_free` 按字段布局判断怎么释放——**C++ 的虚析构函数就是干这个的**（`delete base` 自动调派生析构）。更正宗的 C 做法：给 `cmd_base_t` 加第四个函数指针 `destroy`，每命令自己释放自己（§14 思考题）。

### Step 4.5 main 大瘦身

> 📁 **归属文件**：`src/main.c`（主循环核心，Store 是 §06 的产物，两节合起来才能跑）

## 06.手写哈希表与 Store

🎯 **阶段⑤+⑥ · 哈希表 + Store（约 1.5 小时，第 2 次会话下半场）**。**手写哈希表是 C 版相对 C++ 版新增的毕业重头戏**——C++ 直接 `unordered_map`，C 必须自己写 FNV-1a + 链地址法 + 扩容 rehash。

### Step 5.1 hashmap 骨架

> 📁 **归属文件**：`include/mkv/hashmap.h` + `src/hashmap.c`（**新建**）

```c
/* include/mkv/hashmap.h */
#ifndef MKV_HASHMAP_H
#define MKV_HASHMAP_H

#include <stdbool.h>
#include <stddef.h>
#include "mkv/entry.h"

typedef struct hm_node {
    char *key;                  /* malloc 拷贝，所有权归节点 */
    mkv_entry_t entry;          /* value 所有权随节点 */
    struct hm_node *next;       /* 同桶冲突链 */
} hm_node_t;

typedef struct {
    hm_node_t **buckets;        /* 桶数组 */
    size_t cap;                 /* 桶数（恒为 2 的幂）*/
    size_t len;
} hashmap_t;

bool  hm_init(hashmap_t *m);
void  hm_destroy(hashmap_t *m);
hm_node_t *hm_find(hashmap_t *m, const char *key);
bool  hm_put(hashmap_t *m, const char *key, mkv_entry_t e);
bool  hm_del(hashmap_t *m, const char *key);
size_t hm_size(hashmap_t *m);

#endif
```

```c
/* src/hashmap.c */
#include "mkv/hashmap.h"
#include <stdlib.h>
#include <string.h>

char *mkv_xstrdup(const char *s);

/* ===== FNV-1a：最流行的教学级字符串哈希 ===== */
static size_t fnv1a(const char *s) {
    size_t h = 14695981039346656037ULL;     /* offset basis */
    while (*s) {
        h ^= (unsigned char)*s++;
        h *= 1099511628211ULL;              /* prime */
    }
    return h;
}

bool hm_init(hashmap_t *m) {
    m->cap = 16;                            /* 初始 16 桶（2 的幂）*/
    m->len = 0;
    m->buckets = calloc(m->cap, sizeof *m->buckets);
    return m->buckets != NULL;
}

void hm_destroy(hashmap_t *m) {
    for (size_t i = 0; i < m->cap; i++) {
        hm_node_t *n = m->buckets[i];
        while (n) {
            hm_node_t *next = n->next;
            free(n->key);
            mkv_value_free(&n->entry.value);
            free(n);
            n = next;
        }
    }
    free(m->buckets);
    m->buckets = NULL;
    m->len = m->cap = 0;
}
```

> 💡 **为什么桶数是 2 的幂**：`h & (cap-1)` 位与取模比 `%` 快且等价——`unordered_map`、内核 hashtable 都这么干。**链地址法**：哈希冲突的 key 挂在同一条单链表上。

### Step 5.2 增删查与扩容

```c
/* src/hashmap.c（追加）*/
hm_node_t *hm_find(hashmap_t *m, const char *key) {
    for (hm_node_t *n = m->buckets[fnv1a(key) & (m->cap - 1)]; n; n = n->next)
        if (strcmp(n->key, key) == 0) return n;
    return NULL;
}

/* 负载因子 ≥ 2 时翻倍 rehash */
static bool hm_grow(hashmap_t *m) {
    if (m->len < m->cap * 2) return true;
    size_t ncap = m->cap * 2;
    hm_node_t **nb = calloc(ncap, sizeof *nb);
    if (!nb) return false;
    for (size_t i = 0; i < m->cap; i++) {       /* 旧桶逐节点搬新家 */
        hm_node_t *n = m->buckets[i];
        while (n) {
            hm_node_t *next = n->next;
            size_t h = fnv1a(n->key) & (ncap - 1);
            n->next = nb[h];                    /* 头插进新桶 */
            nb[h] = n;
            n = next;
        }
    }
    free(m->buckets);
    m->buckets = nb;
    m->cap = ncap;
    return true;
}

bool hm_put(hashmap_t *m, const char *key, mkv_entry_t e) {
    if (!hm_grow(m)) return false;
    size_t h = fnv1a(key) & (m->cap - 1);
    for (hm_node_t *n = m->buckets[h]; n; n = n->next) {
        if (strcmp(n->key, key) == 0) {         /* 已存在 → 覆盖 */
            mkv_value_free(&n->entry.value);
            n->entry = e;                       /* value 所有权转移给节点 */
            return true;
        }
    }
    hm_node_t *n = malloc(sizeof *n);           /* 头插新节点 */
    if (!n) return false;
    n->key = mkv_xstrdup(key);
    n->entry = e;
    n->next = m->buckets[h];
    m->buckets[h] = n;
    m->len++;
    return true;
}
```

**✅ 验证**：插入 1000 个 key，`hm_size==1000`、`hm_find("k500")` 命中、桶数从 16 rehash 到 2048。

### Step 5.3 删节点断链 BUG

🎯 **本步目标**：链表删除经典翻车现场，再用**指针的指针**修复。**这是 C 版对应 C++ "迭代器失效"的造 BUG**。

#### 💥 阶段 1：新手写法（cur/prev 双指针）

> ❌ **反例演示**：**不入工程**

```c
bool hm_del_bad(hashmap_t *m, const char *key) {
    size_t h = fnv1a(key) & (m->cap - 1);
    hm_node_t *cur = m->buckets[h], *prev = NULL;
    while (cur) {
        if (strcmp(cur->key, key) == 0) {
            if (prev) prev->next = cur->next;      /* 中间节点 */
            /* ⚠️ 忘了 else：头节点时 m->buckets[h] 没更新！*/
            free(cur->key);
            mkv_value_free(&cur->entry.value);
            free(cur);
            m->len--;
            return true;
        }
        prev = cur;
        cur = cur->next;
    }
    return false;
}
```

删头节点后：`m->buckets[h]` 指向已 free 的内存——同桶下一个 key 的 `hm_find` **要么摸野指针（乱码/崩溃），要么整桶后续 key 全部丢失**。链断了但 `m->len` 照减——**数据结构和计数器从此对不上，之后每个操作都是雷**。（C++ 版的"erase 后 ++it 是 UB"同一个性质：**不一定崩，但随时可能崩**。）

#### 🔧 阶段 2：指针的指针修复

```c
bool hm_del(hashmap_t *m, const char *key) {
    size_t h = fnv1a(key) & (m->cap - 1);
    hm_node_t **pp = &m->buckets[h];  /* ⭐ pp 指向"存放节点地址的那个槽" */
    while (*pp) {
        if (strcmp((*pp)->key, key) == 0) {
            hm_node_t *dead = *pp;
            *pp = dead->next;         /* ⭐ 一步接链：头/中/尾零特判 */
            free(dead->key);
            mkv_value_free(&dead->entry.value);
            free(dead);
            m->len--;
            return true;
        }
        pp = &(*pp)->next;
    }
    return false;
}
```

**`hm_node_t **pp` 的精妙之处**：`pp` 不是指向节点，而是**指向"指向节点的指针"**（桶头或某节点的 next 字段）。删除时 `*pp = dead->next` 一行搞定所有位置——这是 Linux 内核 `list_del` 同款写法，**第 07 章指针的毕业用法**。

**✅ 造 BUG 复现**：错误版跑一遍看到断链 → 换正确版 → 1000 key 随机删 500，`hm_size` 与逐 key `hm_find` 全对。

### Step 5.4 Store 七个方法

> 📁 **归属文件**：`include/mkv/store.h` + `src/store.c`（**新建**）。**本版本先不加锁（单线程），§10 升级 rwlock**。

```c

#define MKV_STORE_H
```

```c
/* src/store.c —— 核心方法 */
#include "mkv/store.h"
#include <stdlib.h>
#include <string.h>

void store_init(mkv_store_t *s) {
    pthread_rwlock_init(&s->rwlock, NULL);
    hm_init(&s->map);
}

void store_destroy(mkv_store_t *s) {
    hm_destroy(&s->map);
    pthread_rwlock_destroy(&s->rwlock);
}

bool store_set(mkv_store_t *s, const char *key, mkv_value_t v) {
    hm_node_t *n = hm_find(&s->map, key);
    if (n) {                                    /* 覆盖：版本+1 + 清 TTL */
        mkv_value_free(&n->entry.value);
        n->entry.value = v;                     /* 所有权转移进 map */
        n->entry.version++;
        n->entry.has_expire = false;            /* Redis 语义：SET 清旧 TTL */
        return true;
    }
    mkv_entry_t e = { .value = v, .created_ms = mkv_now_ms() };
    return hm_put(&s->map, key, e);
}

bool store_get(mkv_store_t *s, const char *key, mkv_value_t *out) {
    hm_node_t *n = hm_find(&s->map, key);
    if (!n || mkv_entry_expired(&n->entry)) return false;   /* 惰性删除 */
    *out = mkv_value_clone(&n->entry.value);    /* ⭐ 深拷贝出参 */
    return true;
}

int store_del(mkv_store_t *s, const char *key) {
    return hm_del(&s->map, key) ? 1 : 0;        /* 幂等：删不存在返 0 */
}

bool store_expire(mkv_store_t *s, const char *key, int seconds) {
    hm_node_t *n = hm_find(&s->map, key);
    if (!n) return false;
    n->entry.has_expire = true;
    n->entry.expire_ms = mkv_now_ms() + (int64_t)seconds * 1000;
    return true;
}

int64_t store_ttl(mkv_store_t *s, const char *key) {
    hm_node_t *n = hm_find(&s->map, key);
    if (!n)                   return -2;
    if (!n->entry.has_expire) return -1;
    int64_t left = (n->entry.expire_ms - mkv_now_ms()) / 1000;
    return left < 0 ? 0 : left;
}

void store_purge_expired(mkv_store_t *s) {
    for (size_t i = 0; i < s->map.cap; i++) {
        hm_node_t *n = s->map.buckets[i];
        while (n) {
            hm_node_t *next = n->next;          /* ⭐ 先存 next 再删（防线）*/
            if (mkv_entry_expired(&n->entry)) hm_del(&s->map, n->key);
            n = next;
        }
    }
}
```

**为什么 `store_get` 是"clone 出参"而不是返回节点指针？** C 版最重要的所有权决策：

> C++ 版 `get` 返回 `shared_ptr<Entry>`——引用计数保证"正在被使用的 Entry 不会被清理线程析构"。**C 没有引用计数**：若返回 `hm_node_t*`，调用方还没用完，另一线程 DEL 同 key → 节点已 free → **悬垂指针**。所以 C 版铁律：**锁内（或单线程下）clone，锁外使用**。多付一次字符串拷贝，换来绝对安全——§10 并发化后你会感谢这条纪律。

```bash

> EXPIRE name 1 → OK
> DEL age → (integer) 1
> TTL name → (integer) 0
> EXIT → bye.
```

SET/GET/DEL/EXPIRE/TTL 全链路走通，main 从 200+ 行缩到 ~40 行 → **从"main 堆代码"到"Command + 手写哈希表 + Store"三层架构的跃迁完成**。`git commit -m "session-2: hashmap + command pattern + store"`。

## 07.错误体系工程化

🎯 **阶段⑦ · 错误体系（第 3 次会话，约 1 小时）**。C++ 版建 5 个异常类的继承树；C 没有异常——04 案例的"错误码 + 上下文"在这里工程化。

### Step 7.1 错误码 vs "打印一句"

C 的真问题不是"异常 vs 错误码"，而是"**错误码 vs 哪里错哪里 printf 一句继续跑**"（后者是新手最大坑）。混合策略：

| 情况 | 例子 | 用什么 |
|------|------|--------|
| 高频常态结果 | GET 不存在的 key | 返回值（`false`）|
| 调用方写错 | SET 缺参、EXPIRE 参数非数字 | 错误码 `MKV_ERR_SYNTAX` |
| 系统资源 | AOF 打不开、磁盘满 | 错误码 `MKV_ERR_IO` |
| 数据文件坏 | AOF 重放遇坏行 | 错误码 `MKV_ERR_AOF_CORRUPT` |

**核心原则**：错误码用于**跨层传递**（解析层发现 → main 统一处理）；"业务上的 false"（miss/删除不存在）用返回值——每秒几万次的常态不走错误通道。

### Step 7.2 错误码与上下文

> 📁 **修改文件**：`include/mkv/errors.h` 升级 + `src/errors.c`（**新建**）

```c
#include "mkv/errors.h"
#include <stdarg.h>
#include <stdio.h>

const char *mkv_err_str(mkv_err_t code) {
    switch (code) {
    case MKV_OK:              return "OK";
    case MKV_ERR_SYNTAX:      return "命令语法错误";
    case MKV_ERR_TYPE:        return "类型不匹配";
    case MKV_ERR_IO:          return "IO 错误";
    case MKV_ERR_AOF_CORRUPT: return "AOF 损坏";
    case MKV_ERR_MEMORY:      return "内存分配失败";
    }
    return "unknown";
}

void mkv_err_set(mkv_error_t *err, mkv_err_t code, const char *fmt, ...) {
    if (!err) return;
    err->code = code;
    err->aof_line = 0;
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(err->msg, sizeof err->msg, fmt, ap);
    va_end(ap);
}
```

### Step 7.3 不检查返回值会咋样

#### 💥 阶段 1：无视错误直接用


**💥 一个用户输错命令，整个服务挂了**。C++ 版这里是 `terminate called after throwing`（至少有提示）；**C 版连一句提示都没有，直接 segfault**——C 的错误体系不是"要不要建"，是"不建就死"。

#### 🔧 阶段 2：统一检查 + 分层处理（C 版的"分层 catch"）

**✅ 造 BUG 复现**：先跑错误版看 segfault，再跑修复版看优雅提示——**"每个可能失败的调用都要检查返回值"从此刻进 DNA**。

### Step 7.4 分层处理守则

1. **fail-fast**：`EXPIRE foo abc` 在工厂的 strtol 处就拦（Step 4.4 已做），错误传播越远排查越难
2. **本层能处理就别上传**：`store_get` miss 返回 false 就够，不设错误码——miss 是常态
3. **跨层错误 main 统一收口**：所有打印错误的代码只在 main 一处，将来接日志（§09）只改一处

## 08.AOF 持久化实现

🎯 **阶段⑧ · 持久化（第 4 次会话上半场，约 2 小时）**。到目前为止进程一关数据全没。Redis 用 RDB（快照）和 AOF（追加日志）对付它，本案例采用 AOF。

### 灵魂三问：动手前先想清楚

❓ **为什么用 AOF 不用 dump（快照）？**

```c
/* ❌ 反例：每次写变化就把全表序列化（不入工程）*/
FILE *f = fopen("data.dump", "wb");       /* 一打开旧文件清空 */
/* 把 10 万个 key 全写一遍…… */
```

**问题**：① **写放大致命**——改 1 个 key 重写全部，100KB 命令变 10MB IO；② **崩溃中段毁文件**——清空后没写完就崩，新旧数据全丢；③ 丢"操作历史"。✅ **追加日志 = 只写"刚发生的事"**——MySQL binlog、PostgreSQL WAL、Kafka 全是这个思路（event sourcing）。

❓ **为什么 `"ab"` 追加而不是 `"wb"` 改写？** `"wb"` 打开瞬间清空文件，历史 100 万行归零；`"ab"` 对应 POSIX `O_APPEND`——**OS 保证每次写原子追加到文件末尾**（文件系统送的免费保障）。**生产环境谁误用 `"wb"` 谁丢数据**。

❓ **fwrite/fflush 之后数据落盘了吗？**

```text
你的代码 → fprintf/fwrite
        ↓
  C 库 stdio 缓冲    ← fflush() 推到这里就返回
        ↓
  内核 page cache    ← write() 到的地方！断电会丢
        ↓
  磁盘扇区           ← 必须 fsync(fd) 才强制刷到这里
```

| 策略 | 性能 | 安全 | 场景 |
|------|------|------|------|
| 不 fflush | 极快 | 进程崩丢 | 不重要日志 |
| 每次 fflush（本案例）| 中 | 进程崩不丢，**断电丢** | 教学默认 |
| 每次 fsync | 慢 10× | **断电不丢** | 银行/订单 |
| 每秒 fsync（Redis everysec）| 较快 | 最坏丢 1 秒 | 工业折中 |

🔑 **持久化的本质是"和 OS 谈一场性能与安全的谈判"**（§14.2 展开）。

### Step 8.1 理解 AOF 原理

```text
启动：    打开 aof.log → 一行行读 → 重放到 store
运行中：  每个写命令 execute 之后 → 追加一行 → fflush
关闭：    什么都不做（已经全在文件里）
```

AOF 的妙处：**写入格式就是命令本身**（`SET name zhangsan\n`），重放走和正常运行**完全一样的命令管道**——新增命令不用改持久化代码，`to_aof_line` 和 `mkv_command_parse` 自动覆盖。**自检**：重放走同一套解析代码？（是）重放要回写 AOF？（不要，否则文件每启动翻倍）新命令要动持久化？（不用）。

### Step 8.2 aof_writer 追加写

> 📁 **归属文件**：`include/mkv/aof.h` + `src/aof.c`（**新建**，此处列写端）

```c
/* include/mkv/aof.h */
#ifndef MKV_AOF_H
#define MKV_AOF_H

#include <stdbool.h>
#include <stddef.h>
#include "mkv/command.h"
#include "mkv/errors.h"

typedef struct {
    FILE *f;
    char path[128];
} aof_writer_t;

bool aof_writer_open(aof_writer_t *w, const char *path);
void aof_writer_close(aof_writer_t *w);
bool aof_append(aof_writer_t *w, const char *line);

typedef struct {
    size_t replayed, corrupted, total_lines;
} aof_report_t;

aof_report_t aof_replay(const char *path, struct mkv_store *store,
                        mkv_error_t *err, bool tolerant);

```

```c
/* src/aof.c —— 写端 */
#include "mkv/aof.h"
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>

bool aof_writer_open(aof_writer_t *w, const char *path) {
    mkdir("data", 0755);              /* POSIX 建目录：已存在返 EEXIST 不算错 */
    errno = 0;
    snprintf(w->path, sizeof w->path, "%s", path);
    w->f = fopen(path, "ab");         /* ⭐ a=append b=二进制（防 Windows \r\n）*/
    return w->f != NULL;
}

void aof_writer_close(aof_writer_t *w) {
    if (w->f) {
        fflush(w->f);
        fclose(w->f);                 /* C 没有 RAII：忘调这行 = fd 泄漏+数据滞留 */
        w->f = NULL;
    }
}

bool aof_append(aof_writer_t *w, const char *line) {
    if (!w->f || fputs(line, w->f) == EOF) return false;
    fflush(w->f);                     /* 推到内核：进程被 kill 也不丢 */
    return true;
}
```

> 💡 `mkdir` 对照 C++ 版的 `fs::create_directories`——C 版手动一行（只建一层；递归建目录留作挑战）。**`aof_writer_close` 就是 C 版的"析构函数"**——C++ 靠 RAII 自动调，C 全靠配对纪律（05 案例 goto close 惯用法的文件版）。

**✅ 验证**：跑两遍程序各 SET 一条，`cat data/aof.log` 看到两行追加（不是覆盖）——亲眼验证 `"ab"` 的追加语义。

### Step 8.3 aof_replay 重放

> 📁 **归属文件**：`src/aof.c`（追加读端）

```c
/* src/aof.c —— 读端（宽松版，Step 8.5 讲严格式）*/
#include "mkv/store.h"
#include "mkv/log.h"

aof_report_t aof_replay(const char *path, struct mkv_store *store,
                        mkv_error_t *err, bool tolerant) {
    aof_report_t r = {0};
    FILE *in = fopen(path, "rb");        /* 不存在 = 全新启动，不是错误 */
    if (!in) return r;

    char line[1024];
    size_t line_no = 0;
    while (fgets(line, sizeof line, in)) {
        line_no++;
        line[strcspn(line, "\r\n")] = '\0';
        if (line[0] == '\0') continue;
        r.total_lines++;

        mkv_tok_t t[16];
        size_t n = mkv_tokenize(line, t, 16);
        mkv_error_t e;
        cmd_base_t *cmd = mkv_command_parse(t, n, &e);
        if (!cmd) {                      /* 坏行 */
            r.corrupted++;
            if (!tolerant) {             /* 严格式：中止启动 */
                mkv_err_set(err, MKV_ERR_AOF_CORRUPT,
                            "line %zu: %s", line_no, e.msg);
                err->aof_line = line_no;
                fclose(in);
                return r;
            }
            KV_LOG_WARN("AOF skip corrupted line %zu: %s", line_no, e.msg);
            continue;                    /* 宽松式：记日志继续 */
        }
        if (cmd->is_write) {
            char out[256];
            cmd->execute(cmd, store, out, sizeof out);   /* 重放（不回写 AOF）*/
            r.replayed++;
        }
        mkv_command_free(cmd);
    }
    fclose(in);
    return r;
}
```

**✅ 验证**（保留为 `tests/test_aof.c`）：`aof_replay` 后 `store_get("hello")` 拿到 `"world"`——**文件 → fgets → tokenize → command_parse → execute → store 全链路闭环**。

### Step 8.4 主循环串 AOF + kill -9 实验

> 📁 **归属文件**：`src/main.c`（关键增量）

```c

/* …命令循环里 execute 成功后 —— */
```

## 09.日志系统实战

🎯 **阶段⑨ · 工程化日志（第 4 次会话下半场，约 1 小时）**。

### Step 9.1 fprintf 升级 KV_LOG

裸 `fprintf` 四个不够用：没时间戳（不知道故障在哪一秒）、没级别（ERROR 和 INFO 混一起没法 grep）、没文件位置（不知道哪行打的）、上线不能关（DEBUG 压垮磁盘 IO）。

> 📁 **归属文件**：`include/mkv/log.h`（**新建**，全放头文件）

```c
/* include/mkv/log.h */
#ifndef MKV_LOG_H
#define MKV_LOG_H

#include <stdio.h>
#include <time.h>
#include <sys/time.h>

enum { KV_LOG_DEBUG = 0, KV_LOG_INFO = 1, KV_LOG_WARN = 2, KV_LOG_ERROR = 3 };

/* 编译期可覆盖：make CFLAGS+="-DKV_LOG_LEVEL=2" 只留 WARN+ERROR */
#ifndef KV_LOG_LEVEL
#define KV_LOG_LEVEL 1                    /* 默认 INFO 起步 */
#endif

/* "HH:MM:SS.mmm"（localtime_r 线程安全版，05 案例 logger 同款）*/
static inline void mkv_now_str(char buf[16]) {
    struct timeval tv;
    gettimeofday(&tv, NULL);
    struct tm tmv;
    localtime_r(&tv.tv_sec, &tmv);
    snprintf(buf, 16, "%02d:%02d:%02d.%03d",
             tmv.tm_hour, tmv.tm_min, tmv.tm_sec, (int)(tv.tv_usec / 1000));
}

/* ⭐ 核心宏：do-while(0) + __FILE__/__LINE__/__func__ */
#define KV_LOG_IMPL(lvl, lvname, fmt, ...)                                  \
    do {                                                                    \
        if ((lvl) >= KV_LOG_LEVEL) {                                        \
            char _ts[16];                                                   \
            mkv_now_str(_ts);                                               \
            fprintf(stderr, "[%s] [%s] [%s:%d %s] " fmt "\n",               \
                    _ts, lvname, __FILE__, __LINE__, __func__,              \
                    ##__VA_ARGS__);                                         \
        }                                                                   \
    } while (0)

#define KV_LOG_DEBUG(fmt, ...) KV_LOG_IMPL(KV_LOG_DEBUG, "DEBUG", fmt, ##__VA_ARGS__)
#define KV_LOG_INFO(fmt, ...)  KV_LOG_IMPL(KV_LOG_INFO,  "INFO ", fmt, ##__VA_ARGS__)
#define KV_LOG_WARN(fmt, ...)  KV_LOG_IMPL(KV_LOG_WARN,  "WARN ", fmt, ##__VA_ARGS__)
#define KV_LOG_ERROR(fmt, ...) KV_LOG_IMPL(KV_LOG_ERROR, "ERROR", fmt, ##__VA_ARGS__)

#endif
```

```c
KV_LOG_INFO("server start, replayed %zu keys", n);
/* 输出：[14:23:01.123] [INFO ] [src/main.c:42 main] server start, replayed 2 keys */
```

> 💡 **精髓**：`__FILE__` / `__LINE__` / `__func__` 是**预处理器**在宏展开处提供的——**函数拿到的永远是函数自己所在的行**。这是日志必须是宏、不能是函数的根本原因。C++ 版用 `<<` 拼接获得类型安全；C 版用 printf 风格 + `format(printf, 3, 4)` 属性让 gcc 查格式串（`%d` 传 `char*` 会警告）。

### Step 9.2 do-while(0) 必须

#### 💥 造 BUG：去掉 do-while(0)

> ❌ **反例演示**：**不入工程**

```c
#define KV_LOG_INFO_BAD(fmt, ...)                              \
    if (1 >= KV_LOG_LEVEL)                                     \

```

```c
    KV_LOG_INFO_BAD("store has data");
else
    KV_LOG_INFO_BAD("store empty");     /* ⚠️ */
```

预处理展开后：

```c

    if (1 >= KV_LOG_LEVEL)
        fprintf(stderr, "[INFO ] store has data\n");
```

## 10.并发安全读写

🎯 **阶段⑩ · 多线程与数据竞争（第 5 次会话，约 1.5 小时）**。05 案例的并发知识在这里毕业验收。

### 灵魂三问：动手前先想清楚

❓ **05 案例的库存用 atomic 修复了，为什么这里不能用 atomic？**

```c
_Atomic hashmap_t map;      /* ❌ atomic 只支持"平凡可拷贝"类型，编译都过不了 */
```

① `_Atomic` 只装得下无指针无堆内存的平凡类型——哈希表内部全是 malloc 的节点和指针；② 真实业务的原子操作远不止读写一个值——`SET` 是"查 key → 插节点 → 清 TTL"三步，任何一步被插足都乱；③ CAS 循环塞不进"找 + 改 + 写"的复合操作。✅ **临界区由若干语句组成时，用锁包起来**——atomic 只解决"单变量读改写"。

❓ **为什么不所有锁都升级 rwlock？** rwlock 内部要维护"读者计数 + 写者标志 + 等待队列"，单次加锁开销是 mutex 的 2-3 倍；写多读少反而更慢；还有写者饥饿。✅ **默认 mutex，读 ≥ 90% 才升级 rwlock**——先量再改。

❓ **Redis 单线程跑得飞起，我们加锁干嘛？** 单线程实现极简（无锁）、无竞态 bug 少一个数量级、KV 瓶颈在网络和内存不在 CPU；代价是只用 1 核 + 长命令卡所有人。教学上必须演示多线程+锁；生产架构取舍见 §14.4。

### Step 10.1 计数器变 1837

🎯 **全书最重要的造 BUG**。两线程各加 1000 次，期望 2000——亲眼看到 1837。

> 🧪 **造 BUG 实验代码**：保留为 `tests/test_race.c`

```c
/* tests/test_race.c */
#include <pthread.h>
#include <stdio.h>

static int counter = 0;          /* 裸 int，未保护 */

static void *adder(void *arg) {
    (void)arg;
    for (int i = 0; i < 1000; i++) counter++;    /* 看似一句，实为三步 */
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, adder, NULL);
    pthread_create(&t2, NULL, adder, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("counter = %d\n", counter);
    return 0;
}
```

```bash
$ make test_race && for i in 1 2 3 4 5; do ./test_race; done
counter = 1837
counter = 1742
counter = 1923
counter = 2000       # 偶尔也能"蒙对"
counter = 1891
```

**💥 期望 2000，实际 1700~2000 摆动；每次不同；代码看起来完全正确。** `counter++` 的三步真身：

```text
1. load  counter → 寄存器    （t1 t2 都读到 100）
2. add   1                     （各变 101）
3. store 寄存器 → counter     （都写回 101）
```

本来加 2 次只加了 1 次——这就是数据竞争（05 案例超卖的最小复现）。把场景搬到 store 上（8 线程并发 SET）——无锁版大概率**段错误**（`hm_put` 头插链表被并发打断 → 结构损坏）或脏写。

**✅ 验证**：① 亲手跑 5 次看到 ≥3 个不同错值；② store 版跑 3 次看到 ≥1 次段错误/脏值；③ 能说出 `counter++` 为什么不是原子的。

> 💡 **进阶武器**：`gcc -fsanitize=thread`（TSan）能在**没出错的那次**也检测出竞争并打印两线程交错栈——`make CFLAGS+="-fsanitize=thread" test_race` 试试。

### Step 10.2 mutex 修复竞争

> 📁 **修改文件**：`store.h`（`pthread_mutex_t mu`）+ `store.c`（每方法首行 lock / 尾行 unlock）

```c
bool store_get(mkv_store_t *s, const char *key, mkv_value_t *out) {
    pthread_mutex_lock(&s->mu);
    hm_node_t *n = hm_find(&s->map, key);
    bool ok = n && !mkv_entry_expired(&n->entry);
    if (ok) *out = mkv_value_clone(&n->entry.value);
    pthread_mutex_unlock(&s->mu);
    return ok;
}
```

**C 版加锁四条纪律**（C++ 有 lock_guard，C 全靠自觉）：

1. **锁在函数第一行、解在最后一个出口**——多 return 用 `goto unlock` 收口（05 案例惯用法最后一次实战）
2. **每个公开方法都要加**——漏一个就有竞争
3. **不能在锁内递归调本类其他公开方法**——两次 lock 同一把 mutex → 死锁（mutex 不可重入）
4. **锁内尽量少做事**——get 锁内只 find + clone，format 留锁外

**✅ 验证**：`for i in $(seq 1 100); do ./test_store_race; done | sort -u | wc -l` 输出 `1`（100 次全部一致）。

### Step 10.3 rwlock 优化

KV 负载**读多写少**（GET:SET 通常 10:1）。mutex 让读互斥太亏，`pthread_rwlock` 让 GET 并发（05 案例 Step 3.3 已实测 2.5 倍差距）。

**📋 读/写方法分类速查表**：

| 类别 | 方法 | 锁 |
|------|------|-----|
| **写** | `set` / `del` / `expire` / `purge_expired` | `pthread_rwlock_wrlock` |
| **读** | `get` / `ttl` / `keys` / `size` | `pthread_rwlock_rdlock` |

```c
bool store_get(mkv_store_t *s, const char *key, mkv_value_t *out) {
    pthread_rwlock_rdlock(&s->rwlock);       /* ⭐ 读锁：多读者并存 */
    /* …逻辑同 mutex 版… */
    pthread_rwlock_unlock(&s->rwlock);
    return ok;
}
```

⚠️ **千万别把写方法写成 rdlock**：写锁写成读锁 = 完全没锁（多个"写者"同时进临界区改链表）——**数据竞争，UB**。

### Step 10.4 锁粒度取舍

更激进的优化是**分片锁**（16 桶段各配一把锁，按 hash 选锁），本案例不实现：教学目标是理解锁的本质；分片让"原子改 N 个 key"复杂化；真实 Redis 是单线程压根不用锁。**锁不是越多越好——先正确，再性能**。

**✅ 验证**：能一句话回答——① Redis 为什么不用锁（单主线程串行 + epoll）；② 什么场景选分片锁（写吞吐到顶且不跨分片）；③ 为什么"原子改 N 个 key"用分片锁难（按序拿 N 把锁防死锁）。

## 11.TTL 后台清理

🎯 **阶段⑪ · 后台线程与优雅停止（约 1 小时）**。加了 EXPIRE 后有个隐藏问题：**没人主动删过期 key**——`store_get` 的惰性删除只在被读到时生效，没人读的过期 key 永远占内存。

### Step 11.1 惰性与主动清理

| 策略 | 触发时机 | 优点 | 缺点 |
|------|---------|------|------|
| **惰性删除** | 读到过期 key 时 | 零额外 CPU | 没人读的过期 key 永不删 |
| **定期扫描** | 后台每 100ms | 兜底覆盖 | 占额外 CPU |

本案例两个都做——**惰性在 store_get（§06 已有），主动在本节后台线程**。

### Step 11.2 忘 join 的两种死法

C++ 版演示"裸 `std::thread` 忘 join → terminate"。**C 没有 terminate，死法更阴险**：

> 🧪 **造 BUG 实验代码**：独立 demo，**不入工程**

```c
/* 死法：后台线程引用 main 的栈对象，main 不 join 就返回 */
static void *purger_bad(void *arg) {
    mkv_store_t *store = arg;             /* 指向 main 的栈变量 */
    while (1) { store_purge_expired(store); usleep(100000); }
    return NULL;
}

int main(void) {
    mkv_store_t store;                    /* 栈对象 */
    store_init(&store);
    pthread_t t;
    pthread_create(&t, NULL, purger_bad, &store);
    /* …REPL… 然后 return 0，忘了 join —— */
}   /* 进程 exit 时 store 栈帧销毁，
      线程可能正在 store_purge_expired 里摸它 → 悬垂访问
      运气好打印乱码，运气差段错误，运气最差什么都不发生（静默 UB）*/
```

**对比 C++ 版**：C++ 的 `std::thread` 忘 join 直接 `std::terminate` **当场爆炸**——用崩溃逼你改；C 的 pthread 忘 join **连一声都不吭**。这就是为什么 C 的线程纪律必须更严：**每个 pthread_create 必须有配对的 pthread_join（或深思熟虑的 detach），没有语言兜底**。

### Step 11.3 main 启动 server

🎯 实现"手动版 jthread"——pthread + `atomic_bool` 停止标志 + join 收尾。

> 📁 **归属文件**：`include/mkv/server.h` + `src/server.c`（**新建**）

```c
/* include/mkv/server.h */
#ifndef MKV_SERVER_H
#define MKV_SERVER_H

#include <pthread.h>
#include <stdatomic.h>
#include <stdbool.h>
#include "mkv/store.h"

typedef struct {
    pthread_t     thread;
    mkv_store_t  *store;        /* 借用：生命周期由 main 的收尾顺序保证 */
    atomic_bool   stop;         /* ⭐ 协作式停止标志（C 版 stop_token）*/
    bool          started;
} mkv_server_t;

bool server_start(mkv_server_t *sv, mkv_store_t *store);
void server_stop(mkv_server_t *sv);     /* 置 stop + join：必须调！*/

#endif
```

```c
/* src/server.c */
#include "mkv/server.h"
#include "mkv/log.h"
#include <unistd.h>

static void *purger_main(void *arg) {
    mkv_server_t *sv = arg;
    KV_LOG_INFO("ttl purger thread started");
    while (!atomic_load(&sv->stop)) {           /* ⭐ 协作式停止 */
        usleep(100 * 1000);                     /* 每 100ms 巡一次 */
        store_purge_expired(sv->store);         /* 内部自己拿写锁 */
    }
    KV_LOG_INFO("ttl purger thread stopped");
    return NULL;
}

bool server_start(mkv_server_t *sv, mkv_store_t *store) {
    sv->store = store;
    atomic_init(&sv->stop, false);
    sv->started = pthread_create(&sv->thread, NULL, purger_main, sv) == 0;
    return sv->started;
}

void server_stop(mkv_server_t *sv) {
    if (!sv->started) return;
    atomic_store(&sv->stop, true);              /* 先说"停下" */
    pthread_join(sv->thread, NULL);             /* 再等它走完 */
    sv->started = false;
}
```

**main 的收尾顺序（C 版的"析构顺序"设计）**：

```c
mkv_store_t store;  store_init(&store);       /* ① 先建：aof 和 server 都要它 */
aof_writer_t aof;    aof_writer_open(&aof, "data/aof.log");   /* ② 再开文件 */
mkv_server_t server; server_start(&server, &store);           /* ③ 最后启动线程 */

/* …REPL 循环… */

server_stop(&server);      /* ⭐ 手动逆序收尾：先停线程（不再摸 store），*/
aof_writer_close(&aof);    /*   再关文件（最后一批 flush），             */
store_destroy(&store);     /*   最后销毁数据                            */
```

**顺序不能颠倒**——先 `store_destroy` 而 purger 还在跑，就是 Step 11.2 的死法。C++ 靠"栈对象逆序析构"自动保证；**C 里这三行的顺序完全靠你手动排**——顺序就是设计。

**✅ 验证**：能回答——① 三个 stop/close/destroy 为什么这个顺序；② `server_start` 为什么是绑指针而不是拷贝 store（拷贝 = §4.4 浅拷贝陷阱）；③ 100ms usleep 的停止延迟怎么改进（生产用 `pthread_cond_timedwait` 精确唤醒，挑战题）。

```c
/* tests/stress.c */
#include <pthread.h>
#include <stdio.h>
#include <time.h>

#include "mkv/store.h"

#define N_THREADS 8
#define N_OPS     100000

static mkv_store_t g_store;

static void *worker(void *arg) {
    long id = (long)arg;
    char key[16];
    mkv_value_t v;
    for (int j = 0; j < N_OPS; j++) {
        snprintf(key, sizeof key, "k%d", j % 100);
        store_set(&g_store, key, mkv_int(id));       /* 写 */
        if (store_get(&g_store, key, &v)) mkv_value_free(&v);   /* 读 */
    }
    return NULL;
}

int main(void) {
    store_init(&g_store);
    pthread_t ths[N_THREADS];

    struct timespec t0, t1;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    for (long i = 0; i < N_THREADS; i++)
        pthread_create(&ths[i], NULL, worker, (void *)i);
    for (int i = 0; i < N_THREADS; i++)
        pthread_join(ths[i], NULL);
    clock_gettime(CLOCK_MONOTONIC, &t1);

    double ms = (t1.tv_sec - t0.tv_sec) * 1000.0 + (t1.tv_nsec - t0.tv_nsec) / 1e6;
    printf("%d ops in %.0f ms = %.0f ops/s\n",
           N_THREADS * N_OPS * 2, ms, N_THREADS * N_OPS * 2.0 / ms * 1000);
    printf("final size = %zu\n", store_size(&g_store));
    store_destroy(&g_store);
    return 0;
}
```

```text
final size = 100
```

## 14.技术思考

### 14.1 命令模式优于 if-else

if-else 不是"丑"，而是**违反开闭原则**：每加命令改主循环，每改主循环全部命令回归测试。命令模式把"加新命令"和"改主流程"**正交化**。更深的好处：**命令对象可以被存起来**——`MULTI/EXEC` 事务（攒 N 个命令一起执行）、命令审计日志、命令回放（AOF 就是），if-else 风格根本做不到。

> 💡 **C 版的加分思考**：① 给 `cmd_base_t` 加第四个函数指针 `destroy`，让每命令自己释放自己（替代 §05 的按 name 判断）；② 把每实例的函数指针抽成每命令一张 `static const` 操作表（实例只存表指针，省 24 字节/实例）——**这两步做完，你就手写了完整的 C++ vtable + 虚析构**。

### 14.2 AOF 的 fsync 策略

本案例每次写后 `fflush`——但 fflush 只把数据从 stdio 缓冲推到**内核 page cache**，整机断电仍丢最后几秒。真落盘要 `fsync(fd)`：`always`（最安全极慢）/ `everysec`（Redis 默认，最坏丢 1 秒）/ `no`（最快）。C 里要 `open()` 拿 fd 再 `fsync(fd)`，`FILE*` 可以用 `fileno()` 转换——挑战二会用到。

### 14.3 C 的手动 jthread

| 维度 | C++ `jthread` | 本案例 pthread + atomic_bool |
|------|---------------|------------------------------|
| 忘 join | terminate 当场炸（逼你改）| **静默悬垂 UB（埋雷）** |
| 协作停止 | 内置 `stop_token` | 手写 `atomic_bool stop` |
| 自动收尾 | 析构自动 stop+join | 手动 `server_stop` 三行纪律 |

**结论**：C++ 的进化方向是"让正确写法成为默认写法"；C 程序师的等价物是**把纪律写进肌肉记忆**——`pthread_create` 必有 `pthread_join`，资源 open 必有 close，malloc 必有 free。本章三个收尾函数的顺序（server_stop → aof_close → store_destroy）就是 C 版的"RAII"。

### 14.4 KV 单线程多线程

Redis 是单线程（指命令执行）：KV 瓶颈在网络和内存不在 CPU；单线程零锁开销无竞态；多机扩展靠水平分片。我们做多线程是**教学目标**（练 pthread/rwlock），不是性能最优。真要做高性能 KV，学单线程 + epoll + 协程的组合。

## 15.衔接与延伸

### 15.1 与上一案例衔接

**05.订单票务** 教你"用 mutex/rwlock/atomic 保证多线程安全"，**06.MiniKV** 在这之上加 AOF 持久化 + 后台定时任务 + 命令模式。两案例的并发原语一脉相承：05 的 `goto unlock` → 06 的锁收尾纪律；05 的 rwlock 实验 → 06 的读写分类锁；05 的线程池 → 06 的 purger 是"单后台线程"的极简形态。

**04.JSON 案例** 的 `json_value_t`（tagged union）与本章 `mkv_value_t` 一脉相承——你甚至可以直接给 MiniKV 加 `JSET key json_string` 命令，把 JSON 字符串 parse 成 `json_value_t` 存进 Value 的字符串位，`JGET key path` 按 JSON Path 取值。

### 15.2 三个延伸挑战

**挑战一（★★★）：加 List 类型 + LPUSH/LRANGE**
- `mkv_value_t` 的 union 加 `struct { char **items; size_t len, cap; } list;`（新枚举 `MKV_LIST`）；
- 新增 `lpush_cmd_t` / `lrange_cmd_t`（基类嵌入同款）；
- AOF 重放路径**完全不用改**——这就是命令模式的好处。

**挑战二（★★★★）：实现 AOF Rewrite**
- 现状：AOF 只增不减，跑久膨胀；
- 实现：定时把内存状态 dump 成"等价但更短的命令序列"写临时文件，`rename()` 原子替换旧 AOF（POSIX rename 的原子性）；
- 关键：rewrite 期间新写命令照常追加到旧文件，最后合并。

**挑战三（★★★★★）：网络化 + RESP 协议**
- 用 POSIX socket（`socket/bind/listen/accept`）让 MiniKV 监听 6379；
- 实现 RESP 协议 parser（`*2\r\n$3\r\nGET\r\n...`）；
- 用 `redis-cli` 直连你的 MiniKV，看到 `PING` 返回 `PONG` 那一刻，你已经做出"协议级兼容 Redis 的服务器"了。
