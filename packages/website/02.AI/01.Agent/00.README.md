## 文章详细设计

### 第 1 篇：Agent 全景认知 —— LLM 如何从"聊天"走向"干活"

**概念篇**
- Agent 的定义与核心公式：`Agent = LLM + Planning + Memory + Tools`
- Agent vs RAG vs Workflow vs Chatbot 的本质区别
- 为什么 2025 是 Agent 元年：从 Copilot 到 Autopilot 的范式转移
- Agent 的三种架构模式：Router / Tool-Use / Multi-Agent

**实战篇**
- 用 `openai` SDK 体验一次完整 Agent 调用循环（手动 ReAct 循环，不依赖框架）
- 拆解一次 `Thought → Action → Observation → Final Answer` 的完整过程

**思考篇**
- 什么时候该用 Agent，什么时候一个简单的 Chain 就够了
- Agent 开发的三大挑战：幻觉放大、成本爆炸、可控性下降

### 第 2 篇：手写第一个 Agent —— 10 行代码跑通 Tool Calling

**概念篇**
- Function Calling 的原理：从 Prompt 注入到结构化输出的演进
- Tool Schema 设计：JSON Schema 规范与描述词的艺术
- OpenAI / Anthropic / 开源模型对 Tool Calling 的实现差异

**实战篇**
- 纯 Python 手写一个 `搜索 + 计算器 + 天气查询` 的 Agent（不依赖框架，约 80 行）
- 工具返回结果如何回传给 LLM 继续推理
- 处理工具调用失败的优雅降级

**思考篇**
- Tool 粒度怎么定？一个万能 Tool vs 多个原子 Tool
- Safety：Agent 操作数据库/文件系统时的沙箱策略

---

### 第 3 篇：Agent 记忆系统 —— 短期、长期与工作记忆的工程实现

**概念篇**
- 三种记忆的类比：短期记忆=对话上下文 / 长期记忆=向量数据库 / 工作记忆=执行状态
- 上下文窗口的"注意力衰减"问题与滑动窗口策略
- 记忆压缩的三种方案：摘要、关键帧、分层记忆

**实战篇**
- 实现一个带记忆的客服 Agent：
  - 短期记忆：`messages` 列表管理 + Token 预算控制
  - 长期记忆：ChromaDB 存储用户历史对话 + 检索增强
  - 工作记忆：一个 `TaskState` 对象追踪当前任务进度
- 对比：有无记忆的 Agent 对话质量差异

**思考篇**
- 记忆≠上下文塞满，什么时候该"遗忘"
- OpenAI Assistants API 的 Thread 机制 vs 自建记忆的成本对比

---

### 第 4 篇：Agent 的工具生态 —— 从 API 调用到浏览器操控

**概念篇**
- Tool 的分类：API 工具 / 代码执行器 / UI 操控 / 文件操作 / 数据库查询
- 从 Function Calling 到 MCP：工具标准化的演进
- 工具注册、发现、调用的完整生命周期

**实战篇**
- 给 Agent 装上三把"瑞士军刀"：
  - `PythonREPLTool`：让 Agent 自己写代码算数学
  - `ShellTool`：让 Agent 操作文件系统
  - `TavilySearch`：联网搜索
- 实现一个"数据分析 Agent"：读取 CSV → 写 Python 分析 → 生成报告

**思考篇**
- 工具调用的 Token 成本黑洞如何控制
- 如何防止 Agent 的"工具滥用"（无限循环调用）

### 第 5 篇：LangChain + LangGraph —— 用图编排告别"面条式"Agent

**概念篇**
- LangChain 解决了什么：统一 Tool/Model/Prompt 的抽象层
- 为什么需要 LangGraph：链式调用的局限性
- 图编排核心概念：State、Node、Edge、Conditional Edge、Checkpoint

**实战篇**
- 用 LangGraph 重构第 4 篇的数据分析 Agent：
  ```
  读取CSV → 理解需求 → 写代码 → 执行 → 结果分析 → 生成报告
     ↑                                    │
     └──────── 如果有错误就重试 ────────────┘
  ```
- 对比：LangChain Chain vs LangGraph 的可读性和可维护性

**思考篇**
- LangGraph vs 传统工作流引擎（Temporal/Airflow）的定位差异
- Human-in-the-loop：在关键节点插入人工审批

### 第 6 篇：Agent 的规划与推理 —— ReAct、CoT、Plan-Execute 怎么选

**概念篇**
- 四种推理策略的深度对比：
  - **ReAct**：思考-行动交替，适合探索型任务
  - **CoT**：先想清楚再动手，适合复杂推理
  - **Plan-and-Execute**：先规划再执行，适合多步骤任务
  - **ReWOO**：把推理和工具调用解耦，省 Token
- 什么时候 LLM 自己就能规划，什么时候需要外部 planner

**实战篇**
- 同一个需求 —— "帮我调研三个竞品并输出对比报告" —— 用三种策略实现：
  - ReAct 版本：边搜边想
  - Plan-Execute 版本：先拆子任务再批量执行
  - 对比 Token 消耗和结果质量

**思考篇**
- 推理策略对模型能力的高度依赖：GPT-4 vs 开源模型的规划能力差距
- 反思机制（Reflection / Self-Critique）能让 Agent 自我纠错吗

---

### 第 7 篇：RAG + Agent 混合架构 —— 让 Agent 拥有"知识外脑"

**概念篇**
- 为什么 RAG 和 Agent 要结合：纯 RAG 不会推理，纯 Agent 没有私有知识
- 三种混合架构：Agent-in-the-Loop / RAG-as-Tool / 双引擎
- 向量检索 vs 图谱检索 vs 混合检索的取舍

**实战篇**
- 构建一个"技术文档问答 Agent"：
  - 用 LangChain 的 `VectorStoreTool` 连接私有文档
  - Agent 自主判断：问题需要检索文档还是直接回答
  - 多文档来源的融合：GitHub Wiki + Confluence + PDF
- 对比：加了 RAG 的 Agent vs 纯 RAG 的回答准确率

**思考篇**
- 检索质量如何影响 Agent 的幻觉率
- Agentic RAG 的典型落地场景：客服、代码库问答、法规查询

---

### 第 8 篇：多 Agent 协作 —— 让两个 Agent 互相对话

**概念篇**
- 多 Agent 系统的四种协作模式：
  - 顺序流水线（Pipeline）
  - 辩论模式（Debate）
  - 层级调度（Hierarchical）
  - 自由协作（Swarm）
- 用 CrewAI 对比：Role-based vs Conversation-based 的优劣

**实战篇**
- 用 CrewAI 搭建一个"内容创作团队"：
  ```
  研究员 Agent → 撰稿人 Agent → 审核员 Agent → 发布员 Agent
       ↓               ↓              ↓              ↓
   搜集素材        写初稿         质量审查       格式+发布
  ```
- 用 AutoGen 实现同一个场景，对比 API 设计

**思考篇**
- 多 Agent 的"沟通税"：Token 消耗指数级增长
- 什么时候该用多 Agent，什么时候一个 Agent 就够了

---

### 第 9 篇：MCP 协议 —— Agent 工具生态的"USB 接口"

**概念篇**
- MCP（Model Context Protocol）解决了什么问题：工具的标准化与复用
- MCP 架构：Client ↔ Server 的 JSON-RPC 通信
- MCP vs A2A（Google Agent-to-Agent）：两种互联互通的路线之争

**实战篇**
- 用 Python SDK 写一个 MCP Server：暴露数据库查询 + 文件操作
- 接入现成的 MCP Server：Brave Search、GitHub、Postgres
- Claude Desktop 配置 MCP，体验即插即用

**思考篇**
- MCP 的安全边界：谁能调用，能调什么
- MCP 生态现状：有哪些成熟 Server 可以直接用

---

### 第 10 篇：Agent 评测与可观测性 —— 你的 Agent 到底靠不靠谱

**概念篇**
- Agent 评测为什么比 LLM 评测难：多步骤、有状态、工具调用
- 评测指标体系：任务完成率 / 工具调用准确率 / 平均步数 / Token 成本
- 可观测性三支柱：Traces（追踪）、Metrics（指标）、Logs（日志）

**实战篇**
- 搭建评测流水线：
  - 用 LangSmith / Opik 追踪 Agent 的每一步决策
  - 设计 50 条测试用例，对比 Agent 预期行为 vs 实际行为
  - 用 `promptfoo` 做自动化回归测试
- 可视化 Agent 的"决策树"：每一步 Thought/Action/Observation

**思考篇**
- 评测自动化 vs 人工评审的取舍
- Agent 的"过度自信"问题：如何检测 Agent 在瞎编

---

### 第 11 篇：Agent 生产化部署 —— 从 Demo 到线上服务

**概念篇**
- 生产级 Agent 的核心挑战：流式输出、并发、超时、重试、安全
- 架构选型：FastAPI + Async vs LangServe vs 直接部署
- 流式输出的三种方案：SSE、WebSocket、chunked response

**实战篇**
- 将第 7 篇的文档问答 Agent 部署为 API 服务：
  - FastAPI 异步封装 + 流式 SSE 推送
  - Token 预算控制 + 超时熔断
  - Docker 容器化 + docker-compose 一键启动
- 压测：100 并发下 Agent 的表现和瓶颈

**思考篇**
- Agent 的"思考时间"如何影响用户体验（用户等待 vs 后台异步）
- LLM API 的限流和成本控制策略

---

### 第 12 篇：Agent 架构演进与未来 —— 综合实战 + 趋势展望

**概念篇**
- 回顾 12 篇文章的知识地图
- Agent 架构设计的决策树：选模型 → 选框架 → 定工具 → 加记忆 → 做评测 → 部署
- 2025-2027 Agent 技术趋势

**实战篇**
- 端到端项目：一个能帮你管理日程、写日报、搜资料的 Agent
  - **能力**：日历查询 + 邮件草拟 + 搜索 + Markdown 日报生成
  - **架构**：LangGraph 编排 + ChromaDB 记忆 + MCP 工具箱
  - **部署**：Docker 部署 + 钉钉/飞书 Webhook 接入
- 完整源码 + 部署文档

**思考篇**
- 从这个小项目出发，还能扩展什么（代码审查、自动发布、数据监控）
- Agent 开发的"第一性原理"：所有复杂 Agent 都是简单 Agent 的组合
