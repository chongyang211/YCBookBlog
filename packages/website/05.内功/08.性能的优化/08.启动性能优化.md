# 8.启动性能优化

> 📍 **本篇位置**：第 8 卷 · 性能的优化之道 · 第 8 篇（综合场景 · 启动）
> 🎯 **核心矛盾**：**启动是所有性能的综合题**——类加载、链接、I/O、渲染、网络全部在抢同一段时间；而且启动没有"稳态"，每一毫秒都是一次性消费、每一次打开都重新算账。
> 📌 **综合案例投影（战役 8）**：YC 商城冷启动 3.2s，渠道监测启动流失率 18%。排段：Pre-main 600ms（dex/so 加载）+ Application 1.4s（30 个 SDK 串行 init）+ 首屏 800ms（3 个接口串行，承接战役 7）+ 字体 400ms。启动器并行 + Baseline Profiles + 接口预取 + 字体子集化 → **3.2s → 1.1s，流失 18% → 7%**；iOS / H5 同步专项。
> 🌐 **跨平台覆盖**：Android（Zygote/App Startup/Baseline Profiles）· iOS（dyld/Order File）· Web（Code Splitting/LCP）· 服务端 JVM（CDS/Native Image）· Flutter/RN（预编译/Isolate）
> 🔗 **延伸阅读**：← [8.7 网络传输性能优化](./07.网络传输性能优化.md) · → [8.9 包体与资源优化](./09.包体与资源优化.md)
> 🧠 **一句话心法**：**启动优化四板斧——删 / 延 / 并 / 预**。
