# 5.I_O与存储性能优化

> 📍 **本篇位置**：第 8 卷 · 性能的优化之道 · 第 5 篇（六大维度 · I/O）
> 🎯 **核心矛盾**：从寄存器 1ns 到 HDD 10ms，**存储延迟跨 7 个数量级**；但代码里的 `read` 看上去都一样——不懂物理的优化都是蒙的。
> 📌 **综合案例投影（战役 5）**：YC 商城大促预演 2 小时后，订单库写 TPS 从 50 万跌到 5 万，CPU/网络正常——iostat 看到 `await` 2ms → 80ms，blktrace 定位**审计日志每次 write 都 fsync**。攒批 fsync + 慢查询治理后 TPS 恢复 48 万并 +30%；移动端同步把 SharedPreferences 全量写迁到 MMKV。
> 🌐 **跨平台覆盖**：Linux 服务端（iostat/blktrace/eBPF）· Android（SharedPreferences/MMKV/Perfetto）· iOS（APFS/Core Data/Instruments）· Web（缓存/IndexedDB）· DB（MySQL/PG/SQLite）
> 🔗 **延伸阅读**：← [8.4 线程调度与并发性能优化](./04.线程调度与并发性能优化.md) · → [8.6 渲染与帧率卡顿优化](./06.渲染与帧率卡顿优化.md)
> 🧠 **一句话心法**：**所有 I/O 优化 = 更少 syscall + 更顺序访问 + 更合适缓冲 + 更批量刷盘**。
