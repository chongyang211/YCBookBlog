# 7.网络传输性能优化

> 📍 **本篇位置**：第 8 卷 · 性能的优化之道 · 第 7 篇（六大维度 · 网络）
> 🎯 **核心矛盾**：**延迟 ≠ 带宽**——一次首屏 800ms 里，真正"算"的时间可能只有 50ms，剩下 750ms 都在 DNS / TCP / TLS / RTT / 排队 / 重传。
> 📌 **综合案例投影（战役 7）**：YC 商城首屏 2.3s，服务端 RT 只占 80ms——瀑布图：DNS 400ms（运营商劫持 + 未用 HTTPDNS）+ TCP 200ms + TLS 300ms + **串行 3 个接口** 1.2s。预连接 + HTTPDNS + 合并请求 + 离线包四板斧 → **首屏 2.3s → 600ms，转化 +18%**；弱网专项超时率 15% → 2%。
> 🌐 **跨平台覆盖**：Android（OkHttp/Cronet/HTTPDNS）· iOS（URLSession/ATS）· Web（浏览器预连接/Service Worker）· 服务端（内网 RPC/连接池/超时传递）
> 🔗 **延伸阅读**：← [8.6 渲染与帧率卡顿优化](./06.渲染与帧率卡顿优化.md) · → [8.8 启动性能优化](./08.启动性能优化.md)
> 🧠 **一句话心法**：**优化带宽不如优化 RTT 数**。
