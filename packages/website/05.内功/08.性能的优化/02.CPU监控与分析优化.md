# 2.CPU监控与分析优化

> 📍 **本篇位置**：第 8 卷 · 性能的优化之道 · 第 2 篇（六大维度 · CPU）
> 🎯 **核心矛盾**：**高 CPU ≠ 慢，低 CPU 也不一定快**。真正要回答的是——CPU 时间花在哪、哪个函数吃掉它、它是不是在真的"算"。
> 📌 **综合案例投影（战役 2）**：YC 商城大促预演，网关 CPU 95% 告警，扩容 3 倍无效。top 看 user 99%，Async Profiler 定位 `ConcurrentHashMap.get` 占 65%——根因是**促销价目表的 key 没重写 hashCode，哈希碰撞链表化**。修 1 行，CPU 95% → 32%，缩容回原规模。
> 🌐 **跨平台覆盖**：服务端 JVM（Async Profiler/JFR/perf）· Go（pprof）· Node（--prof/V8）· Android（Perfetto/simpleperf）· iOS（Instruments）
> 🔗 **延伸阅读**：← [8.1 性能优化方法论与度量](./01.性能优化方法论与度量.md) · → [8.3 内存监控与治理](./03.内存监控与治理.md)
> 🧠 **一句话心法**：**CPU 100% 不是答案，是开始**。
> 🚧 **文档状态**：按 `00.大纲规划.md` 建立的**结构骨架**，大节与写作要点已就位，正文待逐节填充。
