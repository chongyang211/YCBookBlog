# 9.包体与资源优化

> 📍 **本篇位置**：第 8 卷 · 性能的优化之道 · 第 9 篇（综合场景 · 包体）
> 🎯 **核心矛盾**：**冗余四根源**——代码冗余、资源冗余、依赖冗余、元数据冗余；但 90% 的"减包大会"只盯着资源，错过真正的大头。
> 📌 **综合案例投影（战役 9）**：YC 商城 APK 80MB，渠道下载转化连续 3 个月下滑。常规减图减到 72MB 就停滞——换方法：**R8 全量混淆 + 依赖替换（3 个全家桶 → 自实现）+ 字体子集化（10MB → 200KB）+ ABI 拆分 + Dynamic Feature（营销插件按需下发）**，一月降到 **55MB（下载转化 +23%，低端机崩溃 -40%）**；H5 主 bundle 2.3MB → 480KB。
> 🌐 **跨平台覆盖**：Android（R8/APK Analyzer/App Bundle）· iOS（App Thinning/Bitcode）· Web（Tree Shaking/代码分割）· Flutter（--analyze-size）· RN（Hermes 字节码）
> 🔗 **延伸阅读**：← [8.8 启动性能优化](./08.启动性能优化.md) · → [8.10 性能工程化与防劣化](./10.性能工程化与防劣化.md)
> 🧠 **一句话心法**：**代码靠编译器、资源靠流程、依赖靠纪律、元数据靠平台**。
> 🚧 **文档状态**：按 `00.大纲规划.md` 建立的**结构骨架**，大节与写作要点已就位，正文待逐节填充。

## 01.开篇灵魂拷问

> 📝 待填充：1.1「减图已经减到底了」——资源天花板之惑；1.2「Tree Shaking 开了为什么没减」——动态性之惑；1.3「APK 装到设备怎么又变大」——安装大小之惑。

## 02.包体的四根源模型

> 📝 待填充：① 代码（主代码 + 库 + 泛型膨胀）② 资源（图片 / 字体 / 音视频 / 多语言）③ 依赖（间接依赖 / 全家桶 / 重复符号）④ 元数据（符号表 / 调试信息 / Bitcode / 清单）；2.1 YC 实测占比（资源 55% + 代码 25% + 依赖 15% + 元数据 5%）；2.2 包体大小 vs 安装大小 vs 下载大小；2.3 面试锚点「包体优化方向」。

## 03.包体识图

> 📝 待填充：3.1 Android APK Analyzer 分段与版本对比；3.2 iOS Linkmap 分析 `.o` 占比；3.3 Web webpack-bundle-analyzer / rollup-plugin-visualizer；3.4 Flutter `--analyze-size`；3.5 典型包体画像（资源型 / 代码型 / 依赖型）。

## 04.代码与资源优化

## 05.跨平台对照
