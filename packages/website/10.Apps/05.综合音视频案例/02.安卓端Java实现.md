# 第二章：MiniPlayer · Android 端实现（Java + AndroidX）

> **前置阅读**：[00.总览](/pages/miniplayer5/)、[01.架构设计与五端对照](/pages/mp5arch/)。本文假设你已了解五层架构、PlayerState 状态机与接口契约。
>
> **本文定位**：本篇是 MiniPlayer 的 **Android 原生实现**——XML + Activity/Fragment + ViewBinding + ExoPlayer(Media3) + Room + ForegroundService + MediaSession。读完本篇你会掌握：**（1）MediaStore 扫描与运行时权限的版本分叉**；**（2）ExoPlayer 的 Playlist API 与状态回调体系**；**（3）后台播放三件套（ForegroundService + MediaSession + MediaStyle 通知）**；**（4）音频焦点与线控**——这些正是 Android 平台"母语级"开发的核心考点。
>
> **与 Web 篇 / Qt 篇 / Electron 篇的关系**：五端共享同一套 PlayerState 状态机与接口契约（[01.架构设计 §1.4/§1.5](/pages/mp5arch/)）。Android 端的"平台物理约束"最典型——生命周期被系统随时打断、后台执行被严格限制、权限模型三代同堂。学会 Android 端的这些约束处理，你会真正理解"为什么移动端和桌面端的架构决策完全不同"。

## 01.本端选型说明

### 1.1 为什么选 ExoPlayer 不选 MediaPlayer

| 对比项 | MediaPlayer | ExoPlayer (Media3) |
|-------|-------------|-------------------|
| 视频支持 | 需自己接 SurfaceView | PlayerView 开箱即用 |
| 播放列表 | 无，需自己管理 | Playlist API 原生支持 |
| 状态回调 | 简陋，易泄漏 | Listener 体系完整 |
| 倍速 | 6.0+，精度差 | `PlaybackParameters` 精细 |
| HTTP/HLS | 手动 | 内置 |
| 后台结合 | 需自己接 MediaSession | MediaSession 集成成熟 |
| 内存泄漏 | `setDataSource` 抛异常后必须 reset | Builder 模式 + `release()` 一条路 |

教学上两者都会碰：§02 MVP 用 `MediaPlayer` 20 行跑通（感受原始 API 的脆弱），§04 重构换 `ExoPlayer`（感受工程化收益），这个"**先丑后好**"的过程正是 Android 进阶要体会的。

> **为什么用 Media3 而不是老的 ExoPlayer 2.x？** 2022 年后 ExoPlayer 并入 AndroidX Media3（`androidx.media3` 包名），老包名 `com.google.android.exoplayer2` 已停止演进。Media3 的 `MediaItem`/`Player` 接口设计更干净，且与 `MediaSessionService` 无缝集成。**新工程一律用 Media3**。

### 1.2 UI 栈选型

- **XML + Activity/Fragment + ViewBinding**：与"Android 提升进阶"卷调性一致，纯 Java 全程可用；
- RecyclerView + ListAdapter + DiffUtil 做列表；ViewModel + LiveData 做状态；
- **不引入 Compose**（需 Kotlin，超出本端语言设定）——但会在 §11 挑战题给 Compose 迁移路线。

### 1.3 状态管理：LiveData 而不是 StateFlow

本端用 `LiveData<PlayerState>`（对照架构篇 §1.4 五端状态广播表）。理由：

1. 纯 Java 下 LiveData 的用法最简（StateFlow 需要 Kotlin 协程）；
2. LiveData **自动感知生命周期**——Activity 处于 STOPPED 时不会触发 UI 更新，这正是播放器场景需要的（后台时 UI 不刷，回前台一次性同步）；
3. 挑战题里会给 StateFlow 迁移对照。

### 1.4 与五端兄弟篇的对照速览

| 考点 | Android 篇 | Web 篇 | Qt 篇 | Electron 篇 |
|------|-----------|--------|-------|------------|
| 引擎 | ExoPlayer | `<audio>` + Web Audio | QMediaPlayer | Chromium `<audio>` |
| 状态广播 | LiveData + ViewModel | Pinia store | QObject 属性+信号 | Zustand + IPC |
| 后台 | ForegroundService + MediaSession | Page Visibility + Media Session API | MPRIS/MPNowPlaying/SMTC | 自写 C++ 共享库 |
| 扫描 | MediaStore | File System Access API | std::filesystem | Node fs |
| 持久化 | Room (SQLite) | Dexie (IndexedDB) | QSqlDatabase | better-sqlite3 |
| 权限 | 运行时（三代分叉） | 无 | 无 | 无 |

### Step 2.4 MediaPlayer 硬编码播放（20 行感受原始 API）

```java
// MainActivity.java —— MVP 版（后续 §03/§04 会大改）
package com.ycbook.miniplayer;

import android.media.MediaPlayer;
import android.os.Bundle;
import android.widget.Button;
import android.widget.TextView;
import androidx.appcompat.app.AppCompatActivity;
import com.ycbook.miniplayer.databinding.ActivityMainBinding;

public class MainActivity extends AppCompatActivity {

    private ActivityMainBinding binding;      // ⭐ ViewBinding：编译期生成，null 安全
    private MediaPlayer player;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        binding = ActivityMainBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        binding.btnToggle.setOnClickListener(v -> toggle());
    }

    private void toggle() {
        if (player == null) {
            // ⭐ MVP：硬编码 assets 路径。§03 会换成 MediaStore 扫描结果
            player = MediaPlayer.create(this, R.raw.demo);
            player.setOnCompletionListener(mp -> {
                binding.tvStatus.setText("COMPLETED");
                releasePlayer();
            });
            player.start();
            binding.tvStatus.setText("PLAYING");
        } else if (player.isPlaying()) {
            player.pause();
            binding.tvStatus.setText("PAUSED");
        } else {
            player.start();
            binding.tvStatus.setText("PLAYING");
        }
    }

    private void releasePlayer() {
        if (player != null) {
            player.release();     // ⭐ 不释放 → 每次旋转都泄漏一个 MediaPlayer
            player = null;
        }
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        releasePlayer();          // Activity 销毁 = 播放器销毁（MVP 阶段的等式）
    }
}
```

**四个细节**：

1. **`MediaPlayer.create()` 是便捷工厂**：内部做了 `setDataSource + prepare`（同步！主线程大文件会 ANR）。§04 换 ExoPlayer 后这个问题自动消失。
2. **`release()` 而不是 `stop()`**：stop 后还能 start，release 才真正回收 native 资源。
3. **旋转屏幕**：`onDestroy → onCreate` 走一遍，播放中断——这是 MVP 的已知局限，§04 用 ViewModel 解决。
4. **`R.raw.demo`**：把 mp3 放 `res/raw/` 目录即可。只是 MVP 临时方案。

### Step 3.1 `MediaItem` 实体（对照架构篇 §1.3）

```java
// data/MediaItem.java —— 对照架构篇 §1.3 的 MediaItem 定义
package com.ycbook.miniplayer.data;

import androidx.room.ColumnInfo;
import androidx.room.Entity;
import androidx.room.PrimaryKey;

@Entity(tableName = "media")
public class MediaItem {

    public enum MediaType { AUDIO, VIDEO }

    @PrimaryKey
    @NonNull
    public String id;              // 稳定主键：SHA1(uri + size + date_modified)

    @ColumnInfo(name = "type")
    public MediaType type;

    @NonNull
    public String uri;             // content:// MediaStore URI

    public String title;           // 元数据标题，缺省用 DISPLAY_NAME
    public String artist;
    public String album;
    public long durationMs;
    public int bitrateKbps;        // 0 表示未知
    public String coverPath;       // 提取出的封面缓存路径，null 占位

    public int rating;             // 0-5，0 未评分
    public long addedAt;
    public Long lastPlayedAt;      // null = 从未播放

```

**与四端兄弟的对照**（架构篇 §1.3 类型映射表的 Android 行落地）：

- `long` 主键 → **`String` id**：Java 的 long 够，但为了和 Web/Electron 的 string id 对齐，直接用 SHA1 hex；
- 空值 → **`Long`（包装类型）**：Java 的 `long` 不能为 null，`lastPlayedAt` 必须用包装类；
- URI 而非 path：**Android 10+ scoped storage 下只能拿 content:// URI**，直接 File 路径行不通。

### Step 3.2 扫描器：MediaStore 查询 vs 自扫描的取舍

**两条路线**：

| 维度 | MediaStore 查询 ⭐（本端采用） | 自扫描 /sdcard 目录 |
|------|---------------------------|-------------------|
| 权限 | READ_MEDIA_AUDIO/VIDEO（API 33+） | READ_EXTERNAL_STORAGE + MANAGE_EXTERNAL_STORAGE（商店拒审） |
| 性能 | 系统级索引，毫秒级 | 递归 IO，秒级 |
| 元数据 | TITLE/ARTIST/DURATION 自带（系统已解析） | 要自己 MediaMetadataRetriever 逐个读 |
| 实时性 | 依赖系统扫描广播 | 即时 |
| SD 卡/OTG | 自动覆盖 | 要自己处理 StorageVolume |

**结论**：**MediaStore 优先**。只有当用户指定"扫描某个文件夹"且该文件夹不被索引时，才走 `DocumentFile` 递归。本案例一期只做 MediaStore 路线。

```java
// data/MediaScanner.java（骨架，完整实现见配套工程）
package com.ycbook.miniplayer.data;

import android.content.ContentResolver;
import android.content.ContentUris;
import android.content.Context;
import android.net.Uri;
import android.provider.MediaStore;
import java.security.MessageClock;   // 占位：实际用 java.security.MessageDigest

public class MediaScanner {

    public interface ScanCallback {
        void onProgress(int scanned);
        void onDone(java.util.List<MediaItem> items);
    }

    private final Context context;

    public MediaScanner(Context context) { this.context = context; }

    public void scanAsync(ScanCallback cb) {
        // 后台线程执行（Step 3.6 讲线程模型）
        new Thread(() -> cb.onDone(queryMediaStore())).start();
    }

    private java.util.List<MediaItem> queryMediaStore() {
        java.util.List<MediaItem> out = new java.util.ArrayList<>();
        ContentResolver cr = context.getContentResolver();

        // ⭐ 音频 + 视频两次查询（MediaStore 的物理分表）
        out.addAll(queryKind(cr, MediaStore.Audio.Media.EXTERNAL_CONTENT_URI,
                MediaStore.Audio.Media.class, MediaItem.MediaType.AUDIO));
        out.addAll(queryKind(cr, MediaStore.Video.Media.EXTERNAL_CONTENT_URI,
                MediaStore.Video.Media.class, MediaItem.MediaType.VIDEO));
        return out;
    }

    private java.util.List<MediaItem> queryKind(ContentResolver cr, Uri collection,
                                                Class<?> unused, MediaItem.MediaType type) {
        java.util.List<MediaItem> out = new java.util.ArrayList<>();

        String[] projection = {
                MediaStore.MediaColumns._ID,
                MediaStore.MediaColumns.DISPLAY_NAME,      // 文件名（fallback title）
                MediaStore.MediaColumns.SIZE,
                MediaStore.MediaColumns.DATE_MODIFIED,
                MediaStore.MediaColumns.DURATION,          // API 29+，含 Q 兼容分叉
        };
        // 音频表额外列
        if (type == MediaItem.MediaType.AUDIO) {
            projection = new String[]{
                    MediaStore.MediaColumns._ID,
                    MediaStore.MediaColumns.DISPLAY_NAME,
                    MediaStore.MediaColumns.SIZE,
                    MediaStore.MediaColumns.DATE_MODIFIED,
                    MediaStore.MediaColumns.DURATION,
                    MediaStore.Audio.Media.TITLE,
                    MediaStore.Audio.Media.ARTIST,
                    MediaStore.Audio.Media.ALBUM,
            };
        }

        String selection = MediaStore.MediaColumns.DURATION + " >= ?";
        String[] args = { String.valueOf(10_000) };   // ⭐ 架构篇 ScanConfig.minDurationMs=10s
        String sortOrder = MediaStore.Audio.Media.TITLE + " ASC";

        try (android.database.Cursor c = cr.query(collection, projection, selection, args, sortOrder)) {
            if (c == null) return out;
            int idCol = c.getColumnIndexOrThrow(MediaStore.MediaColumns._ID);
            while (c.moveToNext()) {
                long id = c.getLong(idCol);
                Uri itemUri = ContentUris.withAppendedId(collection, id);

                MediaItem m = new MediaItem();
                m.type = type;
                m.uri = itemUri.toString();
                m.durationMs = type == MediaItem.MediaType.AUDIO
                        ? safeLong(c, MediaStore.Audio.Media.DURATION)
                        : safeLong(c, MediaStore.Video.Media.DURATION);
                // ... 其余字段填充，完整代码见配套工程
                m.id = stableId(itemUri, c);
                out.add(m);
            }
        }
        return out;
    }

    /** ⭐ 稳定 ID：SHA1(uri + size + mtime) —— 和 Qt/Web/Electron 端同一算法 */
    private String stableId(Uri uri, android.database.Cursor c) {
        try {
            java.security.MessageDigest md = java.security.MessageDigest.getInstance("SHA-1");
            md.update(uri.toString().getBytes());
            md.update(String.valueOf(safeLong(c, MediaStore.MediaColumns.SIZE)).getBytes());
            md.update(String.valueOf(safeLong(c, MediaStore.MediaColumns.DATE_MODIFIED)).getBytes());
            StringBuilder sb = new StringBuilder();
            for (byte b : md.digest()) sb.append(String.format("%02x", b));
            return sb.substring(0, 16).toString();
        } catch (Exception e) {
            return uri.toString();   // 降级：直接用 uri
        }
    }

    private long safeLong(android.database.Cursor c, String col) {
        int i = c.getColumnIndex(col);
        return i >= 0 && !c.isNull(i) ? c.getLong(i) : 0;
    }
}
```

**三个关键设计**：

1. **`DURATION >= 10000` 过滤**：架构篇 §1.3 ScanConfig 的 `minDurationMs`，直接在 SQL 层过滤掉录音碎片、微信语音等短音频。
2. **try-with-resources 关 Cursor**：老代码常见 `cursor.close()` 遗漏 → Lint 会警告，但 try-with-resources 才是防异常泄漏的正解。
3. **稳定 ID 与三端一致**：Qt 端 SHA1(path+size+mtime)、Web 端 SubtleCrypto、Electron 端 node:crypto——**同一个算法跨五端**，这是案例对照的基础设施。

### Step 3.3 运行时权限：三代分叉

Android 读写媒体库的权限模型经历了三代：

| 版本 | 读音频/视频 | 说明 |
|------|-----------|------|
| API ≤ 32 | `READ_EXTERNAL_STORAGE` | 读整个共享存储 |
| API 33+ | `READ_MEDIA_AUDIO` / `READ_MEDIA_VIDEO` / `READ_MEDIA_IMAGES` | 细粒度，互不影响 |
| API 34+ | 同上 + `READ_MEDIA_VISUAL_USER_SELECTED` | 用户可只授权部分照片（视频暂未生效） |

权限工具类：

```java
// ui/PermissionHelper.java
package com.ycbook.miniplayer.ui;

import android.Manifest;
import android.content.Context;
import android.content.pm.PackageManager;
import android.os.Build;
import androidx.core.content.ContextCompat;
import java.util.ArrayList;
import java.util.List;

public class PermissionHelper {

    /** 按系统版本返回需要申请的权限组 */
    public static String[] mediaReadPermissions() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {   // API 33+
            return new String[]{
                    Manifest.permission.READ_MEDIA_AUDIO,
                    Manifest.permission.READ_MEDIA_VIDEO,
            };
        }
        return new String[]{ Manifest.permission.READ_EXTERNAL_STORAGE };
    }

    public static boolean hasAll(Context ctx) {
        for (String p : mediaReadPermissions()) {
            if (ContextCompat.checkSelfPermission(ctx, p) != PackageManager.PERMISSION_GRANTED) {
                return false;
            }
        }
        return true;
    }

    /** 申请时 33+ 若部分授权（如只给了音频没给视频）也要能跑 */
    public static List<String> missing(Context ctx) {
        List<String> out = new ArrayList<>();
        for (String p : mediaReadPermissions()) {
            if (ContextCompat.checkSelfPermission(ctx, p) != PackageManager.PERMISSION_GRANTED) {
                out.add(p);
            }
        }
        return out;
    }
}
```

### Step 3.4 MediaMetadataRetriever 补齐元数据 + 封面

MediaStore 的 TITLE/ARTIST 依赖系统扫描时解析，**部分格式（FLAC 的 Vorbis Comment、部分 m4a）会缺失**。对缺失项用 Retriever 兜底：

```java
// data/MediaScanner.java 的补充方法
private void fillMetadataIfNeeded(Context ctx, MediaItem m) {
    boolean needTitle  = m.title == null || m.title.equals(m.fallbackName());
    boolean needArtist = m.artist == null || m.artist.startsWith("<unknown>");
    if (!needTitle && !needArtist && m.coverPath != null) return;

    android.media.MediaMetadataRetriever r = new android.media.MediaMetadataRetriever();
    try {
        r.setDataSource(ctx, android.net.Uri.parse(m.uri));     // ⭐ content URI 重载
        if (needTitle) {
            String t = r.extractMetadata(android.media.MediaMetadataRetriever.METADATA_KEY_TITLE);
            m.title = (t != null && !t.isEmpty()) ? t : m.fallbackName();
        }
        if (needArtist) {
            String a = r.extractMetadata(android.media.MediaMetadataRetriever.METADATA_KEY_ARTIST);
            m.artist = (a != null) ? a : "未知艺术家";
        }
        if (m.coverPath == null) {
            byte[] art = r.getEmbeddedPicture();      // 内嵌封面（APIC 帧）
            if (art != null && art.length > 0) {
                m.coverPath = saveCoverCache(ctx, m.id, art);
            }
        }
    } catch (Exception ignored) {
        // 单个文件解析失败不应中断整个扫描
    } finally {
        r.release();      // ⭐⭐ 不 release = fd 泄漏，扫 1000 首歌直接崩
    }
}

private String saveCoverCache(Context ctx, String id, byte[] png) {
    try {
        java.io.File dir = new java.io.File(ctx.getCacheDir(), "covers");
        dir.mkdirs();
        java.io.File f = new java.io.File(dir, id + ".jpg");
        try (java.io.FileOutputStream os = new java.io.FileOutputStream(f)) {
            os.write(png);
        }
        return f.getAbsolutePath();
    } catch (Exception e) {
        return null;
    }
}
```

**为什么 finally 里 release？** `setDataSource` 对损坏文件会抛 RuntimeException，如果 release 写在 try 尾部就永远执行不到。**fd 泄漏是本端第一大资源坑**——扫几百首后 `ls /proc/<pid>/fd` 会看到几百个未关闭句柄。

### Step 3.5 RecyclerView + ListAdapter + DiffUtil

用 `ListAdapter`（自带后台 diff 的 RecyclerView.Adapter）：

```java
// ui/MediaListAdapter.java

import android.view.LayoutInflater;
import android.view.ViewGroup;
import androidx.annotation.NonNull;
import androidx.recyclerview.widget.DiffUtil;
import androidx.recyclerview.widget.ListAdapter;
import androidx.recyclerview.widget.RecyclerView;
import com.ycbook.miniplayer.data.MediaItem;
import com.ycbook.miniplayer.databinding.ItemMediaBinding;

public class MediaListAdapter extends ListAdapter<MediaItem, MediaListAdapter.VH> {

    public interface OnItemClick { void onClick(MediaItem item, int position); }

    private final OnItemClick listener;

    public MediaListAdapter(OnItemClick listener) {
        super(new DiffUtil.ItemCallback<MediaItem>() {
            @Override public boolean areItemsTheSame(@NonNull MediaItem a, @NonNull MediaItem b) {
                return a.id.equals(b.id);                    // ⭐ 稳定 ID 的价值就在这
            }
            @Override public boolean areContentsTheSame(@NonNull MediaItem a, @NonNull MediaItem b) {
                return a.title.equals(b.title)
                    && a.durationMs == b.durationMs
                    && a.lastPlayedAt == b.lastPlayedAt;
            }
        });
        this.listener = listener;
    }

    @NonNull @Override
    public VH onCreateViewHolder(@NonNull ViewGroup parent, int viewType) {
        return new VH(ItemMediaBinding.inflate(
                LayoutInflater.from(parent.getContext()), parent, false));
    }

    @Override
    public void onBindViewHolder(@NonNull VH h, int position) {
        MediaItem m = getItem(position);
        h.binding.tvTitle.setText(m.title);
        h.binding.tvArtist.setText(m.artist != null ? m.artist : "未知艺术家");
        h.binding.tvDuration.setText(formatMs(m.durationMs));
        h.itemView.setOnClickListener(v -> listener.onClick(m, position));
    }

    static String formatMs(long ms) {
        long s = ms / 1000;
        return String.format("%d:%02d", s / 60, s % 60);
    }

    static class VH extends RecyclerView.ViewHolder {
        final ItemMediaBinding binding;
        VH(ItemMediaBinding b) { super(b.getRoot()); binding = b; }
    }
}
```

**ListAdapter vs 普通 Adapter**：`submitList()` 内部自动走 DiffUtil，**在后台线程 diff、主线程只 notify 增量**。扫描完成刷新 2000 条时普通 `notifyDataSetChanged()` 会整列表闪烁，ListAdapter 丝滑。

### Step 3.6 扫描线程模型

```java
// ui/MainViewModel.java（§03 阶段版，§04 会扩展 PlayerState）
package com.ycbook.miniplayer.ui;

import android.app.Application;
import androidx.annotation.NonNull;
import androidx.lifecycle.AndroidViewModel;
import androidx.lifecycle.LiveData;
import androidx.lifecycle.MutableLiveData;
import com.ycbook.miniplayer.data.MediaItem;
import com.ycbook.miniplayer.data.MediaScanner;
import java.util.List;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class MainViewModel extends AndroidViewModel {

    private final ExecutorService io = Executors.newSingleThreadExecutor();
    private final MutableLiveData<List<MediaItem>> library = new MutableLiveData<>();
    private final MutableLiveData<Boolean> scanning = new MutableLiveData<>(false);
    private final MediaScanner scanner;

    public MainViewModel(@NonNull Application app) {
        super(app);
        scanner = new MediaScanner(app);
    }

    public LiveData<List<MediaItem>> getLibrary() { return library; }
    public LiveData<Boolean> getScanning()       { return scanning; }

    public void refreshLibrary() {
        scanning.setValue(true);
        io.execute(() -> {                     // ⭐ 后台线程，绝不碰 UI
            List<MediaItem> items = scanner.scanSync();
            // postValue：后台线程往主线程 LiveData 投递
            library.postValue(items);
            scanning.postValue(false);
        });
    }

    @Override
    protected void onCleared() {
        io.shutdown();     // ViewModel 销毁 = 扫描线程关闭
        super.onCleared();
    }
}
```

**架构铁律**（对照架构篇 §1.2"三条铁律"）：扫描和 DB 一律后台线程；`setValue` 只能主线程调、`postValue` 任何线程可调；ViewModel 永远不持有 Activity 引用。

### Step 4.1 PlayerState：五端共享的状态九元组

对照 [架构篇 §1.4](/pages/mp5arch/) 的 PlayerState 定义，Android 落地为不可变类：

```java
// service/PlayerState.java
package com.ycbook.miniplayer.service;

import com.ycbook.miniplayer.data.MediaItem;

/** 不可变状态对象 —— 每次变化都 new 一个（对照架构篇 §1.4 九元组） */
public class PlayerState {

    public enum State { IDLE, PREPARING, PLAYING, PAUSED, ERROR }
    public enum PlayMode { SEQUENCE, REPEAT_ONE, SHUFFLE }

    public final State state;
    public final MediaItem currentMedia;        // null = 无
    public final long positionMs;
    public final long durationMs;
    public final float speed;                   // 0.5 - 2.0
    public final float volume;                  // 0.0 - 1.0
    public final boolean muted;
    public final PlayMode playMode;
    public final long loopA, loopB;             // A-B 循环，-1 表示未开启

    public PlayerState(State state, MediaItem currentMedia, long positionMs,
                       long durationMs, float speed, float volume, boolean muted,
                       PlayMode playMode, long loopA, long loopB) {
        this.state = state; this.currentMedia = currentMedia;
        this.positionMs = positionMs; this.durationMs = durationMs;
        this.speed = speed; this.volume = volume; this.muted = muted;
        this.playMode = playMode; this.loopA = loopA; this.loopB = loopB;
    }

    public static PlayerState idle() {
        return new PlayerState(State.IDLE, null, 0, 0, 1f, 1f, false,
                PlayMode.SEQUENCE, -1, -1);
    }
}
```

**为什么不可变？** LiveData 每次 setValue 都会通知所有 observer。如果状态可变、UI 拿到引用后随手改字段，会造成"UI 改状态"的反向数据流——违反架构篇"依赖只能向下"铁律。**不可变对象 + 每次新建** 是五端状态管理的共同选择（Web 篇 Pinia 的 state 快照、Qt 的属性信号、Electron 的 Zustand subscribe 都遵循这个思路）。

### Step 4.2 PlayerManager：ExoPlayer 事件翻译层（心脏类）

```java
    private boolean userSeeking = false;

    // —— 位置节流（对照架构篇 §1.4 的 200ms 规则）——
    private final android.os.Handler handler = new android.os.Handler(android.os.Looper.getMainLooper());
    private long lastReportMs = 0;

    public PlayerManager(Context ctx, StateChanged notifier) {
        this.notifier = notifier;
        player = new ExoPlayer.Builder(ctx).build();
        player.addListener(this);
        startProgressTick();
    }

    // ========== 队列契约 ==========

    public void setQueue(java.util.List<com.ycbook.miniplayer.data.MediaItem> items, int startIndex) {
        queue.clear();
        queue.addAll(items);
        playAt(startIndex);
    }

    public void playAt(int index) {
        if (index < 0 || index >= queue.size()) return;
        queueIndex = index;
        com.ycbook.miniplayer.data.MediaItem m = queue.get(index);

        // ⭐ MediaStore content URI 直接喂给 ExoPlayer，无需 File 路径
        player.setMediaItem(androidx.media3.common.MediaItem.fromUri(android.net.Uri.parse(m.uri)));
        player.prepare();
        player.play();

        pushState(PlayerState.State.PLAYING);
    }

    // ========== 控制契约（对照架构篇 §1.5）==========

    public void toggle() {
        if (player.isPlaying()) player.pause();
        else player.play();
    }

    public void seekTo(long ms) {
        player.seekTo(ms);
        pushState();            // 立即反馈，不等下一 tick
    }

    public void setSpeed(float rate) {
        player.setPlaybackParameters(new PlaybackParameters(rate));
        pushState();
    }

    public void setVolume(float v) { player.setVolume(v); pushState(); }
    public void setMuted(boolean m) { player.setVolume(m ? 0 : lastVolume); pushState(); }

    public void setMode(PlayerState.PlayMode m) { mode = m; pushState(); }

    public void next()     { playAt(nextIndex(+1)); }
    public void previous() { playAt(nextIndex(-1)); }

    /** ⭐ 播放模式决策树（和 Qt/Web/Electron 端逐字一致） */
    private int nextIndex(int dir) {
        if (mode == PlayerState.PlayMode.REPEAT_ONE) return queueIndex;
        if (mode == PlayerState.PlayMode.SHUFFLE) {
            if (queue.size() <= 1) return queueIndex;
            int r;
            do { r = (int) (Math.random() * queue.size()); } while (r == queueIndex);
            return r;
        }
        int n = queueIndex + dir;
        if (n >= queue.size()) n = 0;         // 顺序模式循环
        if (n < 0) n = queue.size() - 1;
        return n;
    }

    // ========== Player.Listener：引擎事件统一向上翻译（铁律三）==========

    @Override
    public void onIsPlayingChanged(boolean isPlaying) {
        pushState(isPlaying ? PlayerState.State.PLAYING : PlayerState.State.PAUSED);
    }

    @Override
    public void onPlaybackStateChanged(int playbackState) {
        if (playbackState == Player.STATE_ENDED) {
            next();      // 顺序播完自动下一首
        }
    }

    @Override
    public void onPlayerError(androidx.media3.common.PlaybackException error) {
        pushState(PlayerState.State.ERROR);
    }

    // ========== 位置节流：Handler 200ms（对照架构篇 §1.4 表）==========

    private void startProgressTick() {
        handler.post(new Runnable() {
            @Override public void run() {
                if (!userSeeking && player != null) {
                    long now = android.os.SystemClock.uptimeMillis();
                    if (now - lastReportMs >= 200) {
                        pushState();         // 带 position 的全量状态
                        lastReportMs = now;
                    }
                }
                handler.postDelayed(this, 200);
            }
        });
    }

    // ========== 状态聚合与广播 ==========

    private float lastVolume = 1f;

    private void pushState() { pushState(null); }

    private void pushState(PlayerState.State override) {
        PlayerState s = new PlayerState(
                override != null ? override : mapState(),
                queueIndex >= 0 ? queue.get(queueIndex) : null,
                player.getCurrentPosition(),
                player.getDuration(),
                player.getPlaybackParameters().speed,
                player.getVolume(),
                player.getVolume() == 0,
                mode,
                -1, -1);
        notifier.onChange(s);
    }

    private PlayerState.State mapState() {
        switch (player.getPlaybackState()) {
            case Player.STATE_IDLE:      return PlayerState.State.IDLE;
            case Player.STATE_BUFFERING: return PlayerState.State.PREPARING;
            case Player.STATE_READY:
                return player.isPlaying() ? PlayerState.State.PLAYING : PlayerState.State.PAUSED;
            case Player.STATE_ENDED:     return PlayerState.State.PAUSED;
        }
        return PlayerState.State.IDLE;
    }

    public void release() {
        handler.removeCallbacksAndMessages(null);
        player.release();
    }

    public void setUserSeeking(boolean v) { userSeeking = v; }
}
```

**与 §02 MediaPlayer 版的对照**（重构收益清单）：

| §02 痛点 | ExoPlayer 解法 |
|---------|---------------|
| `prepare()` 同步阻塞主线程 | `prepare()` 异步 + `STATE_BUFFERING` 状态 |
| 旋转屏幕播放中断 | Player 挪进 ViewModel/Service，Activity 重建不释放 |
| 无播放列表 | `queue + queueIndex` 本端自管理（或用 ExoPlayer 原生 Playlist API） |

| 错误回调残缺 | `onPlayerError` 带错误码 + cause |

### Step 5.2 MediaRepository：DB 优先缓存策略

```java
// data/MediaRepository.java
public class MediaRepository {

    public interface RepoCallback<T> { void onResult(T data); }

    private final MediaDao dao;
    private final MediaScanner scanner;
    private final ExecutorService io = Executors.newSingleThreadExecutor();

    public MediaRepository(Context ctx) {
        dao = AppDatabase.get(ctx).mediaDao();
        scanner = new MediaScanner(ctx);
    }

    /** ⭐ 秒开策略：先给 DB 缓存，后台刷新后二次投递 */
    public void refreshLibrary(RepoCallback<List<MediaItem>> cb) {
        io.execute(() -> {
            // 1. 后台线程全量重扫
            List<MediaItem> fresh = scanner.scanSync();
            // 2. upsert 进库（IGNORE 策略：库里有就不动 rating 等用户数据）
            dao.insertMedia(fresh.toArray(new MediaItem[0]));
            // 3. 把最新列表给 UI
            cb.onResult(fresh);
        });
    }

    public void recordPlay(String mediaId, long positionMs) {
        io.execute(() -> {
            dao.recordPlay(mediaId, System.currentTimeMillis(), positionMs);
            dao.trimHistory();
        });
    }

    public void getLastPosition(String mediaId, RepoCallback<Long> cb) {
        io.execute(() -> cb.onResult(dao.getLastPosition(mediaId)));
    }

    public void toggleFavorite(String mediaId) { /* 略，见配套工程 */ }
}
```

**为什么 upsert 用 IGNORE？** 用户给某首歌打了 5 星（rating 在 media 表），重新扫描时若用 REPLACE 会把 rating 重置为 0。**扫描数据是"系统真相"，用户数据是"用户真相"，两者字段级合并**——REPLACE 只覆盖元数据字段：

### Step 6.1 PlaybackService 骨架

```java
// service/PlaybackService.java（骨架，完整实现见配套工程路线图）
package com.ycbook.miniplayer.service;

import android.app.Notification;
import android.app.NotificationChannel;
import android.app.NotificationManager;
import android.app.PendingIntent;
import android.app.Service;
import android.content.Context;
import android.content.Intent;
import android.os.Build;
import android.os.IBinder;
import androidx.annotation.Nullable;
import androidx.core.app.NotificationCompat;
import androidx.media.app.NotificationCompat.MediaStyle;

public class PlaybackService extends Service {

    public static final String CHANNEL_ID = "playback";
    public static final int NOTI_ID = 1001;

    private PlayerManager playerManager;
    private androidx.media.session.MediaControllerCompat controller;

    @Override
    public void onCreate() {
        super.onCreate();
        createChannel();

        // ⭐ PlayerManager 从 ViewModel 迁到这里 —— 生命周期跟随 Service
        playerManager = new PlayerManager(this, this::onStateChanged);

        // MediaSession 初始化（Step 6.3 详述）
        setupMediaSession();
    }

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        // ⭐ 启动即前台：5 秒内必须 startForeground，否则 ANE 崩溃（API 26+）
        startForeground(NOTI_ID, buildNotification());
        handleAction(intent);
        return START_NOT_STICKY;
    }

    private void handleAction(Intent intent) {
        if (intent == null || intent.getAction() == null) return;
        switch (intent.getAction()) {
            case "action.play":  playerManager.toggle(); break;
            case "action.next":  playerManager.next(); break;
            case "action.prev":  playerManager.previous(); break;
            case "action.stop":
```

### Step 6.2 通知刷新策略

每 200ms 的 position tick **绝不能**每次都 `notify()`（通知栏会疯狂重绘、耗电）。正确做法：

```java
private void onStateChanged(PlayerState s) {
    // ⭐ 只在"用户可感知的变化"时刷通知：换歌、播放/暂停切换
    if (s.state != lastNotifiedState || s.currentMedia != lastNotifiedMedia) {
        NotificationManager nm = getSystemService(NotificationManager.class);
        nm.notify(NOTI_ID, buildNotification());
        lastNotifiedState = s.state;
        lastNotifiedMedia = s.currentMedia;
    }
    // 进度不进通知 —— 锁屏进度由 PlaybackState 的 position + playbackState + speed
    // 推算（Step 6.3 的 setPlaybackState 自带），系统自己走表
}
```

```java
private void pushSessionMetadata(PlayerState s) {
    if (s.currentMedia == null) return;
    android.media.MediaMetadata.Builder mb = new android.media.MediaMetadata.Builder()
            .putString(android.media.MediaMetadata.METADATA_KEY_TITLE, s.currentMedia.title)

        if (bmp != null) mb.putBitmap(android.media.MediaMetadata.METADATA_KEY_ALBUM_ART, bmp);
    }
    mediaSession.setMetadata(mb.build());

    int state = s.state == PlayerState.State.PLAYING
            ? android.media.session.PlaybackState.STATE_PLAYING
            : android.media.session.PlaybackState.STATE_PAUSED;
    mediaSession.setPlaybackState(new android.media.session.PlaybackState.Builder()
            .setState(state, s.positionMs, s.state == PlayerState.State.PLAYING ? 1f : 0f)
            .setActions(android.media.session.PlaybackState.ACTION_PLAY
                      | android.media.session.PlaybackState.ACTION_PAUSE
                      | android.media.session.PlaybackState.ACTION_PLAY_PAUSE
                      | android.media.session.PlaybackState.ACTION_SKIP_TO_NEXT
                      | android.media.session.PlaybackState.ACTION_SKIP_TO_PREVIOUS
                      | android.media.session.PlaybackState.ACTION_SEEK_TO)
            .build());
}
```

**⚠️ 造 BUG 现场**：故意不调 `setPlaybackState`（只 setMetadata），运行 → 锁屏控件**灰显不可点**。因为系统认为 Session "没有活跃的播放"就不渲染控制按钮。修法就是上面的 `setPlaybackState + setActions`。

**锁屏进度自己走的原理**：`setState(PLAYING, positionMs, speed)` 三个参数给了系统"当前时刻 + 位置 + 速率"，系统用 `(now - lastUpdateTime) * speed + positionMs` 自行推算——**我们的 200ms tick 完全不需要碰通知**，这就是 Step 6.2 的底层依据。

### Step 7.1 LyricsParser（对照 Web 篇 Step 7.1 同一算法）

```java
// service/LyricsParser.java
public class LyricsParser {

    public static class Line {
        public final long timeMs;
        public final String text;
        Line(long t, String s) { timeMs = t; text = s; }
    }

    /** 解析 LRC 文本：支持一行多时间标签 [00:14.20][00:48.30]、元信息标签跳过 */
    public static List<Line> parse(String lrc) {
        List<Line> out = new ArrayList<>();
        if (lrc == null) return out;

        for (String raw : lrc.split("\n")) {
            String line = raw.trim();
            if (line.isEmpty()) continue;

            List<Long> stamps = new ArrayList<>();
            // 循环剥掉行首所有 [mm:ss.xx]
            while (line.startsWith("[")) {
                int close = line.indexOf(']');
                if (close < 0) break;
                Long ms = parseStamp(line.substring(1, close));
                if (ms == null) break;      // [ar:...] 元信息 → 剩余整行跳过
                stamps.add(ms);
                line = line.substring(close + 1);
            }
            if (stamps.isEmpty()) continue;

            for (long ms : stamps) out.add(new Line(ms, line));
        }
        Collections.sort(out, (a, b) -> Long.compare(a.timeMs, b.timeMs));
        return out;
    }

    private static Long parseStamp(String s) {
        // mm:ss.xx / mm:ss.xxx / mm:ss
        String[] parts = s.split("[:.]");
        if (parts.length < 2) return null;
        try {
            long mm = Long.parseLong(parts[0]);
            long ss = Long.parseLong(parts[1]);
            long frac = 0;
            if (parts.length == 3) {
                String f = parts[2];
                while (f.length() < 3) f += "0";
                frac = Long.parseLong(f.substring(0, 3));
            }
            return mm * 60_000 + ss * 1000 + frac;
        } catch (NumberFormatException e) {
            return null;
        }
    }
}
```

**LRC 文件从哪来？** 同目录同名（`xxx.mp3` ↔ `xxx.lrc`），通过 MediaStore 查 `_data` 列拿真实路径再替换后缀（API 29+ 需要 `MediaStore.Audio.Media.DATA` 列仍在，但访问文件本体要用 `content URI openInputStream`——生产代码建议把 lrc 一起扫进库，v0.1 简化用 assets 演示）。

### Step 7.2 自定义 LyricsView：onDraw 绘制

```java
// ui/LyricsView.java —— 精简版（完整渐变高亮 + fling 惯性见配套工程路线图）
public class LyricsView extends View {

    private final List<LyricsParser.Line> lines = new ArrayList<>();
    private int currentIndex = -1;
    private final Paint paintNormal = new Paint(Paint.ANTI_ALIAS_FLAG);
    private final Paint paintActive  = new Paint(Paint.ANTI_ALIAS_FLAG);
    private float scrollY = 0;                     // 平滑滚动目标
    private float lastScrollY = 0;

    public LyricsView(Context ctx, AttributeSet attrs) {
        super(ctx, attrs);
        paintNormal.setTextSize(sp(15));
        paintNormal.setColor(0x88FFFFFF);
        paintActive.setTextSize(sp(17));
        paintActive.setColor(0xFFFFFFFF);
        paintActive.setFakeBoldText(true);
    }

    public void setLines(List<LyricsParser.Line> l) {
        lines.clear();
        lines.addAll(l);
        currentIndex = -1;
        invalidate();
    }

    /** 播放进度变化时调用（外部从 PlayerState 观察） */
    public void setPositionMs(long ms) {
        int idx = binarySearch(ms);                 // ⭐ 二分查找当前行
        if (idx != currentIndex) {
            currentIndex = idx;
            scrollY = idx * getLineHeight() - getHeight() / 2f;
            invalidate();
        }
    }

    private int binarySearch(long ms) {
        int lo = 0, hi = lines.size() - 1, ans = -1;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;
            if (lines.get(mid).timeMs <= ms) { ans = mid; lo = mid + 1; }
            else hi = mid - 1;
        }
        return ans;
    }

    @Override
    protected void onDraw(Canvas canvas) {
        super.onDraw(canvas);
        if (lines.isEmpty()) {
            canvas.drawText("暂无歌词", 40, getHeight() / 2f, paintNormal);
            return;
        }
        // 平滑滚动插值（每帧靠近目标 20%）
        lastScrollY += (scrollY - lastScrollY) * 0.2f;
        canvas.save();
        canvas.translate(0, -lastScrollY);
        float y = getPaddingTop() + getLineHeight();
        for (int i = 0; i < lines.size(); i++) {
            Paint p = (i == currentIndex) ? paintActive : paintNormal;
            canvas.drawText(lines.get(i).text, 40, y, p);
            y += getLineHeight();
        }
        canvas.restore();
        if (Math.abs(scrollY - lastScrollY) > 1f) postInvalidateOnAnimation();  // 继续动画
    }

    private float getLineHeight() { return sp(44); }
    private float sp(int v) { return v * getResources().getDisplayMetrics().scaledDensity; }
}
```

**为什么 onDraw 而不是 ScrollView + TextView？** 歌词需要**中心行放大 + 上下渐隐 + 平滑跟随**三种效果同时做，ScrollView 的子 View 模型做不到跨行的颜色渐变。自绘是播放器歌词的行业标配（网易云/QQ 音乐全是自绘）。

### Step 9.1 android.media.audiofx.Equalizer 挂到 ExoPlayer

**关键时机**：Equalizer 必须在 **audioSessionId 可用之后**（即 ExoPlayer prepare 完成、开始输出音频后）创建，过早创建 session 是 0。

```java
// service/EqualizerController.java
public class EqualizerController {

    private android.media.audiofx.Equalizer eq;
    private final short[] bandLevels = new short[10];   // 每频段 dB × 100

    /** ⭐ 必须在 Player.STATE_READY 后调用（audioSessionId 才有效） */
    public void attach(int audioSessionId) {
        release();
        try {
            eq = new android.media.audiofx.Equalizer(0, audioSessionId);
            eq.setEnabled(true);

            int bands = eq.getNumberOfBands();          // 设备不同可能是 5/10 频段
            for (short i = 0; i < bands && i < 10; i++) {
                eq.setBandLevel(i, bandLevels[i]);
            }
        } catch (Exception e) {
            eq = null;   // 某些设备的 audiofx 不可用（厂商裁剪），降级为无 EQ
        }
    }

    public void setBand(int band, float gainDb) {
        if (eq == null || band >= eq.getNumberOfBands()) return;
        short level = (short) Math.round(gainDb * 100);   // 单位是 milli-Bel = dB × 100
        bandLevels[band] = level;
        eq.setBandLevel((short) band, level);
    }

    public float[] bandFrequencies() {
        if (eq == null) return new float[0];
        int n = eq.getNumberOfBands();
        float[] out = new float[n];
        for (short i = 0; i < n; i++) {
            out[i] = eq.getBandLevelRange()[0];   // 简化：实际用 getCenterFreq(i)
        }
        return out;
    }

    public void release() {
        if (eq != null) { eq.release(); eq = null; }
    }
}
```

```java
        cancel();
        long totalMs = minutes * 60_000L;

        timer = new android.os.CountDownTimer(totalMs - 10_000, totalMs) {
            @Override public void onTick(long untilFade) { /* 不用 */ }
            @Override public void onFinish() {
                // 进入最后 10 秒 → 线性淡出
                fade = android.animation.ValueAnimator.ofFloat(pm.getVolume(), 0f);
                fade.setDuration(10_000);
                fade.addUpdateListener(a -> pm.setVolume((Float) a.getAnimatedValue()));
                fade.addListener(new android.animation.AnimatorListenerAdapter() {
                    @Override public void onAnimationEnd(android.animation.Animator a) {
                        pm.pause();
                        pm.setVolume(1f);      // 恢复音量，下次播放不受影响
                        done.onFinish();
                    }
                });
                fade.start();
            }
        }.start();
    }

    public void cancel() {
        if (timer != null) { timer.cancel(); timer = null; }
        if (fade != null)  { fade.cancel();  fade = null; }
    }
}
```

### Step 9.4 ⚠️ EQ 的暂停失效坑

**现象**：暂停 → 调 EQ band → 恢复播放 → EQ 没生效。

**原因**：部分设备（尤其高通 DSP 机型）在 audio track 停止时会**重置 audiofx 链**，之后 set 的 band 全部丢弃。

**修法**：监听 `onIsPlayingChanged(true)` 时**重新 apply 全部 band**：

```java
@Override
public void onIsPlayingChanged(boolean isPlaying) {
    if (isPlaying && eqController != null) {
        eqController.reapplyAll();    // 把 bandLevels 数组整体重设一遍
    }
    // ...
}
```

### Step 9.5 🧪 阶段⑧ 验收

- ✅ EQ 拉低音 +6dB 能听出鼓声变重；切"古典"预设有可闻差异
- ✅ 暂停 → 调 EQ → 恢复播放，EQ 仍然生效（Step 9.4 修复后）
- ✅ 定时 1 分钟（测试档）→ 最后 10 秒渐弱 → 暂停 → 手动恢复播放音量正常

## 11.挑战题

1. **Media3 MediaSessionService 重构**：把 §06 的"手搓三件套"（Service + MediaSessionCompat + MediaStyle）替换为 `androidx.media3.session.MediaSessionService`——官方新姿势代码量减半，自动处理通知/线控/助手。对照两种实现的行数与边界情况（如 Android 12 通知 trampoline 限制）。

2. **接入 HLS 直播**：ExoPlayer 原生支持 m3u8。在媒体库加"直播源"入口（URL 直链），处理直播特有状态（无 duration、seek 禁用、断流重连 `LoadErrorInfo`）。

3. **Android Auto / 车机**：`MediaLibraryService` + `MediaBrowserCompat`，把播放队列以内容树形式暴露给车机/助手。需要 `automotive` 或 `auto` 的 meta-data 声明。

4. **Compose 迁移**：把 `MediaListAdapter` + XML 换成 `LazyColumn` + `@Composable`，对照 DiffUtil 与 Compose 的 key-based recomposition 机制差异（需 Kotlin，作为本端"毕业后"练习）。

5. **播放队列持久化**：现在队列在内存，进程死亡丢失。把 queue + queueIndex 存 Room，冷启动恢复"上次听到的位置"（对照断点续播，粒度升级到队列级）。

6. **音频焦点完整版**：§06 只处理了 BECOMING_NOISY；完整实现 `AudioFocusRequest`（`AUDIOFOCUS_GAIN` / `AUDIOFOCUS_LOSS_TRANSIENT` / `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK`），处理来电中断后自动恢复、短视频 App 抢占时压低音量。

## 12.本端小结

### 12.1 Android 端的"平台物理约束"清单

做完本端，你应该能脱口而出这些 Android 特有的约束（其他四端没有的）：

- **生命周期不受控**：Activity 随时被销毁重建 → 状态必须上移到 ViewModel/Service
- **后台执行受限**：息屏 1 分钟后普通 Service 被冻结 → 必须前台服务 + 常驻通知
- **权限三代同堂**：READ_EXTERNAL_STORAGE / READ_MEDIA_* / VISUAL_USER_SELECTED 一套代码三分叉
- **Scoped Storage**：拿不到文件路径只有 content URI → 所有 IO 走 ContentResolver
- **通知即能力**：Android 13+ 连显示通知本身都要运行时权限
- **PendingIntent 可变性**：Android 12+ 必须显式 IMMUTABLE/MUTABLE

### 12.2 与兄弟端的对照收获

| 考点 | 你在 Android 端学到 | 在哪端会遇到"同款不同形" |
|------|-------------------|------------------------|
| 状态唯一数据源 | LiveData<PlayerState> | Web:Pinia / Qt:属性+信号 / Electron:Zustand |
| seek 拖动标志位 | `setUserSeeking` | 四端同款坑，五种语言实现 |
| 后台播放三件套 | FGS + MediaSession + MediaStyle | Web:Media Session API / Qt:MPRIS / Electron:自写 C++ |
| 拔耳机暂停 | BECOMING_NOISY 广播 | iOS:AVAudioSession interruption / 桌面端无此概念 |
| 历史去重上限 | SQL DELETE ... NOT IN | 五端同一 SQL（Qt/Electron 直用） |
| 稳定 ID | SHA1(uri+size+mtime) | 五端同一算法 |
