# 第一章：MiniPlayer 架构设计与五端对照

本文是五端实现的**公共设计基座**：五篇端实现文档都假设你已经读过本文。我们将确定五件事——**分层架构、数据模型、播放状态机、接口契约、五端 API 映射**。读完本文，你在任何一端动手写代码前，都已经知道"要造哪几个类、每个类管什么、类之间怎么说话"。

> **五端范围说明**：本案例的"五端"指 **5 篇实现文档** —— Android / iOS / Web / **Qt 桌面（Linux+macOS+Windows 三合一）** / **Electron 桌面（Linux+macOS+Windows 三合一）**。其中 Qt 和 Electron 两篇都用同一份工程产出三平台原生可执行文件，但工程哲学截然不同——Qt 是"C++ 作主语言"，Electron 是"C++ 作服务提供者、被 TS 调用"。详见 [05.Qt桌面端](/pages/mp5qt0/) 与 [06.Electron桌面端](/pages/mp5elec/)。本文下述表格的 **Qt 桌面** 列和 **Electron 桌面** 列分别对应这两篇。

---

## 1.1 为什么五端要共享一套设计

**因为本案例的教学价值就藏在"同与不同"里**：

- **同的部分**（数据模型、状态机、分层）：证明这些是"产品本质"，与平台/工程方式无关；
- **不同的部分**（引擎 API、后台机制、异步模型、跨语言边界）：暴露每个平台的"物理约束"，这才是平台工程的考点。

如果不先固化公共设计，五端各写各的，读者做完 Android 再看 iOS 会像换了一个项目；固化之后，五端代码**像同一个灵魂穿五件衣服**。Qt 与 Electron 两篇用了同一套 C++ 代码的影子（SQL schema、状态机、系统媒体控制），但封装边界完全不同——这是本案例最值得品味的工程对照。

## 1.2 五层架构详解

```text
┌─────────────────────────────────────────────────────┐
│ ⑤ UI 层                                             │
│    Activity/Fragment · UIViewController · Vue 组件   │
│    · QWidget / QMainWindow · React 组件              │
│    只做"展示 + 转发用户动作"，不持有播放状态           │
├─────────────────────────────────────────────────────┤
│ ④ Controller / ViewModel 层                         │
│    持有 PlayerState，把引擎事件翻译成 UI 可订阅的状态  │
│    Android: ViewModel+LiveData · iOS: 控制器属性+KVO │
│    Web: Pinia store · Qt: QObject 属性+信号          │
│    Electron: Zustand store（renderer 进程内）         │
├─────────────────────────────────────────────────────┤
│ ③ PlayerService 层（每端的心脏）                     │
│    播放/暂停/seek/倍速/队列管理/下一首决策            │
│    后台生命周期（前台服务/AVAudioSession/            │
│    MPRIS+MPNowPlaying+SMTC 三端桥接）                │
│    Electron 特有：三进程模型 (main/preload/renderer) │
│    + FFI 边界 (koffi → libmp_native.*)              │
├─────────────────────────────────────────────────────┤
│ ② MediaRepository 层                                │
│    扫描文件系统 → 读元数据 → 写入/读取本地 DB        │
│    对上层暴露"全部/音频/视频/我喜欢/历史"五类查询      │
├─────────────────────────────────────────────────────┤
│ ① Platform Engine 层（平台黑盒）                     │
│    ExoPlayer · AVPlayer · <audio>/<video>            │
│    · QMediaPlayer · Chromium <audio>/<video>+Web Audio│
└─────────────────────────────────────────────────────┘
```

**三条铁律**（五端通用，违反任何一条都会在阶段④⑤翻车）：

1. **依赖只能向下**：UI → ViewModel → Service → Repository → Engine。Engine 永远不知道 UI 的存在。
2. **播放状态只有一个数据源**（Single Source of Truth）：全部来自 PlayerService，UI 只是它的镜像。谁让 UI 自己记录 `isPlaying`，谁的进度条就会跳动。
3. **引擎事件统一向上翻译**：Engine 的回调/信号先进入 Service，由 Service 归一化为统一事件，再广播给 ViewModel。

**Electron 篇独有的第四条**：**C ABI 边界只传基础类型**。koffi FFI 的参数只能用 string / int / buffer / POD struct，不能传 C++ 对象或 STL 容器。详见 [06.Electron §3.3](/pages/mp5elec/)。

## 1.3 数据模型（五端共享）

### 核心实体

```text
MediaItem                     // 音频和视频统一建模
├── id: long                  // 稳定主键（路径的 hash）
├── type: MediaType           // AUDIO / VIDEO
├── path: string              // 绝对路径
├── title: string             // 元数据标题，缺省用文件名
├── artist: string
├── album: string
├── durationMs: long
├── bitrateKbps: int?         // 码率（展示用）
├── coverPath: string?        // 提取出的封面缓存路径
├── rating: int               // 0-5 星，0 表示未评分
├── addedAt: long             // 入库时间
└── lastPlayedAt: long?       // 最近播放时间（断点续播用）

Playlist                      // 用户创建的歌单/播放列表
├── id: long
├── name: string
├── coverPath: string?        // 用户自选或自动取首曲封面
├── createdAt: long
└── mediaIds: long[]          // 有序，支持拖动排序

PlayRecord                    // 播放历史（append-only）
├── mediaId: long
├── playedAt: long
└── positionMs: long          // 播放到哪里（断点续播用）

Favorite                      // 我喜欢
└── mediaId + favoredAt

RecentFile                    // 最近打开（独立于播放历史，文件级）
├── path: string
├── openedAt: long
└── accessible: bool          // 文件还在不在

LyricLine                     // 歌词行
├── timeMs: long              // [mm:ss.xx] 解析结果
└── text: string

SubtitleTrack                 // 字幕轨（外挂或内嵌）
├── id: string                // 内嵌用轨道索引；外挂用文件路径
├── language: string          // "zh-CN" / "en" / "ja"
├── title: string?            // "简体中文"、"英文"
├── isExternal: bool          // true=外挂文件；false=内嵌
└── format: SubtitleFormat    // SRT / VTT / ASS

AudioTrack                    // 音轨（仅视频可能多轨）
├── id: string                // 轨道索引
├── language: string
├── title: string?
└── channels: int             // 1 单 / 2 立体 / 6 环绕

Chapter                       // 章节（支持章节元数据的 mp4/mkv）
├── index: int
├── title: string
├── startMs: long
└── endMs: long

ScanConfig                    // 扫描配置
├── directories: string[]     // 用户添加的扫描目录
├── includeAudio: bool
├── includeVideo: bool
└── minDurationMs: long       // 小于此时长（如 10 秒）跳过
```

### 五端类型映射表

| 模型字段 | Android (Java) | iOS (OC) | Web (TS) | Qt 桌面 (C++) | Electron (TS + C++) |
|---------|----------------|----------|----------|---------------|---------------------|
| MediaItem | `class` + Room `@Entity` | `MediaItem : NSObject` | `interface MediaItem` | `struct MediaItem` | TS 侧 `interface` + C++ 侧 `MpMetadata` POD struct |
| 枚举 MediaType | `enum class` | `typedef NS_ENUM` | union `"audio"\|"video"` | `enum class MediaType` | TS union + C ABI `int32_t` 整数值 |
| 时间戳 | `long` | `NSTimeInterval` | `number` | `std::chrono::milliseconds` | TS `number` + C ABI `int64_t`（避免 JS Number 精度丢失，用 `BigInt` 包装） |
| 列表 | `List<>` + DiffUtil | `NSArray` | `Media[]` | `std::vector` | TS `Array` + FFI 边界用"**指针+长度+释放函数**"三件套 |
| 空值 | `@Nullable` | `nil` / `NSNull` | `?`/`undefined` | `std::optional` | TS `null` + C ABI `nullptr`（字符串用 const char* 可为 NULL） |
| 歌单关联 | Room `@Relation` | FMDB 中间表 | Dexie 多表 join | SQL JOIN | **better-sqlite3** 同 Qt 的 SQL JOIN，Node 侧预处理 |

> **对照考点**：OC 没有原生枚举泛型集合、C++ 没有反射、Web 的 number 会丢 long 精度（id 用 string）、Electron 的 FFI 边界再加一层"**C++ 内部数据结构 → C ABI POD → JS 对象**"的转换成本——这些"语言物理约束"会直接影响数据模型在每端的落地形态。

## 1.4 播放状态机（五端共享）

```text
                 prepare(path)
    ┌────────┐ ───────────────→ ┌───────────┐  onReady   ┌─────────┐
    │ IDLE   │                  │ PREPARING │ ─────────→ │ PAUSED  │
    └────────┘ ←─────────────── └───────────┘            └─────────┘
        ↑          error()           ↑  ↑                  play() ↓ ↑ pause()
        │                           │  └────────────────┌─────────┐
        │         stop()            └───────────────────│ PLAYING │
        └───────────────────────────────────────────────└─────────┘
                                                              ↓ error()
                                                          ┌─────────┐
                                                          │  ERROR  │
                                                          └─────────┘
```

**状态广播九元组**（UI 唯一允许消费的播放状态）：

```text
PlayerState {
  // —— 基础播放 ——
  state:        IDLE | PREPARING | PLAYING | PAUSED | ERROR
  currentMedia: MediaItem?
  positionMs:   long          // 每 200~500ms 节流上报
  durationMs:   long
  speed:        float         // 0.5 ~ 2.0

  // —— 音频 ——
  volume:       float         // 0.0 ~ 1.0
  muted:        bool
  playMode:     SEQUENCE | REPEAT_ONE | SHUFFLE
  loopAB:       { aMs: long, bMs: long }?   // A-B 循环点，null 表示未开启

  // —— 视频（type=VIDEO 时有效） ——
  isFullscreen: bool
  isPictureInPicture: bool
  aspectRatio:  ORIGINAL | R_16_9 | R_4_3 | FILL | FIT
  rotationDeg:  0 | 90 | 180 | 270
  brightness:   float         // 0.0 ~ 1.0（UI 覆盖层亮度）
  currentAudioTrack:    string?
  currentSubtitleTrack: string?    // null 表示关闭字幕
  availableAudioTracks:    AudioTrack[]
  availableSubtitleTracks: SubtitleTrack[]
}
```

**五端状态广播机制对照**（本文最重要对照之一）：

| 能力 | Android | iOS | Web | Qt 桌面 | Electron |
|------|---------|-----|-----|---------|----------|
| 状态持有 | ViewModel + LiveData/MutableStateFlow | 控制器属性 + KVO/委托回调 | Pinia `ref` 响应式 | QObject 属性 + `property`/信号 | Zustand store（renderer）；跨进程事件走 `ipcRenderer.on` |
| 位置节流 | Handler `postDelayed` 循环 | `CADisplayLink` / `addPeriodicTimeObserver` | `requestAnimationFrame`/`setInterval` | `QTimer` 200ms | `requestAnimationFrame`（renderer）或 `setInterval` 200ms（main 侧） |
| 生命周期安全 | LiveData 自动感知 | weak delegate | 组件卸载清理 watcher | Qt 父子对象树自动销毁 | React useEffect cleanup + Electron `window.on('closed')` 释放 FFI 资源 |
| 跨进程边界 | — | — | — | — | **main ↔ renderer 走 IPC**（`ipcMain.handle` / `ipcRenderer.invoke`），所有状态变更广播通过 `webContents.send` |

## 1.5 PlayerService 接口契约

五端的 Service 层都实现同一组方法（伪代码，各端映射为 interface / protocol / 抽象基类 / TS interface + C ABI 双层契约）：

```text
interface PlayerService {
  // —— 基础播放控制 ——
  prepare(media: MediaItem)            // 装载并暂停在 0
  play() / pause() / toggle() / stop()
  seekTo(positionMs: long)             // 包含"精准跳转"场景
  setSpeed(rate: float)

  // —— 音频控制 ——
  setVolume(volume: float)             // 0.0 ~ 1.0
  setMuted(muted: bool)
  toggleMute()
  setLoopAB(aMs: long?, bMs: long?)    // 任一为 null 则取消 A-B 循环
  setCrossfade(seconds: int)           // 曲目间淡入淡出时长，0 表示关闭

  // —— 队列 ——
  setQueue(items: MediaItem[], startIndex: int)
  getQueue(): MediaItem[]              // 供 UI 可视化
  reorderQueue(fromIndex: int, toIndex: int)
  removeFromQueue(index: int)
  next() / previous()                  // 受播放模式影响
  setMode(mode: SEQUENCE | REPEAT_ONE | SHUFFLE)

  // —— 视频控制 ——
  enterFullscreen() / exitFullscreen()
  enterPictureInPicture() / exitPictureInPicture()
  setAspectRatio(ratio: AspectRatio)
  setRotation(deg: 0 | 90 | 180 | 270)
  setBrightness(value: float)          // UI 覆盖层，不碰系统亮度
  takeSnapshot(): string               // 返回保存后的文件路径

  // —— 字幕与多轨 ——
  loadExternalSubtitle(filePath: string): SubtitleTrack
  selectSubtitleTrack(trackId: string?)   // null = 关闭字幕
  selectAudioTrack(trackId: string)

  // —— 状态订阅 ——
  observeState(): Observable<PlayerState>

  // —— 后台能力（阶段⑥）——
  enterBackground() / exitBackground()
  onSystemMediaAction(action: PLAY|PAUSE|NEXT|PREV|SEEK|STOP)
  onAudioFocusChanged(gain: bool)      // 来电/其他 App 抢占时触发

  // —— 均衡器（阶段⑨）——
  setEqualizerBand(band: int, gainDb: float)
  applyEqualizerPreset(preset: EqPreset)
}
```

另一组由 `MediaRepository` 承担（扫描/持久化/歌单/评分），避免 Service 过度膨胀：

```text
interface MediaRepository {
  // 扫描与导入
  startScan(config: ScanConfig): Observable<ScanProgress>
  importFiles(paths: string[])         // 拖拽导入
  importUrl(url: string)               // URL 直链

  // 查询
  queryAll() / queryAudio() / queryVideo()
  searchKeyword(kw: string)

  // 歌单
  createPlaylist(name: string): long
  deletePlaylist(id: long)
  renamePlaylist(id: long, newName: string)
  addToPlaylist(playlistId: long, mediaIds: long[])
  reorderInPlaylist(playlistId: long, from: int, to: int)

  // 收藏 / 评分 / 历史
  toggleFavorite(mediaId: long)
  setRating(mediaId: long, stars: int)
  pushPlayRecord(record: PlayRecord)
  pushRecentFile(path: string)
  getLastPosition(mediaId: long): long
}
```

**五端"接口契约"落地形态对照**：

| 端 | 契约形态 | 备注 |
|----|---------|------|
| Android | Java `interface` + `PlayerService` 实现类 | Service 可先做普通类，阶段⑥再迁入 ForegroundService |
| iOS | OC 协议 `@protocol PlayerServiceProtocol` | 配合 delegate 回调 |
| Web | TS `interface` + Pinia store 内部实现 | 契约主要用于约束 store 的 actions |
| Qt 桌面 | 抽象基类 `class PlayerService` + 信号 | 用 Qt 信号做 observeState；三端共用同一组头文件 |
| Electron | **双层契约**：TS `interface`（renderer 用）+ C ABI 头文件 `mp_native.h`（main 调 C++ 用） | PlayerService 本体在 renderer，Repository/系统媒体在 main；两层之间走 IPC 通道 + `contextBridge` 白名单 |

## 1.6 五端 API 映射总表

按功能逐条映射，写代码时当"字典"查。**Qt 桌面** 和 **Electron 桌面** 两列各自覆盖 Linux/macOS/Windows 三平台：

| 功能 | Android | iOS | Web | Qt 桌面 | Electron 桌面 |
|------|---------|-----|-----|---------|---------------|
| 播放本地文件 | `ExoPlayer.setMediaItem` + `LocalUri` | `AVPlayer` + `AVPlayerItem` | `audio.src = URL.createObjectURL(file)` | `QMediaPlayer::setSource` | `audio.src = 'file://' + path`（main 侧 preload 转换为 `safe-file://`） |
| 播放 HTTP 直链 | 内置 HLS | m3u8 原生支持 | Safari 原生 / hls.js | GStreamer / 系统 | Chromium 原生（Electron 自带 ffmpeg lib） |
| 播放/暂停 | `play/pause` | `play/pause` | `play/pause` | `play/pause` | `play/pause`（Chromium 原生） |
| seek | `seekTo(ms)` | `seekToTime:` | `currentTime = s` | `setPosition(ms)` | `audio.currentTime = s` |
| 倍速 | `setPlaybackParameters` | `rate` 属性 | `playbackRate` | `setPlaybackRate` | `audio.playbackRate` |
| **音量** | `ExoPlayer.setVolume` | `AVPlayer.volume` | `audio.volume` | `QAudioOutput.setVolume` | Web Audio `GainNode.gain.value` |
| **静音** | `AudioManager.setStreamMute` | `AVPlayer.muted` | `audio.muted` | `QAudioOutput.setMuted` | `audio.muted` 或 `GainNode.gain = 0` |
| 进度监听 | `Player.Listener` | `addPeriodicTimeObserver` | `timeupdate` 事件 | `positionChanged` 信号 | `timeupdate` + rAF 节流 |
| **全屏** | `FLAG_FULLSCREEN` | `prefersStatusBarHidden` | `requestFullscreen()` | `QWindow::showFullScreen` | `win.setFullScreen(true)`（主进程）或 `videoEl.requestFullscreen()` |
| **宽高比** | `AspectRatioFrameLayout.setResizeMode` | `videoGravity` | `object-fit` | `setAspectRatioMode` | CSS `object-fit` + `transform: scaleX` |
| **画中画 PiP** | `enterPictureInPictureMode()` | `AVPictureInPictureController` | `requestPictureInPicture()` | 无系统级 → 置顶迷你窗 | **Chromium 原生 `requestPictureInPicture()`**（三端均原生支持，体验最佳） |

| **视频截图** | `TextureView.getBitmap` | `AVAssetImageGenerator` | `canvas.drawImage` | `QVideoWidget.grab()` | `canvas.drawImage(video)` → `toBlob` → `app.getPath('pictures')` |
| **视频旋转** | `videoFrameMetadataListener` + Matrix | `AVPlayerLayer.transform` | CSS `transform: rotate` | 自绘旋转 | CSS `transform: rotate` + 容器尺寸补偿 |
| 取元数据 | `MediaMetadataRetriever` | AVAsset `metadata` | music-metadata-browser | TagLib (C++) | **TagLib (C++)** 封装在 `mp_native` → koffi 调用（和 Qt 篇用同一个 TagLib） |
| 列表 UI | RecyclerView | UITableView | v-for | QListView + Model | React map + 虚拟列表（`react-window`） |
| 本地 DB | Room | FMDB | Dexie (IndexedDB) | QSqlDatabase | **better-sqlite3**（Node 原生模块，schema 与 Qt 篇一致） |
| **系统媒体控制** ⭐ | MediaSessionCompat | MPRemoteCommandCenter | Media Session API | **Linux**: MPRIS/D-Bus · **macOS**: MPRemoteCommandCenter · **Windows**: SMTC（Qt 内直接 C++ 调用） | **同 Qt 三平台**，但封装在 `mp_native.{so/dylib/dll}` 内部，Node.js 通过 koffi 调 `mp_sysmedia_init/update`，回调经 `setImmediate` 回主线程 |

| **打包** | AAB / APK | IPA | Web Bundle | ELF/.app/.exe (CMake) | AppImage/deb + .dmg + .exe（electron-builder，需把 .so/.dylib/.dll 作为 extraResources 打入） |

## 1.7 快捷键与手势标准

**五端用同一套"用户动作 → 命令"的语义层**，各端只做绑定层（键码到命令的映射、手势到命令的映射）不一样。这样在任何端上用户的"肌肉记忆"都一致。

### 标准快捷键表

| 动作 | 快捷键 | 对应 Service 方法 |
|------|-------|-----------------|
| 播放 / 暂停 | `Space` | `toggle()` |
| 停止 | `Esc`（视频：退出全屏优先） | `stop()` |
| 后退 5 秒 | `←` | `seekTo(pos - 5000)` |
| 前进 5 秒 | `→` | `seekTo(pos + 5000)` |
| 后退 30 秒 | `Shift + ←` | `seekTo(pos - 30000)` |
| 前进 30 秒 | `Shift + →` | `seekTo(pos + 30000)` |
| 音量 +5% | `↑` | `setVolume(v + 0.05)` |
| 音量 -5% | `↓` | `setVolume(v - 0.05)` |
| 静音切换 | `M` | `toggleMute()` |
| 倍速 -0.25x | `[` | `setSpeed(s - 0.25)` |
| 倍速 +0.25x | `]` | `setSpeed(s + 0.25)` |

## 1.9 全局约定

1. **命名**：五端类名统一 `PlayerService / MediaRepository / MediaScanner / LyricsParser / EqualizerController`，只换各端命名风格（OC 前缀 `MP`、C++ 命名空间 `mp::`、Electron C ABI 前缀 `mp_`）。
2. **时间单位一律毫秒**（`long`），只在调用引擎 API 的最后一刻转换（iOS 秒、Web 秒）。
3. **线程规则**：扫描和 DB 在后台线程/协程；UI 只在主线程；引擎回调一律 post 回主线程。
4. **错误分层**：引擎错误 → Service 归一化为 `PlaybackException(code, message)` → UI 统一 Toast/Snackbar 提示。
5. **测试素材**：仓库提供 `assets/media/` 目录（2 首 mp3 + 1 个 mp4 + 对应 .lrc），五端自测用同一套素材，保证截图/验收输出一致。
