**🔍 工程纪实：首轮静态核查修复清单（供读者学习）**

v0.1 代码落定后用子代理做了一次完整静态核查，发现并修复了 9 处"**没装 Qt 也能发现**"的问题——这些坑都是**真实项目**里会遇到的 Qt 工程常见错误，列出来当成一份"**写 Qt 时要绕开的雷**"：

| 严重度 | 问题 | 修复 |
|-------|------|------|
| 🔴 严重（直接编译失败） | `LibraryPage.h` 的槽签名 `onScanBatchFound(QVector<mp::MediaItem>)` 用了 `mp::MediaItem` 但没 include/前向声明 → `moc_LibraryPage.cpp` 展开时报 `'MediaItem' is not a member of namespace 'mp'` | `LibraryPage.h` 顶部补 `#include "types/MediaItem.h"` |
| 🟡 跨线程元类型 | `QVector<mp::MediaItem>` 作为 `Qt::QueuedConnection` 的 payload，但 `main.cpp` 只 `qRegisterMetaType<MediaItem>`——Qt 不保证自动展开 `QVector<T>` | `main.cpp` 补一行 `qRegisterMetaType<QVector<mp::MediaItem>>("QVector<mp::MediaItem>")` |
| 🟡 Qt 6.4 回退分支缺 include | `ThemeManager.cpp` 的 `#else` 分支用了 `QColor` 和 `QPalette` 但没显式 include，Qt 6.4 构建会炸 | 顶部加 `#include <QColor>` + `#include <QPalette>` |
| 🟡 CMake 版本坑 | `if(LINUX)` 要求 CMake **3.25+**；本工程最低 3.21 → 3.21-3.24 下 Linux 分支被静默跳过（§09 接 MPRIS 时才会发现） | 两处 `if(LINUX)` 全改成 `if(CMAKE_SYSTEM_NAME STREQUAL "Linux")` |
| 🟡 UX 一致性 | `PlayerBar` 整个左区（leftW）加了 PointingHandCursor，但只有封面 `m_cover` 发射 clicked 跳转 → 鼠标以为可点，点标题/艺术家没反应 | 去掉 leftW 的 setCursor，手型只给 cover |
| 🟡 死代码 | `SettingsPage` 的 `m_uiTick` 启动了但没连任何槽 | 删掉 QTimer 成员，剩余时间显示完全由 `SleepTimer::stateChanged` 驱动 |
| 🟢 优化 | `ProgressSlider::paintEvent` 的 `QFontMetrics fm` 定义了没用 → `-Wunused-variable` 噪声 | 改为用 fm 实际计算气泡宽（`horizontalAdvance(txt) + 14`） |
| 🟢 优化 | `LyricsParser` 的 `[offset:+200]`（含加号前缀）在部分区域设置下 `toLongLong` 会失败 | 解析前 `s.startsWith('+') && s.remove(0, 1)` |
| 🟢 优化 | `MediaRepository::removeById` 的三目运算符冗余（favorite 和 play_record 都是 `media_id`） | 简化为二元三目 |

**学到的套路**：

1. **AUTOMOC 的"头文件参数类型完整性"**：Qt 的 AUTOMOC 会以 `#include "YourWidget.h"` 开头生成 `moc_YourWidget.cpp`，所以**凡出现在信号槽签名里的类型，必须在该头文件可见**（include 或前向声明都行，但模板实例化通常需要完整类型）。这是比普通 C++ 更严格的 include 卫生要求。

2. **`qRegisterMetaType` 的"容器 payload"问题**：跨线程 `Qt::QueuedConnection` 投递 **容器类型**（`QVector<T>` / `QList<T>` / `QMap<...>`）时，Qt 需要**容器类型本身**的 meta 信息，不是只注册 T。实践经验：**容器化 payload 必须单独注册一遍**。

3. **CMake 内置变量的版本门槛**：`LINUX` / `BSD` / `IOS` 这几个"写起来方便"的内置变量都是 CMake 3.25+ 新增的。想兼容老 CMake 用 `CMAKE_SYSTEM_NAME STREQUAL "Linux"`——这也是 Kitware 官方文档的推荐写法。

4. **"手型光标"是 UX 契约**：鼠标变手型 = 用户期待可点击。任何加 `setCursor(Qt::PointingHandCursor)` 的区域都必须真的能响应点击，否则是 UX 事故。

## 01.本端选型说明

### 1.1 为什么是 Qt 6 Widgets 而不是 GTK / QML / Electron / 单平台原生

| 方案 | 跨桌面能力 | 评价 |
|------|----------|------|
| **Qt 6 Widgets** ⭐ | Linux/macOS/Windows 三端一等公民 | **选它**——QMediaPlayer 10 行出声；信号槽天然对应四端"状态广播"；CMake 一等公民；30 年工业验证 |
| Qt 6 QML | 同样三端 | 动效漂亮但与 UIKit/Vue 心智重叠度低；教学对照性弱 |
| GTK4 + GStreamer | Linux 一流，macOS/Windows 二等公民 | 跨平台质量不如 Qt；GStreamer 手动管线对新手过重 |
| Electron + Vue | 全平台 | **与本案例 Web 端完全重复**，零教学增量 |
| 各平台原生三份（WPF / AppKit / GTK） | — | 工作量 ×3；想体验这条路线可去 [07.挑战题](/pages/mp5more/) 的 WPF 版 |

### 1.2 Qt 跨桌面的真实价值

一份代码产出三份原生可执行文件的工程现实：

```text
mini_player_desktop/
├── CMakeLists.txt                ← 单一构建系统
├── src/                          ← 95% 共享代码（UI/播放/DB/扫描/歌词/EQ）
│   ├── ui/
│   ├── service/
│   └── data/
└── platform/                     ← 5% 平台特化（§09）
    ├── linux/MprisAdapter.cpp         ← D-Bus MPRIS
    ├── macos/MPNowPlayingAdapter.mm   ← Objective-C++ 混编
    └── windows/SmtcAdapter.cpp        ← C++/WinRT

构建产物：
  Linux   → ./MiniPlayer                   （ELF, ~15MB）
  macOS   → ./MiniPlayer.app               （Bundle, ~35MB 含 Qt 框架）
  Windows → ./MiniPlayer.exe               （PE + DLLs, ~40MB）
```

**95% 共享的根本原因**：

- **UI**：QWidget 本身就是跨平台抽象，`QMainWindow`/`QListView`/`QSlider` 在三端表现为原生外观；
- **音视频**：QMediaPlayer 底层按平台自动桥接——Linux→GStreamer / macOS→AVFoundation / Windows→Media Foundation；
- **数据库**：SQLite 跨平台 C 库，`QSqlDatabase` 三端二进制兼容；
- **异步**：QThread + 信号槽模型三端完全一致；
- **文件系统**：`std::filesystem` 与 `QFile` 已抽象路径分隔符与权限模型。

### 1.3 "跨桌面派" vs "原生派"的工程权衡

Qt 桌面是"**一份代码跨平台**"的工程路线。真实工程里还有另一条路——"**各平台原生三份**"（Windows 用 WPF/WinUI、macOS 用 AppKit/SwiftUI、Linux 用 GTK）：

| 维度 | Qt 跨桌面派（本篇） | 各平台原生派（如 WPF） |
|------|-------------------|---------------------|
| 跨平台 | ✅ 一份代码三端 | ❌ 每端各写一份 |
| 融入系统生态 | 良好（原生外观，但 Fluent/Material 深度不如原生） | 极致（动效、控件完全是系统亲儿子） |
| 包体积 | 稍大（含 Qt DLLs） | 极小（系统框架自带） |
| 启动速度 | 快（本机代码直接起） | 快（但 .NET 等有冷启动） |
| 工作量 | ×1 | ×3 |
| 招聘匹配 | 跨平台桌面岗位（WPS、VSCode、Figma 桌面） | 原生应用岗位（Office 插件、OA 系统） |

**本案例的选择**：主线用 Qt 覆盖三平台，想体验原生派路线（以 Windows WPF 为代表）去看 [07.挑战题](/pages/mp5more/) 的扩展篇——同样是 Windows，WPF 怎么在 Fluent UI、SMTC 融入、启动速度上做得更深。两条路线在真实工程里都存在，这正是教学价值所在。

### 1.4 Qt Multimedia 的真相：它只是"遥控器"

`QMediaPlayer` 不解码媒体——它是**平台媒体后端的统一遥控器**：

| 平台 | 实际后端 | 需要安装什么 |
|------|---------|-----------|
| Linux | **GStreamer** | `gstreamer1.0-plugins-good/bad/libav` |
| macOS | **AVFoundation**（同 iOS） | 系统自带，零安装 |
| Windows | **Media Foundation** | 系统自带（Win10 1809+） |

这个事实决定两件事：

1. 装环境必须按平台配好后端（Linux 最容易踩坑，§02 详述）；
2. 视频渲染用 `QVideoWidget`，我们不碰解码（与四端"不碰 FFmpeg"原则一致）。

## 03.MVP 骨架 【阶段①】

> 🎯 **阶段目标**：三端共用的 CMake 工程跑起来，一个按钮播放硬编码 mp3——**让"同一份代码三端出声"的 Qt 价值首次具身体感**。

**灵魂三问**：

> 1. `QApplication::exec()` 的事件循环和其他端的"主线程"是什么关系？（事件循环 = 心跳；堵住它 UI 就冻结，为 §04 后台扫描埋伏笔）
> 2. 为什么 Qt 的"hello world"也要 `app.exec()`？（信号槽/定时器/`QMediaPlayer` 的异步回调**全部**由这个循环驱动——不 `exec`，`QMediaPlayer::play()` 调完立刻析构）
> 3. `.pro` 与 `CMakeLists.txt` 为什么选后者？（Qt 6 官方已转向 CMake，三端 IDE 都原生支持；qmake 保留但不再新加能力）

### Step 3.1 CMake 工程骨架（三端一份）

Qt 6 的 CMake 支持是**原生一等公民**——`qt_add_executable` / `qt_add_resources` / `AUTOMOC` 一行开——不再是 qmake 时代的"额外适配层"。

创建 `code/App/mini-player-qt/CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.21)
project(MiniPlayer VERSION 0.1.0 LANGUAGES CXX)

# macOS 平台特化（§09 MPNowPlaying）要混 Obj-C++，提前开 OBJCXX
if(APPLE)
    enable_language(OBJCXX)
endif()

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# 信号槽 / 资源文件 / UI 文件自动预处理（省了手动 moc/rcc/uic）
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTORCC ON)
set(CMAKE_AUTOUIC ON)

# MSVC 中文源码必备：/utf-8（否则 C4819 警告 + 可能乱码）
if(MSVC)
    add_compile_options(/utf-8 /W3 /permissive-)
else()
    add_compile_options(-Wall -Wextra -Wpedantic)
endif()

# Qt 6 组件：Core/Gui/Widgets 是必选；Multimedia 管音视频；Sql 管 SQLite
find_package(Qt6 6.4 REQUIRED COMPONENTS
    Core Gui Widgets Multimedia MultimediaWidgets Sql
)

# Linux 需要 DBus（§09 MPRIS）；macOS/Windows 没这个组件
if(CMAKE_SYSTEM_NAME STREQUAL "Linux")
    find_package(Qt6 QUIET COMPONENTS DBus)
endif()

qt_standard_project_setup()
```

**关键决策**：

| 决策 | 为什么 |
|------|-------|
| `cmake_minimum_required 3.21` | 既支持 Qt 6 的 `qt_add_executable`，又兼容 Ubuntu 22.04（CMake 3.22）/ macOS Monterey |
| `AUTOMOC` 开到底 | Qt 的信号槽魔法靠 moc 预处理 `Q_OBJECT` 宏；CMake 自动检测**所有带 `Q_OBJECT` 的头文件**并产 moc 代码 |
| 不区分 `TARGET_LINK_LIBRARIES` 的 debug/release | Qt 6 的 CMake 已自动处理 |
| **不写** `if(APPLE)` 分支代码 | 本工程 95% 代码三端共用，5% 平台特化（§09）靠 `target_sources(... if ...)` 单独加 .cpp，不侵入 95% 主干 |

::: info 📎 对比 Web 工程的 `package.json`
Web 端用 Vite + pnpm，依赖声明在 JSON 里。桌面端用 CMake + 系统包管理器（brew/apt/vcpkg）。两者的本质都是"**告诉工具链去哪里找库**"，只是桌面端的库是 .so/.dylib/.dll 的原生动态库，Web 端是 .js 模块。
:::

### Step 3.2 核心数据模型 `MediaItem`

动手前先把"**一首歌/一个视频**"的类型敲定——四端共用的概念模型。创建 `src/types/MediaItem.h`：

```cpp
#pragma once

#include <QString>
#include <QMetaType>
#include <QDateTime>

namespace mp {

enum class MediaType { Audio, Video };

inline const char* toString(MediaType t) {
    return t == MediaType::Video ? "video" : "audio";
}
inline MediaType mediaTypeFromString(const QString& s) {
    return s == QStringLiteral("video") ? MediaType::Video : MediaType::Audio;
}

/** 数据模型 · MediaItem：音频/视频统一建模（对照架构篇 §1.3） */
struct MediaItem {
    /** 稳定 ID：path+size+mtime 的 SHA1 前 16 字节；重复导入 ID 一致 */
    QString id;
    MediaType type = MediaType::Audio;
    QString filePath;              // 绝对路径
    QString title;
    QString artist;
    QString album;
    qint64  durationMs = 0;
    qint64  sizeBytes  = 0;
    qint64  addedAt    = 0;        // Unix 秒
    QString coverPath;
    bool    exists     = true;     // 运行时字段（不入库）

    bool isValid() const { return !id.isEmpty() && !filePath.isEmpty(); }
};

/** 播放状态机：对照架构篇 §1.4 */
enum class PlaybackState { Idle, Loading, Playing, Paused, Ended, Error };

enum class LoopMode { Order, Single, Random };

} // namespace mp

// 让自定义类型可跨线程/信号槽/QVariant 传递
Q_DECLARE_METATYPE(mp::MediaItem)
Q_DECLARE_METATYPE(mp::PlaybackState)
Q_DECLARE_METATYPE(mp::LoopMode)
```

**三个"必做"决定**：

1. **`struct` 而非 `class`**：MediaItem 是**值语义数据**（没有身份、无需继承），`struct` 更直接；`QVector<MediaItem>` 复制/移动开销小
2. **`Q_DECLARE_METATYPE`**：这是让自定义类型能走 `QVariant` 和信号槽的注册宏；**仅声明不够**，`main.cpp` 还要调用 `qRegisterMetaType()`
3. **`namespace mp`**：全局命名空间防止和 Qt 自带的 `MediaMetadata` 之类冲突

::: tip 💡 四端对照
- Android: `data class MediaItem(...)` + Room `@Entity`
- iOS: `MediaItem : NSObject` + `NSSecureCoding`
- Web: `interface MediaItem {...}`（TypeScript）
- **Qt**: `struct` + `Q_DECLARE_METATYPE`
:::

### Step 3.3 入口 `main.cpp`

Qt 应用的 `main.cpp` 比其他端"显式"得多——数据库初始化、主题应用、QSS 加载都是你亲手调的，没有 Spring/依赖注入魔法。

创建 `src/main.cpp`：

```cpp
#include <QApplication>
#include <QFile>
#include <QDir>
#include <QStandardPaths>

#include "data/DbManager.h"
#include "service/ThemeManager.h"
#include "ui/MainWindow.h"
#include "types/MediaItem.h"

int main(int argc, char* argv[]) {
    // ---- 1. 注册自定义类型（跨线程传 QVector<MediaItem> 必备）----
    qRegisterMetaType<mp::MediaItem>("mp::MediaItem");
    qRegisterMetaType<mp::PlaybackState>("mp::PlaybackState");
    qRegisterMetaType<mp::LoopMode>("mp::LoopMode");
    // Qt 6 的 QVector 已是 QList 别名；两种名字都注册更稳
    qRegisterMetaType<QList<mp::MediaItem>>("QList<mp::MediaItem>");
    qRegisterMetaType<QVector<mp::MediaItem>>("QVector<mp::MediaItem>");

    QApplication app(argc, argv);

    // ---- 2. 组织信息（QSettings 和跨平台路径都靠这个）----
    QCoreApplication::setOrganizationName("YCCoding");
    QCoreApplication::setOrganizationDomain("yccoding.com");
    QCoreApplication::setApplicationName("MiniPlayer");
    QCoreApplication::setApplicationVersion("0.1.0");

    // ---- 3. 数据库初始化（跨三端的"写入位置"自动适配） ----
    // Linux  : ~/.local/share/MiniPlayer/library.db
    // macOS  : ~/Library/Application Support/MiniPlayer/library.db
    // Windows: %APPDATA%\MiniPlayer\library.db
    const QString dataDir = QStandardPaths::writableLocation(QStandardPaths::AppDataLocation);
    QDir().mkpath(dataDir);
    const QString dbPath = dataDir + QStringLiteral("/library.db");
    if (!mp::DbManager::instance().init(dbPath)) {
        qWarning("[main] 数据库初始化失败: %s", qUtf8Printable(dbPath));
        // 不致命——内存模式仍可运行
    }

    // ---- 4. 主题（深浅色自动跟随系统）----
    mp::ThemeManager::instance().applyInitial();

    // ---- 5. 全局 QSS（打包进 resources，运行时注入）----
    QFile qssFile(QStringLiteral(":/resources/style.qss"));
    if (qssFile.open(QIODevice::ReadOnly | QIODevice::Text)) {
        app.setStyleSheet(QString::fromUtf8(qssFile.readAll()));
    }

    // ---- 6. 主窗口 + 启动事件循环 ----
    mp::MainWindow w;
    w.resize(1200, 760);
    w.show();

    return app.exec();   // ← 这就是 Qt 的"心跳"
}
```

**理解 `app.exec()` 是关键**：

```text
┌─────────────────────────────────────────────────┐
│  app.exec() 开始阻塞在这里                        │
│   ├─ 分发所有鼠标/键盘事件给 Widget              │
│   ├─ 处理所有 QTimer 定时触发                    │
│   ├─ 分发所有信号槽（Qt::QueuedConnection）      │
│   ├─ 分发所有 QMediaPlayer 的 positionChanged   │
│   └─ 分发所有跨线程的 invokeMethod               │
│  ↓ 当最后一个窗口关闭/调用 app.quit() 时退出      │
│  return 到 main() 的末尾                         │
└─────────────────────────────────────────────────┘
```

::: warning ⚠️ 新手必踩的坑
如果你在 `app.exec()` **之前**调 `player.play()` 然后立刻 `return`，你会听不到任何声音——`QMediaPlayer` 的音频解码/输出全部由事件循环驱动，没有循环就等于"按了播放键就立刻关电源"。
:::

## 04.媒体扫描与列表 【阶段②】

> 🎯 **阶段目标**：选个目录能扫出所有音视频文件，走进后台线程不冻 UI，用 `QListView` 展示带封面的列表——**让 App "有东西可以播" 的第一步**。

**灵魂三问**：

> 1. 扫 10 万个文件为什么必须开线程？（主线程 = 事件循环 = UI 心跳；同步 I/O 直接把心跳锁死）
> 2. `std::filesystem::recursive_directory_iterator` vs `QDirIterator` 选哪个？（**选 QDirIterator**：对软链环更稳、原生 UTF-16 Windows 路径、Qt 对象信号链整合）
> 3. 为什么扫描只记路径不读 ID3？（**元数据 lazy**：首次播放时 QMediaPlayer 已经打开文件，顺手读 `QMediaMetaData` 回填——省掉大量 I/O 和外部 TagLib 依赖）

### Step 4.1 扫描器 `MediaScanner` 接口设计

创建 `src/data/MediaScanner.h`。关键是：**所有耗时方法都是 `public slot`**（可通过 `QMetaObject::invokeMethod` 跨线程调用），所有产出都走 **`signal`**：

```cpp
#pragma once

#include <QObject>
#include <QStringList>
#include <QAtomicInteger>
#include "types/MediaItem.h"

namespace mp {

class MediaScanner : public QObject {
    Q_OBJECT
public:
    explicit MediaScanner(QObject* parent = nullptr);

    /** 支持的扩展名（小写，含点） */
    static const QStringList& audioExts();
    static const QStringList& videoExts();

    /** 根据单文件绝对路径解析 MediaItem（可主线程直接调） */
    static MediaItem itemFromFile(const QString& absolutePath);

    /** 根据 path+size+mtime 组合生成稳定 id */
    static QString stableId(const QString& absolutePath, qint64 size, qint64 mtime);

public slots:
    /** 后台扫描：遍历目录（支持多个根），分批 emit found + progress + finished */
    void scanDirectories(const QStringList& roots);
    void cancel();

signals:
    void started(int roughTotalGuess);
    void progress(int done, int total);
    void batchFound(QVector<mp::MediaItem> items);
    void finished(int totalFound);
    void failed(const QString& reason);

private:
    QAtomicInteger<int> m_cancelled = 0;   // 跨线程安全取消标志
};

} // namespace mp
```

**4 个设计决定**：

| 决定 | 原因 |
|------|------|
| 继承 `QObject` 不继承 `QThread` | Qt 官方推荐：**worker 对象 `moveToThread`**，而不是 override `QThread::run()`；前者的信号槽机制更自然 |
| `scanDirectories` 是 `public slot` | 槽函数既可以当普通成员函数调，也能被 `invokeMethod(..., Qt::QueuedConnection, ...)` 跨线程异步投递 |
| 产出用 `signal batchFound(QVector<MediaItem>)` | 分批上报而不是一次性返回；UI 可以"扫一边显示一边" |
| `QAtomicInteger<int> m_cancelled` | 用户关窗/切目录时能立即取消；原子变量**不需要互斥锁** |

### Step 4.2 稳定 ID 算法

同一个文件被扫到两次时**必须生成相同 ID**（不然每次重启 App，SQLite 都认为是新文件）。实现 `MediaScanner::stableId`：

```cpp
// src/data/MediaScanner.cpp
#include "MediaScanner.h"

#include <QDirIterator>
#include <QFileInfo>
#include <QCryptographicHash>
#include <QDateTime>

namespace mp {

const QStringList& MediaScanner::audioExts() {
    static const QStringList L = { ".mp3", ".flac", ".m4a", ".aac", ".ogg", ".wav", ".opus" };
    return L;
}
const QStringList& MediaScanner::videoExts() {
    static const QStringList L = { ".mp4", ".mkv", ".mov", ".webm", ".m4v", ".avi" };
    return L;
}

QString MediaScanner::stableId(const QString& path, qint64 size, qint64 mtime) {
    const QByteArray input = (path + QString::number(size) + QString::number(mtime)).toUtf8();
    const QByteArray hash  = QCryptographicHash::hash(input, QCryptographicHash::Sha1);
    return QString::fromLatin1(hash.toHex().left(16));   // 16 字节足够唯一
}

} // namespace mp
```

**为什么是 `path + size + mtime`？**

- **仅 path**：用户复制一份到别处 → 两个 ID 相同，但其实是两个文件（如果 size 不同一样算一个）
- **仅 size + mtime**：巧合率太高（两首歌都是 4:32、5.1MB 并不罕见）
- **三者组合 + SHA1**：碰撞率 ≈ 0；重命名文件后 ID 变——这是**期望行为**（视为新文件）
- **只取前 16 字节**：128 位足够不冲突，字符串短好塞 URL/日志

::: tip 💡 四端对照
- Android: Room 的 `id = UUID.randomUUID()`（每次导入都新）→ 不如本方案"去重再导入"友好
- iOS: `MPMediaEntityPersistentID`（系统分配的 64 位 int）
- Web: `btoa(file.name + file.size + file.lastModified).slice(0, 16)`
- **Qt**: `SHA1(path+size+mtime).hex().left(16)` ✅
:::

### Step 4.3 单文件解析 `itemFromFile`

静态方法，拿到路径就能返回 MediaItem：

```cpp
static MediaType detectType(const QString& suffix) {
    const QString s = QStringLiteral(".") + suffix.toLower();
    if (MediaScanner::audioExts().contains(s)) return MediaType::Audio;
    if (MediaScanner::videoExts().contains(s)) return MediaType::Video;
    return MediaType::Audio;
}

MediaItem MediaScanner::itemFromFile(const QString& absolutePath) {
    MediaItem m;
    QFileInfo fi(absolutePath);
    if (!fi.exists() || !fi.isFile()) return m;

    const QString suffix = fi.suffix().toLower();
    const QString suffixDot = QStringLiteral(".") + suffix;
    if (!audioExts().contains(suffixDot) && !videoExts().contains(suffixDot)) {
        return m;   // 不认识的扩展名直接返回无效 MediaItem
    }

    const qint64 mtime = fi.lastModified().toSecsSinceEpoch();
    m.id          = stableId(absolutePath, fi.size(), mtime);
    m.type        = detectType(suffix);
    m.filePath    = absolutePath;
    m.title       = fi.completeBaseName();       // 不含扩展名的文件名
    m.artist      = QStringLiteral("Unknown");   // §05 播放时才有真元数据
    m.album       = QStringLiteral("Unknown");
    m.sizeBytes   = fi.size();
    m.addedAt     = QDateTime::currentSecsSinceEpoch();
    m.exists      = true;
    return m;
}
```

**关键取舍：标题先用文件名**。这里**不**调用 TagLib——首次播放时 QMediaPlayer 自带解码能力，会把 `QMediaMetaData` 填好；§05 `onMediaStatusChanged` 里拿到后回写库即可。这省掉了：

- 一个外部 C++ 依赖（TagLib）
- 扫描时的大量 I/O（每个 mp3 文件都要读前 10KB 的 ID3 头）
- 跨平台兼容性问题（TagLib 在 Windows 需要特殊编译配置）

### Step 4.4 后台扫描 `scanDirectories`

这是本阶段最关键的函数——**正确处理"UI 不冻结 + 可取消 + 分批上报"三件事**：

```cpp
void MediaScanner::cancel() { m_cancelled.storeRelaxed(1); }

void MediaScanner::scanDirectories(const QStringList& roots) {
    m_cancelled.storeRelaxed(0);
    emit started(roots.size());

    // 组装名称过滤器（供 QDirIterator）
    QStringList namedFilters;
    namedFilters.reserve(audioExts().size() + videoExts().size());
    for (const QString& e : audioExts()) namedFilters << QStringLiteral("*%1").arg(e);
    for (const QString& e : videoExts()) namedFilters << QStringLiteral("*%1").arg(e);

    QVector<MediaItem> batch;
    batch.reserve(64);
    int totalFound = 0;
    int seen = 0;
    constexpr int kBatchSize = 32;

    for (const QString& root : roots) {
        if (!QFileInfo(root).isDir()) continue;
        QDirIterator it(root, namedFilters,
                        QDir::Files | QDir::Readable | QDir::NoDotAndDotDot,
                        QDirIterator::Subdirectories | QDirIterator::FollowSymlinks);

        while (it.hasNext()) {
            // 1️⃣ 取消检查：下一个文件边界
            if (m_cancelled.loadRelaxed()) {
                if (!batch.isEmpty()) emit batchFound(batch);
                emit finished(totalFound);
                return;
            }
            it.next();
            const QString absPath = it.filePath();
            const MediaItem m = itemFromFile(absPath);
            if (m.isValid()) {
                batch.push_back(m);
                ++totalFound;
            }
            ++seen;
            // 2️⃣ 分批 emit：每 32 条上报一次（节流）
            if (batch.size() >= kBatchSize) {
                emit batchFound(batch);
                batch.clear();
                emit progress(totalFound, seen);
            }
        }
    }
    // 3️⃣ 收尾：最后不满一批的也要 emit
    if (!batch.isEmpty()) emit batchFound(batch);
    emit progress(totalFound, seen);
    emit finished(totalFound);
}
```

**三个精妙之处**：

1. **`QDirIterator` 名称过滤器**：Qt 内部走操作系统原生 API（`FindFirstFile` / `readdir`），比 `std::filesystem` 对 Windows UTF-16 路径更稳
2. **`kBatchSize = 32`**：这是**信号槽频率节流**——如果每个文件 emit 一次，UI 线程队列会被 10 万条信号撑爆（Qt::QueuedConnection 的 push 本身也有开销）
3. **`m_cancelled` 不加锁**：`QAtomicInteger` 的原子 load/store 比互斥锁快 10 倍以上；"**可能延迟 1 个文件才取消**"是可以接受的——反正用户按取消的时候眨个眼也 1 个文件了

### Step 4.5 LibraryPage：挂载 Scanner 到后台线程

重头戏来了。创建 `src/ui/LibraryPage.cpp` 的扫描触发部分：

```cpp
#include "LibraryPage.h"
#include "data/MediaRepository.h"
#include "data/MediaScanner.h"
#include "components/ToastHost.h"

#include <QFileDialog>
#include <QStandardPaths>
#include <QThread>

void LibraryPage::onImportDirectory() {
    // 1️⃣ 默认目录：三端自动对（Music vs Movies 的差异 QStandardPaths 处理）
    const QString defaultDir = QStandardPaths::writableLocation(QStandardPaths::MusicLocation);
    const QString dir = QFileDialog::getExistingDirectory(this, tr("选择要扫描的媒体目录"), defaultDir);
    if (dir.isEmpty()) return;

    // 2️⃣ 清理旧 scanner（若还在跑，取消并等）
    if (m_scanThread) {
        if (m_scanner) m_scanner->cancel();
        m_scanThread->quit();
        m_scanThread->wait(1000);
        m_scanThread->deleteLater();
        m_scanThread = nullptr;
        m_scanner = nullptr;
    }

    // 3️⃣ 新建 QThread + 把 worker move 过去（不要 setParent 到 QThread，这不等于 moveToThread）
    m_scanThread = new QThread(this);
    m_scanner    = new MediaScanner();          // ⚠️ 不设 parent：parent 必须和 scanner 同线程
    m_scanner->moveToThread(m_scanThread);

    // 线程退出时自动删除 scanner
    connect(m_scanThread, &QThread::finished, m_scanner, &QObject::deleteLater);

    // 4️⃣ 跨线程信号槽（默认 Qt::AutoConnection = 跨线程时自动走 Queued，到 UI 线程才执行槽）
    connect(m_scanner, &MediaScanner::batchFound, this, &LibraryPage::onScanBatchFound);
    connect(m_scanner, &MediaScanner::finished,   this, &LibraryPage::onScanFinished);
    connect(m_scanner, &MediaScanner::started, this, [this](int){
        m_statusLabel->setText(tr("正在扫描目录..."));
    });
    connect(m_scanner, &MediaScanner::progress, this, [this](int done, int /*total*/){
        m_statusLabel->setText(tr("已发现 %1 个媒体文件...").arg(done));
    });

    // 5️⃣ 启动线程 + 通过 QMetaObject::invokeMethod 触发槽（跨线程调用的正道）
    m_scanThread->start();
    QMetaObject::invokeMethod(m_scanner, "scanDirectories",
                              Qt::QueuedConnection,
                              Q_ARG(QStringList, { dir }));
    ToastHost::instance()->show(tr("开始扫描: ") + dir, ToastHost::Info);
}

void LibraryPage::onScanBatchFound(QVector<MediaItem> items) {
    if (items.isEmpty()) return;
    m_repo->upsertBatch(items);   // 批量入 SQLite（§06）
}

void LibraryPage::onScanFinished(int total) {
    ToastHost::instance()->show(tr("扫描完成，共导入/更新 %1 条").arg(total), ToastHost::Success);
    if (m_scanThread) {
        m_scanThread->quit();
        m_scanThread->wait(1500);
        m_scanThread->deleteLater();
        m_scanThread = nullptr;
        m_scanner = nullptr;
    }
    reload();   // 从 SQLite 重新读列表
}
```

**跨线程信号槽的本质**：

```text
[Scanner Thread]                         [UI Thread]
  emit batchFound(items) ──┐
                           │
           Qt 内部的 EventQueue 投递
                           │
                           └──→ Event Loop 下一轮
                                 └→ 调用 onScanBatchFound(items)
                                     ← 槽函数在 UI 线程执行
```

**精髓**：`items` 这个 `QVector<MediaItem>` 会被 **Qt 自动跨线程拷贝一份**（这就是 §03 `main.cpp` 里 `qRegisterMetaType<QVector<MediaItem>>` 的用武之地）。你**不需要**手动加锁！

### Step 4.6 Model/View/Delegate：封面列表

**9 个自定义 Role** 的 `data()` 实现一次把每个字段都暴露出来——这样 `QListView` + `QStyledItemDelegate` 可以通过 `index.data(TitleRole)` 直接拿到类型安全的值，而不是像 Web 端那样 `item.title`。

然后在 `LibraryPage` 里装配：

```cpp
m_model    = new MediaListModel(this);

m_list     = new QListView(this);

m_list->setItemDelegate(m_delegate);

```

- `setUniformItemSizes(true)` → QListView 认定所有 row 等高，**可以 O(1) 定位第 N 行的 y 坐标**，10 万行滚动不卡
- `setVerticalScrollMode(ScrollPerPixel)` → 像素级滚动而不是行级跳（和 macOS/现代浏览器一致的手感）

### Step 4.7 ⚠️ "造 BUG" 实验（强烈推荐亲手做）

把 `onImportDirectory` 里的 `QMetaObject::invokeMethod(..., Qt::QueuedConnection, ...)` 临时换成**同步直接调用**：


## 05.播放控制与状态管理 【阶段③⭐】

> 🎯 **阶段目标**：封装 `PlayerService` 这个"心脏类"——UI 层只通过它调播放/暂停/跳转/音量，engine（`QMediaPlayer`）的事件翻译为语义级信号。再加上一个**自绘的 ProgressSlider**，就有了 90% 可用的播放体验。

**灵魂三问**：

> 1. 四端里谁的"状态广播机制"最优雅？（**Qt 信号槽**：类型安全 + 自动跨线程 + 编译期检查——这是本章对照核心）
> 2. `QMediaPlayer` 的状态/错误信号新旧并存，连接哪个？（Qt 5 的 `error(QMediaPlayer::Error)` 已废弃，Qt 6 用 `errorOccurred(err, string)`）
> 3. 播放模式决策树放 Service 还是 UI？（**放 Service**：Random/Order/Single 是数据层概念，UI 只负责显示当前模式和触发切换）

### Step 5.2 构造函数：接 engine 事件

构造函数要做的是**接 `QMediaPlayer` 五个信号 + 启动节流 timer + 从 SQLite 恢复音量/循环模式**：

### Step 5.3 200ms 节流：避免 UI 洪水刷

`QMediaPlayer::positionChanged` 的频率在不同平台不同（Linux GStreamer 大约 10Hz，macOS AVFoundation 大约 30Hz，Windows MF 不固定）。**UI 一秒重绘 30 次完全没必要**（人眼看进度条 5Hz 都够了），但却**非常伤笔记本电池**。

节流策略：

```cpp
void PlayerService::onEnginePositionChanged(qint64 posMs) {
    if (m_seeking) return;     // 拖动期间不被覆盖（Step 5.4）
    m_positionMs = posMs;
    // 不在这里 emit —— 由 200ms 节流 tick 发射
}

void PlayerService::onTick() {
    if (!m_seeking) emit positionChanged(m_positionMs);
    // 每 5 秒记一次断点（§06 断点续播）
    const qint64 now = QDateTime::currentMSecsSinceEpoch();
    if (now - m_lastRecordedAtMs >= 5000 && m_current.isValid() && m_repo) {
        m_repo->recordPlay(m_current.id, m_positionMs);
        m_lastRecordedAtMs = now;
    }
}

void PlayerService::setState(PlaybackState s) {
    if (m_state == s) return;
    m_state = s;
    emit stateChanged(s);
    // 关键：Playing 时启动 ticker，其它状态停
    if (s == PlaybackState::Playing) {
        if (!m_ticker->isActive()) m_ticker->start();
    } else {
        m_ticker->stop();
    }
}
```

**精髓**：

- engine 的 `positionChanged` 只负责**更新内存变量**（`m_positionMs`）
- UI 的 `positionChanged` 由 **200ms QTimer 节流后发射**
- 暂停/停止时 ticker 停了，**既不浪费 CPU 也不触发 UI 重绘**

::: tip 💡 四端对照：位置节流
- Android: `MainHandler.postDelayed(this, 200)` 自己循环
- iOS: `AVPlayer.periodicTimeObserver(forInterval: CMTime(0.2))` 系统提供
- Web: `requestAnimationFrame` + 节流闭包
- **Qt**: `QTimer::setInterval(200)` + `setState` 里控制开关
:::

### Step 5.4 ⭐ seek 标志位：四端同款坑

**问题**：用户拖进度条到 50% 位置，engine 还在上报 "当前 10 秒" 的旧位置 —— 拖拽体验瞬间"回弹"。

**解决**：UI 在**开始拖动的瞬间**设置标志位 `m_seeking = true`，释放时清除。期间任何 engine 位置上报都被过滤。

```cpp
void PlayerService::seek(qint64 ms) {
    if (m_durationMs <= 0) return;
    ms = qBound<qint64>(0, ms, m_durationMs);
    m_player->setPosition(ms);
    m_positionMs = ms;
    emit positionChanged(ms);
}

void PlayerService::onEnginePositionChanged(qint64 posMs) {
    if (m_seeking) return;    // ← 关键这一行
    m_positionMs = posMs;
}
```

UI 侧的 ProgressSlider 会在**鼠标按下时**调 `setSeeking(true)`，**释放时**先 `seek(ms)` 再 `setSeeking(false)`。

**四端 Bug 对照**（这是**所有端都会踩**的坑）：

| 端 | 症状 | 修复 |
|---|------|------|
| Android ExoPlayer | 拖拽回弹 100-300ms | `isSeeking` 标志 + 释放时触发 seekTo |
| iOS AVPlayer | 拖拽回弹（periodicTimeObserver 覆盖） | `isDragging` + stop observer during drag |
| Web `<audio>` | timeupdate 事件覆盖 | `isSeeking` + sliderPressed/sliderReleased |
| **Qt QMediaPlayer** | 一样回弹 | `m_seeking` 标志 + `onEnginePositionChanged` 开头过滤 ✅ |

### Step 5.5 播放模式决策树

`next()` 的核心：根据 `LoopMode` 和"是否自动触发"（auto_=true 表示 `EndOfMedia`），决定下一首是哪首：

```cpp
void PlayerService::next(bool auto_) {
    if (m_queue.isEmpty() || !m_current.isValid()) return;
    int idx = -1;
    for (int i = 0; i < m_queue.size(); ++i)
        if (m_queue[i].id == m_current.id) { idx = i; break; }
    if (idx < 0) return;

    int nextIdx = 0;
    if (auto_ && m_loopMode == LoopMode::Single) {
        // 单曲循环 + 自动触发 → 重放当前
        nextIdx = idx;
    } else if (m_loopMode == LoopMode::Random) {
        // 随机 → 任选一个非当前
        if (m_queue.size() == 1) { nextIdx = 0; }
        else {
            do { nextIdx = QRandomGenerator::global()->bounded(m_queue.size()); }
            while (nextIdx == idx);
        }
    } else {
        // 顺序 / 单曲+手动点下一首 → 顺着来
        nextIdx = (idx + 1) % m_queue.size();
    }
    const MediaItem tgt = m_queue[nextIdx];
    m_current = tgt;
    emit currentChanged(m_current);
    m_positionMs = 0;
    emit positionChanged(0);
    loadIntoEngine(tgt, true);
    persistQueueAndPosition();
}

void PlayerService::previous() {
    if (m_queue.isEmpty() || !m_current.isValid()) return;
    // > 3s 回到开头（音乐软件惯例，四端一致）
    if (m_positionMs > 3000) { seek(0); return; }
    int idx = -1;
    for (int i = 0; i < m_queue.size(); ++i)
        if (m_queue[i].id == m_current.id) { idx = i; break; }
    if (idx < 0) return;
    const int prev = (idx - 1 + m_queue.size()) % m_queue.size();
    const MediaItem tgt = m_queue[prev];
    // ... (同 next 的更新代码)
}
```

**决策树口诀**："自动 + 单曲 → 重放；随机 → bounded 排除当前；其它 → `(idx+1) % n`"。

**"> 3s 回开头"** 是所有主流音乐软件（iTunes/网易云/千千静听/Spotify）的惯例——用户按"上一首"大概率是想"重听当前"，仅在前 3 秒按才认为是真的往回切。

### Step 5.6 lazy 元数据回填

扫描阶段只记文件名（§04 决定不读 TagLib）。真正的 ID3 元数据在**首次播放的那一刻** QMediaPlayer 已经打开文件，顺手拿到了——这就是 `onMediaStatusChanged` 里 `LoadedMedia` 分支的用武之地：

```cpp
void PlayerService::onMediaStatusChanged(QMediaPlayer::MediaStatus st) {
    switch (st) {
        case QMediaPlayer::LoadingMedia:
            setState(PlaybackState::Loading);
            break;
        case QMediaPlayer::LoadedMedia:
        case QMediaPlayer::BufferedMedia: {
            // ---- 元数据到位：回填 Title/Artist/Album/Duration ----
            if (m_repo && m_current.isValid()) {
                const QMediaMetaData md = m_player->metaData();
                const QString title  = md.stringValue(QMediaMetaData::Title);
                const QString artist = md.stringValue(QMediaMetaData::ContributingArtist).isEmpty()
                                       ? md.stringValue(QMediaMetaData::AlbumArtist)
                                       : md.stringValue(QMediaMetaData::ContributingArtist);
                const QString album  = md.stringValue(QMediaMetaData::AlbumTitle);
                const qint64  dur    = m_player->duration();
                m_repo->upsertMetadata(m_current.id, title, artist, album, dur);
                // 更新内存快照 → UI 据此刷新显示
                if (!title.isEmpty())  m_current.title  = title;
                if (!artist.isEmpty()) m_current.artist = artist;
                if (!album.isEmpty())  m_current.album  = album;
                m_current.durationMs = dur;
                emit metadataResolved(m_current);
            }
            break;
        }
        case QMediaPlayer::EndOfMedia:
            setState(PlaybackState::Ended);
            next(true);     // 自动触发 → 走 §5.5 决策树
            break;
        case QMediaPlayer::InvalidMedia:
            m_errorText = tr("无效的媒体（格式不支持或文件损坏）");
            emit errorOccurred(m_errorText);
            setState(PlaybackState::Error);
            break;
        default: break;
    }
}
```

**巧妙之处**：`upsertMetadata` 用 `COALESCE(NULLIF(:title, ''), title)` SQL——**空值不覆盖已有值**，避免某些格式元数据不全时反而覆盖掉之前的信息。

### Step 5.7 自绘 `ProgressSlider`：进度条的现代做法

Qt 自带 `QSlider` 的样式**用 QSS 能美化到 70%**，但：

- 渐变 fill + 顶部 1px 高光 → QSS 搞不定
- hover 时轨道变粗（4px→8px）→ QSS 搞不定
- 拖动时 thumb 外画光环 → QSS 搞不定
- 悬浮显示 "时间气泡"（Spotify 风） → QSS 根本做不到

答案：**继承 `QWidget` 全自绘**。核心是 `paintEvent` 把"底轨 → fill → thumb → bubble"四层按顺序画出来：

```cpp
// src/ui/components/ProgressSlider.cpp（节选 paintEvent）
void ProgressSlider::paintEvent(QPaintEvent*) {
    QPainter p(this);
    p.setRenderHint(QPainter::Antialiasing);

    const qreal pct = (m_durationMs > 0)
        ? static_cast<qreal>(m_dragging ? m_draftMs : m_positionMs) / m_durationMs
        : 0.0;
    const int W = width();
    const int H = height();

    // 1️⃣ 底轨（hover 时变粗）
    const int railHCur = (m_hovering || m_dragging) ? 8 : 4;
    const int railY = (H - railHCur) / 2;
    QPainterPath railPath;
    railPath.addRoundedRect(QRectF(0, railY, W, railHCur), railHCur/2.0, railHCur/2.0);
    p.fillPath(railPath, QColor(0, 0, 0, 24));

    // 2️⃣ Fill（紫粉渐变）
    const int fillW = static_cast<int>(W * pct + 0.5);
    if (fillW > 0) {
        QPainterPath fillPath;
        fillPath.addRoundedRect(QRectF(0, railY, fillW, railHCur), railHCur/2.0, railHCur/2.0);
        QLinearGradient grad(0, 0, W, 0);
        grad.setColorAt(0.0, QColor(0x8b, 0x5c, 0xf6));   // brand-1 紫
        grad.setColorAt(1.0, QColor(0xec, 0x48, 0x99));   // brand-2 粉
        p.fillPath(fillPath, grad);
        // 顶部 1px 高光
        p.fillRect(QRectF(0, railY, fillW, 1), QColor(255, 255, 255, 80));
    }

    // 3️⃣ Thumb（hover / dragging / focus 时才显示）
    if (m_hovering || m_dragging || hasFocus()) {
        const int cx = static_cast<int>(W * pct + 0.5);
        const int cy = H / 2;
        qreal d = 14;
        if (m_dragging) d *= 1.25;
        QRectF thumbR(cx - d/2.0, cy - d/2.0, d, d);
        if (m_dragging) {
            // 外圈光环
            p.setBrush(QColor(0x8b, 0x5c, 0xf6, 60));
            p.setPen(Qt::NoPen);
            qreal halo = d + 10;
            p.drawEllipse(QRectF(cx - halo/2.0, cy - halo/2.0, halo, halo));
        }
        p.setBrush(Qt::white);
        p.setPen(QPen(QColor(0xec, 0x48, 0x99), 2.5));
        p.drawEllipse(thumbR);
    }

    // 4️⃣ 悬浮时间气泡
    if (m_hovering && !m_dragging && m_durationMs > 0) {
        const qreal r = qBound(0.0, m_hoverPos.x() / W, 1.0);
        const qint64 ms = static_cast<qint64>(r * m_durationMs);
        const int mm = int(ms / 60000);
        const int ss = int((ms / 1000) % 60);
        const QString txt = QStringLiteral("%1:%2")
                               .arg(mm, 1, 10, QChar('0'))
                               .arg(ss, 2, 10, QChar('0'));
        // ... 画圆角矩形 + 文字（略）
    }
}
```

鼠标事件三件套：


## 06.本地持久化 SQLite 【阶段④】

> 🎯 **阶段目标**：所有扫描结果、播放历史、收藏、设置项都落到 SQLite；关掉 App 再开，媒体库、历史、断点、音量全部一行代码不丢。

**灵魂三问**：

> 1. 为什么选 `QSqlDatabase` 而不是 SQLite C API 或 ORM？（**中间最优**：类型安全 + 自动 bind + 日志；比裸 API 省 60% 代码，比 ORM 少 2 层间接性）
> 2. **参数绑定** vs 字符串拼接——不就是转义不转义吗？（**不仅是转义**：绑定走 driver 的二进制协议，根本就不用担心字符内容；拼接是 2024 年还会被 OWASP Top-1 的"SQL 注入"源头）
> 3. 需要迁移脚本吗？（**v0.1 还不需要**：`CREATE TABLE IF NOT EXISTS` + `ON CONFLICT DO UPDATE` 已经吸收了"幂等建表 + 幂等 upsert"。真正要加字段时再考虑 `PRAGMA user_version` 迁移）

### Step 6.1 三种访问 SQLite 的姿势对比

| 姿势 | 代码量 | 类型安全 | 跨平台 | 推荐度 |
|-----|-------|---------|-------|-------|
| SQLite C API (`sqlite3_prepare_v2`) | ★★★★★ 很多 | ★ 全走 void* | 需手动链接 libsqlite3 | ⭐ 底层学习用 |
| ORM（如 QxOrm/sqlpp11） | ★ 少 | ★★★★★ | ★★★★ 看库 | ⭐⭐ 本案例体量用不上 |
| **`QSqlDatabase`** | ★★ 中 | ★★★ `QVariant` 转换 | ★★★★★ Qt 自带 | ⭐⭐⭐⭐⭐ |

本工程选 `QSqlDatabase`：Qt 内置、零额外依赖、"预处理语句 + 参数绑定" 的现代 SQL 实践一行不少。

```cpp
#include "DbManager.h"
#include <QSqlQuery>
#include <QSqlError>
#include <QFileInfo>
#include <QDebug>

namespace mp {

DbManager& DbManager::instance() {
    static DbManager inst;      // Meyers Singleton，C++11 保证线程安全
    return inst;
}

DbManager::DbManager() = default;

bool DbManager::init(const QString& dbFilePath) {
    if (m_opened) return true;    // 幂等
    m_path = dbFilePath;

    QSqlDatabase db;
    if (QSqlDatabase::contains()) {    // 用默认连接名
        db = QSqlDatabase::database();
    } else {
        db = QSqlDatabase::addDatabase(QStringLiteral("QSQLITE"));
    }
    db.setDatabaseName(dbFilePath);
    if (!db.open()) {
        qCritical() << "[DbManager] 打开数据库失败:" << db.lastError().text();
        return false;
    }

    m_opened = true;
    if (!applyPragmas())   qWarning() << "[DbManager] 应用 pragma 失败";
    if (!createTables())   qWarning() << "[DbManager] 建表失败";
    qInfo() << "[DbManager] 已打开数据库:" << dbFilePath;
    return true;
}

QSqlDatabase DbManager::database() const { return QSqlDatabase::database(); }
bool DbManager::isOpen() const { return m_opened && database().isOpen(); }
```

**三个要点**：

1. **Meyers Singleton**：`static` 局部变量 → C++11 保证"**线程安全的首次初始化**"
2. **默认连接名**（不传第二参数）：Qt 6 的 `QSqlDatabase` 默认连接**可以跨线程**使用（Qt 5 需要每线程一个）
3. **幂等 `init`**：`m_opened` 守卫，多次调用不会出错

### Step 6.3 关键 PRAGMA：WAL + synchronous=NORMAL

```cpp
bool DbManager::applyPragmas() {
    QSqlQuery q(database());
    // 写日志旁路——写入时不阻塞读（关键 pragma）
    if (!q.exec(QStringLiteral("PRAGMA journal_mode = WAL"))) return false;
    // 比 FULL 快 2 倍，比 OFF 更安全
    if (!q.exec(QStringLiteral("PRAGMA synchronous = NORMAL"))) return false;
    // 启用外键（SQLite 默认关的 ！）
    if (!q.exec(QStringLiteral("PRAGMA foreign_keys = ON"))) return false;
    return true;
}
```

**三个 PRAGMA 的作用**：

| PRAGMA | 效果 | 代价 |
|--------|------|------|
| `journal_mode = WAL` | 写日志旁路——写入时不阻塞读；读/写可并发 | 多出一个 `.db-wal` 文件 |
| `synchronous = NORMAL` | 不等每次 fsync；崩溃可能丢最后几事务 | 丢的是"最近 1 秒的播放历史"，可接受 |
| `foreign_keys = ON` | 启用外键约束 | SQLite 默认是关的（兼容老代码），所以每次都要开 |

```cpp
        QStringLiteral(

            "  media_id TEXT PRIMARY KEY,"
            "  added_at INTEGER NOT NULL"
            ")"),

        // 4. 全局 KV 设置（音量、循环模式、主题……）
        QStringLiteral(

            "  k TEXT PRIMARY KEY,"
            "  v TEXT NOT NULL"
            ")"),
    };

    for (const QString& sql : ddl) {
        if (!q.exec(sql)) {
            qCritical() << "[DbManager] 建表失败:" << q.lastError().text() << "\n  SQL:" << sql;
            return false;

    return true;
```

**4 张表的 schema 对照架构篇 §1.5**。三个细节：

2. **`file_path TEXT NOT NULL UNIQUE`**：双保险，防手动改 ID

**关键是 `upsertBatch`——这是扫描完 32 条批量入库的函数**，用 `ON CONFLICT DO UPDATE` 做幂等 upsert + 一个事务包起来：

```cpp
bool MediaRepository::upsertBatch(const QVector<MediaItem>& items) {
    if (items.isEmpty()) return true;
    QSqlDatabase db = DbManager::instance().database();
    if (!db.transaction()) return false;      // ⭐ 事务开始

    QSqlQuery q(db);
    q.prepare(QStringLiteral(
        "INSERT INTO media (id, type, file_path, title, artist, album,"
        "  duration_ms, size_bytes, cover_path, added_at) "
        "VALUES (:id, :type, :path, :title, :artist, :album,"
        "  :dur, :size, :cover, :added) "
        "ON CONFLICT(id) DO UPDATE SET "          // ⭐ 幂等 upsert
        "  title=excluded.title, artist=excluded.artist, album=excluded.album,"
        "  duration_ms=excluded.duration_ms, size_bytes=excluded.size_bytes,"
        "  cover_path=excluded.cover_path"));

    for (const auto& m : items) {
        q.bindValue(":id",     m.id);
        q.bindValue(":type",   QString::fromLatin1(toString(m.type)));
        q.bindValue(":path",   m.filePath);
        q.bindValue(":title",  m.title);
        q.bindValue(":artist", m.artist);
        q.bindValue(":album",  m.album);
        q.bindValue(":dur",    m.durationMs);
        q.bindValue(":size",   m.sizeBytes);
        q.bindValue(":cover",  m.coverPath);
        q.bindValue(":added",  m.addedAt);
        if (!q.exec()) {
            qWarning() << "[Repo] upsert 失败:" << q.lastError().text();
            db.rollback();                      // ⭐ 失败回滚
            return false;
        }
    }
    return db.commit();                         // ⭐ 全部成功才提交
}
```

**事务的三个作用**：

1. **原子性**：32 条批量要么全成要么全不成，不会出现"一半是新的一半是旧的"
2. **性能**：SQLite 单条 INSERT 要 `fsync` 一次（WAL 下也是），32 条打包成一个 fsync 快 30 倍
3. **崩溃安全**：扫到一半进程被 kill，WAL 不会把残缺的事务应用到主库

### Step 6.6 元数据只覆盖非空值

`upsertMetadata` 是 §05 PlayerService 首次播放时回填用的——**空值不覆盖**是关键：

```cpp
bool MediaRepository::upsertMetadata(const QString& id, const QString& title,
                                      const QString& artist, const QString& album,
                                      qint64 durationMs) {
    QSqlQuery q(DbManager::instance().database());
    q.prepare(QStringLiteral(
        "UPDATE media SET"
        "  title  = COALESCE(NULLIF(:title, ''), title),"      // ⭐ 空值不覆盖
        "  artist = COALESCE(NULLIF(:artist, ''), artist),"
        "  album  = COALESCE(NULLIF(:album, ''), album),"
        "  duration_ms = CASE WHEN :dur > 0 THEN :dur ELSE duration_ms END "
        "WHERE id = :id"));
    q.bindValue(":title",  title);
    q.bindValue(":artist", artist);
    q.bindValue(":album",  album);
    q.bindValue(":dur",    durationMs);
    q.bindValue(":id",     id);
    return q.exec();
}
```

**SQL 技巧**：

- `NULLIF(:title, '')` → 空字符串转 NULL
- `COALESCE(NULL, title)` → 用旧值
- 组合效果：**只有 `:title` 不为空字符串时才覆盖**

这避免了"某些 FLAC 文件 artist 元数据缺失 → 覆盖掉之前已经手动改好的 artist"的恶性 bug。

### Step 6.7 搜索：绑定变量防 SQL 注入

```cpp
QVector<MediaItem> MediaRepository::search(const QString& keyword) {
    QVector<MediaItem> out;
    if (keyword.trimmed().isEmpty()) return out;
    QSqlQuery q(DbManager::instance().database());
    q.prepare(QStringLiteral(
        "SELECT %1 FROM media "
        "WHERE title LIKE :kw OR artist LIKE :kw OR album LIKE :kw OR file_path LIKE :kw "
        "ORDER BY added_at DESC").arg(QString::fromLatin1(kSelectCols)));

    // ⭐ bindValue 走 driver 的参数通道，根本就不走字符串
    q.bindValue(":kw", QStringLiteral("%%%1%%").arg(keyword.trimmed()));

    if (!q.exec()) { qWarning() << q.lastError().text(); return out; }
    while (q.next()) out.push_back(rowToItem(q));
    return out;
}
```

**为什么说 `bindValue` 比字符串转义更安全**？

- 字符串拼接：`"WHERE title LIKE '%" + userInput + "%'"` → 用户输入 `' OR 1=1 --` 直接拖库
- 字符串转义：`"WHERE title LIKE '%" + escape(userInput) + "%'"` → 依赖你的 `escape` 函数正确（90% 的历史 CVE 都是这里出错）
- **参数绑定**：`WHERE title LIKE :kw` + `bindValue(":kw", userInput)` → SQL 语法和用户数据**走两条通道**，根本不会被当成 SQL 执行

**全工程 100% 绑定变量**——这是 2024 年所有数据库代码的最低标准。

### Step 6.8 断点续播闭环

断点续播的三个点在三个文件里联动：

```cpp
// 1. PlayerService::onTick（§05）：每 5 秒记一次位置
void PlayerService::onTick() {
    if (!m_seeking) emit positionChanged(m_positionMs);
    const qint64 now = QDateTime::currentMSecsSinceEpoch();
    if (now - m_lastRecordedAtMs >= 5000 && m_current.isValid() && m_repo) {
        m_repo->recordPlay(m_current.id, m_positionMs);   // ← 这里
        m_lastRecordedAtMs = now;
    }
}

// 2. MediaRepository::recordPlay：INSERT 一行
bool MediaRepository::recordPlay(const QString& id, qint64 positionMs) {
    QSqlQuery q(DbManager::instance().database());
    q.prepare(QStringLiteral(
        "INSERT INTO play_record (id, media_id, position_ms, played_at) "
        "VALUES (:rid, :mid, :pos, :t)"));
    q.bindValue(":rid", QUuid::createUuid().toString(QUuid::WithoutBraces));
    q.bindValue(":mid", id);
    q.bindValue(":pos", positionMs);
    q.bindValue(":t",   QDateTime::currentSecsSinceEpoch());
    return q.exec();
}

// 3. MediaRepository::lastPosition：下次播放前查
qint64 MediaRepository::lastPosition(const QString& id) {
    QSqlQuery q(DbManager::instance().database());
    q.prepare(QStringLiteral(
        "SELECT position_ms FROM play_record WHERE media_id = :id "
        "ORDER BY played_at DESC LIMIT 1"));
    q.bindValue(":id", id);
    if (!q.exec() || !q.next()) return 0;
    return q.value(0).toLongLong();
}
```

## 07.LRC 歌词同步 【阶段⑥】

> 🎯 **阶段目标**：加载 .lrc 文件 → 解析时间戳 → 自绘滚动高亮 → 点击任意行跳播。全部用 Qt 原生 API，不引入第三方库。

**灵魂三问**：

> 1. LRC 的 "一行多个时间戳" 怎么处理？（展开为多行 → `std::sort` → 二分定位；比 iOS Swift 版 Dictionary 多戳更直观）
> 2. 歌词滚动用 `QScrollArea` 还是自绘？（**自绘**：QScrollArea 的滚动是粗糙的像素级，没法做"居中 + 加粗 + 平滑动画"组合；`QPropertyAnimation` 直接驱动一个 `scrollY` 变量更干净）
> 3. 如何做到 60fps 滚动？（**不画屏幕外的行**：`y < -rowH || y > H + rowH` 直接 `continue`——10000 行歌词也只画 20 行左右）

### Step 7.1 LRC 格式速览

LRC 文件格式实际有 3 种元素：

```text
[ti:曲名]                       ← 元数据头（可选）
[ar:艺术家]
[al:专辑]
[offset:+200]                   ← 全局偏移（毫秒）

[00:12.34]第一行歌词             ← 单戳
[00:30.00][01:30.00]副歌        ← 多戳（一行歌词在 30s 和 1:30 都唱）
[00:45.123]毫秒精度             ← 支持 3 位小数
```

### Step 7.2 LyricsParser：数据结构与接口

创建 `src/service/LyricsParser.h`：

### Step 7.3 LyricsParser 实现：正则 + "一行多戳展开"

```cpp
#include "LyricsParser.h"
#include <QRegularExpression>
#include <algorithm>

namespace mp {

LyricsDocument LyricsParser::parse(const QString& lrcText) {
    LyricsDocument doc;
    if (lrcText.isEmpty()) return doc;

    // 匹配时间戳 [mm:ss.xx] 或 [mm:ss]；一行可多个
    static const QRegularExpression kTimeRe(
        QStringLiteral(R"(\[(\d{1,2}):(\d{1,2})(?:[.:](\d{1,3}))?\])"));
    // 匹配元数据头 [ti:xxx]
    static const QRegularExpression kMetaRe(
        QStringLiteral(R"(^\s*\[([a-zA-Z]+):([^\]]*)\]\s*$)"));

    const QStringList rawLines = lrcText.split(QRegularExpression(QStringLiteral("\r?\n")));
    for (const QString& raw : rawLines) {
        const QString line = raw.trimmed();
        if (line.isEmpty()) continue;

        // 元数据头
        auto metaMatch = kMetaRe.match(line);
        if (metaMatch.hasMatch()) {
            const QString key = metaMatch.captured(1).toLower();
            const QString val = metaMatch.captured(2).trimmed();
            doc.meta[key] = val;
            if (key == QStringLiteral("offset")) {
                QString s = val;
                if (s.startsWith(QLatin1Char('+'))) s.remove(0, 1);
                bool ok = false;
                const qint64 ms = s.toLongLong(&ok);
                if (ok) doc.offsetMs = ms;
            }
            continue;
        }

        // ⭐ 时间戳 + 文本：收集所有时间戳
        QVector<qint64> stamps;
        auto it = kTimeRe.globalMatch(line);
        int lastEnd = 0;
        while (it.hasNext()) {
            auto m = it.next();
            const qint64 mm = m.captured(1).toLongLong();
            const qint64 ss = m.captured(2).toLongLong();
            const QString msStr = m.captured(3);
            qint64 ms = 0;
            if (!msStr.isEmpty()) {
                // "34" → 340ms；"345" → 345ms；关键的 2-vs-3 位小数处理
                if (msStr.size() == 2)      ms = msStr.toLongLong() * 10;
                else                        ms = msStr.toLongLong();
            }
            stamps.push_back(mm * 60'000 + ss * 1'000 + ms);
            lastEnd = m.capturedEnd();
        }
        if (stamps.isEmpty()) continue;

        // ⭐ 一行多戳 → 展开成多行
        const QString text = line.mid(lastEnd).trimmed();
        for (qint64 t : stamps) {
            doc.lines.push_back(LyricLine{ t, text });
        }
    }

    // 排序（展开后顺序可能被打乱）
    std::sort(doc.lines.begin(), doc.lines.end(),
              [](const LyricLine& a, const LyricLine& b){ return a.timeMs < b.timeMs; });
    return doc;
}

int LyricsParser::findLineIndex(const QVector<LyricLine>& lines, qint64 posMs) {
    if (lines.isEmpty() || posMs < lines.first().timeMs) return -1;
    // 二分：最后一个 <= posMs 的
    int lo = 0, hi = lines.size() - 1, ans = -1;
    while (lo <= hi) {
        const int mid = (lo + hi) >> 1;
        if (lines[mid].timeMs <= posMs) { ans = mid; lo = mid + 1; }
        else                             hi = mid - 1;
    }
    return ans;
}

} // namespace mp
```

**三个精妙处**：

1. **一行多戳的"展开法"**：不保留多戳结构，而是展开成多行各带一个戳 → 后续二分查找逻辑统一到最简单
2. **2 位 vs 3 位小数的归一化**：`[00:12.34]` 的 `34` 代表 340ms，不是 34ms；`[00:12.345]` 的 `345` 才是 345ms——`msStr.size() == 2 ? *10 : *1` 一行解决
3. **`static const QRegularExpression`**：Qt 的 `QRegularExpression` 构造很贵（要编译正则），用 `static` 保证全程只构造一次

### Step 7.4 LyricsWidget：全自绘滚动

创建 `src/ui/LyricsWidget.h`：

```cpp
#pragma once

#include <QWidget>

namespace mp {

class LyricsWidget : public QWidget {
    Q_OBJECT
    Q_PROPERTY(qreal scrollY MEMBER m_scrollY)   // ⭐ 让 QPropertyAnimation 直接驱动

protected:

    void mousePressEvent(QMouseEvent* e) override;

private:
    static constexpr int kRowH = 32;
```

**关键**：`Q_PROPERTY(qreal scrollY MEMBER m_scrollY)` 让 `QPropertyAnimation` 可以直接驱动这个变量——改变 `m_scrollY` 后 Qt 自动调 `update()` 重绘。

### Step 7.5 setPositionMs 触发动画

```cpp
#include "LyricsWidget.h"
#include <QPainter>
#include <QPropertyAnimation>
#include <QMouseEvent>

namespace mp {

void LyricsWidget::setLrcText(const QString& text) {
    m_doc = LyricsParser::parse(text);
    m_activeIdx = -1;
    m_scrollY = 0;
    update();
}

void LyricsWidget::setPositionMs(qint64 ms) {
    if (m_doc.lines.isEmpty()) return;
    const int newIdx = LyricsParser::findLineIndex(m_doc.lines, ms - m_doc.offsetMs);
    if (newIdx == m_activeIdx) return;   // 节流：只在换行时触发动画
    m_activeIdx = newIdx;

    // 滚动动画：OutCubic 缓动，420ms
    const qreal targetY = m_activeIdx * kRowH;
    auto* ani = new QPropertyAnimation(this, "scrollY");
    ani->setDuration(420);
    ani->setStartValue(m_scrollY);
    ani->setEndValue(targetY);
    ani->setEasingCurve(QEasingCurve::OutCubic);
    ani->start(QAbstractAnimation::DeleteWhenStopped);
}
```

**精髓**：

- **节流在"行号变化"级**：`QMediaPlayer::positionChanged` 可能一秒 30 次，但歌词平均每行 2-5 秒，`newIdx == m_activeIdx` 直接短路 — 一首歌只触发 50 次动画
- **`DeleteWhenStopped`**：动画完成后 Qt 自动 delete，不漏内存

### Step 7.6 paintEvent：从中心向两侧绘制

```cpp
void LyricsWidget::paintEvent(QPaintEvent*) {
    QPainter p(this);
    p.setRenderHint(QPainter::Antialiasing);

    if (m_doc.lines.isEmpty()) {
        p.setPen(QColor(0x94, 0xa3, 0xb8));
        QFont f = p.font(); f.setPixelSize(14); p.setFont(f);
        p.drawText(rect(), Qt::AlignCenter,
                   tr("暂无歌词 · 加载 .lrc 文件以同步显示"));
        return;
    }

    const int H = height();
    const qreal centerY = H / 2.0;

    // 从中心向两侧绘制
    for (int i = 0; i < m_doc.lines.size(); ++i) {
        const int y = static_cast<int>(centerY + i * kRowH - m_scrollY);
        if (y < -kRowH || y > H + kRowH) continue;   // ⭐ 屏幕外跳过

        const bool isActive = (i == m_activeIdx);
        const bool isPast   = (i < m_activeIdx);

        QColor color = isActive ? QColor(0x8b, 0x5c, 0xf6)                   // 当前行紫色
                                : (isPast ? QColor(0x94, 0xa3, 0xb8, 160)   // 过去淡化
                                          : QColor(0x94, 0xa3, 0xb8, 220)); // 未来较亮
        QFont f = p.font();
        f.setPixelSize(isActive ? 20 : 14);
        f.setBold(isActive);
        p.setFont(f);
        p.setPen(color);
        p.drawText(QRect(0, y - kRowH / 2, width(), kRowH),
                   Qt::AlignCenter,
                   m_doc.lines[i].text.isEmpty()
                       ? QStringLiteral("♪") : m_doc.lines[i].text);
    }
}
```

**三个性能/视觉技巧**：

1. **屏幕外剪枝**：`y < -kRowH || y > H + kRowH` → 10000 行歌词只画 ~20 行
2. **过去/未来差异化透明度**：过去的歌词 `alpha=160`、未来 `alpha=220`——制造"焦点感"
3. **空行占位 ♪**：空歌词行用音符占位，视觉上不"塌陷"

### Step 7.7 点击行跳播

```cpp
void LyricsWidget::mousePressEvent(QMouseEvent* e) {
    if (m_doc.lines.isEmpty()) return;
    const qreal centerY = height() / 2.0;
    // 反推：鼠标 y → 歌词行索引
    const qreal relY = e->position().y() - centerY + m_scrollY;
    const int idx = qRound(relY / kRowH);
    if (idx >= 0 && idx < m_doc.lines.size()) {
        emit lineClicked(m_doc.lines[idx].timeMs);
    }
}
```

### 📎 对应代码（v0.1 工程）

| 关注点 | 工程文件 | 关键 API/技巧 |
|-------|---------|--------------|
| LRC 解析（支持一行多戳 + offset） | `service/LyricsParser.cpp` | `QRegularExpression::globalMatch` + `std::sort` |

**🧠 教学点**：Qt 的 `QPropertyAnimation` 可以作用在**任何 Q_PROPERTY**上。本例把 `scrollY` 做成 property（`Q_PROPERTY(qreal scrollY READ scrollY WRITE setScrollY)`），动画引擎自动按时间步进调 `setScrollY`，每次调用触发 `update()` 重绘——这就是"**声明一个值，让它动画起来**"的最小心智。四端对照：Android `ValueAnimator`、iOS `UIView.animate`、Web `CSS transition` 都是同款心智。

## 08.搜索 + 主题 【阶段⑦】

> 🎯 **阶段目标**：搜索框带 220ms 防抖、主题三态（Auto/Light/Dark）、系统主题切换自动跟随——让 App 看起来"**像桌面原生应用**"而不是"用 Qt 做的 demo"。

**灵魂三问**：

> 1. QSS vs QStyle vs 自绘，三者什么关系？（**QSS = CSS**；**QStyle = render pipeline**；**自绘 = `paintEvent`**。本工程 60% QSS + 10% QStyle 定制 + 30% 自绘）
> 2. Qt 6.5 的 `QStyleHints::colorScheme()` 做了什么？（**一行跨平台**：Linux 走 xdg-desktop-portal、macOS 走 NSAppearance、Windows 10+ 走注册表。你以前要写 100 行平台特化）
> 3. 搜索防抖放在哪一层？（**UI 层**：Service/Repository 不需要知道"用户输入慢"的概念，关掉 `QLineEdit` 后 `t->start(220)` 自然失效）

### Step 8.1 搜索框 + 防抖

搜索框是普通的 `QLineEdit`，关键是**不要每敲一个键就查一次 SQLite**。220ms 防抖：

```cpp
// src/ui/LibraryPage.cpp（节选）
LibraryPage::LibraryPage(PlayerService* player, MediaRepository* repo, QWidget* parent)
    : QWidget(parent), m_player(player), m_repo(repo) {

    m_search = new QLineEdit(this);
    m_search->setPlaceholderText(tr("搜索标题 / 艺术家 / 专辑..."));
    m_search->setClearButtonEnabled(true);
    m_search->setFixedHeight(32);
    // ... 其它布局

    connect(m_search, &QLineEdit::textChanged, this, &LibraryPage::onSearchChanged);
}

void LibraryPage::onSearchChanged(const QString&) {
    // 防抖：220ms 内多次输入只触发一次 reload
    static QTimer* t = nullptr;
    if (!t) {
        t = new QTimer(this);
        t->setSingleShot(true);
        connect(t, &QTimer::timeout, this, &LibraryPage::reload);
    }
    t->start(220);   // 每次 textChanged 都重置这个定时器
}
```

**精髓**：

- `setSingleShot(true)` → 只触发一次
- `t->start(220)` 是**重置性**的：如果 220ms 内再调一次 `start`，前一次的定时器被取消
- 用 `static QTimer*` 延迟初始化，避免成员变量满天飞

然后 `reload()` 走 Repo 的 `search`：

::: tip 💡 四端对照：防抖/节流
- Android: `debounceAfter(220, ::reload)` 自己写 Handler
- iOS: `Timer.scheduledTimer(withTimeInterval: 0.22, ...)` + `timer?.invalidate()`
- Web: lodash `debounce(reload, 220)` 或自实现闭包
- **Qt**: `QTimer::singleShot` + `start()` 的重置语义——**不用 lodash**

### Step 8.4 Qt 6.5+ 一行跨平台监听系统主题

实现 `src/service/ThemeManager.cpp`（节选关键段）：

```cpp
#include "ThemeManager.h"
#include <QApplication>
#include <QGuiApplication>
#include <QStyleHints>
#include <QSettings>
#include <QWidget>
#include <QStyle>
#include <QColor>
#include <QPalette>

namespace mp {

ThemeManager& ThemeManager::instance() {
    static ThemeManager inst;
    return inst;
}

void ThemeManager::applyInitial() {
    // 1️⃣ 从 QSettings 读上次模式
    QSettings s;
    const QString v = s.value(QStringLiteral("theme"), QStringLiteral("auto")).toString();
    if      (v == QStringLiteral("light")) m_mode = ThemeMode::Light;
    else if (v == QStringLiteral("dark"))  m_mode = ThemeMode::Dark;
    else                                    m_mode = ThemeMode::Auto;

    // 2️⃣ ⭐ Qt 6.5+ 一行跨平台监听系统深色切换
#if QT_VERSION >= QT_VERSION_CHECK(6, 5, 0)
    connect(QGuiApplication::styleHints(), &QStyleHints::colorSchemeChanged,
            this, &ThemeManager::onSystemColorSchemeChanged);
#endif

    // 3️⃣ 计算当前是否深色
    m_darkActive = (m_mode == ThemeMode::Dark) ||
                   (m_mode == ThemeMode::Auto && computeDarkFromSystem());
    applyToApp(m_darkActive);
}

bool ThemeManager::computeDarkFromSystem() const {
#if QT_VERSION >= QT_VERSION_CHECK(6, 5, 0)
    // ⭐ 一行跨平台
    return QGuiApplication::styleHints()->colorScheme() == Qt::ColorScheme::Dark;
#else
    // 兜底：Qt 6.4 以下靠猜（看 Window 背景色亮度）
    const QColor win = QGuiApplication::palette().color(QPalette::Window);
    return win.lightness() < 128;
#endif
}

void ThemeManager::onSystemColorSchemeChanged() {
    if (m_mode != ThemeMode::Auto) return;   // 强制模式下不理会系统变化
    const bool dark = computeDarkFromSystem();
    if (dark == m_darkActive) return;
    m_darkActive = dark;
    applyToApp(dark);
    emit darkActiveChanged(dark);
}

void ThemeManager::applyToApp(bool dark) {
    // QSS 的 property selector 切换：给所有顶层窗口设 property[theme]，
    // 然后 unpolish → polish → update 三连触发 QSS 重匹配
    for (QWidget* w : qApp->topLevelWidgets()) {
        w->setProperty("theme", dark ? "dark" : "light");
        w->style()->unpolish(w);
        w->style()->polish(w);
        w->update();
    }
}

void ThemeManager::setMode(ThemeMode m) {
    m_mode = m;
    QSettings s;
    const QString v = (m == ThemeMode::Light) ? QStringLiteral("light") :
                      (m == ThemeMode::Dark)  ? QStringLiteral("dark")  : QStringLiteral("auto");
    s.setValue(QStringLiteral("theme"), v);
    emit modeChanged(m);

    const bool dark = (m == ThemeMode::Dark) ||
                      (m == ThemeMode::Auto && computeDarkFromSystem());
    if (dark != m_darkActive) {
        m_darkActive = dark;
        applyToApp(dark);
        emit darkActiveChanged(dark);
    }
}

} // namespace mp
```

### Step 8.5 MainWindow 主题自动同步

`ThemeManager::applyInitial()` 在 `main.cpp` 里 `MainWindow` 构造**之前**调用——此时 `qApp->topLevelWidgets()` 还是空的，无法 polish。所以 MainWindow 构造末尾要**自己 polish 一次**：

```cpp
// MainWindow 构造函数末尾
auto applyTheme = [this]{
    const bool dark = ThemeManager::instance().isDarkActive();
    setProperty("theme", dark ? "dark" : "light");
    style()->unpolish(this);
    style()->polish(this);
    update();
};
applyTheme();     // 构造完立刻应用一次

connect(&ThemeManager::instance(), &ThemeManager::darkActiveChanged, this,
        [applyTheme](bool){ applyTheme(); });
```

**顺序必须**：先 `main.cpp` `ThemeManager::applyInitial()`（设置 `m_darkActive`）→ 再 `new MainWindow`（构造函数末尾 `applyTheme()` 读取并应用）。颠倒会出现"启动闪白一下"的问题。

```cpp
// platform/linux/MprisAdapter.cpp（关键三段：注册服务 / 变更通知 / 把 D-Bus 回调桥到 Qt 信号）
#include "MprisAdapter.h"
#include <QDBusConnection>
#include <QDBusMessage>
#include <QCoreApplication>

namespace mp {

MprisAdapter::MprisAdapter(QObject* parent) : SystemMediaAdapter(parent) {
    // 对象树绑定：这两个 adaptor 挂在 this 上，析构自动清理
    new MprisRootAdaptor(this);
    new MprisPlayerAdaptor(this);

    auto bus = QDBusConnection::sessionBus();

    // 1️⃣ 挂载对象到 /org/mpris/MediaPlayer2
    if (!bus.registerObject(QStringLiteral("/org/mpris/MediaPlayer2"), this)) {
        qWarning() << "[MPRIS] registerObject failed";
        return;
    }
    // 2️⃣ 注册服务名（关键：带 PID 后缀，防多实例冲突）
    const QString name = QStringLiteral("org.mpris.MediaPlayer2.MiniPlayer.instance%1")
                             .arg(QCoreApplication::applicationPid());
    if (!bus.registerService(name)) {
        qWarning() << "[MPRIS] registerService failed:" << name;
    }
}

MprisAdapter::~MprisAdapter() {
    QDBusConnection::sessionBus().unregisterObject(
        QStringLiteral("/org/mpris/MediaPlayer2"));
}

void MprisAdapter::setMetadata(const MediaItem& it) {
    m_current = it;
    emitPropertiesChanged({ QStringLiteral("Metadata") });
}

void MprisAdapter::setPlaybackState(PlaybackState s) {
    m_state = s;
    emitPropertiesChanged({ QStringLiteral("PlaybackStatus") });
}

void MprisAdapter::setPosition(qint64 posMs, qint64 durMs) {
    m_positionMs = posMs;
    m_durationMs = durMs;
    // Position 不走 PropertiesChanged（MPRIS 规范要求），要配合 Seeked 信号
}

/** MPRIS 的"状态变化通知"统一走标准 D-Bus 的 PropertiesChanged 信号 */
void MprisAdapter::emitPropertiesChanged(const QStringList& props) {
    QDBusMessage sig = QDBusMessage::createSignal(
        QStringLiteral("/org/mpris/MediaPlayer2"),
        QStringLiteral("org.freedesktop.DBus.Properties"),
        QStringLiteral("PropertiesChanged"));

    QVariantMap changed;
    for (const QString& p : props) {
        if (p == QLatin1String("PlaybackStatus")) {
            const char* v = (m_state == PlaybackState::Playing) ? "Playing"
                          : (m_state == PlaybackState::Paused)  ? "Paused" : "Stopped";
            changed[p] = QString::fromLatin1(v);
        } else if (p == QLatin1String("Metadata")) {
            QVariantMap md;
            md["mpris:trackid"] = QVariant::fromValue(QDBusObjectPath(
                QStringLiteral("/org/mpris/MediaPlayer2/MiniPlayer/track/%1").arg(m_current.id)));
            md["mpris:length"] = qint64(m_current.durationMs) * 1000;    // μs
            md["xesam:title"]  = m_current.title;
            md["xesam:artist"] = QStringList{ m_current.artist };
            md["xesam:album"]  = m_current.album;
            if (!m_current.coverPath.isEmpty())
                md["mpris:artUrl"] = QUrl::fromLocalFile(m_current.coverPath).toString();
            changed[p] = md;
        }
    }
    sig << QStringLiteral("org.mpris.MediaPlayer2.Player")
        << changed << QStringList{};
    QDBusConnection::sessionBus().send(sig);
}

/* ===== D-Bus 回调 → Qt 信号 ===== */

void MprisPlayerAdaptor::Play()      { emit m_owner->playRequested(); }
void MprisPlayerAdaptor::Pause()     { emit m_owner->pauseRequested(); }
void MprisPlayerAdaptor::PlayPause() {
    if (m_owner->state() == PlaybackState::Playing) emit m_owner->pauseRequested();
    else                                             emit m_owner->playRequested();
}
void MprisPlayerAdaptor::Next()     { emit m_owner->nextRequested(); }
void MprisPlayerAdaptor::Previous() { emit m_owner->previousRequested(); }
void MprisPlayerAdaptor::Seek(qint64 offsetUs) {
    const qint64 newMs = m_owner->positionMs() + offsetUs / 1000;
    emit m_owner->seekRequested(qMax<qint64>(0, newMs));
}
void MprisPlayerAdaptor::SetPosition(const QDBusObjectPath&, qint64 positionUs) {
    emit m_owner->seekRequested(positionUs / 1000);
}
```

```cpp
SmtcAdapter::SmtcAdapter(HWND hwnd, QObject* parent) : SystemMediaAdapter(parent) {

void SmtcAdapter::setMetadata(const MediaItem& it) {
    auto updater = m_smtc.DisplayUpdater();
    updater.Type(MediaPlaybackType::Music);
    auto music = updater.MusicProperties();
    music.Title(hstring(it.title.toStdWString()));
    music.Artist(hstring(it.artist.toStdWString()));
    music.AlbumTitle(hstring(it.album.toStdWString()));

    // 封面：从本地路径读 → RandomAccessStream
    if (!it.coverPath.isEmpty()) {
        try {
            auto file = winrt::Windows::Storage::StorageFile::GetFileFromPathAsync(
                hstring(it.coverPath.toStdWString())).get();
            updater.Thumbnail(RandomAccessStreamReference::CreateFromFile(file));
        } catch (...) { /* 封面缺失不致命 */ }
    }
    updater.Update();   // 千万别忘，不然前面全白做
}

        (s == PlaybackState::Playing) ? MediaPlaybackStatus::Playing
      : (s == PlaybackState::Paused)  ? MediaPlaybackStatus::Paused
      : (s == PlaybackState::Idle)    ? MediaPlaybackStatus::Closed
                                      : MediaPlaybackStatus::Stopped);
}

void SmtcAdapter::setPosition(qint64 posMs, qint64 durMs) {
    SystemMediaTransportControlsTimelineProperties tl;
    tl.StartTime(std::chrono::milliseconds(0));
    tl.EndTime(std::chrono::milliseconds(durMs));
    tl.Position(std::chrono::milliseconds(posMs));
    tl.MinSeekTime(std::chrono::milliseconds(0));
    tl.MaxSeekTime(std::chrono::milliseconds(durMs));

}

        case SystemMediaTransportControlsButton::Pause:    emit pauseRequested();    break;
        case SystemMediaTransportControlsButton::Next:     emit nextRequested();     break;

}
```

## 10.均衡器 + 睡眠定时 【阶段⑧】

- Step 10.1 EQ 实现策略——`QMediaPlayer` 没有直挂 EQ 接口，三端走各自路径：
  - **Linux**：GStreamer `equalizer-10bands` 元素插入管线
  - **macOS**：`AVAudioEngine` + `AVAudioUnitEQ`（更现代也更强）
  - **Windows**：XAudio2 的 `FXEQ` 效果器
  - 用抽象类 `EqualizerBackend` 隔离，上层 10 滑块 UI 完全共享
- Step 10.2 预设/自定义 + SQLite 存 JSON（5 预设 + 自定义曲线）
- Step 10.3 睡眠定时：`QTimer` + 音量渐弱（`QPropertyAnimation` 控 volume，三端共用）
- Step 10.4 曲目间淡入淡出（crossfade）：两个 `QMediaPlayer` 实例交替 + volume 交叉
- 🧪 **验收**：三端 EQ 都能听出"低音增强"的差异；睡眠定时到点音量平滑归零

### 📎 对应代码（v0.1 工程 · 睡眠定时已实现）

| 关注点 | 工程文件 | 关键 API/技巧 |
|-------|---------|--------------|
| 睡眠定时核心 | `service/SleepTimer.{h,cpp}` | `QTimer` + `remainingMs` 计算 + 最后 10 秒**线性淡出** |
| 淡出算法 | `SleepTimer::onTick` 内 `ratio = remain / 10000` | 不用 QPropertyAnimation（节省对象开销），每 500ms tick 一次直接 `setVolume(saved * ratio)` |
| 取消时恢复 | `SleepTimer::cancel` | 恢复 `m_savedVolume`，避免用户觉得"音量被偷走了" |
| UI 控件 | `ui/SettingsPage.cpp` 睡眠卡片 | `QSpinBox` + 启动/取消按钮 + 500ms UI tick 显示剩余时间 |
| 空选保护 | `SettingsPage::onStartTimer` | 没当前曲目直接 Toast 提醒 |

**EQ 保留的扩展点**：当前 `PlayerService` 用 `QAudioOutput` 简单输出。若接 EQ，有两种工程路径：

```cpp
// 路径 A（推荐）：平台特化，走各自 DSP
//   Linux  → GStreamer equalizer-10bands 插件
//   macOS  → AVAudioEngine + AVAudioUnitEQ
//   Windows→ XAudio2 FXEQ
// 用一个 EqualizerBackend 抽象，和 SystemMediaAdapter 一个套路。

// 路径 B（三端共用但受限）：换成 QAudioSink + 自己做 PCM 滤波
//   QAudioDecoder → BiquadFilter 链（10 阶）→ QAudioSink
//   能跑但 PCM 层串接增加复杂度，仅适合音频，不适合视频。
```

## 12.挑战题

本章 6 道挑战题按**从易到难**排序，前 3 道推荐"读完本篇就能动手"，后 3 道需要跨出 Qt 的舒适区。每道题都给出目标、关键文件/API、风险点、验收标准和预估时长——**不是开放式幻想，是能真正做完的小工程**。

### 挑战 1：Qt QML 版（★★☆☆☆ · 预估 10h）

**目标**：保留现有后端（`PlayerService` / `MediaRepository` / `MediaScanner` / `SleepTimer` 全部一行不改），把 UI 层换成 QML，对比两种 UI 范式的开发效率。

**关键决策**：

- **数据暴露**：`PlayerService` 已经有 `Q_PROPERTY(... NOTIFY ...)`，QML 直接 bind 即可，不需要适配层
- **ListModel**：现在的 `MediaListModel` 继承 `QAbstractListModel` + 实现 `roleNames()`，QML `ListView.delegate` 原样消费
- **工程改造**：`CMakeLists.txt` 加 `find_package(Qt6 COMPONENTS Quick QuickControls2)` + `qt_add_qml_module(...)`

**关键文件**：

```text
src/qml/
├── Main.qml                    # 替代 MainWindow
├── PlayerBar.qml               # 替代 ui/PlayerBar.cpp（心疼半个月自绘）
├── LibraryView.qml
├── PlayingView.qml
└── components/
    ├── CoverImage.qml          # 替代 CoverLabel
    └── ProgressBar.qml         # 替代 ProgressSlider（QML 内置动画框架更顺手）
```

**风险点**：

- QML + Widgets **不要混用**（混了 OpenGL 上下文会打架）；要么全 QML（`QQmlApplicationEngine`），要么全 Widgets
- QML 的 `MediaPlayer` 元素是 QtMultimedia 的另一套 API；想沿用 `PlayerService` 就得像现在一样让 `QMediaPlayer` 住在 C++ 侧，QML 只订阅 `Q_PROPERTY`
- QML 热重载很爽，但调试栈不如 C++ 深——复杂逻辑**务必留在 C++**

**🧪 验收**：QML 版和 Widgets 版共用一个 SQLite 库，交替启动都能读到相同播放历史；视觉上 QML 版自带更流畅的过渡动画。

### 挑战 2：PipeWire 替代 PulseAudio 后端（★★★☆☆ · 预估 6h · Linux Only）

**目标**：验证 Qt 6 的 `QMediaPlayer` 在 PipeWire 环境下低延迟 + 多路由能力。

**背景**：Qt 6 的 Linux Multimedia 后端走 GStreamer，而 GStreamer 的 audio sink 既可以是 `pulsesink` 也可以是 `pipewiresink`。现代发行版（Fedora 36+、Ubuntu 23.04+）默认已经是 PipeWire。

**关键 API**：

```bash
# 启动前强制走 PipeWire 后端（PulseAudio 兼容层也是 PipeWire 实现的）
GST_DEBUG=3 PULSE_SERVER="" PIPEWIRE_LATENCY="256/48000" ./build/MiniPlayer

# 看 sink 列表
pw-cli list-objects | grep -A3 'media.class = "Audio/Sink"'
```

**风险点**：

- Qt 6 Multimedia 没暴露直接设 sink 的 API，只能靠 GStreamer 环境变量
- PipeWire 的"图式音频路由"要用 Helvum / qpwgraph 可视化排错

**🧪 验收**：MiniPlayer 和另一个播放器（如 Rhythmbox）同时出声，`pw-top` 显示两个 node；拔耳机音频流无缝切回扬声器（PipeWire 原生热插拔）。

### 挑战 3：树莓派 5 ARM64 交叉编译（★★★☆☆ · 预估 8h）

**目标**：在 x86_64 开发机上**交叉编译**出 aarch64 的 MiniPlayer，SCP 到树莓派 5 桌面环境运行。

**关键命令**：

```bash
# 开发机（Ubuntu x86_64）
sudo apt install g++-aarch64-linux-gnu qt6-base-dev-tools:arm64

# 交叉工具链文件
cat > rpi5-toolchain.cmake <<'EOF'
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR aarch64)
set(CMAKE_C_COMPILER   aarch64-linux-gnu-gcc)
set(CMAKE_CXX_COMPILER aarch64-linux-gnu-g++)
set(CMAKE_FIND_ROOT_PATH /path/to/rpi5-sysroot)
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
EOF

cmake -S . -B build-arm64 -DCMAKE_TOOLCHAIN_FILE=rpi5-toolchain.cmake
cmake --build build-arm64 -j
scp build-arm64/MiniPlayer pi@raspi5:~/
```

**风险点**：

- **sysroot 必须是 RPi5 的真实根文件系统**（含 /usr/lib 下所有 .so），不能用 x86 的
- Qt Multimedia 依赖 GStreamer，sysroot 要包含 `libgstreamer-1.0-0:arm64`
- 树莓派默认用 KMS/DRM 没装 X11，Qt 可以直接走 EGLFS 平台插件

**🧪 验收**：`file MiniPlayer` 输出 `ELF 64-bit LSB executable, ARM aarch64`；RPi5 上双击 .desktop 启动即可播放 mp3，CPU 占用 < 20%（RPi5 CPU 性能已经可以）。

### 挑战 4：macOS 公证 + Sparkle 自动更新（★★★★☆ · 预估 10h · macOS Only）

**目标**：真正打一份能分发给陌生人的 .dmg——过 Gatekeeper + 过 XProtect + 支持 app 自升级。

**关键流程**：

1. **开发者证书**：Apple Developer Program ($99/yr) → Keychain Access 导出 "Developer ID Application" + "Developer ID Installer"
2. **签名**：
   ```bash
   macdeployqt build/MiniPlayer.app -codesign="Developer ID Application: Your Name (TEAMID)"
   codesign --deep --force --verify --verbose --sign "..." build/MiniPlayer.app
   ```
3. **公证**：
   ```bash
   ditto -c -k --keepParent build/MiniPlayer.app MiniPlayer.zip
   xcrun notarytool submit MiniPlayer.zip --apple-id "..." --team-id TEAMID --password "app-specific-pw" --wait
   xcrun stapler staple build/MiniPlayer.app      # 装订公证票据
   ```
4. **Sparkle 集成**：GitHub [sparkle-project/Sparkle](https://sparkle-project.org/) 的 `SPUStandardUpdaterController`——需要用 `.mm` 混编调 Obj-C API，和 §9.3 的 MPNowPlaying 一个套路

**风险点**：

- **Hardened Runtime** 必须开启（Info.plist 的 entitlements），否则公证直接拒
- Qt 二进制通过 `macdeployqt` 后，还要**递归签名所有 Frameworks**（含 .dylib）
- Sparkle 需要 Ed25519 签名密钥，和 Apple 开发者证书是**两套独立体系**

**🧪 验收**：陌生人双击 .dmg 直接运行无"损坏"报错；修改一个字符串发 v1.0.1，老版本点"检查更新"自动下载并替换。

### 挑战 5：Windows 代码签名 + MSI 安装包（★★★★☆ · 预估 8h · Windows Only）

**目标**：真正打一份能让 Windows SmartScreen 不报警的 .msi。

**关键流程**：
