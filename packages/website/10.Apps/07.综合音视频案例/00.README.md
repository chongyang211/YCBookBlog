# MiniPlayer 五端对照：从 0 到 1 打造跨平台音视频播放器

本案例是 `10.Apps` 卷的**毕业设计级综合案例**：我们用**同一个产品需求**——一个"能播放、能后台、能收藏、能同步歌词"的本地音视频播放器——在 **5 个平台**上各做一次"母语级"实现：

- **Android**：Java + AndroidX（XML + Activity）
- **iOS**：Objective-C（UIKit + AVFoundation）
- **Web**：Vue 3（Composition API + Pinia）
- **Linux**：C++（Qt 6 Widgets + Qt Multimedia）
- **Windows**：C#（WPF + XAML + MVVM）

五端一次集齐 **Java / OC / JS / C++ / C#** 五大主流语言系。学完这套案例，你收获的不是"会写 5 个播放器"，而是**同一个需求在不同平台约束下如何演化出不同的架构决策**——这是远超"会用某个框架"的跨平台工程能力。

> **写作体例**：本案例仿照《C++ 入门到精通》的 [迷你KV存储引擎](/pages/97f31a/) 与 [迷你编译器解释器](/pages/d647c8/) 两篇毕业设计的结构——**渐进学习节奏 + 灵魂三问 + 阶段目标卡片 + 验收命令**。每端 1 篇，每篇按 8 个阶段推进，绝不一上来甩 4000 行代码。

## 产品定位

> **做一个"能跑能停、能后台、能收藏、能同步歌词"的本地音视频播放器。**

三条产品原则：

1. **纯本地优先**：媒体来自本机文件系统扫描，一期不引入服务端。这保证五端对称、离线可用、教学聚焦。
2. **音频为主线，视频为支线**：视频渲染只做"系统播放器 + Surface/Layer/Widget"级别的接入，不陷入编解码泥潭。
3. **平台惯例优先**：后台播放、通知控制、耳机线控等能力，每端用该平台的"官方正教"实现，这正是本案例的教学价值所在。

## 功能全景：8 个阶段

```text
🎯 阶段① MVP 骨架          · 2 h · 启动 App → 硬编码路径 → 播放一首 mp3
🎯 阶段② 媒体扫描与列表     · 3 h · 扫目录读元数据 → 列表展示 → 点击播放
🎯 阶段③ 播放控制           · 3 h · 播放/暂停/上下首/进度拖动/倍速 + 视频画面层
🎯 阶段④ 本地持久化         · 3 h · SQLite/IndexedDB：历史 / 我喜欢 / 最后播放位置
🎯 阶段⑤ 后台播放 + 通知    · 4 h · 息屏继续放 + 通知栏/锁屏控件 + 线控/蓝牙 ⭐
🎯 阶段⑥ LRC 歌词同步       · 2 h · 解析 .lrc → 滚动高亮 → 双向跳转
🎯 阶段⑦ 搜索 + 主题        · 2 h · 标题/艺术家/专辑搜索 + 深浅色切换
🎯 阶段⑧ 均衡器 + 睡眠定时  · 3 h · 10 频段 EQ + N 分钟暂停 + 设置页
—————————————————————————————————————————————
                  合计每端 ≈ 22 小时
```

每个阶段的详细功能点：

| 阶段 | 功能点 |
|------|--------|
| ① MVP 骨架 | 工程搭建、最小 UI、硬编码播放一首 mp3、播放/暂停按钮 |
| ② 媒体扫描 | 递归扫描音频目录（mp3/flac/m4a/wav）与视频目录（mp4/mkv/mov）、读取 ID3 元数据（标题/艺术家/专辑/时长/封面）、媒体库列表（全部/音频/视频三个 Tab） |
| ③ 播放控制 | 播放状态机、进度条双向绑定、上一首/下一首/顺序/单曲/随机、倍速（0.5x-2.0x）、视频画面层（音频模式 ↔ 视频模式切换） |
| ④ 本地持久化 | 播放历史（最近 200 条）、我喜欢列表、最后播放位置断点续播、扫描结果缓存（秒开） |
| ⑤ 后台播放 | 后台/息屏继续播放音频、系统媒体通知（播放/暂停/上下首）、耳机线控与蓝牙耳机按键、视频模式锁屏暂停 |
| ⑥ LRC 歌词 | 解析 .lrc 文件、逐行滚动高亮、点击歌词行跳转播放位置、无歌词时显示占位 |
| ⑦ 搜索与主题 | 关键词模糊搜索（标题/艺术家/专辑）、深色/浅色主题切换、跟随系统 |
| ⑧ 均衡器与定时 | 10 频段图形均衡器（预设 + 自定义）、睡眠定时器（15/30/60 分钟后淡出暂停）、设置页（扫描目录、缓存清理） |

## 共享五层架构

五端共享同一套分层架构，每端的目录结构保持**三段式对齐**（`ui/` `service/` `data/`）：

```text
┌────────────────────────────────────────────────┐
│  UI 层        Activity / UIViewController /    │
│               Vue 组件 / QWidget / XAML Window │
├────────────────────────────────────────────────┤
│  Controller / ViewModel 层（状态管理）          │
├────────────────────────────────────────────────┤
│  PlayerService（播放、队列、状态广播、后台）     │
├────────────────────────────────────────────────┤
│  MediaRepository（扫描 / 元数据 / DB 聚合）      │
├────────────────────────────────────────────────┤
│  Platform Engine（ExoPlayer / AVPlayer /        │
│                  <audio>/<video> / QMediaPlayer │
│                  / MediaElement）               │
└────────────────────────────────────────────────┘
```

> 读者在不同端之间切换时，"**同名目录做同件事**"，心智负担最小。详细设计见 [01.架构设计与五端对照](/pages/mp5arch/)。

## 学习路径建议

**路径一（推荐）：主攻一端 + 通读其余四端**

1. 选你最熟悉的一端，完整做完 8 个阶段（动手）；
2. 其余四端只读"架构对照 + 阶段⑤后台播放 + 各端特色坑"三部分（精读）；
3. 最后回看五端总表，体会每行背后的架构权衡。

**路径二：五端并行**

每做完一个阶段就切到另一端做同一阶段。适合时间充裕（90h+）且想横向打通的读者，风险是容易烂尾，建议最多并行两台。

**路径三：对照式速读**

只读不写，把五端文档当"API 对照手册"用，适合已经会某一端、想快速了解其他平台做法的读者。

### Linux 端如何运行与查看（5 种方案）

Qt 6 应用在 Linux 上就是一个普通 ELF 可执行文件，弹一个原生窗口。按友好度排序：

```bash
# 方案 A：原生 Ubuntu 22.04/24.04
sudo apt update
sudo apt install -y qt6-base-dev qt6-multimedia-dev cmake g++ \
                    libsqlite3-dev libtag1-dev \
                    gstreamer1.0-plugins-good gstreamer1.0-plugins-bad \
                    gstreamer1.0-libav
cd mini_player/linux-cpp
cmake -B build -S . -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
./build/MiniPlayer          # 弹出原生窗口
```

```powershell
# 方案 C：Windows 11 + WSL2（自带 WSLg，Linux GUI 直接弹到 Windows 桌面）
wsl --install -d Ubuntu-24.04
wsl -d Ubuntu-24.04
# 容器内执行与方案 A 相同的命令
```

## FAQ

**Q1：为什么不做 Flutter / React Native / Compose Multiplatform 一套代码跨五端？**
本案例的教学目标是**理解每个平台的原生机制**（后台、通知、媒体会话），跨平台框架恰恰把这些差异抹平了。学完本案例再学跨平台框架，你会清楚它替你做了什么、付出了什么代价。

**Q2：视频播放会不会太重？**
不会。五端的视频能力都是系统播放器级别的（ExoPlayer/AVPlayer/`<video>`/QMediaPlayer/MediaElement），渲染层各自接到 PlayerView / AVPlayerLayer / video 标签 / QVideoWidget / MediaElement 即可。我们不碰 FFmpeg 软解。

**Q3：可以只做音频跳过视频吗？**
可以。视频只出现在阶段②的扫描扩展和阶段③的画面层切换，其余阶段与纯音频版完全一致。

**Q4：Linux 端没有 Linux 电脑怎么办？**
用 WSLg（Windows 11）或 UTM 虚拟机（macOS），见上文"Linux 端如何运行与查看"。

**Q5：为什么 Windows 端选 WPF 而不是 WinUI 3 / Electron / Qt？**
WPF 成熟稳定、文档最全、`MediaElement` 开箱即用；WinUI 3 生态尚在过渡；Electron 与 Web 端重复、Qt 与 Linux 端重复，没有教学增量。详见 [06.Windows端实现](/pages/mp5win0/) §1。
