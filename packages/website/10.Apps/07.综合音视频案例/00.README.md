# MiniPlayer 五端对照：从 0 到 1 打造跨平台音视频播放器

本案例是 `10.Apps` 卷的**毕业设计级综合案例**：我们用**同一个产品需求**——一个"能播放、能后台、能收藏、能同步歌词"的本地音视频播放器——用 **4 种原生技术栈**在 **6 个平台**上做一遍"母语级"实现：

- **Android**：Java + AndroidX（XML + Activity）
- **iOS**：Objective-C（UIKit + AVFoundation）
- **Web**：Vue 3（Composition API + Pinia）
- **Qt 桌面（Linux + macOS + Windows 三合一）**：C++ + Qt 6 Widgets——**一份 CMake 工程，产出三份原生可执行文件**

一次集齐 **Java / OC / JS / C++** 四大主流语言系，覆盖 Android / iOS / Web / Linux / macOS / Windows 六个平台。学完这套案例，你收获的不是"会写几个播放器"，而是**同一个需求在不同平台约束下如何演化出不同的架构决策**——这是远超"会用某个框架"的跨平台工程能力。

> **写作体例**：本案例仿照《C++ 入门到精通》的 [迷你KV存储引擎](/pages/97f31a/) 与 [迷你编译器解释器](/pages/d647c8/) 两篇毕业设计的结构——**渐进学习节奏 + 灵魂三问 + 阶段目标卡片 + 验收命令**。每端 1 篇，每篇按 9 个阶段推进，绝不一上来甩 4000 行代码。

## 产品定位

> **做一个"能跑能停、能后台、能收藏、能同步歌词"的本地音视频播放器——音频对标网易云/千千静听，视频对标 Infuse/PotPlayer 的基础功能子集。**

三条产品原则：

1. **纯本地优先**：媒体来自本机文件系统扫描，一期不引入服务端。这保证五端对称、离线可用、教学聚焦。
2. **音视频平衡覆盖**：两种形态的**基础能力都必须齐全**（音量/字幕/全屏/画中画/多轨切换都在），但渲染层统一走系统播放器，不陷入编解码泥潭。
3. **平台惯例优先**：后台播放、通知控制、耳机线控等能力，每端用该平台的"官方正教"实现，这正是本案例的教学价值所在。

每个阶段的详细功能点：

| 阶段 | 功能点 |
|------|--------|
| ① MVP 骨架 | 工程搭建、最小 UI、硬编码播放一首 mp3、播放/暂停按钮 |
| ② 媒体扫描与导入 | 递归扫描音频目录（mp3/flac/m4a/wav/aac/ogg）与视频目录（mp4/mkv/mov/webm）；元数据提取（标题/艺术家/专辑/时长/封面/码率）；拖拽文件/文件夹导入；粘贴 URL 直接播放；"最近打开"独立于播放历史的文件级记录；媒体库三 Tab（全部/音频/视频） |
| ③ 核心播放控制 | 播放状态机；进度条双向绑定 + 精准跳转（点击时间输入）；上一首/下一首；顺序/单曲/随机播放模式；0.5x-2.0x 倍速；**音量滑块 + 静音切换**；**A-B 循环**（指定起止点反复播）；播放队列可视化（当前列表查看/拖动排序/删除） |
| ④ 视频播放增强 ⭐ | **全屏 + 退出全屏**；**宽高比切换**（原比例/16:9/4:3/铺满/自适应）；**画中画 PiP**（移动端/桌面端双支持）；**字幕加载**（SRT/VTT 外挂字幕 + 拖拽加载）；**多字幕轨/多音轨切换**（内嵌字幕）；**视频截图**到相册/下载目录；**视频旋转**（90°/180°/270°）；**亮度覆盖层**（UI 层叠加，非系统设置） |
| ⑤ 本地持久化 | 用户创建的**歌单/播放列表**（增删改排序）；我喜欢列表；**曲目评分**（1-5 星）；播放历史（最近 200 条）；最后播放位置断点续播；扫描结果缓存（秒开）；最近打开文件 |
| ⑥ 后台 + 系统媒体控制 | 后台/息屏继续播放音频；系统媒体通知（播放/暂停/上下首/seek）；耳机线控（单击/双击/三击）与蓝牙耳机按键；**音频焦点**与中断恢复（来电、其他 App 抢占、闹钟）；视频模式退后台自动暂停 |
| ⑦ 歌词 + 封面展示 | 解析 .lrc 文件（含增强格式/多语言）；逐行滚动高亮；点击歌词行跳转播放位置；无歌词时显示占位；**封面大图页**（旋转动画、模糊背景）；**频谱可视化**（Web Audio AnalyserNode 等效能力，各端选做） |
| ⑧ 快捷键 + 手势 + 搜索 | **全局快捷键**（Space 暂停、←→跳转、↑↓音量、F 全屏、M 静音、[/] 倍速、,/.帧级步进等 15+ 组）；**手势控制**（移动端横滑进度/竖滑音量亮度、桌面端鼠标滚轮）；关键词模糊搜索（标题/艺术家/专辑/文件名）；深浅主题切换 + 跟随系统；**i18n**（中英至少两种） |
| ⑨ 均衡器 + 定时 + 设置 | 10 频段图形均衡器（流行/古典/摇滚/爵士/低音增强 5 种预设 + 自定义曲线）；睡眠定时（15/30/60/90 分钟 + 自定义，到点淡出暂停）；**曲目间淡入淡出**（crossfade）；设置页（扫描目录管理、缓存清理、重置、关于） |

## 共享五层架构

五端共享同一套分层架构，每端的目录结构保持**三段式对齐**（`ui/` `service/` `data/`）：

```text
┌────────────────────────────────────────────────┐
│  UI 层        Activity / UIViewController /    │
│               Vue 组件 / QWidget / XAML Window │
├────────────────────────────────────────────────┤
│  Controller / ViewModel 层（状态管理）          │
├────────────────────────────────────────────────┤
│  PlayerService（播放、队列、状态广播、后台）     │
├────────────────────────────────────────────────┤
│  MediaRepository（扫描 / 元数据 / DB 聚合）      │
├────────────────────────────────────────────────┤
│  Platform Engine（ExoPlayer / AVPlayer /        │
│                  <audio>/<video> / QMediaPlayer │
│                  / MediaElement）               │
└────────────────────────────────────────────────┘
```

> 读者在不同端之间切换时，"**同名目录做同件事**"，心智负担最小。详细设计见 [01.架构设计与五端对照](/pages/mp5arch/)。

## 学习路径建议

**路径一（推荐）：主攻一端 + 通读其余四端**

1. 选你最熟悉的一端，完整做完 8 个阶段（动手）；
2. 其余四端只读"架构对照 + 阶段⑤后台播放 + 各端特色坑"三部分（精读）；
3. 最后回看五端总表，体会每行背后的架构权衡。

**路径二：五端并行**

每做完一个阶段就切到另一端做同一阶段。适合时间充裕（90h+）且想横向打通的读者，风险是容易烂尾，建议最多并行两台。

**路径三：对照式速读**

只读不写，把五端文档当"API 对照手册"用，适合已经会某一端、想快速了解其他平台做法的读者。

| Qt 桌面 | Qt 6.4+ / CMake / 对应平台编译器 / 媒体后端 | 三端共用一条命令 `cmake --build build` |
| Windows 原生 | Visual Studio 2022（.NET 桌面开发负载）/ .NET 8 LTS | `dotnet build` 通过 |

### Qt 桌面端如何运行与查看（Linux / macOS / Windows）

Qt 6 在三端都是一等公民，**同一份 CMake 工程产出三份原生可执行文件**：

```bash
# Linux（Ubuntu 22.04/24.04）

                    libsqlite3-dev libtag1-dev \
                    gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-libav
```


## FAQ

**Q1：为什么不做 Flutter / React Native / Compose Multiplatform 一套代码跨五端？**
本案例的教学目标是**理解每个平台的原生机制**（后台、通知、媒体会话），跨平台框架恰恰把这些差异抹平了。学完本案例再学跨平台框架，你会清楚它替你做了什么、付出了什么代价。

**Q2：视频播放会不会太重？**
不会。各端的视频能力都是系统播放器级别的（ExoPlayer/AVPlayer/`<video>`/QMediaPlayer/MediaElement），渲染层各自接到 PlayerView / AVPlayerLayer / video 标签 / QVideoWidget / MediaElement 即可。我们不碰 FFmpeg 软解。

**Q3：可以只做音频跳过视频吗？**
可以。视频密集功能集中在**阶段④**（可整段跳过），阶段②的扫描过滤视频类型即可。但建议至少做到"全屏 + 字幕 + 画中画"三件套。

**Q4：字幕支持到什么程度？**
一期支持 **SRT / VTT 两种外挂字幕格式**，支持多字幕轨切换（内嵌字幕由系统播放器直接解析）。更复杂的 ASS 特效字幕放挑战题。

**Q5：画中画 PiP 各端都支持吗？**
支持矩阵：Android 7.0+、iOS 14+ / iPadOS、Web（Chrome/Edge/Safari）、Qt 桌面（三端均无系统级 PiP，用"置顶迷你窗口"等效实现）、WPF 同样走置顶迷你窗口方案。

**Q6：格式支持到什么程度？**
音频：mp3 / aac / m4a / flac / wav / ogg。视频：mp4(H.264/H.265) / mkv / mov / webm；mkv 和 H.265 在部分端需要系统/浏览器层支持。阶段②扫描按文件头探测而非仅扩展名，不支持的格式灰显并给出原因提示。

**Q7：Qt 桌面端没有对应平台的机器怎么办？**
- **想跑 Linux 版**：Mac 用 UTM + Ubuntu、Windows 用 WSL2 + WSLg，都是开箱有图形界面；
- **想跑 macOS 版**：**必须有 Mac 真机**——Apple 的工具链（Xcode/codesign/notarize）全部强绑定 macOS，无法在其他系统编译；
- **想跑 Windows 版**：Mac 用 Parallels/UTM 装 Windows 11、或租云服务器；
- 一期只跑一端也完全可行，Qt 工程本身保证"将来回到另一端时直接 build 过"。详见 [05.Qt桌面端实现](/pages/mp5qt0/) §2。

**Q8：Windows 平台为什么同时有 Qt 版和 WPF 版？是不是重复？**
不重复，这是本案例最有价值的"**真实工程路线对照**"：
- **Qt 版**（[05](/pages/mp5qt0/)）：工程效率优先，一份代码三端通吃，招聘匹配跨平台桌面岗（WPS、VSCode、Figma 桌面）；
- **WPF 版**（[06](/pages/mp5win0/)）：平台融入优先，Fluent UI 与 SMTC 融入最深，启动最快包体最小，招聘匹配 Windows 原生岗（Office 插件、企业 OA）；
- 这两条路线真实工程里都存在，让你在同一需求下亲手实现两次，才能真正判断"下一个新项目该选哪条"。详见 [05.Qt桌面端](/pages/mp5qt0/) §1.3 的详细对照表。
