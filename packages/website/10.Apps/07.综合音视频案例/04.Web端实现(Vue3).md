## 01.本端选型说明

### 1.1 浏览器沙盒改变了什么（本端最大考点）

| 原生端能力 | Web 端的现实 |
|-----------|-------------|
| 任意扫盘 | ❌ 只能用户主动选目录（File System Access API）或拖拽导入 |
| 真后台播放 | ⚠️ 标签页切后台仍可播（音频不掐），但被节流；关页面即停 |
| 系统通知栏 | ⚠️ Media Session API 提供系统级媒体控件（锁屏/媒体键） |
| 系统 EQ | ❌ 无系统 EQ → 用 Web Audio API 自建（反而教学价值更高） |
| 静态部署零安装 | ✅ 原生端做不到的优势 |

**结论**：Web 端不是"残血原生"，而是"**同一需求在沙盒约束下的重新设计**"——文件导入交互、PWA、Web Audio 都是本端独有亮点。

### 1.2 技术选型

- **Vue 3 + `<script setup>` + TS**：Composition API 与五端"ViewModel"心智对齐；
- **Pinia**：天然就是架构篇的 Controller 层；
- **Dexie**：IndexedDB 的最好封装，存 MediaItem 元数据 + File 句柄；
- 不引入 UI 组件库（自绘，保持与其他端视觉一致）。

## 02.工程搭建与 MVP 骨架 【阶段①】

**灵魂三问**：

> 1. 为什么用 `<audio>` 元素而不是 Web Audio 直解？（答：`<audio>` 免费获得解码/缓冲/流式，Web Audio 是处理链）
> 2. 为什么不用 `new Audio()` 而是模板里写 `<audio ref>`？
> 3. Vite 的 `public/` 和 `src/assets/` 放测试素材有什么区别？

- Step 2.1 `pnpm create vite mini-player-web --template vue-ts`
- Step 2.2 `public/media/` 放测试素材
- Step 2.3 最小 UI：一个按钮 + `<audio>` 元素 + 播放/暂停切换
- Step 2.4 播放本地 URL + `ended` 事件
- 🧪 **验收**：点按钮出声；DevTools Network 看到媒体请求

## 03.媒体导入与列表 【阶段②】

> 🎯 **阶段目标**：两种导入方式（File System Access API 选目录 + 拖拽/文件选择器），解析元数据，三 Tab 列表。

## 04.播放控制与状态管理 【阶段③⭐】

**灵魂三问**：

> 1. Pinia store 里该不该直接持有 `<audio>` 元素？（答：可以，但要用 `shallowRef` + `markRaw`，讲透 Vue 响应式代理 DOM 的代价）
> 2. `timeupdate` 事件频率只有 4Hz，进度条丝滑怎么做？（`requestAnimationFrame` 插值）
> 3. 自动播放策略：什么情况下 `play()` 会 reject？（对照原生端"想播就播"，这是沙盒纪律）

- Step 4.1 `usePlayerStore`：state 五元组（对照架构篇 §1.4）+ actions
- Step 4.2 `<audio>` 事件 → store 的翻译层（play/pause/timeupdate/ended/error）
- Step 4.3 进度条组件：拖动标志位 + rAF 插值（与 Android/iOS 同款问题）
- Step 4.4 播放模式 + `next()/previous()` 决策树
- Step 4.5 倍速 `playbackRate` + 音量/静音
- Step 4.6 `<video>` 画面层 + 音频/视频模式切换 + 全屏 `requestFullscreen`
- ⚠️ 造 BUG 现场：忘处理 `play()` 的 Promise reject → 控制台 Uncaught，UI 卡死，再修
- 🧪 **验收**：拖动丝滑；切页（路由跳转）不断播（audio 元素放在 App 根）

## 06.标签页后台 + Media Session 【阶段⑤⭐·本端平台高峰】

**灵魂三问**：

> 1. 标签页切后台，音频会被掐吗？定时器呢？（音频可播、`setInterval` 被节流到 1Hz）
> 2. 浏览器没有"通知栏"，系统媒体控件从哪来？（Media Session API + `navigator.mediaSession.metadata`）
> 3. 锁屏封面/进度怎么更新？（`setPositionState`）

- Step 6.1 `visibilitychange` 处理：后台换 `requestAnimationFrame` 为 `setInterval`
- Step 6.2 `navigator.mediaSession`：metadata（标题/艺术家/封面）+ actionHandler（play/pause/prev/next/seekto）
- Step 6.3 `setPositionState` 让锁屏进度自己走
- Step 6.4 Web Notification（歌单切歌提示）+ 权限申请时机
- Step 6.5 PWA：manifest + Service Worker 离线壳（媒体本身不入 SW，讲缓存策略）
- 🧪 **验收**：系统媒体浮窗（Win/Mac/Android Chrome）可控制播放；息屏锁屏后仍有锁屏控件

## 09.均衡器 + 睡眠定时 + 构建 【阶段⑧】

> 本端 EQ 是**五端中唯一自建 DSP 链路**的，教学价值最高。

- Step 9.1 Web Audio 接管：`MediaElementSourceNode → 10 × BiquadFilter(peaking) → Gain → destination`
- Step 9.2 自动播放策略：`resume()` 必须在用户手势里（对照三连坑）
- Step 9.3 预设/自定义曲线 + Dexie 持久化
- Step 9.4 睡眠定时：`setTimeout`（后台节流误差分析）+ GainNode 渐弱
- Step 9.5 `vite build` + 产物分析（为什么媒体不入 bundle）
- 🧪 **验收**：EQ 实时生效（延迟 < 50ms）；定时到点淡出
