## 01.本端选型说明

### 1.1 为什么选 WPF（.NET 8）而不是 WinUI 3 / WinForms / Electron / Qt

| 方案 | 优点 | 不选原因 |
|------|------|---------|
| **WPF（.NET 8）** | 成熟稳定文档全；XAML + 数据绑定天然对应 MVVM；`MediaElement` 开箱即用 | ——（选它） |
| WinUI 3 | 最"现代" Windows UI | 生态过渡期，坑多；教学资料新旧混杂 |
| WinForms | 上手最快 | 无数据绑定体系，MVVM 对照价值低 |
| Electron + Vue | 门槛最低 | 与 Web 端完全重复，零教学增量 |
| Qt 6 | 跨桌面 | 与 Linux 端完全重复，零教学增量 |

### 1.2 WPF 的 MVVM：五端"ViewModel"的最完整形态

WPF 的 XAML 数据绑定 + `INotifyPropertyChanged` + `ICommand` 是五端中**最早最完整**的 MVVM 体系（Android Jetpack 的 ViewModel+LiveData 明显借鉴了它）。本端是观察"MVVM 血统"的最佳样本，与 Android 端 §04 互为镜像。

### 1.3 `MediaElement` 的真相

WPF 的 `MediaElement` 底层是 Windows Media Player 组件（也有 FFmpeg 互操作姿势，本案例不碰）。这意味着：**格式支持取决于系统解码器**——mp3/m4a/mp4（H.264）开箱即用，flac/mkv 视系统版本而定，验收环节会专门处理格式回退提示。

## 06.SMTC + 任务栏集成 【阶段⑤⭐⭐·本端平台高峰】

> Windows 的系统媒体能力 = **SMTC（SystemMediaTransportControls）**：锁屏媒体控件、音量浮窗、任务栏缩略图、蓝牙/耳机按键全部接这一处。

**灵魂三问**：

> 1. SMTC 与 Android MediaSession、Linux MPRIS 在架构上谁像谁？（SMTC≈MediaSession：平台 API；MPRIS：开放协议——五端平台哲学对照收官）
> 2. WPF 没有官方 SMTC 封装，`MediaElement` 如何对接？（`SystemMediaTransportControlsInterop` 句柄桥接，本端最硬核一步）
> 3. SMTC 回调在什么线程？直接改 ViewModel 会怎样？

- Step 6.1 `SystemMediaTransportControlsInterop.SetForWindow` 拿到控件实例
- Step 6.2 更新 `DisplayUpdater`：标题/艺术家/封面缩略图
- Step 6.3 `ButtonPressed` 事件：play/pause/next/prev 四命令（回调 `Dispatcher.Invoke` 回 UI 线程）
- Step 6.4 `TimelineProperties`：进度/跳转支持（锁屏拖动进度条）
- Step 6.5 任务栏缩略图按钮（`TaskbarItemInfo`）+ 任务栏进度条两种玩法
- Step 6.6 视频后台最小化自动暂停
- ⚠️ 造 BUG 现场：故意不桥接句柄 → SMTC 控件出现但全是灰的，再修
- 🧪 **验收**：锁屏/音量浮窗/任务栏三处均可控制；耳机按键可用
