## 01.本端选型说明

### 1.1 为什么选 Qt 6 Widgets 而不是 GTK / Qt QML / 终端 UI

| 方案 | 优点 | 不选原因 |
|------|------|---------|
| **Qt 6 Widgets** | QMediaPlayer 10 行出声；信号槽天然对应五端"状态广播"；CMake 一等公民 | ——（选它） |
| GTK4 + GStreamer | 最"GNOME 原生" | 代码量 ×1.5，GStreamer 手动管线对新手过重 |
| Qt QML | 动效华丽 | 与 WPF/UIKit 心智重叠度低，教学对照性弱 |
| ncurses 终端播放器 | C++ 纯度高 | 视频画面层没法学，与产品需求冲突 |

### 1.2 Qt Multimedia 的真相：它只是"遥控器"

`QMediaPlayer` 不解码媒体——它把工作交给**平台媒体后端**（Linux 上是 GStreamer）。这个架构事实决定：

1. 装环境必须装 GStreamer 插件（`good/bad/libav`），缺插件 = 永远 Error 态（§07 高频坑）；
2. 视频渲染用 `QVideoWidget`，我们不碰解码（与五端"不碰 FFmpeg"原则一致）。

## 02.环境搭建：五种运行方案 【会话0】

> **没有 Linux 电脑也能完成本端**。五种方案按推荐度排序，选一种即可。

### 方案 A：原生 Linux（最推荐）

**环境**：Ubuntu 22.04 / 24.04 LTS 桌面版。

```bash
# 1. 安装工具链与 Qt 6（Ubuntu 24.04 自带 Qt 6.4）
sudo apt update
sudo apt install -y \
  build-essential cmake ninja-build \
  qt6-base-dev qt6-multimedia-dev \
  libsqlite3-dev libtag1-dev \
  gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-libav

# 2. 构建与运行
cd mini_player/linux-cpp
cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
./build/MiniPlayer        # ← 弹出原生窗口
```

**验收**：弹窗出现 + 终端无 GStreamer 报错。

### 方案 B：macOS + UTM 虚拟机（Mac 用户首选）

1. App Store 装 [UTM](https://mac.getutm.app/)；
2. 下载 Ubuntu 24.04 **ARM64** 桌面版镜像（Apple Silicon）/ x86_64（Intel）；
3. 新建虚拟机：4 核 / 8GB / 64GB，装系统；
4. UTM 设置开启 **共享目录**（SPICE WebDAV）或直接 `git clone`；
5. 进入系统后执行方案 A 的命令。

**音频**：UTM 默认virtio声卡可用；若无声，设置里把声卡改为 virtio。

### 方案 C：Windows 11 + WSL2 + WSLg（Windows 用户首选）

Windows 11 的 WSL2 自带 **WSLg**，Linux GUI 应用直接弹到 Windows 桌面，不需要任何 X Server。

```powershell
# PowerShell（管理员）
wsl --install -d Ubuntu-24.04
```

```bash
# 进入 WSL 后，执行方案 A 的安装与构建命令
# 运行后窗口像原生 Windows 程序一样弹出，还能钉到任务栏
```

**音频**：WSLg 支持 PulseAudio 直通，多数情况开箱有声；无声时在 `/etc/wsl.conf` 检查 `guiApplications=true`。

### 方案 D：Docker + X11 转发（仅 CI 验证，不推荐开发）

```bash
xhost +local:docker
docker run --rm -it \
  -e DISPLAY=$DISPLAY \
  -v /tmp/.X11-unix:/tmp/.X11-unix \
  -v $(pwd):/app -w /app \
  ubuntu:24.04 bash
# 容器内：apt 安装方案 A 依赖 → cmake 构建
```

音频需要额外挂 PulseAudio socket，播放器体验差，**只用于验证"代码能否编译"**。

### 方案 E：云主机 + VNC（不推荐做播放器）

腾讯云/阿里云 Ubuntu 桌面版 + TigerVNC + RealVNC Viewer。音频走网络延迟明显，仅适合纯 UI 截图。

### 五方案对照表

| 方案 | 窗口体验 | 音频 | 学习成本 | 推荐场景 |
|-----|---------|-----|---------|---------|
| **A. 原生 Linux** | ★★★★★ | ★★★★★ | ★ | 有闲置 PC / 双系统 |
| **B. macOS + UTM** | ★★★★ | ★★★★ | ★★ | Mac 用户首选 |
| **C. Windows + WSLg** | ★★★★ | ★★★ | ★ | Windows 11 用户首选 |
| D. Docker + X11 | ★★ | ★ | ★★★ | 仅 CI 构建验证 |
| E. 云主机 + VNC | ★ | ✗ | ★★ | 不推荐 |

### IDE 选择

- **Qt Creator**（`sudo apt install qtcreator`）：Designer 拖 UI + 调试器一体化，推荐；
- VS Code + CMake Tools + clangd：喜欢 VS Code 的话；
- 命令行 + gdb：本端文档验收命令全部给出命令行形式，不绑定 IDE。

## 07.系统托盘 + MPRIS 【阶段⑤⭐⭐·本端平台高峰】

> Linux 没有"通知栏常驻服务"的 Android 概念，等价能力 = **系统托盘 + D-Bus MPRIS 协议**。

**灵魂三问**：

> 1. 关掉窗口音乐就停，怎么"最小化到托盘继续播"？（`closeEvent` 拦截 + hide）
> 2. GNOME/KDE 的锁屏媒体控件、键盘媒体键从哪读状态？（MPRIS D-Bus 标准协议）
> 3. 为什么 MPRIS 是"协议"而 Android MediaSession 是"API"？（Linux 桌面的自由拼装哲学）

- Step 7.1 `QSystemTrayIcon`：托盘菜单（播放/暂停/上下首/退出）
- Step 7.2 `closeEvent` 拦截 → hide 到托盘 + 首次气泡提示
- Step 7.3 D-Bus 基础 15 分钟速成：总线/服务名/对象路径/接口
- Step 7.4 MPRIS 实现：`org.mpris.MediaPlayer2` + `org.mpris.MediaPlayer2.Player` 两个 XML 定义 → `qdbusxml2cpp` 生成骨架 → 实现属性（PlaybackStatus/Metadata/Position）与方法（Play/Pause/Next/Seek）
- Step 7.5 `Seeked` 信号：拖动进度条后广播，锁屏控件同步跳
- Step 7.6 GNOME Shell / KDE Plasma 锁屏控件实测（截图验收）
- ⚠️ 造 BUG 现场：故意不处理 D-Bus 服务名冲突，同跑两个实例 → 注册失败，再修（唯一实例锁）
- 🧪 **验收**：托盘控制 OK；锁屏出现 MiniPlayer 控件；键盘媒体键可控制
