# 第七章：MiniPlayer 挑战题与扩展

完成五端实现后，本篇给出四个方向的进阶路线。每个方向独立成题，含目标、难度、提示与验收标准，适合作为组队学习或训练营的赛题。

---

## 7.1 方向一：第六端——macOS（Swift + SwiftUI）

| 项目 | 说明 |
|------|------|
| 难度 | ★★★★ |
| 预估 | 15 - 20 小时 |
| 前置 | iOS 端已完成（大量 AVFoundation 知识可复用） |

**目标**：用 Swift + SwiftUI 复刻 MiniPlayer 核心功能（阶段①-⑤）。

**提示**：

- 播放引擎与 iOS 同源（`AVPlayer`），可对照 [03.iOS端实现](/pages/mp5ios0/) 看清"同框架、不同平台惯例"；
- macOS 特有考点：`NSWindow` 多窗口、菜单栏（`MenuBarExtra`）、Dock 徽标进度、替代 iOS 锁屏控件的 `MPNowPlayingInfoCenter`（macOS 上作用于控制中心）。

**验收**：菜单栏迷你控制器 + 播放 + 媒体库三 Tab + 持久化。

---

## 7.2 方向二：HLS 流媒体播放

| 项目 | 说明 |
|------|------|
| 难度 | ★★★☆ |
| 预估 | 6 - 10 小时/端 |
| 前置 | 任一端阶段③完成 |

**目标**：在已有播放器上增加"网络流"入口，播放 HLS 直播/点播源。

**五端要点**：

| 端 | 方案 |
|----|------|
| Android | ExoPlayer 原生 HLS |
| iOS | AVPlayer 原生 HLS（苹果自家协议） |
| Web | Safari 原生 / 其余用 hls.js |
| Linux | GStreamer `hlsdemux`/`souphttpsrc` |
| Windows | FFmpegInteropX 或系统支持视 codec 而定 |

**进阶**：自建 Nginx + ffmpeg 推流，把"直播自己的桌面"作为端到端素材。

**验收**：播放一个公开 HLS 测试源，起播 < 3 秒，seek 正常。

---

## 7.3 方向三：云同步与多端接力

| 项目 | 说明 |
|------|------|
| 难度 | ★★★★★ |
| 预估 | 20+ 小时 |
| 前置 | 任两端已完成 |

**目标**：最小服务端（Go 或 Node.js）+ 五端接入，实现"我喜欢/播放历史/断点"跨端同步。

**设计要点**：

1. 数据模型直接复用架构篇 §1.3（PlayRecord/Favorite 已天然是同步友好的 append-only 结构）；
2. 服务端只做三张表的 REST CRUD + JWT 鉴权，不做实时推送（v1）；
3. 冲突策略：断点取"最后播放时间更大者"，收藏做并集；
4. 安全基线：鉴权全链路、SQL 全参数化、上传文件白名单 + 大小限制。

**验收**：手机听歌到 1:23，桌面端打开同一首自动续播。

## 7.4 方向四：车机与 IoT 延伸

衔接本卷其他章节：

| 题目 | 要点 | 关联 |
|------|------|------|
| Android Auto 媒体浏览 | `MediaBrowserServiceCompat` + `MediaSession` 树形浏览 | Android 卷 |
| 树莓派点唱机 | Linux 端代码交叉编译 ARM64 + GPIO 按键切歌 | Linux/IoT 卷 |
| 语音点歌 | 树莓派 + 麦克风 + 离线 ASR → MPRIS 控制播放 | IoT 卷 |

## 7.5 毕业自测清单

全部答对，说明五端案例真正吃透：

1. 五端的"播放状态唯一数据源"分别落在哪个类？（每端报出类名）
2. 进度条拖动标志位问题在几端出现过？为什么这是必然问题？
3. Android ForegroundService / iOS AVAudioSession / Web 媒体键 / Linux MPRIS / Windows SMTC——哪个是"协议"哪个是"API"？背后平台哲学差异是什么？
4. 五端文件扫描 API 分别是什么？各自的沙盒/权限模型差异？
5. 如果明天要支持一个新格式（如 opus），五端分别要动哪里？
