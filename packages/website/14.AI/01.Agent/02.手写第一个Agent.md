## 一、概念篇（30%）

### 1.1 Function Calling 的原理演进

- 早期方案：Prompt 里塞 JSON 示例，让 LLM"模仿输出"
- 微调时代：OpenAI 用 `function_call` 微调 GPT-3.5-turbo-0613
- 现代方案：原生 Tool Use（Anthropic）、tools 字段（OpenAI）
- 开源模型的追赶：Qwen、DeepSeek、Llama 3 的 tool calling 实现

### 1.2 Tool Schema 的构成

- JSON Schema 规范速览
- name / description / parameters 三要素
- required / enum / anyOf 等进阶特性

### 1.3 OpenAI / Anthropic / 开源模型的差异

- API 形态对比表
- tool_choice 语义差异
- 并行调用（parallel_tool_calls）的支持情况

## 三、思考篇（20%）

### 3.1 Tool 粒度的取舍

- 一个万能 `run_command` vs 多个原子 Tool（`git_log` / `git_diff` / `git_commit`）
- 粒度决策：LLM 能力 × 使用频率 × 安全边界

### 3.2 Safety：Agent 操作数据库/文件系统时的沙箱策略

- 白名单目录
- 只读 vs 读写模式切换
- 危险操作二次确认

### 3.3 Tool 描述的 Prompt Injection 风险

- 用户输入不能直接拼进 tool description
- Schema 校验层要拦截超长/异常字符
