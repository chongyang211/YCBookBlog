## 0️⃣ 一句话定位

从 `std::vector<uint8_t>` 就是一片内存开始，**13 个阶段徒手造一台能跑自己写的汇编程序的"迷你计算机"**，把《计算机组成原理》12 篇专栏的每一个知识点都在自己代码里落一遍。

学完之后你能做到：

- 拿到任何一段 C 代码，说出它在真实计算机里走了几层（补码 → 指令 → 缓存 → TLB → 中断 → DMA → epoll）
- 手写 `fib.asm`，看着它经过词法 → 汇编器 → 二进制 → 内存 → 流水线 → 缓存 → 显示器全链路
- 亲手拉过 8 个"造 BUG"闸门（列优先慢 10 倍 / 伪共享 / 缺页 / 死循环 / 粘包 …），真正理解每一层抽象**为什么长这样**

## 4️⃣ 八次"造 BUG → 修复"高峰全览（对齐 06 §"造 BUG 高峰"清单）

| # | 阶段 | 造什么 BUG | 打脸现场 | 修复方案 |
|---|------|----------|--------|--------|
| 1 | ③ 二进制 | 把 `0.1 + 0.2` 用 IEEE754 加法器算 | 输出 `0.30000000000000004` | 定点数 / decimal 表示 / `epsilon` 比较 |
| 2 | ⑥ 流水线 | 关掉分支预测跑排序数组遍历 | 有序数组慢 3× 于同规模无序 | 打开 2bit 饱和计数器预测 |
| 3 | ⑦ 缓存 | 512×512 矩阵按列优先遍历 | **12s → 0.8s**（15× 打脸）| 改行优先 + 分块 |
| 4 | ⑧ MESI | 双核两线程各写相邻 int（同缓存行）| 加 padding 前后 **QPS 4× 差**| 按 64B 对齐 padding |
| 5 | ⑨ 虚拟内存 | 写地址 `0x0`（未映射页）| MMU 报 page fault → 你自己的 handler 打印栈 | 内核态 handler 映射 + 陷入返回 |
| 6 | ⑩ NUMA | 强制把线程绑在 socket0、内存分在 socket1 | 跨 NUMA 访问慢 30% | 绑核 + `numa_alloc_local` |
| 7 | ⑫ 异常 | 汇编里 `DIV 0` 触发陷阱 | 你自己写的 `#DE` handler 打印 `PC = 0x100C` backtrace | 陷入门返回 · 用户态感知不到 |
| 8 | ⑬ IO | 阻塞 `read()` 等键盘时磁盘任务卡死 | Reactor 看到"单线程串行只能等" | `epoll_wait` + 非阻塞 fd |

> 每个高峰都严格遵循**"先写有 bug 的最小可编译版 → 亲眼看到崩溃/慢速 → 用一句话解释原因 → 写修复版 → benchmark 打脸对比"** 五步法。这与 05 §Step 4.2 超卖现场、06 §Step 10.1 计数器变 1837 完全同源。

## 5️⃣ 阶段拆解到 Step 级别（预告正文详细度）

下面每个阶段列出 Step 级拆解（正文里每个 Step 都会配代码 + 编译命令 + 预期输出）。

### 阶段 ① 骨架 REPL（对应专栏 01）· 1.0h

- Step 1.1 最小 `main` + `while(readLine)` REPL
- Step 1.2 `enum class Cmd { LOAD, RUN, STEP, DUMP, QUIT }`
- Step 1.3 `Machine` 类持有五大部件的空指针（占位）
- Step 1.4 `dump()` 命令打印"五大部件都在，但都是空的"骨架图
- 🧪 验收：`>>> dump` → 打印 5 行 `[Empty] Cpu / Memory / Bus / Io / Ctrl`
- 📌 小结：**冯·诺依曼五大件是骨架，接下来一件件填肉**

### 阶段 ② 存储分层（对应专栏 02）· 1.0h

- Step 2.1 `Storage` 抽象基类：`read/write(addr, n)`
- Step 2.2 `Register`（1 拍延迟）· `Memory`（100 拍延迟）
- Step 2.3 延迟计数器 `Storage::stats()` → 打印命中/访问总时间
- Step 2.4 局部性演示：连续访问 vs 随机访问 · 打印时间比
- 🧪 验收：连续读 100 字节 vs 跳读 100 字节，延迟比 ≈ 1:8
- 📌 小结：**"数据在哪里、多快到"就是存储层次的根本矛盾**

### 阶段 ③ Word · 补码 · 浮点（对应专栏 10）· 1.5h · 🔥 造 BUG 高峰 1

- 💭 **灵魂三问**：为什么整数用补码？为什么浮点会不精确？为什么大小端存在？
- Step 3.1 `Word` = `uint32_t` 包装 · `toBinary()` / `fromHex()` / `endianSwap()`
- Step 3.2 补码加减法器：实现 `add(a, b)` 只用位运算
- Step 3.3 **【造 BUG】** 手写 IEEE754 加法：`fadd(0.1f, 0.2f)` 输出 `0.30000000000000004`
- Step 3.4 位运算实战：`countOnes` / `nextPow2` / bitset 打印
- 🧪 验收：`printf("%.17f", fadd(0.1, 0.2))` 打脸对账系统"一分钱差异"根因
- 📌 小结：**万物皆位 · 补码让减法变加法 · 浮点是"近似"不是"精确"**

### 阶段 ④ ISA & Decoder & masm（对应专栏 07）· 2.0h

- 💭 **灵魂三问**：为什么先定 ISA 再造 CPU？为什么 RISC 只有 40 条指令？7 种寻址方式都必须吗？
- Step 4.1 12 条自定义 RISC 指令：`MOV/ADD/SUB/AND/OR/XOR/JMP/JZ/CALL/RET/LOAD/STORE`
- Step 4.2 指令编码：4-bit opcode + 4-bit rd + 8-bit rs/imm（每条 32bit）
- Step 4.3 7 种寻址方式：立即数 / 寄存器 / 直接 / 间接 / 变址 / 相对 / 基址+偏移
- Step 4.4 `Decoder::decode()` 用 `std::variant<InstAdd, InstJmp, ...>`
- Step 4.5 `masm` 汇编器：读 `.asm` 文件 → 输出 `.bin`
- Step 4.6 `mdisas` 反汇编器：`.bin` 反查回汇编
- 🧪 验收：`masm demo/add.asm && mdisas demo/add.bin` 首尾相符
- 📌 小结：**ISA 是软硬件契约 · 代码密度 vs 硬件复杂度**

### 阶段 ⑤ 单周期 CPU（对应专栏 03 微架构部分）· 2.0h

- Step 5.1 `Cpu` 类 + 8 个通用寄存器 + PC/FLAGS
- Step 5.2 `fetch()` → `decode()` → `execute()` 大循环
- Step 5.3 ALU：加减/逻辑/移位（复用阶段 ③ 的位运算加法器）
- Step 5.4 跑 `add.bin`（3+5=8）→ dump 寄存器
- Step 5.5 跑 `fib.bin` 前 10 项（不含函数调用，纯循环版）
- Step 5.6 **Amdahl 计算**：假设 CPU 花 60% 时间在 ALU，ALU 提速 5× 整体提速多少
- 🧪 验收：`mmach --trace demo/fib.bin` 打印 10 步的 PC/寄存器变化
- 📌 小结：**CPU = 状态机 · 每拍一个指令 · CISC/RISC 的取舍**

### 阶段 ⑥ 5 级流水线 & 分支预测（对应专栏 08）· 2.0h · 🔥 造 BUG 高峰 2

- 💭 **灵魂三问**：为什么流水线快 5 倍是理论上限？数据冒险为什么需要前递？分支预测为什么这么重要？
- Step 6.1 拆 5 stage：`IfStage / IdStage / ExStage / MemStage / WbStage`
- Step 6.2 数据冒险检测 · 前递（forwarding）实现
- Step 6.3 控制冒险：分支时清空流水线（stall）
- Step 6.4 **【造 BUG】** 无分支预测跑排序数组求和 · 记录拍数
- Step 6.5 加入 2bit 饱和计数器预测器 · 有序数组快 3×
- Step 6.6 打脸 benchmark 表格：无序/有序 × 有预测/无预测 四组
- 🧪 验收：预测命中率 ≥ 92%（有序输入）· CPI 从 1.8 降到 1.15
