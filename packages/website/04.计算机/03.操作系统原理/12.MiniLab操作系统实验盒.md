# MiniLab 迷你操作系统实验盒 · 综合案例（C++20 从 0 到 1 徒手造 12 个 OS 子系统小模型）

> **一句话定位**：不造一台完整的 OS，而是造 **12 个独立的"小盒子"**——每盒 100~500 行 C++20，对应《操作系统原理》一节知识点，共用一套 REPL + CSV 导出 + 可视化框架。把 §01~§10 每一节的"核心抽象"都在自己代码里落一遍，并用 **7 次"造 BUG → 打脸"**反向教学。
>
> **📂 配套代码仓库**：`code/Project/MiniLab/`（6 次会话全部完成，共约 **4800 行 C++ + 400 行 Python 画图脚本**，可直接 `make build && make demo-all` 跑通，所有图表自动生成到 `out/plots/`）
>
> **📖 本篇结构**：Part 1 顶层设计方案 · Part 2 第 1 次会话（盒 ①②）· Part 3 第 2-6 次会话（盒 ③-⑫ 阶段卡清单） · Part 4 代码仓库使用指南 · Part 5 后续路线

## 00.从这里开始：这个案例值不值得做？

┌─ 👀 三分钟自检 ───────────────────────────────────────────┐
│ ① 你读完《操作系统原理》10 篇，仍然觉得"知道了"但"用不上"？   │
│ ② 你能背 CFS vruntime 公式，但从没亲眼看过一次调度甘特图？     │
│ ③ 你知道 epoll 比 select 快，但不敢说"10000 连接下快几倍"？   │
│ ④ 你会用 `docker run`，但没亲手 `unshare` 过 PidNamespace？   │
│ ⑤ 你用过 `malloc`，但不知道"free 完内存为什么没还给 OS"？     │
└─────────────────────────────────────────────────────────────┘

只要有一个 ✅，本案例就是给你的。学完之后你能：

- 拿到任何一台机器的性能问题，知道从哪个"盒子"的实验现象出发复现
- 手写 500 行以内的 **调度器 / malloc / 页替换 / inode FS / epoll 服务器 / 协程 / 容器**
- 亲手拉过 **7 个"造 BUG"闸门**：僵尸进程堆积 · 死锁 · ptmalloc 碎片 · Belady 异常 · lsof 占用 · EPOLLET 漏读 · cgroup OOM 误杀
- 每盒都有**漂亮的图表**（甘特图 / 命中率曲线 / 吞吐柱状图 / 碎片率演变 / 资源监控），直接可以贴博客 / PPT

**⚠️ 请务必接受两件事**：

1. **这不是"照抄代码就完事"的项目**。每个盒子都有必看的"失败现场"——跳过 = 白学。
2. **12 个盒子互相独立**，没有"总装"那种高潮，但好处是：**每盒 2-4 小时可独立交付、可独立 commit、可独立贴博客**。你可以周末只做一盒不用担心"烂尾"。

# Part 1 · 顶层设计方案（12 个盒子的建筑总图纸）

## 01.📚 渐进学习节奏（最重要的一段，务必先读）

**本案例按"实验盒"节奏推进**，不同于迷你冯·诺依曼机 / MiniNet 的"大工程 14/16 阶段"。节奏是：

  盒 ② box_coro  用户态有栈协程 + N:M 调度    · 1.5h · 4 Step  🔥 BUG-1 僵尸堆积

【第 2 次会话 · 3.0h · CPU 调度】
  盒 ③ box_sched 五种调度器 + 甘特图可视化    · 3.0h · 5 Step

【第 3 次会话 · 3.5h · 并发 & IPC】
  盒 ④ box_ipc   四种 IPC 带宽压测            · 1.5h · 4 Step
  盒 ⑤ box_lock  哲学家就餐 + 死锁 + 银行家    · 2.0h · 4 Step  🔥 BUG-2 AB-BA 死锁

【第 4 次会话 · 4.0h · 内存管理 ⭐⭐】
  盒 ⑥ box_malloc 迷你 malloc(Buddy+Slab+bins) · 2.0h · 5 Step 🔥 BUG-3 碎片不回收
  盒 ⑦ box_vm    页替换算法模拟器              · 2.0h · 4 Step 🔥 BUG-4 Belady 异常

【第 5 次会话 · 4.0h · 存储 & IO ⭐】
  盒 ⑧ box_fs    inode FS + mkfs + ls         · 2.0h · 5 Step 🔥 BUG-5 lsof 占用
  盒 ⑨ box_io    select/poll/epoll 10k 压测   · 2.0h · 4 Step 🔥 BUG-6 EPOLLET 漏读

【第 6 次会话 · 3.5h · 设备 & 容器（仅 Linux）】
  盒 ⑩ box_drv   内核模块 /dev/myecho          · 1.0h · 3 Step
  盒 ⑪ box_ns    unshare + pivot_root 假容器   · 1.0h · 3 Step
  盒 ⑫ box_cgrp  Cgroup v2 CPU/Memory 限额    · 1.5h · 4 Step 🔥 BUG-7 PageCache 误算

**每个 Step 必须做的三件事**（和 MiniNet 一致）：

> 1. **看 🎯 Step 目标**：明确做什么、不做什么、验收标准
> 2. **写一小段代码就 `cmake --build build -j` 一次**（增量编译 1-3 秒）
> 3. **看到预期输出再进下一个 Step**（**绝不一口气抄完整段代码**）

**每盒的结构模板**（Part 2 会反复看到）：

```text
┌─ 🎯 盒目标卡 ─────────────────┐  ← 盒开头：明确做什么/不做什么
│  完成什么 · 不做什么 · 验收标准 │
└─────────────────────────────┘

   灵魂三问（动手前先想清楚）

   Step X.1：先写最小可编译版（10-30 行）
   Step X.2：make build && ./bin/box_xxx → ✅ 看到预期输出
   Step X.3：再加一个小功能（10-50 行）
   ...

┌─ 🐞 可能踩的坑 & 排错指南 ──┐
┌─ 🧪 盒运行验证 ─────────────┐
┌─ 📊 产出图表（自动生成） ────┐
┌─ 📌 盒小结 · 一句话拎走 ────┐
```

**⚠ 关于"造 BUG 高峰"**（本案例 7 处）：每处都严格五步法：

> 1. 写一个有 bug 的最小可编译版（故意的！）
> 2. 跑起来亲眼看到崩溃 / 慢速 / 错误输出
> 3. 用一句话说清为什么会这样
> 4. 写修复版
> 5. benchmark 修复前后对比（钉死数值）

## 04.为什么选 C++20（技术选型论证）

### 4.1 为什么不选 Python / Rust / Go？

| 维度 | **C++20** | Python | Rust | Go |
|------|-----------|--------|------|-----|
| 与 OS 原语的距离 | ✅ 直接调 `fork/clone/epoll/mmap` | ⚠️ 得绕一层 FFI | ✅ unsafe 可直调 | ⚠️ runtime 托管 |
| 教学匹配度 | ✅ 《C++ 入门到精通》正好 | ❌ 看不到指针/栈 | ⚠️ 所有权分散注意力 | ❌ GC 隐藏内存管理 |
| 性能可信度 | ✅ `-O2` 即 bench 可信 | ❌ 慢 10-50 倍 | ✅ | ✅ |
| 盒 ⑥ 自写 malloc | ✅ `placement new` 原生支持 | ❌ 做不出 | ⚠️ 要走 `GlobalAlloc` 复杂 | ❌ GC 冲突 |
| 盒 ② 协程切换 | ✅ `ucontext` / `boost.context` | ⚠️ 只能用 `greenlet` | ⚠️ `async` 无栈，看不到栈切换 | ❌ 完全看不到调度器 |
| 画图 | ⚠️ 需 `matplotlib-cpp` | ✅ 原生强 | ⚠️ `plotters` 弱 | ⚠️ 库少 |

**折衷策略**：**C++ 写盒子、Python 画图**。C++ 盒子跑完输出 CSV，Python `plot.py` 统一读 CSV 画 PNG。这样 C++ 只用做 C++ 擅长的事，Python 只负责 10 行 `matplotlib` 的事。

### 4.2 为什么选 C++20 而不是 C++11/14/17？

- `std::jthread` + `std::stop_token`：盒 ⑤ 优雅退出不写一个 `shouldStop` 原子
- `std::span<T>`：盒 ⑦ 页替换"窗口"和盒 ⑥ malloc "块视图"参数一致
- `std::format` / `fmt::print`：盒 ③ 甘特图 ASCII 对齐省心
- `concepts` + `requires`：盒 ③ 五个调度器 CRTP 多态更干净
- 协程 `co_await`（但本案例**故意不用**协程语法）：盒 ② 坚持用 `ucontext` 手写，让你亲眼看到栈切换

### 4.3 为什么用 CMake 而不是 bazel / meson

- 和迷你冯·诺依曼机保持一致（降低学习摩擦）
- 12 盒 = 12 个 `add_executable`，一个 `file(GLOB)` 搞定

### 4.4 为什么不接管全局 `operator new`

盒 ⑥ 自写 malloc 是**在私有 arena 里演示算法**，不劫持进程全局分配。原因：

- 劫持 `operator new` 会导致 `std::vector` / `fmt::print` 全部走你的分配器 → 一个 bug 直接 segfault 看不到打印
- 教学目的是看懂 **Buddy 位图 / Slab cache / bins 索引** 的算法，不是取代 glibc
- 想接管的留作毕业作业（README 里有提示路径）

## 05.工程化五件套：如何保证"可运行可观测可对照"

### 5.1 件 1：统一 REPL 框架 `common/repl.hpp`

每盒都自带一个 10 行 REPL 骨架：

```cpp
// common/repl.hpp（简化示意，完整版见代码仓库）
#pragma once
#include <functional>
#include <string>
#include <string_view>
#include <unordered_map>
#include <vector>
#include <iostream>
#include <sstream>

namespace mlab {
class Repl {
public:
    using Cmd = std::function<void(const std::vector<std::string>&)>;
    void reg(std::string name, std::string help, Cmd f) {
        cmds_[name] = {std::move(help), std::move(f)};
    }
    int run(std::string_view prompt = ">>> ") {
        std::string line;
        while (std::cout << prompt && std::getline(std::cin, line)) {
            if (line.empty()) continue;
            auto args = split(line);
            if (args[0] == "quit" || args[0] == "exit") return 0;
            if (args[0] == "help") { show_help(); continue; }
            auto it = cmds_.find(args[0]);
            if (it == cmds_.end()) { std::cout << "unknown: " << args[0] << "\n"; continue; }
            try { it->second.fn({args.begin() + 1, args.end()}); }
            catch (const std::exception& e) { std::cout << "err: " << e.what() << "\n"; }
        }
        return 0;
    }
private:
    struct Entry { std::string help; Cmd fn; };
    std::unordered_map<std::string, Entry> cmds_;
    static std::vector<std::string> split(const std::string& s) {
        std::vector<std::string> r; std::stringstream ss(s); std::string tok;
        while (ss >> tok) r.push_back(tok);
        return r;
    }
    void show_help() {
        for (auto& [k, v] : cmds_) std::cout << "  " << k << " - " << v.help << "\n";
    }
};
}  // namespace mlab
```

**12 盒子都用这个 REPL**。好处：你学会一套交互模式，用 12 遍。

import sys, pandas as pd, matplotlib.pyplot as plt
from pathlib import Path

def plot_sched(df, out):      # 甘特图
    fig, ax = plt.subplots(figsize=(12, 4))
    for _, r in df.iterrows():
        ax.barh(r['pid'], r['dur'], left=r['start'], height=0.6)
    ax.set_xlabel('time (ms)'); ax.set_ylabel('PID')

        plt.plot(sub['frame'], sub['hit_rate'], label=algo, marker='o')
    plt.xlabel('frames'); plt.ylabel('hit rate'); plt.legend()
    plt.savefig(out, dpi=120); plt.close()

if __name__ == '__main__':

    {'sched': plot_sched, 'vm': plot_vm, ...}[kind](df, out)

## 09.盒 ① `box_proc` 进程状态机 + fork/exec/wait（对应专栏 §01）

┌─ 🎯 盒 ① 目标卡 ────────────────────────────────────────┐
│ 完成什么：REPL 支持 `spawn/kill/ps/zombie` 四条命令；       │
│          真实 `fork+exec+wait`，自己画 ASCII 进程树        │
│ 不做什么：不实现 PCB 结构体（因为用的是真 Linux 进程）        │
│ 验收标准：`spawn sleep 3` 后 `ps` 能看到自己的子进程         │
│          `zombie 10` 能触发 BUG-1 并被 `--fix` 修复        │
│ 预计耗时：1.5h · 4 Step                                   │
└─────────────────────────────────────────────────────────┘

💡 **为什么从进程开始？**——因为 fork+exec 是 Unix 哲学的"基本粒子"。你每天用的 `bash`、`make`、`docker`、`git commit --hook` 都是在 fork。看懂 fork，看懂 OS 一半。

⚠️ **本盒核心难点**：**fork 之后父子谁先运行是不确定的**。所以你写的所有同步代码都必须经得起"父先/子先"两种情况。

### 灵魂三问：动手前先想清楚

❓ **为什么 fork 返回两次？**  
→ 严格说只返回一次，只是**调用后两个进程继续执行**。父得到子的 PID，子得到 0。你要靠这个"返回值不同"写两条分支。

❓ **僵尸进程到底是什么？为什么要存在？**  
→ 子进程 `exit` 后内核**不能立即丢掉它**——父进程可能还想知道"退出码是多少""跑了多久"。所以保留一个最小 PCB（≈ 56 字节）等父 `wait`。父不 wait → 僵尸永远挂着。10 万僵尸 = 10 万 PID 槽位 → 系统 PID 耗尽。

❓ **孤儿进程和僵尸谁更可怕？**  
→ 孤儿不可怕——内核 PID=1 的 init（systemd）会"认养"它然后 wait。**僵尸才可怕**——父不死不 wait 它就永远挂着。

✅ **结论**：盒 ① = 让你亲眼见证"父不 wait → 僵尸堆积"的现场。

### Step 1.2 实现 `spawn`：fork + exec

💭 **写代码思路**：这是最经典的 "fork-exec 模式"。注意 fork 后**不能 malloc**（线程不安全风险）、不能持有锁。exec 失败一定要 `_exit(127)` 而不是 `exit(127)`——避免执行父进程的 atexit 回调。

替换 `cmd_spawn`：

```cpp
static void cmd_spawn(const std::vector<std::string>& args) {
    if (args.empty()) { LOG_ERR("usage: spawn <cmd> [args...]\n"); return; }
    pid_t pid = fork();
    if (pid < 0) { LOG_ERR("fork failed: {}\n", std::strerror(errno)); return; }
    if (pid == 0) {
        // --- child ---
        std::vector<char*> argv;
        for (auto& s : args) argv.push_back(const_cast<char*>(s.c_str()));
        argv.push_back(nullptr);
        execvp(argv[0], argv.data());
        // exec 返回 = 失败
        fmt::print(stderr, "[child] exec failed: {}\n", std::strerror(errno));
        _exit(127);
    }
    // --- parent ---
    children.push_back({pid, args[0]});
    LOG_INFO("spawned pid={} cmd={}\n", pid, args[0]);
}
```

**✅ 验收**：

```bash

### Step 1.3 BUG-1 复现：`zombie` 命令

💭 **写代码思路**：故意写一个"疯狂 spawn 不 wait"的命令，然后在同一个 shell 里跑 `ps -ef | grep box_proc`，亲眼看到 `<defunct>` 列队。

static void cmd_zombie(const std::vector<std::string>& args) {
    int n = args.empty() ? 10 : std::stoi(args[0]);
    for (int i = 0; i < n; ++i) {
        pid_t pid = fork();
        if (pid == 0) { _exit(0); }  // 子立即退出
        if (pid > 0) children.push_back({pid, "zombie"});
    }
    LOG_WARN("spawned {} children without wait! check `ps -ef | grep defunct`\n", n);
}
```

### Step 1.4 修复：SIGCHLD handler + waitpid（五步法第 4-5 步）

💭 **写代码思路**：在 `main` 一开始注册 `SIGCHLD` handler，handler 里循环 `waitpid(-1, &status, WNOHANG)` 清理所有已 exit 的子。注意 **`WNOHANG` 必须有**——不然 handler 会卡住。

在 `main` 前加：

```cpp
static void sigchld_handler(int) {
    int saved_errno = errno;         // 信号 handler 必须保存 errno
    while (true) {
        int status;
        pid_t pid = waitpid(-1, &status, WNOHANG);
        if (pid <= 0) break;
        // 从 children 里移除（信号 handler 里只做 async-signal-safe 操作，这里简化）
        write(STDOUT_FILENO, ".", 1);
    }
    errno = saved_errno;
}
```

`main` 开头加：

```cpp
struct sigaction sa{};
sa.sa_handler = sigchld_handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
sigaction(SIGCHLD, &sa, nullptr);
```

### Step 1.5（加分）ASCII 进程树

💭 **思路**：读 `/proc/*/stat` 的 ppid 字段（Linux），或 macOS 下用 `sysctl KERN_PROC_ALL`，建树后 DFS 打印。只做 Linux 版（30 行）：

```cpp
#include <filesystem>
#include <fstream>
#include <map>

static void cmd_tree(const std::vector<std::string>&) {
#ifndef __linux__
    LOG_WARN("tree only on Linux\n");
    return;
#else
    std::map<pid_t, std::vector<pid_t>> kids;
    std::map<pid_t, std::string> names;
    for (auto& e : std::filesystem::directory_iterator("/proc")) {
        auto name = e.path().filename().string();
        if (!std::all_of(name.begin(), name.end(), ::isdigit)) continue;
        std::ifstream st(e.path() / "stat");
        pid_t pid, ppid; std::string comm; char state;
        st >> pid >> comm >> state >> ppid;
        kids[ppid].push_back(pid);
        names[pid] = comm;
    }
    std::function<void(pid_t, int)> dfs = [&](pid_t p, int d) {
        fmt::print("{}{} {}\n", std::string(d * 2, ' '), p, names[p]);
        for (auto c : kids[p]) dfs(c, d + 1);
    };
    dfs(1, 0);
#endif
}
```

## 10.盒 ② `box_coro` 用户态有栈协程 + N:M 调度（对应专栏 §01 协程）

┌─ 🎯 盒 ② 目标卡 ────────────────────────────────────────┐
│ 完成什么：500 行实现有栈协程类 `Coroutine` + 工作窃取调度器   │
│          `co_spawn` 启动 10 万协程，证明栈 2KB 可行          │
│          `co_yield` 主动让出，`co_sleep` 定时唤醒            │
│ 不做什么：不用 C++20 的 `co_await`（故意！要看 ucontext 切换）│
│ 验收标准：10 万协程常驻内存 < 300MB（对比：10 万线程 ≈ 800GB）│
│ 预计耗时：1.5h · 4 Step                                   │
└─────────────────────────────────────────────────────────┘

💡 **为什么要手写有栈协程？**——C++20 的 `co_await` 是**无栈**协程，背后是编译器把函数拆成状态机。看不到"栈切换"的瞬间。而**有栈协程 = 两个 `ucontext_t` 之间 `swapcontext`**，你能亲眼看到 SP、PC、栈顶在切换前后的变化。

⚠️ **本盒核心难点**：**`ucontext` 已被 POSIX 标记为 Obsolete**。Linux 还好用，macOS 需要 `-D_XOPEN_SOURCE=600`。生产用 `boost::context` 更快（switch 15ns vs ucontext 500ns），但 ucontext 零依赖最适合教学。

### 灵魂三问

❓ **协程为什么比线程"轻"？**  
→ 三件事省了：① 栈小（2KB vs 8MB）② 不进内核（swapcontext 纯用户态）③ 不需要 kernel 分配 PCB。总代价 ≈ 1/100。

❓ **协程为什么必须"主动让出"？**  
→ 用户态没有时钟中断权限，只能靠协程自己 `yield`。所以**计算密集型协程会"卡死"调度器**——这是 Go runtime 后来加入"抢占式调度"的根本原因。

❓ **N:M 到底是什么意思？**  
→ N 个用户态协程**映射到** M 个 OS 线程上调度。本案例 M=hardware_concurrency（通常 8-16），N 可以是 100 万。每个 M 有自己的"本地队列"，闲了去别人队列**偷任务**（Work Stealing）。

### Step 2.1 `Coroutine` 类骨架 + ucontext 切换

📁 `boxes/02_coro/coroutine.hpp`

```cpp
#pragma once
#include <ucontext.h>
#include <functional>
#include <vector>
#include <cstddef>

namespace mlab {

class Coroutine {
public:
    enum State { Ready, Running, Suspended, Dead };

    Coroutine(std::function<void()> fn, std::size_t stack_sz = 8 * 1024)
        : fn_(std::move(fn)), stack_(stack_sz) {
        getcontext(&ctx_);
        ctx_.uc_stack.ss_sp = stack_.data();
        ctx_.uc_stack.ss_size = stack_.size();
        ctx_.uc_link = nullptr;              // 执行完返回 nullptr 则 exit(0)
        // makecontext 只能传 int 参数——用 trick：把 this 指针拆成两个 int
        auto hi = reinterpret_cast<uintptr_t>(this) >> 32;
        auto lo = reinterpret_cast<uintptr_t>(this) & 0xFFFFFFFF;
        makecontext(&ctx_, (void(*)())&Coroutine::entry, 2,
                    static_cast<int>(hi), static_cast<int>(lo));
    }

    void resume(ucontext_t* caller) {
        caller_ = caller;
        state_ = Running;
        swapcontext(caller, &ctx_);          // 关键：栈瞬移！
    }

    void yield() {
        state_ = Suspended;
        swapcontext(&ctx_, caller_);
    }

    State state() const { return state_; }

private:
    static void entry(int hi, int lo) {
        auto self = reinterpret_cast<Coroutine*>(
            (static_cast<uintptr_t>(hi) << 32) | static_cast<uint32_t>(lo));
        self->fn_();
        self->state_ = Dead;
        // 落到 uc_link=nullptr，上下文结束后会 _exit——我们改为 yield 回 caller
        swapcontext(&self->ctx_, self->caller_);
    }

    std::function<void()> fn_;
    std::vector<char> stack_;
    ucontext_t ctx_{};
    ucontext_t* caller_ = nullptr;
    State state_ = Ready;
};

}  // namespace mlab
```

**💭 关键点解释**：

- `makecontext` 的参数是 `int`，但 `this` 是 64 位指针。**不能直接传**。必须拆成高低 32 位两个 `int`，`entry` 里再拼回来。这是 ucontext 的历史债。
- `uc_link = nullptr` 意味着协程函数 return 后进程直接 `_exit(0)`——这不是我们想要的。所以 `entry` 结尾手动 `swapcontext` 回 caller。
- `stack_.data()` 要保证**栈对齐 16 字节**。`std::vector<char>` 分配器默认已对齐。

💭 **思路**：先不管 N:M，就单线程跑。写一个 `Scheduler` 持有 `std::vector<Coroutine>`，`run_until_empty()` 循环弹出每个协程 `resume` 一下，死了就 remove。

📁 `boxes/02_coro/scheduler.hpp`

```cpp
#pragma once
#include "coroutine.hpp"
#include <deque>
#include <memory>

namespace mlab {

class Scheduler {
public:
    void co_spawn(std::function<void()> fn, std::size_t stack = 8 * 1024) {
        ready_.emplace_back(std::make_unique<Coroutine>(std::move(fn), stack));
    }

    void run_until_empty() {
        getcontext(&main_ctx_);
        while (!ready_.empty()) {
            auto co = std::move(ready_.front()); ready_.pop_front();
            co->resume(&main_ctx_);
            if (co->state() != Coroutine::Dead) ready_.push_back(std::move(co));
            // 死协程 unique_ptr 在作用域结束时自动析构释放栈
        }
    }

private:
    ucontext_t main_ctx_{};
    std::deque<std::unique_ptr<Coroutine>> ready_;
};

}  // namespace mlab
```

### Step 2.4（加分）N:M 调度 + 工作窃取（简化版）

💭 **思路**：改成 `std::thread` 池 M=8，每线程一个 `Scheduler`。空闲时随机挑一个"受害者"从其 `ready_` 尾部**偷一半**任务。

class MTScheduler {
    std::vector<Scheduler> locals_;
    std::vector<std::jthread> workers_;
public:
    void run(std::size_t M = std::thread::hardware_concurrency()) {
        locals_.resize(M);
        for (std::size_t i = 0; i < M; ++i) {
            workers_.emplace_back([this, i, M](std::stop_token st) {
                while (!st.stop_requested()) {
                    if (!locals_[i].step()) {       // 本地空
                        // steal
                        auto victim = (i + 1 + rand() % (M - 1)) % M;
                        locals_[i].steal_from(locals_[victim]);
                    }
                }
            });
        }
    }
};

💡 **为什么要专门做调度器盒子？**——因为调度是 OS 里**唯一"算法纸上就能验证"**的子系统。你不需要配 MMU、不需要真跑进程，只要有一组"模拟任务"，就能把 Linux 过去 40 年所有调度器演进在 150 行里重放一遍。看懂这盒 = 看懂 `/proc/sched_debug` 的每一列。

⚠️ **本盒核心难点**：**CFS 不是公平——是加权公平**。很多人读专栏能背出"vruntime += 实际时间 × 1024/weight"但说不清为啥是 1024，为啥 nice=-20 和 nice=19 差 5917 倍。这盒就逼你用 1024 这个数本身写代码，一次搞透。

### 灵魂三问：动手前先想清楚

❓ **为什么不是时钟驱动的"真实"调度器？**  
→ 因为"真实"没有信息量。本盒目的是**对比五种算法在同一输入下的差异**。真实调度器要和时钟中断、SMP 迁移、CPU cache 热度绞在一起，掩盖算法本质。我们做"时间 tick 模拟器"：每 1ms 推进一下，拨拨算盘记录。看算法 100% 清晰。

❓ **CFS 为什么要用红黑树，而不是堆？**  
→ 两个硬需求：① **找最小 vruntime**（O(log n)——堆也能做）② **按 pid 精确删除中间节点**（因为任务 sleep/wakeup/exit 需要动态进出队列——堆做不到 O(log n) 删除任意元素）。所以必选平衡 BST。C++ 里用 `std::set` 完美模拟红黑树（libstdc++ 的 `set` 就是红黑树实现）。

❓ **MLFQ 的"周期性提升到最高级"规则，到底防什么？**  
→ 防**饥饿**。想象一个长期占 CPU 的后台编译任务，一次次被 MLFQ 降级到最低级（时间片最长），一旦有新的高优先级交互任务进来，它会**永远得不到 CPU**。周期性全部提升到最高级 = 给低级任务"赦免日"，防止无限等待。真实 Linux 的早期 O(1) 调度器就吃过这个亏，才被 CFS 取代。

✅ **结论**：盒 ③ = 用 1 个基类 + 5 个派生类，把 OS 调度器 40 年演进在 500 行里重放一遍。

### Step 3.1 `Task` 结构 + `.task` 文件解析器（~60 行）

💭 **写代码思路**：先把"任务"抽象好——这决定了后面所有算法共享的输入。字段设计原则：**算法需要什么就加什么，但要兼容最苛刻的 CFS**。CFS 需要 nice 值，所以 Task 必带 nice。响应时间需要 `first_run_at`，就加上。

📁 `boxes/03_sched/task.hpp`

```cpp
#pragma once
#include <string>
#include <vector>
#include <fstream>
#include <sstream>
#include <optional>
#include <climits>

namespace mlab::sched {

struct Task {
    std::string pid;         // 任务名（A/B/C...）
    int arrive;              // 到达时间 (ms)
    int burst;               // 需要 CPU 的总时间 (ms)
    int nice = 0;            // -20 ~ 19，默认 0

    // --- 运行时字段（算法填充） ---
    int remaining = 0;       // 剩余 burst
    int first_run_at = -1;   // 第一次拿到 CPU 的时间（算响应时间用）
    int finish_at = -1;      // 完成时间（算周转时间用）
    int wait_total = 0;      // 累计等待时间

    void reset() {
        remaining = burst;
        first_run_at = -1;
        finish_at = -1;
        wait_total = 0;
    }

    int response() const { return first_run_at - arrive; }         // 响应时间
    int turnaround() const { return finish_at - arrive; }          // 周转时间
};

// 解析 .task 文件
inline std::vector<Task> load_tasks(const std::string& path) {
    std::ifstream f(path);
    if (!f) throw std::runtime_error("open failed: " + path);
    std::vector<Task> ts;
    std::string line;
    while (std::getline(f, line)) {
        if (line.empty() || line[0] == '#') continue;
        std::stringstream ss(line);
        Task t;
        ss >> t.pid >> t.arrive >> t.burst;
        if (!(ss >> t.nice)) t.nice = 0;      // nice 可选
        t.reset();
        ts.push_back(t);
    }
    return ts;
}

}  // namespace mlab::sched
```

### Step 3.2 调度器基类 + 甘特图输出 + FCFS 实现（~90 行）

💭 **写代码思路**：五个算法共享"任务队列 + tick 推进 + 甘特段记录"三件事，但**选谁跑**的策略不同——这就是经典的"模板方法 / 策略模式"场景。用 CRTP 比虚函数快一点点（不是关键），但主要是让 Step 3.3/3.4/3.5 的实现看起来清爽——每个算法只重写一个 `pick_next` 即可。

📁 `boxes/03_sched/scheduler.hpp`

```cpp
#pragma once
#include "task.hpp"
#include <vector>
#include <string>
#include <optional>
#include <fmt/core.h>

namespace mlab::sched {

struct GanttSegment {
    int start;
    int dur;
    std::string pid;    // "IDLE" 表示 CPU 空转
};

// CRTP 基类：子类必须提供 pick_next(current_time, ready_tasks) → Task* or nullptr
template <class Derived>
class SchedulerBase {
public:
    void run(std::vector<Task>& tasks) {
        for (auto& t : tasks) t.reset();
        int now = 0;
        int done = 0;
        Task* running = nullptr;
        int run_start = 0;

        auto commit_segment = [&](int end) {
            if (end > run_start)
                gantt_.push_back({run_start, end - run_start,
                                  running ? running->pid : "IDLE"});
        };

        while (done < (int)tasks.size()) {
            // 1. 让子类挑下一个该跑的任务
            Task* next = static_cast<Derived*>(this)->pick_next(now, tasks);

            // 2. 如果切换了任务，提交上一段甘特段
            if (next != running) {
                commit_segment(now);
                run_start = now;
                running = next;
                if (running && running->first_run_at < 0)
                    running->first_run_at = now;
            }

            // 3. 推进 1ms
            if (running) {
                running->remaining -= 1;
                if (running->remaining == 0) {
                    running->finish_at = now + 1;
                    done++;
                    commit_segment(now + 1);
                    run_start = now + 1;
                    running = nullptr;
                }
            }
            // 其他未运行且已到达任务 wait++
            for (auto& t : tasks) {
                if (&t == running) continue;
                if (t.arrive <= now && t.remaining > 0) t.wait_total++;
            }
            ++now;
            if (now > 10000) { fmt::print("WARN: timeout\n"); break; }
        }
    }

    void print_gantt() const {
        // 按 pid 分行打印
        if (gantt_.empty()) return;
        int end = gantt_.back().start + gantt_.back().dur;
        // 收集所有 pid
        std::vector<std::string> pids;
        for (auto& s : gantt_)
            if (s.pid != "IDLE" &&
                std::find(pids.begin(), pids.end(), s.pid) == pids.end())
                pids.push_back(s.pid);
        for (auto& p : pids) {
            fmt::print("{}: ", p);
            for (int t = 0; t < end; ++t) {
                bool hit = false;
                for (auto& s : gantt_)
                    if (s.pid == p && t >= s.start && t < s.start + s.dur) {
                        hit = true; break;
                    }
                fmt::print("{}", hit ? "▇" : " ");
            }
            fmt::print("\n");
        }
        // 时间轴
        fmt::print("t: ");
        for (int t = 0; t < end; ++t)
            fmt::print("{}", (t % 5 == 0) ? std::to_string(t % 10)[0] : '.');
        fmt::print("\n");
    }

    const std::vector<GanttSegment>& gantt() const { return gantt_; }

protected:
    std::vector<GanttSegment> gantt_;
};

// ===== FCFS：先到先得 =====
class FCFS : public SchedulerBase<FCFS> {
public:
    Task* pick_next(int now, std::vector<Task>& tasks) {
        // 已有运行中就继续（非抢占）
        for (auto& t : tasks)
            if (t.arrive <= now && t.remaining > 0 && t.first_run_at >= 0 && t.finish_at < 0)
                return &t;
        // 否则按 arrive 挑最早到达的
        Task* best = nullptr;
        for (auto& t : tasks)
            if (t.arrive <= now && t.remaining > 0)
                if (!best || t.arrive < best->arrive) best = &t;
        return best;
    }
};

}  // namespace mlab::sched
```

### Step 3.3 SJF（非抢占）+ RR（时间片）两个经典算法（~70 行）

📁 追加到 `scheduler.hpp`

```cpp
// ===== SJF：短作业优先（非抢占）=====
class SJF : public SchedulerBase<SJF> {
public:
    Task* pick_next(int now, std::vector<Task>& tasks) {
        // 非抢占：当前任务继续
        for (auto& t : tasks)
            if (&t && t.first_run_at >= 0 && t.remaining > 0 && t.finish_at < 0)
                return &t;
        // 选剩余 burst 最小的（在"非抢占+未开始"场景剩余==初始）
        Task* best = nullptr;
        for (auto& t : tasks)
            if (t.arrive <= now && t.remaining > 0)
                if (!best || t.remaining < best->remaining) best = &t;
        return best;
    }
};

// ===== RR：轮转，带时间片 =====
class RR : public SchedulerBase<RR> {
public:
    explicit RR(int quantum_ms) : q_(quantum_ms) {}
    Task* pick_next(int now, std::vector<Task>& tasks) {
        // 当前任务时间片还没用完就继续
        if (last_ && last_->remaining > 0 && used_ < q_) {
            used_++;
            return last_;
        }
        // 轮转：从 last_idx+1 开始找下一个 ready
        int n = tasks.size();
        for (int i = 1; i <= n; ++i) {
            int idx = (last_idx_ + i) % n;
            auto& t = tasks[idx];
            if (t.arrive <= now && t.remaining > 0) {
                last_ = &t;
                last_idx_ = idx;
                used_ = 1;      // 本 tick 已用 1ms
                return &t;
            }
        }
        last_ = nullptr;
        return nullptr;
    }
private:
    int q_;
    Task* last_ = nullptr;
    int last_idx_ = -1;
    int used_ = 0;
};
```

### Step 3.4 MLFQ：4 级反馈队列 + 周期提升防饥饿（~120 行）

💭 **写代码思路**：MLFQ 的灵魂是**"行为决定级别"**——用完时间片 → 降级；主动让出（本盒简化为"没有 IO 事件"所以不触发）→ 保级；长期不运行 → 周期性全体提升。本盒省略 IO 行为，只实现"降级 + 周期提升"两条规则。

```cpp
// ===== MLFQ：4 级反馈队列 =====
class MLFQ : public SchedulerBase<MLFQ> {
public:
    static constexpr int LEVELS = 4;
    static constexpr int BOOST_PERIOD = 50;    // 每 50ms 全部提升到 L0
    const int QUANTUM[LEVELS] = {2, 4, 8, 16}; // L0 最高优先级，时间片最短

    Task* pick_next(int now, std::vector<Task>& tasks) {
        // 周期性 boost
        if (now > 0 && now % BOOST_PERIOD == 0) {
            for (auto& [tid, lv] : level_) lv = 0;
        }
        // 任务初次见到就入 L0
        for (auto& t : tasks)
            if (t.arrive <= now && t.remaining > 0 && !level_.count(t.pid))
                level_[t.pid] = 0;

        // 判断当前任务是否用完时间片
        if (last_ && last_->remaining > 0) {
            if (used_ < QUANTUM[level_[last_->pid]]) {
                used_++;
                return last_;
            }
            // 用完 → 降级
            if (level_[last_->pid] < LEVELS - 1) level_[last_->pid]++;
        }

        // 从最高优先级开始找 ready 任务
        for (int lv = 0; lv < LEVELS; ++lv) {
            Task* best = nullptr;
            for (auto& t : tasks)
                if (t.arrive <= now && t.remaining > 0 && level_[t.pid] == lv)
                    if (!best || t.arrive < best->arrive) best = &t;
            if (best) { last_ = best; used_ = 1; return best; }
        }
        last_ = nullptr; return nullptr;
    }
private:
    std::unordered_map<std::string, int> level_;
    Task* last_ = nullptr;
    int used_ = 0;
};
```

### Step 3.5 CFS：vruntime 公式 + 红黑树 + nice 权重实战（~130 行·重点中的重点）⭐

💭 **写代码思路**：Linux CFS 做了两件事——① 用 vruntime 把"实际跑了多久"按 nice 权重**归一化**（nice 越高跑得越慢→vruntime 增长越快→被挑中概率越低）② 用红黑树按 vruntime 排序，始终挑最小的跑。本 Step 就 100% 还原这两步。

**📐 CFS 核心类**（追加到 `scheduler.hpp`）：

```cpp
#include <set>

// ===== CFS：完全公平调度 =====
class CFS : public SchedulerBase<CFS> {
public:
    // 虚拟运行时间（放大 1000 避免浮点）
    using VR = long long;

    Task* pick_next(int now, std::vector<Task>& tasks) {
        // 新到达的任务入树
        for (auto& t : tasks) {
            if (t.arrive <= now && t.remaining > 0 && !inserted_.count(&t)) {
                // 新来者给 min_vruntime 避免占便宜
                vruntime_[&t] = min_vr_;
                rbt_.insert({vruntime_[&t], &t});
                inserted_.insert(&t);
            }
        }
        // 当前任务 vruntime 增加
        if (last_) {
            VR delta = 1000LL * 1024 / weight_of(last_->nice);  // ms × 1024/w，放大 1000
            vruntime_[last_] += delta;
            // 重新插回红黑树（因 vruntime 变了，排序会变）
            rbt_.erase({last_vr_, last_});
            if (last_->remaining > 0) rbt_.insert({vruntime_[last_], last_});
        }
        if (rbt_.empty()) { last_ = nullptr; return nullptr; }

        // 挑最小 vruntime 的（红黑树最左）
        auto it = rbt_.begin();
        last_ = it->second;
        last_vr_ = it->first;
        min_vr_ = last_vr_;   // 维护 min_vruntime（Linux 真实用法）
        return last_;
    }

private:
    struct Cmp {
        bool operator()(std::pair<VR, Task*> a, std::pair<VR, Task*> b) const {
            if (a.first != b.first) return a.first < b.first;
            return a.second < b.second;      // 平局用指针保唯一
        }
    };
    std::set<std::pair<VR, Task*>, Cmp> rbt_;
    std::unordered_map<Task*, VR> vruntime_;
    std::set<Task*> inserted_;
    Task* last_ = nullptr;
    VR last_vr_ = 0;
    VR min_vr_ = 0;
};
```

│          ③ OPT 作为理论上界，所有算法 <= 它                  │
│ 预计耗时：2.0h · 4 Step                                    │
└──────────────────────────────────────────────────────────┘

💡 **为什么页替换是 OS 里最优雅的一节？**——因为它是**唯一能用小学数学水平证明定理**的内核算法。Belady 1966 年证明"OPT 最优"用的是归纳法；Mattson 1970 年证明"栈算法不会异常"用的是集合论。你在本盒会**亲眼看到异常被复现**，然后用 20 行代码**证明它为何发生**。

⚠️ **本盒核心难点**：Belady 异常的触发序列**不是随机的**——必须是精心构造的 `1 2 3 4 1 2 5 1 2 3 4 5`。生成器要内置这个序列，不然你跑 100 遍随机访问看不到异常，还以为自己代码错了。

### 灵魂三问：动手前先想清楚

❓ **"缺页"到底是什么？模拟器要模拟什么？**  
→ 缺页 = "要访问的页不在物理帧中"。模拟器只做**三件事**：① 维护"当前在物理帧里的页集合" ② 收到访问 → 判断命中/缺页 ③ 缺页 + 帧满 → 按算法挑一页淘汰。**不涉及**磁盘 IO、不涉及真实地址翻译——纯粹是集合的进出。

❓ **为什么 FIFO 会 Belady 而 LRU 不会？**  
→ 核心区别：FIFO 的"淘汰谁"**只看入帧顺序**，不看访问模式；LRU 看访问模式。栈算法性质（Mattson）：**帧数 N 时的页集合 ⊂ 帧数 N+1 时的页集合**。LRU 满足，FIFO 不满足——所以 LRU 单调改进，FIFO 可能倒退。

❓ **OPT 既然"最优"为什么不用它？**  
→ 因为 OPT 需要**知道未来访问序列**才能挑"最远未来才用"的页淘汰。现实中我们不是预言家。OPT 的价值是**理论上界**——任何其他算法命中率不可能超过它。工程里用它来评估："我们算法距离最优还差多少"。

✅ **结论**：本盒 = 用 300 行代码重放整个页替换算法演进史，并严格复现 Belady 异常。

#include <vector>
#include <fstream>
#include <sstream>
#include <string>
#include <stdexcept>

namespace mlab::vm {

// 页号序列（每个元素 = 一次访问的虚拟页号 vpn）
using Trace = std::vector<int>;

// 从文件读 trace（每行一个数字，# 开头注释）
inline Trace load_trace(const std::string& path) {
    std::ifstream f(path);
    if (!f) throw std::runtime_error("open failed: " + path);
    Trace r;
    std::string line;
    while (std::getline(f, line)) {
        if (line.empty() || line[0] == '#') continue;
        std::stringstream ss(line);
        int v;
        while (ss >> v) r.push_back(v);
    }
    return r;
}

// === 内置几个经典 trace ===

// Belady 异常触发序列（1966 原始论文）
inline Trace belady_classic() {
    return {1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5};
}

// 顺序扫描：1,2,3,...,N 重复
inline Trace sequential(int n_pages, int rounds = 3) {
    Trace t;
    for (int r = 0; r < rounds; ++r)
        for (int i = 1; i <= n_pages; ++i) t.push_back(i);
    return t;
}

// 循环访问 N+1 页但只有 N 帧 → LRU 100% 缺页（最差场景）
inline Trace loop_bigger_than_frames(int n_pages, int rounds = 3) {
    return sequential(n_pages, rounds);
}

// 工作集：热页 (1..hot) 占 80% 访问，冷页 (hot+1..total) 占 20%
inline Trace working_set(int hot, int total, int len, uint32_t seed = 42) {
    std::mt19937 rng(seed);
    std::uniform_real_distribution<> p(0, 1);
    std::uniform_int_distribution<> hot_pick(1, hot);
    std::uniform_int_distribution<> cold_pick(hot + 1, total);
    Trace t;
    for (int i = 0; i < len; ++i)
        t.push_back(p(rng) < 0.8 ? hot_pick(rng) : cold_pick(rng));
    return t;
}

}  // namespace mlab::vm

### Step 7.2 Replacer 基类 + FIFO + LRU（~110 行）⭐

💭 **写代码思路**：和盒 ③ 一样用 CRTP——所有算法共享"访问流循环 + 命中/缺页记账"，只是**替换策略不同**。关键 API 设计：`access(vpn)` 返回 bool（true=命中，false=缺页）。所有算法都用 `std::unordered_set` 维护"在帧内的页集合"，便于 O(1) 判存在；至于**淘汰谁**，各算法用自己的数据结构。

📁 `boxes/07_vm/replacer.hpp`

```cpp
#pragma once
#include <unordered_set>
#include <unordered_map>
#include <list>
#include <deque>
#include <vector>
#include <string>
#include <climits>

namespace mlab::vm {

// 替换基类（非 CRTP 为简洁；本盒五个算法性能差异不显著，虚函数够用）
class Replacer {
public:
    explicit Replacer(int frames) : cap_(frames) {}
    virtual ~Replacer() = default;

    // 一次页访问：返回 true=命中，false=缺页
    bool access(int vpn) {
        total_++;
        if (in_frame(vpn)) {
            hits_++;
            on_hit(vpn);
            return true;
        }
        faults_++;
        if ((int)resident_.size() >= cap_) {
            int victim = pick_victim();
            resident_.erase(victim);
            on_evict(victim);
        }
        resident_.insert(vpn);
        on_insert(vpn);
        return false;
    }

    bool in_frame(int vpn) const { return resident_.count(vpn) > 0; }
    int faults() const { return faults_; }
    int hits()   const { return hits_;   }
    int total()  const { return total_;  }
    double hit_rate() const { return total_ ? (double)hits_ / total_ : 0; }

    virtual std::string name() const = 0;

protected:
    virtual void on_insert(int vpn) = 0;
    virtual void on_hit(int /*vpn*/) {}       // 多数算法命中不动数据结构
    virtual void on_evict(int /*vpn*/) {}
    virtual int  pick_victim() = 0;

    int cap_;
    std::unordered_set<int> resident_;
    int total_ = 0, hits_ = 0, faults_ = 0;
};

// ===== FIFO：先进先出 =====
class FIFO : public Replacer {
public:
    explicit FIFO(int f) : Replacer(f) {}
    std::string name() const override { return "FIFO"; }
protected:
    void on_insert(int vpn) override { queue_.push_back(vpn); }
    int  pick_victim() override {
        int v = queue_.front(); queue_.pop_front();
        return v;
    }
private:
    std::deque<int> queue_;
};

// ===== LRU：最近最久未使用 =====
class LRU : public Replacer {
public:
    explicit LRU(int f) : Replacer(f) {}
    std::string name() const override { return "LRU"; }
protected:
    void on_insert(int vpn) override {
        order_.push_front(vpn);
        pos_[vpn] = order_.begin();
    }
    void on_hit(int vpn) override {
        order_.erase(pos_[vpn]);
        order_.push_front(vpn);
        pos_[vpn] = order_.begin();
    }
    void on_evict(int vpn) override { pos_.erase(vpn); }
    int  pick_victim() override {
        int v = order_.back(); order_.pop_back();
        return v;
    }
private:
    std::list<int> order_;                                    // 头=最新，尾=最旧
    std::unordered_map<int, std::list<int>::iterator> pos_;   // O(1) 定位
};

}  // namespace mlab::vm
```

### Step 7.3 🔥 BUG-4 Belady 异常现场复现（打脸！）

**🔥 跑上面的 main，预期输出**：

```
frames=3 | FIFO faults=9  | LRU faults=10
frames=4 | FIFO faults=10 | LRU faults=8      ← 看这里!
frames=5 | FIFO faults=5  | LRU faults=5
```

**打脸点**：**FIFO 从 3 帧→4 帧，缺页数从 9 涨到 10**——多给一帧反而更差。这就是 **Belady 异常**。

**一句话解释**：FIFO 淘汰"进得最早"，但"进得最早"的页可能恰好**是最快要再次访问的热页**（如 trace 里的 1 和 2）。4 帧时反而把 1、2 挤出了帧，加剧了缺页。LRU 看访问热度，不会犯这个错。

**📐 严格证明栈算法为何不会 Belady**（简化版）：

> 定理（Mattson 1970）：对任意 trace，若算法 A 满足"**栈性质**"——即时刻 t 下 N 帧的页集合 ⊂ (N+1) 帧的页集合——则 N 增大时缺页数不会增加。
>
> 证明：若某次访问在 N 帧时命中，则该页在 N 帧集合内，由栈性质也在 N+1 帧集合内 → N+1 帧也命中。所以 N+1 帧的命中集合 ⊇ N 帧的命中集合，缺页集合 ⊆ 对方。∎
>
> LRU 栈性质直观理解：N+1 帧和 N 帧用同样的访问历史，前者多留了"第 N+1 最近使用"的页，其他 N 页完全一样 → 严格包含。
> FIFO 不满足：N+1 帧的 FIFO 队列是**完全不同的入队顺序**，淘汰的页也不同，可能把 N 帧时留着的页提前淘汰了。

### Step 7.4 Clock + 增强 Clock（4 类）+ OPT 理论上界（~140 行）

💭 **写代码思路**：Clock 是 FIFO 的实用改良——用 1 bit **R（referenced）** 来"假装"LRU，省去 LRU 维护链表的 O(1) 开销（真实硬件里链表操作要用原子+锁，很慢）。增强 Clock 再加 1 bit **M（modified）**，优先淘汰"没动过的"页（省写盘）。

追加到 `replacer.hpp`：

```cpp
// ===== Clock（Second-Chance，二次机会算法）=====
class Clock : public Replacer {
public:
    explicit Clock(int f) : Replacer(f), ring_(f, -1), ref_(f, 0) {}
    std::string name() const override { return "Clock"; }
protected:
    void on_insert(int vpn) override {
        // 找空槽
        for (int i = 0; i < cap_; ++i) {
            int idx = (hand_ + i) % cap_;
            if (ring_[idx] == -1) {
                ring_[idx] = vpn;
                ref_[idx] = 1;
                return;
            }
        }
    }
    void on_hit(int vpn) override {
        for (int i = 0; i < cap_; ++i) if (ring_[i] == vpn) ref_[i] = 1;
    }
    void on_evict(int vpn) override {
        for (int i = 0; i < cap_; ++i) if (ring_[i] == vpn) ring_[i] = -1;
    }
    int pick_victim() override {
        while (true) {
            if (ring_[hand_] == -1) { int tmp = hand_; hand_ = (hand_ + 1) % cap_; return -1; }
            if (ref_[hand_] == 0) {
                int v = ring_[hand_];
                hand_ = (hand_ + 1) % cap_;
                return v;
            }
            ref_[hand_] = 0;       // 给第二次机会
            hand_ = (hand_ + 1) % cap_;
        }
    }
private:
    std::vector<int> ring_;
    std::vector<int> ref_;
    int hand_ = 0;
};

// ===== 增强 Clock（4 类）：(R, M) 二元组 =====
// 类 0: R=0, M=0 → 最佳淘汰（没近期用、没改）
// 类 1: R=0, M=1 → 次佳（没用但改过，淘汰要写回磁盘）
// 类 2: R=1, M=0 → 不淘汰
// 类 3: R=1, M=1 → 更不淘汰
class EnhClock : public Replacer {
public:
    explicit EnhClock(int f) : Replacer(f), ring_(f, -1), r_(f, 0), m_(f, 0) {}
    std::string name() const override { return "EnhClock"; }

    void mark_modify(int vpn) {    // 外部模拟"写入"
        for (int i = 0; i < cap_; ++i) if (ring_[i] == vpn) m_[i] = 1;
    }
protected:
    void on_insert(int vpn) override {
        for (int i = 0; i < cap_; ++i) {
            int idx = (hand_ + i) % cap_;
            if (ring_[idx] == -1) {
                ring_[idx] = vpn; r_[idx] = 1; m_[idx] = 0;
                return;
            }
        }
    }
    void on_hit(int vpn) override {
        for (int i = 0; i < cap_; ++i) if (ring_[i] == vpn) r_[i] = 1;
    }
    void on_evict(int vpn) override {
        for (int i = 0; i < cap_; ++i) if (ring_[i] == vpn) ring_[i] = -1;
    }
    int pick_victim() override {
        // Pass 1：找 (0,0) 不清 R
        for (int i = 0; i < cap_; ++i) {
            int idx = (hand_ + i) % cap_;
            if (ring_[idx] != -1 && r_[idx] == 0 && m_[idx] == 0) {
                int v = ring_[idx]; hand_ = (idx + 1) % cap_; return v;
            }
        }
        // Pass 2：找 (0,1)，清 R
        for (int i = 0; i < cap_; ++i) {
            int idx = (hand_ + i) % cap_;
            if (ring_[idx] != -1 && r_[idx] == 0 && m_[idx] == 1) {
                int v = ring_[idx]; hand_ = (idx + 1) % cap_; return v;
            }
            r_[idx] = 0;    // Pass 2 清 R
        }
        // Pass 3：此时都是 (0,*)，再找一次
        return pick_victim();
    }
private:
    std::vector<int> ring_;
    std::vector<int> r_, m_;
    int hand_ = 0;
};

// ===== OPT：Belady 最优算法（上帝视角）=====
class OPT : public Replacer {
public:
    OPT(int f, const Trace& future) : Replacer(f), future_(future) {}
    std::string name() const override { return "OPT"; }
protected:
    void on_insert(int) override { pos_++; }
    void on_hit(int)    override { pos_++; }
    int  pick_victim() override {
        // 找 resident 中"最远才用"的页
        int farthest = -1, victim = -1;
        for (int p : resident_) {
            int next = next_use(p);
            if (next > farthest) { farthest = next; victim = p; }
        }
        return victim;
    }
private:
    int next_use(int vpn) const {
        for (int i = pos_ + 1; i < (int)future_.size(); ++i)
            if (future_[i] == vpn) return i;
        return INT_MAX;    // 不再用 → 最优淘汰
    }
    const Trace& future_;
    int pos_ = 0;          // 当前访问在 trace 中的位置
};

}  // namespace mlab::vm
```

**⚠️ 坑**：OPT 的 `pos_` 和基类的 `access` 调用顺序容易混。因为我们的基类是先 `in_frame` 判断再调 `pick_victim`，所以 `pos_` 必须在 `access` 结束后才递增。本案例让 `on_insert` / `on_hit` 分别递增，保证两条路径都走到。

        algos.push_back(std::make_unique<Clock>(frames));

┌─ 🐞 可能踩的坑 & 排错指南 ────────────────────────────────┐
│ 坑 1：Belady 没复现，可能 trace 长度不够 / 序列抄错         │
│       → 必须严格 `1 2 3 4 1 2 5 1 2 3 4 5`，不能改一位      │
│ 坑 2：Clock 的 `hand_` 跳过空槽时越界                       │
│       → 必须用 `% cap_` 包起来，不能用 `if (hand_>=cap_)`   │
│ 坑 3：OPT 的 `next_use` 把当前位置也算进去                   │
│       → 必须从 `pos_ + 1` 开始找                            │
│ 坑 4：OPT 对"永远不再用"的页返回 0                           │
│       → 必须返回 `INT_MAX`，否则会优先淘汰仍要用的页         │
│ 坑 5：LRU 命中时忘了把 iterator 失效                         │
│       → 用 `std::list::splice` 更快；本案例 erase+push_front │
│         保证 iterator 更新（见代码里 `pos_[vpn] =`）         │
│ 坑 6：增强 Clock 的 Pass 3 可能无限递归                      │
│       → Pass 2 清 R 后 Pass 3 一定能命中 (0,*)，但要加递归  │
│         深度断言防万一                                       │
└──────────────────────────────────────────────────────────┘

### 📌 盒 ⑦ 小结

| 维度 | 一句话拎走 |
|---|---|
| 核心抽象 | 页替换 = **决定淘汰谁** 的策略 |
| 五算法本质 | FIFO 看入帧序 · LRU 看访问热度 · Clock 用 1 bit 近似 LRU · EnhClock 加 1 bit 避免脏页写盘 · OPT 看未来 |

```cpp
// BUG 版
if (ev.events & EPOLLIN) {
    char buf[128]; read(fd, buf, sizeof(buf));   // ← 只读一次!
    // 结果：高水位时内核缓冲还有数据，但没下次事件了
}

// FIX 版
if (ev.events & EPOLLIN) {
    while (true) {
        char buf[128];
        ssize_t n = read(fd, buf, sizeof(buf));
        if (n == 0) { close(fd); break; }
        if (n < 0) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) break;  // 读完了
            close(fd); break;
        }
        // process buf
    }
}
```

## 18.第 6 次会话 · 盒 ⑩ `box_drv` 内核模块 `/dev/myecho`（§09）

┌─ 🎯 盒 ⑩ 目标卡 ────────────────────────────────────────┐
│ 完成什么：真正的 Linux 内核模块（C 不是 C++），字符设备      │
│          写入 /dev/myecho 的内容可以从同一节点读回            │
│ 不做什么：不做阻塞/非阻塞复杂变种（够见世面即可）             │
│ 验收标准：`echo hi > /dev/myecho && cat /dev/myecho` 输出 hi │
│ 预计耗时：1.0h · 3 Step · ⚠️ 仅 Linux                     │
└─────────────────────────────────────────────────────────┘

### 📁 `boxes/10_drv/myecho.c`（完整约 80 行）

```c
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/uaccess.h>
#include <linux/cdev.h>
#include <linux/slab.h>

#define BUF_SIZE 4096
static dev_t dev_num;
static struct cdev c_dev;
static char *buffer;
static size_t buffer_len;

static ssize_t myecho_read(struct file *f, char __user *u, size_t sz, loff_t *o) {
    size_t to_copy = min(sz, buffer_len - (size_t)*o);
    if (to_copy == 0) return 0;
    if (copy_to_user(u, buffer + *o, to_copy)) return -EFAULT;
    *o += to_copy;
    return to_copy;
}

static ssize_t myecho_write(struct file *f, const char __user *u, size_t sz, loff_t *o) {
    size_t to_copy = min(sz, (size_t)BUF_SIZE);
    if (copy_from_user(buffer, u, to_copy)) return -EFAULT;
    buffer_len = to_copy;
    return to_copy;
}

static struct file_operations fops = {
    .owner = THIS_MODULE, .read = myecho_read, .write = myecho_write,
};

static int __init myecho_init(void) {
    buffer = kzalloc(BUF_SIZE, GFP_KERNEL);
    alloc_chrdev_region(&dev_num, 0, 1, "myecho");
    cdev_init(&c_dev, &fops);
    cdev_add(&c_dev, dev_num, 1);
    pr_info("myecho loaded, major=%d\n", MAJOR(dev_num));
    return 0;
}
static void __exit myecho_exit(void) {
    cdev_del(&c_dev); unregister_chrdev_region(dev_num, 1); kfree(buffer);
}
module_init(myecho_init); module_exit(myecho_exit);
MODULE_LICENSE("GPL");
```

### Step 清单

| Step | 做什么 |
|---|---|
| 10.1 | 内核头 `apt install linux-headers-$(uname -r)` |
| 10.2 | 写 `myecho.c` + 内核风格 `Makefile`（见 `obj-m += myecho.o`） |
| 10.3 | `sudo insmod myecho.ko`，`mknod /dev/myecho c $MAJOR 0`，测 echo+cat |

### ⚠️ 坑清单

- 内核崩了 `dmesg -w` 看栈
- 不同内核版本 `file_operations` 字段略有差异
- **第一次写 LKM 建议先在虚拟机里玩**，宿主机 panic 真的会断

### 📌 一句话拎走

字符设备 = `cdev + fops` 四件套（read/write/open/release），一切 /dev 下的字符节点都这个套路。

## 19.第 6 次会话 · 盒 ⑪ `box_ns` unshare 假容器（§10）

┌─ 🎯 盒 ⑪ 目标卡 ────────────────────────────────────────┐
│ 完成什么：200 行 C++ 实现"迷你 docker run"                 │
│          隔离 PID/MNT/UTS/NET namespace，chroot rootfs      │
│ 不做什么：不实现网络 veth（下一步才做）                      │
│ 验收标准：容器内 `ps` 看不到宿主机进程，`hostname` 是独立的   │
│ 预计耗时：1.0h · 3 Step · ⚠️ 仅 Linux + sudo              │
└─────────────────────────────────────────────────────────┘

### 核心代码（约 60 行主体）

```cpp
#include <sched.h>
#include <sys/wait.h>
#include <sys/mount.h>
#include <unistd.h>
#include <fmt/core.h>
#include <cstring>

static char child_stack[1024 * 1024];

static int child(void* arg) {
    const char* rootfs = static_cast<const char*>(arg);
    sethostname("mycontain", 9);
    chroot(rootfs);                      // 换根（简化版 pivot_root）
    chdir("/");
    mount("proc", "/proc", "proc", 0, nullptr);   // 容器内的 /proc
    execl("/bin/sh", "sh", nullptr);
    return 1;
}

int main(int argc, char** argv) {
    if (argc < 2) { fmt::print("usage: {} <rootfs>\n", argv[0]); return 1; }
    int flags = CLONE_NEWPID | CLONE_NEWNS | CLONE_NEWUTS | CLONE_NEWNET | SIGCHLD;
    pid_t pid = clone(child, child_stack + sizeof(child_stack), flags, argv[1]);
    if (pid < 0) { perror("clone"); return 1; }
    waitpid(pid, nullptr, 0);
    return 0;
}
```

### Step 清单

| Step | 做什么 |
|---|---|
| 11.1 | 准备 rootfs：`debootstrap focal /tmp/rootfs` 或拉 alpine tar |
| 11.2 | 实现 `clone` + 四种 NS，sh 能进但 ps 异常 |
| 11.3 | 在容器内 mount proc，`ps` 恢复正常 |

### ⚠️ 坑

- 不 mount proc 的话 `ps` 读宿主机 /proc → 隔离失效
- CLONE_NEWNET 后容器没有网络（下一盒才解决）

### 📌 一句话拎走

Docker 90% 的"魔法"就是 **clone(CLONE_NEW*) + chroot + mount**。剩下 10% 是镜像和网络。
