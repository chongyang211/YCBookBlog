## 1. 案例引入

### 1.1 头部免费打击

上一篇糖果充建好了四层指标体系, Q4 数据全线飘红。他正在部门年终会上做汇报——**"北极星涨 68%, 留存涨 51%, NPS 从 6 到 7.5"**——老板 A 总频频点头, 财务姐姐们坐在角落笑得很开心。

会议进行到一半, 糖果充手机弹了一条消息, 是竞对公司市场部的朋友发来的:

```
朋友: "老糖, 你们发现了吗? 
      XX 公司昨晚发了一个'AI 财务对账中台', 
      完全对标你们的产品, 还免费。 
      我看你们几家客户群里已经开始讨论了。"
```

糖果充打开链接, 越看越紧:

```
XX 公司 (行业头部, 上市公司) 的"AI 财务对账中台":
- 免费 (核心付费点是他们的 ERP)
- 功能是糖果充产品的 3 倍
- UI 现代化, 有暗黑模式、有 AI 助手
- 支持 20+ 家银行接口, 糖果充只支持 3 家
- 已被 5 家一线互联网公司试点使用
- 昨晚发的 demo 视频, 一夜之间转发 1.2 万
```

会议现场老板 A 总也看到消息了, 直接问糖果充:

```
A 总: "小杨, 我刚看到 XX 公司发的新东西。你怎么看?
      我们要不要跟上? 他们免费我们收费, 客户会走的吧?"

糖果充: (心跳加速) "我看看 demo 再说。"

A 总: "别看 demo 了, 你直接告诉我: 抄还是不抄?"

糖果充: (急了) "……我建议抄一部分, 我们的用户不能流失。"

A 总: "抄什么? 抄多少? 3 个月能上线吗? 我们的现有客户抄完后会更满意吗?"

糖果充: (答不上来)
```

会后糖果充回工位, 消息群里已经是一片慌乱:

```
[群消息]
销售总监: "刚接到 3 家客户电话, 都在问我们要不要出免费版, 
         不然他们要试用 XX 公司的。"
李姐:    "小杨, XX 公司那个 AI 提问功能好厉害啊, 我们能不能加?"
产品同事: "他们那个 UI 是我看过所有 B 端产品里最好看的, 我们的太土了。"
另一位工程师: "刚看了他们的功能列表, 我们至少差 30 个功能。"
```

**所有人都在说"我们输了, 快抄"**。糖果充夜里在工位坐到 11 点, 越想越乱:

```
选项 A - 全面对标:  抄他所有功能 + 做免费版 
  预估: 6 个月 + 6 人月 + 抛弃现有付费商业模式

选项 B - 局部对标:  抄他 5 个最重要的功能
  预估: 3 个月, 现有客户不流失, 但仍无法差异化

选项 C - 完全不抄:  坚持自己的方向
  预估: 有可能客户流失一半, 但保留独特性

选项 D - 转变方向:  找一个 XX 公司做不了的定位
  预估: 需要重新想清楚"我们到底是谁", 短期无优势
```

**4 个选项, 每个都有风险**。糖果充给老周发了一条消息: "**老周, 我该怎么办?**" 老周回了一个字: "**慌**"。

半小时后老周补了一条:

```
老周: "你现在做的第一件事不是决定'抄不抄', 
      是决定'怎么看'——
      你连他到底是什么定位、抢的是谁的市场、
      对我们的哪部分客户有威胁都不知道, 
      你怎么可能做正确的决策?
      
      记住一句话: 差异比更好重要。你不需要比他强,
      你只需要比他不一样, 而且不一样的那部分刚好是你的用户要的。"
```

### 1.2 顺藤摸根因

带着这条线往下挖:

- **假设 1**: 糖果充产品不如竞品好? ——**功能上确实不如**, 但"不如"不等于"要输"
- **假设 2**: 应该学竞品的所有功能? ——**这是最容易的错**, 抄完只会变成"更差的他"
- **假设 3**: 应该完全无视竞品? ——**也不对**, 忽视会让你在市场上错失机会
- **假设 4**: 那正确的做法是什么? ——**理解竞品的定位**, 然后**找到差异化空间**
- **假设 5**: 什么叫"理解竞品"? ——**不是列功能对比表**, 而是拆到战略层, 看他要抢什么市场、什么用户、什么价值
- **假设 6**: 差异化怎么找? ——**"我们对谁不一样"**, 不是"我们比他好"——差异化定位公式
- **假设 7**: 什么时候该抄、什么时候不该抄? ——**抄还是不抄的决策树**
- **假设 8**: 作为系列的收官, 六篇怎么合璧? ——**六信合璧飞轮**

仔细分析这次慌乱的根因:

```
表象                                真实问题
────────────────────────────────────────────────
"竞品出了 3 倍功能, 我们输了"      → 只看功能表面, 没看战略定位
"客户要走, 抄就完了"                → 抄完就是"更差的他", 差异化尽失
"UI 不好看, 快改"                   → 表现层是最浅层, 抄了没用
"他免费我也免费"                    → 战略层照抄, 商业模式跟着崩
"6 人月能抄完"                     → 团队不是无限资源, 抄他就没时间做自己
```

**根因**: 糖果充**没有竞品分析框架**——只会**表层比对功能**, 不会**深层拆解定位**。所有工程师第一次面对竞品冲击的反应都是"**抄**", 但抄的结果几乎全都是"**更差的他**"。真正需要的是: **看透竞品在争什么, 然后找到你能守住 + 他没法过来抢的那块地**。

这一段里至少藏着 8 个原理点:

```
① 竞品分析的正确流程是什么?                          → 第 2 章
② 谁是我的竞品? 只有直接竞品吗?                       → 第 3 章
③ 怎么拆竞品? 只列功能对比够吗?                       → 第 4 章
④ SWOT 怎么用在竞品分析里? 30 分钟能做完吗?           → 第 5 章
⑤ 什么是差异化定位? 一句话怎么表达?                    → 第 6 章
⑥ 抄还是不抄的决策依据是什么?                          → 第 7 章
⑦ 竞品分析常见反模式?                                  → 第 8 章
⑧ 六篇产品思考怎么合起来看?                            → 第 10 章
```

### 1.3 要回答什么

这个事故就是本篇的**主线案例**。带着上面 8 个问号往下走。本篇路线:

```
竞品分析五步 (第 2 章)
   ↓
竞品四象限 (第 3 章) ─→ 解开"谁才是竞品"
   ↓
五层拆解 (第 4 章) ─→ 解开"从战略到 UI 怎么系统看"
   ↓
SWOT 精简 (第 5 章) ─→ 解开"30 分钟做完战略画像"
   ↓
差异化定位 (第 6 章) ─→ 解开"不是更好, 是不一样"
   ↓
抄或不抄决策树 (第 7 章) ─→ 解开"具体到每个功能怎么判"
   ↓
反模式 (第 8 章) + 跨岗位 (第 9 章)
   ↓
综合案例 + 系列收官 (第 10 章)
```

📌 **本篇定位**: 这是"产品思考"系列的**收官之作**。前五篇教你**看到用户、挖到真需求、做取舍、做 MVP、看真数据**——这些都是**内功**。本篇教你**在竞争的江湖里如何自处**——**外功**。**没有内功的外功是花架子, 没有外功的内功是自嗨**。**读完六篇, 一个工程师才能完整地完成"从造代码的人到造产品的人"的转型**。

## 2. 分析全景图

### 2.1 分析五步

一次完整的竞品分析, 包含五步:

```
┌───────────────────────────────────────────────────────────┐
│                    竞品分析五步                              │
├───────────────────────────────────────────────────────────┤
│  ① 圈定 (Scope)     圈出真正的竞品 (四象限)                 │
│  ② 拆解 (Analyze)   五层拆解 (战略 → 表现)                  │
│  ③ 画像 (Portrait)  SWOT + 定位画像                         │
│  ④ 定位 (Position)  找到差异化空间                          │
│  ⑤ 决策 (Decide)    抄/不抄/规避 具体动作                    │
└───────────────────────────────────────────────────────────┘
```

**五步属性速查**:

| 步 | 输入 | 输出 | 糖果充 V1 翻车点 |
|---|---|---|---|
| 圈定 | 竞品名字 | 4 类竞品清单 | ❌ 只看 XX 公司这一个直接竞品 |
| 拆解 | 竞品产品 | 五层拆解报告 | ❌ 只看到"功能多 3 倍"(表现层) |
| 画像 | 拆解报告 | SWOT 表 | ❌ 无 |
| 定位 | 画像 | 差异化空间 | ❌ 直觉判断"要抄" |
| 决策 | 差异化 + 团队产能 | 具体功能级动作清单 | ❌ 情绪化"全部抄" |

### 2.2 为什么这么切

竞品分析不就是"看看别人做了啥, 抄过来吗"? 为什么要五步?

**论证**:

**1.没圈定就找错对手**——糖果充只盯着 XX 公司一个直接竞品, 但对他真正威胁最大的可能是**替代品**(比如 Excel + Notion 组合方案)或**间接竞品**(比如 IT 部门自己开发的内部工具)。**只看直接竞品 = 战术上的勤奋掩盖战略上的懒惰**。

**2.没拆解就看错重点**——竞品分析报告写"XX 公司功能比我们多 30 个"是没用的, 因为它没告诉你**为什么多**、**给谁用**、**要抢什么价值**。**功能是表现层, 不理解战略层就等于没分析**。

**3.没画像就无法回答"我们的优劣势"**——SWOT 强迫你回答四个问题: 我们的优势/劣势/机会/威胁分别是什么。**不做 SWOT, 你永远只知道"竞品更强"这一个模糊感觉**。

**4.没定位就无法差异化**——市场上"更好"的产品输给"更不一样"的产品的案例, 数不胜数(iPod 输给 iPhone 不是因为 iPod 不好, 是因为 iPhone 是"不一样")。**定位的价值 = 承认你不可能在所有维度都赢, 选一个维度赢到底**。

**5.没决策就是白分析**——做完前四步如果不落地在"哪些抄, 哪些不抄, 哪些反向", 前面全白干。决策的价值 = **让分析变成动作**。

反向验证: **没这五步会怎样**? 答案就是第 1 章, 糖果充在慌乱中要"全面对标", 抄完只会变成"更差的 XX 公司"。

**结论**: 五步的本质是**"从直觉反应升级为理性决策"**。竞品来了, 大多数工程师第一反应是"慌", 五步法教你**在慌之前先看清楚**。

## 3. 竞品四象限

### 3.1 四象限定义

**关键洞察**: 竞品不是只有"和你做一样东西的公司"。四类都是竞品:

```
                     解决相同问题
                          ▲
                          │
                   直接竞品 │  间接竞品
                (功能相似) │  (功能不同但解同一问题)
                          │
                          │
       目标用户相同 ───────┼─────────── 目标用户不同
                          │
                          │
                   替代竞品 │  潜在竞品
                (用完全   │  (未来可能进入你市场)
                不同方式) │
                          ▼
                     解决相似问题
```

**四类竞品的定义 + 拿糖果充练手**:

**① 直接竞品** (功能相似 + 用户相似)

```
定义: 提供相似功能, 服务相似目标用户
特点: 最显眼, 最容易看到, 也是团队最容易紧张的
糖果充的直接竞品: XX 公司的"AI 财务对账中台"

分析价值: 中等 —— 你必须知道, 但不能只看
```

**② 间接竞品** (功能不同 + 解决同一问题)

```
定义: 用不一样的方式解决同一个用户问题
特点: 容易被忽视, 但威胁常常更大
糖果充的间接竞品: 
  - 财务外包公司 (直接解决"月底加班"的问题, 用人力)
  - RPA 工具 (用录制自动化解决对账问题)
  - 高级 Excel 模板 (免费, 财务圈流传)

分析价值: 高 —— 常常揭示"用户真正的选择菜单"
```

**③ 替代竞品** (用完全不同方式)

```
定义: 用完全不同的产品品类解决相同/相似需求
特点: 最不像"竞品", 但可能是市场颠覆者
糖果充的替代竞品:
  - AI 财务助理 (类 GPT 的对话式财务, "你说需求它做")
  - 银行直连服务 (银行主动推送对账数据, 无需系统)

分析价值: 高 —— 揭示未来 3-5 年市场演化方向
```

**④ 潜在竞品** (未来可能进入)

```
定义: 目前不在这个市场, 但有能力/动机进入
特点: 大公司/大平台/新技术都可能是
糖果充的潜在竞品:
  - 大型云平台 (阿里云/腾讯云的财务 SaaS)
  - 银行系金融科技 (银行自建的对账工具)
  - 大模型公司 (通用 AI 助手切入垂直行业)

分析价值: 中 —— 提醒你别只盯着眼前, 也要看远
```

### 3.2 对账系统练手

**四象限完整版**:

```
                     解决相同问题
                          ▲
                          │
     [直接竞品]            │      [间接竞品]
     - XX 公司 AI 对账中台  │   - 财务外包公司
     - 用友/金蝶对账模块    │   - RPA 工具
                          │   - 高级 Excel 模板
                          │
   目标用户相同 ───────────┼────────────── 目标用户不同
                          │
                          │
     [替代竞品]            │      [潜在竞品]
     - AI 财务助理 (GPT-类) │   - 阿里云财务 SaaS
     - 银行直连服务        │   - 大模型垂直助手
                          │   - 银行系金融科技
                          ▼
                     解决相似问题
```

**四象限的价值**: 糖果充之前只盯着直接竞品 XX 公司, 但四象限展开后:

```
真正的威胁排序 (糖果充意料之外):
  第 1: 替代竞品 - AI 财务助理 (未来 1-2 年可能颠覆)
  第 2: 直接竞品 - XX 公司 (眼前的威胁)
  第 3: 间接竞品 - 财务外包 (客户已经在流失的口子)
  第 4: 潜在竞品 - 银行系金融科技 (3-5 年后可能进场)

而糖果充之前只在担心第 2 位, 完全忽视了 1/3/4 位
```

**结论**: **四象限的价值不是列全竞品, 而是发现"你没意识到的威胁"和"你没意识到的机会"**。**盯着眼前的直接竞品打, 常常输在你没看到的角落**。

## 4. 五层拆解框架

看到 XX 公司的新产品, 大多数工程师的反应是**列功能对比表**——但这只覆盖了竞品的**5% 表层**。真正的竞品分析要看**五层** (借鉴 Jesse James Garrett《用户体验要素》):

```
┌─────────────────────────────────────────────┐
│  ⑤ 表现层 (Surface)     UI 视觉、色彩、字体   │  <- 最浅
│─────────────────────────────────────────────│
│  ④ 框架层 (Skeleton)    信息架构、导航布局    │
│─────────────────────────────────────────────│
│  ③ 结构层 (Structure)   交互设计、流程逻辑    │
│─────────────────────────────────────────────│
│  ② 范围层 (Scope)       功能列表、内容范围     │
│─────────────────────────────────────────────│
│  ① 战略层 (Strategy)    目标用户、商业模式    │  <- 最深
└─────────────────────────────────────────────┘
```

**核心洞察**: **竞品分析必须从下往上看**——先看战略, 再看范围, 最后看表现。**从上往下看 = 只学到表面 = 抄的都是壳**。

### 4.1 战略层

**问题**: 竞品**为什么**做这个产品?

**拿 XX 公司的 AI 对账中台练手**:

```
战略拆解:
  目标用户: 中大型企业的 CFO / 财务总监 (决策者)
            而不是财务专员 (使用者)
  核心价值: 帮企业"用 AI 替代 3-5 位财务专员的工作"
  商业模式: 免费送对账工具, 但绑定他们的付费 ERP 系统
  底层逻辑: "先低成本获客, 再高毛利收割"—— 云厂商经典打法
  隐藏动机: 大厂想垄断中大型企业市场, 收窄第三方对账工具的空间

对比糖果充的战略:
  目标用户: 中小企业的财务专员 + 财务主管 (直接使用者)
  核心价值: 帮财务"月底不加班 + 出错少 + 有排面"
  商业模式: 直接 SaaS 订阅, 客户对账门户加价包
  底层逻辑: "深度绑定使用者体验, 使用者推荐给决策者"

关键发现:
  XX 公司争的是"决策者的采购预算"
  糖果充争的是"使用者的日常喜爱"
  ★ 目标用户完全不同 —— 表面重合, 战略上根本没重叠
```

**这一层看完你就知道**: 糖果充没必要"全面对标"——**因为他们根本不是抢同一批用户**。

### 4.2 范围层

**问题**: 竞品**做了哪些**功能? **哪些做了不做**?

```
XX 公司的功能范围:
  ✓ AI 智能对账
  ✓ 多币种支持 (20+ 币种)
  ✓ 银行直连 (20+ 家银行)
  ✓ 报表引擎 (500+ 模板)
  ✓ 权限管理 (企业级 RBAC)
  ✓ 审计日志
  ✓ AI 助手对话
  ✓ 移动端 App
  ✓ ERP 深度集成 (仅他们自家 ERP)
  ✗ 不支持第三方 ERP
  ✗ 不支持定制化字段
  ✗ 不支持 API 开放 (锁死在他们生态)

糖果充的功能范围:
  ✓ A4 发票识别 (深度优化, 准确率 99.7%)
  ✓ 客户对账门户
  ✓ 月度亮点摘要
  ✓ 供应商晚到发票补录
  ✗ 无 AI 对话
  ✗ 银行直连仅 3 家
  ✗ 无移动端
  ✓ 独立部署, 不锁生态
  ✓ 支持第三方 ERP 对接
  ✓ 高度定制化 (支持自定义字段)

关键发现:
  XX 公司: 广度取胜, 但锁生态 (绑定他们的 ERP)
  糖果充: 深度取胜, 但生态开放 (可接任何 ERP)
  ★ 用户如果不用 XX 公司的 ERP → 糖果充是更好的选择
  ★ 用户如果不想被锁死 → 糖果充是唯一选择
```

### 4.3 结构层

**问题**: 竞品的**交互流程**是怎样的?

```
XX 公司的对账流程:
  Step 1: 打开 AI 助手, 用对话方式描述"要对账"
  Step 2: AI 自动识别可用数据源, 自动拉取
  Step 3: AI 呈现"我理解你要 XXX, 是这样吗"
  Step 4: 用户确认, AI 自动完成对账
  Step 5: 有异常时 AI 弹出"我发现 3 处问题"
  
特点: 
  ★ 极度自动化, 但用户"参与感"低
  ★ 依赖 AI 判断, 但 AI 错了归属不清
  ★ 新用户上手快 (对话就行), 但深度用户不够灵活

糖果充的对账流程:
  Step 1: 用户手动选择"对账时间范围"
  Step 2: 用户手动上传/拉取数据源  
  Step 3: 系统辅助识别 (发票 OCR 等), 但用户逐条确认
  Step 4: 用户主动点击"完成对账"
  Step 5: 系统提示异常, 但由用户判断处理

特点:
  ★ 半自动化, 用户参与度高
  ★ 用户主导, 责任清晰
  ★ 新用户学习成本高, 但深度用户操作快
```

**关键洞察**: **交互流程的不同, 反映了两家公司对"用户角色"的理解不同**——

```
XX 公司: 认为用户"想省事, 交给 AI 就好"
糖果充: 认为用户"想省事, 但也不想背锅"
```

**用户实际怎么想**?——**取决于用户是谁**。CFO 会更倾向"交给 AI"(他不做具体操作), 财务专员会更倾向"我主导"(他要为具体数字负责)。**这就是战略层的用户不同, 导致交互层必然不同**。

### 4.4 框架层

**问题**: 竞品的**信息架构**是怎么组织的?

```
XX 公司 (以"AI 助手"为主入口):
  主导航: [AI 对话] [数据看板] [报告中心] [设置]
  信息架构: 围绕 "AI 对话" 组织, 其他是辅助
  
糖果充 (以"业务流程"为主入口):
  主导航: [首页] [发票管理] [对账中心] [客户门户] [报告]
  信息架构: 围绕 "对账业务流" 组织
  
关键发现:
  XX 公司: 前端是"AI 中心化"设计 (押注 AI 对话是未来)
  糖果充: 前端是"业务中心化"设计 (稳扎稳打的传统 SaaS)
  ★ 如果 AI 对话真的成为财务软件的主要交互方式, 糖果充的框架会落后
  ★ 但如果 AI 只是补充 (不取代业务流), 糖果充的框架反而更稳
```

### 4.5 表现层

**问题**: 竞品的**视觉设计**是怎样的?

```
XX 公司:
  设计风格: 现代化、扁平化、大量白色 + 蓝紫渐变
  暗黑模式: 有
  动效: 丰富
  移动适配: 完整响应式 + 独立 App
  设计成熟度: A+ (专业 UI 团队)

糖果充:
  设计风格: 传统 B 端、灰白基调、无渐变
  暗黑模式: 无
  动效: 简洁
  移动适配: 仅响应式, 无 App
  设计成熟度: B (工程师主导 UI)

关键发现:
  ★ 表现层差距大, 但对财务用户可能没那么重要
  ★ 财务用户看重的是"数据不出错", 不是"UI 好不好看"
  ★ 但对决策者 (CFO/总监) 演示时, UI 有加分
```

**五层拆解总结**:

| 层 | 内容 | XX 公司 vs 糖果充 | 差距重要性 |
|---|---|---|:---:|
| 战略 | 目标用户 + 商业模式 | 完全不同 (决策者 vs 使用者) | ⭐⭐⭐⭐⭐ |
| 范围 | 功能覆盖 | 广度差 3 倍, 但锁生态 vs 开放 | ⭐⭐⭐⭐ |
| 结构 | 交互流程 | AI 中心 vs 业务中心 | ⭐⭐⭐ |
| 框架 | 信息架构 | AI 对话为主 vs 业务导航为主 | ⭐⭐ |
| 表现 | 视觉设计 | 差距明显但影响有限 | ⭐ |

**结论**: **越深层的差异, 越是"你没法抄"; 越浅层的差异, 越是"抄了没用"**。糖果充最初以为要抄的"30 个功能"、"AI 对话"、"暗黑模式"——**全是表面。真正决定胜负的是战略层**。

## 5. SWOT 精简版

五层拆完之后, 用 **SWOT** 快速做战略画像:

```
┌────────────────────────────────────────────────────┐
│                    SWOT 四象限                       │
├────────────────────────────────────────────────────┤
│                                                      │
│   S (Strengths)          │   W (Weaknesses)         │
│   内部优势               │   内部劣势                │
│                          │                          │
│──────────────────────────┼──────────────────────────│
│   O (Opportunities)      │   T (Threats)            │
│   外部机会               │   外部威胁                │
│                          │                          │
└────────────────────────────────────────────────────┘
```

**糖果充 vs XX 公司的 SWOT** (30 分钟做完版):

```
┌────────────────────────────────────────────────────┐
│  糖果充团队 SWOT                                    │
├────────────────────────────────────────────────────┤
│                                                      │
│   S (优势):                W (劣势):                │
│   • 深度绑定财务使用者      • 团队规模小             │
│   • 对账准确率 99.7%       • 无 AI 对话能力         │
│   • 客户 NPS 7.5           • UI 落后                │
│   • 生态开放 (不锁 ERP)     • 品牌知名度低           │
│   • 定制化能力强           • 无移动端                │
│                                                      │
│─────────────────────────────────────────────────────│
│                                                      │
│   O (机会):                T (威胁):                │
│   • 中小企业 SaaS 市场     • XX 公司免费降维         │
│     未被巨头充分覆盖        • AI 对话可能成为标配    │
│   • 客户对独立部署有需求   • 团队被"抄袭焦虑"绑架     │
│   • 用户主导 AI 的诉求上升  • 客户被免费诱惑而流失    │
│   • ERP 开放对接是趋势     • 大厂垄断决策者预算       │
│                                                      │
└────────────────────────────────────────────────────┘
```

**SWOT 完成后, 提取 4 个战略动作**:

```
① SO 策略 (用优势抓机会):
   → 加大"独立部署 + 生态开放"宣传, 抓中小企业市场
   → 深度提升 NPS, 让"使用者热爱"成为最大护城河
   
② WO 策略 (补劣势抓机会):
   → 引入 AI 助手, 但保持"用户主导"(不学 XX 全自动)
   → 补移动端基础版, 至少能查看
   
③ ST 策略 (用优势防威胁):
   → 客户白名单 + 承诺"数据不锁", 对冲 XX 免费诱惑
   → 深度绑定财务专员, 让使用者成为客户内部反对 XX 的力量
   
④ WT 策略 (补劣势防威胁):
   → 团队心态建设: 不学 XX 的全部, 只学他值得学的
   → 建立"竞品追踪日报", 3 个月内不被外界情绪带偏
```

**结论**: **SWOT 不是应付作业, 而是 30 分钟找到"打法"**——从战略优劣势 + 外部机会威胁交叉出 4 类具体动作。

## 6. 差异化定位公式

### 6.1 不是更好是不同

**竞品分析的最高境界**: **不是找到怎么"打赢"竞品, 是找到"我们对谁不一样"**。

**经典案例**:

```
iPod 时代 (2001):    "1000 首歌装进口袋" —— 强调容量 (直接竞争 MP3)
iPhone 时代 (2007):   "手机 + iPod + 上网" —— 重新定义品类
特斯拉:              "不是更好的燃油车, 是电动车" —— 换赛道
西南航空:            "不是更豪华的航空, 是最便宜的" —— 极端定位
无印良品:            "没有 logo 的高质量" —— 反向差异
```

**关键**: 差异化的两个核心问题是 —— **"对谁不一样?"** 和 **"哪一点不一样?"**

### 6.2 定位陈述句

**差异化定位公式** (来自 Geoffrey Moore《跨越鸿沟》):

```
For [目标用户 / 对谁],
  Who [有什么痛点或需求],
Our [产品类别] is [独特价值主张],
  That [独特优势, 与竞品的差异化点],
  Unlike [主要竞品], [他们的不足 / 局限].
```

**中文版**:

```
为 [谁], 
  他们 [有什么痛点],
我们的 [产品] 是 [独特品类],
  它能 [独特价值],
  不像 [竞品] 那样 [有什么不足].
```

### 6.3 产品练手

**糖果充最初的定位陈述** (被 XX 公司发布逼出来的):

```
版本 1 (慌乱版):
"我们是一款帮企业做对账的 SaaS 工具, 
 支持发票识别、对账门户、报表生成。"

问题:
- 没说给谁
- 没说独特价值
- 没和竞品区分
- 完全可替代
```

**用差异化定位公式重写**:

```
版本 2 (差异化版):

为 [中小企业的财务主管和专员] (对谁: 不是 CFO), 
  他们 [每月加班对账, 又怕被大厂 SaaS 锁死生态, 
       更怕 AI 全自动化后自己没排面] (痛点: 三层),
我们的 [独立部署 + 生态开放的对账 SaaS] 是 [他们真正能主导的工具],
  它能 [深度定制 + 生态开放 + 让使用者始终掌控],
  不像 [XX 公司的 AI 对账中台] 那样 [锁死在他们的 ERP 生态, 
                                     用 AI 剥夺使用者的价值感].
```

**这段定位的三层价值**:

```
Layer 1: 目标用户明确 → 中小企业财务主管/专员, 不是 CFO
                       (跟 XX 公司完全不同的用户群)

Layer 2: 独特价值三点 → 独立部署 / 生态开放 / 使用者主导
                       (这三点 XX 公司做不到, 因为战略上他们要锁生态)

Layer 3: 差异清晰 → 我们不比 XX 强, 我们对不同的用户不一样, 
                    刚好我们的用户不喜欢 XX 的做法
```

**用这段定位反推所有决策**:

```
决策 1: 要不要抄"AI 对话"?
       → 部分抄, 但保留"用户主导" 的边界
       → 做"AI 助手 + 用户确认" 模式, 不做"AI 自动执行"

决策 2: 要不要免费?
       → 不免费, 但推出"社区版" (小规模企业免费, 数据独立)
       → 免费 = 输战略层, 但"社区版"能保住入口

决策 3: 要不要抄"银行直连 20+ 家"?
       → 不抄全部, 只抄最重要的 5 家
       → 但深度做"银行对接开放平台", 让客户自己或第三方对接

决策 4: 要不要抄"AI 助手对话"?
       → 抄, 但方向是"辅助使用者", 不是"取代使用者"
       → 例: AI 帮李姐生成"月度亮点摘要"的初稿, 李姐修改后发出
```

**看, 差异化定位一旦想清楚, 所有具体决策就自然而然有了答案**。

## 7. 抄不抄决策树

到了具体功能层面, 用**决策树**判断每个功能:

```
                    竞品新功能 X
                        │
                        ▼
              ┌── 是我们目标用户要的吗? ──┐
              │                            │
             不是                          是
              │                            │
              ▼                            ▼
          ★ 不抄, 无视            ┌── 符合我们的差异化定位吗? ──┐
                                  │                              │
                                 是                             不是
                                  │                              │
                                  ▼                              ▼
                        ┌── 能做到不比他差吗? ──┐         ★ 不抄, 转化
                        │                        │         (做我们独特版本)
                       能                      不能
                        │                        │
                        ▼                        ▼
                    ★ 抄, 快速跟上          ★ 不抄, 保持特色
                    (成本可控时)             (硬拼没意义)
```

**四种决策落地** (拿 XX 公司功能练手):

**决策 A: 不抄, 无视** (目标用户不重叠)

```
功能: "跨国多币种 20+ 支持"
原因: 我们目标用户是中小企业, 没多国业务
决策: 不做, 无视
```

**决策 B: 抄, 快速跟上** (目标用户要 + 符合我们定位 + 能做到不比他差)

```
功能: "移动端查看对账"
原因: 财务主管出差时也想看, 是我们用户的真实痛点
      符合"深度绑定使用者"的定位
      技术上可以做到 (基础版即可)
决策: Q1 内做出基础版 (只查看, 不操作)
```

**决策 C: 不抄, 转化 (做独特版本)** (目标用户要, 但不符合我们定位)

```
功能: "AI 全自动对账"
原因: 用户确实好奇 AI
      但"全自动"不符合我们"用户主导"的定位
决策: 做"AI 助手辅助", 而非"AI 全自动"
     具体: AI 帮忙识别 + 用户确认 + 责任归用户
     
差异化点: XX 公司的 AI 自动 → 责任不清; 
        糖果充的 AI 辅助 → 用户始终主导
```

**决策 D: 不抄, 保持特色** (目标用户要, 符合定位, 但硬拼没意义)

```
功能: "全球 20+ 家银行深度直连"
原因: 我们用户主要在国内
      硬做 20+ 家会稀释资源
决策: 只做用户实际用的 5-8 家 + 建"银行对接开放平台" 
     让客户自己/第三方接入其他银行
     
差异化点: XX 公司的"我们做 20 家" → 用户必须等他做; 
        糖果充的"开放平台" → 用户可自定, 更灵活
```

**用决策树把 XX 公司的 30 个新功能过一遍**:

```
不抄, 无视:     10 个 (目标用户不重叠的)
不抄, 转化:      8 个 (做独特版本)
不抄, 保持特色:  7 个 (硬拼没意义)
抄, 快速跟上:    5 个 (真该跟上的)

结果: 30 个功能 → 5 个抄 (16%) + 15 个做独特版本 (50%) + 10 个无视 (34%)
```

**看**: **不是"全面对标"也不是"完全无视", 是"差异化对齐"**。这就是竞品分析的成熟做法。

## 8. 竞品分析反模式

工程师做竞品分析最容易犯的 8 个反模式:

| 反模式 | 症状 | 危害 | 修复 |
|--------|------|------|------|
| 只看直接竞品 | 眼中只有一家 XX 公司 | 忽视间接/替代/潜在竞品 | 四象限展开 |
| 功能对比表迷信 | 写 A 有 B 无的表格 | 只看到 5% 表面 | 五层拆解, 从战略开始 |
| 恐慌式全面对标 | 竞品出啥抄啥 | 变成"更差的他" | 决策树逐个判 |
| 忽视 UI/UX 差距 | "反正 B 端不看脸" | 决策者演示会失分 | 表现层至少做到 60 分 |
| 只抄不做差异化 | 抄完没自己特色 | 用户找不到选你的理由 | 差异化定位公式 |
| 无视目标用户差异 | 假设"用户都一样" | 抄错方向 | 战略层先看用户 |
| 竞品分析一次性 | 分析完就完了 | 竞品在变, 认知落后 | 竞品追踪日报/周报 |
| 分析不落地 | 报告写完就归档 | 团队做不出反应 | SWOT + 具体动作清单 |

**结论**: 这 8 条覆盖了工程师做竞品分析 95% 的翻车场景。做完竞品分析后自检一遍。

## 9. 给不同岗位的话

**如果你是做硬件的**: 硬件的竞品分析最难的是**"看不见的战略层"**——大厂的硬件产品发布你看到功能, 但**他们的供应链战略、生态战略你看不到**。硬件竞品拆五层, 前 3 层 (战略/范围/结构) 尤其重要, 因为硬件"抄 UI"是最没用的 (壳都不好抄)。**硬件铁律**: **别抄单点功能, 要看竞品的整体产品矩阵——他为什么在这时候出这个产品, 是切入哪块市场**。

**如果你是做算法的**: 算法工程师最容易在竞品分析里迷信"论文精度对比"——**"我们的模型 F1 比他们高 2%"**。真正的算法竞品分析在**应用层**——**竞品的模型用在什么业务场景、面向什么用户、错误怎么处理**。**算法竞品的战略层看**: 是"通用大模型对齐" (押注 AGI) 还是 "垂直深度优化" (押注 domain expertise)。**算法铁律**: **模型是护城河的错觉——真护城河是数据 + 场景 + 团队, 不是模型本身**。

**如果你是做运维 / SRE 的**: 运维平台的竞品分析最容易被"功能列表"骗——**"他们有 100 个监控指标, 我们只有 30 个"**。真正的运维竞品分析看**运维文化差异**——**他们是"平台驱动"(SRE 完全自动化) 还是"人机协同" (研发自主运维)**。这两种模式适合的团队完全不同。**运维铁律**: **别看竞品有多少功能, 要看他"解决了哪个 pattern 的故障"—— 我们运维的差异化点常常在文化不在功能**。

**如果你在传统行业 (银行/制造/政企/医疗)**: 传统行业的竞品分析最难的是**"竞品是本地厂商"**——**每个区域有自己的竞品, 没有统一"头部"**。**打法**: 用四象限时特别关注**间接竞品**——**"客户不用你, 会用什么替代"** 常常不是另一家公司的产品, 而是**"客户自己找了 Excel + 外包组合"**。**传统行业铁律**: **差异化不比"技术先进", 比"本地化服务" + "关键人员关系" + "行业理解深度"—— 这三点抄不去**。

## 10. 综合案例与收官

### 10.1 竞品应对

回到糖果充。老周提醒他"先看清楚再决定"后, 糖果充做了三件事:

**第一件事 (Day 1-3): 冷静下来, 做五层拆解**

- 花 3 天时间, 团队 3 人分别拆战略/范围/结构 三层, 糖果充亲自拆战略层
- 关键发现: **XX 公司的目标用户是 CFO/决策者, 糖果充是财务专员**——**战略层不重合**

**第二件事 (Day 4-5): SWOT + 差异化定位**

- 团队 5 人做一次 SWOT 会议 (2 小时)
- 提取出糖果充的三大差异化点: **独立部署 / 生态开放 / 使用者主导**
- 写出定位陈述句, 全团队认可

**第三件事 (Day 6-10): 决策树 + 行动清单**

- 用决策树逐个判断 XX 公司的 30 个新功能
- 得出行动清单:
  - 5 个必抄 (Q1 内做)
  - 15 个转化为独特版本 (Q2 内做)
  - 10 个无视
- 同时列出 3 个"XX 公司做不了但我们能做"的独特功能 (Q1-Q2 主推)

**5 天后, 糖果充给 A 总的汇报**:

```
糖果充: "A 总, 五天的分析我做完了。三个结论:
        
        结论 1: XX 公司和我们不是同一批用户。
               他们抢 CFO 的采购预算, 我们抢财务专员的日常喜爱。
               战略上没直接冲突。
        
        结论 2: 抄他们所有功能是错的。抄 5 个必抄, 15 个转化为独特版本, 
               10 个无视。总投入 3 个月, 不影响主线。
        
        结论 3: 我们要主推 3 个 XX 公司做不了的独特点:
               ① 完全独立部署 (数据不离开客户机房)
               ② 生态开放 (客户可自选 ERP)  
               ③ 使用者主导 AI (不用担心背锅)
        
        请您批准这个方向。"

A 总: "好, 就这么办。你比一周前那个说'快抄'的小杨长大了。"
```

**三个月后的季度会**:

```
糖果充团队的 Q1 数据:
  客户流失率:  2% (预期最差 30%, 结果几乎无流失)
  新客户增长:  8 家 (含 3 家从 XX 公司竞标中败选后转投)
  北极星:      50 (超目标 40)
  NPS:         8.0 (提升)

关键: 3 家从 XX 公司败选后转投糖果充的客户, 明确说的理由:
  客户 A: "XX 公司要求我们迁移到他们 ERP, 我们不想被锁死"
  客户 B: "XX 公司的 AI 太自动化了, 我们财务不敢用"
  客户 C: "XX 公司的独立部署方案报价高 3 倍, 你们的正合适"

★ 这三个理由, 全是糖果充的三大差异化点
```

**这就是竞品分析真正的价值——不是"打赢"竞品, 是"让我们的用户找到我们不可替代的理由"**。

### 10.2 六篇能力回望

**糖果充的一年**——从"造代码的人"到"造产品的人"——**完整走完六个坎**:

```
第 1 篇 (用户视角):
  Q1: 造对账系统 V1, 三个月日活为零
  → 学到"承认自己不是用户", V2 上线爆火

第 2 篇 (用户需求分析):
  Q2 初: 12 个需求全做, 10 个无人用
  → 学到 5Why + JTBD, 挖出真需求, 只做 5 个爆火

第 3 篇 (优先级排序):
  Q2 中: 三方需求都说最急, 团队卡死
  → 学到 RICE + Kano + 三方评审, 30 个需求砍到 8 个

第 4 篇 (MVP):
  Q3 初: 发票六件套, 5 件套无人用
  → 学到 MVP 三形态 + BML + 砍功能四刀, 从 6 人月缩到 2 人月

第 5 篇 (数据指标):
  Q3 末: 盯 DAU 涨 30%, 被老板问懵
  → 学到北极星 + AARRR/RARRA + 四层指标, 建成产品仪表盘

第 6 篇 (竞品分析):
  Q4 末: XX 公司免费冲击, 慌乱要抄

```

**六篇的方法论一句话总结**:

```
第 1 篇: 换位置 (从"我造了什么"到"用户凭什么用")
第 2 篇: 挖真因 (从"用户说什么"到"用户真要什么")
第 3 篇: 做取舍 (从"都要做"到"敢砍掉")
第 4 篇: 快验证 (从"做完美"到"先活下来")
第 5 篇: 看真数据 (从"漂亮数字"到"健康指标")
第 6 篇: 找参照系 (从"抄竞品"到"差异化定位")
```

### 10.3 六信合璧飞轮

**六篇不是并列关系, 而是飞轮**——**每一篇的输出是下一篇的输入, 循环加速**:

```
              第 1 篇: 换位置
             (看到真实用户)
                    │
                    ▼
              第 2 篇: 挖真因
             (听懂真实需求)
                    │
                    ▼
              第 3 篇: 做取舍
             (排出真实优先级)
                    │
                    ▼
              第 4 篇: 快验证
             (造出最小 MVP)
                    │
                    ▼
              第 5 篇: 看真数据
             (北极星 + 指标)
                    │
                    ▼
              第 6 篇: 找参照系
             (差异化定位)
                    │
                    │
       ┌────────────┘
       │
       ▼
   回到第 1 篇 (基于差异化定位, 重新看用户)
   
每一次循环, 产品都进化一次
每一次进化, 团队都长大一次
```

**飞轮的意义**:

```
第一次循环: 6-12 个月, 你从"造代码"变成"造产品"
第二次循环: 3-6 个月, 你从"造产品"变成"造产品线"
第三次循环: 1-3 个月, 你从"造产品线"变成"造平台"

飞轮转得越快, 团队进化越快
```

### 10.4 速查与练习

**竞品分析自检卡** (每季度一次, 或重大竞品动作时):

```
□ 1. 我圈出了四象限里的所有竞品吗? (直接/间接/替代/潜在)
□ 2. 我做了五层拆解, 不是只列功能对比表吗?
□ 3. 我用 SWOT 提取了 4 类具体动作 (SO/WO/ST/WT) 吗?
□ 4. 我写出了差异化定位陈述句 (For/Who/Our/That/Unlike) 吗?
□ 5. 我用决策树逐个功能判过"抄/不抄/转化/无视"吗?
□ 6. 我至少列了 3 个"竞品做不了但我们能做"的独特点吗?
□ 7. 我的分析不是一次性的, 有竞品追踪机制 (日报/周报) 吗?
□ 8. 我的分析落地到了具体动作清单 + 责任人 + Deadline 吗?
```

**竞品分析速查表**:

| 场景 | 动作 |
|---|---|
| 竞品发新功能, 团队慌乱 | 冷静 5 天, 走五步分析 |
| 老板问"抄不抄" | 决策树逐个判, 给分层清单 |
| 团队争"我们要跟上" | 战略层拆开, 常常发现不用跟 |
| 只看到功能差距 | 从表现层退回到战略层看 |
| 完全无视竞品 | 至少每季度一次四象限扫描 |
| 抄了变成"更差的他" | 用差异化定位公式重新写 |
| 想找差异化 | 从三大点入手: 用户/价值/生态 |
| 决策后 3 个月不复盘 | 竞品追踪日报, 3 个月复盘 |

**30 天竞品分析练习**:

```
Week 1 (四象限 + 五层拆解):
  拿你的产品, 画一次完整的竞品四象限
  重点: 至少列 8 个竞品 (直接/间接/替代/潜在各 2 个)
  然后选最重要的 1 家, 做完整五层拆解
  你会发现: 直接竞品可能不是最大威胁

Week 2 (SWOT + 定位陈述):
  召开团队 SWOT 会议 (2 小时)
  产出 4 类战略动作 (SO/WO/ST/WT), 各 2-3 个
  写出差异化定位陈述句, 全团队讨论共识
  贴到工位墙上

Week 3 (决策树):
  找出竞品最近发布的 10 个新功能
  用决策树逐个判决: 抄/转化/无视/保持
  形成具体动作清单
  记录: 有几个原本团队想抄的, 走完流程后决定不抄

Week 4 (竞品追踪机制):
  建一个"竞品追踪频道" (钉钉/飞书/Slack)
  每天更新: 竞品发布、招聘、融资、客户新闻
  每周一份周报, 每季一份复盘
  尝试运行 1 个月, 看是否比"临时慌乱"决策质量高
```

**练完 30 天你会得到什么**:
- 一份属于你团队的**竞品四象限图 + 差异化定位陈述句**
- 一种反射: **听到"XX 出新功能" 先深呼吸, 再走五步分析**
- 一种自信: **敢在老板面前说"这个不用抄, 我们的用户不需要"**
- 一种能力: **从"跟随者" 升级为 "定位者"**
