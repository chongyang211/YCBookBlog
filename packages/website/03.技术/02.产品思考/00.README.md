# 产品思考系列

> 程序员的产品思维——代码之外，你造的到底是谁用的

## 一、这个系列讲什么

技术能力练到一定阶段，几乎所有工程师都会撞上同一堵墙：**"我技术不差，为什么我做的东西没人用？"**

再往下细分，是六个反复出现的坎：

```
① 做的东西技术上完美, 但真实用户为零        → 用户视角缺失
② 按用户提的需求做了, 用户还是骂           → 挖不到真需求
③ 需求列 30 条, 团队一个月做 3 条          → 排不出优先级
④ 想做全套完美产品, 结果 80% 的功能没人碰   → 做不出真 MVP
⑤ 数据涨了, 但被问付费率答不上来           → 建不起指标体系
⑥ 竞品发新功能就想抄, 抄完用户反而流失      → 看不懂竞品
```

**这六个坎不是产品经理的坎，是每一个"从造代码的人转变为造产品的人"的工程师必然要跨的坎**。跨过去，你不再只是"能做出功能"，而是"能做出被用、被留、被推荐的东西"。

跨不过去，你的技术生涯会长期卡在"高级执行者"这一档——写得快、写得好，但**不知道自己为什么在写**。

## 二、主线人物：糖果充

系列沿用《程序员精进路》里的主角 **糖果充**。精进路里他是一个正在成长的一线工程师，本系列里，他已经 32 岁，8 年工龄，从后端工程师转成某公司的产品负责人。

**为什么用糖果充**：
- 精进路里的糖果充解决的是"怎么把代码写好、方案讲清楚"
- 产品思考里的糖果充解决的是"怎么让写出来的东西真的被人用"
- 两条线在他身上首尾相接，你能看到一个工程师**完整的**成长弧

糖果充的失败案例、翻车经历、被点醒的瞬间，是本系列六篇的**主线案例**。每一篇都从他的一次翻车开始，用一整篇讲透那次翻车背后的方法论。

## 三、六篇路线图

```
第 1 篇: 产品思维入门指南
   ↓  糖果充造了没人用的对账系统
   ↓  → 学会"用户视角"、价值公式、场景三问
   
第 2 篇: 用户需求分析方法
   ↓  糖果充照用户说的做, 用户还是骂
   ↓  → 学会挖真需求、5Why、JTBD、真伪反隐
   
第 3 篇: 功能优先级排序法
   ↓  糖果充手上 30 个需求, 团队 5 人一个月做 3 个
   ↓  → 学会 RICE、Kano、MoSCoW、优雅拒绝
   
第 4 篇: 最小可行产品设计
   ↓  糖果充做了六件套, 用户只用其中一件
   ↓  → 学会 MVP、BML 循环、砍功能四刀法
   
第 5 篇: 产品数据指标设计
   ↓  DAU 涨 30%, 老板问付费率糖果充答不上来

第 6 篇: 竞品分析方法实践 (系列收官)
   ↓  照抄竞品新功能, 自家用户流失 40%
   ↓  → 学会竞品五层、SWOT、差异化定位
   ↓
一个工程师完成"从造代码的人到造产品的人"的转型
```

## 五、跨行业适配

本系列面向**所有程序员**——不管你做的是：

- 互联网 C 端（社交、电商、内容、工具）
- 互联网 B 端（SaaS、中后台、企业服务）
- 硬件（消费电子、IoT、工业设备）
- 算法（推荐、CV、NLP、大模型应用）
- 运维 / SRE / DevOps
- 传统行业（银行、制造、政企、医疗）

每一篇方法论主体之后，都有 **「给不同岗位朋友的话」** 小节，把该篇方法论在你所在领域的**变形**和**注意点**点出来。不是"互联网黑话对齐传统行业"，是每类工程师都能对号入座。

## 六、如何阅读

**从头顺着读**：如果你正处在"技术不错、开始接触产品但迷茫"的阶段（工作 2–5 年常见），建议按顺序读。六篇之间是**递进关系**——第 1 篇教你换视角，第 2 篇教你挖真相，第 3 篇教你做取舍，第 4 篇教你先活下来，第 5 篇教你看真数据，第 6 篇教你找参照系。

**按坎点读**：如果你已经在做产品、正卡在某一坎上，直接跳到对应编号：

- 我的东西没人用 → 第 1 篇
- 用户需求听不懂 → 第 2 篇
- 需求太多做不过来 → 第 3 篇
- 老想做全套完美产品 → 第 4 篇
- 数据看了但没方向 → 第 5 篇
- 老板要抄竞品 → 第 6 篇

**当手册反复查**：每一篇末尾都有**速查表**、**模板**和**30 天练习**。合上文档你随时能翻回来找到那张卡。

## 七、与精进路的关系

```
《程序员精进路》: 技术侧成长 (方案/架构/表达/评审/协作/团队)
              ↓  同一主角糖果充
《产品思考》 :   产品侧成长 (视角/需求/取舍/MVP/数据/竞品)
              ↓  同一主角糖果充
一个工程师的完整生涯路径图
```

两个系列共用糖果充这条主线。**精进路解决"怎么把技术这门手艺练精"，产品思考解决"练精之后往哪里用"**。互不依赖，但一起读收获更完整。

## 八、写在最后

本系列不是产品经理培训教材。市面上产品经理的书够多了，绝大多数对工程师不够友好——要么太业务、要么太玄学、要么把工程师当成"资源"而不是"决策方"。

**这个系列的立场是**：**工程师是产品决策的一部分**。不是给产品经理打工，是和产品经理并肩做决策。你懂技术，也懂产品，你就是那个稀缺的"能翻译两种语言的人"。

翻开第 1 篇，从糖果充第一个没人用的系统开始。
