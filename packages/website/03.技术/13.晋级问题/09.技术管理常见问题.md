# 技术Leader面试速答清单

> 面试/答辩前 10 分钟快速过一遍：每题一句话核心答案，详细展开见 01-08 各专题篇。

2. 技术规范速答

# 1.技术管理速答

- 从写代码到带团队怎么调整定位？→ 从「我做好」到「团队做好」，最大的坑是事必躬亲。
- 做了管理还要不要写代码？→ 保留 20%-30% 参与核心模块，保持判断力。
- 接手新团队前三个月做什么？→ 一月多听少动、二月小步快跑、三月定方向。
- 项目进度落后了应该怎么办？→ 加人/砍范围/调优先级三选一，记住 Brooks 法则。
- 需求永远做不完怎么沟通？→ 主动做减法，先上线最小闭环再迭代。
- 团队有人不服从管理怎么办？→ 先私下沟通，事实反馈给改进机会，制度管人流程管事。
- 核心骨干提出离职怎么办？→ 挖真实动机（钱/成长/氛围），留不住好聚好散+知识沉淀。
- 和上级意见冲突时怎么办？→ 敢表达+服从决策+事后复盘，焦点是方案不是输赢。

# 2.技术规范速答

- 规范为什么难落地怎么破局？→ 工具自动化 > 流程卡点 > 人工审查 > 口头约定。
- 什么是线上变更的三板斧？→ 可灰度、可监控、可回滚，缺一不可。
- Code Review 走形式怎么办？→ MR 小批量、标准明确、抽查反馈。
- 规范的松紧度应该怎么把握？→ 底线规范强约束，风格规范弱引导。
- 第三方库的引入应该怎么管理？→ 引入评审、版本锁定、禁止私拉 fork。

# 3.技术建设速答

- 技术债应该怎么识别和偿还？→ 固定比例时间+随需求小步重构+专项治理，用数据说服业务方。
- 可观测性的三支柱是什么？→ Metrics、Logging、Tracing。
- 研发效能用什么指标来度量？→ DORA 四指标：部署频率、前置时间、变更失败率、恢复时间。
- 稳定性建设包含哪些内容？→ SLA/SLO/SLI + 压测 + 限流降级熔断 + 混沌演练。
- 四级监控是怎么分层的？→ 资源 → 组件 → 接口 → 业务。

# 4.技术攻坚速答

- 线上出了问题应该怎么排查？→ 先止血再定位：回滚/降级优先，再分层缩小范围。
- 性能优化的方法论是什么？→ 先测量再优化，避免直觉优化。
- 秒杀系统应该怎么设计？→ 削峰、限流、库存预扣、热点隔离。
- 大规模重构用什么策略？→ 绞杀者模式渐进替换，不推倒重来。
- 不停机数据迁移怎么做？→ 双写 → 灰度切读 → 数据校验 → 回滚设计。
- 事故复盘的原则是什么？→ 对事不对人，改进项有负责人有期限有回头看。

# 5.团队成长速答

- 团队梯队应该怎么建设？→ 识别高潜、培养 backup，避免「离了谁就不转」。
- 新人培养的机制是什么？→ mentor 制 + 30-60-90 目标 + 第一个小任务。
- 晋级答辩怎么辅导成员？→ 案例选取 + STAR 结构 + 量化结果。
- 团队分享怎么不流于形式？→ 案例驱动、代码演示、解决实际问题。
- 职业倦怠怎么识别干预？→ 识别信号（产出降/沉默/抗拒变化），调项目/休假/换角色。

# 6.业务与产品速答

- 老板问质量变好怎么回答？→ 用数据答：故障数/时长/变更失败率/逃逸缺陷趋势。
- 什么是质量左移的方法？→ 在需求与设计阶段挡住问题，兜底成本是左移的十倍。
- 降本百分之三十先砍什么？→ 先砍浪费（僵尸服务/重复建设）再砍能力，SLA 底线不降。
- 团队的瓶颈在哪里怎么破？→ 关键人/并行/协作三种瓶颈，对症下药不加人。
- MVP 的本质到底是什么？→ 最小成本验证核心假设，不是功能残缺版。
- 怎么判断一个需求的真伪？→ 看用户愿意付什么代价，嘴上想要≠真需求。
- 需求的优先级应该怎么排序？→ RICE 数据化排序，代替谁嗓门大听谁的。
- 什么是一个产品的北极星指标？→ 与用户价值强相关的唯一指标，一个产品只有一个。
