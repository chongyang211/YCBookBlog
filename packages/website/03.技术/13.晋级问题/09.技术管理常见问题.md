# 技术Leader面试速答清单

> 面试/答辩前 10 分钟快速过一遍：每题一句话核心答案，详细展开见 01-08 各专题篇。

#### 目录介绍
- 1.技术管理速答
- 2.技术规范速答
- 3.技术建设速答
- 4.技术攻坚速答
- 5.团队成长速答
- 6.业务与产品速答

# 1.技术管理速答

- 从写代码到带团队？→ 从「我做好」到「团队做好」，最大的坑是事必躬亲。
- 还写不写代码？→ 保留 20%-30% 参与核心模块，保持判断力。
- 新官上任三步？→ 一月多听少动、二月小步快跑、三月定方向。
- 进度落后怎么办？→ 加人/砍范围/调优先级三选一，记住 Brooks 法则。
- 需求做不完？→ 主动做减法，先上线最小闭环再迭代。
- 有人不服管？→ 先私下沟通，事实反馈给改进机会，制度管人流程管事。
- 骨干离职？→ 挖真实动机（钱/成长/氛围），留不住好聚好散+知识沉淀。
- 和上级冲突？→ 敢表达+服从决策+事后复盘，焦点是方案不是输赢。

# 2.技术规范速答

- 规范怎么落地？→ 工具自动化 > 流程卡点 > 人工审查 > 口头约定。
- 变更三板斧？→ 可灰度、可监控、可回滚，缺一不可。
- CR 走形式？→ MR 小批量、标准明确、抽查反馈。
- 规范松紧？→ 底线规范强约束，风格规范弱引导。
- 三方库怎么管？→ 引入评审、版本锁定、禁止私拉 fork。

# 3.技术建设速答

- 技术债怎么还？→ 固定比例时间+随需求小步重构+专项治理，用数据说服业务方。
- 监控三支柱？→ Metrics、Logging、Tracing。
- 效能度量？→ DORA 四指标：部署频率、前置时间、变更失败率、恢复时间。
- 稳定性建设？→ SLA/SLO/SLI + 压测 + 限流降级熔断 + 混沌演练。
- 四级监控？→ 资源 → 组件 → 接口 → 业务。

# 4.技术攻坚速答

- 线上问题排查？→ 先止血再定位：回滚/降级优先，再分层缩小范围。
- 性能优化方法论？→ 先测量再优化，避免直觉优化。
- 秒杀设计？→ 削峰、限流、库存预扣、热点隔离。
- 大规模重构？→ 绞杀者模式渐进替换，不推倒重来。
- 不停机迁移？→ 双写 → 灰度切读 → 数据校验 → 回滚设计。
- 复盘原则？→ 对事不对人，改进项有负责人有期限有回头看。

# 5.团队成长速答

- 梯队建设？→ 识别高潜、培养 backup，避免「离了谁就不转」。
- 新人培养？→ mentor 制 + 30-60-90 目标 + 第一个小任务。
- 晋级辅导？→ 案例选取 + STAR 结构 + 量化结果。
- 分享不流于形式？→ 案例驱动、代码演示、解决实际问题。
- 职业倦怠？→ 识别信号（产出降/沉默/抗拒变化），调项目/休假/换角色。

# 6.业务与产品速答

- 质量变好了吗？→ 用数据答：故障数/时长/变更失败率/逃逸缺陷趋势。
- 质量左移？→ 在需求与设计阶段挡住问题，兜底成本是左移的十倍。
- 降本 30%？→ 先砍浪费（僵尸服务/重复建设）再砍能力，SLA 底线不降。
- 团队瓶颈？→ 关键人/并行/协作三种瓶颈，对症下药不加人。
- MVP 本质？→ 最小成本验证核心假设，不是功能残缺版。
- 真伪需求？→ 看用户愿意付什么代价，嘴上想要≠真需求。
- 优先级排序？→ RICE 数据化排序，代替谁嗓门大听谁的。
- 北极星指标？→ 与用户价值强相关的唯一指标，一个产品只有一个。
