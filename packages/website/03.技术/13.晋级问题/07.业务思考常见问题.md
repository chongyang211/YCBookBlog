# 1.业务连续性（事前预防）

- **问：业务连续性怎么建？**
  答：在系统设计、测试验证、变更管控三个阶段层层设防，而不是「出了事再救火」；三道防线各管一段、相互衔接。

- **问：故障注入不是搞破坏吗？为什么要做？**
  答：故障注入是「打疫苗」——用可控的小剂量故障（依赖中断、网络延迟、资源耗尽）验证系统的免疫能力，暴露问题在用户之前。

- **问：容灾预案写了没人验证，等于没有吗？**
  答：等于没有——必须常态化演练（预案核对、真实切换、恢复计时）；演练发现的问题要反哺架构，预案随系统演进更新。

- **问：为什么 80% 的故障来自变更？怎么管住变更？**
  答：变更引入新代码与新配置，是风险最集中的动作；管住靠发布流水线、灰度分批、回滚预案、变更窗口，「可灰度、可监控、可回滚」三问缺一不可。

- **问：业务量涨多少倍系统会倒？容量怎么算？**
  答：通过压测摸清容量水位线（安全水位/扩容水位/红线水位）；大促容量公式 = 预估峰值 × 冗余系数；摸不清容量等于裸奔。

# 2.质量连续性（事中控制）

- **问：老板问「这个季度质量变好了吗」，你怎么回答？**
  答：靠质量数据体系说话——故障数、故障时长、变更失败率、逃逸缺陷数的趋势；没有数据的「变好了」是感觉不是结论。

- **问：什么是质量左移？**
  答：在需求与设计阶段就把质量问题挡住——需求评审带测试视角、技术方案做故障模式分析；而不是等测试阶段兜底，兜底成本是左移的十倍。

- **问：自动化用例越攒越多、越攒越烂怎么办？**
  答：分层维护（核心用例重点保）、失败用例清零机制（失败必须处理）、用例与代码同仓库演进；测试数据也要统一构造与管理。

- **问：质量红线怎么定？赶工期能不能跳过测试？**
  答：红线要清晰（P0 故障零容忍/核心链路覆盖率门槛）；「质量让步」要有审批与记录机制——谁批准、补测计划、回头看检查，不能悄悄放水。

# 3.运营连续性（事后改进）

- **问：业务的生命线指标怎么守护？**
  答：先定义运营红线（支付成功率/订单履约率/数据准确性）；红线配监控、告警与应急响应链路，突破红线自动触发最高优先级响应。

- **问：故障发生的第一小时做什么？**
  答：按预案分工——指挥（决策）、操作（止血）、通报（对内对外口径统一）；止损优先于根因，恢复业务永远排第一。

- **问：一个故障修完就结束了吗？**
  答：没有——要举一反三：单点扫描到面（同类风险批量治理）、沉淀安全基线文档化；把故障变成案例库与演练素材，让价值最大化。

- **问：人比系统更危险，怎么防？**
  答：把「人会犯错」当前提而不是意外；四道防线——流程防呆、双人复核、权限最小化、演练教育；想犯错也犯不了才是好设计。

- **问：复盘会开成甩锅会怎么办？**
  答：主持人只引导事实与时间线，禁止追责个人；改进项必须可执行（有负责人、有时间点）；改进项闭环追踪，下次复盘先查上次的改进项。

# 4.成本与效率

- **问：云资源成本怎么管？**
  答：先盘点分类（计算/存储/带宽/中间件）；建成本可视化看板（按团队/按业务/按趋势）；明确谁对成本负责，成本要有 owner。

- **问：资源优化的三板斧是什么？**
  答：弹性伸缩（潮汐业务按需扩缩）、竞价实例（可中断任务用便宜资源）、存储与带宽挤脂肪（冷数据归档、CDN 优化、日志降采样）。

- **问：构建提速这种小事值得投入吗？**
  答：值得——每省一分钟 × 每日构建次数 × 人数 = 团队节省的总时间；认知效率（上手成本、协作等待）的优化同理，是复利型投入。

- **问：降本 30% 先砍什么？**
  答：先砍浪费再砍能力——僵尸服务、冗余容灾、重复建设优先于裁人；降本的服务质量底线（SLA）不能降，要向业务方证明「降本不降质」。

- **问：人效比怎么度量才不被玩坏？**
  答：吞吐类指标看趋势不看绝对值；必须结合质量指标防「快而烂」；度量是仪表盘不是 KPI 钉子——指标一变 KPI 就会被优化变形。

# 5.团队效能

- **问：团队产出怎么度量？**
  答：三类指标组合使用——交付吞吐（需求交付周期/在制品数）、质量（故障率/返工率）、工程能力（覆盖率/构建时长）；单看任何一个都会被优化变形。

- **问：需求从提出到上线，真正写代码的时间占多少？**
  答：通常不到一半——大部分浪费在等待与审批；用价值流分析砍掉这些浪费（需求就绪标准、自动化卡点），比催程序员写快点有效得多。

- **问：团队打不动了，瓶颈在哪？**
  答：三种典型瓶颈——关键人瓶颈（别让支付只有一人懂）、并行瓶颈（限制每人同时只做两件事）、协作瓶颈（跨团队等待占比）；对症下药而不是加人。

- **问：六个人怎么打十个人的仗？**
  答：靠杠杆不靠加班——工具杠杆（自动化）、流程杠杆（标准化）、人才杠杆（招聘与培养）；杠杆放大的产能才是可持续的。

# 6.业务理解与价值判断

- **问：技术人怎么懂业务？**
  答：建立业务体感——看数据大盘、听客服录音、跟着销售跑一趟；比产品更懂用户的技术才有话语权。

- **问：这个技术项目值多少钱？**
  答：用商业语言汇报技术价值——故障一分钟损失多少收入、效率提升节省多少人力成本；把技术指标翻译成钱，业务方才听得懂。

- **问：大促要冲量、系统要保稳，怎么决策？**
  答：事前约定——容量冗余度、降级预案、熔断阈值在活动前定好，而不是出了事再吵；冲量与保稳的边界要白纸黑字。

- **问：技术人发现的机会怎么推动成业务项目？**
  答：找业务方共创（不是自己偷偷做）、小成本验证（demo 或试点数据）、用业务语言讲收益；技术驱动创新要借业务的力。
