# 1.代码与协作规范

- **问：代码规范怎么定才能落地？Code Review 怎么不走形式？**
  答：风格靠 lint 工具强制而非口头约定；CR 明确标准与流程，MR 控制粒度（小批量、可回滚、描述清晰）；CR 要有抽查与反馈机制防止走过场。

- **问：分支模型怎么选？提交信息怎么管？**
  答：小团队主干开发、多团队并行可 GitFlow；提交信息用 feat/fix/refactor 等前缀；发布必须走预发环境、灰度、回滚预案，禁止直接改线上。

- **问：命名规范怎么治理？**
  答：项目、模块、类、函数统一约定（见名知意），建立团队术语表；治理中英文混用与拼音命名，新代码立即执行、老代码随改随修。

- **问：三方库引入怎么管？**
  答：引入需评审（维护活跃度、许可证、包体积）；版本锁定、统一升级窗口；禁止私拉 fork 与源码拷贝，防止失联依赖。

# 2.文档与接口规范

- **问：哪些文档必须写？写多少合适？**
  答：架构设计、接口定义、线上事故复盘、新人上手指南四类必须有；够用就好避免形式主义；把文档更新绑定进流程（如发布前检查）才能保持不过期。

- **问：接口规范怎么定？**
  答：RESTful 与 RPC 各自的约定；版本管理遵守兼容原则（只增不改不删）；错误码统一；接口文档与 mock 同步维护。

- **问：接口上线前评审什么？**
  答：过评审清单——命名、幂等、分页、超时、限流、降级；破坏性变更必须通报并留迁移期，不能让调用方踩坑。

# 3.数据与安全规范

- **问：数据库规范怎么落地？**
  答：建表规范（命名、必填字段、软删除）；大表变更走 DDL 评审、低峰执行；设定慢查询治理目标；索引规范靠审查与工具双重把关。

- **问：敏感数据怎么管？**
  答：数据分级（公开/内部/机密）；导出与查询审批留痕；测试环境禁止用生产真实数据，必须有脱敏方案。

- **问：安全规范至少要包含哪些？**
  答：密钥管理（环境变量/密钥平台，禁止入库入仓）；权限最小化；敏感数据脱敏；上线前安全扫描（SAST/DAST）。

# 4.线上纪律

- **问：值班与线上纪律怎么定？**
  答：约定变更窗口；oncall 轮值机制；报警响应 SLA；事故分级与升级路径清晰；坚决杜绝「改一下就上线」。

- **问：什么是变更三板斧？**
  答：可灰度、可监控、可回滚——任何线上变更必须能回答这三个问题，缺一不可，否则不允许执行。

- **问：生产环境权限怎么治理？**
  答：权限最小化（跳板机、审批、双人复核）；高危操作（删表、清缓存、强制重启）必须二次确认并留痕。

# 5.规范落地方法论

- **问：规范为什么难落地？怎么破？**
  答：靠工具自动化 > 流程卡点 > 人工审查 > 口头约定；新规范先试点再推广，配套迁移方案与时间表，而不是一刀切全面铺开。

- **问：规范太严影响效率、太松形同虚设，怎么把握？**
  答：分层约束——底线规范（安全、线上纪律）强约束零容忍；风格规范（格式、命名）弱引导靠工具自动处理。

- **问：规范要不要定期修订？**
  答：要——每季度评审、废止过时条款；任何人都有权提修订建议，但必须走评审，避免规范变成个人的偏好。
