# 1.角色与定位

- **问：从写代码到带团队，如何调整定位？**
  答：核心转变是从「我做好」到「团队做好」，从个人产出到团队产出；前期最大的坑是事必躬亲、不敢放权。

- **问：做了管理还要不要写代码？时间怎么分配？**
  答：建议保留 20%-30% 参与核心模块（评审关键 MR、写核心设计），既保持技术判断力，又不与团队产出抢时间。

- **问：接手一个新团队，前三个月做什么？**
  答：第一个月多听少动（1on1 全覆盖、摸清业务与人员、找出最大痛点），第二个月小步快跑（解决一两个痛点建立信任），第三个月定方向（技术规划与团队规范落地）。

- **问：你的管理风格是什么？**
  答：对不同成熟度成员用不同方式——新人指令式、骨干授权式、资深成员教练式；没有最好的风格，只有最合适的风格。

# 2.任务与排期

- **问：如何把需求拆成合适的任务粒度并分配？**
  答：按成员能力与成长诉求分配（高难度给骨干、稳态任务给新人、搭配带教）；同时避免「能者多劳」失衡，防止骨干过载、新人缺成长。

- **问：如何估时与识别风险？进度落后了怎么办？**
  答：估时三招——加缓冲、拆里程碑、识别依赖；进度落后时在「加人、砍范围、调优先级」里选，注意 Brooks 法则：向延期项目加人会更延期。

- **问：需求永远做不完，怎么和产品沟通？**
  答：主动做减法——砍需求、分阶段交付；用「先上线最小闭环再迭代」的策略保住核心目标，而不是拒绝或全接。

- **问：什么时候值得为速度欠技术债？**
  答：可以欠债，但不能糊涂债——每个技术债都要记录（内容、原因、偿还计划），随需求小步偿还，否则利滚利压垮迭代速度。

- **问：多条业务线同时压需求怎么办？**
  答：建立需求准入与优先级机制——统一入口、每周需求评审、团队容量透明化，让排队看得见而不是互相插队。

# 3.人与团队

- **问：如何定目标与做绩效沟通？**
  答：目标用 OKR/SMART；绩效沟通用「事实+影响+期望」结构，对事不对人；激励因人而异——成长型给挑战、稳定型给认可、倦怠型给轮岗或新方向。

- **问：1on1 怎么做才不流于形式？**
  答：固定频率，聊进展、blockers、成长、情绪四类话题；关键是倾听而非说教，听到负面情绪和离职倾向要深挖而不是回避。

- **问：如何建设团队梯队、避免「离了谁就不转」？**
  答：识别高潜、培养 backup（关键模块必须有人能接）；通过轮岗、结对、文档化降低单点依赖。

- **问：成员绩效差，怎么处理？**
  答：先给改进机会而不是直接打差绩效——PIP 要明确标准、给足支持、留有余地；改进仍无果再走绩效流程。

- **问：团队有冲突怎么办？如何营造氛围？**
  答：技术分歧对人不对事；建立心理安全感（敢说不知道、敢报坏消息）；小胜利也要有仪式感，胜利要庆祝。

- **问：核心成员提离职怎么办？**
  答：先了解真实原因（钱、成长、氛围、家庭），能挽留的认真挽留；留不住的好聚好散——交接清单+知识沉淀，事后复盘管理根因。

# 4.协作与向上向下

- **问：与其他团队有分歧怎么处理？**
  答：先对齐目标再谈方案，用数据与用户价值说话；谈不拢升级到上级仲裁，而不是私下对抗或消极抵制。

- **问：如何做向上管理？**
  答：汇报结论先行、数据支撑、带风险与方案；主动争取资源；把上级目标承接住并拆解落地，让上级对你有预期管理。

- **问：如何向下传导公司战略与坏消息？**
  答：把公司战略翻译成团队听得懂的目标；做坏消息传递者（裁员、降本、砍项目）时要坦诚、给解释、不失公信力。

- **问：和产品经理需求理解有分歧怎么办？**
  答：建立需求评审机制，用「价值、方案、成本」三问对齐；先就「为什么做」达成一致，再谈「怎么做」。

# 5.招聘与组织

- **问：如何招到对的人？**
  答：先定义岗位画像；面试题要有区分度，用 STAR 追问细节判断真实水平；试用期设定明确的考察目标。

- **问：团队按什么维度划分？什么时候拆/合？**
  答：按业务域、技术层或职能划分，取决于协作成本与业务规模；专项攻坚用虚拟团队（组建快、解散也要干脆）。

- **问：怎么做人才盘点？**
  答：技能矩阵+人才九宫格（绩效×潜力）；基于盘点结果制定培养计划与招聘计划，让梯队建设有据可依。

# 6.新场景管理

- **问：远程/混合团队怎么管？**
  答：信息透明靠文档化、异步沟通、录制重要会议；考察产出用结果导向而非工时；定期线下聚维系凝聚力。

- **问：AI 编码助手普及后，团队管理要怎么变？**
  答：调整分工与质量门槛（AI 产出也要 CR）；考核看真实产出而非「用了多少 AI」；警惕成员核心能力空心化，保持深度理解的要求。

- **问：如何管理不同代际的成员？**
  答：不用同一套方法套所有人——管理比自己资深的成员靠尊重与授权，管理新生代要给意义感、边界感、即时反馈。
