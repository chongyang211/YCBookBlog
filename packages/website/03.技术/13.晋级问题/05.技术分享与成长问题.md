# 1.团队分享机制

- **问：如何建立团队分享机制且不流于形式？**
  答：定固定频率与轮值；分享要案例驱动、代码演示、解决实际问题；配套激励机制（积分、评优、晋升材料认可）。

- **问：不同层级的成员分别分享什么？**
  答：新人分享学习心得与踩坑记录；骨干分享架构设计、原理剖析、技术方案；素材从日常来——每次难题排查都是好主题。

- **问：分享只有 PPT 一种形式吗？**
  答：不——代码共读会、故障复盘会、论文研读、外部大会参会转述都有效；15 分钟闪电演讲与深度分享搭配，轻重结合。

- **问：怎么保证分享的质量？**
  答：要求有「我的踩坑/我的判断/我的取舍」，不是念文档；分享后文档归档、精华摘录进 Wiki，沉淀为团队资产。

# 2.学习氛围建设

- **问：如何带动团队的学习氛围？**
  答：读书会、源码共读、外部大会参会后的转述分享；鼓励参与开源与技术社区，把外部视野带回来。

- **问：学习型团队有什么机制保障？**
  答：技术雷达定期更新（采用/试验/评估/淘汰四档）；内部技术委员会运作新技术试点；每个试点都有立项与结论沉淀。

- **问：面试和学习有什么关系？**
  答：面试别人是最好的学习——面别人会暴露自己的知识盲区；把面试题库沉淀为团队的学习地图，一举两得。

# 3.个人成长路径

- **问：如何为成员规划成长路径？**
  答：分技术专家路线与管理路线；安排「跳一跳够得着」的挑战任务促进成长；定期回顾技能矩阵做成长反馈。

- **问：如何辅导成员准备晋级答辩？**
  答：案例选取（有难度有结果）、STAR 结构组织、量化结果呈现；晋级失败后做心理建设与改进计划，明年再来。

- **问：专家通道常见的坑是什么？**
  答：转管理又转回技术的安置要提前想好；专家通道要避免「高职级做低职级的事」；给专家真正的技术决策权，否则通道形同虚设。

- **问：如何识别与干预职业倦怠？**
  答：识别信号——产出下降、沉默、抗拒变化；干预手段——调项目、休假、换角色；Leader 自己倦怠了要找上级或同侪聊，别硬扛。

# 4.新人培养

- **问：新人 mentor 制怎么设计？**
  答：带教内容清单化、阶段目标明确；快速上手三件事——环境、文档、第一个小任务；目标是「教会思考」而不只是「教会做」。

- **问：新人 30-60-90 怎么定目标？**
  答：第一个月熟悉环境出小活、第二个月独立交付模块、第三个月能带一个小需求；每个阶段设检查点并给反馈。

- **问：高潜和普通成员怎么差异培养？**
  答：高潜给「超出能力的任务+高反馈」；普通成员给「清晰的目标+稳定节奏」；避免把所有资源押在少数人身上，梯队要成建制。

# 5.输出与影响力

- **问：如何鼓励成员做技术输出？**
  答：输出即学习——复盘与写作对成长有复利；帮成员克服「没什么可写」的心态：写踩坑、写方案对比、写源码笔记，从小开始。

- **问：团队对外影响力怎么做？有什么价值？**
  答：技术博客/公众号运营、技术大会投稿演讲、参与开源项目；影响力直接降低招聘成本、提升团队品牌与成员自豪感。

- **问：怎么把个人经验变成团队资产？**
  答：知识资产化三手段——文档化、工具化、课程化；避免「人走知识走」；代码评审意见也要沉淀复用，好问题值得被更多人看到。
