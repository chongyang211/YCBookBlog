# 1.产品思维

- **问：为什么做的东西技术完美却没人用？**
  答：用户视角缺失——想的是「怎么实现功能」而不是「解决谁的什么问题」；用场景三问自检：什么场景被谁使用？不用会怎样？用完下一步是什么？三问答不上来基本是伪需求。

- **问：产品的价值怎么衡量？**
  答：价值公式——价值 = 新体验 - 旧体验 - 替换成本；技术人常犯三个高估：高估用户意愿、低估学习成本、忽视迁移摩擦。

- **问：技术视角和产品视角差在哪？**
  答：技术人想「怎么实现」，产品人想「为什么做」；训练自己在写代码前先问用户价值，是转型的第一步。

- **问：内部工具需要产品思维吗？**
  答：需要——内部平台产品化（接口文档、易用性、服务承诺）决定它有没有人用；开发者体验（DX）也是产品设计。

# 2.用户与需求

- **问：照用户说的做了，为什么用户还是骂？**
  答：用户说的（want）不等于用户真正要的（need），更不等于深层动机（job）；要挖到动机层，才能做对事。

- **问：什么是 5Why 追问法？举个例子。**
  答：用户说「我要导出 Excel」，连问五个为什么——报表慢→领导要看数→决策周期长→他要的其实是数据服务而非导出功能；追问到动机层，方案完全不同。

- **问：怎么判断真伪需求？**
  答：看用户愿意付出什么代价（时间/钱/改变习惯）；低成本验证——假门测试、人工兜底、landing page 收意向；嘴上说想要、行动不买单的就是伪需求。

- **问：用户访谈怎么问才不被「礼貌性表扬」骗？**
  答：不问「你觉得好吗」，问「你上次什么时候用的、用完做了什么」；问具体行为而不是观点，行为不会说谎。

- **问：同一个功能对不同用户价值一样吗？**
  答：不一样——新手要引导、专家要效率、管理员要管控；先识别核心用户画像并排序服务，不做「面向所有人」的设计。

- **问：什么是 JTBD？**
  答：用户「雇佣」你的产品来完成什么任务；想清楚这一点，你会发现替代品不只有竞品，还有 Excel 和纸笔。

# 3.优先级与取舍

- **问：手上 30 个需求、一个月只能做 3 个，怎么办？**
  答：需求池统一管理（来源、状态、价值评估）+ 定期清理；用 RICE 等方法数据化排序，代替「谁嗓门大听谁的」。

- **问：RICE 排序法是什么？**
  答：Reach（覆盖量）× Impact（影响度）× Confidence（信心）÷ Effort（工作量）；用数据代替直觉排优先级，排序过程可复现、可讨论。

- **问：Kano 模型怎么用？**
  答：基本型需求（没有就骂）必须满足、期望型需求（越多越满意）按性价比做、兴奋型需求（意外惊喜）适度投放；资源按这三层分配。

- **问：怎么优雅地拒绝一个需求？**
  答：给数据依据（为什么现在不做）、给替代方案（手动兜底/已有功能）、给重新评估的条件（什么时候再看）；拒绝的姿势比拒绝本身更重要。

- **问：老板的「紧急需求」插队怎么处理？**
  答：快速评估代价（挤掉什么、延迟什么）并与老板对齐；协商砍范围或换排期，而不是无脑接；不做需求的奴隶，也不做需求的敌人。

# 4.MVP 与迭代

- **问：MVP 是「功能残缺的版本」吗？**
  答：不是——MVP 是「用最小成本验证核心假设」的产品；验证目标决定砍什么留什么，砍掉的是不能验证假设的部分，不是随便砍。

- **问：砍功能有什么方法？**
  答：四刀法——砍掉只服务少数人的、砍掉没有闭环的、砍掉验证不了假设的、砍掉数据证明没人用的。

- **问：什么是 BML 循环？**
  答：Build（构建）→ Measure（度量）→ Learn（学习）；每一轮迭代都要回答：我验证了什么假设、结论是什么、下一步改什么。

- **问：想做六件套一次惊艳所有人，为什么错？**
  答：结果往往是 80% 的功能没人碰——用「一件做到极致」代替「六件都做」；完美主义的陷阱是把子弹打完才发现靶子找错了。

- **问：架构也要 MVP 吗？**
  答：要——先用简单方案验证业务，再随规模演进；避免「业务还没验证、架构先过度设计」，技术方案的复杂度要匹配业务阶段。

# 5.数据指标

- **问：什么是北极星指标？**
  答：一个产品只有一个北极星——与用户价值强相关的唯一指标；从业务目标推导（搜索产品的北极星是搜索成功率而非搜索次数），防止动作变形。

- **问：AARRR 是什么？**
  答：海盗模型——获客/激活/留存/变现/推荐五个环节各有指标；用于定位产品漏斗的薄弱环节，哪个环节转化差补哪个。

- **问：指标分哪几层？什么是反指标？**
  答：四层——结果指标（GMV/DAU）→ 过程指标（转化率/留存率）→ 技术指标（耗时/成功率）→ 反指标（防好指标被做坏：如推送提活跃但伤留存）。

- **问：什么是好指标、坏指标？**
  答：好指标是比率而非绝对数、是先导而非滞后、难以被人为操纵；累计注册数这类虚荣指标只会麻痹自己。

- **问：数据驱动的边界在哪？**
  答：数据告诉你「是什么」，还要用户访谈告诉你「为什么」；A/B 测试注意最小样本量与陷阱（偷看结果、多重比较）。

# 6.竞品分析

- **问：竞品发新功能就想抄，为什么抄完用户反而流失？**
  答：先分析竞品做这个功能的动机（用户差异？商业目标？试错？），再判断适不适合自己；盲目对齐会丢掉自己的差异化定位。

- **问：竞品分析怎么做？**
  答：五个维度——目标用户、核心功能、商业模式、数据表现、技术架构；产出物是对比矩阵与机会点清单，不是截图集。

- **问：竞品分几层？**
  答：直接竞品（同需求同方案）、间接竞品（同需求不同方案）、替代品（不解决也行）；真正的威胁常来自跨界。

- **问：怎么体验竞品才是对的？**
  答：以真实用户身份深度使用，不是逛五分钟截图；记录自己的关键体验点——首次上手、核心任务、付费决策三个时刻。

- **问：跟竞品全面对齐还是单点突破？**
  答：技术人常犯「功能对齐强迫症」；差异化往往来自场景聚焦而非功能数量，单点打透比全面平庸更有胜算。
