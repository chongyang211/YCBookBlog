## 05.技术分享的模版

> **文档定位**：你已写好一篇技术博客，要把它改编成一场可讲的分享。博客是"写给人读"，分享是"讲给人听"——读者能回看、能跳过，听众不能。本文讲怎么把一篇写好的文章二次加工成一场分享。
> **篇幅**：30 / 45 分钟两档（短讲 30，深讲 45）。
> **怎么用**：01-06 是「准备」，第 07 章才是你上台要照讲的**分享正文终稿**。复制第 07 章结构，把 `<>` 填成你的内容，口语化，直接讲。

### 使用说明

**适用范围**

1. 已有技术博客，要在组内、周会或外部做分享
2. 把一篇长文压缩成短分享
3. 外部技术大会 talk 的初稿

**和 03 / 04 的区别**

| 维度 | 03 技术业务分享 | 04 业务串讲 | 05 技术分享（本文） |
|---|---|---|---|
| 来源 | 做过的事 | 写过的代码 | 写过的博客 |
| 重点 | 结构化展示 | 代码原理深讲 | 长文 → 口语改编 |
| 受众 | 内 + 外 | 同组开发 | 内 / 外都行 |
| 独有优势 | SCQA 开场 | 原理讲透 | 有读者反馈可备 Q&A |

**时间分配（30 / 45 分钟场次）**

| 段 | 内容 | 30min | 45min |
|---|---|---|---|
| 开场 | SCQA 点题 | 3 min | 4 min |
| 问题与排查 | 痛点 + 怎么查出来的 | 7 min | 10 min |
| 方案与数据 | 关键做法 + 前后对比 | 12 min | 18 min |
| 总结与边界 | 带走什么 + 适用边界 | 5 min | 8 min |
| Q&A | 提问 | 3 min | 5 min |

（合计 30 / 45，可按场地上下浮动 2-3 min）

### 01.从博客提炼主线

#### 1.0 目标与适用

把一篇已写好的长博客压成「一句话价值 + 删减清单 + 一条主线 + 受众」。这是 02-07 所有章节的输入。

- 为什么先做这步：博客是「写给人读」（可回看、可跳读），分享是「讲给人听」（线性、易走神）。第一步先定**讲什么**，后面才谈**怎么讲**。
- 适用场景：你已经有成稿博客，要改编成分享。若还没博客，回到 03 模版（从项目直接分享）。

#### 1.1 输出模板（直接填）

- **一句话价值**：<博客解决什么 / 听众带走什么>。一句话说出这篇博客解决了什么问题，以及听众听完能带走什么方法或认知；先说「听众带走什么」，别说「我讲了什么」。
- **删什么（不适合讲的）**：删 <…>　留 <…>。用「删 / 留」对照列出博客里不适合口头讲的部分（过长前置、边角案例、内部配置）；判断标准：不讲这条听众还能跟住主线就删，否则留。
- **定主线（只一条）**：<痛点 → 排查 → 解法 → 数据>。只留一条故事线，博客可多线，分享听不过来两条；支线一律砍或留 Q&A。
- **受众与前置**：<谁听 / 需要什么基础 / 不必懂什么>。写清听众是谁、要什么基础、哪些可以不讲，这决定后面砍细节的尺度。

#### 1.2 写法提示（逐条展开）

- **一句话价值**：先说「听众带走什么」，别说「我讲了什么」。合格标准——别人听完能复述「这篇我学到……」，否则重写。
- **删减清单**：用「删 / 留」对照，别只列删的。判断标准：不讲这条，听众还能跟住主线吗？能就删，不能就留。
- **定主线**：只能一条。博客可以多线，分享听不过来两条线；支线一律砍或留 Q&A。
- **受众与前置**：写清「谁听、要什么基础、不必懂什么」，这决定后面砍细节的尺度（组内可深，跨部门要浅）。

#### 1.3 补充：主线图（一眼看清结构）

```
博客: 背景 → 排查 → 三方案 → 数据 → 总结
分享: 问题(痛点) → 方法(为什么这样解) → 结果(数据 + 可复用)
```

### 02.结构改编

#### 2.0 目标与适用

把博客章节重排成分享的「问题 → 方法 → 结果」，并写好 SCQA 开场。这是把「读」转「听」的关键一步。

#### 2.1 输出模板（直接填）

- **章节 → 分享映射**：把博客每章对应到分享段（1 开场 / 2 问题 / 3 方案 / 4 总结），并写清每章在分享里「怎么处理」（浓缩一句话 / 保留方法论 / 只讲落地 1 个 / 用对比图 / 提炼经验）。每个博客章节都要落到某一分享段，别留「孤儿内容」。
- **SCQA（开场用）**：S <共识背景>　C <冲突/问题>　Q <所以今天讲什么>　A <今天安排>。第一句点问题，别从「背景」长铺垫。
- **砍细节留方法**：删 <…>　留 <…>。博客的「是什么」略，分享要「为什么这么做、方法能不能复用」。

#### 2.2 写法提示（逐条展开）

- **重排顺序**：博客顺序 ≠ 分享顺序。统一重排成「问题 → 方法 → 结果」，听众注意力才顺着走。
- **SCQA**：第一句点问题（S/C），别从「背景」长铺垫；Q 点明今天讲什么；A 点明安排。四句撑起开场。
- **章节映射**：每个博客章节都要落到某一分享段，别留「孤儿内容」（写了却没地方讲）。

#### 2.3 补充：时间轴映射（控时直接套）

```
[0-3] 开场 SCQA  [3-10] 问题  [10-22] 方案  [22-26] 数据  [26-30] 总结
（45min 档按 4/10/18/6/7 等比放大，见第 04 章）
```

#### 2.4 补充：钩子设计（让开场抓人）

- 数字钩：`「首页滚动只有 48fps，用户说卡」` 比 `「今天讲性能优化」` 抓人。
- 反差钩：`「我们试了三种方案，最贵的那个反而最差」`。
- 钩子放 SCQA 的 C（冲突）位，冲突越强，听众越想听解法。

### 03.内容打磨（讲给人听）

#### 3.0 目标与适用

把「读得懂」变成「听得进」——加演示、讲为什么、一页一观点、数据对比。博客读者能回看代码，听众需要**体感**。

#### 3.1 输出模板（直接填）

- **演示清单**：<哪几处加图/代码/demo，贴 PPT 第几页>。选关键 1-2 处给听众体感，代码贴链接不念。
- **讲为什么（每点写取舍）**：<选 A 放弃 B，因为…>。博客已写实现，分享讲「当时为什么选它、放弃了什么」。
- **一页一观点**：<观点1> <观点2> <观点3>（每页只 1 个）。并列多点拆多页或合并成「一句结论 + 展开」。
- **数据对比**：<前> → <后>（前后对比图）。用前后箭头比一段数字有冲击力。
- **金句/类比**：<一句能让听众记住的话>。难懂概念配生活类比（见 3.3）。

#### 3.2 写法提示（逐条展开）

- **演示**：代码贴链接不念；选关键 1-2 段放 PPT 当演示，给听众「看到」的体感。
- **讲为什么**：「为什么」比「是什么」重要——博客已写实现，分享讲「当时为什么选它、放弃了什么」。
- **一页一观点**：博客一节能写五点，分享一页只讲一个；并列多点拆多页或合并成「一句结论 + 展开」。
- **数据对比**：用前后箭头（48 → 58fps），比一段数字有冲击力。

#### 3.3 补充：类比库（难懂概念配生活类比）

- 封装 ≈ 自动售货机（按按钮拿货，看不到内部机械）
- 接口 ≈ 插座标准（电器不关心电厂是谁）
- 依赖注入 ≈ 借充电宝（用前塞进来，不自己造）
- 多态 ≈ 同一个插头，不同电器插上干不同的事

#### 3.4 补充：PPT 页规划（一页一观点示例）

```
30min 版（约 8 页）:
P1 问题(48fps 卡)  P2 排查方法  P3 关键解法(异步布局)
P4 数据(48→58)  P5 对比方案  P6 踩坑  P7 适用边界  P8 一句话带走

45min 版（约 12 页）:
在 30min 版基础上，P3/P4 各拆 1-2 页深入，并加多案例 / 互动页
```

### 04.控时与节奏（30 / 45 两档）

#### 4.0 目标与适用

同一篇博客，按 30 / 45 分钟剪不同深度。30min 讲透主线，45min 加对比方案、踩坑与适用边界。场次不同，深度不同，但主线不变。

#### 4.1 输出模板（直接填）

- **30min 版**：讲 <问题 + 排查方法 + 关键解法 + 数据 + 总结>　砍 <对比方案细节 / 多案例 / 扩展边界>。
- **45min 版**：讲 <上面全有 + 对比方案 + 踩坑 + 适用边界 + 更多演示/互动>　砍 <基本不砍>。
- **逐分钟（30min 档）**：开场 3 / 问题 7 / 方案 12 / 数据 4 / 总结 4。严格按脚本，前松后紧必然超时。
- **逐分钟（45min 档）**：开场 4 / 问题 10 / 方案 18 / 数据 6 / 总结 7。
- **超时应急**：真超时先砍 <…> 保 <…>。

#### 4.2 写法提示（逐条展开）

- **30min**：讲透主线（问题 → 排查 → 解法 → 数据），对比方案、踩坑、边界可略或留 Q&A。
- **45min**：加「还试过什么、为什么放弃」（对比方案）、踩坑实录、适用边界；让听众既学方法又避坑。
- **逐分钟**：严格按脚本，前松后紧必然超时（数据被草草带过）。

#### 4.3 补充：彩排节奏（三遍法）

- 第一次通读，记每段实际耗时（通常比想的长）。
- 第二次对着逐分钟脚本卡点，超处即砍。
- 第三次只过开场 + 过渡 + 总结（最易忘的三处）。

#### 4.4 补充：超时应急脚本

```
真超时 → 先砍「扩展/对比方案」→ 再砍「踩坑细节」→ 保「问题+关键解法+数据」
最后一句永远留「一句话带走」，别被掐断在中间
```

### 05.现场表达

#### 5.0 目标与适用

写好开场三句、段间过渡、Q&A 预案、互动题。前期内容再好，现场表达拉垮也白讲。

#### 5.1 输出模板（直接填）

- **开场三句**：<问题> <价值> <安排>。第一句点问题、第二句点价值、第三句点安排，不寒暄「大家好我是谁」。
- **过渡句（段间）**：1→2 <…>　2→3 <…>　3→4 <…>。用因果过渡（见 5.4），别喊「接下来讲第 X 部分」。
- **Q&A 预案**：Q1 <…> A <…> / Q2 <…> A <…> / Q3 <…> A <…>。用博客评论当题库，备 ≥3 个。
- **互动题**：<现场抛给听众的一个问题>。

#### 5.2 写法提示（逐条展开）

- **开场三句**：不寒暄「大家好我是谁」；第一句点问题、第二句点价值、第三句点安排。
- **过渡句**：用「找到原因了，那怎么解」这种因果过渡，而非「接下来讲第三部分」无效过渡。
- **Q&A**：用博客评论当题库（独有优势），备 ≥3 个高频问题。

#### 5.3 补充：冷场 / 救场话术

- 没人答互动题：自问自答「我猜有人会想…，其实…」。
- 被问住：记下来「这个好问题，我会后查实回复」，别当场编。
- 时间剩太多：展开「适用边界」或「还试过什么」。

#### 5.4 补充：过渡句库（可复用）

```
问题→方法: 「卡在哪清楚了，那怎么解？」
方法→数据: 「改完一测，效果在这」
数据→总结: 「所以这套能复用到哪」
```

### 06.演练与自检

#### 6.0 目标与适用

上台前打勾清单 + 反模式对照 + 试讲打分。这一步决定你是「讲完了」还是「讲好了」。

#### 6.1 输出模板（直接填）

- **五要点**：1 提炼　2 砍　3 演示　4 为什么　5 Q&A。
- **清单（12 条打勾）**：见 6.3，逐条打勾，不达标不开讲。
- **反模式（对照）**：见 6.4，翻车清单逐条自查。
- **试讲打分**：流畅 □　超时 □　卡壳 □（写在哪段）。录像回看专看卡壳段。

#### 6.2 写法提示（逐条展开）

- **清单**：逐条打勾，不达标不开讲；别凭感觉「应该 ok」。
- **反模式**：是「翻车清单」，逐条自查自己有没有中。
- **试讲**：录像回看，专看卡壳段；卡壳通常因为那页没写逐字稿。

#### 6.3 补充：12 条清单（直接打勾）

上台前逐条打勾，不达标不开讲：

- [ ] **提炼与改编（4 条）**
  - [ ] 1. 一句话价值说清了（解决什么 / 带走什么）
  - [ ] 2. 博客里不适合讲的部分已删（前置 / 边角 / 配置）
  - [ ] 3. 主线只有一条（痛点 → 排查 → 解法 → 数据）
  - [ ] 4. 用了 SCQA 开场，没从背景长铺垫
- [ ] **打磨与表达（4 条）**
  - [ ] 5. 关键处加了演示 / 对比图，不是只读代码
  - [ ] 6. 讲了「为什么选这个方案」，不只「怎么做的」
  - [ ] 7. 数据用前后对比呈现
  - [ ] 8. 一页一观点，没把博客五点塞一页
- [ ] **控时与现场（4 条）**
  - [ ] 9. 按场次档位剪好了（30/45）
  - [ ] 10. 过渡句自然，不喊「接下来讲第 X 部分」
  - [ ] 11. 备了 ≥3 个 Q&A（来自博客反馈）
  - [ ] 12. 留了 Q&A 时间，没讲到最后一秒

#### 6.4 补充：反模式表（翻车对照）

| # | 反模式 | 现象 | 危害 | 对法 |
|:--:|---|---|---|---|
| 1 | 念博客 | 把文章逐段读一遍 | 听众不如自己看 | 03 讲为什么 |
| 2 | 不剪辑 | 20 分钟塞完整长文 | 重点淹没 | 01 删减 |
| 3 | 无演示 | 纯讲实现 | 听众没体感 | 03 加演示 |
| 4 | 无 Q&A | 不备问题 | 现场冷场 | 05 备题库 |
| 5 | 超时 | 前松后紧 | 数据草草带过 | 04 控时 |
| 6 | 从背景铺垫 | "先讲一下大背景" | 10 秒走神 | 02 SCQA |

### 07.分享正文终稿（照这个讲）

> 上面 01-06 是「准备」，这一章才是你上台要讲的**分享稿本身**。复制下面结构，把 `<>` 填成你的内容，口语化，直接照讲。每场差异在 3.x 子主题的数量（控时见第 04 章）。填充示例见 [06.面向对象设计技术分享](./06.面向对象设计技术分享.md)。

```markdown
# [标题] → 技术分享

> 一句话价值: <解决什么 / 听众带走什么>
> 档位: 30 / 45 分钟   受众: <>

## 1. 开场（SCQA）  [3-4min · 口语三句，不寒暄]
S: <共识背景>   C: <冲突/问题>   Q: <所以讲什么>   A: <今天安排>
讲法: 第一句点问题，第二句点价值，第三句点安排，不铺垫定义

## 2. 背景与问题  [6-8min · 先现象后根因]
- 痛点: 1-3 个真实事故/场景（带数字更有冲击力）
- 为什么重要: 不解决会怎样
- 根因: 一句话本质
- 常见误区: 人们通常怎么理解错（引出下面的正解）

## 3. 核心内容  [主体 10-15min · 每个子主题讲透]
### 3.1 <子主题1：一个观点>
- 概念: 一句话说清是什么
- 为什么: 解决什么 / 放弃了什么（对比，别只讲是什么）
- 案例/代码: 1 段核心代码或场景（演示用）
- 数据: 前后对比（有图更好）
### 3.2 <子主题2> ...
### 3.3 <子主题3> ...
讲法: 一页一观点；子主题数量按控时档位裁剪

## 4. 演示与实战  [3-5min · 可选但强烈建议]
- 现场 demo / 前后对比图 / 互动小测验
- 把最关键的一处给听众体感

## 5. 总结与决策  [3-4min]
- 决策卡 / 清单 / 一句话带走
- 适用边界: 什么时候不成立
- 反模式: 这条知识最容易被怎么用错

## 6. Q&A  [留 10% 时间]
- 备问: Q1 <> / Q2 <> / Q3 <> / Q4 <>

## 参考
- 原博客 / 文档链接
```
