## 05.技术分享的模版

> **文档定位**：你已写好一篇技术博客，要把它改编成一场可讲的分享。博客是"写给人读"，分享是"讲给人听"——读者能回看、能跳过，听众不能。本文讲怎么把一篇写好的文章二次加工成一场分享。
> **篇幅**：10 / 20 / 30 分钟三档。
> **怎么用**：01-06 是「准备」，第 07 章才是你上台要照讲的**分享正文终稿**。复制第 07 章结构，把 `<>` 填成你的内容，口语化，直接讲。

### 使用说明

**适用范围**

1. 已有技术博客，要在组内、周会或外部做分享
2. 把一篇长文压缩成短分享
3. 外部技术大会 talk 的初稿

**和 03 / 04 的区别**

| 维度 | 03 技术业务分享 | 04 业务串讲 | 05 技术分享（本文） |
|---|---|---|---|
| 来源 | 做过的事 | 写过的代码 | 写过的博客 |
| 重点 | 结构化展示 | 代码原理深讲 | 长文 → 口语改编 |
| 受众 | 内 + 外 | 同组开发 | 内 / 外都行 |
| 独有优势 | SCQA 开场 | 原理讲透 | 有读者反馈可备 Q&A |

**时间分配（20 分钟场次）**

| 段 | 内容 | 时长 |
|---|---|---|
| 开场 | SCQA 点题 | 2 min |
| 问题与排查 | 痛点 + 怎么查出来的 | 6 min |
| 方案与数据 | 关键做法 + 前后对比 | 8 min |
| 总结与 Q&A | 带走什么 + 提问 | 4 min |

### 01.从博客提炼主线

> 目标：把一篇长博客压成「一句话价值 + 删减清单 + 一条主线 + 受众」。这是后面所有章节的输入。

**① 输出模板（直接填）**

```markdown
## 1. 提炼输出
- 一句话价值: <博客解决什么 / 听众带走什么>
- 删什么(不适合讲的): 删 <>  留 <>
- 定主线(只一条): <痛点 → 排查 → 解法 → 数据>
- 受众与前置: <谁听 / 需要什么基础 / 不必懂什么>
```

**② 写法提示**
- 价值句先说「听众带走什么」，别说「我讲了什么」
- 删减用「删 / 留」对照，别只列删的
- 主线只能一条，多线就砍（听众听不过来两条线）

**③ 补充：主线图（让结构一眼看清）**

```
博客: 背景 → 排查 → 三方案 → 数据 → 总结
分享: 问题(痛点) → 方法(为什么这样解) → 结果(数据 + 可复用)
```

### 02.结构改编

> 目标：把博客章节重排成分享的「问题 → 方法 → 结果」，并写好 SCQA 开场。

**① 输出模板（直接填）**

```markdown
## 2. 改编输出
- 章节 → 分享映射:
  | 博客章节 | 分享段 | 处理 |
  |---|---|---|
  | <> | 1 开场 | <> |
  | <> | 2 问题 | <> |
  | <> | 3 方案 | <> |
  | <> | 4 总结 | <> |
- SCQA(开场用): S<> C<> Q<> A<>
- 砍细节留方法: 删 <> 留 <>
```

**② 写法提示**
- 博客顺序 ≠ 分享顺序，重排成「问题 → 方法 → 结果」
- SCQA 第一句就点问题，别从「背景」长铺垫
- 每个博客章节都要落到某一分享段，别留孤儿内容

**③ 补充：时间轴映射（控时直接套）**

```
[0-2] 开场 SCQA  [2-8] 问题  [8-16] 方案  [16-19] 数据  [19-20] 总结
```

### 03.内容打磨（讲给人听）

> 目标：把「读得懂」变成「听得进」——加演示、讲为什么、一页一观点、数据对比。

**① 输出模板（直接填）**

```markdown
## 3. 打磨输出
- 演示清单: <哪几处加图/代码/demo，贴 PPT 第几页>
- 讲为什么(每点写取舍): <选 A 放弃 B，因为…>
- 一页一观点: <观点1> <观点2> <观点3>(每页只 1 个)
- 数据对比: <前> → <后>(前后对比图)
- 金句/类比: <一句能让听众记住的话>
```

**② 写法提示**
- 代码贴链接不念；关键 1-2 段放 PPT 当演示
- 「为什么」比「是什么」重要，博客已写实现
- 数据用前后箭头，比一段数字有冲击力

**③ 补充：类比库（难懂概念配生活类比）**
- 封装 ≈ 自动售货机（按按钮拿货，看不到内部机械）
- 接口 ≈ 插座标准（电器不关心电厂是谁）
- 依赖注入 ≈ 借充电宝（用前塞进来，不自己造）

### 04.控时与节奏（三档）

> 目标：同一篇按 10/20/30 剪不同深度，并排逐分钟脚本防超时。

**① 输出模板（直接填）**

```markdown
## 4. 控时脚本
- 10min: 讲 <> 砍 <>
- 20min: 讲 <> 砍 <>
- 30min: 讲 <> 砍 <>
- 逐分钟(20min档): 开场2 / 问题6 / 方案8 / 总结4
- 超时应急: 真超时先砍 <> 保 <>
```

**② 写法提示**
- 10min 只留「问题 + 最关键一招 + 数据」，其余留 Q&A
- 30min 才加对比方案 / 踩坑 / 适用边界
- 严格按逐分钟，前松后紧必然超时

**③ 补充：彩排节奏**
- 第一次通读，记每段实际耗时
- 第二次对着逐分钟脚本卡点
- 第三次只过开场 + 过渡 + 总结（最易忘的三处）

### 05.现场表达

> 目标：写好开场三句、段间过渡、Q&A 预案、互动题，现场不卡壳。

**① 输出模板（直接填）**

```markdown
## 5. 表达脚本
- 开场三句: <问题> <价值> <安排>
- 过渡句(段间): 1→2 <>  2→3 <>  3→4 <>
- Q&A预案: Q1<> A<> / Q2<> A<> / Q3<> A<>
- 互动题: <现场抛给听众的一个问题>
```

**② 写法提示**
- 开场不寒暄「大家好我是谁」，三句点题
- 过渡用「找到原因了，那怎么解」而非「接下来讲第三点」
- Q&A 用博客评论当题库，备 ≥3 个

**③ 补充：冷场 / 救场话术**
- 没人答互动题：自问自答「我猜有人会想…，其实…」
- 被问住：记下来「这个好问题，我会后查实回复」，别当场编
- 时间剩太多：展开「适用边界」或「还试过什么」

### 06.演练与自检

> 目标：上台前打勾清单 + 反模式对照 + 试讲打分。

**① 输出模板（直接填）**

```markdown
## 6. 自检输出
- 五要点: 1提炼 2砍 3演示 4为什么 5Q&A
- 清单(12条打勾): □1…□12…
- 反模式(对照): 见下表
- 试讲打分: 流畅□ 超时□ 卡壳□(写在哪段)
```

**② 写法提示**
- 清单逐条打勾，不达标不开讲
- 反模式是「翻车清单」，逐条自查
- 试讲录像回看，专看卡壳段

**③ 补充：12 条清单（直接打勾）**

```
提炼与改编（4 条）
□ 1. 一句话价值说清了(解决什么/带走什么)
□ 2. 博客里不适合讲的部分已删(前置/边角/配置)
□ 3. 主线只有一条(痛点→排查→解法→数据)
□ 4. 用了 SCQA 开场, 没从背景长铺垫

打磨与表达（4 条）
□ 5. 关键处加了演示/对比图, 不是只读代码
□ 6. 讲了"为什么选这个方案", 不只"怎么做的"
□ 7. 数据用前后对比呈现
□ 8. 一页一观点, 没把博客五点塞一页

控时与现场（4 条）
□ 9. 按场次档位剪好了(10/20/30)
□ 10. 过渡句自然, 不喊"接下来讲第X部分"
□ 11. 备了 ≥3 个 Q&A(来自博客反馈)
□ 12. 留了 Q&A 时间, 没讲到最后一秒
```

**④ 补充：反模式表（翻车对照）**

| # | 反模式 | 现象 | 危害 | 对法 |
|:--:|---|---|---|---|
| 1 | 念博客 | 把文章逐段读一遍 | 听众不如自己看 | 只讲为什么 |
| 2 | 不剪辑 | 20 分钟塞完整长文 | 重点淹没 | 1.2 删减 |
| 3 | 无演示 | 纯讲实现 | 听众没体感 | 3.1 加演示 |
| 4 | 无 Q&A | 不备问题 | 现场冷场 | 5.3 备题库 |
| 5 | 超时 | 前松后紧 | 数据草草带过 | 4.x 控时 |
| 6 | 从背景铺垫 | "先讲一下大背景" | 10 秒走神 | 2.2 SCQA |

### 07.分享正文终稿（照这个讲）

> 上面 01-06 是「准备」，这一章才是你上台要讲的**分享稿本身**。复制下面结构，把 `<>` 填成你的内容，口语化，直接照讲。每场差异在 3.x 子主题的数量（控时见第 04 章）。填充示例见 [06.面向对象设计技术分享](./06.面向对象设计技术分享.md)。

```markdown
# [标题] → 技术分享

> 一句话价值: <解决什么 / 听众带走什么>
> 档位: 10 / 20 / 30 分钟   受众: <>

## 1. 开场（SCQA）  [2-3min · 口语三句，不寒暄]
S: <共识背景>   C: <冲突/问题>   Q: <所以讲什么>   A: <今天安排>
讲法: 第一句点问题，第二句点价值，第三句点安排，不铺垫定义

## 2. 背景与问题  [6-8min · 先现象后根因]
- 痛点: 1-3 个真实事故/场景（带数字更有冲击力）
- 为什么重要: 不解决会怎样
- 根因: 一句话本质
- 常见误区: 人们通常怎么理解错（引出下面的正解）

## 3. 核心内容  [主体 10-15min · 每个子主题讲透]
### 3.1 <子主题1：一个观点>
- 概念: 一句话说清是什么
- 为什么: 解决什么 / 放弃了什么（对比，别只讲是什么）
- 案例/代码: 1 段核心代码或场景（演示用）
- 数据: 前后对比（有图更好）
### 3.2 <子主题2> ...
### 3.3 <子主题3> ...
讲法: 一页一观点；子主题数量按控时档位裁剪

## 4. 演示与实战  [3-5min · 可选但强烈建议]
- 现场 demo / 前后对比图 / 互动小测验
- 把最关键的一处给听众体感

## 5. 总结与决策  [3-4min]
- 决策卡 / 清单 / 一句话带走
- 适用边界: 什么时候不成立
- 反模式: 这条知识最容易被怎么用错

## 6. Q&A  [留 10% 时间]
- 备问: Q1 <> / Q2 <> / Q3 <> / Q4 <>

## 参考
- 原博客 / 文档链接
```
