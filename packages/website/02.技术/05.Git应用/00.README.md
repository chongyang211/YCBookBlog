## 一、为什么再写一本 Git 书

打开任何一家书店的技术区，或者搜索引擎里输入「Git 教程」，扑面而来的大多是同一副面孔——

> **命令 A + 参数 B + 一行说明 + 下一条命令**。

于是读者陷入了一种奇怪的循环：**「学过、忘了、再学、再忘」**。每一次遇到冲突、误操作、`detached HEAD`，都要重新在搜索框里打字，重新读一遍陌生又熟悉的文档，重新在心里犹豫「这条命令到底会不会毁掉我的代码」。

问题从来不在读者。问题在于——**大多数 Git 教程只教「怎么做」，从不教「为什么」**。

* 为什么分支可以毫秒级创建，而不是像 SVN 那样几分钟？
* 为什么 `git reset --hard` 之后，代码还能通过 `reflog` 找回来？
* 为什么两个人改同一个文件的不同行，Git 能自动合并，改同一行就冲突？
* 为什么 Linus 用两周就能写出 Git，而 SVN 团队用了十年？

**这本书就是为了回答这些「为什么」而写。** 只有理解了「为什么」，命令才能真正变成你脑袋里的心智地图，而不是键盘上的机械记忆。

## 二、这不是一本命令手册

本书恪守三条不成文的规矩，请读者在翻开每一章之前记住：

**第一，故事优先，命令其次。** 每一章都从一个真实的开发场景切入——凌晨三点崩溃的项目、周一早上 47 条未读消息的 Slack、误删四天工作成果的手滑瞬间。Git 的每一条命令，都是为了解决某一类具体的痛而生的。抽掉「痛」，命令就成了无根的浮木。

**第二，心智模型优先，操作步骤其次。** 我们会花大量篇幅讲清楚 blob / tree / commit 三种对象、SHA-1 哈希、DAG 有向无环图、reflog 的循环队列、pack 文件的压缩机制——这些看似「底层的」东西，恰恰是让你「上层敢用」的根本原因。**看得越透，用得越稳。**

**第三，实战优先，理论其次。** 每一章都配套完整的、可复现的 Shell 脚本。你可以打开终端，一行一行敲下去，亲眼看到 Git 如何工作。**读一百遍不如敲一遍。**

## 四、每章的通用体例

为了让阅读体验统一、检索方便，每一章都会遵循相同的结构：

1. **章前诗 / 引子**——一个真实场景引入，让你先「痛」再「治」。
2. **本章目录（TOC）**——快速跳转，长文不再迷路。
3. **正文小节**——每节结尾都有「一句话总结」或「速查表」。
4. **心智模型剖析**——本章涉及的底层原理、数据结构、历史脉络。
5. **综合实战**——可复现的完整 Shell 剧本，从零到一走完全流程。
6. **本章回顾**——一张速查表凝练全章要点。
7. **思考题**——3~5 道开放题，供你与自己对话。
8. **延伸阅读**——官方文档、经典博客、书籍章节的精准指路。
9. **命令速查附录**——本章所有命令的一站式收藏。
10. **下一章预告**——承上启下，让全书连成一条线。

## 五、如何使用本书

**给自学的读者**：请一定打开终端。本书的每一段代码都是可以运行的，请务必**边读边敲**——手感是理论无法替代的。

**给团队的读者**：可以把每一章作为读书会的一次分享——花 40 分钟共读，然后 20 分钟对着章末的「思考题」讨论。九次读书会后，团队的 Git 水位会有质的跃迁。

**给培训师**：本书的每一章都可以独立成课。「综合实战」小节可以直接改成课堂 Live Coding 剧本。「思考题」适合作为课后作业。

**给写博客的读者**：欢迎引用、改编，但请注明出处。技术传承本身就是版本控制的一部分。

## 六、全书心法预告

请把下面这五句话打印出来，贴在电脑显示器上方——它们是全书十章浓缩后的骨髓：

> **1. Git 只有三个区域**：工作区、暂存区、版本库。一切命令都在这三者之间搬运数据。
>
> **2. 分支只是一个 40 字节的指针**。创建分支毫秒级——所以大胆开、频繁合、及时删。
>
> **3. 永远先 `fetch` 再决定 `merge` 还是 `rebase`**。盲目 `git pull` 是绝大多数协作冲突的根源。
>
> **4. 只要 commit 过，就能用 `reflog` 找回来**。Git 是后悔药最多的工具——**30 天内你做的任何操作都有记录**。
>
> **5. 团队协作靠纪律，不靠记忆**。保护分支 + PR 审查 + Conventional Commits + CI，四件套缺一不可。

这五句心法，在正文中会反复以不同视角出现，帮助你从「看到」到「悟到」，最终到「做到」。

## 七、致读者

Git 不是一门语言，也不是一个框架。它更像是一门**手艺**——需要长期地、耐心地打磨，才能内化为你身体的一部分。

我用了整整一年的时间，把自己十年来在 Git 上踩过的每一个坑、听过的每一个提问、解答过的每一个报错，都写进了这本书。它不是完美的，但它是**真诚的**。

如果你能在读完之后，把那句「Git 好难」，改成「Git 挺有意思」——那这本书就没有白写。

现在，请深吸一口气，翻开下一章——**第 01 章 · 心智地图之全景**。
