# 1.数据结构基础

### 1.1 线性结构

- **数组与链表的特性对比**：数组的随机访问O(1)与链表的插入删除O(1)对比，单链表翻转、环形链表判断（快慢指针）、合并两个有序链表必问。
- **用栈实现队列的经典方法**：用两个栈实现队列、用两个队列实现栈，单调栈经典题（下一个更大元素、柱状图最大矩形），单调队列（滑动窗口最大值）。深度精讲见 6.9。
- **哈希表的冲突解决与负载因子**：必问，冲突解决（开放寻址、链地址法、再哈希），负载因子，一致性哈希原理（LRU/LFU设计见第4章设计题）。深度精讲见 6.3。
- **布隆过滤器的原理与误判率**：Bloom Filter的原理与用途（判断元素可能存在/一定不存在），误判率如何计算，为什么不能删除元素，计数布隆过滤器如何支持删除。
- **跳表的结构与Redis的应用**：跳表的结构（多层索引链表）与查询复杂度O(logn)，插入删除如何维护索引层，为什么Redis有序集合用跳表而不用红黑树（实现简单/范围查询/内存可调）。深度精讲见 6.1。
- **循环队列与双端队列的实现**：环形队列如何区分队空和队满（牺牲一个空间/计数器/标记位），deque的底层实现（分段连续数组），双端队列与栈/队列的关系。
- **前缀和与差分的两种技巧**：区域和检索（一维/二维前缀和）、和为K的子数组（前缀和+哈希）、航班预订统计（差分）。

### 1.2 树结构

- **二叉树的遍历与经典题**：必问，三种遍历（前中后序）的递归与迭代写法，层序遍历，二叉树的最近公共祖先，二叉树的直径。
- **BST与红黑树及B+树对比**：BST的插入删除查找，AVL与红黑树的差异（平衡条件），红黑树的应用（HashMap/TreeMap/epoll），B树与B+树的区别及在数据库中的应用。深度精讲见 6.2。
- **堆的建堆过程与TopK问题**：大根堆小根堆的建堆过程，堆排序O(nlogn)，Top K问题的两种解法（堆 vs 快速选择）。深度精讲见 6.4。
- **字典树Trie的实现与应用**：实现Trie、单词搜索II、添加与搜索单词、数组中两个数的最大异或值。
- **Trie的三种空间优化方案**：普通Trie的空间开销问题，三叉搜索树（TST）的原理，双数组Trie（DoubleArray Trie）如何用两个数组模拟。

### 1.3 图结构

- **图的遍历与经典算法汇总**：DFS与BFS，拓扑排序，最短路径（Dijkstra、Floyd、Bellman-Ford），最小生成树（Prim、Kruskal），并查集。
- **搜索进阶的A星与双向BFS**：A*算法的原理与启发函数的选取原则（可采纳性），与Dijkstra的区别（有向目标的贪心），双向BFS如何优化搜索空间，Dijkstra为什么不能处理负权边。
- **并查集的优化与复杂度**：路径压缩与按秩合并的实现，时间复杂度为什么近似O(1)（阿克曼反函数），并查集在Kruskal最小生成树中的判环应用。深度精讲见 6.6。

# 6.深度精讲（数据结构与算法设计口述版）

> 说明：本章是核心题的口述版深度精讲，讲到复杂度推导与工业级取舍层面。每题结构：一句话定调 → 分层展开 → 拉开差距的深水区 → 收尾，面试时按此节奏口述。

### 6.1 跳表的结构与Redis的应用

答：一句话定调，**跳表是「用空间换层级的多级链表」，单点查询 O(logn) 靠的是「每次期望跳过一半」，而 Redis 选它不选红黑树是为了范围查询和实现简单**。

**结构先立住**：底层是完整有序链表，上层是「抽稀的索引层」，**每个节点以概率 p（通常 1/2 或 1/4）晋升到上一层**（插入时抛硬币决定高度）。查询从最高层出发：**在当前层向右走到「下一个比目标大」之前，下一层继续**，层层降维逼近目标。

**O(logn) 的直觉推导**（深水区一，比背结论有说服力）：以 p=1/2 为例，**第 k 层的节点数期望是 n/2^k**，最高层期望只有 O(1) 个节点；**查询在每层的「横向步数」期望是 1/p（即 2 步）**——因为目标在当前层的两个相邻索引节点之间时下降，而「跨越」的概率结构决定期望步数是常数。**总步数 = 层数 O(logn) × 每层期望 2 步 = O(logn)**。这是「概率平衡」：**不需要像 AVL 那样刻意维持结构，随机就自然平衡**。

**为什么 Redis 有序集合选跳表不选红黑树**（必答的工程理由）：

1. **范围查询天然友好**：zrange 要的是「定位起点后顺着底层链表走」，跳表找到起点直接沿链表遍历 O(range)；红黑树要做中序遍历，**要回溯父节点，缓存不友好且实现繁琐**；
2. **实现简单到离谱**：插入删除就是「改几个 next 指针加一次抛硬币」，红黑树的旋转与变色的边界情况能写出一本书；
3. **内存可调**：p 取 1/4 时**索引开销从 n 降到 n/3**，用速度换内存有旋钮可拧（Redis 用 1/4）；
4. **zskiplist 的工业细节**：Redis 实现里还有 **backward 指针（支持反向遍历 ZREVRANGE）和 span 跨度（O(1) 拿排名 ZRANK）**，这些是链表结构的独有福利，树结构加这些要伤筋动骨。

**深水区二：跳表的最坏情况**——概率保证的是期望，**极端情况下所有节点都抛出最高层（退化成 n 层楼梯）或全在底层（退化成单链表）**，查询 O(n)。工程上的兜底是**限制最大层数**（Redis 定死 32 层），最坏退化为 O(n) 但概率低到宇宙热寂级别（2^-32）。

收尾：跳表和红黑树是「**随机化对确定性**」的两种哲学，内存场景（Redis 单机）选实现简单可调的跳表，内核场景（epoll）选确定性的红黑树，**没有更好的，只有更合适的**。

> 面试官追问点：跳表的并发性能为什么比红黑树好？应答思路：跳表的插入只影响「局部几个前驱指针」，可用细粒度锁或 CAS 按层加锁；红黑树的平衡操作可能触发从插入点到根的连锁旋转，锁范围天然更大——ConcurrentSkipListMap 选跳表就是这个理由。

### 6.2 红黑树、AVL与B+树的取舍逻辑

答：一句话定调，**三种树回答三个不同的问题：AVL 答「查询最狠」，红黑树答「增删查的均衡」，B+树答「磁盘友好的外存组织」**。

**AVL vs 红黑树（本质是平衡严格度的取舍）**：AVL 的平衡条件是**任意节点左右子树高度差 ≤1**，查询确实更快（高度更矮，log(n) 的常数更小）；**代价是插入删除的维护成本**：AVL 一次插入可能引起**从插入点到根的连锁旋转（O(logn) 次旋转）**；红黑树放宽为「**黑高相等 + 无连续红节点**」的弱平衡——**最长路径最多是最短的 2 倍**（黑节点数相等，红的不连续所以最多翻倍），插入删除**至多 2 次旋转就能恢复**（变色向上冒泡 + 一次双旋封顶）。**读写比的分界**：读极多写极少选 AVL（查询快那一点点），增删频繁选红黑树（维护便宜一大截），**工业界的默认答案是红黑树**（Linux 的 CFS 调度器用增删如流的 rbtree，epoll 的就绪事件管理同理）。

**红黑树为什么「够用」的数学直觉**（深水区一）：高度是 logn 到 2logn 之间，**查询最多多走一倍路径**（每层一次指针解引用，纳秒级），而 AVL 省下的那点查询时间**远盖不住连锁旋转的写放大**。这是「常数的 2 倍」换「维护的 O(logn) 变 O(1)」的稳赚买卖。

**B/B+ 树的本质是「为磁盘重新发明树」**（深水区二）：内存的随机访问是纳秒级均匀的，**磁盘/SSD 的随机读是以块为单位的慢操作**，树结构要优化的目标从「比较次数」变成「**IO 次数**」。两个针对性改造：

1. **多叉降高**：节点大小对齐一个磁盘页（16KB），**一页塞几百个键**，**扇出 500 时千万数据只要 3 层**（500^3 > 10^8），即千万级表查询只要 3 次 IO；
2. **B+ 树的三个设计**：**非叶子节点只存键不存数据**（同样一页能塞更多键、扇出更大）；**数据全在叶子层**（查询性能稳定，任何键都是同深度到达）；**叶子层串成有序链表**（范围查询顺叶子扫，这是 MySQL 范围扫描快的原因）。

**B 树 vs B+ 树的分野**：B 树非叶子也存数据，**单点查询可能在中途命中（少一次 IO）**，但扇出变小、范围查询要中序回溯；**数据库索引清一色 B+ 树**是「范围扫描是主流负载 + 性能可预测」的胜利。

收尾：三个结构的选型逻辑串起来就是「**访存介质的物理特性决定数据结构形态**」：内存均匀快 → 二叉树（比较次数最优）；磁盘按块慢 → 多叉树（IO 次数最优）；这题答到介质特性，就从背书到了理解。

> 面试官追问点：为什么 LSM 树（LevelDB/RocksDB）也挑战 B+ 树？应答思路：LSM 把随机写转成顺序写（WAL + memtable 刷盘），写吞吐碾压 B+ 树；代价是读要查多层 SSTable（布隆过滤器缓解）和后台 compaction 的写放大——**写多读少选 LSM，读多写少选 B+**，又是负载决定结构。

### 6.3 哈希表的冲突解决与一致性哈希

答：一句话定调，**拉链法和开放寻址是「冲突处理」的两条路线，选择标准是删除频率和缓存友好性；一致性哈希解决的是「分布式环境下的 rehash 风暴」**。

**拉链 vs 开放寻址的对照**：

1. **拉链法**：冲突串链表（Java HashMap 的方案），**删除简单（摘链）**、负载因子可超 1、适合增删频繁；代价是**链表节点的指针跳转缓存不友好**（现代 HashMap 用「链表转红黑树」兜底病态冲突）；
2. **开放寻址**：冲突就探测下一个槽（线性探测、二次探测、**双重哈希**），**所有数据连续在数组里，缓存命中率极高**（Go map 就是线性探测）；**删除是死穴——直接清空会断掉探测链**，必须留「墓碑（DELETED）标记」或周期性 rehash 重建（Go 的做法），**这也是开放寻址要求负载因子低（Go 阈值 6.5/8）的原因：探测序列不能太挤**；
3. **线性探测的聚集问题**：同义词连成一片，插入越探越远；**双重哈希用第二个哈希函数决定步长，把聚集打散**。

**rehash 的时机与渐进式**：负载因子超阈值（Java 0.75、Go 6.5）就扩容（翻倍），**所有键重新分布**；一次性 rehash 的大对象会卡顿（Redis 的字典用**渐进式 rehash**：新旧两表并存，每次增删改查顺手搬一部分，读完再切换）。

**深水区：一致性哈希的完整推导**（分布式必考）：

1. **朴素取模的问题**：`hash(key) % N`，**N 变化（扩容缩容）时几乎全部 key 重新映射**，缓存全部穿透到数据库（rehash 雪崩）；
2. **哈希环**：把哈希空间首尾相连成环（0 到 2^32-1），**节点和 key 都哈希到环上，key 顺时针找最近的节点**；节点增删只影响「**本节点到逆时针方向前驱之间**」的 key（约 1/N），其余全不动；
3. **虚拟节点**：节点少时环上分布不均（数据倾斜），**每个物理节点虚拟成 150-200 个 vnode 散布环上**，统计上均匀；副产品是**异构节点的权重调节**（性能好的机器多放 vnode）。

收尾：哈希表层答「单机散列」，一致性哈希答「集群散列」，**共同的灵魂是「均匀」和「稳定」——均匀为了性能，稳定为了变更代价最小**。

> 面试官追问点：哈希碰撞攻击怎么回事？应答思路：构造大量同哈希值的 key，拉链法退化成 O(n) 链表扫描（DoS 攻击，2011 年各大语言中招）；防御是给哈希函数加**随机种子**（每进程不同），攻击者无法离线构造碰撞集。

### 6.4 TopK问题的两种解法对比

答：一句话定调，**「全排序、堆、快速选择」是三档火力：全排序 O(nlogn) 最蠢但最稳，堆 O(nlogk) 管内存受限，快速选择 O(n) 均摊最快但最坏 O(n²)**。

**先破直觉**：TopK 不需要全排序——**只需要「前 K 个对」，和 K 之外的部分各自无序都行**，这半序性就是优化空间的来源。

**解法一：小顶堆求「最大的 K 个」**（注意是**小顶**堆，反直觉但必讲清楚）：维护 K 容量的小顶堆，**堆顶是「当前冠军组里最弱的」**；新元素比堆顶大就踢掉堆顶换进来，否则丢弃。**复杂度 O(n·logk)**：每个元素一次堆顶比较 O(1)，进堆的只有约 K + 期望 O(K·log(n/k)) 次、每次 O(logk)。

**堆解法的真正价值是「数据流场景」**（深水区一）：

1. **内存受限**：10 亿个数 4GB 内存放不下，**堆只要 O(k) 内存**，数据可以流式过一遍（磁盘/网络都行）；
2. **在线算法**：数据一条条来，**任何时刻查询都是「目前为止的 TopK」**，全排序和快选都做不到在线；
3. 工业对应：**每个分片节点本地堆求 TopK，汇总到中心再对 K 条做堆**（MapReduce 的经典模式）。

**解法二：快速选择（QuickSelect）**：快排的 partition 把数组分成「pivot 左边都小、右边都大」，**pivot 落到下标 n-k 就是答案，只递归一侧**；**期望复杂度 O(n)**（n + n/2 + n/4 + ... = 2n），**最坏 O(n²)**（每次 partition 都切在最边上）。**中位数的中位数（BFPRT）能保证最坏 O(n)**（精心选 pivot），但常数大到工程上没人用——**面试提到它就赢了，强调「理论保证换工程常数」的取舍**。

**深水区二：实践中的混合策略**——**数据量小先全排序**（内置 sort 是高度优化的快排变体，百万级也就几十毫秒）；**海量数据先哈希分桶再各桶 TopK**（分布式 + 削减单机数据量）；**近似 TopK 用 Count-Min Sketch / 堆衰减**（热度榜的时间衰减，老数据自动掉出）。

收尾：TopK 的答题心法是「**按约束选武器：内存紧 → 堆（O(k) 空间 + 在线）；要极限快 → 快速选择；数据小 → 别闹了直接 sort**」。

> 面试官追问点：求「第 K 大」和「前 K 个」复杂度一样吗？应答思路：一样（找到第 K 大的 pivot 后右边就是前 K）；但「前 K 个还要有序」要多花 O(klogk) 排 K 个元素，总复杂度不变但常数增加——题面差一个词，答案差一步。

### 6.5 LRU缓存的设计与实现

答：一句话定调，**LRU = 哈希表（O(1) 定位）+ 双向链表（O(1) 摘除与插入），核心不变式是「链表顺序 = 访问时间顺序，头是新客尾部是该淘汰的旧客」**。

**两个结构的分工**：哈希表存 key → 链表节点的映射（**O(1) 找到节点**）；双向链表维护访问序（**O(1) 把节点摘下来挪到头部**——双向链表的摘除不需要前驱查找，单向链表做不到）。**单独哪个都不够**：只有哈希没有序，只有链表查找 O(n)。

**get 和 put 的完整动作**（口述时按步骤走）：

1. **get(key)**：哈希查节点，**没有返回 -1；有则「摘下节点、头插」并返回值**（刚被访问，刷新热度）；
2. **put(key, value)**：key 已存在就更新值并刷新到头；**不存在则头插新节点，且如果超容量就「删尾」**——**删尾前要先从哈希表里删掉尾节点的 key**（双向链表拿得到 key 所以可行，这步顺序写反就内存泄漏/幽灵键）。

**深水区一：为什么 LinkedHashMap 能白嫖**：Java 的 LinkedHashMap 有个 accessOrder 模式（**get 也算访问，自动把节点移到尾部**），`new LinkedHashMap(capacity, loadFactor, true)` 加重写 removeEldestEntry 就是一个 LRU——**它的实现正是哈希表加双向链表的融合体**（Entry 同时挂在哈希桶和链表上），所以「手写 LRU」和「LinkedHashMap 原理」是同一道题。

**深水区二：工程级的三个升级点**：

1. **并发**：直接 ConcurrentHashMap + synchronized 链表操作是「全局锁」，高并发下热点 key 的头插全串行；**分片 LRU**（按 key 哈希到 N 个独立 LRU）降低锁粒度，代价是全局语义变「近似 LRU」；
2. **Redis 的近似 LRU**（必出彩点）：Redis **不维护全局链表**（双向链表对每个对象额外 3 个指针，内存敏感的 Redis 不干），而是**每个对象记 24bit 的 lru 时钟，淘汰时随机采样 5 个 key 淘最旧的**——**O(1) 的采样近似，换掉 O(1) 但高侵入的精确链表**，Redis 4 又加了 LFU 模式（计数器衰减）；
3. **伪 LRU（PLRU）**：CPU 缓存的树形近似位，每个节点一个 bit 表示「哪边最近没用过」，**只要 logn 个 bit 就近似 LRU**——硬件场景 bit 即成本，近似换空间到极致。

收尾：LRU 是「**组合两个 O(1) 结构解决一个复合问题**」的范本（定位 O(1) + 挪动 O(1)），面试官真正想听的是**两个结构各自解决什么、不变式怎么维持**，背 API 谁都会。

> 面试官追问点：LFU 比 LRU 难在哪？应答思路：LFU 要按「频次 + 同频次的时间」双维排序，频次会变（访问就加一，节点要在桶间搬家），需要「频次桶的双向链表 + 频次索引」（Redis 4 的方案）或堆，维护成本高一档；LRU 只有一维（时间），这也是 LRU 更普及的原因。

### 6.6 并查集的路径压缩与按秩合并

答：一句话定调，**并查集只干两件事（find 找根、union 合并），路径压缩加按秩合并后单次操作均摊 O(α(n))，α 是反阿克曼函数，「实际等于常数」**。

**基础结构**：parent 数组（**每个元素记父节点，根节点即集合代表**）；find 沿 parent 爬到根（沿途都是「同集合的证据链」）；union 把一个根挂到另一个根下。**朴素实现的坑**：链式合并（每次把大树挂小树）退化成 O(n) 的长链——find 要爬整条。

**两个优化的分工**：

1. **路径压缩**（find 时做）：爬到根后，**沿途所有节点直接改挂到根**（递归一行：`parent[x] = find(parent[x])`）——**下次再查这条链上任何点都是一步到根**；
2. **按秩合并 / 按大小合并**（union 时做）：**矮树挂高树**（rank 近似树高），防止越合越深。

**深水区一：复杂度的正确表述**——单用路径压缩是**均摊 O(logn)**，单用按秩合并是**最坏 O(logn)**，**两者合用是均摊 O(α(n))**：α(n) 是阿克曼函数的反函数，**n 达到宇宙原子数时 α ≤ 4**——所以工程语境说「近似 O(1)」但要能报出 α 的名字和出处（Tarjan 证明）。**注意「均摊」的含义**：单次最坏仍可能 O(logn)，是「多次操作摊薄后趋近常数」。

**深水区二：两种工程变体**：

1. **带权并查集**（边上有信息）：节点间存「相对关系」（如「比根大多少」），find 压缩路径时同步更新权值（`weight[x] = weight[x] + weight[px]` 的链式累加）——**「食物链」「区间和判定」类题的解法**，把并查集从「集合判定」升级成「关系代数」；
2. **可撤销并查集**（回溯场景）：**不路径压缩（压缩会破坏可撤销性），按秩合并且用栈记录每次 union 的改动**——回溯时弹栈恢复；**用于「动态加边的连通性」（离线删边反向加边）**——因为压缩的「拍平」不可逆，可撤销版本牺牲 α 换回溯能力。

收尾：并查集的答题心法，「**数组存爹、find 爬根、union 挂树，两个优化各管一次操作的深度，合起来 α(n)**」，再补一句「面试常考的三个变形：带权、可撤销、离散化预处理」。

> 面试官追问点：为什么 Kruskal 最小生成树选并查集？应答思路：Kruskal 按边权排序逐条尝试加边，「这条边的两端是否已连通」是纯集合查询——并查集的判连 O(α) 完美匹配，加边即 union；Prim 适合稠密图（点中心扩展），两者选型看边密度。

### 6.7 动态规划的状态设计方法论

答：一句话定调，**DP 的三步是「定义状态（dp[i] 的精确含义）→ 推转移方程 → 定计算顺序」，80% 的难题死在第一步「状态定义得不够准」**。

**状态设计的三个来源**（比背题重要）：

1. **从暴力递归里找**：写出递归解，**「函数参数里变化的量」就是状态**（递归的「记忆化」就是 DP 的镜像）——爬楼梯递归 f(n)，dp[n] 就是状态；
2. **加维度消后效性**：**一维 dp 解决不了「当前选择影响未来」时加一维记录历史**——股票问题的「是否持股」（dp[i][0/1]）、限制交易次数（dp[i][k][0/1]）——**「维度的本质是：完整描述『下一步决策所需的全部信息』」**；
3. **换个对象定义**：**「以 i 结尾」还是「前 i 个里」**——最长递增子序列必须「以 i 结尾」（dp[i] 只看尾部才能转移），「前 i 个」版本推不出转移（不知道接谁后面）——**定义错了转移就断了，这是新手最常见的卡点**。

**转移方程的两类模板**：

1. **选择型**（每步有分支取最优）：`dp[i] = max/min(dp[j] + cost, ...)`——背包「选或不选」、打家劫舍「偷或不偷」；
2. **区间型**（大区间依赖小区间）：`dp[i][j] = f(dp[i+1][j], dp[i][j-1])`——**按区间长度从小到大枚举**（计算顺序：len 从 2 到 n）——石子合并、戳气球、回文子串。

**深水区一：背包问题的一张表**——**0-1 背包（每件一次）**：`dp[j] = max(dp[j], dp[j-w] + v)`，**一维滚动必须倒序枚举 j**（正序会让「本轮已更新的值」被再次使用=物品重复选）；**完全背包（无限件）**：正序枚举 j（就是要复用）；**恰好装满与至多装满**：初始化 dp[0]=0 其余 -∞（恰好）/ 全 0（至多）——**「枚举方向和初始化就是背包的全部细节」**。

**深水区二：状态压缩 DP**——**n ≤ 20 的「集合型」问题**（旅行商、棋盘覆盖）：**用二进制位表示「已访问的集合」**，dp[S][i] = 访问过 S 集合、当前在 i 的代价——**状态的转移是「枚举不在 S 里的 j」**；**合法状态预筛 + lowbit 枚举子集的技巧**（`for (int s = S; s; s = (s-1) & S)` 枚举真子集）。**「状态是集合」是状态设计的第四个来源**，n 的范围（20）就是提示信号。

收尾：DP 答题的心法，「**状态定义要能『自圆其说』（dp[i] 的语义一句话说得清），转移要能『自证合法』（所有依赖的子状态先算出）**」，两问都通，剩下的只是敲键盘。

> 面试官追问点：记忆化搜索和递推 DP 怎么选？应答思路：记忆化「状态天然按递归展开、不用管计算顺序」（难想顺序的区间/图上 DP 友好）但有递归栈开销；递推「顺序明确、常数小、可滚动优化空间」——**面试先写记忆化保证正确，时间富余再改递推**是稳妥策略。

### 6.8 二分查找的边界与模板体系

答：一句话定调，**二分死的从来不是思想是边界：「循环条件（< 还是 <=）」「中点偏移（+1 还是 not）」「收缩方向（left=mid 还是 right=mid）」三个决策配套使用，两套模板覆盖全部场景**。

**两套模板**（先背框架再谈理解）：

1. **找精确值（闭区间 [l, r]）**：`while (l <= r)`，命中返回；`r = mid - 1 / l = mid + 1`——**区间缩小必然发生（两端都跨过 mid），不会死循环**；
2. **找边界（左闭右开 [l, r) 的「找第一个满足」）**：`while (l < r)`，`mid = (l + r) >> 1`（**向下取整**），`if (check(mid)) r = mid; else l = mid + 1`——**结束时 l == r 即答案位置**；「找最后一个满足」则 `mid = (l+r+1) >> 1`（**向上取整**）配 `l = mid / r = mid - 1`。

**死循环的机理还原**（深水区一，比背模板值钱）：**当收缩写 `l = mid` 而 mid 向下取整时**，区间 [l, l+1] 里 mid 算出 l——**l = mid 赋值后区间不动，永远循环**。所以铁律是：**`l = mid` 必须配向上取整（mid 至少是 l+1），`r = mid` 必须配向下取整（mid 至多是 r-1）**——**「中点的取整方向要保证区间必缩」**，理解这条就能自己推导而不是背四套模板。

**深水区二：二分答案**——「求最小的最大值/最大的最小值」的识别信号：**答案有单调性（可行域是前缀/后缀状）+ 直接构造难 + 验证一个候选值容易**——「吃香蕉的珂珂」（速度越大越可行）、「运送包裹」（运力越大越可行）：**二分的是答案空间不是数组下标**，check 函数是「按这个候选值模拟是否满足约束」——**「二分的是单调的东西，数组只是最常见的一种」**是这题的升维句。

**深水区三：浮点二分与精度**——`while (r - l > eps)` 循环固定次数（100 次足够，**比 eps 判断更稳，避免精度下的死循环**）；**「二分求平方根」的迭代次数 ≈ log2(值域/eps)**——能报出次数概念就证明理解收敛速度。

收尾：二分答题的心法，「**先说清找什么（精确/左边界/右边界）、再报配套的取整与收缩方向、最后讲『区间必缩』的不变量**」——三句话稳过，二分答案的识别是加分。

> 面试官追问点：旋转数组找目标值怎么做？应答思路：每次二分**判「mid 的哪半边是有序的」（和端点比较）**，有序的那半边用端点判断目标在不在——在则收缩到这半，不在则收缩到另半；「两段有序」的二分本质是「每轮至少半边恢复有序性可判」。

### 6.9 单调栈与单调队列的应用模式

答：一句话定调，**单调栈解决「下一个更大元素」类问题（空间换时间的最近关系），单调队列解决「滑动窗口最值」，两者的共同灵魂是「不可能是答案的元素及时出队」**。

**单调栈的机制**：栈里维护「递减序列」（栈底大栈顶小），**新元素比栈顶大时，栈顶元素的「下一个更大」就是它——弹出并结算**；被弹出的元素永远不会再是后面元素的答案（**「比你小又比你早的，不可能挡住后来的」**——这是「弹出的合法性证明」，能口述它才是懂了）。**每个元素最多进出栈一次，总复杂度 O(n)**。

**三个经典应用对照**：

1. **每日温度**（找下一个更大）：弹栈时结算 `res[弹出的] = 当前下标 - 弹出下标`；
2. **柱状图最大矩形**：**找「左右两边第一个更矮」**——弹栈时「当前元素是右边界、弹出后新栈顶是左边界」，宽度相乘结算；**加哨兵（首尾补 0 高度）统一边界处理**是工程细节；
3. **接雨水**：**横向逐层结算**（弹栈时当前柱和新栈顶之间的高度差 × 宽度），和纵向按列结算殊途同归——**「按层还是按列」两种视角都讲，说明真理解**。

**单调队列的机制**（深水区一）：双端队列维护「窗口内的递减序列」，**新元素从队尾弹出所有比它小的再入队（它们不可能是后面窗口的最大值）**；**队头出队只因为滑出窗口（下标过期）**。**「最大值在队头、且队列里的元素按值递减按时间递增」是双重不变式**——滑动窗口最大值的 O(n) 解。**队尾弹（维护单调性）和队头弹（维护窗口范围）的分工**是手写时的最大坑。

**深水区二：两个变形题**：

1. **绝对差不超过限制的最长子数组**（LC 1438）：**滑动窗口 + 单调队列 × 2（一个维护最大一个维护最小）**——窗口扩张直到「max - min > limit」再收缩左端，**队列是「窗口内最值的 O(1) 查询器」**；
2. **带延迟的队列优化**：**跳跃游戏 VI 之类的 DP 转移是 `dp[i] = max(dp[i-k..i-1]) + nums[i]`**——**DP 的区间最值依赖正好是滑动窗口**，单调队列把 O(nk) 优化成 O(n)：**「单调队列优化 DP」是它从数据结构工具升维成算法组件的证据**。

收尾：单调结构答题的心法，「**弹出的都是不可能成为答案的（证明合法性），留下的都是待定候选（维持单调性）**」，能对任何一道新题说出「谁不可能」就能现场推导。

> 面试官追问点：为什么单调栈能保证 O(n)？应答思路：总操作数 = 入栈次数 + 出栈次数 = 2n（每元素各一次封顶），虽然单轮 while 可能弹多个，**均摊分析**：把每次弹出记账给被弹元素，每元素一生只被弹一次——和并查集的均摊是同一套账本思想。

### 6.10 KMP算法的next数组推导

答：一句话定调，**KMP 的 next 数组存「模式串每个前缀的最长相等前后缀」，失配时跳到「已匹配部分的 border」继续，主串指针永不回退是 O(n+m) 的来源**。

**先讲暴力为什么慢**：主串每轮失配后**主串指针回退、模式串归零重来**——最坏 O(nm)（主串 "aaaa...ab" 配 "aab" 的病态例）。**KMP 的洞察：失配时「主串中已匹配的那段」和「模式串的前缀」完全相同——模式串自己知道自己前缀的信息，就能推出「主串接下来该从模式的哪个位置继续比」**。

**next 数组的语义**（必须先钉死）：`next[i] = 模式串 [0..i] 这段前缀的「最长相等真前后缀」的长度`——"ababc" 的 next = [0,0,1,2,0]（**"abab" 的 border 是 "ab" 长 2**）。**它是模式串的自我剖析，「主串没参与计算」**——预处理 O(m) 与主串无关。

**失配时的跳转逻辑**：主串 i 与模式 j+1 失配——**已匹配的 [0..j] 和主串 [i-j..i-1] 相同**；**该段的最长 border（长度 next[j]）意味着主串接下来的 next[j] 个字符已经和模式的前 next[j] 个「预匹配」了**——**j 跳到 next[j]（j 指针回退但主串 i 不动）**，从 j+1 继续。**「j 的多次跳转」= 沿 border 嵌套链回退**（border 的 border 也是 border，跳到没有为止）。

**深水区一：next 数组的自求解**——**next 数组本身就是「模式串自己和自己做 KMP」**：求 next[i] 时，j = next[i-1]（上一位的 border 延伸候选），**比较 s[i] 与 s[j]**：相等 next[i] = j+1；不等 **j 跳 next[j] 再试**（border 链回退）——**「用已求出的 next 求下一个 next」的递归结构**，这是 KMP 最烧脑也最值得讲清的部分。

**深水区二：nextval 优化与工程取舍**——失配跳转后**如果模式串新位置字符和失配位置字符相同**（如 "aaaab" 配主串 "aaac"，跳了还是 a 还会失配），nextval 把这种「无效跳」提前抹平（nextval[j] 再跳一层）；**工程现实**：标准库的字符串查找（如 Java 的 indexOf、C++ 的 search）**多数用 Boyer-Moore 的简化版（坏字符/好后缀启发）**——**平均 sublinear（跳着比）但最坏差；KMP 是「最坏稳定 O(n+m)」的理论保证**，**「BM 平均快、KMP 最坏稳、Sunday 实现简单」的三分天下**能说全就是加分。

收尾：KMP 答题的心法，「**next 是模式串的 border 表，失配跳转的本质是『用模式串的自我相似性换主串指针的不回退』**」，自求解的递归结构讲清楚，这题就从背到了懂。

> 面试官追问点：为什么叫「_border」？应答思路：border 即「既是前缀又是后缀的真子串」，它是「失配时唯一可能续上的接口」——跳到 next[j] 后主串接下来的字符和模式串前 next[j] 个字符必然相等（border 的定义保证），所以不用重新比——**名字背后就是算法正确性的证明本身**。
