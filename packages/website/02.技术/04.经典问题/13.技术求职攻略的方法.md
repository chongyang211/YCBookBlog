# 技术求职全攻略

> 简历 → HR 面 → 技术面 → 谈薪 → 复盘：一条完整的求职闭环

```text
求职是一场完整的战役，每个环节都在为下一个环节铺路：

  简历（10 秒抓住 HR）→ HR 面（通过软性问题筛选）→ 技术面（验证硬实力）
  → 谈薪（不谈钱只会让你更不值钱）→ 复盘（不复盘等于白面）

  任何一环掉链子，前面的努力都会打折。
  这篇攻略把整条链路一次讲透。
```

## 一、简历优化——让面试官想见你

### 1.1 简历的唯一目的

```text
简历的读者是谁？
  HR：用 10 秒扫关键词 → "这个人匹配吗？"
  面试官：用 30 秒扫项目经历 → "有意思吗？值得问吗？"

你的简历必须在 10 秒内让 HR 看到关键词，在 30 秒内让面试官产生好奇。
```

**简历不是你的职业生涯流水账——是你最精彩的 30 秒预告片。**

### 1.2 STAR 法则——每一段经历都讲一个故事

```text
STAR = Situation + Task + Action + Result
       背景      任务      动作      结果

❌ 流水账写法：
"负责订单系统的开发与维护。"

✅ STAR 写法：
"主导订单系统重构（S），解决旧系统在双十一 QPS 从 200 暴涨到 2000 时频繁超时的问题（T）。
将同步支付流程拆分为消息队列异步处理，引入 Redis 缓存热点商品数据（A）。
重构后 P99 延迟从 4.2s 降到 180ms，双十一期间零故障处理 120 万笔订单（R）。"
```

**STAR 中最重要的字母是 R（结果）。** 没有结果的动作只能说明"我做过"，有结果的动作说明"我做成过"。

### 1.3 量化——数字比形容词有力一百倍

```text
❌ "显著提升了系统性能"
❌ "负责核心模块开发"
❌ "优化了用户体验"

✅ "P99 延迟从 3.2s 降到 120ms——提升 26 倍"
✅ "独立设计支付模块，支撑日订单从 1000 增长到 50000"
✅ "App 崩溃率从 0.8% 降到 0.05%，应用商店评分从 3.2 升到 4.6"
```

**能量化的用数字，不能量化的用对比。** "重构了 XX 模块"不可见；"重构前每次改一个字段要改 4 个文件，重构后只改 1 个"——可见。

### 1.4 项目经历的筛选——不是越多越好

```text
简历上放 8 个项目，面试官一个都问不深。
简历上放 3 个项目，每个都经得起 20 分钟深挖——胜率更高。

筛选标准：选你最想被面试官问到的那 2-3 个项目。
  - 你在这个项目中的角色是"主导"还是"参与"？（优先放主导的）
  - 你能讲清楚这个项目的技术决策吗？（为什么选 A 不选 B？）
  - 这个项目有可量化的产出吗？（没有数字的项目不放进简历）
```

### 1.5 常见坑及修正

| 坑 | 问题 | 修正 |
|---|---|---|
| **技能列表像菜单** | "熟练 Java、Python、Go、K8s、Docker..." 写 20 个 | 分档：精通(1-2个) / 熟练(3-4个) / 了解。面试官会挑你写"精通"的往死里问 |
| **没有个人贡献** | "参与 XX 项目" | 改为主谓宾："我设计了 XX 的数据库 schema"、"我引入了 XX 方案将错误率降到 YY" |
| **堆砌专业术语** | 一句话里塞 5 个 buzzword | 每个技术名词后面都跟一句"用它解决了什么问题" |
| **简历超过一页** | 5 年经验 3 页简历 | 5 年以下经验一页足够。除非 10 年+资深岗，否则不要超过两页 |
| **个人评价写废话** | "吃苦耐劳、团队协作能力强" | 删掉。没人信这种自我评价。用项目经历中的事实来证明你的能力 |

### 1.6 格式硬规则

```text
□ PDF，不是 Word——Word 在不同电脑上排版会乱
□ 文件名：杨充-Android开发工程师-5年.pdf（不要叫"简历.pdf"）
□ 纯文本可搜索——不要把你的简历做成一张大图（HR 的 ATS 系统搜不到）
□ 不超过一页（5 年经验以内）
□ 没有错别字——找一个人帮你看一遍，自己看 100 遍也可能漏掉
```

### 1.7 小结

```text
简历优化三原则：

1. 10 秒能扫完 → 结构清晰：个人信息（2行） + 技能（3行） + 工作经历（3段 STAR）
2. 每句话都有数字 → 能量化就量化，不能量化就对比
3. 引导面试走向 → 你写的每一项，都等于在告诉面试官"请问我这个"
   ——不要写你不想被问到的东西
```

## 二、HR 面试——高频问题与应答思路

> HR 面考察的不是技术，是"你这个人"：稳定性、协作性、自我认知与求职动机。
> 下面按主题归类高频问题，每题给"回答提示"与"参考话术"。

### 2.1 开场与自我认知

**请做一下自我介绍**

回答提示：不要只说姓名、年龄、工作经验（这些简历上都有）。企业最想知道的是你能否胜任：最强的技能、最深入研究的领域、做过的最成功的事。**用"我是谁 + 我做成过什么 + 我为什么来"三段式**，控制在 1-2 分钟。

**你最大的优点是什么？**

回答提示：说具体的品质 + 例子。"沉着冷静、条理清楚"配上"我在 XX 项目里如何临场解决 XX 问题"——**没有例子的优点是形容词，有例子的优点是证据**。

**说说你最大的缺点？**

回答提示：直接说"小心眼、懒、效率低"肯定不行。思路：**说一个真实但无害的缺点 + 你正在怎么改进它**。"我对细节有点执念，早期容易在优化上花过多时间——后来我学会了先定时间盒，优先交付主干。"——比"我的缺点是太追求完美"真诚十倍。

**最能概括你自己的三个词？**

回答样本：适应能力强、有责任心、做事有始终——**每个词后面必须跟一个具体例子**。

### 2.2 动机与匹配

**为什么要离职？**

回答提示：这是高危题。**再大的委屈也不要抱怨前公司**，面试官会想"他以后也会这么说我们"。最佳策略是**把原因归到自己身上**：想找更大的成长空间、当前工作与长期规划不合、现有平台已到瓶颈——积极正面，不自贬也不贬人。

**你为什么愿意到我们公司来工作？**

回答提示：面试前务必研究这家公司（主营业务、近期动态、技术博客）。**"贵公司 XX 业务在行业内的做法我很感兴趣，我在 XX 方面的积累正好能用上"**——研究过的求职者和没研究过的，第一句话就听得出来。

**在五年内，你的职业规划？**

回答提示：不要说"不知道"（会丧失机会），也不要空喊"做管理"。比较稳的答法："**我准备在技术领域持续深入，希望能独立负责一个核心模块/方向**，同时按公司的发展需要成长。"

**你对我们公司了解多少？**

回答提示：有备而来的求职者才能过关。提前查公司主营业务、产品线、技术动态，回答时自然带出你了解的信息——**企业欢迎的是"知己"，不是"盲人"**。

**你能为我们公司带来什么？**

回答提示：重复自己的优势并落到具体："我做过 XX，上手即可产出；我在 XX 方面的经验可以帮团队规避我踩过的坑。"——**用事实说话，别开支票**（"我一定会带来 XX 业务"这种大话是大忌）。

### 2.3 薪资与到职

**说说你对薪资的要求？**

回答提示：报太低贬低自己，报太高显得分量过重。**黄金规则是不先报价**——先了解岗位职责，让对方先亮牌（详细话术见第四章薪资谈判）。如果必须报：**给一个具体数字而不是宽泛范围**（宽范围只会拿到最低值），并且说明这是基于市场调研的。

**何时可以到职？**

回答提示："如果被录用，可以按公司规定时间到职。"若还在职，说明交接周期（通常一个月），正规公司会通融——**不辞而别式的"明天就来"反而显得不专业**。

### 2.4 协作与冲突

**工作时跟领导意见不同怎么办？**

回答样本：①原则上尊重和服从安排，私底下以请教的口吻婉转表达想法；②领导没采纳，也认真按要求完成工作；③若领导的要求违背原则，会坚决提出反对意见，仍无果则向上级反映——**"先尊重表达、再服从执行、原则问题有底线"三段式**。

**你和别人发生过争执吗？**

回答提示：这是陷阱题，考的是成熟度。**答案的核心是"通过沟通和妥协解决"**，展示你以事为出发点（对事不对人）、能妥协、能从争执中达成更好方案——而不是证明"我吵赢了"。

**上级领导抢了你的功劳怎么办？**

回答样本：先主动和主管领导沟通（沟通是解决人际问题的最好办法）；若对方认识到问题则视情况修复关系；若变本加厉，再向上级反映——**先内部沟通、留有余地、有底线有升级路径**。

**和同事、上司难以相处，你怎么办？**

回答样本：①先从自身找原因，检讨工作方式和为人处世；②找机会沟通，请对方指出我的不足；③以大局为重，做好本职工作——**"自省 → 沟通 → 坚守本职"的顺序不要乱**。

### 2.5 压力与应变

**说说你对加班的看法？**

回答提示：公司问这个不是一定要你加班，是测奉献意愿。回答样本："工作需要时我义不容辞；同时我也会提高效率，减少不必要的加班。"——**既表态又显效率意识**。

**工作出现失误并造成损失，你会怎么做？**

回答样本：①首要的是想方设法弥补或挽回损失；②分清责任，是我的责任我承担，是团队的失误就一起复盘总结；③从错误中吸取经验，检讨工作方法——**"止损 → 担责 → 复盘"的顺序体现了成熟度**。

**如果你没被录用，你怎么打算？**

回答样本：①敢于面对，不气馁；②认真复盘这次面试，从自身找差距；③查漏补缺、加强学习；④回到本职继续踏实工作；⑤有机会再次参加竞争——**把失败当数据点**（这个心态在第五章复盘会展开）。

**你工作经验欠缺，如何能胜任这项工作？**

回答样本：承认欠缺 + 展示补偿项："读书期间我一直在这个行业做兼职/项目，实际工作的复杂度我有体感；我有较强的责任心和学习能力，学校所学加实践经验让我能胜任这个职位。"——**诚恳、具体、不空谈**。

**对这项工作，你有哪些可预见的困难？**

回答提示：不宜直接列出具体困难（会让对方怀疑你不行）；迂回战术："工作中出现困难是难免的，只要有坚忍不拔的毅力、良好的合作精神和事前周密的准备，任何困难都可以克服。"

**你还有什么问题要问吗？**

回答提示：说"没问题"等于放弃展示自己。**好的反问**："新人有没有培训机制？""团队的晋升机制是什么样的？""团队目前最大的技术挑战是什么？"——**体现学习热情和上进心，别第一句就问福利**（技术面的反问清单见第三章 3.5）。

## 三、技术面试——考的是思考过程

### 3.1 底层逻辑——面试官在找什么

```text
面试官不是来难为你的。他带着一个问题走进面试间：
"我愿意和这个人一起工作吗？"

这个问题拆成三个子问题：
1. 他能独立解决问题吗？        → 算法 + 系统设计
2. 他能把问题想清楚吗？        → 思考过程比答案更重要
3. 他有什么是我从简历上看不到的？ → 项目深挖
```

**技术面试不是在考试——是在模拟一次工作协作。** 你边想边说，面试官边听边引导，这个互动过程本身就是考核。

### 3.2 算法面试——不是背题，是展示思路

```text
拿到题目的前 60 秒做三件事：
  1. 复述题目确认理解："你的意思是——输入一个数组，返回不重复的元素？"
  2. 举一个具体例子确认边界："如果输入 [1,2,2,3]，输出应该是 [1,2,3] 对吗？"
  3. 先说思路再说代码："最暴力的方法是两层循环 O(n²)——但我们可以用哈希表 O(n)"

卡住了的三步自救：
  1. "让我先想一个最暴力的解法——哪怕时间复杂度很差"
     → 先说出能用的方案，面试官知道你能解决问题
  2. "这个暴力解法的瓶颈在 XX 步骤——有没有办法优化这里？"
     → 自己指出问题，展示分析能力
  3. 真想不到："你能给我一个提示吗？我想确认方向是对的。"
     → 这不扣分。工作中你不会拒绝同事的帮助

写完代码后的 2 分钟：
  □ 自己跑一个测试用例——用最开始举的例子走一遍代码
  □ 指出代码的局限性："数据量超过 100 万时需要改为分治"
  □ 讨论优化方向："空间卡得更紧可以用原地算法但会改变原数组"
```

### 3.3 系统设计——不要背"秒杀系统设计"

```text
四步法：
1. 澄清需求（2 分钟）："用户是谁？DAU 多少？读写比例？一致性要求？"
   → 不问需求直接画架构图 = 扣分
2. 给一个简单方案（3 分钟）："MVP 一周上线会这么干——单体 + MySQL + 单机 Redis"
   → 表明你知道 scale 不重要的时候不需要微服务
3. 找瓶颈并演进（10 分钟）：加缓存 → 读写分离 → 消息队列 → 分库分表
   → 每一步说明"为什么加"，而不是"教科书上说该加"
4. 总结 trade-off（2 分钟）："代价是一致性退化为最终一致——不能接受的话，兜底是 XX"

不要背，要演：
"我先想到 Redis 预扣库存——但 Redis 挂了怎么办？"
"那加数据库兜底——数据库扛不住——再加消息队列削峰。"
"等等，消息队列也有吞吐上限——要不要前置一个限流？"
→ 面试官看到你在思考，而不是在背诵。
```

### 3.4 项目深挖——面试官在验证简历

```text
三类必问问题：
1. 难度验证："这个项目最难的部分是什么？"
   → 答"都还行"说明你做的都是 CRUD，或者没深入
2. 决策验证："为什么选 Kafka 而不是 RabbitMQ？"
   → 答"组里在用"不是决策，是跟随
3. 结果验证："你怎么衡量项目成功了？"
   → 答"上线了就成功了"说明没有产品思维

每个项目提前准备一个"失败点"（翻车 → 复盘 → 改进的小故事）：
"上线后发现数据库连接池设太小，大促当晚连接耗尽——临时改配置重启扛了过去。
复盘后做了两件事：① 配置变更前做压测验证 ② 加了连接池使用率的监控告警。"
```

### 3.5 反问环节——这是你面试公司的机会

```text
❌ "没有。" → 不是不感兴趣就是没准备，扣分
❌ 第一个问题就问加班 → 可以问，但别放第一个

✅ 展示思考深度的问题：
  "团队目前遇到的最大的技术挑战是什么？"
  "你们技术决策的流程是什么样的？"
  "团队内 code review 的文化怎么样？"
  "这个岗位前三个月的成功标准是什么？"
  "团队里最优秀的那个工程师是什么样子的？"
```

## 四、薪资谈判——不谈钱只会让你更不值钱

### 4.1 心理建设：你值多少，不是公司说了算

```text
工程师最常见的薪资心态：
  "不好意思开口"、"怕谈崩了"、"公司给了就不错了"

招聘的真相：
  HR 报给你的第一个数，不是你的价值——是他们的预算底线。
  预算区间通常是报价的 15%-30% 往上还有空间。
  你没有在"多要钱"——你只是没让他们用底价买到你。
```

### 4.2 薪酬的完整构成——不是只有月薪

```text
一份 offer 的价值 = 现金 + 股票/期权 + 福利 + 隐形价值

现金：
  □ 月薪 × 发薪月数（12 还是 13 还是更多？）
  □ 年终奖：过去两年实际发了多少？（问"平均"，不是"最多"）
  □ 签字费：一次性给的，用来弥补你放弃的上一家年终奖

股票/期权（RSU/Option）：
  □ 总价值多少？分几年归属？（通常 4 年，每年 25%）
  □ 行权价多少？公司没上市 → 期权接近于白纸

福利：
  □ 公积金比例（5% vs 12% 差很多）
  □ 餐补/房补/交通补——加起来每月可能多 2000-5000
  □ 补充商业保险（有家庭的话很值钱）

隐形价值：
  □ 技术成长——和高手共事比一年多 10 万月薪更重要
  □ 赛道前景与工作强度——时薪 = 年薪 ÷ 年工作小时数。别只看年薪
```

### 4.3 报价话术——什么时候说、怎么说

```text
黄金规则：谁先说数字谁劣势。

HR："你期望的薪资是多少？"

❌ "我期望 30K。" → 如果预算是 35-40K，你亏了
✅ "我还不太了解这个岗位的具体职责——能先聊聊吗？之后觉得合适薪资可以再谈。"
✅ 被追问："我更关注成长空间，薪资相信市场会给公允报价。
   如果一定要一个范围，基于我对市场的了解，大概在 XX-YY 之间。"

拿到 offer 后——你不是在哀求，是在谈判（他们已经决定要你了）：
"非常感谢 offer！我对团队和方向都很感兴趣。
看了下整体 package，和我的预期还有些差距——如果 base 能到 XX，我就很确定了。"

注意：
  - 不要拿不想去的 offer 来 bluff（万一对方说"那你去那家吧"）
  - 不要说"另一个 offer 给了 XX"——要说"市场水平大概是 XX"
  - 谈判一轮就够，不要反复拉扯
```

### 4.4 期权/股票的避坑清单

```text
□ 是期权（Option）还是 RSU？
   → Option 要出钱行权，公司不上市就是废纸
   → RSU 直接给股票，上市了就是真金白银

□ 行权价格 vs 最近一轮融资估值——没有折扣就要警惕

□ 离职后期权多久内必须行权？标准 90 天，给 10 年是加分项

□ 公司上一轮融资是什么时候？现金流还能烧多久？
   → 融了 5000 万但只剩 2 个月现金流的期权 ≈ 废纸

□ 口头承诺的期权不作数——必须写在合同里
```

### 4.5 谈判红线——这些情况直接走

```text
□ "薪资保密，不要和同事讨论" → 讨论薪资受劳动法保护。
   不让讨论 = 有人被压价了，怕你知道。

□ "现在低一点，半年后调薪" → 不写进合同等于没说。

□ "我们 996 但是给钱多" → 算时薪：
   30K × 12 ÷ (12小时 × 6天 × 50周) = 时薪 100 元
   20K × 12 ÷ (8小时 × 5天 × 50周) = 时薪 120 元
   你觉得哪个更值？

□ "期权以后会很值钱" → 期权在变现之前价值 = 0。
   不要用不确定的期权代替确定的现金。
```

## 五、面试复盘——不复盘等于白面

### 5.1 为什么要复盘

```text
一场面试 1 小时，你被问了 10+ 个技术问题。
如果面完就翻篇——下一次面试，同样的问题你还是答不好。

复盘不是让你自责——是让你发现"我在哪里卡住了"，然后补上。
你面的每一场都是免费的实战训练。不复盘＝浪费了入场券。
```

### 5.2 面试后三十分钟的记录模板

```text
面完趁着还在公司楼下（或刚关掉视频），花 5 分钟填这个：

## 面试记录
- 公司/岗位：
- 日期：
- 面试官角色（TL/架构师/HR）：

## 技术问题清单
| # | 问题 | 我的回答 | 答对了吗？ | 标准答案/改进 |
|---|---|---|---|---|
| 1 | HashMap 和 ConcurrentHashMap 区别 | ... | ❌ | 查漏补缺 |
| 2 | 系统设计：设计一个短链系统 | ... | ✅ | 还不错 |

## 卡壳点记录
→ 例："动态规划那道题，我知道要用 DP 但推不出状态转移方程"

## 反问中学到的信息
→ 能判断这个团队的技术氛围和工作强度

## 这次面试最大的收获（只写一条）
→ 例："以前没准备过消息队列的对比，这次被问了——回去补"
```

### 5.3 失败分析——不是"我不够好"

```text
面试失败有三种原因，只有一种是你需要担心的：

类型 1：技能不匹配（能补）
  → "他们要做云原生，我没学过 K8s"
  → 方向不同，不是你不行。想去的方向就去学。

类型 2：面试发挥失常（能练）
  → "常规算法题，紧张得脑子一片空白"
  → 多 mock interview，或者自己录自己讲。

类型 3：气场不合（不是你的问题）
  → "面试官全程看电脑，问的问题都很敷衍"
  → 这家公司不值得去——面试官的态度就是入职后同事的态度。
```

**拿到拒信不是审判——是一个数据点。** 10 次失败里可能有 5 次方向不匹配、3 次发挥失常、2 次气场问题——真正需要你大补的只有 3 次。

### 5.4 持续改进——两周一个循环

```text
两周循环：
  第 1 周：面 2-3 家 → 每次面完立刻复盘
  第 2 周：复盘弱项 → 针对性学 → mock interview 验证
  循环

不要一次性面 10 家——你会连续犯同样的错误，而且没时间在面试之间改进。
理想节奏：一周最多面 3 家，每两家之间隔一天复盘和补漏。
```

### 5.5 建立个人知识漏洞库

```text
每场面试后，更新三个列表：

1. 答得好的问题（自信区）→ 下次可以把这块讲得更精彩
2. 答得模糊的问题（灰色区）→ 看了但没理解透——本周要啃的
3. 完全不会的问题（盲区）→ 知识地图上的空白——标记下来，排期学习

一个月后回看——盲区列表变短了，自信心变长了。这就是复盘的复利。
```

### 5.6 心态——面试是概率游戏

```text
一个技术岗平均收到 200 份简历，面 15 个人，发 3 个 offer，最后 1 人入职。

这意味着：
  - 你需要面 15 家才能期望拿到 1 个 offer
  - 被拒 14 次不是"你不值钱"——是概率本来就如此
  - 你需要的不是"每一场都赢"，是"在拿到 offer 之前别崩"

把每一场面试当练习，把 offer 当 bonus——心态会好很多。
```

## 六、全流程行动清单

```text
投递前（简历）：
  □ 用 STAR 重写最近的项目——重点是 R（结果）
  □ 项目砍到 2-3 个最能打的，每项都有数字
  □ 技能列表分档，"精通"的确保能被深挖 5 分钟
  □ PDF + 规范文件名 + 无错别字

面试前（准备）：
  □ 研究目标公司：主营业务、近期动态、技术博客
  □ 过一遍 HR 高频问题：自我介绍、离职原因、优缺点各有 1 分钟版本
  □ 每个简历项目准备"最难的问题"和"犯过的错误"各一个
  □ 准备 3 个反问问题

面试中（发挥）：
  □ 算法题：先复述确认 → 说思路 → 写码 → 跑用例
  □ 系统设计：四步法，先问需求再画图
  □ 边想边说，卡住就求助——不硬扛

谈 offer（谈判）：
  □ 不先报价；拿到 offer 后只谈一轮
  □ 算总包：现金 + 股票（当 0.5 折算）+ 公积金 + 福利 + 时薪
  □ 期权查三样：类型、行权价、归属条款——写进合同

面后（复盘）：
  □ 30 分钟内填记录模板
  □ 失败按三类归因，只对"技能不匹配"采取行动
  □ 两周一个循环：面 → 复盘 → 补漏 → 再面
```

**最后一句**：求职的每个环节都可以被准备、被练习、被复盘——**把求职当成一个工程项目来管理，你就是自己职业生涯最好的架构师。**
