# 技术规范

主流编程语言代码规范与 Git 提交规范合集——统一风格，减少低级错误，提升代码可读性。

## 规范核心维度

每份规范涵盖以下维度：

```
命名       → 变量/函数/类/文件，见名知意
格式       → 缩进/换行/空格，统一风格
注释       → 解释Why不解释What
异常处理   → try-catch规范，不吞异常
并发       → 线程安全、锁的使用
最佳实践   → 行业公认的推荐做法
```

## 快速参考

### Git 提交消息格式

```
<type>(<scope>): <subject>

feat(用户模块): 添加登录功能
fix(支付模块): 修复金额计算精度问题
docs(README): 更新部署文档
```

## 核心原则

1. **宁可规范多一点，不可随意写** - 团队统一比个人习惯更重要
2. **工具自动化** - ESLint/Prettier/CheckStyle 自动检查，减少人工 Code Review
3. **持续更新** - 规范随语言版本和技术演进同步更新
4. **新人友好** - 规范是新成员快速融入团队的导航图
5. **说清楚 Why** - 每条规则都要有理由，不搞"我觉得应该这样"
