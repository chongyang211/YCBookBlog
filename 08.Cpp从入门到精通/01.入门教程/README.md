

## 01.基础语法

- 1.1.1 C++语言介绍：是一种静态类型的、编译式的、通用的、大小写敏感的、不规则的编程语言，支持过程化编程、面向对象编程和泛型编程。
- 1.1.2 C++的特点：包括面向对象开发的四大特性：封装，继承，多台，抽象。
- 1.1.3 C++标准库：1.核心语言；2.C++ 标准库；3.标准模板库（STL）。
- 1.2.1 编译器是什么：是将 C++ 源代码转换为机器代码的工具，使程序能够在计算机上运行。
- 1.2.2 GCC编译器：通过 g++ 来编译cpp文件，编译后会生成一个a.out文件。
- 1.2.3 Clang编译器：Clang 是 LLVM 项目的一部分，专注于提供快速编译和清晰的错误信息。
- 1.2.5 IDE开发环境：IDE 集成了编译器、编辑器、调试器等工具，提供更便捷的开发体验。
- 1.4.0 最简单编译：g++ main.cpp，由于命令行中未指定可执行程序的文件名，编译器采用默认的 a.out。
- 1.4.1 编译单个文件：g++ program.cpp -o program，
- 1.4.2 编译多个文件：g++ main.cpp utils.cpp -o program，
- 1.4.3 指定C++标准：g++ 有些系统默认是使用 C++98，我们可以指定使用 C++11 来编译 main.cpp 文件。
- 1.6.1 命名空间概念：您可能会写一个名为 xyz() 的函数，在另一个可用的库中也存在一个相同的函数 xyz()。防止命名冲突，将代码逻辑分组。

## 02.数据类型

- 3.1.1 基本数据类型：比较常见有int，short，long，long long等不同的类型。还有浮点型，字符型，布尔型数据。
- 3.2.1 有符号类型：有符号类型可以存储负数、正数和零，其中最高位用于表示符号（0 表示正数，1 表示负数）。
- 3.2.2 无符号类型：无符号类型是指只能表示非负数（包括零）的数据类型。例如，unsigned int表示无符号整数。
- 3.2.3 固定宽度整数类型：它们提供了明确大小的整数类型，方便跨平台开发时确保数据大小的一致性。
- 3.3.1 字符类型列表：字符型变量用于显示单个字符，字符型变量并不是把字符本身放到内存中存储，而是将对应的ASCII编码放入到存储单元。
- 3.3.2 字符类型特点：`char` 可以是有符号或无符号，具体取决于编译器和平台。 通常用于存储 ASCII 字符（0 到 127）。
- 3.4 浮点类型：浮点类型用于表示实数（即带小数点的数字）。它们基于 IEEE 754 标准，提供了不同精度的浮点数表示。
- 3.5 布尔类型：布尔数据类型代表真或假的值。
- 3.6.1 变量：给一段指定的内存空间起名，方便操作这段内存。
- 3.6.2 常量：第一种宏常量`#define 常量名 常量值`；第二种在变量定义前加关键字const，修饰该变量为常量，不可修改。
- 3.7 类型转换：将一种数据类型转换为另一种数据类型的过程。C++ 提供了多种类型转换方式，包括隐式转换和显式转换。
- 3.7.1 隐式类型转换：隐式类型转换由编译器自动完成，通常发生在赋值、表达式计算或函数调用时。
- 3.7.2 显式类型转换：C风格转换是强制转化，比如将double转化为int类型。C++风格是提供了四种显式转换运算符，更加安全和明确。
- 3.7.2.1 static_cast：用于基本数据类型之间的转换，以及具有继承关系的类之间的转换。
- 3.7.2.2 dynamic_cast：用于具有多态性的类之间的转换（通常用于向下转型），转换失败时返回 `nullptr`。
- 3.7.2.3 const_cast：用于移除或添加 `const` 或 `volatile` 修饰符。
- 3.7.3.4 reinterpret_cast：用于低级别的类型转换，通常用于指针或整数之间的转换。

## 04.复合类型

- 4.1.1 复合数据类型：是由基本数据类型组合而成的更复杂的数据结构。它们允许将多个值组织在一起，以便更高效地管理和操作数据。

- 4.5.1 什么是联合体：是一种特殊的数据类型，它允许在相同的内存位置存储不同的数据类型。

## 06.函数

- 6.1.1 函数概念：是一段可重用的代码块，用于执行特定的任务。函数可以提高代码的模块化、可读性和可维护性。
- 6.1.2 函数声明和定义：函数的定义一般主要有5个步骤，返回值类型，函数名，参数，函数体语句，return返回值。
- 6.1.3 函数分类：
- 6.1.4 Lambda函数:C++11 引入了 Lambda 函数，用于定义匿名函数。
- 6.2.1 值传递：传递参数的副本，函数内对参数的修改不会影响原始值。
- 6.2.2 引用传递：传递参数的引用，函数内对参数的修改会影响原始值。
- 6.4.1 函数重载案例：是指在同一个作用域内，可以定义多个同名函数，但它们的参数列表不同。函数重载允许使用相同的函数名来实现不同的功能。
- 6.5.1 内联函数是什么：通过将函数体直接插入到调用处，内联函数可以避免函数调用的额外开销（如栈帧的创建和销毁），从而提高程序的执行效率。
- 6.5.2 内联函数定义：在函数声明或定义前加上 `inline` 关键字：编译器会尝试将函数调用替换为函数体，以减少函数调用的开销。

## 07.指针

- 7.1.1 什么是指针：它存储了一个内存地址。指针可以指向其他变量或对象的内存地址，通过指针，可以直接访问和操作内存中的数据。
- 7.1.2 指针声明：语法是`数据类型 *指针变量名;`，举一个例子，int *number，那么number便是一个指针。
- 7.1.3 指针初始化：指针在使用前必须初始化，否则会指向一个未知的内存地址，可能导致程序崩溃。
- 7.1.3 指针占用空间：在 C++ 中，指针的大小取决于编译器和操作系统的位数。在 32 位系统中，指针通常占用 4 个字节（32 位）的内存空间。
- 7.2.1 取地址运算符：`&` 用于获取变量的内存地址。
- 7.2.2 解引用运算符：`*` 用于访问指针指向的内存地址中的值。
- 7.4 指针和函数：指针可以作为函数的参数或返回值，用于传递或返回内存地址。
- 7.5 指针与常量：1.常量指针；2.指向常量的指针；3.指向常量的常量指针。
- 7.6.1 指针的指针：指针可以指向另一个指针。
- 7.6.2 函数指针：函数指针是指向函数的指针变量，可以用于动态调用函数。
- 7.7.1 空指针：空指针通常用来表示指针没有被初始化或者指向了无效的内存地址。在 C++ 中，空指针的值通常是 0 或者使用 nullptr 关键字表示。
- 7.7.2 野指针：野指针是指指向未知内存地址或已释放的内存地址的指针，使用野指针可能会导致程序崩溃、内存泄漏或产生不可预测的行为。

## 08.引用

- 8.1.1 什么是引用：引用是一个变量的别名，它必须在声明时初始化，并且一旦绑定到一个变量后，就不能再绑定到其他变量。
- 8.1.2 引用的声明：给变量起别名，`数据类型 &引用名 = 变量名;`
- 8.2.1 引用必须初始化：引用在声明时必须绑定到一个变量，否则会编译错误。
- 8.2.2 引用不能重新绑定：引用一旦绑定到一个变量后，就不能再绑定到其他变量。
- 8.2.3 引用访问数据：通过引用可以访问和修改原变量的值。
- 8.4.1 引用作为函数参数：函数可以返回引用，但必须确保返回的引用指向的变量在函数调用结束后仍然有效。
- 8.4.2 引用作为函数返回值：引用可以作为函数的返回值，但必须确保返回的引用指向有效的内存。
- 8.5.1 常量引用：常量引用（const 引用）用于防止通过引用修改原变量，同时避免拷贝开销。
- 8.6 引用的本质：引用的本质在c++内部实现是一个指针常量。

- 9.3.3 结构体const场景：使用 const 关键字修饰结构体意味着该结构体实例是不可修改的，即其成员变量在声明后不能被修改。

## 13.多线程

- 13.1.1 线程介绍：C++11 引入了标准库支持多线程编程，提供了 `std::thread` 类来创建和管理线程。
- 13.1.2 创建线程：使用 `std::thread` 创建线程，需要传入一个可调用对象（如函数、Lambda 表达式、函数对象等）。
- 13.1.3 等待线程结束：调用 `join()` 会阻塞当前线程，直到目标线程执行完毕。
- 13.1.4 分离线程：使用 `detach()` 将线程与主线程分离，线程在后台独立运行。
- 13.1.5 检查线程：使用 `joinable()` 检查线程是否可以被 `join()` 或 `detach()`。
- 13.2.1 多线程头文件：分别是 `<atomic>, <thread>, <mutex>, <condition_variable>` 和 `<future>`。
- 13.2.2 创建多线程：使用 `std::thread` 创建多个线程，每个线程执行不同的任务。
- 13.2.3 多线程数据竞争：多个线程同时访问共享资源，导致未定义行为。
- 13.2.4 死锁：多个线程互相等待对方释放锁，导致程序无法继续执行。
- 13.3 同步机制：多线程访问共享资源时，需要使用同步机制避免数据竞争。
- 13.3.2 condition_variable：用于线程同步的工具，通常与 `std::mutex` 结合使用，用于实现线程间的等待和通知机制。
- 13.3.3 atomic：原子操作是不可分割的操作，确保在多线程环境下的正确性。

**15.内存分配堆和栈**

- 15.1 如何理解c++内存分区模型：将内存大方向划分为4个区域，代码区，全局区，栈区，堆区
- 15.1.1 如何理解代码区：存储程序的二进制代码（即编译后的机器指令）。
- 15.1.2 如何理解全局区：1.全局变量存储在全局区，2.静态局部变量存储在全局区。特点是在程序启动时分配，程序结束时释放。
- 15.1.3 如何理解栈区：存储局部变量、函数参数、函数返回地址等。一般在函数方法中，比如局部变量存储在栈区，方法调用完后就释放。
- 15.1.4 如何理解堆区：存储动态分配的内存（如 new 和 malloc 分配的内存），这些动态内存需要手动释放
- 15.2.1 什么是动态内存：指程序在运行时（而不是编译时）从堆区（Heap）分配的内存。通过 new 和 delete 操作符来分配和释放内存。
- 15.2.5 如何理解内存泄漏：如果动态分配的内存没有被释放，会导致内存泄漏。解决方法：确保每次 new 都有对应的 delete。
- 15.2.6 如何理解野指针：未初始化的指针称为野指针，访问野指针会导致未定义行为。
- 15.2.7 如何理解悬空指针问题：释放内存后，指针仍然指向已释放的内存地址，称为悬空指针。解决方法：释放内存后将指针置为 nullptr。

### **4. 注意事项**
1. **`#error` 和 `#warning` 的区别**：
    - `#error` 会终止编译过程，而 `#warning` 只会生成警告消息，编译会继续。
2. **跨编译器支持**：
    - `#error` 是所有 C++ 编译器都支持的，但 `#warning` 并非所有编译器都支持（例如 MSVC 不支持 `#warning`）。
    - 在 MSVC 中，可以使用 `#pragma message` 实现类似 `#warning` 的功能。
3. **消息内容**：
    - 错误或警告消息应尽量清晰明确，帮助开发者快速定位问题。

---

### **5. 在 MSVC 中使用 `#pragma message`**
由于 MSVC 不支持 `#warning`，可以使用 `#pragma message` 来生成警告消息。

#### **语法**
```cpp
#pragma message("警告消息")
```

#### **示例**
```cpp
#ifdef DEBUG
#pragma message("Debug mode is enabled. Performance may be affected.")
#endif
```

- 如果 `DEBUG` 宏已定义，编译时会输出消息：
  ```
  message: Debug mode is enabled. Performance may be affected.
  ```

---

### **6. 综合示例**
以下是一个综合使用 `#error`、`#warning` 和 `#pragma message` 的示例：

```cpp
#include <iostream>

// 检查 C++ 版本
#if __cplusplus < 201703L
#error "This code requires C++17 or later."
#endif

// 检查平台支持
#ifndef _WIN32
#warning "This code is optimized for Windows. Other platforms may not be fully supported."
#endif

// 提醒未完成的功能
#pragma message("The feature 'X' is under development and may not work as expected.")

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
```

### **7. 总结**
- `#error` 用于强制终止编译并生成错误消息，适合用于检查不满足的条件。
- `#warning` 用于生成警告消息，适合用于提醒开发者注意潜在问题。
- 在 MSVC 中，可以使用 `#pragma message` 替代 `#warning`。
- 合理使用这些指令可以提高代码的健壮性和可维护性。
