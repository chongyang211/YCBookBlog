## 01.崩溃的原因

### 1.1 内存访问违规

1. 空指针解引用：CPU尝试访问受保护的内存地址0x0，触发硬件异常。

```cpp
int* ptr = nullptr;
*ptr = 42; // 崩溃：访问地址0x0
```

2. 野指针解引用：访问已释放或未初始化的指针。

```cpp
int* ptr = new int(42);
delete ptr;
*ptr = 100; // 崩溃：访问已释放内存
```

崩溃的原理是内存释放后，操作系统可能已将该内存区域标记为不可访问。

3. 缓冲区溢出：数组越界、字符串操作超出分配空间。

```cpp
char buffer[10];
strcpy(buffer, "This string is too long!"); // 崩溃：栈溢出
```

崩溃的原理是写入超出分配内存边界，破坏栈结构或关键数据。

4. 使用已释放的内存：在delete/free后继续使用指针。

```cpp
int* ptr = new int(42);
delete ptr;
delete ptr; // 崩溃：双重释放
```

崩溃的原理是，内存管理器检测到同一内存块被多次释放。对同一内存区域多次调用delete/free。

### 1.2 栈溢出

1. 无限递归或过深的递归导致栈空间耗尽。

```cpp
void recursiveFunction() {
    char buffer[1024]; // 大局部变量
    recursiveFunction(); // 无限递归
}
```

原理：栈空间有限（通常1-8MB），递归深度过大耗尽栈空间

2. 在栈上分配过大的局部变量（如大数组）。

```cpp
void vulnerableFunction(char* input) {
    char buffer[10];
    strcpy(buffer, input); // 无边界检查
}

int main() {
    char largeInput[1000] = {0};
    vulnerableFunction(largeInput); // 破坏栈结构
}
```

原理：缓冲区溢出覆盖返回地址或栈帧指针

### 1.3 整数除零

整数除法中除数为零。

```cpp
int a = 10;
int b = 0;
int c = a / b; // 崩溃：整数除零
```

原理：CPU触发除零异常（x86平台为#DE异常）

### 1.7 多线程问题

死锁、竞争条件、线程间非法访问。

```cpp

void increment() {
    for (int i = 0; i < 1000000; i++) {
        counter++; // 非原子操作
    }
}

    std::thread t1(increment);
    std::thread t2(increment);
```

## 02.崩溃的流程

### 2.1 硬件异常

硬件异常：CPU检测到非法操作（如无效内存访问、除零）会触发中断，内核将中断转换为信号发送给进程。

1. CPU执行非法操作（如访问无效内存地址） 
2. CPU触发硬件中断（如x86的#GP、#PF异常）

### 2.2 信号生成

内核介入：中断处理程序将硬件异常转换为信号，内核向目标进程发送信号（如SIGSEGV、SIGFPE）。常见信号：

1. SIGSEGV（段错误）：无效内存访问 
2. SIGFPE（浮点异常）：算术错误 
3. SIGILL（非法指令）：执行无效指令 
4. SIGBUS（总线错误）：对齐错误

### 2.3 信号处理

信号处理：

1. 如果进程注册了信号处理函数，则执行该函数。 
2. 如果没有注册，则执行默认操作（通常是终止进程并生成核心转储）。

### 2.4 核心转储

核心转储：如果系统配置允许，内核会生成核心转储文件（core dump），包含进程崩溃时的内存状态、寄存器值、堆栈等信息。

### 2.5 进程终止

进程终止：进程被终止，父进程可通过wait系列函数获取退出状态。

## 03.崩溃监听原理

### 3.1 Linux信号处理

```cpp
#include <csignal>
#include <cstdlib>
#include <iostream>
#include <execinfo.h> // 用于获取堆栈跟踪

void signalHandler(int signal) {
    const char* signalName = "Unknown";
    switch(signal) {
        case SIGSEGV: signalName = "SIGSEGV"; break;
        case SIGABRT: signalName = "SIGABRT"; break;
        case SIGFPE: signalName = "SIGFPE"; break;
        case SIGILL: signalName = "SIGILL"; break;
        case SIGBUS: signalName = "SIGBUS"; break;
    }
    std::cerr << "Received signal: " << signalName << " (" << signal << ")" << std::endl;
    
    // 获取堆栈跟踪
    void* array[50];
    size_t size = backtrace(array, 50);
    char** symbols = backtrace_symbols(array, size);
    
    if (symbols) {
        std::cerr << "Stack trace:" << std::endl;
        for (size_t i = 0; i < size; i++) {
            std::cerr << symbols[i] << std::endl;
        }
        free(symbols);
    }
    
    // 生成核心转储
    std::cerr << "Generating core dump..." << std::endl;
    abort(); // 触发核心转储
}

int main() {
    // 注册信号处理函数
    signal(SIGSEGV, signalHandler);
    signal(SIGABRT, signalHandler);
    signal(SIGFPE, signalHandler);
    signal(SIGILL, signalHandler);
    signal(SIGBUS, signalHandler);
    
    // 你的代码
    // ...
    
    return 0;
}
```

### 3.2 C++异常处理

```cpp
#include <exception>
#include <iostream>
#include <stdexcept>

void terminateHandler() {
    std::cerr << "Unhandled exception!" << std::endl;
    
    try {
        // 尝试重新抛出当前异常
        throw;
    } catch (const std::exception& e) {
        std::cerr << "Exception: " << e.what() << std::endl;
    } catch (...) {
        std::cerr << "Unknown exception" << std::endl;
    }
    
    // 生成堆栈跟踪或核心转储
    abort();
}

int main() {
    std::set_terminate(terminateHandler);
    
    try {
        // 你的代码
        // ...
    } catch (const std::exception& e) {
        std::cerr << "Caught exception: " << e.what() << std::endl;
    }
    
    return 0;
}
```
