## 01.前言介绍

### 1.1 JavaScript与浏览器的关系

JavaScript本身只是一门编程语言，它的"能力"来自**宿主环境**提供的API。浏览器是最重要的宿主环境，提供了DOM、BOM、网络、存储等一系列API。

理解浏览器的渲染原理和事件系统，是写出高性能前端应用的基础。

### 1.2 为什么要理解渲染原理

```javascript
// 以下代码会触发几次重排？
element.style.width = '100px';
element.style.height = '200px';
element.style.margin = '10px';
```

如果不了解渲染原理，你可能以为是3次。但现代浏览器有**批处理优化**，实际上可能只触发1次。但如果你在中间读取了布局信息，就会**强制同步布局**，变成3次。

## 03.从URL到页面：完整渲染流程

### 3.1 关键渲染路径

```
HTML → DOM树
              ↘
               → Render Tree → Layout → Paint → Composite → 屏幕
              ↗
CSS → CSSOM树
```

### 3.2 详细步骤

```
1. 导航阶段
   DNS解析 → TCP连接 → TLS握手 → HTTP请求 → 接收响应

2. 解析阶段
   HTML字节流 → 字符 → Token → DOM树
   CSS字节流 → 字符 → Token → CSSOM树

3. 构建渲染树（Render Tree）
   DOM树 + CSSOM树 → 渲染树
   - display:none的元素不在渲染树中
   - 伪元素在渲染树中但不在DOM树中

4. 布局（Layout）
   计算每个元素的精确位置和大小
   - 从根节点开始，递归计算
   - 考虑盒模型、浮动、定位

5. 绘制（Paint）
   将布局结果转换为绘制指令列表
   - 按照堆叠上下文的顺序

6. 合成（Composite）
   将页面分成图层，分别光栅化
   在GPU中合成最终画面
```

### 3.3 阻塞渲染的资源

```html
<!-- CSS阻塞渲染：浏览器必须等CSS下载完才能构建渲染树 -->
<link rel="stylesheet" href="style.css">

<!-- JS阻塞解析：遇到script标签会暂停HTML解析 -->
<script src="app.js"></script>

<!-- async：异步下载，下载完立即执行（不保证顺序） -->
<script async src="analytics.js"></script>

<!-- defer：异步下载，HTML解析完后按顺序执行 -->
<script defer src="app.js"></script>
```

**疑惑**：为什么JS要阻塞HTML解析？

**答疑**：因为JS可以通过`document.write()`修改HTML文档流。如果不阻塞，解析器可能已经往前解析了，但JS又插入了新内容，导致结果不确定。

**结果**：现代实践——用`defer`或将脚本放在`</body>`前。`document.write()`已被废弃。


## 04.DOM树的构建过程

### 4.1 HTML解析过程

```
HTML字节: 3C 68 74 6D 6C 3E ...

字符化:   <html>...

Token化:
  StartTag: html
  StartTag: head
  StartTag: title
  Character: "My Page"
  EndTag: title
  EndTag: head
  StartTag: body
  ...

DOM树构建:
  Document
  └── html
      ├── head
      │   └── title
      │       └── "My Page"
      └── body
          └── ...
```

### 4.2 HTML解析器的容错

HTML解析器非常宽容，能处理各种错误：

```html
<!-- 浏览器能正确处理 -->
<p>Hello
<p>World
<!-- 自动关闭第一个<p>，插入</p> -->

<table>
    <div>This shouldn't be here</div>
    <tr><td>Data</td></tr>
</table>
<!-- div被移到table外面 -->

<html>
<html>  <!-- 第二个html被忽略 -->
```

### 4.3 DOM节点类型

```javascript
Node.ELEMENT_NODE     = 1;   // <div>
Node.TEXT_NODE        = 3;   // 文本内容
Node.COMMENT_NODE     = 8;   // <!-- 注释 -->
Node.DOCUMENT_NODE    = 9;   // document
Node.DOCUMENT_TYPE_NODE = 10; // <!DOCTYPE html>
Node.DOCUMENT_FRAGMENT_NODE = 11; // DocumentFragment
```

### 4.4 DocumentFragment优化

```javascript
// ❌ 差：每次appendChild都触发DOM更新
for (let i = 0; i < 1000; i++) {
    const li = document.createElement('li');
    li.textContent = `Item ${i}`;
    list.appendChild(li);  // 1000次DOM操作
}

// ✅ 好：使用DocumentFragment批量插入
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
    const li = document.createElement('li');
    li.textContent = `Item ${i}`;
    fragment.appendChild(li);  // Fragment在内存中，不触发渲染
}
list.appendChild(fragment);   // 1次DOM操作
```


## 05.CSSOM与样式计算

### 5.1 CSSOM的构建

```css
body { font-size: 16px; }
.container { width: 80%; }
.container p { color: #333; line-height: 1.5; }
```

```
CSSOM树:
StyleSheet
└── Rule: body { font-size: 16px }
└── Rule: .container { width: 80% }
└── Rule: .container p { color: #333; line-height: 1.5 }
```

### 5.2 样式计算（Style Recalculation）

浏览器为每个可见DOM元素计算最终样式：

```
样式计算步骤:
1. 收集所有匹配的CSS规则（选择器匹配）
2. 按照特异性（Specificity）排序
3. 处理继承
4. 处理层叠
5. 将相对值转换为绝对值
   - 80% → 960px
   - 1.5em → 24px
   - red → rgb(255, 0, 0)
```

### 5.3 选择器匹配方向

```css
.container .item .title { color: red; }
```

浏览器匹配选择器是**从右到左**的：

```
1. 找到所有class="title"的元素
2. 检查其祖先中是否有class="item"
3. 再检查更上层是否有class="container"
```

**疑惑**：从右到左不是更慢吗？

**答疑**：从右到左可以更快**排除**不匹配的元素。如果从左到右，先找`.container`，然后遍历所有后代，大部分后代都不是`.item .title`，浪费了遍历时间。从右到左先找`.title`（数量少），再向上验证，更快排除不匹配的路径。


## 06.布局（Layout/Reflow）

### 6.1 布局计算的内容

```
布局阶段计算:
1. 盒模型尺寸
   - content width/height
   - padding, border, margin
   
2. 定位
   - 正常流（Normal Flow）
   - 浮动（Float）
   - 绝对定位（Absolute/Fixed）
   - Flexbox
   - Grid
   
3. 溢出处理
   - overflow: hidden/scroll/auto
```

### 6.2 布局的递归性质

```
布局是自顶向下的递归过程:

1. 父元素确定自己的宽度（通常来自父元素的约束）
2. 遍历子元素：
   - 确定每个子元素的位置（根据display、float、position）
   - 确定每个子元素的宽度
   - 递归计算每个子元素的布局
3. 根据子元素的高度，确定父元素的高度
4. 将所有信息写入布局树
```

### 6.3 触发布局的操作

```javascript
// 读取以下属性会触发同步布局（强制Reflow）
element.offsetWidth
element.offsetHeight
element.offsetTop
element.offsetLeft
element.clientWidth
element.clientHeight
element.scrollTop
element.scrollHeight
element.getComputedStyle()
element.getBoundingClientRect()
```


## 07.绘制（Paint）与合成（Composite）

### 7.1 绘制

布局完成后，浏览器将元素转换为**绘制指令**：

```
绘制指令示例:
1. 绘制背景色
2. 绘制背景图
3. 绘制边框
4. 绘制子元素
5. 绘制文本
6. 绘制轮廓（outline）
```

### 7.2 图层（Layer）

浏览器将页面分成多个图层，每个图层独立绘制：

```
触发创建新图层的条件:
- 有3D变换（transform: translateZ, rotate3d等）
- 使用will-change属性
- video、canvas元素
- 有CSS动画的元素
- position: fixed
- 有overflow:scroll的元素
```

### 7.3 合成

```
合成过程:
1. 将每个图层划分为小块（Tiles）
2. 在光栅化线程中将小块转换为位图（Raster）
3. 合成线程收集所有位图
4. 通过GPU合成最终画面
5. 输出到屏幕

关键优势:
- 合成操作在合成线程进行，不阻塞主线程
- 只有变化的图层需要重新绘制
- GPU擅长合成操作，非常快
```

### 7.4 仅触发合成的属性

```css
/* 这些属性只触发合成，跳过布局和绘制 */
transform: translate(10px, 20px);
opacity: 0.5;

/* 性能最好的动画只使用transform和opacity */
.animated {
    transition: transform 0.3s, opacity 0.3s;
    will-change: transform, opacity;
}
```


## 08.重排与重绘的触发与优化

### 8.1 三种渲染更新路径

```
路径1: JS → Style → Layout → Paint → Composite（重排）
  触发：改变尺寸、位置、添加/删除元素

路径2: JS → Style → Paint → Composite（重绘）
  触发：改变颜色、背景、阴影

路径3: JS → Style → Composite（最优）
  触发：改变transform、opacity
```

### 8.2 强制同步布局（Layout Thrashing）

```javascript
// ❌ 强制同步布局——性能灾难
for (let i = 0; i < elements.length; i++) {
    const width = container.offsetWidth;  // 读取（触发同步布局）
    elements[i].style.width = width + 'px'; // 写入（使布局失效）
    // 下次循环读取offsetWidth时，又要重新布局！
}

// ✅ 读写分离
const width = container.offsetWidth;  // 只读一次
for (let i = 0; i < elements.length; i++) {
    elements[i].style.width = width + 'px';  // 只写
}
// 批量写入后，浏览器在下一帧统一布局
```

### 8.3 使用requestAnimationFrame

```javascript
// ❌ 在事件处理中直接修改DOM
element.addEventListener('scroll', () => {
    element.style.transform = `translateY(${window.scrollY}px)`;
    // 可能在一帧内触发多次
});

// ✅ 使用rAF合并更新
let ticking = false;
element.addEventListener('scroll', () => {
    if (!ticking) {
        requestAnimationFrame(() => {
            element.style.transform = `translateY(${window.scrollY}px)`;
            ticking = false;
        });
        ticking = true;
    }
});
```

### 8.4 批量DOM操作

```javascript
// ❌ 逐个修改
list.style.display = 'none';  // 触发重排
el1.style.width = '100px';
el2.style.height = '200px';
list.style.display = 'block'; // 触发重排

// ✅ 使用class一次性修改
element.classList.add('new-styles');

// ✅ 使用cssText
element.style.cssText = 'width:100px; height:200px; margin:10px;';
```


## 09.事件系统的三阶段模型

### 9.1 事件传播的三个阶段

```
          ┌──── 捕获阶段 ────┐  ┌──── 冒泡阶段 ────┐
          │                  │  │                  │
          ↓                  │  │                  ↑
       window                │  │               window
          ↓                  │  │                  ↑
       document              │  │              document
          ↓                  │  │                  ↑
        <html>               │  │               <html>
          ↓                  │  │                  ↑
        <body>               │  │               <body>
          ↓                  │  │                  ↑
        <div>                │  │               <div>
          ↓                  ↓  ↑                  ↑
        <button> ────────── 目标阶段 ──────── <button>
```

### 9.2 三个阶段详解

**捕获阶段（Capture Phase）**：

```javascript
// 从window向下到目标元素
document.addEventListener('click', handler, true);
// 第三个参数true = 在捕获阶段触发
```

**目标阶段（Target Phase）**：

```javascript
// 在目标元素上触发
// 此时捕获和冒泡的处理器都会按注册顺序触发
button.addEventListener('click', handler1, true);  // 捕获
button.addEventListener('click', handler2, false);  // 冒泡
// 在目标上，按注册顺序执行：handler1, handler2
```

**冒泡阶段（Bubble Phase）**：

```javascript
// 从目标元素向上到window
document.addEventListener('click', handler, false);
// 第三个参数false（默认）= 在冒泡阶段触发
```

### 9.3 历史背景

**疑惑**：为什么有捕获和冒泡两个方向？

**答疑**：这是浏览器战争的遗产。Netscape提出事件捕获（从外到内），IE提出事件冒泡（从内到外）。W3C在DOM Level 2规范中统一了两者，形成了三阶段模型。

### 9.4 阻止传播

```javascript
element.addEventListener('click', (e) => {
    e.stopPropagation();
    // 停止事件继续传播（包括捕获和冒泡）
    // 但同一元素上的其他处理器仍会执行
});

element.addEventListener('click', (e) => {
    e.stopImmediatePropagation();
    // 停止传播，且同一元素上后续的处理器也不执行
});
```

### 9.5 不冒泡的事件

```javascript
// 以下事件不冒泡
'focus'     // 聚焦（使用focusin可冒泡）
'blur'      // 失焦（使用focusout可冒泡）
'mouseenter' // 鼠标进入（使用mouseover可冒泡）
'mouseleave' // 鼠标离开（使用mouseout可冒泡）
'load'      // 加载完成
'unload'    // 卸载
'resize'    // 窗口大小变化
'scroll'    // 滚动（在某些元素上冒泡）
```


## 10.事件委托的原理与实现

### 10.1 什么是事件委托

利用事件冒泡，在父元素上统一处理子元素的事件：

```javascript
// ❌ 给每个子元素绑定事件
const items = document.querySelectorAll('.item');
items.forEach(item => {
    item.addEventListener('click', handleClick);
});
// 1000个元素 = 1000个事件处理器 = 大量内存

// ✅ 事件委托
document.querySelector('.list').addEventListener('click', (e) => {
    const item = e.target.closest('.item');
    if (item) handleClick(item);
});
// 1个事件处理器，无论多少子元素
```

### 10.2 通用委托函数

```javascript
function delegate(parent, selector, eventType, handler) {
    parent.addEventListener(eventType, (e) => {
        const target = e.target.closest(selector);
        if (target && parent.contains(target)) {
            handler.call(target, e);
        }
    });
}

// 使用
delegate(document.body, '.btn', 'click', function(e) {
    console.log('按钮被点击:', this.textContent);
});
```

### 10.3 事件委托的优势

1. **内存效率**：减少事件处理器数量
2. **动态元素**：新添加的子元素自动被处理
3. **批量管理**：一个处理器管理所有子元素

### 10.4 不适合委托的场景

```javascript
// 不冒泡的事件不能委托
// focus/blur → 使用focusin/focusout
// mouseenter/mouseleave → 使用mouseover/mouseout

// 需要精确target的场景
// 如拖拽操作，需要在特定元素上追踪mousemove
```

### 11.2 MutationObserver

```javascript
// 监控DOM变化
const observer = new MutationObserver((mutations) => {
    for (const mutation of mutations) {
        if (mutation.type === 'childList') {
            console.log('子节点变化');
        } else if (mutation.type === 'attributes') {
            console.log('属性变化:', mutation.attributeName);
        }
    }
});

observer.observe(element, {
    childList: true,     // 子节点增删
    attributes: true,    // 属性变化
    subtree: true,       // 监控所有后代
    characterData: true  // 文本内容变化
});

// 停止观察
observer.disconnect();
```

### 11.3 IntersectionObserver

```javascript
// 元素可见性检测（替代scroll事件监听）
const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
        if (entry.isIntersecting) {
            // 元素进入视口
            loadImage(entry.target);
            observer.unobserve(entry.target);
        }
    });
}, {
    rootMargin: '100px',  // 提前100px触发
    threshold: 0.1         // 10%可见时触发
});

// 懒加载图片
document.querySelectorAll('img[data-src]').forEach(img => {
    observer.observe(img);
});
```

### 11.4 ResizeObserver

```javascript
// 元素尺寸变化检测（替代window.resize）
const observer = new ResizeObserver((entries) => {
    for (const entry of entries) {
        const { width, height } = entry.contentRect;
        console.log(`元素大小: ${width}x${height}`);
    }
});

observer.observe(element);
```

## 12.现代渲染优化技术

### 12.1 CSS Containment

```css
/* contain告诉浏览器，元素的变化不影响外部 */
.widget {
    contain: layout;  /* 布局变化不影响外部 */
    contain: paint;   /* 绘制不溢出边界 */
    contain: size;    /* 尺寸不依赖子元素 */
    contain: strict;  /* 以上全部 */
    contain: content; /* layout + paint */
}

/* content-visibility自动跳过屏幕外元素的渲染 */
.list-item {
    content-visibility: auto;
    contain-intrinsic-size: 200px;  /* 预估高度 */
}
```

### 12.2 will-change

```css
/* 告诉浏览器元素即将变化，提前创建图层 */
.animated {
    will-change: transform;
}

/* 注意：不要滥用，每个图层消耗内存 */
/* 应该在动画开始前添加，结束后移除 */
```

```javascript
element.addEventListener('mouseenter', () => {
    element.style.willChange = 'transform';
});
element.addEventListener('transitionend', () => {
    element.style.willChange = 'auto';
});
```

### 12.3 Web Worker卸载计算

```javascript
// 将耗时计算移到Worker线程，避免阻塞渲染
const worker = new Worker('heavy-calc.js');

worker.postMessage({ data: largeDataSet });

worker.onmessage = (e) => {
    const result = e.data;
    updateUI(result);  // 在主线程更新UI

```

### 12.4 OffscreenCanvas

```javascript
// 在Worker中进行Canvas渲染
const offscreen = canvas.transferControlToOffscreen();
const worker = new Worker('canvas-worker.js');
worker.postMessage({ canvas: offscreen }, [offscreen]);
```

### 12.6 总结：DOM事件与渲染核心要点

1. **渲染管线**：DOM → CSSOM → Render Tree → Layout → Paint → Composite
2. **重排最昂贵**——改变尺寸和位置触发，尽量避免
3. **重绘次之**——改变外观但不影响布局
4. **合成最便宜**——只有transform和opacity可以做到
5. **CSS选择器从右向左匹配**——避免过深的嵌套
6. **事件三阶段**：捕获 → 目标 → 冒泡
7. **事件委托**利用冒泡在父元素统一处理
8. **强制同步布局**是性能杀手——读写分离
9. **Observer API**替代轮询——Intersection/Mutation/Resize
10. **content-visibility**可以自动跳过屏幕外元素的渲染
