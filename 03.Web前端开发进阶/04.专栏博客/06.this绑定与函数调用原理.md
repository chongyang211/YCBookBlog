## 01.前言介绍

### 1.1 this是JavaScript最令人困惑的特性之一

```javascript
const obj = {
    name: "Alice",
    greet() {
        console.log(this.name);
    }
};

obj.greet();          // "Alice"
const fn = obj.greet;
fn();                 // undefined（严格模式）或 ""（非严格模式，window.name）
```

同一个函数，不同的调用方式，`this`指向完全不同。这是很多bug的根源。

### 1.2 疑惑：为什么this不在定义时确定

Java/C++中的`this`总是指向当前实例，在编译时就能确定。为什么JavaScript的`this`要在运行时确定？

**答疑**：JavaScript的函数是**一等公民**——可以被赋值给变量、作为参数传递、作为返回值。函数不绑定到任何对象，它可以被任何对象调用。因此`this`必须在调用时动态确定。

**结果**：`this`不是"函数属于谁"，而是"函数被谁调用"。


## 02.this的本质：调用点决定

### 2.1 调用点（Call Site）

决定`this`指向的关键是**调用点**——函数在代码中被调用的位置。

```javascript
function foo() {
    // 调用栈: global → foo
    console.log(this);
}

function bar() {
    // 调用栈: global → bar
    foo();  // 调用点：在bar中
}

bar();  // 调用点：在全局中
```

### 2.2 四种绑定规则

```
this的绑定规则（按优先级从低到高）:

1. 默认绑定（Default Binding）
   → 独立函数调用
   → this = 全局对象（非严格模式）或 undefined（严格模式）

2. 隐式绑定（Implicit Binding）
   → 作为对象方法调用
   → this = 该对象

3. 显式绑定（Explicit Binding）
   → call/apply/bind
   → this = 指定的对象

4. new绑定（New Binding）
   → new构造调用
   → this = 新创建的对象
```


## 03.默认绑定

### 3.1 非严格模式

```javascript
function foo() {
    console.log(this);  // window（浏览器）或 global（Node.js）
}

foo();  // 独立调用，没有任何对象引用

var a = 42;
function bar() {
    console.log(this.a);  // 42（this指向window，window.a = 42）
}
bar();
```

### 3.2 严格模式

```javascript
"use strict";

function foo() {
    console.log(this);  // undefined
}

foo();

// 注意：只有函数体内的严格模式才影响this
function bar() {
    console.log(this);  // window（bar自身不是严格模式）
}

(function() {
    "use strict";
    bar();  // 调用点在严格模式中，但bar本身不是严格模式
    // this仍然是window（取决于bar的定义，不是调用点的模式）
})();
```

实际上严格模式的判定规则是：**函数自身是否在严格模式下定义**。


## 04.隐式绑定与隐式丢失

### 4.1 隐式绑定

```javascript
const obj = {
    name: "Alice",
    greet() {
        console.log(this.name);
    }
};

obj.greet();  // "Alice" — obj调用greet，this指向obj
```

### 4.2 链式调用中只看最后一层

```javascript
const obj1 = {
    obj2: {
        name: "Bob",
        greet() {
            console.log(this.name);
        }
    }
};

obj1.obj2.greet();  // "Bob"（this指向obj2，不是obj1）
```

### 4.3 隐式丢失

这是最常见的`this`陷阱：

```javascript
const obj = {
    name: "Alice",
    greet() {
        console.log(this.name);
    }
};

// 陷阱1：赋值给变量
const fn = obj.greet;
fn();  // undefined（this丢失，变成默认绑定）

// 陷阱2：作为回调传递
function doSomething(callback) {
    callback();  // 这里是独立调用，不是obj.callback()
}
doSomething(obj.greet);  // undefined

// 陷阱3：setTimeout
setTimeout(obj.greet, 100);  // undefined
// 等价于：const fn = obj.greet; setTimeout(fn, 100);

// 陷阱4：数组方法
const fns = [obj.greet];
fns[0]();  // undefined（数组元素是函数引用，不是方法调用）
```

### 4.4 解决隐式丢失

```javascript
// 方案1：包装函数
setTimeout(() => obj.greet(), 100);  // "Alice"

// 方案2：bind
setTimeout(obj.greet.bind(obj), 100);  // "Alice"

// 方案3：箭头函数（在类中使用）
class User {
    name = "Alice";
    greet = () => {
        console.log(this.name);  // 词法this，永远指向实例
    };
}
```


## 05.显式绑定：call/apply/bind

### 5.1 call和apply

```javascript
function greet(greeting, punctuation) {
    console.log(`${greeting}, ${this.name}${punctuation}`);
}

const user = { name: "Alice" };

greet.call(user, "Hello", "!");     // "Hello, Alice!"
greet.apply(user, ["Hello", "!"]);  // "Hello, Alice!"

// call和apply的唯一区别是参数传递方式
// call: 参数逐个传递
// apply: 参数以数组形式传递
```

### 5.2 bind

```javascript
function greet(greeting) {
    console.log(`${greeting}, ${this.name}`);
}

const user = { name: "Alice" };
const boundGreet = greet.bind(user);

boundGreet("Hello");  // "Hello, Alice"
boundGreet("Hi");     // "Hi, Alice"

// bind返回一个新函数，this被永久绑定
// 即使再次call/apply也无法改变
boundGreet.call({ name: "Bob" }, "Hey");  // "Hey, Alice"（仍然是Alice）
```

### 5.3 bind的偏函数应用

```javascript
function multiply(a, b) {
    return a * b;
}

const double = multiply.bind(null, 2);  // 固定第一个参数为2
double(5);   // 10
double(10);  // 20

const triple = multiply.bind(null, 3);
triple(5);   // 15
```

### 5.4 显式绑定null/undefined

```javascript
function foo() {
    console.log(this);
}

// 传null或undefined时：
// 非严格模式：this变为全局对象
// 严格模式：this就是null/undefined

foo.call(null);       // window（非严格）或 null（严格）
foo.call(undefined);  // window（非严格）或 undefined（严格）

// 安全的做法：传入空对象
const empty = Object.create(null);
foo.call(empty);  // {} 不影响全局
```


## 06.new绑定

### 6.1 new的四步骤与this

```javascript
function Person(name) {
    // 1. 创建新对象 {}
    // 2. 新对象的[[Prototype]]设为Person.prototype
    // 3. this绑定到新对象
    this.name = name;  // 给新对象添加属性
    // 4. 如果没有return对象，返回新对象
}

const alice = new Person("Alice");
alice.name;  // "Alice"
```

### 6.2 return的影响

```javascript
function Foo() {
    this.a = 1;
    return { b: 2 };  // 返回对象
}
const foo = new Foo();
foo.a;  // undefined（新对象被丢弃了）
foo.b;  // 2

function Bar() {
    this.a = 1;
    return 42;  // 返回原始值
}
const bar = new Bar();
bar.a;  // 1（原始值返回被忽略）
```

### 6.3 new.target

```javascript
function Foo() {
    if (!new.target) {
        throw new Error('Foo must be called with new');
    }
    this.name = "foo";
}

Foo();      // Error: Foo must be called with new
new Foo();  // { name: "foo" }

// 在class中，new.target指向被new调用的构造函数
class Parent {
    constructor() {
        console.log(new.target.name);
    }
}
class Child extends Parent {}

new Parent();  // "Parent"
new Child();   // "Child"（new.target是Child，不是Parent）
```


## 07.箭头函数的词法this

### 7.1 箭头函数没有自己的this

```javascript
const obj = {
    name: "Alice",
    
    // 普通函数：this取决于调用方式
    regular() {
        console.log(this.name);
    },
    
    // 箭头函数：this继承自定义时的外部作用域
    arrow: () => {
        console.log(this.name);  // this是定义时外层的this（全局/模块）
    },
    
    // 嵌套的箭头函数
    delayed() {
        setTimeout(() => {
            console.log(this.name);  // this继承自delayed的this
        }, 100);
    }
};

obj.regular();   // "Alice"
obj.arrow();     // undefined（this是全局对象）
obj.delayed();   // "Alice"（箭头函数继承了delayed中的this=obj）
```

### 7.2 箭头函数的底层原理

箭头函数在引擎内部通过`[[Environment]]`捕获外层的`this`：

```javascript
// 箭头函数没有[[Construct]]，不能new
const Arrow = () => {};
new Arrow();  // TypeError

// 箭头函数没有arguments
const fn = () => {
    console.log(arguments);  // ReferenceError（严格模式）或外层arguments
};

// 箭头函数没有prototype
const F = () => {};
F.prototype;  // undefined

// call/apply/bind无法改变箭头函数的this
const arrow = () => this;
arrow.call({ x: 1 });  // 仍然是外层的this
```

### 7.3 何时使用箭头函数

```javascript
// ✅ 回调函数
arr.map(item => item.name);
setTimeout(() => this.save(), 100);
element.addEventListener('click', () => this.handleClick());

// ✅ 简单的转换函数
const double = x => x * 2;
const isPositive = n => n > 0;

// ❌ 对象方法
const obj = {
    name: "Alice",
    greet: () => console.log(this.name)  // this不是obj！
};

// ❌ 构造函数
const Person = (name) => { this.name = name; };  // 不能new

// ❌ 需要arguments的函数
const sum = () => [...arguments].reduce((a, b) => a + b);  // arguments不可用

// ❌ 动态上下文的回调
button.addEventListener('click', () => {
    this;  // 不是button，是外层this
});
// 应该用普通函数如果需要this指向button
```


## 08.绑定优先级

### 8.1 优先级排序

```
new绑定 > 显式绑定 > 隐式绑定 > 默认绑定
```

### 8.2 证明：new > 显式绑定

```javascript
function foo(a) {
    this.a = a;
}

const obj = {};
const bound = foo.bind(obj);
bound(2);
console.log(obj.a);  // 2（bind生效，this=obj）

const instance = new bound(3);
console.log(obj.a);     // 2（没变）
console.log(instance.a); // 3（new覆盖了bind的this）
```

### 8.3 证明：显式 > 隐式

```javascript
function foo() {
    console.log(this.a);
}

const obj1 = { a: 1, foo };
const obj2 = { a: 2 };

obj1.foo();           // 1（隐式绑定）
obj1.foo.call(obj2);  // 2（显式覆盖隐式）
```

### 8.4 完整的判断流程

```
判断this的值:

1. 是否是箭头函数？
   → 是：this = 定义时外层作用域的this（不能更改）
   
2. 是否是new调用？
   → 是：this = 新创建的对象
   
3. 是否使用call/apply/bind？
   → 是：this = 指定的对象
   
4. 是否作为对象方法调用？
   → 是：this = 该对象
   
5. 以上都不是？
   → 严格模式：this = undefined
   → 非严格模式：this = 全局对象
```


## 09.手写实现call/apply/bind

### 9.1 实现call

```javascript
Function.prototype.myCall = function(context, ...args) {
    // 处理null和undefined
    if (context === null || context === undefined) {
        context = globalThis;
    }
    
    // 将原始类型包装为对象
    context = Object(context);
    
    // 用Symbol避免属性冲突
    const fnKey = Symbol('fn');
    
    // 将函数设为context的方法
    context[fnKey] = this;
    
    // 调用（此时函数内的this就是context）
    const result = context[fnKey](...args);
    
    // 清理临时属性
    delete context[fnKey];
    
    return result;
};

// 验证
function greet(greeting) { return `${greeting}, ${this.name}`; }
greet.myCall({ name: "Alice" }, "Hello");  // "Hello, Alice"
```

### 9.2 实现apply

```javascript
Function.prototype.myApply = function(context, argsArray) {
    if (context === null || context === undefined) {
        context = globalThis;
    }
    context = Object(context);
    
    const fnKey = Symbol('fn');
    context[fnKey] = this;
    
    const result = argsArray 
        ? context[fnKey](...argsArray) 
        : context[fnKey]();
    
    delete context[fnKey];
    return result;
};
```

### 9.3 实现bind

```javascript
Function.prototype.myBind = function(context, ...boundArgs) {
    const originalFn = this;
    
    function boundFunction(...callArgs) {
        // 如果是new调用，this指向新实例（忽略bind的context）
        const thisArg = this instanceof boundFunction ? this : context;
        return originalFn.apply(thisArg, [...boundArgs, ...callArgs]);
    }
    
    // 维护原型链（使得new bound()的实例仍然能访问原函数prototype上的方法）
    if (originalFn.prototype) {
        boundFunction.prototype = Object.create(originalFn.prototype);
    }
    
    return boundFunction;
};

// 验证
function Person(name, age) {
    this.name = name;
    this.age = age;
}

const BoundPerson = Person.myBind(null, "Alice");
const p = new BoundPerson(25);
console.log(p.name);  // "Alice"
console.log(p.age);   // 25
console.log(p instanceof Person);  // true
```


## 10.函数的内部属性

### 10.1 [[Call]]和[[Construct]]

每个函数对象都有`[[Call]]`内部方法（通过`()`调用时触发）。有些函数还有`[[Construct]]`方法（通过`new`调用时触发）。

```javascript
// 普通函数：同时有[[Call]]和[[Construct]]
function Foo() {}
Foo();      // [[Call]]
new Foo();  // [[Construct]]

// 箭头函数：只有[[Call]]
const bar = () => {};
bar();      // [[Call]]
new bar();  // TypeError（没有[[Construct]]）

// class constructor：只有[[Construct]]
class Baz {}
Baz();      // TypeError（没有[[Call]]可直接调用）
new Baz();  // [[Construct]]
```

### 10.2 arguments对象

```javascript
function foo(a, b, c) {
    console.log(arguments);       // [1, 2, 3]（类数组对象）
    console.log(arguments.length); // 3
    console.log(arguments.callee); // foo（非严格模式）
    
    // 转为真正的数组
    const arr1 = Array.from(arguments);
    const arr2 = [...arguments];
    const arr3 = Array.prototype.slice.call(arguments);
}

foo(1, 2, 3);
```

### 10.3 length属性

```javascript
function foo(a, b, c) {}
foo.length;  // 3（形参个数）

function bar(a, b = 1, c) {}
bar.length;  // 1（第一个默认参数之前的参数个数）

function baz(a, ...rest) {}
baz.length;  // 1（rest参数不计入）
```

### 10.4 name属性

```javascript
function foo() {}
foo.name;  // "foo"

const bar = function() {};
bar.name;  // "bar"（从变量名推断）

const baz = function qux() {};
baz.name;  // "qux"（使用函数自身的名称）

const obj = {
    method() {},
    get prop() {}
};
obj.method.name;  // "method"
// getter的name: "get prop"

(new Function()).name;  // "anonymous"
(() => {}).name;        // ""
```

### 10.5 caller（已废弃）

```javascript
function outer() {
    inner();
}

function inner() {
    console.log(inner.caller);  // outer（非严格模式）
    // 严格模式下访问caller会报TypeError
}
```

`caller`已被废弃，不应在生产代码中使用。

### 10.6 函数调用的V8内部流程

当你调用一个函数时，V8引擎内部经历了以下精密的步骤：

```
函数调用 f(arg1, arg2) 在V8中的完整流程:

1. 类型检查
   → 检查f是否是可调用对象（有[[Call]]内部方法）
   → 如果不可调用，抛出TypeError: f is not a function

2. 准备调用帧（Call Frame）
   → 保存当前执行上下文（返回地址、寄存器状态）
   → 创建新的栈帧

3. 参数处理
   → 评估参数表达式（从左到右）
   → 将参数推入栈帧
   → 参数数量不匹配时：
     - 多余的参数可通过arguments访问
     - 不足的参数填充undefined

4. this绑定决议
   → 根据调用方式确定this值（四种规则）
   → 非严格模式下对this进行包装（Boxing）
     null/undefined → globalThis
     原始值 → 包装对象

5. 创建执行上下文
   → 建立VariableEnvironment和LexicalEnvironment
   → 绑定this值
   → 处理变量/函数声明的提升

6. 执行函数体
   → Ignition逐条执行字节码
   → 收集类型反馈信息（Type Feedback）
   → 热点函数触发TurboFan优化编译

7. 返回处理
   → 获取返回值（无return语句时返回undefined）
   → 销毁当前栈帧
   → 恢复调用方的执行上下文
   → 将返回值交给调用方
```

**this的Boxing（包装）原理**——这解释了一个微妙的行为：

```javascript
function showThis() {
    console.log(typeof this);
}

// 非严格模式
showThis.call(42);        // "object"（42被包装成Number对象）
showThis.call("hello");   // "object"（"hello"被包装成String对象）
showThis.call(true);      // "object"（true被包装成Boolean对象）
showThis.call(null);      // "object"（null被替换为globalThis）

// 严格模式
"use strict";
function showThisStrict() {
    console.log(typeof this);
}
showThisStrict.call(42);      // "number"（不包装）
showThisStrict.call(null);    // "object"（null本身）
showThisStrict.call(undefined); // "undefined"
```

这就是为什么ECMAScript规范在`OrdinaryCallBindThis`步骤中区分了严格模式和非严格模式——非严格模式下的this永远是对象类型，这是一个有意的设计，保证了`this.xxx`的属性访问在非严格模式下不会因为this是原始值而报错。

### 10.7 函数的prototype属性与__proto__的关系

这是最容易混淆的概念之一，需要从V8内部视角理解：

```javascript
function Foo() {}

// Foo作为对象，有__proto__（指向Function.prototype）
Foo.__proto__ === Function.prototype;  // true

// Foo作为构造函数，有prototype属性
// 这个prototype是给new Foo()创建的实例用的
Foo.prototype;  // { constructor: Foo }

// 二者完全不同的用途
// __proto__: Foo自己的原型链（作为对象时的继承链）
// prototype: Foo的实例的原型链模板

// 当执行 new Foo() 时:
const instance = new Foo();
instance.__proto__ === Foo.prototype;  // true
// 实例的__proto__指向构造函数的prototype

// 函数的双重身份示意图:
//
// Foo (函数对象)
//  ├── __proto__ → Function.prototype → Object.prototype → null
//  │   （Foo作为对象的继承链）
//  │
//  └── prototype → { constructor: Foo }
//      （Foo作为构造函数，给实例用的模板）
//          ↑
//     instance.__proto__
```


## 11.尾调用优化

### 11.1 什么是尾调用

尾调用是指函数的**最后一个动作**是调用另一个函数：

```javascript
// 尾调用
function foo() {
    return bar();  // bar的返回值直接作为foo的返回值
}

// 不是尾调用
function foo() {
    const result = bar();
    return result;  // 最后的动作是return，不是调用
}

// 不是尾调用
function foo() {
    return bar() + 1;  // 最后的动作是加法，不是调用
}

// 不是尾调用
function foo() {
    bar();  // bar之后还有隐式的return undefined
}
```

### 11.2 尾调用优化（TCO）

正常的函数调用会创建新的栈帧。如果引擎检测到尾调用，可以复用当前栈帧：

```javascript
// 无优化：每次递归创建新栈帧
function factorial(n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // 不是尾调用（还要乘以n）
}
// 调用栈增长到n层

// 尾调用优化形式
function factorial(n, acc = 1) {
    if (n <= 1) return acc;
    return factorial(n - 1, n * acc);  // 尾调用
}
// 如果引擎支持TCO，调用栈保持常数大小
```

### 11.3 TCO的支持现状

```
Safari (JSC)：完全支持TCO ✅
V8 (Chrome/Node)：不支持通用TCO ❌
SpiderMonkey (Firefox)：不支持TCO ❌
```

V8团队认为TCO会使调试困难（调用栈中看不到中间帧），因此选择不实现。

**替代方案——Trampoline**：

```javascript
function trampoline(fn) {
    return function(...args) {
        let result = fn.apply(this, args);
        while (typeof result === 'function') {
            result = result();
        }
        return result;
    };
}

const factorial = trampoline(function f(n, acc = 1) {
    if (n <= 1) return acc;
    return () => f(n - 1, n * acc);  // 返回thunk，不是直接递归
});

factorial(100000);  // 不会栈溢出
```


## 12.函数式编程中的this

### 12.1 纯函数不需要this

```javascript
// 函数式风格：不依赖this
const add = (a, b) => a + b;
const multiply = (a, b) => a * b;

// 组合
const compose = (...fns) => x => fns.reduceRight((acc, fn) => fn(acc), x);
const pipe = (...fns) => x => fns.reduce((acc, fn) => fn(acc), x);

const transform = pipe(
    x => x * 2,
    x => x + 1,
    x => x.toString()
);

transform(5);  // "11"
```

### 12.2 柯里化

```javascript
function curry(fn) {
    const arity = fn.length;
    return function curried(...args) {
        if (args.length >= arity) {
            return fn(...args);
        }
        return (...moreArgs) => curried(...args, ...moreArgs);
    };
}

const add = curry((a, b, c) => a + b + c);
add(1)(2)(3);     // 6
add(1, 2)(3);     // 6
add(1)(2, 3);     // 6

// 实际应用
const map = curry((fn, arr) => arr.map(fn));
const filter = curry((fn, arr) => arr.filter(fn));

const doubleAll = map(x => x * 2);
const evens = filter(x => x % 2 === 0);

doubleAll([1, 2, 3]);      // [2, 4, 6]
evens([1, 2, 3, 4, 5]);    // [2, 4]
```

### 12.3 函数组合中避免this问题

```javascript
// 使用闭包代替this
function createCounter(initial = 0) {
    let count = initial;
    
    return {
        increment: () => ++count,
        decrement: () => --count,
        getCount: () => count,
        reset: () => { count = initial; }
    };
}

const counter = createCounter();
const { increment, getCount } = counter;
// 解构后不丢失状态（因为用的是闭包，不是this）
increment();
increment();
getCount();  // 2
```

### 12.4 总结：this的核心要点

1. **this在调用时确定**——不是定义时
2. **四种绑定规则**：new > 显式 > 隐式 > 默认
3. **箭头函数继承外层this**——无法通过call/apply/bind改变
4. **隐式丢失**是最常见的陷阱——赋值、回调、setTimeout
5. **bind返回永久绑定的新函数**——连new都只能部分覆盖
6. **严格模式下默认绑定是undefined**——不是全局对象
7. **函数式编程尽量不用this**——用闭包和纯函数代替
