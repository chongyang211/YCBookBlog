# 卷二 · 综合案例总导读

> 本卷是**卷一《语法卷》**的配套实战篇。学完卷一 17 章基础语法后，通过 11 个循序渐进的项目把散落的知识点串起来，形成"能独立写项目"的能力。

---

## 01.定位与使用方式

本卷的每一篇都按**"照着写 · 抄得懂 · 改得动"**三个层次设计：

1. **照着写**：每个小节先给需求、再给代码片段，读者跟着键入即可跑通。
2. **抄得懂**：代码后必有"为什么这样写 / 关键机制原理"小节，回答"C++ 为什么不能像 Python 那样随手写"。
3. **改得动**：每篇结尾留 2-3 个"延伸挑战"，鼓励读者用新学的特性重构。

> **声明**：本卷代码风格以 **C++17** 为基线，兼容 C++20/23 新特性（会明确标注）；编译器建议 GCC ≥ 10 / Clang ≥ 12 / MSVC ≥ 19.30；构建系统推荐 CMake ≥ 3.16。

### 5.2 代码风格

| 项目 | 约定 |
|------|------|
| 命名 | 类 `PascalCase`、函数/变量 `camelCase`、常量 `UPPER_SNAKE`、成员后缀无 `_`（避免与用户 C 习惯冲突） |
| 命名空间 | 教学代码用 `using namespace std;` 简化；工程代码（07/08/09/10/11）明确写 `std::` |
| 头文件保护 | `#pragma once`（现代写法） |
| 空指针 | 一律 `nullptr`，禁止 `NULL` / `0` |
| 内存 | 卷二前半段允许裸 `new/delete` 作为反面教材；后半段（09 起）全面 RAII |
| 标准 | 基线 C++17；用到 C++20 特性会标注 `🆕 C++20` |
| 错误处理 | 用户输入校验用**返回码**；资源/越界/解析失败用**异常** |

### 5.3 术语统一

| 术语 | 本卷统一译法 |
|------|------------|
| member function | 成员函数（不用"方法"） |
| instance | 对象（不用"实例"，除了 STL 章） |
| pointer | 指针（裸指针用"raw pointer"） |
| smart pointer | 智能指针 |
| lambda | Lambda 表达式（首字母大写） |

## 06.常见疑问 FAQ

**Q1：为什么有些案例（01/04）仍然用 `struct` 和裸数组？**

A：卷一第 5 章先讲 `struct`，第 9 章才讲 `class`。01/04 故意保留"C 风格 C++"作为历史对照，让读者在 02/03 看到"类化"后的同一问题，体会封装的价值。

**Q2：为什么 03/06 里还有 `new Employee[N]` 这样的裸指针？**

A：这两个案例的**主题是多态**，卷一第 10 章刚学完，此时还没学 RAII（第 12 章）。我们保留裸指针版本，等第 11 案例 JSON 序列化器再统一升级为 `std::unique_ptr<Node>`，让读者亲眼看到"同一份代码，RAII 版本少了多少行 `delete`"。

**Q3：并发三连（07/08/09）之间是什么关系？**

A：
- **07 票务**：多线程最基础——几个 `thread` + 一把 `mutex`，看到"为什么并发不安全"。
- **08 轮询**：单线程定时器 + 策略模式，看到"`std::function` + 抽象接口"的威力。
- **09 线程池**：前两者的融合——多线程 + 任务队列 + `future`，把 07 的裸 `thread` 升级为工程级组件。

**Q4：10 和 11 和前 9 个有什么不同？**

A：前 9 个是"业务模拟"（能跑就行）；10 和 11 是"工具型"（为别的项目服务），更贴近真实工程师在做的事——**写一个工具给别人用**。这也是"从学习者到工程师"的最后一跃。
