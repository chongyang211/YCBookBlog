## 01.轮训管理系统

### 1.1 产品需求

主要功能：

1. 可以灵活设置轮询的时间（例如固定间隔、动态调整间隔等）
2. 暴露一个doAction接口，用于执行用户定义的任务
3. 支持启动、停止、暂停、继续等操作、
4. 支持任务执行超时监控
5. 支持任务执行结果的回调或记录
6. 支持多线程（轮询在一个线程，任务执行可以在另一个线程或线程池）
7. 异常处理

### 1.2 设计核心思路

我们将设计一个Polling类，它包含以下主要部分：

- 配置：轮询间隔（可以是固定值，也可以是动态计算的函数）、任务超时时间等。 
- 状态：运行状态（运行、暂停、停止） 
- 线程：轮询线程，用于定时触发任务。 
- 任务执行：使用一个线程池来执行任务，避免任务执行时间过长影响下一次轮询。 
- 超时监控：为每个任务设置超时，超时则取消任务（如何取消是一个难点，这里我们可以使用future和超时等待）

### 1.3 开发的步骤

1. 定义轮询器的配置结构（包含轮询间隔、超时时间等）
2. 定义轮询器的状态枚举
3. 实现轮询器类，包含启动、停止、暂停、继续等方法
4. 实现轮询线程函数，其中使用条件变量等待，并可以响应暂停和停止
5. 实现任务执行部分，使用线程池执行任务，并监控超时
6. 添加统计信息记录
7. 异常处理

### 1.5 核心组件说明

类名：PollingEngine ，成员：

∙ 配置：PollingConfig
∙ 状态：PollingState
∙ 互斥锁和条件变量：用于控制暂停和继续
∙ 线程：轮询线程
∙ 任务：std::function<void()> 用户定义的任务
∙ 线程池：我们使用一个简单的线程池（为了代码量，我们自己实现一个简单的线程池，或者使用std::async，但为了控制超时，我们使用std::async并配合future等待超时）

由于需要超时控制，我们可能不采用线程池，而是每次启动一个线程（或者使用std::async）来执行任务，然后等待其完成，如果超时则丢弃（但无法真正停止任务，只能等待任务自然结束，或者使用其他方法中断，但C++标准没有提供中断线程的方法，所以超时后我们只能标记超时，任务还会继续运行直到完成，但我们不再关心其结果）。

考虑到任务可能长时间运行，我们决定使用线程池，并且每个任务提交到线程池，然后轮询线程等待一段时间（超时时间）来获取结果。如果超时，则记录超时，但任务仍在后台运行。这样可能会累积任务，所以我们需要限制任务队列的长度，或者丢弃新任务（但这里我们只轮询一个任务，所以每次轮询只触发一个任务，下一个任务必须等待上一个任务完成？不，我们允许任务重叠，即如果任务执行时间很长，而轮询间隔很短，那么任务会并行执行。如果不想并行，我们可以设置最大并发数为1，即线程池只有一个线程，这样任务会排队执行。

因此，我们设计一个线程池，它可以设置线程数量。如果设置为1，则任务顺序执行（即不会并行）；如果大于1，则可能并行。

线程池功能：

∙ 构造函数创建固定数量的线程。
∙ 提交任务（返回future）
∙ 关闭线程池（等待所有任务完成）

### 1.6 功能丰富

1. 轮询间隔策略：固定间隔、指数退避、随机间隔等。
2. 任务队列：支持多个任务，每个任务有自己的执行时间和超时时间（但题目要求暴露一个doAction，所以这里我们简化，只执行一个任务，但可以扩展）
3. 统计信息：记录任务执行次数、成功次数、失败次数、超时次数等。

### 1.7 轮训工作流程

1. 启动后，在轮询线程中循环，直到停止。
2. 每次循环开始，检查状态：如果暂停，则等待条件变量；如果停止，则退出。
3. 计算下一次轮询需要等待的时间（根据策略，可能是固定间隔，也可能是动态的，比如根据上次任务执行结果调整）
4. 等待这段时间（使用条件变量等待，这样可以在暂停或停止时被唤醒）
5. 等待结束后，如果状态是运行，则提交任务到线程池，并记录提交时间。
6. 使用future等待任务完成，并设置超时时间。如果在超时时间内完成，则记录结果；如果超时，则记录超时，但任务仍在后台运行（我们无法取消，只能丢弃future，任务继续运行，但我们不再关心）。
7. 根据任务执行结果，可能调整轮询间隔（例如，如果任务失败，则增加间隔；成功则重置为初始间隔）

注意：轮询间隔策略可以设计为策略模式，但为了简化，我们使用std::function来设置间隔计算函数。

```cpp
class TimeConverter {
public:
    // 将时间转化为秒
    static long toNanoseconds(long duration , TimeUnit unit) {
        switch (unit) {
            case TimeUnit::NANOSECONDS:
                return duration;
            case TimeUnit::MICROSECONDS:
                return duration * 1000;
            case TimeUnit::MILLISECONDS:
                return duration * 1000 * 1000;
            case TimeUnit::SECONDS:
                return duration * 1000 * 1000 * 1000;
            case TimeUnit::MINUTES:
                return duration * 60000000000L;
            default: throw std::invalid_argument("Invalid time unit");
        }
    }
};
```

## 04.轮询策略接口设计

### 4.1 策略接口分析

轮询策略接口和具体策略，定义策略接口，然后实现三种策略：固定间隔、指数退避、随机间隔。

策略接口设计（IPollingStrategy）

1. 固定间隔策略（FixedIntervalStrategy）
2. 指数退避策略（ExponentialBackoffStrategy）
3. 随机间隔策略（RandomIntervalStrategy）

### 4.2 轮询策略接口

IPollingStrategy 是一个通用的轮询策略接口，通过实现具体的子类，可以定义不同的轮询逻辑（如固定间隔、指数退避等）。在实际使用中，可以根据需求选择合适的策略，并结合具体场景进行优化。

它包含了一些纯虚函数，需要子类实现具体的逻辑。

```cpp
class IPollingStrategy {
public:
    //析构函数
    virtual ~IPollingStrategy(){}
    //获取下一次轮训
    virtual long getNextInterval() = 0;
    //重置策略状态
    virtual void reset() = 0;
    //记录任务成功
    virtual void recordSuccess() = 0;
    //记录任务失败
    virtual void recordFailure() = 0;
    //获取策略配置信息
    virtual std::string getConfigInfo() const = 0;
};
```

- ~IPollingStrategy，虚析构函数确保派生类的析构函数能够正确调用，避免资源泄漏。
- getNextInterval，纯虚函数，子类需要实现具体的逻辑，返回下一次轮询的时间间隔（单位可以是毫秒、秒等）。
- reset，纯虚函数，子类需要实现逻辑，重置策略的内部状态（例如计数器、失败次数等）。
- recordSuccess，纯虚函数，子类需要实现逻辑，记录任务成功的状态（例如增加成功计数器）。
- recordFailure，纯虚函数，子类需要实现逻辑，记录任务失败的状态（例如增加失败计数器）。
- getConfigInfo，纯虚函数，子类需要实现逻辑，返回策略的配置信息（例如策略名称、参数等）。

### 4.3 改进建议

1. 线程安全：如果策略在多线程环境中使用，需要确保线程安全（例如使用互斥锁）。
2. 扩展性：可以通过添加更多配置参数（例如退避因子）来增强策略的灵活性。
3. 日志记录：可以添加日志记录功能，方便调试和监控策略的行为。

## 05.具体策略实现

### 5.1 固定间隔策略

FixedIntervalStrategy 是一个简单的固定间隔轮询策略实现。通过改进时间单位转换和配置信息输出，可以使其更易用和易读。

```cpp
class FixedIntervalStrategy : public IPollingStrategy {
private:
    const long interval_ns;
public:
    FixedIntervalStrategy(long interval, TimeUnit unit)
    : interval_ns(TimeConverter::toNanoseconds(interval, unit)) {}

    virtual long getNextInterval() override { return interval_ns; }
    virtual void reset() override {}
    virtual void recordSuccess() override {}
    virtual void recordFailure() override {}

    virtual std::string getConfigInfo() const override {
        std::ostringstream oss;
        oss << "FixedInterval: " << interval_ns << " ns";
        return oss.str();
    }
};
```

测试效果如下所示（在 `main` 中创建实例并调用 `getConfigInfo` / `getNextInterval`）：

```cpp
int main() {
    using namespace PollingSystem;
    FixedIntervalStrategy strategy(1000, TimeUnit::MILLISECONDS); // 固定间隔 1000ms
    std::cout << "Config: " << strategy.getConfigInfo() << std::endl;
    // 获取下一次轮询间隔
    std::cout << "Next interval: " << strategy.getNextInterval() << " ns" << std::endl;
    return 0;
}
```

预期打印：

```text
Config: FixedInterval: 1000000000 ns
Next interval: 1000000000 ns
```

`1000 ms` 被 `TimeConverter::toNanoseconds` 转成 `1_000_000_000 ns`——**所有内部时间统一存储为 ns**，对外接口才允许多种时间单位。这是"接口友好 + 内部统一"的经典做法：调用方用 `MILLISECONDS` 写得舒服，框架内部走纳秒级运算保证精度。

> 🧠 **`getNextInterval` 多次调用永远返回同一个数**：因为这是"固定间隔"策略——这正是策略模式可替换性的最低要求。下一节 `ExponentialBackoffStrategy` 每次返回的值会**翻倍**，但接口签名 `long getNextInterval()` 完全不变。**调用方代码 `int ns = strategy_->getNextInterval()` 一行不用改**就能切换策略，这就是策略模式的核心价值。

### 5.2 指数退避策略

ExponentialBackoffStrategy 是一个实现了 指数退避策略 的类，继承自 IPollingStrategy 接口。它用于在轮询或重试操作中动态调整等待时间，以避免资源浪费或系统过载。

ExponentialBackoffStrategy 的主要功能包括：

- 动态调整等待时间：根据策略计算下一次轮询或重试的等待时间。
- 指数退避：每次失败后，等待时间以指数方式增长，直到达到最大值。
- 重置策略：在成功时重置等待时间到初始值。
- 配置信息：提供策略的配置信息，便于调试和监控。

```cpp
class ExponentialBackoffStrategy : public IPollingStrategy {
private:
    const long initial_ns;
    const long max_ns;
    long current_ns;
public:
    ExponentialBackoffStrategy(long initial, long max, TimeUnit unit)
        : initial_ns(TimeConverter::toNanoseconds(initial, unit)),
          max_ns(TimeConverter::toNanoseconds(max, unit)),
          current_ns(initial_ns) {}

    virtual long getNextInterval() override {
        long result = current_ns;
        current_ns = std::min(current_ns * 2, max_ns);
        return result;
    }

    virtual void reset() override { current_ns = initial_ns; }
    virtual void recordSuccess() override { reset(); }
    virtual void recordFailure() override {}

    virtual std::string getConfigInfo() const override {
        std::ostringstream oss;
        oss << "ExponentialBackoff: Initial=" << initial_ns
            << "ns, Max=" << max_ns << "ns";
        return oss.str();
    }
};
```

改进建议：

- (1) 线程安全：如果策略在多线程环境中使用，可以添加线程安全支持（例如使用 std::mutex）。
- (2) 更友好的配置信息：在 getConfigInfo 中，可以返回更易读的时间单位（例如 "Initial=1s, Max=10s" 而不是 "Initial=1000000000ns, Max=10000000000ns"）。
- (3) 退避因子：可以添加一个退避因子（例如 factor），允许自定义间隔的增长速度（例如 current_ns = std::min(current_ns * factor, max_ns)）。
- (4) 失败计数器：可以添加一个失败计数器，记录连续失败的次数，并在达到一定阈值时触发特定逻辑。


### 5.3 随机间隔策略

```cpp
//随机间隔策略
class RandomIntervalStrategy : public IPollingStrategy {
private:
    const long min_ns;
    const long max_ns;
    std::default_random_engine engine;
public:
    RandomIntervalStrategy(long min, long max, TimeUnit unit) :
    min_ns(TimeConverter::toNanoseconds(min,unit)),
    max_ns(TimeConverter::toNanoseconds(max,unit)),
    engine(std::random_device()) {
    }

    virtual long getNextInterval() override {
        std::uniform_int_distribution<long> dist(min_ns,max_ns);
        return dist(engine);
    }
    virtual void reset() override {}
    virtual void recordSuccess() override {}
    virtual void recordFailure() override {}

    virtual std::string getConfigInfo() const override {
        std::ostringstream oss;
        oss << "RandomInterval: Min=" << min_ns
            << "ns, Max=" << max_ns << "ns";
        return oss.str();
    }
};
```

### 6.3 记录任务结果

```cpp
void recordResult(const TaskResult& result) {
    total++;
    if (result.success) {
        success++;
    } else {
        failure++;
    }

    // 保留最近100条结果
    recentResults.push_back(result);
    if (recentResults.size() > 100) {
        recentResults.pop_front();
    }
}
```

### 6.4 打印统计摘要

```cpp
void printSummary() const {
    std::cout << "=== Task Statistics ===" << std::endl;
    std::cout << "Total runs: " << total << std::endl;
    std::cout << "Success: " << success << " ("
              << (total ? (success * 100.0 / total) : 0.0) << "%)" << std::endl;
    std::cout << "Failure: " << failure << " ("
              << (total ? (failure * 100.0 / total) : 0.0) << "%)" << std::endl;
    if (!recentResults.empty()) {
        std::cout << "\nRecent results (last " << recentResults.size() << "):" << std::endl;
        for (const auto& res : recentResults) {
            auto timeStr = formatTime(res.timestamp);
            std::cout << "[" << timeStr << "] " << (res.success ? "SUCCESS" : "FAILURE")
                      << ": " << res.message << std::endl;
        }
    }
}
```

### 6.5 格式化时间戳

```cpp
std::string formatTime(const std::chrono::steady_clock::time_point& tp) const {
    // 使用相对时间而不是绝对时间
    auto duration = tp.time_since_epoch();
    auto hours = std::chrono::duration_cast<std::chrono::hours>(duration);
    auto minutes = std::chrono::duration_cast<std::chrono::minutes>(
        duration % std::chrono::hours(1));
    auto seconds = std::chrono::duration_cast<std::chrono::seconds>(
        duration % std::chrono::minutes(1));
    auto milliseconds = std::chrono::duration_cast<std::chrono::milliseconds>(
        duration % std::chrono::seconds(1));
    std::stringstream ss;
    ss << std::setfill('0')
       << std::setw(2) << hours.count() % 24 << ":"
       << std::setw(2) << minutes.count() << ":"
       << std::setw(2) << seconds.count() << "."
       << std::setw(3) << milliseconds.count();
    return ss.str();
```

```cpp
void Poller::run() {
    while (running_) {
        //设置间隔时间。
        long next_interval = 0;
        {
            //根据不同的策略设置时间
            std::unique_lock<std::mutex> lock(mutex_);
            //计算下一次执行间隔时间
            next_interval = strategy_->getNextInterval();
            // 等待条件：1) 到达间隔时间 2) 被唤醒 3) 暂停状态
            auto now = std::chrono::steady_clock::now();
            auto wake_time = now + std::chrono::nanoseconds(next_interval);
            while (running_ &&std::chrono::steady_clock::now() < wake_time &&!paused_) {
                cond_.wait_until(lock, wake_time);
            }
            // 检查是否暂停
            if (paused_) {
                cond_.wait(lock, [this] { return !paused_ || !running_; });
                continue;
            }
            // 检查是否停止
            if (!running_) {
                break;
            }
        }
        // 执行任务
        executeAction();
    }
}
```

然后看一下如何执行任务

```cpp
    void Poller::executeAction() {
        auto start_time = std::chrono::steady_clock::now();
        TaskResult result(false, "Unknown result", std::chrono::steady_clock::now());
        try {
            if (task_timeout_ns_ > 0) {
                // 带超时的任务执行
                std::future<TaskResult> future = std::async(std::launch::async, action_);
                auto status = future.wait_for(std::chrono::nanoseconds(task_timeout_ns_));
                if (status == std::future_status::ready) {
                    result = future.get();
                } else {
                    result = TaskResult(false, "Task timed out", std::chrono::steady_clock::now());
                }
            } else {
                // 不带超时的任务执行
                result = action_();
            }
        } catch (const std::exception& e) {
            result = TaskResult(false, std::string("Exception: ") + e.what(),
                      std::chrono::steady_clock::now());
        } catch (...) {
            result = TaskResult(false, "Unknown exception", std::chrono::steady_clock::now());
        }
        auto end_time = std::chrono::steady_clock::now();
        auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end_time - start_time).count();
        // 记录结果并更新策略
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (result.success) {
                strategy_->recordSuccess();
            } else {
                strategy_->recordFailure();
            }
        }
        // 输出执行信息
        std::cout << "Action executed in " << duration << "ms. Result: "
                  << (result.success ? "SUCCESS" : "FAILURE") << " - " << result.message << std::endl;
    }

```

启动后 `Poller` 内部 `worker_thread_` 立即开始干活：① 询问 `strategy_->getNextInterval()` 拿到 1s；② 在条件变量上等 1s；③ 调用 `sampleAction()` 执行任务；④ 拿任务结果调 `recordSuccess` / `recordFailure`；⑤ 回到步骤①。**这就是"轮询"的本质——策略告诉它"下次什么时候醒"，任务函数告诉它"醒了干啥"，两者完全解耦**。

### 8.4 完整闭环测试

把 8.1～8.3 拼装成一个端到端的 main，跑 5 秒后干净停止：

```cpp
int main() {
    using namespace PollingSystem;
    auto sampleAction = [/* 同 8.1 */]() -> TaskResult { /* ... */ };

    Poller poller(
        std::unique_ptr<IPollingStrategy>(
            new FixedIntervalStrategy(1000, TimeUnit::MILLISECONDS)),
        sampleAction
    );

    poller.start();

    // 让它跑 5 秒，期间应当执行约 5 次任务
    std::this_thread::sleep_for(std::chrono::seconds(5));

    // 暂停 → 切换策略 → 继续
    poller.pause();
    poller.updateStrategy(std::unique_ptr<IPollingStrategy>(
        new ExponentialBackoffStrategy(500, 4000, TimeUnit::MILLISECONDS)));
    poller.resume();

    std::this_thread::sleep_for(std::chrono::seconds(5));

    poller.stop();
    return 0;
}
```

预期打印（具体执行次数、耗时、成功/失败比例每次运行有微小差异）：

```text
Poller started.
Action executed in 51ms. Result: SUCCESS - Operation succeeded #1
Action executed in 50ms. Result: SUCCESS - Operation succeeded #2
Action executed in 152ms. Result: FAILURE - Simulated failure #3
Action executed in 51ms. Result: SUCCESS - Operation succeeded #4
Action executed in 50ms. Result: SUCCESS - Operation succeeded #5
Poller paused.
Strategy updated: ExponentialBackoff: Initial=500000000ns, Max=4000000000ns
Poller resumed.
Action executed in 51ms. Result: SUCCESS - Operation succeeded #6
Action executed in 152ms. Result: FAILURE - Simulated failure #7
Action executed in 50ms. Result: SUCCESS - Operation succeeded #8
Poller stopped.
```

5 秒固定间隔阶段执行了 5 次任务（每秒 1 次，符合 `FixedInterval(1000ms)`）；切换到指数退避后，因为 `recordSuccess` 会重置 `current_ns = initial_ns`，连续成功时仍接近 500ms 间隔，但一遇到失败下次就翻倍。

> 🧠 **`updateStrategy` 配合 `unique_ptr` 自动析构旧策略**：`strategy_ = std::move(new_strategy)` 这一行实际上做了三件事：① 旧的 `FixedIntervalStrategy` 被 unique_ptr 析构释放；② 新的 `ExponentialBackoffStrategy` 接管；③ 调用 `reset()` 重置内部状态。**这是 RAII 让"运行时换策略"变得安全的典型场景**——如果用裸指针 `IPollingStrategy* strategy_`，开发者必须手动 `delete` 旧的、否则就是内存泄漏。

> ⚠️ **`pause + resume` 期间任务执行计数不会清零**：`sampleAction` 里的 `static int counter` 是函数级静态变量，活到程序结束。所以 resume 后任务编号是 6、7、8 而不是从 1 重启——这其实是合理的：用户的"任务计数"应当和"策略生命周期"解耦。如果你想让计数随策略重置，应当用一个外部的 `std::atomic<int>` 而非 `static`。

## 10.核心组件说明

### 10.1 时间系统

支持多种时间单位（纳秒到分钟）、精确的时间转换工具类——所有内部存储统一为纳秒，对外接口暴露 `TimeUnit` 枚举供调用方按业务需要选择。这种"内部统一 + 接口多元"的模式，是写工具库的通用做法。

### 10.2 轮询策略系统

抽象基类 `IPollingStrategy` + 三种内置实现（FixedInterval / ExponentialBackoff / RandomInterval）。新增策略只需继承重写 4 个虚函数，**无需改动 `Poller` 一行代码**——开闭原则的教科书示范。

### 10.3 任务统计系统

`TaskStatistics` 用 `std::deque<TaskResult>` 滚动存最近 100 条结果（`push_back + pop_front`），既限制了内存占用、又保留了足够的近期信息。这种"环形缓冲"思维在监控系统、日志收集器中无处不在。

### 10.4 核心轮询器功能

`Poller` 类封装了完整的生命周期：start / stop / pause / resume / updateStrategy / triggerNow / setTaskTimeout。每个公开方法都用 `std::lock_guard<std::mutex>` 保护共享状态——这是 07 案例并发训练的延续。

### 10.5 高级特性

- **任务超时监控**：`std::async + std::future::wait_for` 给每个任务设硬上限。
- **策略热切换**：运行时调 `updateStrategy` 即可换间隔策略，配合 `unique_ptr` 自动释放旧策略。
- **手动触发**：`triggerNow` 通过 `cond_.notify_all()` 强制唤醒等待中的轮询线程，实现"立即执行一次"。
- **异常隔离**：任务函数抛出的异常被 `try/catch (...)` 兜住，不会传到轮询线程导致进程崩溃。

> 💡 **本案例已经具备生产级框架的雏形**：把它和 [09.简易的线程池](./09.简易的线程池.md) 组合，就是一个"定时任务调度器"——很多公司监控系统的内核就是这样搭出来的。

### 11.2 与下一案例的递进

[09.简易的线程池](./09.简易的线程池.md) 是**并发三连的收官**——把 07 的"多线程"和 08 的"`std::function` 任务抽象"拧在一起，再加上"`future/promise` 跨线程传值"和"模板 + 完美转发"，组成工程师日常都在用的**线程池组件**。09 是整个卷二**难度最高**的一篇，建议 07/08 都吃透后再进。

### 11.3 三个延伸挑战

**A（基础）· 再写一种策略**：实现一个 `LinearBackoffStrategy`——间隔从 1s 线性增长到 10s 后封顶。只需继承 `PollStrategy` 重写 `nextInterval()`，整个框架不用改一行。这就是**开闭原则**（Open-Closed Principle）的威力。

**B（进阶）· 并发多任务**：当前一个 `Poller` 只管一个任务。扩展为 `Poller` 内部管 N 个任务，每个任务有独立的策略和开关。这需要把任务从 `std::function<void()>` 扩展为 `struct Task { std::string name; std::function<void()> fn; std::unique_ptr<PollStrategy> strategy; std::atomic<bool> enabled; }`。

**C（挑战）· 把时间工具换成 C++20 `std::chrono::sys_time`**：如果你的编译器支持 C++20，把 `TimeUtil` 里所有"手写时间戳转字符串"替换为 `std::format("{:%Y-%m-%d %H:%M:%S}", tp)`（配合 `<chrono>` + `<format>`）。这是**现代 C++ 时间处理的终极写法**。
