## 01.需求说明

### 1.1 JSON 数据模型

JSON（RFC 8259）规定一个值只能是以下 6 种之一：

```
Value ::= null
        | true | false            (Bool)
        | Number                  (Int64 或 Double)
        | String                  ("...")
        | Array                   ([Value, Value, ...])
        | Object                  ({"key": Value, ...})
```

注意最后两种——**数组和对象里装的还是 Value**——这就形成了**递归定义**。任何 JSON 实现都要回答同一个问题：**C++ 里怎么表达这种既可以是简单类型又可以是容器的"和类型"**？

### 1.2 目标 API

```cpp
#include "mini_json.hpp"
using mj::Value;

// 解析
Value v = mj::parse(R"({"name": "zhang", "age": 30, "hobbies": ["cpp", "go"]})");
std::cout << v["name"].get<std::string>() << "\n";      // zhang
std::cout << v["age"].get<int64_t>() << "\n";           // 30
std::cout << v["hobbies"][0].get<std::string>() << "\n"; // cpp

// 构造
Value out = Value::object();
out["ok"] = true;
out["data"] = Value::array({1, 2, 3});
std::cout << out.dump(2) << "\n";
//   {
//     "ok": true,
//     "data": [1, 2, 3]
//   }

// 错误处理
try { mj::parse("{invalid}"); }
catch (const mj::parse_error& e) {
    std::cerr << e.what() << "\n";   // parse_error at line 1 col 2: expected '"'
}
```

### 1.3 为什么 JSON 是绝佳教学案例

- **和类型（sum type）**：6 种可能性，正是 `std::variant` 的主场。
- **递归结构**：数组/对象元素又是 Value，考验读者对指针/容器选择的理解。
- **解析**：递归下降，比正则更贴近编译原理的基本功。
- **异常**：解析失败必须抛；类型访问错误也必须抛；两种异常不能混。
- **API 设计**：`operator[]`、`get<T>()`、`dump(indent)` 都是极好的接口设计练习。

### 1.4 覆盖的卷一知识点

```
第 5 章  复合类型        → vector<Value>、map<string, Value>
第 8 章  指针与引用       → const Value& 传递
第 12 章 动态内存/RAII    → 不用裸 new，全部 RAII
第 14 章 异常处理         → parse_error / type_error 层次
第 16 章 STL 模板         → std::variant、std::visit、std::map
第 18 章 特性图谱         → std::variant（C++17）、std::optional（可选）
```

## 02.值的表达：`Value` 类

### 2.1 六种 JSON 类型

```cpp
namespace mj {
    enum class Type { Null, Bool, Int, Double, String, Array, Object };
}
```

（`Int` 和 `Double` 在 JSON 语义上都是 Number，但 C++ 里区分更安全——避免把整数 `42` 取成 `42.0` 再失去精度。）

### 2.2 选型：`variant` vs 继承 vs 联合

| 方案 | 优点 | 缺点 |
|------|------|------|
| C 风格 `union` + `type` 标记 | 零开销 | ❌ 不支持 `std::string` 这类含析构的类型（RAII 冲突） |
| 继承 + 虚函数 | OOP 风格 | ❌ 必须堆分配 + 虚函数 overhead；值语义丢失 |
| **`std::variant`（C++17）** | ✅ 栈上存储、类型安全、支持 `visit` | 需要 C++17 及以上 |

本案例选 `std::variant`——既是卷一第 18 章的主力特性，也是现代 C++ 建模**和类型**的标准答案。

### 2.3 `Value` 的定义

```cpp
class Value {
public:
    using Array  = std::vector<Value>;
    using Object = std::map<std::string, Value>;

    using Data = std::variant<
        std::monostate,   // Null  ← monostate 表示"什么都没有"
        bool,             // Bool
        int64_t,          // Int
        double,           // Double
        std::string,      // String
        Array,            // Array
        Object            // Object
    >;

    // 构造函数（略……包括 Value()、Value(bool)、Value(int)、Value(double)、
    //                    Value(const char*)、Value(std::string)、Value(Array)、Value(Object)）

    Type type() const;
    bool is_null()   const { return std::holds_alternative<std::monostate>(data_); }
    bool is_bool()   const { return std::holds_alternative<bool>(data_); }
    bool is_int()    const { return std::holds_alternative<int64_t>(data_); }
    // ...

    template <typename T>
    const T& get() const;   // 类型不匹配抛 type_error

    const Value& operator[](const std::string& key) const;   // Object 下标
    const Value& operator[](size_t index) const;              // Array 下标

    std::string dump(int indent = 0) const;

private:
    Data data_;
};
```

## 03.递归结构的处理

### 3.1 数组存 `vector<Value>`

一个 JSON 数组 `[1, "x", [true]]` 对应：

```cpp
Value::Array arr;
arr.emplace_back(int64_t{1});
arr.emplace_back(std::string{"x"});
arr.emplace_back(Value::Array{Value{true}});
Value v{std::move(arr)};
```

### 3.2 对象存 `map<string, Value>`

有序性：**JSON 标准没有规定对象内 key 的顺序**，但实际工程里往往希望"美化输出时字段顺序稳定"。我们用 `std::map`（按 key 字典序），简单且够用。若希望保留插入顺序，换 `std::vector<std::pair<std::string, Value>>`。

### 3.3 为什么这里不能用 `unique_ptr`

可能有读者想：*"`Value` 很大（包含 variant），`Array` 里存 `unique_ptr<Value>` 不是更省内存吗？"*

**不行**。`unique_ptr` 的核心语义是"独占所有权、**不可拷贝**"。但用户可能写：

```cpp
Value src = Value::array({1, 2, 3});
Value dst = src;   // ← 必须允许拷贝
```

`Array = vector<unique_ptr<Value>>` 会让拷贝编译不过（或悄悄变成 move）。**JSON 是值语义**，所以直接存 `vector<Value>`。如果确实要省内存（大数组、频繁传递），可以：

- 用 `std::shared_ptr<const Value>` 做**只读共享**（写时拷贝）；
- 或者在 API 层用 `const Value&` 避免复制。

这一节对应卷一第 12 章"**unique_ptr 和 shared_ptr 的场景选型**"。

## 04.访问 API 的设计

### 4.1 类型查询

```cpp
bool is_number() const { return is_int() || is_double(); }
```

### 4.2 取值 `get<T>()` 的类型安全

```cpp
template <typename T>
const T& Value::get() const {
    if (!std::holds_alternative<T>(data_)) {
        throw type_error("Value is not of type " + std::string(typeid(T).name()));
    }
    return std::get<T>(data_);
}
```

用户侧：

```cpp
Value v{42};
std::cout << v.get<int64_t>();     // 42
std::cout << v.get<std::string>(); // 抛 type_error
```

**注意**：`std::get<T>(variant)` 本身类型不匹配就会抛 `std::bad_variant_access`。我们多包一层是为了：
1. 抛**自定义异常类型**，和解析错误分开；
2. 附带可读的错误消息。

### 4.3 下标 `operator[]` 的两难

- `const Value& operator[](const string&) const` 返回引用——但 key 不存在时怎么办？
  - 选项 A：抛 `std::out_of_range`
  - 选项 B：返回一个"空洞 Value"
  - 选项 C：`at(key)` 严格、`operator[]` 宽松
- **本案例选 A**（抛异常），因为 JSON 是外部数据，静默失败容易掩盖 bug。

## 05.解析器实现

### 5.1 递归下降法概览

递归下降：**每个文法规则对应一个函数，规则互相嵌套就变成函数互相调用**。

```
parseValue() ─┬─ parseNull()
              ├─ parseBool()
              ├─ parseNumber()
              ├─ parseString()
              ├─ parseArray()   ← 里面会再调 parseValue()
              └─ parseObject()  ← 里面会再调 parseValue()
```

底层依赖一个"光标状态"：

```cpp
class Parser {
    const std::string& src_;
    size_t pos_ = 0;
    int line_ = 1, col_ = 1;
public:
    Value parseValue();
private:
    char peek() const;
    char next();
    void skipSpace();
    bool match(const char* literal);
    [[noreturn]] void fail(const std::string& msg);
};
```

### 5.2 跳过空白

```cpp
void Parser::skipSpace() {
    while (pos_ < src_.size()) {
        char c = src_[pos_];
        if (c == ' ' || c == '\t') { ++pos_; ++col_; }
        else if (c == '\n')        { ++pos_; ++line_; col_ = 1; }
        else if (c == '\r')        { ++pos_; }
        else break;
    }
}
```

### 5.3 解析 `null` / `true` / `false`

```cpp
Value Parser::parseValue() {
    skipSpace();
    if (pos_ >= src_.size()) fail("unexpected end of input");
    char c = src_[pos_];
    if (c == 'n') { if (!match("null"))  fail("expected 'null'");  return Value{}; }
    if (c == 't') { if (!match("true"))  fail("expected 'true'");  return Value{true}; }
    if (c == 'f') { if (!match("false")) fail("expected 'false'"); return Value{false}; }
    if (c == '"') return Value{parseString()};
    if (c == '[') return parseArray();
    if (c == '{') return parseObject();
    if (c == '-' || (c >= '0' && c <= '9')) return parseNumber();
    fail(std::string("unexpected character '") + c + "'");
}
```

### 5.4 解析数字

```cpp
Value Parser::parseNumber() {
    size_t start = pos_;
    if (src_[pos_] == '-') ++pos_;
    while (pos_ < src_.size() && std::isdigit((unsigned char)src_[pos_])) ++pos_;
    bool is_double = false;
    if (pos_ < src_.size() && src_[pos_] == '.') {
        is_double = true; ++pos_;
        while (pos_ < src_.size() && std::isdigit((unsigned char)src_[pos_])) ++pos_;
    }
    if (pos_ < src_.size() && (src_[pos_] == 'e' || src_[pos_] == 'E')) {
        is_double = true; ++pos_;
        if (pos_ < src_.size() && (src_[pos_] == '+' || src_[pos_] == '-')) ++pos_;
        while (pos_ < src_.size() && std::isdigit((unsigned char)src_[pos_])) ++pos_;
    }
    std::string num = src_.substr(start, pos_ - start);
    col_ += num.size();
    if (is_double) return Value{std::stod(num)};
    return Value{static_cast<int64_t>(std::stoll(num))};
}
```

### 5.5 解析字符串（含转义）

```cpp
std::string Parser::parseString() {
    if (next() != '"') fail("expected '\"'");
    std::string out;
    while (pos_ < src_.size()) {
        char c = next();
        if (c == '"') return out;
        if (c == '\\') {
            char esc = next();
            switch (esc) {
                case '"':  out.push_back('"');  break;
                case '\\': out.push_back('\\'); break;
                case '/':  out.push_back('/');  break;
                case 'n':  out.push_back('\n'); break;
                case 't':  out.push_back('\t'); break;
                case 'r':  out.push_back('\r'); break;
                case 'b':  out.push_back('\b'); break;
                case 'f':  out.push_back('\f'); break;
                case 'u':  // 6 字符 \uXXXX → 简化版：只支持 ASCII 范围
                    // 工程库还需处理代理对（surrogate pair），本案例省略
                    fail("\\u escape not supported in mini version");
                default:   fail(std::string("invalid escape '\\") + esc + "'");
            }
        } else {
            out.push_back(c);
        }
    }
    fail("unterminated string");
}
```

### 5.6 解析数组 / 对象

```cpp
Value Parser::parseArray() {
    next();  // eat '['
    Value::Array arr;
    skipSpace();
    if (peek() == ']') { next(); return Value{std::move(arr)}; }
    while (true) {
        arr.emplace_back(parseValue());
        skipSpace();
        char c = next();
        if (c == ']') return Value{std::move(arr)};
        if (c != ',') fail("expected ',' or ']'");
    }
}

Value Parser::parseObject() {
    next();  // eat '{'
    Value::Object obj;
    skipSpace();
    if (peek() == '}') { next(); return Value{std::move(obj)}; }
    while (true) {
        skipSpace();
        std::string key = parseString();
        skipSpace();
        if (next() != ':') fail("expected ':'");
        Value val = parseValue();
        obj.emplace(std::move(key), std::move(val));
        skipSpace();
        char c = next();
        if (c == '}') return Value{std::move(obj)};
        if (c != ',') fail("expected ',' or '}'");
    }
}
```

### 6.2 美化模式 `dump(2)`

`std::visit` 优雅地分发到每种类型，缩进层级作为参数递归下传：

```cpp
void writeValue(std::ostream& os, const Value::Data& d, int indent, int depth) {
    std::visit([&](const auto& v) {
        using T = std::decay_t<decltype(v)>;
        if constexpr (std::is_same_v<T, std::monostate>) {
            os << "null";
        } else if constexpr (std::is_same_v<T, bool>) {
            os << (v ? "true" : "false");
        } else if constexpr (std::is_same_v<T, int64_t> || std::is_same_v<T, double>) {
            os << v;
        } else if constexpr (std::is_same_v<T, std::string>) {
            writeString(os, v);
        } else if constexpr (std::is_same_v<T, Value::Array>) {
            writeArray(os, v, indent, depth);
        } else if constexpr (std::is_same_v<T, Value::Object>) {
            writeObject(os, v, indent, depth);
        }
    }, d);
}
```

`std::visit` + `if constexpr` 在编译期选择分支——**编译后的代码等同于一个 switch**，零运行时类型判断开销。这是**卷一第 18 章**里提到但很少示范的模式。

## 07.异常设计

### 7.1 两种异常

```cpp
class json_error : public std::runtime_error {
public:
    using std::runtime_error::runtime_error;
};

class parse_error : public json_error {  // 解析失败
public:
    parse_error(std::string msg, int line, int col)
        : json_error(std::move(msg)), line_(line), col_(col) {}
    int line() const { return line_; }
    int col()  const { return col_; }
private:
    int line_, col_;
};

class type_error : public json_error {   // 类型访问错误
    using json_error::json_error;
};
```

分两种类型是因为它们的**处理策略不同**：
- `parse_error`：输入数据问题，通常记日志+回退默认值；
- `type_error`：代码 bug，通常让它冒泡到崩溃，方便修复。

### 7.2 错误位置

`parse_error` 捎带 `line_`/`col_`，错误消息样例：

```
parse_error at line 3 col 15: expected ':' after key "name"
```

### 7.3 与第 10 章测试框架对接

```cpp

└── examples/
    ├── echo.cpp       ← 读 JSON 再美化打印
    └── benchmark.cpp  ← 与 nlohmann::json 对比性能
```

| 机制 | 作用 | 对应卷一章 |

### 9.3 性能与工程级库的差距

用 `benchmark.cpp` 在 1 MB 的真实 API 响应上测试（单次解析）：

| 库 | 耗时 | 内存峰值 |
|----|------|---------|
| nlohmann::json | ~8 ms | ~3 MB |
| simdjson | ~0.3 ms | ~1.1 MB |
| **mini_json（本案例）** | ~25 ms | ~5 MB |

慢 3 倍、内存多 60%，但**代码量只有 nlohmann::json 的 1/30**。这就是**教学版 vs 工程版**的典型差距——工程版必须把字符串短小优化（SSO）、内存池、SIMD 扫描、迭代式解析、`std::string_view` 零拷贝等所有把戏都用上。

## 10.技术思考

### 10.1 `std::variant` vs C 联合体：类型安全从哪来

C 的 `union` 是**标记不足的"原始"和类型**：

```c
struct Value {
    enum Type t;
    union { int i; double d; char* s; };  // 你必须自己看 t 决定用哪个字段
};
```

问题：
- ❌ 不能装 `std::string`（含非平凡构造/析构）——C++98 起编译器直接拒绝；C++11 起允许但要用户手写 `placement new` + 显式析构；
- ❌ 访问错误类型字段是 **UB**；
- ❌ 拷贝/移动/析构全靠你自己。

`std::variant` 解决了这三个问题：
- ✅ 可以装任何类型（含 `string`、`vector`）；
- ✅ 用错类型会抛 `std::bad_variant_access`，不是 UB；
- ✅ 拷贝/移动/析构由库自动处理。

代价：每个 `variant<T1, T2, ...>` 内部带一个"标签字节"，实际内存对齐后多占 4-8 字节——在 JSON 这种结构里完全可忽略。

### 10.2 为什么 JSON 实现通常用递归？

JSON 的文法是**自嵌套**的——数组里可以套数组，对象里可以套对象。"递归数据结构"天然匹配"递归下降解析"。

非递归（迭代）的替代方案有：
- **栈 + 状态机**：手动把递归展开成 `std::stack<State>`；
- **SAX 风格**：不构建树，只触发 `onArrayBegin()`/`onKey()`/`onValue()`/... 回调。

工程库如 simdjson 为了极致性能用的是 SAX 变种 + SIMD 扫描，但**可读性**比递归下降差一个数量级——教学首选递归。

### 10.3 `shared_ptr` 会造成循环引用吗？JSON 里如何避免

`shared_ptr` 的经典陷阱：A 指 B、B 指 A，两个引用计数都降不到 0，永久泄漏。

但 **JSON 是一棵树**——DAG 都算不上——子节点不可能指回父节点。所以本案例即便用 `shared_ptr<Value>` 也不会循环。**但**：如果未来把 JSON 扩展成"JSON Pointer 引用"（类似 YAML 的锚点），循环就来了，此时必须用 `weak_ptr` 把指向"上级"的指针弱化。这个问题在卷三第 4 章会专门展开。

### 11.3 三个延伸挑战

**A（基础）· 支持 `\u` Unicode 转义**：让 `parseString` 能处理 `"\u4e2d\u6587"` → `"中文"`。需要处理 UTF-16 代理对（`\uD83D\uDE00` 要合并成一个码点再 UTF-8 编码）。

**B（进阶）· SAX 模式**：提供另一个入口 `parse_sax(src, handler)`，不构建 `Value` 树，只在"遇到 value"时调用 `handler.onNumber(v)` 等回调。对比两种模式下的**内存峰值**（提示：SAX 模式处理 100 MB 的 JSON 不应超过几 KB）。

**C（挑战）· 对象到 JSON 的自动映射**：模仿 nlohmann::json 的 `NLOHMANN_DEFINE_TYPE_INTRUSIVE` 宏，让用户写：
```cpp
struct User {
    std::string name;
    int age;
    MJ_DEFINE_JSON(User, name, age);  // 一个宏搞定
};
User u = v.get<User>();
```
这需要宏 + 模板的联合施法——10 章和 11 章的内功合流。完成后你就能自豪地说："**我真的懂 `nlohmann::json` 了**"。
