## 01.预约系统需求

### 1.1 系统简介

学校现有几个规格不同的机房，由于使用时经常出现"撞车"现象，现开发一套机房预约系统，解决这一问题。

### 1.2 身份简介

分别有三种身份使用该程序

* **学生代表**：申请使用机房
* **教师**：审核学生的预约申请
* **管理员**：给学生、教师创建账号

### 1.3 机房简介

机房总共有3间

* 1号机房   --- 最大容量20人
* 2号机房   --- 最多容量50人
* 3号机房   --- 最多容量100人

### 1.4 申请简介

* 申请的订单每周由管理员负责清空。
* 学生可以预约未来一周内的机房使用，预约的日期为周一至周五，预约时需要选择预约时段（上午、下午）
* 教师来审核预约，依据实际情况审核预约通过或者不通过

### 1.5 系统具体需求

* 首先进入登录界面，可选登录身份有：
  * 学生代表
  * 老师
  * 管理员
  * 退出
* 每个身份都需要进行验证后，进入子菜单
  * 学生需要输入 ：学号、姓名、登录密码
  * 老师需要输入：职工号、姓名、登录密码
  * 管理员需要输入：管理员姓名、登录密码
* 学生具体功能
  * 申请预约    ---   预约机房
  * 查看自身的预约    ---  查看自己的预约状态
  * 查看所有预约   ---   查看全部预约信息以及预约状态
  * 取消预约    ---   取消自身的预约，预约成功或审核中的预约均可取消
  * 注销登录    ---   退出登录
* 教师具体功能
  * 查看所有预约   ---   查看全部预约信息以及预约状态
  * 审核预约    ---   对学生的预约进行审核
  * 注销登录    ---   退出登录
* 管理员具体功能
  * 添加账号    ---   添加学生或教师的账号，需要检测学生编号或教师职工号是否重复
  * 查看账号    ---   可以选择查看学生或教师的全部信息
  * 查看机房    ---   查看所有机房的信息
  * 清空预约    ---   清空所有预约记录
  * 注销登录    ---   退出登录

### 2.2 搭建接口

接受用户的选择，搭建接口。在main中添加代码

```cpp
int main() {
    int select = 0;
    while (true) {
        cout << "======================  欢迎来到传智播客机房预约系统  =====================" << endl;
        cout << endl << "请输入您的身份" << endl;
        cout << "\t\t -------------------------------\n";
        cout << "\t\t|                               |\n";
        cout << "\t\t|          1.学生代表           |\n";
        cout << "\t\t|                               |\n";
        cout << "\t\t|          2.老    师           |\n";
        cout << "\t\t|                               |\n";
        cout << "\t\t|          3.管 理 员           |\n";
        cout << "\t\t|                               |\n";
        cout << "\t\t|          0.退    出           |\n";
        cout << "\t\t|                               |\n";
        cout << "\t\t -------------------------------\n";
        cout << "输入您的选择: ";
        cin >> select; //接受用户选择
        switch (select) {
            case 1: //学生身份
                break;
            case 2: //老师身份
                break;
            case 3: //管理员身份
                break;
            case 0: //退出系统
                break;
            default:
                cout << "输入有误，请重新选择！" << endl;
                clearScreen();
                break;
        }
    }
    pause();
    return 0;
}
```

### 2.3 测试搭建接口

测试，输入0、1、2、3会重新回到界面，输入其他提示输入有误，清屏后重新选择。

完整测试 main：

```cpp
int main() {
    int select = 0;
    while (true) {
        // ...菜单打印（同 2.2）
        cin >> select;
        switch (select) {
            case 1: case 2: case 3: case 0:
                cout << "[占位] 你选择了 " << select << "，等待具体功能接入..." << endl;
                cin.get(); cin.get();
                break;
            default:
                cout << "输入有误，请重新选择！" << endl;
                cin.get(); cin.get();
                break;
        }
        if (select == 0) break;
    }
    return 0;
}
```

预期打印（输入 7 → 退出）：

```text
输入您的选择: 7
输入有误，请重新选择！
输入您的选择: 0
[占位] 你选择了 0，等待具体功能接入...
```

`while(true) + switch + default` 是命令行菜单的最小骨架——后续 1/2/3 三个分支会陆续接入学生 / 老师 / 管理员的"工厂方法"，但**菜单循环本身不会再变**。这一步把 UI 框架先稳住，避免后续业务代码改动时反复调菜单。

> 💡 **菜单循环的两条退出路径**：① `case 0` 显式 `break + 外层判断` 退出（推荐，析构正常走完）；② `case 0: exit(0);`（**不推荐**——跳过栈对象析构，是 05 案例提过的坑）。本案例后续 3.1 直接 `return 0` 就是对照①的最佳实践。

至此，界面搭建完毕

### 5.3 学生登录实现

在student.txt文件中添加两条学生信息，用于测试

添加信息:

```text
1 张三 123
2 李四 123456
```

其中：

* 第一列  代表  **学号**
* 第二列  代表  **学生姓名**
* 第三列  代表  **密码**

在login函数的学生分支中加入如下代码，验证学生身份

```cpp
//学生登录验证
int fId;
string fName;
string fPwd;
while (ifs>>fId && ifs>>fName && ifs>>fPwd) {
    //用户输入的id，姓名和密钥，跟文件做对比
    if (id == fId && name == fName && pwd == fPwd) {
        cout << "学生验证登录成功!" << endl;
        pauseAndCls();
        person = new Student(id, name, pwd);
    }
}
```

测试学生登录。先确保 student.txt 里有"1 张三 123"和"2 李四 123456"两行，主菜单选 1 学生：

```text
输入您的选择: 1
请输入你的学号
1
请输入用户名：
张三 
请输入密码： 
123
学生验证登录成功!
```

三个字段（学号 + 姓名 + 密码）任一对不上都会走到末尾的 `cout << "验证登录失败!"`——比如把姓名故意打成"张4"：

```text
请输入用户名：
张4
请输入密码： 
123
验证登录失败!
```

> ⚠️ **`while(ifs>>fId && ifs>>fName && ifs>>fPwd)` 一旦匹配成功后没 `return / break`**：循环会**继续读完整个文件**才退出。这意味着对本案例没什么副作用（最多多走几次比较），但一旦学生数据规模上千、并且有"匹配后立即扣费"这样的副作用业务，就会变成"重复扣费"灾难。生产代码应当在匹配成功的 `if` 里加 `return` 或 `break`——5.4 教师登录的写法就是对的（带 `return`）。本节学生登录代码漏写 `return`，**建议照 5.4 的样子补上**。

> 🧠 **登录函数返回 `Identity*`、main 中按多态调用 `openMenu()`** 是整个项目的"工厂方法 + 策略模式"开关：login 内部根据 type 走 1/2/3 三条分支，分别 `new` 出 Student / Teacher / Manager 三种子类，**但调用方 main 拿到的是同一个 `Identity*` 类型**，可以一行 `person->openMenu()` 触发三种不同菜单。这就是 03 案例多态在更大规模上的延展。

#### 6.6.4 bug解决

bug描述： 虽然可以检测重复的账号，但是刚添加的账号由于没有更新到容器中，因此不会做检测。导致刚加入的账号的学生号或者职工编号，再次添加时依然可以重复。

```cpp

        if (select == 1)      stu->applyOrder();      // 申请预约
        else if (select == 2) stu->showMyOrder();     // 查看我的预约
        else if (select == 3) stu->showAllOrder();    // 查看所有预约
        else if (select == 4) stu->cancelOrder();     // 取消预约
        else {                                         // 注销登录
            delete person;
            cout << "注销成功" << endl;
            return;
        }
    }
}
```

> 🧠 **`Identity*& person` 为什么要引用？** 因为 `delete person` 后我们希望调用方的 `Identity*` 也变成 nullptr（避免悬垂指针）——只用 `Identity*` 传值的话，`delete` 释放了堆内存但**调用方的指针副本依然非空**。传引用才能把 nullptr 的新值反哺到调用方。延伸挑战 A 改成 `shared_ptr` 后，这条规则会被 `reset()` 自动取代。

### 7.2 申请预约

核心数据结构：预约表用 `map<int, map<string,string>>`——**外层 key 是"预约序号"，内层是"字段名→字段值"**（序号/日期/时段/机房编号/学号/姓名/状态）。

```cpp
void Student::applyOrder() {
    // 1. 展示"未来一周"选项（周一~周五×上午/下午 = 10 种）
    // 2. 展示 3 间机房
    // 3. 把预约写入 order.txt，格式一行：
    //    date:2 interval:1 stuId:1 stuName:张三 roomId:1 status:1
    // status 取值：1 审核中 / 2 审核通过 / -1 审核不通过 / 0 已取消
}
```

> 💡 **字段名带前缀（如 `date:2`）的好处**：解析时用 `pos = line.find(":")` 可以轻松拆出 key/value，**后续加字段也不用改解析代码**——这是 04 简易数据库 "schema 可配置" 思维在小型文件里的直接映射。

### 7.3 显示预约

`showMyOrder` 和 `showAllOrder` 的差异只有一处：前者多一个 `if (stuId == this->id)` 过滤。**这是"同一份数据 + 不同 WHERE 条件 = 不同视图"**的最小示例。

### 7.4 取消预约

只能取消 `status ∈ {1, 2}` 的预约（审核中、通过），状态置 0 后原地写回文件——注意要**先读取全量、再整体覆盖写**，不能"增量追加 status=0 行"，否则文件会膨胀成碎片。

## 08.教师模块

### 8.1 教师子菜单

结构与 7.1 完全对称，`teacherMenu(Identity*& person)` 接 3 个操作：① 查看所有预约、② 审核预约、③ 注销。

### 8.2 查看所有预约

直接复用 `OrderFile` 的全量读取 + 打印循环，**与 7.3 `showAllOrder` 完全共享逻辑**——这是提取 `OrderFile` 类的价值所在：同一份读取代码被学生和老师两个模块复用，"一处改动、两端受益"。

### 8.3 审核预约

只对 `status == 1`（审核中）的预约显示"是否通过"提示：输入 `1` 置 2（通过）、输入 `2` 置 -1（未通过）。与 7.4 取消的写盘模式一样——**全量读 → 修改内存 → 全量覆盖写**。

> ⚠️ **本案例所有"修改预约状态"操作都走"全量读 + 全量写"**：文件只有几十行时没问题，但规模一上百行性能就会肉眼可见地慢。生产数据库用**随机访问 + 定位偏移量原地改一个字段**的方式（对应 C++ 的 `fstream::seekp + write`），但代码会复杂很多——这正是**"从 flat file 升级为数据库"的动机**。

## 09.优化工作

### 9.1 去重操作

见 6.6 章节，已完整实现。核心思路是"每次 add 之后立即重载 vector"——这是典型的**内存与磁盘同步**问题：磁盘写了新记录，但内存 cache 还是旧的，查重自然会漏。**现代 ORM 的解决方式是"统一走仓储接口，仓储负责同步"**，本案例简化为"add 函数末尾调用 initVector()"。

### 10.3 三个延伸挑战

**A（基础）· 智能指针改造**：把 `Identity* manager = new Manager(...)` 全部改为 `std::shared_ptr<Identity> manager = std::make_shared<Manager>(...)`，全局变量也跟着改类型。完成后回头数一下——你删掉了多少 `delete`？这就是 RAII 的威力。

**B（进阶）· 按天统计预约**：目前预约没有"日期"字段。给 `Order` 结构体加 `std::chrono::year_month_day`（C++20）或简单的 `int year, month, day`，增加"查询某天所有预约"功能。

**C（挑战）· 预约时间冲突检测**：同一机房、同一时间段不能被两个预约占用。需要在"申请预约"时遍历已有预约做冲突检查。这里可以引出卷一第 16 章的 `std::set<Order, CompareByTime>` 替代 `std::vector`，让冲突检测从 O(N) 降到 O(log N)。
