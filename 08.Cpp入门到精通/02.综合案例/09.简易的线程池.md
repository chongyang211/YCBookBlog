## 01.简易线程池设计
### 1.1 核心设计思想

线程池（Thread Pool）是一种**预先创建一组工作线程、通过任务队列统一派发工作**的并发模式，用以替代"为每个任务 new 一个 thread 然后 join"的原始写法。核心思想可以概括为三句话：

1. **线程复用**：N 个工作线程常驻，任务来了就取一个线程干活，干完回到池中继续等，避免频繁 `std::thread` 的构造/析构开销（在 Linux 上每次约 10-100μs）。
2. **任务解耦**：生产者（业务代码）只管往队列扔任务，消费者（工作线程）只管从队列取任务执行——这就是**生产者-消费者**模式。
3. **资源控制**：池的大小上限即并发线程数上限，防止海量任务瞬间启动几千个线程导致内存/调度崩溃。

本案例实现的线程池在这三点之上再加两个特性：**① 双优先级队列**（普通任务 + 高优先任务），**② 泛型 `submit` 返回 `std::future`**。


### 1.2 核心设计目标

1. 资源管理优化：避免频繁创建/销毁线程的开销；实现线程复用，提高资源利用率；控制并发线程数量，防止资源耗尽。
2. 任务调度机制：支持任务优先级（普通任务 vs 优先任务）；实现公平的任务分配；确保任务执行顺序可控
3. 线程安全保证：确保多线程环境下数据访问安全；避免竞态条件和死锁；提供异常安全保证

### 2.2 声明公有接口

```cpp
class ThreadPool {
public:
    // 初始化线程池，默认线程数为 CPU 核心数加 1。
    ThreadPool(size_t maxNumberOfThreads = (std::thread::hardware_concurrency() + 1));
    // 带名称的构造函数。
    ThreadPool(const std::string &name, size_t maxNumberOfThreads = (std::thread::hardware_concurrency() + 1));
    // 析构函数
    virtual ~ThreadPool();

    // 任务管理接口
    // 提交普通任务。
    template<class F, class... Args>
    auto postTask(F &&f, Args &&... args) -> std::future<typename std::result_of<F(Args...)>::type>;
    // 提交优先任务。
    template<class F, class... Args>
    auto postPreTask(F &&f, Args &&... args) -> std::future<typename std::result_of<F(Args...)>::type>;
    void postPackagedTask(const std::shared_ptr<std::packaged_task<int()> > &task);
    // 清空普通任务队列。
    void clearTasks();
    // 清空所有任务队列。
    void clearAllTasks();
    // 清空优先任务队列。
    void clearPreTasks();

    // 返回普通任务队列的大小。
    std::size_t taskSize() { return mTasks.size(); }
    // 返回优先任务队列的大小。
    std::size_t preTaskSize() { return mPrepTasks.size(); }
    // 返回所有任务队列的大小。
    std::size_t allTaskSize() { return taskSize() + preTaskSize(); }
protected:
    // 线程启动时的回调（空实现）。
    virtual void onThreadAttached() {};
    // 线程退出时的回调（空实现）。
    virtual void onThreadDetached() {}
private:
    void taskLoop(const std::string &name);
    ThreadPool(const ThreadPool &) = delete;
    ThreadPool(ThreadPool &&) = delete;
    ThreadPool &operator=(const ThreadPool &) = delete;
    ThreadPool &operator=(ThreadPool &&) = delete;
private:
    // need to keep track of threads so we can join them
    // 存储线程池中的线程。
    std::vector<std::thread> mThreads;
    // 普通任务队列。
    std::queue<std::shared_ptr<std::packaged_task<int()> > > mTasks;
    // 优先处理的队列
    std::queue<std::shared_ptr<std::packaged_task<int()> > > mPrepTasks;
    // 保护任务队列的互斥锁。
    std::mutex mQueueMutex;
    // 条件变量，用于线程间的同步。
    std::condition_variable mCv;
    // 标志位，指示线程池是否停止。
    volatile bool mStop;
    // 空闲线程的互斥锁（未在代码中使用）。
    std::mutex mIdleMutex;
};
```

## 03.实现构造函数

实现要点：

1. 初始化 mStop为 false，表示线程池运行状态 
2. 使用 emplace_back直接构造线程对象 
3. 每个线程执行 taskLoop函数 
4. 构造函数重载提供默认线程名称

### 3.1 带名称构造

```cpp
ThreadPool::ThreadPool(const std::string &name, size_t maxNumberOfThreads) : mStop(false) {
    // 初始化 mStop 为 false，表示线程池处于运行状态。
    for (size_t i = 0; i < maxNumberOfThreads; ++i) {
        // 使用 emplace_back 创建 maxNumberOfThreads 个线程，每个线程执行 taskLoop 函数。
        // 将线程池的名称传递给 taskLoop，用于设置线程名称（在支持的系统上）。
        mThreads.emplace_back(&ThreadPool::taskLoop, this, name);
    }
}
```

### 3.3 实现析构函数

作用：销毁线程池，确保所有线程安全退出。

实现要点：

1. 加锁设置 mStop为 true 
2. 使用 notify_all()唤醒所有等待线程 
3. 遍历所有线程并调用 join()等待结束 
4. 确保线程安全退出，避免资源泄漏

```cpp
// 原理：mStop 是一个标志位，用于通知线程退出主循环。mCv.notify_all() 确保所有线程都能检测到 mStop 的变化。join 确保线程池销毁前所有线程都已完成任务。
ThreadPool::~ThreadPool() {
    {
        std::unique_lock<std::mutex> lock(mQueueMutex);
        // 设置 mStop 为 true，通知所有线程停止运行。
        mStop = true;
    }
    // 使用 mCv.notify_all() 唤醒所有等待的线程。
    mCv.notify_all();
    // 使用 std::for_each 和 std::thread::join 等待所有线程执行完毕。
    // std::for_each(mThreads.begin(), mThreads.end(), std::bind(&std::thread::join, std::placeholders::_1));
    // 等待所有线程结束
    for (auto &thread : mThreads) {
        if (thread.joinable()) {
            thread.join();
        }
    }
}
```

## 04.实现清理任务

### 4.1 清空普通任务

作用：清空普通任务队列 mTasks。

```cpp
void ThreadPool::clearTasks() {
    // 功能：使用互斥锁保护队列，逐个移除任务。
    std::unique_lock<std::mutex> lock(this->mQueueMutex);
    while (!this->mTasks.empty()) {
        mTasks.pop();
    }
}
```

### 4.2 清空优先任务

```cpp
void ThreadPool::clearPreTasks() {
    //遍历逐个清除任务
    std::unique_lock<std::mutex> lock(this->mQueueMutex);
    while(!this->mPrepTasks.empty()) {
        mPrepTasks.pop();
    }
}
```

### 4.3 清空所有任务

作用：清空所有任务队列（包括普通任务和优先任务）。

```cpp
// 功能：依次调用 clearTasks 和 clearPreTasks。
void ThreadPool::clearAllTasks() {
    clearTasks();
    clearPreTasks();
}
```

## 05.线程主循环函数

实现要点：

1. 使用条件变量等待任务或停止信号 
2. 优先处理优先任务队列 
3. 任务执行在锁外进行，避免阻塞其他线程 
4. 提供线程生命周期回调点

### 5.1 线程启动时

```cpp
void ThreadPool::taskLoop(const std::string &name) {
    onThreadAttached(); // 线程启动回调
}
```

### 5.2 线程执行任务

```cpp
void ThreadPool::taskLoop(const std::string &name) {
    onThreadAttached(); // 线程启动回调
    while (true) {
        std::shared_ptr<std::packaged_task<int()> > preTask;
        std::shared_ptr<std::packaged_task<int()> > task;
        {
            // 等待条件变量：停止信号或任务可用
            std::unique_lock<std::mutex> lock(this->mQueueMutex);
            //使用 mCv.wait 等待任务队列非空或线程池停止。
            mCv.wait(lock,[this] {
                return this->mStop || !this->mTasks.empty() || !this->mPrepTasks.empty();
            });
            // 检查停止信号
            if (this->mStop) {
                // 如果 mStop 为 true，调用 onThreadDetached() 并退出循环。
                onThreadDetached();
                return;
            }
            // 优先执行优先任务队列 mPrepTasks 中的任务。
            if (!this->mPrepTasks.empty()) {
                preTask = this->mPrepTasks.front();
                this->mPrepTasks.pop();
            }
            //执行普通任务队列 mTasks 中的任务。
            if (!this->mTasks.empty()) {
                task = this->mTasks.front();
                this->mTasks.pop();
            }
        }
        // 执行任务（在锁外执行，避免阻塞其他线程）
        if (preTask) {
            //std::cout << "preTask begin" << std::endl;
            (*preTask)();
            //std::cout << "preTask end" << std::endl;
        }
        if (task) {
            //std::cout << "task begin" << std::endl;
            (*task)();
            //std::cout << "task end" << std::endl;
        }
    }
}
```

### 5.3 一些边界条件

`taskLoop` 设计上要应对几种边界情况，逐条说明：

1. **虚假唤醒（spurious wakeup）**：操作系统可能在没有 `notify` 的情况下唤醒等待中的线程，所以 `mCv.wait(lock, predicate)` 第二个参数是必须的——它会**反复检查条件**，假唤醒就继续 sleep。如果写成无谓词的 `mCv.wait(lock)`，会偶发"明明没任务却开始 pop 队首"的崩溃。
2. **同时收到 stop 和 task**：检查顺序是 `if (mStop) return; → 再处理任务`。意味着**收到停止信号后队列里残留的任务会被丢弃**——这是有意为之的"快速停机"语义。如果改为"必须做完队列里所有任务再退出"（`graceful shutdown`），需要把判断改成 `if (mStop && mTasks.empty() && mPrepTasks.empty()) return;`。
3. **任务里抛异常**：`(*task)()` 调用时 `packaged_task` 内部会捕获异常并通过 `future.get()` 重新抛出——所以**异常不会逃出 worker 线程导致进程崩溃**，但调用方调 `future.get()` 时要 try/catch。
4. **优先任务持续涌入饿死普通任务**：如果连续 `postPreTask` 速度 > 工作线程消化速度，`mPrepTasks` 永远非空，`mTasks` 里的任务**永远没机会运行**。本案例没解决此问题，工程级线程池会引入"老化（aging）"机制——普通任务等够 N ms 后强制提升优先级。

> 💡 **这 4 条几乎涵盖了所有"看似简单实则坑爹"的并发陷阱**——背下来，下次写任何"线程 + 队列"的代码都能本能地想到这些角落。

## 06.任务提交实现

实现要点：

1. 使用模板支持任意类型任务 
2. 使用 std::packaged_task封装任务 
3. 返回 std::future用于获取结果 
4. 任务加入队列后唤醒一个线程 
5. 检查线程池状态，避免已停止时提交任务

### 6.1 提交普通任务

```cpp
template<class F, class... Args>
auto ThreadPool::postTask(F &&f, Args &&... args) -> std::future<typename std::result_of<F(Args...)>::type> {

    using return_type = typename std::result_of<F(Args...)>::type;
    // 封装任务为 packaged_task
    auto task = std::shared_ptr<std::packaged_task<return_type()> >(
        new std::packaged_task<return_type()>(std::bind(std::forward<F>(f), std::forward<Args>(args)...)));
    std::future<return_type> res = task->get_future(); {
        std::unique_lock<std::mutex> lock(mQueueMutex);
        // don't allow enqueueing after stopping the pool
        if (mStop) {
            throw std::runtime_error("enqueue on stopped ThreadPool");
        }
        // push 一个 task任务
        mTasks.push(task);
    }
    mCv.notify_one();
    return res;
}
```

### 6.2 提交优先任务

```cpp
template<class F, class... Args>
auto ThreadPool::postPreTask(F &&f, Args &&... args) -> std::future<typename std::result_of<F(Args...)>::type> {
    using return_type = typename std::result_of<F(Args...)>::type;
    auto task = std::shared_ptr<std::packaged_task<return_type()> >(
        new std::packaged_task<return_type()>(std::bind(std::forward<F>(f), std::forward<Args>(args)...)));
    std::future<return_type> res = task->get_future(); {
        std::unique_lock<std::mutex> lock(mQueueMutex);
        if (mPrepTasks.size() > 500) {
            std::future<int> empFuture = std::async(std::launch::async, []() -> int { return 0; });
            return empFuture;
        }

        // don't allow enqueueing after stopping the pool
        if (mStop) throw std::runtime_error("enqueue on stopped ThreadPool");

        mPrepTasks.push(task);
    }
    mCv.notify_one();
    return res;
}
```

  ```
- **类型推导**：auto和decltype
- **完美转发**：std::forward

    std::unique_lock<std::mutex> lock(mQueueMutex);
    return mPrepTasks.size();
}
```

### 7.3 返回线程数量

```cpp
std::size_t ThreadPool::allTaskSize() {
    return taskSize() + preTaskSize();
}
```

## 08.主函数测试

测试要点：

1. 验证线程池创建和销毁 
2. 测试普通任务和优先任务的执行顺序 
3. 验证任务结果获取 
4. 测试任务清理功能 
5. 验证批量任务处理能力

### 8.1 模拟耗时操作

```cpp
int test1(std::string name, int age) {
    std::cout << "打印1：" << name << " , age " << age << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::cout << "打印1：等待了100ms" << std::endl;
    return 1;
}

int test2(std::string name, int age) {
    std::cout << "打印2：" << name << " , age " << age << std::endl;
    return 2;
}
```

### 8.2 创建线程池

```cpp
ThreadPool pool(4);   // 创建 4 个工作线程
auto future1 = pool.postTask(&test1, "yangchong", 30);
auto future2 = pool.postTask(&test2, "tangxinyi", 29);
```

构造时立即创建 4 个 `std::thread`，每个线程进入 `taskLoop` 在 `mCv.wait` 上**沉睡**（不消耗 CPU）。`postTask` 把任务封装为 `packaged_task` 入队、`mCv.notify_one` 唤醒一个线程——**这是生产者-消费者模式的标准 C++ 实现**。

### 8.3 提交普通任务和优先任务

```cpp
// 提交普通任务
auto future3 = pool.postTask([]() {
    std::cout << "打印3：提交普通任务" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "打印3：提交普通任务执行结束" << std::endl;
    return 42;
});
// 提交优先任务
auto future4 = pool.postPreTask([]() {
    std::cout << "打印4：提交优先任务" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "打印4：提交优先任务执行结束" << std::endl;
    return 100;
});

// 等待结果（阻塞式获取）
std::cout << "future1 result = " << future1.get() << std::endl;
std::cout << "future2 result = " << future2.get() << std::endl;
std::cout << "future3 result = " << future3.get() << std::endl;
std::cout << "future4 result = " << future4.get() << std::endl;
```

预期打印（多线程并发，前几行**输出顺序不固定**，但 `打印1` 必然在 `打印1：等待了100ms` 之前）：

```text
打印1：yangchong , age 30
打印2：tangxinyi , age 29
打印3：提交普通任务
打印4：提交优先任务
打印1：等待了100ms
打印3：提交普通任务执行结束
打印4：提交优先任务执行结束
future1 result = 1
future2 result = 2
future3 result = 42
future4 result = 100
```

4 个任务被分发到 4 个工作线程**并行执行**，3 个 sleep 任务几乎同时完成（总耗时约 1s 而不是 3s）——这就是线程池的价值：**N 个任务、N 个线程并行 → 总耗时 ≈ max(单任务耗时)**。`future.get()` 阻塞等待对应任务完成并取出返回值，类型由模板参数自动推导（test1 / test2 返回 int，lambda 返回 int）。

> 🧠 **`postPreTask` 优先级生效场景在"任务多于线程"时**：本例 4 任务 / 4 线程，优先和普通在 `taskLoop` 拿任务时是同一拨被唤醒，看不出优先效果。改成"提交 10 个普通任务 + 1 个优先任务"，会看到优先任务**永远先于后续普通任务被执行**。这就是双队列调度的本质：**preTask 队列空之前，task 队列等着**。

> ⚠️ **`future.get()` 只能调用一次**：第二次调用会抛 `std::future_error`。如果要把结果分享给多处，得用 `std::shared_future`——但本案例不需要，因为 future 都是临时局部变量。

> 💡 **完整 main 推荐结构**：
> ```cpp
> int main() {
>     ThreadPool pool(4);
>     auto f1 = pool.postTask(&test1, "yangchong", 30);
>     auto f2 = pool.postTask(&test2, "tangxinyi", 29);
>     auto f3 = pool.postTask([]() { /* ... */ return 42; });
>     auto f4 = pool.postPreTask([]() { /* ... */ return 100; });
>     std::cout << f1.get() << " " << f2.get() << " "
>               << f3.get() << " " << f4.get() << std::endl;
>     return 0;   // 触发 ~ThreadPool() → mStop=true → notify_all → 4 线程 join
> }
> ```
> `return 0` 后 `pool` 走析构，**自动 join 所有工作线程，0 个 dangling thread**——这就是 9.2 RAII 保证的"用完即净"。

## 09.核心设计思想

### 9.1 生产者-消费者

- **生产者**：调用 postTask/postPreTask 提交任务的线程
- **消费者**：线程池中的工作线程
- **缓冲区**：任务队列(mTasks/mPrepTasks)
- **同步机制**：互斥锁(mQueueMutex)+条件变量(mCv)

这种模式解耦了任务提交和执行，提高了系统的吞吐量和响应能力。

### 9.2 RAII资源管理

- **构造函数**：创建线程资源
- **析构函数**：自动释放资源（通知停止+等待线程结束）
- **异常安全**：确保异常情况下资源正确释放

```cpp
ThreadPool::~ThreadPool() {
    {
        std::unique_lock<std::mutex> lock(mQueueMutex);
        mStop = true;
    }
    mCv.notify_all();
    for (auto &thread : mThreads) {
        if (thread.joinable()) thread.join();
    }
}
```

### 9.3 双队列优先级设计

- **普通任务队列(mTasks)**：先进先出(FIFO)
- **优先任务队列(mPrepTasks)**：高优先级任务
- **调度策略**：

```cpp
if (!mPrepTasks.empty()) { // 优先处理优先任务
    preTask = std::move(mPrepTasks.front());
    mPrepTasks.pop();
}
if (!mTasks.empty()) { // 再处理普通任务
    task = std::move(mTasks.front());
    mTasks.pop();
}
```

这种设计实现了： 1.紧急任务优先处理；2.普通任务公平调度；3.避免优先级反转问题

### 9.4 future/promise

基于 `future/promise` 的任务结果处理

```cpp
template<class F, class... Args>
auto ThreadPool::postTask(F &&f, Args &&... args) -> std::future<typename std::result_of<F(Args...)>::type> {

    using return_type = typename std::result_of<F(Args...)>::type;
    // 封装任务为 packaged_task
    auto task = std::shared_ptr<std::packaged_task<return_type()> >(
        new std::packaged_task<return_type()>(std::bind(std::forward<F>(f), std::forward<Args>(args)...)));
    // 获取future用于获取结果
    std::future<return_type> res = task->get_future();
    // 任务加入队列
    {
        std::unique_lock<std::mutex> lock(mQueueMutex);
        // push 一个 task任务
        mTasks.push(task);
    }
    mCv.notify_one();
    return res;
}
```

这种设计实现了：1.异步任务结果获取；2.任务执行状态跟踪；3.异常传播机制

### 9.5 线程生命周期

- **线程创建**：构造函数中创建固定数量线程
- **线程回收**：析构函数中安全停止并回收
- **线程状态回调**：

```cpp
void onThreadAttached() { /* 线程启动时调用 */ }
void onThreadDetached() { /* 线程退出时调用 */ }
```

提供扩展点用于线程本地存储(TLS)初始化等操作

### 9.6 锁粒度优化

- **细粒度锁**：只在访问共享数据时加锁
- **锁外执行**：任务执行在锁范围外进行

```cpp
{
    std::unique_lock<std::mutex> lock(mQueueMutex);
    // 访问共享数据
} // 锁自动释放

// 在锁外执行任务
if (task) task(); 
```

这种设计：1.减少锁竞争；2.提高并发性能；3.避免任务执行阻塞其他线程

### 9.7 可扩展性设计

- **模板化任务提交**：支持任意类型任务
- **生命周期回调**：提供扩展点
- **状态查询接口**：便于监控

```cpp
size_t getTaskCount() const;
size_t getPriorityTaskCount() const;
size_t getThreadCount() const;
```

### 9.8 潜在改进方向

1. **动态线程调整**：根据负载自动增减线程
2. **任务窃取机制**：提高负载均衡
3. **任务超时处理**：防止任务长时间阻塞
4. **任务依赖管理**：支持有依赖关系的任务
5. **线程本地队列**：减少锁竞争


## 10.性能与安全平衡
### 10.1 唤醒策略优化

**唤醒策略优化**

- `notify_one()`：提交单个任务时只唤醒一个线程
- `notify_all()`：停止时唤醒所有线程

### 10.2 异常安全

**异常安全**。任务提交时检查线程池状态

```cpp
if (mStop) {
   throw std::runtime_error("线程池已停止，无法提交任务");
}
```

任务执行异常通过future传播

### 10.3 资源清理

```cpp
void clearTasks();
void clearPreTasks();
void clearAllTasks();
```

提供任务队列清理机制，防止无效任务堆积

### 10.4 并发编程技术

1. 锁粒度控制：最小化临界区范围；任务执行在锁外进行
2. 线程安全队列：互斥锁保护队列操作；条件变量同步访问
3. 优雅停止机制：mStop标志位；notify_all唤醒所有线程；join等待线程结束
4. 任务优先级管理：双队列设计（普通/优先）；优先任务优先调度

### 10.5 性能优化技术

1. 避免虚假唤醒：条件变量使用谓词参数
  ```cpp
  mCv.wait(lock, [this] { 
      return mStop || !mTasks.empty() || !mPrepTasks.empty(); 
  });
  ```
2. 任务窃取避免：固定线程数量；工作线程只从共享队列取任务
3. 唤醒优化：提交单个任务时使用notify_one；停止时使用notify_all
4. 移动而非拷贝：任务对象移动而非拷贝；减少内存操作开销

### 11.3 三个延伸挑战

**A（基础）· 统计任务排队时长**：为每个 `submit` 的任务记录"入队时间戳"，工作线程取出时计算"排队时长 = 开始执行时间 - 入队时间"。打印统计摘要（min / max / avg / p99）。这是**性能分析的第一步**。

**C（挑战）· 无锁队列**：把 `std::queue<Task> + std::mutex` 换成 `moodycamel::ConcurrentQueue` 或自己用 `std::atomic` 实现一个 MPMC 无锁环形缓冲。比较 10M 次 submit + execute 的耗时。完成这个挑战，你可以直接跳到**卷三第 7-10 章 原子内存序 / 无锁编程**。
