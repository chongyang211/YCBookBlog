## 01.项目需求和功能

### 1.1 需求介绍

银行账户管理系统，满足你提出的功能需求。该系统支持开户、存款、取款、查询余额、转账、保存数据到文件以及从文件读取数据。

### 1.2 功能要求

**功能要求**：

1. **开户**：创建新账户，输入账户号、姓名和初始余额。
2. **存款**：根据账户号存款，更新账户余额。
3. **取款**：根据账户号取款，更新账户余额。
4. **查询余额**：根据账户号查询当前余额。
5. **转账**：支持从一个账户转账到另一个账户。
6. **保存数据到文件**：将账户数据保存到文件中。
7. **从文件读取数据**：启动时从文件加载账户数据。

### 1.3 设计思路

**面向对象设计**

- **Account 类**：表示一个银行账户，封装了账户号、姓名、余额等属性，以及存款、取款、转账等行为。
- **Bank 类**：管理多个账户，提供开户、存款、取款、查询余额、转账等功能。
- **FileManager 类**：负责将账户数据保存到文件和从文件加载数据，实现了数据的持久化。

**模块化设计**将系统分为多个模块（类），每个模块负责特定的功能：

- **Account**：账户的核心逻辑。
- **Bank**：账户的管理和操作。
- **FileManager**：文件读写操作。
- **Main 函数**：用户交互界面。

**数据持久化**

- 使用文件存储账户数据，确保程序关闭后数据不会丢失。
- 文件格式为 CSV（逗号分隔值），便于读取和解析。

### 1.4 涉及知识点

**面向对象编程（OOP）**

- **封装**：将账户的属性和行为封装在 `Account` 类中，隐藏内部实现细节。
- **继承**：本案例未使用继承，但可以通过继承扩展功能（如不同类型的账户）。
- **多态**：本案例未使用多态，但可以通过多态实现更灵活的设计（如不同账户类型的行为差异）。

**标准模板库（STL）**

- **`std::vector`**：用于存储多个账户，提供动态数组的功能。
- **`std::string`**：用于处理字符串（如账户号、姓名）。
- **`std::ifstream` 和 `std::ofstream`**：用于文件的读写操作。
- **`std::stringstream`**：用于解析文件中的 CSV 数据。

**文件操作**

- **文件读写**：使用 `std::ifstream` 和 `std::ofstream` 实现文件的读取和写入。
- **CSV 格式**：文件中的数据以逗号分隔，便于解析和存储。

**用户输入处理**

- **`std::cin` 和 `std::getline`**：用于从用户输入中获取数据。
- **输入验证**：确保用户输入的金额为正数，账户号存在等。

**错误处理**

- **空指针检查**：在查找账户时，检查返回的指针是否为空。
- **文件打开检查**：在读写文件时，检查文件是否成功打开。

**循环和条件语句**

- **`while` 循环**：用于主菜单的持续显示和用户交互。
- **`switch` 语句**：根据用户选择执行不同的操作。

**函数和模块化**

- **函数封装**：将功能封装到独立的函数中（如 `displayMenu`、`findAccount`）。
- **模块化设计**：将不同功能分配到不同的类中，提高代码的可维护性。

### 2.2 打印菜单

下面是 `BankUserManager.cpp` 中 `showMain()` 的真实写法。注意三个关键点：**全局 `Bank bank`**、**`cin >> choice` 之后立刻 `cin.ignore` 吃掉换行**、**文件名作为局部变量在 `case 7/8` 间共用**。

```cpp
#include "BankUserManager.h"
#include "Bank.h"
#include "FileManager.h"
#include <iostream>
#include <string>
#include <limits>
#include <cstdio>

// 全局 Bank 对象：整个程序共享同一个账户容器
// 生命周期 = 进程生命周期；main 中无需 new，也不会泄漏
Bank bank;

int main() {
    showMain();
    return 0;
}

int showMain() {
    // 数据文件名：保存 / 加载都用它，便于后续改成命令行参数
    std::string filename = "accounts.txt";
    while (true) {
        displayMenu();
        int choice;
        std::cin >> choice;
        // ⚠️ 关键一步：数字读完后，缓冲区里还留着一个 '\n'
        // 若不清掉，后续 openAccount() 里的 getline 会直接读到空字符串
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');

        switch (choice) {
            case 1: { printf("1. 开户\n");           openAccount();   break; }
            case 2: { printf("2. 存款\n");           deposit();       break; }
            case 3: { printf("3. 取款\n");           withdraw();      break; }
            case 4: { printf("4. 查询余额\n");       checkBalance();  break; }
            case 5: { printf("5. 转账\n");           transfer();      break; }
            case 6: { printf("6. 显示所有账户\n");   bank.displayAllAccounts(); break; }
            case 7: {
                printf("7. 保存数据到文件\n");
                FileManager::saveToFile(bank, filename);
                break;
            }
            case 8: {
                printf("8. 从文件加载数据\n");
                FileManager::loadFromFile(bank, filename);
                bank.displayAllAccounts();   // 加载完顺手展示一遍，方便肉眼校验
                break;
            }
            case 0: {
                printf("0. 退出\n");
                std::cout << "退出系统。\n";
                return 0;
            }
            default: {
                std::cout << "无效选择，请重试！\n";
                break;
            }
        }
    }
    return 0;
}
```

> 🧠 **为什么选择 `Bank bank;` 做全局变量？** 因为 `openAccount / deposit / withdraw` 这些**交互层函数**都需要操作同一个账户容器。三种常见方案：① 全局变量（当前做法，最简单）；② 函数传参 `openAccount(Bank& bank)`；③ 把所有函数挪进 `Bank` 类做成员函数（[06.6.2 合并版](#)的做法）。全局变量的缺点是"单元测试时不好替换实现"，但对学习型案例完全够用——看到 ② ③ 两种写法时不要慌，它们只是"把全局状态搬到参数 / 成员里"而已。

class Account {

思考一个问题：为什么构造函数中，字符串string前面要用const修饰，不用可以吗？

```cpp
// 当前的写法（推荐）。const std::string&：传递引用，不会复制字符串，性能更好
Account(const std::string& accNumber, const std::string& accName, double initialBalance);
// 如果不用const和引用。std::string：传值，会复制整个字符串对象，性能较差

```

const 关键字确保在构造函数中不会意外修改传入的参数：

```cpp
Account(const std::string& accNumber, const std::string& accName, double initialBalance) {
    // accNumber = "modified"; // 编译错误！const保护了参数
    this->accountNumber = accNumber; // 正确：只是读取和赋值
}
```

虽然技术上可以不用const，但会失去这些优势，所以强烈建议保持当前的写法。

1. 性能优势：避免不必要的字符串复制
2. 安全性：防止意外修改参数
3. 灵活性：可以接受各种形式的字符串参数

### 3.3 新增开户

创建用户后，我们需要把用户放到集合中。在这里，直接使用c++中vector容器来存储账户的数据。

openAccount() 是银行系统中的开户功能，负责为新客户创建银行账户。功能概述

1. 收集用户信息 - 获取账户号、姓名、初始余额
2. 数据验证 - 确保输入格式正确
3. 创建账户 - 调用银行系统创建新账户
4. 用户交互 - 提供友好的输入提示

```cpp
// 开户：用户输入 → 局部变量 → Bank 对象 → Account 对象创建
void openAccount() {
    // 1. 声明局部变量存储用户输入
    std::string accNumber, name;  // 账户号和姓名（字符串类型）
    double initialBalance;        // 初始余额（浮点数类型）

    // 2. 获取账户号
    std::cout << "请输入账户号: ";
    std::getline(std::cin, accNumber);   // ← 用 getline 而非 cin>>，为了兼容带空格的输入
    if (bank.findAccount(accNumber) != nullptr) {
        std::cout << "账户号已存在！" << std::endl;
        return;
    }

    // 3. 获取用户姓名
    std::cout << "请输入姓名: ";
    std::getline(std::cin, name);        // 姓名可能含空格 / 中文，同样用 getline

    // 4. 获取初始余额（带循环校验：非数字 / 负数都重新输入）
    std::cout << "请输入初始余额: ";
    while (!(std::cin >> initialBalance) || initialBalance < 0) {
        std::cout << "请输入有效的非负数: ";
        std::cin.clear();                // 清除 fail state
        std::cin.ignore(10000, '\n');    // 丢掉坏输入，防止死循环
    }
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');  // 为下一次 getline 清掉 '\n'

    // 5. 调用银行系统创建账户
    bank.createAccount(accNumber, name, initialBalance);
}
```

思考一个问题：为何字符串用 `getline`，而数字用 `cin >>`？两者行为对比：

| 工具 | 分隔符 | 典型场景 | 踩坑点 |
|------|--------|---------|--------|
| `std::getline(cin, str)` | 换行符 `\n` | 姓名、地址这种"可能含空格" | 前面 `cin>>` 残留的 `\n` 会让它瞬间返回空串 |
| `std::cin >> num` | 空白字符（空格/Tab/换行） | 数字、单个单词 | 输入 `abc` 会进 fail state，不 `clear()` + `ignore()` 就死循环 |

**组合拳**：只要同时出现 `cin >>` 和 `getline`，就必须在 `cin >> x;` 之后补一行 `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');`——这是 C++ 交互式程序最经典的"换行符魔咒"解法。

然后我们看一下创建用户和添加用户到集合中的代码

```cpp
// Bank类，开户
void createAccount(const std::string& accNumber, const std::string& accName, double initialBalance) {
    //创建用户对象
    Account newAccount(accNumber, accName, initialBalance);
    //将用户对象存储到集合中
    accounts.push_back(newAccount);
    std::cout << "开户成功！" << std::endl;
}

// Account
Account::Account(const std::string &accNumber, const std::string &accName, double accBalance) {
    this->accountNumber = accNumber;
    this->name = accName;
    this->balance = accBalance;
}
```

代码执行流程：

1. 创建临时对象：在栈上创建Account对象
2. 复制构造：push_back会复制这个对象到vector中
3. 析构临时对象：方法结束时临时对象被销毁
4. 保留副本：vector中保存了对象的副本

思考一个问题，这里创建用户对象，然后存储到集合中。创建对象有哪些方式，当前代码有优化空间吗？

1. 方法1: 栈上创建临时对象

直接初始化（当前使用的方式）。优点：语法简洁，自动管理内存。缺点：会发生复制，性能稍差

```cpp
Account newAccount(accNumber, accName, initialBalance);
```

拷贝初始化。可能触发额外的复制构造函数调用

```cpp
Account newAccount = Account(accNumber, accName, initialBalance);
```

列表初始化（C++11）。现代C++推荐方式，更安全

```cpp
Account newAccount{accNumber, accName, initialBalance};
```

2. 直接在容器中构建（推荐）

```cpp
void Bank::createAccount(const std::string &accNumber, const std::string &accName, double initialBalance) {
  // 直接在vector中构造对象，避免复制
  accounts.emplace_back(accNumber, accName, initialBalance);
  std::cout << "开户成功！" << std::endl;
}
```

优势分析：

✅ 零复制：直接在容器内存位置构造对象
✅ 性能更好：避免临时对象创建和复制
✅ 内存效率：减少内存分配次数

3. 动态内存分配

传统new方式。需要手动管理内存，容易内存泄漏

```cpp
void Bank::createAccount(const std::string &accNumber, const std::string &accName, double initialBalance) {
    Account* newAccount = new Account(accNumber, accName, initialBalance);
    accounts.push_back(*newAccount);  // 解引用后复制
    delete newAccount;  // 手动释放内存
}
```

智能指针方式

```cpp
// 如果accounts是 vector<unique_ptr<Account>>
void Bank::createAccount(const std::string &accNumber, const std::string &accName, double initialBalance) {
    auto newAccount = std::make_unique<Account>(accNumber, accName, initialBalance);
    accounts.push_back(std::move(newAccount));
}
```

设计模式体现：

1. 命令模式: openAccount()作为一个命令封装了开户操作
2. 委托模式: 将具体的账户创建委托给Bank类处理
3. 分层架构: UI层(openAccount) → 业务层(Bank) → 数据层(Account)

### 3.5 数据验证补全

上一节 3.3 的代码对"账户号已存在"做了拦截，但还缺了几项校验——让我们对照一下**源码中已有的**和**仍需补全的**：

| 校验点 | 源码是否已做 | 说明 |
|--------|------|------|
| 账户号重复 | ✅ 已做 | `bank.findAccount(accNumber) != nullptr` → return |
| 初始余额为负 | ✅ 已做 | `while (... || initialBalance < 0)` 循环重输 |
| 输入非数字导致 fail state | ✅ 已做 | `while (!(std::cin >> initialBalance))` + `cin.clear()` |
| 账户号为空字符串 | ❌ 未做 | 留给延伸挑战 A |
| 姓名为空 | ❌ 未做 | 留给延伸挑战 A |
| 账户号格式（6 位数字等） | ❌ 未做 | 留给延伸挑战 A |

**源码里那段"非数字 + 负数"双保险长什么样**（3.3 里已经贴过，这里聚焦讲原理）：

```cpp
while (!(std::cin >> initialBalance) || initialBalance < 0) {
    std::cout << "请输入有效的非负数: ";
    std::cin.clear();                // ① 清除 fail 标志位
    std::cin.ignore(10000, '\n');    // ② 丢掉坏输入直到换行
}
```

**三条规则要同时满足**循环才退出：① `cin >> x` 成功返回（输入是数字）；② `x >= 0`；③ 只要前两条任一失败就继续提示。`cin.clear()` 不处理 `ignore()`，反之亦然——两者**必须成对出现**，少写一个都会导致死循环（fail state 不清，下一次 `cin >>` 直接返回不读；残留坏输入不清，刚 clear 完立刻再次失败）。

**验证一下重复开户的拒绝路径**：先开 `12345 / 张三 / 1000`，再用相同账户号开第二次：

```text

账户号已存在！
```

`findAccount` 返回非空指针 → 立即 `return`，没走到 `createAccount`。这正是"先查再写"模式：每一次写操作前都先 `find`，能挡住绝大多数业务异常（重复主键、转账给自己、给不存在的账户存钱……）。

> ⚠️ **真实项目中的更严格做法**：应当把"输入 + 校验 + 转换"封装成一个**独立的输入函数** `double readPositiveDouble(const std::string& prompt);`，把 3 行重复的 `cin/clear/ignore` 收进去。本案例为了和源码 1:1 对应没做这层抽象，但做大项目时这是第一个应该提炼的工具函数——延伸挑战 A 会引导你完成这件事。

思考一个问题：为什么在 Bank::deposit 方法中要使用指针而不是普通对象？

1. 该案例中使用指针，主要是避免对象复制。
  ```cpp
  // 使用指针（正确方式）
  Account* account = &(*it);  // 获取原对象的地址
  account->deposit(amount);   // 直接修改vector中的原对象
  ```

优势分析： 1.零复制：只存储对象地址，4-8字节；2.直接修改：操作的就是vector中的原对象；3.数据一致：余额真正被更新

2. 使用普通对象，无法修改原对象，导致存款操作失败。

```
// 如果使用普通对象（错误方式）
Account account;  // 默认构造的空对象
for (auto it = accounts.begin(); it != accounts.end(); ++it) {
    if (it->getAccountNumber() == accNumber) {
        account = *it;  // 复制整个Account对象！
        break;
    }
}
account.deposit(amount);  // 只修改了副本，原对象不变！
```

使用普通对象存在的问题：

- 复制开销：Account对象包含string和double，复制成本高
- 修改失效：修改的是副本，vector中的原对象余额不会改变
- 数据不一致：存款操作失败，但用户以为成功了

值语义 vs 指针语义，核心概念理解：

```cpp
// 值语义：操作副本
Account copy = original;    // 创建副本
copy.deposit(100);         // 修改副本，原对象不变

// 指针语义：操作原对象
Account* ptr = &original;  // 指向原对象
ptr->deposit(100);         // 修改原对象
```

void Bank::transfer(const std::string &fromAccNumber, const std::string &toAccNumber, double amount) {
    //先找到转入账户
    Account* fromAccount = findAccount(fromAccNumber);
    //然后找到转出账户
    Account* toAccount = findAccount(toAccNumber);
    if (fromAccount && toAccount) {
        //两个账户不为空时，才可以转账
        fromAccount->transfer(*toAccount, amount);
    } else {
        std::cout << "账户不存在！" << std::endl;
    }
}

//在Account中
bool Account::transfer(Account &targetAccount, double amount) {
    if (amount > 0 && amount <= balance) {
        balance -= amount;
        targetAccount.deposit(amount);
        std::cout << "转账成功！当前余额: " << balance << std::endl;
        return true;
    } else {
        std::cout << "转账金额无效或余额不足！" << std::endl;
        return false;
    }
}

### 5.1 保存数据到文件

`FileManager::saveToFile` 把内存中的 `vector<Account>` 一行一行写成 CSV 文件，实现"进程退出后数据不丢"。先看**最简版本**理解骨架，再看源码里的**进阶版本**看看多做了什么。

#### 骨架版：理解 4 个步骤

- `ofstream`：输出文件流，专门用于写入文件
- `std::ios::out`：指定为输出模式，文件存在则覆盖

```cpp
void FileManager::saveToFile(const Bank &bank, const std::string &filename) {
    std::ofstream ofs;
    ofs.open(filename, std::ios::out);
    if (ofs.is_open()) {
        //获取所有账户集合（const 引用，避免复制整个 vector）
        const std::vector<Account> &accounts = bank.getAccounts();
        //遍历存储数据
        for (std::vector<Account>::const_iterator it = accounts.begin(); it != accounts.end(); ++it) {
            ofs << it->getAccountNumber() << ","
                << it->getName() << ","
                << it->getBalance() << "\n";
        }
        ofs.close();
        std::cout << "数据保存成功" << std::endl;
    } else {
        std::cout << "无法打开文件" << std::endl;
    }
}
```

**业务流程 4 步**：① `bank.getAccounts()` 拿只读引用；② 迭代器逐个访问 `Account`；③ 按 `"accNum,name,balance\n"` 格式拼字符串；④ 通过 `<<` 操作符写入磁盘。

思考一下：`const std::vector<Account>&` 里的 `const` 为何不能省？

1. **避免复制整个 vector**（性能）：去掉 `&` 就会触发一次拷贝构造，100 万账户时是灾难性的开销
2. **保证不修改原数据**（语义）：`saveToFile` 是"只读操作"，`const` 是把这个承诺写进类型里——编译器会替我们检查，任何试图 `accounts.push_back(...)` 的代码都会编译失败

#### 进阶版：源码里实际的写法

打开 `bank/FileManager.cpp` 看真实实现，你会发现比骨架版多了 4 处改进：

```cpp
void FileManager::saveToFile(const Bank &bank, const std::string &filename) {
    std::ofstream ofstream;
    ofstream.open(filename.c_str(), std::ios::out);
    if (!ofstream.is_open()) {
        std::cout << "无法打开文件" << std::endl;
        return;                                    // ① 及早返回：减少嵌套层级
    }
    ofstream << "AccountNumber,Name,Balance\n";    // ② CSV 表头：第三方工具可读

    const std::vector<Account> &accounts = bank.getAccounts();
    for (const auto& account : accounts) {         // ③ 范围 for + auto：C++11 简化写法
        ofstream << "\"" << account.getAccountNumber() << "\","
                << "\"" << account.getName() << "\","
                << std::fixed << std::setprecision(2)           // ④ 固定 2 位小数
                << account.getBalance() << "\n";
        if (ofstream.fail()) {
            throw std::runtime_error("写入文件失败");           // ⑤ 写失败抛异常
        }
    }
    ofstream.flush();                              // ⑥ 强制刷新缓冲区
    std::cout << "数据保存成功" << std::endl;
}
```

| 编号 | 改进点 | 为什么 |
|------|-------|-------|
| ① | 及早返回（guard clause） | `if (!...) return;` 比 `if (...) { 正常逻辑 } else { 错误 }` 缩进更浅 |
| ② | 加 CSV 表头 | Excel / pandas / `csv.DictReader` 都能按列名识别 |
| ③ | `for (const auto& x : v)` | 比迭代器版本少写一半代码，不需要 `it->` 语法 |
| ④ | `std::fixed + setprecision(2)` | `ofs << 150.0` 默认打印 `150`，加了之后打印 `150.00`——金额场景必须固定 2 位 |
| ⑤ | `throw runtime_error` | 磁盘满 / 权限丢失等极端场景，默默吞掉会让用户以为保存成功 |
| ⑥ | `flush()` | 确保数据真正落盘，而不是停在操作系统缓冲区里——进程崩了也不会丢 |

> 💡 **为什么 `filename.c_str()` 而不是直接 `filename`？** 在 C++11 之前，`ofstream::open` 只接受 `const char*`，必须用 `.c_str()` 转换。C++11 之后两种都支持，但老代码里普遍保留这种写法——读到时不要疑惑。

### 5.2 从文件读取数据

反向操作：把 CSV 文本一行行解析回 `Account` 对象，并塞回 `Bank` 的 `vector` 里。

```cpp
void FileManager::loadFromFile(Bank &bank, const std::string &filename) {
    std::ifstream ifs;
    ifs.open(filename.c_str(), std::ios::in);
    if (ifs.is_open()) {
        //创建一个集合
        std::vector<Account> accounts;
        //一次读取一行
        std::string line;
        while (std::getline(ifs, line)) {
            // 将每行转换为字符串流
            std::istringstream iss(line);
            std::string accNumber, name, balance;
            // 使用逗号作为分隔符，提取字段
            if (std::getline(iss, accNumber, ',') &&
                std::getline(iss, name, ',') &&
                std::getline(iss, balance, ',')) {
                std::cout << "账号: " << accNumber << ", 用户名: " << name
                          << ", 余额: " << balance << std::endl;
                try {
                    double value = std::stod(balance);
                    std::cout << "余额，转换后的值: " << value << std::endl;
                    accounts.push_back(Account(accNumber, name, value));
                } catch (const std::invalid_argument& e) {
                    std::cerr << "余额，无效的参数: " << e.what() << std::endl;
                } catch (const std::out_of_range& e) {
                    std::cerr << "余额，超出范围: " << e.what() << std::endl;
                }
            } else {
                std::cerr << "解析失败: " << line << std::endl;
            }
        }
        ifs.close();
        std::cout << "数据加载成功！" << std::endl;
    } else {
        std::cout << "无法打开文件" << std::endl;
    }
}
```

**解析链路**（磁盘字节流 → 对象）：

```text
accounts.txt  ──→  std::getline(ifs, line)     // ① 切"行"：遇 '\n' 停
                    "001,yangchong,150"
                         │
                         ▼
              std::istringstream iss(line)     // ② 把这行包成一个字符串流
                         │
                         ▼
     std::getline(iss, field, ',') ×3           // ③ 切"字段"：遇 ',' 停，切 3 次
        │        │        │
      "001"  "yangchong"  "150"
                         │
                         ▼
                    std::stod(balance)          // ④ 字符串 → double（可能抛异常）
                         │
                         ▼
              Account(accNumber, name, value)   // ⑤ 构造对象
                         │
                         ▼
                  accounts.push_back(...)       // ⑥ 收入局部 vector
```

> ⚠️ **源码里的一个隐藏 bug**：`loadFromFile` 只把数据 `push_back` 到**局部变量** `accounts`，**没有**调用 `bank.setAccounts(accounts)` 写回 `Bank`！这意味着函数结束时所有加载的数据会随局部变量析构——打印看起来正常，但 `bank.displayAllAccounts()` 其实还是旧数据。**修复方法**是在 `ifs.close()` 之前加一行：
>
> ```cpp
> bank.setAccounts(accounts);   // 把解析好的 vector 塞回 Bank
> ```
>
> 这正是 `Bank.h` 里为什么要提供 `setAccounts` 方法的原因——延伸挑战 D 会让你补上这个修复并复现前后差异。

### 5.3 存数据潜在问题

**问题 1：字段分隔符与数据冲突**

```cpp
// 当前实现的问题
ofs << it->getName() << ",";  // 如果姓名包含逗号怎么办？

// 姓名："张,三" 会导致 CSV 格式错误
// 保存结果：123456,张,三,1500.50  // 被误解析为 4 个字段
```

**修法**：① 用引号包围字段（5.1 进阶版做法）；② 换一个罕见分隔符如 `|`；③ 换成 JSON/protobuf 等有明确转义规则的格式。

**问题 2：只检查 open、不检查 write**

```cpp
if (ofs.is_open()) {
    // 只检查文件打开，没有检查写入是否成功
    // 磁盘满 / 只读挂载 / 硬件故障时，写入静默失败
}
```

**修法**：每次 `<<` 后都查 `ofs.fail()`，或者循环结束时 check 一次，失败就抛异常（5.1 进阶版做法）。

**问题 3：文件编码问题**

中文姓名在 Windows（GBK）和 Linux/macOS（UTF-8）之间搬移时乱码——当前实现没有显式指定编码。**修法**：① 规定"文件一律 UTF-8"；② 读取时先检测 BOM 头并按需转换；③ 换成 JSON 等自描述编码的格式。

**小结**：这 3 个问题把"玩具级 CSV"和"生产级数据文件"分开了。本案例主要目标是"跑通闭环"，不追求生产级别——但理解问题所在，比假装问题不存在更重要。

## 07.项目概括总结

### 7.1 类详细设计

#### 7.1.1 Account 类（实体层）

**属性**：

- `accountNumber`：账户号
- `name`：账户持有人姓名
- `balance`：账户余额

**方法**：

- `deposit` / `withdraw` / `transfer`：三大核心业务动作
- `display`：格式化输出
- `getXxx() const`：只读访问器

**设计要点**：所有 setter 都不暴露——余额的变更只能通过 `deposit/withdraw/transfer` 这三条受控路径，把"不变式"（余额 ≥ 0、存取必须是正数）封装在类内部。

#### 7.1.2 Bank 类（管理层）

**属性**：

- `std::vector<Account> accounts`：账户容器

**方法**：

- `createAccount` / `findAccount`：生命周期 + 定位
- `deposit` / `withdraw` / `queryBalance` / `transfer`：按账户号分发到对应 `Account`
- `displayAllAccounts` / `getAccounts` / `setAccounts`：批量操作 + 外部数据交换

**设计要点**：Bank **不直接持有业务规则**，它只负责"按账号找对象"然后把操作委托给 `Account`——单一职责原则的直接体现。

#### 7.1.3 FileManager 类（持久化层）

**方法（全部 `static`）**：

- `saveToFile(const Bank&, const std::string&)`
- `loadFromFile(Bank&, const std::string&)`

**设计要点**：所有方法都是 `static`——说明 `FileManager` 无状态（不存储任何成员变量），只是一组"工具函数"的命名空间。这比写一堆全局函数更有组织感，也比写成单例更轻量。

#### 7.1.4 BankUserManager.cpp（交互层）

**功能**：

- `displayMenu` / `showMain`：显示菜单 + 主循环 + switch 分发
- `openAccount` / `deposit` / `withdraw` / `checkBalance` / `transfer`：5 个交互函数，负责"收数据 + 交给 Bank"

**设计要点**：**UI 层绝不碰业务规则**。所有 `openAccount` 做的只是"把 `cin` 读到的字符串/数字转交给 `bank.createAccount`"——有一天改成 GUI 或 HTTP API，只需要替换这一层。

### 7.2 类关系图与职责边界

```text
┌─────────────────────────────────────────┐
│   交互层 BankUserManager.cpp            │   ← 只做 I/O，不写业务规则
│   - showMain() + 8 个菜单函数           │
│   - 全局 Bank bank;                     │
└────────────────┬────────────────────────┘
                 │ 调用
                 ▼
┌─────────────────────────────────────────┐
│   管理层 Bank                            │   ← 按账号分发，委托给 Account
│   - vector<Account> accounts;           │
│   - createAccount/findAccount/...       │
└────────────────┬────────────────────────┘
                 │ 组合（vector<Account>）
                 ▼
┌─────────────────────────────────────────┐
│   实体层 Account                         │   ← 承担业务规则：余额不变式
│   - string accountNumber/name;          │

└─────────────────────────────────────────┘
                 ▲
                 │ 静态方法读写

```

**关键分割线**：

- UI 和管理层的分界线：**"是在和人对话，还是在和数据对话？"**
- 管理和实体的分界线：**"是在处理集合，还是在处理单体？"**
- 持久化和其他所有层的分界线：**"是在和磁盘打交道，还是在和内存打交道？"**

把这三条分界线画清楚，未来即使要支持 10 种账户类型 / GUI 界面 / MySQL 后端，系统的主结构都不需要推倒重来。

### 7.3 扩展性设计

| 扩展方向 | 需要改动的层 | 不需要改动的层 |
|---------|-------------|--------------|
| 支持多种账户类型（储蓄/信用卡） | Account（改为基类 + 虚函数） | Bank / FileManager / UI（多态透明） |
| 改用 GUI（Qt/ImGui） | 新写一个 UI 层 | Account / Bank / FileManager 完全不动 |

这就是**分层架构**的价值：**变更被限制在一两层之内**，而不是到处散落。

## 08.衔接与延伸

### 8.1 与上一案例的差异

| 维度 | 01 通讯录 | 02 银行账户（本篇） |
|------|----------|---------------------|
| 数据封装 | `struct Person` 裸数据 | `class Account` + `private` 成员 + `getter` |
| 容器 | `Person personArray[100]` 定长数组 | `std::vector<Account> accounts` 动态数组 |
| 持久化 | ❌ 无 | ✅ `FileManager` 类 + CSV 文件 |
| 输入处理 | `cin >>` 足够 | `cin >>` + `getline` + `cin.ignore` 组合 |
| 异常处理 | ❌ 无 | ✅ `try/catch` 处理 `std::stod` 抛的异常 |
| 模块切分 | 1 个管理类 | 4 层架构（UI / 管理 / 实体 / 持久化） |

### 8.2 与下一案例的递进

[03.职工管理系统](./03.职工管理系统.md) 会让你看到本案例**最大的局限**——`Account` 只有一种类型。如果银行要支持"储蓄账户"和"信用卡账户"两种，存款规则不同（信用卡可以透支）、显示格式不同，**本案例的 `Account` 类该怎么改？** 03 给出的答案是：**抽象基类 + 虚函数**，即"多态"。延伸挑战 C 就是通往 03 的桥梁。

### 8.3 四个延伸挑战

**A（基础）· 输入校验函数化**：把 `openAccount()` 中反复出现的"`cin` + `clear` + `ignore`"三件套提炼为独立工具函数：

```cpp
// 工具函数签名示例
bool readString(const std::string& prompt, std::string& out, bool allowEmpty = false);
bool readPositiveDouble(const std::string& prompt, double& out);
```

进一步加入业务约束：账户号必须是 6 位数字、姓名非空。可以用 `std::regex`（卷一第 16 章简介）或手写 `isdigit` 循环实现。

**B（进阶）· 利息计算**：为 `Account` 类加一个 `double calcInterest(int days) const` 方法，按"年化 2.5%、日息复利"计算指定天数的利息。主菜单增加"查询利息"选项。这是**运算符重载 + 成员函数 `const`** 的综合练习。

**C（挑战）· 多账户类型（为 03 做准备）**：

- 把 `Account` 标记为抽象基类（加一个纯虚函数 `virtual void printType() const = 0`）
- 派生 `SavingsAccount`（储蓄，只能 `deposit/withdraw`）和 `CreditAccount`（信用卡，允许透支 -5000 额度）
- `std::vector<Account>` 改为 `std::vector<std::unique_ptr<Account>>`（卷一第 12 章）
- 观察：`accounts.push_back(std::make_unique<SavingsAccount>(...))` 后，遍历调用 `acc->display()` 时多态是如何生效的

**D（修 bug）· 补齐 loadFromFile**：5.2 指出 `loadFromFile` 没有调用 `bank.setAccounts(accounts)`，意味着加载的数据**根本没进 Bank**。这是源码中真实存在的 bug：

1. 先编译运行当前版本，选 7 保存 → 退出 → 重启 → 选 8 加载 → 再选 6 查看，观察**列表是空的**
2. 在 `FileManager::loadFromFile` 的 `ifs.close()` 之前加 `bank.setAccounts(accounts);`
3. 重新编译，重复上面步骤，现在选 6 能看到完整账户列表

这是体会"测试驱动"的好机会——**先复现 bug、再修 bug、再验证修复**。
