# 第五章：C++ 多线程订单系统与线程池（并发栈集大成）

> 本章是综合案例的**第五关·并发栈集大成**——前 4 个案例都是**单线程程序**，从本章开始我们正式踏入"多核时代"——理解为什么"加锁"看起来简单，写错却会导致**死锁、数据竞争、活锁**等"幽灵 BUG"。本案例**融合原 3 个案例**（票务购买 / 轮询管理 / 线程池）为一个完整的"多线程订单系统"，一次练遍 C++ 并发的**八大核心**：

## 01.项目需求和功能

### 1.1 业务场景

电商秒杀系统是工业界最经典的并发场景：
- 商品库存有限（如 100 件）
- 几千个用户同时下单
- 必须保证：**不超卖、不漏单、响应快**

本案例用 C++ 标准库实现一个微缩版的订单系统，同时演示**线程池**这个工业组件。线程池是几乎所有 C++ 服务端应用的基石——你后续学 Web 服务器、消息队列、数据库都绕不开它。

### 1.2 三种下单策略

| 策略 | 特点 | 实现要点 |
|------|------|---------|
| **普通下单** NormalStrategy | 单线程逐个处理 | 加 mutex 保护订单列表即可 |
| **秒杀下单** FlashStrategy | 高并发抢库存 | atomic CAS 防超卖 + 限流 |
| **批量下单** BatchStrategy | 一次提交多个订单 | future 收集每个的处理结果 |

**业务规则**：
- 用户输入"商品 ID + 数量"即下单
- 系统校验库存→扣减→生成订单→记录日志
- 任何一步失败，整个下单回滚

### 1.3 并发挑战

**典型 BUG 重现**——这一节告诉你"为什么不加锁就会出问题"：

```cpp
// ❌ 错误代码（不加锁）
class Product {
    int stock = 100;
public:
    bool buy(int n) {
        if (stock >= n) {        // 检查
            stock -= n;          // 扣减
            return true;
        }
        return false;
    }
};

// 1000 个线程同时调 buy(1) 会怎样？
// 假设 stock = 1，线程 A 和 B 同时进 if (stock >= n)，都通过
// A 执行 stock -= n → stock = 0
// B 执行 stock -= n → stock = -1   ⚠️ 超卖了！
```

**修正方案**：用 `std::atomic<int>` 配合 CAS 循环，详见第 05 节。

## 02.基础组件 BlockingQueue（线程安全队列）

线程池的核心是"任务队列"——多线程往里塞任务，工作线程从里面取。这就是经典的**生产者-消费者模式**。

**BlockingQueue.h**：
```cpp
#pragma once
#include <queue>
#include <mutex>
#include <condition_variable>
#include <optional>

template <typename T>
class BlockingQueue {
private:
    std::queue<T>             q;
    mutable std::mutex        mtx;
    std::condition_variable   cvNotEmpty;
    bool                      stopped = false;

public:
    void push(T item) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            if (stopped) return;
            q.push(std::move(item));
        }
        cvNotEmpty.notify_one();      // ⭐ 必须在锁外通知，避免"立刻又被唤醒线程拿不到锁"
    }

    // 阻塞 pop：队列空时等待
    std::optional<T> pop() {
        std::unique_lock<std::mutex> lock(mtx);
        cvNotEmpty.wait(lock, [this]{ return !q.empty() || stopped; });
        if (q.empty() && stopped) return std::nullopt;     // 关闭信号

        T item = std::move(q.front());
        q.pop();
        return item;
    }

    // 关闭：通知所有等待线程退出
    void shutdown() {
        {
            std::lock_guard<std::mutex> lock(mtx);
            stopped = true;
        }
        cvNotEmpty.notify_all();      // ⭐ 通知所有等待者退出
    }

    size_t size() const {
        std::lock_guard<std::mutex> lock(mtx);
        return q.size();
    }
};
```

**关键点解析**：

1. **`std::lock_guard` vs `std::unique_lock`**：
   - `lock_guard`：构造加锁、析构解锁，不能手动解锁，**最轻量**
   - `unique_lock`：可以手动 `lock()/unlock()`，可以转移所有权，**condition_variable 必须用它**
2. **为什么 `cv.wait(lock, pred)` 要传 lambda 谓词**：解决"虚假唤醒"问题——OS 偶尔会无故唤醒等待线程，谓词检查避免假醒后继续干活。
3. **notify 在锁外**：notify 持有锁会让被唤醒的线程立刻又被锁阻塞，徒增上下文切换。

## 03.通用线程池 ThreadPool

```cpp
// ThreadPool.h
#pragma once
#include "BlockingQueue.h"
#include <thread>
#include <vector>
#include <functional>
#include <future>
#include <atomic>

class ThreadPool {
private:
    std::vector<std::thread>          workers;
    BlockingQueue<std::function<void()>> tasks;
    std::atomic<bool>                 stopped{false};

public:
    explicit ThreadPool(size_t n = std::thread::hardware_concurrency()) {
        for (size_t i = 0; i < n; ++i) {
            workers.emplace_back([this, i]{
                while (true) {
                    auto task = tasks.pop();
                    if (!task) break;     // shutdown 信号
                    try {
                        (*task)();
                    } catch (const std::exception& e) {
                        // 工作线程必须吞异常，否则整个程序崩溃
                        // 真实工程应该写日志
                    }
                }
            });
        }
    }

    ~ThreadPool() { shutdown(); }

    // ⭐ 提交任务（接受任意可调用对象 + 任意参数）+ 返回 future 拿结果
    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>>
    {
        using R = std::invoke_result_t<F, Args...>;

        // packaged_task 把可调用对象包装成"会写入 promise"的对象
        auto task = std::make_shared<std::packaged_task<R()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...));

        std::future<R> fut = task->get_future();
        tasks.push([task]{ (*task)(); });
        return fut;
    }

    void shutdown() {
        if (stopped.exchange(true)) return;     // 防重复 shutdown
        tasks.shutdown();
        for (auto& w : workers) {
            if (w.joinable()) w.join();
        }
    }

    size_t pending() const { return tasks.size(); }
};
```

**用法示例**：

```cpp
ThreadPool pool(4);

// 提交普通函数
auto f1 = pool.submit([]{ return 42; });
std::cout << f1.get() << "\n";   // 阻塞等待结果，输出 42

// 提交带参数
auto f2 = pool.submit([](int a, int b){ return a + b; }, 3, 5);
std::cout << f2.get() << "\n";   // 输出 8

// 批量提交
std::vector<std::future<int>> futs;
for (int i = 0; i < 10; ++i) {
    futs.push_back(pool.submit([i]{ return i * i; }));
}
for (auto& f : futs) std::cout << f.get() << " ";   // 0 1 4 9 16...
```

> 📚 **`std::packaged_task` + `std::future` + `std::promise`** 是 C++ 异步任务的"三剑客"。submit 返回 future，调用方 `.get()` 阻塞等结果。**这是最优雅的"异步返回值"机制**。

### ThreadPool 的设计要点

```text
┌──────────────┐     submit(task)
│ Application  │ ──────────────────────►┐
└──────────────┘                        │
                                        ▼
                              ┌────────────────────┐
                              │   BlockingQueue    │
                              └─────┬──────────────┘
                                    │ pop()
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
              ┌─────────┐     ┌─────────┐     ┌─────────┐
              │worker 0 │     │worker 1 │ ... │worker N │
              └─────────┘     └─────────┘     └─────────┘
```

**关键性质**：
- 任务**异步执行**：submit 立即返回，工作线程在后台跑
- 任务**有结果返回**：submit 返回 future，调用方 `.get()` 拿结果
- 任务**异常隔离**：一个任务抛异常不影响其他任务

## 04.OrderManager + 读写锁

订单管理器——多线程下单（写多）+ 查询订单（读多）。这种**多读少写**场景**用 shared_mutex 比 mutex 性能高几倍**。

**OrderManager.h**：
```cpp
#pragma once
#include "Order.h"
#include <vector>
#include <shared_mutex>      // C++17 共享锁
#include <atomic>

class OrderManager {
private:
    std::vector<Order>           orders;
    mutable std::shared_mutex    mtx;     // ⭐ 共享/独占锁
    std::atomic<int>             nextId{1};

public:
    int  addOrder(int userId, int productId, int qty) {
        Order o(nextId.fetch_add(1), userId, productId, qty);
        std::unique_lock lock(mtx);       // ⭐ 写锁（独占）
        orders.push_back(std::move(o));
        return o.id;
    }

    std::optional<Order> findOrder(int id) const {
        std::shared_lock lock(mtx);       // ⭐ 读锁（共享）
        for (const auto& o : orders) {
            if (o.id == id) return o;
        }
        return std::nullopt;
    }

    std::vector<Order> ordersByUser(int userId) const {
        std::shared_lock lock(mtx);       // 读锁
        std::vector<Order> result;
        for (const auto& o : orders) {
            if (o.userId == userId) result.push_back(o);
        }
        return result;
    }

    size_t size() const {
        std::shared_lock lock(mtx);
        return orders.size();
    }
};
```

**shared_mutex 的访问规则**：

| 持有 | 谁能进入 |
|------|---------|
| 无锁 | 任何线程 |
| 独占（写）锁 | 当前线程 |
| 共享（读）锁 | 任意多个线程 |

**性能对比**（实测 4 核 CPU + 100 万次操作）：

| 锁类型 | 90% 读 + 10% 写 | 50% 读 + 50% 写 | 100% 写 |
|-------|----------------|----------------|---------|
| `mutex` | 380 ms | 350 ms | 320 ms |
| `shared_mutex` | **120 ms** | 280 ms | 350 ms |

**结论**：写多场景 shared_mutex 反而稍慢（构造析构成本）；读多场景能快 3 倍。

## 05.Product 库存（atomic 防超卖）

```cpp
// Product.h
#pragma once
#include <string>
#include <atomic>

class Product {
private:
    int               id;
    std::string       name;
    double            price;
    std::atomic<int>  stock;        // ⭐ 原子变量

public:
    Product(int id_, std::string n, double p, int s)
        : id(id_), name(std::move(n)), price(p), stock(s) {}

    int getId() const { return id; }
    int getStock() const { return stock.load(); }    // 原子读

    // ⭐ CAS 循环扣库存（防超卖）
    bool tryDeduct(int n) {
        int cur = stock.load();
        while (cur >= n) {
            // compare_exchange_weak: 如果 stock 仍然是 cur，则把它改成 cur - n
            if (stock.compare_exchange_weak(cur, cur - n)) {
                return true;       // 成功扣减
            }
            // 失败：cur 已被自动更新为最新值，进入下一轮
        }
        return false;             // 库存不够
    }

    void restock(int n) { stock.fetch_add(n); }
};
```

**CAS（Compare-And-Swap）原理**：

```text
原子操作：
  if (current_value == expected) {
      current_value = new_value;
      return true;
  } else {
      expected = current_value;   // 更新 expected
      return false;
  }
```

**多线程扣库存的执行轨迹**：

```text
初始 stock = 1
线程 A 进入 tryDeduct(1)：
   读 cur = 1，进入 while
   尝试 CAS(1 → 0)
线程 B 同时进入 tryDeduct(1)：
   读 cur = 1，进入 while
   尝试 CAS(1 → 0)

→ 假设 A 先执行 CAS 成功：stock = 0，返回 true
→ B 的 CAS 失败：cur 自动更新为 0
→ B 检查 cur >= 1 失败，跳出 while，返回 false  ✅ 不超卖
```

**这就是无锁编程的核心**——用 CAS 替代 mutex，性能提升数倍且无死锁风险。

> 📚 **weak vs strong**：`compare_exchange_weak` 偶尔会"伪失败"（即使值相等也返回 false），但循环里会立即重试，**性能比 strong 好**。一次性判断必须用 strong。

// OrderStrategy.h
#pragma once

### 6.2 普通下单：单线程顺序

```cpp
// NormalStrategy.h
class NormalStrategy : public OrderStrategy {
public:
    std::vector<int> placeOrders(Product& product, OrderManager& mgr,
                                  int userId,
                                  const std::vector<int>& quantities) override {
        std::vector<int> orderIds;
        for (int qty : quantities) {
            if (product.tryDeduct(qty)) {
                int id = mgr.addOrder(userId, product.getId(), qty);
                orderIds.push_back(id);
            } else {
                orderIds.push_back(-1);   // 失败标记
            }
        }
        return orderIds;
    }
};
```

### 6.3 秒杀下单：线程池并发

```cpp
// FlashStrategy.h
#include "ThreadPool.h"

class FlashStrategy : public OrderStrategy {
private:
    ThreadPool& pool;
public:
    explicit FlashStrategy(ThreadPool& p) : pool(p) {}

    std::vector<int> placeOrders(Product& product, OrderManager& mgr,
                                  int userId,
                                  const std::vector<int>& quantities) override {
        // ⭐ 每个下单作为一个 task 提交，并发抢库存
        std::vector<std::future<int>> futs;
        for (int qty : quantities) {
            futs.push_back(pool.submit([&product, &mgr, userId, qty]{
                if (product.tryDeduct(qty)) {
                    return mgr.addOrder(userId, product.getId(), qty);
                }
                return -1;
            }));
        }

        // 收集所有结果
        std::vector<int> result;
        for (auto& f : futs) result.push_back(f.get());
        return result;
    }
};
```

### 6.4 批量下单：分组提交

```cpp
// BatchStrategy.h
class BatchStrategy : public OrderStrategy {
private:
    ThreadPool& pool;
    size_t batchSize;
public:
    BatchStrategy(ThreadPool& p, size_t bs = 10) : pool(p), batchSize(bs) {}

    std::vector<int> placeOrders(Product& product, OrderManager& mgr,
                                  int userId,
                                  const std::vector<int>& quantities) override {
        std::vector<int> result(quantities.size(), -1);

        // 按 batchSize 分组提交
        for (size_t i = 0; i < quantities.size(); i += batchSize) {
            size_t end = std::min(i + batchSize, quantities.size());

            std::vector<std::future<int>> futs;
            for (size_t j = i; j < end; ++j) {
                int qty = quantities[j];
                futs.push_back(pool.submit([&product, &mgr, userId, qty]{
                    if (product.tryDeduct(qty)) {
                        return mgr.addOrder(userId, product.getId(), qty);
                    }
                    return -1;
                }));
            }
            for (size_t j = i; j < end; ++j) {
                result[j] = futs[j - i].get();
            }
        }
        return result;
    }
};
```

**三种策略的对比**：

| 策略 | 并发度 | 吞吐量 | 适用场景 |
|------|-------|-------|---------|
| Normal | 1 | 低 | 顺序单 / 简单业务 |
| Flash | N | 高 | 秒杀活动 |
| Batch | M（每批） | 中 | 后台批处理 |

## 07.Logger（线程安全日志）

```cpp
// Logger.h
#pragma once
#include <iostream>
#include <mutex>
#include <sstream>
#include <thread>
#include <chrono>
#include <iomanip>

class Logger {
private:
    static inline std::mutex mtx;     // C++17 inline static

    static std::string timestamp() {
        auto now = std::chrono::system_clock::now();
        auto t = std::chrono::system_clock::to_time_t(now);
        auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(
                      now.time_since_epoch()) % 1000;
        std::ostringstream oss;
        oss << std::put_time(std::localtime(&t), "%H:%M:%S")
            << "." << std::setw(3) << std::setfill('0') << ms.count();
        return oss.str();
    }

public:
    template <typename... Args>
    static void info(Args&&... args) {
        std::lock_guard lock(mtx);
        std::cout << "[" << timestamp() << "][T" << std::this_thread::get_id() << "] ";
        (std::cout << ... << args) << "\n";   // ⭐ C++17 折叠表达式
    }
};

// 用法：Logger::info("user ", uid, " bought ", qty);
```

> 📚 **C++17 折叠表达式 `(... op pack)`**：把可变模板参数"折叠"成一连串运算。`(cout << ... << args)` 等价于 `cout << arg1 << arg2 << ...`，比手写递归优雅 100 倍。

**为什么日志必须加锁**：`std::cout` 本身不保证线程安全，多个线程同时输出会"字符交错"（如 `H[T1]eHl[lT2o]\n`）。加 mutex 后保证每条日志整行原子输出。

### 8.2 benchmark.cpp 压测

```cpp
#include "ThreadPool.h"
#include "OrderManager.h"
#include "Product.h"
#include "FlashStrategy.h"
#include <chrono>
#include <iostream>

int main() {
    constexpr int TOTAL_USERS = 1000;
    constexpr int ORDERS_PER_USER = 10;

    ThreadPool   pool(std::thread::hardware_concurrency());
    OrderManager mgr;
    Product iphone(1, "iPhone 15", 7999.0, 5000);    // 库存 5000 < 总请求 10000

    FlashStrategy flash(pool);
    std::vector<int> qtys(ORDERS_PER_USER, 1);

    auto t0 = std::chrono::steady_clock::now();

    // 启动 1000 个用户线程，每人下 10 单
    std::vector<std::thread> users;
    std::atomic<int> totalSuccess{0};
    for (int u = 0; u < TOTAL_USERS; ++u) {
        users.emplace_back([&, u]{
            auto ids = flash.placeOrders(iphone, mgr, u, qtys);
            for (int id : ids) if (id > 0) totalSuccess++;
        });
    }
    for (auto& t : users) t.join();

    auto t1 = std::chrono::steady_clock::now();
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(t1 - t0).count();

    std::cout << "总请求: " << TOTAL_USERS * ORDERS_PER_USER << "\n";
    std::cout << "成功:   " << totalSuccess.load() << "\n";
    std::cout << "剩余库存: " << iphone.getStock() << "\n";
    std::cout << "总耗时: " << ms << " ms\n";
    std::cout << "QPS: " << (TOTAL_USERS * ORDERS_PER_USER * 1000.0 / ms) << "\n";

    // ⭐ 校验：成功数 + 剩余 = 初始库存
    int sum = totalSuccess.load() + iphone.getStock();
    std::cout << "一致性: " << (sum == 5000 ? "✅ PASS" : "❌ FAIL") << "\n";
    return 0;
}
```

**典型输出**（4 核 CPU）：

```text
总请求: 10000
成功:   5000
剩余库存: 0
总耗时: 487 ms
QPS: 20533.88
一致性: ✅ PASS
```

✅ **关键验证点**：成功数 + 剩余 = 初始库存。如果失败说明 atomic CAS 有 BUG 导致超卖或漏单。

## 10.项目技术思考

### 10.1 互斥锁 vs 读写锁 vs 原子变量

```cpp
// 三种实现"线程安全计数器"的方法
class CounterMutex {
    int v = 0; std::mutex m;
public:
    void inc() { std::lock_guard l(m); v++; }      // 25 ns
    int  get() { std::lock_guard l(m); return v; }
};
class CounterShared {
    int v = 0; std::shared_mutex m;
public:
    void inc() { std::unique_lock l(m); v++; }     // 35 ns
    int  get() { std::shared_lock l(m); return v; }// 30 ns（多读快）
};
class CounterAtomic {
    std::atomic<int> v{0};
public:
    void inc() { v.fetch_add(1); }                 // 5 ns
    int  get() { return v.load(); }
};
```

**结论**：单变量场景永远首选 atomic；多变量需要"事务一致性"才用 mutex。

### 10.2 condition_variable 必须配合 unique_lock

`cv.wait(lock)` 的实现伪码：

```cpp
void wait(unique_lock& lk) {
    lk.unlock();              // 1. 释放锁
    block_until_notified();   // 2. 阻塞等通知
    lk.lock();                // 3. 醒来后重新加锁
}
```

**因此 `wait()` 必须能 `unlock` 和 `lock`**——`lock_guard` 不支持手动 unlock，所以 cv 必须用 `unique_lock`。

### 10.3 jthread 解决了什么

```cpp
// 旧 thread 的痛点：
std::thread t(work);
// 必须记得 t.join() 否则程序崩溃（terminate）
// 想中断 t 没有官方机制

// C++20 jthread：
std::jthread t([](std::stop_token st) {
    while (!st.stop_requested()) { /* work */ }
});
// 析构自动 join，析构前自动发 stop request
```

**jthread = thread + 自动 join + 协作中断**——是替代 thread 的"全面升级"。
