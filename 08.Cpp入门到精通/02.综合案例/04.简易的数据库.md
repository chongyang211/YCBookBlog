## 1. 数据库系统需求

### 1.1 需求介绍

本项目旨在使用C++实现一个简易的内存数据库系统，帮助学习者理解数据库的基本原理和操作。

该系统支持基本的数据库操作，包括表的创建、数据的增删改查，以及数据的持久化存储。

- **简单易用**：提供直观的API接口，便于理解和使用

## 3. 定义数据结构

### 3.1 列结构体

```cpp
// 数据类型枚举
enum DataType {
    TYPE_INT,      // 整型
    TYPE_FLOAT,    // 浮点型
    TYPE_STRING    // 字符串型
};

// 列类 - 定义表的列结构
class Column {
public:
    std::string name;  // 列名
    DataType type;     // 数据类型

    Column(const std::string& name, DataType type) : name(name), type(type) {}
};
```

**设计说明**：

- 使用枚举类型定义支持的数据类型，确保类型安全
- Column类封装列的基本属性：名称和数据类型
- 构造函数简化对象创建过程

### 3.2 行结构体

**设计说明**：

- 使用void*指针数组存储不同类型的数据。但同时缺少类型安全性，因为void*指针缺乏编译时类型检查
- columnTypes数组记录每个数据的类型，用于正确的类型转换
- 析构函数确保动态分配的内存得到正确释放

```cpp
// 行类 - 存储一行数据
class Row {
public:
    std::vector<void*> data;              // 存储实际数据的指针数组
    std::vector<DataType> columnTypes;    // 存储每列的数据类型

    ~Row() {
        // 析构函数负责释放动态分配的内存
        for (size_t i = 0; i < data.size(); i++) {
            if (data[i]) {
                switch (columnTypes[i]) {
                    case TYPE_INT:
                        delete static_cast<int*>(data[i]);
                        break;
                    case TYPE_FLOAT:
                        delete static_cast<float*>(data[i]);
                        break;
                    case TYPE_STRING:
                        delete static_cast<std::string*>(data[i]);
                        break;
                }
            }
        }
    }
};
```

### 3.3 表结构体

Table类采用了简单直观的关系型数据库表结构设计：

- 包含表的基本信息：表名、列定义、行数据。
- 使用指针数组管理行对象，便于动态添加和删除
- 析构函数确保所有行对象得到正确释放

```cpp
// 表类 - 表示数据库中的一张表
class Table {
public:
    std::string name;              // 表名
    std::vector<Column> columns;   // 列定义
    std::vector<Row*> rows;        // 行数据

    Table(const std::string& name) : name(name) {}

    ~Table() {
        // 析构函数释放所有行对象
        for (size_t i = 0; i < rows.size(); i++) {
            if (rows[i]) delete rows[i];
        }
    }
};
```

列式存储元数据： columns存储表的结构信息（列名和数据类型），使用Column类封装列的属性，包含名称和数据类型枚举

行式存储数据：rows存储实际的数据行，每个Row包含void*指针数组来存储不同类型的数据。

### 3.4 数据库结构体

设计理念：1.Database作为顶层容器，管理多个Table对象；2.采用指针存储Table，便于动态管理和多态扩展。

```text
Database (数据库层)
  └── Table (表层)
      ├── Column (列定义层)
      └── Row (数据行层)
```

职责分离：

1. Database：管理表集合、提供数据库级操作
2. Table：管理行数据、维护表结构
3. Row/Column：处理具体数据存储

```cpp
// 数据库类 - 管理多张表
class Database {
public:
    std::vector<Table*> tables;  // 存储所有表的指针

    ~Database() {
        // 析构函数释放所有表对象
        for (size_t i = 0; i < tables.size(); i++) {
            if (tables[i]) delete tables[i];
        }
    }

    // 核心功能接口
    void createTable(const std::string& tableName, const std::vector<Column>& columns);
    void insertRow(const std::string& tableName, const std::vector<void*>& data);
    void deleteRow(const std::string& tableName, int rowIndex);
    void updateRow(const std::string& tableName, int rowIndex, const std::vector<void*>& data);
    void queryTable(const std::string& tableName);
    void saveToFile(const std::string& filename);
    void loadFromFile(const std::string& filename);
};
```

**设计说明**：

- Database类是系统的核心，管理所有表对象
- 提供完整的数据库操作接口
- 使用RAII原则管理资源生命周期

## 4. 核心功能实现

### 4.1 创建表

```cpp
void Database::createTable(const std::string& tableName, const std::vector<Column>& columns) {
    Table* table = new Table(tableName);  // 创建新表对象
    table->columns = columns;              // 设置列定义
    tables.push_back(table);               // 添加到数据库中
    std::cout << "createTable 表 '" << tableName << "' 创建成功！" << std::endl;
}
```

**实现要点**：

- 动态创建Table对象
- 复制列定义到新表中
- 将表添加到数据库的表集合中
- 提供用户反馈信息

可以在main方法中测试创建表功能，创建数据库测试如下：

```cpp
int main() {
    Database db;
    // 定义 3 列：ID(整型) / Name(字符串) / Age(整型)
    std::vector<Column> columns;
    columns.push_back(Column("ID", TYPE_INT));
    columns.push_back(Column("Name", TYPE_STRING));
    columns.push_back(Column("Age", TYPE_INT));
    db.createTable("Users", columns);
    return 0;
}
```

预期打印：

```text
createTable 表 'Users' 创建成功！
```

只有一行成功提示，但背后已经做了 3 件事：① `Database::tables` 这个 `vector<Table*>` 多了一个元素；② 该元素指向堆上 `new Table("Users")`；③ 这张 `Table` 的 `columns` 成员复制了入参的 3 个 `Column` 对象——schema 已经"安家"了，但 `rows` 还是空的，这就是下一节插入要做的事。

> 🧠 **schema 与 data 分两步走**：传统数据库（MySQL）的 `CREATE TABLE` 和 `INSERT INTO` 是两条独立 SQL，本案例完全照搬这个设计——`createTable` 只设置 `columns`、绝不碰 `rows`。这种**元数据与数据分离**的思路，是 04 案例和 03 职工管理最大的世界观差异：03 里 `Worker` 类的字段写死在 C++ 头文件里，每加一个字段都要改代码；这里加一列只需要 `columns.push_back(Column("xxx", TYPE_INT))`，**程序不用重新编译**。

整体代码如下所示：

```cpp
void Database::insertRow(const std::string& tableName, const std::vector<void*>& data) {
    // 查找目标表
    for (size_t i = 0; i < tables.size(); i++) {
        if (tables[i]->name == tableName) {
            Row* row = new Row();  // 创建新行对象
            row->columnTypes.resize(tables[i]->columns.size());
            
            // 根据列类型复制数据
            for (size_t j = 0; j < tables[i]->columns.size(); j++) {
                row->columnTypes[j] = tables[i]->columns[j].type;
                switch (tables[i]->columns[j].type) {
                    case TYPE_INT:
                        row->data.push_back(new int(*(int*)data[j]));
                        break;
                    case TYPE_FLOAT:
                        row->data.push_back(new float(*(float*)data[j]));
                        break;
                    case TYPE_STRING:
                        row->data.push_back(new std::string(*(std::string*)data[j]));
                        break;
                }
            }
            tables[i]->rows.push_back(row);  // 添加行到表中
            std::cout << "行插入成功！" << std::endl;
            return;
        }
    }
    std::cout << "表 '" << tableName << "' 不存在！" << std::endl;
}
```

存在不足的地方：1.缺少返回值指示操作成功/失败；2.需要验证数据长度与列数匹配；3.应添加类型兼容性检查。

**测试插入数据**。在 4.1 创建表的 `main` 末尾追加两行插入：

```cpp
// 插入第一行：1 / Alice / 25
std::vector<void*> row1;
row1.push_back(new int(1));
row1.push_back(new std::string("Alice"));
row1.push_back(new int(25));
db.insertRow("Users", row1);

// 插入第二行：2 / Bob / 30
std::vector<void*> row2;
row2.push_back(new int(2));
row2.push_back(new std::string("Bob"));
row2.push_back(new int(30));
db.insertRow("Users", row2);

// 故意用错表名，验证错误分支
std::vector<void*> rowX;
rowX.push_back(new int(99));
db.insertRow("NotExist", rowX);
```

预期打印：

```text
表 'Users' 创建成功！
行插入成功！
行插入成功！
表 'NotExist' 不存在！
```

两行成功 + 一行失败——`Users.rows` 多了 2 个 `Row*`、每个 `Row` 内部 `data` 又新 new 了 3 块堆内存（int / string / int），与列定义按位置一一对应。**注意失败分支只是打印一行警告，调用方传进来的 `new int(99)` 那块堆内存却没人 delete——这是当前实现的一个小漏洞**，列在 4.2 末尾的"不足之处"里，正式生产代码必须由调用方在错误分支里手动 `delete`。

> ⚠️ **`void*` 的代价：编译器帮不了你**。如果调用方一不小心把第 2 列的字符串写成 `new std::string` 之外的类型（比如 `new char[]`），insertRow 内部的 `*(std::string*)data[j]` 会**直接 segfault**——`void*` 把"类型由调用方负责"的责任从编译期推到了运行期。这就是延伸挑战 A 推荐换成 `std::variant<int, float, std::string>` 的根本原因：让编译器替你把这层校验做了。

### 4.4 删除行数据

设计理念：

1. 通过表名定位目标表（SQL语义）
2. 使用行索引直接定位要删除的行（简化的WHERE条件）
3. 参数类型选择：const string&避免拷贝，int表示索引位置

步骤1：表查找

```cpp
for (size_t i = 0; i < tables.size(); i++) {
    if (tables[i]->name == tableName) {
        // 找到目标表，执行删除逻辑
    }
}
```

步骤2：索引有效性验证

```cpp
// 边界检查：确保索引非负且在有效范围内
if (rowIndex >= 0 && rowIndex < tables[i]->rows.size()) {
    // 执行删除操作
} else {
    std::cout << "行索引无效！" << std::endl;
}
```

步骤3：内存释放与容器更新

```cpp
delete tables[i]->rows[rowIndex];                    // 释放Row对象内存
tables[i]->rows.erase(tables[i]->rows.begin() + rowIndex); // 从容器中移除
```

内存管理策略： 1.先释放，后移除：确保没有内存泄漏；2.delete调用Row的析构函数，自动释放所有列数据的内存；3.vector::erase()从容器中移除指针，保持容器完整性

```cpp
void Database::deleteRow(const std::string& tableName, int rowIndex) {
    for (size_t i = 0; i < tables.size(); i++) {
        if (tables[i]->name == tableName) {
            // 检查行索引有效性
            if (rowIndex >= 0 && rowIndex < tables[i]->rows.size()) {
                delete tables[i]->rows[rowIndex];  // 释放行对象内存
                tables[i]->rows.erase(tables[i]->rows.begin() + rowIndex);  // 从容器中移除
                std::cout << "行删除成功！" << std::endl;
            } else {
                std::cout << "行索引无效！" << std::endl;
            }
            return;
        }
    }
    std::cout << "表 '" << tableName << "' 不存在！" << std::endl;
}
```

**实现要点**：
- 验证表名和行索引的有效性
- 先释放行对象的内存，再从容器中移除
- 提供详细的错误信息

> 🧠 **`erase` + 显式 `delete` 这个组合很 C++**：`vector<Row*>` 存的是裸指针，`erase` 只把指针从容器里挪走、**不会 delete 指针指向的堆对象**。这就是为什么必须先 `delete tables[i]->rows[rowIndex]`、再 `erase`——顺序反了就漏 delete。如果改成 `vector<unique_ptr<Row>>`，`erase` 会自动 `delete`，多余的手动 `delete` 反而要去掉——这就是延伸挑战里"用智能指针重写"的价值所在。

### 4.5 更新行数据
```cpp
void Database::updateRow(const std::string& tableName, int rowIndex, const std::vector<void*>& data) {
    for (size_t i = 0; i < tables.size(); i++) {
        if (tables[i]->name == tableName) {
            if (rowIndex >= 0 && rowIndex < tables[i]->rows.size()) {
                Row* row = tables[i]->rows[rowIndex];
                // 更新每列的数据
                for (size_t j = 0; j < tables[i]->columns.size(); j++) {
                    switch (tables[i]->columns[j].type) {
                        case TYPE_INT:
                            *(int*)row->data[j] = *(int*)data[j];
                            break;
                        case TYPE_FLOAT:
                            *(float*)row->data[j] = *(float*)data[j];
                            break;
                        case TYPE_STRING:
                            *(std::string*)row->data[j] = *(std::string*)data[j];
                            break;
                    }
                }
                std::cout << "行更新成功！" << std::endl;
            } else {
                std::cout << "行索引无效！" << std::endl;
            }
            return;
        }
    }
    std::cout << "表 '" << tableName << "' 不存在！" << std::endl;
}
```

**实现要点**：
- 直接修改现有行对象中的数据
- 根据数据类型进行正确的指针转换和赋值
- 不需要重新分配内存，提高效率

--------        --------        --------

> ⚠️ **更新和"删旧 + 插新"的内存模型截然不同**：`updateRow` 这里 `*(int*)row->data[j] = *(int*)data[j]` 是**原地修改 int 指向的那块堆内存**——`row->data[j]` 这个 void* 自始至终指着同一块地址。而 03 案例里"修改 = 销毁 + 重建"，因为派生类类型可能换。本案例列类型在 schema 里**已经写死**（INT 永远是 INT，不可能改成 STRING），原地改值即可——少一次 `delete + new` 的开销，性能更好。

> ⚠️ **调用方传进的 `newRow` 元素没人 delete**：`updateRow` 把入参 int / string 的值**复制**到了原对象上，但**入参本身 new 出来的指针**没释放——和 4.2 一样，是 `void*` 接口的设计漏洞。生产代码里 update 调用方应当：
> ```cpp
> for (auto* p : newRow) delete /* 按类型 */ p;  // 用完手动释放
> ```
> 这种"调用方负责释放"的契约必须在文档里写清楚。

### 5.1 保存数据到文件
```cpp
void Database::saveToFile(const std::string& filename) {
    std::ofstream file(filename.c_str(), std::ios::binary);
    if (!file) {
        std::cout << "无法打开文件 '" << filename << "'！" << std::endl;
        return;
    }

    // 保存表的数量
    size_t tableCount = tables.size();
    file.write((char*)&tableCount, sizeof(tableCount));

    // 保存每张表的数据
    for (size_t i = 0; i < tables.size(); i++) {
        Table* table = tables[i];
        
        // 保存表名
        size_t nameLength = table->name.size();
        file.write((char*)&nameLength, sizeof(nameLength));
        file.write(table->name.c_str(), nameLength);

        // 保存列信息
        size_t columnCount = table->columns.size();
        file.write((char*)&columnCount, sizeof(columnCount));
        
        for (size_t j = 0; j < table->columns.size(); j++) {
            const Column& column = table->columns[j];
            size_t columnNameLength = column.name.size();
            file.write((char*)&columnNameLength, sizeof(columnNameLength));
            file.write(column.name.c_str(), columnNameLength);
            file.write((char*)&column.type, sizeof(column.type));
        }

        // 保存行数据
        size_t rowCount = table->rows.size();
        file.write((char*)&rowCount, sizeof(rowCount));

        for (size_t j = 0; j < table->rows.size(); j++) {
            Row* row = table->rows[j];
            for (size_t k = 0; k < table->columns.size(); k++) {
                switch (table->columns[k].type) {
                    case TYPE_INT:
                        file.write((char*)row->data[k], sizeof(int));
                        break;
                    case TYPE_FLOAT:
                        file.write((char*)row->data[k], sizeof(float));
                        break;
                    case TYPE_STRING: {
                        std::string* str = (std::string*)row->data[k];
                        size_t strLength = str->size();
                        file.write((char*)&strLength, sizeof(strLength));
                        file.write(str->c_str(), strLength);
                        break;
                    }
                }
            }
        }
    }

    file.close();
    std::cout << "数据库保存成功！" << std::endl;
}
```

**实现要点**：
- 使用二进制格式保存，提高效率和准确性
- 保存数据结构的层次信息：表数量→表信息→列信息→行数据
- 对字符串类型特殊处理，先保存长度再保存内容
- 确保文件操作的安全性检查

**测试保存**。在 4.6 之后追加一行：

```cpp
db.saveToFile("database.dat");
```

预期打印：

```text
数据库保存成功！
```

只有一行字，但磁盘上多了一个 `database.dat`——用 `xxd database.dat | head` 偷看一眼，会发现它是**纯二进制**的：开头几字节是表数量（size_t = 8 字节），紧接着是表名长度、表名 ASCII、列数量……每个字段都按写入顺序紧凑排布，**没有任何分隔符**。

> 🧠 **二进制 vs 02 案例的 CSV**：02 银行账号管理用的是 `001,yangchong,150` 这种纯文本格式，**人能直接读**但解析时要 `getline + split`、字段类型全是字符串。本案例反过来：**写入时 `file.write((char*)&value, sizeof(int))`，读取时 `file.read` 直接拿到 int 值**——零字符串转换、零精度损失，但代价是文件**完全不可读**，调试时只能写一个 dump 工具。生产数据库基本都走二进制（MySQL `.ibd`、SQLite 文件），原因就是性能和精度。

> ⚠️ **size_t 跨平台陷阱**：`sizeof(size_t)` 在 32 位机器上是 4 字节、64 位机器上是 8 字节。本案例直接 `file.write((char*)&tableCount, sizeof(tableCount))` 把 size_t 原样写进文件——**32 位写、64 位读会立刻 GG**。生产代码应当显式用 `uint32_t` / `uint64_t` 固定大小，并且加 magic number + 版本号在文件头，否则版本一升级就读不出老数据。

### 5.2 从文件加载数据
```cpp
void Database::loadFromFile(const std::string& filename) {
    std::ifstream file(filename.c_str(), std::ios::binary);
    if (!file) {
        std::cout << "无法打开文件 '" << filename << "'！" << std::endl;
        return;
    }

    // 读取表的数量
    size_t tableCount;
    file.read((char*)&tableCount, sizeof(tableCount));

    // 读取每张表的数据
    for (size_t i = 0; i < tableCount; i++) {
        // 读取表名
        size_t nameLength;
        file.read((char*)&nameLength, sizeof(nameLength));
        char* nameBuffer = new char[nameLength + 1];
        file.read(nameBuffer, nameLength);
        nameBuffer[nameLength] = '\0';
        std::string tableName(nameBuffer);
        delete[] nameBuffer;

        Table* table = new Table(tableName);

        // 读取列信息
        size_t columnCount;
        file.read((char*)&columnCount, sizeof(columnCount));

        for (size_t j = 0; j < columnCount; j++) {
            size_t columnNameLength;
            file.read((char*)&columnNameLength, sizeof(columnNameLength));
            char* columnNameBuffer = new char[columnNameLength + 1];
            file.read(columnNameBuffer, columnNameLength);
            columnNameBuffer[columnNameLength] = '\0';
            std::string columnName(columnNameBuffer);
            delete[] columnNameBuffer;

            DataType columnType;
            file.read((char*)&columnType, sizeof(columnType));

            table->columns.push_back(Column(columnName, columnType));
        }

        // 读取行数据
        size_t rowCount;
        file.read((char*)&rowCount, sizeof(rowCount));

        for (size_t j = 0; j < rowCount; j++) {
            Row* row = new Row();
            for (size_t k = 0; k < table->columns.size(); k++) {
                const Column& column = table->columns[k];
                switch (column.type) {
                    case TYPE_INT: {
                        int* value = new int;
                        file.read((char*)value, sizeof(int));
                        row->data.push_back(value);
                        break;
                    }
                    case TYPE_FLOAT: {
                        float* value = new float;
                        file.read((char*)value, sizeof(float));
                        row->data.push_back(value);
                        break;
                    }
                    case TYPE_STRING: {
                        size_t strLength;
                        file.read((char*)&strLength, sizeof(strLength));
                        char* strBuffer = new char[strLength + 1];
                        file.read(strBuffer, strLength);
                        strBuffer[strLength] = '\0';
                        std::string* value = new std::string(strBuffer);
                        delete[] strBuffer;
                        row->data.push_back(value);
                        break;
                    }
                }
            }
            table->rows.push_back(row);
        }

        tables.push_back(table);
    }

    file.close();
    std::cout << "数据库加载成功！" << std::endl;
}
```

**实现要点**：
- 按照保存时的格式逆序读取数据
- 动态分配内存重建数据结构
- 正确处理字符串的读取和内存管理
- 确保读取过程中的内存安全

### 5.3 持久化闭环测试

把"创建 + 插入 + 保存"和"加载 + 查询"分到两个 Database 实例里跑，模拟"程序退出再启动"：

```cpp

    // —— 第一阶段：建表、插数、落盘 ——
    {
        Database db;
        std::vector<Column> columns;
        columns.push_back(Column("ID", TYPE_INT));
        columns.push_back(Column("Name", TYPE_STRING));
        columns.push_back(Column("Age", TYPE_INT));
        db.createTable("Users", columns);

        std::vector<void*> r1;
        r1.push_back(new int(1));
        r1.push_back(new std::string("Alice"));
        r1.push_back(new int(25));
        db.insertRow("Users", r1);

        std::vector<void*> r2;
        r2.push_back(new int(2));
        r2.push_back(new std::string("Bob"));
        r2.push_back(new int(30));
        db.insertRow("Users", r2);

        db.saveToFile("database.dat");
    }   // db 在这里析构，内存全清

    // —— 第二阶段：用一个全新的 Database 加载磁盘数据 ——
    Database newDb;
    newDb.loadFromFile("database.dat");
    newDb.queryTable("Users");
    return 0;
}
```

预期打印：

```text
表 'Users' 创建成功！
行插入成功！
行插入成功！
数据库保存成功！
数据库加载成功！
表 'Users' 数据：
ID      Name    Age
1       Alice   25
2       Bob     30
```

`newDb` 在加载之前是个完全空白的对象——它的 `tables` 是空 `vector`。`loadFromFile` 走完之后，整张 `Users` 表连同 schema、连同两行数据全都重建出来：每一行的 `int` / `string` 都是**新 new 出的堆内存**，`Row*` 也是新的，**和保存前完全是两套对象，但值一模一样**。这就是"持久化"四个字的含义：让数据脱离进程生命周期独立存在。

> 💡 **闭环验证才是判定持久化是否合格的唯一标准**：很多新手的代码 `saveToFile` 看起来没报错就以为成功了，但要么写盘格式漏字段、要么 read 顺序与 write 顺序对不上——这种 bug **只有在"重新加载并对比"时才会暴露**。所以无论是写文件还是写网络协议，**永远要把 save / load 写完后立刻跑一次 round-trip**，并且尽可能加 `assert(saved == loaded)`。02 案例 CSV 持久化、03 案例文本持久化都是这个逻辑。

## 7.问题和思考

### 7.1 遍历为何用size_t

这里提一个问题：for遍历，为何用size_t而不是int？使用size_t的原因是什么？

1.类型匹配

```cpp
// rows.size() 返回的是 size_t 类型
std::vector<Row*> rows;
size_t vectorSize = rows.size();  // 类型匹配
```

2.避免编译器警告

```cpp
// 使用int会产生警告：signed/unsigned comparison
for (int i = 0; i < rows.size(); i++) {  // 警告！
    // ...
}

// 使用size_t没有警告
for (size_t i = 0; i < rows.size(); i++) {  // 正确
    // ...
}
```

3.语义更准确：size_t专门用于表示大小和索引，语义明确。int可以是负数，但数组索引不应该是负数

4.标准库一致性

```cpp
// 标准库容器的成员函数都返回size_t
vector::size()     // 返回size_t
string::length()   // 返回size_t
array::size()      // 返回size_t
```

[05.演讲比赛系统](./05.演讲比赛系统.md) 会切换到**完全不同的思维**——从"通用数据容器"回到"业务专用模型"，但**让 STL 容器来扛重活**。你会看到 `map<int, vector<Player>>` 这样的嵌套容器如何用两三行代码完成本案例需要 50 行手写循环的工作。这一对比会让你深刻理解："会用 STL 的 C++ 工程师一个顶三个"。

### 8.3 三个延伸挑战

**A（基础）· 用 `std::variant` 替换原生 `union`**：如果你当前用的是 `union ColumnValue { int i; float f; char s[64]; }`，升级为 `using ColumnValue = std::variant<int, float, std::string>;`（C++17）。然后用 `std::visit` 统一打印所有类型——代码会从 `switch` 地狱变成优雅的单行。

**B（进阶）· WHERE 子句**：给 `select` 操作加上条件过滤，例如：
```cpp
db.select("users", {"name","age"}, [](const Row& r) { return r.get<int>("age") >= 18; });
```
这里需要用 `std::function<bool(const Row&)>`（卷一第 16 章）作为过滤器参数。

**C（挑战）· 简易 SQL 解析**：从字符串 `"SELECT name FROM users WHERE age > 18"` 解析出动作 / 列 / 表 / 条件，调用对应的 API。这是**字符串处理 + 状态机**的硬核训练，做下来基本等于写了 MiniSQL 的第一版。
