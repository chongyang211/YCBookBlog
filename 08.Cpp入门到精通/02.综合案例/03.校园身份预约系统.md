# 第三章：校园身份预约系统

> 本章是"STL 全家桶 + 多模块协作"的**集中训练**。相比 [02.银行账户](./02.银行账户管理系统.md) 单一业务（账户）+ 单文件 CSV，本案例会做**四件升级**：
>
> 1. **三态身份抽象**：`User` 基类 + `Student / Teacher / Admin` 三种身份子类——比银行账户的"账户类型"层次更深，每种身份有自己的菜单、权限、操作。
> 2. **STL 全家桶**：`std::map<int, Computer>` + `std::multimap<int, Speech>` + `std::set<int>` + `std::sort + lambda`——一次案例练遍卷一第 16 章核心容器和算法。
> 3. **多模块文件矩阵**：`users.csv` + `rooms.csv` + `reservations.csv` 三个文件协同读写，模拟真实系统的"多张表"模型。
> 4. **lambda 排序与统计**：用 lambda 写比较器、过滤器、聚合器，告别"为了一次排序写一个比较函数"。
>
> 学完本章，你将真正理解"STL 是 C++ 的瑞士军刀"。

## 01.项目需求和功能

### 1.1 需求介绍

校园里有三类人需要协同：**学生**预约机房做实验、**教师**审核预约并评分演讲、**管理员**维护系统数据。本案例用一个控制台程序模拟这三类身份的全部交互，让读者一次掌握 **OOP 多态 + STL 全家桶 + 多文件持久化**的协同。

**为什么是"校园系统"而不是"演讲比赛"或"机房预约"？**

原书 12 案例里有"演讲比赛"和"机房预约"两个案例，知识点高度重叠（都是 STL 容器 + 排序 + 文件 IO）。本卷把它们融合为"校园系统"，**让两个业务在同一个程序里共存**——这正是真实工业项目的样子：一个系统服务多种业务。

### 1.2 三类用户的功能矩阵

| 功能 | Student | Teacher | Admin |
|------|---------|---------|-------|
| 登录 | ✅ | ✅ | ✅ |
| 浏览机房 | ✅ | ✅ | ✅ |
| 预约机房 | ✅ | ❌ | ❌ |
| 取消自己预约 | ✅ | ❌ | ❌ |
| 报名演讲 | ✅ | ❌ | ❌ |
| 审核预约 | ❌ | ✅ | ✅ |
| 演讲评分 | ❌ | ✅ | ❌ |
| 添加用户 | ❌ | ❌ | ✅ |
| 添加机房 | ❌ | ❌ | ✅ |
| 数据统计 | ❌ | ✅ | ✅ |

> 这种"按身份分发功能"的设计在工业界叫 **RBAC**（基于角色的访问控制）。本案例只做最简单的"硬编码 RBAC"，企业级 RBAC 见卷四。

### 1.3 设计思路：身份驱动 + 容器分工

**身份驱动**：登录后 `main` 拿到一个 `std::shared_ptr<User>`，调 `user->mainMenu()` 进入该身份独有的菜单——这就是**多态分发**。

**容器分工**：

| 实体 | 容器 | 选型理由 |
|------|------|---------|
| 用户 | `std::map<string, shared_ptr<User>>` | 用账号作主键，O(log n) 查找 |
| 机房 | `std::map<int, Computer>` | 用编号作主键，按编号有序遍历 |
| 演讲报名 | `std::multimap<int, Speech>` | 一个轮次（key = round 1/2）有多个演讲 |
| 已被预约的机房编号 | `std::set<int>` | 快速判断"这个机房是否被预约"，O(log n) |
| 预约记录 | `std::vector<Reservation>` | 顺序追加 + 全量遍历审核 |

**学完这个案例你会懂**：选 STL 容器不是"我习惯用 vector"，而是要根据**访问模式 + 顺序需求 + 是否允许重复**三个维度选择。

## 03.User 抽象身份基类

### 3.1 User.h

```cpp
#pragma once
#include <string>
#include <iostream>

class User {
protected:
    std::string userId;
    std::string userName;
    std::string password;

public:
    User(const std::string& id, const std::string& name, const std::string& pwd)
        : userId(id), userName(name), password(pwd) {}
    virtual ~User() = default;

    // 纯虚：每种身份有自己的菜单
    virtual void mainMenu() = 0;

    // 纯虚：返回身份标签 'S'/'T'/'A'，用于 CSV 反序列化
    virtual char roleTag() const = 0;

    // 校验密码
    bool verify(const std::string& pwd) const { return password == pwd; }

    const std::string& getId()   const { return userId; }
    const std::string& getName() const { return userName; }

    // 序列化为 CSV 行
    virtual std::string toCsv() const {
        return std::string(1, roleTag()) + "," + userId + "," + userName + "," + password;
    }
};
```

### 3.2 三种身份的派生类

**Student.h**（先只放声明，业务实现在第 06 节）：
```cpp
#pragma once
#include "User.h"
class CampusSystem;

class Student : public User {
private:
    CampusSystem* sys;       // 反向引用，用来调用业务方法
public:
    Student(const std::string& id, const std::string& name, const std::string& pwd,
            CampusSystem* s = nullptr)
        : User(id, name, pwd), sys(s) {}
    void mainMenu() override;
    char roleTag() const override { return 'S'; }
    void setSystem(CampusSystem* s) { sys = s; }
};
```

> ⚠️ **设计陷阱**：`Student` 持有 `CampusSystem*` 是为了"学生需要调系统功能"。这里**用裸指针不是疏忽**——`User` 和 `CampusSystem` 互相引用，如果都用 `shared_ptr` 会形成循环引用导致内存泄漏。**这就是用裸指针表达"非拥有关系"**的标准模式。

**Teacher.h** / **Admin.h** 结构完全相同，把类名改成 `Teacher`/`Admin`，`roleTag()` 返回 `'T'`/`'A'` 即可。

### 3.3 演示登录分发

让 `login()` 真正返回不同子类的多态对象（**这是阶段 ① 的最终验收**）：

```cpp
// 把 login() 改成：
shared_ptr<User> login() {
    // ... 输入身份和账号
    switch (role) {
        case 1: return make_shared<Student>(id, "test", pwd);
        case 2: return make_shared<Teacher>(id, "test", pwd);
        case 3: return make_shared<Admin>(id, "test", pwd);
    }
    return nullptr;
}
```

`user->mainMenu()` 会**自动**调用对应子类的菜单——这就是**多态的力量**：`main` 函数完全不需要 `if (role == 1) studentMenu(); else if ...`。

### 4.3 Reservation 预约

```cpp
// Reservation.h
#pragma once
#include <string>

enum class ResStatus { Pending, Approved, Rejected, Cancelled };

class Reservation {
public:
    int         resId;          // 预约 ID（自增）
    std::string studentId;      // 哪个学生（外键）
    int         computerId;     // 哪个机房（外键）
    std::string date;           // 日期 YYYY-MM-DD
    ResStatus   status = ResStatus::Pending;

    Reservation() = default;
    Reservation(int rid, const std::string& sid, int cid, const std::string& d)
        : resId(rid), studentId(sid), computerId(cid), date(d) {}

    std::string statusText() const {
        switch (status) {
            case ResStatus::Pending:   return "待审核";
            case ResStatus::Approved:  return "已批准";
            case ResStatus::Rejected:  return "已拒绝";
            case ResStatus::Cancelled: return "已取消";
        }
        return "未知";
    }
};
```

> 📚 **C++ 知识点 · `enum class`**：相比 C 风格 `enum`，`enum class` 不会污染命名空间，类型也更严格——你必须写 `ResStatus::Pending` 而不能直接写 `Pending`，并且不能隐式转 int。这是卷一第 3 章的内容。

## 05.STL 容器选型与 CampusSystem 总管理器

### 5.1 为什么 map / multimap / set 各取所长

**核心问题**：每个数据放进哪种容器最合适？

| 数据 | 选用 | 理由 |
|------|------|------|
| 用户表 | `map<string, shared_ptr<User>>` | 按 userId 查找，且每个 userId 唯一 |
| 机房表 | `map<int, Computer>` | 按编号查找，编号有序 |
| 演讲报名 | `multimap<int, Speech>` | 一个 round 多个学生报名（重复 key） |
| 已被占用机房 | `set<int>` | 只关心"是否在集合中"，不关心 value |
| 预约记录 | `vector<Reservation>` | 顺序追加 + 全量审核遍历 |

**反例对比**：

❌ 全部用 vector 装：每次查询要 O(n)，10000 用户场景下慢得没法用
❌ 全部用 unordered_map：哈希容器无序，"按编号顺序遍历机房"做不到
❌ 用 vector 装演讲、自己写"按 round 分组"：reinventing the wheel，multimap 一行搞定

### 5.2 CampusSystem.h 总览

```cpp
// CampusSystem.h
#pragma once
#include "User.h"
#include "Computer.h"
#include "Speech.h"
#include "Reservation.h"
#include <map>
#include <set>
#include <vector>
#include <memory>

class CampusSystem {
private:
    std::map<std::string, std::shared_ptr<User>> users;     // 用户表
    std::map<int, Computer>                       rooms;    // 机房表
    std::multimap<int, Speech>                    speeches; // round -> Speech
    std::set<int>                                 reservedRooms;  // 已被预约的机房编号
    std::vector<Reservation>                      reservations;   // 全量预约
    int nextResId = 1;

    std::string usersFile     = "users.csv";
    std::string roomsFile     = "rooms.csv";
    std::string resFile       = "reservations.csv";

public:
    CampusSystem();

    // 登录
    std::shared_ptr<User> login(const std::string& id, const std::string& pwd);

    // ====== Student 业务 ======
    void listRooms() const;
    bool reserveRoom(const std::string& sid, int roomId, const std::string& date);
    bool cancelReservation(const std::string& sid, int resId);
    bool signupSpeech(const std::string& sid, const std::string& topic, int round);

    // ====== Teacher 业务 ======
    void listPendingReservations() const;
    bool reviewReservation(int resId, bool approved);
    void scoreSpeech(const std::string& sid, int round, double score);
    void rankSpeechesByScore(int round) const;     // ⭐ lambda 排序

    // ====== Admin 业务 ======
    bool addUser(std::shared_ptr<User> u);
    bool addRoom(const Computer& c);
    void statistics() const;

    // ====== 持久化 ======
    void loadAll();
    void saveAll();

    // 友元访问（FileStore 需要直接读写私有字段）
    friend class FileStore;
};
```

## 06.Student 业务

### 6.1 浏览机房（map 遍历）

```cpp
void CampusSystem::listRooms() const {
    cout << "\n=== 机房列表 ===\n";
    cout << left << setw(6) << "编号" << setw(8) << "容量"
         << setw(20) << "配置" << setw(8) << "状态\n";
    cout << string(42, '-') << "\n";

    // ⭐ 范围 for + 结构化绑定（C++17）
    for (const auto& [id, room] : rooms) {
        bool occupied = reservedRooms.count(id) > 0;
        cout << left << setw(6) << id << setw(8) << room.capacity
             << setw(20) << room.spec
             << (occupied ? "占用中" : "空闲") << "\n";
    }
}
```

> 📚 **C++17 结构化绑定**：`for (const auto& [id, room] : rooms)` 自动把 `pair<int, Computer>` 拆成 `id` 和 `room`，比 `it->first / it->second` 优雅得多。

### 6.2 预约机房（map + set 联合）

```cpp
bool CampusSystem::reserveRoom(const string& sid, int roomId, const string& date) {
    // 校验机房存在
    if (rooms.find(roomId) == rooms.end()) {
        cout << "[预约] 机房不存在\n";
        return false;
    }
    // 校验未被占用
    if (reservedRooms.count(roomId) > 0) {
        cout << "[预约] 该机房已被预约\n";
        return false;
    }

    Reservation r(nextResId++, sid, roomId, date);
    reservations.push_back(r);
    reservedRooms.insert(roomId);   // ⭐ 同时更新 set 加速后续判断

    cout << "[预约] 提交成功，预约号 " << r.resId << "（待审核）\n";
    return true;
}
```

**两个数据结构同步更新**——这是 STL 应用的常见模式：用 vector 存"完整记录"、用 set 存"快速索引"。

### 6.3 取消预约

```cpp
bool CampusSystem::cancelReservation(const string& sid, int resId) {
    // ⭐ std::find_if + lambda 查找
    auto it = std::find_if(reservations.begin(), reservations.end(),
        [resId, &sid](const Reservation& r) {
            return r.resId == resId && r.studentId == sid;
        });

    if (it == reservations.end()) {
        cout << "[取消] 预约不存在或不属于你\n";
        return false;
    }
    if (it->status != ResStatus::Pending) {
        cout << "[取消] 该预约已被审核，无法取消\n";
        return false;
    }

    it->status = ResStatus::Cancelled;
    reservedRooms.erase(it->computerId);    // 同步清理 set
    cout << "[取消] 已取消\n";
    return true;
}
```

### 6.4 报名演讲（multimap）

```cpp
bool CampusSystem::signupSpeech(const string& sid, const string& topic, int round) {
    if (round != 1 && round != 2) {
        cout << "[演讲] round 只能是 1 或 2\n";
        return false;
    }
    // ⭐ multimap 允许同 key 多 value
    speeches.insert({round, Speech(sid, topic, round)});
    cout << "[演讲] 报名成功 - 第 " << round << " 轮 - " << topic << "\n";
    return true;
}
```

**为什么用 multimap 而不是 `map<int, vector<Speech>>`**？

| 对比 | `multimap<int, Speech>` | `map<int, vector<Speech>>` |
|------|------------------------|---------------------------|
| 插入 | `m.insert({1, s})` | `m[1].push_back(s)` |
| 按 round 全量取 | `m.equal_range(1)` 返回迭代器对 | `m[1]` 返回引用 |
| 跨 round 排序 | 直接全量遍历 | 要先扁平化到 vector |
| 选用 | ✅ 当主要操作是"按 key 分组遍历" | ✅ 当 vector 之间还要计算 |

```cpp
void CampusSystem::listPendingReservations() const {

}

bool CampusSystem::reviewReservation(int resId, bool approved) {

    if (it == reservations.end()) return false;

    it->status = approved ? ResStatus::Approved : ResStatus::Rejected;
    if (!approved) reservedRooms.erase(it->computerId);   // 拒绝时释放占用
```

### 7.2 演讲评分 + lambda 排序

```cpp
void CampusSystem::scoreSpeech(const string& sid, int round, double score) {
    auto range = speeches.equal_range(round);   // ⭐ 取 round 这个 key 的所有 entry
    for (auto it = range.first; it != range.second; ++it) {
        if (it->second.studentId == sid) {
            it->second.score = score;
            cout << "[评分] " << sid << " 第 " << round << " 轮 - " << score << " 分\n";
            return;
        }
    }
    cout << "[评分] 未找到该报名\n";
}

void CampusSystem::rankSpeechesByScore(int round) const {
    // 把 multimap 中 round 的 entry 抽到 vector，按分数排序
    std::vector<Speech> arr;
    auto range = speeches.equal_range(round);
    for (auto it = range.first; it != range.second; ++it) arr.push_back(it->second);

    // ⭐ lambda 比较器：分数高的在前
    std::sort(arr.begin(), arr.end(),
        [](const Speech& a, const Speech& b) { return a.score > b.score; });

    cout << "\n=== 第 " << round << " 轮排名 ===\n";
    int rank = 1;
    for (const auto& s : arr) {
        cout << "  " << rank++ << ". " << s.studentId
             << " - " << s.topic << " - " << s.score << " 分\n";
    }
}
```

> 📚 **lambda 表达式语法**：`[capture](param) -> ret { body }` 这五个部分。本案例的 lambda 大多是"无捕获"或"按引用捕获 [&]"——要用闭包变量时一定要清楚它的生命周期，否则野引用！

### 7.3 算法函数 find_if / count_if

| 算法 | 作用 | 示例 |
|------|------|------|
| `find_if(b,e,pred)` | 找第一个满足条件的迭代器 | 取消预约时找特定 resId |
| `count_if(b,e,pred)` | 统计满足条件的个数 | 数有多少个 Pending 预约 |
| `accumulate(b,e,init,op)` | 累加（含 lambda 自定义运算） | 算所有预约的天数总和 |
| `sort(b,e,cmp)` | 排序（lambda 可自定义） | 演讲按分数倒排 |
| `for_each(b,e,fn)` | 对每个元素执行 fn | 批量处理 |

### 8.2 数据统计（accumulate + lambda）

```cpp
void CampusSystem::statistics() const {
    cout << "\n=== 数据统计 ===\n";
    cout << "用户总数: " << users.size() << "\n";
    cout << "机房总数: " << rooms.size() << "\n";

    // ⭐ accumulate + lambda 实现"按身份分类计数"
    int students = std::accumulate(users.begin(), users.end(), 0,
        [](int sum, const auto& kv) {
            return sum + (kv.second->roleTag() == 'S' ? 1 : 0);
        });
    int teachers = std::accumulate(users.begin(), users.end(), 0,
        [](int sum, const auto& kv) {
            return sum + (kv.second->roleTag() == 'T' ? 1 : 0);
        });

    cout << "  学生: " << students << " | 教师: " << teachers
         << " | 管理员: " << users.size() - students - teachers << "\n";

    cout << "预约总数: " << reservations.size() << "\n";
    int pending = std::count_if(reservations.begin(), reservations.end(),
        [](const Reservation& r) { return r.status == ResStatus::Pending; });
    cout << "  待审: " << pending
         << " | 已审: " << reservations.size() - pending << "\n";

    cout << "演讲报名: " << speeches.size() << " 人次\n";
    cout << "  第 1 轮: " << speeches.count(1)
         << " | 第 2 轮: " << speeches.count(2) << "\n";
}
```

> 这个 `statistics()` 函数把 lambda + STL 算法的精髓全部展示了——**没有一个 for 循环，全是声明式的"我要什么"，而不是"怎么算"**。

|------|------|--------|

### 9.2 完整性校验

加载顺序很关键——**先加载被引用的，再加载引用方**：

```cpp
void CampusSystem::loadAll() {
    // 1. 先加载用户和机房（被引用方）
    loadUsers(usersFile);
    loadRooms(roomsFile);
    // 2. 再加载预约（引用方），同时校验外键
    loadReservations(resFile);
}

void CampusSystem::loadReservations(const string& f) {
    ifstream ifs(f);
    if (!ifs) return;
    string line;
    while (getline(ifs, line)) {
        // ... 解析 5 个字段
        // ⭐ 外键校验
        if (users.count(studentId) == 0) {
            cout << "[Load] 跳过孤儿预约 - 学生 " << studentId << " 不存在\n";
            continue;
        }
        if (rooms.count(roomId) == 0) {
            cout << "[Load] 跳过孤儿预约 - 机房 " << roomId << " 不存在\n";
            continue;
        }
        reservations.push_back({...});
        if (status == ResStatus::Pending || status == ResStatus::Approved) {
            reservedRooms.insert(roomId);   // 重建 set 索引
        }
        nextResId = max(nextResId, resId + 1);
    }
}
```

> ⚠️ **加载顺序错就会全乱**：如果先加载预约再加载用户，外键校验全部失败，所有预约都会被丢弃。**这就是真实数据库系统的"约束依赖"问题**。

### 9.3 完整启动流程

```cpp
int main() {
    CampusSystem sys;
    sys.loadAll();

    while (true) {
        cout << "\n=== 校园系统 ===\n";
        cout << "1. 登录  2. 注册（仅 Admin 已建账号才能登录） 0. 退出\n";
        int op; cin >> op;
        if (op == 0) { sys.saveAll(); break; }
        if (op == 1) {
            string id, pwd;
            cout << "账号: "; cin >> id;
            cout << "密码: "; cin >> pwd;
            auto u = sys.login(id, pwd);
            if (!u) { cout << "登录失败\n"; continue; }

            // 关键：把 sys 注入子类
            if (auto p = dynamic_pointer_cast<Student>(u)) p->setSystem(&sys);
            else if (auto p = dynamic_pointer_cast<Teacher>(u)) p->setSystem(&sys);
            else if (auto p = dynamic_pointer_cast<Admin>(u))   p->setSystem(&sys);

            u->mainMenu();   // ⭐ 多态分发到对应身份的菜单
        }
    }
    return 0;
}
```

> 📚 **`dynamic_pointer_cast<Derived>(basePtr)`**：在 `shared_ptr` 上做"安全的向下转型"。如果基类指针实际不是这个子类，会返回空指针。注意它需要基类有 virtual 函数（多态类型）才能工作。

## 11.项目技术思考

### 11.1 map vs unordered_map 怎么选

| 维度 | `map` | `unordered_map` |
|------|------|-----------------|
| 底层 | 红黑树 | 哈希表 |
| 查找 | O(log n) | O(1) 均摊 |
| 顺序 | 按 key 有序 | 无序 |
| 哈希冲突 | 无此概念 | 有，最坏 O(n) |
| 选用 | 需要"有序遍历"或"范围查询" | 只关心存在性和快速查询 |

**本案例为什么全用 map**：机房列表要按编号有序显示给用户、用户表也常按字典序查看——**有序场景选 map，纯查询场景选 unordered_map**。

### 11.2 multimap vs map<K, vector<V>>

两者功能可以互相替代，但侧重不同：

- `multimap<K, V>`：每个 (K, V) 单独存储，迭代时每个 entry 是 pair。**适合"按 key 分组遍历"**。
- `map<K, vector<V>>`：每个 key 对应一个 vector。**适合"vector 内还要做计算"**（排序、去重、求和）。

本案例 `rankSpeechesByScore` 需要把同 round 的演讲单独排序——其实 `map<int, vector<Speech>>` 会更合适！这就是教学设计的"故意陷阱"，请在挑战 A 中改造它。

### 11.3 shared_ptr 还是 raw pointer

| 关系 | 推荐 |
|------|------|
| User 拥有自己的字段（name/pwd） | 值类型即可 |
| CampusSystem 拥有 User | `shared_ptr<User>`（map 中存这个） |
| User 引用回 CampusSystem | **裸指针 `CampusSystem*`**（避免循环引用！） |

记住这条铁律：**"拥有关系用智能指针，引用关系用裸指针"**——否则 shared_ptr 循环引用，永远释放不掉。这就是为什么 C++ 还有个 `weak_ptr`（卷三再讲）。
