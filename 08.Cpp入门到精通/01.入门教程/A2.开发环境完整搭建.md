## 01.目标与现实

### 1.1 为什么需要"完整"的开发环境

很多 C++ 入门教材的环境部分只让你装一个 Dev-C++ 或者 VC++ 6.0（一个比读者年纪还大的 IDE），结果出现两个问题：

1. **学的语法是 C++98 时代的**——上面给你看的"hello world"用的是 `<iostream.h>`（带 `.h`，已废弃 20 年）
2. **学完写不了真项目**——工业界没人用 Dev-C++

本书的态度是：**第一行 hello world，就用工业界的工具链**。

### 1.2 一个合格 C++ 工作站的最小集

```
┌─────────────────────────────────────────────────────────────┐
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────────┐ │

│  │  GCC / Clang │   │ CMake (3.20+)│   │ VSCode / CLion   │ │
│  │  / MSVC      │   └──────────────┘   └──────────────────┘ │
│  └──────────────┘                                            │
│         +                  +                  +              │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────────┐ │

│  │ gdb / lldb   │   │ vcpkg / Conan│   │ clang-tidy       │ │
```

### 1.3 不同操作系统的差异

| 系统 | 主流编译器 | 包管理 | 优势 |
|------|-----------|--------|------|
| **macOS** | Apple Clang（系统自带）/ GCC（brew） | Homebrew | 与 Linux 一致，工具链整齐 |
| **Linux** | GCC（默认）/ Clang | apt / yum / pacman | 工业界服务器主战场 |
| **Windows** | MSVC / MinGW / Clang-cl | vcpkg / Chocolatey | 游戏 / 桌面应用主战场 |

> **强烈建议**：如果你是新手，且未来想做"后端 / 系统编程 / 嵌入式"方向，**优先用 macOS 或 Linux**。如果用 Windows 必须装 WSL2 或 MSYS2，至少有一个类 Unix 环境。


## 02.编译器三选一对比

### 2.1 GCC：最广泛使用的开源编译器

```
来源：GNU 项目（Free Software Foundation）
发布于：1987 年
许可证：GPL
最新版本：GCC 14.2（2024）
```

**优点**：
- 历史最久、Linux 默认编译器
- 几乎能编译你能想到的任何 C++ 代码
- 优化能力极强（`-O2` / `-O3` / `-Os`）

**缺点**：
- 错误信息冗长，模板出错时能刷出几百行
- macOS 上 `gcc` 命令默认是 Apple Clang 的别名，需要显式安装真正的 GCC

### 2.2 Clang：错误信息友好、与 LLVM 工具链一体

```
来源：Apple、Google 等共同开发
发布于：2007 年
许可证：Apache 2.0
最新版本：LLVM/Clang 18（2024）
```

**优点**：
- **错误信息极其友好**，对模板报错有"指出问题点"的箭头
- 编译速度通常比 GCC 快 10-30%
- 与 LLVM 工具链（lldb、libc++、Sanitizers、clang-tidy、clang-format）一体
- macOS 上是事实默认编译器

**缺点**：
- 个别 GCC 扩展不兼容（极少遇到）

### 2.3 MSVC：Windows 平台的事实标准

```
来源：Microsoft
发布于：1993 年（VC++ 1.0）
许可证：商业（社区版免费）
最新版本：MSVC 19.40（VS 2022 17.10）
```

**优点**：
- Windows 平台兼容性最好
- 与 Visual Studio 调试器深度整合
- C++20 支持速度甚至比 GCC/Clang 快

**缺点**：
- 仅 Windows
- 命令行工具（`cl.exe`）使用习惯与 Unix 系不同
- 编译错误信息不如 Clang 友好

### 2.4 三大编译器选择决策树

```
你的目标平台是什么？
├─ macOS / iOS                  → Clang（系统自带，brew 装更新版本）
├─ Linux 服务器 / 嵌入式         → GCC（默认）+ Clang（备用）
├─ Windows 桌面 / 游戏           → MSVC
└─ 跨平台                       → 三者都装，CI 上跑全部三套
```

> **本书所有代码**都同时在 GCC / Clang / MSVC 通过；个别平台差异会在章节中明确标注。


## 03.macOS 完整环境搭建

### 3.1 安装 Xcode Command Line Tools

```bash
# 一行命令，会弹窗安装（约 2 GB）
xcode-select --install

# 完成后验证
clang++ --version
# 输出形如：Apple clang version 15.0.0 (clang-1500.x.x.x)
```

**这一步装了什么**：

- Apple Clang 编译器（`clang` / `clang++`）
- Apple LLVM 工具链
- `make` / `git` / 标准 Unix 工具
- macOS SDK

### 3.2 通过 Homebrew 安装 GCC 与 LLVM

如果还没装 Homebrew：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

然后安装额外编译器：

```bash
# 安装最新 GCC（带 g++-13 / g++-14 等版本号命令）
brew install gcc

# 安装最新 LLVM（带 clang++ / clang-tidy / clang-format / lldb 等）
brew install llvm cmake ninja

# 验证
g++-14 --version       # GNU GCC 14
$(brew --prefix llvm)/bin/clang++ --version   # 最新 LLVM Clang
cmake --version        # CMake
```

> **注意**：在 macOS 上，`g++` 命令默认指向 Apple Clang。如果想用真正的 GCC，需要写 `g++-14`。

### 3.3 验证三个 hello world

```bash
mkdir -p ~/cpp-test && cd ~/cpp-test
cat > hello.cpp << 'EOF'
#include <iostream>
int main() {
    std::cout << "Hello, modern C++!\n";
}
EOF

# Apple Clang
clang++ -std=c++17 hello.cpp -o hello_clang && ./hello_clang

# Homebrew GCC
g++-14 -std=c++17 hello.cpp -o hello_gcc && ./hello_gcc

# Homebrew Clang（更新版本）
$(brew --prefix llvm)/bin/clang++ -std=c++20 hello.cpp -o hello_llvm && ./hello_llvm
```

三条命令都输出 `Hello, modern C++!` 即环境就绪。


## 04.Linux（Ubuntu/Debian）环境搭建

### 4.1 build-essential 套件

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git gdb

# build-essential 包含：gcc、g++、make、libc 头文件
# 验证
g++ --version    # GNU GCC（取决于 Ubuntu 版本：22.04 是 11，24.04 是 13）
cmake --version  # CMake 3.22+
```

### 4.2 安装高版本 GCC 与 Clang

如果系统自带的 GCC 版本太低，加官方 PPA：

```bash
# 安装 GCC 13
sudo add-apt-repository ppa:ubuntu-toolchain-r/test -y
sudo apt update
sudo apt install -y gcc-13 g++-13

# 安装 Clang 18
wget -qO- https://apt.llvm.org/llvm-snapshot.gpg.key | sudo apt-key add -
sudo apt-add-repository "deb http://apt.llvm.org/$(lsb_release -cs)/ llvm-toolchain-$(lsb_release -cs)-18 main"
sudo apt update
sudo apt install -y clang-18 lldb-18 lld-18 clang-tidy-18 clang-format-18
```

### 4.3 update-alternatives 切换默认编译器

```bash
# 把 g++-13 设成默认 g++
sudo update-alternatives --install /usr/bin/g++ g++ /usr/bin/g++-13 100
sudo update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-13 100

# 验证
g++ --version    # 应该是 13.x
```


## 05.Windows 环境搭建

### 5.1 选项 A：Visual Studio 2022 + MSVC

**最推荐 Windows 用户的方案。**

1. 下载 [Visual Studio 2022 Community](https://visualstudio.microsoft.com/vs/community/)（免费）
2. 安装时勾选 **"使用 C++ 的桌面开发"** 工作负载
3. 自动包含：MSVC 编译器、CMake、Windows SDK、调试器

```cmd
:: 验证（在"开发人员命令提示符"里执行）
cl /?
cmake --version
```

### 5.2 选项 B：MSYS2 + MinGW-w64

如果不想装 Visual Studio：

1. 下载 [MSYS2](https://www.msys2.org/) 安装
2. 打开 MSYS2 MINGW64 终端：

```bash
pacman -Syu
pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-clang mingw-w64-x86_64-cmake mingw-w64-x86_64-ninja
```

把 `C:\msys64\mingw64\bin` 加到 PATH 中即可在 cmd / PowerShell 使用 `g++`。

### 5.3 选项 C：WSL2 + Ubuntu

**强烈推荐**给希望"在 Windows 上以 Linux 方式工作"的读者：

```powershell
# 在 PowerShell（管理员）执行
wsl --install -d Ubuntu-22.04
```

重启后，你将在 Windows 上拥有一个完整的 Ubuntu 环境，按 §04 步骤配置即可。VSCode 通过 *Remote - WSL* 插件直接接入。


## 06.CMake：现代 C++ 项目的标准构建系统

### 6.1 为什么不用 g++ 命令行

```bash
g++ -std=c++17 -Wall -Wextra -O2 -I include -L lib -l mylib \
    src/main.cpp src/utils.cpp src/db.cpp -o app
```

这种命令一旦项目超过 5 个文件就**不可维护**。CMake 让你用**声明式**配置：

```cmake
add_executable(app src/main.cpp src/utils.cpp src/db.cpp)
target_link_libraries(app PRIVATE mylib)
```

### 6.2 一个最小可用的 CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.20)
project(HelloCpp VERSION 1.0 LANGUAGES CXX)

# 全局 C++ 标准
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# 警告全开
if (MSVC)
    add_compile_options(/W4)
else()
    add_compile_options(-Wall -Wextra -Wpedantic)
endif()

add_executable(hello hello.cpp)
```

构建：

```bash
mkdir build && cd build
cmake ..
cmake --build . -j
./hello
```

### 6.3 多文件 / 多目录的 CMake 模板

```
my_project/
├── CMakeLists.txt
├── include/
│   └── my_project/
│       └── utils.hpp
├── src/
│   ├── main.cpp
│   └── utils.cpp
└── tests/
    └── test_utils.cpp
```

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyProject VERSION 1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# 主可执行文件
add_executable(my_project
    src/main.cpp
    src/utils.cpp
)
target_include_directories(my_project PRIVATE include)

# 测试（开关）
option(BUILD_TESTS "Build unit tests" ON)
if (BUILD_TESTS)
    enable_testing()
    add_subdirectory(tests)
endif()
```

> **更复杂的 CMake 模板**（多模块、跨平台、安装、依赖管理）会在卷二第 13 章展开。

### 6.4 CMake 命令速查

| 命令 | 作用 |
|------|------|
| `cmake -S . -B build` | 用源目录 `.`，构建目录 `build` |
| `cmake --build build` | 编译 |
| `cmake --build build -j 8` | 并行 8 线程 |
| `cmake --build build --target clean` | 清理 |
| `cmake --build build --config Release` | 指定 Release 模式（多配置生成器） |
| `cmake -DCMAKE_BUILD_TYPE=Debug -S . -B build` | Debug 模式 |
| `cmake -G Ninja -S . -B build` | 用 Ninja 生成（比 make 快很多） |
| `ctest --test-dir build` | 跑单元测试 |


## 07.VSCode 配置 C++ 开发环境

### 7.1 必装插件清单

| 插件 | 作用 |
|------|------|
| **C/C++**（Microsoft） | 语法高亮、IntelliSense、调试 |
| **CMake Tools**（Microsoft） | CMake 集成、状态栏构建按钮 |
| **CMake** （twxs） | CMake 语法高亮 |
| **clangd**（LLVM） | **最强 C++ LSP**——比微软自带 IntelliSense 准 |
| **CodeLLDB** | LLDB 调试器集成（macOS/Linux） |
| **Better C++ Syntax** | 更细致的语法着色 |

> **重要**：装了 `clangd` 后**禁用 C/C++ 插件的 IntelliSense**（保留它的调试功能）。两者并用会冲突。

### 7.2 推荐的 settings.json

```json
{
    "C_Cpp.intelliSenseEngine": "disabled",
    "clangd.arguments": [
        "--background-index",
        "--clang-tidy",
        "--header-insertion=iwyu",
        "--completion-style=detailed"
    ],
    "cmake.configureOnOpen": true,
    "cmake.buildDirectory": "${workspaceFolder}/build",
    "editor.formatOnSave": true,
    "[cpp]": {
        "editor.defaultFormatter": "llvm-vs-code-extensions.vscode-clangd"
    },
    "files.associations": {
        "*.h": "cpp",
        "*.hpp": "cpp",
        "*.tpp": "cpp"
    }
}
```

`clangd` 需要项目根有 `compile_commands.json`。CMake 自动生成它：

```cmake
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
```

或者构建后做一个软链接：

```bash
ln -s build/compile_commands.json .
```

### 7.3 一键编译 + 调试配置

`.vscode/launch.json`：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug C++ (LLDB)",
            "type": "lldb",
            "request": "launch",
            "program": "${workspaceFolder}/build/my_project",
            "args": [],
            "cwd": "${workspaceFolder}",
            "preLaunchTask": "CMake: build"
        }
    ]
}
```

按 **F5**——CMake 自动构建 → LLDB 启动 → 可以下断点、单步调试。


## 08.其他 IDE 简介

### 8.1 CLion：JetBrains 出品最顺手的 C++ IDE

- 内置 CMake、调试器、版本控制、单元测试集成
- 自带强大的"代码 inspections"
- 学生有免费教育版
- **缺点**：年费 / 内存占用大

### 8.2 Visual Studio：Windows 唯一选择

- Windows 上写 C++ 的"事实标准"
- 调试器是公认的世界第一
- Community 版个人 / 学生 / 小团队免费

### 8.3 Vim / Neovim：硬核选手的"自配 IDE"

- 配 `clangd` + `coc.nvim` / `nvim-lspconfig`，可以达到 IDE 级别的体验
- 学习曲线陡峭，但配好后非常高效

## 10.调试与排错的"工具箱"预告

下面这些工具卷一不展开，但你应当**心中有数**——遇到问题知道用哪个：

| 场景 | 工具 | 在哪卷讲 |
|------|------|--------|
| 运行时崩溃 | gdb / lldb | 卷四第 1、4 章 |
| 内存泄漏 | AddressSanitizer / Valgrind | 卷四第 5、6、7 章 |
| 未定义行为 | UndefinedBehaviorSanitizer | 卷四第 6 章 |
| 数据竞争 | ThreadSanitizer | 卷四第 6 章 |
| 性能分析 | perf / Instruments / Tracy | 卷四第 9-11 章 |
| 静态分析 | clang-tidy / cppcheck | 卷四第 14 章 |
| 代码格式化 | clang-format | 卷四第 14 章 |

**编译期开启 Sanitizer 的命令**（卷四会反复用到）：

```bash
g++ -std=c++17 -g -O1 -fsanitize=address,undefined hello.cpp -o hello_asan
./hello_asan
```


## 11.本章新手陷阱 Top 5

### 陷阱 1：用 macOS 的 `gcc` 以为自己在用 GCC

```bash
$ gcc --version
Apple clang version 15.0.0   # ❌ 这其实是 Clang！
```
**正解**：macOS 上想用真 GCC 必须写 `g++-13` / `g++-14`。

### 陷阱 2：装了多个编译器但 PATH 没指对

`g++ --version` 显示 7.x，但你装了 13.x —— 99% 是 PATH 优先级问题。
**正解**：`which g++` 看实际指向；用 `update-alternatives` 或 PATH 顺序调整。

### 陷阱 3：CMake 不指定 `CMAKE_CXX_STANDARD`

```cmake
add_executable(app main.cpp)  # ❌ 默认 C++14 或更老
```
**正解**：每个 `CMakeLists.txt` 顶部都加上：
```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
```

### 陷阱 4：Windows 上 `cmake --build .` 没指定配置

```cmd
cmake --build .     :: ❌ 默认 Debug，性能很差
cmake --build . --config Release   :: ✅
```

### 陷阱 5：VSCode 同时启用 Microsoft IntelliSense 和 clangd

两者打架，提示一会一个，错误信息混乱。
**正解**：装了 clangd 就把 `"C_Cpp.intelliSenseEngine": "disabled"`。
