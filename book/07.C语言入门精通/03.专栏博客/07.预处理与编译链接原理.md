## 一、引言：从源码到可执行文件

### 1.1 编译的四个阶段

```
hello.c → [预处理] → hello.i → [编译] → hello.s → [汇编] → hello.o → [链接] → hello
```

```bash
# 分步编译
gcc -E hello.c -o hello.i    # 预处理
gcc -S hello.i -o hello.s    # 编译
gcc -c hello.s -o hello.o    # 汇编
gcc    hello.o -o hello      # 链接

# 一步到位
gcc hello.c -o hello
```

### 1.2 为什么要分四个阶段？

每个阶段有明确的职责：

| 阶段 | 输入→输出 | 核心任务 |
|------|----------|---------|
| 预处理 | `.c` → `.i` | 文本替换：宏展开、头文件包含、条件编译 |
| 编译 | `.i` → `.s` | 语义分析：类型检查、优化、生成汇编 |
| 汇编 | `.s` → `.o` | 翻译：将汇编指令转为机器码 |
| 链接 | `.o` → 可执行文件 | 组装：符号解析、地址重定位、合并段 |

## 二、预处理阶段详解

### 2.1 预处理器做什么

```c
// 原始代码 hello.c
#include <stdio.h>
#define PI 3.14159
#define SQUARE(x) ((x) * (x))

int main() {
    double area = PI * SQUARE(5.0);
    printf("面积: %f\n", area);
    return 0;
}
```

预处理后 `gcc -E hello.c`：

```c
// stdio.h的所有内容被展开（通常几千行）
// ...
extern int printf(const char *, ...);
// ...

int main() {
    double area = 3.14159 * ((5.0) * (5.0));
    printf("面积: %f\n", area);
    return 0;
}
```

### 2.2 预处理的完整操作

```
1. 三字符组替换（Trigraph）— C23已移除
   ??= → #, ??( → [, ??) → ]

2. 行拼接
   将 \ 结尾的行与下一行合并

3. 注释替换
   将所有注释替换为单个空格

4. 宏展开
   替换所有 #define 定义的宏

5. 头文件包含
   递归展开 #include 指令

6. 条件编译
   处理 #if/#ifdef/#ifndef/#else/#endif

7. #pragma 指令
   传递给编译器的特殊指令

8. #line 指令
   修改行号和文件名信息
```

### 2.3 #include的搜索路径

```c
#include <stdio.h>    // 尖括号：搜索系统头文件路径
#include "myheader.h"  // 双引号：先搜索当前目录，再搜索系统路径

// 搜索顺序（双引号）：
// 1. 当前文件所在目录
// 2. -I 选项指定的目录
// 3. 系统默认目录（/usr/include, /usr/local/include 等）

// 搜索顺序（尖括号）：
// 1. -I 选项指定的目录
// 2. 系统默认目录
```

```bash
# 查看系统默认搜索路径
gcc -v -E -x c /dev/null

# 添加搜索路径
gcc -I/path/to/headers hello.c
```

## 三、宏定义的高级用法

### 3.1 对象宏与函数宏

```c
// 对象宏
#define MAX_SIZE 100
#define VERSION "1.0.0"

// 函数宏
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define MIN(a, b) ((a) < (b) ? (a) : (b))

// 多行宏
#define SWAP(a, b) do { \
    typeof(a) _tmp = (a); \
    (a) = (b);            \
    (b) = _tmp;           \
} while(0)
```

### 3.2 宏的陷阱

```c
// 陷阱1：缺少括号
#define SQUARE_BAD(x) x * x
int result = SQUARE_BAD(3 + 1);  // 展开为 3 + 1 * 3 + 1 = 7，不是16！
#define SQUARE_GOOD(x) ((x) * (x))  // 正确

// 陷阱2：副作用
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int x = 5, y = 3;
int m = MAX(x++, y++);  // x被增加两次！
// 展开: ((x++) > (y++) ? (x++) : (y++))

// 陷阱3：分号问题
#define LOG(msg) printf("[LOG] %s\n", msg);
if (error)
    LOG("发生错误");  // 分号导致if-else断裂
else
    LOG("正常");

// 解决：使用do-while(0)包裹
#define LOG(msg) do { printf("[LOG] %s\n", msg); } while(0)
```

### 3.3 字符串化与连接

```c
// # 运算符：将参数转为字符串
#define STRINGIFY(x) #x
#define TO_STRING(x) STRINGIFY(x)  // 两层，先展开再字符串化

printf("%s\n", STRINGIFY(hello));     // "hello"
printf("%s\n", STRINGIFY(3 + 4));     // "3 + 4"

#define VERSION_MAJOR 2
printf("%s\n", TO_STRING(VERSION_MAJOR));  // "2"（先展开为2再字符串化）
printf("%s\n", STRINGIFY(VERSION_MAJOR));  // "VERSION_MAJOR"（不展开）

// ## 运算符：连接两个token
#define CONCAT(a, b) a##b
int CONCAT(my, Var) = 42;  // 展开为 int myVar = 42;

#define MAKE_FUNC(name) void func_##name()
MAKE_FUNC(init) { printf("init\n"); }   // void func_init()
MAKE_FUNC(cleanup) { printf("cleanup\n"); }  // void func_cleanup()
```

### 3.4 可变参数宏

```c
// C99引入 __VA_ARGS__
#define LOG(fmt, ...) printf("[LOG] " fmt "\n", ##__VA_ARGS__)
// ## 在__VA_ARGS__为空时去掉前面的逗号

LOG("启动");              // printf("[LOG] 启动\n")
LOG("值=%d", 42);         // printf("[LOG] 值=%d\n", 42)
LOG("x=%d y=%d", 1, 2);  // printf("[LOG] x=%d y=%d\n", 1, 2)

// C23引入 __VA_OPT__
#define LOG2(fmt, ...) printf("[LOG] " fmt __VA_OPT__(,) __VA_ARGS__ "\n")

// 带文件名和行号的日志宏
#define DEBUG(fmt, ...) \
    fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__, ##__VA_ARGS__)
```

### 3.5 预定义宏

```c
printf("文件: %s\n", __FILE__);       // 当前文件名
printf("行号: %d\n", __LINE__);       // 当前行号
printf("函数: %s\n", __func__);       // 当前函数名（C99）
printf("日期: %s\n", __DATE__);       // 编译日期 "Apr 13 2026"
printf("时间: %s\n", __TIME__);       // 编译时间 "14:30:00"
printf("标准: %ld\n", __STDC_VERSION__); // C标准版本

#ifdef __GNUC__
printf("GCC版本: %d.%d.%d\n", __GNUC__, __GNUC_MINOR__, __GNUC_PATCHLEVEL__);
#endif
```

## 四、条件编译

### 4.1 基本指令

```c
// #ifdef / #ifndef
#ifdef DEBUG
    printf("调试信息: x = %d\n", x);
#endif

#ifndef HEADER_H
#define HEADER_H
// 头文件内容
#endif

// #if / #elif / #else
#if defined(LINUX)
    #include <unistd.h>
#elif defined(WINDOWS)
    #include <windows.h>
#else
    #error "不支持的平台"
#endif

// 表达式条件
#if __STDC_VERSION__ >= 201112L
    // C11特性
    _Static_assert(sizeof(int) == 4, "int不是4字节");
#endif

// 编译器特性检查
#if __has_attribute(always_inline)
    #define FORCE_INLINE __attribute__((always_inline)) inline
#else
    #define FORCE_INLINE inline
#endif
```

### 4.2 条件编译的实际应用

```c
// 1. 跨平台兼容
#ifdef _WIN32
    #define PATH_SEP '\\'
    #define EXPORT __declspec(dllexport)
#else
    #define PATH_SEP '/'
    #define EXPORT __attribute__((visibility("default")))
#endif

// 2. 调试/发布版本切换
#ifdef NDEBUG
    #define ASSERT(expr) ((void)0)
    #define LOG(...)     ((void)0)
#else
    #define ASSERT(expr) \
        ((expr) ? (void)0 : assert_fail(#expr, __FILE__, __LINE__))
    #define LOG(...) fprintf(stderr, __VA_ARGS__)
#endif

// 3. 特性开关
#define FEATURE_ENCRYPTION 1
#define FEATURE_COMPRESSION 0

#if FEATURE_ENCRYPTION
    #include "encryption.h"
#endif
```

### 4.3 #pragma指令

```c
// 1. 头文件保护（非标准但广泛支持）
#pragma once

// 2. 对齐控制
#pragma pack(push, 1)
struct Packed { /* ... */ };
#pragma pack(pop)

// 3. 警告控制
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-variable"
int unused = 42;
#pragma GCC diagnostic pop

// 4. 链接时指定库（MSVC）
#pragma comment(lib, "user32.lib")

// 5. 自定义消息
#pragma message("编译mylib模块...")
```

## 五、头文件机制

### 5.1 头文件的作用

```c
// mylib.h — 声明接口
#ifndef MYLIB_H
#define MYLIB_H

// 类型定义
typedef struct {
    int x, y;
} Point;

// 常量
#define MAX_POINTS 100

// 函数声明
Point create_point(int x, int y);
double distance(Point a, Point b);
void print_point(Point p);

// 外部变量声明
extern int point_count;

#endif // MYLIB_H
```

```c
// mylib.c — 实现
#include "mylib.h"
#include <stdio.h>
#include <math.h>

int point_count = 0;

Point create_point(int x, int y) {
    point_count++;
    return (Point){x, y};
}

double distance(Point a, Point b) {
    int dx = a.x - b.x;
    int dy = a.y - b.y;
    return sqrt(dx * dx + dy * dy);
}

void print_point(Point p) {
    printf("(%d, %d)\n", p.x, p.y);
}
```

### 5.2 头文件保护

```c
// 方法1：传统的include guard
#ifndef MYHEADER_H
#define MYHEADER_H
// ... 内容 ...
#endif

// 方法2：#pragma once（更简洁，非标准但广泛支持）
#pragma once
// ... 内容 ...

// 为什么需要保护？
// a.h 包含 b.h
// main.c 同时包含 a.h 和 b.h
// 如果没有保护，b.h 的内容被包含两次
// 导致重复定义错误
```

### 5.3 声明与定义的区别

```c
// 声明（可以出现多次）
extern int global_var;           // 变量声明
int add(int a, int b);          // 函数声明
struct Node;                     // 类型前向声明
typedef unsigned int uint;       // typedef（声明性质）

// 定义（只能出现一次）
int global_var = 42;             // 变量定义
int add(int a, int b) {          // 函数定义
    return a + b;
}
struct Node {                    // 类型定义
    int data;
    struct Node *next;
};

// 头文件中只放声明，不放定义（static inline例外）
// 定义放在对应的.c文件中
```

## 六、编译阶段：从C到汇编

### 6.1 编译器的工作流程

```
预处理后的源码(.i)
    ↓
[词法分析] → Token流
    ↓
[语法分析] → 抽象语法树(AST)
    ↓
[语义分析] → 类型检查、符号表
    ↓
[中间代码生成] → IR（如GCC的GIMPLE/RTL，LLVM的IR）
    ↓
[优化] → 常量折叠、死代码消除、循环优化等
    ↓
[代码生成] → 目标平台汇编代码(.s)
```

### 6.2 编译优化级别

```bash
gcc -O0 prog.c  # 无优化（默认，编译快，调试友好）
gcc -O1 prog.c  # 基本优化（减小代码大小和执行时间）
gcc -O2 prog.c  # 标准优化（推荐的生产级别）
gcc -O3 prog.c  # 激进优化（可能增大代码、循环展开、向量化）
gcc -Os prog.c  # 优化代码大小
gcc -Og prog.c  # 调试友好的优化（GCC 4.8+）
```

### 6.3 常见编译优化技术

```c
// 1. 常量折叠
int x = 3 + 4;  // 编译时直接计算为 int x = 7;

// 2. 常量传播
const int N = 100;
int arr[N];       // 编译器知道N=100

// 3. 死代码消除
if (0) {
    printf("永远不执行\n");  // 编译器直接删除
}

// 4. 循环展开
for (int i = 0; i < 4; i++) {
    arr[i] = i;
}
// 可能展开为：
// arr[0] = 0; arr[1] = 1; arr[2] = 2; arr[3] = 3;

// 5. 内联展开
static inline int square(int x) { return x * x; }
int y = square(5);  // 直接替换为 int y = 5 * 5; → int y = 25;

// 6. 尾调用优化
int factorial(int n, int acc) {
    if (n <= 1) return acc;
    return factorial(n - 1, n * acc);  // 优化为循环
}

// 7. 公共子表达式消除
int a = b * c + d;
int e = b * c + f;
// 优化为:
// int tmp = b * c;
// int a = tmp + d;
// int e = tmp + f;
```

## 七、汇编阶段：从汇编到机器码

### 7.1 汇编器的工作

```
汇编代码(.s)
    ↓
[汇编器(as)] 
    ↓
目标文件(.o)
    ├── ELF头部
    ├── .text段（机器码）
    ├── .data段（初始化数据）
    ├── .bss段（未初始化数据声明）
    ├── .rodata段（只读数据）
    ├── 符号表(.symtab)
    ├── 字符串表(.strtab)
    └── 重定位表(.rel.text, .rel.data)
```

### 7.2 目标文件分析

```bash
# 查看段信息
readelf -S main.o

# 查看符号表
readelf -s main.o
nm main.o

# 反汇编
objdump -d main.o

# 查看重定位信息
readelf -r main.o
```

### 7.3 符号表详解

```c
// main.c
int global_var = 42;
static int static_var = 100;
extern int extern_var;

static void helper() { }
void public_func() { helper(); }
int main() { return 0; }
```

```bash
$ nm main.o
0000000000000000 D global_var     # D: 全局已初始化数据
0000000000000004 d static_var     # d: 局部已初始化数据
                 U extern_var     # U: 未定义（需要链接时解析）
0000000000000000 t helper         # t: 局部文本（static函数）
0000000000000010 T public_func    # T: 全局文本
0000000000000020 T main           # T: 全局文本
```

符号类型：
```
大写 = 全局符号（对其他文件可见）
小写 = 局部符号（对其他文件不可见）
T/t: 代码段
D/d: 已初始化数据段
B/b: BSS段
U:   未定义（外部引用）
```

## 八、链接阶段：符号解析与重定位

### 8.1 链接器的两大任务

```
任务1: 符号解析
  - 将每个符号引用关联到一个确切的符号定义
  - 检查未定义符号和重复定义

任务2: 重定位
  - 将多个目标文件的同类段合并
  - 修改代码中的地址引用（重定位条目）
```

### 8.2 符号解析过程

```c
// a.c
int shared_var = 1;      // 定义
void func_a() {
    extern int shared_var; // 引用 → 解析到a.c的定义
    printf("%d\n", shared_var);
}

// b.c
extern int shared_var;    // 引用 → 解析到a.c的定义
void func_b() {
    shared_var = 2;
}

// main.c
extern void func_a();     // 引用 → 解析到a.c的定义
extern void func_b();     // 引用 → 解析到b.c的定义
int main() {
    func_a();
    func_b();
    func_a();
}
```

### 8.3 重定位过程

```
编译时（目标文件中）:
  call 0x00000000    ; 目标地址暂时为0
  ; 重定位条目: R_X86_64_PC32 func_a

链接时:
  1. 确定func_a在最终可执行文件中的地址 = 0x401234
  2. 计算偏移并填入call指令
  call 0x401234      ; 地址已确定

重定位类型:
  R_X86_64_PC32:  相对寻址（PC-relative）
  R_X86_64_32:    绝对寻址32位
  R_X86_64_64:    绝对寻址64位
  R_X86_64_PLT32: 通过PLT的间接调用
```

### 8.4 强符号与弱符号

```c
// 强符号：函数和已初始化的全局变量
int strong_var = 42;      // 强符号
void strong_func() { }    // 强符号

// 弱符号：未初始化的全局变量
int weak_var;             // 弱符号

// GCC显式弱符号
__attribute__((weak)) void optional_func() {
    printf("默认实现\n");
}

// 链接规则：
// 1. 两个强符号同名 → 链接错误（multiple definition）
// 2. 一强一弱同名 → 选择强符号
// 3. 两个弱符号同名 → 选择占用空间大的
```

## 九、静态链接详解

### 9.1 静态库的创建与使用

```bash
# 编译源文件
gcc -c math_lib.c -o math_lib.o
gcc -c string_lib.c -o string_lib.o

# 创建静态库（.a = archive）
ar rcs libmylib.a math_lib.o string_lib.o

# 查看静态库内容
ar t libmylib.a

# 链接静态库
gcc main.c -L. -lmylib -o main
# -L. : 在当前目录搜索库
# -lmylib : 链接libmylib.a
```

### 9.2 静态链接的过程

```
main.o + libmylib.a → 可执行文件

过程：
1. 链接器扫描main.o，记录未解析的符号
2. 按命令行顺序扫描每个库文件
3. 对于每个库(.a)中的每个目标文件(.o)：
   - 如果该.o定义了当前未解析的符号 → 包含该.o
   - 如果该.o没有需要的符号 → 跳过
4. 重复直到所有符号都被解析

重要：库的搜索顺序很关键！
gcc main.o -lmath -lutil  # 正确
gcc -lmath -lutil main.o  # 可能出错（main.o的符号还没被记录）
```

### 9.3 静态链接的优缺点

```
优点：
1. 独立性：不依赖外部库文件，可移植性好
2. 性能：不需要运行时符号解析，启动更快
3. 稳定性：不会因为库版本更新而出问题

缺点：
1. 文件大小：库代码被完整复制到每个可执行文件
2. 内存占用：多个程序使用同一个库，内存中有多份副本
3. 更新困难：库更新需要重新编译所有使用它的程序
4. 许可证问题：某些LGPL库不允许静态链接
```

## 十、动态链接与共享库

### 10.1 共享库的创建

```bash
# 编译为位置无关代码（PIC）
gcc -fPIC -c math_lib.c -o math_lib.o
gcc -fPIC -c string_lib.c -o string_lib.o

# 创建共享库
gcc -shared -o libmylib.so math_lib.o string_lib.o

# 带版本号
gcc -shared -Wl,-soname,libmylib.so.1 -o libmylib.so.1.0.0 *.o
ln -s libmylib.so.1.0.0 libmylib.so.1  # soname链接
ln -s libmylib.so.1 libmylib.so         # 开发链接

# 链接共享库
gcc main.c -L. -lmylib -o main

# 运行时需要找到库
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./main
```

### 10.2 PIC（位置无关代码）

```
为什么需要PIC？
- 共享库在不同进程中可能被加载到不同的虚拟地址
- 代码中的地址引用不能是硬编码的绝对地址

PIC的实现：
- 使用GOT（Global Offset Table）间接引用全局数据
- 使用PLT（Procedure Linkage Table）间接调用函数
- 通过PC相对寻址访问GOT

// 非PIC代码
mov eax, [0x601000]    // 绝对地址，加载到不同地址就不对了

// PIC代码
mov eax, [rip + GOT_offset]   // 相对于当前PC的偏移
// 运行时，动态链接器填写GOT表
```

### 10.3 GOT和PLT

```
PLT（Procedure Linkage Table）— 函数调用的跳板：

调用 printf:
1. call printf@PLT       ; 跳转到PLT中printf的条目
2. PLT条目:
   jmp *GOT[printf]      ; 第一次：GOT中存放的是延迟解析代码的地址
                          ; 之后：GOT中存放的是printf的真实地址
3. 延迟解析（首次调用时）:
   push printf的索引
   jmp 动态链接器的解析函数
   → 找到printf真实地址 → 填入GOT → 跳转到printf

这就是"延迟绑定"（Lazy Binding）：
- 减少启动时间（不需要解析所有符号）
- 未调用的函数永远不需要解析
```

### 10.4 动态加载（dlopen）

```c
#include <dlfcn.h>

int main() {
    // 在运行时加载共享库
    void *handle = dlopen("./libplugin.so", RTLD_LAZY);
    if (!handle) {
        fprintf(stderr, "加载失败: %s\n", dlerror());
        return 1;
    }
    
    // 查找符号
    typedef int (*PluginFunc)(int, int);
    PluginFunc add = (PluginFunc)dlsym(handle, "plugin_add");
    
    char *error = dlerror();
    if (error) {
        fprintf(stderr, "符号查找失败: %s\n", error);
        dlclose(handle);
        return 1;
    }
    
    // 调用
    printf("结果: %d\n", add(3, 4));
    
    // 卸载
    dlclose(handle);
    return 0;
}
```

### 11.2 自定义链接器脚本（嵌入式常用）

```
/* link.ld */
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}

SECTIONS
{
    .text : {
        *(.text)
        *(.text*)
        *(.rodata)
    } > FLASH

    .data : {
        *(.data)
        *(.data*)
    } > RAM AT > FLASH    /* 加载地址在FLASH，运行地址在RAM */

    .bss : {
        *(.bss)
        *(.bss*)
        *(COMMON)
    } > RAM
}
```

## 十二、常见链接错误与解决

### 12.1 undefined reference

```bash
# 错误
/tmp/ccXXXX.o: undefined reference to `my_function'

# 原因：
# 1. 忘记链接包含该函数的.o或.a文件
# 2. 函数名拼写错误
# 3. C++名字修饰问题（C++调用C库需要extern "C"）
# 4. 库的链接顺序不对

# 解决：
gcc main.o mylib.o -o main                    # 方案1
gcc main.o -L. -lmylib -o main               # 方案2
gcc main.o -Wl,--start-group -la -lb -Wl,--end-group  # 循环依赖
```

### 12.2 multiple definition

```bash
# 错误
multiple definition of `global_var'

# 原因：同一个全局变量在多个文件中定义
# 解决：只在一个.c文件中定义，其他文件用extern声明

// 错误：header.h
int global_var = 42;  // 每个包含此头文件的.c都会定义一次

// 正确：header.h
extern int global_var;  // 声明

// 正确：source.c
int global_var = 42;    // 定义（只在一个文件中）
```

### 12.3 库搜索路径问题

```bash
# 运行时找不到共享库
./main: error while loading shared libraries: libmylib.so: cannot open...

# 解决方案：
# 1. 设置环境变量
export LD_LIBRARY_PATH=/path/to/lib:$LD_LIBRARY_PATH

# 2. 添加到系统配置
echo "/path/to/lib" | sudo tee /etc/ld.so.conf.d/mylib.conf
sudo ldconfig

# 3. 编译时指定rpath
gcc main.c -L. -lmylib -Wl,-rpath,/path/to/lib -o main
```

## 十三、Makefile与构建系统

### 13.1 Makefile基础

```makefile
# 变量
CC = gcc
CFLAGS = -Wall -Wextra -g -O2
LDFLAGS = -lm

# 源文件和目标文件
SRCS = main.c utils.c parser.c
OBJS = $(SRCS:.c=.o)
TARGET = myapp

# 默认目标
all: $(TARGET)

# 链接
$(TARGET): $(OBJS)
	$(CC) $(OBJS) -o $(TARGET) $(LDFLAGS)

# 编译规则（模式规则）
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

# 自动生成依赖
-include $(OBJS:.o=.d)

%.d: %.c
	$(CC) -MM $< > $@

# 清理
clean:
	rm -f $(OBJS) $(TARGET) *.d

.PHONY: all clean
```

### 13.2 Makefile核心概念

```makefile
# 规则格式
target: dependencies
	recipe (命令，必须用Tab缩进)

# 自动变量
# $@  目标文件
# $<  第一个依赖
# $^  所有依赖
# $?  比目标新的依赖
# $*  匹配的词干

# 条件判断
ifeq ($(DEBUG), 1)
    CFLAGS += -DDEBUG -g
else
    CFLAGS += -DNDEBUG -O2
endif

# 函数
SOURCES = $(wildcard src/*.c)
OBJECTS = $(patsubst src/%.c, build/%.o, $(SOURCES))
```

### 13.3 分离编译的意义

```
多文件项目中，修改一个文件只需要重新编译该文件，而不是全部：

源文件     目标文件      可执行文件
main.c  → main.o   ─┐
                      ├→ myapp
utils.c → utils.o  ─┤
                      │
parse.c → parse.o  ─┘

如果只修改了utils.c：
- 只需要重新编译utils.o
- 然后重新链接
- 节省大量编译时间（大项目效果明显）

make通过比较文件时间戳来判断哪些需要重新编译
```

## 十四、总结与面试高频问题

### 14.1 核心知识总结

```
编译链接全景图：

预处理(.c → .i):
  #include展开 → 宏替换 → 条件编译 → 纯C代码

编译(.i → .s):
  词法分析 → 语法分析 → 语义分析 → 优化 → 汇编代码

汇编(.s → .o):
  汇编指令 → 机器码 + 符号表 + 重定位表

链接(.o → 可执行文件):
  符号解析 → 段合并 → 地址重定位 → 可执行文件

静态链接: 库代码复制到可执行文件
动态链接: 运行时通过GOT/PLT间接调用
```

### 14.2 面试高频问题

**Q1: #include <> 和 #include "" 的区别？**
```
<>: 搜索系统头文件路径
"": 先搜索当前目录，再搜索系统路径
```

**Q2: 头文件中能定义函数吗？**
```
可以，但只限于：
1. static函数（每个编译单元一份副本）
2. static inline函数（建议内联）
3. C11的_Noreturn等特殊函数

普通函数定义在头文件中会导致多重定义错误。
```

**Q3: static函数和全局函数的区别？**
```
static函数：只在当前编译单元（.c文件）可见
全局函数：对所有编译单元可见，可被外部链接

符号表中：
static → 局部符号(t)
全局 → 全局符号(T)
```

**Q4: 静态链接和动态链接的区别？**
```
静态链接：编译时将库代码复制到可执行文件
  优点：独立运行，启动快
  缺点：文件大，无法共享，更新需重编译

动态链接：运行时加载共享库
  优点：文件小，内存共享，更新方便
  缺点：依赖外部库文件，启动稍慢
```

**Q5: 什么是位置无关代码（PIC）？**
```
PIC是可以在任意地址加载执行的代码。
通过GOT间接访问全局数据，通过PLT间接调用函数。
共享库必须使用PIC，因为不同进程可能将其加载到不同地址。
```

> **核心思想**：理解编译链接的完整过程，是深入理解C语言程序运行机制的关键。预处理是文本级别的操作，编译是语义级别的转换，链接是二进制级别的组装。掌握这些原理，才能理解各种编译错误和链接错误的根本原因，才能在多文件项目中游刃有余。
