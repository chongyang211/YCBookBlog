# 未定义行为与安全编程

## 1. 引言：C语言中最危险的陷阱

C语言赋予程序员极大的自由度，但"能力越大，责任越大"。C标准中有一类特殊的概念——**未定义行为（Undefined Behavior, UB）**，它是无数诡异Bug、安全漏洞和生产事故的根源。

### 1.1 一个令人困惑的例子

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int x = INT_MAX;
    if (x + 1 > x) {
        printf("数学正确: x+1 > x\n");
    } else {
        printf("数学错误: x+1 <= x\n");
    }
    return 0;
}
```

直觉告诉我们，`x + 1 > x`永远为真。但这个程序的行为是**未定义的**，因为有符号整数溢出是UB。编译器可能：
- 输出"数学正确"（溢出后`INT_MIN < INT_MAX`）
- 输出"数学错误"
- 编译器直接优化掉整个if判断
- 程序崩溃

实际上，开启优化后GCC和Clang通常会直接输出"数学正确"，因为编译器**假设UB不会发生**，从而推断`x + 1 > x`恒为真。

### 1.2 为什么要深入理解UB

| 理由 | 说明 |
|------|------|
| **Bug排查** | 很多"灵异"Bug的根源是UB |
| **安全漏洞** | 大量CVE漏洞源自UB |
| **可移植性** | UB在不同平台表现不同 |
| **性能优化** | 理解UB有助于写出编译器友好的代码 |
| **职业素养** | 区分优秀C程序员和普通C程序员的关键 |

### 1.3 C标准的三种"不确定"行为

C标准定义了三种不同程度的"不确定"行为，它们的危险程度完全不同：

```
┌─────────────────────────────────────────────────────────────┐
│                    C标准行为分类                              │
├─────────────────┬───────────────────┬───────────────────────┤
│  未定义行为(UB)  │ 实现定义行为(IDB)  │  未指定行为(USB)       │
│  最危险          │  中等风险          │  较低风险              │
│                 │                   │                       │
│ 标准完全不规定   │ 标准要求实现选择   │  标准给出几种可能      │
│ 任何事都可能发生  │ 一种行为并文档化   │  但不要求文档化        │
│                 │                   │                       │
│ 例：解引用NULL   │ 例：char是否有符号 │  例：函数参数求值顺序   │
│ 例：数组越界     │ 例：int的大小      │  例：子表达式求值顺序   │
│ 例：有符号溢出   │ 例：右移有符号数   │  例：结构体填充字节值   │
└─────────────────┴───────────────────┴───────────────────────┘
```

## 2. 未定义行为的本质

### 2.1 什么是未定义行为

C11标准（ISO/IEC 9899:2011）3.4.3的定义：

> **未定义行为**：使用不可移植的或有错误的程序构造，或使用有错误的数据时的行为，本国际标准对此不施加任何要求。

关键词：**不施加任何要求**。这意味着：

```
UB发生后，以下任何结果都是"合法"的：
├── 程序看似正常运行（最危险！给人虚假的安全感）
├── 程序输出错误结果
├── 程序崩溃（段错误、总线错误等）
├── 程序进入死循环
├── 编译器生成任意代码
└── 鼻子里飞出恶魔（nasal demons，经典玩笑）
```

### 2.2 为什么C标准要保留UB

**疑惑**：为什么不把所有行为都定义清楚？

**答疑**：UB的存在有深刻的技术原因。

#### 原因一：性能优化

```c
// 有符号整数溢出是UB，编译器可以假设它不发生
// 这使得以下优化成为可能：
for (int i = 0; i <= n; i++) {
    // 编译器可以优化为有限循环（假设i不会溢出回绕）
}
// 如果有符号溢出有定义（如回绕），编译器就不能做这种假设
```

#### 原因二：硬件差异

```c
// 不同CPU对同一操作的行为不同
// 例如：整数除零
// x86: 触发异常 #DE
// ARM: 返回0（某些模式下）
// 如果标准要求某种特定行为，某些平台就需要额外的检查代码
```

#### 原因三：简化实现

```c
// 例如：数组越界访问
int arr[10];
arr[15] = 42;  // UB
// 如果要求越界检查，每次数组访问都需要比较索引和数组大小
// 这对性能密集的代码是不可接受的
```

**论证**：C的设计哲学是"信任程序员"，UB是这种哲学的体现——不为不需要的东西付费，给编译器最大的优化空间。

**结果**：UB使得C语言在不同硬件上都能生成高效的本机代码，这是C几十年来持续作为系统编程语言的关键原因。

### 2.3 编译器如何利用UB进行优化

现代编译器会**积极假设UB不会发生**，并基于此进行优化。

#### 示例一：消除"不可能"的代码路径

```c
int foo(int x) {
    if (x + 1 < x) {
        // 有符号溢出是UB → 编译器假设不发生
        // 因此 x+1 < x "不可能"为真
        return -1;  // 这段代码会被优化掉
    }
    return 0;
}
// 优化后等价于：
int foo(int x) { return 0; }
```

#### 示例二：空指针检查消除

```c
void bar(int *p) {
    int x = *p;       // 解引用p
    if (p == NULL) {  // 检查p是否为NULL
        printf("p is null\n");
        return;
    }
    printf("x = %d\n", x);
}
// 编译器推理：
// 1. 第1行解引用了p → 若p为NULL则是UB → 假设p不为NULL
// 2. if(p == NULL)永远为假 → 删除整个if分支
// 这就是为什么NULL检查必须在解引用之前！
```

#### 示例三：循环优化

```c
void process(int *data, int n) {
    for (int i = 0; i < n; i++) {
        data[i] = i * 2;
    }
    // 编译器假设i*2不溢出，可使用更高效的指令
    // 假设i < n最终为假，循环必然终止
    // 从而可以进行循环展开、向量化等优化
}
```

## 3. 常见未定义行为全面分类

### 3.1 内存类UB

#### 空指针解引用

```c
void null_deref_examples(void) {
    // 1. 直接解引用NULL
    int *p = NULL;
    *p = 42;  // UB!

    // 2. malloc失败后未检查
    int *arr = malloc(sizeof(int) * 1000000000L);
    arr[0] = 1;  // 如果malloc返回NULL，UB!

    // 3. 对NULL指针做算术
    int *q = NULL;
    int *r = q + 1;  // UB! 即使不解引用

    // 正确做法：
    int *safe = malloc(sizeof(int) * 100);
    if (safe == NULL) {
        perror("malloc failed");
        return;
    }
    safe[0] = 1;
    free(safe);
}
```

#### 缓冲区溢出

```c
void buffer_overflow_examples(void) {
    // 1. 数组越界写入
    int arr[10];
    arr[10] = 42;  // UB! 越界一个元素

    // 2. 栈缓冲区溢出——经典的安全漏洞
    char buf[16];
    strcpy(buf, "This string is way too long for the buffer");  // UB!

    // 3. 堆缓冲区溢出
    char *heap = malloc(16);
    if (heap) {
        memset(heap, 'A', 32);  // UB!
        free(heap);
    }

    // 正确做法：
    char safe_buf[16];
    strncpy(safe_buf, "Short", sizeof(safe_buf) - 1);
    safe_buf[sizeof(safe_buf) - 1] = '\0';
}
```

#### 使用已释放的内存（Use-After-Free）

```c
void use_after_free_examples(void) {
    // 1. 基本的UAF
    int *p = malloc(sizeof(int));
    *p = 42;
    free(p);
    printf("%d\n", *p);  // UB! 使用已释放的内存

    // 2. 双重释放
    int *q = malloc(sizeof(int));
    free(q);
    free(q);  // UB! 双重释放

    // 3. 返回局部变量的地址——悬垂指针
    // int *create_dangling(void) {
    //     int local = 42;
    //     return &local;  // UB!
    // }

    // 正确做法：释放后置NULL
    int *safe = malloc(sizeof(int));
    if (safe) {
        *safe = 42;
        free(safe);
        safe = NULL;  // 防止误用
    }
}
```

#### 未初始化变量

```c
void uninitialized_examples(void) {
    // 1. 读取未初始化的局部变量
    int x;
    printf("%d\n", x);  // UB!

    // 2. 未初始化的指针
    int *p;
    *p = 42;  // UB!

    // 3. 部分初始化的结构体
    struct Point { int x, y, z; };
    struct Point pt;
    pt.x = 1;
    printf("y = %d\n", pt.y);  // UB! y未初始化

    // 正确做法：
    int safe_x = 0;
    struct Point safe_pt = {0};  // 全部初始化为0
}
```

### 3.2 整数类UB

#### 有符号整数溢出

```c
#include <limits.h>

void signed_overflow_examples(void) {
    // 1. 加法溢出
    int a = INT_MAX;
    int b = a + 1;  // UB! 有符号整数溢出
    // 注意：无符号整数溢出有定义（回绕）
    unsigned int c = UINT_MAX;
    unsigned int d = c + 1;  // 定义良好，d == 0

    // 2. 乘法溢出
    int x = 1000000;
    int y = x * x;  // UB! 结果超出int范围

    // 3. 取反溢出
    int m = INT_MIN;
    int n = -m;  // UB! |INT_MIN| > INT_MAX

    // 4. 除法溢出
    int p = INT_MIN;
    int q = p / (-1);  // UB! 结果无法表示
}

// 安全的加法检查
int safe_add(int a, int b) {
    if ((b > 0 && a > INT_MAX - b) ||
        (b < 0 && a < INT_MIN - b)) {
        return -1;  // 溢出错误处理
    }
    return a + b;
}
```

#### 移位操作UB

```c
void shift_ub_examples(void) {
    int a = 1;
    int b = a << -1;   // UB! 移位量为负数
    int c = a << 32;   // UB! 移位量大于等于位宽
    int d = -1;
    int e = d << 1;    // C11之前是UB

    // 右移负数是实现定义（非UB，但不可移植）
    int f = -8;
    int g = f >> 1;    // 实现定义：可能是-4或大正数

    // 安全的移位操作：
    unsigned safe_shift(unsigned val, int shift) {
        if (shift < 0 || shift >= (int)(sizeof(unsigned) * 8))
            return 0;
        return val << shift;
    }
}
```

#### 除以零

```c
void division_by_zero(void) {
    int a = 42, b = 0;
    int c = a / b;  // UB! 整数除零
    int d = a % b;  // UB!

    // 安全的除法：
    int safe_div(int a, int b) {
        if (b == 0) return 0;
        if (a == INT_MIN && b == -1) return INT_MAX;
        return a / b;
    }
}
```

### 3.3 指针类UB

#### 指针运算越界

```c
void pointer_arithmetic_ub(void) {
    int arr[10];
    int *p = arr;
    int *q = p + 15;   // UB! 超出数组范围
    int *end = arr + 10; // 合法（past-the-end）
    int *bad = arr + 11; // UB!
    // 不能解引用past-the-end指针：*end 是UB!

    // 不同数组间的指针比较
    int a[5], b[5];
    if (&a[0] < &b[0]) { }  // UB!

    // 指针对齐问题
    char buf[8];
    int *ip = (int *)buf;  // 如果buf地址不是4字节对齐，*ip就是UB

    // 安全做法：使用memcpy代替类型双关
    int value;
    memcpy(&value, buf, sizeof(int));  // 安全
}
```

#### 类型别名违规（Strict Aliasing）

```c
void strict_aliasing_ub(void) {
    // 经典的类型双关违规
    float f = 3.14f;
    int *ip = (int *)&f;
    int i = *ip;  // UB! 违反严格别名规则

    // 安全的方式1：联合体（C99/C11合法）
    union { float f; int i; } u;
    u.f = 3.14f;
    printf("%d\n", u.i);

    // 安全的方式2：memcpy（推荐）
    float f2 = 3.14f;
    int i2;
    memcpy(&i2, &f2, sizeof(i2));
}
```

### 3.4 序列点与求值顺序UB

```c
void sequence_point_ub(void) {
    int i = 0;
    i = i++;           // UB! 两次修改同一变量

    int a = 5;
    int b = a + a++;   // UB!
    int c = ++a + a++; // UB!

    int x = 0;
    printf("%d %d\n", x++, x++);  // UB/未指定

    // 安全的写法：分开写
    int j = 0;
    int temp = j;
    j++;
}
```

### 3.5 其他重要UB

```c
// 1. 修改字符串字面量
void modify_string_literal(void) {
    char *s = "hello";
    s[0] = 'H';  // UB! 字符串字面量是只读的
    // 正确做法：
    char s2[] = "hello";
    s2[0] = 'H';  // 合法
}

// 2. 格式化字符串不匹配
void format_string_ub(void) {
    printf("%s\n", 42);       // UB! int不是字符串
    printf("%d\n", 3.14);    // UB! double不是int
    printf("%d %d\n", 42);   // UB! 缺少参数

    // 格式化字符串攻击
    char *user_input = "...";
    printf(user_input);       // 严重安全漏洞！
    printf("%s", user_input); // 安全
}

// 3. 无限循环无副作用（C11起）
void infinite_loop_ub(void) {
    while (1) { }   // UB! 无副作用的无限循环，编译器可能删除

    // 安全的忙等待：
    volatile int flag = 0;
    while (!flag) { } // flag是volatile，有可观测的副作用
}

// 4. 违反对象生命周期
int *return_local(void) {
    int x = 42;
    return &x;  // UB! x在函数返回后被销毁
}
```

## 4. 实现定义行为与未指定行为

### 4.1 实现定义行为（Implementation-Defined）

标准提供几种可能的行为，要求实现选择其中一种并**文档化**。比UB安全但不可移植。

```c
void implementation_defined_examples(void) {
    // 1. char是有符号还是无符号
    char c = 255;
    if (c < 0) printf("char is signed\n");      // x86
    else       printf("char is unsigned\n");     // ARM
    // 建议：明确使用 signed char 或 unsigned char

    // 2. 整数类型的大小
    // long: Linux64为8字节, Windows64为4字节
    printf("sizeof(long) = %zu\n", sizeof(long));

    // 3. 有符号整数的右移
    int x = -8;
    int y = x >> 1;  // 算术移位: -4 (大多数) / 逻辑移位: 大正数

    // 4. 位域的符号性
    struct { int flag : 1; } bits;
    // flag是有符号还是无符号？实现定义！
    // 建议：位域总是使用 unsigned int

    // 5. 类型转换
    unsigned int big = UINT_MAX;
    int converted = (int)big;  // 实现定义！
}
```

### 4.2 未指定行为（Unspecified）

标准提供几种可能的行为，实现每次可以选择任意一种，不需要文档化。

```c
void unspecified_examples(void) {
    // 1. 函数参数求值顺序
    int x = 0;
    printf("%d %d\n", ++x, ++x);  // 未指定顺序

    // 2. 相同字符串字面量是否共享存储
    const char *a = "hello";
    const char *b = "hello";
    // a == b 的结果是未指定的
    // 正确的字符串比较用strcmp

    // 3. 结构体填充字节的值
    struct { char a; int b; } s1 = {1, 2}, s2 = {1, 2};
    // 不能用memcmp比较结构体！填充字节值未指定
    // 正确做法：逐字段比较
}
```

### 4.3 编写可移植代码的建议

```c
#include <stdint.h>
#include <stdbool.h>

// 1. 使用固定宽度整数类型
int32_t precise_int = 42;

}
```

## 5. 编译器的UB利用——真实案例

### 5.1 Linux内核NULL检查消除（CVE-2009-1897）

```c
// 2009年Linux内核中的代码：
struct sock *sk = tun->sk;  // 第1步：解引用tun
if (!tun)                    // 第2步：检查tun是否为NULL
    return POLLERR;

// GCC推理：
// 1. 第1步解引用了tun → 若tun为NULL则UB → tun不为NULL
// 2. if(!tun)永远为假 → 删除检查
// 结果：NULL检查被优化掉，产生安全漏洞！

// 修复：先检查再解引用
if (!tun)
    return POLLERR;
struct sock *sk = tun->sk;
```

### 5.2 整数溢出检查被优化掉

```c
int check_overflow(int x) {
    if (x + 100 < x) {  // 想检测溢出
        printf("overflow!\n");
        return -1;
    }
    return x + 100;
}
// 编译器：有符号溢出是UB → x+100 >= x恒成立 → 删除检查
// 优化后等价于：
int check_overflow(int x) { return x + 100; }

// 正确的溢出检查（GCC/Clang内建函数）：
int safe_check(int x) {
    int result;
    if (__builtin_add_overflow(x, 100, &result)) {
        printf("overflow!\n");
        return -1;
    }
    return result;
}
```

### 5.3 死循环被消除

```c
int flag = 0;
void wait_for_flag(void) {
    while (!flag) { }      // 编译器可能删除此循环！
    printf("Flag is set!\n");
}
// 推理：flag非volatile，循环体不改flag → flag恒为0 → 无限循环是UB → 跳过

// 正确做法：
#include <stdatomic.h>
atomic_int safe_flag = ATOMIC_VAR_INIT(0);
void safe_wait(void) {
    while (!atomic_load(&safe_flag)) { }
    printf("Flag is set!\n");
}
```

## 6. 安全编程实践

### 6.1 防御性编程原则

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <assert.h>
#include <errno.h>

// 原则1：输入验证
int parse_age(const char *input) {
    if (input == NULL) return -1;
    size_t len = strlen(input);
    if (len == 0 || len > 3) return -1;
    for (size_t i = 0; i < len; i++) {
        if (input[i] < '0' || input[i] > '9') return -1;
    }
    long age = strtol(input, NULL, 10);
    if (age < 0 || age > 150) return -1;
    return (int)age;
}

// 原则2：检查所有返回值
void *safe_malloc(size_t size) {
    if (size == 0) size = 1;
    void *ptr = malloc(size);
    if (ptr == NULL) {
        fprintf(stderr, "Fatal: malloc(%zu) failed: %s\n", size, strerror(errno));
        abort();
    }
    return ptr;
}

// 原则3：使用安全的字符串函数
void safe_string_copy(char *dest, size_t dest_size, const char *src) {
    if (!dest || !src || dest_size == 0) return;
    size_t src_len = strlen(src);
    if (src_len >= dest_size) {
        memcpy(dest, src, dest_size - 1);
        dest[dest_size - 1] = '\0';
    } else {
        memcpy(dest, src, src_len + 1);
    }
}

// 原则4：使用断言检查前置条件
void process_buffer(const unsigned char *buf, size_t len) {
    assert(buf != NULL && "buffer must not be NULL");
    assert(len > 0 && "buffer length must be positive");
    assert(len <= 1024 * 1024 && "buffer too large");
}
```

### 6.2 安全的整数运算

```c
#include <stdint.h>
#include <stdbool.h>
#include <limits.h>

bool safe_add_int(int a, int b, int *result) {
    if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b))
        return false;
    *result = a + b;
    return true;
}

bool safe_sub_int(int a, int b, int *result) {
    if ((b > 0 && a < INT_MIN + b) || (b < 0 && a > INT_MAX + b))
        return false;
    *result = a - b;
    return true;
}

bool safe_mul_int(int a, int b, int *result) {
    if (a == 0 || b == 0) { *result = 0; return true; }
    if (a > 0) {
        if (b > 0) { if (a > INT_MAX / b) return false; }
        else       { if (b < INT_MIN / a) return false; }
    } else {
        if (b > 0) { if (a < INT_MIN / b) return false; }
        else       { if (a != 0 && b < INT_MAX / a) return false; }
    }
    *result = a * b;
    return true;
}

bool safe_div_int(int a, int b, int *result) {
    if (b == 0) return false;
    if (a == INT_MIN && b == -1) return false;
    *result = a / b;
    return true;
}

// 推荐：使用GCC/Clang内建函数
bool safe_add_builtin(int a, int b, int *result) {
    return !__builtin_add_overflow(a, b, result);
}

bool safe_mul_builtin(int a, int b, int *result) {
    return !__builtin_mul_overflow(a, b, result);
}
```

### 6.3 安全的内存操作

```c
// 安全的动态数组
typedef struct {
    int *data;
    size_t size;
    size_t capacity;
} IntArray;

IntArray *intarray_create(size_t initial_capacity) {
    IntArray *arr = malloc(sizeof(IntArray));
    if (!arr) return NULL;
    if (initial_capacity == 0) initial_capacity = 16;
    arr->data = calloc(initial_capacity, sizeof(int));
    if (!arr->data) { free(arr); return NULL; }
    arr->size = 0;
    arr->capacity = initial_capacity;
    return arr;
}

bool intarray_push(IntArray *arr, int value) {
    if (!arr) return false;
    if (arr->size >= arr->capacity) {
        size_t new_cap;
        if (__builtin_mul_overflow(arr->capacity, 2, &new_cap)) return false;
        size_t alloc_size;
        if (__builtin_mul_overflow(new_cap, sizeof(int), &alloc_size)) return false;
        int *new_data = realloc(arr->data, alloc_size);
        if (!new_data) return false;
        arr->data = new_data;
        arr->capacity = new_cap;
    }
    arr->data[arr->size++] = value;
    return true;
}

bool intarray_get(const IntArray *arr, size_t index, int *out) {
    if (!arr || index >= arr->size || !out) return false;
    *out = arr->data[index];
    return true;
}

void intarray_destroy(IntArray *arr) {
    if (arr) { free(arr->data); free(arr); }
}
```

### 6.4 安全的字符串处理

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>
#include <errno.h>
#include <stdarg.h>

// 安全的字符串拼接
char *safe_strjoin(const char *s1, const char *s2) {
    if (!s1) s1 = "";
    if (!s2) s2 = "";
    size_t len1 = strlen(s1), len2 = strlen(s2);
    size_t total;
    if (__builtin_add_overflow(len1, len2, &total) ||
        __builtin_add_overflow(total, 1, &total))
        return NULL;
    char *result = malloc(total);
    if (!result) return NULL;
    memcpy(result, s1, len1);
    memcpy(result + len1, s2, len2 + 1);
    return result;
}

// 安全的整数解析
typedef enum {
    PARSE_OK, PARSE_ERROR_NULL, PARSE_ERROR_EMPTY,
    PARSE_ERROR_FORMAT, PARSE_ERROR_RANGE,
} ParseResult;

ParseResult safe_parse_int(const char *str, int *result) {
    if (!str || !result) return PARSE_ERROR_NULL;
    while (isspace((unsigned char)*str)) str++;
    if (*str == '\0') return PARSE_ERROR_EMPTY;
    char *endptr;
    errno = 0;
    long val = strtol(str, &endptr, 10);
    if (errno == ERANGE) return PARSE_ERROR_RANGE;
    if (endptr == str) return PARSE_ERROR_FORMAT;
    while (isspace((unsigned char)*endptr)) endptr++;
    if (*endptr != '\0') return PARSE_ERROR_FORMAT;
    if (val < INT_MIN || val > INT_MAX) return PARSE_ERROR_RANGE;
    *result = (int)val;
    return PARSE_OK;
}

// 安全的格式化字符串
char *safe_format(const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);
    int needed = vsnprintf(NULL, 0, fmt, args);
    va_end(args);
    if (needed < 0) return NULL;
    char *result = malloc((size_t)needed + 1);
    if (!result) return NULL;
    va_start(args, fmt);
    vsnprintf(result, (size_t)needed + 1, fmt, args);
    va_end(args);
    return result;
}
```

### 7.2 AddressSanitizer (ASan)

```bash
gcc -fsanitize=address -fno-omit-frame-pointer -g test.c -o test
# 检测：堆/栈/全局缓冲区溢出、UAF、Double-Free、内存泄漏
```

工作原理：ASan使用**影子内存**（Shadow Memory），每8字节应用内存对应1字节影子内存。在分配区域周围插入"红区"（Poison区域），每次内存访问前检查影子字节是否允许访问。

```c
// ASan能检测的问题示例
void test_asan(void) {
    char *buf = malloc(10);
    buf[10] = 'x';  // heap-buffer-overflow
    free(buf);

    int *p = malloc(sizeof(int));
    free(p);
    *p = 42;  // heap-use-after-free

    int arr[10];
    arr[10] = 42;  // stack-buffer-overflow
}
```

```c
// UBSan能检测的问题示例
void test_ubsan(void) {

    int y = x + 1;          // signed integer overflow
```

## 8. 编码规范与安全标准

### 8.1 MISRA C核心规则

MISRA C由汽车产业软件可靠性协会制定，广泛应用于安全关键系统。

```c
// 规则1: 不使用动态内存分配（安全关键系统）
static int data_pool[1024];
static size_t pool_idx = 0;

// 规则2: 不使用递归，用迭代代替
int factorial_iterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) result *= i;
    return result;
}

// 规则3: 所有switch必须有default
void process_state(int state) {
    switch (state) {
        case 0: handle_idle(); break;
        case 1: handle_running(); break;
        default: handle_error(); break;
    }
}

// 规则4: 所有if-else if链必须以else结尾
void check_value(int x) {
    if (x > 100) handle_high();
    else if (x > 50) handle_medium();
    else handle_low();  // 必须有
}

// 规则5: 循环计数器不能在循环体内修改
// 规则6: 显式类型转换
unsigned int u = 42;
int i = (int)u;  // 显式
```

### 8.2 CERT C核心规则

```c
// INT32-C: 确保有符号整数运算不溢出
// MEM30-C: 不要访问已释放的内存 → free后置NULL

    }
}
```

## 9. 实战：从UB到安全代码的重构

### 9.1 不安全的用户输入处理

```c
// ========== 原始不安全代码 ==========
void process_user_input(void) {
    struct { char name[32]; char email[64]; int age; } user;
    char input[256];
    gets(input);                    // 问题1: gets无边界检查
    strcpy(user.name, input);      // 问题2: strcpy无边界检查
    scanf("%s", user.email);       // 问题3: scanf %s无边界检查
    scanf("%d", &user.age);        // 问题4: 未验证返回值和范围
    printf(user.name);             // 问题5: 格式字符串漏洞！
}
```

```c
// ========== 安全重构后 ==========
static int read_line(char *buf, size_t bufsize) {
    if (!buf || bufsize == 0) return -1;
    if (fgets(buf, (int)bufsize, stdin) == NULL) {
        buf[0] = '\0'; return -1;
    }
    size_t len = strlen(buf);
    if (len > 0 && buf[len-1] == '\n') {
        buf[--len] = '\0';
    } else if (len == bufsize - 1) {
        int c;
        while ((c = getchar()) != '\n' && c != EOF) {}
    }
    return (len > 0) ? 0 : -1;
}

int process_user_input_safe(void) {
    struct { char name[32]; char email[64]; int age; } user;
    char input[256];

    printf("Enter name: ");
    if (read_line(input, sizeof(input)) != 0) return -1;
    safe_string_copy(user.name, sizeof(user.name), input);

    printf("Enter email: ");
    if (read_line(input, sizeof(input)) != 0) return -1;
    safe_string_copy(user.email, sizeof(user.email), input);

    printf("Enter age: ");
    if (read_line(input, sizeof(input)) != 0) return -1;
    ParseResult pr = safe_parse_int(input, &user.age);
    if (pr != PARSE_OK || user.age < 0 || user.age > 150) return -1;

    printf("Hello, %s\n", user.name);  // %s而非printf(name)
    return 0;
}
```

### 9.2 不安全的链表实现重构

```c
// ========== 原始不安全代码 ==========
struct Node { int data; struct Node *next; };
struct Node *head = NULL;

void insert(int data) {
    struct Node *n = malloc(sizeof(struct Node)); // 未检查NULL
    n->data = data; n->next = head; head = n;
}
void remove_node(int data) {
    struct Node *curr = head, *prev = NULL;
    while (curr) {
        if (curr->data == data) {
            if (prev) prev->next = curr->next;
            else head = curr->next;
            free(curr); // curr已free但可能被后续代码误用
            return;
        }
        prev = curr; curr = curr->next;
    }
}
// 没有清理函数，内存泄漏
```

```c
// ========== 安全重构后 ==========
typedef struct Node { int data; struct Node *next; } Node;
typedef struct { Node *head; size_t size; } LinkedList;

void list_init(LinkedList *list) {
    if (!list) return;
    list->head = NULL; list->size = 0;
}

bool list_insert(LinkedList *list, int data) {
    if (!list) return false;
    Node *node = malloc(sizeof(Node));
    if (!node) return false;
    node->data = data;
    node->next = list->head;
    list->head = node;
    list->size++;
    return true;
}

bool list_remove(LinkedList *list, int data) {
    if (!list || !list->head) return false;
    Node **pp = &list->head;
    while (*pp) {
        Node *curr = *pp;
        if (curr->data == data) {
            *pp = curr->next;
            curr->next = NULL;
            free(curr);
            list->size--;
            return true;
        }
        pp = &curr->next;
    }
    return false;
}

void list_destroy(LinkedList *list) {
    if (!list) return;
    Node *curr = list->head;
    while (curr) {
        Node *next = curr->next;
        free(curr);
        curr = next;
    }
    list->head = NULL;
    list->size = 0;
}
```

## 11. 总结

### 11.1 UB的核心教训

```
未定义行为的三大定律：
━━━━━━━━━━━━━━━━━━━━━
第一定律：UB永远不会"碰巧正确"
  → 今天"正常"，换编译器/优化级别/平台时随时爆发

第二定律：编译器比你更擅长利用UB
  → 你以为的"只是溢出"可能导致安全检查被删除

第三定律：UB是传染性的
  → 任何位置的UB都可能影响完全无关的代码
```

### 11.2 安全编码金字塔

```
        ╱╲
       ╱  ╲       7. 代码审查和安全审计
      ╱ 7  ╲
     ╱──────╲     6. 遵循编码规范(MISRA/CERT C)
    ╱   6    ╲
   ╱──────────╲   5. 静态分析工具
  ╱     5      ╲
 ╱──────────────╲ 4. 运行时检测(Sanitizer/Valgrind)
╱       4        ╲
╱──────────────────╲ 3. 防御性编程(输入验证/边界检查/NULL检查)
╱        3          ╲
╱────────────────────╲ 2. 编译器警告(-Wall -Wextra -Werror)
╱         2           ╲
╱──────────────────────╲ 1. 理解UB（知道什么是不允许的）
╱          1            ╲
╱════════════════════════╲
```

### 11.3 关键要点速查

| 类别 | 常见UB | 安全替代方案 |
|------|--------|-------------|
| 空指针 | `*p`当p为NULL | 解引用前检查NULL |
| 缓冲区溢出 | `strcpy`, `gets`, `sprintf` | `strncpy`, `fgets`, `snprintf` |
| UAF | free后继续使用 | free后置NULL |
| 整数溢出 | `INT_MAX + 1` | `__builtin_add_overflow` |
| 移位UB | `1 << 32`, `1 << -1` | 验证移位量范围 |
| 除零 | `a / 0` | 除法前检查除数 |
| 别名违规 | `*(int*)&float_val` | `memcpy`或联合体 |
| 序列点 | `i = i++` | 拆分为多条语句 |
| 格式字符串 | `printf(user_input)` | `printf("%s", user_input)` |
| 字符串字面量 | `"hello"[0] = 'H'` | 使用`char[]`数组 |
| 无限循环 | `while(1){}` | 使用volatile或atomic |
| 未初始化 | 读取未初始化变量 | 声明时初始化 |

### 11.4 推荐的开发工作流

```
编码阶段：
  → 遵循编码规范，使用安全函数
  → 启用编译器全部警告 + -Werror
  → 所有输入验证、所有返回值检查

测试阶段：
  → Debug构建用ASan+UBSan运行全部测试
  → 用Valgrind检查内存泄漏
  → 定期运行Cppcheck/clang-analyzer

发布阶段：
  → Release构建启用 -D_FORTIFY_SOURCE=2
  → 启用 -fstack-protector-strong
  → 启用 PIE + RELRO

维护阶段：
  → 代码审查关注UB和安全问题
  → 持续集成中自动运行Sanitizer
  → 跟踪CVE，及时修补
```

C语言的UB既是一把双刃剑，也是理解底层计算机系统的窗口。掌握了UB的知识，你就掌握了编写真正安全、高效C代码的钥匙。记住：**写C代码时，你不是在和编译器合作，你是在和编译器签订一份精确的合同——合同的每一条款都来自C标准。**
