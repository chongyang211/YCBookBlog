## 01.合并分支需求

将feature分支合并到develop分支。首先，确保当前在develop分支，然后执行git merge feature。

但要注意，合并前最好先拉取最新的develop分支代码，避免冲突增多。另外，合并后可能会遇到冲突，需要手动解决。大概的操作步骤：

1. 确保当前分支是develop：git checkout develop 
2. 拉取最新的develop分支：git pull origin develop 
3. 合并feature分支：git merge feature 
4. 如果有冲突，解决冲突并提交。 
5. 推送合并后的develop分支：git push origin develop

## 02.确保分支状态正确

```bash
# 切换到 develop 分支
git checkout develop

# 拉取最新代码（避免合并冲突）
git pull origin develop

# 切换到 feature 分支
git checkout feature

# 更新 feature 分支
git pull origin feature
```

## 03.检查分支状态

```bash
# 查看分支关系图
git log --graph --oneline --all -10

# 检查未提交的更改
git status

# 比较分支差异
git diff develop..feature
```

## 04.执行合并操作

### 4.1 标准合并方式

```bash
# 切换到 develop 分支
git checkout develop

# 执行合并
git merge feature
```

### 4.2 推荐方式：使用 `--no-ff` 选项

```bash
git merge --no-ff feature
```

**为什么推荐 `--no-ff`？**

- 保留功能分支的完整历史
- 明确显示功能合并点
- 避免丢失分支上下文信息

## 05.解决冲突和提交

### 5.1 如何解决冲突

当出现冲突时：

```bash
# 查看冲突文件
git status

# 手动解决冲突（使用编辑器修改文件）
# 这一步解决冲突

# 标记冲突已解决
git add <resolved-file>

# 完成合并
git commit
```

### 5.2 合并冲突预防策略

1. **频繁同步**：每天至少一次将 develop 合并到 feature
   ```bash
   git checkout feature
   git merge develop
   ```
2. **小批量提交**：避免大规模更改的单次提交
3. **明确责任**：每个功能模块有明确负责人



## 06.合并后push推送

### 6.1 推送更改到远程仓库

```bash
git push origin develop
```

### 6.2 清理分支（可选）

```bash
# 删除本地 feature 分支
git branch -d feature

# 删除远程 feature 分支
git push origin --delete feature
```

## 07.合并策略分析

| 策略 | 命令 | 适用场景 | 优点 | 缺点 |
|------|------|----------|------|------|
| **标准合并** | `git merge feature` | 小型功能 | 简单快速 | 历史不清晰 |
| **非快进合并** | `git merge --no-ff feature` | 推荐常规使用 | 保留完整历史 | 产生额外提交 |
| **变基合并** | `git rebase develop` | 保持线性历史 | 提交历史整洁 | 可能破坏分支 |
| **压缩提交** | `git merge --squash feature` | 简化历史 | 单个整洁提交 | 丢失开发过程 |

## 五、高级合并技巧

### 1. 选择性合并（cherry-pick）
```bash
# 查看提交哈希
git log --oneline feature

# 选择特定提交合并
git checkout develop
git cherry-pick <commit-hash>
```

### 2. 使用 Pull Request（GitHub/GitLab）
1. 在仓库创建 Pull Request
2. 代码审查和讨论
3. 自动化测试通过
4. 点击合并按钮

### 3. 复杂合并的调试
```bash
# 查看合并细节
git show <merge-commit-hash>

# 分析文件历史
git blame <filename>

# 可视化合并过程
git log --merge -p <path>
```

## 六、常见问题解决方案

### 1. 合并后发现问题
```bash
# 撤销合并（合并尚未推送）
git reset --hard HEAD~1

# 撤销合并（合并已推送）
git revert -m 1 <merge-commit-hash>
```

### 2. 长期分支的合并策略
```bash
# 创建临时合并分支
git checkout -b merge-temp develop
git merge --no-ff feature

# 解决所有冲突后
git checkout develop
git merge --ff-only merge-temp
```

### 3. 巨型分支的合并
```bash
# 分阶段合并
git merge feature/part1
git merge feature/part2

# 或使用子树合并
git merge -s subtree feature
```

## 七、企业级最佳实践

1. **保护主分支**：设置 develop 分支为受保护分支
2. **强制代码审查**：要求至少 1 个批准才能合并
3. **自动化检查**：
    - 静态代码分析
    - 单元测试覆盖率
    - 构建成功率
4. **合并检查清单**：
    - [ ] 代码审查完成
    - [ ] 测试覆盖率达标
    - [ ] 文档已更新
    - [ ] 迁移脚本已测试
    - [ ] 性能基准测试通过

## 总结：完美合并的黄金法则

1. **提前沟通**：合并前通知团队成员
2. **频繁合并**：每天合并 develop 到 feature
3. **小步前进**：保持功能分支小巧专注
4. **测试优先**：合并前运行完整测试套件
5. **记录明确**：编写清晰的合并提交信息
6. **及时清理**：合并后删除已合并的分支

遵循这些实践，您将掌握高效、无痛的 Git 合并工作流，使团队协作更加顺畅！
