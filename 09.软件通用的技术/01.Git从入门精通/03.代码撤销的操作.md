## 1.撤销工作区的修改

**撤销工作区的修改（未添加到暂存区）**

- **场景**：修改了文件，但还没有执行 `git add`，想要撤销这些修改。
- **命令**：
  ```bash
  git checkout -- <file>
  ```
  例如：
  ```bash
  git checkout -- main.py
  ```
  如果要撤销所有文件的修改：
  ```bash
  git checkout -- .
  ```

## 2.撤销暂存区的修改

**撤销暂存区的修改（已 `git add` 但未 `git commit`）**
- **场景**：将修改添加到暂存区，但还没有提交，想要撤销暂存区的修改。
- **命令**：
  ```bash
  git reset HEAD <file>
  ```
  例如：
  ```bash
  git reset HEAD main.py
  ```
  如果要撤销所有暂存区的修改：
  ```bash
  git reset HEAD .
  ```

## 3.撤销提交

**撤销提交（已 `git commit` 但未 `git push`）**

- **场景**：提交了代码，但还没有推送到远程仓库，想要撤销这次提交。
- **命令**：
  ```bash
  git reset --soft HEAD^
  ```
    - `HEAD^` 表示上一个提交。
    - `--soft` 选项会保留修改内容，将提交撤销到暂存区。
    - 如果使用 `--hard` 选项，会彻底丢弃修改：
      ```bash
      git reset --hard HEAD^
      ```

## 4.撤销远程提交

**撤销远程提交（已 `git push`）**
- **场景**：已经将提交推送到远程仓库，想要撤销这次提交。
- **命令**：
  ```bash
  git revert <commit-hash>
  ```
    - `commit-hash` 是要撤销的提交的哈希值。
    - `git revert` 会创建一个新的提交来撤销之前的提交，而不是直接删除提交。

## 5.修改最后一次提交

**修改最后一次提交**

- **场景**：提交后发现提交信息有误，或者漏掉了某些文件，想要修改最后一次提交。
- **命令**：
  ```bash
  git commit --amend
  ```
    - 如果只是修改提交信息：
      ```bash
      git commit --amend -m "新的提交信息"
      ```
    - 如果还要添加漏掉的文件：
      ```bash
      git add <file>
      git commit --amend
      ```

## 6.撤销合并操作

**撤销合并操作**
- **场景**：合并分支后发现有问题，想要撤销合并。
- **命令**：
  ```bash
  git merge --abort
  ```
  如果已经完成合并，可以使用 `git reset` 回退到合并前的状态：
  ```bash
  git reset --hard HEAD^
  ```

---

### **7. 撤销 `git stash` 操作**
- **场景**：使用 `git stash` 暂存了修改，想要恢复这些修改。
- **命令**：
  ```bash
  git stash pop
  ```
  如果只想恢复但不删除暂存的内容：
  ```bash
  git stash apply
  ```

---

### **8. 撤销 `git rebase` 操作**
- **场景**：执行 `git rebase` 后发现有问题，想要撤销。
- **命令**：
  ```bash
  git rebase --abort
  ```

---

### **9. 查找历史版本并恢复**
- **场景**：想要恢复到某个历史版本。
- **命令**：
  ```bash
  git checkout <commit-hash>
  ```
  例如：
  ```bash
  git checkout abc1234
  ```
  如果要恢复整个项目到某个历史版本：
  ```bash
  git reset --hard <commit-hash>
  ```

---

### **10. 强制推送（慎用）**
- **场景**：本地撤销了提交，需要强制推送到远程仓库。
- **命令**：
  ```bash
  git push --force
  ```
  **注意**：强制推送会覆盖远程仓库的历史记录，可能导致团队协作问题，慎用！

---

### **总结**
| 场景                         | 命令                                      |
|------------------------------|------------------------------------------|
| 撤销工作区修改               | `git checkout -- <file>`                 |
| 撤销暂存区修改               | `git reset HEAD <file>`                  |
| 撤销本地提交                 | `git reset --soft HEAD^`                 |
| 撤销远程提交                 | `git revert <commit-hash>`               |
| 修改最后一次提交             | `git commit --amend`                     |
| 撤销合并操作                 | `git merge --abort` 或 `git reset --hard HEAD^` |
| 撤销 `git stash` 操作        | `git stash pop` 或 `git stash apply`     |
| 撤销 `git rebase` 操作       | `git rebase --abort`                     |
| 恢复到历史版本               | `git checkout <commit-hash>`             |
| 强制推送                     | `git push --force`                       |

根据具体场景选择合适的命令，谨慎操作，避免数据丢失！
