## 01.Cherry-Pick核心概念

### 1.1 什么是Cherry-Pick

Cherry-Pick 是 Git 的**选择性提交移植**命令，它允许你将特定提交（而非整个分支）应用到当前分支。就像从树上挑选特定樱桃一样，你可以选择性地提取代码变更。

### 1.2 与Merge/Rebase区别

| 操作 | 作用范围 | 提交历史 | 适用场景 |
|------|----------|----------|----------|
| **Merge** | 整个分支 | 保留原始提交 | 功能完整合并 |
| **Rebase** | 整个分支 | 重写提交历史 | 清理分支历史 |
| **Cherry-Pick** | 单个提交 | 创建新提交副本 | 精准移植特定修复 |

## 02.Cherry-Pick基础操作

### 2.1 基本语法

```bash
git cherry-pick <commit-hash>
```

### 2.2 操作流程

```bash
# 1. 切换到目标分支
git checkout main

# 2. 执行 cherry-pick
git cherry-pick abc123def

# 3. 解决冲突（如有）
# 4. 提交解决结果
git cherry-pick --continue
```

## 03.高级Cherry-Pick技巧

### 3.1 多提交选择

```bash
# 选择连续提交范围
git cherry-pick abc123..def456

# 选择不连续提交
git cherry-pick abc123 def456 xyz789
```

### 3.2 提交编辑选项

```bash
# 编辑提交信息
git cherry-pick -e abc123

# 不自动提交（修改后手动提交）
git cherry-pick -n abc123
```

### 3.3 签名与追踪

```bash
# 添加 Signed-off-by
git cherry-pick -s abc123

# 保留原提交者信息
git cherry-pick -x abc123
```

## 04.实际场景中使用情况

假设你在 bugfix-branch 上修复了一个 bug，提交哈希为 abc123。你想将这个修复应用到 main 分支：

1. 切换到 main 分支：git checkout main
2. 运行 cherry-pick：git cherry-pick abc123
3. 如果成功，main 分支将包含 abc123 的更改。


## 06.Cherry-Pick常见陷阱

### 6.1 常见问题

- **依赖丢失**：提交依赖未移植的父提交
- **冲突雪崩**：多个相关提交分开移植导致重复冲突
- **历史污染**：重复提交破坏提交历史清晰度

### 6.2 替代方案评估

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 完整功能移植 | Merge | 保留完整上下文 |
| 多相关提交 | Rebase | 保持提交顺序 |
| 紧急热修复 | Cherry-Pick | 快速精准 |
| 长期分支同步 | 定期 Merge | 减少冲突 |
