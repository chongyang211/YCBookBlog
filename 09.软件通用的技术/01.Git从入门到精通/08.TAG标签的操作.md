# TAG标签的操作
## 目录介绍
- 1.创建标签
- 2.查看标签
- 3.推送标签
- 4.删除标签
- 5.切换到标签




`git tag` 是 Git 中用于管理标签（Tag）的命令。标签通常用于标记项目的重要节点，例如版本发布（如 `v1.0.0`）。与分支不同，标签是静态的，通常不会随着提交而移动。

## 1.创建标签

#### **轻量标签（Lightweight Tag）**

轻量标签只是一个指向特定提交的引用，不包含额外信息。

```bash
git tag <tag_name>
```
例如：
```bash
git tag v1.0.0
```

#### **附注标签（Annotated Tag）**

附注标签是一个完整的 Git 对象，包含标签名称、标签信息、创建者、日期等元数据。

```bash
git tag -a <tag_name> -m "Tag message"
```

例如：

```bash
git tag -a v1.0.0 -m "Release version 1.0.0"
```

## 2.查看标签

#### **列出所有标签**

```bash
git tag
```

#### **查看标签详情**

```bash
git show <tag_name>
```

例如：

```bash
git show v1.0.0
```

#### **按模式搜索标签**

```bash
git tag -l "v1.*"
```

例如，列出所有以 `v1.` 开头的标签。

## 3.推送标签

默认情况下，`git push` 不会推送标签。需要显式推送标签。

#### **推送单个标签**

```bash
git push origin <tag_name>
```

例如：

```bash
git push origin v1.0.0
```

#### **推送所有标签**

```bash
git push origin --tags
```

## 4.删除标签

#### **删除本地标签**
```bash
git tag -d <tag_name>
```
例如：
```bash
git tag -d v1.0.0
```

#### **删除远程标签**

```bash
git push origin :refs/tags/<tag_name>
```
例如：
```bash
git push origin :refs/tags/v1.0.0
```

---

### **5. 切换到标签**
标签指向的是特定的提交，因此可以切换到标签对应的代码状态。
```bash
git checkout <tag_name>
```
例如：
```bash
git checkout v1.0.0
```

注意：切换到标签后，会进入“分离头指针”（detached HEAD）状态。如果需要基于标签修改代码，可以创建新分支：
```bash
git checkout -b <new_branch_name> <tag_name>
```
例如：
```bash
git checkout -b release-v1.0.0 v1.0.0
```

---

### **6. 基于标签创建分支**
如果需要基于标签开发新功能或修复问题，可以创建新分支：
```bash
git branch <new_branch_name> <tag_name>
```
例如：
```bash
git branch hotfix-v1.0.0 v1.0.0
```

---

### **7. 重命名标签**
Git 没有直接重命名标签的命令，可以通过以下步骤实现：
1. 删除旧标签：
   ```bash
   git tag -d <old_tag_name>
   git push origin :refs/tags/<old_tag_name>
   ```
2. 创建新标签：
   ```bash
   git tag <new_tag_name> <commit_hash>
   git push origin <new_tag_name>
   ```

---

### **8. 标签与版本管理**
标签通常用于标记版本发布。常见的版本号格式是 `v<major>.<minor>.<patch>`，例如 `v1.2.3`：
- **主版本号（Major）**：重大更新，可能不兼容旧版本。
- **次版本号（Minor）**：新增功能，向下兼容。
- **修订号（Patch）**：修复问题，向下兼容。

例如：
```bash
git tag -a v1.2.3 -m "Release version 1.2.3"
```

---

### **9. 标签与 CI/CD**
在持续集成/持续部署（CI/CD）中，标签常用于触发发布流程。例如：
- 当推送 `v1.0.0` 标签时，自动构建并发布版本。
- 使用 `git describe` 获取当前代码的标签信息：
  ```bash
  git describe --tags
  ```

---

### **总结**
`git tag` 是 Git 中管理标签的核心命令，常用于标记版本发布。以下是常用操作：
- 创建标签：`git tag <tag_name>` 或 `git tag -a <tag_name> -m "message"`
- 查看标签：`git tag` 或 `git show <tag_name>`
- 推送标签：`git push origin <tag_name>` 或 `git push origin --tags`
- 删除标签：`git tag -d <tag_name>` 和 `git push origin :refs/tags/<tag_name>`
- 切换到标签：`git checkout <tag_name>`
- 基于标签创建分支：`git branch <new_branch_name> <tag_name>`

通过合理使用标签，可以更好地管理项目的版本和发布流程！ 🚀
