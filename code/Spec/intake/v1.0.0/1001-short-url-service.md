# 短链接：让文章分享链接变短 + 能看点击量

> 📌 **这是教学案例**（Story 1001「短链接服务」全套样例之一，导读见 `docs/07-case.md`）。
> 真实需求请复制 `templates/intake-template.md` 起草。本文件刻意保留原话的口语化与歧义。

## 原始需求（原话）

> 王敏 2026-08-03 10:24：
> "咱们文章的链接太长了，发到群里直接被截断成两行，用户点不了，转化率特别差。
> 能不能做个那种 t.cn 一样的短链？最好能看多少人点过。"

> 王敏 2026-08-03 例会补充：
> "链接最好别太快失效，有的活动文章会反复推。但是那种活动页过期的，
> 链接过期了也别给用户报错，跳个说明页就行。"

## 相关背景

- 平台文章 URL 形如 `https://www.example-content.com/articles/2026/08/how-we-built-our-cms`，普遍 80+ 字符
- 竞品 A / B 均已提供短链 + 基础点击统计
- 现有 `share-service` 只做分享渠道适配，无短链能力
- 移动端 App 的「分享到会话」走的系统分享面板，同样受长 URL 影响

## 待澄清点

- [ ] 短链保留期多久？永久还是默认 N 天可配置？
- [ ] 是否允许用户自定义短码后缀（如 `s.example.com/618sale`）？
- [ ] 点击统计需要哪些维度（总量 / 按天 / 按渠道 / 按地域）？给谁看（运营后台？）？
- [ ] 目标 URL 的范围：只允许本平台文章，还是任意外链？
- [ ] 短链域名是用主域子域（`s.example-content.com`）还是新购域名？
- [ ] 是否需要防刷 / 防滥用（恶意创建短链指向外部钓鱼页）？
- [ ] 移动端分享入口是否本期就要接入，还是先只做 Web 端？
