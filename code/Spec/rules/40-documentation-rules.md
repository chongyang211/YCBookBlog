# 文档规则

## 哪些变更必须同步更新文档

| 变更类型 | 需要更新的文档 |
|----------|----------------|
| 新增功能完成 | spec 状态改为 `implemented` |
| 实现偏离 spec | 更新 spec 或在 spec 中标注偏离说明 |
| 公共 API/接口变更 | 更新相关 API 文档（如有） |
| 架构变更 | 更新 `docs/` 中相关架构文档 |
| 新增重要依赖 | 在 spec 或 docs 中说明 |
| 项目结构变更 | 更新 `README.md` |

## 实现偏离 Spec 时的处理

如果实现过程中发现 spec 的某些要求不合理或需要调整：

1. **不要沉默地偏离**——必须明确说明偏离点
2. **在变更摘要中标注**——说明偏离了什么、为什么
3. **建议更新 spec**——提供具体的 spec 修改建议
4. **等待确认**——重大偏离应在实施前获得确认

## 文档更新的最小要求

每次完成一个 spec 的实施后，至少确保：

1. spec 文件的 `Status` 字段已更新
2. spec 文件的 `Updated` 日期已更新
3. 如果验收标准已验证通过，标记对应的 checkbox
4. 变更摘要中包含"文档同步"部分

## Docs 目录

`docs/` 用于存放：

- 架构决策记录（ADR）
- 模块设计文档
- 部署/运维说明
- 其他与 spec 不同层级的补充文档

`docs/` 中的文档不替代 spec，两者互补：
- **spec**：描述"要做什么"
- **docs**：描述"为什么这样做"和"怎样运行/维护"
