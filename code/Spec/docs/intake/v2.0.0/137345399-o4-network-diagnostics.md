## Debug 页面可视化呈现（2026-08-28 补充需求）

> 网络检测与测速放到上位机 **Demo 的 Debug 页面**呈现，把检测流程**可视化**展示出来，现场排查时一目了然。

- **检测流程可视化**：四层检测（物理层 → 本地层 → 连接层 → 服务层）按执行顺序逐步展示——每层显示「检测中 / 通过 ✓ / 失败 ✗」状态、失败原因与错误码、关键中间数据（如当前 IP / 网关 / DNS / 路由表优先级 / Ping 网关时延）；上层失败即止（对齐 O2 遇失败停止策略），未执行层显示「跳过（上游失败）」
- **测速结果展示**：最近一次测速时间、上下行速率、弱网判定结论（对照弱网标准阈值）
- **呈现载体**：Demo Debug 页（对应检测触发方式中的「Demo 按钮触发」，触发与展示同页闭环）；上报通道另行走既有上报链路，Debug 页仅做现场可视化

## M3/M4 网络问题实测经验（检测规则与配置策略设计输入，2026-08-28 补充）

> 以下为 M3/M4 实际遇到并解决的问题，梳理为「问题与根因 / 设计输入」两部分，作为 Design 阶段检测规则与网络配置策略的硬约束。

| # | 主题 | 问题与根因（实测） | 设计输入 |
|---|------|------------------|---------|
| 1 | **网线插拔判定失效** | 内核 `carrier` 标志本应表征网线插拔，但 M3 因给模组分网导致 carrier **恒为 1**，无法体现物理插拔 | 网络层可用性判据改为「**能否 Ping 通网关**」：通=可用，不通=不可用。**特别禁止 Ping 百度等公网**做判据——设备可能部署在私有化环境，Ping 不通公网 ≠ 网络不可用；**Ping 网关最靠谱** |
| 2 | **无 DHCP 路由器场景** | 设备不支持无 DHCP 的路由器：static 模式下「没获取到 IP」≠「没连上路由器」——路由器无 DHCP 且设备未手动配 IP 时会**永远无 IP，但链路实际已连**（其他 AP 同理） | 本地层检测需**区分两个状态**：链路已连接 vs IP 已配置；检测结论输出「已连路由器但无 IP（疑似路由器无 DHCP 或需静态配置）」而非笼统「未连接」 |
| 3 | **路由 metric 优先级** | 双网口（WiFi+以太网）时出口由**路由表 metric** 决定（越小优先级越高）；实测出现「WiFi 可用、以太网不可用，但以太网网关优先级更高 → 流量走以太网 → 设备断网」 | ① 连接层检测应采集并输出**当前路由表及优先级**（`ip route show`）；② 配置侧须**保证可用网络的网关路由优先级更高**；③ 检测到「活动路由指向不可用网口」应作为明确告警项输出 |
| 4 | **DNS 配置错误** | 默认 DNS = 网关（用户不填时），用户填了则用指定值；DNS 配错 → 后台域名解析失败 → 连不上后台 | 连接层检测须包含 **DNS 解析检查**（解析后台域名），并把当前生效 DNS 纳入检测结果输出；DNS 可达但解析失败是独立失败项 |
| 5 | **静态 WiFi 参数按 SSID 隔离** | 静态 WiFi 模式使用少但需支持；且是**一个 WiFi（SSID）一套静态配置，非全局唯一** | 配置模型：静态参数（IP/掩码/网关/DNS）绑定 SSID 存储；**切换 WiFi 后静态参数必须跟着切换**（沿用目标 SSID 自己的那套） |
| 6 | **以太网/WiFi 优先级与无感切换** | KYC 约定**以太网 > WiFi**（具体以产品经理定义为准）；优先级语义：以太网不可用自动切换 WiFi；两者都可用时优先以太网 | 网络策略需实现**优先级 + 无感切换**：主用网口失效时自动降级备用（对业务无感），恢复后回升主用；切换过程应触发检测/测速重跑（衔接测速触发方式） |
| 7 | **静态以太网不切换（例外规则）** | 静态以太网配置了错误参数、但 WiFi 可用时，**不切换到 WiFi**——静态的含义就是明确要求使用该配置 | 优先级自动切换规则（#6）的**例外**：静态网口配置错误导致不通时，**提醒用户修改静态参数**而非切换网络；检测结论需区分「静态配置错误（需用户改参数）」与「链路故障（可自动切换）」 |

### 问题 → 四层检测映射（Design 阶段检测项设计索引）

| 检测层 | 吸收的实测经验 | 检测项输入 |
|--------|---------------|-----------|
| 物理层 | #1（carrier 失效） | 网线插拔/WiFi 关联状态判定**不以 carrier 为准**，结合链路状态与 #2 链路态综合判断 |
| 本地层 | #2（无 DHCP）、#5（SSID 静态配置） | IP 配置状态（含「已连无 IP」特殊态）；当前生效配置（DHCP/静态；静态 WiFi 参数随 SSID） |
| 连接层 | #1（Ping 网关判据）、#3（路由 metric）、#4（DNS）、#6（优先级） | Ping 网关（唯一可用性判据，禁公网）；路由表与活动出口优先级；DNS 解析后台域名；当前活动网口与优先级状态 |
| 服务层 | #4（DNS 错 → 连不上后台） | 后台域名连通（依赖连接层 DNS 结论）；区分 DNS 故障与服务端故障 |

## 可复用资产（O2 网络检测，已初步侦察）

- **位置**：`src/iotservice_linux/src/operations/strategy/`（14 个文件）
- **架构**（策略模式）：
  - `BaseNetworkStrategy` 基类 + 四层 Strategy：`physical_layer_strategy`（物理层）/ `local_network_strategy`（本地层）/ `connectivity_strategy`（连接层）/ `service_strategy`（服务层）
