# docs 目录

## 用途

`docs/` 存放与 spec 互补的补充文档，包括但不限于：

- **架构决策记录（ADR）**：为什么选择某种技术方案
- **模块设计文档**：复杂模块的内部设计说明
- **部署/运维说明**：如何构建、部署、运行项目
- **接口文档**：API 使用说明
- **会议/讨论记录**：影响设计的重要讨论结论

## 与 Spec 的区别

- **spec**：描述"要做什么"——功能需求、验收标准
- **docs**：描述"为什么这样做"和"怎样运行/维护"

## 什么时候应该更新 Docs

- 架构或技术方案发生重大变更时
- 部署流程变化时
- 新增重要的外部依赖时
- 接口发生 breaking change 时
- 团队协作约定变更时
