# tests 目录

## 用途

`tests/` 存放所有测试代码。测试与 `specs/` 中的验收标准直接对应，是验证实现正确性的客观手段。

## 如何根据 Spec 与代码变更补测试

1. 阅读 spec 的"验收标准"——每条标准至少一个测试
2. 阅读 spec 的"测试点"——按场景编写测试
3. 阅读 spec 的"边界情况"——每个边界一个测试
4. 测试命名：`Test_[功能]_[场景]_[预期]`
5. 测试放在与被测模块对应的文件中

## 测试与验收标准的关系

| Spec 章节 | 测试类型 | 优先级 |
|-----------|----------|--------|
| 验收标准 | 必须覆盖 | 最高 |
| 测试点-正常路径 | 必须覆盖 | 高 |
| 测试点-边界条件 | 必须覆盖 | 高 |
| 测试点-错误处理 | 必须覆盖 | 高 |
| 非功能需求 | 按需覆盖 | 中 |

## 组织结构

- 测试文件与被测模块对应
- 相关测试用逻辑分组
- 每个测试独立可运行，不依赖执行顺序
