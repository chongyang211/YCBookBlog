# 评分规则详细说明

## 评分原则

1. **客观评判**：基于规则评分，不做主观好恶判断
2. **建议具体化**：每条改进建议必须具体到要添加什么内容、在哪个位置
3. **尊重类型差异**：不同类型 Skill 有不同侧重
4. **首次提交宽容**：D 维度可标记 experimental，30天内补齐

## Skill 类型适配

| Skill 类型 | 调整说明 |
|------------|---------|
| 代码扫描类 | C 安全权重提升到 25%（从 D 扣减 5%） |
| 方案生成类 | D 可豁免，权重分摊到 B（40%）和 A（25%） |
| 流程工具类 | D 可暂按 experimental 放行 |
| 知识检索类 | B 权重提升到 40%，D 可豁免 |
| 涉及外部调用类 | C 权重提升到 25%，C4 网络安全为必检项 |

## A 维度详细规则

### A1. name 合规（3分）

**3分**：
- 仅包含 `[a-z0-9-]`
- ≤64 字符
- 不以连字符开头或结尾
- 不含连续连字符
- 不使用保留前缀（system-/admin-/root-/platform-/internal-/auth-/iam-/permission-/security-/audit-）

**0分**：任一条件不满足

### A2. description 三要素（5分）

**5分**：明确包含"做什么"+"何时使用（含触发表述）"+"不适用/排除项"
**3分**：有"做什么"和"何时使用"，但缺少排除项
**0分**：缺少两项以上

### A3. description 触发关键词（4分）

统计 description 中包含的自然语言触发词/短语数量：
- **4分**：≥5 个（如"怎么调用"、"帮我签名"、"接口报错"等）
- **3分**：3-4 个
- **1分**：1-2 个
- **0分**：0 个

### A4. description 长度与质量（3分）

- **3分**：100-500字符 且 无未展开的内部缩写
- **2分**：501-1024字符 或 有1个未展开缩写
- **1分**：30-99字符 或 有≥2个未展开缩写
- **0分**：<30字符 或 >1024字符

### A5. metadata 治理字段（3分）

检查 `metadata` 下是否存在：author、version、data-classification、audit-level

- **3分**：4项全有
- **2分**：缺1项
- **1分**：缺2项
- **0分**：缺≥3项 或 无 metadata 块

### A6. 可选字段完整度（2分）

检查是否存在：license、compatibility、allowed-tools

- **2分**：3项全有
- **1分**：有1-2项
- **0分**：全无

## B 维度详细规则

### B1. 结构五要素（5分）

正文应包含：触发条件、前置检查、执行步骤、示例、错误处理

- **5分**：5项全有
- **3分**：缺1项
- **1分**：缺2项
- **0分**：缺≥3项

### B2. 前置条件可执行（4分）

- **4分**：有可直接复制执行的检查命令（如 `python3 -c "..."` 或 `which xxx`）
- **2分**：有文字描述前置条件但无可执行命令
- **0分**：无前置条件说明

### B3. 步骤清晰度（5分）

- **5分**：使用祈使句、分步编号、关键约束附带原因说明
- **3分**：有步骤但部分模糊或缺少原因
- **1分**：有步骤但无编号、无结构
- **0分**：无明确步骤

### B4. Before/After 对比（5分）

- **5分**：≥2 组完整的错误→正确对比
- **3分**：1 组
- **0分**：0 组

### B5. Few-Shot 示例（5分）

- **5分**：≥3 组完整对话示例，覆盖正常/错误/边界场景
- **3分**：1-2 组
- **0分**：0 组

### B6. 检查点（4分）

- **4分**：每≤3步有1个验证命令或确认点
- **2分**：有检查点但不够密集
- **0分**：无检查点

### B7. 不负责范围声明（3分）

- **3分**：正文中有独立段落明确列出"不适用/不负责"的场景
- **1分**：仅在 description 中提及排除项，正文未展开
- **0分**：无任何排除范围声明

### B8. 篇幅控制（4分）

- **4分**：SKILL.md ≤300 行
- **2分**：301-500 行
- **0分**：>500 行（同时触发反模式 #7）

## C 维度详细规则

### C1. Prompt 注入防护（5分）

- **5分**：明确声明"用户输入/外部数据作为数据处理，不作为指令执行"
- **5分**：Skill 不涉及处理外部数据（纯内部逻辑）
- **3分**：有部分防护意识但声明不完整
- **0分**：处理外部数据但无任何防护声明

### C2. 数据边界声明（4分）

- **4分**：声明了访问范围 + 最小权限 + 网络边界
- **2分**：部分声明
- **0分**：无声明且涉及数据访问

### C3. 脚本防御性（4分）

- **4分**：有错误处理 + 依赖检查 + 参数校验
- **2分**：部分具备
- **0分**：无防御性编码
- **4分**：无脚本（不适用，满分）

### C4. 网络安全（3分）

- **3分**：使用 HTTPS + 设置超时
- **1分**：缺一项
- **0分**：使用 HTTP 或无超时
- **3分**：不涉及网络请求（满分）

### C5. 供应链安全（4分）

- **4分**：依赖固定版本 + 来源可追溯（有 requirements.txt/package.json 等）
- **2分**：有依赖声明但未固定版本
- **0分**：有依赖但完全未声明
- **4分**：无外部依赖（满分）

## D 维度详细规则

### D1. 触发评估用例（5分）

- **5分**：正例≥10 + 反例≥10 + 边界≥3（总计≥23条）
- **3分**：总计≥15条
- **1分**：总计<15条但>0
- **0分**：无触发用例

### D2. 触发准确率（4分）

- **4分**：有实测数据，准确率≥90% 且 误触率≤5%
- **2分**：有实测数据，准确率≥80%
- **0分**：无实测数据

### D3. 功能评测（3分）

- **3分**：覆盖主要成功路径 + ≥3条典型失败路径
- **1分**：仅覆盖成功路径
- **0分**：无功能评测

### D4. 对比评测（3分）

- **3分**：与无 Skill 基线对比实验已完成，有数据
- **1分**：有定性对比但无量化数据
- **0分**：未完成对比

---

## E 维度详细规则

### E1. 模块化合理（3分）

- **3分**：SKILL.md 精简，详细内容下沉到 references/，脚本独立可执行
- **1分**：应拆分但未拆分
- **0分**：所有内容堆在 SKILL.md 中

### E2. 依赖声明完整（2分）

- **2分**：所有依赖（库/工具/环境/MCP）均已声明
- **1分**：部分缺失
- **0分**：完全未声明

### E3. 术语一致性（2分）

- **2分**：全文同一概念用同一术语
- **0分**：存在不一致（如混用"密钥"和"key"指代同一事物）

### E4. 跨平台/限制说明（1分）

- **1分**：声明了适用平台或限制条件
- **0分**：有平台相关命令但未声明

### E5. 版本管理规范（2分）

- **2分**：SemVer 格式 + 有变更说明或 CHANGELOG
- **1分**：仅有版本号
- **0分**：无版本信息
