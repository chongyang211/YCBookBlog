# 变更摘要

在完成 spec 实施和测试后，输出结构化的变更总结，包括改了什么、为什么、影响范围、风险和后续建议。

## 执行步骤

1. **汇总文件变更**
   - 列出所有新增、修改、删除的文件
   - 每个文件说明改动概要

2. **关联 Spec**
   - 指明对应哪个 spec
   - 检查验收标准完成情况

3. **描述关键决策**
   - 实施过程中的设计取舍
   - 偏离 spec 的地方（如有）

4. **评估影响范围**
   - 受影响的模块
   - 接口变更、数据结构变更

5. **识别风险**
   - 潜在问题
   - 需关注的边缘情况
   - 性能影响

6. **建议后续行动**
   - 验证方式
   - 需同步的文档
   - 遗留 TODO

## 输出格式

```markdown
### 变更摘要

**关联 Spec**：specs/<VERSION>/<STORYID>-feature-name.md（Story ID: <STORYID>）
**日期**：[日期]

**改了什么**：
- [文件]：[简述]

**为什么这样改**：
- [决策]：[理由]

**影响范围**：
- 直接影响：[模块/接口]

**风险点**：
- [风险]

**未完成项**：
- [遗留事项]

**建议验证方式**：
1. [步骤]

**文档同步**：
- [ ] 更新 spec 状态
- [ ] 更新验收标准 checkbox
```

## 注意事项

- 变更摘要**不可省略**，是工作流的必须输出
- 摘要应具体到文件和函数级别
- 风险点要诚实列出
- 没有风险写"无已知风险"，不要省略该部分
