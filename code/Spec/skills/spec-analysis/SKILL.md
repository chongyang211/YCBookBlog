# Spec 分析

分析 `specs/` 中的需求规格文档，提取关键信息，评估完整性，识别缺失或模糊之处。

## 执行步骤

1. **读取 spec 全文**
   - 打开指定的 spec 文件完整阅读
   - 如果路径不明确，扫描 `specs/` 目录寻找最匹配的文件

2. **提取关键信息**
   - 目标与非目标
   - 功能需求列表（FR-1, FR-2, ...）
   - 验收标准
   - 边界情况
   - 测试点
   - 风险与未决问题

3. **评估完整性**
   - 检查是否有 `[TBD]` 或空白章节
   - 功能需求是否足够具体（能否直接转化为代码）
   - 验收标准是否可验证（有无明确的通过/失败条件）
   - 边界情况是否覆盖常见异常

4. **识别缺失信息**
   - 功能需求中未定义的行为
   - 数据结构是否完整
   - 接口定义是否清晰
   - 错误处理策略是否明确

5. **输出分析结果**

## 输出格式

```markdown
### Spec 分析：[Story ID] [标题]

**理解摘要**：
[2-5 句话总结这个 spec 要做什么]

**功能需求清单**：
- FR-1: [简述]
- FR-2: [简述]

**完整性评估**：
- ✅ 完整的部分
- ⚠️ 需要澄清的部分
- ❌ 缺失的部分

**建议**：
[在开始实施前需要解决的问题]
```

## 注意事项

- 不要在分析阶段设计解决方案，那是 implementation-planning 的职责
- 如果 spec 有重大缺失，先指出问题，不要假设
- 分析应客观，不替 spec 作者补充未写明的需求
