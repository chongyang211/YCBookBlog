## 03.容器和虚拟化

### 3.1 Docker

在 Linux 下使用 Docker 的主要用途是提供一种轻量级、可移植和高效的容器化技术，用于构建、部署和运行应用程序。

Docker 通过将应用程序及其依赖项打包到一个容器中，解决了“在我的机器上可以运行，但在其他机器上不行”的问题。

在 Linux 下使用 Docker 的主要用途包括：

1. **应用程序隔离**：避免依赖冲突。环境隔离，容器之间共享操作系统内核，但拥有独立的文件系统、网络和进程空间。
2. **跨平台一致性**：确保开发、测试和生产环境一致。
3. **快速部署和扩展**：提高部署效率和弹性扩展能力。
4. **简化依赖管理**：将应用程序及其依赖项打包到容器中。通过 Docker 镜像可以轻松管理应用程序的不同版本。
5. **提高资源利用率**：轻量级且高效。Docker 容器共享主机操作系统内核。
6. **支持 CI/CD**：实现自动化构建和部署。
7. **微服务架构**：支持服务拆分和通信。

**Docker的核心组件**：

- **Docker Engine**：Docker 的核心组件，负责创建和管理容器。
- **Docker Image**：容器的模板，包含应用程序及其依赖项。
- **Docker Container**：Docker 镜像的运行实例。
- **Dockerfile**：用于定义 Docker 镜像的脚本文件。
- **Docker Compose**：用于定义和运行多容器应用程序的工具。
- **Docker Hub**：Docker 镜像的公共仓库，可以分享和下载镜像。

用于容器化应用程序。
```bash
sudo apt install docker.io
sudo systemctl enable --now docker
```

## 08.实际应用开发

### 8.1 启动docker

推荐使用colima，Colima 是一个在 macOS 和 Linux 上运行容器（如 Docker 容器）的工具，它通过虚拟机（VM）来提供容器运行时环境。

```shell
colima start --vm-type=vz --vz-rosetta --arch aarch64 --memory 16 --cpu 8
```

- colima start：这是 Colima 的核心命令，用于启动一个虚拟机实例，以便在其上运行容器。
- --vm-type=vz：vm-type：指定虚拟机的类型。vz：表示使用 macOS 的 Virtualization.framework（虚拟化框架）来创建虚拟机。
- --vz-rosetta：vz-rosetta是启用 Rosetta 2 转译功能。Rosetta 2 是 Apple 提供的一个转译层，允许在 Apple Silicon（如 M1、M2 芯片）上运行 x86_64 架构的应用程序。
- --arch aarch64：arch是指定虚拟机的 CPU 架构。aarch64是表示虚拟机的 CPU 架构为 ARM 64 位（即 Apple Silicon 的原生架构）。
- --memory 16：memory是指定虚拟机分配的内存大小。 16是表示虚拟机分配 16 GB 的内存。根据宿主机的可用内存和应用程序的需求，可以调整此值。
- --cpu 8：cpu是指定虚拟机分配的 CPU 核心数量。8：表示虚拟机分配 8 个 CPU 核心。根据宿主机的 CPU 核心数量和应用程序的需求，可以调整此值。


这条命令的作用是：

- 使用 **Virtualization.framework**（`--vm-type=vz`）启动一个 Colima 虚拟机。
- 启用 **Rosetta 2** 转译功能（`--vz-rosetta`），以便在 Apple Silicon 上运行 x86_64 架构的容器。
- 虚拟机的 CPU 架构为 **ARM 64 位**（`--arch aarch64`），适合 Apple Silicon 设备。
- 虚拟机分配 **16 GB 内存**（`--memory 16`）和 **8 个 CPU 核心**（`--cpu 8`）。

假设你在一台 M1 Mac 上运行这条命令：

```bash
colima start --vm-type=vz --vz-rosetta --arch aarch64 --memory 16 --cpu 8
```

结果：

1. 启动一个基于 Virtualization.framework 的 Colima 虚拟机。
2. 虚拟机使用 ARM 64 位架构（原生支持 M1 芯片）。
3. 启用 Rosetta 2，允许运行 x86_64 架构的容器。
4. 虚拟机分配 16 GB 内存和 8 个 CPU 核心。

检查 Docker 是否已启动，直接运行 docker 命令，如果 Docker 已启动，会显示 Docker 的帮助信息；如果未启动，会提示错误。

```shell
docker info
```

# 调试
## 日志
日志默认位于可执行程序同级目录的log下，最大保留五个文件，每个8M

## M4真机调试
### 打开adb
状态栏时间，多次点击（最少五下）进入Debug页面，打开adb

### 关闭原应用
- 关闭看门口：   dbus-send --system --dest=rockchip.daemon --type=method_call --print-reply  / rockchip.daemon.server.StopWatchDog
- 关闭应用守护： dbus-send --system --dest=rockchip.daemon --type=method_call --print-reply  / rockchip.daemon.server.SetDaemonApp int32:0
- 关闭应用：killall yt-palm
- 删除原来目录： rm -rf /oem/yt-palm/*

### push新应用
- 解压zip
  - 注意不能在设备里unzip，会丢失软链接，需要 ln -s 源文件 目标文件重新创建
  - 可以在mac解压
- adb push 解压后的文件到/oem/yt-palm
- 添加权限：chmod -R 0755  /oem/yt-palm
- 开启新应用 /oem/yt-palm/run.sh
- 后续如果只有应用代码变更，单独push yt-palm到/oem/yt-palm/下即可
