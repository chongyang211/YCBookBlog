## 05.厂商通用能力设计

### 5.1 遇到的问题

现在硬件设备，有一种通用能力，比如静默安装apk，设置自启动应用，更新系统时间，发送韦根协议数据，继电器等，每一家厂商提供的api可能还不同【功能是统一，可能api名称或调用不一样】。

目前有：A，B，C，D，E……等等。频繁适配新的厂商机具，而各家厂商设计的硬件能力不一样，给适配工作和沟通拉齐增加成本。沟通成本高，厂商文档缺少……

### 5.2 解决问题办法

制定了一套功能标准，需要我们厂商预先集成SDK，按照我们的协议实现相关功能。相当于在业务层定义一套统一抽象接口，可以磨平底层的差异。

### 5.3 开发代码实践

设计一套统一的api接口如下所示：

```java
//使用系统层接口能力，比如展示/隐藏状态栏，重启设备，获取mac，静默安装等等
HardwareHelper.getInstance().getSystem().reboot(null);
HardwareHelper.getInstance().getSystem().setNavigationBar(true,null);

//使用硬件业务相关能力。开门
HardwareHelper.getInstance().getAccess().openDoor(new ResultCallback<Boolean>() {
    @Override
    public void result(Boolean aBoolean) {
    	//接收调用api后回调结果
    }
});
//发送韦根协议
HardwareHelper.getInstance().getAccess().writeWiegand("sss".getBytes(),null);
```

## 07.多厂商相机设计

### 7.1 遇到的问题

A，B，C，D，E……等等各种不同的硬件设备，不同的厂商提供不同的相机采集手掌。上层业务对采集图片进行图片质量分析。

### 7.2 解决的方案

抽象一套通用的相机API接口，磨平不同厂商相机采集的差异性。上层业务调用通用API接口！

### 7.3 统一API设计

以下是相机 API 设计的含义和作用：

| API           | 说明   | 场景        |
|---------------|------|---------------------|
| `open();`     | 启动相机 | 初始化相机后打开相机    |
| `close();`    | 关闭相机 | 销毁相机，销毁相机后如果再想用相机，则必须 `open`。|
| `start();`    | 开始采集 | 开始采集，主要是指相机采集流开始。 |
| `stop();`     | 停止采集 | 停止采集，主要是指相机采集流停止。  |
| `setStatus`   | 设置状态 | `setStatus(STOPPED)`：停止识别<br> `setStatus(STANDBY)`：开始识别<br> |
| `setListener` | 数据回调 | 设置相机采集的数据回调。在这个回调里面主要是图片处理工作。 |
