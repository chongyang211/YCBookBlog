## 01.先来看一个案例

模拟了一个电影院售票系统：

1. 共有100张票（private static int num = 100）
2. 3个售票窗口（3个线程）
3. 每个线程不断尝试售票，直到票数为0

### 1.1 卖电影票案例1

继承Thread类的方式卖电影票案例，代码如下所示

```java
public class ThreadDemo {
	public static void main(String[] args) {
		/**
		 * 需求：某电影院目前正在上映贺岁大片，共有100张票，而它有3个售票窗口售票，请设计一个程序模拟该电影院售票。
		 */
		// 创建3个线程对象
		SellTicktes t1 = new SellTicktes() ;
		SellTicktes t2 = new SellTicktes() ;
		SellTicktes t3 = new SellTicktes() ;
		// 设置名称
		t1.setName("窗口1") ;
		t2.setName("窗口2") ;
		t3.setName("窗口3") ;
		// 启动线程
		t1.start() ;
		t2.start() ;
		t3.start() ;
	}
}

public class SellTicktes extends Thread {
	private static int num = 100 ;
	@Override
	public void run() {
		/**
		 * 定义总票数
		 * 
		 * 如果我们把票数定义成了局部变量,那么表示的意思是每一个窗口出售了各自的100张票; 而我们的需求是: 总共有100张票
		 * 而这100张票要被3个窗口出售; 因此我们就不能把票数定义成局部变量,只能定义成成员变量
		 */		
		// 模拟售票
		while(num != 0) {
			if( num > 0 ) {
				System.out.println(Thread.currentThread().getName() + " 正在出售 " + (num--) + " 张票");
			}
		}
	}
}
```

### 1.2 卖电影票案例2

实现Runnable接口的方式卖电影票，代码如下所示，假设有三个窗口

public class SellTicektesDemo {

### 1.3 卖电影票案例3

讲解过电影院售票程序，从表面上看不出什么问题，但是在真实生活中，售票时网络是不能实时传输的，总是存在延迟的情况。

所以，在出售一张票以后，需要一点时间的延迟。改实现接口方式的卖票程序,每次卖票延迟100毫秒

```java
public class ThreadDemo {
    public static void main(String[] args) {
        // 创建3个线程对象
        SellTicktes t1 = new SellTicktes() ;
        SellTicktes t2 = new SellTicktes() ;
        SellTicktes t3 = new SellTicktes() ;
        // 设置名称
        t1.setName("窗口1") ;
        t2.setName("窗口2") ;
        t3.setName("窗口3") ;
        // 启动线程
        t1.start() ;
        t2.start() ;
        t3.start() ;
    }
}

public class SellTicktes extends Thread {
    private static int num = 100 ;
    @Override
    public void run() {
        // 模拟售票
        while(num != 0) {
            if( num > 0 ) {
                try {
                    Thread.sleep(100) ;
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + "正在出售" + (num--) + "张票");
            }
        }
    }
}
```

## 02.线程安全问题探讨

### 2.1 电影票案例分析

这段代码模拟三个售票窗口（三个线程）同时出售100张票。每个线程都会不断地检查剩余的票数（num），如果票数大于0，就出售一张（num减1），直到票数为0。

这段代码在多线程环境下会出现脏数据（数据不一致）问题。具体表现为：

1. 可能卖出超过100张票（比如101张）。 
2. 可能卖出重复的票（多个线程卖同一张票）。 
3. 剩余票数的显示可能出现负数。

### 2.2 线程模型与内存

Java内存模型规定：

1. 主内存(Main Memory)：存储所有共享变量 
2. 工作内存(Working Memory)：每个线程私有的内存空间 
3. 内存屏障(Memory Barrier)：控制工作内存与主内存的数据同步

在Java中，每个线程都有自己的工作内存（也称为线程栈），而所有线程共享主内存（堆内存）。线程对变量的操作遵循以下流程：

1. 读取操作：线程从主内存复制变量到工作内存，然后在工作内存中操作。
2. 写入操作：线程将工作内存中的变量值刷新到主内存。

这种模型导致了两个核心问题：

1. 可见性问题：一个线程对共享变量的修改可能不会立即被其他线程看到。 
2. 原子性问题：对共享变量的操作（如自增）可能被其他线程中断。

### 2.3 为何出现脏数据

首先想为什么出现脏数据这种问题？出现这些问题的根本原因是多个线程同时访问和修改共享变量num，而没有进行同步控制。具体来说：

1. **第一个：原子性问题**

num--这个操作并不是原子操作。它实际上分为三个步骤：

- 1）读取num的当前值；
- 2）将值减1；
- 3）将新值写回num。

如果两个线程同时执行num--，可能会出现以下情况：

- 线程1读取num为100，然后线程2也读取num为100；
- 线程1将100减1得到99，写回num（此时num=99）；
- 线程2也将100减1得到99，写回num（此时num=99）；

这样，两个线程都卖出了第100张票，但实际上只减少了一张票。

2. **第二个：可见性问题**

由于每个线程有自己的工作内存（缓存），在没有同步的情况下，一个线程修改了共享变量，可能不会立即被其他线程看到，导致其他线程操作的是过期的数据。

3. **第三个：顺序性问题**

编译器和处理器可能会对指令进行重排序，这也会导致在多线程环境下出现意想不到的结果。

### 2.4 脏数据产生原理

1. 工作内存与主内存不一致

每个线程都有自己的工作内存，当多个线程同时操作同一个共享变量时，它们各自在自己的工作内存中操作，然后不定时地同步到主内存。这种延迟导致了数据不一致。示例场景：

```text
假设有两个线程A和B，共享变量num=100。
线程A读取num=100到工作内存。
线程B读取num=100到工作内存。
线程A在工作内存中执行num--，变为99，但尚未写回主内存。
线程B在工作内存中执行num--，同样变为99（因为主内存还是100）。
线程A将99写回主内存。
线程B将99写回主内存。
```

结果：主内存最终为99，但实际应该减少两次，即98。这就是典型的原子性问题。

2. 指令交错执行（线程调度）

由于线程调度是操作系统随机进行的，多个线程的指令可能交错执行，导致非原子操作被中断。示例：num--的非原子性

```text
num--在字节码层面分为多个步骤：
aload_0         // 加载this
dup             // 复制栈顶
getfield #2     // 获取字段num（从主内存到工作内存）
iconst_1        // 加载常量1
isub            // 执行减法
putfield #2     // 将结果写回字段（工作内存到主内存）
```

两个线程可能交错执行这些指令，导致数据不一致。

3. 编译器/处理器优化

```text
编译器/处理器可能优化指令顺序：
// 原始代码
if(num > 0) {
    System.out.println("出售 " + num);
    num--;
}

// 可能被重排为：
int temp = num;
num = temp - 1;
System.out.println("出售 " + temp);
```

现代编译器和处理器会对指令进行重排序以优化性能，这可能导致操作顺序与代码顺序不一致，从而引发问题。

### 2.5 核心解决思想

解决方案的核心思想：保证操作的原子性和可见性

1. 原子性（Atomicity）确保一个操作是不可分割的，要么全部执行，要么不执行。在Java中，可以通过以下方式实现：

锁（synchronized）：确保同一时刻只有一个线程执行临界区代码。

原子类（AtomicInteger）：利用CAS（Compare-And-Swap）指令实现无锁原子操作。

2. 可见性（Visibility）确保一个线程对共享变量的修改对其他线程立即可见。实现方式：

volatile关键字：强制所有读写操作直接发生在主内存，禁止缓存。

锁（synchronized）：在释放锁前，会将工作内存刷新到主内存；在获取锁时，会从主内存重新加载变量。

3. 有序性（Ordering）防止指令重排序，确保操作按预期顺序执行。实现方式：

volatile关键字：通过内存屏障禁止重排序。

锁（synchronized）：通过互斥执行保证有序性。

### 2.6 解决问题方案

基本思想：让程序没有安全问题的环境。怎么实现呢？把多个语句操作共享数据的代码给锁起来，让任意时刻只能有一个线程执行即可。

要解决多线程安全问题，我们需要保证操作的原子性、可见性和顺序性。常见的解决方案有：

方案1：使用synchronized关键字（同步代码块或同步方法）：通过加锁，保证同一时间只有一个线程可以执行临界区代码（即访问共享资源的代码）。这样，操作共享变量的过程就变成了原子操作，同时也能保证可见性（因为锁的获得和释放会触发内存屏障，保证变量的可见性）。

方法2：使用Lock接口及其实现类（如ReentrantLock）：与synchronized类似，也是通过加锁机制，但提供了更灵活的锁操作（如可中断、可尝试获取锁、公平锁等）。

方法3：使用原子类（如AtomicInteger）：Java提供了java.util.concurrent.atomic包，其中的原子类可以保证对单个变量的操作是原子性的。例如，我们可以用AtomicInteger来代替int类型的num。

方法4：使用volatile关键字：volatile可以保证变量的可见性（即一个线程修改了变量，其他线程能立即看到最新值），但不能保证复合操作的原子性（比如num--不是原子操作）。因此，在需要原子性的场景下，volatile不能单独解决这个问题。


## 03.线程安全解决实践

### 3.1 synchronized解决同步

同步可以解决安全问题的根本原因就在那个对象上。该对象如同锁的功能

可以保证同一时间只有一个线程能拿到锁，也就保证了同一时间只有一个线程能执行申请锁和释放锁之间的代码。

```java
public void run() {
    while(true) {
        synchronized(SellTickets.class) {
            if(num <= 0) break;
            System.out.println(Thread.currentThread().getName() 
                + " 出售 " + num-- + " 张票");
        }
        // 模拟其他操作耗时
        try { Thread.sleep(10); } catch(Exception e) {}
    }
}
```

大概原理：

- 使用类对象作为锁（静态成员同步）
- 进入同步块前获取监视器锁
- 保证原子性：锁内操作不可分割
- 保证可见性：解锁前将工作内存刷新到主内存
- 保证有序性：防止指令重排序

### 3.2 ReentrantLock解决同步

```java
private static final ReentrantLock lock = new ReentrantLock();

public void run() {
    while(true) {
        lock.lock();
        try {
            if(num <= 0) break;
            System.out.println(Thread.currentThread().getName() 
                + " 出售 " + num-- + " 张票");
        } finally {
            lock.unlock();
        }
    }
}
```

优势：

- 更灵活的加锁机制
- 可尝试获取锁（tryLock）
- 可中断锁（lockInterruptibly）
- 公平锁选项

### 3.3 CAS乐观锁解决同步

Java中提供了对应的原子操作类来实现该操作，并保证原子性，其本质是利用了CPU级别的CAS指令。由于是CPU级别的指令，其开销比需要操作系统参与的锁的开销小。

```java
private static AtomicInteger num = new AtomicInteger(100);

public void run() {
    while(true) {
        int current = num.get();
        if(current <= 0) break;
        
        if(num.compareAndSet(current, current - 1)) {
            System.out.println(Thread.currentThread().getName() 
                + " 出售 " + current + " 张票");
        }
    }
}
```

### 3.4 volatile保证可见性

当使用volatile修饰某个变量时，它会保证对该变量的修改会立即被更新到内存中，并且将其它缓存中对该变量的缓存设置成无效，因此其它线程需要读取该值时必须从主内存中读取，从而得到最新的值。

```java
public static class SellTicktes4 extends Thread {
    private static volatile int num = 100;

    @Override
    public void run() {
        // 模拟售票
        while (num != 0) {
            if (num > 0) {
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + " 正在出售 " + (num--) + " 张票");
            }
        }
    }
}
```
