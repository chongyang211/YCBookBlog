### **类加载流程**

#### **1. 加载（Loading）**
- **触发时机**：当 JVM 执行 `Main` 类的 `main` 方法时，发现需要加载 `MyClass` 类。
- **过程**：
    - JVM 通过 `MyClass` 的全限定名（`MyClass`）查找对应的 `.class` 文件。
    - 将 `.class` 文件的字节码加载到内存中。
    - 在内存中创建一个 `java.lang.Class` 对象，表示 `MyClass` 类。
- **结果**：`MyClass` 类的字节码被加载到内存中，`Class` 对象被创建。

---

#### **2. 连接（Linking）**
连接阶段分为三个子阶段：验证、准备和解析。

##### **2.1 验证（Verification）**
- **目的**：确保加载的字节码文件符合 JVM 规范，保证安全性。
- **过程**：
    - 检查字节码文件的格式是否正确。
    - 检查字节码指令是否合法。
    - 检查类的继承关系是否合理。
- **结果**：如果验证通过，进入准备阶段；否则抛出 `VerifyError`。

##### **2.2 准备（Preparation）**
- **目的**：为类的静态变量分配内存，并设置默认初始值。
- **过程**：
    - 为 `MyClass` 的静态变量 `MESSAGE` 分配内存。
    - 设置 `MESSAGE` 的默认初始值为 `null`（因为 `MESSAGE` 是 `String` 类型）。
- **结果**：静态变量 `MESSAGE` 的内存分配完成，初始值为 `null`。

##### **2.3 解析（Resolution）**
- **目的**：将类、方法、字段的符号引用转换为直接引用。
- **过程**：
    - 将 `MyClass` 类中引用的其他类（如 `System`、`String`）的符号引用转换为直接引用。
    - 将 `sayHello` 方法的符号引用转换为直接引用。
- **结果**：符号引用被解析为直接引用，类可以正常调用其他类和方法。

---

#### **3. 初始化（Initialization）**
- **触发时机**：类首次被主动使用时（如创建实例、访问静态变量或静态方法）。
- **过程**：
    - 执行 `MyClass` 的静态代码块（`static {}`）。
    - 执行静态变量的显式初始化（如 `MESSAGE = "Hello, World!"`）。
- **结果**：
    - 静态代码块输出：`MyClass is loaded and initialized!`
    - 静态变量 `MESSAGE` 被赋值为 `"Hello, World!"`。

---

#### **4. 使用（Usage）**
- **过程**：
    - 在 `Main` 类的 `main` 方法中，创建 `MyClass` 的实例：
      ```java
      MyClass myClass = new MyClass();
      ```
    - 调用 `MyClass` 的 `sayHello` 方法：
      ```java
      myClass.sayHello();
      ```
    - `sayHello` 方法输出：`Hello, World!`
- **结果**：`MyClass` 类的功能被正常使用。

---

#### **5. 卸载（Unloading）**
- **触发时机**：当类的 `Class` 对象不再被引用，且满足以下条件时，类会被卸载：
    - 类的所有实例都已被回收。
    - 类的 `ClassLoader` 已被回收。
    - 类的 `Class` 对象不再被引用。
- **过程**：
    - JVM 的垃圾回收器（GC）回收 `MyClass` 的 `Class` 对象。
    - 释放 `MyClass` 类占用的内存。
- **结果**：`MyClass` 类被卸载，内存被释放。

---

### **完整输出**

运行 `Main` 类时，输出如下：
```
Main class is running...
MyClass is loaded and initialized!
Hello, World!
```

---

### **总结**

类的加载流程包括以下步骤：
1. **加载**：将 `.class` 文件加载到内存中，创建 `Class` 对象。
2. **连接**：
    - 验证：检查字节码的正确性。
    - 准备：为静态变量分配内存并设置默认值。
    - 解析：将符号引用转换为直接引用。
3. **初始化**：执行静态代码块和静态变量的显式初始化。
4. **使用**：创建实例并调用方法。
5. **卸载**：当类不再被使用时，由 JVM 卸载并回收内存。

通过这个案例，可以清晰地理解类的加载流程及其在 JVM 中的运行机制。

## 6.9并发设计模式研究

- 1.1 如何理解不可变解决并发：指的是对象一旦创建，其状态（属性值）就不能被修改。在并发编程中，不可变对象是解决并发问题的一种有效方式，因为它天然线程安全，无需额外的同步机制。
- 1.2 如何理解COW解决并发：核心思想是在修改数据时创建数据的副本，而不是直接修改原始数据。这种技术在多线程环境中非常有用，因为它可以减少锁的使用，提高并发性能。
- 1.3 
- 2.1 不可变如何解决并发问题：最简单的办法就是让共享变量只有读操作，而没有写操作。是没有并发问题的。
- 2.2 如何实现不可变性的类：1.将类声明为final类型；2.对所有字段设置final类型；3.不提供修改状态的方法；4.确保类的内部状态不被暴露
- 2.3 说一下JDK中String不可变性实现：严格遵守不可变类的三点要求：类和属性都是 final 的，所有方法均是只读的。
- 2.5 不可变核心特性有哪些：1.状态不可修改，2.线程是安全的，3.无副作用对其他线程无影响。
- 2.6 Immutability注意点：在使用 Immutability 模式的时候一定要确认保持不变性的边界在哪里，是否要求属性对象也具备不可变性。
- 2.7 不可变应用场景有哪些：1.并发编程中不可变避免数据安全；2.不可变对象适合作为缓存或共享数据；3.不可变对象适合表示配置或常量
