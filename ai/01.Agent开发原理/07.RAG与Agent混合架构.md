# 07.RAG + Agent 混合架构 —— 让 Agent 拥有"知识外脑"

> 📝 **本文待写作**。第 7 篇。纯 RAG 不会推理，纯 Agent 没有私有知识 —— 两者结合才是企业落地的主流形态。

---

## 摘要

RAG 让 LLM 有私域知识，Agent 让 LLM 会做决策。本文讲清三种混合架构（Agent-in-the-Loop / RAG-as-Tool / 双引擎），并做一个"技术文档问答 Agent"实战，对比加了 Agent 前后的回答准确率。

---

## 一、概念篇（30%）

### 1.1 为什么 RAG 和 Agent 要结合

- 纯 RAG 的局限：只会检索，不会追问、不会推理
- 纯 Agent 的局限：没有私有知识，全靠通用能力
- 结合后的能力跃升

### 1.2 三种混合架构

- **Agent-in-the-Loop**：Agent 主导，RAG 作为工具之一
- **RAG-as-Tool**：向量检索封装成 Tool，Agent 自主判断是否调用
- **双引擎**：RAG 出候选，Agent 做验证与补全

### 1.3 检索的三种范式

- 向量检索：语义相似
- 图谱检索：关系精准
- 混合检索：BM25 + Vector + Rerank

## 三、思考篇（20%）

### 3.1 检索质量决定 Agent 的幻觉率

- Garbage In, Garbage Out
- 检索评测：MRR / Recall@K

### 3.2 Agentic RAG 的典型落地场景

- 客服问答
- 代码库问答
- 法规查询
- 医疗辅助

### 3.3 什么时候不该上 Agentic RAG

- 简单 FAQ 用普通 RAG 更快更便宜
- 严格准确率场景要人在环中
