# 九宫格经典游戏合集 · 技术方案设计

> 一句话定位：**一个首页 3×3 九宫格导航、内置 9 款经典单机小游戏的「游戏盒子」，一套代码同时发布到网站（H5）与微信小游戏，纯单机、零后台、零服务器。**

---

## 一、项目概述

### 1.1 需求还原

| 诉求 | 说明 |
|---|---|
| 形态 | 「九宫格」游戏合集 —— 首页 3×3 菜单，每格一款游戏 |
| 必含游戏 | 俄罗斯方块、贪吃蛇、飞机大战、扫雷 等经典款 |
| 运行方式 | 单机，不连接后台 |
| 发布目标 | 小程序 + 网站，可选 WebView 打包 Android / iOS |

### 1.2 边界（做什么 / 不做什么）

**做**：9 款经典单机游戏 + 九宫格首页 + 本地最高分/存档 + 移动端触摸适配。

**不做**（第一版明确砍掉）：
- ❌ 联网对战 / 好友房间 / 排行榜服务器（单机原则）
- ❌ 账号体系 / 云存档
- ❌ 内购、虚拟支付（个人主体也不允许）
- ❌ 重美术资源（Canvas 矢量绘制，无图片包）

---

## 二、平台规则速览（微信小游戏硬性限制）

> 这是决定技术方案最关键的部分。核心矛盾：**「游戏」必须注册为微信小游戏，而小游戏环境不能跑 DOM / WebView，必须用 Canvas/WebGL 渲染。**

### 2.1 小游戏 ≠ 普通小程序（最关键的区别）

| 维度 | 微信小游戏 | 微信小程序 |
|---|---|---|
| 注册类目 | 游戏类 | 应用类 |
| 渲染 | **Canvas / WebGL**，无 DOM | WXML / 可 `<web-view>` 嵌 H5 |
| 能否 WebView 加载网页游戏 | ❌ 不行 | ✅ 可以，但游戏类目会被卡 |
| 适合做游戏 | ✅ 官方推荐 | ❌ 仅限工具类页面 |
| 首发加载 | 主包 ≤ 4M 即下即玩 | 普通小程序包限制 |

**结论**：你的"九宫格游戏合集"若想正经上微信，必须走**微信小游戏**路线，用 Canvas 渲染，**不能指望用 Vue + WebView 套一个 H5 游戏**（游戏类目审核不过，体验也差）。

### 2.2 包大小限制（官方 2026 最新口径）

| 项 | 上限 | 说明 |
|---|---|---|
| **主包（首包）** | **≤ 4M** | 用户首次打开即下载，越小越好 |
| **单个分包** | 不限 | 但受总包约束 |
| **代码包总大小** | **≤ 30M** | 主包 + 所有分包之和 |
| 内存 | 约 **256MB** | 真机实测，低端机更低 |

> ⚠️ 网上「总包 8M / 20M / 50M」等说法均已过时，以官方为准：**主包 4M + 总包 30M**。
>
> 本项目的 9 款 Canvas 2D 经典游戏纯代码预计 < 500KB，**远低于 4M，连分包都不需要**。

### 2.3 主体与变现限制

| 维度 | 个人主体（本项目适用） | 企业主体 |
|---|---|---|
| 注册费用 | 免费 | 微信认证 300 元/年 |
| 内购（IAP） | ❌ 不支持 | ✅ 需版号 |
| 广告变现（IAA） | ✅ 唯一合规路径 | ✅ |
| 版号 | **免**（纯广告可免） | 内购必需 |
| 备案数量上限 | **最多 5 个**小游戏 | 50 个 |
| 可做类目 | 休闲益智等轻休闲 | 全类目 |

### 2.4 其他限制（避坑清单）

1. **广告占比 ≤ 50%**，广告不遮挡核心玩法；
2. **不得诱导分享/关注**（"分享才能复活"属违规，可改"看广告复活"）；
3. 名称不得含「赚钱/提现/公司/集团」等字眼，不得用宽泛领域词；
4. 无虚拟币反向兑换（涉赌红线，本项目纯单机天然规避）。

| 资质 | 是否必需 | 说明 |
|---|---|---|

- 备案首次提交后**名称与主体不可改**，上线前锁定最终名称。

## 四、技术选型

### 4.1 方案对比

| 方案 | 跨端 | 包体 | 上手 | 结论 |
|---|---|---|---|---|
| **TS + Canvas 2D + 平台适配层**（推荐） | H5 + 小游戏 + WebView App | 极小（<500KB） | 中 | ✅ 首选 |
| 原生微信小游戏（JS/TS Canvas） | 仅微信 | 最小 | 易 | 纯微信时可 |
| Cocos Creator | 全平台 | 大（引擎 1MB+） | 中 | 杀鸡用牛刀 |
| Phaser / PixiJS + 适配层 | Web 优先 | 中（引擎几百 KB） | 易 | 备选 |
| Unity WebGL → 小游戏 | 全平台 | 大（首包吃紧） | 难 | 不适用 |

### 4.2 推荐：TypeScript + Canvas 2D + 平台适配层

**为什么选它**：

1. **9 款游戏都是 Canvas 2D 能搞定的**——无需 WebGL、无需物理引擎（俄罗斯方块/贪吃蛇/扫雷/飞机大战全是 2D 网格 + 精灵移动）；
2. **包体最小**——纯 TS 编译后逻辑 + 矢量绘制，无图片/音频素材，主包远小于 4M；
3. **一套代码三端**——核心逻辑与渲染完全一致，只差一个薄薄的「平台适配层」（见 §7）；
4. **契合单机无后台**——不引入网络层，存档走本地存储。

**放弃 Cocos / Unity 的理由**：引擎本身就要吃掉几百 KB~几 MB 首包，对 9 个轻量经典游戏是纯负担，还引入构建复杂度。

## 五、九宫格游戏清单（9 款）

| # | 游戏 | 玩法类型 | 核心数据模型 | 实现要点 |
|---|---|---|---|---|
| 1 | **俄罗斯方块** | 下落消除 | 10×20 网格 + 七种方块 | 旋转碰撞检测、消行计分、下落加速 |
| 2 | **贪吃蛇** | 蛇走吃豆 | 坐标链表（蛇身） | 方向队列防反向、撞墙/撞身判定 |
| 3 | **飞机大战** | 射击躲避 | 玩家/敌机/子弹对象池 | 帧更新、碰撞检测、无尽波次刷分 |
| 4 | **扫雷** | 逻辑推理 | N×M 雷盘 | 布雷、数字扩散（BFS/DFS 展开） |
| 5 | **2048** | 数字合成 | 4×4 矩阵 | 四方向滑动合并、随机生成 |
| 6 | **五子棋** | 棋类 | 15×15 棋盘 | 连五判定，可选极简 AI（评分函数） |
| 7 | **打砖块** | 反弹 | 挡板 + 球 + 砖阵 | 反弹物理、角度偏移、关卡 |
| 8 | **数独** | 数独推理 | 9×9 矩阵 | 生成/挖洞、候选数、合法性校验（呼应"九宫格"主题） |
| 9 | **华容道** | 滑块解谜 | 4×5 棋盘 + 方块 | 布局数据、移动合法性、步数统计 |

> 9 款覆盖「下落消除 / 操作 / 射击 / 逻辑推理 / 数字合成 / 棋类 / 反弹 / 数独 / 滑块」九种经典单机玩法，彼此零依赖、可独立开发与测试。

## 六、总体架构

```
┌─────────────────────────────────────────────────────┐
│                    九宫格首页（app.ts）                 │
│        3×3 导航菜单 · 每格一款游戏 · 最高分展示           │
└──────────────────────┬──────────────────────────────┘
                       │ 启动 / 返回
┌──────────────────────▼──────────────────────────────┐
│              games/（9 款游戏，插件化）                │
│  每个游戏实现统一接口 GameModule：init / update / render │
│  / onTouch / onPause / onResume / destroy              │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────▼──────────────────────────────┐
│              core/（轻量游戏运行时）                    │
│  主循环 requestAnimationFrame · 场景切换 · 输入分发      │
│  对象池 · 存档封装（最高分）· 屏幕适配                   │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────▼──────────────────────────────┐
│        platform/（平台适配层 PlatformAdapter）          │
│    web.ts（浏览器）  wx.ts（微信小游戏）  app.ts(WebView) │
│  抽象：画布/循环/触摸/存储/系统信息/广告/分享              │
└─────────────────────────────────────────────────────┘
```

### 关键设计原则

1. **游戏插件化**：9 款游戏都实现 `GameModule` 接口，首页只做注册与启动，加新游戏 = 新增一个目录 + 一行注册；
2. **平台差异收敛到一层**：核心逻辑永远只依赖 `PlatformAdapter` 接口，不直接碰 `wx.*` 或 `document`；
3. **纯函数逻辑与渲染分离**：每款游戏的规则（如扫雷布雷、2048 合并）写成纯函数，便于单元测试与后续移植。

## 七、平台适配层接口设计

```typescript
// platform/adapter.ts —— 核心逻辑只依赖这个接口
export interface PlatformAdapter {
  // 渲染与循环
  createCanvas(): CanvasLike;                 // 获取主画布
  loop(cb: (dt: number) => void): void;       // 封装 requestAnimationFrame
  // 输入（统一为触摸点序列）
  onTouch(handler: (type: 'start'|'move'|'end', x: number, y: number) => void): void;
  // 本地存储（单机存档）
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
  // 系统信息（屏幕适配 / 安全区）
  getSystemInfo(): { width: number; height: number; pixelRatio: number; safeArea?: Rect };
  // 可选能力（仅小程序端，网站端返回空实现）
  showRewardedAd?(): Promise<boolean>;        // 激励视频：看广告复活/翻倍
  share?(opts: { title: string }): void;      // 分享（不诱导）
}
```

两端实现差异一览：

| 能力 | Web 端（web.ts） | 微信小游戏端（wx.ts） |
|---|---|---|
| 画布 | `document.createElement('canvas')` | `wx.createCanvas()` |
| 循环 | `requestAnimationFrame` | `requestAnimationFrame`（同名） |
| 触摸 | `addEventListener('touchstart'...)` | `wx.onTouchStart/Move/End` |
| 存储 | `localStorage` | `wx.setStorageSync / getStorageSync` |
| 系统信息 | `window.innerWidth` | `wx.getSystemInfoSync()` |
| 广告 | 空实现 | `wx.createRewardedVideoAd()` |
| 分享 | Web Share API（可选） | `wx.shareAppMessage()` |

> 因为抽象只在这一层，**90% 的代码两端完全一致**，发布小游戏时只需把入口切成 `wx.ts`。

## 八、目录结构与构建

```
nine-grid-games/
├── src/
│   ├── core/                    # 运行时：loop / 场景 / 输入 / 对象池 / 存档
│   │   ├── GameModule.ts        # 游戏统一接口（9 款游戏都实现它）
│   │   ├── SceneManager.ts      # 首页 ↔ 游戏 切换
│   │   ├── GameLoop.ts          # 主循环 + 固定步长更新
│   │   ├── Input.ts             # 触摸分发
│   │   ├── Storage.ts           # 本地最高分封装
│   │   └── Screen.ts            # 屏幕适配 / 安全区
│   ├── games/                   # 9 款游戏（每款一个目录，零耦合）
│   │   ├── tetris/  snake/  plane/  minesweeper/
│   │   ├── 2048/  gomoku/  breakout/  sudoku/  klotski/
│   ├── platform/                # 平台适配层
│   │   ├── adapter.ts           # 接口定义
│   │   ├── web.ts               # 浏览器实现
│   │   └── wx.ts                # 微信小游戏实现
│   └── app.ts                   # 九宫格首页 + 游戏注册表
├── minigame/                    # 微信小游戏壳（构建产物）
│   ├── game.json                # 小游戏配置
│   └── project.config.json      # 开发者工具项目配置
├── web/                         # 网站版入口（build 产物）
├── package.json                 # 依赖仅 devDependencies（esbuild/rollup）
└── tsconfig.json
```

**构建工具**：`esbuild`（极快）或 `rollup`，产出两套入口：
- `web/index.html`（网站直开）
- `minigame/game.js`（微信小游戏，配 `game.json`）

**零运行时依赖**：生产代码只用标准 TypeScript，无框架、无引擎、无 npm 运行时依赖（devDependencies 仅构建工具）。

## 九、包体预算

| 组成 | 估算 |
|---|---|
| 9 款游戏逻辑 + 渲染（TS 编译后） | ~100–200 KB |
| 运行时 + 平台适配层 | ~30–50 KB |
| 素材（Canvas 矢量绘制，无图片） | ~0 KB |
| 音效（WebAudio 合成，可选） | ~0 KB（或少量） |
| **主包合计** | **< 500 KB** |

对照限制：主包 ≤ 4M、总包 ≤ 30M。**本项目连 4M 的 1/8 都用不到，无需分包，首屏即点即玩。**

## 十、开发路线图（5 阶段）

| 阶段 | 目标 | 交付物 |
|---|---|---|
| **P0 基建** | 运行时 + 平台适配层（Web 先行跑通） | `core/` + `platform/web.ts` + 空白首页 |
| **P1 打通一款** | 贪吃蛇或俄罗斯方块端到端 | 首页 → 游戏 → 返回 → 存最高分 |
| **P2 补齐 9 款** | 按清单逐款实现 + 自测 | `games/` 九目录齐全 |
| **P3 上小游戏** | `wx.ts` 适配 + 触摸/存档/安全区 | 微信开发者工具真机预览通过 |
| **P4 合规上线** | 软著 + 自审 + ICP 备案 → 提审 | 通过审核、可搜索到 |
| **P5 变现（可选）** | 激励视频（看广告复活/翻倍） | 广告位接入，占比 ≤ 50% |

**关键并行点**：软著（约 60 日）在 P0 启动当天就提交，不要等游戏做完才办。

## 十一、风险与决策点

| 风险 / 决策 | 说明 | 建议 |
|---|---|---|
| 用 Vue 做 DOM 渲染 | 只能走"小程序 + web-view"，游戏类目大概率被卡 | 改用 Canvas，游戏类目必须小游戏 |
| 软著周期长 | 60 日，AI 生成代码会被拒 | 立项即启动，保留真实手写代码 |
| 个人主体不能内购 | 变现只能广告 | 第一版先纯免费上线，变现后置 |
| 名称/主体不可改 | 备案后锁定 | 上线前定死游戏名 |
| 跨端适配成本 | 触摸/安全区/存储两端有差异 | 差异收敛到 `platform/` 一层 |
